# 追従台帳の適用

ユーザーが手動で起動したときに、指定されたプロジェクトで使う。
一覧外のプロジェクトや、WIを登録できないプロジェクトも対象とする。
台帳は本書と同じディレクトリにある `followup-ledger-reviews.md` と、名前が `followup-ledger-settings-` で始まる主題別の4ファイルである。

## 適用する手順

1. 対象プロジェクトの規範と「確認記録」を読む。
   過去に不採用と決めた項目は対象から外す。
2. 残る項目の「当てはまる条件」と「適用済みの見分け方」を現在のコード・設定・検証結果と比べる。
   現物で確認できた適用済みと非該当は変更対象から外す。
   適用済みの判定には現物の証拠を使い、過去の採用記録やWIの登録は証拠から除く。
   条件や現状を確認できなければ、判定不能とし、不足する情報を示す。
3. 該当する未適用の項目は、現在の認可の範囲で適用し、そのプロジェクトの手順で検証する。
   方針との衝突や取り消しの難しい操作など、本人の判断や事前承認が必要な項目だけを確認に回し、独立した他の項目は続ける。
   適用方法が未整備で実施できない場合は判定不能、適用または検証が失敗した場合は失敗として報告し、完了件数の集計から外す。
4. 現物で確認した適用済み・非該当と、適用・検証が成功した項目を、書き込み認可のある確認記録へ保存する。
   成功した新規適用は記録上の「適用済み」とし、報告では「今回適用」と区別する。
   不採用の記録は保持し、判定不能・失敗・確認待ちは適用済みの記録から除く。

## 確認記録

確認記録は過去の採否と現物の確認結果を引き継ぐために使う。

- 保存先は適用先のプロジェクトのリポジトリの外とし、プロジェクトごとに1ファイルを置く。
- 保存先のディレクトリは、ユーザーが指定した場所を使う。
  dotfilesプラグイン（dotfiles本体の`plugins/<名前>/`）のディレクトリの中を指定すると、プラグインのリポジトリを通じて別のPCへ引き継げる。
  プラグインの`.chezmoi-source/`から配布されたホーム側のファイルは、次回の適用で上書きされるため書き込み先にしない。
- 指定が無い場合は、そのPCの`~/.local/state/dotfiles/followup-records/`へ保存する。
- ユーザーが保存先を指定した場合は、その絶対パスを`~/.local/state/dotfiles/followup-records/location`へ1行で保存し、次回からは指定が無くてもその場所を使う。
  保存先を変えた場合は、既存の確認記録を全プロジェクト分まとめて新しい保存先へ移す。
- ファイル名は、プロジェクトのリモートURLからスキームと末尾の`.git`を除いた`<ホスト>/<パス>`（リモートが無ければ作業ツリーの絶対パス）の`/`と`:`を`_`へ置き換えた名前に`.json`を付ける。
  `project`には置き換える前の値を書く。
- 内容は次の形のJSONとする。
  `result`は`採用`、`不採用`、`非該当`、`適用済み`のいずれかで、`checked_on`は確認した日付、`note`は判定の根拠や登録したAWIの要旨を短く書く。

```json
{
  "project": "github.com/example/project",
  "items": {
    "markdown-one-sentence-per-line": {"result": "採用", "checked_on": "2026-11-11", "note": "検査を導入するAWIを登録"}
  }
}
```

`非該当`と記録した項目も、プロジェクトの構成が変わって条件に当たるようになった場合は、今回の現物に基づいて確認し直す。

## 返す報告に含める項目

項目IDごとに、適用済み、今回適用、非該当、判定不能、失敗、確認待ちを区別する。
過去の不採用はその旨を示す。
判定の根拠、今回適用した変更と検証結果、失敗・確認待ちに残る作業、確認記録の保存先と未保存の理由があればその理由を返す。
