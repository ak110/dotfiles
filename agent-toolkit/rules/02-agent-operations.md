# 02-agent-operations.md: エージェントの実行運用

ツールとコマンドの実行、委譲時の保護、プロセスの終了について、
製品横断で常に成立させる規範を扱う。

## ツール・コマンド運用

- 独立した複数のツール呼び出し（複数ファイルの`Read`等）は同一応答内で並列に呼ぶ。依存関係がある場合のみ逐次実行する
- 同一コマンドが複数対象を受理し、対象ごとの個別検証を要しない工程では1回にまとめる
- シェルメタ文字（バッククォート・ドル記号・二重引用符・改行など）を含む本文を単一引数として
  外部コマンドへ渡す場合、本文は`$'...'`のANSI-Cクォートで囲むか、変数へ代入してから`"$VAR"`で展開する。
  プログラミング言語の文字列シリアライザーの出力はシェルの引用規則とは別体系のため、コマンド文字列へ連結しない
  （厳守規定。引用の崩れは本文の欠落・改変またはコマンドの不成立を招く）
- 本文を登録・送信するコマンドが警告またはエラーを出力した場合、終了コードが0でも
  登録結果を取得して本文と照合する。欠落を検出した場合は同じ経路で修復する
- 定型作業の前に、`agent-toolkit/scripts/`配下、各スキルの`scripts/`配下、関連スキル、
  対象リポジトリのタスクランナー定義（`Makefile`・`mise.toml`のtasks・`package.json`のscripts等）を
  確認する。対応する専用スクリプト・スキル・サブコマンド・タスクが存在する場合はそれを使う（努力目標）
- 同一セッションで取得済みのファイルは、変更を観測するまで保持済み内容を再利用する。
  編集後の検収、外部更新後、正確な現行文面が必要な差分適用前に再取得する
- 外部コマンドの初回取得では、呼び出し側で`head`又は`tail`などの切り詰め処理を追加せず、
  既存の実行ツールが返す出力と完全性情報をそのまま観測する（努力目標）
- 実行ツールが切り詰め、容量超過又は期限超過を通知した出力は不完全として扱い、網羅性・件数・終端を根拠とする結論へ用いない。
  出力量が未知のコマンドでは、通知が無い場合も全量と断定せず、行数と終端を確認してから当該結論を確定する。切り詰めを通知しない通常出力は、網羅性に依存しない判断へ用いることができる
- 外部コマンドの引数となる識別子（ツール名・コミット識別子・タグ名・実行ID・PR番号など）は、
  実行結果として得た値の文字列をそのまま呼び出しへ用いる。短縮形からの復元・記憶・推測で組み立てない
  （誤った識別子による別対象への操作を防ぐ）
- 動作確認のために`.env`及び`.env.<接尾辞>`の値を追記、変更又は削除する操作は、
  Bashの追記（`echo ... >>`）又は`sed -i`で行う。編集ツールによる同ファイルの書き換えは行わない。
  鍵、証明書などの他の秘匿ファイルは本項の対象外とし、値を書き換えない

## 基本委譲契約

単発の委譲では、起動前に対象、読取・書込権限及び完了条件を確定する。
受領後は成果物、Git状態と検証結果を実測し、完了報告と照合する。

## 委譲時の厳守事項

本節には、委譲の有無にかかわらず作業ツリーと規範文書を保護する厳守規定と、
基本委譲契約を適用する委譲先にも成立させる受信側の厳守規定を置く。

- 1つの作業ツリーへ書き込む主体は同時に1つだけとする。
  同じworktreeへ書き込む主体を交代させる場合は、後続の実装担当を起動するときと起動側自身が当該worktreeへ書き込むときの双方で、既存の実装担当が終端したことを確認する。
  稼働中の実装担当がある間、起動側は当該worktreeへ書き込まず実施を当該実装担当へ戻し、委譲先を起動できない場合だけ終端の確認後に書込所有権を引き取る。
  異なるレーンへ割り当てた別worktreeの実装担当は、変更ファイルが重複しても相互に待機しない
- 実装担当は同じ作業ツリーの書込所有権を手放す終端報告の前に、自身が起動した全ての外部プロセスと
  背景ジョブの終了を、ツール終了結果又は保持した実行識別子の直接照会で確認する。
  前景ツールの終了後も存続し得る形で起動したプロセスは、実行識別子と終了確認結果を終端報告へ含める。
  実装担当ではない読み取り専用の委譲は対象外とする（厳守規定。終了していないプロセスの所有主体を失うと、
  後続の実装担当が安全に停止できず、1つの作業ツリーへ複数の書込主体が並存し得る）
- 委譲先・背景ジョブの完了待ちでは、シェルコマンドによる能動的な時間待ちを行わず、待機表明でターンを終える。
  当該終端は再開可能な正常状態として扱い、完了通知の受領後に工程を再開する。
  待機と観測の手順は`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`を正本とする
- 同じ計画ファイルに属する実装単位と、明示的な先行成果依存により同じレーンへ割り当てられた複数計画の実装単位は、同じworktreeで依存順に実装し、同時に1つの実装担当だけを置く。先行成果依存の無い計画ファイルを同じworktreeへ割り当てない。
  fast担当が同一失敗箇所の残存を確認して終端した後にfix担当へ移行する場合だけ、起動元が終了確認を完了してからdirty差分を逐次引き継ぐ。
  異なるレーンだけを別worktreeへ割り当てられる
- 委譲先は、自身と同一の役割種別へ再委譲せず、作業量の多さを理由に同種へ分割委譲せず自身で完遂する
- 委譲先は、着手後に現れた担当外ファイルの差分を自身のコマンドの副作用と推定して
  復元・逆パッチ適用・削除しない。共有作業ツリーでは並行する別主体の変更と区別できないため、
  担当外差分は保持して委譲元へ報告し、自身の担当ファイルだけを修正する。複数worktreeで並行作業する場合は
  `refs/stash`が全worktreeで共有されるため、`git stash push`・`git stash pop`・`git stash drop`を直接実行せず、
  承認済みの退避ではworktree横断排他ヘルパーだけを使う。担当外差分を観測した場合は、`refs/stash`共有を原因候補として報告へ含める
- サブエージェントは`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`配下・`agent-toolkit/`配下の規範文書を
  編集しない。例外はメイン側起動プロンプトで改訂を明示許可された場合に限る
- 委譲先は、委譲された範囲を超える不可逆操作（`git push`・削除・投入先を自ら決定する
  フィードバック投入等）を実行せず、当該操作と対象を完了報告で委譲元へ返却する
- 委譲元と委譲先は、ユーザーの認証情報ファイルを複製、移動又は別領域へ保存しない。
  認証を要する操作では既定の認証解決経路を維持し、その経路で成立しない場合は呼び出し元へ差し戻す
  （厳守規定。認証情報の再配置は委譲の信頼境界を越え、異常終了時に複製物を残し得る）。
  例外として、同一リポジトリのworktreeを作業場所として成立させるために、Git管理外の実行前提ファイル
  （`.env`等）を当該worktree内の同じ相対パスへ複製する操作は、本規定の禁止対象に当たらない。
  複製先が複製元と同じリポジトリに属することを`git -C <複製先> worktree list`等の出力で確認できる場合に限る。
  worktree作成時に`.worktreeinclude`（gitignore構文。パターンに一致し、かつgitignore対象のファイルだけを
  複製する）を処理する実行環境で、複製元に`.worktreeinclude`が存在する場合は作成時の自動複製を活用する。
  作成済みのworktreeへはシェルの`cp`で複製する
- 委譲先は、依頼文と適用中のスキル規則が矛盾する場合は着手せず、矛盾の内容を呼び出し元へ差し戻す。
  認証・権限の不足または無効な呼び出しにより次の工程へ進めない場合も、独自の回避策を試みず差し戻す。
  自身の定義又はタスク文書が列挙する職務に該当しない判断が生じた場合も、自ら確定せず差し戻し、当該判断に基づく成果物の変更、再委譲及び工程の打ち切りへ着手しない。
  当該判断に基づく巻き戻し、復元、受領済み素材の削除及びこれらの再委譲は、着手しない操作の具体例とする。職務又はタスク文書が委譲した復元・巻き戻しは対象に含めない
  （厳守規定。誤った判断のまま操作へ進むと反映済みの成果が失われ、差し戻して待てば損害が生じない）
- 委譲先は、指示されたコマンドが想定外の結果（契約上期待される出力の欠落を含む）を返した場合に即時に報告する。
  報告後はタスク契約に沿って事象・期待値・実際値・発生条件・直接的原因を調査し、
  技術的に成立する次の工程を継続する。次の工程が存在しないと確定した場合に限り差し戻す
- 前2項の即時報告は、現在の実行主体が到達可能な機械可読返信識別子を保持し、現在の実行主体へ`SendMessage`が公開され呼び出しに成功する場合だけ、保持した識別子へ1通送る。
  返信識別子を保持しない場合、`SendMessage`が未公開の場合、呼び出しが拒否された場合は、同じ事象を通常の完了報告へ含め、受領側が完了通知とともに逐語で中継する。
  表示名・agent種別を返信先として推定せず、完了報告を`SendMessage`で重複送信しない

## プロセス終了の安全規定

プロセス又はホスト管理ジョブを終了させる操作は、自身が起動し、起動結果から停止用の識別子を取得して保持した対象に限る。
直接起動したOSプロセスの停止にはPIDを用いる。ホスト管理ジョブの停止には、起動結果や背景移行通知が返したタスクIDなど、対象の起動経路が指定する識別子と停止手段を組み合わせる。
別種の識別子へ推測変換せず、パターン一致で対象を特定しない。
パターン一致で該当プロセスをまとめて終了させる操作（`pkill`・`killall`・`pkill -f`等）は、対象の所有権を確認できないため実行しない。

委譲先・背景ジョブの完了を待つ手順と観測手段は、`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`が定める。
