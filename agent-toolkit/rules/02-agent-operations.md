# 02-agent-operations.md: エージェントの実行運用

ツール、コマンド、リポジトリ状態、プロセスの扱いを定める。自分の実行と委譲するコマンドの双方に適用し、連結したコマンドも1つずつ判定する。

## ツール・コマンド運用

### 引用と引数

- 互いの結果に依存しないツール呼び出しは並列に呼び、同じコマンドが複数対象を受け取れるならまとめる（努力目標。往復を減らす）。
- 引数境界を保つ。空白やメタ文字を含む引数はANSI-Cクォートか`"$VAR"`で渡し、データ引数は`--`の後ろへ置く。別のシェルが再解釈するコマンド文字列（ssh、`sh -c`、コンテナー内shellなど）で境界を保てないコードはファイルで渡す。複数行のコードはmanaged-tempの中のファイルに保存し、`bash -c`、`sh -c`、`python -c`には一行で完結するコードだけを渡す。
- 永続状態を変えるコマンドは単独で発行して終了コードを観測する。表示や確認のコマンドと連結すると、最後のコマンドの終了コードが失敗を覆い隠す。
- 専用コマンドの受理形式で成立する用途は、コード評価へ置き換えずにその形式を使う。
- CLI・API・MCPの入力契約は、版を識別した公開仕様か、同じセッションで観測したヘルプ・スキーマで確定してから実行する。
- 読取時の文字コードを入力に合わせ、ホストの自動選択と異なるか不明な場合は明示する。
- 権限設定やauto mode classifierが操作を拒否した場合は、別の手段を試す前に`agent-toolkit:user-confirmation-and-report`の`references/permission-denial.md`を適用する。

### パスと検索

- 既存パスは入力・基準文書・取得済み出力から解決し、推測したパスは実体を検索する。外部コマンドへは絶対パスを渡し、cwdを使うCLIは対象worktreeで起動する。検索手段はGit管理境界に応じて`agent-toolkit:search`で選ぶ。
- 操作の対象と副作用から必要なスキルを判定し、未起動なら操作前に起動する（努力目標。契約の確認不足と独自手順の重複を避ける）。
- 外部から観測できる文言を変えるときは、旧文言を期待するテストを含む直接影響範囲（定義は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「要件・外部仕様」）を固定文字列で探し、送信側と受信側、実装とテストをそろえる。
- Git識別子と別worktreeの指定は`agent-toolkit:commit`の`references/git-identifier.md`に従う。前工程から受け取ったパスや識別子は、移動や終了を起こす操作を間に実行した後に同一性を確かめ直す。

### 出力の保持と観測

- 調査・検証は終了状態と診断で判定し、標準エラーも保持する。機械処理する出力は標準出力と標準エラーを`2>&1`で混ぜず、装飾（色・ページャー）を無効化する。取り込むパスは生成元の終了コード、空でない集合、全パスの実在を確かめる。
- 自分が実行したコマンドは終了コードと出力で判定する。取得済みの出力と本文は、読込表や手順が全文読む資料も含め、編集・外部更新・会話圧縮を観測するまで再利用し、再取得と再実行を避ける。別主体が非同期に変える状態は対象そのものを観測する。
- 初回しか観測できない出力と再取得の費用が高い出力（検証、状態変更、全量比較など）は、行数で切り詰めず全量、終了状態、診断を保持する。出力量が不明な取得は標準出力をファイルへ保存して必要な範囲を読み、限定取得で十分ならコマンド自身の対象・件数指定を使う。後続工程へ渡す大きな中間成果物は、実行環境が一度に受け取れる単位へ分割する。
- Claude Codeのツール結果（種類を問わない）が`<persisted-output>`で始まる場合は、`Output too large`の行の保存先と`Preview`の抜粋だけが届いている。保存先を末尾まで読んでから読了として扱う。全文が必要なテキストは範囲指定なしの取得から始め、事前の容量測定を省く。Claude Codeでは`Read`に`allow_large: true`を指定し、読める量の判定はホストに任せる。`PARTIAL view`の部分取得やエラーが返った場合は全文読了と扱わず、必要な残りを`offset`と`limit`で取得する。Codexの全文取得と保存本文の読取、その他のホスト固有の入力と継続結果の終端観測は各ホストの規範に従う。
- 大量出力は分離した実行で全量を観測し、終了状態と要約を受け取る（努力目標。委譲元のコンテキストを保護する）。委譲の受領物と待機は`agent-toolkit:delegation`に従う。

### 待機と背景実行

- 待機対象が終了状態を返す公開機能を持つときは、それで待ち、重複した状態照会や前景の固定時間待ちを避ける。背景実行したジョブは完了通知を確認し、保存した出力を同じターンで読む。完了通知でターンを再開できないエージェント（自動再開を伝えられていない委譲先など）は、`timeout <ツールの時間上限より短い秒数> sh -c 'until <終了条件のコマンド>; do sleep <秒数>; done'`で前景で待ち、成立しなければ同じ形を再発行する。固定時間の待機がツールの時間上限に達すると、その後に読む出力を得る前に打ち切られるため、終了条件と有限の上限を持つ待機で観測する。
- 背景実行するコマンドには、内部の処理が止まってもコマンド自体が終わる時間上限を持たせる。完了通知はコマンドの終了で届くため、上限が無いと停止の検知が遅れる。`atk agents wait`や`wait_ci.py`など、公開仕様が自身の終了上限と上限到達時の終了状態を定めるコマンドはその上限で十分である。外側の上限（`timeout`コマンドやBashツールの背景実行の`timeout`引数など）は重ねない。ホストの省略時の上限がコマンド自身の上限より短い場合だけ、それより長い値を指定する。コマンド自身の上限より先にホストが止めると、上限到達時の終了状態が失われる。
- 調査用サーバーは到達を要する主体の範囲だけで待ち受け、同じホストの確認にはloopbackを使う。
- 待機の起動と終端観測は`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`「待機区間の構成」に従う。通知で同じセッションを再開できる独立待機は、先に届いた通知から回収し、別の待機の終端まで前景で占有しない。

### `atk`の呼び出し

- `atk`はエージェント環境で出力量を自ら扱い、長い出力は自ら保存して保存先と行数を示す。このため`atk`はパイプにもリダイレクト（`2>&1`や`/dev/null`への破棄を含む）にもつながず、単独で呼び出す。介すと`atk`の終了コードと警告を同じ呼び出しで観測できず、保存先と行数の行だけが後段へ渡る。出力量が不明な取得をファイルへ保存する前項も`atk`には適用しない。常駐と追従の表示（`atk serve`、`atk wi process-loop`の常駐、`atk agents logs --follow`）を背景で起動するときの出力のリダイレクトは対象外とする。出力量は公開された対象限定（`--count`、`--summary-only`、状態・種別・対象リポジトリの指定など）で制御し、全量の機械処理は保存されたファイルへ別の呼び出しで行う。

### 完了と不在の確認

- 削除や回収の完了は対象の不在で確認する。`test -e <絶対パス>; echo "test_e_rc=$?"`を読み取り専用の確認として別の呼び出しで行うか、除去完了を終了コードに含む操作コマンドの結果を使う。`ls`、`find`、`git rev-parse`の非0終了だけで不在を確定しない。

## 作業中に観測したリポジトリ状態変化の扱い

別セッションのcommitと担当外の差分は変わる。開始時のHEADと計画のベースcommitは参照情報として扱い、担当ファイル、直接影響範囲、公開契約、書込所有権、後続操作へ影響する実差分を読む。影響がなければ現在状態で続ける。対象OIDの同一性とデータ完全性を守る確認は保ち、担当外差分を変更しない。

## プロセス終了の安全規定

終了させるプロセスとジョブは、自分の起動が返した停止用識別子で所有を確認できる対象に限る。記憶した名前、部分一致、別種の識別子への推測変換は使わない。失敗した起動でも停止用識別子が返れば所有の根拠になる。自分自身を実行環境の条件で一意に識別できる場合と、引き継ぎ記録が保持する識別子を停止直前に照会して対象コマンドとの一致を確認できる場合も同じである。

作成元の作業単位が回収済みであることを読み取りで確定したエージェント由来の残存資源（プロセス、コンテナーなど）も停止してよい。確定は対象ごとに個別の識別子（コンテナーID、PIDなど）で照会し、次を全て満たすかで判定する。停止した対象と照会結果は報告へ含める。

- 対象の作業ディレクトリ、bind mountの元または実行ファイルのパスが、エージェントの工程が作業単位を作成する配置にある。配置は`<リポジトリ>/.claude/worktrees/`配下、`atk managed-temp`の領域、および対象リポジトリの手順か設定の現物が作業単位の作成先として定める場所とする
- その作業単位が回収済みである。worktreeは対象リポジトリの`git worktree list`に無く、managed-tempの領域は`atk managed-temp list`に登録が無く、いずれもパスが存在しないか空である
- 名前の部分一致やパターンで選んでおらず、停止は照会した識別子を1件ずつ指定する

`git worktree list`に登録済みの作業ツリーに属する資源と、ユーザーが作業ツリーの外で起動した資源は、この条件を満たさないため停止の対象から外れる。

現在のworktree専用の環境単位と、前段の条件で回収済みと確定した作業単位の環境単位は、その専用名を手順か設定の現物から確かめて確定できるときに撤去する。確定できないときは対象と不足条件を委譲元へ返す。
