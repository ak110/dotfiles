# 02-agent-operations.md: エージェントの実行運用

ツール、コマンド、リポジトリ状態、プロセスの扱いを定める。自分の実行と委譲するコマンドの双方に適用し、連結したコマンドも1つずつ判定する。

## ツール・コマンド運用

- 引数が互いの結果に依存しないツールは並列に呼び、同じコマンドが複数対象を受け取れるならまとめる（努力目標。独立した往復を減らす）。
- シェルメタ文字や空白を含む単一引数はANSI-Cクォートか変数への代入後の`"$VAR"`で渡す。言語の文字列シリアライザーをシェルの引用と混同しない。引用が崩れると本文や対象が変わる。
- `ssh`、`docker exec`などで引用を二段以上解釈する場合は、コードをファイルで転送し、対象のシェルへそのファイルを実行対象として渡す。複数行のコードも管理対象一時ファイルに保存する。`bash -c`、`sh -c`、`python -c`には一行で完結するコードだけを渡す。
- 専用コマンドで成立する用途では、その受理形式を使う。コードを評価する入力へ置き換えると引用と検査が複雑になる。

<例>
構造化JSONの項目抽出: `jq`
YAMLの項目抽出: 対象プロジェクトの実行系で動く構造化パーサー
行の抽出: `rg`
</例>

- データ由来の引数にはCLIのデータ引数を使い、位置引数ではオプション終端を付ける。これにより、先頭がハイフンの値をデータとして渡せる。
- CLI、API、MCPツールの入力形式は、対象実装の公開仕様か同じセッションで観測した最下層のヘルプ・スキーマから確定する。同名の実装が複数あるコマンドは版を識別する。未確定の形式は単独のヘルプ取得後に実行する。推測で呼ぶと、誤った対象への操作と再試行を招く。
- テキストの文字コードがホストの既定値と異なるか不明なときは、読取コマンドの文字コード指定を使う。文字化けした本文は判定の根拠から外す。
- 調査と検証では標準エラーを保持する。接続先とコンテナー内のスクリプトにも適用する。`2>/dev/null`で破棄すると、終了コードだけでは原因を判定しにくい。内容が事前に確定し診断を要しない出力だけを破棄する。
- 出力からパスを取り込み次のコマンドへ渡すときは、標準エラーを分け、生成元の終了コード、空でない集合、全パスの実在を確かめる。エラー文をパスとして扱うと別の対象へ操作する。
- 機能の不成立や出力の不整合を主張するときは、標準出力と標準エラーを区別し、根拠の行が現れた経路を示す。複数の生成元が同じ端末へ書く場合の原因誤認を防ぐ。
- コマンド出力を機械処理へ渡すときは、色、ページャー、行番号や装飾を明示オプションで無効化する。無効化できないときは形式を検証し、設定による表示を正規化する。
- 自分が実行したコマンドはその終了コードと出力で判定し、重複する取得を避ける。別主体が非同期に変える状態は対象そのものを観測する。
- 定型作業の前に、対応するスクリプト、スキルやタスクを確認する（努力目標。独自手順の重複を避ける）。
- 取得済みファイルは変更を観測するまで再利用する。上書きや文字列置換の直前、編集後の検収、外部更新後、会話圧縮後には現行本文を読み直す。置換は一致数を検査する手段で行い、複数箇所では置換のたびに現行内容で照合する。
- 外部から観測できる文言を変えるときは、旧文言を期待する検体と直接消費側を固定文字列で探す。同じ契約を持つ送信側と受信側、実装と検体の値と発動条件をそろえる。
- `apply_patch`で既存ファイルを全体置換する場合も同じパスへのUpdate操作を使う。1つのpatchで同じパスをDeleteとAddに分けると適用が失敗する。
- 永続状態を変えるコマンドは単独で発行してその終了コードを観測する。表示や検査との連結は、最後のコマンドが失敗を覆い隠す。
- 待機対象が終了状態を返す公開機能を持つときは、それで待つ。待機中の重複した状態照会や前景の固定時間待ちを避ける。背景ジョブへ移った場合は完了通知を確認し、保存した出力を同じターンで読む。
- 初回しか観測できない出力と再取得の費用が高い出力は、必要な全量、終了状態、診断を保持する。検証、状態変更、全量照合の出力を行数で切り詰めると失われた結果の回復が困難になる。反復可能なファイル、履歴や一覧の先頭・末尾は`head`や`tail`などで確認する。切り詰めた結果は網羅性、件数や終端の根拠から外す。
- 全量の保持が必要で出力量が不明な取得は、標準出力をファイルへ保存して必要な範囲を読む。限定取得だけで目的を満たせるなら、コマンド自身の対象、件数、構造化条件を使う。後続工程へ渡す大きな中間成果物は、実行環境が一度に受け取れる単位へ分割する。
- `Read`の前に行数とバイト数を確認し、hookが示す実効上限の範囲を連続した行範囲で読む。上限で補正された先頭部分は部分取得として扱う。`AGENTS.md`、`SKILL.md`や規範も同じように扱う。上限の正本は`agent-toolkit/agent_toolkit/_hooks/pretooluse/large_reads.py`である。
- `atk`の出力制御には公開された対象限定と`--output-file`を使う。管理対象一時領域の保持と回収は`agent-toolkit/share/managed-temp.md`、検査の起動は`agent-toolkit/share/check-execution.md`を読む。
- 切り詰め、容量超過、期限超過、入力補正で対象を失った結果は、不在、件数、網羅性や終端の根拠から外す。出力が未知なら通知の有無だけで全量と判断せず、保存した行数と終端を確認する。
- 大量出力は分離した実行で全量を観測し、終了状態と要約を受け取る（努力目標。呼び出し元のコンテキストを保護する）。委譲の受領物と待機は`agent-toolkit:delegation`、ファイル検索は`agent-toolkit/share/search.md`を正本とする。
- hookがセッション状態の不足で遮断したときは状態と記録契機を調べる（努力目標。同じ入力の再試行だけでは不足状態が変わらない）。
- 削除や回収の完了は対象の不在で確認する。`test -e <絶対パス>; echo "test_e_rc=$?"`の終了表示は読み取り専用の確認として別の呼び出しで行う。操作コマンドの契約が除去完了を終了コードに含む場合はその結果を使う。`ls`、`find`、`git rev-parse`の非0終了だけで対象不在を確定しない。
- Git識別子と別worktreeの指定は`agent-toolkit:commit`の`references/git-identifier.md`を正本とする。前工程から受け取ったパスや識別子は、その後に移動や終了を起こす操作が介在したときに同一性を再確認する。
- 既存パスは、ユーザー入力、正本、直前の出力、読了済み文書から解決する。構成から推測したパスは`rg --files`か`find`で実体を探す。外部コマンドへは絶対パスを渡し、作業ディレクトリを暗黙に使うCLIは対象のworktreeで起動する。誤ったパスは別の対象への変更につながる。
- 調査用サーバーは到達を要する主体の範囲だけで待ち受ける。同じホストの確認にはloopbackを使い、不要な外部公開を避ける。
- 権限設定やauto mode classifierが操作を拒否した場合は、別経路の試行前に`agent-toolkit:confirmation-and-uwi`の`references/permission-denial.md`を適用する。秘匿値を含むファイルの読取と書換は`agent-toolkit/share/security.md`に従う。

## 作業中に観測したリポジトリ状態変化の扱い

別セッションのcommitと担当外の差分は変わる。開始時HEADと計画のベースcommitは参照情報として扱い、担当ファイル、直接消費側、公開契約、書込所有権、後続操作へ影響する実差分を読む。影響がなければ現在状態で続ける。対象OIDの同一性とデータ完全性を守る検査は保ち、担当外差分を変更しない。

## プロセス終了の安全規定

終了させるプロセスとジョブは、自分の起動が返した停止用識別子で所有を確認できる対象に限る。記憶した名前、部分一致、別種の識別子への推測変換は使わない。失敗した起動でも停止用識別子が返れば所有の根拠になる。自分自身を実行環境の条件で一意に識別できる場合と、引き継ぎ記録が保持する識別子を停止直前に照会して対象コマンドとの一致を確認できる場合も同じである。

現在のworktree専用の環境単位は、その専用名を手順か設定の実測で確定できるときに撤去する。確定できないときは対象と不足条件を呼び出し元へ返す。待機と終端観測は`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`を正本とする。
