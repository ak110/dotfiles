# 02-claude-code.md: Claude Code固有事項

Claude Code固有の実装挙動・制約・サブエージェント運用を扱う。

## ツール呼び出し・タスク管理

- 独立した複数のツール呼び出し（複数ファイルの`Read`等）は同一応答内で並列に呼ぶ。依存関係がある場合のみ逐次実行する
- `AskUserQuestion`の`options`は1問最大4件。判断材料は同一ターン内のテキスト出力でまとめてから発行する
- ユーザーへの質問・承認待ちでターンを終える場合は必ず`AskUserQuestion`を使う（地の文の問いかけのみで終えない）
- 複数工程・複数完遂条件を伴う起動プロンプトの場合は`TaskCreate`で各工程を独立タスク化し、
  全タスクが`completed`になるまで完了報告を発行しない
- `cat -A`等、非印字文字を可視化するオプションは使わない。確認は`Read`・`od -c`・`xxd`で代替する
- 複数ファイルに跨る置換は`agent-toolkit:pyfltr-usage`のgrep/replaceサブコマンドを使う
- 100行超の連続ブロック置換は`Edit`の`old_string`にブロック全体を含めるか行範囲スライスを使う
- `run_in_background=true`の長時間ジョブは`Monitor`で全行取得するか完了マーカーを`grep -q`で待つ。
  マーカー未生成の背景タスク完了検出目的では`Monitor`を起動しない
- `git merge`進行中は`git stash`を使わない。退避は別パスへの`cp`または別ブランチ退避で行う
- 1つの応答内で先頭のツール呼び出しがブロック・エラーでキャンセルされると後続の独立呼び出しも連鎖キャンセルされる。
  各呼び出しの成否を`git diff`・`Read`で個別確認してから次工程へ進む
- auto modeでツール呼び出しが拒否された場合、推測でフラグ追加・迂回を試みず`agent-toolkit:agent-standards`
  `references/auto-mode.md`を参照してカスタムルール追加の要否を判断する

## サブエージェント運用

- `subagent_type`の根拠が無い場合は汎用エージェント（`claude`）を使う
- 複数ディレクトリ・複数ファイルに跨る横断調査・横断置換はメインで逐次処理せず`Explore`または並列`Agent`へ委譲する
- モデル選択: 確定的な検索・単純置換は`haiku`、要約・軽度の推論は`sonnet`、
  設計判断を伴う調査・実装・レビューは`opus`を選ぶ。事前に内容が確定していないコーディングに`sonnet`以下を使わない
- サブエージェント起動は`run_in_background=true`のbackground起動を既定とする。
  `name`は指定しない。`name`付きで起動した場合の挙動が不安定なため、
  起動後に`SendMessage`で対話する必要がある場合に限り指定する。
  並列起動時は単一メッセージ内に複数の起動ブロックを並べ、完了報告はSendMessage(to: 'main')で能動送付させる
- `idle_notification(available)`のみでは完了と判定せず、完了報告本文・`git log`・作業ツリーの実測で判定する
- 新規起動の前に、同一の対象範囲・同一の計画ファイルを扱う既存サブエージェントの生存を確認する。
  完了通知が届かないことをプロセス終了と推定しない。確認手段は`git log`・作業ツリー差分・
  成果物ファイルの`mtime`とする。稼働継続中と判定した場合は新規起動せず既存へ継続を促す
- サブエージェント完了報告の数値と実測が食い違い差し戻した場合、再検査は差し戻し後に受領する
  修正後の完了報告を起点として実施する。差し戻しの送信直後や作業継続中の時点で観測した成果物の
  状態を根拠に未対応と判断しない。成果物ファイルの更新時刻が差し戻し送信以降に動いている間は
  停止・巻き取りの判断を保留し、催促にとどめる。委譲先以外の主体（CI・formatter・並行セッション）
  による更新と区別できない場合も、区別できるまでは保留側へ倒す
- 同一対象で再起動する場合、停止した前エージェントの実行内容から
  完了済み工程・試行済みのアプローチ・観測できた失敗事象を抽出し、起動プロンプトへ引き継ぐ。
  白紙から同じ失敗を再分析させない
- background並列起動中は停滞検知を行う。`git log --oneline -10`・`git status --short`・`TaskList`・
  成果物ファイルの`mtime`を1回の確認でまとめて観測する。前回観測との差分が無ければ停滞と判定する。
  停滞検知時は対象へ`SendMessage`で継続を催促し、応答が無ければメイン側で検証・コミットを巻き取るか
  縮減した新規サブエージェントを起動する
- 停滞検知の仕組みは`ScheduleWakeup`・`CronCreate`・Bash background loopのいずれかで実装し、
  全background起動の完了後またはセッション終了時に停止・登録解除する
- サブエージェントは独立コンテキストで動作するため、委譲プロンプトへ相対参照（「上記」「前述」等）を含めず、
  判断材料・完了報告要件を本文内で完結させる
- 計画ファイル作成のplan mode下委譲では、サンドボックスパスへの書き込みをメイン側が検収し正規パス
  （`~/.claude/plans/`配下）へ反映する。委譲先は正規パスの削除・移動をしない
- サブエージェントは`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`配下・`agent-toolkit/`配下の規範文書を
  編集しない。例外はメイン側起動プロンプトで改訂を明示許可された場合に限る
  （`plan-impl-executor`が規範文書を対象ファイル一覧に含む計画を実装する場合など）
- 委譲されたタスク範囲を超える不可逆操作（`git push`・削除等）は完了報告で委譲元へ返却し、自身では実行しない
- サブエージェント出力（レビュー指摘・調査結果）の統合は、通番・重大度／観点・区分・箇所・内容・対応方針の
  6列表で提示してから修正に着手する。対応不要と判断した指摘は
  `（メイン判断: 不対応 — <理由>）`または`（ユーザー判断: 不対応 — <理由>）`を末尾に注記する

## 識別子・環境変数

配布物完結の環境変数は`AGENT_TOOLKIT_<PURPOSE>`形式とする。
代表例は`AGENT_TOOLKIT_PRIVATE_NOTES`（`atk mq`管理repoのroot、既定`~/private-notes/`）と
`AGENT_TOOLKIT_STOP_GATE_DEBUG`（デバッグ出力）である。個人環境完結は`DOTFILES_`を使う。
`agent-toolkit/rules/`・`agent-toolkit/agents/`配下はサブディレクトリを設けずフラット構造を保つ。

## 公式リファレンス

スキル新規作成・hook実装では公式マーケットプレイス（`anthropics/claude-plugins-official`）の
`skill-creator:skill-creator`・`plugin-dev`各スキルを参照する。認識相違時は
`https://code.claude.com/docs/ja/`配下（`skills.md`・`sub-agents.md`・`hooks.md`等）を`WebFetch`で取得する。
