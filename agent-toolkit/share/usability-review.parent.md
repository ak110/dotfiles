# ユーザビリティレビューの起動と検収

```text
起動対象: usability-review.subagent.md
```

エンドユーザーが操作する画面の追加または変更がある場合、メインは同じ対象HEADに対するユーザビリティレビュー担当と実行レビュー担当を並列に起動し、修正後も並列に再判定し、統合前に両方の収束（ユーザビリティレビューの`合格`または`未確定`と、実行レビューの未解決0件）を確認する。この運用を「並列画面レビュー」と呼ぶ。対象はHTML、CSS、画面コンポーネント、単体HTML成果物を含む。ユーザビリティレビューには実装担当から独立したthreadを使う。ユーザビリティレビューは自動テストが判定しないUXを評価し、機能の正しさはPlaywrightを含むE2Eテストと実行レビューが確かめる。

## 起動

対象worktreeを対象リポジトリの作業ツリーから確定する。
メインは`検証環境`を渡す前に、対象worktreeの書込主体へ対象リポジトリの手順で対象HEADの再配備または起動を依頼し、完了を確認する。レーン工程の書込主体はレーン担当とする。実装途中に配備済みの環境を使う場合も対象HEADへ更新する。修正後の再判定でも、新しい対象HEADで同じように準備する。
同じplugin rootの`share/usability-review.subagent.md`を指定して担当を起動する。起動の形は`agent-toolkit:delegation`の`references/base-contract.md`「`<役割名>.subagent.md`を指定する起動」に従い、`cwd`は対象worktreeの絶対パスとする。`extra_params`へは次の名前付き入力を渡す。

- 対象worktree: `cwd`と同じ絶対パス。
- 変更画面: 差分が変更した画面のパスまたはURLと、操作で表示する状態へ到達する手順。
- 主要シナリオ: 計画またはWIが指定するエンドユーザーの作業の流れと、そこで確かめるUX上の観点。受入シナリオの期待結果を判定基準として渡さず、データの反映や操作の成否といった機能の正しさを確かめる項目も含めない。
  変更画面ごとに書き、完成条件が異なる画面はシナリオの文を分ける。まとめると、ある画面にだけ求めた結果が別の画面の判定根拠になる。
  各画面の観点は、その画面に対するWIの完成条件と計画の受入シナリオが求める範囲に限る。計画の`## 実施内容`などの要約が完成条件より広い結果を述べる場合は、WIの完成条件に合わせて範囲を決める。
- 検証環境: 対象プロジェクトの手順から確定したローカル起動形または127.0.0.1の稼働中URL。
- 引き継ぎ記録先: 値は`agent-toolkit:delegation`の`references/base-contract.md`「`<役割名>.subagent.md`を指定する起動」が指す`引き継ぎ記録先`の書式に従う。
- round: 初回は1、同じ担当への再判定では直前の番号に1を足す。
- レーン識別子: レーンの作業を対象とする起動に限り、そのレーンの識別子。session識別名を`<レーン識別子>-usability-review`にする。

## 返却後

返却された記録が対象HEADと`判定の回数`を示すか確認する。`合格`と`不合格`では完遂を試みたシナリオ、観測状態とキャプチャーの実在を確認する。`未確定`では、返却値に`E2E環境`、`Playwrightのライブラリ`、`ブラウザー操作ツール`の3つの`試行:`行がそろうかを確認する。欠ける場合は受理せず、同じ担当threadへ欠けた手段の試行と再判定を求める。担当が起動したプロセスの終了は担当の義務とし、返却後に残留を確かめる工程は設けない。

`不合格`は根拠がその画面に対するWIの完成条件の範囲の内か外かで次のとおり扱う。

| `不合格`の根拠 | 扱い |
| --- | --- |
| 範囲外の観察で、エンドユーザーの停止場面か誤った結果を示す不足 | 観察を判定の根拠から外し、範囲を示して同じ担当threadへ再判定を依頼する。不足は`agent-toolkit:user-confirmation-and-report`の`references/judgment.md`「認可を要する操作」の範囲外の不足の区分で判定し、バグの修正は既存不良の扱いに従ってprocess-wiの同じ実行の中で是正し、新しい挙動の追加は同書「確認を要する事項」の確認へ送る |
| 範囲外の観察で、停止場面を示さないもの | 観察を判定の根拠から外し、範囲を示して同じ担当threadへ再判定を依頼する。観察は参考記録とする |
| 範囲内の根拠 | 次の手順で修正と再判定を行う |

1. 指摘に記録された画面状態、操作順、表示幅と観測結果を修正条件として同じ実装担当へ返す。レーン工程では同じレーン担当が修正する
2. 担当が新しい対象HEADの画面を実ブラウザーで同じ条件に進め、試した条件と実際の表示結果を再提出したことを確認する
3. 同じユーザビリティレビュー担当threadへの再判定と実行レビュー担当への再レビューを、同じHEADで並列に依頼する

統合前に、同じ対象HEADについてユーザビリティレビューの`合格`または`未確定`の記録と、実行レビューの未解決指摘0件を確認する。ユーザビリティレビューの記録を計画の検証結果へ加える。`未確定`では利用できなかった描画手段と未確認の画面状態を完了報告へ記す。
