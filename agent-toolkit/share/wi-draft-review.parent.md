# 通常AWIの投入前レビュー

```text
起動対象: wi-draft-review.subagent.md
```

## 起動と受領

通常AWIを`atk wi add`へ渡すときは、本文の起草者と別の担当へ投入前レビューを1回依頼する。人間が原稿を渡した場合も対象とする。UWIは対象外とする。

同時に内容と依存関係を確定した複数本文は1件のレビュー起動へまとめる。先行項目の正式ファイル名だけが未発行の場合も、後続原稿が依存する先行原稿と正式名を記入する箇所をレビュー入力へ示してまとめる。先行原稿の採否・内容・依存関係のいずれかが未確定な組は確定後にレビューする。本文をUTF-8のファイルへ保存する。原稿の対象・除外・認可のいずれかが確認回答に依存する場合は、回答に対応する質問、提示した全選択肢の全文、実際に選ばれた選択肢および自由記述を、ユーザー原文を保持する同じ記録へ保存する。確認回答から独立した原稿の入力は本文と対象リポジトリで完結する。`agents_server.start`の`subagent_md_path`へ`${CLAUDE_PLUGIN_ROOT}/share/wi-draft-review.subagent.md`の絶対パスを渡す。`extra_params`の`レビュー対象`へ原稿ごとに本文ファイルと対象リポジトリの絶対パスを渡し、人間由来の要求がある原稿には原文記録の所在も対応付ける。レビュー担当には読取専用の起動条件を使い、投入は起草者が担う。
`extra_params`の`引き継ぎ記録先`の値は`agent-toolkit:delegation`の`references/base-contract.md`「タスク文書起動」が指す`引き継ぎ記録先`の書式に従う。

担当から本文ごとの`採用`、`修正`、`取り下げ`と理由を受け取る。投入する主体は`agent-toolkit:review-standards`の`references/reviewee.md`に従って指摘の妥当性を判断し、必要な修正または取り下げを反映してから投入する。修正後は指摘への対応結果から再レビューの要否を判定する。結果と処置を、投入を行う主体の引き継ぎ記録へ残す。
正式名だけ未定の組では、先行項目の`atk wi add`成功結果が返したファイル名とレビュー済みの先行原稿を対応付ける。後続原稿へその名前を記入し、依存メタデータと本文の差分が識別子だけで意味を変えないことを起草者が確かめてから依存順に投入する。先行原稿の内容と依存関係のいずれかがレビュー後に変わった場合は、影響を受ける後続原稿を再レビューする。
