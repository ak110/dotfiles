# WI原稿の投入前レビューの起動と検収

```text
起動対象: wi-draft-review.subagent.md
```

投入前レビューは、親エージェントが意味を検収しない専念型の作成主体が、原稿の保存前に独立した中位レビュー担当へ渡して受けるレビューである。付随型では`add-wi.parent.md`に定める親エージェントの検収を用いる（所在参照）。
起動が必要かどうかは、`agent-toolkit:wi-standards`の`references/drafting-workflow.md`「直接起草と独立した検収の選択」に従って判断する。
同節で直接起草を選択できる原稿については、メインエージェントによる意味検収と機械チェックを適用する。

## 起動

`agents_server`の`start`を呼び出し、`cwd`に対象リポジトリの絶対パス、`subagent_md_path`に`wi-draft-review`を指定する。`extra_params`には以下の入力を渡す。工程別の`model_type`は役割表に基づいて解決する。

## 入力

- 必須入力名: `原稿`、`要求と出所`、`成立性の証拠`、`引き継ぎ記録先`。

- `原稿`: 単一原稿の絶対パス、または複数原稿の対応表を保存したUTF-8形式のJSONファイルの絶対パス。対応表は空でない配列とし、各要素に`要求識別子`（一意な文字列）、`原稿`、`要求と出所`、`成立性の証拠`（後ろの3項目は読み取り可能な絶対パス）を含める。共通の出所や証拠がある場合は、同じパスを参照できる。単一原稿の入力もそのまま受け付ける。
- `要求と出所`: 原文、確定した要件、技術判断、割り当て、および由来を記録した既存ファイルの絶対パス。複数原稿を扱う場合は、各原稿に対応付ける。
- `成立性の証拠`: 観測結果、原因、採否の根拠、ならびに引用や構造チェックの結果を記録した絶対パス。共通の資料は1回取得して再利用し、要求ごとの証拠との対応関係を保つ。
- `引き継ぎ記録先`: 省略や継続の扱いはdelegationの共通契約に従う。

同じ作成主体が同時に用意した原稿は対応表でまとめる。まだ到着していない原稿を待つ目的だけの待機は置かない。公開されている3つの入力名やパスの形式は、単一原稿の場合と共通である。対応表を用いる場合でも、`要求と出所`や`成立性の証拠`には共通資料の絶対パスを指定する。要求ごとの対応関係は対応表側で保持し、共通資料は1回取得して各要求へ適用する。
作成主体は、原稿ごとの確認（原文との読み比べ、および`atk wi add --dry-run`または`atk wi edit --dry-run`）の結果を成立性の証拠へ記録し、原稿、要求と出所、成立性の証拠の各ファイルを直接渡す。対応表に含まれる任意の`ユーザー向け部分`には、原稿から抜き出した冒頭部分の絶対パスを指定する。共通の根拠説明や対応表は、渡された形式のまま扱う。

## 検収と修正

元の要求の解釈についてレビュー担当と作成主体で見解が分かれ、結果や作業範囲が変わる場合は、`agent-toolkit:review-standards`の共通規定に立ち返る。
原文、実際の回答、および現物を確認しても解決せず、ユーザー自身の判断に委ねる事項が残る場合は、その判断を要する修正を保留し、双方の解釈と結果をユーザー確認できるメインエージェントへ報告する。
レビュー結果として返却された要求識別子と原稿の集合が、入力した集合と一致することを確認する。要求ごとの意味判定に加え、検収者による冒頭部分の判定、条件付きで起動した読者確認の識別子、結果、証拠を追跡する。合格した原稿は、他の原稿の修正完了を待たずに個別に保存できる。追加の原稿がある場合は、新しい識別子を割り当てて既存の担当へ渡し、取得済みの共通資料を再利用する。
各判定の`読者別探索:`欄を確認する。識別子が記録されている場合は返却内容を読み、その判定がユーザー向け部分に対する確認結果であることを確かめる。再利用時は前回の抽出内容との一致を確認し、起動条件に当てはまらない場合は条件と自己確認の根拠を確かめる。行の欠落や無効な省略がある場合は、合格判定であっても同じ担当へ差し戻して確認を求める。
サブエージェントの終了と報告を受け取ったら、review-standardsを適用して各指摘の採否と必要な再調査の要否を作成主体が確定する。要件との不一致を指摘された場合は、その指摘が前提としている値の出所を、元の要求、実際の回答、ならびに`agent-toolkit:wi-standards`の`references/origin-and-approval.md`「由来と`source`」に照らして採否を判断する。質問や選択肢の説明を要件として扱っている指摘については、その由来を示した上で同じ担当へ再判定を依頼し、ユーザー自身の決定を要する事項のみを確認へ回す。
修正する際は、部分的な追記だけで済ませるのではなく、変更した方式全体の整合性を確かめてから再提出する。確認の対象は、開始、終了、途中の失敗から再開に至る一連の流れとし、基準には`agent-toolkit:wi-standards`の`references/drafting-completion.md`「実現方式の成立」を用いる。修正のたびに新たな状態管理や照会手段を追加するような指摘が続く場合は、方式の維持、縮小、または代替案への切り替えを比較検討する。比較の基準には`agent-basics:writing-standards`の`references/design-heuristics.md`「問題と手段の比例性」を用いる。指摘が繰り返される原因は、`agent-basics:bugfix`の`references/root-cause-scenarios.md`「反復した指摘の原因判定」に従って分析する。成立性に関する未解決事項は、指摘が繰り返された場合でも確実に解消した上で合格とする。修正後は、変更した要求識別子、現行の原稿、差分、直接の影響範囲を同じレビュー担当へ渡して再判定を依頼する。変更のない共通資料や合格済みの要求結果はそのまま保持し、変更のない抽出内容は読者別探索の再点検省略条件に従って再利用する。検収済みの参照関係に基づく正式名への置換のみの差分については、再判定へ戻すことなく、`agent-toolkit:wi-standards`の`references/drafting-workflow.md`「投入」に従って作成主体が先行項目の保存結果と突き合わせた上で保存処理へ進める。未解決の指摘が0件であることと、原稿と証拠の対応関係を確認した上で、共通のWI保存手順を実行する。ユーザー自身の判断が必要な事項は、確認が取れるまで保留する。

## 投入前レビューの返却契約

以下の形式のみを返す。

出力は以下の形式とする。単一原稿の場合はこの形式をそのまま用いる。複数原稿の場合は`レビュー結果:`の下に対話ごとの要求をまとめ、要求ごとに`要求識別子:`と以下の全項目を記載する。すべての要求を漏れなく重複なく返し、資料不足、修正待ち、あるいは読者確認の失敗など一部の事象についても該当する要求にのみ対応付ける。続行不能と追加報告行は、共通契約`rules-subagent.md`「返却形式の受け渡し」に従う。

```text
判定: 合格 | 修正要
対象原稿: <受領した絶対パス>
未解決指摘: <件数>
指摘:
- <対象箇所、実際値、期待値、根拠と適用理由。0件なら「なし」>
確認した要求と根拠: <確認対象と観測の所在>
ユーザー向け部分の確認: <抽出パス、検収者の判定と根拠、読者別探索を起動した場合は識別子・各抽出の判定・証拠。省略時の値は「記録なし」であり、確認完了とは扱わない>
読者別探索: <起動結果の識別子と返却の所在、または省略の条件と前回の識別子。起動条件非該当の場合はその根拠>
```

技術的に確認できない事項が残る場合は合格とせず、確認対象と不足している根拠を指摘に含める。
`読者別探索:`の項目は修正要を含むすべての判定に記載する。実施の根拠または正当な省略の根拠が確認できない場合は合格としない。
