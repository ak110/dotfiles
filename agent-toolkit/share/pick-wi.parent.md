# pickerの起動と受領

```text
起動対象: pick-wi.subagent.md
```

選定工程の開始時に、process-wiのメインが本書を全文読み、選定の前処理、pickerの起動、出力の検収、キューの占有並びに前のセッションの振り返りと監査の開始へ適用する。
本書は選定工程でメインが読む唯一の資料であり、全体の処理対象を選定させる契約と、前のセッションの振り返り及び自動コードレビュー監査の開始を定める。

## 計画保存先の移行

メインが`atk plans migrate`を1回実行する。当該コマンドは移行対象の有無にかかわらず、先に計画保存先の作業ツリーがcleanであることを検査してremoteと同期する。
他の主体が取得中の計画バンドルは、所有記録の実在により同コマンドが移行対象から除く。
当該コマンドが非0で終了した場合は再試行せず、終了コードと出力を報告して選定を続行する。

## 前のセッションの振り返りと監査

メインは、pickerの起動と並行して、前のセッションを対象とする振り返りと自動コードレビュー監査を開始する。
いずれもレーン工程と並行して進め、公開工程の開始より前に返却の受領と処置の確定を完了する。レーン工程の全レーンの完了を開始条件にしない。

振り返りは、メインが`agent-toolkit:session-review`をSkill機能で起動し、同スキルの別セッション経路を適用する。
起動、受領、即時対応の処置及び引き継ぎ経路の終端は`${CLAUDE_PLUGIN_ROOT}/share/session-review-delegate.parent.md`が定める。
振り返りで同じ時機に修正内容が確定した事象が複数ある場合は、1件の委譲先へまとめて渡す。まとめる対象は、同じ作業ディレクトリで実行でき、書込所有権が競合しない事象とする。事象ごとに委譲先を分ける場合は、その理由を記録する。

対象リポジトリがGitHub上にある場合、自動コードレビューを確認する。GitHub Copilotの取得と判定は`${CLAUDE_PLUGIN_ROOT}/skills/process-wi/references/github-copilot-review-audit.md`を全文読んで実行する。GitHub以外の対象リポジトリでは、以降の自動コードレビュー確認を行わない。

新しい自動レビューの到着を能動的に待機せず、1回だけ取得する。当該セッションで作成するリリースPRに対するGitHub Copilotレビューは次のセッションの監査で扱う。未対応の指摘ごとに、当該セッションで是正するか`agent-toolkit:wi-standards`に従ってAWIを登録するかを確定する前に、監査の返却を受領する。既に是正済み又は根拠付きで対応不要と確定した指摘について、分類と根拠の記録及び未解決threadの解決は監査担当が同書に従って実行する。取得に失敗した場合は完了として報告せず、必須の外部資料を取得できない場合の確認経路へ送る。

監査で同一セッションの是正を選んだ場合は、成果物の変更とcommitを終端担当の起動より前に完了する。自動レビュー監査は繰り返さない。

監査担当は対象リポジトリの成果物を変更しない。GitHubのPull Requestへの返信、コメント投稿とthreadの解決は当該制約の対象外とし、実行の範囲は同書が定める。メインは監査担当から全指摘の所在、判定及び処置を受け取り、指摘ごとの処置を確定する。起動方法は`agent-toolkit/rules/01-agent.md`「委譲の要否判定」に従って選び、現行成果物をプロジェクト規範へ照合できない方法を既定にしない。

## 起動

メインはキュー一覧とAWI本文を自ら取得せず、pickerへ選定させる。
`agents_server`の`start`へ`model_type="pick_wi"`と対象リポジトリの絶対パスを渡して起動する。engine、model及びeffortはサーバーが解決するため指定しない。

起動の前に`atk managed-temp create --prefix pick-wi`を1回実行し、終了コード0と単一行の絶対パスを確認する。当該ディレクトリ直下の`pick-wi.txt`を選定結果の出力先ファイルとし、メインが当該領域を所有する。

起動文は`agent-toolkit:delegation`のSKILL.mdの`## 送信`に従い、1行目で`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`を指す。次を名前付き必須入力とし、これ以外を渡さない。

- `対象リポジトリ`: 対象リポジトリの絶対パス
- `プロジェクト規範`: プロジェクト規範の絶対パス
- `選定結果の出力先ファイル`: 選定結果の出力先ファイルの絶対パス
- `引き継ぎ記録先`: `atk managed-temp create --prefix=handoff`で作成した領域の直下のファイルの絶対パス。当該委譲の全工程の完了後に`atk managed-temp cleanup --path <当該領域の絶対パス>`で回収する
- ユーザーが処理対象のAWIを明示した場合は、当該ファイル名の一覧

ユーザーが本スキルの起動時又は起動後の追加指示で処理対象を明示した場合もpickerを省略せず、指定ファイル名を選定制約として渡す。
本文の取得、処理区分、依存順、レーン分け、中断再開項目の再開位置及び確認境界の判定は、いずれの経路でもpickerが一貫して担う。

## 出力の受領

pickerは`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`が定める形式で、処理開始まで完了した集合を`status: completed`として出力先ファイルへ書き込み、ツール戻り値へは`status`、`output_file`、`lines`の3行だけを返す。
候補集合の自己検査と処理開始はpickerが同じターンで行い、メインは受理の往復を置かない。
メインはツール戻り値の`output_file`が起動文で渡した絶対パスと一致することを確認し、当該ファイルを読んで以降の検収へ用いる。一致しない場合と当該ファイルを読み取れない場合は、観測値を添えて同じpicker threadへ再取得を指示する。
メインは出力のファイル名、選定時点の状態、要求単位の由来、区分、レーン、計画ファイル、再開位置、確認境界、固有順序、プロジェクト規範が指定する情報、上流投入の区分、投入先、要求及び`answered_uwis`を検収する。
プロジェクト規範が指定する情報は`project_notes`が運ぶ。当該規範が当該情報を定めていない対象リポジトリでは全項目が既定値`なし`となり、当該行は出力されない。メインは`なし`以外の値を当該規範が定める用途だけへ用いる。
確認境界には、充足済み候補で実在を確認したコミット又は実装箇所の最小情報を含めることができる。
上流投入の区分の行がある場合は、投入先と要求の行があり、いずれも`なし`でないことを確認する。区分の行が無い場合は、投入先と要求の行も無いことを確認する。3行がいずれも無い項目は、上流リポジトリの改訂を要しないものとして扱う。
要求単位の由来は、`人間由来`と`エージェント由来`のいずれかの区分を伴う値であることを確認する。区分を伴わない値を受領した場合は、当該値を計画担当へ渡さず、同じpicker threadへ区分の確定を指示する。
`answered_uwis`は、`なし`であるか、重複の無いUWIのファイル名の一覧であることを確認する。
`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`が既定値との一致により出力しないと定めた行は、不在を当該既定値として解釈し、欠落として扱わない。
欠落、重複、形式外の値のいずれかを検出した場合は「選定工程の完了」節へ進まず、観測値を添えてpickerへ再取得を指示する。
成功時の出力はレーンの起動に必要な構造化情報だけとする。
メインは、上流へ投入する要求、確認境界の候補位置及び`project_notes`が運ぶ内容を除き、AWI本文、項目別の採否理由、候補の調査過程を含む対象実装の調査結果を受け取らない。
メインがこれらを読むのは、pickerの`needs_escalation`、ユーザーの介入、第2ラウンド以降の収束判断など、内容に基づく判断が実際に必要になった時点に限る。
その時点で該当するAWI本文、計画、レビュー指摘管理表のうち判断に要るものを直接読む。
`needs_escalation`の場合は、pickerの結果を変更せず、返された確認事項をメインが`AskUserQuestion`で確認する。回答を得られない場合は、メインが`agent-toolkit:wi-standards`に従ってUWIを登録し、元項目へ依存を追加して`inbox`かつ`blocked`で保持する。確認への回答かUWIの回答を受領して一般的な同一担当継続契約へ渡す。

pickerは要求の不採用と、既存commit・既存実装による充足を確定しない。採否と充足の成否はレーンの計画担当が確定する。計画担当が確定した全AWI行は、実施範囲の有無にかかわらず`agent-toolkit:process-wi`の統合担当へ渡す。メインはAWI行を直接`reject`又は`adopt`しない。キュー入力の不整合と、本文だけから明白なユーザー選好・外部待ちだけをpickerが`needs_escalation`で返し、メインが確認する。

同一セッション中にUWIの回答を受領した場合は、メインが回答をUWIへ保存し、UWIを先に終端して元項目の依存解除を確認する。
routeとtaskが有効なら同じpicker threadを再開し、その他は一般的な継続契約に従う。別セッションまで機械的に待たない。

## 終端工程の承認スコープ

pickerの出力を検収した後、メインが本節を適用して当該セッションの承認スコープを確定する。

`AGENT_TOOLKIT_PROCESS_LOOP_SESSION`の値が`1`である起動を自動常駐起動、それ以外を手動起動とする。`atk wi process-loop`が子セッションへ当該変数を設定するため、この観測で両者を判別できる。判別は選定工程の実行中に1回だけ行う。

手動起動では、pickerが固定した各AWIの完成条件から、release、tag、push、PR若しくはMRの作成又は配布に当たる終端工程を抽出する。抽出した工程のうち、操作、対象及び外部可視の結果が当該AWIの本文へ明示されているものだけを、要求の由来を問わず当該セッションの承認スコープとして保持する。保持する項目は、AWIの正本ファイル名、操作、対象、影響範囲と、当該記載を含む完成条件の引用とする。

自動常駐起動では承認スコープを保持しない。完成条件へ当該工程の記載が無いAWIも保持の対象にしない。

承認スコープを保持した工程について、計画担当と終端担当のいずれかが同じ操作、同じ対象かつ同じ影響範囲の実行を要求する場合は、同じ範囲の承認を重ねて求めるUWIと確認を発行せずに実行する。bump種別、公開先又は生成物を新たに具体化して対象若しくは影響範囲が承認スコープと異なる場合は、その差分だけを`agent-toolkit/rules/01-agent.md`「協調と自律」の確認経路へ送り、承認スコープの残りを取り消さない。

破壊的操作の実行前に行う実行内容、影響範囲及び復元方法の説明は、承認スコープの有無にかかわらず維持する。

## 選定工程の完了

処理開始はpickerが実行する。メインは`atk wi start-processing`を自ら実行しない。
メインは`atk wi list --target-repo=<repo> --skip-pull`を1回実行する。`decisions[].awi`の全件が`processing`にあることと、`answered_uwis`のうち`decisions`へ現れないファイル名が`processing`にないことを、同じ出力から1回のコマンドで照合する。
レーン工程へ進まずに選定工程を終える場合は、`atk managed-temp cleanup --path <起動前に作成した領域の絶対パス>`を1回実行して出力先ファイルを回収し、終了コード0を確認する。レーン工程へ進む場合は、pickerの出力をレーンの起動と公開工程の終端担当への受け渡しが消費し終えるまで当該領域を保持し、公開工程へ渡す入力を確定した後に同じコマンドで回収して終了コード0を確認する。回収の条件は`agent-toolkit/rules/02-agent-operations.md`「ツール・コマンド運用」が定める管理対象一時領域の規定に従い、出力先ファイルの読取1回を用途の完了として扱わない。
`decisions`に無いファイル名が`processing`にあることは、当該回の処理対象ではないため選定工程の完了を妨げない。ユーザーが処理対象を明示した処理回では、当該項目が`processing`に残ることが正常であるためである。
配置されていない項目が1件でもある場合は、計画ファイル、managed-temp、worktree及び実装担当の起動を含むレーン工程へ進まない。

レーン工程へ進まない場合は、再取得した各項目の保存状態と`decisions[].awi`の一覧を対照し、`processing`へ遷移していない項目を確定する。当該項目のファイル名、観測した保存状態及び当該セッションで再実行しない理由を`agent-toolkit:wi-standards`に従って登録し、選定工程を終える。当該セッションではレーン工程と公開工程へ進まない。

起動時に固定した集合だけを、そのセッションの処理対象とする。
レーン工程の全レーンが後始末まで完了した後もready一覧を再取得せず、公開工程へ進む。

レーン工程の進行中に新しいレーンを追加すると、その分だけ並列度が下がって全体の所要時間が延びる。
選定工程で割り当てなかった作業は、既存レーンの対象へ入る場合を除き、次の処理回又は次セッションへ回す。
ユーザーの指示によりレーン工程の進行中に新しい作業が確定した場合も、当該セッションで着手する必要があるかを判断してから起動し、
着手しない作業はAWIへ登録する。
