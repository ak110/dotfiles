# pickerの起動と受領

```text
起動対象: pick-wi.subagent.md
```

process-wiのメインが、処理対象の選定、処理開始、前セッションの振り返り及び自動コードレビュー監査の開始へ適用する。

## 前のセッションの振り返りと監査

pickerと並行して`agent-toolkit:session-review`の別セッション経路を開始する。対象がGitHub上にある場合は`skills/process-wi/references/github-copilot-review-audit.md`に従って自動コードレビューを1回取得する。両方の返却と処置確定を公開工程の開始条件とし、新しいレビューを待機しない。監査担当は対象リポジトリの成果物を変更しない。

## 起動

メインはキュー一覧とAWI本文を自ら取得せず、`agents_server`の`start`でpickerを1件起動する。
`subagent_md_path`には`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`を解決した絶対パスを渡す。
`extra_params`には次の名前付き入力、`cwd`には対象リポジトリの絶対パスを渡す。
`atk managed-temp create --prefix pick-wi`で作成した領域の`pick-wi.txt`を出力先とする。

- `対象リポジトリ`: 絶対パス
- `プロジェクト規範`: 絶対パス
- `選定結果の出力先ファイル`: 絶対パス
- `引き継ぎ記録先`: 管理対象一時領域内の絶対パス
- ユーザーが処理対象を明示した場合は当該ファイル名一覧

ユーザー指定がある場合もpickerを省略しない。本文取得、依存順、レーン分け、再開位置及び確認境界はpickerが担う。

## 出力の受領

pickerから`status`、`output_file`及び`lines`の3行を受領し、出力先が起動時の絶対パスと一致することを確認して本文を読む。各decisionのファイル名、選定時状態、要求単位の由来、区分、レーン、再開位置、確認境界、固有順序、`project_notes`、上流投入情報を検収する。

再開位置がある項目では、作業root内の計画ファイルの絶対パスであり、計画の`関連WI`が対象AWIを含むことを確認する。再開位置が無い項目は新しい計画を起草する対象とする。既定値との一致により省略された行は、pickerの出力契約が定める既定値として解釈する。

欠落、重複、形式外の値又は照合不一致を検出した場合は、観測値を添えて同じpicker threadへ再取得を指示する。`needs_escalation`では結果を変更せず、確認事項を確認経路へ送る。回答を得られない場合はUWIを登録し、依存する項目を`inbox`かつ`blocked`で保持する。

pickerは不採用と既存実装による充足を確定しない。レーン担当が計画で採否を確定し、全AWI行を統合担当へ渡す。メインはAWIを直接`reject`又は`adopt`しない。

## 終端工程の承認スコープ

手動起動では、固定したAWIの完成条件に明示されたrelease、tag、push、PR若しくはMR又は配布を、記載された操作、対象及び影響範囲に限って承認スコープとして保持する。自動常駐起動では保持しない。承認済み範囲を重ねて確認せず、新しく具体化して範囲が変わる部分だけを確認経路へ送る。破壊的操作の事前説明は維持する。

## 選定工程の完了

処理開始はpickerが行う。メインは`atk wi list --target-repo=<repo> --skip-pull`を1回実行し、選定された全項目が`processing`にあり、対象外の回答済みUWIが`processing`にないことを照合する。不一致ではレーン工程へ進まず、状態と理由を記録する。

処理対象は起動時に固定した集合だけとする。出力先の管理対象一時領域は、レーン起動と公開工程への受け渡しが全て完了した後に回収する。ready一覧を再取得せず、全レーンの完了後は公開工程へ進む。
