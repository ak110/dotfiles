# pickerの起動と受領

```text
起動対象: pick-wi.subagent.md
```

process-wiのメインが、処理対象の選定、処理開始、および選定時点で確定する終端工程の承認スコープの保持へ適用する。

## 起動

メインはキュー一覧とAWI本文の取得をpickerへ委ね、`pick-wi.subagent.md`を指定してpickerを1件起動する（`agent-toolkit:delegation`の`references/base-contract.md`「`<役割名>.subagent.md`を指定する起動」）。
`cwd`は対象リポジトリの絶対パスとし、`extra_params`には次の名前付き入力を渡す。
セッションのmanaged-temp（`agent-toolkit:managed-temp`）の直下の`pick-wi.yaml`を出力先とする。

- `選定結果の出力先ファイル`: 絶対パス
- `引き継ぎ記録先`: 値は`agent-toolkit:delegation`の`references/base-contract.md`「`<役割名>.subagent.md`を指定する起動」が指す`引き継ぎ記録先`の書式に従う
- `AWIファイル名一覧`: ユーザーが処理対象を明示した場合、または即時対応で追加が確定した場合のAWIファイル名の一覧。指定が無い場合は送らない

ユーザー指定がある場合もpickerを起動する。本文取得、依存順、レーン分けおよび再開位置はpickerが担う。

`start`の前に、対象リポジトリがmiseの設定ファイルを持ち、対象リポジトリで実行した`mise trust --show`が`untrusted`を示す場合は`mise trust <対象リポジトリの絶対パス>`を実行する。
未trustの設定があると委譲先がプラグインのMCPサーバーとhookを起動できず、`agents_server`は事前確認の失敗としてpickerを起動しない。準備の範囲は`agent-toolkit/skills/process-wi/references/run-lanes.md`「レーンと資源」が専用worktreeへ行うmise trustと同じとする。

## 出力の受領

pickerから4行の返却を受領する。欄は`状態`、`出力先`、`行数`、`書込対象の検査`である。
出力先が起動時の絶対パスと一致することを確認する。
続けて返却欄の値にかかわらず、受領側自身が最新の出力先へ`atk run-script pick-wi-check -- --work-dir <対象リポジトリの絶対パス> <出力先の絶対パス>`を単独で実行し、終了コードと出力行を得る。このコマンドは最初に出力先をYAMLとして読み、pickerの出力契約が定める項目名、必ず持つ行と値の型を確かめる。続けて`書込対象`、`公開工程の書込対象`および`書き込まない反映先`の和がAWI本文の反映先とUWIの本文に明示されたパスを覆い、3区分が重複しないことを確かめ、受領の可否を判定する。
コマンドの結果を得てから返却欄との整合を判定する。`書込対象の検査`の欄は`completed`では最新の出力先に対する`終了コード0`、`needs_escalation`では観測した非0の終了コードか実行できなかった理由を示す。

- 終了コード1と、`次の操作:`が選定結果の修正を示す終了コード2（YAML構文、項目名、必ず持つ行または値の型の誤り）は、返却欄の値にかかわらずその出力行を観測値として添えて後述の手順で同じpicker threadへ再取得を指示する
- `次の操作:`が引数、パスまたはprivate-notesの確認を示す終了コード2は、受領側の実行の誤りか環境の問題である。案内に従って引数か場所を直して同じコマンドを再実行し、pickerへの再取得には送らない。出力先が実在しない場合は返却の欠落として同じpicker threadへ再取得を指示する
- 終了コード0でも、返却欄の`状態`や`書込対象の検査`がこの結果と合わない場合は、観測値を添えて同じpickerへ欄の訂正を求める
- `書込対象の検査`の欄を持たない3行の返却は結果不明として扱い、欄の省略を合格へ補完せず、このコマンドの結果で判定する

終了コード0で欄が整合した出力の本文を読む。
`pick-wi-check`が保証するのは選定結果のYAML構文、項目名、必ず持つ行と値の型、パスの被覆、同段階の別レーンの重複パスの根拠、および後段の先行指定の形式である。分類と変更する定義の独立性はpickerの本文読解と、後段のメインの検収で確かめる。終了コード0が示す範囲と、読解で確かめる意味の範囲を分けて判定する。
作業を求める回答済みUWIの項目では、回答に起因する3区分の分類を、UWIの質問・判断材料・回答を読んで検収する。回答がパスを明示しない場合は`pick-wi-check`が比べるパスが無く、終了コード0はUWIの書込範囲を確かめた結果にならない。pickerが限定調査で導いた範囲と、そのレーンの`根拠`の記述が回答の作業内容と合うかを確かめ、欠けや食い違いは後述の不一致として扱う。
`選定`の各項目を`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`の`## 出力`が定める項目、省略時の値、省略規則と比べて検収する。
同じレーンの`担当モデル.実装担当`の明示指定が両立するか確認する。異なる値なら対象WIと指定値を示して同じpicker threadへ割当の修正を求める。段階化した結果は、単一段階案と段階案の完了見込み、後段の先行統合条件が各レーンの`根拠`で一致するか確認する。
`プロジェクト規範の指定`が指すファイルは実在して読み取れることを確認する。上流投入の3行は`上流投入`の値に応じた必須性と省略規則を確認する。`レーンの所要時間`は`なし`でないレーンとの集合一致、重複の不在、非負の2つの秒数を確認する。根拠も空でないことを確かめる。レーン数は`選定`の件数を`WI数`とした`floor((WI数+9)/10)`と比べ、上限を超える場合は、超過の根拠を超過分のレーンの`根拠`が示すか確かめる。認める根拠は、分割不能条件だけで6000秒を超える連結成分から他の連結成分を分けたこととし、示さない場合は後述の不一致として扱う。pickerが文面の上限規則を守らずに上限を超えた割当を返した事例があるため、受領側でも比べる。
`公開工程の書込対象`を持つ項目では、対象リポジトリの規範が全レーン統合後の公開工程だけへ書込を割り当てる節と各pathを`レーンの所要時間`の`根拠`から確認する。根拠を確認できないpathは競合集合から外さず、不一致として同じpicker threadへ再取得を指示する。

`選定`と`レーンの所要時間`が空の選定結果も正常な選定結果として受領し、レーンを起動せずに自動コードレビュー監査と公開工程へ進む。

別レーンの`選定`の項目どうしで`書込対象`の重なる書込対象を求める。ディレクトリ範囲は末尾の`/`で識別し、文字列の一致に加えてパス要素の包含関係を比べる。範囲と配下のファイル、範囲どうしの包含も重なりとし、似た名前の別ディレクトリは区別する。同段階で重なる対象ごとに、双方の`レーンの所要時間`の`根拠`が共通するファイルか狭い方の範囲を挙げ、変更する定義が交わらないことを示すか確認する。異なる段階で重なる対象では、後段が先行レーンの統合後に始まる条件を確認する。対象、定義または先行条件が欠ける場合は不一致とし、観測した重なりと2つのAWIを添えて、後述の手順で同じpicker threadへ再取得を指示する。

<例>
`src/`と`src/model.py`、双方の理由が同ファイルの異なる定義を示す: 独立性を確認して受領する。
`src/`と`src/models/`、一方の理由に共通範囲か変更する定義が無い: 不一致として再取得する。
`src/`と`src-old/model.py`: パス要素が異なるため、この組は書込対象の重なりに含めない。
</例>

メインは候補内の同一リポジトリの依存を、正規化した`target_repo`と`depends_on`から推移的にたどる。起動前に、依存の両端が同じレーンにあり依存先が先行することを検収する。書込競合の順序は`depends_on`とは分ける。別レーンの開始順だけで候補内依存を満たす割当は受理しない。
通常中断の`~/.claude/plans`内の絶対パスと、観測のみの再開位置が持つ`private-notes/plans/`からの相対パスを計画識別として読み、同じ計画を指す全項目が同じレーンにあることを確かめる。異なるレーンにあれば、計画、各AWIおよび各レーンを示して同じpicker threadへ再取得を指示する。`計画なし`と再開位置なしは計画識別の対象外とする。

上流投入の3行の省略時の値と省略を解決した`選定`の各項目について、「出力」の`上流投入`と`レーン`の組合せ条件も検収する。`上流投入`の行を省略した`レーン: なし`などの不一致は、後段の同一pickerへの再取得へ戻す。通常レーンがある外部操作だけの項目は、ファイル変更が無いことを理由に再取得しない。

固定形式に適合する出力を受領した時点で選定結果を検証し、監査の終端を待たずに選定工程の完了とレーン起動へ進む。受領済みのpickerを再び待機または起動せず、そのまま終端させる。

再開位置が`反映後の観測だけが残る`で始まらない項目では、`~/.claude/plans`内の計画ファイルの絶対パスであり、計画の`関連WI`が対象AWIを含むことを確認する。
`agent-toolkit:process-wi`の`references/finish-session.md`「セッション終了」はAWI本文へ再開記録（最後の`## 反映後の観測の再開記録`の節）を追記し、pickerはその記録から`反映後の観測だけが残る`で始まる観測のみの再開位置を返す。この値では前文の計画ファイルの確認に代えて、AWI本文の最後の同名節が持つ`計画`の値と再開位置の`計画:`の値が一致することを確かめる。値が`private-notes/plans/`からの相対パスの場合は、`atk config get private_notes`が返す場所の`plans/`配下にその計画が実在し、計画の`関連WI`が対象AWIを含むことも確かめる。値が`計画なし`の場合は計画の確認を省く。
再開位置が無い項目は新しい計画を起草する対象とする。省略時の値との一致により省略された行は、pickerの出力契約が定める省略時の値として解釈する。

欠落、重複、形式外の値または不一致を検出した場合だけ、観測値を添えて同じpicker threadへ再取得を指示する。`needs_escalation`では結果をそのまま保持し、確認事項をユーザー確認する。回答を得られない場合はUWIを登録し、その回答を得るまで進められない項目を`atk wi hold`で保留する。選定後に`processing`へ移した項目は`atk wi hold --state=processing <ファイル名>`で保留する。

メインはpickerの出力へ不採用と既存実装による充足の確定が含まれないことを検収する。選定工程ではメインがAWIを直接`reject`または`adopt`せず、採否と通常の終端はレーン担当が行う。反映後の観測だけが残る延期`adopt`は`agent-toolkit:process-wi`の`references/finish-session.md`「セッション終了」に従う。採否の確定はレーン担当の職務であり、その職務境界は`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`が定める。

## 終端工程の承認スコープ

環境変数`AGENT_TOOLKIT_PROCESS_LOOP_SESSION`の値が`1`の起動を自動常駐起動、それ以外を手動起動とする。`atk wi process-loop`が子セッションへこの変数を設定するため、この観測で両者を判別できる。判別の結果は選定工程の中で使い回す（努力目標。重複する照会を省く）。

手動起動では、固定したAWIの完成条件に明示されたrelease、tag、push、PRもしくはMRまたは配布を、記載された操作、対象および影響範囲に限って承認スコープとして保持する。自動常駐起動では保持しない。承認済み範囲はそのまま用い、新しく具体化して範囲が変わる部分だけをユーザー確認する。破壊的操作の事前説明は維持する。

## 選定工程の完了

処理開始はpickerが行う。メインは`atk wi list --target-repo=<対象リポジトリの絶対パス> --skip-pull`を1回実行し、選定された全項目が`processing`にあり、対象外の回答済みUWIが`processing`にないことを確認する。回答済みUWIの本文が指し、pickerが同じ工程で`unhold`した元項目も選定された全項目に含め、同じ確認の対象とする。不一致ではレーン工程へ進まず、状態と理由を記録する。

対象リポジトリのプロジェクト規範が選定工程の完了時点での評価と記録を求める条件を定める場合は、同じ工程でその条件を評価し、規範が定める記録先へ判定結果を保存する。記録は選定工程の内側で完了させる。条件の内容と記録先はプロジェクト規範に従い、本書への再掲を省く（努力目標。定義を持つ文書を1つに保つ）。

処理対象は受領した選定結果の`選定`の集合を基準とする。追加した処理対象WIは次節で検収してから同じ`選定結果の出力先ファイル`へ追記する。

## 処理対象WIの追加

ユーザーが処理中にAWIを対象へ加えるよう明示した場合と、即時対応で投入または再利用するAWIが確定した場合は、そのファイル名だけを候補差分とする。メインは通常の新着を探すためにready一覧を再取得しない。指示の無い新着はprocess-wiの次の実行へ残す。

候補差分がある場合、メインは元の選定結果とは別の出力先ファイルと引き継ぎ記録先を確保する。`AWIファイル名一覧`へ候補差分を渡してpickerを起動し、`既存レーンの選定結果の出力先ファイル`へ元の`選定結果の出力先ファイル`の絶対パスを渡す。pickerは指定項目だけを処理開始し、各項目の`プロジェクト規範の指定`、既存レーンとの書き込むファイルと節（`書込対象`）の重なり、同じ再開計画を持つ既存レーンを出力する。メインは追加出力の`選定`、`レーンの所要時間`、処理開始状態および候補差分との集合一致を「出力の受領」と同じ基準で検収する。同じ再開計画を持つ既存レーンが根拠に記録されている追加項目は、その既存レーンへの割当を費用比較より先に確定する。

メインは`agent-toolkit:process-wi`の`references/run-lanes.md`「処理中に確定した必須是正レーン」の割当基準で、追加出力のレーン識別子を既存または新規のレーン識別子へ対応付ける。既存レーンの`選定`の項目と識別子を保ち、追加した項目だけを固有の順序で`選定結果の出力先ファイル`へ追記する。既存レーンへ割り当てた追加分はその`レーンの所要時間`へ見込み時間と理由を反映し、新規レーンの`レーンの所要時間`は重複しない識別子で追加する。追記後の`選定結果の出力先ファイル`へ`atk run-script pick-wi-check`を再実行し、終了コード0を確認する。同じ再開計画の別レーン割当を含む非0では割当を直し、追記後の全体が終了コード0になってからレーン担当へ追加分を渡す。あわせて`選定`と`レーンの所要時間`の集合、AWI名の重複、依存順を再検収する。`選定結果の出力先ファイル`へ追記する前に別出力を直接レーンへ渡すと、実行レビューと終端の対象集合に追加分が含まれなくなる。

## 選定理由への質問

処理対象WIについて、包含、除外または構成の理由をユーザーが尋ねた場合は、`${CLAUDE_PLUGIN_ROOT}/share/pick-wi-explain.parent.md`を全文読み、同書に従って説明担当を起動して結果を受領する。
