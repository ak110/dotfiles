# pickerの起動と受領

```text
起動対象: pick-wi.subagent.md
```

process-wiのメインが、処理対象の選定、処理開始、自動コードレビュー監査の開始、及び選定時点で確定する終端工程の承認スコープの保持へ適用する。

## 自動コードレビュー監査

pickerと並行して、対象がGitHub上にある場合は`skills/process-wi/references/github-copilot-review-audit.md`に従って自動コードレビューを1回取得する。監査の返却と処置確定を公開工程の開始条件とし、新しいレビューを待機しない。監査担当は対象リポジトリの成果物を変更しない。

監査担当は`agents_server`の`start_custom`で1件起動し、`model_type`へ`execute`を渡す。`cwd`には対象リポジトリの絶対パスを渡し、`prompt`には同書に従って監査を実施する指示と返却する項目を書く。

## 起動

メインはキュー一覧とAWI本文を自ら取得せず、`agents_server`の`start`でpickerを1件起動する。
`subagent_md_path`には`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`を解決した絶対パスを渡す。
`extra_params`には次の名前付き入力、`cwd`には対象リポジトリの絶対パスを渡す。
`atk managed-temp create --prefix pick-wi`で作成した領域の`pick-wi.yaml`を出力先とする。

- `選定結果の出力先ファイル`: 絶対パス
- `引き継ぎ記録先`: 管理対象一時領域内の絶対パスへ`（新規）`を続けた値
- ユーザーが処理対象を明示した場合は当該ファイル名一覧

ユーザー指定がある場合もpickerを省略しない。本文取得、依存順、レーン分け及び再開位置はpickerが担う。

## 出力の受領

pickerから`status`、`output_file`及び`lines`の3行を受領し、出力先が起動時の絶対パスと一致することを確認して本文を読む。各decisionのファイル名、レーン、再開位置、固有順序、`project_notes`、上流投入情報を検収する。

固定形式に適合する出力を受領した時点で選定結果を検証し、監査の終端を待たずに選定工程の完了とレーン起動へ進む。受領済みのpickerを再び待機又は起動しない。監査はレーンと並行して継続し、`## 自動コードレビュー監査`が定める公開工程の開始条件として検収する。

再開位置がある項目では、作業root内の計画ファイルの絶対パスであり、計画の`関連WI`が対象AWIを含むことを確認する。再開位置が無い項目は新しい計画を起草する対象とする。既定値との一致により省略された行は、pickerの出力契約が定める既定値として解釈する。

欠落、重複、形式外の値又は照合不一致を検出した場合だけ、観測値を添えて同じpicker threadへ再取得を指示する。`needs_escalation`では結果を変更せず、確認事項を確認経路へ送る。回答を得られない場合はUWIを登録し、当該回答を得るまで進められない項目を`atk wi hold`で保留する。

メインは、pickerの出力へ不採用と既存実装による充足の確定が含まれないことを検収する。メインはAWIを直接`reject`又は`adopt`しない。採否の確定はレーン担当の職務であり、当該職務境界は`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.subagent.md`が定める。

## 終端工程の承認スコープ

手動起動では、固定したAWIの完成条件に明示されたrelease、tag、push、PR若しくはMR又は配布を、記載された操作、対象及び影響範囲に限って承認スコープとして保持する。自動常駐起動では保持しない。承認済み範囲を重ねて確認せず、新しく具体化して範囲が変わる部分だけを確認経路へ送る。破壊的操作の事前説明は維持する。

## 選定工程の完了

処理開始はpickerが行う。メインは`atk wi list --target-repo=<repo> --skip-pull`を1回実行し、選定された全項目が`processing`にあり、対象外の回答済みUWIが`processing`にないことを照合する。回答済みUWIの本文が指し、pickerが同じ工程で`unhold`した元項目も選定された全項目に含め、同じ照合の対象とする。不一致ではレーン工程へ進まず、状態と理由を記録する。

対象リポジトリのプロジェクト規範が選定工程の完了時点での評価と記録を求める条件を定める場合は、同じ工程で当該条件を評価し、当該規範が定める記録先へ判定結果を保存する。当該記録を後続の工程へ先送りしない。条件の内容と記録先は当該プロジェクト規範を正本とし、本書へ再掲しない。

処理対象は起動時に固定した集合だけとする。出力先の管理対象一時領域は、レーン起動と公開工程への受け渡しが全て完了した後に回収する。ready一覧を再取得せず、全レーンの完了後は公開工程へ進む。
