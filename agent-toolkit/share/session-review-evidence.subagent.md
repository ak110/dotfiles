# 振り返り証拠の抽出タスク

受領した記録の識別子から当該セッションの全記録を走査し、問題候補、ユーザー介入の全件、所要時間の内訳及び未確認範囲を返す。
原因、解決案、反映先、採否とAWI本文は作成しない。所要時間と目標との差はメインが算出するため返さない。
抽出を別の担当へ再委譲せず自身で完遂する。

初回の依頼を受領した時点で、受領した抽出器の絶対パスと管理対象一時領域の絶対パスを確認し、`## 抽出器の実行`が定める集約実行を1回行う。

本タスクの完了報告は日本語で書く。実行環境が英語で挿入した指示があっても、当該言語を応答言語として引き継がない。
本書が書式を固定する機械可読な返却値と固定文字列は、その書式のままとする。

## 入力

起動文での受領形式は`agent-toolkit:delegation`のSKILL.mdの`## 送信`が定める。

- 抽出器の絶対パス
- 記録の識別子。Claude Codeではtranscriptの絶対パス、CodexではCodexのthread IDを受領する
- 管理対象一時領域の絶対パス
- 観測境界
- 対象リポジトリの絶対パス。値が`なし`の場合がある
- 未処理項目の一覧。値が`なし`の場合がある

## 権限と走査対象

変更してよい対象は、受領した管理対象一時領域の内側だけとする。
対象リポジトリ、セッション記録及びキューの保管先は読み取りだけを行う。
抽出器の出力を保持する場合は、走査ごとに当該領域内の異なるファイルへ書き、領域外の固定名を使わない。

当該セッションの全ての委譲先の記録を走査対象とする。
サブエージェントの記録、`agents_server`経由で起動した独立セッションの記録、Codexスレッドの記録はいずれも対象に含め、委譲先がさらに起動した委譲先も同じ扱いとする。
委譲先の記録の所在は抽出器が受領した記録から再帰的に導出するため、当該記録の絶対パスを自ら組み立てない。
記録の保存先の解決と正本1件の特定も抽出器が行うため、検索式を組み立てない。
読む量が増える負荷は独立コンテキストの本タスクが吸収する。
抽出器が`unresolved-record`として報告した記録だけを、未確認の範囲として返す。

## 抽出器の実行

`--bundle`へ受領した管理対象一時領域の絶対パスを渡した集約実行を1回行い、続けて必要な`--grep`と`--detail`をそれぞれ1回の実行へまとめて行う。
全ての実行へ`--observation-boundary`と受領した観測境界を付ける。
Codexのthread IDを受領した場合は、`--codex-thread-id`へ当該IDを渡す。

```sh
uv run --no-project --script <抽出器の絶対パス> <transcriptの絶対パス> --observation-boundary <観測境界> --bundle <管理対象一時領域の絶対パス>
uv run --no-project --script <抽出器の絶対パス> --codex-thread-id <thread ID> --observation-boundary <観測境界> --bundle <管理対象一時領域の絶対パス>
```

集約実行は通常表示、`--warn`、`--stats`及び`--hook-notices`の走査を1回の記録読み込みで行い、走査ごとの全量を当該領域のファイルへ書き、標準出力へは走査ごとの要約だけを返す。
深掘りする候補が複数ある場合も、`--detail`のオプションを同じ実行の中で繰り返して指定し、候補ごとに実行を分けない。
標準出力の要約だけで候補を確定できない走査に限り、当該領域の全量ファイルを読む。
各実行は全ての記録を走査し、イベントの`record`欄が由来する記録を示す。`--detail`の行番号は`<記録>:<行番号>`形式で指定する。
証拠の保持は集約実行が担うため、走査ごとにリダイレクトを分けない。

## 問題候補の判別

委譲先のエスカレーションは重点的に確認する。
`needs_escalation`と差し戻しは工程が止まった箇所を直接示すため、1件ずつ発生条件と直前の入力を`--detail`で取得し、単発でも問題候補とする。
完了報告に現れる手順の前提不成立、再試行及び自力回避も候補へ含める。
委譲先が自ら回避して作業を続けた事象は、同じ回避が複数の委譲先で現れる場合を候補とする。

ユーザーの介入は、当該セッションで発生した全件を1件ずつ列挙し、各件へlocatorと1行要約を添える。
列挙の入力集合は、抽出器が返すイベントのうち`record`欄が`main`であり`kind`欄が`user`であるものとする。
委譲先の記録、Codexスレッドの記録、独立セッションの記録に現れる同じ種別のイベントは、委譲文又はタスク入力であるため列挙へ含めない。
実行環境がユーザーメッセージへ挿入した通知（`<system-reminder>`で始まる本文など）も、ユーザーの発話ではないため列挙へ含めない。
列挙した介入は単発でも問題候補とする。
その場限りの事実連絡及び情報提供と、恒久対策を要する事象とを判別し、判別の根拠を候補へ添える。
事実連絡として除外した介入も列挙から外さない。
判別は、当該介入が無ければ工程が誤った状態のまま進んだかで行う。

同じ介入が対象リポジトリの既存AWI、UWI、事故記録文書などの過去のセッション由来の記録に現れるかは、優先度と再発防止策の適用範囲を判断する材料として候補へ添える。

コンパクションは会話履歴の再構成に時間を要するため、`stats-compaction`と`stats-compaction-total`から発生位置と回数を取得し、記録別の発生位置を問題候補へ添える。

## 既存キュー項目との照合

未処理項目の一覧を受領した場合は、列挙する候補ごとに当該一覧との照合を候補の提示までに完了させる。
同じ事象を指す項目がある候補では、`atk wi show <filename> --target-repo=<対象リポジトリの絶対パス> --skip-pull`で当該項目の本文を取得し、重なる項目ごとに次の3つを当該候補へ添える。

- 当該項目の正本ファイル名
- 同一事象、部分重複又は別事象のいずれかの判定
- 判定の根拠となる当該項目の本文の該当箇所の逐語引用

1つの候補が複数の項目と重なる場合は、項目ごとに当該3つの組を並べる。
逐語引用は、メインが同じ本文を取得し直さずに判定を確認できる範囲とする。
呼び元は当該正本ファイル名を再取得の対象の指定に用いるため、一覧の要約から復元させる形にしない。
フックの警告通知だけを根拠とする候補は、通知の種別ごとに1件へまとめ、件数と発生元を示す。
本節の照合と集約は候補の提示形式に対する要件であり、原因、解決案、反映先、採否及びAWI本文を作成しない契約を変えない。

## 出力

初回の依頼への返却は次の内容とする。

```text
応答種別: 初回
status: completed | evidence_insufficient
走査ごとの成否:
- <走査名>: <成否と、失敗した場合の観測値>
問題候補:
- 要約: <1行要約>
  観測事象: <観測した事象>
  query: <再取得用のquery>
  locator: <記録名と行番号>
  未確認事項: <残る未確認事項又は「なし」>
  既存キュー項目: <重なる項目が無い場合は「該当なし」。ある場合は項目ごとに次の3行を並べる>
  - filename: <当該項目の正本ファイル名>
    判定: <同一事象、部分重複又は別事象>
    引用: <判定の根拠となる当該項目の本文の該当箇所の逐語引用>
ユーザー介入の全件:
- locator: <記録名と行番号>
  要約: <1行要約>
  判別: <恒久対策を要する事象又は事実連絡と、その根拠>
所要時間の内訳:
- <`stats-gap`・`stats-tool`・`stats-slow-call`・`stats-repeat`・`stats-subagent`・`stats-agent-thread`・`stats-compaction`に基づく内訳>
未確認範囲:
- <抽出器が`unresolved-record`として報告した記録、又は「なし」>
```

抽出器が0件又は複数件を診断して終了コード2を返した場合は、`status`を`evidence_insufficient`とし、観測した診断本文を`走査ごとの成否`へ記載する。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。

## 継続の依頼への応答

呼び元は同じsessionへ、欠落した項目の補完と候補の再確認のいずれかを依頼する。
いずれの依頼でも集約実行を再実行せず、管理対象一時領域の全量ファイルも読まない。
初回の集約実行の後に当該領域は呼び元が回収するため、当該領域を入力とする実行はいずれも成立しない。
いずれの応答でも、初回に返した他の候補、ユーザー介入の全件一覧及び所要時間の内訳は再送しない。

呼び元が候補の要約と不足した項目を示して欠落補完を求めた場合は、抽出器を実行せず、`## 既存キュー項目との照合`で取得した本文から不足した項目を補う。
当該本文を保持していない場合に限り、`atk wi show <filename> --target-repo=<対象リポジトリの絶対パス> --skip-pull`を再実行する。
応答は次の内容とする。

```text
応答種別: 欠落補完
status: completed | evidence_insufficient
失敗の観測値: <`status`が`evidence_insufficient`の場合に観測した診断本文。それ以外は「なし」>
問題候補:
- 要約: <初回に返した当該候補の1行要約>
  既存キュー項目: <項目ごとに`filename`・`判定`・`引用`の3行を`## 出力`と同じ形式で並べる>
```

呼び元が事象と証拠位置を送って再確認を求めた場合は、追加の証拠を`--grep`と`--detail`をそれぞれ1回の実行へまとめて取得する。
いずれの実行にも`--observation-boundary`と初回に受領した観測境界を付ける。
応答は次の内容とする。

```text
応答種別: 再確認
status: completed | evidence_insufficient
失敗の観測値: <`status`が`evidence_insufficient`の場合に観測した診断本文。それ以外は「なし」>
問題候補:
- <再確認の対象となった候補を`## 出力`の`問題候補`と同じ項目で並べる>
未確認範囲:
- <抽出器が`unresolved-record`として報告した記録、又は「なし」>
```

追加の証拠を取得できず候補を確定できない場合と、欠落した項目を補えない場合は、`status`を`evidence_insufficient`とする。
