# rules-common.codex.md: Codexの全エージェントに適用する規範

本文書はCodex環境における`AGENTS.md`として、Codexの全エージェント（メインエージェント、サブエージェント、委譲先）へ配送され、`agent-toolkit/rules/`配下の常時規範と同等の拘束力を持つ。
Codex固有の公開機能と、常時規範との差分事項を規定する。Codexのメインエージェントにのみ適用する差分事項は、`rules-main.codex.md`で扱う。

## Codex固有の入出力

- agent-toolkitの各種規範、手順、またはCLIが指定するMCPツールは、Codex環境では`functions.exec`の内部から`tools.mcp__<サーバー名>__<ツール名>(...)`の形式で呼び出す。対象となるツールには、agents_serverの`start`、`send_message`、`kill`、`stop`、`list`、`show`や、pyfltrの`run`などが含まれる。直接的な関数一覧の確認とは別に、同一の`exec`内にある`ALL_TOOLS`の各要素の`name`および`description`を参照して、ツールの存在と引数仕様を確認する。stdio形式のMCPサーバーは起動から登録完了までに数秒を要する場合があるため、起動直後に見つからない場合は一定時間待機したうえで、別の`exec`から再度照会して存在の有無を判定する。観測結果と再検証手順は、`docs/development/audit-records.md`の「agent-toolkit/share/rules-common.codex.md：Codex固有の入出力：2026年10月22日」に記載されている。
- コマンド出力の取得と待機処理は、`02-agent-operations.md`「出力の保持と観測」「待機と背景実行」の結果契約に従う。ファイルの読み取りには`cat -- <絶対パス>`または`sed -n '<開始行>,<終了行>p' -- <絶対パス>`を使用し、JSONには`jq`を使用する。資料の取得範囲は`02-agent-operations.md`「標準の読取・実行・一時領域」に従う。全体を読む資料の出力が切り詰められた場合は、行範囲を進めて末尾まで取得する。
- `functions.exec`から`exec_command`を呼び出す場合は、返却されたオブジェクト全体を`text(r)`へ渡し、本文、診断情報、`exit_code`、`session_id`を保持する。外側の`cell_id`は`functions.wait`、内側の`session_id`は`write_stdin`を用いて同一ターン内に終了まで回収する。`exit_code`が存在せず`session_id`が存在する結果は実行中として扱い、同一実行のコマンドを重複して再発行することは避ける。
- 明示的な指示がない限り、Officeファイルは原本を直接変更せずに取り扱う。CSVファイルは利用側の要求仕様に従って処理し、仕様が不明な場合はUTF-8（BOM付き）で保存する。
- `apply_patch`を用いて既存ファイルを全面的に置換する場合も、同一パスに対するUpdate操作を使用する。1つのpatch内で同一パスをDelete操作とAdd操作に分割して指定すると適用に失敗する。

コマンドの戻り値および二層待機に関する監査記録は、`docs/development/audit-records.md`の「agent-toolkit/share/rules-common.codex.md：Codex固有の入出力：2026年10月19日」に記載されている。

## Codexのplugin root解決

- 最初の`SKILL.md`を読み込む前に、自身の起動通知に記載されたagent-toolkitのルートパス、またはCLIの絶対パスにおける`scripts/`の親ディレクトリから`<plugin root>`を確定し、実体および`skills/`ディレクトリが存在することを確認する。
- agents_serverの起動時指示に`agent-toolkit plugin root: <絶対パス>`として示された配布物の配置場所は、当該委譲処理が利用する配布物として最優先し、同一ルートにある`skills/<スキル名>/SKILL.md`を読み込む。
- 起動通知とCLIの絶対パスのいずれからもルートパスを確定できない場合は、`codex plugin list --json`の実行結果をプログラム内で取得して確認する。プラグイン導入版を変更した後の再解決でも同様の手順で取得する。`installed`の一覧からagent-toolkitを一意に特定し、識別子、marketplace、version、有効状態、および解決結果のみを返却する。
- プラグイン導入情報からのルートパスは、`<Codexホーム>/plugins/cache/<marketplaceName>/<name>/<version>`として解決する。Codexホームのパスは、環境変数`CODEX_HOME`が設定されている場合はその値、未設定の場合は`~/.codex`とし、実体および`skills/`ディレクトリが存在することを確認する。
- 情報の取得失敗、対象の不在、対象が一意に定まらない状況、無効化状態、または実体の欠落が発生した場合は、原因を明確に分類して委譲元へ報告する。モデルへ返却する情報は対象の識別情報、解決結果、および診断情報に限定し、ルートパスは前述の実在確認を経て確定する。
- 確定したルートパスは保持し、公開サブコマンドを持たないプラグイン内部のリソースも同一のルートパスから読み込む。導入版が変更された後は新たな導入情報に基づいて再解決を実施し、全リソースを同一ホストかつ同一導入版のルートパスから一貫して読み込む。

## agent-basicsの資源解決

品質基準の正式な提供元は`agent-basics`である。`agent-basics:writing-standards`などの資料を参照する際は、当該プラグイン自身のルートパスから解決する。
開発環境における同一チェックアウト内では、agent-toolkitと同一の親ディレクトリに存在する`agent-basics/.claude-plugin/plugin.json`のnameおよび`skills/`ディレクトリの存在を確認して利用する。
配布先環境では、`codex plugin list --json`の導入済み情報から同一マーケットプレイスに属する有効なagent-basicsを一意に特定し、前節と同様の対応関係（Codexホーム、marketplace、name、version）に基づいてルートパスを解決する。
実体や`skills/`ディレクトリを取得できない場合は、原因を特定して委譲元へ報告する。別バージョンのキャッシュディレクトリを推測で選択することは避ける。
agent-toolkitのルートパスとagent-basicsのルートパスは個別に保持し、品質基準の参照先パスへagent-toolkitのルートパスを代入しない。

## Claude Code向けに配置された規範の読込

Claude Codeが自動的に読み込む規範のうち本文書へ埋め込まれていないものについては、Codexのエージェントも読み込みを行い、各ファイルが定める適用範囲に合致する条文に従う。これはClaude Codeと同一の作業を同一の規範の下で遂行するためである。以下の読み込み対象は任意（オプショナル）であり、実在が確認されたファイル、およびglobパターンを展開した後の集合のみを読み込みや検索の対象として渡し、未読の本文を読み込む。単一の対象ファイルが存在しないこと、パターンに一致するファイルが0件であること、またはディレクトリが存在しないことは正常な空集合として扱い、ファイルの読み取りや一覧取得における権限エラーなどは不在と区別して診断する。

任意の読み込み対象は、対象が存在しない場合でも終了コード0を返し、実在する対象のみを一覧表示する1回の確認コマンドで検証する。ユーザー単位の確認には以下のコマンドを使用できる。起点のディレクトリや対象ファイルが存在しない場合は空出力となり、一覧取得時の権限エラーが発生した場合は診断メッセージとともに対象外の終了コードが返る。プロジェクト直下の確認についても、起点と対象を揃えて同様の考え方で実施する。

```sh
if test -d "$HOME/.claude"; then find "$HOME/.claude" -maxdepth 2 \( -path "$HOME/.claude/CLAUDE.md" -o -path "$HOME/.claude/rules/*.local.md" \) -type f; fi
```

- プロジェクト直下に配置された`.agents/skills/`、`AGENTS.md`が存在しない場合における`CLAUDE.md`、`CLAUDE.local.md`、および作業内容に該当する`.claude/rules/`を読み込む。
- ユーザー単位で配置された`~/.claude/CLAUDE.md`、および`~/.claude/rules/`直下の`*.local.md`（実行ホストごとにユーザーが配置した固有規範）は、作業開始時に読み込む。
- 起動時の指示に同一ファイルの内容が`atk-auto`などの境界タグ付きで含まれている場合は、その本文を読了済みとして扱う。
- `~/.claude/rules/agent-toolkit/`配下および`~/.claude/rules/myprojects-common.md`は、本文書内に`atk-auto`要素として埋め込み済みであるため、読み込み対象から除外する。`~/.claude/rules/myprojects.md`はClaude Code向けのホスト別プロジェクト一覧と同期方針を定めたものであり、Codex環境には`myprojects-common.md`が同一主題の共通部分を届けるため、同様に読み込み対象から除外する。
- `~/.codex/agent-toolkit/rules/`は配布元から同期された本文として扱い、dotfiles固有のスキルはClaude Code側の原本へのシンボリックリンクとして扱う。

## 第三者への作用と認可

第三者に対する作用の有無は、`agent-toolkit:user-confirmation-and-report`の「認可を要する操作」に定義された第三者の範囲、および`01-agent.md`「役割分担」の原則に基づいて判断する。
依頼内容、WI、または成立済みの承認事項において明示された対象の範囲外にある第三者のシステム、外部サービス、外部リポジトリ、または個人へ作用を及ぼす操作は、対象と操作内容を明確に特定した事前承認を得てから実行する。
該当する操作には、外部への送信、投稿、PRやIssueの作成、コードの提供、アカウントの作成、認証試行や脆弱性検証などが含まれる。許可範囲内であると確定できない対象は、すべて範囲外として扱う。
公開資料の読み取り操作は、事前承認を必要とする作用の対象外とする。

範囲外の操作が必要となった場合は、`agent-toolkit:user-confirmation-and-report`の「手段の選択」に従って事前承認の手続きへ回送し、委譲先は委譲元へ報告する。
実害がないように見える設計、明示的な禁止規定の不在、代替手段の枯渇、または検証用・模擬環境であるという推測を根拠として操作を実行しない。また、第三者による拒否をユーザーからの作業依頼の認可によって上書きできない。

確認に対する回答についても、対象と操作内容を明確に指定して承諾した明示的な回答のみを承認として扱う。
対象の明示がない「続けて」「最善の判断で進めて」といった一般的な継続指示、自動生成された配送・継続メッセージ、無応答、または文脈からの推測を承認の根拠としない。
生成された指示文の由来については、`01-agent.md`「方針が衝突する場合の優先順位」に従って区別する。

第三者への情報発信や外部プロジェクトへの貢献は、ユーザーが準備した既存のアカウントと身元を用いて行い、発信内容と目的を明確に開示する。
架空の身元の使用、新規アカウントの勝手な作成、およびなりすまし行為は不適合とする。
2要素認証（2FA）やCAPTCHAなどの本人確認手続きの回避、ならびに信頼獲得を目的とした事前の貢献や支持表明の投稿も不適合とする。

## Codexホスト契約の適用

Codexが規定するsystem、developer、userの命令階層は、user側の`AGENTS.md`や個別規範から上書きできない上位の前提条件として厳格に遵守する。
`AGENTS.md`、プロジェクト固有規範、および常時規範は配送されたroleの権限範囲内で適用し、ホスト側が上書きを許容している範囲においては`01-agent.md`「方針が衝突する場合の優先順位」に従う。
ホストの公開機能、個別ツールの入出力契約、権限境界、強制打ち切り処理についても、同節の優先順位比較の対象外となる前提条件として遵守する。

ツール実行前の簡潔な`commentary`（説明）を要求するホスト環境では、ツール呼び出しの直前に短い`commentary`を出力する。コード評価を伴うコマンドでは実行内容、読み取り対象、確認目的を説明し、承認を要するコマンドでは内容、影響範囲、復元手順を実行前に説明する。

context windowを切り替える前は、枯渇通知を受けた場合も含め、`share/work-contract.md`「作成と所有」に従って自身の役割と起動入力に対応する記録先を確定する。記録先がない単発の委譲でも、未完了の工程を残して切り替える場合は同節の記録先未指定時の扱いに従う。
現在の依頼、進捗、残工程、原本や委譲入力の所在は、同書「記録する内容」が定める作業記録と各原本に保存する。委譲先の記録内容と更新は`agent-toolkit:delegation`の`references/handoff-record.md`に従う。
切替後や依頼が見当たらない場合は、依頼を確認できないと返す前に、自身の作業記録と保存した原本の所在を読み、現在の依頼と残工程を復元する。`引き継ぎ記録先`を受け取った委譲先は、同じ記録先と起動入力も確認する。許可された取得手段で復元できない場合に限り、参照した所在と失敗した操作を明記して返す。
会話圧縮後の復元でも、一時的な作業対象、処理対象のWI、保留事項、承認状態、当初の作業目的、確定済みの要件、残存する完成条件を、対象リポジトリ、private-notes、またはホストの記録原本から再解決し、出所情報の提示には記録原本の記述を使用する。

Codexの`list_agents`が対象エージェントを`running`と返している間の待機、および`interrupt_agent`による中断を許可する条件は、`agent-toolkit:delegation`の`references/codex-runtime.md`「後続操作の共通先行条件」に従う。

Codexの組み込み委譲機能（`spawn_agent`で起動したスレッド）は、`wait_agent`が利用可能な環境であればそれを用いて終了を観測してからターンを終了し、完了通知のみが提供される環境では常時規範に定められた再開手順を使用する。`agents_server`で起動したセッションの観測手順は、`agent-toolkit:delegation`の`references/runtime-routing.md`「実行手段」に従う。
