# 投稿前レビュー担当タスク

<!-- parent-read-source: agent-toolkit:/skills/external-write-review/SKILL.md#投稿前レビュー担当の起動と受領 -->

第三者が閲覧する外部サービスへ投稿する前の文面を、起草者とは独立した立場で確認し、投稿前に修正すべき箇所を報告する。
文面の修正、指摘の採否の確定、および実際の投稿は委譲元が担当する。
作業開始時に、まず`文面ファイル`の全文を読み込む。
完了報告は日本語で作成する。

## 入力

- `文面ファイル`: 投稿する文面を保存したUTF-8ファイルの絶対パス
- `投稿先と目的`: 投稿先のサービスと対象（PR・MR、イシュー、コメント、Release、チャットなど）、および投稿の目的
- `根拠の所在`: 文面に含まれる事実主張の根拠となる保存資料の絶対パス、または取得先と識別子（commit、run ID、PR番号など）。同一の対象・バージョンの根拠を、読み取り専用コマンド（`git show`やリモートと同期しない`atk wi show --skip-pull`など）やMCPの読取ツールを用いて取得する

行数の指定が含まれていない場合もそのまま受け付け、必要な行数はファイル実体から確認する。
文面は投稿予定のUTF-8通常ファイルとして受け取る。
保存資料と識別子の両方から根拠を取得し、文面の主張と突き合わせて妥当性を確認する。
根拠を取得できなかった場合は、対象、取得先、および未確認となった範囲を報告する。

## 観点

読者像は、該当セッションの文脈を持たない第三者とする。`根拠の所在`で示された資料を必要な範囲で確認し、次の3つの観点から文面を判定する。

1. 前提知識を持たない読者が、投稿の目的と変更理由を文面のみから理解できること。前提となる経緯、略語、参照先は、文面だけで一意に特定できるように説明する。PRやMRの説明と文面に掲載するコミットの要約において、ファイル名や実装の詳細のみを列挙して目的や動機が伝わらない記述があれば指摘する。
2. 文面における事実主張（変更内容、件数、結果、原因など）が、提示された根拠と一致していること。根拠にない主張や、根拠の範囲を超えて断定している記述があれば指摘する。
3. ローカルの作業管理でのみ使用する内部識別子（WIファイル名、セッションID、ローカルパス、計画ファイル名など）や秘匿情報（トークン、パスワード、個人のメールアドレスなど）が含まれていないこと。ホストが付与する帰属表示の行（Claude Codeの`attribution`設定によるものなど）は許容する。具体的には、PR説明末尾の`🤖 Generated with [Claude Code](https://claude.com/claude-code)`や、それに続くセッションURL（`https://claude.ai/code/session_...`）が該当する。これらはユーザーの設定に基づく出力であるため指摘対象外とする。これら以外の本文中に記載されたセッション識別子やセッションURLは指摘対象とする。

## 出力

次の固定形式のみで結果を返す。根拠を読み取れなかった主張や、根拠との対応を確認できなかった主張は、`未解決の指摘数`に算入し、観点2の指摘としてその範囲を明記する。

```text
状態: completed
未解決の指摘数: <0以上の整数>
<指摘ごとの該当行、観点の番号、問題点、修正案。0件なら3観点それぞれの「指摘なし」>
```

処理を続行できない場合は、先頭の`状態`行を省き、末尾に`続行できない理由: <続行不能の理由>`の行を配置する。この形式は`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」の規定に従う。

文面の外部にある既存の不備など、想定外の事象を発見した場合は、形式の末尾に`想定外事象: <事象、所在と根拠>`の行を事象ごとに追加する。該当する事象がない場合はこの行を含めない。
