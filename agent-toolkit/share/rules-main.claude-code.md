# rules-main.claude-code.md: Claude Codeのメインエージェント向け規範

この文書はClaude Codeのメインエージェントに適用し、同時に配送する`rules-main.md`へホスト固有の差分を加える。

Claude Codeのホストが挿入する`Usage limit reached; a short grace allowance remains`で始まる注記は、利用上限の猶予通知として扱う。
この通知を受け取ったときは`agent-toolkit:user-confirmation-and-report`を起動し、同スキルが定める状況伝達・続行・再開の手順に沿って進める。
ホストが続行を許可している猶予期間中は残りの工程を進め、再開が禁止された場合は同スキルを通じてユーザーへ状況と必要な操作を伝える。終了判断における`wait`は実際の待機に、`blocked`は観測された技術的な不成立に対してそれぞれ用いる。

## ツールの入出力

- Windows版Claude CodeのBashツールは、引用符付きのheredocや単一引用符内であってもコマンド内の`\\`を`\`へ縮める。そのため、エスケープ表現を含むコードはWriteツールでmanaged-temp配下のファイルへ保存してから実行する。
- 途中報告、質問への回答、確認結果、判明した事実や原因、作業完了報告、振り返りの予告など、ユーザーへ届ける本文は`mcp__agent-toolkit__send_to_user`の`message`へ記述する。拡張思考は画面表示を確認できず、地の文はAPIによって要約へ置き換えられることがあるため、送達手段としては扱わない。確認質問には次節の`AskUserQuestion`を使用する。Function hooks moduleでの登録名は`send_to_user`である。遅延ツール一覧にのみ存在する場合は、ToolSearchへ`select:mcp__agent-toolkit__send_to_user`を渡して取得してから呼び出す。ツールが提供されていない環境では、ターンを終える応答の本文に直接伝える内容を書く。委譲先への入力や記録に「回答済み」と記載できるのは、この送達手段で伝えた回答に限る。

## 自身の会話の記録

- 自身の会話におけるセッションIDとtranscriptの絶対パスには、SessionStartの通知に含まれる「この会話のセッションID」「この会話のtranscript」の値を使用する。会話圧縮、再開、clear、forkを行った後は、新しく届いた値を使用する。別の会話の記録との取り違えを防ぐため、記録の更新時刻順、cwdから推測した名前、MCPの`root_session_id`、委譲先のsession識別子などで代用しない。
- 通知から取得できないと示された値は、BashやPowerShellの環境変数`CLAUDE_CODE_SESSION_ID`から取得する。あるいは特定済みのIDを`atk run-script session-review-evidence -- --claude-session-id <ID>`へ渡して記録を解決する。
- 委譲先へ自身の会話を証拠として渡す際はこの値を使用する。過去の会話や委譲先の記録は、対象として指定された識別子を用いて取得する。

## ユーザー確認（`AskUserQuestion`）

- `AskUserQuestion`を実行する際は、共通読込表の確認資料を参照する（会話圧縮後は再取得する）。各質問に対して同スキルの「確認要否の判定」を適用し、確認が不要な質問は発行せず、自ら確定した案と根拠を発話本文で報告する。
  - 質問数と選択肢数はツールのスキーマに従う。自由記述の回答は各質問に対応し、一般的な返答は別の`response`に格納される。
  - ツール呼び出し前の地の文は要約される可能性があるため、判断材料や直前の回答に含まれる問いへの答えは、質問本文または`preview`の中に含めて提示する。
  - 推奨案は`(Recommended)`を付与した第1選択肢として配置する。`共通前提:`行や質問・選択肢の組み立て方は、同スキルの「確認の選択肢を組む手順」に従う。
- 質問や承認待ちの状態でターンを終えるときは、地の文で問いを記載した場合も含め、回答待ちの登録として`AskUserQuestion`を使用する。

## ターンの終え方

最終本文も準備印によらず日本語で確認し、進捗率は共通の30分点検に限る。

- 空応答はホストに再生成を求められる。待機だけで伝える内容がない場合と、`send_to_user`で本文を送達し残工程を終えて通常ターンを閉じる場合は`…`のみを返す。送達ツールがなければ本文自体を最終応答にする。
- `/goal`が設定されているセッションでは、自身が起動した未完了のAgentタスクやBashバックグラウンドタスクが存在しない状態でターンを終えると目標評価が開始され、これらのタスクが実行中である間は目標評価が延期される。背景実行へ移行したMCPの呼び出しは、この延期条件には含まれない。技術的に進められる工程は同じターン内で進める。
  未完了タスクの実行中に行う出力読み取りは進捗確認であり、完了後の結果とは区別して扱う。独立して進められる工程が完了したらタスクの完了通知を待ち、通知を受領した後に改めて出力を全量確認する。待機の起動と結果回収は、goalの有無や対象にかかわらず`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`「待機区間の構成」に従う。
  完了通知が未配送のまま残っている場合は、通知後の同一セッション再開が保証され、他のStop遮断要因がなければホストの通知配送による次ターンへ進み、通知後に保存出力と終了状態を受け取る。保証されない非対話起動は`rules-main.md`「ユーザー向け発話ルール」の待機の項に従う。他の遮断要因が残っている場合に限り、その理由と結果受領に関する警告に従う。
- モードにかかわらず計画ファイルは直接作成し、Plan modeの承認待ちへの移行はユーザーの操作に委ねる。ユーザーがPlan modeへ切り替えた場合は、ホストの制約に従って進める。
