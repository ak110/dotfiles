# rules-main.claude-code.md: Claude Codeのメインエージェントだけに適用する規範

本文書はClaude Codeのメインエージェントだけに適用し、`01-agent.md`及び`02-agent-operations.md`と同じ拘束力を持つ。

## ツールAPIと権限

- Claude Codeは、ツール呼び出しを含まずに地の文も持たない応答を可視出力の欠落として扱い、応答の再生成を要求する。
  `agent-toolkit:delegation`の`references/waiting-and-monitoring.md`が定める待機表明の回など、
  ツール呼び出しを含まずに終え、かつ地の文で伝える内容が無い回だけ、記号1文字（`…`）だけを出力してその要求を満たす。
  同じ応答でツール呼び出しを発行する回は要求の対象外であり、地の文を持たないまま終えてよい。
  この記号を書くのは前述の待機表明の回に限り、ツール呼び出しを伴う回と地の文を書く回はそのまま返す。ツール呼び出しを伴う回へこの記号を付けると、
  ユーザーが読む内容を持たない出力が作業の全ターンへ積み上がる。
  待機だけの回へ地の文で伝える内容を用意しないことは`agent-toolkit/share/rules-main.md`「ユーザー向け発話ルール」が定める。
- `AskUserQuestion`の1回の呼び出しは`questions`を1件以上4件以下、各質問の`options`を2件以上4件以下とする。
  選択肢は2件以上を組む。
  ユーザーが選択肢を選ばずに記述した回答は、選択肢の`label`ではなく記述本文として返る。
  質問ごとの自由記述はその質問の回答へ記述本文が入る。
  質問へ答えず一般の返答をした場合は`response`欄へ別に入る。
- `AskUserQuestion`の呼び出しでは、ターン途中の地の文も直前の地の文もハーネスが要約へ置換することがある。
  置換の有無は実行中のモデルと版に依存するため、置換されない位置は実行前に不明のまま残る。
  判断材料は`question`本文または`options`の`preview`欄へ自己完結で含め、地の文をその置き場所から外す。
- ユーザーへの質問・承認待ちでターンを終える場合は必ず`AskUserQuestion`を使う（地の文の問いかけはターンの終端を回答待ちとして実行環境へ通知せず、回答を得ないまま工程が終わるため）。
- `/goal`が設定されたセッションでは、ターンを終えた時点でそのセッション自身が起動した
  未完了のAgent系タスク又はBash背景ジョブが1件も無い場合に目標評価が発動し、その分のトークンを消費する。
  発動はターンを終えた理由によらず起きる。判定の入力はそのセッションが起動したタスクに限り、
  別のセッションが起動したタスクは判定の外にある。
  MCPツールの背景移行はこの延期の対象へ入らないため、その移行だけで待つ場合は評価が発動する。
  技術的に実行できる工程は同じターンで実行してから結果を報告する。
- 自律実行中は計画立案モードへ遷移せず、計画ファイルを直接作成する。
  同モードの終了時にはユーザーの承認要求が発生するが、自律実行では応答を得られず工程が止まる。
  協調実行では同モードを使ってよい。
  自律実行で同モードへ入ると、進行が承認待ちで停止し、依頼された工程が完了しない。
