# 実行レビュー担当の起動とレビュー修正

```text
起動対象: exec-review.subagent.md
```

メインが実装後のHEADを実行レビュー担当へレビューさせ、指摘への修正と履歴統合を管理する際に本書へ従う。
実行レビュー担当自身の手順は`${CLAUDE_PLUGIN_ROOT}/share/exec-review.subagent.md`を正本とする。
本書は起動、入力生成、レビュー修正及び指摘管理表の保存だけを定め、レビュー分類と判定手順を再定義しない。

## 起動経路別のレビュー基準

レビュー基準は`計画`、`CI記録`、`WI`のうち1つ以上を同時に渡す集合値とする。起動経路ごとの値は次のとおりとする。

| 起動経路 | レビュー基準 |
| --- | --- |
| `agent-toolkit:process-wi`のレーン | `計画,WI` |
| `agent-toolkit:plan-mode`の直接起動 | 計画の`関連WI`が`なし`の場合は`計画`、それ以外は`計画,WI` |
| `agent-toolkit:fast-process-wi` | 計画対象がある処理回は`計画,WI`、無い処理回は`WI` |
| 公開工程のCI失敗修正 | 原因commitに計画契約がある場合は`計画`、無い場合は`CI記録` |

`計画`と`WI`を併せて渡す経路では、計画の`## 実施内容`が挙げるWIを実行レビュー担当が自ら取得するため、当該WIの記録を起動文へ転記しない。
計画へ現れないWI（`agent-toolkit:fast-process-wi`の直接実装対象など）がある場合だけ、当該WIの記録を起動文へ渡す。

## 指摘管理表の準備

初回の実行レビュー担当を起動する直前に、本書がレビュー基準に対応する指摘管理表を準備する。1件の実行レビューは単一の表を使う。保存先は次のとおりとする。

- `計画`を含む場合: 計画ファイルと同じディレクトリの`<計画stem>.exec-review.tsv`
- `WI`だけの場合: `~/.claude/plans/fastwi-<処理開始時点の7文字以上の一意な短縮OID>.exec-review.tsv`
- `CI記録`だけの場合: `~/.claude/plans/ci-<起点commitの7文字以上の一意な短縮OID>.exec-review.tsv`

対応する表が存在しない場合は`atk review-table init <指摘管理表の絶対パス>`を単独実行し、成功の報告と警告の不在を確認する。既存の表がある場合は同じ表を再利用する。同じレビュー担当threadの再レビューでは表を準備し直さない。

## `review_contract`の生成

メインは実装完了と検証結果を受領した後、初回の実行レビュー担当を起動する直前に`review_contract`を生成する。
実行レビュー担当は、初回起動と引き継ぎ再レビューのいずれも`agents_server`の`start`で起動する。
`subagent_md_path`には`${CLAUDE_PLUGIN_ROOT}/share/exec-review.subagent.md`を解決した絶対パスを渡す。
`extra_params`には受信者文書が要求する名前付き入力、`cwd`には対象worktreeの絶対パスを渡す。
生成元は受領するレビュー基準ごとに次のとおりとし、複数の基準を渡す場合は全ての生成元から条項を独立に生成する。

- `計画`: 計画ファイルの`## 概要`、`## 実施内容`、`## 要件・外部仕様`、`## 恒久化・リファクタリング`及び`## 変更履歴`と、開始時点の7文字以上の一意な短縮OIDで特定した実体
- `CI記録`: 起動文へ直接記載するCI記録と、原因commitの親を開始時点の7文字以上の一意な短縮OIDとして特定した実体。CI記録には原因分析結果、修正認可根拠、対象の検証結果、変更目的、対象、公開契約、入力計画を含める。入力計画は変更の由来を示す資料とし、原因commitの計画照合基準にしない
- `WI`: 対象WIの要求、完成条件、要求単位の由来及び確定した採否と、処理開始時点の7文字以上の一意な短縮OIDで特定した実体。`計画`を併せて渡す場合は、計画の`## 実施内容`が挙げるWIを実行レビュー担当が取得した本文を生成元とする

初回の実行レビュー担当を起動する起動文では、既定値の`レビュー種別: 初回レビュー`と`round: 1`を省略する。再レビューを指示する文と引き継ぎ再レビューの起動文には、`round: <ラウンド番号>`の行を含める。ラウンド番号は`${CLAUDE_PLUGIN_ROOT}/share/review-loop-coordination.md`の`## ラウンド番号の正本`が定める値とする。

`review_contract`は、ユーザー目的、現行の公開契約、ユーザー合意、認可の範囲、除外・保持、通常入力、対象外入力、誤許可と誤拒否の消費主体への影響を、独立して成否を判定できる条項ごとに分ける。
同じ累積差分に現在とは別のレビュー基準で認可されたcommitが含まれる場合は、その7文字以上の一意な短縮OID、レビュー基準、認可根拠となる計画・WI・CI記録、認可された対象範囲を独立条項として含める。根拠資料から認可済みと確認した対象範囲だけを現在の基準による重複した認可判定の対象外とし、commitの存在自体を認可根拠にしない。対象外とした変更も、共有する公開契約と安全性、現在の基準が要求する統合結果へは照合する。
各条項は次の形式で起動プロンプトへ直接記載する。

```text
review_contract:
  - 条項: <対象と判定内容>
    内容: <契約本文、又は参照先>
    出典: <計画ファイルの絶対パスと見出し・表の行、開始時点の7文字以上の一意な短縮OIDとリポジトリ相対パス及び識別子、又は明示入力の出所>
```

計画ファイルの記述だけで条項の内容が一意に定まる場合は、`内容`を`参照: <計画ファイルの絶対パス>#<見出し又は表の行>`として渡せる。
参照先を追加で解釈しなければ判定内容が定まらない場合は、契約本文を`内容`へ記載する。
複数の条項を1件へ集約せず、前段が列挙する各観点と出典を欠かさない。別のレビュー基準で認可されたcommitが無い場合は、当該条項を追加しない。
`review_contract`はいずれの永続ファイルにも追記せず、初回起動後は同じ実行レビュー担当のthreadへ保持する。
当該threadが継続不能と確定した場合は、初回起動時と同じ生成元から`review_contract`を再生成して新しい実行レビュー担当へ渡す。
あわせて、`レビュー種別: 引き継ぎ再レビュー`、直前修正の直接影響範囲及び`${CLAUDE_PLUGIN_ROOT}/share/exec-review.subagent.md`の`## 入力`が要求する次の項目だけを渡す。

- `計画`では計画ファイルの絶対パス。`CI記録`では起動文へ直接記載する7項目のCI記録。再帰的CI失敗では7項目を今回の原因commitへ更新する。`WI`では、計画へ現れないWIについてファイル名、要求、完成条件、由来、採否の5項目のWI記録

任意入力の`対象ファイル限定`を用いる場合は、当該対象も渡す。
対象リポジトリ、対象worktree、規範、開始時点の7文字以上の一意な短縮OID、レビュー対象HEAD、変更ファイル一覧、検証結果及びレビュー指摘管理表は、実行レビュー担当が計画、Git状態及び同stemの成果物から解決する。CI記録はメインが原因commitの生成時に保持した情報から起動文へ直接記載する。
継続不能の判定と引き継ぎ手順は`agent-toolkit:delegation`の経路選択契約に従う。

実行レビュー担当を起動する前に、`${CLAUDE_PLUGIN_ROOT}/share/exec-review.subagent.md`の`## 入力`がレビュー基準ごとに列挙する必須入力が起動文にそろっていることを確認する。確認は渡す全てのレビュー基準について行う。`計画`では計画ファイルの実在を確認する。`CI記録`ではCI記録の7項目が全て値を持つことを確認する。`WI`では、`計画`を併せて渡す場合は計画へ現れないWIの有無を確認し、渡すWI記録がある場合だけ5項目が全て値を持つことを確認する。`計画`を渡さない場合はWI記録の5項目が全て値を持つことを確認する。生成した`review_contract`が前段の各観点と出典を欠かさず、絶対パスで示す入力が実在することも同じ時点で確認する。いずれかが欠ける場合は実行レビュー担当を起動せず、欠けていた入力項目又は条項を呼び出し元へ返す。

## レビュー修正

実行レビューは`レビュー基準`が指す全ての記録へ照合した後、同じコンテキストで`review_contract`へ照合する。
公開契約基準に用いる開始時点の7文字以上の一意な短縮OIDは、`計画`を含む場合は実装着手前のworktree、`CI記録`だけの場合は原因commitの親、`WI`だけの場合は処理開始時点とする。
初回の新規起動ではレビュー基準、生成済みの`review_contract`と`引き継ぎ記録先`を`extra_params`へ追加する。
開始時点の7文字以上の一意な短縮OIDは実行レビュー担当が計画か入力記録から取得し、差分を取得する直前に対象リポジトリでcommitへ解決する。記憶又は推測でOIDを組み立てない。

指摘への修正は、当該worktreeを所有する主体が実施する。`agent-toolkit:process-wi`のレーンではレーン担当の同じthreadへ`レビュー指摘の対応をせよ`と`round: <ラウンド番号>`の2行を送り、新しい修正担当を起動しない。`agent-toolkit:plan-mode`の直接起動と`agent-toolkit:fast-process-wi`では、メインが自ら修正する。公開工程のCI失敗修正では終端担当が主作業ツリーで修正する。
同じthreadを継続できない場合は`agent-toolkit:delegation`の経路選択契約に従い、`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`の`## 入力`と同じ形式で新しいレーン担当を起動する。このとき`担当種別`を`レビュー修正担当`とし、`再開位置`へ作業rootの計画ファイルの絶対パスを渡す。
修正する主体はレビュー表とworktreeの実体から指摘の採否、対象の実装commit及び修正方針を確定する。採否の基準、履歴統合、履歴書換え証拠の保存と回復は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`「レビュー修正の履歴統合」、履歴書換えの遮断は`agent-toolkit:commit`の履歴書換え契約を正本とする。
メインがレビュー指摘管理表を読むラウンドは`${CLAUDE_PLUGIN_ROOT}/share/review-loop-coordination.md`の「ラウンドの遷移」が定める範囲に限る。メインは指摘の採否と実装commitへの対応付けを確定せず、成果物、Git状態、検証結果のいずれも再検収しない。
修正する主体が`対応完了`を返した場合は同じレビューthreadへ`再レビューせよ`と`round: <ラウンド番号>`の2行を送り、`対応完了（再レビュー不要）`の場合はレビューを省略する。

## 指摘管理表の保存

`WI`だけのレビュー基準では、収束後に指摘管理表を削除し、private-notesへ保存しない。当該表を後から参照する主体が無く、計画バンドルの付属ファイルにも当たらないためである。
`CI記録`だけのレビュー基準では、同じ再帰的CI失敗処理で表と起点OIDを継続する。収束後に`atk plans commit ci-<起点commitの7文字以上の一意な短縮OID>.exec-review.tsv`で`private-notes/plans/ci/`へ保存する。`agent-toolkit:process-wi`の公開工程では、この保存操作を終端担当が実行する。
`計画`を含むレビュー基準では、計画を所有する主体が`agent-toolkit:plan-mode`の計画ファイル基準「計画ファイルの保存と参照」に従って計画バンドルとともに保存する。
