# プロンプト評価担当の起動と受領

```text
起動対象: refine-prompt.subagent.md
```

`agent-toolkit:refine-prompt`を実行するエージェントが、本書に従ってプロンプト評価担当を起動し、指摘を受領する。
プロンプト評価担当の手順と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/refine-prompt.subagent.md`が定める。

## 起動

評価する指示文をUTF-8のファイルへ保存してから、`agent-toolkit:refine-prompt`のワークフローが決めた体数のプロンプト評価担当を起動する。複数体を起動する場合は、観点の多様性を得るため同じ入力で並行して起動する。

`agents_server`の`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 対象プロンプトを保持するリポジトリの絶対パス |
| `subagent_md_path` | `refine-prompt` |
| `extra_params` | 次の名前付き入力だけ |

- `対象プロンプト`: 対象プロンプトの名前と、本文を保存したファイルの絶対パス
- `シナリオ`: ワークフローで決めた状況設定の1段落。シナリオを与えない場合は`なし`
- `引き継ぎ記録先`: 省略と継続の扱いは`agent-toolkit:delegation`の`references/base-contract.md`「引き継ぎ記録先」に従う

再評価では前回のプロンプト評価担当を継続せず新しいプロンプト評価担当を起動する。前回の指摘と反映を知る担当は評価が偏るためである。シナリオは初回に決めた内容のまま渡し、反映に合わせて容易にしない。実際には残る不明瞭な点を解消済みと判定することになるためである。

## 受領

結果は引数なしの`atk agents wait`で受け取り、起動した全sessionの終端を確認する。
返却が`refine-prompt.subagent.md`の`## 出力`の形式に合い、各指摘が重要度、該当箇所、問題内容、想定される悪影響および種別を持つことを確かめる。形式に合わない返却は、同じ入力で1回だけ新しいプロンプト評価担当を起動し直す。
指摘の統廃合、取捨選択と改善案の作成は`agent-toolkit:refine-prompt`「指摘の集約と改善案作成」に従う。
