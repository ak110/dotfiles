# rules-subagent.md: サブエージェントと委譲先だけに適用する規範

本書はサブエージェントと委譲先に適用する。`agent-toolkit/rules/`の常時規範（`01-agent.md`、`02-agent-operations.md`）が届く起動形態では、共通の判断と実行上の規律はそれらに従う。

## 確認事項の即時通知

ユーザーの確認または事後承認を要する判断は委譲元へ渡す。必要な調査が終わった時点で、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」の確認提示項目を通知する。回答に依存しない作業は続ける。質問ツールを持つホストでも、確認は委譲元へ送る。

本節の通知と想定外事象の通知を即時通知と呼ぶ。即時通知は次の順に判定し、最初に成立した手段だけで1通送る。

1. 環境変数`AGENT_TOOLKIT_OWNER_SESSION`を保持する場合は、本文を`atk agents notify`の`--body`か`--body-file`の一方で渡す。本文がシェルメタ文字（単一引用符、逆引用符、ドル記号、改行など）を含む場合は絶対パスのUTF-8ファイルへ保存して`--body-file`で渡す。この環境変数は設定の有無だけを確かめ、値をコマンド出力、報告および成果物へ記録しない
2. 前項の環境変数を保持せず、到達可能な機械可読返信識別子を保持し、`SendMessage`が公開され呼び出しに成功する場合は、保持した識別子へ送る。Claude Code固有の宛先はホスト別規範が定める
3. いずれも成立しない場合と`atk agents notify`が非0で終了した場合は、同じ事象を通常の完了報告へ含める。受け取った側は完了通知とともに逐語で中継する

`agents_server`の委譲先は`SendMessage`を完了報告の送信に使わず、通常の完了報告を起動時の返却値へ返す。即時通知と完了報告の`想定外事象:`および`続行できない理由:`の行には事象、起動手段またはコマンド、エラー原文、影響範囲、直接的原因が確定済みか未確定か、対象ホストまたはパスを含める。1行へ収められない場合は、全項目を記録した成果物の絶対パスをその行へ示す。受け取った主体が追加の照会をせずに、その事象の判断とAWIの起草を確定できる粒度とする。

## 返却形式の受け渡し

完了報告への追加記載を求める規定の適用範囲は`agent-toolkit:delegation`の`references/receiving.md`「返却形式の適合確認」の返却形式の証跡範囲に従う。
委譲先が続行できないことは、`続行できない理由:`の行だけで表す。
返却全体か、返却形式が定める単位（要求、行など）が続行できない場合は、その単位に`続行できない理由: <続行不能となる事象、その原因となる条件および再開に必要な判断>`の行を置き、同じ単位の状態や結果の行（`状態:`、`結果:`、`判定:`など）は置かない。
全体の状態と単位ごとの結果の両方を持つ形式では、全ての単位が成功の値を持つときだけ全体の`状態:`行を置き、1つでも`続行できない理由:`を持つ単位があれば全体の`状態:`行を置かない。
成功の値が1つだけの状態行も、成功の返却と形式の欠けた返却を区別するため返却形式に残す。
受け取る側は、`続行できない理由:`の行の有無で続行不能を判定する。

続行不能時の返却形式は、委譲先の`<役割名>.subagent.md`、agent定義、委譲プロンプトの順で定めのある形式を用いる。
いずれにも定めが無い場合は、次の1行だけからなる形式を用いる。

```text
続行できない理由: <続行不能となる事象、その原因となる条件および再開に必要な判断>
```

この行は指定された返却形式そのものとして扱い、地の文の禁止の対象から外す。
想定外の結果は後述の`想定外事象:`の手段で返す。

- `想定外事象: <事象と対処>`または`気付いた改善点: <観測した事象と対象>`で始まる行を受け取った主体は、
  全ての該当行を自身の返却の末尾へ同じ形式の行として逐語で引き継ぐ。さらに委譲した担当から受け取った行にも適用し、
  役割・ホスト・段数・終了状態によらず上流へ渡す。指定形式の他の行（`状態:`など）と、それらの行に基づいて受け取った主体が選ぶ次の工程は、標識行の有無によらず同じまま保つ
- 行を省略できる項目を定める取り決めは、項目の省略時の値と、行の不在を省略時の値として解釈することを同じ本文へ書く。この記述を持つ取り決めに従って返却または委譲プロンプトを受け取った主体は、行の不在を省略時の値として扱う。省略時の値の記述が無いまま行を省略すると、受け取る側が欠落と誤認して再取得を指示し、その工程が停止する

## 委譲時の厳守事項

委譲の起動と終端観測は`agent-toolkit:delegation`の`references/runtime-routing.md`「実行手段」で起動前に対にして選ぶ。同じ役割の書込作業は自身で完遂し、独立した確認だけを同スキルの`references/routing.md`に従う読み取り専用の子探索へ分けられる。対象集合と検収の責任、中止・変更・再開の受領内容を保持する。自分が起動していない主体は待たず、必要な依頼を委譲元へ返す。

`AGENTS.md`、`CLAUDE.md`、`.claude/rules/`、`agent-toolkit/`のエージェント向け文書は、委譲プロンプトか追送で名指しされたファイルだけを編集する。新規作成先と移動先も名指しの対象に含める。委譲範囲を超えるpush、削除、投入先を自ら選ぶWI投入は実行せず、対象と必要な判断を返す。担当外の差分を保持し、自分の担当ファイルだけを変える。別主体の差分が自分の契約に影響するかは実差分で判定する。

入力不足は基準の定義から一意に観測できる値だけを補って記録し、未確定値と職務外の判断は委譲元へ返す。想定外は期待・実際・条件・原因を調べ、成立する工程を続ける。判断を要する事象は即時通知し、自ら是正した事象は`想定外事象:`へ集約する。通知契約は「確認事項の即時通知」に従う。

### 作業ツリーと認証情報の扱い

- 委譲元と委譲先は、Git作業ツリー外に実体があるユーザーの認証情報ファイルを元の場所に置いたまま扱う。
  認証を要する操作では通常の認証解決手順を維持し、その手順で成立しない場合は委譲元へ差し戻す。
  認証情報の複製、移動および別領域への保存は、委譲の信頼境界を越え、異常終了時に複製物を残し得る。
  Claude Codeの組み込み`Read`に対する拒否設定はBash経由の複製を遮断しないため、この扱いは実行主体自身の判断で守る。
  ホーム配下の認証情報ファイル（`~/.aws/credentials`など）の複製・移動・別領域への保存は禁止する
- 作業ツリー内のファイルはGit追跡やgitignore、ファイル名、拡張子によらず通常の読取・編集・複製・比較・出力で扱う。
  外部の認証情報を参照する場合は実体の位置で内外を判定する。
  同一リポジトリのworktreeの環境準備では、Git管理外の実行前提ファイル（`.env`等）を同じ相対パスへ複製する。
  複製先が複製元と同じリポジトリに属することは`git -C <複製先> worktree list`等で確認する。
  worktree作成時に`.worktreeinclude`（gitignore構文。パターンに一致し、かつgitignore対象のファイルだけを
  複製する）を処理する実行環境で、複製元に`.worktreeinclude`が存在する場合は作成時の自動複製を活用する。
  作成済みのworktreeへはシェルの`cp`で複製する
- 実装担当は同じ作業ツリーの書込所有権を手放す終端報告の前に、自身が起動した全ての外部プロセスと
  バックグラウンドタスクの終了を、ツール終了結果または保持した実行識別子の直接照会で確認する。
  前景ツールの終了後も存続し得る形で起動したプロセスは、返却形式がその情報の項目を定める場合だけ、実行識別子と終了確認結果を終端報告へ含める。
  項目の定めが無い場合は、終了確認を完了条件として扱い、終端報告を指定形式のまま返す。
  本項の対象は実装担当とし、読み取り専用の委譲は対象から外す。
  終了していないプロセスの所有主体を失うと、後続の実装担当が安全に停止できず、1つの作業ツリーへ複数の書込主体が並存し得る

### 手順どおりに進められない場合の返却

規範・手順の衝突は事象と登録に必要な情報を返し、登録先の判断を委譲元へ委ねる。

### 多段工程の引き継ぎ記録

`引き継ぎ記録先`を受け取った多段工程は`agent-toolkit:delegation`の`references/handoff-record.md`を使う。キュー操作の反映抑止は`agent-toolkit:wi-standards`の`references/subagent-queue-ops.md`に従う。

## 返却と終端

工程境界と完了では、受領した`<役割名>.subagent.md`の返却形式を保ち、観測した結果を次の条件で返す。

- 指定欄に収まらない証拠は成果物へ記録する
- 想定外の事象は必要な情報を備えた`想定外事象:`一行を形式の末尾へ加える
- 作業中に目的に比べて不自然・非効率・反復的な作業に気付いた場合は、`想定外事象:`の行と同じく返却形式の末尾へ`気付いた改善点:`で始まる1行を加えて作業を続ける
- 引き継ぎ記録でその返却までに終えるとした各工程を、完了または返却内の`続行できない理由:`・`想定外事象:`などへ対応付けてから返す。後掲の`待機中:`による一時終了は除く。会話圧縮後は現行記録を読み直す
- 完了報告と中継では、自ら観測した範囲だけを事実として言い切る。他主体の報告と推論には出所・未確認範囲を添え、母集団・数えた層・未検証範囲などの限定を保つ。自身の報告でも孫の報告の中継でも、別の層の主張へ言い換えない
- 実行したコマンドと起動した主体の終了状態を観測してから返す。`待機中: <実行識別子>`で一度ターンを終える例外は、待っている対象の完了通知が同じsessionを再開すると実行環境が`share/agents-server-auto-resume.md`などで伝えた場合だけ適用する。Codexの`functions.exec`のcell IDと`exec_command`のsession IDはこの例外へ含めず、公開されている`functions.wait`と`write_stdin`でそれぞれ同じターンに出力と終了状態を回収する
