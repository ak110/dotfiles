# rules-subagent.md: サブエージェントと委譲先だけに適用する規範

本書はサブエージェントと委譲先に適用する。共通の判断と実行上の規律は`01-agent.md`、`02-agent-operations.md`に従う。

## 確認事項の即時通知

ユーザーの確認または事後承認を要する判断は委譲元へ渡す。必要な調査が終わった時点で、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」の確認提示項目を通知する。権限設定やauto mode classifierが操作を拒否した場合も、拒否本文、取得できた分類名、拒否された操作と対象を委譲元へ速やかに渡す。別の手段で作業が進んでも拒否の情報を保持して通知し、下位委譲先から受け取った拒否も同じ内容を上位へ渡す。拒否後の確認判断は同スキルの`references/permission-denial.md`に従う。回答に依存しない作業は続ける。質問ツールを持つホストでも、確認は委譲元へ送る。

本節の通知と想定外事象の通知を即時通知と呼ぶ。即時通知は次の順に判定し、最初に成立した手段だけで1通送る。

1. 環境変数`AGENT_TOOLKIT_OWNER_SESSION`を保持する場合は、本文を`atk agents notify`の`--body`か`--body-file`の一方で渡す。本文がシェルメタ文字（単一引用符、逆引用符、ドル記号、改行など）を含む場合は絶対パスのUTF-8ファイルへ保存して`--body-file`で渡す。この環境変数は設定の有無だけを確かめ、値をコマンド出力、報告および成果物へ記録しない
2. 前項の環境変数を保持せず、到達可能な機械可読返信識別子を保持し、`SendMessage`が公開され呼び出しに成功する場合は、保持した識別子へ送る。Claude Code固有の宛先はホスト別規範が定める
3. いずれも成立しない場合と`atk agents notify`が非0で終了した場合は、同じ事象を通常の完了報告へ含める。受け取った側は完了通知とともに逐語で中継する

`agents_server`の委譲先は`SendMessage`を完了報告の送信に使わず、通常の完了報告を起動時の返却値へ返す。即時通知と完了報告の`想定外事象:`および`続行できない理由:`の行には、事象、起動手段またはコマンド、エラー原文、影響範囲、直接的原因が確定済みか未確定か、対象ホストまたはパスを含める。1行へ収められない場合は、全項目を記録した成果物の絶対パスをその行へ示す。受け取った主体が追加の照会をせずに、その事象の判断とAWIの起草を確定できる粒度とする。

## 大量出力コマンドの分離実行

大量出力の分離、検索、引用、パス、CLI形式と終了状態は`02-agent-operations.md`が定める。利用できる分離手段がないときはmanaged-tempへ全量を保存して必要な範囲を読む。

## 委譲時の厳守事項

委譲手段と終端の観測手段を起動前に組にする。等しい機能と権限があれば`agents_server`を選ぶ。自分と同じ役割の書込作業は自身で完遂する。同じ担当内の独立した確認は`agent-toolkit:delegation`の`references/routing.md`に従って読み取り専用の子探索へ分けられるが、対象集合と検収の責任は保持する。受け取った中止、変更、再開の指示は受領内容のまま維持する。自分が起動していない主体の完了は待たず、必要な依頼を委譲元へ返す。

`AGENTS.md`、`CLAUDE.md`、`.claude/rules/`、`agent-toolkit/`のエージェント向け文書は、委譲プロンプトか追送で名指しされたファイルだけを編集する。新規作成先と移動先も名指しの対象に含める。委譲範囲を超えるpush、削除、投入先を自ら選ぶWI投入は実行せず、対象と必要な判断を返す。担当外の差分を保持し、自分の担当ファイルだけを変える。別主体の差分が自分の契約に影響するかは実差分で判定する。

入力が欠けたときは、基準となる定義から観測して一意に得られる値を補って記録する。観測で一意に得られない値や職務外の判断は委譲元へ返す。想定外の結果は期待値、実際値、条件、原因を調べて技術的に成立する工程を続ける。委譲元の判断が必要な事象は直ちに通知し、自分で是正した事象は`想定外事象:`へ集約する。通知手順と本文は「確認事項の即時通知」に従う。

### 手順どおりに進められない場合の返却

規範や手順の衝突は、事象と登録に必要な情報を委譲元へ返す。登録先の判断は委譲元が担う。

### 多段工程の引き継ぎ記録

`引き継ぎ記録先`を受け取った多段工程は`agent-toolkit:delegation`の`references/handoff-record.md`を使う。キュー操作の反映抑止は`agent-toolkit:wi-standards`の`references/subagent-queue-ops.md`に従う。

## 返却と終端

作業の結果は、都合の悪い結果も含めて委譲元へ正直に報告する。工程境界と完了では、受領した`<役割名>.subagent.md`の返却形式だけを用いる。指定欄に収まらない証拠は成果物へ記録する。想定外の事象は必要な情報を備えた`想定外事象:`一行を形式の末尾へ加える。作業中に目的に比べて不自然・非効率・反復的な作業に気付いた場合は、`想定外事象:`の行と同じく返却形式の末尾へ`気付いた改善点:`で始まる1行を加えて作業を続ける。実行したコマンドと起動した主体の終了状態を観測してから返す。`待機中: <実行識別子>`で一度ターンを終える例外は、実行環境が`share/agents-server-auto-resume.md`などで同じsessionの自動再開を伝えた場合だけ適用する。形式が変わると委譲元が返却値を判定できない。
