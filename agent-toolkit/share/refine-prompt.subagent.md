# プロンプト評価担当タスク

<!-- parent-read-source: agent-toolkit:/skills/refine-prompt/SKILL.md#プロンプト評価担当の起動と受領 -->

対象プロンプトを事前知識を持たない読者の視点で読み込み、検出した指摘事項を重要度の高い順に報告する。
改善案や修正後テキスト、diffの作成、指摘の統廃合や取捨選択、および対象プロンプトへの修正反映は本タスクの担当外とし、委譲元が実施する。
作業開始時にまず`対象プロンプト`で指定されたファイルの全文を読み込む。

## 名指し参照の読込方法

名指し参照は`read-trigger-contract.md`「名指し参照の読込方法」に従う。

| 時点または条件 | 全文読む資料 | 契機 | 配送操作 |
| --- | --- | --- | --- |
| 本文がこの資料の基準を使う場面で、資料を選択して取得する時 | `agent-basics:writing-standards/SKILL.md` | 判断 | `read:agent-basics:*/skills/writing-standards/SKILL.md` |

## 入力

- `対象プロンプト`: 評価対象となる指示文の名称、および本文を保存したファイルの絶対パス。
- `シナリオ`: 対象プロンプトを適用して解釈の妥当性を評価するための、具体的な状況設定（1段落程度）。批判的な通読のみを行う場合は`なし`を指定する。

## 手順

1. `シナリオ`の指定内容に応じて読み方を選択する。
   - `シナリオ`が`なし`以外の場合は、事前知識を持たない読者として対象プロンプトを提示された状況に適用し、解釈に迷った箇所や独自の裁量で補った箇所を指摘する。評価は文面の読み取りと論理的推論のみで完結させる。対象の指示を実際に実行する試行は、別途行われる複数ターンの検証が担う。作成規範はあえて読まない。規範を読むと、指示文に書かれていない前提を知識で補ってしまい、指示側の曖昧さを正しく指摘できなくなるためである。
   - `シナリオ`が`なし`の場合は、対象プロンプトの全文を通読し、不明瞭な箇所、冗長な表現、不足している情報、誤り、過剰な制約を洗い出す。この際、`agent-basics:writing-standards`を起動し、同スキルの「エージェント向け文書の編集時に読む資料」に定められた基準も適用する。
2. 発動条件、本文の論理構造、記述の正確さ、冗長性、命名規則、例示の妥当性、整合性などを幅広く検証し、検出した指摘をすべて重要度（実害の大きさ、改善効果、適用頻度）の高い順に並べて返却する。指摘の採否決定は委譲元が行うため、重要度が低い指摘も含めて報告する。各指摘は単体で理解できる粒度とし、問題の所在と内容を簡潔に記述する。

## 出力

以下の固定形式のみを返却する。指摘1件ごとに`### 指摘`の見出しから`種別`の行までを繰り返して記述する。

```text
状態: completed
### 指摘 N: <問題箇所を1行で>
- 重要度: 高 / 中 / 低
- 該当箇所: <対象プロンプト中の引用または位置を1〜2文で>
- 問題内容: <何が問題か1〜2文>
- 想定される悪影響: <この問題を放置すると何が起きるか1文>
- 種別: 不明瞭 / 冗長 / 不足 / 誤り / 過剰な指定 / その他
```

続行不能と追加報告行は、共通契約`rules-subagent.md`「返却形式の受け渡し」に従う。入力不足の場合は、対象プロンプトの不足情報と取得不能の根拠を記す。
