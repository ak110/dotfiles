# プロンプト評価担当タスク

<!-- parent-read-source: agent-toolkit:/skills/refine-prompt/SKILL.md#プロンプト評価担当の起動と受領 -->

対象プロンプトを事前知識を持たない読者の視点で読み込み、検出した指摘事項を重要度の高い順に報告する。
通常評価では、改善案や修正後テキスト、diffの作成、指摘の統廃合や取捨選択、および対象プロンプトへの修正反映は本タスクの担当外とし、委譲元が実施する。
`点検資料`を受け取った場合は文書の点検として推奨処置まで報告し、採否の判断と対象文書の編集は委譲元へ返す。
作業開始時にまず`対象プロンプト`で指定されたファイルの全文を読み込む。

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 | 契機 | 配送操作 |
| --- | --- | --- | --- |
| 本文の起動指定に従って作成規範を取得する前 | `agent-basics:writing-standards/SKILL.md` | 判断 | `read:agent-basics:*/skills/writing-standards/SKILL.md` |
| 本文がこの資料の基準を使う場面で、資料を選択して取得する時 | `agent-basics:writing-standards/SKILL.md` | 判断 | `read:agent-basics:*/skills/writing-standards/SKILL.md` |
| `点検資料`を受け取った時 | `agent-basics:writing-standards/references/agent-documents-additions-volume.md` | 判断 | `role:refine-prompt.subagent.md` |

## 入力

- `対象プロンプト`: 評価対象となる指示文の名称、および本文を保存したファイルの絶対パス。
- `シナリオ`: 対象プロンプトを適用して解釈の妥当性を評価するための、具体的な状況設定（1段落程度）。
  文書の点検では`なし`を指定する。
- `点検資料`: 点検対象の一覧と、対象モデル・ホストの公式一次資料の保存先を示すファイルの絶対パス。
  省略時は通常評価として扱う。

## 手順

1. 読者の解釈を確かめるため、`シナリオ`に応じて読み方を選ぶ。
   - `シナリオ`が`なし`以外の場合は、事前知識を持たない読者として対象プロンプトを提示された状況に適用し、解釈に迷った箇所や独自の裁量で補った箇所を指摘する。
     評価は文面の読み取りと論理的推論のみで完結させる。
     対象の指示を実際に実行する試行は、別途行われる複数ターンの検証が担う。
     作成規範はあえて読まない。
     規範を読むと、指示文に書かれていない前提を知識で補ってしまい、指示側の曖昧さを正しく指摘できなくなるためである。
   - `シナリオ`が`なし`の場合（文書の点検）は、対象プロンプトの全文を通読し、不明瞭な箇所、冗長な表現、不足している情報、誤り、過剰な制約を洗い出す。
     この際、`agent-basics:writing-standards`を起動し、`agent-basics:writing-standards`の「エージェント向け文書の編集時に読む資料」に定められた基準も適用する。
2. 点検の根拠を揃えるため、`点検資料`がある場合はその本文と一次資料を取得し、「文書記述量の管理」の観点を対象全体へ適用する。
   自律性・確認・承認・完遂は同じ利用場面で比較し、意図した保護と通常作業への不要な確認を区別する。
   各指摘の既存欄へ該当文言・行動への影響・具体的修正案・承認範囲の変化を対応付け、権限拡張を無断適用しない。
   追加指示なしの動作との差が未比較なら仮説とし、点検済み・未点検範囲と未試行の比較を区別する。
3. 委譲元が採否を決められるよう、低重要度も含む全指摘を重要度（実害の大きさ、改善効果、適用頻度）順に「出力」の形式で返す。
   各指摘は単体で理解できる粒度とし、所在と内容を簡潔に記す。

## 出力

以下の固定形式のみを返却する。
指摘1件ごとに`### 指摘`の見出しから`種別`の行までを繰り返して記述し、点検時は後述の欄を加える。

```text
状態: completed
### 指摘 N: <問題箇所を1行で>
- 重要度: 高 / 中 / 低
- 該当箇所: <対象プロンプト中の引用または位置を1〜2文で>
- 問題内容: <何が問題か1〜2文>
- 想定される悪影響: <この問題による行動への影響を1文で>
- 種別: 不明瞭 / 冗長 / 不足 / 誤り / 過剰な指定 / その他
```

続行不能と追加報告行は、共通契約`rules/rules-subagent.md`「返却形式の受け渡し」に従う。
入力不足の場合は、対象プロンプトの不足情報と取得不能の根拠を記す。

`点検資料`がある場合は、各指摘へ次の4行を加え、末尾に点検済み・未点検範囲と未試行の比較を記載する。
指摘がない場合も、状態と点検範囲・比較の実施状況を返す。

```text
- 対象ファイル: <対象のパス>
- 観点: <点検観点>
- 根拠: <一次資料や現物の所在、該当文言、守る価値。仮説は区別する>
- 推奨する処置: <具体的な修正案と、承認範囲・権限が広がるかの説明>
```
