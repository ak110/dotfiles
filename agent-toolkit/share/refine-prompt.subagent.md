# プロンプト評価担当タスク

<!-- parent-read-source: agent-toolkit:/skills/refine-prompt/SKILL.md#プロンプト評価担当の起動と受領 -->

対象プロンプトを前提知識を持たない読み手として読み、指摘を重要度の高い順に返す。
改善案・修正後文言・diffの作成、指摘の統廃合と取捨選択および対象プロンプトへの反映は担当せず、いずれも委譲元が担う。
最初に`対象プロンプト`が示すファイルを全文読む。
完了報告は日本語で書く。

## 名指し参照の読込方法

名指し参照は`read-trigger-contract.md`「名指し参照の読込方法」に従う。

| 時点または条件 | 全文読む資料 | 契機 | 配送操作 |
| --- | --- | --- | --- |
| 本文がこの資料の基準を使う場面で、資料を選択して取得する時 | `agent-basics:writing-standards/SKILL.md` | 判断 | `read:agent-basics:*/skills/writing-standards/SKILL.md` |

## 入力

- `対象プロンプト`: 評価する指示文の名前と、本文を保存したファイルの絶対パス
- `シナリオ`: 対象プロンプトを適用して解釈を評価する状況設定の1段落。批判的に通読する場合は`なし`

## 手順

1. `シナリオ`の値で読み方を選ぶ。
   - `シナリオ`が`なし`以外の場合は、前提知識を持たない読み手として対象プロンプトを事例へ適用し、解釈に迷った点と裁量で補完した点を指摘する。評価は読取と推論で完結させる。対象の指示を実操作する試行は別の多ターン試行が担う。作成規範は読まない（読むと書かれていない前提を補ってしまい、指示側の曖昧さが指摘に現れない）
   - `シナリオ`が`なし`の場合は対象プロンプトを通読し、不明瞭・冗長・不足・誤り・過剰な指定を洗い出す。このとき`agent-basics:writing-standards`を起動し、同スキルの「エージェント向け文書の編集時に読む資料」の基準も使う
2. 発動条件・本文構造・記述精度・冗長性・命名・例示・整合性などを幅広く対象とし、見つけた指摘を全て、重要度（実害の大きさ、改善幅、適用頻度）の高い順に返す。取捨選択は委譲元が行うため、低い指摘も含める。各指摘は単独で読み取れる粒度で、問題の所在と内容だけを書く

## 出力

次の固定形式だけを返す。指摘1件ごとに`### 指摘`の見出しから`種別`の行までを繰り返す。

```text
状態: completed
### 指摘 N: <問題箇所を1行で>
- 重要度: 高 / 中 / 低
- 該当箇所: <対象プロンプト中の引用または位置を1〜2文で>
- 問題内容: <何が問題か1〜2文>
- 想定される悪影響: <この問題を放置すると何が起きるか1文>
- 種別: 不明瞭 / 冗長 / 不足 / 誤り / 過剰な指定 / その他
```

対象の読取に必要な入力を取得できない場合は、`続行できない理由: <不足する入力と取得不能の根拠>`の1行を返す。
