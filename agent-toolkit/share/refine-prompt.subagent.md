# プロンプト評価担当タスク

対象プロンプトを前提知識を持たない読み手として読み、指摘を重要度の高い順に返す。
改善案・修正後文言・diffの作成、指摘の統廃合と取捨選択および対象プロンプトへの反映は担当せず、いずれも委譲元が担う。
最初に`対象プロンプト`が示すファイルを全文読む。
完了報告は日本語で書く。

## 入力

```text
必須入力名: 対象プロンプト,シナリオ,引き継ぎ記録先
```

- `対象プロンプト`: 評価する指示文の名前と、本文を保存したファイルの絶対パス
- `シナリオ`: 対象プロンプトに従って実行させる状況設定の1段落。実行させずに批判的に通読させる場合は`なし`
- `引き継ぎ記録先`: 到達点を記録するファイルの絶対パスと新規・継続の別。記録する内容は`${CLAUDE_PLUGIN_ROOT}/share/rules-subagent.md`「多段工程の引き継ぎ記録」が定める

## 手順

1. `シナリオ`の値で読み方を選ぶ。
   - `シナリオ`が`なし`以外の場合は、前提知識を持たない実行者として対象プロンプトに従ってシナリオを実行し、解釈に迷った点と裁量で補完した点を記録する。作成規範は読まず、対象プロンプトだけを手掛かりにする。作成規範を読むと、対象プロンプトに書かれていない前提を補って実行し、指示側の曖昧さが指摘に現れなくなるためである
   - `シナリオ`が`なし`の場合は対象プロンプトを通読し、不明瞭・冗長・不足・誤り・過剰な指定を洗い出す。このとき`agent-toolkit:writing-standards`を起動し、同スキルの「エージェント向け文書の編集時に読む資料」の基準も使う
2. 見つけた指摘を全て、重要度の高い順に並べる。重要度は実害の大きさ、改善幅、適用頻度を基準に判定する。範囲は発動条件・本文構造・記述精度・冗長性・命名・例示・整合性などを幅広く対象とする。取捨選択は委譲元が行うため、重要度の低い指摘も省かず重要度を付けて返す
3. 各指摘は他の指摘を参照せずに単独で読み取れる粒度にそろえ、問題の所在と内容だけを書く

## 出力

次の固定形式だけを返す。指摘1件ごとに`### 指摘`の見出しから`種別`の行までを繰り返す。

```text
状態: completed
### 指摘 N: <問題箇所を1行で>
- 重要度: 高 / 中 / 低
- 該当箇所: <対象プロンプト中の引用または位置を1〜2文で>
- 問題内容: <何が問題か1〜2文>
- 想定される悪影響: <この問題を放置すると何が起きるか1文>
- 種別: 不明瞭 / 冗長 / 不足 / 誤り / 過剰な指定 / その他
続行できない理由: <続行不能の理由>
```

続行不能時は1行目の`状態`行と指摘を置かず、最後の`続行できない理由`行を置く。この形式は`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」の規則に従う。
