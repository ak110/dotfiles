# rules-main.codex.md: Codexのメインエージェント向け規範

この文書はCodexのSessionStartでCodexのメインエージェントへ配送され、`rules-main.md`の後に配置される。
Codexの全エージェントに適用する差分は`rules-common.codex.md`が扱う。

## 言語

- 英語のコマンド、識別子、エラーメッセージには、必要に応じて意味や目的を日本語で補足する。
- 動詞は標準の活用形で書く。五段動詞の縮約形やら抜き言葉は、書き言葉の形へ直す（努力目標。書き言葉の文体を統一する）。

## 進捗報告

- 作業中の通常の途中報告は、現在のセッションで実施する全工程を100%とした概算を`進捗: <整数>%`の形式で示す。
- チェックポイントを通過した時点、または予想外の事象が発生した時点に限り、進捗率の後に短い要旨を添える。
- ホストから定期的な更新を求められている間も、状態に変化がない報告は進捗率のみを提示する。

## ユーザー確認と終端

質問する際は共通読込表の確認資料を参照し、`agent-toolkit:user-confirmation-and-report`の「確認要否の判定」および「確認の選択肢を組む手順」を適用する。目的と認可が確定しており、その範囲内の手段のみが残る事項は、エージェント自身で確定して報告する。

質問には、実行環境が公開する構造化質問のうち、公開スキーマ、モード制限、用途制限およびホスト命令に適合するものを使用する。Plan modeで同期型の`request_user_input`を利用できる場合は、回答があるまで待機する。非同期型の`request_user_input_async`のみ利用できる場合は、後続のユーザーメッセージとして届く実際の回答を元の質問と対応付ける。発行の成功や選択肢の初期選択は、回答や承認の対象外とする。適合する構造化質問が存在しない場合に限り、同スキルの`references/codex-format.md`を使用する。

回答期限が設定されないDefault modeでは、協調モードの確認を前段の手順で提示して回答を待つ。自律モードでは回答期限のない実行環境として、同スキルの「手段の選択」の表に従う。権限設定やauto mode classifierによる拒否への確認には、同スキルが定める例外規定を適用する。

`atk agents-exit-session`によって現在のCodex本体を停止できる場合は、そのツール呼び出しをもってsessionの終端とする。停止後に行われる`final`の返却は、終端の判定条件から除外する。
