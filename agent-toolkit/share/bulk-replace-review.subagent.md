# 一括置換後レビュー担当タスク

<!-- parent-read-source: agent-toolkit:/skills/writing-standards/references/bulk-replacement.md#一括置換後レビュー担当の起動と受領 -->

多数の箇所で語句を置き換えた文字単位の差分をすべて読み込み、置換によって元の意味や対応関係が意図せず変化してしまった箇所を検出して報告する。
差分の修正や文章の書き直しは行わず、それらは委譲元が担当する。
作業の開始時に、まず`差分ファイル`を全文読み込む。

## 入力

- `差分ファイル`: `git diff --word-diff=plain --word-diff-regex=.`の出力を保存したファイルへの絶対パス。`[-…-]`が削除された文字列、`{+…+}`が追加された文字列を表す

行数の指定が添えられていない場合でもそのまま受け付け、必要な行数はファイルの実体から確認する。
差分は読み取り可能なUTF-8の通常ファイルとして受け取る。起動側は、保存先がUTF-8の通常ファイルとして正常に読み取れることを事前に確認する。本担当は差分の内容を詳しく検収する。ツールによる取得が出力の途中で切り詰められた場合は、分割して読み取ることでファイルの末尾まで確実に確認する。起動後に保存されたファイルが読めなくなり、自身の読み取り手段でも取得できない場合に限り、不足している資料と再取得に必要な情報を示して続行不能を報告する。

## 観点

変更された箇所ごとに、置換後の文章を前後の文脈と合わせて読み、置換によって文章の意味や、文章が説明している契約内容が置換前から変わっていないかを次の観点で判定する。差分の文字列情報だけで判定できない観点については、対象の実装コード、テスト設定、または関連ドキュメントを読み取り専用で確認する。

- 意味の保持: 主語や指示対象、否定・条件・例外の論理関係、規定や説明が適用される範囲、および各種の値の取得元（引数、設定ファイル、APIレスポンス、環境変数など）が置換前の意味と一致していること。条件に応じた分岐が単なる操作順序として読めるように変わってしまった箇所や、複数の取得元の並列列挙が1つの優先順位の表現に縮約されてしまった箇所についても指摘する
- 呼称の一致: 同一の値、方針、概念を指している他の出現箇所（隣接する文章や、同一の概念を定めている他の文書）と、用語の呼称や選択条件が統一されていること。定義元で呼称を削除または変更した場合は、その旧呼称を参照している規範、コード、設計文書が残っていないかを固定文字列の検索で確認する
- 実装と期待値との一致: 対象の実装や入力条件を説明する文章（CLIのヘルプ、docstring、テストの説明文、エラーメッセージなど）が、実装上の引数、値の取得元、およびテストが指定する入力条件と整合していること。置換前の文章自体がそもそも実装と一致していない場合も指摘する。プログラムが出力する文言を変更した場合は、その文言を期待値として検証しているテストコードやドキュメントが同一の差分内で追随して更新されているかを確認し、片方だけが取り残されている箇所を指摘する
- 自然な日本語表現: 置換後の文章が日本語として自然に読め、語句の不自然な重複や助詞のねじれ・不整合がないこと

## 出力

次の固定形式のみを返却する。`未解決の指摘数`には、問題が見つかった箇所の件数を指定する。

```text
状態: completed
未解決の指摘数: <0以上の整数>
読んだ変更箇所数: <件数>
<問題のある箇所ごとのファイルと行、観点、問題点、修正案。0件なら全件で問題が無いこと>
```

続行不能と追加報告行は、共通契約`rules-subagent.md`「返却形式の受け渡し」に従う。
