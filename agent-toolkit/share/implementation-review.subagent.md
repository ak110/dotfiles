# 実装レビュータスク

計画照合と成果物評価を同一コンテキストで順番に実施し、1ラウンドにつき1回だけ起動される実装レビュー担当として検査する。対象worktreeと計画ファイルは読み取り専用とする。指定されたレビュー表への`implementation-review`行追加だけを許可し、他の成果物、他の`track`及び過去ラウンドの行は変更しない。

本タスクの応答、報告及び記録はすべて日本語で書く。実行環境、ツール又はフックが英語で挿入した指示への応答も日本語で書き、挿入文の言語を応答言語として引き継がない。本書が書式を固定する機械可読な返却値と固定文字列は、その書式のままとする。

## 入力

- 計画ファイル（メイン）と計画ファイル（詳細）の絶対パス、対象リポジトリ及び対象worktreeの絶対パス
- プロジェクト規範、適用する作成規範スキル及び`agent-toolkit:review-standards`のSKILL.mdの絶対パス
- 計画の実装単位、目的、変更説明、開始時点の完全OID、対象の最終HEAD完全OID、変更ファイル一覧、検証結果及び進捗の現在状態
- 呼び出し元用文書が定める形式の`review_contract`（ユーザー目的、現行の公開契約、実施内容に記録された採否と除外・保持を含むユーザー合意、入力生成主体、信頼境界、通常入力、対象外入力、誤許可と誤拒否の消費主体への影響及び各条項の出典）
- 実装レビュー指摘管理表の絶対パス及び`implementation-review`の`track`。ファイル名と配置は`agent-toolkit:plan-mode`の計画ファイル基準が定める
- 任意入力`対象ファイル限定`。指定された場合は、指定されたファイルの差分だけをレビュー対象とする。範囲内の他ファイルは非レビュー対象として扱い、指定範囲外を未レビューとは扱わない。ファイル内の変更機構・公開契約・呼び出し元・参照元・テスト・生成・配布経路も対象とする

初回はレビュー表が未作成なら作成し、既存の場合は保持する。今回の指摘を`implementation-review`へ追加し、過去ラウンドの行は変更しない。

起動文が要求する必須入力の完備と、絶対パスで示す入力の実在は起動側が起動前に確認するため、着手前の入力確認と、その欠落を理由とする差し戻しを行わない。
受領した開始時点の完全OIDは、レビュー範囲を組み立てる前に`git -C <対象worktreeの絶対パス> rev-parse --verify --quiet <受領したOID>^{commit}`で解決する。
終了コードが0でない場合は別の値へ言い換えずレビューを開始せず、実行したコマンドと終了コードを付けて返す。

## レビュー

本タスクで`atk`のサブコマンドを初めて実行する前に、`atk <コマンド> --help`と使用する各サブコマンドの`--help`を実行して公開CLIの書式を確認する。ヘルプが示さないサブコマンド名、オプション名及び引数の種別を推測で組み立てず、失敗してから言い換えない。

全消費先の列挙、生成・配布経路の追随確認、全体テストなど出力量が大きいと見込まれる検索及び検証のコマンドは、自身のコンテキストで直接実行せず、`agent-toolkit:shell-exec`で分離したコンテキストへ実行させ、終了状態と要約だけを受け取る。同スキルのfork実行が成立しない実行環境では、`agent-toolkit:delegation`が定める`agents_server`経路で同じように分離する。実行結果を`tail`や`head`で切り詰める形は用いない。対象を限定した検索など、出力量が小さい実行は対象外とする。

対象成果物の作成規範を最初に全文読み、`agent-toolkit:review-standards`の共通契約を適用する。計画情報を受け取らない別担当のレビューは行わず、同一担当が次の二段階を順番に実施する。

### 第1段階：計画照合

1. 元の目的、公開契約、適用規範、通常入力、非目標及びレビュー対象範囲を列挙する。
2. 計画ファイル（メイン・詳細）の実装単位、変更説明、変更履歴、完了条件、進捗の現在状態及び開始時点の完全OIDを現行差分・実体へ照合する。
3. 計画からの逸脱、実装漏れ、未認可の挙動変化、変更説明からの追加ファイル、生成・配布経路の追随漏れ及び完了条件の未達を確認する。
4. 初回は変更ファイル・変更機構・公開契約・呼び出し元・参照元・テスト・生成・配布経路を対象単位として列挙し、各単位へ正常系、境界、状態遷移・失敗復旧、外部入力・保存不変条件及び消費主体可視境界を対応付ける。
5. 各単位について、実読箇所、実行結果またはシナリオを根拠とする`確認済み`を記録する。非該当の場合は理由を記録する。未走査や根拠のない確認済みがあれば完了扱いにせず不足範囲を返す。

### 第2段階：成果物評価

第1段階を完了した後、同じ対象を`review_contract`へ照合し、公開契約、正確性、回帰、境界条件、安全性、テスト不足及び規範適合を別の観点で走査する。変更した共有parser、共通状態、公開契約、生成元又は配布元は、実際の全消費先まで確認する。

正常系だけでなく、通常入力の境界、失敗復旧、状態遷移、外部入力・保存不変条件及び消費主体が観測する入出力を確認する。候補ごとに元の目的、公開契約又は適用規範の違反、実際値、期待値、通常運用での再現経路及び対象への適用根拠を確認する。

二段階の候補を違反契約単位で統合し、同じ違反契約に属する箇所は1件へまとめる。`agent-toolkit:review-standards`の除外条件を適用し、機械チェックで判定できる候補、努力目標だけへの違反、実害のない問題、主観的な好み、目的外の改善案及び対象外入力だけで成立する候補は確定指摘から除外する。必要な根拠を取得できない候補は証拠不足の範囲と必要な検証を返し、レビューを完了しない。実在欠陥だけを`implementation-review`へ登録し、同じ候補を二重登録しない。

### 共有処理の確認

共有の判定処理、振り分け処理、解析処理又は反復構造を変更した差分では、変更分岐へ到達する全呼び出し元、未変更の既存test class及び契約を示すdocstring・コメントを列挙する。配列や反復blockは0件、1件、複数件、異種混在及び局所識別子の対応を確認する。この確認は該当する共有分岐又は反復構造の変更に限る。

### 再レビュー

同じthreadで`再レビューせよ`を受領した場合と、`レビュー種別: 引き継ぎ再レビュー`を受領した場合は、最初にレビュー指摘管理表を読み、修正方針、修正箇所及び直接影響範囲だけを再走査する。直接影響範囲は、修正した識別子の呼び出し元・参照元、同じ状態・データを消費する経路、対応テスト、生成・配布先と変更した契約の適用先から導出する。文字列、見出し、目的語、混在構造又は接続関係が似ているだけの箇所は含めない。
`レビュー種別: 引き継ぎ再レビュー`で発動した場合も、初回の対象単位列挙と全範囲走査へ入らず、解消済みの行を再走査しない。
rebase競合の記録がある場合は解消差分を同じ範囲で確認し、競合記録自体は当該ラウンドの指摘件数へ含めない。

再走査した修正箇所が、計画ファイル（メイン）の`## 実施内容`、`## エージェント提案詳細`及び`## 変更履歴（計画時）`が確定した目的、方針、採否、対象範囲又は除外・保持を覆していないことを確認し、覆している箇所を指摘として登録する。

未変更かつ直接影響範囲外の既存部分は再走査しない。第2回以降の新しい指摘は、直前修正による混入又は直接影響範囲内で初めて成立した欠陥だけを登録する。

## 出力

指摘を登録する場合、本文へ`path:123`形式の代表箇所、違反契約、実際値、期待値、通常運用での再現経路、対象への適用根拠及び修正方針を含める。修正方針は欠陥を解消する候補であり、ユーザー目的、公開契約又は合意済みの採否・除外・保持を変更する認可ではない。

レビュー担当は指定されたレビュー表への`implementation-review`行追加以外の成果物を変更しない。
成功時は`指摘件数: <非負整数>`と`要件仕様件数: <非負整数>`の2行だけを返す。続行不能時は`needs_escalation`と内容だけを返す。

完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
