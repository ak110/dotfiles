# 再発防止セルフチェックの起動と受領

```text
起動対象: recurrence-self-check.subagent.md
```

`起動対象:`は役割文書のファイル名である。
`start`の`subagent_md_path`には`.subagent.md`を除いた`recurrence-self-check`を渡す。
起動準備は本書の入力・引数・返却契約で行い、起動対象本文を取得しない（定義の編集、委譲先自身の取得、完了後の検収を除く）。
圧縮後は本書を読み直して契約を復元する。

再発防止セルフチェックとは、独立した担当者が具体的な再発防止観点を今回の差分に適用して確認する、実行レビュー内の工程である。
実行レビュー担当は、初回レビュー、再レビュー、および引き継ぎ再レビューの各ラウンドにおいて本書の手順に従って実施する。

## 入力

**1.** 全観点と比較元を揃えるため、観点ファイルを収集し、以下の入力と省略条件を確定する。

- 必須入力名: `観点ファイル`、`今回差分`、`変更ファイル一覧`、`対象worktree`、`未解決指摘`

観点ファイルは、見出し1（H1）が`# 再発防止セルフチェック観点`で始まるMarkdownファイルである。
次の2つの検索コマンドを実行し、実際に存在するファイルの和集合を観点ファイルとして特定する。

```sh
git -C <対象worktreeの絶対パス> grep -l -E '^# 再発防止セルフチェック観点' -- '*.md'
rg -l -e '^# 再発防止セルフチェック観点' --glob '*.md' -- <配布rootの絶対パス>
```

配布rootには、現在のplugin root（`${CLAUDE_PLUGIN_ROOT}`）を指定する。
両方の検索において、終了コード0は該当あり、1は該当なしを意味し、それ以外のコードは検索失敗とみなす。
検索が失敗した場合は、原因を解消したうえで再実行する。
`git grep`で取得したパスは、対象worktreeを基準とする絶対パスに変換する。
対象worktreeが配布物の原本リポジトリであり、配布root内のファイルが対象worktreeで追跡されている原本と同一の実体を指している場合は、作業ツリー側のファイルのみを採用する。
別個の観点ファイルであれば、項目名や記述内容が重複していても個別のファイルとして保持する。
検索コマンド・終了コード・採用ファイル・重複除外ファイルを走査記録へ残す。
0件なら起動を省き、理由と記録の保存先を走査記録に記して通常レビューへ進む。
対象条件・確認内容・根拠規範を備える有効な単位かは担当が本文から判定する。

入力パラメーターは以下の規則に基づいて決定する。

- 観点ファイル: 上述の和集合で得られた絶対パスを格納したJSON配列
- 今回差分: 自身のセッションのmanaged-temp配下に保存した差分ファイルの絶対パス、ならびに比較元と現行版の識別子。
  初回の比較元は開始時点からレビューHEADまでとし、再レビューおよび引き継ぎ再レビューでは前回確認版に保存された前回のレビューHEADから現行HEADまでとする。
  同一HEADの場合は空の差分ファイルを保存し、未解決指摘は別の入力として渡す。
  Git管理外の変更については、受け取った変更前複製（再レビューや引き継ぎ再レビューでは前回本文の複製）と現行本文から差分を生成して保存し、新規追加ファイルは全文を保存する
- 変更ファイル一覧: 今回の差分に含まれるファイルパスの一覧。
  Git管理外の変更も含め、対象worktreeを基準として現行本文を参照できる形式で渡す
- 対象worktree: レビュー対象の作業ツリーの絶対パス
- 未解決指摘: 前回までのセルフチェックに起因する未解決指摘の該当箇所、根拠規範、管理表の識別子、回答内容、および検証結果。
  初回または該当項目がない場合は`なし`とする。
  コマンド実行によって得られた証拠は、保存先ファイルの絶対パスを渡す

引き継ぎ再レビューでは、前回確認版および未解決指摘の情報を前任者の記録から復元して渡す。
比較元を特定できない場合は委譲元へ問い合わせて入力を補完したうえで起動する。
本担当はファイルの読み取りと検索のみで作業を完結させるため、担当側での差分再生成は求めず、保存済みの差分ファイルを渡す。

再レビュー・引き継ぎ再レビューで、管理外ファイル・回答下書きも含む今回差分が空かつセルフチェック由来の未解決が0件なら起動を省く。
空差分・比較元・現行版・未解決0件を、観点なしの場合と同じ走査記録へ残す。
差分か未解決があれば起動する。

## 起動

**2.** 通常走査と独立して点検するため、省略条件に該当しなければ収集した全観点を1担当へ渡して起動する。

`agent-toolkit:/share/exec-review-criteria.md`に基づく走査と並行して、収集した観点全体を1つの担当者へ渡す。
この担当者は、`agents_server`の`task`が役割文書のfrontmatterを参照して工程別の`model_type`を選択する。
`agents_server`の`start`を呼び出す際の役割固有の引数は以下のとおりである。

| 引数 | 値 |
| --- | --- |
| `cwd` | 対象worktreeの絶対パス |
| `subagent_md_path` | `recurrence-self-check` |
| `extra_params` | 前節で確定した各名前付き入力 |
| `model_type` | 実行レビュー担当が`担当モデル`を受け取っている場合はその値。受け取っていない場合は指定しない |

工程を明示的に指定した場合は、その工程向けに定義された候補モデル列が使用される。
起動modeは役割文書での宣言に従う。

## 受領と採否

**3.** 全項目を採否へ対応付けるため、終了結果を回収・検収して管理表と走査記録へ反映し、実行レビューの返却へ進む。

起動、終了の観測、および失敗時のリカバリ手順は、`agent-toolkit:delegation`の契約に従う。
`atk agents wait`によって回収した担当者の終了結果から、`session_id`、`model_type`、`engine`、`model`、`effort`を走査記録に記録する。
`model_type`を指定した場合は渡した値との一致を確認し、指定しなかった場合は実行時の値を記録する。
デフォルト設定の検証は役割宣言と起動処理側が担保する。
結果を実際に取得するまでは、未確認の項目を「適合」とみなさない。
本書「セルフチェックの返却契約」の形式に従って得られた全項目の結果を、入力した観点集合と突き合わせる。

実行レビュー担当は各違反内容を差分および根拠規範と照らし合わせて裏付けを取り、採用する指摘を`agent-toolkit:/share/exec-review-criteria.md`の種類7として既存のレビュー指摘管理表へ登録する。
登録する指摘の本文には、該当する観点ファイルの絶対パスと項目名を記載する。
不採用とした項目については項目ごとの理由を走査記録に残し、既存の指摘へ統合した項目については対応先を記録する。
統合先の指摘本文にも、種類7の根拠となる観点ファイルのパスと項目名を追加する。
前回指摘が解消されたかどうかも現行本文と検証結果をもとに確認し、管理表へ結果を反映する。
すべての項目の結果を登録先または不採用理由と対応付け、未解決件数は既存の指摘と合算して集計する。
実行レビューの収束条件および返却フォーマットは、既存の契約規定に従う。

## セルフチェックの返却契約

全項目について、以下の固定形式のみを返却する。
`前回指摘`には、未解決指摘の各識別子に対応する解消・未解消の状態と、その根拠を記述する。
入力が`なし`の場合は、値に`なし`を設定する。

```text
状態: completed
項目: <観点ファイルの絶対パスと項目名>
判定: <対象外|適合|違反>
根拠: <確認箇所、確認内容、違反では根拠規範の所在>
<項目ごとに項目・判定・根拠を繰り返す>
前回指摘: <識別子ごとの解消・未解消と根拠|なし>
```

続行不能と追加報告行は、共通契約`rules/rules-subagent.md`「返却形式の受け渡し」に従う。
資料不足の場合は、影響する項目、欠けた資料と補完に必要な値を記す。
