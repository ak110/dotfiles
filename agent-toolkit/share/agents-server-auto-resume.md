# 委譲先完了後の自動再開

この実行環境は、追跡中の`agents_server`セッションがすべて終了した後に同一セッションを自動再開する。未回収対象の観測を保持し、同じ終了通知による継続指示は一度だけ届ける。
Codexの組み込み委譲機能（`spawn_agent`）で起動した子スレッドもこの対象となり、すべての子スレッドの終了を確認した後に同一セッションを再開する。
実行環境がバックグラウンドタスクの完了を通知する場合（Claude Codeの`Agent`ツールで起動した委譲先やBashのバックグラウンドタスクなど）も、処理完了後に同様の自動再開が行われる。
未回収の子セッション、子スレッド、またはバックグラウンドエージェントは終了の確認まで追跡し、待機表明の保留と必要な継続を維持する。過去の継続消費やCLIのidle状態だけで追跡を終えず、回収済み対象は再追跡しない。実行時間の上限が設定されているバックグラウンドコマンドには、その上限に基づいた通知喪失の診断を適用する。
自動再開の能力と今回の対象の追跡・保留・継続の成立は区別する。classifierの判定不能で待機を開始できなくても、未回収対象の観測責任は残る。`agent-toolkit:delegation/references/wait-anomalies.md`「待機を開始できない場合」に従い、通知本文の再試行指示で区別する。`gave no verdict (error)`の一時失敗は許された1回と遅延に従い、`gave no verdict (it skipped this action)`の「hard failure」「Don't retry it」は同じ待機の起動を再試行せず、許容された別の観測手段で終了観測を続ける。必須操作を実行できなければ、同節の報告手順へ進む。ホスト制約で続行できない場合は対象の識別子、起動状態、診断と再開条件を委譲元へ渡す。
待機している対象が上記の自動再開の対象であり、かつその対象の完了通知によって同一セッションが再開される場合に限り、`待機中: <実行識別子>`という1行の出力でターンを終了し、再開されたターンで所定の返却形式を返してよい。
なお、Codexの`functions.exec`におけるcell IDや`exec_command`におけるsession IDは、この自動再開の対象外となる。これらは公開されている`functions.wait`や`write_stdin`を用い、同一ターン内で出力と終了状態を回収する。
また、`atk agents wait`によって明示的に結果を回収したセッションは、自動再開の対象から除外される。
複数の子を待つ場合、自動再開は全件の終了後になる。先に終了した子の結果で進める工程が残るときは、待機表明の前に`atk agents wait`で終了した分を回収して進め、全件の結果を待つだけになってから待機表明でターンを終える。
