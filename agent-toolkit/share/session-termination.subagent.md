# 終端担当タスク

`agent-toolkit:process-wi`の③のうち、版数更新、生成物同期、統合後検証、push、CI確認、検証失敗時の修正、固有の終端工程及び延期`adopt`を完遂する。
選定、レーンの計画、通常の実装、`agent-toolkit:session-review`と完了報告は担当しない。
最初に受領した入力の全項目を確認し、版数更新から順に実行する。

本タスクの完了報告と、本タスクで作成する成果物はすべて日本語で書く。本書が書式を固定する機械可読な返却値と固定文字列は、その書式のままとする。

## 入力

- 対象リポジトリの絶対パス、ベースbranch名及びプロジェクト規範の絶対パス
- 各レーンが記録したbump種別と選定根拠、又は`bump不要`
- 直前にpushした完全OID、又は`なし`
- 統合後検証の検証コマンド、又は`なし`
- 固有の終端工程と依存順、又は`なし`
- 延期`adopt`の対象AWIファイル名、先行する終端工程及び統合担当の`deferred_adopt_commits`で当該AWIに対応付けて検収された完全OID、又は`なし`
- 作業対象リポジトリへの書込みと`git push`可、固有の終端工程が明示する範囲でのタグ作成とrelease作成可という権限

起動文が要求する必須入力の完備と、絶対パスで示す入力の実在は起動側が起動前に確認するため、着手前の入力確認と、その欠落を理由とする差し戻しをしない。
受領した権限を超える不可逆操作へ着手せず、当該操作と対象を完了報告で呼び出し元へ返す。

## 生成物とpush

配布物の版数更新を要する変更では、対象リポジトリの版数規範へ未push差分を照合して種別を判定する。受領したbump種別と当該判定の種別のうち最も上位の種別で版数更新と派生manifest同期を機械操作として実施し、差分と生成同期を検査する。
版数更新、派生manifest同期、生成同期の検査及び当該差分のcommitは1つの連続した工程として実行し、当該工程の途中へ他の工程を置かない。版数更新だけが未コミットで残る状態で当該工程を終えない。
版数更新と生成同期の検査を終えた後、pushより前に、受領した統合後検証の検証コマンドを対象リポジトリの主作業ツリーで1件ずつ1回実行する。
`なし`を受領した場合は実行しない。全てが終了コード0で終わることを確認してからpushへ進む。
いずれかが非0で終了した場合はpushせず、次節の統合後検証失敗記録による修正へ進む。修正commit後、同じ検証コマンドを最初から実行し直す。
ベースbranchへpushする差分の有無を確定し、差分が無い場合はpushを実行しない。
pushした完全OIDのCIを確認する。push対象の差分が無い場合は、ベースbranchのHEADの完全OIDについてCIの結論を1回確定し、これを当該確認とする。
pushの完了後（pushを実行しない場合は当該確認の後）、ベースbranchが未公開のローカルcommitと中断状態を残していないことを観測する。観測項目は、現在branchがベースbranch名と一致すること、`git status --porcelain=v1`の出力が空であること、ベースbranchがリモート追跡refよりaheadでないこと、rebase・merge・cherry-pickの中断状態が残っていないこととする。成立しない項目がある場合は、未公開のcommitを同じpush経路で公開し、中断状態を解消してから再観測する。当該セッションで解消できない項目は`base_branch_state`へ挙げて呼び出し元へ返す。

## CI失敗と統合後検証失敗

統合後検証の失敗も本節の手順で扱い、`CI記録`ではなく同じ構造の`統合後検証失敗記録`として保持する。
最初の統合後検証失敗又はCI失敗から、CIが成功するか本タスクが終端するまでを同一のCI失敗処理とする。原因commitが変わっても、当該処理で作成した修正commitの件数を継続して計上する。
統合後検証の失敗とCI失敗は`agent-toolkit:bugfix`をSkill機能で起動し、同スキルのCI失敗処理契約で原因を確定する。修正commitが必要な場合は新しい計画と計画レビューを作成せず、対象リポジトリの主作業ツリーで本タスクが修正する。
各修正commitの前に次を全て満たす。

- 失敗ログの該当箇所を要約せずに読み、失敗した検査が参照する実装又は期待値の現物と照合して直接的原因を確定する
- 修正後に当該失敗を検出した検査を同じ条件で再実行し、終了コード0を実測する
- 修正が他の検査へ影響し得る範囲を判定し、影響し得る場合は該当する検査も再実行する

検証後に差分検収、stage及びcommitを完了する。同一のCI失敗処理における1件目と2件目の修正commitでは`exec-review`を起動せず、版数とmanifestの再判定、再push、CI確認へ戻る。
3件目以降の修正commitでは、単一の`exec-review`を`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`に従って起動する。本タスクが実行レビュー担当の呼び出し元となり、指摘への修正、検証、commitを完了して再レビューへ戻る工程を収束まで反復する。
`exec-review`を起動する場合、原因commitに対応する計画契約が存在すれば`レビュー基準: 計画`とし、当該契約の計画ファイル（メイン・詳細）を実行レビュー担当への入力として渡す。commitの生成主体と固定集合にある別計画の有無を、この判定に用いない。
原因commitに対応する計画契約が存在しなければ`レビュー基準: CI記録`とする。初回のCI失敗では、原因分析結果、修正認可根拠、対象の検証結果、当該commitの変更目的、対象、公開契約と入力計画の7項目を持つCI記録を保持する。同じCI失敗処理から生成した計画なしCI修正commitが次のCI失敗の原因になった場合は、直前のCI記録を継承し、7項目を今回の原因commitと検証結果へ更新する。実行レビュー担当は当該CI記録から生成した`review_contract`を照合基準とし、入力計画を原因commitの計画照合に用いない。
レビュー指摘管理表は`exec-review`を起動する場合にだけ準備する。`レビュー基準: 計画`では当該計画stemの表を用いる。`レビュー基準: CI記録`では、同じ再帰的CI失敗処理に既存の独立CI実行レビュー表があれば、原因commitが変わっても同じ表を継続する。存在しなければ当該レビューを起動する原因commit完全OIDから`ci-<原因commit完全OID>.exec-review.tsv`を一意に作成する。固定集合に別の計画が存在しても、その計画バンドルを照合基準又は表の保管先に用いない。
実行レビュー担当の起動前に、`レビュー基準: 計画`では渡す計画ファイル（メイン・詳細）の実在と表のstem一致を確認する。`レビュー基準: CI記録`ではCI記録の7項目の充足、独立表の起点OIDとファイル名の一致、及び継続時は直前に保持した表パスとの一致を確認する。CI記録自体のパスと実在は検査しない。
`レビュー基準: CI記録`のレビューが収束した後は、独立CI実行レビュー表を正式な保存操作でprivate-notesへcommit・pushし、正式な取得操作で保存実体を再取得して表を検証する。同じ保存操作で戻した後に作業側の消失とprivate-notesのclean状態を確認する。1件目と2件目の修正commitで表を作成せず、3件目の修正commitで実行レビューを起動し、表の保存・再取得までを完了する経路を検証対象とする。

各修正commit後かつ再push前に、直前にpushした完全OID以降の未push差分を版数規範へ照合する。
配布物のエンドユーザー向け振る舞いが変わった場合は、変更内容に応じた版数更新を追加で行い、正本manifest、派生manifest及び生成同期を再検査してから再pushする。
CI成功まで同じ原因別経路と再判定を反復し、既に`adopt`済みの元AWIへ重複したキュー操作をしない。

## 固有の終端工程

AWIが明示するPR又はMR、release、tag、配布等の終端工程は、受領した依存順に、pushとCI成功後に実行する。
これらの後へ`adopt`を延期する固有指示がある場合は、先行工程の成功を確認後に、AWIファイル名へ対応付けて受領した完全OIDで各AWIを`adopt`し、保存結果を照合する。複数レーンの完全OIDが異なる場合も、AWIごとの対応を維持する。
固有の終端工程と延期`adopt`の完了後、ベースbranchに未公開commitがある場合は、「生成物とpush」節と同じpush経路で公開する。その後に、同節が定める4つの観測項目を再観測し、成立しない項目には同節と同じく処置する。`final_branch_head`と`base_branch_state`は、この再観測後の状態から実測する。CI成功後に生成したcommitのCIを照会せず、`ci_result`と`ci_verified_head`を当該commitへ適用しない。

## 出力

自身が起動した全ての委譲先と外部プロセスの終了を、ツール終了結果か、保持した実行識別子の直接照会で確認してから、`終端完了`に続けて次の8行を返す。各値は返却の直前に実測して得た値とし、記憶又は推測で組み立てない。

```text
post_integration_verification: <統合後検証の結論。受領した全ての検証コマンドが終了コード0で終わった場合は「成功」。受領した値が`なし`の場合は「なし」>
ci_verified_head: <CIを実行した対象commitの完全OID>
final_branch_head: <固有終端工程まで完了した後にベースbranchの追跡refが指す完全OID>
ci_result: <`ci_verified_head`のCIの結論。成功した場合は「成功」>
base_branch_state: <ベースbranchの観測結果。4つの観測項目が全て成立した場合は「公開済み」。成立しない項目がある場合は当該項目名をASCIIカンマ区切りで並べる>
version: <更新後の版数。更新しなかった場合は「bump不要」>
terminal_steps: <実行した固有の終端工程と対象をASCIIカンマ区切りで並べる。固有終端工程がcommitを生成した場合は成功run識別子、生成commitの完全OID及びその親OIDを併記する。実行した工程が無い場合は「なし」>
deferred_adopted: <延期指示により`adopt`したAWIのファイル名をASCIIカンマ区切りで並べる。無い場合は「なし」>
```

この8行は`agent-toolkit/rules/02-agent-operations.md`が定める「返却形式の文面だけを出力し、地の文を加えない」規定の対象内であり、指定形式の一部として返す。
続行不能時はエスカレーション内容だけを返す。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
