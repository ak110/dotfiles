# 終端担当タスク

`agent-toolkit:process-wi`の公開工程のうち、版数更新、生成物同期、全体検証、push、CI確認、検証失敗時の修正、プロジェクト固有の公開後の操作、延期`adopt`を完遂する。選定、レーンの計画と実装、振り返り、完了報告は委譲元が担う。
完了報告と成果物は日本語で書く。

## 読込表

次の時点または条件が成立したら、対象の操作の前に同じ行の資料を全文読む。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 版数更新、生成物、push前のチェック、push、CI確認または公開状態の判定に着手する前 | `agent-toolkit:commit`の`references/publish.md` |
| 全体検証かCIが失敗したとき | `agent-toolkit:process-wi`の`references/termination-ci-failure.md` |
| CI定義判定、baseline作成、CI監視または公開後の操作を前提不足で完了できないとき | `agent-toolkit:commit`の`references/push-and-ci.md` |

## 入力

```text
必須入力名: bump種別,引き継ぎ記録先
任意入力名: プロジェクト固有の公開後の操作,延期adopt,公開対象のadopt済みAWI
```

対象リポジトリは起動時の`cwd`が属するGit worktreeのroot、ベースbranch名は起動時の現在branch、プロジェクト規範はその`cwd`で実行ホストがロードする指示ファイルとする。対象リポジトリへの書込みとpush、およびプロジェクト固有の公開後の操作が明示する範囲のタグとreleaseの作成を行える。それを超える不可逆操作へは着手せず、操作と対象を委譲元へ返す。

- `bump種別`: 委譲元が確定した種別と根拠の要約。そのまま使い、根拠に現れる計画ファイルは再読の対象外とする
- 任意の3入力の省略時の値は`なし`とする
- `延期adopt`: 状態変更の対象は、AWIファイル名と実装commitのOID（または空文字列）を組で受領した集合だけとする
- `公開対象のadopt済みAWI`: プロジェクト固有の公開手順で参照するだけで、WIの状態変更には使わない

## 生成物とpush

版数更新、生成物、push前に実行するチェックの選定と実行、push、CI確認、公開状態の判定は、`agent-toolkit:commit`を起動し、読込表の`references/publish.md`に従って実行する。受領した`bump種別`を入力に使い、CIの成功か有効な不在証拠とローカル全体検証の成功を確かめる。

## プロジェクト固有の公開後の操作

親から自身へ渡された工程だけを実行する。認可されたPRまたはMR、release、tag、配布等と、その後に生じたcommitの再公開は`references/publish.md`に従う。

## 延期adoptの終端

先行工程の成功後に、受領したAWIファイル名と実装commitのOIDで`adopt`する。プロジェクト固有の公開後の操作で新しい実装commitが生じた場合は、AWIの要求を実際に反映したOIDを選び直す。実装差分が無い項目は`--commit`を省き、充足の根拠を`--note`か`--note-file`へ記録する。commitを記録する場合は対象リポジトリのworktreeの絶対パスを`--target-repo`へ渡す（`agent-toolkit:wi-standards`「状態と依存」の共通前提）。

残る完成条件はエージェントが到達できる環境を探して観測する（観測主体が人と書かれていても、`agent-toolkit:wi-standards`の`references/awi-body.md`の観測主体の規定に従う）。次の項目は`adopt`せず`processing`のまま残し、`実行した終端工程`へ記す（扱いは`agent-toolkit:process-wi`の`references/run-lanes.md`「採否の確定と終端区分」）。

- 反映後の新プロセスでしか観測できず、この担当が観測を終えられない項目: 残る条件と観測手段。人を観測主体とする条件では、探した環境と観測できなかった理由も
- 観測した結果が完成条件を満たさない項目: 満たさなかった条件と観測の結果

## 出力

自身が起動した全ての委譲先と外部プロセスの終了を確認し、次の形式だけを返す。

```text
終端完了
全体検証: <全体検証をCIの結果で判定した場合は「CI判定」。CIが実行しないチェックの集合を確定できない場合と対象リポジトリにCI定義が無い場合に、タスクランナーが定める全体検証をローカルで実行したときは「ローカル成功」>
CIで検証したcommit: <CI対象commitの7文字以上の一意な短縮OID。`CIの結果`が`CI定義なし`ならCI定義の不在を確かめたcommitの短縮OID>
ベースbranchのHEAD: <ベースbranchの追跡refが指す7文字以上の一意な短縮OID>
CIの結果: <CIが成功した場合はCI成功。CI定義なしは共通判定で不在を確定し、全体検証がローカル成功の場合だけ返す>
ベースbranchの状態: <公開状態の4項目が成立した場合は「公開済み」。それ以外は項目名>
版数: <更新後の版数または「bump不要」>
実行した終端工程: <実行した工程と対象。`全体検証`が「ローカル成功」なら実行した全体検証のコマンド、終了コードおよび警告の有無、「CI判定」ならpush前に実行したCIが実行しないチェックと全体走査のチェックのコマンド、終了コードおよび警告の有無と、その集合を求めた根拠（プロジェクト規範の定めまたは`agent-toolkit:commit`の`references/publish.md`が定める4つの比較の結果）を必ず挙げる。`CIの結果`が`CI定義なし`なら、`references/push-and-ci.md`「公開先に対応するCI定義の判定」で使ったforge・repository・commitと不在の取得・コマンド・終了状態・結果も挙げる。同じtreeで実行済みのため省いたチェックは、省いた理由と実行済みの結果の所在を挙げる。無い場合は「なし」>
延期後にadoptしたAWI: <実際にadoptしたAWIファイル名のJSON文字列配列。反映後の新プロセスでしか観測できない条件が残る項目と、観測が完成条件を満たさなかった項目を含めない。無い場合は[]>
```

続行不能時は`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」の`続行できない理由:`の1行だけを返す。
CI照会不能または公開後の操作の前提不足の場合は、`references/push-and-ci.md`「公開工程の続行不能の受渡し」の対象、失敗した操作と対象、診断、確認済み工程、成功済みの公開後の操作、残工程と再開位置を含める。
1行に収まらない証拠は引き継ぎ記録へ保存し、その絶対パスを同じ行に示す。
完了報告はツール戻り値で1回返し、`SendMessage`では送らない。
想定外事象の追加行は`agent-toolkit/share/rules-subagent.md`に従う。
