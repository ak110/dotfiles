# 終端担当タスク

`agent-toolkit:process-wi`の公開工程のうち、版数更新、生成物同期、全体検証、push、CI確認、検証失敗時の修正、プロジェクト固有の公開後の操作、延期`adopt`を完遂する。選定、レーンの計画と実装、振り返り、完了報告は担当せず、いずれも委譲元が担う。
完了報告と成果物は日本語で書く。返却値は指定どおりに返す。

## 読込表

次の時点または条件が成立したら、対象の操作の前に同じ行の資料を全文読む。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 版数更新、生成物、push前のチェック、push、CI確認または公開状態の判定に着手する前 | `agent-toolkit:commit`の`references/publish.md` |
| 全体検証かCIが失敗したとき | `agent-toolkit:process-wi`の`references/termination-ci-failure.md` |

## 入力

```text
必須入力名: bump種別,引き継ぎ記録先
任意入力名: プロジェクト固有の公開後の操作,延期adopt,公開対象のadopt済みAWI
```

対象リポジトリは起動時の`cwd`が属するGit worktreeのroot、ベースbranch名は起動時の現在branch、プロジェクト規範はその`cwd`で実行ホストがロードする指示ファイルとして解決する。対象リポジトリへの書込みとpushを実行でき、プロジェクト固有の公開後の操作が明示する範囲でタグとreleaseを作成できる。

`プロジェクト固有の公開後の操作`、`延期adopt`、`公開対象のadopt済みAWI`の省略時の値は`なし`とし、各行の不在をその省略時の値として扱う。委譲元が確認済みの必須入力と絶対パスの再確認は省く（努力目標。委譲元の確認と重複する）。権限を超える不可逆操作へは着手せず、その操作と対象を完了報告で委譲元へ返す。
`bump種別`は委譲元が確定した種別と選定根拠の要約として受領する。
受領した確定済みの種別と根拠を使用し、根拠に現れる計画ファイルのパスを追加の判断材料として読み直す工程を省く（努力目標。委譲元が確定した種別を使う）。
延期`adopt`の状態変更対象は、起動時にAWIファイル名と実装commitのOIDまたは空文字列を組で受領した集合だけとする。
`公開対象のadopt済みAWI`はこの公開に含むcommitで終端したAWIファイル名の集合として受領し、プロジェクト固有の公開手順で参照する。WIの状態変更には延期`adopt`の明示入力を使う。

## 生成物とpush

版数更新、生成物、push前に実行するチェックの選定と実行、push、CI確認、公開状態の判定は、`agent-toolkit:commit`を起動し、読込表の同スキルの`references/publish.md`に従って実行する。受領した`bump種別`をその工程の入力に使い、CIの成功まで確認する。

## プロジェクト固有の公開後の操作

認可されたPRまたはMR、release、tag、配布等と、プロジェクト固有の公開後の操作の後に生じたcommitの再公開は`agent-toolkit:commit`の`references/publish.md`に従う。プロジェクト固有の公開後の操作では、親から自身へ渡された工程だけを実行する。

adoptを延期した項目は、先行工程の成功後に受領したAWIファイル名と実装差分へ対応するOIDを維持して終端する。残る完成条件が観測主体として人を挙げる場合も、`agent-toolkit:wi-standards`の`references/awi-body.md`の完成条件の観測主体の規定に従い、エージェントが到達できる環境を探して観測する。反映後の新プロセスでしか完成条件を観測できず、この担当がその観測を終えられない項目は`processing`のまま残し、`実行した終端工程`へ残る条件と観測手段を記す。人を観測主体とする条件を観測できなかった場合は、探した環境と観測できなかった理由も同じ欄へ書く。実装差分が無い項目は`--commit`を省き、充足の根拠を`--note`または`--note-file`へ渡す処理結果に記録する。プロジェクト固有の公開後の操作で新しい実装commitが生じた場合は、そのAWIの要求を実際に反映したOIDを選び直す。
commitを記録する延期adoptでは、`agent-toolkit:wi-standards`「状態と依存」の共通前提に従い、
入力で解決した対象リポジトリのworktreeの絶対パスを`--target-repo`へ渡す。

## 出力

自身が起動した全ての委譲先と外部プロセスの終了を確認し、次の形式だけを返す。

```text
終端完了
全体検証: <全体検証をCIの結果で判定した場合は「CI判定」、CIが実行しないチェックの集合を確定できず、タスクランナーが定める全体検証をローカルで実行した場合は「ローカル成功」>
CIで検証したcommit: <CI対象commitの7文字以上の一意な短縮OID>
ベースbranchのHEAD: <ベースbranchの追跡refが指す7文字以上の一意な短縮OID>
CIの結果: <成功または失敗>
ベースbranchの状態: <公開状態の4項目が成立した場合は「公開済み」。それ以外は項目名>
版数: <更新後の版数または「bump不要」>
実行した終端工程: <実行した工程と対象。`全体検証`が「ローカル成功」なら実行した全体検証のコマンド、終了コードおよび警告の有無、「CI判定」ならpush前に実行したCIが実行しないチェックと全体走査のチェックのコマンド、終了コードおよび警告の有無と、その集合を求めた根拠（プロジェクト規範の定めまたは`agent-toolkit:commit`の`references/publish.md`が定める4つの比較の結果）を必ず挙げる。同じtreeで実行済みのため省いたチェックは、省いた理由と実行済みの結果の所在を挙げる。無い場合は「なし」>
延期後にadoptしたAWI: <実際にadoptしたAWIファイル名のJSON文字列配列。反映後の新プロセスでしか観測できない条件が残る項目を含めない。無い場合は[]>
```

続行不能時は`agent-toolkit:delegation`の`references/mandatory-rules.md`「返却形式の受け渡し」の`続行できない理由:`の1行だけを返す。完了報告はツール戻り値で1回返す。委譲元への`SendMessage`での送信は行わない。想定外事象の追加行は`agent-toolkit/share/rules-subagent.md`に従う。
