# 終端担当タスク

`agent-toolkit:process-wi`の③のうち、版数更新、生成物同期、push、CI確認、CI失敗時の修正、固有の終端工程及び延期`adopt`を完遂する。
選定、レーンの計画、通常の実装、`agent-toolkit:session-review`と完了報告は担当しない。
最初に受領した入力の全項目を確認し、版数更新から順に実行する。

本タスクの完了報告と、本タスクで作成する成果物はすべて日本語で書く。本書が書式を固定する機械可読な返却値と固定文字列は、その書式のままとする。

## 入力

- 対象リポジトリの絶対パス、ベースbranch名及びプロジェクト規範の絶対パス
- 各レーンが記録したbump種別と選定根拠、又は`bump不要`
- 直前にpushした完全OID、又は`なし`
- 固有の終端工程と依存順、又は`なし`
- 延期`adopt`の対象AWIファイル名、先行する終端工程及び統合担当の`deferred_adopt_commits`で当該AWIに対応付けて検収された完全OID、又は`なし`
- 作業対象リポジトリへの`git push`可、固有の終端工程が明示する範囲でのタグ作成とrelease作成可、CI修正レーンの専用worktree作成と回収可という権限

起動文が要求する必須入力の完備と、絶対パスで示す入力の実在は起動側が起動前に確認するため、着手前の入力確認と、その欠落を理由とする差し戻しをしない。
受領した権限を超える不可逆操作へ着手せず、当該操作と対象を完了報告で呼び出し元へ返す。

## 生成物とpush

配布物の版数更新を要する変更では、対象リポジトリの版数規範へ未push差分を照合して種別を判定する。受領したbump種別と当該判定の種別のうち最も上位の種別で版数更新と派生manifest同期を機械操作として実施し、差分と生成同期を検査する。
版数更新、派生manifest同期、生成同期の検査及び当該差分のcommitは1つの連続した工程として実行し、当該工程の途中へ他の工程を置かない。版数更新だけが未コミットで残る状態で当該工程を終えない。
ベースbranchへpushする差分の有無を確定し、差分が無い場合はpushを実行しない。
pushした完全OIDのCIを確認する。push対象の差分が無い場合は、ベースbranchのHEADの完全OIDについてCIの結論を1回確定し、これを当該確認とする。
pushの完了後（pushを実行しない場合は当該確認の後）、ベースbranchが未公開のローカルcommitと中断状態を残していないことを観測する。観測項目は、現在branchがベースbranch名と一致すること、`git status --porcelain=v1`の出力が空であること、ベースbranchがリモート追跡refよりaheadでないこと、rebase・merge・cherry-pickの中断状態が残っていないこととする。成立しない項目がある場合は、未公開のcommitを同じpush経路で公開し、中断状態を解消してから再観測する。当該セッションで解消できない項目は`base_branch_state`へ挙げて呼び出し元へ返す。

## CI失敗

CI失敗は`agent-toolkit:bugfix`をSkill機能で起動し、同スキルのCI失敗処理契約で原因を確定する。修正commitが必要な場合は専用worktreeのCI修正レーンを作成し、
担当種別`CI修正担当`として起動した`execute_model`の実装担当と単一の`exec-review`だけを実行する。新しい計画と計画レビューを作成しない。
起動と受領は`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`と`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`に従い、本タスクが当該レーンの呼び出し元となる。
原因commitに対応する計画契約が存在する場合は`レビュー基準: 計画`とし、当該契約の計画ファイル（メイン・詳細）を実行レビュー担当への入力として渡す。commitの生成主体と固定集合にある別計画の有無を、この判定に用いない。
原因commitに対応する計画契約が存在しない場合は`レビュー基準: CI記録`とする。初回のCI失敗では、原因分析結果、修正認可根拠、対象の検証結果、当該commitの変更目的、対象、公開契約及び入力計画の7項目を持つCI記録を起動文へ直接記載する。同じCI失敗処理から生成した計画なしCI修正commitが次のCI失敗の原因になった場合は、直前のCI記録を継承し、7項目を今回の原因commitと検証結果へ更新する。実行レビュー担当は当該CI記録から生成した`review_contract`を照合基準とし、入力計画を原因commitの計画照合に用いない。
レビュー指摘管理表は、`レビュー基準: 計画`では当該計画stemの表を用いる。`レビュー基準: CI記録`では、同じ再帰的CI失敗処理で既に終端工程用の独立CI実行レビュー表を作成していれば、原因commitが変わっても同じ表を継続する。存在しなければ最初の原因commit完全OIDから`ci-<原因commit完全OID>.exec-review.tsv`を一意に作成する。固定集合に別の計画が存在しても、その計画バンドルを照合基準又は表の保管先に用いない。
実行レビュー担当の起動前に、`レビュー基準: 計画`では渡す計画ファイル（メイン・詳細）の実在と表のstem一致を確認する。`レビュー基準: CI記録`ではCI記録の7項目の充足、独立表の起点OIDとファイル名の一致、及び継続時は直前に保持した表パスとの一致を確認する。CI記録自体のパスと実在は検査しない。
`レビュー基準: CI記録`のレビューが収束した後は、独立CI実行レビュー表を正式な保存操作でprivate-notesへcommit・pushし、正式な取得操作で保存実体を再取得して表を検証する。同じ保存操作で戻した後に作業側の消失とprivate-notesのclean状態を確認する。初回CI失敗、計画なしCI修正commit、再push、当該修正commitに起因する別のCI失敗、2回目の修正、実行レビュー収束、表の保存・再取得までを検証対象とする。

CI修正レーンは修正、検証、commitと実行レビューの収束後に統合へ進む。統合の起動、渡す入力及び検収は`${CLAUDE_PLUGIN_ROOT}/share/lane-integration.parent.md`に従い、`統合区分`へ`マージあり`を渡す。本タスクが当該レーンの直列許可を与える。
各マージ後かつ再push前に、直前にpushした完全OID以降の未push差分を版数規範へ照合する。
配布物のエンドユーザー向け振る舞いが変わった場合は、変更内容に応じた版数更新を追加で行い、正本manifest、派生manifest及び生成同期を再検査してから再pushする。
CI成功まで同じ原因別経路と再判定を反復し、既に`adopt`済みの元AWIへ重複したキュー操作をしない。

## 固有の終端工程

AWIが明示するPR又はMR、release、tag、配布等の終端工程は、受領した依存順に、pushとCI成功後に実行する。
これらの後へ`adopt`を延期する固有指示がある場合は、先行工程の成功を確認後に、AWIファイル名へ対応付けて受領した完全OIDで各AWIを`adopt`し、保存結果を照合する。複数レーンの完全OIDが異なる場合も、AWIごとの対応を維持する。

## 出力

自身が起動した全ての委譲先と外部プロセスの終了を、ツール終了結果か、保持した実行識別子の直接照会で確認してから、`終端完了`に続けて次の7行を返す。各値は返却の直前に実測して得た値とし、記憶又は推測で組み立てない。

```text
pushed_head: <`git -C <対象リポジトリの絶対パス> rev-parse <ベースbranch名>`で取得した、pushを完了した完全OID>
ci_result: <`pushed_head`のCIの結論。成功した場合は「成功」>
base_branch_state: <ベースbranchの観測結果。4つの観測項目が全て成立した場合は「公開済み」。成立しない項目がある場合は当該項目名をASCIIカンマ区切りで並べる>
version: <更新後の版数。更新しなかった場合は「bump不要」>
terminal_steps: <実行した固有の終端工程と対象をASCIIカンマ区切りで並べる。実行した工程が無い場合は「なし」>
deferred_adopted: <延期指示により`adopt`したAWIのファイル名をASCIIカンマ区切りで並べる。無い場合は「なし」>
released: <CI修正レーンで削除を確認したworktreeの絶対パス、branch名及びmanaged-tempの絶対パスをASCIIカンマ区切りで並べる。無い場合は「なし」>
```

この7行は`agent-toolkit/rules/02-agent-operations.md`が定める「返却形式の文面だけを出力し、地の文を加えない」規定の対象内であり、指定形式の一部として返す。
続行不能時はエスカレーション内容だけを返す。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
