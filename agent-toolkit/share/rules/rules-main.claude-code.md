# rules-main.claude-code.md: Claude Codeのメインエージェント向け規範

Claude Codeのメイン向けに`rules-main.md`のホスト差分を定める。

ホストの`Usage limit reached; a short grace allowance remains`で始まる猶予通知には、`agent-toolkit:user-confirmation-and-report`を起動し、状況伝達・続行・再開の手順を適用する。
続行を許可された猶予中は残工程を進め、再開禁止時はユーザーへ状況と必要な操作を伝える。
終了判断の`wait`は実待機、`blocked`は観測した技術的不成立に用いる。

## ツールの入出力

- Windows版Bashツールは、引用符付きheredoc・単一引用符内でも`\\`を`\`へ縮める。
  エスケープを含むコードはWriteでmanaged-tempのファイルへ保存して実行する。
- ユーザー向け本文は`mcp__agent-toolkit__send_to_user`の`message`で送る。
  拡張思考は表示未確認、地の文はAPIで要約され得るため送達に使わない。
  確認質問は`AskUserQuestion`を使う。
  Function hooks moduleでの登録名は`send_to_user`。
  遅延ツールならToolSearchの`select:mcp__agent-toolkit__send_to_user`で取得する。
  未提供なら最終応答に本文を書く。
  この送達手段で伝えた回答だけを、委譲入力・記録へ「回答済み」と書ける。

## 自身の会話の記録

- 自身のセッションID・transcript絶対パスは、SessionStartの「この会話のセッションID」「この会話のtranscript」を使い、圧縮・再開・clear・fork後は新しい通知値へ更新する。
  取り違えを防ぐため、更新時刻順・cwdからの推測名・MCPの`root_session_id`・委譲先IDで代えない。
- 通知で取得不能とされた値は、Bash・PowerShellの`CLAUDE_CODE_SESSION_ID`か、特定済みIDを渡す`atk run-script session-review-evidence -- --claude-session-id <ID>`で解決する。
- 自身の会話を委譲先へ証拠として渡すときもこの値を使う。
  過去・委譲先の会話は指定された識別子で取得する。

## ユーザー確認（`AskUserQuestion`）

- `AskUserQuestion`前に共通読込表の確認資料を読み、圧縮後は再取得する。
  同スキルの「確認要否の判定」を質問ごとに適用し、確認不要なら確定案と根拠を発話で報告する。
  - 質問・選択肢数はツールスキーマに従う。
    自由記述は各質問への回答、一般的な返答は別の`response`で受け取る。
  - 地の文の要約に備え、判断材料と直前の問いへの答えを質問本文か`preview`へ書く。
  - 推奨案は第1選択肢に`(Recommended)`を付ける。
    `共通前提:`・質問・選択肢は同スキル「確認の選択肢を組む手順」に従う。
- 質問・承認待ちでターンを終えるときは、地の文で尋ねた場合も`AskUserQuestion`で回答待ちを登録する。

## ターンの終え方

非同期処理が残らず作業を終える本文は準備印によらず日本語で確認し、途中待機の末尾は言語による遮断の対象から除く。
進捗率は共通の30分点検に限る。

- 空応答はホストに再生成を求められるため、待機だけで伝える内容がない場合と、`send_to_user`で送達し残工程も終えて通常ターンを閉じる場合は`…`を返す。
  送達ツールがなければ最終応答へ本文を書く。
  `/goal`を設定したセッションで、送達して残工程も終えて通常ターンを閉じる場合は、`…`の代わりに担当工程の完了を述べる1文を返す。
  目標の評価が最終応答の完了の記述を読むためであり、報告の全文の再出力は省く。
- `/goal`の目標評価は、自身が起動した未完了のAgent・Bashバックグラウンドタスクがある間だけ延期され、これらが無いターン終了時に始まる。
  背景MCP呼出しは延期条件に含まれない。
  技術的に進められる工程は同じターンで進める。
  実行中の出力は進捗確認とし、結果と区別する。
  独立工程を終えたら完了通知を待ち、受領後に全出力を確認する。
  goalの有無・対象によらず、待機と結果回収は`../../skills/delegation/references/waiting-and-monitoring-intervals.md`「待機区間の構成」に従う。
  未配送の完了通知は、同一セッション再開が保証され他のStop遮断要因が無ければ、次ターンで受けて保存出力・終了状態を回収する。
  再開保証の無い非対話起動は`rules-main.md`「ユーザー向け発話ルール」の待機項、他の遮断要因はその理由と結果受領の警告に従う。
  `/goal`を設定したセッションでは、待機する全対象の終了と結果回収を終えた後、最終ターンを閉じる前に、共通promptと一致する非durableの定期再確認taskを`CronList`で特定して`CronDelete`で削除する。
  目標の評価はStopの時点で残るtaskを未完了と判定し、modの自動回収はその評価より後にしか動かないためである。
  経過時間起動の義務を加えたtask、durableなtask、無関係なcron taskは削除の対象から除く。
  目標を設定していないセッションでは、modの自動回収に任せる。
- 計画ファイルは全モードで直接作成する。
  Plan modeの承認待ちへの移行はユーザー操作に委ね、切替後はホストの制約に従う。
