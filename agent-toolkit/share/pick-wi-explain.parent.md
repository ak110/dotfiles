# 選定理由の説明担当の起動と受領

```text
起動対象: pick-wi-explain.subagent.md
```

処理対象WIについて、包含、除外または構成の理由をユーザーが尋ねた場合に、メインが本書に従って読み取り専用の説明担当を起動し、結果を受領する。
説明担当の手順は`${CLAUDE_PLUGIN_ROOT}/share/pick-wi-explain.subagent.md`が定める。

## 起動

選定工程が終わった後でも同じく起動する。説明担当は`atk`を起動できないため、起動の前に`atk wi show --all --target-repo=<元の選定対象リポジトリの絶対パス> --state=active --skip-pull`を実行し、返った`保存先:`の絶対パスを受領まで保持する。`agents_server`の`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 元の選定対象リポジトリの絶対パス |
| `subagent_md_path` | `pick-wi-explain` |
| `extra_params` | 次の名前付き入力だけ |

- `説明対象の選定結果の出力先ファイル`: 元の`pick-wi.yaml`の絶対パス
- `activeなWI本文の保存先`: 起動の前に実行した`atk wi show`が返した`保存先:`の絶対パス
- `選定理由への質問`: ユーザーの問い

選定結果とactiveなWI本文は読取可能なUTF-8通常ファイルにする。起動側は各保存先がUTF-8の通常ファイルで読み取れるか確かめる。不足なら保存物の補完と`start`の再発行を案内する。選定内容とWI本文の対応の判断は説明担当が担う。

## 受領

`start`が返した`session_id`を`atk agents wait`で観測し、説明担当の結果から対象WIごとの規定上の根拠、技術的必要性、process-wiの同じ実行の中で扱う案と次の実行へ送る案のQCD比較、および推論の区別を検収してユーザーへ伝える。規定への適合だけを結論にしない。
規定の欠陥が判明した場合は処理対象WIを変更せず、メインが`agent-toolkit:bugfix`に従って同じセッションで是正する。
受領時に起動の前と同じ`atk wi show`を実行し、新旧の保存先の`### <ファイル名> [<状態>]`の見出しを比べて、起動前から受領時までのWI状態の変化を確かめる。WI状態の変化を観測した場合と、元の選定結果かレーン割当の変化が報告された場合は、説明の成果とみなさず、変化した主体と影響を調べる。固定済みの選定集合は、質問へ回答する間も変更しない。
