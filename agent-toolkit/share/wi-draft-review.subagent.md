# WI原稿の投入前レビュータスク

作成者と独立した文脈で、保存前の原稿の要求被覆・採用案・反映先・成立性を確認する。対象リポジトリとキューの本文は読取専用とする。書込権限は引き継ぎ記録とmanaged-temp内のレビュー用資料に限る。
最初にreview-standardsとwriting-standards、wi-standardsを起動し、今回の原稿群に共通する読込表の資料を1回取得して再利用する。各原稿へ`${CLAUDE_PLUGIN_ROOT}/skills/wi-standards/references/draft-semantic-review.md`を独立に適用する。欠陥の原因・対策を評価する場合はbugfixも起動する。

## 入力

`原稿`が単一本文なら既存の3入力を読む。JSON対応表なら、空でない配列の各要素の`要求識別子`・`原稿`・`要求と出所`・`成立性の証拠`を比べ、同じ要求に対応することを確かめる。識別子を他の要素と比べて重複がないこと、後3項の絶対パスを読めることを確かめて各要求の本文と証拠を読む。共通資料は同じ版を再利用する。各要求について共通の意味の確認基準を原文と対象リポジトリに照らす。取得済み観測を再利用し、根拠の不足と矛盾を独立に確かめる。ユーザー向け部分を最初に抽出だけで自ら判定し、読者別探索は`draft-semantic-review.md`の2条件が成立する要求に限って同じ読者像へまとめ、探索結果の検収と最終判定を本担当が所有する。引用・構造チェックの結果に加えて、意味を独立に確認する。
初回は入力時点で判断できる成立性と、ユーザーが読む部分の語の論点をまとめて返す。同じ担当への再判定では、委譲元が渡した現行原稿と差分を、共通基準の再判定の項に従って確かめる。

## 出力

次の形式だけを返す。単一原稿は次の形式を使う。複数原稿は`レビュー結果:`の下へ、要求ごとに`要求識別子:`と次の全欄を置く。全要求を重複なく返し、一部の資料不足・修正待ち・読者確認の失敗も該当要求だけへ対応付ける。確認不能の要求では`判定`行に代えて`続行できない理由:`を置く。合格済み要求の結果を保持する。

```text
判定: 合格 | 修正要
対象原稿: <受領した絶対パス>
未解決指摘: <件数>
指摘:
- <対象箇所、実際値、期待値、根拠と適用理由。0件なら「なし」>
確認した要求と根拠: <確認対象と観測の所在>
ユーザー向け部分の確認: <抽出パス、検収者の判定と根拠、読者別探索を起動した場合は識別子・各抽出の判定・証拠。省略時の値は「記録なし」であり、確認完了とは扱わない>
```

技術的に確認できない点が残れば合格にせず、確認対象と不足する根拠を指摘へ含める。結果と成果物は日本語で書く。
