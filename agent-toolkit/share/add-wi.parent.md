# WI投入担当の起動と受領

```text
起動対象: add-wi.subagent.md
```

投入する要求と現在の作業の対象が独立し、投入前の調査が本来の作業から外れる場合に、本書を全文読み、WI投入担当の起動、入力の受け渡し及び返却値の検収へ適用する。
呼び先の作業手順は`${CLAUDE_PLUGIN_ROOT}/share/add-wi.subagent.md`が定める。本書へ呼び先固有の作業手順を書かない。

## 起動経路

投入する全ての要求をまとめ、`agents_server`の`start`で1件の委譲先を起動する。
`subagent_md_path`には`${CLAUDE_PLUGIN_ROOT}/share/add-wi.subagent.md`を解決した絶対パスを渡す。
`extra_params`には`## 渡す入力`の名前付き入力、`cwd`には呼び出し元の作業ディレクトリの絶対パスを渡す。新しい設定キーを追加しない。

## 起動前の前提

要求ごとに、投入先の対象リポジトリと種別を確定していることを確認する。1つの要求が複数の投入先を持つ場合は、要求と投入先の組へ展開してから渡す。
投入先又は種別が欠ける要求は起動文へ含めない。
ユーザーの選好に依存すると既に判明している事項は、回答を得てから当該要求を渡す。回答を得られない事項を含む要求は起動文へ含めない。

## 渡す入力

- `投入する要求`: 要求ごとの識別子、投入先の対象リポジトリ、種別、要求の趣旨、投入前に確定すべき事項、及び保持している場合のユーザー発話の逐語本文と出所
- `引き継ぎ記録先`: `atk managed-temp create --prefix=handoff`で作成した領域の直下のファイルの絶対パス。セッションの管理対象一時領域が通知されている場合は`--session-root <通知された絶対パス>`を付けて作成し、当該子領域は個別に回収せずセッション終了時の回収へ委ねる。独立して作成した領域だけを、当該委譲の全工程の完了後に`atk managed-temp cleanup --path <当該領域の絶対パス>`で回収する

## 受領と検収

次の形式の返却を受領する。

```text
status: completed | needs_escalation
submissions:
- 要求: <呼び出し元が付けた要求の識別子>
  result: completed | needs_escalation
  type: awi | uwi
  filename: <投入したファイル名。既定値は「なし」>
  阻害要因: <needs_escalationの理由。既定値は「なし」>
```

`filename`と`阻害要因`は、値が既定値`なし`と一致する場合に当該行が出力されない。呼び出し元は当該行の不在を既定値`なし`として解釈し、欠落として扱わない。
`submissions`が挙げる要求の識別子が重複せず、その集合が起動文へ渡した要求の集合と過不足なく一致することを確認する。
全要求の`result`が`completed`の場合だけ全体の`status`が`completed`であり、1件以上が`needs_escalation`の場合は全体も`needs_escalation`であることを確認する。
`result`が`completed`の要求は、`filename`の行があり値が`なし`でないことと、`阻害要因`の行が無いことを確認する。続いて`atk wi show <filename> --target-repo=<当該要求の投入先> --skip-pull`が終了コード0で当該項目を返すことを確認する。保存本文を`agent-toolkit:wi-standards`の本文契約と照合し、必須の各節が規定順で存在することと、呼び出し元の会話文脈を参照せずに反映内容、反映先及び完成条件を判断できることを確認する。
`result`が`needs_escalation`の要求は、`阻害要因`の行があり値が`なし`でないことを確認する。阻害条件がユーザーの選好である場合は、呼び出し元が確認経路で回答を得る。

集合、全体の`status`、要求ごとの値、保存本文のいずれかの検収に失敗した場合は、同じWI投入担当へ不一致の修正を指示する。
阻害条件を解消した後は、失敗した要求だけを同じ担当へ渡して再開する。先に`completed`となった要求は再投入しない。
再開後の返却は、再開時に渡した要求の集合に対して同じ規則で検収する。
