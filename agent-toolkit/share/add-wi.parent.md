# WI投入担当の起動と受領

```text
起動対象: add-wi.subagent.md
```

エージェントが通常AWIを投入する場合と、投入済みAWIの内容（対象、範囲、完成条件などの本文）を更新する場合に、本書を全文読み、WI投入担当の起動、入力の受け渡しおよび返却値の検収へ適用する。
`agent-toolkit:process-wi`のレーン工程で上流リポジトリへの投入を要する項目も、同じ委譲で扱う。
呼び先の作業手順と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/add-wi.subagent.md`が定め、本書の記載対象から外す。

## 起動方法

WI投入担当はタスク文書起動（`agent-toolkit:delegation`の`references/base-contract.md`「タスク文書起動」）で起動し、次の単位で分ける。
委譲の目的は、起草を作業文脈の少ない担当へ移すことである。独立した要求を同じ担当へ足すと、先に扱った要求の調査結果と判断がその担当の文脈に残り、後の起草へ入り込む。

- 反映先と完成条件が他の要求と重ならず、単独で採否と実装を判断できる要求は、要求ごとに別の担当を起動する。互いに独立した担当は並行して起動してよい
- 次の要求の組は同じ担当へ渡す。1つの要求を投入先の組へ展開した全ての組（上流投入では同じ`元項目`の組）、`agent-toolkit:wi-standards`の`references/cross-repository-submission.md`が扱う同じ成果の整合を要する組、依存で結ばれた要求（先行項目の正式名を待つ後続を含む）
- 起動後に独立した要求が生じた場合は、新しい担当を起動する。稼働中の担当と終端済みの担当のどちらへも`send_message`で追加しない
- 同じ担当へ追送するのは、その担当へ渡した要求の要件更新と、「受領と検収」が定める修正と再開に限る

`cwd`は呼び出し元の作業ディレクトリの絶対パスとし、上流投入では元項目を保持する対象リポジトリの絶対パスとする。

## 起動前の前提

要求ごとに、投入先の対象リポジトリと種別を確定していることを確認する。1つの要求が複数の投入先を持つ場合は、要求と投入先の組へ展開してから渡す。
投入先または種別が欠ける要求は起動文へ含めず、確定してから渡す。
認識の違いで要件や結果が変わる未確定事項は、回答を得てからその要求を渡す。回答を得られない事項を含む要求は起動文へ含めず、回答の受領まで保留する。

## 渡す入力

- `投入する要求`: 要求ごとの識別子、投入先の対象リポジトリ、種別、要求の趣旨、投入前に確定すべき事項、`source`、および保持している場合のユーザー発話の逐語本文と出所
  - `source`は呼び出し元が`agent-toolkit:wi-standards`「由来と承認」に従って決めた値（`add-awi-by-user`、`session-review`、`process-wi`、対応するスキルを持たない起票では`agent`など）とする
  - 出所には逐語本文と確認回答（質問、提示した全選択肢、実際に選ばれた選択肢、自由記述）を保持する記録ファイルの絶対パスを含める
  - 投入済みAWIを更新する要求と失敗後に再開する要求では、更新または修復する項目の`filename`も渡す。既存AWIの更新では、呼び出し元が`atk wi hold`で保留してから渡し、保存本文の検収後に`atk wi unhold`を実行する
- 上流投入の要求では、`元項目`（元項目のAWIファイル名）と`投入条件`も渡す。`upstream_target_repo`が複数の投入先を含む場合は、元項目と投入先の組へ展開する
- `引き継ぎ記録先`: 値は`agent-toolkit:delegation`の`references/base-contract.md`「タスク文書起動」が指す`引き継ぎ記録先`の書式に従う

## 受領と検収

返却の形式、既定値および省略規則は`${CLAUDE_PLUGIN_ROOT}/share/add-wi.subagent.md`の`## 出力`が定める。呼び出し元は次を確認する。

- `submissions`が挙げる要求の識別子が重複せず、その集合が起動文へ渡した要求の集合と過不足なく一致する
- 全体の`status`が、要求ごとの`result`から同書の規則どおり導かれている
- `result`が`completed`の要求は`filename`が値を持ち、投入先を絶対パスまたは正規化リモートURLで渡した`atk wi show <filename> --target-repo=<その要求の投入先> --skip-pull`が終了コード0でその項目を返す。保存本文が`agent-toolkit:wi-standards`の本文契約を満たし、呼び出し元の会話文脈と元項目を参照せずに反映内容、反映先および完成条件を判断できる
- 同じ保存本文の反映内容と完成条件が、渡した要求（確定した要件と逐語本文）と一致する。案を確定した呼び出し元が起草者の成果を確かめる工程であり、起草者と別の主体による確認をこの検収が担う
- `result`が`condition_not_met`の要求は`条件判定`が不成立の条件、調査対象および実際の確認結果を示す。その要求を投入先のファイル名を用いる後続工程から除く
- `result`が`needs_escalation`の要求は`阻害要因`が値を持つ。阻害条件が認識の違いで要件または結果を変える未確定事項である場合は、呼び出し元がユーザー確認して回答を得る。上流投入では、その要求を含む元項目のレーンを起動せず、元項目の状態も変更せずに阻害条件の解消まで保留する

いずれかの検収に失敗した場合は、同じWI投入担当へ不一致の修正を指示する。
阻害条件を解消した後は、失敗した要求だけを同じ担当へ渡して再開する。先に`completed`か`condition_not_met`となった要求は再投入せず、その結果を保持する。
保存済みの`filename`がある失敗要求はその値も渡し、既存の保存先を同じ投入手順で修復させる。既存AWIの更新と同じ入力の形である。
再開後の返却は、再開時に渡した要求の集合に対して同じ規則で検収する。
