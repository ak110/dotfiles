# 読者別探索担当の起動と受領

```text
起動対象: reader-fit-review.subagent.md
```

文章成果物を含むレビューで、レビュー担当が本書に従って読者別探索担当を起動し、結果を受領する。
読者別探索担当の観点と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/reader-fit-review.subagent.md`が定める。

## 起動

読者別探索担当の起動を省ける差分は、読み手の判断基準、手順、条件または適用範囲を変えない差分とする（努力目標。通常のレビューと重複する起動の費用を避ける）。
誤記、空白、Markdown整形、意味が一意な参照の訂正、既存の文の中で語や呼称を数語直す文言修正などの意味を変えない修正と、コードコメントの差分がこれに当たり、通常のレビューで扱う。コードコメントは文脈混同が起こり得ても重要度が低く、独立した探索の起動と指摘の往復に見合わない。
既存の規定への文や項目の追加、削除、統合、一般化と、条件、手順、判断基準や例示の変更は、行数や文の数が少なくても起動し、省けるか迷う差分も起動する。差分の規模で判断すると、読み手の判断や手順を変える差分から独立した探索が外れ、書き手が気付かなかった読み手の誤解がそのまま残る。

読者ごとに1件ずつ読者別探索担当を起動し、並行させる。

`agents_server`の`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 成果物を含む作業ツリーの絶対パス |
| `subagent_md_path` | `reader-fit-review` |
| `extra_params` | 次の名前付き入力だけ |
| `model_type` | 実行レビュー担当が対象WIの`担当モデル.実行レビュー担当`を受領した場合はその値（指定値と実際値の比較と記録は`agent-toolkit:delegation`の`references/runtime-routing.md`「工程別モデル設定」の担当モデルの段落）。受領しない場合は渡さない |

- `成果物`: 成果物の絶対パスと行数。private-notesにあるWIでは、ファイル名と取得コマンド
- `種別`: 成果物の種別
- `読者像`: その成果物を読む主体と、その主体が既に知っている事柄
- `修正範囲`: 変更前と現行の取得先、今回差分、変更した識別子・契約の直接影響範囲。新規文書・新規回答は新規であることと全文を差分として示す。Git管理外の既存文書・回答下書きはmanaged-tempへ保存した旧本文と比較する

初回も今回差分と直接影響範囲を点検対象とし、全文は文脈の理解に使う。
再レビューでは、起動前に修正範囲と未解決事項から読者ごとの再点検対象を確定する。再点検対象が無い読者は探索を再起動せず、その根拠を自身の走査結果へ残す。再点検対象がある読者には次の入力も渡す。

- `レビュー種別`: `再レビュー`
- `修正範囲`: 前掲の値を前回確認版と現行版の取得先および差分へ更新し、変更した契約の直接影響範囲と、そのうち前回未走査または証拠不足だった範囲を示す。前回確認版は、Gitでは前回レビューしたcommit、Git管理外の文書や質問への回答下書きではmanaged-tempへ複製した前回本文とする
- `未解決事項`: 対象の読者に関係する前回指摘の箇所、違反した規定、発生条件、根本原因、要求した検収手段、応答と検証証拠の取得先。該当する事項が無ければ`なし`

入力や比較元が欠ける場合は不足情報を委譲元へ返し、補完後に起動する。

## 受領

結果は引数なしの`atk agents wait`で受け取る。
起動した読者ごとに終端statusと返却本文を確認する。失敗・本文欠落は結果未取得として扱う。失敗では公開waitの`next_action`と`agent-toolkit:delegation`の`references/runtime-routing.md`が定める回復手順に従い、同じ読者の回復後の結果を受領する。必要結果が回復後も揃わなければ、欠落した読者と再開に必要な事項を`続行できない理由`へ示して工程を止める。完了には失敗の通知に加えて必要な読者の結果の回収を要する。
各指摘の裏付けを成果物の本文と適用する契約で確かめ、採否と根拠、採用分の記録先または不採用理由を自身のレビュー記録へ残す。
同じ原因の既存指摘へ統合する場合も、対応先を示す。
正常終端で本文を持つ`未解決の指摘数: 0`の返却では対応付ける指摘が無いことを記録する。起動前に既存基準で再点検不要と判断した読者は、結果欠落として数える対象から外す。
差分と直接影響範囲の外にある既存不良は想定外事象として、新しい要件はその旨を委譲元へ渡す。通常の未解決件数へ数える対象は、差分と直接影響範囲にある既存要件の指摘に限る。
再レビューで返った初回レビューの不足は通常の再レビュー指摘と区別して委譲元へ返し、不足入力は補完を求める。
