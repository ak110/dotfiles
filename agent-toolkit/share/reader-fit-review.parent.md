# 読者別探索担当の起動と受領

```text
起動対象: reader-fit-review.subagent.md
```

文章成果物を含むレビューで、レビュー担当が本書に従って読者別探索担当を起動し、結果を受領する。
読者別探索担当の観点と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/reader-fit-review.subagent.md`が定める。

## 起動

初回はレビュー開始時点からレビューHEADまでに追加・変更した全ての`.md`・`.md.tmpl`を対象にする（削除は除き、改名は新しいパスで扱う）。誤記や整形だけの差分も意味で選別せず対象に含める。
コードコメントは通常のレビューで扱う。Git管理外の文章成果物と回答下書きは、新規・修正範囲の入力で起動する。

読者ごとに1件ずつ起動し、並行させる。`agents_server`の`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 成果物を含む作業ツリーの絶対パス |
| `subagent_md_path` | `reader-fit-review` |
| `extra_params` | 次の名前付き入力だけ |
| `model_type` | 実行レビュー担当が対象WIの`担当モデル.実行レビュー担当`を受領した場合はその値（比較と記録は`agent-toolkit:delegation`の`references/runtime-routing.md`「工程別モデル設定」の担当モデルの段落）。受領しない場合は渡さない |

- `成果物`: 成果物の絶対パス。private-notesにあるWIでは、ファイル名と取得コマンド
- `種別`: 成果物の種別
- `読者像`: その成果物を読む主体と、その主体が既に知っている事柄
- `修正範囲`: 変更前と現行の取得先、今回差分、変更した識別子・契約の直接影響範囲。新規文書・新規回答は新規であることと全文を差分として示す。Git管理外の既存文書・回答下書きはmanaged-tempへ保存した旧本文と比較させる

再レビューでは、前回と今回の開始時点からそれぞれのレビューHEADまでのファイル別差分を比べ、差分が同一のファイルだけ`再点検対象なし`として再起動を省ける。rebaseで開始時点が変わった場合も両方の差分を比べ、空白を含む変更があるファイルは起動する。再点検対象がある読者には次も渡す。

- `レビュー種別`: `再レビュー`
- `修正範囲`: 前回確認版（Gitでは前回レビューしたcommit、Git管理外ではmanaged-tempへ複製した前回本文）と現行版の差分へ更新し、そのうち前回未走査または証拠不足だった範囲も示す
- `未解決事項`: その読者に関係する前回指摘の箇所、違反した規定、発生条件、根本原因、要求した検収手段、応答と検証証拠の取得先。無ければ`なし`

行数は読む担当が実体から取得する。入力や比較元が欠ける場合は補完してから起動する。
実行レビューの返却では、ファイルごとに起動したsessionのUUID配列か再点検の省略をJSONで申告する。形式とGit差分との対応は`exec-review-evidence-check --help`の`--reader-fit-review`、`--review-start`と前回確認版の入力に従い、Git管理外の申告は同じJSONの`external`へ書く。

## 受領

結果は引数なしの`atk agents wait`で受け取り、読者ごとに終端statusと返却本文を確かめる。失敗・本文欠落は結果未取得とし、公開waitの`next_action`と`agent-toolkit:delegation`の`references/runtime-routing.md`の回復手順で同じ読者の結果を回収する。回復後も揃わなければ、欠落した読者と再開に必要な事項を`続行できない理由`へ示して工程を止める。起動前に再点検不要と判断した読者は欠落に数えない。

各指摘の裏付けを成果物の本文と適用する契約で確かめ、採否と根拠、採用分の記録先または不採用理由（同じ原因の既存指摘へ統合する場合は対応先）を自身のレビュー記録へ残す。`未解決の指摘数: 0`の返却も対応付ける指摘が無いことを記録する。
未解決件数へ数えるのは差分と直接影響範囲にある既存要件の指摘に限る。範囲外の既存不良は想定外事象として、新しい要件はその旨を、再レビューで返った初回レビューの不足は通常の指摘と区別して、それぞれ委譲元へ渡す。
