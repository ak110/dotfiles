# 読者別探索担当の起動と受領

```text
起動対象: reader-fit-review.subagent.md
```

文章成果物を含むレビューで、レビュー担当が本書に従って読者別探索担当を起動し、結果を受領する。
読者別探索担当の観点と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/reader-fit-review.subagent.md`が定める。

## 起動

実行レビュー担当が対象WIの`担当モデル.実行レビュー担当`を受領した場合、読者別探索担当の起動にも同じ`model_type`を指定する。受領しない場合は工程別設定を使う。終端結果の指定値と実際のモデルを引き継ぎ記録へ残す。

読者ごとに1件ずつ読者別探索担当を起動し、並行させる。

`agents_server`の`start`を次の引数で呼ぶ。起動の定型と適用する義務は`agent-toolkit:delegation`の「`<役割名>.parent.md`を持つ委譲の起動」に従う。

| 引数 | 値 |
| --- | --- |
| `cwd` | 成果物を含む作業ツリーの絶対パス |
| `subagent_md_path` | `reader-fit-review` |
| `extra_params` | 次の名前付き入力だけ |
| `mode` | 指定しない |
| `model_type` | 前段の`担当モデル.実行レビュー担当`を受領した場合はその値、受領しない場合は指定しない |

- `成果物`: 成果物の絶対パスと行数。private-notesにあるWIでは、ファイル名と取得コマンド
- `種別`: 成果物の種別
- `読者像`: その成果物を読む主体と、その主体が既に知っている事柄

初回はこの3入力から成果物全体を点検する。
再レビューでは、起動前に読者ごとの再点検対象を確定し、次の入力も渡す。

- `レビュー種別`: `再レビュー`
- `修正範囲`: 前回確認版と現行版の取得先および差分、変更した識別子・契約から導く直接影響範囲、そのうち前回未走査または証拠不足だった範囲
- `未解決事項`: 対象の読者に関係する前回指摘の箇所、違反した規定、発生条件、根本原因、要求した検収手段、応答と検証証拠の取得先。該当する事項が無ければ`なし`

Gitの前回確認版は前回レビューしたcommitから取得し、Git管理外の文書や質問への回答を記録したUWIでは前回本文のmanaged-tempへの複製を使う。
修正範囲と未解決事項の双方から再点検対象が無いと確定した読者は、探索を再起動せず、その根拠を自身の走査結果へ残す。
入力や比較元が欠ける場合は不足情報を委譲元へ返し、補完後に起動する。

読者別探索担当の起動を省ける差分は、読み手の判断基準、手順、条件または適用範囲を変えない差分とする（努力目標。通常のレビューと重複する起動の費用を避ける）。
コードコメントの差分と、誤記、空白、Markdown整形、意味が一意な参照の訂正、既存の文の中で語や呼称を数語直す文言修正がこれに当たり、通常のレビューで扱う。
コードコメントでも文脈混同は起こり得るが、重要度が低く、独立した探索の起動と指摘の往復に見合わないためである。
既存の規定へ文や項目を追加、削除、統合、一般化のいずれかをする差分と、条件、手順、判断基準や例示を変える差分は、行数や文の数が少なくても起動する。
省けるか迷う差分も起動する。
省けるかを差分の規模で判断すると、読み手の判断や手順を変える差分から独立した探索が外れ、書き手が気付かなかった読み手の誤解がそのまま残る。

## 受領

結果は引数なしの`atk agents wait`で受け取る。
各指摘の裏付けを成果物の本文と適用する契約で確かめ、採否と根拠、採用分の記録先または不採用理由を自身のレビュー記録へ残す。
同じ原因の既存指摘へ統合する場合も、対応先を示す。
`未解決の指摘数: 0`の返却では対応付ける指摘が無いことを記録する。
再レビューで返った初回レビューの不足は通常の再レビュー指摘と区別して委譲元へ返し、不足入力は補完を求める。
