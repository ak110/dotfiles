# 読者別探索担当の起動と受領

```text
起動対象: reader-fit-review.subagent.md
```

文章成果物を含むレビューで、レビュー担当が本書に従って読者別探索担当を起動し、結果を受領する。
読者別探索担当の観点と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/reader-fit-review.subagent.md`が定める（所在参照）。

## 名指し参照の読込方法

名指し参照は`read-trigger-contract.md`「名指し参照の読込方法」に従う。

## 起動

初回はレビュー開始時点からレビューHEADまでに追加・変更した全ての`.md`・`.md.tmpl`を対象にする（削除は除き、改名は新しいパスで扱う）。誤記や整形だけの差分も意味で選別せず対象に含める。文章の品質に影響する対象を省くか縮めるかと、見つかった問題を処置するかは`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「QとC・Dの区別」で判定し、費用や所要だけを理由にしない。
コードコメントは通常のレビューで扱う。Git管理外の文章成果物と回答下書きは、新規・修正範囲の入力で起動する。
同じレーンに複数の計画がある場合は、そのレビューの`review_contract`の`別計画の認可`条項が挙げる他計画のcommitを除いた判定対象commitが変えた範囲を対象にする。どの計画にも属さないcommitも対象に含める。他計画のcommitだけが変えた文書は対象から外し、両計画が変えた文書の`修正範囲`には自計画の差分だけを渡す。同じ行を複数計画が変えた場合は最終変更commitへ帰属させる。他計画の記述の前提を自計画が変えた場合は、自計画の差分の直接影響範囲として扱う。

起動単位は本書が所有する。通常リスクを含め、同じ読者像で確認できる用意済みの文書群は、既存の`成果物`配列と各ファイルに1対1の`比較資料`でまとめる。読取量、共通文脈、読者像の違いと確認品質から集合を分割し、全対象・読者ごとの独立判断を保持する。初回・再レビュー・引き継ぎ再レビュー、Git管理下・管理外と回答下書きに同じ契約を適用する。対象ごとの比較元・現行本文・完全差分・判定・指摘・証拠を保持し、集合起動の識別子を各ファイルの申告へ対応付ける。再点検の省略は後掲の既存条件でファイル別に判断する。
起動と終端観測は`agent-toolkit:delegation`の`references/runtime-routing.md`「実行手段」に従う。
`agents_server`を使えない場合のCodex組み込み代替は、`spawn_agent`へ`fork_turns: "none"`を指定して独立した文脈で起動する。
`agents_server`では`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 検証対象の作業ツリーの絶対パス（保存本文でも参照先を判定する対象版） |
| `subagent_md_path` | `reader-fit-review` |
| `extra_params` | 次の名前付き入力だけ |
| `model_type` | 実行レビュー担当が対象WIの`担当モデル.実行レビュー担当`を受領した場合はその値（比較と記録は`agent-toolkit:delegation`の`references/runtime-routing.md`「工程別モデル設定」の担当モデルの段落）。受領しない場合は渡さない |

- `成果物`: 成果物の単一絶対パス、または空でない絶対パスのJSON配列。成果物がWIの場合は、担当自身がそのファイル名を`atk wi show --skip-pull <ファイル名>`（リモートと同期しない指定）へ渡して取得できる。同じ版を固定する必要がある成果物は、委譲元が保存した本文の絶対パスを渡す
- `種別`: 成果物の種別
- `読者像`: その成果物を読む主体と、その主体が既に知っている事柄
- `修正範囲`: 比較元と現行版の識別子（Git管理下はOID、Git管理外は旧本文の複製と現行本文の絶対パス）と、変更した識別子・契約の直接影響範囲。新規文書・新規回答は新規であることと全文を差分として示す。`atk`でしか得られない本文のうち同じ版を固定する必要があるものは、委譲元が`atk wi show`などで取得して自分のセッションのmanaged-tempへ保存する
- `比較資料`: Git管理下の成果物では`{"repository":"/repo","base":"<比較元OID>","head":"<レビューHEAD>","paths":["文書.md"]}`を渡し、`paths`は全成果物のリポジトリ相対パスとする。担当は同じOIDの本文と差分を`git show`・`git diff`で読む。起動側は全成果物の集合と対象HEADの本文が現行本文へ一致することを起動前に確かめる。計画別の判定範囲がある場合は同じオブジェクトへ`判定範囲差分`として、`paths`の各パスから判定範囲だけの差分を保存したファイルの絶対パスへの対応を加える。Git管理外の文書と回答下書きでは`{"比較元本文":"/保存先/before.md","今回差分":"/保存先/change.patch","現行本文":"/成果物.md"}`、または同じ3項目のオブジェクト配列を渡す。複数成果物では配列を渡し、各成果物へ現行本文が1件ずつ対応するようにする（欠落・過剰・重複は拒否される）。3項目は読取可能なUTF-8通常ファイルの絶対パスとし、現行本文を`成果物`と同じパスにする。今回差分は比較元本文と現行本文の本文間の完全な差分とし、起動側は比較元本文へ適用した結果が現行本文と一致しない資料を拒否する。初回の新規成果物だけ`{"比較元本文":"新規","今回差分":"全文","現行本文":"/成果物.md"}`を使える。再レビューと引き継ぎ再レビューの比較元は前回確認版（Git管理下では前回のレビューHEAD、Git管理外では前回本文の複製）にする

集約起動では`修正範囲`にもファイルごとの比較元・現行本文・今回差分を対応付け、全対象を渡す。
成果物とその参照する実装・文書・CLIの存否と挙動は、受領する絶対パスと対象worktreeまたは保存版で判定する。
担当自身が使うスキルと実行基盤（agent-toolkitの配布物）の置き場所は対象版の判定に使わず、そこでの不在を対象版の不在の根拠にしない。

Git管理下の対象は`git diff --name-only --diff-filter=d <今回の開始時点> <レビュー対象HEAD> -- '*.md' '*.md.tmpl'`で求める。起動前に、レビュー対象HEADをcheckoutした作業ツリーで各対象の本文がHEADと一致する（`git diff --quiet <レビュー対象HEAD> -- <パス>`が終了0）ことを確かめる。`review_contract`の判定対象外commitがある場合は、パスごとに自計画の判定対象commitの`git show --format= <commit> -- <パス>`を順に保存して`判定範囲差分`とする。判定範囲の差分が空のファイル（計画外の変更のみ）も、省略の条件を満たさなければ起動する。読者別探索の申告には`paths`のリポジトリ相対パスを使う。
起動側は指定形式と保存物の読取可能性を確かめ、欠落や参照不能なら補完と`start`の再発行を案内する。

再レビューでは、前回と今回の開始時点からそれぞれのレビューHEADまでのファイル別差分を、それぞれの`review_contract`の判定範囲で比べる。
差分と契約境界が同一のファイルだけ`再点検対象なし`として再起動を省ける。
前回契約が無い旧入力は従来の比較を使い、契約境界が変わった箇所は再点検する。
rebaseで開始時点が変わった場合も両方の差分を比べ、空白を含む変更があるファイルは起動する。再点検対象がある読者には次も渡す。

- `レビュー種別`: `再レビュー`
- `修正範囲`: 前回確認版（Gitでは前回レビューしたcommit、Git管理外では自分のセッションのmanaged-tempへ複製した前回本文）と現行版の比較へ更新し、そのうち前回未走査または証拠不足だった範囲も示す。Git管理下では`比較資料`の`base`を前回レビューしたcommitにする
- `未解決事項`: その読者に関係する前回指摘の箇所、違反した規定、発生条件、根本原因、要求した検収手段、前回指摘への応答（採否と不採用理由、範囲外とした場合の割当先）と検証証拠を持つファイルの絶対パス（コマンドで得る証拠は出力を自分のセッションのmanaged-tempへ保存して渡す）。複数は絶対パスのJSON配列にし、説明は保存物へ書いて値にはパスだけを渡す（パスと説明を連結した値は起動前に拒否される）。無ければ`なし`

行数は読む担当が実体から取得する。入力や比較元が欠ける場合は補完してから起動する。
実行レビューの返却では、ファイルごとに起動結果の識別子の配列か再点検の省略をJSONで申告する。
識別子は`agents_server`の`session_id`（UUID）、Claude Codeの`Agent`ツールのagent ID（16進列、`agent-`付き16進列）、Codexの組み込み委譲`spawn_agent`が返す`task_name`（`/root/<名前>`のagentのパス）を受理する。組み込み委譲で起動した場合は返却の`task_name`をそのまま申告する。集約起動では各ファイルへ同じ起動結果の識別子を記す。
申告の形式と対象集合は実行レビュー担当の返却契約が定め、Git差分の対象は今回の開始時点からレビューHEADまでの変更`.md`・`.md.tmpl`から`review_contract`の判定対象外commitだけが変えたファイルを除いた集合とする。
Git管理外の対象集合は、回答下書きの絶対パスと`Git管理外の変更`の元ファイルのうち`.md`・`.md.tmpl`の絶対パスとする。申告の`external`は対象集合の絶対パスごとに`{"sessions":["<起動結果の識別子>"]}`または`{"omission":"再点検対象なし","previous":"/前回本文の複製.md"}`を持つオブジェクトとする。後者はround 2以上で、前回本文の複製と現行本文のバイト列が一致する場合だけ使える。対象集合と申告の欠落・過剰は委譲元の受領確認で差し戻される。`文章成果物なし`はGit差分の対象とGit管理外の対象集合がともに空の場合に限る。

## 受領

結果は選択した起動手段の終端観測で受け取り、読者ごとに終端statusと返却本文を確かめる。
`agents_server`では引数なしの`atk agents wait`を使う。
`Agent`ツールの起動と終端観測は`agent-toolkit:delegation`の`references/runtime-routing.md`「実行手段」に従う。
一部の資料不足・失敗・本文欠落は対象と読者ごとの結果未取得とし、起動手段が示す次の操作と同書の回復手順で同じ読者の結果を回収する。
回復後も揃わなければ、欠落した読者と再開に必要な事項を`続行できない理由`へ示して工程を止める。
起動前に再点検不要と判断した読者は欠落の対象外とする。
入力不足や資料の対応の不成立で止まった探索は、資料を補完して同じ読者の探索を再起動し、範囲を確定できなかった探索の判定を今回の完了に使わない。補完できなければ必要な資料と理由を`続行できない理由`へ示して委譲元へ返す。前回の探索結果と現行差分の直接確認だけでは今回の独立探索の完了は成立しない。再点検の省略は前掲のファイル別差分の一致によってのみ判定し、資料不足は省略条件に含めない。

各指摘の裏付けを成果物の本文と適用する契約で確かめ、採否と根拠、採用分の記録先または不採用理由（同じ原因の既存指摘へ統合する場合は対応先）を自身のレビュー記録へ残す。`未解決の指摘数: 0`の返却も対応付ける指摘が無いことを記録する。
採否は指摘が根拠とした作成規範の条文に本文が反するか、読者像が本文だけから行為者・対象・条件・結果を一意に読めず判断・操作・検証を誤るか進めないかで判定する。文章成果物の実害は`agent-toolkit:review-standards`の両役割に共通する規定に従う。計画・WIの完成条件の充足や、機能上の害が無いこと、説明の追加を求める指摘であることだけを不採用の理由にしない。説明の追加の要否は`agent-basics:writing-standards`の`references/writing.md`「文章の共通規定」の情報を加える前の判定で決める。作成規範への違反は既存要件の指摘として扱う。不採用理由は指摘ごとに、条文の非該当・範囲外・事実の誤りのいずれかと、その根拠を記録する。
未解決件数へ数えるのは差分と直接影響範囲にある既存要件の指摘に限る。範囲外の既存不良は想定外事象として、新しい要件はその旨を、再レビューで返った初回レビューの不足は通常の指摘と区別して、それぞれ委譲元へ渡す。
