# レーン担当の起動と受領

```text
起動対象: exec.subagent.md
```

メインが`agent-toolkit:process-wi`のレーンを実行する際、本書に従ってレーン担当を起動し、計画作成完了、実装完了及びエスカレーションを受領する。
レーン担当は計画の起草、実装、近接検証、commit、レビュー修正、統合を同じthreadで担う。
レーン担当自身の手順は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`を正本とする。

## 入力

起動文の1行目で`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`を指し、`agents_server`の`start`へ`model_type="execute"`を渡して起動する。
必須入力の項目名は、本書冒頭の`起動対象:`が挙げる受信者の`必須入力名:`が並べるものとし、起動文の構成と列挙形式は`agent-toolkit:delegation`のSKILL.mdの`## 送信`が定める。
各項目の値は次のとおり確定する。

- `担当種別`: `レーン担当`。公開工程のCI失敗修正では`CI修正担当`
- `起動経路`: `agent-toolkit:process-wi`
- `対象worktree`: 当該レーンの専用worktreeの絶対パス。用途、管理対象領域の絶対パス、作成時のHEAD完全OID、作成主体、所有主体、回収対象及び専用branch名を同じ形式で併記する
- `プロジェクト規範`: 対象リポジトリの`AGENTS.md`の絶対パス
- `AWIファイル名一覧`: pickerが確定した順序を保持したAWIファイル名一覧と、各AWIの`origin`。`upstream_submission`が`混在`の項目では上流へ投入済みの要求と対象リポジトリ側で計画する要求の対応も併記する
- `固有指示`: AWI固有の処理順、公開、確認又は検証指示。無い場合は`なし`
- `再開位置`: 中断したレーンを再開する場合に、作業rootに残る計画ファイルの絶対パス。新規のレーンでは`なし`
- `作成規範`: 対象リポジトリのプロジェクト規範が指定する作成規範スキルの名称
- `複製元`: 複製元のリポジトリルートの絶対パス
- `対象外worktree`: 対象外worktreeの絶対パス
- `git操作に用いるworktree`: `対象worktree`と同じ値
- `引き継ぎ記録先`: `atk managed-temp create --prefix=handoff`で作成した領域の直下のファイルの絶対パス。当該委譲の全工程の完了後に`atk managed-temp cleanup --path <当該領域の絶対パス>`で回収する
- `権限`: commit可、ffマージ可、作業対象リポジトリへのpush不可。`git diff`、`git show`、`git log`、`git status`など作業ツリーを変更しないGitの調査操作は、許可する操作の列挙にかかわらず常に許可する。`agent-toolkit/rules/02-agent-operations.md`の`対象リポジトリとキュー管理リポジトリの区別`節のとおり、`atk`がキュー管理リポジトリへ行う反映は当該権限の対象外とする

`権限`の行は本書の文面のまま起動文へ写し、言い換え、要約又は操作名の列挙への縮小をしない。
`CI修正担当`では、上記のうち`AWIファイル名一覧`、`固有指示`及び`再開位置`を渡さず、起動文へ直接記載する`CI記録`を渡す。`CI記録`の構造は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`の`## 入力`が定め、原因分析結果、修正認可根拠、対象の検証結果、変更目的、対象、公開契約、入力計画の7項目がそろっていることを起動前に確認する。

## 計画作成完了の受領

レーン担当は計画ファイルを作成した時点で`計画作成完了`と計画ファイルの絶対パスを返し、メインの応答を待つ。
メインは当該計画ファイルの`## 概要`と`## 実施内容`を読み、次を確認する。計画ファイルの他の節、AWI本文及び対象実装は読まない。

- `## 実施内容`の各AWI行の`由来`が、pickerが返した`origin`と一致する。一致しない場合は当該行と`origin`を示して差し戻す
- 人間由来のWIに不採用の範囲が1件でも含まれる場合は、行全体の採否値にかかわらず、当該範囲、原文との差異、技術的理由及び代替案をユーザーへ示して確認する。不採用の範囲の有無は`採否`列の値だけで判定せず、`部分採用`の行は`根拠`列を読んで判定する。確認を得るまで実装開始を返さない。回答を得られない場合の扱いは`agent-toolkit:wi-standards`と`agent-toolkit:process-wi`の`skills/process-wi/references/run-lanes.md`「採否の確定と終端区分」に従う
- 採用する実施範囲を持つAWI行が1行以上あるかを判定し、レーンの統合区分を`マージあり`又は`マージなし`と確定する

確認の完了後に、同じレーン担当threadへ`実装開始`又は`実装なし`のいずれか1行を返す。`実装なし`を返したレーンでは実装と実行レビューを行わず、`${CLAUDE_PLUGIN_ROOT}/share/lane-integration.parent.md`に従って統合指示を送る。

## 実装完了の受領

レーン担当は全ての実装をcommitした後に`実装完了`と`検証結果`を返す。
メインは`検証結果`を伴わない完了値を受領した場合、実行レビューへ進まず、同じthreadへ当該記録の返却を求める。
`検証結果`を受領した後、対象worktreeのHEADをレビュー対象とし、`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`に従って実行レビューへ進む。
レビュー修正はレーン担当の同じthreadへ返し、新しい修正担当を起動しない。

## エスカレーションの受領

レーン担当から`needs_escalation`を受領した場合は、`${CLAUDE_PLUGIN_ROOT}/share/review-loop-coordination.md`の`## エスカレーションの事由別の扱い`に従って区分し、回答だけを同じthreadへ返す。
ユーザーの選好に依存する判断は確認経路へ送り、回答を受領してから返す。
同じthreadを継続できない場合の扱いは`agent-toolkit:delegation`の経路選択契約に従い、新しいレーン担当を起動する場合は`再開位置`へ作業rootの計画ファイルの絶対パスを渡す。
