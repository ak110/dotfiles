# レーン担当の起動と受領

```text
起動対象: exec.subagent.md
```

メインが`agent-toolkit:process-wi`のレーンを実行する際、本書に従ってレーン担当を起動し、計画作成完了、実装完了及びエスカレーションを受領する。
レーン担当は計画の起草、実装、近接検証、commit、レビュー修正、統合を同じthreadで担う。
レーン担当自身の手順は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`を正本とする。

## 入力

`agents_server`の`start`へ`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`を解決した絶対パスを`subagent_md_path`、次の名前付き入力を`extra_params`、対象worktreeの絶対パスを`cwd`として渡す。
必須入力の項目名は`担当種別`と`引き継ぎ記録先`とする。
各項目の値は次のとおり確定する。

- `担当種別`: `レーン担当`。公開工程のCI失敗修正では`CI修正担当`
- `選定結果の出力先ファイル`: pickerが返した固定出力ファイルの絶対パス
- `レーン識別子`: pickerが当該レーンへ割り当てた識別子
- `固有指示`: AWI固有の処理順、公開、確認又は検証指示。無い場合は当該行を送らない
- `再開位置`: 中断したレーンを再開する場合に、作業rootに残る計画ファイルの絶対パス。新規のレーンでは当該行を送らない
- `引き継ぎ記録先`: `atk managed-temp create --prefix=handoff`で作成した領域の直下のファイルの絶対パス。セッションの管理対象一時領域が通知されている場合は`--session-root <通知された絶対パス>`を付けて作成し、当該子領域は個別に回収せずセッション終了時の回収へ委ねる。独立して作成した領域だけを、当該委譲の全工程の完了後に`atk managed-temp cleanup --path <当該領域の絶対パス>`で回収する

対象worktree、Git操作用worktree、複製元、linked worktree、プロジェクト規範は、受信者が起動時の`cwd`とGitから解決する。作成規範は変更対象から解決し、起動経路と権限は受信者の固定タスク契約を用いる。
`CI修正担当`では、上記のうち`選定結果の出力先ファイル`、`レーン識別子`、`固有指示`及び`再開位置`を渡さず、起動文へ直接記載する`CI記録`を渡す。`CI記録`は原因分析結果、修正認可根拠、対象の検証結果、変更目的、対象、公開契約、入力計画の7項目からなり、全てがそろっていることを起動前に確認する。

## 計画作成完了の受領

レーン担当は計画ファイルを作成した時点で`計画作成完了`と計画ファイルの絶対パスを返し、メインの応答を待つ。
メインは当該計画ファイルの`## 概要`と`## 実施内容`を読み、次を確認する。計画ファイルの他の節、AWI本文及び対象実装は読まない。

- 人間由来のWIに不採用の範囲が1件でも含まれる場合は、行全体の採否値にかかわらず、当該範囲、原文との差異、技術的理由及び代替案をユーザーへ示して確認する。不採用の範囲の有無は`採否`列の値だけで判定せず、`部分採用`の行は`根拠`列を読んで判定する。確認を得るまで実装開始を返さない。回答を得られない場合の扱いは`agent-toolkit:wi-standards`と`agent-toolkit:process-wi`の`skills/process-wi/references/run-lanes.md`「採否の確定と終端区分」に従う
- 採用する実施範囲を持つAWI行が1行以上あるかを判定し、レーンの統合区分を`マージあり`又は`マージなし`と確定する
- `## 実施内容`で`根拠`が`事後承認対象:`から始まる行を保持する。当該行がある場合は、ユーザーが観測する結果、採用理由及びトレードオフがそろっていることを確認し、欠落時は計画を差し戻す。UWIの投入時機は`agent-toolkit:process-wi`の`skills/process-wi/references/run-lanes.md`「実装とレビュー」が定める

確認の完了後に、同じレーン担当threadへ`実装開始`又は`実装なし`のいずれか1行を返す。`実装なし`を返したレーンでは実装と実行レビューを行わず、`${CLAUDE_PLUGIN_ROOT}/share/lane-integration.parent.md`に従って統合指示を送る。

## 実装完了の受領

レーン担当は全ての実装をcommitした後に`実装完了`と`検証結果`を返す。
メインは`検証結果`を伴わない完了値を受領した場合、実行レビューへ進まず、同じthreadへ当該記録の返却を求める。
`検証結果`を受領した後、対象worktreeのHEADをレビュー対象とし、`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`に従って実行レビューへ進む。
レビュー修正はレーン担当の同じthreadへ返し、新しい修正担当を起動しない。
レビュー収束後は、保持した`事後承認対象:`の行を現行計画から読み直し、`skills/process-wi/references/run-lanes.md`「実装とレビュー」の事後承認型UWI工程を完了してから統合へ進む。

## エスカレーションの受領

レーン担当から`needs_escalation`を受領した場合は、`${CLAUDE_PLUGIN_ROOT}/share/review-loop-coordination.md`の`## エスカレーションの事由別の扱い`に従って区分し、回答だけを同じthreadへ返す。
ユーザーの選好に依存する判断は確認経路へ送り、回答を受領してから返す。
同じthreadを継続できない場合の扱いは`agent-toolkit:delegation`の経路選択契約に従い、新しいレーン担当を起動する場合は`再開位置`へ作業rootの計画ファイルの絶対パスを渡す。
