# 実行レビュー反復の調整

実行レビューの呼び出し元が、指摘の受領、修正、再レビュー及びエスカレーションを収束まで調整する。
レビューイーは、`agent-toolkit:process-wi`では当該レーンのレーン担当、`agent-toolkit:plan-mode`の直接起動と`agent-toolkit:fast-process-wi`ではメインとする。

## ラウンド番号の正本

レビュー指摘管理表に同じ系統で記録された最大ラウンド番号を正本とする。初回は1、再レビューは最大値+1とし、会話上の回数から推測しない。同じラウンドを別表又は別番号へ複製しない。

## 応答済みの判定

レビューイーは全指摘へ採否、根拠、対応内容及び検証証拠を記録する。呼び出し元は管理表の未応答件数をCLIで取得し、0件の場合だけ再レビューへ進む。返却文の「対応済み」を管理表の観測に代用しない。

## ラウンドの遷移

1. レビュー担当が対象HEADをレビューし、指摘を管理表へ登録する。
2. 未解決指摘が0件なら収束とする。
3. 指摘がある場合は、レビューイーが現物と照合して採否を確定する。採用した指摘に必要な成果物修正、近接検証及び管理表への証拠記録を完了し、対象worktreeにcommit対象の差分が生じた場合だけcommitする。計画ファイルだけの修正はcommitを要しない。
4. 同じレビュー担当へ、同じ起点OID、レビュー基準、`review_contract`及び管理表を渡して再レビューさせる。
5. 未解決指摘が0件になるか、本書のエスカレーション条件に達するまで反復する。

前ラウンドの指摘を管理表から削除せず、解決状態と証拠を維持する。再レビューでは起点OIDから新しい対象HEADまでの全差分を対象とする。

## 採用案の確定

指摘の採否は`agent-toolkit:review-standards`に従い、要件、公開契約、実装及び検証結果へ照合して確定する。指摘の文面だけを根拠に同意しない。採用しない指摘にも根拠を管理表へ記録する。

## 反復原因の判定

同じ論点が再発した場合は、直前の修正が指摘を満たさなかったのか、指摘が新しい要件を追加したのか、レビュー契約が不足していたのかを現物から判定する。新しい要件又は認可範囲の変更に当たる場合は修正せず、エスカレーションへ送る。

## エスカレーションの事由別の扱い

| 事由 | 呼び出し元の処置 | 再開位置の記録 |
| --- | --- | --- |
| ユーザーの選好、要件又は認可範囲の変更 | 確認経路で回答を得て同じレビューイーへ返す | 不要 |
| 外部状態又は権限の不足 | 回復手段を確認し、ユーザー操作が必要なら確認経路へ送る | 必要 |
| 同じ論点の2回目以降の差し替え | 意図を確認してから修正する | 必要 |
| 技術的に解消できる実装欠陥 | レビューイーが同じ工程で修正する | 不要 |
| 同じthreadを継続できない | 後続担当へ同じ作業root、計画、管理表及び確定済み判断を渡す | 必要 |

`再開位置の記録`が`必要`の行では、計画ファイルを作業rootへ残し、`## 進捗ログ`へ完了工程、阻害条件及び再開位置を書く。キュー項目への追記は行わない。

エスカレーションへの回答後は、既存の管理表とラウンド番号を継続する。新しい表を作成せず、解決済み指摘を未解決へ戻さない。
