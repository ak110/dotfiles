# 実行レビュー反復の調整

実行レビューの呼び出し元が、指摘の受領、修正、再レビューおよびエスカレーションを収束まで調整する。
レビューイーは、`agent-toolkit:process-wi`ではそのレーンのレーン担当、`agent-toolkit:plan-mode`のメインによる起動ではメイン、公開工程のCI失敗修正では終端担当が起動する`CI修正担当`とする。

## ラウンド番号の保持先

レビュー指摘管理表に同じ系統で記録された最大ラウンド番号に従う。初回は1、再レビューは最大値+1とし、値の出所は管理表の記録に限る。同じラウンドは1つの表の1つの番号で表す。

## 応答済みの判定

レビューイーは全指摘へ採否、根拠、対応内容および検証証拠を記録する。呼び出し元は管理表の未応答件数をCLIで取得し、0件の場合だけ再レビューへ進む。判定の入力は管理表の観測とし、返却文の「対応済み」はその代わりから外す。

## ラウンドの遷移

1. レビュー担当が対象HEADをレビューし、指摘を管理表へ登録する。
2. 未解決指摘が0件なら収束とする。
3. 指摘がある場合は、レビューイーが現物と比べて採否を確定する。採用した指摘に必要な成果物修正、変更範囲の検証および管理表への証拠記録を完了し、対象worktreeにcommit対象の差分が生じた場合だけcommitする。計画ファイルだけの修正はcommitを要しない。
4. 同じレビュー担当へ、同じ起点OID、レビュー基準、初回に受領した`review_contract`があればその短い直接契約または検証済みYAMLの絶対パス、および管理表を渡して再レビューさせる。計画だけから条項を生成した場合は、初回に読んだ計画を継続する。
5. 未解決指摘が0件になるか、本書のエスカレーション条件に達するまで反復する。

前ラウンドの指摘は解決状態と証拠を伴って管理表に残す。再レビューでは起点OIDから新しい対象HEADまでの全差分を対象とする。

## 採用案の確定

指摘の採否は`agent-toolkit:review-standards`に従い、要件、公開契約、実装および検証結果と比べて確定する。同意の根拠はこの比較から得る。採用しない指摘にも根拠を管理表へ記録する。

## 反復原因の判定

同じ論点が再発した場合は、直前の修正が指摘を満たさなかったのか、指摘が新しい要件を追加したのか、レビュー契約が不足していたのかを現物から判定する。新しい要件または認可範囲の変更に当たる場合は修正せず、エスカレーションへ送る。

## エスカレーションの事由別の扱い

| 事由 | 呼び出し元の処置 | 再開位置の記録 |
| --- | --- | --- |
| 計画の条項とWIの明示条件の衝突 | WIの明示条件から契約が一意に定まる場合はWIを優先して確定し、同じレビューイーへ返す。人間由来の要求の解釈が分かれる場合はユーザー確認で確定してから返す | 不要 |
| 完成条件を外して残りをadoptする判断要請 | `${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`「統合の指示と受領」の失効受理条件へ照合する。否定したユーザーコメントか関連UWI回答がある場合は、否定の要求単位と不採用の根拠を照合して同じ担当へ返す。根拠がない場合は、既存の確認手段でユーザー判断を求める | 必要 |
| ユーザーの選好、要件または認可範囲の変更 | ユーザー確認で回答を得て同じレビューイーへ返す | 不要 |
| 外部状態または権限の不足 | 回復手段を確認し、ユーザー操作が必要ならユーザー確認する | 必要 |
| 同じ論点の2回目以降の差し替え | 意図を確認してから修正する | 必要 |
| 技術的に解消できる実装欠陥 | レビューイーが同じ工程で修正する | 不要 |
| 同じthreadを継続できない | 後続担当へ同じ作業root、計画、管理表および確定済み判断を渡す | 必要 |

`再開位置の記録`が`必要`の行では計画ファイルを作業rootへ残し、`atk run-script plan-progress --`で`## 進捗ログ`へ完了工程、阻害条件および再開位置を書く。記録先は計画ファイルとし、キュー項目は変更しない。

完成条件の判断をUWIで待つ場合は、`agent-toolkit:wi-standards`「状態と依存」に従い元AWI全体を保留する。
UWIへ元項目、解除条件と再開工程を記録し、回答済みUWIの取り込みへ接続する。
回答前は失効を承認して統合へ渡さず、依存しない他項目の作業を続ける。
この保留は前段のキュー項目を変更しない再開記録とは区別する。全要求を不採用にしてrejectする判断も、失効とは別に扱う。

エスカレーションへの回答後は、既存の管理表とラウンド番号を継続する。同じ表を使い続け、解決済み指摘は解決済みのまま保つ。
