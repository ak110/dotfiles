# レビューラウンドの受領

メインは`feedbacks-planner`、`plan-review-executor`及び`plan-executor`から返る`review_round`を本書に従って受領する。
レビュー担当の点検、レビューイーの採否・修正ならびに調整担当の状態遷移は各役割の正本へ委ねる。

## checkpoint

各ラウンドのcheckpointは次の4値だけを受理する。

```text
status: checkpoint
type: review_round
round: <ラウンド番号>
findings_count: <指摘件数>
```

第1・第2ラウンドでは、ユーザー判断又は認可範囲外の変更が別途示されていない限り、通常`続行せよ`だけを返す。
第3ラウンド以降は、対応するレビュー指摘管理表を読む。未解消の各行について、レビュー担当が記録した違反契約及び発生条件を次の順に照合し、最初に該当した1つだけを指示する。

- 同じ違反契約及び発生条件を持つ指摘が未解消のまま残る場合は、`agent-toolkit:reviewee-standards`の反復時の深掘り手順を適用した再設計又は簡素化を指示する
- 前回の是正が生じさせた別の欠陥、又は前回のラウンドで未走査だった直接影響範囲の欠陥である場合は、当該欠陥だけの是正を指示する

上記のいずれにも該当しない新しい局所修正、同じ未達の再要求、及びラウンド数だけを理由とする継続を指示しない。
ラウンド数は調整担当が保持する`round`を用い、レビュー表の行数又は実行時進捗ログの行数から導出しない。

`needs_escalation`を受領した場合は内容を確認し、回答だけを同じ調整担当へ返す。
内容が、指摘の前提又は要求する検収経路の成否がレビュー担当の再検証を経ても確定しないことを示す場合は、当該レビューの継続を回答しない。確定していない前提を計画の確定内容と対象の実体へ照合して解消してから回答し、解消できない場合は確認経路へ送る。
メインは成果物、Git状態、検証結果及びレビュー表を完了報告の再検収目的で読み直さない。
