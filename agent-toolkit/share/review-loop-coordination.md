# レビューラウンドの受領

メインは`feedbacks-planner`、`plan-review-executor`及び`plan-executor`から返る`review_round`を本書に従って受領する。
レビュー担当の点検、レビューイーの採否・修正ならびに調整担当の状態遷移は各役割の正本へ委ねる。

## checkpoint

本節はメインが受領する条件と、受領後にメインが返す指示だけを定める。
checkpointを返さないラウンドで調整担当が指示を送る相手と、その相手を確定する手順は、
各調整agent定義が保持する状態に応じて当該定義が定める。

調整担当は第1・第2ラウンドのcheckpointをメインへ返さず、レーン内で次のラウンドへ進める。
第3ラウンド以降のラウンドと、指摘0件で収束したラウンドだけをメインへ返す。
ユーザー判断又は認可範囲外の変更が生じた場合は、ラウンド番号にかかわらず`needs_escalation`で返す。

メインへ返すcheckpointは次の4値だけを受理する。

```text
status: checkpoint
type: review_round
round: <ラウンド番号>
findings_count: <指摘件数>
```

第3ラウンド以降は、対応するレビュー指摘管理表を読む。未解消の各行について、レビュー担当が記録した違反契約及び発生条件を次の順に照合し、最初に該当した1つだけを指示する。

- 同じ違反契約及び発生条件を持つ指摘が未解消のまま残る場合は、`agent-toolkit:reviewee-standards`の反復時の拡張原因分析手順を適用した再設計又は簡素化を指示する
- 前回の是正が生じさせた別の欠陥、又は前回のラウンドで未走査だった直接影響範囲の欠陥である場合は、当該欠陥だけの是正を指示する

上記のいずれにも該当しない新しい局所修正、同じ未達の再要求、及びラウンド数だけを理由とする継続を指示しない。
ラウンド数は調整担当が保持する`round`を用い、レビュー表の行数又は実行時進捗ログの行数から導出しない。

`needs_escalation`を受領した場合は内容を確認し、回答だけを同じ調整担当へ返す。
内容が、指摘の前提又は要求する検収経路の成否がレビュー担当の再検証を経ても確定しないことを示す場合は、当該レビューの継続を回答しない。確定していない前提を計画の確定内容と対象の実体へ照合して解消してから回答し、解消できない場合は確認経路へ送る。
メインは成果物、Git状態、検証結果及びレビュー表を完了報告の再検収目的で読み直さない。

## 計画レビューの打ち切り

計画レビューは第5ラウンドを上限とする。第5ラウンドの指摘件数が0件でない場合、メインは新しいラウンドを起動せず、今回の計画範囲を確定する。
未解消の各指摘について、当該論点を今回の計画へ含めないと成果物が技術的に成立しないかだけを判定する。指摘の妥当性を判定の基準にしない。
成立しないと判定した指摘は、`最終是正のみ実施せよ`を調整担当へ返す。それ以外の指摘は、`agent-toolkit:feedback-standards`に従って次回のフィードバックへ登録する。
当該指示を受領した後の送信先は各調整agent定義が定める。調整担当は下流から`対応完了（最終是正）`を受領した場合、再レビューへ進まず、各定義が定める完了文字列をメインへ返す。
本節の上限は計画レビューだけに適用し、実装レビューへ適用しない。
