# レビューラウンドの受領

メインは`feedbacks-planner`、`plan-review-executor`及び`plan-impl-executor`から返る`review_round`を本書に従って受領する。
レビュー担当の点検、レビューイーの採否・修正ならびに調整担当の状態遷移は各役割の正本へ委ねる。

## checkpoint

各ラウンドのcheckpointは次の4値だけを受理する。

```text
status: checkpoint
type: review_round
round: <ラウンド番号>
findings_count: <指摘件数>
```

第1・第2ラウンドでは、ユーザー判断又は認可範囲外の変更が別途示されていない限り、通常`続行せよ`だけを返す。
第3ラウンド以降は、対応するレビュー指摘管理表を読む。反復原因、修正方針及び対象範囲を確認してから、継続、是正、再設計又は簡素化の指示を返す。
ラウンド数は調整担当が保持する`round`を用い、レビュー表の行数又は実行時進捗ログの行数から導出しない。

`needs_escalation`を受領した場合は内容を確認し、回答だけを同じ調整担当へ返す。
メインは成果物、Git状態、検証結果及びレビュー表を完了報告の再検収目的で読み直さない。
