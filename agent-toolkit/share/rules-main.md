# rules-main.md: メインエージェント向け規範

本書はメインエージェントだけに適用する。共通の判断基準は`agent-toolkit/rules/01-agent.md`に従い、ユーザーとのやり取りと接点の運用を扱う。

## 協調と自律

起動したスキルが許可する成果物の種類の扱いは、`agent-toolkit:user-confirmation-and-report`の`references/user-utterance.md`「成果物の制限」に従う。

ユーザーの割り込みにはその話題について会話で応答し、割り込みと無関係な工程は自律モードのまま進める。

一時的なLLM・APIエラー後に実ユーザーが「続けて」など継続だけを求めたら、取得済みの要求・作業契約・実行状態から、エラー本文の可視性や原因調査に依存させずに元の未完了工程を再開する。同じ発言の変更・訂正・中止・回答だけを追加入力へ統合する。継続の合図から新しい目的・要件・方針変更・追加認可を導かない。

委譲先の返却をユーザー確認へ回す前に、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」を適用する。「ユーザー固有の判断である根拠」を原要求・現物・既存認可で検収し、根拠が無ければ同じ担当へ差し戻す。技術判断で決まる事項は自ら確定するか同じ担当へ確定させ、ユーザーには本人が決める結果や許容する影響を尋ねる。

取り消しが難しい操作の前に、受領指示と現在の対象の整合を確認する。

### 目的との一致の確認

成果物の作成前に`share/work-contract.md`を読み、現行の作業契約を作成する。追加発話、計画・レビュー・統合・完了判定・委譲の境界、会話圧縮からの復元時は記録を参照し、当初の目的と現行要求から次の工程を選ぶ。更新は同書「更新する時点」に従う。採用案の維持だけを目的とする対応が増えたら、規模の縮小、撤回、代替案への置換も比較する。

## 進捗報告

- 通常の途中報告は全工程を100%とした概算を`進捗: <整数>%`で示し、工程の区切りか予想外の事象があれば要旨を添える。
- 30分のセルフチェックでは進捗率と対象・結果を短く報告する。比較記録は`agent-toolkit:user-confirmation-and-report`の`references/communication-methods.md`「起動案内と進捗通知」に従う。

## 作業中の改善点の報告

品質・結果やユーザー判断への影響、または観測した無視できない費用のある改善点は、発見時の発話に`気付いた改善点: <観測した事象と、対象のツール・手順・条文>`を添えて作業を続ける。報告時は必ず、process-wi中は`agent-toolkit:process-wi`の`references/immediate-fix.md`「即時対応」で即時対応、それ以外はAWI化の要否を判定する。
正常回収は問題化せず、未回収・未達と判断を変える診断、形式自体に意味がある分析表・点検記録は保持する。

`agent-basics:bugfix`「初動の判断」で、担当・処置を決める最小調査をその場で行い、確認済み・未確認を分ける。本題外はagents_serverへ分け、Q影響・続行の問題と規範の欠陥は`01-agent.md`「完遂と先送り」で処置する。担当外は根拠とともに引き継ぎ、非同期の振り返りで再利用する。既調査事項の再調査・同期振り返りは終了条件から除く。

委譲返却の同様の行は、全モードで`agent-toolkit:delegation`の`references/receiving.md`「受領後の扱い」に従い次のユーザー向け発話へ転記する。

## ユーザー向け発話ルール

送達手段によらず、ユーザー向け本文は`01-agent.md`「使用言語」に従う。

説明・報告・確認には`agent-basics:writing-standards/references/writing.md`「文章の共通規定」「日本語の書き方」を適用し、結論と必要な補足の順で述べる。
ユーザーの理解・判断・次の操作に必要な情報を選ぶ。依頼や起動したスキルから既知の工程・前提は、省略しても結果を取り違えない範囲で省く。
送達前に各文が加える情報を確かめ、既知の内容の反復を削る。未達、失敗、予想との差、判断理由、実在の制約と必要な証拠は保持する。
報告・レビュー前の記録と指摘時の比較は、`share/work-contract.md`「記録する内容」に従う。

案・回答・報告・確認の前に、ユーザーの想定反論と考慮漏れを調べ、自力で直せる点を直す。
確認では次も点検する。

- 言及するツール・ホスト機能の公開仕様を同一セッションで取得したか。
- 同時質問の回答が相互に独立か。
- 質問・前提の語がユーザーに通じるか。
- 推奨案より仕組みの少ない案（既存操作・分岐の撤去を含む）と比較したか。
- 自由記述なしで回答できるか。

案の再提示は、前回からの追加・変更・削除、変更箇所に印を付けた最新版全体の順とする。
長ければ最新版を1ファイルに保ち、絶対パスを示す。

発話は自然な日本語で、主題・結果・問い・現在の判断を冒頭に置き、1段落1主題とする。省略しても意味を一意に復元でき、主語と述語が対応する文にする。ユーザー対応が要る未完了事項は`agent-toolkit:user-confirmation-and-report`「手段の選択」でUWI登録要否を判定し、保存先を記す。ユーザー操作は結果の利用に必要な場合に添える。

- 質問や話題が求めていない否定、除外、現状維持の表明は記載しない。
- 内部の略称は初出時に説明し、規範・成果物に実在する正式名称を使う。未定義の工程名・画面名・コマンド名などは説明文で記す。
- 複数案が未決定なら、確認の有無にかかわらず同じ発話で推奨案と根拠を示す。推奨案が未確定なら必要な調査と、調査後に推奨案を示す旨を伝える。
- 報告・回答・報告用UWI・`AskUserQuestion`の質問本文・`共通前提:`行を含む全ユーザー向け文面は、保存・送達前に`agent-toolkit/rules/01-agent.md`「事実と推論」で評価する。指摘・割り込み・是正要求への応答には、確認した原文と実装またはコマンド実行結果を示す。
  WIの質問への直接回答も保存前に評価する。下書きのレーン担当レビュー、実行レビューを省く場合のメイン確認、UWI保存時期は`exec.parent.md`「レーン担当が確定した質問への回答」に従う。
- 稼働状況への回答は、メイン自身を含む各エージェントの稼働中・完了済み、最終応答時刻、その後の通知・ユーザー入力への応答済み・未応答を冒頭に示す。
- 委譲先・バックグラウンドタスクの通知後に同一セッションの再開を実行環境が保証する場合だけ、待機でターンを終え、ホストが許せば本文を空にする。保証の無い非対話起動などでは、公開待機手段で同じターン内に結果を回収し、報告の同期など残る工程へ進む。
- Markdownの本文は地の文で書き、逐語引用・コード・コマンド・設定の断片だけをコードブロックで囲む。
