# Tailwind CSS記述スタイル

対象バージョン: Tailwind CSS v4系（参考実利用バージョン: 4.3）。v3からの移行点を含む公式ドキュメントは<https://tailwindcss.com/docs>を参照する。

## セットアップ・設定（v4のCSS-first設定）

- `tailwind.config.js`を新規作成せず、CSSファイル内の`@theme`ディレクティブでデザイントークンを定義する（v4のCSS-first設定が標準であり、JS設定ファイルは互換目的の`@config`経由でのみ許容されるため）
- エントリCSSは`@import "tailwindcss";`の1行で読み込む（`@tailwind base/components/utilities`はv4で廃止）
- 色・フォント・ブレークポイント・イージング等のトークンは`@theme { --color-brand-500: oklch(...); }`のようにCSS変数として定義する（生成される全ユーティリティとネイティブCSS変数の双方から同一トークンを参照できるため）
- 既定のカラーパレットを丸ごと置き換える場合は`--color-*: initial;`で初期化してから独自パレットを定義する（既定色との混在による命名衝突・意図しない残存を避けるため）
- ダークモードの判定基準を変更する場合は`@custom-variant dark (&:where(.dark, .dark *));`のようにCSSで`dark`バリアントを再定義する（v4では`darkMode`設定キーではなくCSS側で制御するため）
- プレフィックスが必要な場合は`@import "tailwindcss" prefix(tw);`を使う（`@config`経由の互換設定に頼らない）

## ユーティリティファースト運用

- スタイリングはユーティリティクラスの直接記述を第一選択とし、`@apply`によるコンポーネントクラス抽出は多用しない（ユーティリティの意図が失われ、HTMLとCSSの二重管理が発生するため）
- 同一の見た目パターンが3箇所以上で反復する場合に限り、`@apply`ではなくコンポーネント分割で共通化する
- CSSモジュールやVue/Svelteの`<style>`ブロックなど別バンドル経路のスタイルでは、`@apply`より`var(--color-blue-500)`のようなCSS変数の直接参照を優先する。当該経路の`@apply`・`@variant`は`@reference`によるテーマ読み込みが別途必要でビルド性能も下がるため

## クラス整列

- `prettier-plugin-tailwindcss`を導入し、クラス順序の整形をフォーマッタに委ねる
- 手動でのクラス順序調整はしない（フォーマッタの出力と衝突し、保存のたびに差分が発生するため）

## 動的クラス名の禁止

- `` `bg-${color}-600` ``のような文字列連結・テンプレートリテラルでクラス名を生成しない（Tailwindはソースファイルをプレーンテキストとしてスキャンするため、実行時にしか確定しない名前は生成対象から漏れる）
- 条件分岐でクラス名を切り替える場合は完全なクラス名を分岐の両方に書く（例: `color === "red" ? "bg-red-600" : "bg-green-600"`）
- コンポーネントのバリアント管理には、完全なクラス名の対応表（オブジェクトリテラル等）を用いる

## レスポンシブ・ダークモード・カスタムテーマの推奨パターン

- レスポンシブは`md:`・`lg:`等のブレークポイントプレフィックスを基準スタイルに追記する形で書く（モバイルファーストの既定ブレークポイントに合わせるため）
- ダークモードは`dark:`バリアントをベースユーティリティへ直接併記し、専用CSSファイルを分離しない（`dark:lg:hover:bg-indigo-600`のように他バリアントとも合成できるため）
- カスタムブレークポイント・カスタムイージング等は`@theme`内で`--breakpoint-3xl: 120rem;`のように命名規則（`--breakpoint-*`・`--color-*`等）に沿って追加する（既定トークンと同じ生成規則に乗るため）

## アンチパターン

- `[mask-type:luminance]`のような任意値記法を汎用スタイルの常用手段にしない。同じ値を繰り返し使う場合は`@theme`のトークンへ昇格する
- `!important`相当の`!`修飾子（例: `text-red-500!`）を特異度問題の恒常的な回避策にしない。特異度問題が生じた場合は根本原因であるセレクタ設計・読み込み順序を見直す
- 巨大なクラス文字列を1行にまとめて記述したままレビューしない（整形結果を前提に、レイアウト・配色・状態という意味のある単位でグルーピングする）
