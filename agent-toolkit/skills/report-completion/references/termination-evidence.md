# 終了工程の判断の記録

本書は、メインエージェントがStop hookによる遮断を受けた際の手順、および完了報告の省略、作業の中止・置換、待機、技術的不成立に関する判断を記録する際の手順を定める。
適用するプロジェクト規範によって`agent-toolkit:report-completion`の起動を省略する場合は、本スキルを起動せずに本書を直接参照する。

Stop hookが同スキルの起動不足を理由に処理を遮断した場合、起動が必要な作業を完了させてセッションを終了するのであれば同スキルを起動し（Codex環境では`SKILL.md`を読む）、同スキルの`SKILL.md`「工程」に定められた残りの手順を進める。
報告本文の文面修正や全文の再送をしても、遮断は解除されない。

## プロジェクト規範による省略

メインエージェントは、`agent-toolkit/rules/01-agent.md`「方針が衝突する場合の優先順位」に基づき、対象の作業において本スキルの起動を省略するかどうかを判断する。
省略する場合は、次のJSONを一時領域に保存したうえで、`atk run-script termination-evidence -- --decision-file <判断JSONの絶対パス>`を実行して判断を記録し、通常の報告をする。

```json
{
  "session_id": "現在の会話の識別子",
  "action": "omit-completion",
  "work_id": "観測済み作業の識別子",
  "reason": "規範の意味と優先順位から省略する理由",
  "policy_file": "/対象リポジトリ/CLAUDE.md",
  "target_repo": "/対象リポジトリ"
}
```

各識別子はStop hookの通知から取得する。
Claude Code環境では、`atk run-script termination-evidence -- --context`を実行することでも現在の識別子を取得できる（取得できる項目は次節を参照）。
省略の判断は人間の入力を根拠とするため、取得結果の`input_id`に値が存在する会話においてのみ記録可能である。
`policy_file`には対象リポジトリ内で適用するプロジェクト規範の絶対パスを指定し、`target_repo`には観測した成果作業が属するGitリポジトリのルートの絶対パスを指定する。
複数のリポジトリにまたがる成果作業が存在する場合は、リポジトリごとに作業を区切って個別に判断する。
記録処理は`policy_file`から規範の全文を読み込んで保存し、観測された成果作業の対象と所在、現在のメインエージェント、会話、人間入力の対応関係を確認する。
省略対象の`input_id`は、現在の会話における直近の人間入力に対応付ける。
指定した`input_id`が現在の人間入力を指していること、および`quote`の内容が規範全文と一致していることを確認する。
規範の解釈と優先順位の適用は、メインエージェントが判断する。
規範の内容が変更された場合、新たな判断をする場合、あるいは新しい人間入力の後に成果作業が発生した場合は、過去の省略記録を流用せず、改めて判断する。
省略の記録は指定した作業の起動不足に対してのみ有効であり、別の作業における起動不足や、process-loopにおける`atk agents-exit-session`の実行義務はそのまま残る。
process-wi all-reposのリポジトリ担当は成果と残工程を統括へ返し、統括が報告を集約し、必要な手順でホストを終了する。
振り返りは別担当の非同期処理であり、本書の省略判断と通常の終了条件の対象外とする。手動の振り返りを依頼された場合は、その独立した要求を保持する。

## 中止・置換・待機・技術的不成立

ホストからの猶予通知によって続行が許可されている間は、残りの工程を進める。ホストによって再開が禁止された場合は、現在の状況と再開に必要な操作を`agent-toolkit:user-confirmation-and-report`に沿ってユーザーに伝える。
`wait`は実際に継続中の待機処理がある場合に記録し、`blocked`は観測された失敗によって技術的に続行できない場合に記録する。

作業の中止や別作業への置換が指示された場合、確認への回答や起動した委譲先の結果を待つ場合、あるいは技術的に続行できない場合は、`atk run-script termination-evidence -- --decision-file <判断JSONの絶対パス>`を実行してその判断を記録する。
判断JSONには、`session_id`、`action`（`cancel`、`replace`、`start`、`resume`、`wait`、`blocked`のいずれか）、対象の`work_id`、および`reason`を含める。
中止・置換・開始・再開の場合はユーザーの元の入力を示す`input_id`を、確認待ちの場合は投入した未回答UWIの`uwi_file`を、委譲先の待機の場合は`target_session_id`を、技術的不成立の場合は失敗した呼び出しの`call_id`を指定する。
記録処理は各識別子から本文や応答を読み込み、その由来と対象を確認する。
`quote`は省略可能であり、指定した場合は取得された実体の全文と一致しているかを確認する。
`session_id`、`work_id`、直近のユーザー入力の`input_id`は、遮断通知から取得する。
Claude Code環境では、`atk run-script termination-evidence -- --context`を実行して取得できる。
取得結果には、人間入力の有無にかかわらず`session_id`と現在の`work_id`が含まれる。`input_id`と原文の`quote`は、人間入力を観測した場合にのみ値が設定され、観測されていない場合は`null`となる。
委譲先の待機や技術的不成立は実行結果を根拠とするため、人間入力が存在しない自動起動の会話であっても、取得した`session_id`と`work_id`を用いて記録できる。
中止・置換・開始・再開は人間の元の入力を根拠とするため、`input_id`に値が存在する場合にのみ記録できる。
判断の記録は指定した作業にのみ作用し、ユーザーの割り込みと直接関係しない他の作業に関する起動不足は解消されない。
生成されたStop hookの継続入力や注記はユーザーの元の入力として受理されず、完了の自己申告を記録する操作も用意されていない。
証拠が取得できない場合、Stop hookは遮断せず、判定不能であった旨を記録する。
自律モードにおける報告用UWIの保存検収と`atk agents-exit-session`の実行は、Stop hookの判定とは別に、同スキルの手順6と手順7によって定められている。
