# 常時稼働サーバーへの反映

反映を担当するメインまたは委譲先が、反映の要否・先行結果の再利用・開始時機を本書で判断する。
報告用UWI・送達・ホスト終了の担当は、それぞれの役割契約に従う。

常時稼働サーバーへの反映: 対象プロジェクトが開発機上で常時稼働するサーバーを持ち、そのプロジェクト規範やタスクランナー定義で反映手順と稼働確認手順の両方が定められている場合に実施する。
起動元の工程が先行して反映した結果（反映済みHEADの一意な短縮OID、反映コマンドの終了ステータス、稼働確認結果）があり、報告時点の主作業ツリーで短縮OIDを解決した結果がHEADと一致し、両方の処理が成功していれば再反映を省略する。
それ以外の場合は現行のHEADを反映し、稼働を確認する。
報告には再反映の有無と稼働確認の結果を含める。
反映しない場合はその理由と未反映の状態を報告し、ユーザーの対応が必要な残作業については`agent-toolkit:atk-mode/references/delivery.md`「手段の選択」に沿って個別UWIの登録要否を判定する。
自明な反映手順の案内は報告に添える。
起動元の工程が反映を先行して開始できるのは、反映処理が対象リポジトリへの書き込みを行わず、公開向けの入力を生成せず、公開操作や成果物・排他リソースと競合しない場合に限る。

委譲先が反映した場合は、上記の結果を委譲元へ返す。
本書を読むこと自体は、報告・終了をその担当へ追加する認可ではない。
