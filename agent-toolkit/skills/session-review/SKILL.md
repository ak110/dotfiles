# セッション振り返り

最上位セッションのメインエージェントだけが本スキルを起動する。
別のエージェントからタスクを受領した実行主体は自身をサブエージェントと判定し、本スキルを起動せず、起動判断を呼び出し元へ返す。
メインが自身と全サブエージェントの記録をまとめてセッション全体を分析するため、サブエージェントによる個別起動は分析対象の重複又は欠落を生じさせる。

次のセッション以降で同じユーザー介入、レビュー反復、手戻り又は無駄が再発しないよう、現セッションの問題を独立コンテキストで洗い出し、メインが恒久対策を確定する。

## 問題候補の抽出

メインは抽出を始める前に、読み込み済みのプロジェクト規範や参照文書、ユーザー指示に、
対象プロジェクトと処理規模に対応するセッションの所要時間目標が定められているかを確認する。
目標が定められている場合は、対象と目標値を問題候補抽出の入力へ含める。
目標が定められていない場合は、全対象へ適用する固定値を新設又は推定しない。

1. `agent-toolkit:delegation`を起動し、`agents_server.start`へ`model_type="session_review"`を渡してengine、model及びeffortの解決をサーバーへ委ねる。
2. メインが読み込んだ本`SKILL.md`の絶対パスから現行plugin rootを確定し、`skills/session-review/scripts/session_review_evidence.py`の実在を確認する。実在しなければ分析失敗として扱う。
3. メインが`atk managed-temp create --prefix session-review`を実行し、標準出力が単一の絶対パスであり、そのパスが実在するディレクトリであることを確認する。非0終了又は不実在の場合は分析失敗として扱う。この領域はメインが所有し、振り返り担当が抽出結果を保持する場所として渡す。続けてメインが`date -u +%Y-%m-%dT%H:%M:%SZ`を実行し、終了コード0と単一行の出力を確認して観測境界として保持する。境界より後に親記録へ追加されるメイン自身の進捗報告を、過去の未完了工程と誤認させないためである。
4. `agents_server`で通常の読み取り専用サブエージェントを1つ起動する。専用agent定義、固定モデル及び代替モデルを使わない。起動文へは、人間向けの本文を日本語で書き、実行環境が英語で挿入した指示の言語を応答言語として引き継がない条件と、抽出を別の担当へ再委譲せず自身で完遂する条件を含める。
5. Claude Codeでは、メインが把握する現在のtranscript絶対パスを渡す。Codexではメインの`CODEX_THREAD_ID`を渡し、サブエージェントは抽出器へ`--codex-thread-id`で当該IDを渡す。いずれの実行環境でも、確認済み抽出器の絶対パス、手順3の管理一時領域の絶対パス及び同じ手順の観測境界を渡す。記録の保存先の解決と正本1件の特定は抽出器が行うため、サブエージェントは検索式を組み立てない。抽出器が0件又は複数件を診断して終了コード2を返した場合は`evidence_insufficient`とする。
6. サブエージェントが変更してよい対象は、渡された管理一時領域の内側だけとする。対象リポジトリ、セッション記録及びフィードバック保管先は読み取りだけを行う。抽出器の出力を保持する場合は、走査ごとに当該領域内の異なるファイルへ書き、領域外の固定名を使わない。
7. 当該セッションの全ての委譲先の記録を走査対象とする。サブエージェントの記録、`agents_server`経由で起動した独立セッションの記録、Codexスレッドの記録はいずれも対象に含め、委譲先がさらに起動した委譲先も同じ扱いとする。所在は抽出器がメインの記録から再帰的に導出するため、メインは委譲先の記録の絶対パスを渡さない。件数、出力量、所要時間を理由に走査対象を絞らない。読む量が増える負荷は、独立コンテキストのサブエージェントへ切り出すことで吸収する。抽出器が`unresolved-record`として報告した記録だけを、未確認の範囲として返させる。
8. 初回依頼には振り返りの起動理由を含めない。サブエージェント自身が、通常表示、`--warn`、`--stats`、`--hook-notices`及び必要な`--grep`・`--detail`をそれぞれ1回ずつ実行する。全ての実行へ`--observation-boundary`と受領した観測境界を付ける。各実行は全ての記録を走査し、イベントの`record`欄が由来する記録を示す。`--detail`の行番号は`<記録>:<行番号>`形式で1回のオプションにつき1つ指定し、複数指定ではオプションを繰り返す。
9. 委譲先のエスカレーションは重点的に確認する。`needs_escalation`と差し戻しは工程が止まった箇所を直接示すため、1件ずつ発生条件と直前の入力を`--detail`で取得し、単発でも問題候補とする。完了報告に現れる手順の前提不成立、再試行及び自力回避も候補へ含める。委譲先が自ら回避して作業を続けた事象は、同じ回避が複数の委譲先で現れる場合を候補とする。
10. ユーザーの介入は単発でも問題候補とする。その場限りの事実連絡及び情報提供と、恒久対策を要する事象とを判別し、判別の根拠を候補へ添える。判別は、同じ介入が対象リポジトリの既存フィードバック、TBD、事故記録文書などの過去のセッション由来の記録に現れるかと、当該介入が無ければ工程が誤った状態のまま進んだかで行う。過去のセッション由来の記録に同じ介入が現れる候補は再発として返し、メインは当該候補の恒久対策を必ず確定する。
11. サブエージェントは`status`、各走査の成否、問題候補ごとの要約・観測事象・再取得用query・locator・未確認事項及び全体の未確認範囲だけを返す。原因、解決案、反映先、採否、フィードバック本文はいずれも作成しない。所要時間目標を入力で受け取った場合は、`--stats`で実測した所要時間、目標の超過有無、`stats-gap`・`stats-tool`・`stats-slow-call`・`stats-repeat`・`stats-subagent`・`stats-agent-thread`に基づく内訳も返す。

証拠の保持は次の形で行う。

```sh
uv run --no-project --script <抽出器の絶対パス> <transcriptの絶対パス> --observation-boundary <観測境界> --stats > <管理一時領域の絶対パス>/stats.jsonl
uv run --no-project --script <抽出器の絶対パス> --codex-thread-id <thread ID> --observation-boundary <観測境界> --stats > <管理一時領域の絶対パス>/stats.jsonl
```

メインはサブエージェントのqueryとlocatorが指す証拠だけを再取得する。再取得後、Claude Codeの`~/.claude/references/session-review-dotfiles.md`又はCodexの`~/.codex/references/session-review-dotfiles.md`が存在すれば、対応する文書をメインが全文読む。この参照文書を通常サブエージェントへは渡さない。セッション全体の要約・再抽出のいずれも作成しない。

メインは振り返り担当の終端と返却内容を検収した後、`atk managed-temp cleanup --path <手順3で確認した絶対パス>`を実行し、終了コード0を確認して領域を回収する。振り返りが異常終了した場合は、原因調査に必要な間だけ領域を保持し、調査を終えた時点で同じコマンドで回収する。

ユーザーによるエージェントの間違い等の指摘又は同じ成果物・責任範囲のレビュー第3ラウンドが起動理由であり、対応する候補が初回出力に無い場合は、同じ`agents_server` sessionへ`send_message`で当該事象と証拠位置を送り、対象を再確認させる。別sessionを起動しない。

## 所要時間目標との照合

所要時間目標が定められ、実測所要時間がその目標を超えた場合は、問題候補の有無にかかわらず目標超過を問題候補へ加える。
メインは所要時間の内訳から寄与の大きい工程と反復を特定し、
品質、必須工程及び検収範囲を維持したまま所要時間を短縮する改善提案を作成して振り返りの成果へ含める。
改善提案は、内訳で確認した時間寄与と短縮する工程を対応付ける。

## 原因と対策

問題候補が1件以上なら`agent-toolkit:bugfix`を起動し、観測事象、2系統4段階の原因分析、原因分析の品質確認、原因起点の類似見直し、是正・横展開・再発防止及び反映要否をメインが確定する。

再発防止処置の必須性、省略できる条件及び良い案を確定できない場合の終端は`agent-toolkit:bugfix`の再発防止処置の必須性節に従う。`agent-toolkit:process-feedbacks`だけが起動理由で問題候補が無い場合は、対策なしで完了できる。

採用した対策のフィードバック又はTBDは`agent-toolkit:feedback-standards`に従って起草・重複判定・投入する。本スキルは本文形式・CLI手順のいずれも定義しない。

確定した内容は候補別の判定記録の表へ記録する。

## 候補別の判定記録

メインは問題候補ごとに、`候補`、`欠陥判定`、`直接的原因`、`根本原因`、`既存規範が適用されなかった理由`、`処置`の6列表へ1行を記録し、振り返りの成果へ含める。

- `候補`には観測事象と再取得用のlocatorを書く
- `欠陥判定`には欠陥とするか否かを書き、欠陥としない場合はそう判定した観測根拠を併記する
- `直接的原因`には観測事象を発生させる実行時・データ・設定上の機構を書く
- `根本原因`には`agent-toolkit:bugfix`の原因分析で確定した結論を書く
- `既存規範が適用されなかった理由`には、当該事象を統治する既存規範がある場合に、その規範が実行経路で適用されなかった原因を書く。統治する規範が無い場合はその旨を書く
- `処置`には是正・横展開・再発防止の各処置と、同一セッションでの実装状態又は根本原因を覆うactive項目のファイル名を書く

次のいずれかに該当する行が残る間は振り返りを完了しない。

- 欠陥と判定した行に処置が無い
- 既存規範へ違反した事象で、当該規範の存在だけを処置としている
- 参照するactive項目が根本原因と必要な全処置の一部しか覆っていない

該当する行は、`agent-toolkit:bugfix`の再発防止処置の必須性に従って処置を確定するか、同節に従ってTBDを登録してから完了する。

## 分析失敗

サブエージェント起動、親transcript解決又は証拠抽出が失敗した場合は、同じ実効設定で1回だけ自動再試行する。再失敗時は、推奨案「TBDへ記録して元作業を継続」と代替案「その場で再試行」を`AskUserQuestion`で確認する。

回答期限超過時は`agent-toolkit:feedback-standards`に従い、セッションID、失敗事象、解除条件及び「当該セッションをresumeしてsession-reviewを再実行する」再開工程をTBDへ記録する。transcriptパスは保存しない。メインによる全量分析又は別モデルへのフォールバックは行わない。

手動起動では分析未完了を報告できる。`agent-toolkit:process-feedbacks`から起動した場合は、分析未完了とTBDを`agent-toolkit:completion-report`へ返し、元作業の完了を妨げない。
