# セッション振り返り

同じユーザー介入、レビュー反復、手戻りまたは無駄が再発しないよう、対象セッションの問題を見つけ、原因と対策を確定した通常AWIを投入する。
原因と対策の最終判断と統合は、メインが同じセッション内で自身のコンテキストで行う。事実の収集は`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「事象単位の並列調査委譲」が定める条件で独立した担当へ委譲する。
メインが元の記録を持ち、委譲先へ取得できる証拠を渡す。最終判断を別の環境へ移すと、元の記録へ届かず候補の文脈を組み立て直すことになる。
`atk run-script session-review-prepare`はツール実行結果と自動挿入本文を除いたセッション全体の流れ（会話の流れ）と、雑音になる候補を機械的に除いた問題候補（`candidates.md`）を書く。観点を限定して抽出した候補だけを読むと、どの観点にも当たらない問題が分析の入力に現れない。そこでメインは会話の流れを先に通読して問題を探し、`candidates.md`は通読では得られない事象を補うために使う。

## 読込表

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 工程2で`atk run-script session-review-prepare`の`reference_document`が値を持つ場合 | `reference_document`が示す対象リポジトリ固有の振り返り参照文書 |
| 工程3で問題を選別する前 | `references/analysis.md` |
| 工程4で問題ごとに`agent-toolkit:bugfix`を起動した時点（`references/analysis.md`「原因と対策」がユーザー介入を拡張原因分析の条件に当たるものとして扱うため） | `agent-toolkit:bugfix`の`references/root-cause-analysis.md` |
| 工程5で要求をWI投入担当へ渡す前 | `${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md` |

## 実行主体

最上位セッションのメインエージェントが自身のセッションを振り返り対象として本スキルを起動する。別のエージェントからタスクを受け取った実行主体は自身をサブエージェントと判定し、起動判断を委譲元へ返す。1つの実行主体が対象セッションの全ての記録をまとめて抽出するため、個別起動は候補の重複または欠落を生じさせる。
メインは振り返りの工程と最終判断を担う。工程3と工程4でユーザー介入の候補を扱う場合や、独立した複数の事象を扱う場合は、事実の収集を`agent-toolkit:bugfix`の条件に従って委譲する。対策AWIの本文の起草と投入は、`agent-toolkit:wi-standards`「投入と取得」に従ってWI投入担当へ委譲する。

## 工程

1. セッションのmanaged-temp（`agent-toolkit:managed-temp`）の中へ、実行ごとに異なる名前（`session-review-<時刻>`など）の作業ディレクトリを作成する。続けて`atk run-script session-review-prepare`を次のいずれか1つの形で1回実行する。同じセッションで振り返りを再実行した場合に前回の出力を上書きしないよう、名前を実行ごとに変える。Claude Codeで把握している現在のtranscript絶対パスを`--transcript`へ渡し、Codexでは`CODEX_THREAD_ID`を`--codex-thread-id`へ渡す。`--target-repo`は対象リポジトリを確定できた場合だけ渡す。

   ```text
   atk run-script session-review-prepare -- --transcript <transcriptの絶対パス> --work-dir <作業ディレクトリの絶対パス> --target-repo <対象リポジトリの絶対パス>
   atk run-script session-review-prepare -- --codex-thread-id <thread ID> --work-dir <作業ディレクトリの絶対パス> --target-repo <対象リポジトリの絶対パス>
   ```

   このコマンドは証拠bundleを抽出し、作業ディレクトリへ会話の流れ（`conversation.md`。メイン記録の発話、ツール呼び出しおよび失敗したツール結果の標識を時系列で並べる）、問題候補（`candidates.md`）、セッション統計（`stats.md`）を書く。キューは変更しない。
   標準出力の1行JSONは、3つの文書の所在（`conversation_path`、`candidates_path`、`stats_path`）と、対象リポジトリ固有の振り返り参照文書（`reference_document`。無ければnull）を持つ。また、準備時刻（`prepared_at`）と発話件数（`utterance_counts`）を持つ。候補件数（`candidate_total`と種別ごとの`candidate_counts`）、除外件数（`excluded_counts`）、発生記録の読飛ばし行数（`failure_ledger_skipped`）も含む。経過秒（`elapsed_seconds`）とコンパクション回数（`compaction_count`）は所要時間の分析へ使う。
   終了コードが0でない場合と、標準出力が1行のJSONではない場合は`## 分析失敗`へ進む。
2. `candidates.md`より先に`conversation.md`を全範囲読み、観点を限定せずにセッション全体から問題を列挙する。遠回り、手戻り、同じ論点の反復、ユーザーによる是正、時間を費やした工程はその例である。
   - 推測で組んだコマンドの試行錯誤、同じ資料の読み直し、採用した設計の書き直し、規範の解釈へ費やした工程、委譲先への指示不足による手戻り、関連ファイルや定義元へ到達するまでの遠回り、現行に合わない資料を根拠にした判断は標識を残さず候補に現れないため、会話の流れのツール呼び出しと前後の発話から探す。検索語や探索場所を変える反復、定義元の探し直し、参照先への案内不足で別の文書をたどる遠回りなども、この観点で扱う。
   - メインと委譲先が作業中に伝えた`気付いた改善点:`で始まる行は、会話の流れから全件を問題の列挙へ含める。
   - ホストが1回で読める量を超える場合は、`agent-toolkit/rules/02-agent-operations.md`「ツール・コマンド運用」と`agent-toolkit/share/rules-main.codex.md`「Codex固有の入出力」の分割取得に従って範囲を分け、全範囲を読む。会話圧縮で自身のコンテキストから失われた区間も、会話の流れから読む。
   - `reference_document`が値を持つ場合は、読込表の行に従ってその文書を読み、対象リポジトリ固有の振り返り観点と所要時間目標を解決する。
3. `candidates.md`を通読の補助として読み、通読で見つけた問題との対応付けと、通読では得られない事象の追加に使う。通読では得られない事象は、直近30日の複数セッションで反復した失敗署名、hook通知の発生源と件数、除外件数、委譲先の内部である。候補に対応しない通読の問題も独立して扱い、通読の問題と候補から問題を選別する。公開待機中に調査とAWI原稿を準備した場合は、正式な候補選別の結果と公開後の現行状態に照らして採否を確定する。公開結果へ依存する問題は、結果が確定した後の本工程で調べる。選別と工程4の確定の判断基準は`references/analysis.md`を適用する。確定に証拠の全文が要る候補だけ、候補一覧が示す記録位置を`atk run-script session-review-evidence`の`--detail`へ渡すか、`--grep`で照会する。所要時間の分析には`stats.md`を使う。
4. 工程3で選別した問題ごとに、メインが自ら`agent-toolkit:bugfix`を起動し、事象、期待する契約、実際の結果および発生条件を入力として適用する。同じセッションで先に起動していても、対策を確定する振り返りごとに改めて適用する。WI投入担当も起草時に原因を分析するが、予告に示す原因と対策はメインが確定するため、メインの原因分析を代えない。
   1. 問題ごとに2つの問いへ答える。1つは事項が既存の上位規範（`agent-toolkit/rules/01-agent.md`のQCDや「完遂と先送り」など）から導かれるか、もう1つは条文の追加より除去・緩和・一般化で目的を達成できるかである。
   2. 初動、拡張原因分析の判定、原因、類似見直しの結果と対策・横展開処置・再発防止策の内容を証拠と比べ、原因と対策を1案へ確定して工程5へ渡す。
   3. 見送る問題も同じ工程で原因と比較を確定し、工程5の予告と工程6の最終報告を起草する前に、見送りの根拠が元の不成立、原因および比較の結果と対応することを`references/analysis.md`の基準で確かめる。
5. 工程4で確定した原因と対策を要求として、`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「起動方法」の単位でWI投入担当へ渡す。投入するAWIが1件以上ある場合は、担当を起動する前に、`agent-toolkit:completion-report`の`references/report-formats.md`「振り返り結果報告のフォーマット」に従う予告（AWIの欄は`（投入予定: <H1タイトル>）`）を可視の発話本文へ直接書く。可視出力だけで応答を終えず、同じ応答で担当を起動する。投入するAWIが0件なら予告を出力しない。要求ごとの`source`は`session-review`とし、要求間の依存（先行項目の正式名を待つ後続）も要求の趣旨へ書く。依存を渡す場合は、同書「渡す入力」に従って先行成果の必要性の根拠を要求へ含める。ユーザー発話を逐語引用する要求では、その原文を保持する記録ファイル（`conversation.md`や`atk run-script session-review-evidence`の出力など）の絶対パスを出所に含める。返却の検収は同書「受領と検収」に従い、メインが最終判断と報告を担う。
6. 検収の後の扱いは起動元に応じて分ける。`agent-toolkit:completion-report`から起動された場合は、振り返りの結果と投入結果（投入の有無、ファイル名、予告との差分）を同スキルへ渡す。手動起動の場合は同スキルの書式に従って最終報告を直接発話する。最終報告の種類は同スキルの冒頭の規定に従う。Stop hookは準備の結果と可視発話の報告見出しを使い、不足段階と`agent-toolkit:completion-report`が定める報告本文の判定の違反を示す。遮断への対処と、中止・待機の判断の記録は`agent-toolkit:completion-report`の工程の末尾に従う。

振り返り工程の所要時間目標は300秒とする。計測範囲は本スキルの起動から、振り返りの最終報告（投入するAWIが1件以上なら`## AWI投入結果報告`、0件なら`## 振り返り結果報告`）の出力までとし、予告の出力は計測の終点に含めない。目標は完了条件に含めず、超過は次の振り返りの所要時間の分析で改善の起点として扱う。

## 候補の抽出

候補は`atk run-script session-review-evidence`が生成し、`atk run-script session-review-prepare`が1候補を1行の要約と記録位置で`candidates.md`へ載せる。ユーザー介入とエスカレーションは本文の全文を載せ、hook通知には通知が判定した直前のアシスタント発話を添える。失敗したコマンドとツールは失敗署名で集約し、直近30日に複数の最上位セッションで観測した種類を候補へ載せ、単発の失敗は`candidates.md`の件数表と`single-session-failure`へ計上する。
次の結果は候補から除き、区分ごとの件数だけを`candidates.md`の候補から除いた件数へ数える。

- ユーザー介入ではない入力（`atk wi process-loop`、再開機構、実行環境が生成した定時prompt、委譲先の入力、初期要求、提示した選択肢をそのまま選んだ確認への回答）
- 想定外事象を持たず正常な完了だけを示す委譲返却
- 正常な否定結果（出力なしの検索、Gitのグローバルオプションや設定の未定義、単独の`atk`が返す`該当0件:`の行と終了コード1）
- 単独の`atk agents wait`が返す待機継続の終了コード3
- 検証コマンドが欠陥を検出した終了コード1
- auto mode classifierの一時的な判定不能と`atk wi add`・`edit`の本文表記診断の警告
- 応答言語hookの警告と、blockまたはwarn以外の区分のhook出力

検証コマンドの引数誤りやコマンド不在は除外の対象外とする。単独の`atk`と`atk agents wait`の除外では`失敗:`か`警告:`の行を伴う結果、別の終了コードおよび`&&`やパイプで連結したコマンドを対象外とする。連結全体の終了コードは単独のコマンドの結果と区別できないためである。各区分の判定条件は`scripts/session_review_evidence.py`の判定関数のdocstringが定める。
`気付いた改善点:`で始まる行を持つ委譲返却は、正常な完了の形式や本文長によらず`delegate-return`候補へ残す。
アシスタント本文の表示用短縮でも、省略区間の標識行を全文で保持する。メインが転記していない改善点も分析の入力となる。

## 分析失敗

`atk run-script session-review-prepare`が失敗した場合は、診断が一時的な原因を示すなら同じ入力で再実行する。同じ診断での再失敗を確かめた場合と、診断が一時的な原因を示さない場合は`agent-toolkit:wi-standards`に従い、セッションID、失敗事象、原因、解除条件および再現手順を持つ欠陥AWIを登録する。再開工程は「そのセッションをresumeしてsession-reviewを再実行する」とし、transcriptパスは記録の対象から外す。全記録をメインのコンテキストへ読み込んで分析すると、以降の判断へ回す容量が尽きる。
手動起動では分析未完了を報告できる。`agent-toolkit:completion-report`から起動した場合は、分析未完了と欠陥AWIを同スキルへ返し、元作業はそのまま完了させる。
