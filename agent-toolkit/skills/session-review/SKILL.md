# セッション振り返り

同じユーザー介入、レビュー反復、手戻り又は無駄が再発しないよう、対象セッションの問題を見つけ、原因と対策を確定した通常AWIを投入する。
分析と対策の確定はメインが同じセッション内で自身のコンテキストで行う。
セッションの文脈を持たない別の主体へ分析を渡すと、その主体は候補を読み直して文脈を組み立て直すところから始め、別の環境では元の記録へ届かない。
準備スクリプトは雑音になる候補を機械的に除き、会話の流れと問題候補の一覧を書くことで、メインが読む量を抑える。

## 実行主体

最上位セッションのメインエージェントが自身のセッションを振り返り対象として本スキルを起動する。別のエージェントからタスクを受け取った実行主体は自身をサブエージェントと判定し、起動判断を呼び出し元へ返す。1つの実行主体が対象セッションの全ての記録をまとめて抽出するため、個別起動は候補の重複又は欠落を生じさせる。
メインは振り返りの担当を起動せず、次の工程を自ら実行する。投入前のChallengerレビューは`agent-toolkit:wi-standards`の通常の手順として起動する。

## 工程

1. セッション領域（`agent-toolkit:managed-temp`）の中へ、実行ごとに異なる名前（`session-review-<時刻>`など）の作業ディレクトリを作成し、準備スクリプトを次のいずれか1つの形で1回実行する。同じセッションで振り返りを再実行した場合に前回の出力を上書きしないよう、名前を実行ごとに変える。Claude Codeで把握している現在のtranscript絶対パスを`--transcript`へ渡し、Codexでは`CODEX_THREAD_ID`を`--codex-thread-id`へ渡す。`--target-repo`は対象リポジトリを確定できた場合だけ渡す。

   ```text
   atk run-script session-review-prepare -- --transcript <transcriptの絶対パス> --work-dir <作業ディレクトリの絶対パス> --target-repo <対象リポジトリの絶対パス>
   atk run-script session-review-prepare -- --codex-thread-id <thread ID> --work-dir <作業ディレクトリの絶対パス> --target-repo <対象リポジトリの絶対パス>
   ```

   準備スクリプトは証拠bundleを抽出し、作業ディレクトリへ会話の流れ（`conversation.md`）、問題候補の一覧（`candidates.md`）、セッション統計（`stats.md`）を書く。キューは変更しない。
   標準出力の1行JSONは、3つの文書の所在（`conversation_path`、`candidates_path`、`stats_path`）と、対象リポジトリ固有の振り返り参照文書（`reference_document`。無ければnull）を持つ。また、準備時刻（`prepared_at`）と発話件数（`utterance_counts`）を持つ。さらに候補件数（`candidate_total`と種別ごとの`candidate_counts`）、除外件数（`excluded_counts`）、経過秒（`elapsed_seconds`）及びコンパクション回数（`compaction_count`）も含む。
   終了コードが0でない場合と、標準出力が1行のJSONではない場合は`## 分析失敗`へ進む。
2. `conversation.md`を読み、セッション全体の流れを振り返る。探す対象は遠回り、手戻り、同じ論点の反復、ユーザーによる是正、時間を費やした工程である。推測で組んだコマンドの試行錯誤、同じ資料の読み直し、採用した設計の書き直し、規範の解釈へ費やした工程、委譲先への指示不足による手戻りは標識を残さず候補に現れないため、会話の流れから探す。会話圧縮で自身のコンテキストから失われた区間も、会話の流れから読む。`reference_document`が値を持つ場合は、その文書を全文読み、対象リポジトリ固有の振り返り観点と所要時間目標を解決する。
3. `candidates.md`と会話の流れから問題を選別し、`agent-toolkit:bugfix`を適用して原因と対策を1案へ確定する。判断基準は`references/analysis.md`を全文読んで適用する。確定に証拠の全文が要る候補だけ、候補一覧が示す記録位置を抽出器の`--detail`へ渡すか、`--grep`で照会する。所要時間の分析には`stats.md`を使う。
4. 確定した対策を`agent-toolkit:wi-standards`の通常AWIとして起草する。同じ振り返りで確定した全本文を`${CLAUDE_PLUGIN_ROOT}/share/wi-draft-review.parent.md`のChallengerレビュー1回へまとめ、`atk wi add --source session-review`で投入する。
5. 結果を`agent-toolkit:completion-report`の振り返り結果報告へ渡す。

振り返り工程の所要時間目標は300秒とする。計測範囲は本スキルの起動から、振り返り結果報告の出力までとする。目標は完了条件の外に置き、超過は次の振り返りの所要時間の分析で改善の起点として扱う。

## 候補の抽出

候補は抽出器が生成し、準備スクリプトが1候補を1行の要約と記録位置で候補一覧へ載せる。ユーザー介入とエスカレーションは本文の全文を載せ、hook通知には通知が判定した直前のアシスタント発話を添える。
抽出器は対象セッション自身の常駐処理、再開機構、実行環境が生成した定時prompt、委譲先の入力、初期要求、提示した選択肢をそのまま選んだ確認への回答を利用者介入の候補から除き、block又はwarn以外の区分を持つhook出力を候補から除く。選択肢のいずれとも一致しない回答と自由記述を伴う回答は候補に残す。
想定外事象を持たず正常な完了だけを示す委譲返却（1回の配送で終えた委譲先の前置きの文を持つものと、報告した終了コードが全て0で失敗・警告・診断の無いコマンド実行の委譲を含む）は候補から除く。検索が出力なしで一致0件を返した結果（パイプラインの最終段の検索と、検索を起動する`xargs`の終了コード123を含む）及び`atk wi add`・`edit`の本文表記診断の警告も候補から除く。hookが遮断したツール呼び出しの失敗とhook通知と同じ本文の警告はhook通知の候補へまとめ、発生源と区分ごとに件数の多い種類とツールごとの最多の種類を残す。

## 分析失敗

準備スクリプトが失敗した場合は、同じ入力で1回だけ再実行する。再失敗した場合は`agent-toolkit:wi-standards`に従い、セッションID、失敗事象、原因、解除条件及び再現手順を持つ欠陥AWIを登録する。再開工程は「当該セッションをresumeしてsession-reviewを再実行する」とし、transcriptパスは記録の対象から外す。全記録をメインのコンテキストへ読み込んで分析すると、以降の判断へ回す容量が尽きる。
手動起動では分析未完了を報告できる。`agent-toolkit:completion-report`から起動した場合は、分析未完了と欠陥AWIを同スキルへ返し、元作業はそのまま完了させる。
