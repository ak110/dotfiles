# 振り返りの判断基準

`agent-toolkit:session-review`の`SKILL.md`「工程」で、メインが通読で見つけた問題と問題候補を選別し、原因と対策を確定するときの判断基準を定める。工程と入出力は同スキルのSKILL.md、振り返り結果報告の書式は`agent-toolkit:completion-report`が定める。

## 入力と照会

入力は`atk run-script session-review-prepare`が書いた会話の流れ、`candidates.md`、セッション統計と、メイン自身のコンテキストとする。会話の流れは観点を限定せずに問題を探す起点、`candidates.md`は通読の問題との対応付けと通読では得られない事象の追加に使う。
既読証拠は同じ記録位置と内容に対する判断へ再利用する。再準備した場合は追加・変更箇所が既存判断を変えるときだけ詳細を読み直す。

会話の流れは準備が生成した`conversation.md`の全体をメインが1つの時系列として確認する。委譲入力・規範読込の概要は`comparison-materials.md`、メインと全担当の費用はセッション統計から得る。比較材料は記録別の参照資料として対象・時点・全文位置を選ぶのに使い、詳細は必要な記録位置だけ照会する。
比較材料では、直接本文とファイル参照、明示読取と命令文字列だけの観測、返却本文の量と現在のファイルサイズを区別する。参照ファイルの本文量・自動配送・読了は、受領記録などの証拠が無ければ未確認とする。tokenとcacheは実行系の計数定義を使い、Codexの総inputへcached inputを再加算しない。候補文書と統計文書の未確認範囲は未解決の記録と識別子を得られなかった呼び出しを示すため、正常な件数だけから全範囲を確認済みとしない。

直接原因を確定できない候補と、比較する操作や成果の材料が概要から欠ける場合は、異常候補が先に無くても次の手段で全文と契約を取得する。会話圧縮はメインのコンテキストから区間を失わせるだけで記録には圧縮前のイベントが残る（Claude Codeの`compact_boundary`、Codexの`compacted`）ため、圧縮された区間の事象も分析の対象とし、記録から確認できないことを原因未確定の根拠にしない。

- 記録位置を`atk run-script session-review-evidence --`の`--detail`へ渡して全文を取得する。検索語からは`--grep`、委譲先を含むツール呼び出しの列挙は`--tool-calls`を使う。同コマンドは委譲先（Claude Codeのサブエージェント記録と`agents_server`の子セッション記録）を再帰的に収集する
- 記録に理由の本文が無い事象は、同じ呼び出しの再実行による再現と実装の読解で確定する

照会と再現を試みても確定できない場合（記録ファイルの削除、`unresolved-delegation`として報告される委譲先など）に限り原因を未確定とし、確定できない理由の結論と再取得先を振り返り結果報告の「対策を見送った問題」へ書き、照会と再現の経過は証拠へ残す。
介入の趣旨などユーザーの判断を要する要素が残る候補は推測で確定せず、`agent-toolkit:user-confirmation-and-report`に従って確認する。

全候補を通読で得た問題と取得済み証拠へ対応付け、同一事象の根拠が足りる部分は再利用する。追加・変更・未確認・不一致だけを補完する。メインは全体像、原因と採否の確定を担い、基準付き走査の非該当全件を重ねて再走査しない。

## 一次選別

通読で見つけた問題は同じ事象を指す候補とまとめ、対応する候補が無いものも独立して原因分析へ進める。
候補の種別によらず、元の期待する契約、実際の不成立、発生条件を判定する。回復した場合（本文の受領・追送・代替手段での完了など）も元の原因を分析し、回復の事実と要した操作は別に記録する。遮断・警告の解消後に目的を達した後続作業も、一連の作業の品質・総費用として次の共通比較へ渡す。
必要な裏付け調査、出力上限に従う分割読取、起動時のスキル展開、変更後の再確認、用途に沿う歴史資料の参照は、元の契約の不成立を観測しない限り、回数、日付やroleだけでエージェントの誤りへ分類しない。規範が求める工程の量の過大さは「規範適用による目的逸脱」で判定する。
契約の不成立という欠陥と、品質を保って費用・時間を下げられる改善機会を区別する。成功した通常操作、正常な返却、良い手段の再利用も、不成立が無いことだけで除外せず、成立条件・代替手段・総費用を比べる。準備・実行・検収・後始末・値の転記・工程境界を含む一連の作業と、離れた区間で同じ入力を組み立て直した反復も対応付け、各操作が守る成果と要求元から、責務の移動・統合、既存機構の利用、削除・簡素化で品質を保てる案と現状維持を比べる。良い手段があることだけでAWIを増やさず、改善を要する消費側と得られる結果を特定して「原因と対策」へつなぐ。材料は既存の通読と必要な詳細照会から得て、新しい候補抽出、監視、常設担当や全操作の台帳は本判断の対象外とする。
情報探索・参照の問題は、選別の段階から「情報探索の問題」に従って探していた情報と証拠を対応付ける。
除外するのは恒久対策を要しないことが明確な候補だけとし、根拠を「対策を見送った問題」へ書く。探索の深さと再発防止策の要否・終了は重大度に応じて判断する（`agent-toolkit:bugfix`の`SKILL.md`「QとC・Dの区別」）。ユーザー自身の秘匿値の露出と、その対応の要否・時機を伝えた発話は、`agent-toolkit/rules/01-agent.md`「完遂と先送り」の扱いで終えていれば除外区分`own-secret-exposure`で判定済みとし、過剰反応自体の是正をユーザーが求めた発話は分析へ送る。既存規範が作業中に適用されなかった問題は条文の存在を理由に除外せず、不確かな候補も分析へ送る。
過去の振り返りやキュー処理で不採用が確定した案は、新しい観測か要件変更を対応付けられる場合だけ再評価する。

- 失敗したコマンドとツール: 複数の最上位セッションで反復した失敗署名ごとに、終了コード、コマンド、診断、発生セッション数から原因を調べ、再発防止策か採らない理由を確定する。反復の有無は実際の記録から判定し、反復の未観測だけでは恒久対処の要否を確定しない。単発の失敗は、会話の流れから遠回りや手戻りの原因と分かった場合だけ分析へ送る
- 委譲返却: 正常な完了だけの返却を除いた残りを本文の内容まで判定し、想定外事象を持つ返却はその事象を判定する。`続行できない理由:`の行を持つ返却（旧形式の状態値で続行不能を示した返却を含む）は独立した候補とする
- hook通知: 候補にはblockかwarnの通知だけが載る（応答言語hookの警告は`response-language-notice`の件数だけ）。通知ごとに、操作の目的、`--detail`で得た原記録、通知に従った後の結果を対応付ける。そのうえで操作の出力の不良、呼び出し方に規範を適用しなかったこと、通知の案内と実際の操作の不一致を区別する。
  発生源ごとに`agent-toolkit:writing-standards`の`references/claude-hooks-block-warn.md`の事前に防ぐ型か遮断後に対処する型かを判定する。遮断後に対処する型の発火は欠陥として扱わず、1回の対処で解消しなかった場合、同じ呼び出しで反復した場合、頻度から同書の費用比較の結論が変わる場合だけ見直す。
  事前に防ぐ型には規範、判定条件、フック撤去、遮断後に対処する型への移行から1件以上の改善案を対応付け、現状維持ならその発火が規範どおりに操作を停止させた根拠を書く。事前工程を加える案はその工程が操作ごとに増やす呼び出しを費用として書く
- 権限拒否: `agent-toolkit:user-confirmation-and-report`の`references/permission-denial.md`「偽陽性と判断できる拒否への対応」の適用条件が成立していたかと、成立していた場合にそのフローが適用されたかを判定する。
  委譲先の拒否は委譲元の記録で判定する。成立していたのに適用されなかった拒否は「原因と対策」へ送り、進行への影響の有無によらず未適用の原因と処置を判定する。許可ルールを変える案は、拒否本文と分類名を証拠として`agent-toolkit:writing-standards`の`references/auto-mode.md`のワークフローへ送る
- 手順書の作業を一時スクリプトで代替した箇所: その手順が後で再実行されるか（有効期限のある資格情報の更新、設定の再登録、別環境の構築、定期作業など）を、手順書の本文と扱う値から判定する。再実行されるなら、スクリプトを手順の所有リポジトリのスクリプト置き場へ置き手順書をそれを使う形へ改める対策を、そのリポジトリを`target_repo`とする通常AWIとして「原因と対策」へ送る（同じセッションで是正済みなら除く）。1回限りの作業は対象外とする
- その場のコードによる加工: `adhoc-processing`の候補と通読で見つけた後加工や同目的のコマンドの反復について、呼び出しごとの目的（何の出力から何を得たか）を特定し、反復するかを判定する。同じセッションで同じ目的の加工が2回以上ある場合、スキルや規範の手順が実行のたびに求める工程（逐語引用の文字位置の計算など）を進めるための加工、`agent-toolkit`のコマンドの出力の形が必要にした加工は反復とする（後の2つは1回の観測でも反復）。反復する加工は「原因と対策」へ送り、比べる案と評価順は`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「反復する加工の問題」に従う。反復しない1回限りの調査は、目的と反復しない根拠を「対策を見送った問題」へ書いて除く
- `気付いた改善点:`で始まる行: その場で原因分析をしていない改善の機会として「原因と対策」へ送る。その場でユーザーへ伝えたことを除外の理由にしない

### ユーザー介入の判定規則

ローカルな終了操作と関連する訂正・続行は、共通判定の`non-changing-request`に従い分析・報告から外す。通読や候補一覧に残る場合も問題・再発防止要求・見送りの説明へ変換しない。終了操作の語を含む別の要求や方針変更は趣旨どおり扱う。この扱いは「一次選別」と「原因と対策」の報告にも適用する。

介入・WIの記入欄の是正・ユーザー確認の必須性と除外区分は、`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「ユーザー介入と確認の判定」に従う。元発話と構造化確認の全欄を判断の入力とする。
介入として抽出された発話が生成本文だった場合の人間入力への誤分類も共通分析へ渡す。生成本文の判定は`agent-toolkit/agent_toolkit/_common/runtime_inserted.py`と`session-review-evidence --user-events`の抽出条件が持つ。

## 比較して探す観点

### コストの無駄の確認

毎回、準備済みの読込・反復・結果量の集計と、メイン・全担当のトークン内訳を使い、次の17観点を確認する。
編集・外部更新・圧縮後の再読、分割取得、独立検収と別文脈での判断に必要な読込を、削減可能な重複と分ける。
無駄と判断したものは「原因と対策」へ送り、改善を採用しないものは見送りの根拠を残す。
確認は毎回行い、欠陥の判定には回数や量とともに対象・担当・目的の対応を使う。

| 観点 | 比較する材料 |
| --- | --- |
| 同じファイルの重複読込 | 対象別の合計・担当別回数、範囲、結果量と位置 |
| 同じ記録内の再取得・再実行 | 同じツールと入力の反復 |
| 大量結果の直接取込み | 結果本文量の上位と委譲・対象限定の代替 |
| スキルと規範の累積読込 | Skill名別集計、参照資料と目的 |
| 委譲入力の過剰・冗長 | 比較材料の直接本文量と参照可能な本文 |
| 複数担当の重複調査 | 対象別の担当回数と独立検収の必要性 |
| モデル段位の不適合 | 担当別の実モデル・トークンと判断の難度 |
| 委譲の総費用 | 担当別トークン・応答回数・返却量と成果 |
| キャッシュ効率 | cache_creationの反復、応答間隔と再開 |
| 会話圧縮と読み直し | 圧縮回数と圧縮後の読込 |
| 照会・待機の反復 | 反復集計と終了を返す待機手段 |
| 振り返り自身の費用 | 再準備と証拠照会の反復 |
| レビューの往復・後出し | 通読と担当別トークン、再読・再検証 |
| 重複した検証 | 通読、遅い呼出しとCIの検証範囲 |
| 入力形式の誤りによる再試行 | 通読と反復集計 |
| 出力トークンの過大 | 応答別トークン上位、報告と再掲 |
| 使われなかった取得・返却 | 通読、読込集計と後続の消費 |

この確認の結論は報告の`費用確認`へ1行で示す。
以下の比較表は全範囲を通読する補助であり、この毎回の確認と併用する。

### 通読で使う比較

全範囲の通読で、対応する操作や成果がある観点を比較に使う。表は例示であり、表の外にも目的・契約・利用結果・QCDの同じ比較を適用する。各行の毎回の合否記入と、文字数・回数・token量だけによる欠陥・必須対策の判定は対象外とする。既存の判断に接続する行は該当節を参照する。

| 観点 | 比較する記録・成果と判定への接続 |
| --- | --- |
| 範囲の拡大 | 当初の成果と計画改訂・委譲・最終差分を比べ、設計やレビュー由来の追加も探す。規範由来は「規範適用による目的逸脱」を使う |
| 例示への固定 | 目的と例示、比較案と利用結果を比べ、例示の外も目的を満たす対象へ含める |
| 割込・圧縮後の脱落 | 要求の追加・変更・撤回・完了と引継ぎ・保留・最終報告を比べる |
| 完了条件のすり替え | 要求された利用結果と検証主体・公開確認・最終報告を比べる |
| 必要な確認の負担 | 質問・全選択肢・回答・再質問と必要な判断材料を比べ、確認の必要性と提示の重複・明瞭さを分ける。必要性は「ユーザー介入の判定規則」を使う |
| 説明と行動の不一致 | ユーザーの問い、判断変更の説明、実際の操作、最終報告を比べる |
| 実利用への適合 | エンドユーザー・利用場面と成果物・実操作の証拠を比べ、形式的成功だけで決めない |
| 証拠以上の事実主張 | 報告の主な事実主張と取得結果・終了状態・省略・未確認範囲を比べる。「情報探索の問題」に接続する |
| 実装と同じ誤解を持つテスト | 要件由来の期待結果・反例と実装・テストを比べ、「原因と対策」の契約比較に接続する |
| 合格を目的にした対処 | 失敗から合格までの差分、除外設定・期待値と必要機能を比べる |
| 検証対象の不一致 | 最後の修正・生成・検証の時刻、パス、版、OIDと完了根拠を比べる |
| 前提確認の遅れ | 権限・環境・正常な手順の初期確認と後半の手戻りを比べる |
| 根拠の無い追加設計 | 状態管理・監視・互換・フォールバックの設計理由と観測事象・消費側を比べる |
| 必要な追従の不足 | 生成元・消費側・公開手段・配布先・OSペアと最終結果を比べ、全消費側の契約確認へ接続する |
| 委譲単位の過小・過大 | 作業の独立性・規模と準備・入力・返却を比べ、直接実行と委譲の総費用を評価する |
| 不要な工程依存 | 先行成果を使う実際の入力と起動・返却・待機を比べ、時刻の重なりだけで依存と決めない |
| 作業量の偏り | 担当範囲・複雑さと担当別の所要を比べ、単純な件数差だけで原因と決めない |
| 重複調査 | 各担当の既知情報・検索・読取と入力・返却の再利用を比べ、必要な独立検収と分ける |
| 委譲入力・所有権の不足 | 目的・完了条件・版・パス・権限・境界と追加質問・担当外操作を比べる |
| 正常返却の未検収 | 正常返却と元の完成条件・実成果・検収記録を比べる。候補からの正常除外を一律撤回せず全文を照会する |
| レビューの後出し・往復 | 各回の指摘・修正・判定変更と初回に取得できた根拠を比べ、第3ラウンド以外も探す |
| 成功した呼出しの集約 | 「所要時間の分析と改善」の成功した同種の反復と公開の複数対象指定の比較を使う |
| 既存機能の未利用 | 必要な操作とヘルプ・公開オプション・実際の手作業を比べ、加工を伴わない通常操作も探す |
| 表記が異なる同原因の失敗 | 診断・意図・回復を比べ、署名が異なっても契約の同じ誤解を探す |
| 成功するポーリング | 照会の時点・状態変化と終了を返す待機機能を比べ、成功した短い照会も扱う |
| 出力設計による読み直し | 元出力と必要情報・追加照会・回復を比べ、不要な情報・項目欠落・表示の使いやすさを探す |
| 読取操作の副作用 | 許可した操作と実装・設定・前後差分を比べ、正常終了でも共有状態の変更を確かめる |
| 資源の所有と終端 | 起動識別子と終了・回収の証拠を比べ、完了の申告だけで所有資源の終端を決めない |
| 証拠の寿命 | 保存先・回収時点と後続の消費工程を比べ、必要な時点で照会できるか評価する |
| 累積読込量と重複 | スキル起動列・参照資料・時点・取得量と目的の操作を比べる。「規範適用による目的逸脱」に接続する |
| 毎回の費用確認 | 担当別のRead対象・範囲・Skill・結果量、反復上位、大量結果の位置、メインのtoken上位を既存の統計から確認する。必要な読込と削減可能な重複を分け、確認結果を報告へ1行で示す |
| 想起しにくい構成 | 判断前の迷い・再読と条文配置・適用条件を比べ、失敗前の探索も扱う |
| 版・時点・配布手段の混在 | 実行時の導入版と参照パス・生成物・履歴を比べ、事象時点の文面を確かめる |
| 代替指標の目的化 | 件数・書式・工程通過・警告消失と要求結果を比べる |
| 責務と読者のずれ | 担当の責務・使う情報と文書の適用範囲・読込契機・要求入力を比べ、量だけで誤読込と決めない |
| 対策累積の複雑化 | 過去対策・条文・例外と通常作業の読込・確認・理解の負担を比べ、除去・集約を検討する |
| 失敗の無い改善機会 | 正常な作業の全手順・利用結果と既存手段による代替を比べ、加工・規範・時間の類型以外も探す |
| 良い手段の再利用 | 同目的の実作業間で入力・工程・品質と成立条件を比べ、改善を要する別の消費側へ適用できるか判断する |
| 不具合の起きなかった適用機会 | 同条件の対策前後、適用証拠と結果を比べ、条件の不発生と原因への効果を分ける |
| 対策の副作用と総費用 | 対策差分・適用頻度と通常の操作の増分を比べ、ツール・テスト・状態管理も対象にする |
| 測定単位のずれ | 統計の定義・母集団・外部待ち・cache・担当構成と品質結果を比べる |
| 改善要求の分断と滞留 | 既存キューの共通原因・状態・日時と実施結果を比べ、登録件数を効果へ代用しない |
| 振り返り自身の費用 | 準備後の起草・投入・質問・終了記録と目的を比べる。振り返り自身の確認のためだけに再準備を繰り返さず、終端した区間を既存照会で扱う |
| 抽出の偽陰性 | 原記録と候補・除外区分・抽出条件を比べ、正常返却や単発失敗の除外を代表例で確かめる |
| 縮約による文脈喪失 | 縮約された入力・成果と全文・差分を比べ、比較材料の不足からも詳細照会へ進む |
| 正常・非律速委譲の問題 | 担当別入力・返却・費用と完成条件、必要な内部位置を比べ、非律速を品質・費用の除外理由にしない |
| 要約に出ない費用 | 担当別tokens・cache・応答回数・入力規模と時間を比べる |
| 実行系・呼出形式の被覆差 | 同種の記録と抽出の入力契約・実ログ・形式別の検証を比べ、ラッパー内部を無条件に同等とみなさない |
| 未確認範囲の受渡し | 「入力と照会」の未解決記録の扱いを使い、確認済み範囲と照会不能を分ける |
| 委譲入力の過剰・冗長 | 起動・追送本文と参照ファイルの本文、配送済み規範、必要な事実・認可・範囲を比べ、繰返し・不要情報・先入観を分けて評価する |

## 原因と対策

選別した問題と時間分析で得た律速条件は、発見元の分類や前例の有無を問わず`agent-toolkit:bugfix`を起動して共通手順へ渡す。問題の選別と見送りの判断（QとC・Dの区別、重大度、再発防止策の必須性と使えない根拠）は同スキルの起動時に届く`SKILL.md`の初動基準で行う。具体的な原因分析へ進む場合の介入の判定、規範の未適用と目的逸脱、反復、類似見直し、処置の階層は同スキルの`references/root-cause-analysis.md`に従う。
過去の項目は`candidates.md`の同種記録と、由来・状態を限定しない`atk wi grep --summary-only --state=all --target-repo=<対象リポジトリの絶対パス> --skip-pull -F -- '<語>'`が返す候補から得る。本文は`atk wi show`で読む。記号を正規表現として使う場合だけ`-F`を外して`'<Pythonの正規表現>'`を渡す（終了コード1は正常な一致0件）。同種記録は文の大半の一致で探すため、言い回しの異なる是正は本文検索で補う。取得した記録と今回の条件を同スキルの過去対策との比較へ渡し、比較の根拠は証拠へ、原因分析と振り返り結果報告には結論と再取得先を記録する。反復した問題は過去項目名、前回の段、原因が残った条件も記す。未終端AWIへの投入の要否は「既存キュー項目との重複確認」で別に判定する。

振り返り結果報告への記録:

- 共通判定で除外した介入・WI記入欄の是正・確認は、`判定済み`の根拠の先頭へ除外区分を書く
- 候補の表示と報告の追跡は`SKILL.md`の候補IDと報告の契約を使う
- 分析後の見送りは、非欠陥・原因未確定・処置を採用しない判断を分けて根拠を「対策を見送った問題」へ書く。見送りの根拠は、`agent-toolkit:bugfix`の`SKILL.md`「再発防止策の必須性」が定める使えない根拠（適用が抜けた既存規範、後段での回復、別論点の判断、未確定の寄与）に当たらないものに限る。再発防止策なしの終了は`agent-toolkit:bugfix`の`SKILL.md`「QとC・Dの区別」で判断し、Q影響、重大度、探索範囲・限界・許容する残存リスク、評価した案と採らない理由・反復を記録する。重大な問題で成立する手段が無ければ未達として`未確定`の行へ書く
- 欠陥の処置は通常AWIへ渡す。1件の再発防止策で複数問題を覆う場合も、各根本原因と処置の対応を分析記録と対策要求へ残す

報告・確認・UWIの手段と回答待ちは`agent-toolkit:user-confirmation-and-report`に従う。

### 情報探索の問題

探索の証拠と原因・対策はbugfixの`references/root-cause-analysis.md`「情報探索の問題」で確定する。対策要求には探していた情報、探索区間、文書の順序、定義元と阻害理由を（資料の陳腐化では参照した記述・現行との差・判断への影響も）、根拠の絶対パスと記録位置へ対応付けて渡す。AWIの節の分担は`agent-toolkit:wi-standards`、原稿と根拠の検収は`share/add-wi.parent.md`「受領と検収」に従い、振り返り結果報告からはAWIのファイル名で到達できるようにする。

## 既存キュー項目との重複確認

AWIの起草では`agent-toolkit:wi-standards`の`references/drafting-completion.md`「重複判定」に従って未終端の既存項目と比べる。既存項目が事象、原因、完成条件を全て覆う場合は投入せず、そのファイル名と対応根拠を「確定した問題と対策」へ書く。一部だけを覆う問題と新しい証拠を持つ問題は不足分を起草する。過去対策の有効性と反復は「原因と対策」で判定し、本節の重複とは区別する。

## 規範適用による目的逸脱

事象と原因・対策はbugfixの`references/root-cause-analysis.md`「規範の未適用と目的逸脱」「前提の再検討」で判定し、条文の所在（ファイルと節）、観測した停止、採用案と根拠を記録する。
正常に完了した場合も、読込・準備・検収・後始末の量と守る成果を比べ、規範が求める工程の簡略化を比較の対象にする。
維持する条文の再現条件と許容理由は「対策を見送った問題」へ書き、改訂を採用する場合は対象の条文を扱うAWIへ渡す。`agent-toolkit:review-standards`の`references/judgment-details.md`「規定の適用可否」が求める改訂の提案はこの投入で扱う。

## 所要時間の分析と改善

セッション統計から寄与の大きい工程と反復を特定し、品質を保ったまま単位時間あたりに処理するユーザー由来のWIの件数を最大化する改善を確定する（エージェント由来のWIは別に数える。所要時間とトークンコストの削減はこの尺度を高める手段）。律速条件を確定したら「原因と対策」の過去対策との比較へ進み、その結果を当回の短縮案へ反映する。律速順位と300秒目標は調査の優先順に使い、改善候補は全体から選ぶ。短い成功操作も、適用頻度、入力を組み立て直す費用、トークンと保守の費用を含めて比べる。
メイン区間、レーン内部、公開・検証区間、振り返り自身のいずれにも同じ判断を適用する。
振り返り自身の300秒超過は`SKILL.md`の工程6から今回の分析へつなぐ。起動から最終報告までの超過を1事象とし、原因、必要な全処置と報告内容が確定した時点で処置済みとする。追加WIの投入で経過秒が増えたことだけでは同一事象の分析を再起動せず、別の原因が判明した場合だけその原因を「原因と対策」と通常のWI投入へ加える。準備後のユーザー発話による再実行は、処置済みでも`SKILL.md`の工程6に従う。

- 短縮の対象は統計が示す律速区間（メインだけの区間とagent thread別の排他区間）とする。threadの排他区間が律速なら、内部の工程・反復・待機の内訳を`stats.md`の`律速threadの内訳:`から得て、全文が要る位置だけ`--detail`か`--grep`で照会する。委譲先の所要時間と反復回数は`agent-toolkit:writing-standards`の`references/session-records.md`「集計値の典拠」の3つの確認に従って比べる。未計測として除くthreadは、記録ファイルが無いか`unresolved-delegation`と報告された対象に限り、その対象を記録する
- 委譲先の返却本文が述べる時間の使い道と、所要時間目標が適用されないことは見送りの根拠にしない。候補ごとに原因への作用と品質・費用を比べ、内部を分解していない区間は内訳未確定とする。計測できない短縮秒数と、記録から成立を判断できる工程の改訂は区別して採否を決める
- 対象は必須工程と検収範囲を含む全工程（`agent-toolkit:process-wi`と`atk wi process-loop`の手順、それが従う規範、本スキルの工程と`atk run-script session-review-prepare`を含む）とし、撤去、順序の変更、並行化を候補とする。手順や規範の撤去・置換は、条文の保護対象と成果、導入した変更と計画ファイルから導入目的を調べて採否を決める。目的と保護の必要性は、現在の要件と認可の下で`agent-toolkit:wi-standards`の`references/drafting-completion.md`「方針と判断の記録との比較」に従って評価する。現在も必要な目的は、より低い費用の手段で満たせると確定した場合に置き換える
- 重複した検証の排除と待ち時間の活用を観点に含める。CIが同じ検証を担う環境では公開前のローカルの全体検証を重複とし、CIが長い環境でCI失敗の見込みが高い場合に限り、変更箇所と直接影響範囲への部分実行を先に行う
- 外部サービスの利用上限、レート制限、課金枠による待機の扱いを変える対策は、AWIで確定する前に`agent-toolkit:wi-standards`「由来と承認」の程度・裁量の判定を適用する。
  待機やモデル・実行先の切替には「確認要否の判定」を適用し、指定された費用・サービス・待機条件を保つ技術判断は自ら確定する。比較には停止、実行先の切替、打ち切り、上限の事前回避に加えて現行の待機を続ける案も残す
- 短時間に反復したコマンドも、呼び出しごとの所要時間と律速区間への寄与から見直す（努力目標）。入力形式の誤りによる反復は最下層のヘルプか仕様の取得を先行させ、成功した同種操作の反復は複数対象の指定で統合できるかを比べる
- 複雑なシェル実行の専用ツール化の候補は「一次選別」のその場のコードによる加工の反復判定で決め、比べる案・評価順・採用条件は`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「反復する加工の問題」に従う。手順書の作業を一時スクリプトで代替した箇所は、後の再実行を「一次選別」の同じ箇所で判定する。Claude CodeとCodexに同じ基準を適用する
- コンパクションは回数と合計時間を記録し、コンテキスト消費自体を減らす案（取得範囲の限定、調査の分離など）を比べる。発生閾値の引上げは候補から除く
- 改善へ結び付いた件数が少ない候補区分は、抽出条件を限定する候補とする
- 案の採否は品質への影響と、トークンコストと保守コストの大幅な増加の有無で判定する

改善効果は既存の統計と証拠で裏付けられる範囲だけを数値にする。短縮秒数を数値化できるAWIには1セッションあたりの見込みと典拠の統計値を観測・推定の別とともに書き、推定には算出式と前提を添える。根拠が足りない場合は削減できる工程と未計測を記し、秒数作成だけを目的とする再収集は求めない。複数案の合計、改善後の全体時間、目標との差と超過の律速区間は振り返り結果報告へ1回だけ記す。前後比較は同じ観測済み区間の集合に限る。
所要時間目標は振り返りの完了条件から外し、超過の有無によらず既存の統計・証拠を使い、根拠が不足する律速区間だけを追加照会・再現する。超過しなかった場合は得られた証拠から改善提案の要否を判断し、有効な処置を特定できなければ特定できない理由の結論と再取得先を「対策を見送った問題」へ書き、試みた照会と候補比較は証拠へ残す。超過した場合は再発防止策を必須とし、律速区間へ作用する対策を確定する（所要時間だけの問題はC・Dだけの問題として扱い、良い案が無ければ`再発防止策なし`の行へ書く）。今回の律速区間への処置は、AWI化基準など別の対象への先行回答と分けて確定する。先行回答はその質問が対象とした要求だけに使い（`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「原文からの具体化を要する軸」）、新しい律速原因は過去の不採用判断や既存AWIの存在とは別に原因への作用で採否を決める。見送りの理由は証拠から示し、目標を達成の判定、工程の省略、停止や先送りの条件に使わない。
所要時間、トークン量、リクエスト数をユーザーが読む文面へ書く場合はセッション統計の値だけを典拠とし、比率には`agent-toolkit:writing-standards`の`references/session-records.md`「集計値の典拠」の基準差を併記する。

モデル別にトークン量から時間を見積もる場合は、モデル・推論設定・runtime・接続条件をそろえた応答単位の所要とusageを使い、入力、cached input、出力の重複を除いて校正する。
例えば`応答秒数 = 固定費 + 未キャッシュ入力の係数 × 未キャッシュ入力 + キャッシュ入力の係数 × キャッシュ入力 + 出力の係数 × 出力`を候補とし、別の応答で誤差を確かめ、標本数と誤差範囲を添える。
セッション全体の経過秒数には並行実行・ツール実行・人間や利用上限の待機が混ざるため、それを総トークンで割った値をモデル速度へ使わない。
校正に必要な対応記録が得られない場合は数値予測を未確定とし、既存証拠から再読・重複調査・入力の再生成などの削減対象を比較する。
時間超過時は推定式の残差だけでモデル過負荷へ帰属させず、工程と待機の内訳を確認し、品質を保つトークン削減と既存機構への集約を比べる。
