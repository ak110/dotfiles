# 受入シナリオ検証の試行と常駐サービスの観測

本書は受入シナリオ検証（`${CLAUDE_PLUGIN_ROOT}/share/workflow-phases.md`「用語」）を実施するエージェントへ、エージェント向け文書の改訂を試行で検証する手順と、本番の起動単位から起動する対象を公開前に観測する起動条件を提供する。

## エージェント向け文書の試行

エージェント向け文書の改訂を固定入力へ適用する試行では、実装担当が読み取り専用の委譲へ入力と対象文書を渡す。
委譲先はスキルを実際に起動せず、文書の判定手順を入力へ適用して結果を返す。
文書の読取範囲と返却根拠には`${CLAUDE_PLUGIN_ROOT}/share/agents-server-explore.md`「文書の判定試行」を適用する。別の読み取り専用の起動手段を使う場合も、その契約を委譲入力へ含める。
実装担当は対象節全体と必要参照先の読取、対象版・節・結論・根拠所在と逐語引用・判定不能点を返却から確認する。抜粋だけの判定や未読を文書不足とする返却は、同じ担当へ必要な読取を指示してから合否を判定する。
実装担当は返却を期待結果と比べ、入力・対象文書の版・返却結果・比較と合否をmanaged-tempの記録へまとめ、その記録の絶対パスを検証結果へ記す。
対象文書の版は、対象リポジトリのcommitと相対パス、または本文を複製した絶対パスで再取得できるようにする。
入力や返却を別ファイルへ保存した場合も、同じ記録にその絶対パスを記し、実行レビュー担当が取得できるようにする。
シナリオが原稿の生成と保存を求める場合は、返答に含まれる原稿も実装担当が保存し、同じ記録へ原稿の絶対パスを記す。
この試行の検証は実装担当が所有する。試行ではスキルを起動しないため、各スキルが定める起動してよいエージェントの制限（`agent-toolkit:session-review`を最上位セッションのメインエージェントに限る規定など）は試行の委譲先に適用しない。
通常の処理としてスキルを実際に起動する場合は、そのスキルが定める起動してよいエージェントと、操作の認可に従う。

## 検証資源の分離

試験の操作、入力の注入、故障注入と自動終了の失敗が触れる資源について、所有者と共有範囲を確認して実行先を選ぶ。エンドユーザーや他の処理が使う資源を共有する場合は、別のセッション・仮想環境・専用端末など、必要資源を分離できる実行先を使う。分離できなければ既存の認可に基づく利用調整へ進み、認可が不足する場合は確認する。担当間の排他と終了時の復元だけでは、試験中のエンドユーザーから資源を分離したことにならない。この理由で利用調整を求める対象は、エンドユーザーと資源を共有する試験に限る。

Windowsの非表示desktopで完結するダイアログ試験と、同じwindow stationのクリップボードや実入力を使う試験は共有範囲が異なる。画面を別desktopへ置いた場合も、クリップボードや実入力の分離を個別に確かめる。故障注入と自動終了失敗の観測先も同じ基準で選び、停止しなかった対象がエンドユーザーへ作用しない範囲を確保する。

分離のための変更と、期待結果の成否に作用する条件を区別し、必要な起動条件・入力・状態を保って観測する。条件を再現できない場合は差と理由を記録し、合格の範囲を再現済みの条件に限定する。

## 常駐サービスの公開前の観測

常駐するサービスなど本番の起動単位（systemd unit、コンテナー定義、タスクスケジューラーの登録など）から起動する対象を公開前に観測する場合は、稼働中の実体と分離して起動し、分離のために変える値を稼働中の実体と衝突する値（待受ポート、状態ディレクトリ、単一起動の排他資源など）に限る。完成条件の成否が依存する起動条件は本番と同じにする。起動条件には、起動単位の設定（停止シグナルの配送範囲、停止のタイムアウト、環境変数、作業ディレクトリなど）と、常駐する子プロセスや外部接続を生む設定を含む。systemd unitでは、同じunit設定を`systemd-run --user`の一時unitへ渡すなどの手段で起動単位ごと再現できる。再現できない起動条件が残る場合は、その条件と理由を観測記録へ書く。起動単位の外での直接起動や設定ディレクトリの一括差し替えは、成否を左右する条件を失わせ、本番と異なる条件で合格させる。
