# 検証対象の品質基準と記録操作

検証対象の選定に関する品質基準の定義元は、`agent-basics:check-execution`の`references/verification-scope.md`である。呼び出し元が指定した条件や読み込み範囲は、同名の正式な品質資料へ引き継ぐ。節の指定が存在する場合は移動先の実見出しへ対応付け、指定がない場合は従来の全文読み込み契約を維持する。すでに同一バージョンの本文を取得している場合は、再取得せずにその内容を再利用する。

検証対象を選定する際は、`agent-toolkit:wi-standards`の`references/awi-body.md`「完成条件」に定められた自己観測の原則と未確認範囲の扱いを適用する。また、公開前に行う全体検証については、`agent-toolkit:commit`の`references/publish.md`「検証とCI」の規定に従う。

## 名指し参照の読込方法

本文内の各参照における適用条件を確認し、選択した資料の指定範囲を読み取ってから、その基準を用いた具体的な判断に進む。起動時の行に指定された資料は、起動時の本文とともに提供される。

## 実行のしかた

- 計画ファイルで確定した検証行は、本スキルの`SKILL.md`「統合実行ツール経由の起動」に従って各コマンドを順に実行し、コマンドごとの終了コードと出力の要点を確認する。計画凍結後に作成された訂正済み検証表を引き継いでいる場合は、その表に記載されたコマンド群を実行する。訂正表の書式、保持方法、および引き継ぎ手順は、`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「検証と終端工程」に従う。
- すでに保存されている実行結果を確認する際は、子プロセスを不要に再実行せず保存ログを直接読み取る。保存された標準出力と標準エラー出力は`sed -n`コマンドやファイル読み取りツールで参照し、JSONデータは`jq`コマンドを用いて読み取った上で、取得時点のHEADコミット、カレントディレクトリ（cwd）、および終了コードを同一記録から確認する。読み取り失敗、データの欠落、または終了コードが未記録の状態を成功とみなすことは避ける。
- 先行して取得した成功結果と、修正後の限定再実行の結果を組み合わせる場合は、品質基準の定義元にある「実行条件と再実行」に従って各成功集合の適用可否を判定し、完全なテスト名、取得バージョン、および合否結果を要求事項へ対応付ける。
- テスト結果を完成条件と突き合わせる際は、pytestであれば`-v`オプションを指定し、vitest、Playwright、dotnet testなどではテスト名と実行結果が1件ずつ出力されるレポート形式を用いて実行し、その出力に含まれるテスト名と結果行を根拠として利用する。静的解析などの診断結果は、pyfltrの`show-run --commands <コマンド名> --output-format=jsonl`による保存ログから読み取る。プログレス表示のドット（点）や成功総数のカウント表示のみに基づいて個別のテストの合否を判定することは避ける。
