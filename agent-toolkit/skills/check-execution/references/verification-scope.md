# 変更範囲の検証の対象選定

本書は変更範囲の検証で動かすチェックとテストを選ぶエージェント（計画担当、実装担当、実行レビュー担当、計画なしで変更するエージェント）へ、対象を選ぶ判断基準を与える。
変更範囲の検証は変更ファイルとその直接影響範囲を対象にし、リポジトリ全体の検証はCIへ委ねる。全体検証の判定とpush前に実行するチェックは`agent-toolkit:commit`の`references/publish.md`「検証とCI」が定める。
直接影響範囲を対象から外すと、そのテストの失敗はpush後のCIで初めて見つかり、修正と再実行の往復が増える。

## 直接影響範囲の類型

変更された契約を読む・呼び出す主体と、その契約を期待値に持つテストを、リポジトリ全体から集める。
近傍のテストを起点に、参照名だけでなく共通の入力・出力・起動手段から関係をたどる。固定文字列検索は所在の補助とする。
想起の手掛かりはimport・継承・共有関数、横断テスト、文字コード、コマンド・hook、通知・標準エラー・終了後処理、生成物・スナップショット、設定パーサー、実行中の再読込、親子で共有する時間上限とする。

共有設定、pytestの`conftest.py`の補助やfixture実装、テストツールの設定を変更する場合は、その設定・補助・実装を読むテスト全体が直接影響範囲になる。読込先の増減を伴わない実装変更にも適用する。
読込範囲が全テストと一致する場合も、その範囲をローカルで実行し、CIだけへ委ねない。サブディレクトリだけまたは単一テストだけへ作用する変更は、実際の読込範囲をローカル検証の対象とする。

## 範囲の決め方

- 横断テストはプロジェクト規範の識別手段と実行形で選ぶ。先行チェックを再利用できるのは結果を使う時点で同じ内容への実行が完了している場合だけとする。後続hookの対象と自動実行のない対象も変更範囲へ含め、修正・rebase・統合で実体が変われば所定のチェックを再実行する
- 複数の呼び出し手段が共有する処理や出力の契約、広く使われる共通処理を変え、読む側を探索で列挙しきれない場合は、それらの呼び出し手段のテストを含む検証単位全体（パッケージ全体のテストなど）を実行する
- 名前を削除または改名する変更では、変更ファイルの外に残る参照を検出する静的解析（型チェックなど）をリポジトリ全体へ実行し、変更範囲の検証へ含める
- 差分指定（差分オプション、`git diff --name-only`など）には、読む側のテストを別の引数で加える
- 対象はファイル単位で並べる。検証単位全体（パッケージ全体のテストなど）とリポジトリ全体の静的解析は、ファイルを並べず、その範囲を指定する
- 対象は実差分で確定し、計画の列挙との差を読む側まで補う。除外理由は検証記録（計画では`## 要件・外部仕様`の直接影響範囲）へ残す

## 実行のしかた

- 計画で確定した検証行は`atk run-script plan-verify -- --plan <絶対パス> --worktree <絶対パス> --timeout <正の有限秒数>`で保存付きで実行する。直前の`--list`で全対象と順序が実差分を含むことを確認し、各record_pathと両出力を検証対象へ対応付ける。計画行の入力形式は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「検証」が所有する
- 初回の変更範囲の検証では、変更ファイルに適用できるチェックを全て動かす。修正後の再実行では、失敗したチェックだけに限定してよい
- 並行する別の書込主体が新しい呼び出し元を加えると結果が変わる検証（共有契約やパッケージ外の呼び出し元を変えた変更の検証、全体を走査するチェック）は、プロジェクト規範が統合後の検証として定める場合に、統合時にも実行する
