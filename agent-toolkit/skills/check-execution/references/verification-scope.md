# 変更範囲の検証の対象選定

本書は変更範囲の検証で動かすチェックとテストを選ぶエージェント（計画担当、実装担当、実行レビュー担当、計画なしで変更するエージェント）へ、対象を選ぶ判断基準を与える。
変更範囲の検証は変更ファイルとその直接影響範囲を対象にし、リポジトリ全体の検証はCIへ委ねる。全体検証の判定とpush前に実行するチェックは`agent-toolkit:commit`の`references/publish.md`「検証とCI」が定める。
直接影響範囲を外すと、そのテストの失敗はpush後のCIで初めて見つかり、修正と再実行の往復が増える。

## 直接影響範囲の類型

変更された契約を読む・呼び出す主体と、その契約を期待値に持つテストをリポジトリ全体から集める。参照名だけでなく共通の入力・出力・起動手段からも関係をたどり、固定文字列検索は所在の補助とする。
想起の手掛かり: import・継承・共有関数、横断テスト、文字コード、コマンド・hook、通知・標準エラー・終了後処理、生成物・スナップショット、設定パーサー、実行中の再読込、親子で共有する時間上限。

共有設定、pytestの`conftest.py`の補助やfixture、テストツールの設定を変更した場合は、それを読むテスト全体が直接影響範囲になる（読込先が増減しない実装変更も同じ）。読込範囲が全テストに一致する場合もローカルで実行し、CIだけへ委ねない。

## 範囲の決め方

- 横断テストはプロジェクト規範の識別手段と実行形で選ぶ。先行チェックの結果を再利用できるのは、同じ内容に対する実行が完了している場合だけとする。後続hookの対象と自動実行のない対象も含め、修正・rebase・統合で実体が変われば再実行する
- 複数の呼び出し手段が共有する処理や契約を変え、読む側を列挙しきれない場合は、検証単位全体（パッケージ全体のテストなど）を実行する
- 名前を削除または改名する変更では、変更ファイルの外に残る参照を検出する静的解析（型チェックなど）をリポジトリ全体へ実行する
- 差分指定（差分オプション、`git diff --name-only`など）を使う場合は、読む側のテストを別の引数で加える
- 対象は実差分で確定し、計画の列挙との差を読む側まで補う。除外理由は検証記録（計画では`## 要件・外部仕様`の直接影響範囲）へ残す

## 実行のしかた

- 計画で確定した検証行は本スキルの`SKILL.md`「統合実行ツール経由の起動」の`plan-verify`で実行する
- 保存済みの結果は子を再実行せずに読む。plan-verifyの結果まとめは`results_path`を`atk run-command --records-file <絶対パス>`へ、計画なしの保存済み実行は`--record <record_path>`の反復で渡し、順序・argv・cwd・取得版・Git状態・子とwrapperの終了状態・両出力へ到達する。旧記録の`unrecorded`は未記録として保持し、読取失敗・欠損・破損を成功と扱わない
- 保存結果の試験・診断を完成条件へ対応付けるときは、両証拠CLIで試験を`--junit-xml`と`--junit-record`から、診断を`--diagnostics-file`・`--diagnostics-record`・`--diagnostics-conditions`と必要な`--diagnostics-source`から読む。`--list-results --results-summary`と完全テスト名・診断識別子の詳細で意味を判定し、`--select-row <配列:N>`と`--result-test`・`--result-diagnostic`・`--evidence-file`・`--mode`で要求行へ保存する（原文・sourceの転記や手製のJSONは要らない）。診断の比較条件と保存時本文は取得時の保存物を使う
- 初回は変更ファイルに適用できるチェックを全て動かし、修正後の再実行は失敗したチェックへ限定してよい
- 並行する別の書込主体が新しい呼び出し元を加えると結果が変わる検証（共有契約やパッケージ外の呼び出し元を変えた変更の検証、全体を走査するチェック）は、プロジェクト規範が統合後の検証として定める場合に統合時にも実行する
