# 作業完了報告

実装、計画、AWI投入など、成果を伴う作業をメインが完了したときに適用する。
適用の要否は、そのセッションで確定した成果物があるかで判定する。回答を返すに留まり成果物の確定を伴わない依頼は、適用の対象から外れる。単発の調査依頼がその例であり、調査報告をもとにその後の作業が発生する可能性があるためである。
サブエージェントが呼び出し元へ返す完了報告も適用の対象から外れる。

報告は`## 作業完了報告`と`## 振り返り結果報告`の独立した2つの節として順に出力する。
作業完了報告を先に出力するため、ユーザーは元作業の完了を振り返りの待機時間より先に把握できる。

## 完了の到達水準

「完了」は、既知の問題を含めて対応済みである状態を指す。
ユーザーの操作が必須の事項だけが残った状態まで到達してから完了と報告する。
完了として報告できるのは、対象の全体を処理した状態とする。代表箇所だけの対処と一部の件数だけの反映は、途中経過として報告する。

## 工程

1. 対象プロジェクトが開発マシン上で常時稼働するサーバーを持ち、そのプロジェクトの規範又はタスクランナー定義が稼働環境への反映手段と稼働確認手段の双方を定義している場合は、その反映手段で変更を反映し、その稼働確認手段で反映後の稼働を確認する。常時稼働するサーバーを持たないプロジェクトと、双方の手段を定義していないプロジェクトは対象外とする。反映しない場合は、その理由と、ユーザーが自分で反映するために必要な操作を報告へ含める。
2. メイン自身が作成した管理対象一時領域を検収し、管理CLIで回収する。
3. そのセッションで確定した人間由来の判断が`agent-toolkit/rules/01-agent.md`「協調と自律」の保存対象と照合済みであることを確認する。同節はこの照合を要求単位と計画の起草工程で実施すると定めるため、本手順では照合の結果を確認するに留める。起草工程で照合していない場合だけ、ここで照合し、保存又はAWIの投入を完了させる。
4. `## 作業完了報告のフォーマット`に従って作業完了報告を1回出力する。報告本文は実行環境がターンの終端として扱う可視出力であるため、出力だけでターンを終えず、手順5の起動を同じ応答で行う。
5. `agent-toolkit:session-review`を手順4の出力と同じ応答で起動する。

   そのセッションの振り返りを既に実施している場合は、その成果が分析した範囲の終端と現在のセッションの記録の終端を照合する。
   終端より後に作業を継続している場合は、その範囲を対象として`agent-toolkit:session-review`を起動し、既に分析した範囲は対象から外す。
   起動を省略できるのは、照合の結果として未分析の作業が無い場合とする。振り返りの成果が存在することは、省略の条件から外れる。
6. 手順5の結果として作業ツリー又は履歴が変わり、起動元の工程がその変更の公開を定める場合は、その公開手順を完了してから次へ進む。
7. 起動元の工程が報告前に完了させる確認を定める場合は、その確認を完了してから次へ進む。
8. `agent-toolkit:session-review`が所要時間目標に対応する入力を保持している場合は、報告の直前に所要時間を取得する。入力は抽出器の絶対パスと、`--transcript`又は`--codex-thread-id`へ渡した値とする。`date -u +%Y-%m-%dT%H:%M:%SZ`を実行して終了コード0と単一行の出力を確認する。続けてその値を`--elapsed-until`へ渡して抽出器を実行し、返った`elapsed_seconds`をそのセッションの所要時間とする。報告する値は取得の時点までの実測である。入力を保持していない場合は本手順を省く。
9. `agent-toolkit:session-review`が正常完了した場合だけ、`## 振り返り結果報告のフォーマット`に従って振り返り結果報告を作業完了報告に続けて出力する。未実施又は失敗の場合は本手順を省く。
10. 起動元の工程が報告の完了後に実行する工程を定める場合は、その工程を実行する。`agent-toolkit:process-wi`では、報告完了後に`atk agents-exit-session`を単独で実行する工程が該当する。
    振り返り結果報告を出力したセッションではその報告と同じ応答へ、振り返り未実施のセッションでは作業完了報告と同じ応答へ、この工程を含める。
    報告の完了後にその応答で実行するのはこの工程だけとし、通常の作業ターンへの復帰は次の指示を受け取ってから行う。
    報告本文は実行環境がターンの終端として扱う可視出力であり、工程を別の応答へ分けると、その工程が起動されないまま常駐処理が停止する。

## 作業完了報告のフォーマット

手順5の起動より前に、次の書式で1回出力する。振り返りを実行する旨の予告行は書かない。

```text
## 作業完了報告

<1文の元作業の完了結果>

### 成果

- <元作業に対する成果の全体>

### 投入したWI

- <ファイル名>: <H1タイトル>
- <ファイル名>: <H1タイトル> (target_repo=<...>)
```

`### 成果`へ書く対象は、そのセッションで受け取った依頼（元作業）に対する成果の全体とする。
セッションの途中で生じた別事象への処置は、元作業に対する成果と区別できる形で添える。
同一セッションで本スキルを2回目以降に起動して報告する場合も、既に報告済みの成果を含めて元作業に対する成果の全体を再構成する。
報告の発行に先立って、そのセッションで受け取った依頼と`### 成果`の各項目の対応を照合する。依頼のうちいずれの項目にも対応しないものがある場合は、その依頼の達成状況を追加してから発行する。
振り返りが未完了でも元作業が完了していれば、冒頭は元作業の完了を言い切る。

`### 投入したWI`は、そのセッションで作業完了報告のテキスト出力前に投入した全WI（AWIとUWI、種別は問わない）を対象とする。処理対象として取得した項目は対象外とする。
0件の場合は`- なし`と書く。1件あたりの表示は`- <ファイル名>: <H1タイトル>`とし、`target_repo`が現在の対象リポジトリと異なる場合だけ、末尾へ半角空白1字に続けて`(target_repo=<正規化リモートURL又は絶対パス>)`を追記する。

振り返りが未実施又は失敗となる場合は、`### 投入したWI`の直後へ次の節を追加し、振り返り結果報告を発行しない。

```text
### 振り返り

- session-review未実施: <理由。関連するUWIがある場合はファイル名を末尾に併記>
```

未実施の理由は2種に分類する。既に振り返りを実施した成果がそのセッションの記録の終端まで覆っているため起動を省略した場合は`成果を再利用したため起動省略`、準備工程、振り返り担当の起動、親transcriptの解決又は証拠抽出のいずれかが再試行後も失敗して`analysis_failed`となった場合は`分析失敗のためUWIへ記録`とする。

`### 振り返り`節を持つ作業完了報告と、振り返り結果報告を持つ作業完了報告のいずれかが、セッションごとに1回だけ発行される状態を保つ。両方は発行しない。

## 振り返り結果報告のフォーマット

`agent-toolkit:session-review`が正常完了した場合だけ、作業完了報告と同じ応答へ続けて次の書式で1回出力する。

```text
## 振り返り結果報告

- 成果ファイル: <session-reviewが書いた成果ファイルの絶対パス>
- 判定記録: 候補<N>件 (欠陥<X>件 / 非欠陥<Y>件)
- 規範停止候補: <K>件
- 所要時間: <実測秒数>秒 / 目標 <目標秒数>秒 (<達成 or 未達>)

### 対策として投入したWI

- <ファイル名>: <H1タイトル>
- <ファイル名>: <H1タイトル> (target_repo=<...>)
```

各値の取得元は次のとおりとする。

- `成果ファイル`は`agent-toolkit:session-review`が振り返り担当を通じて書いた出力先ファイルの絶対パスとする
- `判定記録`の`候補<N>件`は成果ファイルの`## 問題候補の判定記録`節が持つ候補表の行数の総和、`欠陥<X>件`はその表の欠陥判定欄が欠陥である行数、`非欠陥<Y>件`はそれ以外の行数とする。`X + Y = N`が成立しない場合は集計を取り直す
- `規範停止候補`は成果ファイルの`## 規範適用による停止`節の表の行数とする。同節が0件を宣言している場合は`0`とする
- `所要時間`は手順8で取得した`elapsed_seconds`とし、目標が定められていないセッションでは行末を`目標なし`に置き換えて実測秒数の後ろへ書く
- `### 対策として投入したWI`は、`agent-toolkit:session-review`の実行中（作業完了報告のテキスト出力後から振り返り結果報告のテキスト出力前まで）に新規投入された全WIを対象とする。0件の場合は`- なし`と書く。1件あたりの表示規則は`### 投入したWI`と同じとする

完了判定は`## 工程`の各項目の充足で行い、呼び出し忘れ検出用の状態フラグは作成しない。
状態フラグはセッション途中で失われて誤警告を反復させ、正当な工程を誤って遮断した実績がある。
