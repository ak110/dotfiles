# 作業完了報告

実装、計画、AWI投入など、成果を伴う作業をメインが完了したときに適用する。
適用の要否は、そのセッションで確定した成果物があるかで判定する。回答を返すに留まり成果物の確定を伴わない依頼は、適用の対象から外れる。単発の調査依頼がその例であり、調査報告をもとにその後の作業が発生する可能性があるためである。
サブエージェントが呼び出し元へ返す完了報告も適用の対象から外れる。

## 完了の到達水準

「完了」は、既知の問題を含めて対応済みである状態を指す。
ユーザーの操作が必須の事項だけが残った状態まで到達してから完了と報告する。
完了として報告できるのは、対象の全体を処理した状態とする。代表箇所だけの対処と一部の件数だけの反映は、途中経過として報告する。

1. 対象プロジェクトが開発マシン上で常時稼働するサーバーを持ち、そのプロジェクトの規範又はタスクランナー定義が稼働環境への反映手段と稼働確認手段の双方を定義している場合は、その反映手段で変更を反映し、その稼働確認手段で反映後の稼働を確認する。常時稼働するサーバーを持たないプロジェクトと、双方の手段を定義していないプロジェクトは対象外とする。反映しない場合は、その理由と、ユーザーが自分で反映するために必要な操作を報告へ含める。
2. メイン自身が作成した管理対象一時領域を検収し、管理CLIで回収する。
3. そのセッションで確定した人間由来の判断を`agent-toolkit/rules/01-agent.md`「協調と自律」の保存対象と照合する。対象がある場合は、同節が定める保存又はAWIの投入が完了し、後続のエージェント由来の判断だけでは変更できない状態を確認してから次へ進む。計画を作成していない作業も本項の対象とする。
4. `agent-toolkit:session-review`を起動する。

   そのセッションの振り返りを既に実施している場合は、その成果が分析した範囲の終端と現在のセッションの記録の終端を照合する。
   終端より後に作業を継続している場合は、その範囲を対象として`agent-toolkit:session-review`を起動し、既に分析した範囲は対象から外す。
   起動を省略できるのは、照合の結果として未分析の作業が無い場合とする。振り返りの成果が存在することは、省略の条件から外れる。
5. 手順4の結果として作業ツリー又は履歴が変わり、起動元の工程がその変更の公開を定める場合は、その公開手順を完了してから次へ進む。
6. 起動元の工程が報告前に完了させる確認を定める場合は、その確認を完了してから次へ進む。
7. `agent-toolkit:session-review`が所要時間目標に対応する入力を保持している場合は、報告の直前に所要時間を取得する。入力は抽出器の絶対パスと、`--transcript`又は`--codex-thread-id`へ渡した値とする。`date -u +%Y-%m-%dT%H:%M:%SZ`を実行して終了コード0と単一行の出力を確認する。続けてその値を`--elapsed-until`へ渡して抽出器を実行し、返った`elapsed_seconds`をそのセッションの所要時間とする。報告する値は取得の時点までの実測である。取得した値と所要時間目標との比較は本手順で確定する。入力を保持していない場合は本手順を省く。
8. 次の形式で1回だけ報告する。

```text
[1文の完了結果]

## 成果

- [作業固有の成果]

## 振り返り

- session-review: [実施結果 / 分析未完了とUWI]
- 所要時間: [手順7で取得した値と所要時間目標との比較 / 目標が定められていないため記載しない]
```

振り返りが未完了でも元作業が完了していれば、冒頭は元作業の完了を言い切る。
`## 成果`へ書く対象は、そのセッションで受け取った依頼（元作業）に対する成果の全体とする。
セッションの途中で生じた別事象への処置は、元作業に対する成果と区別できる形で添える。
同一セッションで本スキルを2回目以降に起動して報告する場合も、既に報告済みの成果を含めて元作業に対する成果の全体を再構成する。本手順の「1回だけ」は1回の起動につき1回を指す。
報告の発行に先立って、そのセッションで受け取った依頼と`## 成果`の各項目の対応を照合する。依頼のうち`## 成果`のいずれの項目にも対応しないものがある場合は、その依頼の達成状況を追加してから発行する。
完了判定は本手順の各項目の充足で行い、呼び出し忘れ検出用の状態フラグは作成しない。
状態フラグはセッション途中で失われて誤警告を反復させ、正当な工程を誤って遮断した実績がある。
9. 起動元の工程が報告の完了後に実行する工程を定める場合は、その工程を実行する。`agent-toolkit:process-wi`では、報告完了後に`atk agents-exit-session`を単独で実行する工程が該当する。
   その工程を定める起動元では、手順8の報告本文の出力と工程の起動を同じ応答へ含める。
   報告の完了後にその応答で実行するのはこの工程だけとし、通常の作業ターンへの復帰は次の指示を受け取ってから行う。
   報告本文は実行環境がターンの終端として扱う可視出力であり、工程を別の応答へ分けると、その工程が起動されないまま常駐処理が停止する。
