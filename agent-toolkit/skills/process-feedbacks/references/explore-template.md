# フィードバック調査タスク

指定されたフィードバックの成立性と反映候補を、読み取り専用で調査せよ。成果物を修正しない。

## 入力

- 排他的な次のいずれか一方
  - フィードバック原文経路では対象のフィードバックファイル名、対象リポジトリ及び事前割当した素材ID
  - 直接経路では対象の素材IDと本文、投入元及び引用範囲
- プロジェクト規範の絶対パス
- `review-checklists.md`の絶対パス
- バグ対応の場合だけ`agent-toolkit:bugfix`の絶対パス
- 調査対象と完了条件

入力が欠ける場合は推測せず欠落項目を返す。

## 調査

- フィードバック原文経路では起動直後に`atk mq show <filename> --target-repo=<repo> --skip-pull`を1回実行する。
  表示用見出し、YAML frontmatter及びCLI付加の末尾改行を除いたフィードバック本文を調査対象とする。
  同じ表示結果のfrontmatterにある`source`の文字列を改変せず投入元識別子として記録し、欄が無い場合は「値なし」と記録する。
  直接経路では受領した本文を調査対象とする
- 入力資料と対象ファイルを全文読み、定義、参照元、呼び出し元、test、生成・配布経路を確認する
- 各要求を素材内の本文出現順に要求ID（`R-<事前割当素材ID>-<3桁連番>`）へ割り当て、素材参照に事前割当した素材IDを記録する
  他素材の要求数を参照せず、要求IDを中央統合時に再採番しない
- 要求ごとに現行実装と既存規範へ対応付け、対応済み、未対応、衝突、未検証を区分する
- 既存要求へ追加・分割する場合は素材名前空間の最大連番+1以降を使い、既存要求IDを維持する。統合する場合は既存行とIDを維持し、統合用IDを生成しない
- 指定された調査観点ごとに実行結果または実装箇所を根拠として示す
- 外部仕様は公式一次資料で裏付ける。当該仕様が方針選択の根拠となる場合は実機再現も併せて示す
- 反映案の採否を決めず、呼び出し元が採否を確定できる事実だけを返す
- 事象の発生契機を特定できない場合は、実装に加えて対象リポジトリの開発・運用文書（`docs/`配下など）を対象語で検索し、
  記録済みの発火契機・既知挙動を確認する。確認した記録は根拠として返し、記録が無い場合はその事実を未検証事項へ含める

## 出力

フィードバックファイル名、素材ID、投入元識別子、引用範囲、要求ID、要求ごとの素材参照、区分、採用候補の範囲、根拠、未検証事項、`write_status: unchanged`を返す。
対象リポジトリとフィードバック管理領域を変更しない。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
