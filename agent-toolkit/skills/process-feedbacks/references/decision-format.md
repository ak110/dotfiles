# 採否結果と後始末

## 採否結果

フィードバックごとに次を記録する。

```markdown
### <filename>: <要約>

- 原文正本ID: <提示素材の原文正本ID>
- 人間由来の指示又は方針の優先度: <項目に対応する優先順位と根拠>
- 調査根拠: <項目ごとの実測・履歴・既存規範又は一次資料>
- 欠陥原因: <採否確定時に個別に確定した原因。該当しない場合は該当なしの根拠>
- 採否: 採用 | 部分採用 | 不採用 | 保留
- 採否理由: <実測した根拠。仕組みを維持・修正する場合は、削除・簡素化案と比較した根拠。完全採用以外は項目固有の採否理由又は原文との差異を含める>
- 投入元識別子: <原文frontmatterのsource文字列。欄が無い場合は「値なし」>
- 適用優先順位: <session-review起点の項目だけ。優先順位4に準じる判断を記載>
- 懐疑的判定の根拠: <session-review起点の項目だけ。通常起点より懐疑的に判定した根拠>
- 採用範囲: <部分採用時だけ>
- 除外範囲: <部分採用時だけ>
- 反映先: <採用時だけ>
- 反映内容: <採用時だけ>
- 確認: <不採用確認用`user_decisions`で必要なAskUserQuestionの質問、回答又は保存したTBD。session-review以外の項目だけ>
- 移管先: <別リポジトリの場合のtarget_repo、指定済みsource（ない場合は該当なし）、登録ファイル名、登録・照合結果。該当しない場合は該当なし>
- 解除条件: <保留時だけ>
```

原文案の文言、列挙又は節配置を技術判断で調整した場合は、差異と根拠を`採否理由`又は`反映内容`へ記録する。

各項目の採否確定では、原文正本ID、人間由来の指示又は方針の優先度、調査根拠、欠陥原因及び採否理由を同じ記録へ対応付ける。
関連性の低い項目を同じ包括理由だけで一括判断せず、同じ`--note`を複数項目へ使う場合も各項目で同じ理由が成立する根拠を記録する。
完全採用以外の結果は項目固有の採否理由・原文との差異を記録し、部分採用では採用範囲・除外範囲・採否理由のすべてを記録する。

投入元識別子は`source`の文字列又は「値なし」を改変せず記録する。
`session-review`を値に持つ`source: session-review`だけをエージェント由来と判定し、優先順位4へ照合する。
`source: plan`（`plan`）、`source: alert-monitor`（`alert-monitor`）、その他のsource、source欠落及び不明は人間由来として扱う。
その他の値を含めて値を保持したまま生成経路固有の規定へ照合する。

部分採用は独立した複数要求に限り、原文との差異、採用範囲、除外範囲及び採否理由を記録する。
部分採用を理由にAskUserQuestionを機械的に発行せず、`agent-toolkit/rules/01-agent.md`「協調と自律」節の確認経路は
不採用候補の由来境界に従って適用する。
`source: session-review`と確認できる項目の不採用は追加確認を要しない。
それ以外の項目の不採用は、原文との差異と技術的理由を示す`AskUserQuestion`の回答後だけ確定する。
回答が得られない場合は同じ質問内容をTBDへ保存して元項目を保留し、回答又はTBDを確認できない状態では`reject`を実行しない。
不採用確認用`user_decisions`は通常の将来判断TBDと区別する。直接回答は同じ`feedbacks-planner`系統へ返し、回答なしで保存したTBDは依存設定と保留確認後の結果を同じ系統へ返す。
保留項目を含む全項目の採否一覧と採用範囲だけで計画起草を続行し、通常の将来判断TBDの暫定判断を不採用確認へ混在させない。
別リポジトリ項目は、保持済みの本文を正しい`target_repo`へ移管して登録し、sourceがある場合は同じ値を渡す。
sourceを指定した場合は移管先の`source`、本文、`target_repo`、移管先ファイル名を`atk mq show`で照合する。
sourceを指定しない場合は本文、`target_repo`、移管先ファイル名だけを照合し、成功後だけ元項目を終端する。

sourceによる由来境界の判定と利用者認可の確認を分ける。
sourceは由来境界の判定にだけ用い、source又はフィードバック本文から利用者認可を推定しない。

## 後始末

- 不採用は項目固有の採否理由を含む判定確定後に`atk mq reject <filename> --note=<採否理由>`で終端させる
- 採用は対象commitのpush完了後に
  `atk mq adopt <filename> --note=<反映概要> --commit=<完全長SHA>`で終端させる
- 保留は解除条件を永続化してinboxへ戻し、終端させない

`--note`には1行の結果を渡す。`--commit`は対象リポジトリの完全長SHAとし、rejectへは渡さない。
実行後に対象エントリを再取得し、`## 処理結果`の採否、note、commitを入力と照合する。
