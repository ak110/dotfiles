# 採否結果と後始末

## 採否結果

### 上位カテゴリの評価

category gateの警告が出た場合は、個別項目だけでなく上位カテゴリを規範化又は仕組み化すべきかを必ず評価する。
採用する場合は反映先と内容、不採用の場合は既存正本、費用対効果、適用範囲のいずれかに基づく根拠を記録する。

フィードバックごとに次を記録する。

```markdown
### <filename>: <要約>

- 採否: 採用 | 部分採用 | 不採用 | 保留
- 理由: <実測した根拠。提案が前提とする仕組みを維持・修正する場合は、削除・簡素化案と比較した根拠>
- 採用範囲: <部分採用時だけ>
- 除外範囲: <部分採用時だけ>
- 反映先: <採用時だけ>
- 反映内容: <採用時だけ>
- 解除条件: <保留時だけ>
```

部分採用は独立した複数要求に限る。不採用と除外要求がユーザー由来の要求を覆す場合は、
`agent-toolkit/rules/01-agent.md`「協調と自律」節のモード別経路へ送る。
自己生成起点で既存対応済みと実測できる不採用は追加確認を要しない。

## 後始末

- 不採用は判定確定後に`atk mq reject <filename> --note=<理由>`で終端させる
- 採用は対象commitのpush完了後に
  `atk mq adopt <filename> --note=<反映概要> --commit=<完全長SHA>`で終端させる
- 保留は解除条件を永続化してinboxへ戻し、終端させない

`--note`には1行の結果を渡す。`--commit`は対象リポジトリの完全長SHAとし、rejectへは渡さない。
実行後に対象エントリを再取得し、`## 処理結果`の採否、note、commitを入力と照合する。
