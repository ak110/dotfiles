# 採否結果と後始末

## 採否結果

フィードバックごとに次を記録する。

```markdown
### <filename>: <要約>

- 採否: 採用 | 部分採用 | 不採用 | 保留
- 理由: <実測した根拠。提案が前提とする仕組みを維持・修正する場合は、削除・簡素化案と比較した根拠>
- 投入元識別子: <原文frontmatterのsource文字列。欄が無い場合は「値なし」>
- 適用優先順位: <session-review起点の項目だけ。優先順位4に準じる判断を記載>
- 懐疑的判定の根拠: <session-review起点の項目だけ。通常起点より懐疑的に判定した根拠>
- 採用範囲: <部分採用時だけ>
- 除外範囲: <部分採用時だけ>
- 反映先: <採用時だけ>
- 反映内容: <採用時だけ>
- 解除条件: <保留時だけ>
```

原文案の文言、列挙又は節配置を技術判断で調整した場合は、差異と根拠を`理由`又は`反映内容`へ記録する。

投入元識別子は`source`の文字列又は「値なし」を改変せず記録する。
`session-review`は優先順位4へ照合する。
`alert-monitor`、`plan`、値なし及びその他の値は、値を保持したまま生成経路固有の規定へ照合する。
フィードバック本文又は投入元識別子から、人間由来又は利用者認可を推定しない。

部分採用は独立した複数要求に限る。不採用と除外要求がユーザー由来の要求を覆す場合は、
`agent-toolkit/rules/01-agent.md`「協調と自律」節のモード別経路へ送る。
`session-review`起点で既存対応済みと実測できる不採用は追加確認を要しない。

## 後始末

- 不採用は判定確定後に`atk mq reject <filename> --note=<理由>`で終端させる
- 採用は対象commitのpush完了後に
  `atk mq adopt <filename> --note=<反映概要> --commit=<完全長SHA>`で終端させる
- 保留は解除条件を永続化してinboxへ戻し、終端させない

`--note`には1行の結果を渡す。`--commit`は対象リポジトリの完全長SHAとし、rejectへは渡さない。
実行後に対象エントリを再取得し、`## 処理結果`の採否、note、commitを入力と照合する。
