# 実装差分のcodexレビュー

`careful-review`と`plan-impl-executor`が実装差分全体を単一のレビュー系で点検し、
応答と成果物の不変性を検収するための手順を定める。

## 初回レビュー

委譲先へ次の絶対パスを渡し、着手時に全文をReadさせる。

- 本ファイル
- `plan-codex-implementation-review-task.md`
- 計画ファイル（提示された場合）
- 適用する品質規範
- プロジェクト規範

タスク本文は作業ディレクトリ、対象差分と不変参照点、変更意図、完了条件だけに限定し、
規範本文を転記しない。観点・カテゴリ・ファイルによる複数起動は行わない。

計画は作成時点の実装を基にしている。計画と実差分が一致しない場合は、
計画の字面だけで不適合とせず、計画の意図、進捗ログ、現行実装を照合して判定する。

## 変更検知と復元

レビュー前に所有者だけが読み書きできる一時ディレクトリを作成する。
対象ファイルごとに起動直前の状態を次のとおり記録する。

- 起動前に存在するファイルは、既存の未コミット変更を含む内容を一時ディレクトリへ複製する
- 起動前に存在しないファイルは、不在であることを対象パスと対応づけて記録する
- 存在するファイルの内容ハッシュと、対象全体の`git diff`を記録する

レビュー応答の受領後に対象ごとの存在状態と内容ハッシュを再取得し、起動前の記録と比較する。
レビュー中の変更を検知した場合は、変更主体をレビュー担当と断定せず、
並行する別主体による変更の可能性を含めて変更内容を確認する。
復旧操作へ進む前に、変更ファイルの一覧・変更内容の要約・退避先パス・具体的な復旧手順を
呼び出し元へ提示し、明示的な実行確認を得る。
確認を得た後に限り、復旧を実装・修正系へ委譲する。

HEADの変化を検知した場合は自動復旧せず、想定外のコミットを退避用ブランチで保全して、
基準HEAD・想定外コミット・退避先ブランチを呼び出し元へ報告する。
追跡ファイルと未追跡ファイルの復旧方法を含む以後の処理は、
`agent-toolkit/rules/02-claude-code.md`「サブエージェント運用」節の
作業用複製における記録・変化検出・復旧手順に従う。
復旧後は対象ごとの存在状態と内容ハッシュ、および`git diff`がレビュー前の記録と一致することを確認する。
その後にレビュー指摘の当否を判断し、採用指摘だけを実装・修正系へ引き継ぐ。

変更が無い場合も起動前後の照合結果を記録する。
復元と照合が完了した後に一時バックアップを除去し、一時ディレクトリが残っていないことを確認する。
レビュー担当による直接編集と、実装・修正系による正規反映は区別して記録する。

## 再レビュー

採用指摘は実装・修正系へ全文で渡す。
修正後は同じレビュー系へ、前回指摘と反映結果を渡して再レビューする。
代替経路で毎回新しく起動する場合は、同じreference群、前回レビュー応答、反映結果を全文で渡す。

初回1回と再レビュー4回の合計5ラウンドを上限とする。
致命的・重大の指摘が解消し、採用した軽微指摘の反映を確認した時点で完了とする。
5ラウンド目にも致命的・重大指摘が残る場合は完了とせず、指摘全文、重大度、対象箇所、
再現根拠、必要な修正を省略せず呼び出し元へ返す。
呼び出し側は`status: needs_escalation`として扱う。
