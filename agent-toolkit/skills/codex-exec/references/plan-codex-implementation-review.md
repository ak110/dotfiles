# 計画準拠レビューと独立レビュー

承認済み計画の実装後に行う二系統レビューの共通契約を定める。

## 共通条件

- final commitを対象に、計画準拠系と独立系を別route/threadで並列実行する
- reviewerは成果物を読み取り専用とし、起動前後の`git status --short`と対象commitを照合する
- reviewerが必要とする再現出力だけを管理対象一時領域へ保存する
- 各指摘は重大度、箇所、再現根拠、修正方針、`violated_contract`を含む
- ユーザー合意、計画、公開契約、実行結果のいずれも破らない軽微な好み、将来仮定、目的外改善は指摘しない

## 共通委譲契約

作業場所、書込主体、出力言語、プロセス所有権、不可逆操作権限を各系統へ渡す。
計画準拠系と独立系の再現証跡ディレクトリを別々に作成し、各系統専用の再現証跡ディレクトリとする。

## 外部実行と再現証跡

外部実行を保持する場合は所有主体と安定した識別子を返す。主張は標準出力、標準エラー、終了コードで裏付ける。

## 初回レビュー

ユーザーが明示・合意した現行の外部契約、または適用規範により確定した契約を基準にする。
独立系にはこれらに加えて`review_contract`だけを渡す。内容は入力生成主体、信頼境界、通常入力、
対象外入力、誤許可と誤拒否の影響とする。ユーザー発話全文は渡さず、作者の推論を渡さず、
変更意図や実装方針も渡さない。

## 再レビュー

採用指摘の修正後に最終検証と二系統レビューを再実行し、修正が新たな契約違反を導入していないことを確認する。

## 計画準拠レビュー

計画、ユーザー合意、公開契約、進捗ログ、実差分、検証結果を照合する。
計画からの逸脱、実装漏れ、許容されていない挙動変化、生成・配布経路の追随漏れだけを指摘する。
指摘が無い場合も、対象commit、点検範囲、短い「指摘なし」を返す。

## 独立レビュー

計画本文と他レビューの出力を入力せず、外部契約、変更ファイル、実差分、呼び出し元、テスト、
生成・配布経路から正確性、回帰、境界条件、テスト不足を点検する。
好みや別設計の提案を指摘へ含めない。指摘が無い場合も、対象commit、点検範囲、短い「指摘なし」を返す。

## 指摘反映と再レビュー

実装系は各指摘の事実と`violated_contract`を実測し、採否と根拠を6列表へ記録する。
ユーザー合意と衝突する指摘は自動反映せず、モード別の確認へ返す。
採用指摘の修正後は最終検証と二系統レビューを再実行する。finalize後に対象commitが変わった場合も同様とする。

二系統一組を1ラウンドとし、最大5ラウンドとする。上限時に未解決指摘が残る場合は、
対象commit、点検範囲、未解決指摘、検証結果、route/threadを保持して`needs_escalation`とする。
未解決指摘が無い場合だけ`completed`とする。各roundの応答全文は保持・再掲しない。
