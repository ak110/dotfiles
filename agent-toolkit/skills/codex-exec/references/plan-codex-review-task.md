# 計画ファイルレビュータスク

## 入力

本節を総合レビュー系へ渡す資料契約の正本とする。

- `plan-review-delegation.md`、`plan-codex-review.md`、本ファイル、計画ファイルの絶対パスを受け取り、着手時に全文を読む
- 適用する品質規範はスキル名で受け取り、各スキルのトリガー規則に従って着手時に全文を読む
- `agent-toolkit:plan-mode`のSKILL.mdとプロジェクト規範の絶対パスを受け取り、着手時に全文を読む
- 作業ディレクトリ、条件付き複製元、初回または限定再レビューの別、限定再レビュー時の差分一式を受け取る
- 入力が欠ける場合は欠落項目を返し、推測で補わない

## レビュー

- 計画内部の整合性、実装可能性、現行実装との一致、規範適合、日本語品質を点検する
- 初回レビューでは計画全体を点検し、指摘を初版内補正・スコープ拡大・独立問題へ区分する
- スコープ拡大は、計画した変更から不具合へ至る実行結果または静的な呼び出し・参照経路を根拠として示す
- 独立問題は、初版の成立性へ影響するかを確認して区分する
- バグ計画の分類には、`## 背景`直下にある`### 計画メタ情報`の固定値`作業種別`だけを用いる。
  作業種別が欠落・未知値・複数値の場合は分類契約の不成立として指摘し、タイトル、依頼内容、背景、
  提示素材の自然言語から分類を推測しない
- 作業種別が単一の`バグ対応`の場合だけ、`### バグ調査結果`の有無にかかわらず、受領した`plan-mode/SKILL.md`から
  `references/bugfix.md`を解決して全文を読む。表全体が欠落している場合は指摘する。
  要求原文から期待する契約、4原因区分、根本原因、類似母集団、3処置へ追跡できるかを点検する
- 根本原因が直接的原因の言い換えに留まる場合、類似母集団が識別子・コード形状だけで定義される場合、
  再発防止処置が是正テストだけで同じ原因の混入・見逃しを防がない場合は指摘する
- 提示素材と`### ユーザー合意済み事項`を、`### 実施内容`、`## 変更内容`、`### エージェント判断`へ突合する。
  計画が用いる分類名にかかわらず、明示された外部可視のコマンド、引数、操作順序、入出力、
  公開インターフェースの変更を検出し、変更がある場合はユーザー合意の根拠を要求する
- 計画が新たに追加する拒否条件、受理する入力値の縮小、容量・件数制限、ネットワーク遮断、権限強化、
  既存コマンドや導入済み機能の利用不可化を列挙する
- 各制約について、現行実装で成功する利用シナリオを確認する
- 成功経路を失う場合は、計画上の分類名にかかわらず公開契約変更として扱い、ユーザー合意の根拠を要求する
- 再レビューでは前回の採用指摘、反映結果、反映差分を点検する
- 再レビューの新規指摘は、反映差分との因果関係と再現根拠を示す
- 認証・認可に関する主張は、共通ミドルウェアまたは認証フックから
  ルーター・コントローラーを経て最終ハンドラーまでの実行経路を追跡し、
  局所実装だけを根拠に公開契約を確定しない。
  Blueprintは対象プロジェクトで用いるルーターの一例として扱う
- 非Webアプリケーションでは、共通の認証・認可入口から
  コマンドまたはイベントのディスパッチを経て最終処理までを同じ観点で追跡する
- 応答フィールドに関する主張は、内部オブジェクトの生成箇所から
  シリアライズ・フィルターを経て利用者が観測できる値まで追跡する
- 計画ファイルとリポジトリを読み取り専用として扱う
- 対象worktreeと条件付き複製元の非変更を完了条件とする
- 指摘ごとに重大度、対象箇所、根拠、修正方針を示す

## 出力

- 重大度は`致命的`、`重大`、`軽微`から選ぶ
- 指摘がある場合は、重大度、区分、対象箇所、根拠、修正方針を全件返す
- 指摘がない場合は「指摘なし」と明記する
- `worktree_check_result`は`target`と条件付き`source`ごとに`exit_code`、compareのJSON全体を保持する
  `compare_json`、`repository_changed`、`worktrees_changed`、`classification`を記載する。
  `classification`は`unchanged`、`repository_changed`、`worktree_state_only`、`error`、
  `source`が無い場合の`not_applicable`から選び、`changed|unchanged`の二値へ縮約しない。
  終了コード2は`error`、`repository_changed=true`は`repository_changed`、
  `repository_changed=false`かつ`worktrees_changed=true`は`worktree_state_only`、両方falseは`unchanged`とする
