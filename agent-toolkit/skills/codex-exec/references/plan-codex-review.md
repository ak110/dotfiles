# 計画ファイルのcodexレビュー

`plan-file-finalizer`が計画ファイルの機械チェック・修正と総合レビューを
別系統で実施するための手順を定める。
実装・修正担当は専用の書き込み契約に従い、レビュー担当は対象を変更せず指摘と根拠だけを返す。

## 用途別task reference

委譲の用途ごとに次のtask referenceを1件だけ選ぶ。

- 機械チェック・修正: `plan-codex-review-fix-task.md`
- 総合レビュー: `plan-codex-review-task.md`

既存の作業ディレクトリを対象worktreeの唯一の入力として使う。
作業用複製では、呼び出し元から複製元リポジトリの絶対パスも受け取る。
非該当時は`対象外`を受け取る。委譲先が使う複製元パスは受領値に限定する。

各委譲の直前に、対象worktreeと条件付き複製元へ
`${CLAUDE_PLUGIN_ROOT}/scripts/_worktree_snapshot.py capture`を実行する。
委譲元は対象リポジトリ外へ所有者限定の親一時ディレクトリだけを用意し、
その配下の未作成のパスを対象worktreeと複製元へ別々の出力先として指定する。
出力先はhelperが作成するため、委譲元は出力先そのものを事前に作成せず、同じ出力先を再利用しない。
計画ファイルのほかに許可する書き込みは、これらの出力先に限る。
委譲直後に同helperの`compare`を実行し、HEAD、追跡差分、未追跡内容を比較する。

変化を検出した場合は`status: needs_escalation`、`review_completed: false`とする。
変更対象、復旧可能な退避先、記録済みHEADからの追跡内容復元とパッチ再適用、
未追跡実体の復元、委譲後追加パスの除去候補を含む具体的な復旧手順を報告する。
復旧の実行主体は、呼び出し元の明示確認後に開始する別工程とする。

変化を検出しなかった場合と、報告した復旧が完了した場合に限り、
委譲元が親一時ディレクトリを配下の出力先ごと除去し、残存しないことを確認する。
復旧が未完了の間は、退避内容が復旧の唯一の入力となるため出力先を保持する。

## 総合レビューの初回委譲

総合レビュー系の委譲先へ次の絶対パスを渡し、着手時に全文をReadさせる。

- 本ファイル
- 「用途別task reference」節で選んだ総合レビュー用task reference
- 対象計画ファイル
- 適用する`agent-toolkit:review-standards`・`agent-toolkit:writing-standards`・
  `agent-toolkit:agent-standards`と対象固有スキル
- `agent-toolkit:plan-mode`のSKILL.md。バグ計画の点検で
  `references/bugfix.md`を解決する起点となる
- プロジェクト規範

タスク本文は作業ディレクトリ、対象、完了条件だけに限定し、規範本文を転記しない。
観点・ファイル・文書種別による複数起動は行わない。
作業ディレクトリと条件付き複製元は、退避と変更検知の契約を適用する。

## 機械チェック委譲

実装・修正系へは、本ファイル、機械チェック・修正用の`plan-codex-review-fix-task.md`、
および同task referenceが参照する`plan-codex-implementation-task.md`を渡す。
`plan-file-finalizer`が実装・修正系へ渡すタスク本文には、次の検査・違反修正・再検査を全て含める。

1. 計画ファイル本体へ次のコマンドを実行する

   ```text
   uv run --script ${CLAUDE_PLUGIN_ROOT}/skills/plan-mode/scripts/check_plan_file.py <計画ファイルの絶対パス>
   ```

2. 終了コード1のerror区分違反を全件修正し、終了コード0まで再実行する
3. 終了コード2では、対象パス・読み取り権限・文字エンコーディングを是正して再実行する
4. 終了コード2を解消できない場合は、原因を`escalation_points`へ記録して`needs_escalation`で返す
5. `[warn]`接頭辞付きの出力は内容を確認し、修正するか許容理由を`check_results`へ記録する
6. 次のコマンドで計画ファイル本体を直接検査する

   ```text
   uvx pyfltr run --no-fix --allow-external-paths \
     --work-dir <対象リポジトリの絶対パス> \
     --commands=typos,markdownlint,textlint,designmd,lychee,colloquial-check \
     --enable=colloquial-check \
     <計画ファイルの絶対パス>
   ```

7. 違反または警告を計画ファイル本体で修正し、終了コード0まで同じコマンドを再実行する
8. 次のコマンドを計画ファイル本体へ実行し、検出内容を修正して終了コード0まで再実行する

    ```text
    uv run --script ${CLAUDE_PLUGIN_ROOT}/skills/writing-standards/scripts/check_dash.py <計画ファイルの絶対パス>
    ```

9. 修正後に3検査を再実行し、終了コード・error件数・warning件数を`check_results`へ記録する

## 変更検知

レビュー前に計画ファイルを一時退避し、内容ハッシュを記録する。
レビュー応答の受領後に内容ハッシュと差分を比較する。

変更を検知した場合は、変更ファイルの一覧・変更内容の要約・退避先パス・具体的な復元手順を
呼び出し元へ提示し、明示的な実行確認を得る。
確認後に限り、実装・修正系へ退避内容の復元を委譲する。
復元後の内容ハッシュが退避時と一致したことを確認してから、採用指摘の反映へ進む。

## 指摘反映と再レビュー

計画レビューにおける採否の最終確定者は、対象計画に責任を持つ
`agent-toolkit:plan-mode`の呼び出し元とする。
計画レビューの採否は重大度と初版スコープとの関係を別々に判定する。
`plan-file-finalizer`は初回レビュー前に、初版の`### 実施内容`、
`### ユーザー合意済み事項`、`## 変更内容`の原文と内容ハッシュを比較基準として保存する。
再起動時は同じ比較基準と全ラウンドの累積変更を入力から引き継ぐ。
再起動後の計画ファイルから比較基準を再計算しない。

指摘は次の3区分とする。

- 初版内補正: 比較基準の成果、合意、対象パスを維持したまま矛盾または実装不能を解消する
- スコープ拡大: 対象パス、成果、合意、利用者が観測する挙動のいずれかを変更する
- 独立問題: 初版の変更を実施しなくても存在し、初版の成立性を損なわない

各ラウンドで、`scope_baseline`の`implementation_summary`・`user_agreements`・
`change_content`と現行の3節を要素別に比較する。
各要素の差分を累積し、差分ごとに3区分、承認状態、反映状態、反映結果を記録する。
スコープ拡大の指摘は、計画変更から不具合までの実行結果または静的な呼び出し・参照経路を根拠とする。
根拠が成立した指摘は計画へ反映する前に、比較基準との差分、必要性、選択肢を
`needs_escalation`で呼び出し元へ返す。
呼び出し元の承認後は記録済みの同じ項目の承認状態だけを更新する。
独立問題は現在の計画へ統合せず、再現済みの事象だけを`out_of_scope_findings`へ記載する。
独立問題だけを理由に`needs_escalation`を返さない。
初版内補正と呼び出し元が承認したスコープ拡大だけを、
確定済みの採否に従って実装・修正系へ渡す。
未承認のスコープ拡大と独立問題は実装・修正系へ渡さない。

`採否確定後・反映前`では採用指摘を反映してから、
`反映後・再レビュー前`へ移行する。
修正後の再レビューは、前回の採用指摘、反映結果、反映差分、
現在のラウンドで反映前後に生じた機械修正前後の差分を対象とする。
新規指摘は統合した差分が生じさせた不具合に限定し、
因果となる差分と再現根拠を示す。
限定再レビュー後は指摘の有無にかかわらず、レビュー中の変更を検知し、
初版3要素との累積差分の区分と承認状態を更新する。
初回1回と再レビュー4回の合計5ラウンドを上限とする。
再起動時は受領した累積`review_rounds`を起点とし、各レビュー開始前に5未満であることを確認する。
レビュー応答を受領するたびに累積値へ1を加算し、再起動によって回数をリセットしない。
致命的・重大指摘の解消、未承認のスコープ変更がないこと、採用した初版内補正と
承認済みのスコープ拡大が反映済みであることを完了条件とする。
未解決事項は指摘全文、重大度、対象箇所、根拠、必要な修正、選択肢を
`escalation_points`へ記録し、`status: needs_escalation`で呼び出し元へ返す。
