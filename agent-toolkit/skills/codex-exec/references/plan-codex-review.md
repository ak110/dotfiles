# 計画ファイルのcodexレビュー

`plan-file-finalizer`が計画ファイルの機械チェック・修正と総合レビューを
別系統で実施するための手順を定める。
実装・修正担当は専用の書き込み契約に従い、レビュー担当は対象を変更せず指摘と根拠だけを返す。

## 初回委譲

委譲先へ次の絶対パスを渡し、着手時に全文をReadさせる。

- 本ファイル
- `plan-codex-review-task.md`
- 対象計画ファイル
- 適用する`agent-toolkit:review-standards`・`agent-toolkit:writing-standards`・
  `agent-toolkit:agent-standards`と対象固有スキル
- プロジェクト規範

タスク本文は作業ディレクトリ、対象、完了条件だけに限定し、規範本文を転記しない。
観点・ファイル・文書種別による複数起動は行わない。

## 機械チェック委譲

実装・修正系へは、本ファイルと`plan-codex-review-fix-task.md`を渡す。
読み取り専用の`plan-codex-review-task.md`は渡さない。
`plan-file-finalizer`が実装・修正系へ渡すタスク本文には、次の検査・違反修正・再検査を全て含める。

1. 計画ファイル本体へ次のコマンドを実行する

   ```text
   uv run --script ${CLAUDE_PLUGIN_ROOT}/skills/plan-mode/scripts/check_plan_file.py <計画ファイルの絶対パス>
   ```

2. 終了コード1のerror区分違反を全件修正し、終了コード0まで再実行する
3. 終了コード2では、対象パス・読み取り権限・文字エンコーディングを是正して再実行する
4. 終了コード2を解消できない場合は、原因を`escalation_points`へ記録して`needs_escalation`で返す
5. `[warn]`接頭辞付きの出力は内容を確認し、修正するか許容理由を`check_results`へ記録する
6. 計画ファイルを対象リポジトリ直下の一意な一時パスへ複製する
7. 複製には既存ファイルと衝突しない`.plan-check-<stem>-<プロセス固有識別子>.md`を使う
8. 一時複製へ`uvx pyfltr run --no-fix <一時パス>`を実行する
9. 違反または警告を計画ファイル本体で修正し、最新の内容から一時複製を再作成して終了コード0まで再実行する
10. 次のコマンドを計画ファイル本体へ実行し、検出内容を修正して終了コード0まで再実行する

    ```text
    uv run --script ${CLAUDE_PLUGIN_ROOT}/skills/writing-standards/scripts/check_dash.py <計画ファイルの絶対パス>
    ```

11. 修正後に3検査を再実行し、終了コード・error件数・warning件数を`check_results`へ記録する
12. 検査結果の成否にかかわらず一時複製を除去し、`git status --short`で未追跡の一時ファイルが残っていないことを確認する

計画ファイルは対象リポジトリ外に置かれる場合がある。
`pyfltr`へ計画ファイルの外部パスを直接渡すと検査対象から除外されるため、リポジトリ内の一時複製を検査対象とする。

## 変更検知

レビュー前に計画ファイルを一時退避し、内容ハッシュを記録する。
レビュー応答の受領後に内容ハッシュと差分を比較する。

変更を検知した場合は、変更ファイルの一覧・変更内容の要約・退避先パス・具体的な復元手順を
呼び出し元へ提示し、明示的な実行確認を得る。
確認後に限り、実装・修正系へ退避内容の復元を委譲する。
復元後の内容ハッシュが退避時と一致したことを確認してから、採用指摘の反映へ進む。

## 指摘反映と再レビュー

計画レビューにおける採否の最終確定者は、対象計画に責任を持つ
`agent-toolkit:plan-mode`の呼び出し元とする。
実装差分レビューでは`agent-toolkit:careful-review`の呼び出し元が最終確定者となり、
経路ごとに対象成果物の最上位責任主体が異なる。
事実確認済みの致命的・重大指摘は採用すべきとの見解とし、
軽微指摘は品質への寄与に基づく採否案を作成する。
対象範囲の変更や計画方針の再構成を要する指摘は、設計判断が必要な指摘として扱う。
設計判断が必要な場合、codex経路では判断材料をプロンプトへ含め、
Claude代替では`model: opus`を指定し、実装・修正系には採否案と技術的根拠を返させる。
`plan-file-finalizer`は採否案と対象の実体を照合し、`review_summary`への自身の見解の記載に留める。
実装・修正系と`plan-file-finalizer`はいずれも不対応注記を付さない。
呼び出し元の判断を要する指摘は、観測事実と選択肢を`needs_escalation`で返す。

`agent-toolkit:plan-mode`の呼び出し元が採否を確定した後、
採用指摘は原文、重大度、対象箇所、期待する反映結果を実装・修正系へ渡す。
反映後は同じレビュー系`threadId`へ、前回指摘と実装・修正系の反映結果を渡して再レビューする。
Claude代替では前回レビュー応答と反映結果を全文で渡して新規起動する。

初回1回と再レビュー4回の合計5ラウンドを上限とする。
致命的・重大の指摘が解消した時点で完了とする。
5ラウンド目にも致命的・重大指摘が残る場合は完了としない。
指摘全文、重大度、対象箇所、根拠、必要な修正を`escalation_points`へ省略せず記録し、
`status: needs_escalation`で呼び出し元へ返す。
`agent-toolkit:plan-mode`の呼び出し元による採否が未確定の指摘が残る場合は、
観測事実と選択肢を呼び出し元へ返す。
