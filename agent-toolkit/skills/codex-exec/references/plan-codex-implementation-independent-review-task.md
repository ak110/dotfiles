# 独立した実装差分レビュータスク

## 入力

- `plan-codex-implementation-review.md`と本ファイルの絶対パスを受け取り、着手時に全文を読む
- 変更ファイル一覧、計画着手前SHA、品質規範、プロジェクト規範、
  作業ディレクトリの絶対パスを受け取る
- 品質規範とプロジェクト規範は着手時に全文を読む
- 必須入力が欠ける場合は欠落項目を返し、推測で補わない

計画、進捗ログ、ユーザー発話、変更意図、許容済み挙動変化、コミットメッセージ、
計画準拠系を含む他レビューの出力は入力として受け取らず、参照しない。

## レビュー

- `git diff <計画着手前SHA>..HEAD -- <変更ファイル一覧>`と変更後ファイルを確認する
- 必要に応じて呼び出し元、参照元、テスト、生成・配布経路を調査する
- 正確性、回帰、実装漏れ、境界条件、テスト不足、保守性、規範適合を点検する
- `plan-codex-implementation-review.md`「初回レビュー」節が定める導出観点を点検する
- 再レビューでは、実装・修正系が返した一括修正後の影響監査について、点検対象と結果を照合する
- 計画ファイル、進捗ログ、コミットメッセージ、他レビューの出力を調査対象に含めない
- 対象成果物を読み取り専用として扱う

## 出力

- 指摘ごとに系統内通番、重大度、観点、箇所、内容、再現根拠、修正方針を返す
- 計画対応・独立提案の区分は返さない。区分判定は実装・修正系が担う
- `review_coverage`として、観点ごとの点検結果を「観点・点検対象・指摘件数」の形式で返す。
  指摘が無い観点も件数0として返す
- `review_impact_audit`として、一括修正後の再レビューでは影響監査の点検結果を返し、
  初回レビューでは「対象外」とする
- 再レビューで新規指摘を返す場合は、同referenceが定める3分類のいずれかを根拠付きで示す
- 指摘がない場合は「指摘なし」と明記する
