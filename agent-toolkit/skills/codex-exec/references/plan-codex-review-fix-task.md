# 計画ファイル機械チェック・修正タスク

## 入力

本節を機械チェック・修正系へ渡す資料契約の正本とする。

- `plan-review-delegation.md`、`plan-codex-review.md`、本ファイル、`plan-codex-implementation-task.md`の絶対パスを受け取り、着手時に全文を読む
- 計画ファイル、品質規範、対象固有スキル、プロジェクト規範の絶対パスを受け取り、着手時に全文を読む
- 初回機械検査または指摘反映の処理種別を受け取る
- 対象リポジトリと正規計画ファイルの絶対パスを受け取る
- 指摘反映では指摘全文、区分、呼び出し元が確定した採否、承認状態を受け取る
- 入力が欠ける場合は欠落項目を返し、推測で補わない

## レビュー指摘の妥当性検討

総合レビュー指摘の反映を担当する場合、指摘の妥当性は本系統が検討し、採否案と技術的根拠を返す。
`agent-toolkit:plan-mode`の呼び出し元が実測と要求原文を照合し、最終的な採否を確定する。
検討の観点は`plan-codex-implementation-task.md`「レビュー指摘の妥当性検討」節に従う。
特に、指摘が計画の確定事項、要求元の原文、ユーザーの明示指示と衝突しないかを確認する。
衝突する場合は、衝突箇所を根拠へ記して不採用案とする。

## 処理種別ごとの実行工程

| 処理種別 | 実行工程 | 書き込み許可先 |
| --- | --- | --- |
| 初回機械検査 | 正規計画へ3検査、違反修正、再検査を実施する | 正規計画だけ |
| 指摘反映 | 採用済み指摘だけを正規計画へ反映し、3検査を実施する | 正規計画だけ |

3検査は`plan-codex-review.md`「機械チェック委譲」節に従う。
対象リポジトリのファイルは読み取り専用とし、変更しない。
共有作業ツリーの変化だけを理由に処理を再実行せず、着手時に必要な対象ファイルを読み直す。

## 共通禁止事項

- 計画本文が`## 変更内容`として含む変更後文面は、計画ファイルの記述対象である。
  当該文面を対象リポジトリの実ファイルへ適用しない
- `git commit`、`git add`、`git push`を実行しない。
  コミットは呼び出し元の工程であり、本系統の担当外である
- 呼び出し元が採用指摘へ含めた実装コードや設定ファイルの文面案を対象リポジトリへ適用しない

## 出力

- `operation`と`status: completed|needs_escalation`を記載する
- 解消できない違反または実行不能がある場合は、原因を`escalation_points`へ記載する
- 正規計画の変更前と変更後のSHA-256を`plan_sha256_before`と`plan_sha256_after`へ記載する
- 各変更を機械違反または採用済み指摘へ対応づけ、`plan_change_summary`へ記載する
- 各検査の初回と最終の終了コード、error件数、warning件数を`check_results`へ記載する
- 対象リポジトリを変更していないことを`repository_write_status: unchanged`として記載する
- 外部コマンドを保持した場合は`external_execution`へ所有主体、安定した実行識別子、開始時刻、
  直近の生存確認時刻と結果を記載する。保持しなかった場合は`not_applicable`とする
