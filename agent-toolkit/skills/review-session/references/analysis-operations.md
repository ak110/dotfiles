# 原因分析の運用

## 規範の未適用と目的逸脱

規範が適用されなかった事象と、規範を適用した結果として目的から逸脱した事象は、原因を切り離して分析する。
警告への未対応から検査の強化、誤検出・反復負担へ続く場合は、行動上の原因と対策の副作用を同じ連鎖として評価する。最初の通知、判断、実行、元の成果、変更履歴を対応付け、行動規則の改訂、規範の統合・簡素化、hookの縮小・撤去、維持を比較する。
遮断と毎回の警告を極力避ける方針を前提とし、保持する成果、減る負担、残るリスクから推奨案と是正先を決める。必要性は目的と観測した害から判断する。正当な初回警告と安全保護の撤去には、発火件数に加えて保護の目的と実際の作用を評価する。
必要な対応を一度の警告後に取らなかった行動も是正対象とし、一般則の存在、警告の発火、最終回復だけで是正済みとしない。既存認可内の是正または通常AWIへ接続し、登録・実装と今回条件での解消・後日の効果を区別する。
再発・悪化を問う入力では、個別候補の採否の前に、次の2節で元の問いと分析単位の一致を確かめる。
`agent-basics:bugfix/references/root-cause-severity.md`「前提の再検討」を適用する。
`agent-basics:bugfix/references/root-cause-scenarios.md`「反復した指摘の原因判定」も併用する。
共有する規範・書式・通知・工程の変更も過去対策と比較し、結論を`analysis.md`「原因と対策」の報告へ引き継ぐ。
以下で実際のモデル階層を規定と比較するのは、その情報が対策の選定を左右する場合に限る。
規範本文と必要な変更履歴で欠陥と修正方針を判断できる場合は、記録位置やモデル階層を追加で調べずに調査を終える。
問題発生前のコンテキストにおいて規範の存在判定が`present`であった未適用事象では、記録から確認した実際のモデル階層（上位・中位・軽量）を、`agent-toolkit:delegation`の`references/runtime-routing.md`「代替時の組合せの目安」に照らし合わせる。上位階層あるいはそれと同等以上と確認できるモデルの場合は、モデルの性能不足を原因とみなさず、新たな条文の追記よりも先に、既存条文の削除、緩和、集約、単純化、または一般化を検討する。中位や軽量モデルの場合は、条文が明確であり、権限・手段・入力が適切に揃っていたにもかかわらず失敗したときに限り、工程に割り当てるモデルの変更やモデル自体の改善待ちを対策の候補とする。モデル階層に基づく評価は記録から確実に特定できたモデルのみを対象とし、モデルが不明または記録から欠落している工程については推測で補わない。

規範の問題の有無を問われた場合は、まず規範本文を確認する。本文の確認や必要な変更履歴との比較で欠陥が確定した場合は、セッション記録の照会を省いて規範の是正へ進む。
規範本文に欠陥が見当たらず、未適用の区分によって対策が変わる場合に限り、以下の手順で記録を照会する。

1. 条文から特徴的な1行を選び、`atk run-script session-review-evidence --`の`--context-at <事象の記録位置> --phrase=<文字列>`を実行してコンテキスト内の存在を照会する。得られた判定結果と、条文がコンテキストへ読み込まれた経路を示す`channel`をAWIの`直接的原因`行に記録する。phraseには事象発生時点の条文から文字列を選ぶ（事象後に改訂されている場合は`git log -S`で当時の文面を特定する）。
2. 判定結果を各区分に対応付ける。`absent`は起動契機の欠落や参照時点の問題（条文を含む資料が読み込まれなかった）とする。`dropped-by-compaction`はコンテキスト圧縮時の問題（会話圧縮によって除外され、再読み込みの対象外だったか切り詰めによって欠落した）、`present`は条文の判定条件、責務の所在、または想起性の問題とする。一致した`channel`が`user`と`assistant`のみである場合は、会話の中での単なる言及として扱う。
3. `agent-basics:bugfix/references/root-cause-prevention.md`「再発防止策の必須性」の未適用規範に関する是正原則に従って原因を特定する。条文の想起性を改善する案と、改善後の条文によって誤りの発生を未然に防げる見込みの根拠をAWIへ記録する。その見込みは、`agent-toolkit:delegation/references/agent-documents-basics.md`に示されている読み手（LLM）の特性に基づいて評価する。

目的逸脱には、規範に従ったことによる処理の停止、差し戻し、空転、不要な反復、条文間の矛盾、前提の欠落、あるいは要求を満たさない成果物の生成などが含まれる。正常に完了した工程であっても、資料の読み込み、照会、事前準備、確認に要した作業量を、本来達成すべき目的の操作と比較して評価する。
規範に従って実行される工程は適用されるたびに発生するため、1セッション内で1回発生しただけでも反復的な負担として評価する。ツールの呼び出し回数、資料の読み込み量、所要時間、適用の頻度を考慮し、必読範囲の縮小や集約、準備処理を呼び出される側へ移管する案、または探索自体を不要にする案などを比較検討する。
条文を改訂する際は、本来保護すべき価値、導入目的、および期待される成果に対応付けて内容を整理する。現行の条文をそのまま維持する場合は、同様の停止が発生する条件とそれを許容する理由を記録する。
判断の到達可能性については、`agent-basics:review-standards`の`references/judgment-details.md`「検収手段の到達可能性」に従って確認する。一般的な設計案の比較評価は、`agent-basics:writing-standards/references/design-heuristics.md`に従って行う。

## 通読で使う比較

本節で見出し名だけを示した比較基準は`analysis.md`の各節を指す。記録全体を通読するときは、該当する操作や成果がある観点を比べる。表は代表例であり、表に無い観点にも目的、契約、利用結果、QCDによる同じ比較を適用する。各行の合否を毎回機械的に埋めず、文字数・実行回数・トークン量だけで欠陥や必須対策を判定しない。既存の判断基準と連動する項目は該当する節に従う。

| 観点 | 比較する記録・成果と判定への接続 |
| --- | --- |
| 範囲の拡大 | 当初の成果と計画改訂・委譲・最終差分を比べ、設計やレビュー由来の追加も探す。規範由来のものは「規範適用による目的逸脱」で判定する |
| 例示への固定 | 目的と例示、比較案と実際の利用結果を比べ、例示外でも目的を満たす対象として扱う |
| 割込・圧縮後の脱落 | 要求の追加・変更・撤回・完了と、引き継ぎ記録・保留事項・最終報告を比べる |
| 完了条件のすり替え | 要求された利用結果と、検証の主体・公開確認・最終報告を比べる |
| 定期の通知・点検の未発火 | 経過時間と、規範やhookが一定間隔で届ける通知（進捗の定期セルフチェック、定期再確認など）の記録を比べ、通知が無い区間は発生源と条件を調べる。通知の不在を正常の証拠にしない |
| 必要な確認の負担 | 質問・全選択肢・回答・再質問と必要な判断材料を比べ、確認の必要性（「ユーザー介入の判定規則」で判断）と提示の重複・分かりやすさを分ける |
| 説明と行動の不一致 | ユーザーの問い、判断変更の説明、実際の操作、最終報告を突き合わせる |
| 実利用への適合 | エンドユーザーや利用場面と、成果物・実操作の証拠を比べ、形式的な成否だけで判断しない |
| 証拠以上の事実主張 | 報告の主な事実主張と、取得結果・終了状態・省略・未確認範囲を比べ、「情報探索の問題」と連動させる |
| 実装と同じ誤解を持つテスト | 要件に基づく期待結果・反例と実装・テストを比べ、「原因と対策」の契約比較へつなげる |
| 原因分析の各欄と系統別候補 | セッション内で作成したAWI・計画のバグ単位・ユーザーへの原因説明を比べ、全欄に根拠のない該当なしや処置の言い換えがないか、review-sessionなどの事後検出を検討したか、両系統の類似見直し観点・再発防止策の候補と採否、回帰防止策との区別、処置の原因条件への作用を確認する |
| 合格を目的にした対処 | 失敗から合格までの差分・除外設定・期待値と、本来必要な機能を比べる |
| 検証対象の不一致 | 最後の修正・生成・検証の時刻、パス、版、OIDと、完了の根拠を比べる |
| 前提確認の遅れ | 権限・環境・正常な手順の初期確認と、後半の手戻りを比べる |
| 根拠の無い追加設計 | 状態管理・監視・互換維持・フォールバックの設計理由と、観測された事象・消費側の要求を比べる |
| 必要な追従の不足 | 生成元・消費側・公開手段・配布先・OSペアと最終結果を比べ、全消費側の契約確認へつなげる |
| 委譲単位の過小・過大 | 作業の独立性・規模と準備・入力・返却の費用を比べ、直接実行と委譲の総費用を評価する |
| 不要な先行工程待ち | 先行成果を実際に使う入力と、起動・返却・待機の時機を比べ、実行時刻の重なりだけで先行成果の完了待ちが必要だったとしない |
| 作業量の偏り | 担当範囲・複雑さと各担当の所要時間を比べ、件数差だけを原因としない |
| 重複調査 | 各担当の既知情報・検索・読取と、入力・返却の再利用を比べ、必要な独立検収と分ける |
| 委譲入力・所有権の不足 | 目的・完了条件・版・パス・権限・作業境界と、生じた追加質問や担当外の操作を比べる |
| 正常返却の未検収 | 正常終了した返却と、元の完成条件・実際の成果物・検収記録を比べて欠陥の有無を判断する。実施方法と費用は「コストの無駄の確認」の採否へ対応付け、全文は要る箇所だけ照会する |
| レビューの後出し・往復 | 各回の指摘・修正・判定変更と初回時点で取れた根拠を比べ、第3ラウンド以降に限らず後出しや往復を探す |
| 成功した呼出しの集約 | `duration-analysis.md`「所要時間の分析と改善」に準じ、成功した同種操作の反復と、公開された複数対象の一括指定を比べる |
| ツールの経済性 | 入力、出力、再加工、再試行、待機と実際の消費工程を比べ、公開オプションによる対象限定・一括化、直接使える出力、参照渡し、標準手段、不要操作の撤去を比較する。既存機能の未利用も確認する |
| 自動チェック | 誤りを検出できる既存コマンド、pre-commit・CIからの呼出し、実行条件、対象範囲、診断を比べ、未接続・無効化・対象漏れの修復と再利用を先に検討し、未被覆部分だけ新設する |
| コーディング規約 | レビューで見逃した誤りを、機械判定できる違反と文脈判断に分ける。禁止API・配置・構文などは型や既存lintへ、判断を要する事項は担当レビューで読む規約へ対応付ける |
| 情報アクセス | 判断に不足した情報、実際の代替・推測、正しい判断に必要な情報源を比べ、ログ・テストデータ・ブラウザ・読み取り専用照会などへ既存認可内で到達できる環境変更を選ぶ |
| 表記が異なる同原因の失敗 | 診断メッセージ・意図・回復手順を比べ、シグネチャが違っても契約への共通の誤解を探す |
| 成功するポーリング | 照会の時点・状態変化と、終了状態を直接返す待機機能を比べ、成功した短時間の照会も対象にする |
| 出力設計による読み直し | 元の出力と、必要だった情報・追加照会・回復手順を比べ、不要な情報、必要項目の欠落、表示の分かりにくさを探す |
| 読取操作の副作用 | 許可された操作と実装・設定・前後の差分を比べ、正常終了でも共有状態が意図せず変わっていないかを確かめる |
| 資源の所有と終了 | 起動時の識別子と終了・回収の証拠を比べ、完了の申告だけで所有資源が終了したとしない |
| 証拠の寿命 | 証拠の保存先・回収の時機と後続の消費工程を比べ、必要な時点で照会できたかを評価する |
| 常時規範の肥大化 | 実際に配送・取得された本文、必要な判断時点、実装担当とレビュー担当の利用箇所を比べ、共通指示の削除・統合、役割と時点に合う読込、参照中心の構成から、守る価値を保って不要な初期読込を減らす案を選ぶ |
| 毎回の費用確認 | 担当ごとのRead対象・範囲・起動スキル・結果量、反復上位、大量結果の位置、メインエージェントのトークン上位を既存の統計で確かめ、必要な読込と減らせる重複を分けて報告に1行で書く |
| ナビゲーション | 探していた情報、検索・読取の順、迷い・誤参照・再探索、見つかった定義元を比べ、正規資料への参照、隠れた依存の明示、索引・配置の整理で次回不要になる探索を示す |
| 版・時点・配布手段の混在 | 実行時に適用された版と参照パス・生成物・履歴を比べ、発生時点の文面を確かめる |
| 代替指標の目的化 | 件数・書式・特定工程の通過・警告の解消と、本来求められた結果を比べる |
| 責務と読者のずれ | 担当の責務・使う情報と、文書の適用範囲・読込の契機・要求された入力を比べ、読込量の多さだけで誤った読込としない |
| 無効な指示 | 指示の適用場面、行動と結果、反復した未適用、追加後も変わらない結果から、撤去・言い換え・適用時機の変更・型や自動チェックへの移行を比較する。対策・条文・例外の蓄積による読込・確認・理解の負担も評価する |
| 失敗の無い改善機会 | 正常に済んだ作業の全手順・利用結果と既存手段での代替を比べ、データ加工・規範・所要時間の典型以外も探す |
| 良い手段の再利用 | 同じ目的の実作業どうしで入力・工程・品質・成立条件を比べ、改善が要る他の消費側へ広げられるかを判断する |
| 対策の副作用と総費用 | 対策の差分・適用頻度と通常操作に加わる負担を比べ、ツール・テスト・状態管理への影響も評価する |
| 測定単位のずれ | `duration-analysis.md`で、定義・母集団・待機・キャッシュ・担当構成と、受入済み成果・人間の負担を比べる |
| 改善要求の分断と滞留 | 既存キュー項目の共通原因・状態・日時と実施結果を比べ、登録件数を対策効果の代わりにしない |
| 振り返り自身の費用 | 準備処理後の起草・投入・質問・終了記録と本来の目的を比べる。ユーザー発話や気付いた改善点（振り返り自身の起動・待機・検収・保存に起因するものを含む）は、準備処理を再実行せず、既存索引と`session-review-evidence`の`--detail`や`--tool-calls`で工程3〜5の追加分析へ送る |
| 抽出の偽陰性 | 元の記録と候補一覧・除外区分・抽出条件を比べ、正常な返却や単発の失敗が不当に除外されていないかを代表例で確かめる |
| 縮約による文脈喪失 | 要約・縮約された入力や成果を全文・差分と比べ、比較材料が足りなければ詳細照会へ進む |
| 正常・非律速委譲の問題 | 担当ごとの入力・返却・費用と、完了条件・必要な内部位置を比べ、律速でないことを品質・費用面の除外理由にしない |
| 要約に出ない費用 | 担当ごとのトークン数・キャッシュ量・応答回数・入力規模と所要時間を比べる |
| 実行系・呼出形式の被覆差 | 同種の記録と、抽出処理の入力契約・実際のログ・形式別の検証結果を比べ、ラッパー内部の処理を無条件に同等としない |
| 未確認範囲の受渡し | 「入力と照会」の未解決記録の扱いに従い、確認済みの範囲と照会できない範囲を分ける |
| 委譲入力の過剰・冗長 | 起動時・追送時の本文と、参照ファイルの本文・配送済みの規範・実際に要った事実・認可・範囲を比べ、重複、不要な情報、先入観による記載を分ける |
