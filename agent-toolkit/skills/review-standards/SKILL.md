# レビュー担当とレビューイーの心得

本スキルは、レビューを実施する主体と、指摘を受領して採否と修正を確定する主体へ判断基準を提供する。
自身の役割を先に確定し、対応する参照資料を全文読む。

いずれの役割でも、判定は`agent-toolkit/rules/01-agent.md`「判断指針」の3段判定に従い、許容性、必要性、実装品質の順に行う。

- レビューを実施する主体（レビュー担当）: `references/reviewer.md`
- 是正要求等（レビュー指摘、改善提案、ユーザーの割り込みや是正要求、作業中の想定外の発見）を受領し、採否と修正を確定する主体（レビューイー）: `references/reviewee.md`
- 計画・設計の採用案や是正要求等の妥当性を評価する場合は、役割を問わず`references/judgment-details.md`

レビュー担当は`references/reviewee.md`を読まず、レビューイーは`references/reviewer.md`を読まない。
一方の役割の資料を他方の判断へ適用しない。

## 対象成果物の作成規範

いずれの役割でも、対象成果物へ適用される作成規範を最初に全文読む。
該当する規範は`agent-toolkit:writing-standards`と、対象リポジトリの`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`配下とする。

## レビュー指摘管理表の共通操作

レビュー担当の指摘追加とレビューイーの応答記録は、いずれも`atk review-table`で行う。
役割ごとのサブコマンドと必須オプションは各参照資料が定める。
`atk review-table add`と`atk review-table respond`は、保存済みの表から読み直した本文との一致判定を出力へ含める。
記録した直後に当該出力の一致判定が全て`一致`であることを確認する。
一致判定が`一致`である場合は、保存本文を再取得して全文比較する工程を行わない。
一致しない箇所が報告された場合だけ、`atk review-table show <表の絶対パス> --track <レビュー区分> --round <ラウンド番号> --format=jsonl`で復号済みの保存本文を取得して差異を特定する。
各セルはJSON文字列として保存するため、`--format=tsv`の出力を当該特定へ用いない。
受理形式、出力の項目名及び項目の順序は同コマンドのヘルプを正本とする。
一致しない箇所を検出した場合は、同じ`atk review-table`の経路で修復してから記録をやり直す。
