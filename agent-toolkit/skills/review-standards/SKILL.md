# レビュー担当とレビューイーの心得

本スキルはレビューを実施するエージェントと、指摘を受領して採否と修正を確定するエージェントへ判断基準を提供する。
指摘の確定基準、種類、範囲と書き方は本スキルと`references/reviewer.md`が定める。レビューを担う`<役割名>.subagent.md`とスキルは独自の判定観点を追加せず、不足は本スキルを改訂して補う（観点が分散すると同じ成果物への判定が分岐し、修正と再レビューが収束しない）。
自身の役割を先に確定し、その役割の行の資料を読む。同じエージェントが別の時点で他方の役割を担う場合は、その時点で改めて確定する。

レビューの判断には対象成果物と契約の読取が必要であり、Git実体の確認・検証・表の保存には各操作の手段も要する。資料だけを読める環境では、提示された範囲で裏付けた指摘と、追加の観測が必要な範囲を返す。検証と保存を含む実行レビューは、それらを行えるClaude CodeまたはCodexで続ける。指摘の文面は[文章の品質基準](references/quality-standards.md)で確かめる。

## 読込表

次の時点または条件が成立したら、その操作の前に同じ行の資料を全文読む。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| いずれの役割でも、判定を始める前 | 「対象成果物の作成規範」が指す作成規範 |
| レビューを実施するエージェント（レビュー担当）として判定する前 | `references/reviewer.md` |
| 是正要求等（レビュー指摘、改善提案、ユーザーの割り込みや是正要求、作業中の想定外の発見）を受領し、採否と修正を確定するエージェント（レビューイー）として判定する前 | `references/reviewee.md` |
| 役割を問わず、計画・設計の採用案や是正要求等の妥当性を評価する前 | `references/judgment-details.md` |
| 実行レビュー担当として、指摘を登録するか完成条件証拠へ記入する前 | `references/exec-review-recording.md` |

いずれの役割でも、判定は`agent-toolkit/rules/01-agent.md`「判断指針」の3段判定（許容性、必要性、実装品質の順）に従う。案の必要性・既存機構・過剰設計・点修正と共通原因修正・責務帰属の比較は`agent-toolkit:writing-standards`の`references/design-heuristics.md`「設計案の予備選別」に従う。

## 対象成果物の作成規範

作成規範とは対象成果物の種別に適用する作成側の品質基準を指し、`agent-toolkit:writing-standards`の該当資料と、対象リポジトリの`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`配下のうち実在するものとする。

## 文章成果物の実害

文章成果物では、読者像が本文から行為者・対象・条件・結果を一意に読めず、判断・操作・検証を誤るか進めないことを実害とする。
文章の指摘の採否は、本文が適用する作成規範の条文に反するか、前述の実害があるかで判定する。
機能上の害の有無や計画・WIの完成条件の充足は、文章の採否とは別に確かめる。
エンドユーザー向け文書の誤記と適用対象のスタイル違反はQに影響する指摘として是正する。

## レビュー指摘管理表の共通操作

レビュー指摘管理表は、`atk review-table`が操作するヘッダーなしのTSVで、計画ファイルと同じstemの`.exec-review.tsv`を指す。CI対応レビュー指摘管理表は、対応する計画が無いCI失敗への対応をレビューした指摘を記録するレビュー指摘管理表（`ci-<OID>.exec-review.tsv`）を指す。
`atk review-table init`直後の0バイトの表は指摘0件の初期化済みの表であり、指摘なしで終端するレビューでもヘッダーや仮の指摘行を加えずそのまま使う。監査記録は`docs/development/audit-records.md`の「agent-toolkit/skills/review-standards/SKILL.md：レビュー指摘管理表の共通操作：2026年10月8日」にある。
指摘の追加と応答の記録はいずれも`atk review-table`で行い、指摘箇所、指摘内容、対応内容および理由はファイルのパスを渡すオプションで渡す。役割ごとのサブコマンドと必須オプションは各参照資料が、列の形式と出力は`atk review-table --help`が定める。
`add`と`respond`は保存した本文を送信元と比べて検証するため、終了コード0なら保存本文の再取得と全文比較を省く。
