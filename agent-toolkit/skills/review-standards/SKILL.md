# レビュー担当とレビューイーの心得

本スキルはレビューを実施する主体と、指摘を受領して採否と修正を確定する主体へ判断基準を提供する。
指摘の確定基準、種類、範囲、除外条件と指摘内容の書き方は本スキルと`references/reviewer.md`が定める。レビューを担う`<役割名>.subagent.md`とスキルは独自の判定観点を追加せず、本スキルを参照する。不足を見つけた場合は本スキルを改訂する。観点が複数箇所へ分かれると、同じ成果物への判定が分岐し、修正と再レビューの収束が妨げられる。
自身の役割を先に確定する。読む資料は次の読込表のうちその役割の行が定める。

## 読込表

次の時点または条件が成立したら、その操作の前に同じ行の資料を全文読む。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| いずれの役割でも、判定を始める前 | 「対象成果物の作成規範」が指す作成規範 |
| レビューを実施する主体（レビュー担当）として判定する前 | `references/reviewer.md` |
| 是正要求等（レビュー指摘、改善提案、ユーザーの割り込みや是正要求、作業中の想定外の発見）を受領し、採否と修正を確定する主体（レビューイー）として判定する前 | `references/reviewee.md` |
| 役割を問わず、計画・設計の採用案や是正要求等の妥当性を評価する前 | `references/judgment-details.md` |
| 実行レビュー担当として、指摘を登録するか完成条件証拠へ記入する前 | `references/exec-review-recording.md` |

各判断へ適用するのは、その時点で確定した役割に対応する資料だけとする。
同じ主体が別の時点で他方の役割を担う場合は、その時点で改めて役割を確定し、対応する行の資料を読む。

いずれの役割でも、判定は`agent-toolkit/rules/01-agent.md`「判断指針」の3段判定に従い、許容性、必要性、実装品質の順に行う。
案の必要性、既存機構、ライフサイクルの複雑性、過剰設計、点修正と共通原因修正、共通原因および責務帰属の比較は、いずれの役割でも`agent-toolkit:writing-standards`の`references/design-heuristics.md`「設計案の予備選別」に従う。

## 対象成果物の作成規範

作成規範とは対象成果物の種別に適用する作成側の品質基準（`agent-toolkit:writing-standards`の該当資料とプロジェクト規範）を指す。
該当する規範は`agent-toolkit:writing-standards`と、対象リポジトリの`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`配下とする。読む時点は読込表の最初の行が定め、いずれの役割でも他の資料より先に読む。

## レビュー指摘管理表の共通操作

レビュー指摘管理表は、`atk review-table`が操作する8列のTSVで、計画ファイルと同じstemの`.exec-review.tsv`を指す。CI対応レビュー指摘管理表は、対応する計画が無いCI失敗について、CIのエラーへの対応内容をレビューしたときの指摘を記録するレビュー指摘管理表（`ci-<OID>.exec-review.tsv`）を指す。
レビュー担当の指摘追加とレビューイーの応答記録は、いずれも`atk review-table`で行う。
指摘箇所、指摘内容、対応内容および理由はいずれもファイル経由で渡す。受理形式はファイルのパスを渡すオプションだけである。
役割ごとのサブコマンドと必須オプションは各参照資料が定める。
`atk review-table add`と`atk review-table respond`は保存済みの表から読み直した本文を送信元本文と比べる。
終了コードが0であれば本文が一致したとみなし、保存本文の再取得と全文比較を省く。
受理形式、出力の項目名と項目の順序は同コマンドのヘルプに従う。
