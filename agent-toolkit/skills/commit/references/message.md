# コミットメッセージ

本書は、コミットメッセージの件名、フォーマット、type、description、本文、および`Co-Authored-By:`に関する規約を定める。
本書の内容は`.gitmessage`と配布対象の範囲が異なるため、意図的に重複して記載している。
なお、コミットメッセージの第1行を「件名」と呼ぶ。

プロジェクト固有の方針が定められていない場合は、Conventional Commits形式で記述する。プロジェクトで独自の固定文言体系（カテゴリ名や決まった件名パターンなど）が指定されている場合は、それに従う。
プロジェクトの方針は、`CLAUDE.md`、`AGENTS.md`、`.claude/rules/`、コミットテンプレート、lint設定など、明文化された既存のドキュメントから確認する。明文化されていない事項については、同種の複数のコミットで一貫して観測され、かつ明文の方針と矛盾しない形式のみを慣例として採用し、単発のコミット履歴は判断根拠から除外する。明文の方針とコミット履歴が矛盾している場合は、`agent-basics:review-standards`の`references/judgment-details.md`「矛盾の原因調査」に従って対応する。

- 形式: `<type>[(<scope>)]: <description>`とする。破壊的変更（Breaking Change）を含む場合は`!`を付与する。本文やトレーラー（trailer）を記載する場合は、件名のあとに空行を1行挿入する。
- typeと`!`の付与は、成果物を利用する主体（配布先のエンドユーザー、開発者、またはエージェント）の振る舞いにどのような影響を与えるかに応じて選択する。機能の追加、修正、パフォーマンス改善はそれぞれ`feat`、`fix`、`perf`とし、消費主体の振る舞いに直接影響しない内部変更は`chore`、`ci`、`refactor`、`docs`、`test`とする。lintやformatterの設定、CI手順、依存パッケージ群の整理など、開発者向けの設定変更には`!`を付けない。
- エージェント向け文書は配布先エージェントの判断や振る舞いを直接規定するため、判断の分岐条件の変更、規範の削除、機能的な規範の改訂などは`chore`としては扱わない。振る舞いを変更する場合は`fix`、振る舞いを変えない構造整理であれば`refactor`とする。
- scopeは、変更が単一のモジュールや特定の機能に閉じている場合に限り、短い名詞で指定する（努力目標）。
- descriptionは日本語で記述し、変更対象と変更内容または問題の種類が一目で把握できる簡潔な表現にする。複数の変更が含まれる場合は共通の目的にまとめて件名とし、変更が必要となった背景や個別の詳細事項は本文に記載する。エンドユーザーが呼び出すAPI名、設定キー、画面上で目にする識別子などはそのまま表記し、読み手が直接知り得ない内部識別子のみを必要に応じて平易な言葉に言い換える。
- 本文の記述は任意とする。本文を記載する場合は、`agent-toolkit:delegation/references/writing.md`「文章の共通規定」に従う。

## `Co-Authored-By:`

`Co-Authored-By:`の値は、ユーザーの明示指示、明文化されたプロジェクト方針、実行環境が提示する帰属指定の順に確認し、最初に見つかった定義に従って決定する。空文字列が指定されている場合は、帰属表示を明示的に無効化したものとして扱う。
いずれの定義も存在しない場合は、`Co-Authored-By: <実行中のモデルの表示名> <noreply@<モデル提供元のドメイン>>`を付与する（Codex環境でのドメインは`openai.com`とする）。
設定するモデル名と推論量（effort）は、コミットを実行するターンのホスト記録から実際に観測された値を用いる。モデルの設定値やエイリアス、起動時の候補一覧などは単なる起動用パラメーターとして扱い、実際に観測できた場合にのみトレーラーを付与する。
このトレーラーは最終的なコミットメッセージに1回だけ追加し、既存の異なるトレーラーはそのまま保持する。

- Claude Code環境では、帰属指定に含まれる`{model}`や`{effort}`が自動展開されずにそのまま渡されるため、エージェント自身が値を取得して記述する。推論量はBashで`printenv CLAUDE_EFFORT`を実行して取得する。モデル名は、ホストから通知されたモデルIDから末尾の角括弧の装飾（`[1m]`など）を除去した値とする（PreToolUseフックが期待値を突き合わせる際の`message.model`にはこの装飾が含まれないためである）。`claude-<系列>-<主版>-<副版>`（末尾に8桁の日付が付いている場合も含む）の形式は、`Claude <系列の先頭大文字> <主版>.<副版>`へ変換する。この形式に当てはまらないIDはそのまま使用する。推論量の文字列は先頭を大文字にする（例: `Co-Authored-By: Claude Opus 5.5 / Medium <noreply@anthropic.com>`）。
- Codex環境では、本書をシェル経由で読み取った際に、PreToolUseの追加コンテキストとして、読み取り時点で観測されたモデルと推論量に基づく帰属行が渡される。これが観測できない場合は推測で補わず、コミットを実行するターンのホスト記録を確認する。
- ドキュメント読み取り時の情報は後から変化する可能性があるため、コミットを実行する直前にも現在のモデルと推論量を再確認する。期待値と異なる行、不正な形式の行、あるいは重複した行が存在する場合はPreToolUseフックによって遮断され、通知メッセージに正しい帰属行が示されるため、その行を指定してコミットを再実行する。
