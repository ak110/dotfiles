# コミットメッセージ

本書はコミットメッセージの件名、形式、type、description、本文と`Co-Authored-By:`の規約を定める。
本書のコミットメッセージ方針は`.gitmessage`と配布範囲が異なるため意図的に重複させる。

コミットメッセージ第1行は「件名」と呼び、コミット文脈の記述で本表記に統一する。

コミットメッセージはConventional Commits形式で書く（プロジェクト方針が無い場合）。
プロジェクト方針で固定文言体系（カテゴリ名・固定件名等）が指定されている場合は、その体系に従う。
プロジェクト方針は、対象リポジトリの`CLAUDE.md`・`AGENTS.md`・`.claude/rules/`配下、
コミットテンプレート、lint設定などの明文化された情報から確認する。所在は実在するものに限り、存在を確かめてから読むか検索の対象へ渡す。
明文化された方針が扱わない事項では、同種の複数コミットで一貫して観測され、
明文化された方針と矛盾しない形式だけをプロジェクト内の慣例として優先する。
慣例の根拠は同種の複数コミットにわたる一貫した観測とし、単発のコミット履歴は候補から外す。
方針と履歴が矛盾する場合は`agent-toolkit:review-standards`の`review-standards/references/judgment-details.md`「矛盾の原因調査」に従う。

- 形式: `<type>[(<scope>)]: <description>`。破壊的変更は`!`を付ける
- 本文またはtrailerを持つ場合は、件名と後続行の間に空行を1行置く。件名だけの場合は空行を加えない
- typeは成果物の消費主体への影響で選ぶ。開発作業への影響と、配布先のエンドユーザー・開発者・エージェントの振る舞いへの影響を区別する。機能追加・修正・性能は`feat`/`fix`/`perf`、振る舞いに直接影響しない内部変更は`chore`/`ci`/`refactor`/`docs`/`test`とする
- scopeは単一モジュール・機能に閉じる範囲を短い名詞で任意に示し、複数にまたがるか曖昧なら省く（努力目標。範囲の誤読を避けるため）
- `!`も消費主体の振る舞いへの影響を基準に判断する
  lint/format設定・CI/ワークフロー手順・依存グループ入れ替えなど開発者向け設定の変更は、`!`の対象から外れる
- エージェント向け文書は配布先でエンドユーザーまたはエージェントの振る舞いを構成するため、本文中の判断分岐、規範削除および機能的な規範変更は`chore`の対象から外す。配布先の振る舞いを変える場合は`fix`、変えない構成の整理は`refactor`とする
- descriptionは日本語で、リリースノートの読者と後続開発者へ目的を簡潔に伝える。変更内容より必要性・可能になること・防ぐ問題を先に示し、scopeが省かれても対象を特定できる粒度にする（努力目標。目的と範囲を伝えるため）
  - エンドユーザーが呼び出す・設定する・目にする識別子は原表記を保つ。言い換えは知り得ない内部識別子に限り、対象を一意に特定できる語を選ぶ
- 計画ファイルにコミットメッセージ案を書く時点でも上記基準でセルフチェックする
- 本文（body）は任意。記載する場合の読み手、粒度、分量および構造は`agent-toolkit:writing-standards`の`references/writing.md`「人間向け文章の共通規定」に従う
- `Co-Authored-By:`の値はユーザーの明示指示、明文化されたプロジェクト方針、実行環境が提示する帰属の指定の3つの取得元をこの順に確かめ、
  最初に観測できた定義から決定する。
  いずれの取得元にも定義が無い場合は`Co-Authored-By: <実行中のモデルの表示名> <noreply@<モデル提供元のドメイン>>`を付ける。Codexのドメインは`openai.com`とする。空文字列の指定は帰属の明示的な無効化として扱う。
  帰属の指定と前記の形へ入れるモデルと推論量（effort）は、commitを実行するturnのホスト記録から観測した値とし、モデル設定、aliasおよび起動候補は起動用の値として扱う。trailerを付けるのは入れる値を観測できた場合だけとする。
  `Co-Authored-By:`は最終コミットメッセージへ1回だけ付け、既存の異なるtrailerを保持する
  - Claude Codeは帰属の指定の`{model}`と`{effort}`を値へ置き換えずに渡すため、エージェントが値を得て書く。推論量はBashで`printenv CLAUDE_EFFORT`を実行して得る（ホストがturnへ適用した値）。モデルはホストが通知するモデルIDから、1Mコンテキストの構成などで末尾に付く角括弧の印（`[1m]`など）を除いた値を使う。PreToolUseは期待値を記録の`message.model`から求め、この値は印を持たないためである。その値を`claude-<系列>-<主版>-<副版>`（末尾に8桁の日付が付く場合を含む）から`Claude <系列の先頭大文字> <主版>.<副版>`の表示名へ変換し、形の合わないIDはそのまま使う。推論量は先頭を大文字にする（例: `Co-Authored-By: Claude Opus 5.5 / Medium <noreply@anthropic.com>`）
  - Codexでは本書をシェルで実際に読み取ると、PreToolUseの追加コンテキストが読取時点に観測したモデルと推論量の帰属行を届ける。plugin rootや配布先が異なっても本書のファイル引数から判定し、引用・検索・別資料には配送しない。観測できない場合は行を推測せず、commitするturnのホスト記録を確認する。明示指定と無効化の取得順は前段に従う
  - 先行配送は読取時点の観測であり、通常commit直前にも現在のモデルと推論量を確認する。期待値と異なる行、不正な行と重複行はPreToolUseが遮断し、通知が現在必要な帰属行を示す。遮断された場合はその帰属行で実行し直す。既存の帰属確認の対象外の入力とClaude Codeの取得手順は前段に従う
