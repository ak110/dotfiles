# 作業用ブランチと退避物の扱い

作業の退避、バックアップ、または実験のために作成した一時ブランチ、`git stash`による退避データ、別ディレクトリへの複製ファイルなどは、その目的を果たした段階で速やかに削除する（努力目標。不要な退避物が蓄積すると、後続の作業で必要なデータの判別が難しくなるため）。
委譲先エージェントの完了報告に退避識別子や複製のパスが含まれている場合は、委譲元エージェントが結果を受領・検収する際に、本書の手順に従って削除などの処置をする（これは、委譲先に対して退避物の勝手な破棄を禁じる規定と対をなすものである）。

退避物を削除する際は、その内容が「採用された変更」なのか「不要として破棄された変更」なのかを明確にし、採用された変更であれば統合先のブランチへ確実に反映されていることを確認してから行う。過去のエージェントによる退避物と誤変更は、`agent-toolkit/rules/02-agent-operations.md`「プロセス終了の安全規定」で由来と現在の利用、必要な成果、認可を調べる。保持する場合は保護対象または残るユーザー判断と、将来回収するための条件を記録に残す。

作業着手前から存在していた未コミットの差分を「不採用」として破棄する前には、必要に応じて復元できるように退避を確保しておく。並行するworktreeでは既存の`atk worktree-stash`を利用し、マージが進行中の状態では本書に定める「別パスへの複製」または「別ブランチの作成」の手順を用いる。なお、private-notesリポジトリにおける退避の禁止および差分破棄の禁止規定は常に維持する。

- 一時ブランチ: `git cherry -v <統合先> <対象ブランチ>`および`git diff --diff-filter=A --name-only <統合先>..<対象ブランチ>`を実行し、統合先ブランチに同等の変更がすべて取り込まれており、対象ブランチにのみ存在するファイルがないことを確認する。cherry-pickや履歴の整理を経た統合先ではパッチID（patch-id）が一致しない場合があるため、変更されたファイル群を対象に`git diff <対象ブランチ> <統合先> -- <files>`を実行して内容を比較する。
- `git stash`: `git stash show --include-untracked -p <識別子>`を実行して追跡対象と未追跡ファイルの両方の差分を確認したうえで、`atk worktree-stash drop '<識別子>'`を用いてファイルロックのもとでOIDを再確認しながら削除する。worktree固有の参照への退避（`refs/worktree/<退避ラベル>`）も同一の手順で安全に処理する。
- 別パスへの複製: `diff`コマンドを用いて、複製元ディレクトリと内容を比較・確認する。

## merge進行中の退避

`git merge`が進行している状態での差分退避は、別パスへのファイルコピー（`cp`）または別ブランチの作成によって行う。マージが進行している最中に`git stash`を実行すると、`git stash pop`で復元した際にコンフリクト解決中の状態やマージのコンテキストが正常に復元されず、それまでの解決作業の結果が失われてしまうためである。別パスへ複製したデータについても、作業完了後は本書の確認手順に沿って確実に回収・削除する。
