## 依存と冷却時間

`depends_on`は、先に終了させておくべきキュー項目のファイル名を保持する。
これは、先行する項目の成果物が存在しないと、後続のWIを安全に実施できない場合や完成の判定が成り立たない場合に限って設定する。
依存先を設定する際は、待っている成果物の内容、先行成果物がないと成り立たない工程や完了条件、および現行の成果物では代替できない理由を、依存先ごとに後続項目の本文中へ明記する。
同一ファイルを変更すること、変更範囲が重複すること、作業順序の好みの問題、あるいは共通方針を反映することなどは、依存関係を設定する理由から除く。
書き込みの競合や実装の順序については、レーンの割り当てによって調整する。
依存先には、`target_repo`が異なるリポジトリの項目を指定できる。
同一のファイル名を持つ項目が複数の`target_repo`に存在する場合は、依存元と同じ`target_repo`の項目を優先して依存先とし、該当するものがない場合はそのファイル名を持つすべての項目を依存先として扱う。
依存関係は、`atk wi set-dependencies <filename> --depends-on <filename>`を実行することで、`inbox`、`processing`、`hold`の状態にある項目へ登録する。
このコマンドは項目の保存状態を変更しないため、保留期間中に本文の修正と依存関係の確定をまとめて行うことができる。
項目が`ready`か`blocked`かの判定は、メタデータに記録された依存関係のみに基づいて導き出される。

`cooldown_until`は、AWIのみに設定できる属性である。
初回投入時には`atk wi add --cooldown-until <タイムゾーン付きISO 8601日時>`で指定し、複数の`--body-file`を同時に渡した場合はすべての項目に同一の期限が保存される。
空文字列や不正な形式の日時、タイムゾーンの指定がない日時、UWIやbatchとの併用、および通常本文のfrontmatterでの直接指定は受け付けられない。
既存の`inbox`または`hold`の状態にあるAWIに対しては、`atk wi edit <filename> --cooldown-until <日時>`で設定でき、この編集操作に空文字列を渡すことで設定を解除できる。
UWIに対して日時を設定する操作は拒否される。
もしUWIに期限が保存されていると、着手可否判定において不正な期限として扱われてしまうため、同様の編集操作で空文字列を渡して解除しておく。
なお、`processing`の項目は設定と解除の受付対象外である。
設定された期限が到来した後は、他に続行できない理由がなければ状態が自動的に`ready`へ移行する。
先送りを選ぶ前に`agent-toolkit:user-confirmation-and-report`「確認要否の判定」と「由来と承認」を適用する。
待てば解決する見込みは、既知の解除時刻、提供予定、同条件の一次情報や実際の観測など、具体的な根拠で判断する。
解決の保証までは要求せず、任意に決めた再確認日や将来APIが追加される可能性だけを根拠にしない。

## 着手不能要因の分類

| 解除される契機 | 該当する要因 | 設定方法 |
| --- | --- | --- |
| 時間の経過のみ | レート制限に伴うバックオフ、再試行間隔の待機、指定期日の到来待ち、および解決する見込みの根拠がある外部公開の再確認までの待機 | `cooldown_until`を設定する |
| 実在する先行キュー項目の終了 | 先行するキュー項目の作業成果待ち。別リポジトリの成果物を待つ場合であっても、待機対象がキュー項目として実在していればここに該当する | 該当項目のファイル名を`depends_on`に直接追加する |
| ユーザーからの回答 | ユーザーの回答が得られないと作業を進められない要因 | [uwi-format.md](uwi-format.md)の事前承認型書式に従ったUWIを作成・保存し、元の項目の`depends_on`へそのUWIを加える（「承認型UWIと元項目」） |

UWIとして起票するのは、対応方針の選択や実施可否の判断が必要であり、その問いを1文で端的に表現できる事項に限る。
外部環境の制約や別環境での作業実施といった事情は単なる発生場所に過ぎないため、UWIを起票する直接の根拠にはせず、ユーザーによる判断が不可欠であるという点を行動の根拠とする。
すでにユーザーから認可を得ている操作の実施については、`agent-toolkit:process-wi`に定められた外部操作の手順に沿って進める。
一連の関連作業が完了した後に必要となるユーザー側の対応については、`agent-toolkit:user-confirmation-and-report`「手段の選択」に基づいてUWIを登録すべきかどうかを判定する。
登録が必要と判断した場合は、関連するAWIの完了工程に登録予定を記録し、そのAWIを担当するエージェントがUWIの正常な保存を確認する。
先行作業の完了を待つだけの事項は、依存関係（`depends_on`）として整理する。
外部公開待ちの`cooldown_until`は再確認までの待機を解除する。
外部の解除条件と解除後の作業をAWI本文へ残し、期限到来時に条件を確かめる。
公開日が不定でも、解決する見込みの根拠があり必要な判断が済んでいれば、次の再確認時点を設定できる。
見込みを確認できない場合はcooldownを設定せず、残りの見送り・別案・外部変更待ちの扱いを事前承認型UWIで確認する。
UWIの保存・元項目の依存設定・inboxへの差戻し・回答後の再開は、`states-and-dependencies-approvals.md`「承認型UWIと元項目」と「回答済みUWIの取り込み」に従う。
