# UWI本文の書式

UWI本文は次の順序で書く。冒頭へ、回答者が何を回答するかを示す疑問文を1文置き、必要に応じて当該問いが生じた目的を同じ位置へ続ける。`--question-type`が`choice`又は`yes-no`の場合は、次に`## 選択肢と帰結`のH2を置き、選択肢と各選択肢を選んだ場合の帰結を書く。`free-form`の場合は、自由記述で回答できる問いとし、当該節を置かない。最後に`## 判断材料`のH2を置き、判断を変える事実（背景、影響範囲、復元手段）だけを書く。
体言止めの表題だけを冒頭へ置く形と、問いが背景説明の後に現れる形は用いない。`--question-type=choice`でも冒頭の疑問文を省略しない。
ツールが自動付与する`## 質問`と`## 回答`の見出しは本文と同じ階層のH2となるため、本文へ置くH2はこの2つと異なる名前にし、H3以深で節を細分しない。
回答者が対象ファイルと他のキュー項目を参照せずに判断できる情報を本文へ保持する。識別子は対象との関係を示す文脈語とともに用いる。

問いの主題と、選択肢を置く形式での選択肢の主題の選び方は、`agent-toolkit:review-standards`の`references/judgment-details.md`「確認の選択肢を組む手順」に従う。

`atk wi add --type=uwi`へ渡す本文は質問本文だけとし、ツールが自動付与する`## 質問`見出し、`## 回答`以降及び回答欄マーカーを含めない。既存UWIを起草の起点にする場合は、当該見出しと回答欄を除去する。
`## 回答方法`節は、`--question-type`が`choice`と`yes-no`の場合は書かない。ブラウザーUIがfrontmatterの`question_type`と`choices`から回答の選択肢を表示するためである。自由記述で返信形式を指定する必要がある場合だけ置く。

外部環境の実機確認を依頼する場合は、対象環境・事前条件・番号付き操作、確認場所と取得値、本文へ直接記載した期待値、回答欄へ貼り付ける最小の返信形式及び確認できない場合の記載内容を`## 判断材料`へ含める。

複数項目の判断を求める場合は、変更前後が分かる差分又は対象全文、各項目の採用と不採用の影響、起票者の推奨と根拠を示す。回答者が個別に判断する必要のない項目は共通する判断基準で群にまとめ、群単位の一括回答を許容する。

事後承認型UWIは、実施済みの対応、当該対応を選んだ根拠及び当該対応を取り消す手段を`## 判断材料`へ含める。
問いは`--question-type=choice`の2択とし、選択肢を`その対応で問題無い`と`問題がある`とする。
`問題がある`の説明には、望む是正内容を回答欄へ書くよう求める文を置く。
