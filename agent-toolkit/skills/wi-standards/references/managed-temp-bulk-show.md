# 一括取得の管理対象一時領域

同一対象リポジトリの複数ファイル名を同一工程で取得する場合は、実行ツールの戻り値の切り詰めを避けるため、次のライフサイクルを対象リポジトリごとに1回実施する。

1. SessionStartが管理対象一時領域を通知している場合、取得主体が`atk managed-temp create --prefix wi-show --session-root <通知された絶対パス>`を実行する。通知が無い場合は`atk managed-temp create --prefix wi-show`を実行する。終了コード0、標準出力が単一の絶対パス、かつそのパスが実在するディレクトリである場合だけ成功とする。作成した領域と保存内容は作成主体が単独で所有し、パスと内容は自身の工程の中だけで扱う。
2. 作成時に得た絶対パスの`wi-show.stdout`へ、`atk wi show <filename>... --skip-pull`の標準出力を保存する。完全性は保存したファイルの内容で判定し、実行ツールの戻り値は補助の情報として扱う。
3. 終了コード0で全項目が出力された場合だけ保存ファイルを本文として採用する。出力順序と本文境界は`atk wi show`のCLI契約とする。
4. 採用後は本文照合へ進む。非0終了の場合は、部分出力を本文として採用しないことを確定する。独立登録した領域では、作成時の標準出力と同一で実在する絶対パスを検収して`atk managed-temp cleanup --path <検収済み絶対パス>`を実行する。セッションrootの子領域はセッション終了時の回収へ委ね、個別のcleanupを省く。
5. 独立登録した領域ではcleanupの終了コード0を確認してから、非0終了では取得主体の工程が定める終了コード別の経路（停止か要求した全項目の単数再取得）へ進む。セッションrootの子領域と採用時は本文の後続照合へ進む。
6. 保存不能と判定する条件は次の3つだけとする。いずれかに該当する場合は、独立登録した回収対象があればcleanup成功を確認してから分割取得へ代替する。
   - 標準出力のファイル保存機能又は絶対パスの読取機能が無い。
   - `managed-temp create`が非0終了してパスを作成できない。
   - 保存・再読込が失敗した。
7. 独立登録した領域の作成後にcleanupが非0終了した場合は、絶対パスとエラーを起動主体へ返して停止する。この場合の分割取得、新しい一時領域の作成及び後続工程は、起動主体の判断を得てから行う。

対象リポジトリ又は取得条件が異なる場合は集合を分ける。単一項目、警告・エラー後のその項目だけの再取得及びUWI回答確認では、単数形の取得をそのまま使う。
