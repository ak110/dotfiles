## 要求固有性と記載量

複数repoへの投入で共有する本文は`cross-repository-submission.md`「独立したAWIへの分割と依存」に従う。
原因分析表や逐語引用も、代表AWIの明示参照によって満たせる。
各AWIの冒頭は、それだけで目的と変更が分かるようにする。

1つの事実は1箇所にのみ記載し、他の節からは節名や項目名で参照する。
同じ識別子を説明ごとに繰り返し記載することは避ける。
ただし、`## 原因分析`における表や行の構造は維持する。

本文には、元の要求そのものか、その要求に固有の採否判断、実装、完成判定に直接必要な記述のみを残す。
通常のバージョン更新や生成物の同期、一般原則を変更しない旨の宣言、汎用的な検証やCIの手順、通常の記録更新、投入前に行った調査の途中経過などは記載から除く。
一方で、必要な境界条件、根本原因、検討した代替案、外部から観測可能な結果、および否定形の完成条件は残す。
説明文の追記を反映内容や完成条件へ含める前には、`agent-basics:writing-standards/references/writing-common.md`「文章の共通規定」にある「情報を追加する前の判断」を適用する。
H2見出し以降の記述の詳しさは、`agent-basics:writing-standards/references/writing-readers.md`「読み手別の追加注意点」におけるエージェント向け文書の規定に従う。
なお、タイトルとH1直下の記述はユーザーを読者とするため、エージェント向けの規定ではなく`SKILL.md`冒頭の用語基準に従う。
要求に固有の事実や契約、ユーザーが指定した手段、硬い制約は具体的に記載し、一般的な実装手順や検証方法の解説は省く。
本文は、実装担当者が登録時に確認した対象、判断と根拠を再調査せずに着手できる粒度で記述する。
これが本書の各規定が担保すべき価値である。
調査の結果、正常な対象と変更が必要な対象が混在している場合は、冒頭の1文で両者とAWIが変更する範囲を対照して示し、`欠陥`、`不足`、`未追随`といった評価語には必ず具体的な対象名を添える。
素材から確認できた確定事実と起草者の推測を明確に区別し、確定要件には事実のみを記載する。
対象を調査手順によって表現する場合であっても、指示する対象集合を本文から一意に判定できるように記述する。
エージェント由来の通常AWIには、影響範囲や改修規模の見込みを1〜2行で任意に記載できる。
既存の規範の適用範囲に言及する場合は、条文を含む文書のパスと節名を参照し、本文中への再掲を控える（努力目標）。
参照のみでは完成条件を一意に特定できず再掲する場合は、その理由を明記する。
条文自体の変更を求める項目において変更前後の文面を引用することは、ここでの再掲には当たらない。

## 節の構成と分担

複数バグの現象・期待する契約と原因分析の対応は、`analysis-records.md`「原因分析の記録先」に従う。
H1直下の要約と各バグの具体情報の記録先を分け、計画担当が各バグの期待する契約まで再取得できるようにする。

H1のタイトルは目的と変更が一目で短く分かる表現とし、発生原因の仕組みや具体的な対応手段は本文中に記載する。
タイトルの用語は`SKILL.md`冒頭の基準に従う（例: 「チャット会話作成時に特定条件でデッドロックが発生する不具合の修正」）。
各内容は次の表に示す節へ配置し、他の節からは節名で参照する。
既存の目的と反映内容の記述で、プロジェクトの目的に対する依頼の役割と今回達成する結果を後続担当へ渡す。
推定した目的と明示要件を区別し、必要な関連変更も指定された限定と認可の内側で選ぶ。

| 節 | 記載する内容 | 記載しない内容 |
| --- | --- | --- |
| H1直下 | 目的、変更の要点、変更後の結果を人間が理解しやすい語彙と順序で短く記述する。語彙は`SKILL.md`冒頭の基準に従う | 調査記録、具体的な反映内容や根拠の詳細（各H2節へ記載する）、説明のない内部呼称 |
| `## 反映内容と反映先` | 変更内容、対象、適用条件、除外、対象別の採否。要求とエージェントの判断を区別する | 成立根拠や発生原因の重複 |
| `## 原因分析` | 観測された不具合を起点としbugfixを起動して起草し、直接的原因を確定した場合、所定の分析表、原因の成立条件、類似見直しの結論と必要な根拠 | 変更内容の重複 |
| `## 調査結果と判断根拠` | 他の項目と重複しない登録時の重要な事実、採否理由、制約、再取得可能な根拠。版や環境が結論を左右する場合は併記する | 調査の途中経過、一時ファイルだけへのリンク |
| `## 完成条件` | 目的、変更内容、原因分析から一意に導けない観測結果、境界、今回固有の検収条件 | 変更内容の言い換えや一般的な検証手順 |
| `## ユーザー指摘の逐語引用` | ユーザーの原文と必要な回答済み注記 | エージェントの質問・説明・判断との混同 |
