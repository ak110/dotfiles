# 対象リポジトリとprivate-notesの区別

作業対象のリポジトリと、AWI、UWI、計画ファイルを保管するprivate-notesリポジトリ（`atk config get private_notes`が返すリポジトリ）は、明確に区別して扱う。報告においてリポジトリのパスや状態を記載する際は、どちらのリポジトリを指しているかを必ず明記する。

- 変更対象の特定、差分の確認、コミット、変更の退避や巻き戻しなどの作業は、依頼が指定した対象リポジトリの作業ツリーで行う
- エージェントによるprivate-notesへの変更は、`atk wi`、`atk plans`、`atk serve`を通じて行う。`atk`がGit履歴の分岐やrebaseの失敗を報告し、再実行しても解消しない場合に限り、その出力に示された回復手順の範囲内で`git`コマンドを直接実行してよい。その際は、実行前後の状態と実施した操作を報告に含める。なお、private-notesは常駐プロセスの`atk wi process-loop`や`atk serve`、および別セッションによって並行して更新されるため、回復手順の範囲内であっても`atk worktree-stash`、`git stash`、または未コミット差分の破棄しない
- AWIおよびUWIの投入は、`atk config get private_notes`が返す作業ツリーへ直接行い、専用の別作業ツリーを作成しない。別の作業ツリーで作成されたローカルコミットは、ユーザーや後続のセッションへ反映されないためである
- private-notes内の未コミット差分（年月ごとの固定ディレクトリに配置されたWIや計画ファイルを含む）は、`atk wi commit`を実行して確定させる。作業ツリーがクリーンでないことを理由にコマンドが失敗した場合でも、変更を退避させてはならず、同コマンドでコミットを確定させるか、その差分を保持している別プロセスの終了を待機する
- 委譲先へ伝達する「push不可」という制約は、対象リポジトリに対する`git push`を禁止するものであり、`atk`がprivate-notesに対して内部的に行うコミットやプッシュは対象外とする
- ユーザーが外部のエディターを用いてキュー内のファイルを直接編集することは制限されない。その際生じた未コミットの変更は、`atk wi commit`を実行して確定させる
