# 複数リポジトリへの投入

本書は複数リポジトリへ投入するAWI、同じ成果の整合を要求する複数のAWI、上流リポジトリの改訂を要する要求と、別リポジトリへ移す元項目の扱いを定める。

## 独立したAWIへの分割と依存

- 各リポジトリの現行状態を確かめ、それぞれが自身の対象だけで完結するAWIへ分ける。各本文に規則の内容、反映先、完成条件を持たせ、投入元固有の後続本文も直接書く。現行成果物だけで実施と完成判定ができる組には、整合や投入順だけを理由に`depends_on`を付けない
- 後続AWIに先行成果が必要な場合は、待つ成果と成立しない工程か完成条件を後続本文へ書き、先行AWIを登録して得たファイル名を後続の`depends_on`へ指定する。依存は後続から先行への一方向とし、先行AWIの完成条件に後続の着手・完了を含めない
- 複数のリポジトリで不可分であり単一計画・単一検証でしか成立しない変更だけを1つの計画へ集約する

## 上流リポジトリへの投入と元項目

- 対象リポジトリで実装できず上流の改訂を要する要求は移管せず、上流へ新規AWIとして投入して元項目を残す。投入する本文には要求内容、対象リポジトリの識別子、上流の改訂後に対象リポジトリで行う作業（無ければ上流成果の確認だけが残る旨）を書く
- 投入後は元項目の依存を投入先のファイル名で更新し（保持する既存依存も同じ実行で指定する）、`processing`なら`inbox`へ戻して、`blocked_reason=dependency-unmet-external`となることを確かめる
- 先行・上流項目が未終端でも、元項目を保留する前にその`完成条件`を対象リポジトリの現行HEADと成果物で確かめ、確かめた条件、HEADの7文字以上の短縮OID、判定結果を記録する。充足していれば状態によらず依存を解除し、`--commit`を省いて終端する（`states-and-dependencies.md`「状態遷移」）。確かめられなければ実装済みと推定せず、依存先、未達の条件、再開条件を明記して保留する
- 上流項目の終端後は、対象リポジトリ側の残作業を実施するか上流成果を確認して元項目を終端する

## 元項目の移管

- 元項目そのものを別リポジトリへ移す場合は、frontmatterと本文を含む全体を正しい`target_repo`へ`agent-toolkit:wi-standards`で登録する。置き換えるのは予約キー`target_repo`だけとし、`alert_keys`などの非予約キーと`source`は保持する（通常の`atk wi add`はfrontmatterの`target_repo`をCLI値で置き換えない）
- 登録に成功した後だけ、移管先リポジトリとファイル名を除去の理由として記録して元項目を除去する
