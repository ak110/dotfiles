# 複数リポジトリへの投入

本書は、複数のリポジトリへ投入するAWI、同一成果の整合性を求める複数のAWI、上流リポジトリの改訂が必要な要求、および別リポジトリへ移管する元項目の取り扱いを定める。

## 独立したAWIへの分割と依存

- 各リポジトリの現行状態を確認し、それぞれが自身の管理対象のみで完結する個別のAWIへと分割する。それぞれの本文に規則の内容、反映先、完成条件を記載し、投入元に固有の後続本文も直接記述する。現行の成果物のみで実施および完成判定が可能な組み合わせについては、整合性の維持や投入順序のみを理由とした`depends_on`の設定は見送る。
- 後続のAWIの実施に先行成果が必要な場合は、待機すべき先行成果、および先行成果がないと成立しない工程や完成条件を後続の本文へ記載する。そのうえで、先行AWIを登録して得られたファイル名を後続の`depends_on`に指定する。依存関係は後続から先行への一方向のみとし、先行AWIの完成条件から後続の着手や完了を除外する。
- 複数のリポジトリにまたがり不可分であって、単一の計画と単一の検証によってのみ成立する変更に限り、1つの計画へ集約する。

## 上流リポジトリへの投入と元項目

- 対象リポジトリ単独では実装できず上流リポジトリの改訂が必要となる要求は、元項目を移管するのではなく、上流リポジトリへ新規AWIとして投入したうえで元項目を保持する。投入する本文には、要求内容、対象リポジトリの識別子、および上流の改訂後に対象リポジトリ側で実施する作業内容（作業がない場合は、上流成果の確認のみが残る旨）を記載する。
- 上流への投入完了後は、元項目の依存関係を新たに投入したAWIのファイル名で更新する（維持すべき既存の依存関係も同一の実行で指定する）。元項目の状態が`processing`であれば`inbox`へ戻し、`blocked_reason=dependency-unmet-external`が設定されることを確認する。
- 先行項目や上流項目が未終端の状態であっても、元項目を保留する前にその`完成条件`が満たされているかを、対象リポジトリの現行HEADと成果物から確認する。確認した条件、HEADの7文字以上の短縮OID、判定結果を記録に残す。条件を充足していれば、現在の状態にかかわらず依存関係を解除し、`--commit`を省略して終端処理を行う（`states-and-dependencies.md`「状態遷移」）。条件の充足を確認できなければ、実装済みと推定することなく、依存先、未達の条件、および再開条件を明記したうえで保留する。
- 上流項目の終端後は、対象リポジトリ側の残作業を実施するか、または上流の成果を確認して元項目を終端する。

## 元項目の移管

- 元項目そのものを別リポジトリへ移管する場合は、frontmatterと本文を含む全体を、正しい`target_repo`を指定して`agent-toolkit:wi-standards`の手順で登録する。更新するキーは予約キーである`target_repo`のみとし、`alert_keys`などの非予約キーおよび`source`の値はそのまま保持する（通常の`atk wi add`はfrontmatter内の`target_repo`をCLI引数の値で自動置換しない仕様である）。
- 登録処理が成功したことを確認した後に限り、移管先のリポジトリ名とファイル名を除去理由として記録したうえで、元の項目を除去する。
