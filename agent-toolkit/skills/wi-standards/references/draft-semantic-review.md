# WI原稿の意味の確認

付随型の委譲元、専念型の投入前レビュー担当と直接起草するメインは、原稿・原要求と実回答の出所・現物・取得済み証拠を独立に比べる。採否・成立性・完成判定の定義元は`drafting-completion.md`であり、wi-standardsの読込表の調査前・原稿確定前に指定した共通基準を適用する。取得済み証拠を再利用し、確認側が起草の取得・保存工程を再構成する前提は置かない。原要求が現在の回答・案の確定を求める場合は`agent-toolkit:user-confirmation-and-report`「成果物の制限」に照らして、その場の回答と後続の完成条件を区別する。

## ユーザーが読む部分

検収の最初に、AWIでは原稿のタイトル行から最初のH2直前までを、末尾の空行も含めて改変せずに写してmanaged-tempへ保存する。wi-draft-prepareの`ユーザー向け部分`と`比較資料`があれば、その生成済み抽出を使う。原稿全体の検収時に現行本文と抽出の一致を確かめ、変更があれば同じ機械抽出で更新する。UWIでは冒頭の問い・理由・推奨する回答を原稿から改変せずに抽出する。要約や言い換えは抽出に使わない。要求識別子・原稿・抽出・比較資料の対応を保持する。
付随型の委譲元と専念型の投入前レビュー担当は、原稿全体を読む前に抽出部分だけで次の2基準を自ら判定する。直接起草するメインの自己判定も同じ基準を使う。

- AWIでは`awi-body.md`「節の構成と分担」のH1直下の内容（欠陥起点の有無に対応する区分）、UWIでは`uwi-format.md`「構成」の内容を、その部分だけからユーザーの語で言い直せる。
- wi-standards冒頭の方法で全名詞句を列挙し、列挙した句を受領した逐語本文の各句と比べて全句を含むことを確かめ、4種か説明の無い内部の呼び名へ分類する。説明の無い内部の呼び名を全件指摘する。

読者別探索担当を起動するのは、同じ要求か同じ項目について、ユーザーが読む部分の分かりにくさをユーザーが是正している場合（逐語本文、UWIの`## 回答`、AWIの`## ユーザーコメント`）、または検収者が基準に照らして合否を判定できない名詞句を挙げた場合だけとする。
起動は`share/reader-fit-review.parent.md`に従い、種別はWIのユーザー向けの部分、読者像はwi-standards冒頭の語の基準が前提とする知識を持つユーザーとする。AWIの欠陥起点の有無も渡す。
同じ読者像で同時に確認できる抽出は、要求との対応を保って既存の`成果物`配列と1対1の`比較資料`配列へまとめる。新規は各要素を`{"比較元本文":"新規","今回差分":"全文","現行本文":"<抽出パス>"}`とする。素材は抽出とその比較資料に限り、原稿全体の要求被覆・由来・採用案・反映先・成立性は意味の検収主体が所有する。
返却の名詞句の一覧と各抽出の全名詞句を比べて全句を含むかを確かめ、欠けた句は検収者が分類して指摘へ加える。集合起動の識別子と各抽出の判定・指摘・証拠を要求ごとに対応付ける。基準を満たさない原稿だけを修正要として作成主体へ返す。再発防止策もユーザーの語で言い直せるかを判定する。委譲元が修正例を示す場合も本文の処置の層を保ち、本文が再発防止策を採用しない原稿では冒頭にもその結論を書く。
再判定は変更した抽出とその直接影響を対象にし、本文と契約境界が同一の抽出は親契約の既存の再点検省略条件で再利用する。資料不足・失敗は要求と読者ごとに記録し、親契約の補完・回復・終端観測で回収する。

## 原稿全体と返却の検収

原稿全体へ`drafting-completion.md`の「採否と実現方式の確定」「実現方式の成立」「対象集合の仕分け」「未確定事項と確認」「確定の判定」「投入前の読み直し」「方針と判断の記録との比較」を適用する。新しい通常AWIには「重複判定」、欠陥起点には「原因と定義の所有者」と同資料が参照するbugfixの基準も適用する。原文・実回答・現物と取得済み証拠で、要件分類、処置の比例性と必要性、一連の処理全体、原因と被覆、既存判断、未確認範囲を独立に判定する。原稿が課す操作制約は原文が指定した工程に対応しているかも確かめる。

- 渡した要求集合と返却の要求識別子が重複なく一致する。複数原稿にも各要求を独立に適用する。
- 付随型の`起草結果`の状態・結果・続行できない理由・省略値は`share/add-wi.subagent.md`「起草の返却」と一致する。専念型の結果は`share/wi-draft-review.subagent.md`「出力」と一致する。
- 原稿と証拠の絶対パスが実在して読め、AWIは`awi-body.md`、UWIは`uwi-format.md`を満たす。`他AWIへ割当`は受領した割当先の値だけである。
- 既存項目の再利用・部分被覆は既存本文と共通基準の「重複判定」で独立に裏付ける。再利用には保存開始を送らず既存項目を投入結果とする。
- `判断の変更`は確定要件の対象・範囲・外部可視の結果と両立し、付加する手段・条件は共通基準の必要性を満たす。
- `condition_not_met`は投入不要の結論と根拠を示す。人間由来要求の不投入は`origin-and-approval.md`「承認」で確定してから後続の保存集合から外す。
- 先行項目の正式名が未確定でも、要求・証拠から参照先と箇所が一意なら意味を検収できる。正式名への置換と保存後の一致確認は作成主体の`drafting-workflow.md`「投入」で行う。

委譲元と専念型の投入前レビュー担当は、原稿と成立性の証拠を読み、`再発防止策`行が挙げた問題が対策の範囲の外にあることを確かめ、`agent-basics:bugfix`の`references/root-cause-analysis.md`「処置の階層」の持ち込みの試験をする。成立しない原稿は処置を`対策`へ書き直すか再発防止策を選び直すよう作成主体へ戻す。

## 初回と再判定・差戻し

初回は入力時点で判断できる成立性とユーザーが読む部分の語の論点をまとめて返す。不足の指摘には採用案の成立か要求達成を左右する理由を対応付ける。共通基準が投入前に確定する公開契約、必要な値への到達、開始・終了・途中失敗からの再開を独立に確かめる。成立性を変えない内部設計・実装単位・検証手順の具体化は計画工程へ渡す。
再判定では前回指摘の解消、修正差分と直接影響、要求追加を分け、新しい指摘を初回から残った不足・修正由来の不成立・要求追加へ分類する。全文は整合の文脈として読み、修正の外で新しい内部設計を求めることは範囲外とする。前回になかった重大な不成立は根拠を添えて返す。
不合格と、確認手段のある未確認範囲は作成主体へ戻すか検収主体が確かめて渡す。自己取得できない資料やユーザーだけの値はその値を必要とする要求に限って続行できない理由とし、解除に必要な入力を示す。一部要求の修正待ち・資料不足・読者確認の失敗で、他の合格済み要求の保存を止めない。
