# 通常AWIの本文：継続的な方針の保存と既存箇所の見直し

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 実作業の経験から保存する候補を選ぶ前 | `agent-basics:writing-standards/references/investigation-experience.md` |
| 変更後の設計品質を確かめる前 | `agent-basics:writing-standards/references/design-heuristics-quality.md` |
| エージェント向け文書を新設・改訂する要求を書く前 | `agent-basics:writing-standards/references/agent-documents-additions-volume.md` |
| 同じ原因を持つ類似箇所を見直す前 | `agent-basics:bugfix/references/spread.md` |

## 継続的な方針の保存

将来の方針、選定基準、却下理由、制約、前提などは、判断時に読む場所へ保存する（恒久化）。
WIや計画の中に書くだけでは保存にならない。
この判断は、計画ファイルの有無によらず、要求を起草する時と処理する時に行う。

- 候補は、WI本文・ユーザーコメント、確認回答、ユーザー指摘の逐語引用に渡された発話から抽出し、表現の範囲・確度を保って一時の指示と一般の方針を分ける。
  実作業の結果から再利用価値のある成功手順や教訓も候補にし、採否は次に利用する場面と原記録から判断する
- 局所の実装と一般の方針の保存は別に判定し、局所修正だけで保存済みとは扱わない
- 反映先は、その知見を要する判断の際にエージェントがその文書を実際に読むかで選ぶ。
  自動チェックツールへ反映する場合は、チェック失敗時にエージェントが見る位置に制約の理由を併記する
- 保存する変更は`## 反映内容と反映先`の項目として、知見、出所、反映先のファイルと節を書く。
  反映先で適用する仕様や置換の境界も同じ項目に書く
- 既存の規範で充足する候補は該当箇所を、保存しない候補はその理由を`## 調査結果と判断根拠`に書く
- バグ対応では、`## 原因分析`の`再発防止:`の行と`## 反映内容と反映先`の項目を対応付ける

## 既存箇所の見直し

今回の変更で必要になる既存箇所の見直しは、付帯作業として実装と同時に行い、成果物全体の設計品質を保つ。

- 検討対象は、変更・新設する成果物の変更後のファイル全体、参照・呼び出し・読込表で結び付く関連成果物（定義、呼び出し元、既存テスト、生成・配布手順など）、新設・分割する構造、継続的な方針の反映先とする
- 観点と判定基準は`agent-basics:writing-standards/references/design-heuristics-quality.md`「設計品質の劣化確認」に従う。
  設計の劣化を是正する箇所や、併せて整理すれば類似処理・責務・記述の分散を解消できる箇所は、対象、現状の問題、対応を`## 反映内容と反映先`の項目として書く。
  確認の結論は`## 調査結果と判断根拠`に書く
- WIを入力とする計画でも、WI本文の調査結果と判断根拠に設計品質の評価がなければ、WIで確定した実現方式を同じ基準で評価する
- エージェント向け文書を新設・改訂する要求では、`agent-basics:writing-standards/references/agent-documents-additions-volume.md`「文書記述量の管理」を確認する。
  同じ文書への変更全体について責務の範囲、読込の時点、既存記述との重複などを比べ、整理の結論を書く。
  行数は要求で扱わず、上限の判定はプロジェクトの機械チェックに任せる
- テストの更新、直接影響範囲の同期、生成物の再生成など実装に付随する作業は、独立した項目にせず対象の項目へ含める
- 同じ原因を持つ類似箇所の見直しは`agent-basics:bugfix/references/spread.md`「同じ仕組みの他の箇所」に従う
- 変更範囲の外にあり是正の必要も今回生じない既存の不備を見つけた場合は、`agent-basics:bugfix`を起動して対処する
