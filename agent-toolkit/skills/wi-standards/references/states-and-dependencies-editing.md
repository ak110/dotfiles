# 状態と依存：保留と本文修正

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## 保留と本文修正

1. エージェントは、`inbox`および`hold`の状態にある項目を`atk wi rm`で削除できる。
   ユーザーはブラウザーUIを使うことで、終了済みの項目も含めて削除できる。
   本文の編集自体は、`inbox`、`processing`、`hold`のいずれの状態でも実行可能である。
   本文の修正が必要であると判断した時点、または対象と根拠が明確な懸念が寄せられた時点では、採否の確定や詳細な調査を待たずに、直ちに`atk wi hold <ファイル名>`を実行して項目を保留にする。
   保留にしないまま時間を置くと、別の処理主体が古い要求内容をもとに作業を始めてしまう可能性があるためである。
   保留の期間は、調査、認識合わせ、修正案の起草から、保存した本文の一致確認を終えて`atk wi unhold`を実行するまでの全工程に及ぶ。
   誤って投入したことが確認できた項目は、`atk wi rm`で削除する。
   エージェントが編集のために保留した項目は、修正、保存した本文の検収、`atk wi unhold`を、独立した他の作業より先に進め、保留の時間を最小限にする。
   修正の採否や内容を決めるために必要な他項目の調査は先に行ってよく、その修正に関係しない全件調査や別の要求の作業は解除の後に行う。
   修正にユーザーの判断や外部の入力が必要な間は、保留と再開の条件を保ったまま、回答に依存しない作業へ進む。
   対象項目がすでに`processing`になっている場合は、保留や本文の置き換えは行わず、後述する「処理中の項目の扱い」に従う。
   対象の状態を確認した後に別の処理主体が`processing`へ遷移させてしまい、`atk wi hold`が失敗した場合も同様に対処する。
   すでに`hold`になっている項目は、保留状態を維持したまま修正と検収を進める。

2. 処理中の項目の扱い: エージェント環境から実行する`atk wi edit`は、`processing`状態にある項目の本文全体を置き換える操作を受け付けない。
   現在処理が進んでいる要求内容を途中で書き換えてしまうと、実行中のセッションで処理される内容が意図せず変化してしまうためである。
   エージェントが内容を変更したい場合は、変更後の要求を新しい項目として改めて投入し、既存の処理中項目に対しては`--append`による追記のみを行う。
   エージェント環境からの公開追記は`## 処理結果`の後ろに追記され、元の要求内容と分離して保存される。
   なお、ユーザー自身による操作はこの制限の対象外である。
