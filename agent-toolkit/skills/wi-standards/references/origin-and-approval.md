# 由来と承認

本書は`agent-toolkit:wi-standards`「由来と承認」の本文であり、WIの要求単位の由来、`source`の値、明示由来、承認として扱う記述、範囲語と程度・裁量の線の位置、ユーザー専用の記入欄および逐語転記を定める。

構造化確認を由来に使う場合、逐語一致の対象は`session-review-evidence --user-events`が出力する`text`と`user_response`の回答・自由記述だけとする。質問と選択肢を持つ`assistant_context`は意味、対象、除外および認可の解釈にだけ使い、JSONL一行全体の部分一致は証拠から除外する。

`source`は本文全体の初期値としての由来を示す。`source`の欠落だけを初期値で人間由来とし、値を持つ項目は全て明示由来が無い限りエージェント由来とする。保存済みの値をそのまま保持し、過去の項目は保存時の形式で扱う。

エージェントが投入する項目は`source`を必須とする。スキルを起動して投入する場合は、そのスキル名からプラグイン名の修飾を除いた値（`add-awi-by-user`、`process-wi`、`session-review`など）を用いる。対応するスキルを持たない起票は`agent`を用いる。`atk run-skill`が起動したセッション（最初の入力の`atk-auto`要素の`source`が`run-skill`）が投入するUWI（事前承認型、事後承認型、報告用UWI）は`source`を`run-skill`とし、`--scope`へ目的文が示すスキル名をそのまま渡す。次回の同じスキルの実行が過去の実行のUWIを識別するためである。同じセッションが投入するAWIの`source`には前段の規則を適用する。ユーザーの指示に基づいてエージェントが投入する項目にも同じ規則で値を付け、人間由来として扱う範囲は次の明示由来で示す。

要求単位に記録された次の明示由来は、個別の指定がない場合に本文全体へ適用する由来より優先する。

- 末尾の厳密なH2 `## ユーザーコメント`配下の要求
- UWIの`## 回答`に記録された要求
- 関連計画の実施内容に記録された由来
- 出所と引用範囲を保持した対話回答

明示由来の有無は種類ごとに本文を確認して判定する。同見出しは末尾の厳密なH2として定義されたユーザー専用の記入欄であり、出所と引用範囲を保持した対話回答はこれとは別の明示由来として、別の見出しの下に置かれることがある。

`出所と引用範囲を保持した対話回答`はその回答の逐語引用が本書末尾の逐語転記が定める記法で本文へ存在する場合だけ成立する。明示由来の根拠は逐語引用とし、ユーザーの発言を要約した記述と言い換えた記述は根拠から外す。確認回答の記録を明示由来や承認の根拠に使う場合、ユーザーの回答として扱うのは選ばれた選択肢と自由記述だけとする。`atk run-script session-review-evidence`の現行の出力では`text`と`user_response`（`answers`と`notes`）がこれに当たり、質問と選択肢は`assistant_context`（`question`と`options`）が持つ。WI本文などに保存済みの、`質問:`・`選択肢:`・`回答:`・`自由記述:`の行頭ラベルを持つ記録では、`回答:`と`自由記述:`の値がこれに当たる。質問本文、質問本文の中の`共通前提:`行、選択肢の説明はエージェントが書いた文とし、ユーザーから異論が返らなかったことは合意の根拠から外す。選ばれた選択肢が確定するのはその質問が問うた判断であり、案の意味は質問と選択肢の文面から読む。`共通前提:`行がユーザーと以前に合意した前提を書いている場合は、その前提を合意した発話か確認回答の逐語引用を根拠にする。
逐語引用から直接導けない具体的な対象、範囲または外部可視の結果をエージェントが補った場合、その補足は引用の外へ置き、エージェント由来として扱う。関連計画は人間由来の要求とエージェントが具体化した要求を実施内容の由来欄で分けて記録する。
対話回答の出所は、出所と引用範囲を記した本文の逐語引用から判定する。引用に示された発話元と、WIを作成したセッションおよび実行環境は別の事実として扱う。後二者は作成処理の記録など、その事実に直接対応する根拠から判定する。
由来を分離できない要求は人間由来として扱う。要求単位の一部でも人間由来なら、全部か一部を不採用にする前に、原文との差異、技術的理由と代替案を示してユーザーの明示承認を得る。承認として扱えるのは明示承認だけとし、事後承認、変更の可逆性、採用済み範囲の有無は承認の判定材料から外す。未承認の人間由来要求を終端すると、ユーザーが依頼した未完了範囲が処理対象から消失する。
ユーザーがAWIの`## ユーザーコメント`とUWIの`## 回答`のいずれかへ処理側に宛てた質問を直接記入した場合は、回答をUWIへ記録してユーザーへ返す。AWI本文に逐語引用や対話回答として転記された質問は、`source`の値を問わず投入セッションで解決済みとして扱い、処理側がUWIへ回答を記録する対象から外す。UWIへの回答保存を、処理側が対象の維持または変更を確定してWIを終端する条件とする。質問への回答は、自律モードでユーザーへ届ける回答をUWIへ記録する一般則の一部として扱う。

要求の一部を別作業へ渡すことを理由に元のWIから除く場合は、受渡し先のWIが実在し、除く要求単位をその本文が過不足なく含むことを確認する。受渡し先が無い場合は元のWIへ要求を戻すか、新しいWIの本文と投入を先に確定する。参照だけの予定を受渡し完了として扱うと、要求がどちらの作業にも残らない。

ユーザーが範囲語または開放列挙で示した集合をエージェントが狭める場合は、`agent-toolkit:user-confirmation-and-report`の`references/judgment.md`「原文からの具体化を要する軸」が定める事前の明示承認を要する。

程度または裁量が元の表現に含まれる要求でどこに線を引くかも、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」で決める。次の表現がこれに当たる。

```text
消せるだけ消して
できる範囲で
```

確認するのは、調べた後も線の位置によって要件・意図の曖昧さ（`agent-toolkit:user-confirmation-and-report`「確認要否の判定」3）が残る場合か、ユーザーだけが持つ値（許容する費用や手放してよい保護・検出力などの選好）が残る場合である。確認本文には線の位置ごとに変わる外部可視の結果と推奨を書く。案の効果とリスクや費用の比較が走査した対象の観測根拠（件数、実際に得た値、既存の文面の集計など）とQCDで決まる場合はこの値に当たらないため、確認せずにエージェントが線を引き、その根拠と残した対象を完了報告へ書く。
許容する待機時間・再試行回数、別モデルなど代替手段へ移る時点と移行を許すかも、ユーザーだけが持つ値の例であり、待機と切替の選好はユーザーの回答から取得する。
具体値や切替方針に回答がある場合は、その回答の対象と範囲へ適用する。

この区別を欠くと、裁量の境界まで確認へ送る過剰な確認と、開放集合を閉じた縮小の看過が同時に生じる。
範囲語か開放列挙の集合の未走査部分は、前段の範囲語の段落と程度・裁量の段落の対象外とする。走査が技術的に成立する間は`01-agent.md`「完遂と先送り」に従って走査を続け、後続の工程や事後の申し出へ回さずに完遂する。
回答を得られない場合の保留と終端は`SKILL.md`「状態と依存」の事前承認型UWIと`rejected`の規定に従う。

人間由来のWI本文、ユーザーコメント、UWI回答、対話回答のいずれかに、外部操作、対象および範囲が明記されていれば、その範囲の承認として扱う。WIの本文と記入欄から承認として扱うのはこの明記がある場合に限り、`source`値だけの場合、空のコメント欄、エージェントの推奨、一般的な「進めて」は承認の判定材料から外す。手動起動した`agent-toolkit:process-wi`が保持する終端工程の承認スコープは、手順を承認源とする別の承認であり、`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.parent.md`「終端工程の承認スコープ」が定める。読み書きする主体はユーザーとエージェントだけとする。署名、認証、監査用の仕組みは追加しない。

UWIの`## 回答`節とAWIの`## ユーザーコメント`節はユーザーだけが書き込む欄とし、エージェント環境から起動した`atk`はこれらの節を含む本文の投入と編集を拒否する。
`atk wi edit`が本文を`--body-file`で受け取る場合は、`## ユーザーコメント`節を編集の対象から外し、保存済みの内容をそのまま残す。
エージェント由来のAWIの`## ユーザーコメント`またはUWIの`## 回答`が、その項目の前提、対象、方針または採否を否定する場合は、ユーザーの是正要求として扱う。
その記述を受け取った主体は、対象が未終端の場合、比較確認より先に`SKILL.md`「状態と依存」の保留の手順で対象を自動処理から外す。続けて`agent-toolkit:review-standards`を起動し、`references/reviewee.md`の`ユーザー指摘の受領`に従って比較確認と採否を確定する。
続けて受領した主体が`agent-toolkit:bugfix`を起動し、`references/response.md`に従って原因分析の要否を判定し、類似見直しと再発防止策の確定まで行う。
再発防止策には、同じ原因で投入される他の項目を防ぐ処置を選ぶ。AWI本文の書き換えは、その項目1件への対策として扱う。
エージェント由来の要求への否定をその項目の採否だけで処理すると、同じ原因で投入される他の項目と確認事項を防げない。
エージェント環境から起動した`atk wi edit`は`processing`の項目の本文置換を拒否する。処理中の要求を書き換えると、その要求がそのセッションで処理されるかが変わるためである。エージェントは、書き換えたい内容を新しい項目として投入し、その項目へは`--append`による追記だけを行う。ユーザーの操作はこの拒否の対象外とする。
エージェントがユーザーの要求を起点としてWIを投入する場合は、その要求の採否と実装方針の根拠となったユーザーの発言を、本文中へ出所と引用範囲を示して逐語で転記する。転記する発話に質問が含まれる場合は、投入するセッションでその質問へ回答し、逐語引用の近くに回答を済ませたことを記す。回答がWI投入担当の調査で確定する事実（原因、対象範囲など）に依存する場合は、返却で確定した内容を根拠に回答し、投入前に回答を終えることは求めない。返却前に伝える場合は未観測の記述を推定と明示し、返却後に`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「受領と検収」で比べる。転記する本文は`agent-toolkit:writing-standards`の`references/writing.md`「ユーザー入力素材の取扱い」が定める逐語引用の記法で囲み、原文を改変しない。転記は逐語で行い、要約や言い換えを行ってはならない。本規定は`source`の値によらず、全ての投入方法へ適用する。転記の置き場所は本文中とし、前掲の2つの見出しはユーザーが作成する。転記はエージェントが書いた記述であり、ユーザー自身の記入欄とは別の扱いとする。
