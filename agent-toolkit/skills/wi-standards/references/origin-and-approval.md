# 由来と承認

本書はWIの要求単位の由来、`source`の値、承認として扱う記述、範囲語と程度、ユーザー専用の記入欄と是正要求および逐語転記を定める。

## 由来と`source`

`source`は本文全体の由来の初期値を示す。`source`の欠落だけを人間由来とし、値を持つ項目は明示由来が無い限りエージェント由来とする。保存済みの値と形式はそのまま扱う。

エージェントが投入する項目は`source`を必須とし、起動したスキル名からプラグイン名の修飾を除いた値（`add-awi-by-user`、`process-wi`、`session-review`など）、対応するスキルが無い起票では`agent`を用いる。ユーザーの指示に基づく投入も同じ規則で値を付け、人間由来の範囲は明示由来で示す。
`atk run-skill`が起動したセッション（最初の入力の`atk-auto`要素の`source`が`run-skill`）が投入するUWIは`source`を`run-skill`とし、`--scope`へ目的文が示すスキル名をそのまま渡す。次回の同じスキルの実行が過去のUWIを識別するためである。同じセッションのAWIには前段の規則を適用する。

要求単位に記録された次の明示由来は、本文全体の由来より優先する。種類ごとに本文を確かめて判定する。

- 末尾の厳密なH2 `## ユーザーコメント`配下の要求（ユーザー専用の記入欄）
- UWIの`## 回答`に記録された要求
- 関連計画の実施内容に記録された由来
- 出所と引用範囲を保持した対話回答（別の見出しの下に置かれることがある）

対話回答が明示由来になるのは、その逐語引用が「逐語転記」の記法で本文にある場合だけとし、根拠は要約や言い換えでなく逐語引用とする。逐語引用から直接導けない対象、範囲、外部可視の結果をエージェントが補った場合は、引用の外へ置いてエージェント由来とする。引用の発話元と、WIを作成したセッション・実行環境は別の事実であり、後二者は作成処理の記録などから判定する。

確認回答の記録のうちユーザーの回答として扱うのは、選ばれた選択肢と自由記述だけである。`atk run-script session-review-evidence`の出力では`text`と`user_response`（`answers`と`notes`）がこれに当たり、質問と選択肢を持つ`assistant_context`（`question`と`options`）は意味、対象、除外、認可の解釈にだけ使う。JSONL一行全体の部分一致は証拠から外す。保存済みの`質問:`・`選択肢:`・`回答:`・`自由記述:`の行頭ラベルを持つ記録では、`回答:`と`自由記述:`の値がこれに当たる。
質問本文、`共通前提:`行、選択肢の説明はエージェントが書いた文であり、異論が返らなかったことを合意の根拠にしない。選ばれた選択肢が確定するのはその質問が問うた判断だけである。`共通前提:`行が以前の合意を書いている場合は、その合意の発話か確認回答の逐語引用を根拠にする。

## 承認

由来を分離できない要求は人間由来として扱う。人間由来を一部でも含む要求単位を全部か一部不採用にする前に、原文との差異、技術的理由と代替案を示してユーザーの明示承認を得る。事後承認、変更の可逆性、採用済み範囲の有無は承認の判定材料から外す。未承認のまま終端すると、ユーザーが依頼した範囲が処理対象から消える。

人間由来のWI本文、ユーザーコメント、UWI回答、対話回答に外部操作、対象および範囲が明記されていれば、その範囲の承認として扱う。`source`値だけ、空のコメント欄、エージェントの推奨、一般的な「進めて」は承認にしない。手動起動した`agent-toolkit:process-wi`の終端工程の承認スコープは同スキルのSKILL.md「終端工程の承認スコープ」が定める。署名、認証、監査用の仕組みは設けず、読み書きする主体はユーザーとエージェントだけとする。

要求の一部を別作業へ渡すことを理由に元のWIから除く場合は、受渡し先のWIが実在し、除く要求単位を過不足なく含むことを確かめる。受渡し先が無ければ元のWIへ戻すか、新しいWIを先に確定する。同じ委譲元が同時に渡した分割起票の組と、投入先の外の対象を通知して委譲元へ割当を残した場合は、元のWIを先に保存してよい。受渡し先の実在と処置の対応は、委譲元が`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「保存の検収」で確かめる。

## 範囲語と程度

ユーザーが範囲語か開放列挙で示した集合は、`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「原文の保持と取り込み」の範囲の記録書式で書く。集合を狭める除外は同スキル「原文からの具体化を要する軸」の事前の明示承認を要し、その出所を除外とともに書く。
次のように程度や裁量を含む要求でどこに線を引くか、待機時間・再試行回数、代替手段への切替は、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」で決める。

```text
消せるだけ消して
できる範囲で
```

確認するのは、調べた後も線の位置で要件・意図の曖昧さが残る場合か、許容費用や手放してよい保護などユーザーだけが持つ値が残る場合に限る。走査した対象の観測根拠とQCDで決まる線はエージェントが引き、根拠と残した対象を完了報告へ書く。確認する場合は線の位置ごとの外部可視の結果と推奨を示し、回答はその対象と範囲へ適用する。
範囲語か開放列挙の集合の未走査部分は確認の対象から外す。走査が技術的に成立する間は`agent-toolkit/rules/01-agent.md`「完遂と先送り」に従って完遂する。
回答を得られない場合の保留と終端は`states-and-dependencies.md`「承認型UWIと元項目」と「終端」に従う。

## ユーザー専用の記入欄と是正要求

UWIの`## 回答`とAWIの`## ユーザーコメント`はユーザーだけが書き込む。エージェント環境から起動した`atk`はこれらの節を含む本文の投入と編集を拒否し、`atk wi edit --body-file`では`## ユーザーコメント`を編集対象から外して保存済みの内容を残す。
エージェント由来の項目のユーザーコメントか回答が、その項目の前提、対象、方針または採否を否定する場合は、ユーザーの是正要求として扱う。受け取ったエージェントは、対象が未終端なら先に`states-and-dependencies.md`「保留と本文修正」で保留し、`agent-toolkit:review-standards`の`references/reviewee.md`の`ユーザー指摘の受領`で採否を確定する。続けて`agent-toolkit:bugfix`の`SKILL.md`「問題を見つけたときの対処」に従い、類似見直しと再発防止策の確定まで行う。本文の書き換えはその1件への対策にすぎず、処置の層（対策・横展開処置・再発防止策）は同スキルの`references/root-cause-analysis.md`「処置の階層」で区別する。
ユーザーがこれらの欄へ処理側宛ての質問を書いた場合は、回答をUWIへ記録して返し、その保存を対象の維持・変更を確定してWIを終端する条件とする。
既存WI（状態を問わない）を別の判断の前提・制約・代替案の不採用理由・完成条件などの根拠に用いる場合も、ユーザー専用の記入欄を含めて全文を読み、「由来と`source`」の要求単位の明示由来から有効な要求を確定して使う。エージェント由来の本文とユーザーコメントか回答が衝突する場合は、要求単位の由来と`agent-toolkit/rules/01-agent.md`「方針が衝突する場合の優先順位」で有効な前提を決め、ユーザーが是正した本文の記述を根拠から外す。根拠に用いる判断の主体が、その項目の是正要求の受領者でなくても同じとする。

## 逐語転記

`## ユーザー指摘の逐語引用`へ転記した発話は、そのAWIを投入したセッション（投入元のセッション）へ向けた発話であり、質問か否か、解決の明記、`source`によらず投入元で解決済みとして扱う。処理側（実行レビュー担当、`atk run-script exec-review-evidence-check`、統合時の完成条件判定）は逐語引用を達成や回答の対象にせず、`## 反映内容と反映先`と`## 完成条件`を解釈する根拠として読む。処理側が達成を確かめるユーザーの発話は、処理側宛ての`## ユーザーコメント`、回答済みUWIの`## 回答`、計画の`ユーザー指示`行、完成条件節の無い人間由来のAWI本文である。

ユーザーの要求を起点にWIを投入する場合は、採否と実装方針の根拠となった発言を、出所と引用範囲を示して逐語で本文へ転記する。記法は`agent-toolkit:writing-standards`の`references/writing.md`「ユーザー入力素材の取扱い」に従い、原文を改変せずに写す。保存済みの発話記録を出所とする転記は、`drafting-completion.md`「投入前の読み直し」の逐語引用の項にある取り込み操作で行う。`source`と投入方法によらず適用する。転記はエージェントが書く記述であり、ユーザー専用の2つの記入欄とは別に扱う。
転記する発話に質問が含まれる場合は投入元が回答し、送達済みの質問だけ引用の近くに回答済みと記す。回答内容が確定しただけでは送達完了と扱わない。WI投入担当の調査結果を要する回答の時機と返却後の訂正は`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「受領後の報告」に従う。
