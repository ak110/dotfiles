# 旧形式計画ファイルの読み取り互換基準

本書は、旧単一ファイル形式（対応する`<stem>.detail.md`が存在しない形式）および旧二ファイル形式（`<stem>.detail.md`が存在する形式）で書かれた計画ファイルを読み取る際の判別条件と、表の列名規約を定めている。
これらの旧形式は既存計画の読み取りにのみ適用し、新しい計画はすべて現行の書式で作成する。
読み取りで受理する値は、`agent_toolkit/_plan/structure/constants.py`に定義された読み取り互換用の定数に従う。

既存計画ファイルに含まれる旧表記の固定記述（計画メタ情報の`実装詳細`行、`- バグ調査ファイル:`で始まる参照行、`~/.claude/plans`（`LEGACY_PORTABLE_ROOT`）への参照や旧絶対パス、`<計画stem>.tsv`形式のレビュー指摘管理表など）は、後方互換性維持のためそのまま受理する。
既存計画に記録されているID、系統名、表の内容は現行の値のまま維持し、新規に作成する計画では現行書式の記法を用いる。計画構造の自動チェックツールは旧形式を正常に処理した上で、現行書式への移行を促す警告（warning）を出力する。

## 旧形式の判別

対応する`<stem>.detail.md`が存在するかどうかで、旧二ファイル形式と旧単一ファイル形式を判別する。
detailファイルが存在しない場合は、旧単一ファイル形式としてチェックを行う。

旧単一ファイル形式における固定H2見出しは、以下の順序で配置する。`## バグ調査結果`は作業種別がバグ対応である場合にのみ設ける。

1. `## 概要`
2. `## 実施内容`
3. `## 提示素材`
4. `## 変更履歴`
5. `## バグ調査結果`
6. `## 恒久化・リファクタリング内容`
7. `## 実装資料`
8. `## 完了条件`
9. `## 進捗ログ`

旧単一ファイル形式では、`## 概要`から`## 変更履歴`までを人間向けの固定領域とし、`## 変更履歴`の直後から`## 進捗ログ`の直前までを実装者向けの領域として扱う。

旧二ファイル形式のメインファイルが受理するH2見出しには、次の2つの系統がある。

1. `## 概要`、`## 実施内容`、`## エージェント提案詳細`、`## 提示素材`、`## 変更履歴（計画時）`、`## 検証区分`、`## 終端工程`、`## 進捗ログ（実行時）`
2. `## 概要`、`## 実施内容`、`## 提示素材`、`## 変更履歴`、`## 検証区分`、`## 終端工程`、`## 進捗ログ`

対応する`<stem>.detail.md`の固定H2見出しは、`## 恒久化・リファクタリング内容`、`## 実装資料`、`## 完了条件`の順序で並ぶ。
計画メタ情報には`起動経路`、`対象リポジトリ`、`作業種別`、`ベースコミット`、および`計画ファイル（詳細）`が含まれる。`実装詳細`という項目名は、`計画ファイル（詳細）`の旧名として受理する。

## 読み取る表の列名

- `## 実施内容`: `実施内容`、`採否`、`ユーザー指示との関係`、`根拠`。さらに古い形式では`採否`列を含まない3列表となる
- `## 提示素材`の素材表: `素材ID`、`種別`、`キューID`、`投入元`、`引用範囲`
- `## 提示素材`の要求表: `要求ID`、`素材参照`、`実装に必要な要件`、`採否`、`採用範囲`、`除外範囲`、`根拠`
- `## 変更履歴（計画時）`または`## 変更履歴`: `ID`、`起点`、`指摘内容`、`採否・現在の結論`、`同期先`
- `## 検証区分`: `区分`、`検証コマンド`の2列で構成され、`レーン内検証`、`統合後検証`の2行を持つ
- `### 実装単位`: `単位ID`、`目的`、`先行依存`、`統合順`、`近接検証`。さらに古い形式では`対象の実施内容`を加えた6列表となる
- `### 合意済みの除外・保持`: `合意内容`、`対象と箇所`、`素材・要求参照`、`確認方法`
- `## 進捗ログ（実行時）`または`## 進捗ログ`: `日時`、`完了した工程`、`結果・特記事項`
- 現行の単一ファイル書式における`### 受入シナリオ`: `利用目的と後続行動`列を持たない6列表。第3列が`利用者と入口`となっている形式や、最終列が改名前の名称になっている形式も含む。列の並び順は`PLAN_LEGACY_ACCEPTANCE_TABLE_HEADERS`で規定されており、表頭に対応する列数や空セルの有無を検証する

素材IDは`P-`で始まる形式、要求IDは`R-<素材ID>-<3桁連番>`、実装単位IDは`U-[0-9]{3}`形式を受理する。
変更履歴のIDは、`R<正の整数>-<系統名>`形式のほか、旧二ファイル形式の`C-`や`H-`形式および旧系統名、旧単一ファイル形式の`C-<3桁連番>`形式および`conformance`系統を受理する。
これらのIDを新しく採番することはせず、既存の値をそのまま維持する。

旧形式における`text`コードフェンスや`原文参照`列、原因分析表を持たない固定14行の旧調査表、本文内に調査表を含む旧形式、統廃合前の行構成を持つ調査表についても、読み取り互換性維持のためそのまま受理する。

## 現行規範の所在

旧形式の列名に直接結びつかない規範については、現行書式の規定に従う。
実施内容を記述する粒度、採否の値、ユーザー合意との整合性の確認、参照元の検索と計上の基準は`plan-file-standards.md`で規定する。ユーザー発話の解釈手順は、`agent-toolkit:user-confirmation-and-report`の`references/user-utterance.md`「ユーザー発話の解釈」以降の各節に従う。
旧書式を扱う際は、`plan-file-standards.md`が指定する計上先を、`## 実装資料`内のファイル群別の変更説明と`## 完了条件`へと読み替える。
レビュー指摘管理表の列の定義（列契約）は、`agent-toolkit/agent_toolkit/_atk/review_table.py`およびそのテストコードで規定する。
