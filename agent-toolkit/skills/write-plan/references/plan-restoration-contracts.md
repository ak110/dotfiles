# 保持・復元を伴う計画の契約

本書は、状態の保持、不変性、完全復元などを要件や外部仕様（契約）に含む計画や、過去の契約への巻き戻し・過去の契約の撤去を伴う変更を計画する際の調査手順を定める。

## 保持・不変性・完全復元の契約

保持、不変性、完全復元を計画の契約やユーザー確認の選択肢に記載する場合は、内容を確定する前に採用する入力形式がその不変性を表現できるか確認する。あわせてデータが経由する既存の処理（保存、読み込み、UI、エディターなど）によって意図しない変換（再シリアライズ、トリム、値の補完や正規化など）が加わらないかも対象の実装コードで確認する。契約、完了条件、選択肢には、不変とする対象、許容する変換、および不変性が成立する範囲を、齟齬のない同じ条件で記述する。

## 復元・巻き戻し型の変更

- 対象項目ごとに導入された目的を調査し、維持・修正・撤去のいずれとするかを項目別に判定して`## 要件・外部仕様`へ記録する
- 現在の状態が、過去に失われた後に意図して確立されたものかどうかを、後続のコミット履歴、利用側が観測する仕様、実装コメントなどから確認する。意図的な再設計である場合は復元の対象から外し、その根拠を記録する
- 由来の追跡は記述単位で行う。現存する値は`git blame -L`、削除された値は`git log -S`で特定した削除コミットの親コミットに対するblame、再導入された値は現在の行と過去の削除元の双方を調べる。最終更新者や`git log -S`の最新結果だけを根拠にして導入元を断定しない
- 過去の方式へ戻す変更では、その方式を前提として後から追加された回避策、条件分岐、例外処理、運用規定などを、導入コミット以降の履歴調査や方式名の検索によって列挙する。復元後に前提が成立しなくなるものについては、撤去や修正を同じ計画に含める。維持するものについては、復元後も前提が成立する根拠を記録する
