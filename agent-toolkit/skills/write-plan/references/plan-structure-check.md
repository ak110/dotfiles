# 計画構造の自動チェック

本書は、[plan-file-standards.md](plan-file-standards.md)で定義された計画構造の検証に用いる形式要件と実行手順を定める。

すべての節に共通して、自動チェックが受け付ける形式要件は次のとおりである。

- GFM表のセル内でリテラルの`|`を記述する場合は、コードスパン内であっても`\|`とエスケープする
- `plan-file-standards.md`が列名や行名を定めている固定テーブルは、名称と順序が完全一致しているかを判定する。同じ列名を持つ固定テーブルの配置は節ごとに1つまでとし、データ行は少なくとも1つのセルに値を持たせる
- 固定のH3見出しを定めている節には、そのH3見出しのみを配置する。同一の親見出しの下では、同一文言の見出しは1つに限る
- 本文に「なし」と記述するよう定められている箇所では、「なし」の1行のみを配置する
- 計画メタ情報の`関連WI`の子項目は、半角空白2文字のインデントに続けて`-`と半角空白1文字を置き、ファイル名は`yyyymmdd-hhmmss-nnn.md`の形式で重複なく一意に指定する
- `## 実施内容`の`由来`に記載するWIファイル名からは、パス区切り文字、半角丸括弧、および空白文字を除外する
- `## 要件・外部仕様`と`## 公開工程`には、必ず具体的な内容を記述する
- 起動形式で参照しているスキルやサブエージェントは、その定義の実在を必須とする
- コードフェンス（```）は必ず閉じる
- `## 変更履歴`の配下は地の文とコードブロックで記述し、`### ユーザー発言<連番>`の連番は1から欠番なく昇順で配置する
- `~/.claude/plans`直下の計画ファイルは、起草の段階から`plan-file-storage.md`「計画ファイルの保存と参照」のstem規約に従い、保存工程の受理条件を満たす命名とする（直下に存在しない計画ファイルについてはファイル名の検証を省略する）

検証処理は`skills/write-plan/scripts/check_plan_file.py`が担う。現在のagent-toolkit環境から計画ファイルの絶対パスを渡して次の形式で実行する（内部スクリプトを別のPythonから直接起動した場合は、この公開コマンドの案内を表示して終了コード2で終了する）。

```sh
atk run-script plan-check -- --reject-migration-warnings /absolute/path/to/plan.md
```

- `--reject-migration-warnings`: 新規作成や改訂の際に、旧形式からの移行警告をエラーとして扱う。保存済みの計画ファイルを読み取るだけの検証では省略する。なお、旧形式（単一9節構成、2ファイル構成）は[legacy-plan-file-standards.md](legacy-plan-file-standards.md)の読み取り互換として受け付けられ、移行警告が出力される
- `--work-dir`: 解決されたGitルートが、計画メタ情報の`対象リポジトリ`と一致しているかを確認する。対象リポジトリがセッションの作業ディレクトリと異なる場合や、専用のworktreeで作業している場合は、そのパスを`--work-dir`に渡すか、そのディレクトリを作業ディレクトリとして実行する（複製元の作業ツリーから実行すると拒否される）
- `--selection-file <選定工程の`選定結果の出力先ファイル`の絶対パス> --lane <レーン識別子>`: `agent-toolkit:process-wi`のレーン実行時に追加する。そのレーンにおいて`再開位置`を持たないWIの集合が`関連WI`と完全に一致しているか、および人間由来の実施行に`根拠`が記載されているかを確認する。`再開位置`を持つWIは既存の計画を引き継いで進めるため、`関連WI`に含めると余剰と判定されてエラーになる
- `--expected-wi <WIファイル名>`: 保存済み対応表から取得したすべての計画対象と比較する場合に、対象件数分だけ繰り返し指定する。関連WIの欠落、余剰、重複の有無や、人間由来の行における根拠の記載を集合比較で検証する。直接実装の対象や別worktreeの項目は比較元から除外する。本オプションを省略した場合は、通常の構造チェックのみを行う。選定YAML指定との同時使用や不正なWIファイル名が渡された場合は終了コード2、不一致時は対象WIを含む診断メッセージを出力して終了コード1、一致時は（他の構造違反がなければ）終了コード0となる
- `--prior-plan <先行計画の絶対パス>`: 計画を凍結した後に同じレーンへAWIを追加した場合は、先行する計画ファイルをすべてこのオプションで繰り返し指定する。各計画間での`関連WI`の重複を検知・拒否し、それらの和集合を対象WI集合と比較する（先行計画自体の構造再検証は省略する）
- 複数の計画ファイルへの分割: 初回に複数の計画へ分割した場合は、すべての計画ファイルの絶対パスを位置引数に並べて1回で検証する。各計画を個別に判定して診断メッセージの先頭にパスを付与し、全体の和集合を比較する。`--agent-rule-path`で指定した各パスは、いずれかの計画本文に含まれていれば受理される。同一ファイルを重複指定した場合は終了コード2となる。1件ずつ他の計画を先行計画に指定して検証すると、未検証の計画に含まれるWIが集合に入らず検証に失敗するため注意する

構造に関する定数や値の抽出ロジックは、`agent-toolkit/agent_toolkit/_plan/structure/`に従う。なお、素材と要約の意味的な一致、根拠の妥当性、検討の実質的な妥当性については、レビュー工程で確認する。
