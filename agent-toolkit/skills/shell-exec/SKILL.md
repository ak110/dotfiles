# シェル実行委譲

本スキルは、委譲されたコマンドをBashで実行して結果を報告する手順を提供する。
メインのコンテキストから分離したfork実行であり、実行するコマンドと結果の要約方針を引数で受け取る。

## 起動

呼び出し元は本スキルを`Skill`ツールで起動し、実行するコマンドと結果の要約方針を引数へ渡す。`context: fork`を解釈する実行環境では、この起動だけで分離が成立する。

`context: fork`を解釈しない実行環境では、`agents_server`の`start`へ`model_type`として`explore_fast`、`cwd`として作業ディレクトリの絶対パス、`prompt`として本スキルの実行ルールと同じ内容の指示を渡し、同じ応答で`wait`を発行する。この経路では、実行するコマンド、結果の要約方針、及び生出力を委譲元へ転記しない条件を`prompt`へ書く。

`model_type`へ`explore_fast`を用いるのは、`agent-toolkit/scripts/_atk_config.py`が定める設定キーのうち軽量な区分が`explore_fast_model`であり、frontmatterの`model: haiku`と同じ意図に対応するためである。分離実行のために新しい設定キーを追加しない。

## 指示

以下の指示に従う。

$ARGUMENTS

引数の展開結果から実行するコマンドを一意に特定できない場合は、コマンドを推測せずBashを実行しない。
この場合は`引数未受領: shell-execへ実行コマンドが渡されていない`だけを返して終了する。

## 実行ルール

- 指示された操作のみを実行し、指示にない操作を追加しない
- 認証エラー・コマンド失敗時は出力をそのまま報告し、独自の回避策を試みない
- 報告は観測事実のみとし、指示で求められた情報を漏れなく含める
- `gh`や`glab`の操作など長出力が予想されるコマンド列を受け付ける
- CI失敗後のログ取得・要約は受け付ける。CI完了までの待機は受け付けない
  （待機は`git push`を実行した委譲元が自身で実施する）
- コマンドの生出力はfork内で確認し、メインへの報告へ全文転記しない
- 終了状態、警告、依頼で指定された値、後続判断に必要な要約を報告する
- 失敗原因の特定に必要な行だけを原文のまま添える
- 実行は前景を既定とし、`Bash`の`timeout`へ想定所要を上回る値を上限600000ミリ秒まで明示して指定する
- `timeout`を明示しない場合の前景待機は既定120秒であり、超過すると実行環境がコマンドを背景へ移す。明示した場合は指定値まで前景で待つ
- 実行前から上限を超える見込みの検査は、対象を分割した複数回の実行として受け取る。分割されていない指示は実行せず、分割が必要である旨と分割単位の候補を報告して終える
- `Bash`を最初から背景実行に指定しない。前景で完了するコマンドだけを実行対象とし、実行方式を背景既定へ変えない
- 上限内に収まる見込みで前景実行したコマンドを実行環境が背景へ移した場合は、結果を回収せず、背景へ移された事実、タスクID及び出力ファイルの絶対パスを報告して終える
  - forkが最終応答を返した時点で実行環境が背景taskを終了させるため、fork自身は当該コマンドの完了を待てない
  - 2026年8月にClaude Codeのfork型スキルで実測し、背景へ移されたtaskの出力が`[killed]`となり、完了通知が到達しないことを確認した
  - 再検証は上限内の`timeout`を指定した長時間コマンドを1回実行して行う
  - 呼び出し元は対象を分割するか`timeout`の指定値を上げて再度委譲する
