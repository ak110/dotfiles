# 管理対象一時領域

本スキルは一時ファイルの置き場所と、管理対象一時領域を個別に作成する例外用途を定める知識のスキルである。

## セッション領域

SessionStartはセッションごとに管理対象一時領域（以下「セッション領域」）を作成し、その絶対パスを実行環境が文脈へ追加する本文で通知する。
一時ファイルは原則としてセッション領域の直下へ、用途の分かるファイル名で置く。
turnをまたいで読む成果物、委譲先へ絶対パスで渡す成果物及び引き継ぎ記録もここへ置いてよい。
まとまったファイル群を置く場合は、セッション領域の中へサブディレクトリを作成してよい。
汎用の一時ディレクトリ作成コマンドが作る作業ツリー内や共有の一時ディレクトリに代えて、セッション領域を使う。
委譲元と委譲先のいずれが生成する場合も、作業目的のファイル（退避・比較・中間出力）は分量によらず対象リポジトリの作業ツリーの外へ置く。作業ツリー内へ置くとそのセッションの成果物と混在して差分の特定を要し、削除のやり残しがそのままコミット対象へ入る。

セッション領域はセッションの終了では削除されず、最終更新から7日を超えた後の`atk`の実行時に自動で削除される。
実行主体は回収しない。`agents_server`経由のsessionや`--resume`で同じ会話を再開した場合も、同じ`session_id`には同じセッション領域が通知される。

## 個別に作成する例外用途

`atk managed-temp create --prefix <用途>`で個別の領域を作成するのは、次の場合に限る。

- セッション領域の通知を受け取っていない場合。回収は7日の自動削除へ委ねてよい
- 別のファイルシステム名前空間（Dockerなど）から同じパスへ到達させるため、`--root`で共有ディレクトリを指定する場合
- Git worktreeなど`.git`を含む領域を置く場合。7日の自動削除は`.git`を含む領域を削除しないため、作成した工程が不要になった時点で`atk managed-temp cleanup --path <絶対パス>`で回収する

個別に作成する領域には、対応するAWIを`--awi <ファイル名>`で複数記録できる。

## 設定領域を変更する前の一時バックアップ

版管理又は自動同期が有効な設定領域（etckeeperが管理する`/etc`など）を変更する前に一時バックアップが必要になった場合は、変更前の版をその領域のローカル履歴から取り出せるかを先に確認する。
取り出せる場合は、その履歴の版をバックアップとして使う。別の複製が必要な場合は、設定領域の内側ではなく管理対象一時領域へ置く。
設定領域へ置いたファイルは自動commitで履歴へ入る。後から削除しても、そのファイルを追加したcommitはローカル履歴と送出済みの外部履歴に残る。

ローカルの自動commitと、外部remoteへのpush又は同期は別々に確認する。
外部への送出が設定されている場合は、領域内へ置いたファイルが外部の履歴へ届く前提で保存先を選ぶ。
変更後はローカル履歴と外部の同期先をそれぞれ調べ、作業用ファイルが含まれていないことを確かめる。
