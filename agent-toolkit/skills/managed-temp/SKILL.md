# managed-temp

一時ファイルの置き場所と、managed-tempの中へ個別のディレクトリを作成する例外用途を定める。

## セッションのmanaged-temp

SessionStartはセッションごとにmanaged-tempの中へ専用のディレクトリ（セッションのmanaged-temp）を作成し、その絶対パスを文脈へ通知する。
一時ファイル、turnをまたいで読む成果物、委譲先へ絶対パスで渡す成果物、引き継ぎ記録はここへ置く（サブディレクトリも可）。作業ツリー内の一時ディレクトリや共有の一時ディレクトリの代わりにここを使う。
作業目的のファイル（退避・比較・中間出力）は、委譲元と委譲先のどちらが作成する場合も分量によらず作業ツリーの外へ置く。作業ツリー内へ置くと成果物と混在し、削除のやり残しがコミットへ入る。

セッションのmanaged-tempは最終更新から7日を超えた後の`atk`の実行時に自動で削除されるため、エージェントは回収しない。同じ`session_id`で再開した会話には同じ領域が通知される。
`Agent`ツールのサブエージェントには担当専用の子ディレクトリが通知される。一時ファイルはそこへ置き、親の領域は委譲元が渡したファイルの読み書きに使ってよい。

## 個別に作成する例外用途

`atk managed-temp create --prefix <用途>`で個別の領域を作成するのは、セッションのmanaged-tempで用途を満たせない場合に限る。

<例>
セッションのmanaged-tempの通知を受け取っていない場合: 作成し、回収は7日の自動削除へ委ねてよい。
別のファイルシステム名前空間（Dockerなど）から同じパスへ到達させる場合: `--root`で共有ディレクトリを指定する。
Git worktreeなど`.git`を含む領域を置く場合: 作成する。
</例>

7日の自動削除は`.git`を含む領域を削除しないため、作成した工程が不要になった時点で`atk managed-temp cleanup --path <絶対パス>`で回収する。
process-wiのレーン用領域は`atk lane create`がworktree・branch・所有sessionと対応付けて登録する。統合後も追加に備えて保持し、全工程と外部プロセスの終了後に`atk lane delete`（通常終了とprocess-loopの子終了後も同じく回収する）が固有撤去・worktree・branch・個別領域の順で回収する。メインは所有資源を手書きで再登録しない。未統合・dirty・稼働中・不明・部分失敗の資源は登録と成果を保持する。登録と回収結果への参照は個別領域の外へ置き、回収結果は通常の7日保持へ委ねる。次回開始時は`atk lane delete --list`で残存理由と再開する操作を読む。
`.git`を含む領域へ置くのは作業ツリーとそれとともに捨ててよいものに限る。完成条件証拠、検証記録、引き継ぎ記録または完了報告が参照する保存物（検証の出力、手動観測の記録など）と、委譲先へ指定する保存先は、委譲元か委譲先のセッションのmanaged-tempにする。こうしておけば回収時に中身を確かめずに捨てられる。
個別の領域には対応するAWIを`--awi <ファイル名>`で記録できる。

## 設定領域を変更する前の一時バックアップ

版管理または自動同期が有効な設定領域（etckeeperが管理する`/etc`など）を変更する場合は、変更前の版をその領域のローカル履歴から取り出せるならそれをバックアップに使う。別の複製が要る場合は領域の内側ではなくmanaged-tempへ置く。
領域内へ置いたファイルは自動commitで履歴へ入り、後で削除してもローカル履歴と送出済みの外部履歴に残る。ローカルの自動commitと外部への送出をそれぞれ確かめ、変更後は両方に作業用ファイルが含まれていないことを確かめる。
