# 原因分析を記録する場所と表

本書は観測した欠陥の原因分析を記録するエージェントへ、記録先（AWIの`## 原因分析`と計画ファイル（バグ））と、そこへ置く原因分析表と調査表の構成を定める。拡張原因分析の条件に該当しない局所不良でも、AWIの`## 原因分析`を起草する前と計画ファイル（バグ）を作成する前に読む。

## 原因分析の記録先

原因分析後に確定した最終バグ単位は、観測した欠陥を起点とする通常AWIの`## 原因分析`へ記録する。計画はその節をWIファイル名で参照し、分析の記述をWIの1箇所へ保つ。
計画ファイル（バグ）を作成する条件と見出し構成は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「バグ調査」が、保存先と参照行の書式は同スキルの`references/plan-file-storage.md`が定める。

原因分析表は`要因系統`、`L1 現象`、`L2 判断`、`L3 構造`、`L4 システム`の5列とし、
`作り込み要因`、`見逃し要因`の2行を固定順で置く。
到達しなかった段のセルには`該当なし`と、その段まで掘らずに処置を確定できる根拠を書く。

調査表は`項目`と`内容`の2列とし、計画ファイル（バグ）では次の8行を固定順で書く。

| 行名 | 記載内容 |
| --- | --- |
| 現象 | 事象に加えて発生条件と実際値を含める |
| 期待する契約 | 事象の対象が満たすべき仕様、規範、公開契約 |
| 直接的原因 | 観測した不具合を発生させる実行時・データ・設定上の機構 |
| 原因分析の根拠 | 再現結果、`git blame`、導入コミット、資料の該当箇所。件数や記録の値を挙げる場合は、値ごとに、その値が主張の対象を表すことを確かめた生成元と、原因とした条件を満たさない群との比較（両群の件数）を併記する。比較の群を数えていない値と生成元を確かめていない値は、`references/initial-analysis.md`「直接的原因と事象時点の確定」の推定として書く |
| 対策 | 観測した不具合そのものと、それを固定した誤ったテスト・文書の修正 |
| 類似見直し観点 | 破られた不変条件または誤った判断規則、その適用境界、根本原因を成立させる各単位との対応 |
| 類似見直し結果 | 母集団、是正対象と予防対象へ分けた該当箇所の列挙、非該当の根拠、是正対象へ実施する横展開処置（列挙から導出できる件数は書かない） |
| 再発防止策 | 混入を防ぐか見逃さない仕組み、選定した優先順位の段、上位段を採用しない根拠、段4で処理自身の失敗を採用しない根拠、根本原因を成立させる各単位との対応、維持する契約とその選択の理由を残す先 |

計画ファイル（バグ）はバグ単位ごとの見出しの配下へ、原因分析表と調査表をこの順で置く。
拡張原因分析の条件に該当しない局所不良では、原因分析表の各セルと、拡張原因分析固有の行（類似見直し観点、
類似見直し結果、再発防止策）へ
`該当なし`と拡張原因分析の条件に該当しない根拠を書く。
表の構成、行名・列名および順序は本節が定めるとおりに保つ。

AWIの`## 原因分析`は原因分析表と、調査表のうち`直接的原因`、`原因分析の根拠`、`類似見直し観点`、`再発防止策`の4行をこの順で持つ2列表で構成する。
`再発防止策`行には選定した優先順位の段、上位段を採用しない根拠、根本原因を成立させる各単位との対応を書く。変更の具体は`## 反映内容と反映先`が持つ。
調査表の残る行はAWIの既存の節が持つ。`現象`と`期待する契約`はH1直下、`対策`と、横展開処置・再発防止策の変更内容は`## 反映内容と反映先`（処置の層を項目ごとに明記する）、`類似見直し結果`は`## 適用範囲`が持つ。
局所不良のAWIでは原因分析表を置かず、`直接的原因`、`原因分析の根拠`と、拡張原因分析の条件に該当しない根拠を書く。
1件のAWIが複数のバグ単位を持つ場合は、`## 原因分析`の中へバグ単位ごとのH3を置く。

複数の観測事象は、直接的原因と対策の変更単位がともに同じ場合だけ1つのバグ単位へ統合する。
直接的原因または対策の変更単位のいずれかが異なる場合は分ける。統合の条件は直接的原因と対策の変更単位の一致とし、根本原因の共通は統合の判定から外す。
同じ根本原因でも入力解析と状態更新のように直接的原因が異なる事象は別のバグ単位にする。
同じ直接的原因と対策から保存失敗と再試行停止のような複数症状が生じる場合は統合できる。
対応網羅確認では、計画メタ情報の関連WIに現れる各バグが、WIの`## 原因分析`と計画ファイル（バグ）のどちらかにある確定したバグ単位へ対応することを確認する。
計画の`### 恒久化`は原因分析を記録した資料（WIの`## 原因分析`と`## 反映内容と反映先`か、計画ファイル（バグ）の調査表）を参照し、類似見直しの記述はその資料だけに置く。
