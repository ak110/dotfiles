# 原因分析を記録する場所と表

本書は観測した欠陥の原因分析を記録するエージェントへ、記録先（AWIの`## 原因分析`と計画ファイル（バグ））と表の構成を定める。局所不良でも、AWIの`## 原因分析`を起草する前と計画ファイル（バグ）を作成する前に読む。

## 原因分析の記録先

確定したバグ単位は、観測した欠陥を起点とする通常AWIの`## 原因分析`へ記録し、計画はその節をWIファイル名で参照する（分析の記述をWIの1箇所に保つ）。
計画ファイル（バグ）の作成条件と見出し構成は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「バグ調査」、保存先と参照行の書式は同スキルの`references/plan-file-storage.md`が定める。

原因分析表は`要因系統`、`L1 現象`、`L2 判断`、`L3 構造`、`L4 システム`の5列とし、`作り込み要因`、`見逃し要因`の2行をこの順で置く。到達しなかった段には`該当なし`と、その段まで掘らずに処置を確定できる根拠を書く。

調査表は`項目`と`内容`の2列とし、計画ファイル（バグ）では次の8行をこの順で書く。

| 行名 | 記載内容 |
| --- | --- |
| 現象 | 事象に加えて発生条件と実際値を含める |
| 期待する契約 | 事象の対象が満たすべき仕様、規範、公開契約 |
| 直接的原因 | 観測した不具合を発生させる実行時・データ・設定上の機構 |
| 原因分析の根拠 | 再現結果、`git blame`、導入コミット、資料の該当箇所。件数や記録の値を挙げる場合は、値ごとに、その値が主張の対象を表すことを確かめた生成元と、原因とした条件を満たさない群との比較（両群の件数）を併記する。確かめていない値は`SKILL.md`「直接的原因と事象時点の確定」の推定として書く |
| 対策 | 観測した不具合そのものと、それを固定した誤ったテスト・文書の修正 |
| 類似見直し観点 | 破られた不変条件または誤った判断規則、その適用境界、根本原因を成立させる各単位との対応 |
| 類似見直し結果 | 母集団、是正対象と予防対象へ分けた該当箇所の列挙、非該当の根拠、是正対象へ実施する横展開処置（列挙から導出できる件数は書かない） |
| 再発防止策 | 混入を防ぐか見逃さない仕組み、選定した優先順位の段、上位段を採用しない根拠、段4で処理自身の失敗を採用しない根拠、根本原因を成立させる各単位との対応、維持する契約とその選択の理由を残す先 |

計画ファイル（バグ）はバグ単位ごとの見出しの配下へ原因分析表と調査表をこの順で置く。局所不良でも類似見直しと再発防止の要否は`SKILL.md`「初動と拡張原因分析の判定」と`root-cause-analysis.md`の共通判定で決め、類似見直しの観点と結果は直接的原因から得た内容を記録する。原因分析表の到達しない段と、共通判定で該当しない行には`該当なし`と根拠を書く。表の行名・列名・順序は変えない。

AWIの`## 原因分析`は原因分析表と、調査表のうち`直接的原因`、`原因分析の根拠`、`類似見直し観点`、`再発防止策`の4行をこの順で持つ2列表で構成する。`再発防止策`行には選定した段、上位段を採用しない根拠、根本原因の各単位との対応を書き、変更の具体は`## 反映内容と反映先`が持つ。残る行の置き場所は、`現象`と`期待する契約`がH1直下、`対策`と横展開処置・再発防止策の変更内容が`## 反映内容と反映先`（処置の層を項目ごとに明記）、`類似見直し結果`が`## 適用範囲`である。
局所不良のAWIは原因分析表を置かず、`直接的原因`、`原因分析の根拠`、条件に該当しない根拠を書く。複数のバグ単位を持つAWIは、`## 原因分析`の中へバグ単位ごとのH3を置く。

複数の観測事象を1つのバグ単位へ統合するのは、直接的原因と対策の変更単位がともに同じ場合だけとする。根本原因の共通は統合の根拠にしない（同じ根本原因でも入力解析と状態更新のように直接的原因が異なれば分け、同じ原因と対策から保存失敗と再試行停止が生じるなら統合できる）。
対応網羅確認では、計画メタ情報の関連WIの各バグが、WIの`## 原因分析`か計画ファイル（バグ）の確定したバグ単位へ対応することを確かめる。
計画の`### 恒久化`は原因分析を記録した資料を参照し、類似見直しの記述はその資料だけに置く。
