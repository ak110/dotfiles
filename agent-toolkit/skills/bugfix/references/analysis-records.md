# 原因分析を記録する場所と表

本書は観測した欠陥の原因分析を記録するエージェントへ、記録先（AWIの`## 原因分析`と計画ファイル（バグ））と表の構成を定める。拡張原因分析の対象外の不良でも、AWIの`## 原因分析`を起草する前と計画ファイル（バグ）を作成する前に読む。

## 原因分析の記録先

確定したバグ単位は、観測した欠陥を起点とする通常AWIの`## 原因分析`へ記録し、計画はその節をWIファイル名で参照する（分析の記述をWIの1箇所に保つ）。
計画ファイル（バグ）の作成条件と見出し構成は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「バグ調査」、保存先と参照行の書式は同スキルの`references/plan-file-storage.md`が定める。

原因分析表は`要因系統`、`L1 現象`、`L2 判断`、`L3 構造`、`L4 システム`の5列とし、`作り込み要因`、`見逃し要因`の2行をこの順で置く。到達しなかった段には`該当なし`と根本原因を確定した結論を短く書き、判断過程は証拠へ残す。

調査表は`項目`と`内容`の2列とし、計画ファイル（バグ）では次の8行をこの順で書く。

| 行名 | 記載内容 |
| --- | --- |
| 現象 | 事象に加えて発生条件と実際値を含める |
| 期待する契約 | 事象の対象が満たすべき仕様、規範、公開契約 |
| 直接的原因 | 観測した不具合を発生させる実行時・データ・設定上の機構 |
| 原因分析の根拠 | 再現結果、`git blame`、導入コミット、資料の該当箇所。件数や記録の値を挙げる場合は、値ごとに、その値が主張の対象を表すことを確かめた生成元と、原因とした条件を満たさない群との比較（両群の件数）を併記する。確かめていない値は`SKILL.md`「直接的原因と事象時点の確定」の推定として書く |
| 対策 | 観測した不具合そのものと、それを固定した誤ったテスト・文書の修正 |
| 類似見直し観点 | `SKILL.md`「QとC・Dの区別」の判定結果、重大度と根拠、破られた不変条件または誤った判断規則、その適用境界、根本原因を成立させる各単位との対応 |
| 類似見直し結果 | 母集団、是正対象と予防対象、必要な横展開処置、完了の結論と再取得先。処理する担当の判断に影響する探索の限界・残存リスクは本文へ残し、検索方法、非該当理由、独立走査と再検討の経過は証拠へ残す |
| 再発防止策 | 選定した段、根本原因の各単位への作用、選定理由と維持する契約の記録先。採用なしの場合は`SKILL.md`「QとC・Dの区別」による終了の結論を書く。終了の根拠には、`SKILL.md`「再発防止策の必須性」が定める使えない根拠（適用が抜けた既存規範、後段での回復、別論点の判断、未確定の寄与）を使わない。案の比較と各段を評価した過程は証拠へ残す |

計画ファイル（バグ）はバグ単位ごとの見出しの配下へ原因分析表と調査表をこの順で置く。拡張原因分析の対象外の不良でも、類似見直しと再発防止は`root-cause-analysis.md`の共通基準で判定し、類似見直しの観点と結果、再発防止策は根本原因から得た内容を記録する。表の行名・列名・順序は変えない。

AWIの`## 原因分析`は原因分析表と、調査表のうち`直接的原因`、`原因分析の根拠`、`類似見直し観点`、`再発防止策`の4行をこの順で持つ2列表で構成する。`類似見直し観点`行にはQとC・Dの区別、重大度と探索の深さの根拠を書く。`再発防止策`行には選定した段と、重大度に応じて評価した案・選定根拠・根本原因の各単位への作用を対応付ける。変更の具体は`## 反映内容と反映先`が持つ。残る行の置き場所は、`現象`と`期待する契約`がH1直下、`対策`と横展開処置・再発防止策の変更内容が`## 反映内容と反映先`（処置の層を項目ごとに明記）、`類似見直し結果`が`## 適用範囲`である。
拡張原因分析の対象外の不良のAWIは原因分析表を省いてよく、前記の4行と、条件に該当しない根拠を書く。複数のバグ単位を持つAWIは、`## 原因分析`の中へバグ単位ごとのH3を置く。

複数の観測事象を1つのバグ単位へ統合するのは、直接的原因と対策の変更単位がともに同じ場合だけとする。根本原因の共通は統合の根拠にしない（同じ根本原因でも入力解析と状態更新のように直接的原因が異なれば分け、同じ原因と対策から保存失敗と再試行停止が生じるなら統合できる）。バグ単位を分けても、根本原因を同じくする問題の類似見直しと再発防止の完了は`root-cause-analysis.md`「類似見直しと再発防止の完了」で全件を対象に判定する。
対応網羅確認では、計画メタ情報の関連WIの各バグが、WIの`## 原因分析`か計画ファイル（バグ）の確定したバグ単位へ対応することを確かめる。
計画の`### 恒久化`は原因分析を記録した資料を参照し、類似見直しの記述はその資料だけに置く。
処置と完成条件の被覆の結論は`root-cause-analysis.md`「類似見直し」の比較元へ対応付け、既存の類似見直し結果と再発防止策の記録へ残す。
