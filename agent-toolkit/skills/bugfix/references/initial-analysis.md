# 初動の確定基準

本書は`SKILL.md`「初動と拡張原因分析の判定」の初動で、事象、期待する契約、直接的原因と発生条件を確定する基準と、対策の影響範囲を調べる範囲を定める。拡張原因分析の要否はこの確定の後に同節で判定する。

## 直接的原因と事象時点の確定

- 処置案を検討する前に、事象、実際の結果および発生条件を再現・ログ・実装から確定する。期待する契約は対象の目的を定める仕様・設計記録・規範から確定し、実装が述べる前提や文言は比べられる側として扱う。次に直接的原因、作り込み要因、見逃し要因および類似範囲を確定し、その後にだけ対策・横展開処置・再発防止策を選定する。直接的原因は、候補の機構だけを変えた対照で事象が変わることを観測して確定する。次の3種の値は推定として扱う。1つ目は同時に変化した値の相関だけから得た候補である。2つ目は原因とした条件を満たす側で事象が起きた件数だけを数え、条件を満たさない群の件数と比べていない値である。3つ目は計測手段や記録の項目が主張の対象を表すかを、その値を書き込む処理（実装、公式資料、記録の構造の定義）で確かめていない値であり、出力の到着時刻を処理の時刻とみなす計測や、記録の項目名からその文面を書き手の原文とみなした集計がこれに当たる。設定、依存版、外部状態、規範・スキル・手順の条文その他の可変値を原因へ用いる場合（条文が適用されなかった、条文が欠けていたと述べる場合を含む）は、その値と文面が事象時点にも同じ形で適用されていたことを履歴か当時の記録で確かめる。履歴は`git log -S '<文面の特徴的な語>' -- <パス>`や、事象時点のcommitに対する`git show <commit>:<パス>`で調べる。事象後の現行の値と文面だけでは事象時点の値を確定せず、時点を確かめていない候補は推定として扱う。類似範囲は直接的原因の機構を共有する対象全体とし、症状を観測した呼び出し元や、上限の超過など症状の程度で狭めない
- 上流（ライブラリ、ツール、OS、外部API、ホスト）の挙動または変更が直接的原因の候補である場合は、上流の資料を確かめる。資料は該当機能の公式ドキュメント、リリースノートと公式CHANGELOG、該当commitとソース差分、提供元の公開Issueトラッカーにある同じ事象の報告（既知の回避策、提供元の見解と対応状態）とする。実装（ホスト本体のバイナリ、ライブラリのソースなど）の読解と実機再現はこれらの資料の補完として使い、代わりにしない。実装で見つけた内部の名前は公開資料の用語と異なることがあるため、資料は機能の説明と公開資料側の用語でも探す。Claude Code本体の内部名`narration`と、公式ドキュメントの「progress update」がその例である。回避処理の採用には、挙動差分の観察に加えて一次資料の裏付けを必須とする。既知の報告に回避策や提供元の見解がある場合は、採る回避処理との関係（採るか、採らない理由）を原因分析の記録へ書く

## 対策の影響範囲

- 対策を確定する前に、その対策が変える値や動作の影響範囲を実装からたどる。直接影響範囲（変更前の動作を前提として書かれた既存の指定を含む）と別発生源（いずれも定義と範囲は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「要件・外部仕様」）を対象とし、追随が必要な箇所を対策へ含める。影響が局所にとどまると考えられる場合も同じ範囲を調べる。除外、免除または解決済みとして扱う対策では、保証する側の規定や実装で先行動作が成立し、除外する側がその動作を前提としているか、双方の現物を読んで確かめる。主体をまたぐ場合も先行側の保証を確かめ、保証が無ければ同じ対策に含める

## 母集団と件数を数える層

- ユーザーが失敗例その他の観測事象の実物を提示した場合は、対象の母集団を発話の範囲語から確定してから発生条件を定める。提示された実物は母集団の一例として扱う。範囲語と例示が併存する場合の優先順位は`agent-toolkit:user-confirmation-and-report`の`references/user-utterance.md`に従う
- エンドユーザーが観測した症状の件数や該当対象を数えるときは、エンドユーザーが観測する層で数える。画面では描画結果、CLIでは出力がこの層に当たる。中間の値（一覧APIの戻り値、状態ファイルなど）や一部の記録（特定の形式や付随ファイルを持つ記録だけなど）で数える場合は、その値からエンドユーザーが観測する層までの変換（表示側での検索の引き直し、抽出条件、件数上限など）を実装からたどる。変換が該当の判定を変えないことと、数えなかった記録に該当が無いことを確かめてから母集団として使う。件数を成果物（AWIの`## 原因分析`の`原因分析の根拠`行など）へ書くときは、数えた層と、中間の値で数えた場合に確かめた変換を併記する。この項はユーザーが実物を提示したかによらず適用する。中間の値が正しくても後段の変換を経た結果が正しいとは限らず、手前の層で数えると症状の大半が母集団から外れ、是正をやり直すことになる

## 外部からの不具合報告

- 外部から受け取った不具合報告が、別の環境、別の版、過去の時点のいずれかでは事象が生じないと述べている場合は、その主張の成否を判定してから発生条件を確定する。判定は報告が挙げる環境または版が配備する成果物の実装差分を取得し、その成果物へ差し替えて再現することで行う。判定結果と根拠を成果物へ書く。報告に事象が生じない環境・版・時点の記述が無い場合は、この判定を省く

## 作業途中で発見した事象

- 作業途中で発見した事象は、着手前に記録した状態と現在の差分を先に突合し、進行中の未コミット変更で混入した事象と着手前から存在する事象を区別する
  - 進行中の未コミット変更で混入した場合は、現在の指示、計画、実装判断を混入原因として調べる。既存機能の導入履歴は別の系統として扱う
