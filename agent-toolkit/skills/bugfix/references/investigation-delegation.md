# 事象単位の調査の委譲

本書はバグ対応とCI失敗対応、振り返りの事実収集で、事象ごとの観測事実の収集を独立した担当へ委譲する主体へ、委譲の単位と委譲プロンプトへ渡す情報を定める。拡張原因分析の条件に該当しない局所不良でも、事象単位の調査を委譲する前に読む。

## 事象単位の並列調査委譲

バグ対応とCI失敗対応の調査工程に適用する。

独立事象ごとに観測事実の収集を分ける。初回は症状または失敗ジョブを単位とし、
報告後に同一原因を統合し、複数原因を分割する。
ユーザー介入に由来する事象では、事実の収集を独立した担当へ委譲する。独立した文脈は委譲元の仮説に引きずられない調査をもたらし、その利益は原因が非自明な場合に大きい。直接的原因が観測で自明な単一の介入では、委譲の起動費用と待ち時間がその利益を上回ることがあるため、委譲を任意とする。介入以外でも独立した事象が2件以上ある場合は、事象ごとに並列で委譲する。どちらにも当たらない単一事象の委譲は任意とする。
委譲では`agent-toolkit:delegation`に従い、委譲プロンプトへ事象、期待する契約、実際の結果、
発生条件、ログと資料の絶対パス、対象commit、再現手順だけを渡す。
委譲プロンプトへ渡すのはこの7項目とし、委譲元の仮説、原因の候補と考えた実装箇所、修正案、他事象の調査結果、類似見直しの母集団の定義および調査範囲の限定は自身の手元に残す。これらを渡すと調査担当がその仮説を検証する範囲へ調査を狭め、独立したコンテキストで別の原因へ到達する利益が失われる。
報告された推定と対策案は候補として実際に確かめ、原因と処置の確定は委譲元が所有する。
