# 問題を見つけたときの対処

対処の候補を選ぶ前に「判断指針」の3段判定を適用し、許容されない対象、操作、副作用を候補から除く。
対処案の構造比較には`agent-toolkit:writing-standards`の`references/design-heuristics.md`「設計案の予備選別」を適用する。

作業中に発見した問題は、まず事象・期待値・実際値・発生条件・直接的原因を確定し、
続いて同スキルの「初動と拡張原因分析の判定」に従う。
原因分析の要否判定、原因分析、類似見直し及び対策・横展開処置・再発防止策の確定は同スキルに従う。

- 終了コードが0でも出力に警告が含まれる場合は対処する。警告は処理の一部が未適用又は未完了であることを示す場合があり、成否は終了コードと警告の不在の両方で判定する
- 要件へ波及する変更と、`agent-toolkit:confirmation-and-uwi`の`references/judgment.md`「認可を要する操作」に当たる対処はユーザー確認し、合意を得てから着手する。内部実装に閉じる対処は自律的に完遂する。ただし依頼が調査、確認又は報告だけを求める場合は、内部実装に閉じる対処にも「完遂と先送り」が定める成果物の種別による範囲を適用し、着手の可否を確認する
- フック、ツール、実行環境のいずれかが挿入した通知について、通知が挙げる対象が自身の担当に属さないこと、通知が求める処置をこのセッションで実行できないこと、通知の前提が実在しないことのいずれかを観測した場合は、その観測を通知機構の欠陥の観測として扱う。通知が指示する終端に従うことと、観測した欠陥の処置を確定することを別の工程として両方行う。処置は同一セッション内の是正、又は`agent-toolkit:wi-standards`に従うAWI投入の提案とし、いずれかを実施して終える。通知の文面が対象外なら何もせず終える旨を含む場合、その文面は個々の通知への応答だけを定め、通知機構自体の欠陥への処置の要否は本項が定める。通知の指示に従う終端が処置の発議を省く根拠になると、同じ欠陥が別のセッションで繰り返し発生する
