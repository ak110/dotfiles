# 問題を見つけたときの対処

対処の候補を選ぶ前に「判断指針」の3段判定を適用し、許容されない対象、操作、副作用を候補から除く。
対処案の構造比較には`agent-toolkit:writing-standards`の`references/design-heuristics.md`「設計案の予備選別」を適用する。

作業中に発見した問題は、同スキルの「初動と拡張原因分析の判定」に従う。
原因分析の要否判定、原因分析、類似見直しおよび対策・横展開処置・再発防止策の確定は同スキルに従う。

- 自分の作業で導入していない既存不良を見つけた場合は、原則として同じセッションで類似見直しと再発防止策まで是正し終える。作業の続行を妨げない不自然さ・非効率・反復（ツールの使い勝手の悪さを含む）は、その場の是正の対象から外す。メインは`agent-toolkit/share/rules-main.md`「協調と自律」、委譲先は`agent-toolkit/share/rules-subagent.md`「返却と終端」の`気付いた改善点:`の行で扱う。影響調査や設計選定をそのセッションで実施できない場合など、`agent-toolkit/rules/01-agent.md`「完遂と先送り」が先送りを認める条件に当たる不良は、同節に従ってWIへ送る。同スキルの初動判定で拡張原因分析を要する不良、または類似見直しか再発防止策を要する不良は、元の作業と文脈を分けるため`${CLAUDE_PLUGIN_ROOT}/share/defect-investigation.parent.md`に従って調査を委譲する。修正は返った対策に従い、見つけた主体が元の文脈で行う。拡張原因分析を要さず1箇所で是正が完結する軽微な不良は、見つけた主体がその場で直す。委譲先として動作する主体が担当範囲外の不良を見つけた場合は、`agent-toolkit/rules/01-agent.md`「完遂と先送り」に従って委譲元へ返す。実行中のスキル（`agent-toolkit:process-wi`など）が不良の扱いを定める場合は、そのスキルの手順に従う。WIの完成条件の範囲外で見つけたエンドユーザー向けの不足は、`agent-toolkit:user-confirmation-and-report`の`references/judgment.md`「認可を要する操作」の範囲外の不足の区分で判定する。文書を機能の制約へ合わせる是正を選んだ場合も、欠如した機能を同じ区分で判定する。是正が新しい挙動の追加に当たる不足は、実行中のスキルの手順で扱う場合も既存不良として自ら是正も先送りもせず、同書「確認を要する事項」の確認へ送る
- 終了コードが0でも出力に警告が含まれる場合は、警告の意味を確かめる。警告は処理の一部が未適用または未完了であることを示す場合があり、成否は終了コードと、未適用・未完了を示す警告の不在の両方で判定する。未適用・未完了を示す警告には対処し、処理と無関係と判断した警告（依存の非推奨通知など）はその根拠を報告へ残す
- ユーザーが示した要件を変える変更と、`agent-toolkit:user-confirmation-and-report`の`references/judgment.md`「認可を要する操作」に当たる対処はユーザー確認し、合意を得てから着手する。要件を満たす手段の選択は`agent-toolkit:user-confirmation-and-report`「確認要否の判定」で決める。内部実装に閉じる対処は自律的に完遂する。ただし依頼が調査、確認または報告だけを求める場合は、内部実装に閉じる対処にも「完遂と先送り」が定める成果物の種別による範囲を適用し、着手の可否を確認する
- フック、ツール、実行環境のいずれかが挿入した通知について、通知が挙げる対象が自身の担当に属さないこと、通知が求める処置をこのセッションで実行できないこと、通知の前提が実在しないことのいずれかを観測した場合は、その観測を通知機構の欠陥の観測として扱う。通知が指示する終端に従うことと、観測した欠陥の処置を確定することを別の工程として両方行う。処置は同一セッション内の是正、または`agent-toolkit:wi-standards`に従うAWI投入の提案とし、いずれかを実施して終える。同じ欠陥を扱う未終端のWIが既にある場合は、そのWIの参照を処置として扱える。通知が「対象外なら何もせず終える」と指示する場合も、その指示が定めるのは個々の通知への応答だけである。通知機構自体の欠陥に対処するかは本項が定める。通知の指示に従う終端が処置の発議を省く根拠になると、同じ欠陥が別のセッションで繰り返し発生する
