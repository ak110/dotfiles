# 問題を見つけたときの対処

対処の候補を選ぶ前に「判断指針」の3段判定を適用し、許容されない対象、操作、副作用を候補から除く。
対処案の構造比較には`agent-toolkit:writing-standards`の`references/design-heuristics.md`「設計案の予備選別」を適用する。

作業中に発見した問題は、同スキルの「初動と拡張原因分析の判定」に従う。
原因分析の要否判定、原因分析、類似見直しおよび対策・横展開処置・再発防止策の確定は同スキルに従う。

- 自分の作業で導入していない既存不良を見つけた場合は、同じセッションで類似見直しと再発防止策まで是正し終える。同スキルの初動判定で拡張原因分析を要する不良、または類似見直しか再発防止策を要する不良は、元の作業と文脈を分けるため`${CLAUDE_PLUGIN_ROOT}/share/defect-investigation.parent.md`に従って調査を委譲する。修正は返った対策に従い、見つけた主体が元の文脈で行う。拡張原因分析を要さず1箇所で是正が完結する軽微な不良は、見つけた主体がその場で直す。委譲先として動作する主体が担当範囲外の不良を見つけた場合は、`agent-toolkit/rules/01-agent.md`「完遂と先送り」に従って呼び出し元へ返す。処理回を担うスキルが不良の扱いを定める場合は、そのスキルの手順に従う
- 終了コードが0でも出力に警告が含まれる場合は対処する。警告は処理の一部が未適用または未完了であることを示す場合があり、成否は終了コードと警告の不在の両方で判定する
- ユーザーが示した要件を変える変更と、`agent-toolkit:confirmation-and-uwi`の`references/judgment.md`「認可を要する操作」に当たる対処はユーザー確認し、合意を得てから着手する。要件を満たす手段の選択は`agent-toolkit:confirmation-and-uwi`「確認要否の判定」で決める。内部実装に閉じる対処は自律的に完遂する。ただし依頼が調査、確認または報告だけを求める場合は、内部実装に閉じる対処にも「完遂と先送り」が定める成果物の種別による範囲を適用し、着手の可否を確認する
- フック、ツール、実行環境のいずれかが挿入した通知について、通知が挙げる対象が自身の担当に属さないこと、通知が求める処置をこのセッションで実行できないこと、通知の前提が実在しないことのいずれかを観測した場合は、その観測を通知機構の欠陥の観測として扱う。通知が指示する終端に従うことと、観測した欠陥の処置を確定することを別の工程として両方行う。処置は同一セッション内の是正、または`agent-toolkit:wi-standards`に従うAWI投入の提案とし、いずれかを実施して終える。通知が「対象外なら何もせず終える」と指示する場合も、その指示が定めるのは個々の通知への応答だけである。通知機構自体の欠陥に対処するかは本項が定める。通知の指示に従う終端が処置の発議を省く根拠になると、同じ欠陥が別のセッションで繰り返し発生する
