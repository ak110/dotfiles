# レビューイー側心得

本スキルは、レビュー指摘、改善提案、ユーザーの割り込みや是正要求、作業中の想定外の発見を受領した主体が、修正の必要性を立証し、安全な修正と検証を完了するための知識を提供する。
以下では、これらを是正要求等と呼ぶ。
是正要求等の根拠となる原文、対象への適用条件及び現在の成果物を最初に確認せよ。

## 修正要否の立証

指摘は、観測事実、違反する目的又は契約、対象への適用条件、通常運用で生じる実害及び裏付けを照合して採否を確定する。
いずれかの根拠が不足する行は採否を確定せず、証拠不足の範囲と必要な検証をレビュー工程へ返す。

レビュー担当の指摘は、レビュー担当が立証済みの事実として扱わない。
各指摘の事実と違反契約を自身でも実測する。
対象実装と契約本文の実読、公式一次資料又は実機再現により、通常運用での再現経路及び消費主体への影響を独立に測定する。
裏付けを取得できない是正要求等は修正対象から分離し、証拠不足の範囲と必要な検証をレビュー工程へ返す。
好み、将来仮定、目的外改善、対象外の入力前提か異なる脅威モデルだけで成立する候補は採用しない。

採否確定前に、問題と手段の比例性を独立に再判定する。
レビュー担当の修正方針を新しい要件として扱わず、複写するだけで採用しない。
何も変更しない案を含め、残置した場合の実害と認知・保守費用、修正・検証・再レビューの費用、変更が増やす複雑性を同じライフサイクルで比較する。
実害がなく意味も変えない単独の誤記は、独立した修正と再レビューを起こさない。
同じ成果物に重大な修正があり再レビューする場合は、追加費用が小さい誤記も同時に是正する。
エンドユーザー向け文書の誤記と適用対象のスタイル違反、重大な実害、明示要件違反、公開契約違反及びセキュリティ欠陥は、費用だけを理由に残置しない。
比較階層と比例性の判定は、`../review-standards/references/judgment-details.md`を解決して正本とする。

計画ファイルの章構成、段落構成、表現選択、書き方又は情報配置だけを変える指摘は採用しない。
記述間の矛盾は、実装時の判断で解消できず、計画の実施可能性か公開契約を損なう場合だけ採用する。
いったん不採用とした案を再採用する場合は、不採用時の原文と根拠を読み直し、当時の理由が失効したことを現行の実測で確認する。
理由の失効を確認できない場合は再採用せず、必要な判断を呼び出し元へ返す。

## 安全な修正

修正が必要だと立証できた場合だけ、確認した欠陥を解消する必要十分な対策だけを選ぶ。
最小差分ではなく、元の目的、公開契約及び原因に対して必要十分な変更範囲を採用する。
同じ違反契約が通常運用で再現する範囲を実装コード、テスト、規範文書と計画本文から検索し、成立する欠陥を同じ修正回で一括修正する。
文字列、見出し、目的語又は接続関係だけが似る箇所は修正範囲へ含めない。
検索方法、確認した範囲、各箇所の採否及び修正との対応を、呼び出し文脈が指定する成果物へ記録する。

修正前に、同じ対象の過去の指摘、採否、ユーザー合意、設計理由及び事故対策を確認する。
過去の不採用理由が失効していない案、保持対象、除外範囲か既存の成功経路を、局所修正の都合で変更しない。
修正に永続状態、所有権、期限、復旧経路か互換経路の新設が必要な場合は、元の目的と非目標へ差し戻す。
計画又は上位設計が指定した方式で契約を満たせない場合は条件追加を重ねず、不成立の理由と実測を呼び出し元へ返す。

直前の修正後に同じ問題が再発した場合、局所修正を止め、現在の設計の維持、再設計、簡素化及び撤去を比較する。
欠陥を解消し、新たな問題を作成しない案を立証できない場合は、追加修正を確定せず、比較した案と確定できない理由を呼び出し元へ返す。
ラウンド数、指摘の分類、記録と収束判定は、呼び出し文脈が指定するレビュー調整側の正本へ委ねる。

## 公開可能性の検証

採用した各是正要求等について、違反契約の原文を修正後の成果物へ再適用し、違反が解消したことを確認する。
変更全体を通読又はレビューし、元の目的、明示要件、公開契約、保持・除外対象及び既存の成功経路を維持していることを確認する。
修正で新たに書いた内容は、確度、因果及び出所を点検し、推量の断定、未実測の一律帰属及びエージェント判断のユーザー由来化を除く。
対象の選択条件又は解決条件を変更した場合は、判定に用いる全入力と全分岐を実読し、対象集合の過不足と変更しない入力の結果を確認する。

変更に最も近いテスト、lint、format、型検査、生成物同期と、呼び出し文脈が定める全体検査のうち該当するものを実行する。
失敗、警告、検証不足の範囲と修正による新たな問題を残したまま完了しない。
成果物が修正直後の状態で公開されても事故を起こさないと、実測結果と自己点検から説明できる状態だけを修正完了とする。
説明できない場合は修正を確定せず、不足する検証又は判断を呼び出し元へ返す。

レビュー表が指定された場合は、渡された修正対象の`track`集合だけを扱う。
渡された集合の外に属する`track`の行を採否判断と更新の対象にせず、`atk review-table`の公開CLI契約に従って応答と検証を完了する。
盲検系レビュー担当へ渡す情報は自ら拡張しない。
