# レビューイー側心得

本スキルは、レビューイーが指摘を検証し、採否と修正を確定する際の知識を提供する。
指摘の根拠となる原文と対象への適用条件を最初に確認せよ。
レビューを実施する主体は`agent-toolkit:review-standards`を用いる。

## 指摘の検証

指摘が根拠とする原文と対象への適用条件を確認し、指摘の成立性と修正方法を別々に確定する。
各指摘の事実と違反契約を自身でも実測する。
根拠又は適用条件が不足する指摘は再取得するか`未検証`へ分離する。
好み、将来仮定、目的外改善、裏付けの無い候補は採用しない。

重大度ラベル付きの指摘では、受領した指摘が持つ値をそのまま用い、重大又は中程度の実在欠陥だけを採用する。
重大度を持たない指摘や改善提案では、観測事実、違反する契約、利用者影響への対応から採否を確定する。
重大度の定義を照会する目的でレビューアー側スキルを読み込まない。

## 採否の独立確定

採否確定前に、指摘を通常運用の再現経路と入力主体へ照合し、問題と手段の比例性を独立に再判定する。
対象外の入力前提又は異なる脅威モデルだけで成立する候補は不採用とする。
レビュー担当の修正方針を新しい要件として扱わず、複写するだけで採用しない。
修正に永続状態、所有権、期限、復旧経路、互換経路の新設が必要な場合は、元の目的と非目標へ差し戻す。
比較階層と比例性の判定は`agent-toolkit:review-standards`の`references/judgment-details.md`を正本とする。

## 修正の実施

成果物に責任を持つ最上位の主体が確定した範囲内で最小限に修正する。
採用指摘と同じ混入要因、動機的要因、見逃し原因が及ぶ箇所を確認し、成立する欠陥を同じ修正回で一括修正する。

## 修正後の自己点検

採用した各指摘について、指摘が引用した違反契約の原文を修正後の成果物へ再適用する。
当該箇所で違反が成立しないことを確認する。
保持契約と合意済みの除外・保持が維持されていることを確認する。
呼び出し文脈が定める検証の再実行を完了する。

修正で新たに書いた文は、採用指摘が引用した契約に加えて確度、因果、出所を点検する。
確度は提示素材・観測が推量に留まる事項を断定へ変えないこと、
因果は実測で裏付けていない一律帰属を書かないこと、
出所はエージェントが導出した理由を利用者由来と解釈され得る形で並置しないこととする。
確度を弱める場合は、根拠となる観測範囲を同じ文へ残す。
修正で対象の選択・解決条件を新設又は変更した場合は、判定に用いる入力（外部コマンド出力の全項目、実装の分岐、設定の全経路）を実読し、選択条件が対象集合を過不足なく定めることを確認する。

## 詳細手順

計画・設計の採用案や指摘・発見の妥当性を評価する場合は、
`agent-toolkit:review-standards`配下の`references/judgment-details.md`を併せて全文読む。
