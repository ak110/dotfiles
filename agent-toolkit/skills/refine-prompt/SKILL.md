# プロンプトの改善案の検討

エージェントへの指示文を前提知識の無いプロンプト評価担当に読ませて指摘を集め、メインが改善案と採否を確定して反映する。
評価担当の入力・手順・出力は`${CLAUDE_PLUGIN_ROOT}/share/refine-prompt.subagent.md`、起動と受領は本書「プロンプト評価担当の起動と受領」が定める。

評価担当の起動と試行には委譲手段、参照資料と対象の実行機能が必要である。これらが無い場合は、提示されたプロンプトを本セッションで直接評価し、直接評価であることと未実施の試行を明示する。独立した担当による試行とファイルへの反映は、それらを行えるClaude CodeまたはCodexで続ける。指摘と改善案の文には[文章の品質基準](references/quality-standards.md)を使う。

## 読込表

次の時点または条件が成立したら、その操作の前に同じ行の資料を全文読む。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 改善案を作成する前（エージェント向け文書が対象の場合） | `agent-toolkit:writing-standards`の「エージェント向け文書の編集時に読む資料」 |
| 対話と成果物を評価する多ターン試行を選んだ時と結果を受領する時 | `references/multi-turn-trials.md` |
| 実セッションから小課題を作り、条文変更の効果を比較する方法を選んだ時 | `references/multi-turn-trials.md` |

## 使用条件

frontmatterの条件に加えて、頻繁に使うskillや自動化の中核プロンプトを堅牢化したい場合にも使う。
単発利用のプロンプト（起動コストに見合わない）と、書き手の主観的選好を反映したいだけの場合は対象外とする。この対象外は本スキルという手段の選択に限り、プロンプトの欠陥がQに影響する問題なら処置の要否は`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「QとC・Dの区別」に従う。
挙動の不一致を問題として調べる場合は、原因を指示の曖昧さと決めつけず、評価や追記案の選定より前に`agent-toolkit:bugfix`を起動する。その初動・原因分析・対策選定の結果、指示の改訂を評価する必要があれば本スキルを使う。一般のプロンプト改善はこの条件と分けて扱う。

## ワークフロー

Plan modeの外で実行する（Claude Codeでは`ExitPlanMode`で抜ける）。本スキルは元の依頼の計画作成要否を変えないため、`agent-toolkit:plan-mode`の呼び出しは不要である。

1. `agent-toolkit:writing-standards`を呼び出す。問題を起点とする評価では「使用条件」で確定した原因と対策の範囲を入力とし、評価担当の指摘を原因の確定に代えない。
2. 対象を確定し、シナリオへ適用する読取専用の単発評価、シナリオなしの批判的通読、実操作・対話・成果物を採点する多ターン試行から目的に合う方法を選ぶ。単発評価は指摘の返却で完結する。シナリオは反復の間も初回の内容を保つ。シナリオを反映に合わせて易しくすると、改訂前後の評価を比べられなくなる。
3. 対象の分量と論点数から評価担当の数を決めて起動し、指摘を受領する。
4. 指摘を集約して改善案を作成し、「指摘の集約と改善案作成」に従って採否を確定し反映する。
5. ユーザーが対話による採否・反復を求めた起動では、続行か終了かをユーザーに確認する。続行では新しい評価担当を起動して再評価する。品質確認のためエージェントが起動した場合は、必要な評価と反映を終えたら確認せず元の依頼の残工程へ進む。反映後は対象の編集手順を定めるスキル、`agent-toolkit:check-execution`、`agent-toolkit:completion-report`の工程へ進む。

委譲手段（`agent-toolkit:delegation`）を利用できない環境では、同一セッション内で直接評価し、結果提示時に「プロンプト評価担当を起動できないため直接評価」と明記する。
多ターン試行は`references/multi-turn-trials.md`の独立した両役を起動できる環境で手動実行し、結果の差を同じ事例での観測として受領する。
既存の固定課題と単発評価で判断できる場合はそれを使い、実セッション由来の比較が採否を変え得る場合だけ、同資料「実セッション由来の小課題による比較」を選ぶ。

## 指摘の集約と改善案作成

メインが意図を保って重複・近接をまとめ、`agent-toolkit:review-standards`と`references/reviewee.md`で採否を判定する。定義元の転記要求は`agent-toolkit:writing-standards`の`references/agent-documents-basics.md`「定義の所有者」で判定する。
採用する指摘には改善案のdiffを作成する。評価担当の出力はユーザーへ直接表示されないため、指摘は原文に近い形で残す。

- 品質確認のためエージェントが起動した場合は、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」で技術指摘の採否を自ら確定し、目的・結果の変更やユーザーだけの選好・認可が残る部分だけを問う
- ユーザーが対話による採否を求めた起動では、後掲の書式で提案を示し、回答可能な件数ずつ確認する。質問の組み方は`agent-toolkit:user-confirmation-and-report`「確認の選択肢を組む手順」に従う。Claude Codeでは`AskUserQuestion`の`multiSelect`で最大4件ずつ、`label`を「提案N: <変更対象>」、`description`へ変更前後の要点を書く。片方だけ採ると本文が矛盾する提案は同じ選択肢にまとめる。チェックを採用、未チェックを却下とし、修正したい場合は「Other」欄へ番号と修正内容を書くよう質問本文で案内し、その指示に沿って反映する

### ユーザー提示フォーマット（1件ごとに繰り返す）

````text
### 提案 N: <変更対象を1行で>
- 指摘元: <プロンプト評価担当が報告した該当箇所と問題内容を1〜2文で>
- 変更理由: <なぜ変更すべきか1〜2文>
- 変更内容: 以下のdiff形式で示す。新規追加なら`+`のみ、削除なら`-`のみでよい

  ```diff
  - <現在の文言>
  + <変更後の文言>
  ```

- 期待効果: <この変更で何が改善するか1文>
- 追随対象: <採用時に追随する他の文書・記述。無い場合は「なし」>
- 種別: 加筆 / 書き換え / 削除
````

## プロンプト評価担当の起動と受領

```text
起動対象: refine-prompt.subagent.md
```

`agent-toolkit:refine-prompt`を実行するエージェントが、本書に従ってプロンプト評価担当を起動し、指摘を受領する。
プロンプト評価担当の手順と返却形式は`${CLAUDE_PLUGIN_ROOT}/share/refine-prompt.subagent.md`が定める。

### 起動

評価する指示文をUTF-8のファイルへ保存し、`agent-toolkit:refine-prompt`のワークフローが決めた体数を同じ入力で並行して起動する。`agents_server`の`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 対象プロンプトを保持するリポジトリの絶対パス |
| `subagent_md_path` | `refine-prompt` |
| `extra_params` | 次の名前付き入力だけ |

- `対象プロンプト`: 対象プロンプトの名前と、本文を保存したファイルの絶対パス
- `シナリオ`: ワークフローで決めた状況設定の1段落。シナリオを与えない場合は`なし`

単発評価は読取専用で指摘の返却までを完結させる。
委譲元は入力と返却を当初の目的・現行要求と比べて検収する。記録の更新は`share/work-contract.md`「更新する時点」に従う。

再評価では前回の担当を継続せず新しく起動する（前回の指摘と反映を知る担当は評価が偏る）。シナリオは初回の内容のまま渡し、反映に合わせて容易にしない。

### 受領

結果は引数なしの`atk agents wait`で受け取る。返却が`${CLAUDE_PLUGIN_ROOT}/share/refine-prompt.subagent.md`「出力」の形式に合わない場合は、同じ入力で1回だけ新しい担当を起動し直す。
指摘の統廃合、取捨選択と改善案の作成は`agent-toolkit:refine-prompt`「指摘の集約と改善案作成」に従う。

多ターン試行では同参照文書の自由本文の委譲を使い、両役の終端、全対話、提出物と採点結果を受領する。
既存のプロンプト評価担当の指摘リストへ多ターンの結果を混ぜず、機能、隠した要件、対話の判定を事例別に読む。
