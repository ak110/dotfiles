# 計画モード

計画ファイルを作成し、承認後の実装を`plan-impl-executor`へ引き継ぐ。
計画はユーザーが結果と判断を確認でき、fresh sessionの実装者が必要な材料を取得できる状態にする。

## 進め方

1. 適用規範、変更対象全文、定義・参照・呼び出し元、既存テスト、生成・配布経路、類似実装を調査する
2. 技術的に確定できない利用者依存事項だけをモード別の確認へ送る
3. 調査工程を完了してから、メインが計画ファイル初版を起草する
4. `references/plan-review-delegation.md`に従い機械検査と総合レビューを別系統で実施する
5. 計画ファイル、成立させる結果、ユーザー指示との差分、レビュー反映状況を提示する
6. 承認後に`references/plan-impl-caller-reception.md`を読み、`plan-impl-executor`へ引き継ぐ

バグ対応では`agent-toolkit:bugfix`を起動し、直接的原因、深掘り要否、必要な原因区分、
類似見直し、是正・横展開・再発防止を確定する。
委譲を用いる工程では`agent-toolkit:delegation`を起動し、経路固有の条件だけを操作直前に読む。

## 計画ファイルの完成条件

計画は別コンテキストの実装者が必要十分な判断材料を取得できる実装契約とする。
表現形式を目的化せず、変更の性質に応じた説明単位と粒度をauthorが選ぶ。

`## 目的`、`## 実装契約`、`## 完了条件`、`## 進捗ログ`を一意に記載する。
4つの意味アンカーの順序は固定せず、追加H2を許容する。
H1、全文diff、ファイルごとのH3、コードブロック、現行行数、標準実行順序、計画自身のパスは必須としない。

### 目的

利用者が得る成果、解消する問題、利用者合意を記載する。
実装方法から独立して観測できる結果を優先する。

### 実装契約

対象範囲と、現行実装から安全に再取得できない判断、制約、必要な順序、生成・配布経路を記載する。
変更説明は共通方針、ファイル群、個別差分、正確な文面のうち必要十分な形式を選ぶ。
対象一覧の各パスは個別説明または明示したファイル群のいずれかから変更契約を特定できる状態にする。
同じパス集合を所属表やファイル別見出しへ重複して記載しない。

一般的なコード構造、標準のcommit・レビュー手順、リポジトリから再取得できる全文は省略できる。
利用者合意と異なる判断、実装者が安全に決められない選択、通常と異なる順序は省略しない。

### 完了条件

利用者が観測できる成果と、実装者が成否を判定できる検証条件を記載する。
外部仕様や実行時挙動に依存する事実は一次資料か実機実行で裏付ける。

### 進捗ログ

計画作成中は調査とレビューの現在状態をauthorが記録する。
実装開始後は呼び出し元を既定の書込主体とし、各commit単位の受領時と最終レビュー時に
現在状態、commit、検証結果、計画との差異、blockerを更新する。
固定表、route、thread、全操作履歴は要求しない。

### 計画メタ情報

`## 実装契約`直下の`### 計画メタ情報`へ、対象リポジトリ、完全長のベースコミット、作業種別を記載する。
作業種別は`- 作業種別: <固定値>`の記法とし、固定値には`バグ対応`または`通常変更`を用いる。
コロンはASCIIの`:`、コロン後は半角空白1字とする。

### バグ調査結果

バグ対応では`agent-toolkit:bugfix`の`references/root-cause-analysis.md`に従い、
確定したバグ単位、原因区分、類似見直し、3処置を実装契約から特定できる状態にする。
固定の表、見出し名、行順序は要求しない。

### 対象ファイル一覧

`## 実装契約`直下の`### 対象ファイル一覧`へ全対象を通常箇条書きで列挙し、対象範囲のSSOTとする。

```text
- `<パス>`
- `<パス>`（新設）
- `<パス>`（削除）
```

パスは対象リポジトリ相対で記載する。
既存対象、新設対象、削除対象の注記はベースコミット上の状態と一致させる。
同じパスを重複させず、コードフェンス内の類似箇条書きは対象一覧に数えない。

### 機械検査

`scripts/check_plan_file.py`は4アンカー、最小メタ情報、対象一覧の空・重複・危険パス、
ベースコミット上の対象状態、未閉鎖フェンス、呼び出すskill・agentの実在を検査する。
`--base-commit`指定時は実差分と対象一覧の不一致もエラーにする。
意味の妥当性は総合レビューで確認する。

## 計画ファイルの保存

保存先は`~/.claude/plans/<stem>-<rand>.md`とし、`<rand>`は`openssl rand -hex 2`の実行結果を使う。
初版作成前にnoclobberで占有し、成功直後に同じパスを読み、本文全体を書き込む。
既存計画は改名せず、同じパスを改訂する。

## 計画作成プロセス自体を変更する場合

工程、検査、レビュー経路を追加する改訂では、同一改訂内で簡素化または撤去も比較する。
恒常費に見合わない工程を追加しない。
