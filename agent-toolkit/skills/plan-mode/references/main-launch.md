# メインによる起動の実装と終端

本書は`agent-toolkit:plan-mode`をメインが起動した場合の、計画作成後の実装、実行レビュー、保存と報告の工程を定める。

メインによる起動では、要求を受け取ったメインが計画の起草、実装、実行レビューの反映および保存までを自ら所有する。
専用worktreeを作成せず、要求を受け取った時点の作業ディレクトリが属する作業ツリーで、メインが自ら実装する。

1. `agent-toolkit:writing-standards`の該当資料を読み、計画の`## 要件・外部仕様`に従って実装する。`### 受入シナリオ`の各行に対応する公開された呼び出し手段（コマンド・画面・API・hookなど）を通る結合・E2Eテストを実装単位へ含めて変更範囲の検証で実行し、シナリオ別のテスト名と合否を検証結果へ記録する。手動観測では入力と結果をmanaged-tempの中へ保存する。`## 検証`の変更範囲を検証し、commitする。実装単位ごとのcommitとコミットメッセージは`agent-toolkit:commit`に従う
2. `${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`に従って実行レビュー指摘管理表を準備し、同書の起動入力と生成された返却の受領手順を使う。完成条件証拠は担当が初回に生成する出力先として渡し、メインは雛形を事前生成しない。画面差分があれば同じ対象HEADのユーザビリティレビュー担当と実行レビュー担当を並列に起動し、修正後も並列に再判定する。指摘への修正はメインが実施し、修正commitの履歴統合は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`「レビュー修正の履歴統合」と同じ順序で行う
3. 終端前に、同じ共通parentの整合確認で生成された実行レビュー未解決0件を確認する。返却の`想定外事象:`が伝える差分外の既存不良も、同parentの受領手順で取得して処置へ渡す。画面差分では同じ対象HEADのユーザビリティレビューの`合格`または`未確定`も確認する。リポジトリ全体を対象とする自動チェックとCIの成否は公開工程で判定し、変更範囲の検証の成功は実行工程で判定する
4. `atk run-script plan-progress --`で`## 進捗ログ`へ完了判定を記録し、`atk plans commit <計画ファイル名>`で保存する。`agent-toolkit:completion-report`の公開工程を適用し、報告する
