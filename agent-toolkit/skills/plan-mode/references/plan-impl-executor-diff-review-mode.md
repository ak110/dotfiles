# plan-impl-executorの差分限定レビュー調整モード

## 入力

- 対象worktree、着手前SHA（発火元の生成規則で確定した完全OID）及びレビュー対象の現行HEAD完全OID
- 変更ファイル一覧（`対象ファイル限定`としてレビュータスクへ渡す解消箇所・累積差分の変更ファイル）
- 照合先計画パス一覧
- 検証コマンド（発火元が指定する検証区分。手順6はレーン内検証）
- 実装レビュー用managed temp領域の絶対パス
- 再レビュー時は今回のレビュー表と修正対象となるレビュー表の絶対パス

発火元はレーンworktreeでの競合解消、統合後検証、上流進行rebase後の3つである。本executorが起動されるのは手順6の競合解消だけであり、手順10・12では本executorを起動しない。

## 準備とレビュー

実装担当の工程とcommit統合を開始せず、対象worktreeのHEADが受領したレビュー対象OIDと一致することを実測する。変更ファイル一覧がない場合、一覧のcommitが現行HEADの祖先でない場合又は必須入力が欠ける場合は`needs_escalation`で返し、マージ結果から範囲を補完しない。

レビュー対象は`merge_review_pending`が報告した解消箇所と、そのファイル内の累積差分に限定する。準拠系は関係計画ごと、盲検系は統合した`review_contract`で実施する。採用指摘は`execute_fix_model`で起動する差分限定レビュー修正担当へ渡し、指定された条件を検証する。修正commitだけを出力へ列挙する。

レビュー表と付随ファイルだけを指定された管理対象一時領域へ保存し、構造検証と実在・分量を検収する。準拠系では指摘と影響箇所へ適用される全計画を照合し、着手前SHAの公開契約へ承認済み変更を合成する。認可範囲外、計画間衝突又は適用条項との対応不能は実装担当へ渡さず`needs_escalation`で返す。

採用指摘の修正では修正用の実装担当を新規起動する直前に`atk config get execute_fix_model`を実行する。
`agent-toolkit:plan-mode`の実装担当契約、対象worktree、レビュー表の絶対パスと修正対象として確定した採用指摘の`track`集合を単一の`差分限定レビュー修正担当`へ渡す。
関係計画パス一覧、検証コマンド、規範、作成規範スキル及び`reviewee-standards/SKILL.md`も同じ担当へ渡す。
起動文へ担当種別を`差分限定レビュー修正担当`として明示する。履歴を書き換えず、`rewrite_guard: not_applicable`を維持する。
