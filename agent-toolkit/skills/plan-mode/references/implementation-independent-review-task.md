# 独立した実装差分レビュータスク

最終commitの成果物を、計画準拠系と独立した観点から読み取り専用で検査する。成果物を修正しない。

## 入力

- 対象worktree、プロジェクト規範、該当する作成規範スキル、`../../review-standards/SKILL.md`の絶対パス
- 計画着手前SHA、レビュー対象commit、変更ファイル一覧、検証結果
- `review_contract`: ユーザー目的、現行の公開契約、ユーザー合意、合意済みの除外・保持、入力生成主体、信頼境界、
  通常入力、対象外入力、誤許可と誤拒否の利用者影響
- 初回または再レビューの別。再レビューでは、同一thread継続でも新規起動でも、今回の系統・ラウンド表と対応`.lock`、及び同じ系統の過去全ラウンド表と対応`.lock`の絶対パスをラウンド昇順で並べた一覧を必須差分入力として受け取る
- 今回の系統・ラウンド（独立系）に対応する実装レビュー指摘管理表の絶対パス。指定されたmanaged temp領域内の
  `<ラウンド>-independent.tsv`と対応する同名`.lock`を用いる
- 再レビューでは、今回の系統・ラウンド表だけへ指摘を追加し、同じ系統の過去全ラウンド表と対応`.lock`の絶対パスをラウンド昇順で並べた一覧も受け取る。過去表へは追記しない。計画準拠系の表と対応`.lock`はこの一覧へ含めない

計画ファイル、進捗ログ、コミットメッセージ、計画準拠系を含む他レビューの出力は受け取らず参照しない。
ユーザー発話全文、作者の推論、変更意図、実装方針は含めない。

## レビュー

調整主体は初回strict検証の前に今回の表へ`atk review-table init <レビュー表>`を実行し、続けて`atk review-table validate <レビュー表>`を実行する。
各ラウンドの二系統並列レビュー起動前は調整主体が前ラウンドの独立系表を`atk review-table validate <レビュー表>`で検証する。レビュー担当はラウンド開始時に`atk review-table validate --allow-unanswered <レビュー表>`を実行して今回の表の構造を検証し、表を全文読んでから成果物を点検する。
再レビューのレビュー担当は、同じ系統の過去全ラウンド表をラウンド昇順で1つずつ`atk review-table validate <レビュー表>`へ渡して検証し、各表を全文読取する。過去表の先頭3列を今回の表へ追加せず、指摘は今回の系統・ラウンド表だけへ`atk review-table add`で追加する。
計画準拠系の表や出力を受け取らず、両系統の担当が終端した後に調整主体が各表を個別に統合する。
指摘はレビュー表へ`atk review-table add`で追加し、先頭3列（重要度・指摘箇所・指摘内容）の複合キーを変更しない。
レビュー表の列は重要度、指摘箇所、指摘内容、対応要否、対応内容、対応不要理由の6列に固定する。

- 差分、変更後ファイル、呼び出し元、参照元、テスト、生成・配布経路を必要な範囲で読む
- 公開契約、正確性、回帰、境界条件、安全性、テスト不足、規範適合を点検する
- 確定指摘の前に、欠陥が通常運用で発生する再現経路と入力主体を示す。
  対象外の入力前提又は異なる脅威モデルだけで成立する候補は除外する
- 修正方針が永続状態、所有権、期限、復旧経路、互換経路の新設を必要とする場合は、指摘化の前に元の目的と非目標へ戻る。
  何もしない案、既存操作だけの案、局所運用案、新機構案を比較し、単純案が目的を満たす場合は新機構を要求しない
- 共有の判定処理、振り分け処理、解析処理の変更では、変更分岐へ到達する全呼び出し元、未変更の既存test class、
  契約を示すdocstring・コメントの列挙を確認する。配列又は反復blockでは、0件、1件、複数件、異種混在、
  局所識別子の対応を確認する。書込担当の報告に不足があれば既存のレビュー工程内で列挙と実行を補う
- 計画との照合と実装漏れは計画準拠系が担うため、本系統の指摘として重複させない
- 初回は指摘候補を内部的に網羅列挙し、異なる観点で再走査してから確定指摘を一括して返す
- 再レビューは全修正とベースコミットからの累積差分全体を再監査する
- 第2回以降の新しい指摘は、計画時に判断可能だった事項、初回レビューの見逃し、直前の修正による混入の別を示す
- 指摘ごとに`review_contract`の違反条項、対象への適用根拠、
  実行結果、公式資料、実装箇所のいずれかの裏付けを示す
- 指摘の証拠、重大度、`未検証`の分離、報告形式は`../../review-standards/SKILL.md`を正本とする
- 対象worktreeを変更しない。起動前後のGit状態を報告する

## 出力

対象commit、点検範囲、`write_status: unchanged`を返す。
実在する指摘はレビュー表へ登録し、`指摘内容`に観点、`violated_contract`、対象への適用根拠、根拠及び修正方針を含める。
修正方針は`review_contract`を変更する認可ではない。
指摘がない場合は`指摘なし`と明記する。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
