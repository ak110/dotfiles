# 実装盲検レビュータスク

最終commitの成果物を、準拠系と独立した観点から読み取り専用で検査する。成果物を修正しない。

## 入力

- 対象worktree、プロジェクト規範、該当する作成規範スキル、`../../review-standards/SKILL.md`の絶対パス
- 計画着手前SHA、レビュー対象commit、変更ファイル一覧、検証結果
- 任意入力`対象ファイル限定`。計画着手前SHAからレビュー対象commitまでの差分のうち、
  指定されたファイルの差分だけをレビュー対象とする。範囲内の他ファイルは非レビュー対象として扱い、
  未レビューと扱わない。指定が無い場合は範囲の全差分をレビュー対象とする
- `review_contract`: ユーザー目的、現行の公開契約、ユーザー合意、合意済みの除外・保持、入力生成主体、信頼境界、
  通常入力、対象外入力、誤許可と誤拒否の利用者影響
- 初回または再レビューの別。再レビューでは、同一thread継続でも新規起動でも、今回のラウンド番号と今回のレビュー表の絶対パスを必須差分入力として受け取る
- 実装レビュー指摘管理表の絶対パス。指定されたmanaged temp領域内の`review.tsv`を用い、盲検系の`track`は`independent`とする
- 再レビューでは、今回のラウンドの指摘を同じ表へ`atk review-table add --round <ラウンド> --track independent`で追加する。過去ラウンドの行は変更しない。自系統以外の`track`の行や出力はこの必須差分入力へ含めない

計画ファイル、進捗ログ、コミットメッセージ、準拠系を含む他レビューの出力は受け取らず参照しない。
ユーザー発話全文、作者の推論、変更意図、実装方針は含めない。

## レビュー

盲検系のレビュー担当は、表の読み取りに`atk review-table validate --allow-unanswered <レビュー表>`と`atk review-table show --track independent <レビュー表>`だけを用い、表ファイルを全文読取しない。
指摘は`atk review-table add --round <ラウンド> --track independent`で同じ表へ登録する。
自系統以外の`track`の行や出力を受け取らず、実装差分を独立した観点から点検する。

- 差分、変更後ファイル、呼び出し元、参照元、テスト、生成・配布経路を必要な範囲で読む
- 公開契約、正確性、回帰、境界条件、安全性、テスト不足、規範適合を点検する
- 全レビュー系統へ共通する観点は`../../review-standards/SKILL.md`を正本とする
- 共有の判定処理、振り分け処理、解析処理の変更では、変更分岐へ到達する全呼び出し元、未変更の既存test class、
  契約を示すdocstring・コメントの列挙を確認する。配列又は反復blockでは、0件、1件、複数件、異種混在、
  局所識別子の対応を確認する。実装担当の報告に不足があれば既存のレビュー工程内で列挙と実行を補う
- 計画との照合と実装漏れは準拠系が担うため、本系統の指摘として重複させない
- 初回は指摘候補を内部的に網羅列挙し、異なる観点で再走査してから確定指摘を一括して返す
- 再レビューは全修正とベースコミットからの累積差分全体を再監査する
- 第2回以降の新しい指摘は、計画時に判断可能だった事項、初回レビューの見逃し、直前の修正による混入の別を示す
- 指摘ごとに`review_contract`の違反条項、対象への適用根拠、
  実行結果、公式資料、実装箇所のいずれかの裏付けを示す
- 指摘の証拠、重大度、`未検証`の分離、報告形式は`../../review-standards/SKILL.md`を正本とする
- 対象worktreeを変更しない。起動前後のGit状態を報告する

## 出力

対象commit、点検範囲、`write_status: unchanged`を返す。
実在する指摘はレビュー表へ登録し、`指摘内容`に観点、`violated_contract`、対象への適用根拠、根拠及び修正方針を含める。
修正方針は`review_contract`を変更する認可ではない。
指摘がない場合は`指摘なし`と明記する。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
