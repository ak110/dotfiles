# 独立した実装差分レビュータスク

最終commitの成果物を、計画準拠系と独立した観点から読み取り専用で検査する。成果物を修正しない。

## 入力

- 対象worktree、プロジェクト規範、該当author skill、`agent-toolkit:review-standards`の絶対パス
- 計画着手前SHA、レビュー対象commit、変更ファイル一覧、検証結果
- `review_contract`: ユーザー目的、現行の公開契約、ユーザー合意、保持対象、入力生成主体、信頼境界、
  通常入力、対象外入力、誤許可と誤拒否の利用者影響
- 初回または再レビューの別。再レビュー時は全採用指摘、修正結果、前回からの差分

計画ファイル、進捗ログ、コミットメッセージ、計画準拠系を含む他レビューの出力は受け取らず参照しない。
ユーザー発話全文、作者の推論、変更意図、実装方針は含めない。

## レビュー

- 差分、変更後ファイル、呼び出し元、参照元、テスト、生成・配布経路を必要な範囲で読む
- 公開契約、正確性、回帰、境界条件、安全性、テスト不足、規範適合を点検する
- 共有gate、dispatcher、parserの変更では、変更分岐へ到達する全呼び出し元、未変更の既存test class、
  契約を示すdocstring・コメントの列挙を確認する。配列又は反復blockでは、0件、1件、複数件、異種混在、
  局所識別子の対応を確認する。writerの報告に不足があれば既存のreview工程内で列挙と実行を補う
- 計画との照合と実装漏れは計画準拠系が担うため、本系統の指摘として重複させない
- 初回は指摘候補を内部的に網羅列挙し、異なる観点で再走査してから確定指摘を一括して返す
- 再レビューは全修正とベースコミットからの累積差分全体を再監査する
- 第2回以降の新しい指摘は、計画時に判断可能だった事項、初回レビューの見逃し、直前の修正による混入の別を示す
- 指摘ごとに`review_contract`の違反条項、対象への適用根拠、
  実行結果、公式資料、実装箇所のいずれかの裏付けを示す
- 指摘の証拠、重大度、`未検証`の分離、報告形式は`agent-toolkit:review-standards`を正本とする
- 対象worktreeを変更しない。起動前後のGit状態を報告する

## 出力

対象commit、点検範囲、`write_status: unchanged`を返す。
実在する指摘には`I-<通番>`、重大度、観点、箇所、内容、`violated_contract`、
対象への適用根拠、根拠、修正方針を含める。修正方針は`review_contract`を変更する認可ではない。
指摘がない場合は`指摘なし`と明記する。
