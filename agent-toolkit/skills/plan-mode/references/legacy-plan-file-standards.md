# 旧形式計画ファイルの読み取り互換基準

本書は、旧単一ファイル形式（対応する`<stem>.detail.md`を持たない形式）と、旧二ファイル形式（`<stem>.detail.md`が実在する形式）を読み取るための判別条件と列名を示す。
いずれの旧形式も既存計画の読み取りだけに用い、新規計画は現行書式で生成する。
受理する値の正本は`agent_toolkit/_plan/structure/constants.py`の読み取り互換定数とする。

既存計画に残る旧綴りの固定記法（計画メタ情報の`実装詳細`行、`- バグ調査ファイル:`で始まる参照行、旧rootと旧絶対パス、`<計画stem>.tsv`のレビュー表）は読み取り互換として受理する。
既存のID、系統名及び表は現在の値のまま保ち、新規計画では現行書式の値を使う。構造検査は旧形式を受理し、現行書式への移行をwarningで案内する。

## 旧形式の判別

対応する`<stem>.detail.md`の実在により、旧二ファイル形式と旧単一ファイル形式を分ける。
detailが実在しない場合は旧単一ファイル形式として検査する。

旧単一ファイル形式の固定H2は次の順とする。`## バグ調査結果`は作業種別がバグ対応の場合だけ置く。

1. `## 概要`
2. `## 実施内容`
3. `## 提示素材`
4. `## 変更履歴`
5. `## バグ調査結果`
6. `## 恒久化・リファクタリング内容`
7. `## 実装資料`
8. `## 完了条件`
9. `## 進捗ログ`

旧単一ファイル形式では人間向け固定領域を`## 概要`から`## 変更履歴`まで、実装者向け領域を`## 変更履歴`直後から`## 進捗ログ`直前までとする。

旧二ファイル形式が受理するメインH2には次の2系列がある。

1. `## 概要`、`## 実施内容`、`## エージェント提案詳細`、`## 提示素材`、`## 変更履歴（計画時）`、`## 検証区分`、`## 終端工程`、`## 進捗ログ（実行時）`
2. `## 概要`、`## 実施内容`、`## 提示素材`、`## 変更履歴`、`## 検証区分`、`## 終端工程`、`## 進捗ログ`

対応する`<stem>.detail.md`の固定H2は、`## 恒久化・リファクタリング内容`、`## 実装資料`、`## 完了条件`の順である。
計画メタ情報は`起動経路`、`対象リポジトリ`、`作業種別`、`ベースコミット`及び`計画ファイル（詳細）`を持ち、`実装詳細`は最後の項目の旧名として受理する。

## 読み取る表の列名

- `## 実施内容`: `実施内容`、`採否`、`ユーザー指示との関係`、`根拠`。さらに古い形式では`採否`を持たない3列
- `## 提示素材`の素材表: `素材ID`、`種別`、`キューID`、`投入元`、`引用範囲`
- `## 提示素材`の要求表: `要求ID`、`素材参照`、`実装に必要な要件`、`採否`、`採用範囲`、`除外範囲`、`根拠`
- `## 変更履歴（計画時）`又は`## 変更履歴`: `ID`、`起点`、`指摘内容`、`採否・現在の結論`、`同期先`
- `## 検証区分`: `区分`、`検証コマンド`の2列で、`レーン内検証`、`統合後検証`の2行
- `### 実装単位`: `単位ID`、`目的`、`先行依存`、`統合順`、`近接検証`。さらに古い形式では`対象の実施内容`を加えた6列
- `### 合意済みの除外・保持`: `合意内容`、`対象と箇所`、`素材・要求参照`、`確認方法`
- `## 進捗ログ（実行時）`又は`## 進捗ログ`: `日時`、`完了した工程`、`結果・特記事項`
- 現行書式の`### 受入シナリオ`: 最終列を改名前の名前で持つ6列表。列の並びは`PLAN_LEGACY_ACCEPTANCE_TABLE_HEADER`が定め、現行の6列表と同じく列数と空セルを確かめる

素材IDは`P-`で始まる形式、要求IDは`R-<素材ID>-<3桁連番>`、実装単位IDは`U-[0-9]{3}`形式を受理する。
変更履歴のIDは`R<正の整数>-<系統名>`形式のほか、旧二ファイル形式の`C-`・`H-`形式と旧系統名、旧単一ファイル形式の`C-<3桁連番>`形式と`conformance`系統を受理する。
これらのIDは新規に採番せず、既存の値をそのまま保つ。

旧形式の`text`フェンスと`原文参照`列、原因分析表を持たない固定14行の旧調査表、本文内に調査表を持つ旧形式、統廃合前の行構成を持つ調査表も読み取り互換として受理する。

## 現行規範の所在

旧形式の列名に紐づかない規範は現行書式側を正本とする。
実施内容の記載粒度、採否の値、ユーザー合意との照合、参照元検索と計上は`plan-file-standards.md`が、ユーザー発話の解釈は`agent-toolkit/share/rules-main.md`が定める。
旧書式では、`plan-file-standards.md`が指す計上先を`## 実装資料`のファイル群別の変更説明と`## 完了条件`へ読み替える。
レビュー指摘管理表の列契約は`agent-toolkit/agent_toolkit/_atk/review_table.py`とそのテストを正本とする。
