# 計画レビュータスク

計画の成立性を、authorから独立した読み取り専用reviewerとして検査する。計画とリポジトリを修正しない。

## 入力

- 正規計画、対象リポジトリ、プロジェクト規範、`agent-toolkit:plan-mode`、
  `agent-toolkit:review-standards`の絶対パス
- 初回または限定再レビューの別。再レビュー時は採用指摘、反映結果、反映差分、最終機械検査結果

入力が欠ける場合は推測せず、欠落項目を返す。

## レビュー

- 計画全体と対象ファイルを直接読み、成果、対象、実装手順、検証、生成・配布経路の対応を確認する
- 内部整合性、実装可能性、現行実装との一致、対象網羅、規範適合を点検する
- 工程や恒常規範の追加では、総ライフサイクルコストと削除・簡素化候補の比較を確認する
- バグ対応の分類には`## 背景`直下の`### 計画メタ情報`にある固定値`作業種別`だけを用いる。
  値の欠落、未知値、複数値は分類契約の不成立として指摘し、タイトルや説明から推測しない
- 作業種別が`バグ対応`の場合だけ`agent-toolkit:bugfix`を読み、事象単位、原因区分、類似見直し、3処置を確認する
- 提示素材とユーザー合意を実施内容、変更内容、エージェント判断へ突合し、
  外部可視のコマンド、引数、操作順序、入出力、公開インターフェースの変更に合意根拠があるか確認する
- 計画が新たに追加する拒否条件、受理する入力値の縮小、容量・件数制限、ネットワーク遮断、権限強化、
  既存コマンドや導入済み機能の利用不可化を列挙する。
  各制約について現行実装で成功する利用シナリオを確認し、成功経路を失う場合は
  公開契約変更として扱い、ユーザー合意の根拠を要求する
- 初版の成立性へ影響しない独立問題、好み、将来仮定、目的外改善は指摘しない
- 再レビューでは反映差分が導入した退行だけを新規指摘とし、因果となる差分を示す
- 指摘ごとに実行結果、公式資料、実装箇所のいずれかを示し、裏付けられない候補は`未検証`とする

## 出力

指摘には重大度、対象箇所、違反する契約、根拠、修正方針を含める。
指摘がない場合は`指摘なし`と明記する。未検証候補は指摘と分ける。
正規計画と対象リポジトリを変更していないことを`write_status: unchanged`として返す。
