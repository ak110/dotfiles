# 計画レビューの直接委譲

`agent-toolkit:plan-mode`の呼び出し元が、正規計画の機械チェック・修正系と
総合レビュー系を直接管理する手順を定める。
呼び出し元は比較基準、全ラウンドの累積差分、採否、反映状態を保持し、
各委譲先は受信側task referenceが定める作業だけを担当する。

## 入力と状態

呼び出し元は正規計画ファイルと対象リポジトリの絶対パスを保持する。
継続時は次の値を省略せず、前回返却値をそのまま使う。

- 初回に保存した`scope_baseline`
- 全ラウンドの累積`scope_changes`
- 機械チェック・修正系と総合レビュー系のroute、thread、Agent識別子、所有主体、全応答履歴
- 累積`review_rounds`
- 確定済みの採否、反映結果、反映差分、最終機械検査結果
- 不採用内容を保持する`review_resolution`
- `初回レビュー前`、`初回レビュー後・採否確定前`、`採否確定後・反映前`、
  `反映後・再レビュー前`のいずれかの`continuation_state`

再開時に比較基準を現行計画から再計算しない。
routeまたは識別子が無い未開始系統は`not_started`と`なし`を記録し、履歴は`なし`、回数は0とする。

## 共通委譲契約

初回の計画レビューpromptはreview task reference、計画ファイル、対象worktreeの絶対パスを基本形とする。
referenceが定める規範、schema、報告書式をpromptへ再掲せず、今回限りの例外制約だけを追加する。

呼び出し元と各中間委譲先は、受領した次の制約を子孫の委譲先へ同じ意味で伝える。

- 作業場所: 対象リポジトリと正規計画の絶対パス
- 書込主体: 書込可能な主体と、その主体が書き込める正規計画の絶対パス
- 出力言語: 完了報告、指摘、成果物へ使用する言語
- プロセス所有権: 外部コマンドまたは背景ジョブを起動・停止できる主体
- 不可逆操作権限: 削除、復旧、git履歴変更、外部公開操作の可否と許可範囲

委譲前に、直接の呼び出し元が完了本文を受領できる経路を確定する。
通常のツール戻り値、完了通知、検収可能な記録のいずれも確保できない経路は使用しない。
中間委譲先は子孫の完了本文を自身で受領し、その結果を自身の完了報告へ含める。
子孫から祖先への直接送信を完了配送経路として前提にしない。

## 正規計画の直接検査

機械チェック・修正系だけが正規計画へ書き込める。
同系統は対象リポジトリを読み取り専用として扱い、着手時に正規計画全文と検査に必要な対象ファイルを読む。
総合レビュー系は正規計画と対象リポジトリを読み取り専用として扱い、着手時に正規計画全文と
レビューに必要な対象ファイルを読む。

レビュー中に共有作業ツリーが変化しても、その事実だけでは調査、レビュー、投入準備を無効にしない。
レビューの再実行またはエスカレーションは、計画要件自体の変更、正規計画への未検収の変更、
レビュー対象の成立性を変える事実を観測した場合に限る。
実装担当は着手時に現行実装を再読し、利用者向け成果を維持したまま実装手順を調整する。

## 初回機械検査と比較基準

書き込み可能な最初の委譲前に、初版の`### 実施内容`、
`### ユーザー合意済み事項`、`## 変更内容`の原文を取得する。
3要素の原文と内容ハッシュを`scope_baseline`として1回だけ保存する。

機械チェック・修正系へ`plan-codex-review-fix-task.md`の初回機械検査を委譲する。
同系統は`check_plan_file.py`、pyfltr、`check_dash.py`をこの順に正規計画へ実行する。
違反は正規計画だけで修正し、3検査を再実行する。
呼び出し元は各検査の初回と最終の終了コード、警告、正規計画の変更概要と前後SHA-256を検収する。
終了コード2または同じ失敗が2回続いた場合は、`continuation_state: 初回レビュー前`で未解決事項を返す。

## 外部実行と再現証跡

委譲先が外部コマンドまたは背景ジョブを保持する場合、完了報告へ所有主体、安定した実行識別子、
開始時刻、直近の生存確認時刻と結果を含める。
呼び出し元は成果物差分だけで停滞を判定せず、所有主体が提示した識別子を直接照会する。
実行が生存している間は差分が無くても停滞と扱わない。終了操作は所有主体だけが行う。
生存確認不能、識別子消失、終了後の結果未回収を区別して返す。

外部ツール・外部実行系の挙動を根拠とする指摘は、実行したコマンド、主要な環境条件、
終了コード、標準出力、標準エラーで裏付ける。
裏付けられない主張は確定事実として採用せず、`未検証`と明記して区別する。

## 総合レビューと指摘集合

初回機械検査の検収後、総合レビュー系へ正規計画と対象リポジトリ全体を1回委譲する。
応答を受領した時点で`review_rounds`へ1を加える。
重大または中程度の実在欠陥だけを指摘として受理し、受理した各指摘は次の2区分へ分類する。

- 初版内補正: 比較基準の対象パス、成果、合意、利用者が観測する挙動を変えず、矛盾または実装不能を解消する
- スコープ拡大: 比較基準の対象パス、成果、合意、利用者が観測する挙動のいずれかを変更する

初版を変更しなくても存在し、初版の成立性を損なわない独立問題はレビュー指摘として受理しない。

同一ラウンドの指摘は集合として扱う。各指摘が実装の成立性、公開契約、検証結果のどれへ
実害を与えるかを実測して採否を確定する。
改善提案、スタイル指摘、仮想上の問題、目的外の問題は指摘集合へ含めず、個別の修正往復を開始しない。

スコープ拡大は反映前に比較基準との差分、必要性、選択肢を返し、呼び出し元の承認を待つ。
機械チェック・修正系が各指摘の事実を実測して採否案を返し、呼び出し元が最終的な採否を確定する。

## 累積差分と反映

各レビュー応答と各反映後に、比較基準の3要素と現行の3節を要素別に比較する。
前ラウンドとの差分だけで判定せず、初版から現行までの総差分を毎回再計算する。
各差分へ区分、根拠、採否、承認状態、反映状態、反映結果を対応づけて`scope_changes`へ累積する。
過去の項目を削除または再採番せず、同じ差分の状態だけを更新する。

採否が1件でも未確定の場合は`continuation_state: 初回レビュー後・採否確定前`で返す。
採用した初版内補正と承認済みのスコープ拡大だけを機械チェック・修正系へ渡す。
同系統は判断を正規計画へ直接反映し、3検査で確認する。
呼び出し元は変更概要、前後SHA-256、検査結果を検収し、
`continuation_state: 反映後・再レビュー前`へ移る。

限定再レビューは同じ総合レビュー系を継続する。
入力は前回の採用指摘、確定済みの採否、反映結果、反映差分、最終機械検査結果とする。
新規指摘は直前の反映が導入した退行だけを受理し、因果となる差分と再現根拠を要求する。

## 継続経路と代替測定

同じ総合レビュー系を継続する前に、完了本文の受領経路が前回と同じく利用可能であることを確認する。
同じAgentを再開でき、直接の呼び出し元が完了本文を受領できる場合は同じAgentを使う。
受領経路を確保できない場合は、前回応答と確定済み状態を全文で渡せる新しい経路を使う。

Claude代替経路へ固定時間の優劣を仮定しない。各経路の開始時刻、完了時刻、再試行回数、
外部実行の生存確認結果、完了本文の受領成否を記録し、同じ入力条件で得た実測値から経路を選ぶ。
所要時間だけを理由に、生存中の外部実行を停止または重複起動しない。

## ラウンド上限と完了判定

初回レビュー1回と限定再レビュー4回を合わせ、累積5ラウンドを上限とする。
再起動時も受領した`review_rounds`を使い、値をリセットしない。
5ラウンド目は既知指摘の確定スナップショットとし、新規指摘を探索する第6ラウンドは開始しない。
技術的に解消できない重大・中程度の指摘、未承認のスコープ拡大、必須出力不足が残る場合は、
指摘全文、根拠、必要な修正、全継続値を`needs_escalation`で返す。

次の全条件が成立した場合だけ`status: completed`とする。

- 3検査の最終終了コードが0であり、未対処の警告が無い
- 正規計画の実体と検収対象の絶対パスが一致する
- 重大・中程度の指摘と、直前の反映が導入した同水準の退行を解消している
- `scope_changes`の全項目で採否、承認状態、反映状態が確定している

未解決事項がある場合は`needs_escalation`と`continuation_state`を返す。
正常完了時は一時ディレクトリの後始末を要求しない。
