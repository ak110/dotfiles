# 計画レビュー

計画authorが機械検査、指摘の検収、計画修正を所有し、独立reviewerへ成立性の評価だけを委譲する。

## authorの機械検査

初版の起草後、author自身が正規計画へ次を実行する。

1. `check_plan_file.py`

違反は正規計画で修正し、全検査を再実行する。終了コード、警告、修正概要を保持する。
機械検査を別のwriterへ委譲せず、正規計画の書込主体をauthor 1名に保つ。

## 独立reviewer

機械検査の成功後、`agent-toolkit:delegation`に従って独立reviewerを起動する。
起動文は受信者への命令を先頭に置き、次の絶対パスと今回のレビュー種別だけを渡す。

- `references/plan-review-task.md`
- 正規計画
- 対象リポジトリ
- プロジェクト規範
- `agent-toolkit:plan-mode`と`agent-toolkit:review-standards`

reviewerは正規計画と対象リポジトリを読み取り専用とする。
authorは起動前後のGit状態を比較し、reviewerの書き込みを検出した場合は結果を採用しない。

## 指摘の検収と修正

authorは各指摘の根拠を実測し、重大または中程度の実在欠陥だけを採用する。
好み、将来仮定、目的外改善、裏付けの無い候補は採用しない。
採否と対応結果を6列表へ統合してから、採用指摘を正規計画へ一括反映する。
スコープ、公開契約、ユーザー合意を変える修正はモード別の確認へ送る。

反映後はauthorが機械検査を再実行し、同じreviewerへ採用指摘、反映差分、検査結果だけを渡して限定再レビューする。
新規指摘は直前の反映が導入した退行だけを受理する。

同一箇所へ2ラウンド連続で指摘が出た場合は、小修正を反復せず当該計画部分を再設計する。
初回と限定再レビューを合わせて5ラウンドを上限とし、未解決の実在欠陥が残る場合は
指摘、根拠、必要な判断を`needs_escalation`として返す。

機械検査がエラー0で成功し、重大・中程度の指摘を解消し、未承認の変更が無い場合だけ計画レビューを完了する。
