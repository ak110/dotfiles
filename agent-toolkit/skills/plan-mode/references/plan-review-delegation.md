# 計画レビューの直接委譲

`agent-toolkit:plan-mode`の呼び出し元が、計画ファイルの機械チェック・修正系と
総合レビュー系を直接管理する手順を定める。
呼び出し元は比較基準、全ラウンドの累積差分、採否、反映状態を保持し、
各委譲先は受信側task referenceが定める作業だけを担当する。

## 入力と状態

呼び出し元は正規計画ファイル、対象リポジトリ、条件付き複製元の絶対パスを保持する。
複製元が無い場合は`対象外`を保持する。
継続時は次の値を省略せず、前回返却値をそのまま使う。

- 初回に保存した`scope_baseline`
- 全ラウンドの累積`scope_changes`
- 機械チェック・修正系と総合レビュー系のroute、thread、Agent識別子、所有主体、全応答履歴
- 累積`review_rounds`
- 確定済みの採否、反映結果、反映差分、最終機械検査結果
- 委譲単位の`review_workspace`、clone、計画原本コピー、レビュー用計画コピー、計画差分の絶対パス
- `out_of_scope_findings`、`required_same_session_findings`、不採用内容を保持する`review_resolution`
- `初回レビュー前`、`初回レビュー後・採否確定前`、`採否確定後・反映前`、
  `反映後・再レビュー前`のいずれかの`continuation_state`

再開時に比較基準を現行計画から再計算しない。
routeまたは識別子が無い未開始系統は`not_started`と`なし`を記録し、履歴は`なし`、回数は0とする。

## 共通委譲契約

呼び出し元と各中間委譲先は、受領した次の制約を子孫の委譲先へ同じ意味で伝える。

- 作業場所: 対象リポジトリ、レビュー用clone、正規計画、レビュー用計画コピーの絶対パス
- 書込主体: 書込可能な主体と、主体ごとの書込許可先
- 出力言語: 完了報告、指摘、成果物へ使用する言語
- プロセス所有権: 外部コマンドまたは背景ジョブを起動・停止できる主体
- 不可逆操作権限: 削除、復旧、git履歴変更、外部公開操作の可否と許可範囲

委譲前に、直接の呼び出し元が完了本文を受領できる経路を確定する。
通常のツール戻り値、完了通知、検収可能な記録のいずれも確保できない経路は使用しない。
中間委譲先は子孫の完了本文を自身で受領し、その結果を自身の完了報告へ含める。
子孫から祖先への直接送信を完了配送経路として前提にしない。

## 隔離レビュー作業領域

plan mode下の呼び出し元は正規計画ファイル以外へ書き込まない。
書き込み可能な機械チェック・修正系が、管理対象一時ディレクトリを次の完全コマンドで作成する。

    uv run --no-project --script <helper> create --prefix plan-review-workspace

Claude Codeでは`${CLAUDE_PLUGIN_ROOT}/scripts/_managed_temp.py`を使う。
Codexでは本referenceの絶対パスからplugin rootを確定し、
`<plugin rootの絶対パス>/scripts/_managed_temp.py`を使う。
標準出力の絶対パスを再生成せず保持し、その配下へ次の完全コマンドで隔離作業領域を作成する。

    uv run --no-project --script <plugin root>/scripts/_review_workspace.py create \
      --source-repo <対象リポジトリの絶対パス> \
      [--conditional-source-repo <条件付き複製元の絶対パス>] \
      --plan-file <正規計画ファイルの絶対パス> \
      --output-dir <管理対象一時ディレクトリ>/review

`create`は成功時に0、入力、取得、再現の失敗時に2を返し、成功時は次の絶対パスをJSONで返す。

- Git管理領域を共有しない`review_repo`
- 作成後に不変とする`original_plan`
- 機械チェック・修正系だけが書き込める`review_plan`
- 外部ツール主張の再現証跡だけを置く`reproduction_dir`
- 終了時に生成する`plan_diff`

helperは対象リポジトリの開始時HEAD、index、未ステージ差分、未追跡通常ファイルと
シンボリックリンクをcloneへ再現し、元状態との一致とGit管理領域の分離を検査する。
条件付き複製元がある場合は独立したsnapshotを取得し、作成中と終了時の不変を検査する。
cloneではルートの`.git`を除く全ファイルをGitの無視設定に依存せず一覧化する。
開始時と終了時の追加、削除、内容、mode、シンボリックリンク先の変更を検査する。
レビュー担当へはcloneと計画コピーだけを渡し、対象リポジトリと正規計画ファイルを調査入力へ含めない。
cloneは全系統で読み取り専用とする。総合レビュー系は計画コピーも読み取り専用とし、
機械チェック・修正系だけが`review_plan`へ書き込める。
各委譲先は自身の外部ツール主張を裏付ける証跡に限り、`reproduction_dir`へ書き込める。

委譲後は同じ機械チェック・修正系が次の完全コマンドを実行する。

    uv run --no-project --script <plugin root>/scripts/_review_workspace.py finish \
      --workspace-dir <管理対象一時ディレクトリ>/review

`finish`はcloneと正規計画が不変なら0、どちらかの変化を検出したら1、入力や比較の失敗なら2を返す。
完了報告にはJSONの`source_plan_unchanged`、`source_repo_unchanged`、`source_repo_compare`を保持する。
条件付き複製元がある場合は`conditional_source_repo_unchanged`と
`conditional_source_repo_compare`も保持し、無い場合は両方を`null`とする。
同じJSONの`review_repo_unchanged`、`review_repo_compare`、`review_files_compare`、`plan_changed`も保持する。
さらに、`plan_sha256_before`、`plan_sha256_after`、`plan_diff`を保持する。
終了コード0で得た`plan_diff`だけを呼び出し元が検収し、正規計画ファイルへ反映する。
終了コード1と2では反映せず、隔離作業領域を保持して原因と変更パスを返す。

対象リポジトリ、条件付き複製元、正規計画のいずれかが委譲中に別主体から変化した場合、
当該レビュー結果は使用しない。
元状態を自動復旧せず、現状態を新しい入力としてレビューをやり直すか、既存の保全・確認・復旧手順へ進む。

## 初回機械検査と比較基準

書き込み可能な最初の委譲前に、初版の`### 実施内容`、
`### ユーザー合意済み事項`、`## 変更内容`の原文を取得する。
3要素の原文と内容ハッシュを`scope_baseline`として1回だけ保存する。

機械チェック・修正系へ`plan-codex-review-fix-task.md`の初回検査を委譲する。
同系統は隔離レビュー作業領域を作成してから、`check_plan_file.py`、pyfltr、`check_dash.py`を
この順にレビュー用計画コピーへ実行し、違反を同ファイルだけで修正して3検査を再実行する。
呼び出し元は各検査の初回と最終の終了コード、警告、`plan_diff`を検収する。
終了コード2または同じ失敗が2回続いた場合は、`continuation_state: 初回レビュー前`で未解決事項を返す。

## 外部実行と再現証跡

委譲先が外部コマンドまたは背景ジョブを保持する場合、完了報告へ所有主体、安定した実行識別子、
開始時刻、直近の生存確認時刻と結果を含める。呼び出し元は成果物差分だけで停滞を判定せず、
所有主体が提示した識別子を直接照会する。実行が生存している間は差分が無くても停滞と扱わない。
終了操作は所有主体だけが行う。生存確認不能、識別子消失、終了後の結果未回収を区別して返す。

外部ツール・外部実行系の挙動を根拠とする指摘は、`reproduction_dir`内の最小再現で裏付ける。
再現証跡へコマンド、主要な環境条件、終了コード、標準出力、標準エラーを保存する。
再現できない主張は確定事実として採用せず、未検証の留保や改善提案として区別する。
再現のためにclone、対象リポジトリ、正規計画へ書き込まない。

## 総合レビューと指摘集合

初回機械検査の検収後、総合レビュー系へレビュー用計画コピーとclone全体を1回委譲する。
応答を受領した時点で`review_rounds`へ1を加える。
各指摘は重大度と独立に次の3区分へ分類する。

- 初版内補正: 比較基準の対象パス、成果、合意、利用者が観測する挙動を変えず、矛盾または実装不能を解消する
- スコープ拡大: 比較基準の対象パス、成果、合意、利用者が観測する挙動のいずれかを変更する
- 独立問題: 初版を変更しなくても存在し、初版の成立性を損なわない

同一ラウンドの指摘は集合として扱う。実装の成立性、公開契約、検証結果へ影響する指摘か、
`agent-toolkit/rules/01-agent.md`「完遂と先送り」節が同一セッション内の対応を要求する指摘が1件でもあれば、
同じ集合の全指摘を実測して採否を確定する。
集合の全件が改善提案・スタイル指摘であり、機能・契約・検証へ実害がなく、
同一セッション内の対応も要求されない場合は、集合全体を反映せず終了できる。
この場合は判定根拠を`review_resolution`へ記録し、個別の修正往復を開始しない。

独立問題は`out_of_scope_findings`へ記録し、現在の計画へ反映しない。
同一セッション内の対応を要求する独立問題は`required_same_session_findings`にも記録する。
スコープ拡大は反映前に比較基準との差分、必要性、選択肢を返し、呼び出し元の承認を待つ。
機械チェック・修正系が各指摘の事実を実測して採否案を返し、呼び出し元が最終的な採否を確定する。

## 累積差分と反映

各レビュー応答と各反映後に、比較基準の3要素と現行の3節を要素別に比較する。
前ラウンドとの差分だけで判定せず、初版から現行までの総差分を毎回再計算する。
各差分へ区分、根拠、採否、承認状態、反映状態、反映結果を対応づけて`scope_changes`へ累積する。
過去の項目を削除または再採番せず、同じ差分の状態だけを更新する。

採否が1件でも未確定の場合は`continuation_state: 初回レビュー後・採否確定前`で返す。
採用した初版内補正と承認済みのスコープ拡大だけを機械チェック・修正系へ渡す。
同系統は新しい隔離作業領域の計画コピーへ判断を反映し、3検査と`finish`を実行する。
呼び出し元は差分と検査結果を検収して正規計画へ反映し、
`continuation_state: 反映後・再レビュー前`へ移る。

限定再レビューは同じ総合レビュー系を継続する。
入力は前回の採用指摘、確定済みの採否、反映結果、反映差分、最終機械検査結果とする。
新規指摘は直前の反映が導入した退行だけを受理し、因果となる差分と再現根拠を要求する。

## 継続経路と代替測定

同じ総合レビュー系を継続する前に、完了本文の受領経路が前回と同じく利用可能であることを確認する。
同じAgentを再開でき、直接の呼び出し元が完了本文を受領できる場合は同じAgentを使う。
受領経路を確保できない場合は、前回応答と確定済み状態を全文で渡せる新しい経路を使う。

Claude代替経路へ固定時間の優劣を仮定しない。各経路の開始時刻、完了時刻、再試行回数、
外部実行の生存確認結果、完了本文の受領成否を記録し、同じ入力条件で得た実測値から経路を選ぶ。
所要時間だけを理由に、生存中の外部実行を停止または重複起動しない。

## ラウンド上限と完了判定

初回レビュー1回と限定再レビュー4回を合わせ、累積5ラウンドを上限とする。
再起動時も受領した`review_rounds`を使い、値をリセットしない。
5ラウンド目は既知指摘の確定スナップショットとし、新規指摘を探索する第6ラウンドは開始しない。
技術的に解消できない致命的・重大指摘、未承認のスコープ拡大、必須出力不足が残る場合は、
指摘全文、根拠、必要な修正、保持中の隔離作業領域、全継続値を`needs_escalation`で返す。

次の全条件が成立した場合だけ`status: completed`とする。

- 3検査の最終終了コードが0であり、未対処の警告が無い
- 正規計画の実体と検収対象の絶対パスが一致する
- 致命的・重大指摘と、直前の反映が導入した退行を解消している
- `scope_changes`の全項目で採否、承認状態、反映状態が確定している
- `required_same_session_findings`の全項目に具体的な対応結果がある
- 最終`finish`の終了コードが0で、対象リポジトリ、条件付き複製元、clone、正規計画に未復旧の変化が無い

正常検収後、呼び出し元は機械チェック・修正系へ後始末を委譲する。
同系統は受領した管理対象一時ディレクトリごとに次の完全コマンドを単独で実行する。

    uv run --no-project --script <helper> cleanup --path <保持した絶対パス>

呼び出し元は終了コード0と対象パスの不在を検収する。
`needs_escalation`で再試行または証跡を保持する場合はcleanupせず、保持パスを返す。
