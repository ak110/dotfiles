# 計画レビューの直接委譲

`agent-toolkit:plan-mode`の呼び出し元が、計画ファイルの機械チェック・修正系と
総合レビュー系を直接管理する手順を定める。
呼び出し元は比較基準、全ラウンドの累積差分、採否、反映状態を保持し、
各委譲先は受信側task referenceが定める作業だけを担当する。

## 入力と状態

呼び出し元は計画ファイル、対象worktree、条件付き複製元の絶対パスを保持する。
複製元が無い場合は`対象外`を保持する。
継続時は次の値を省略せず、前回返却値をそのまま使う。

- 初回に保存した`scope_baseline`
- 全ラウンドの累積`scope_changes`
- 機械チェック・修正系と総合レビュー系のroute、thread、Agent識別子、所有主体、全応答履歴
- 累積`review_rounds`
- 確定済みの採否、反映結果、反映差分、最終機械検査結果
- 機械チェック・修正系が委譲単位で作成した管理対象一時ディレクトリ、計画全文バックアップ、
  サンドボックス計画ファイル、SHA-256、機械修正前後差分、worktree snapshotの絶対パス
- `out_of_scope_findings`、`required_same_session_findings`、不採用内容を保持する`review_resolution`
- `初回レビュー前`、`初回レビュー後・採否確定前`、`採否確定後・反映前`、
  `反映後・再レビュー前`のいずれかの`continuation_state`

再開時に比較基準を現行計画から再計算しない。
routeまたは識別子が無い未開始系統は`not_started`と`なし`を記録し、履歴は`なし`、回数は0とする。

## 初回機械検査と比較基準

書き込み可能な最初の委譲前に、初版の`### 実施内容`、
`### ユーザー合意済み事項`、`## 変更内容`の原文を取得する。
3要素の原文と内容ハッシュを`scope_baseline`として1回だけ保存する。

機械チェック・修正系へ`plan-codex-review-fix-task.md`の初回検査を委譲する。
同系統は`## 委譲単位の退避と変更検知`の退避とsnapshot取得を完了してから、
`check_plan_file.py`、pyfltr、`check_dash.py`をこの順にサンドボックス計画ファイルへ実行し、
違反を同ファイルだけで修正して3検査を再実行する。
呼び出し元は各検査の初回と最終の終了コード、警告、機械修正前後差分を検収する。
委譲先の`plan_file_diff`と、生出力ファイル、バックアップ、サンドボックス計画ファイルの一致も検収する。
検収済みのサンドボックス差分は、呼び出し元が正規計画ファイルへ反映する。
反映後に正規計画ファイルとサンドボックス計画ファイルのSHA-256一致を確認する。
終了コード2または同じ失敗が2回続いた場合は`continuation_state: 初回レビュー前`で未解決事項を返す。

## 委譲単位の退避と変更検知

plan mode下の呼び出し元は、正規計画ファイル以外へ書き込まない。
管理対象一時ディレクトリ、計画全文バックアップ、サンドボックス計画ファイル、
worktree snapshotの作成と後始末は、書き込み可能な機械チェック・修正系が担当する。

機械チェック・修正系は委譲ごとに、次の完全コマンドを単独で実行する。

    uv run --no-project --script <helper> create --prefix plan-review-snapshot

標準出力の管理対象一時ディレクトリを再生成せず保持する。
Claude Codeでは`${CLAUDE_PLUGIN_ROOT}/scripts/_managed_temp.py`を使う。
Codexでは本referenceの絶対パスからplugin rootを確定し、
`<plugin rootの絶対パス>/scripts/_managed_temp.py`を使う。

正規計画ファイルの全文を管理対象一時ディレクトリへ復元可能な通常ファイルとして保存する。
バックアップから書き込み対象のサンドボックス計画ファイルを作成する。
バックアップのSHA-256を同ディレクトリ内の別ファイルへ保存し、値も完了報告へ記録する。

    install -m 600 <正規計画ファイルの絶対パス> <管理対象一時ディレクトリ>/plan-backup.md
    install -m 600 <管理対象一時ディレクトリ>/plan-backup.md <管理対象一時ディレクトリ>/plan-sandbox.md
    sha256sum <管理対象一時ディレクトリ>/plan-backup.md > <管理対象一時ディレクトリ>/plan-backup.sha256

対象worktreeへ次の完全コマンドを実行する。
`capture`は成功時に0、入力または取得失敗時に2を返す。

    uv run --no-project --script <_worktree_snapshot.pyの絶対パス> capture --repo <対象worktreeの絶対パス> --output-dir <管理対象一時ディレクトリ>/target

複製元がある場合は`--repo`へ受領済みの複製元絶対パスを指定し、
`<管理対象一時ディレクトリ>/source`へ同じ`capture`を実行する。
機械チェック・修正系は作業後に、対象worktreeへ次の完全コマンドを実行する。
`compare`は一致時に0、変化検出時に1、入力または比較失敗時に2を返す。

    uv run --no-project --script <_worktree_snapshot.pyの絶対パス> compare --repo <対象worktreeの絶対パス> --snapshot-dir <管理対象一時ディレクトリ>/target

複製元がある場合は受領済みの複製元絶対パスと対応するsnapshotへ同じ`compare`を実行する。
サンドボックス計画ファイルは委譲後にSHA-256を再計算し、
バックアップとの機械修正前後差分を次の完全コマンドで取得する。
差分なしは0、差分ありは1、実行失敗は1より大きい終了状態となるため、差分ありの1を検査失敗として扱わない。

    git -C <対象worktreeの絶対パス> diff --no-index -- <管理対象一時ディレクトリ>/plan-backup.md <管理対象一時ディレクトリ>/plan-sandbox.md

読み取り専用の総合レビュー前には、機械チェック・修正系へ`レビュー前退避`を委譲する。
同系統は退避とsnapshot取得だけを実行し、バックアップとサンドボックスのSHA-256一致と差分なしを返す。
総合レビュー後の正規計画ファイルとバックアップのSHA-256照合、対象worktreeと複製元のsnapshot比較も、
機械チェック・修正系へ委譲する。
書き込み可能な機械チェック・修正系ではサンドボックス差分を`plan_file_diff`と照合し、
採用済みの入力と機械違反の修正だけで構成されることを検収する。

機械チェック・修正系は、SHA-256計算、snapshot比較、統一差分取得の標準出力、標準エラー出力、
終了コードを省略せず完了報告へ記載する。同じ生出力を管理対象一時ディレクトリにも保存する。
呼び出し元はBashを実行せず、`Read`で生出力ファイル、snapshotの`manifest.json`と`tracked.patch`、
計画全文バックアップ、サンドボックス計画ファイルを読み、完了報告の転記値と実体を独立に照合する。
呼び出し元が正規計画ファイルへ反映した後の照合も同じ系統へ委譲し、
呼び出し元は返却された生出力と実体を`Read`で検収する。

対象worktree、複製元、または読み取り専用レビュー中の正規計画ファイルに変化を検出した場合は後続工程を停止する。
変更対象、退避先、記録済みHEAD、具体的な復旧手順を返し、管理対象一時ディレクトリを保持する。
呼び出し元は変更内容、退避先、復旧手順を提示し、復旧の明示確認を得る。
正規計画ファイルだけの変化は、保存した全文バックアップを入力として呼び出し元が復旧する。
対象worktreeと複製元のいずれかに変化がある場合は、確認結果と復旧手順を機械チェック・修正系へ渡し、
`承認済み復旧`として委譲する。同系統は確認済みの変更パスと手順だけを書き込み許可先とし、
除去、checkout、patch適用のうち、承認済み手順に列挙されない操作は実行しない。
復旧後のsnapshot比較、計画ファイルのSHA-256一致、差分なしの再確認は機械チェック・修正系へ委譲する。
再開時の`continuation_state`は、変更を検出した委譲の直前状態を維持する。

## 総合レビューと指摘区分

初回機械検査の検収後、総合レビュー系へ計画ファイル全体を1回委譲する。
応答を受領した時点で`review_rounds`へ1を加える。
総合レビュー系は計画ファイルと対象リポジトリを読み取り専用として扱う。

各指摘は重大度と独立に次の3区分へ分類する。

- 初版内補正: 比較基準の対象パス、成果、合意、利用者が観測する挙動を変えず、矛盾または実装不能を解消する
- スコープ拡大: 比較基準の対象パス、成果、合意、利用者が観測する挙動のいずれかを変更する
- 独立問題: 初版を変更しなくても存在し、初版の成立性を損なわない

計画レビューでは改善提案とスタイル指摘を初回ラウンドだけ対応対象とする。
初回で対応しないと確定した改善提案とスタイル指摘は`atk mq add`へ登録せず破棄する。
判断記録が必要な場合だけ`review_resolution`へ不採用理由を残す。
限定再レビューでは直前の反映が導入した退行だけを新規指摘として受理する。

`agent-toolkit/rules/01-agent.md`「完遂と先送り」節が同一セッション内の対応を要求する項目は、軽微でも破棄しない。
テスト失敗、lint違反、品質ゲートの指摘、機械チェック違反、規模基準に当たらない既存規範違反、陳腐化した記述、変更に必要な周辺追随を含む。
当該項目は全ラウンドで対応対象とし、3区分のいずれかと`required_same_session: true`を記録する。
独立問題の場合は`out_of_scope_findings`と`required_same_session_findings`の双方へ記録する。
現在の計画へ取り込む場合は、比較基準を変える差分をスコープ拡大として承認経路へ送る。

機械チェック・修正系が各指摘の事実を実測し、採否の案と技術的根拠を返す。
呼び出し元は実測と要求原文を照合して採否を確定する。
独立問題は`out_of_scope_findings`へ記録し、現在の計画へ反映しない。
スコープ拡大は反映前に比較基準との差分、必要性、選択肢を返し、呼び出し元の承認を待つ。
同一セッション内の対応を要求する独立問題は破棄しない。
呼び出し元が具体的な対応結果か承認済みの計画反映を記録するまで、未解決とする。

## 累積差分と採否

各レビュー応答と各反映後に、比較基準の3要素と現行の3節を要素別に比較する。
前ラウンドとの差分だけで判定せず、初版から現行までの総差分を毎回再計算する。
各差分へ区分、根拠、採否、承認状態、反映状態、反映結果を対応づけて`scope_changes`へ累積する。
過去の項目を削除または再採番せず、同じ差分の状態だけを更新する。

採否が1件でも未確定の場合は、`continuation_state: 初回レビュー後・採否確定前`で返す。
再開時は受領した採否を同じ`scope_changes`項目へ反映する。
採用指摘が確定した時点で`continuation_state: 採否確定後・反映前`へ移る。

## 反映と限定再レビュー

採用した初版内補正と承認済みのスコープ拡大だけを機械チェック・修正系へ渡す。
同系統はサンドボックス計画ファイルの`## 変更履歴`と依存する全節へ判断を同期し、反映差分を返す。
呼び出し元は差分と検査結果を検収し、正規計画ファイルへ反映する。
反映後に3検査を再実行し、最終結果と機械修正前後差分を保存する。
この時点で`continuation_state: 反映後・再レビュー前`へ移る。

限定再レビューは同じ総合レビュー系を継続する。
入力は前回の採用指摘、確定済みの採否、反映結果、反映差分、
反映後の機械修正前後差分、最終機械検査結果とする。
新規指摘は、統合した差分が直接導入した不具合に限定し、因果となる差分と再現根拠を要求する。
応答受領後に`review_rounds`へ1を加え、変更検知と累積差分の更新を再実行する。

## ラウンド上限と未解決事項

初回レビュー1回と限定再レビュー4回を合わせ、累積5ラウンドを上限とする。
再起動時も受領した`review_rounds`を使い、値をリセットしない。
各レビュー開始前に累積値が5未満であることを確認する。

5ラウンド目の応答は既知指摘の確定スナップショットとする。
採用した既知指摘は反映して3検査を再実行するが、第6ラウンドは開始しない。
技術的に解消できない致命的・重大指摘、未承認のスコープ拡大、
復旧未完了、必須出力不足のいずれかが残る場合は`status: needs_escalation`で返す。
返却には指摘全文、重大度、区分、対象箇所、根拠、必要な修正、選択肢、
保持中の一時ディレクトリ、全継続値を含める。

スコープ拡大の判断待ちは`初回レビュー後・採否確定前`、
採否確定後の反映失敗は`採否確定後・反映前`、
反映後の検査失敗または上限到達後の未解決は`反映後・再レビュー前`で返す。
再開後は当該状態の未完了工程から続行し、完了済みの機械検査、総合レビュー、反映を反復しない。
`review_rounds`が5の場合は限定再レビューを再開せず、既知指摘の反映と検収だけを続行する。

## 完了判定と後始末

次の全条件が成立した場合だけ`status: completed`とする。

- 3検査の最終終了コードが0であり、未対処の警告が無い
- 計画ファイルの実体と検収対象の絶対パスが一致する
- 致命的・重大指摘と、直前の反映が導入した退行を解消している
- `scope_changes`が空、または全項目の採否と承認状態が確定している
- 採用した初版内補正と承認済みのスコープ拡大が反映済みである
- `required_same_session_findings`が空、または全項目に具体的な対応結果か承認済みの計画反映が記録されている
- 対象worktree、条件付き複製元、読み取り専用レビュー中の計画ファイルに未復旧の変化が無い

正常検収後、呼び出し元は機械チェック・修正系へ後始末を委譲する。
同系統は受領した管理対象一時ディレクトリごとに次の完全コマンドを単独で実行する。

    uv run --no-project --script <helper> cleanup --path <保持した絶対パス>

呼び出し元は終了コード0を検収し、削除済みパスを`Read`して不在を確認してから完了報告を返す。
`needs_escalation`で復旧入力または再試行の記録を保持する場合はcleanupせず、保持パスを返す。
