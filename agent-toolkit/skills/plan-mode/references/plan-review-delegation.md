# 計画レビュー

計画authorが機械検査、指摘の検収、計画修正を所有し、独立reviewerへ成立性の評価だけを委譲する。

## authorの機械検査

初版の起草後、author自身が正規計画へ`skills/plan-mode/scripts/check_plan_file.py`を実行する。
違反は正規計画で修正し、全検査を再実行する。終了コード、警告、修正概要を保持する。
機械検査を別のwriterへ委譲せず、正規計画の書込主体をauthor 1名に保つ。

## 独立reviewer

機械検査の成功後、authorは独立reviewerを起動する前に意味自己監査を1巡する。提示素材と合意、
事実主張の実測根拠、表の母集団全件分類、要求と例外、変更履歴と本文、対象と完了条件を
計画全体で照合する。自己監査は品質形成であり、独立reviewerの検証責務を置き換えない。

自己監査を完了後、authorを起動した調整主体がある場合は調整主体が独立reviewerを起動する。
調整主体が無い場合はauthorが`agent-toolkit:delegation`に従って起動する。
起動主体はreviewerの新規起動又は継続接続の直前に`atk config get plan_review_model`を実行し、
`agent-toolkit:delegation`の`references/runtime-routing.md`「工程別モデル設定」に従って経路を解決する。
起動文は受信者への命令を先頭に置き、次の絶対パスと今回のレビュー種別を全レビュー共通の入力として渡す。
初回・再レビュー固有の入力は、後続の規定に従って追加する。

- `plan-review-task.md`
- 正規計画
- 対象リポジトリ
- プロジェクト規範
- `agent-toolkit:plan-mode`と`agent-toolkit:review-standards`

初回レビューでは、計画全文に加えて`## 提示素材`の逐語原文、元のユーザー指示、
復元・巻き戻し型の変更では項目別の維持・修正・撤去の判定と根拠を照合基準として明示的に渡す。
元のユーザー指示は、直接受領した実際の利用者メッセージ又はsenderが人間由来として出所と範囲を明示した逐語引用に限定する。
要約だけを一次入力にせず、reviewerが原文から目的と適用範囲を再確認できる状態にする。

再レビューでは既知でない情報だけを渡す。
同一threadでは「再レビューを実施せよ」に相当する指示だけを送る。
解決内容、変更履歴ID、再監査条項、出力形式、読み取り専用契約を起動文へ再記述しない。
新規起動では初回と同じ入力パス集合と検収済み状態を渡す。
差分要約と追加範囲は計画本文を正本とし、起動文へ再記述しない。

reviewerは正規計画と対象リポジトリを読み取り専用とする。
reviewerを起動した調整主体は起動前後のGit状態を比較し、reviewerの書き込みを検出した場合は結果を採用しない。
調整主体が無い場合はauthorが比較する。

## 指摘の検収と修正

authorは`agent-toolkit:reviewee-standards`を起動し、
`agent-toolkit:review-standards`配下の`references/judgment-details.md`を全文読んで指摘の採否と修正を確定する。
一部しか解消していない指摘は、残余を同じラウンド内で修正してから再レビューへ送る（努力目標）。
計画の目的と合意済みの除外・保持を満たす最小限の修正を選ぶ。
採否と対応結果を6列表へ統合してから、採用指摘を正規計画へ一括反映する。
スコープ、公開契約、ユーザー合意を変える修正はモード別の確認へ送る。

採否の確定前と反映後に、`## 提示素材`、`## 実施内容`、任意の`### 合意済みの除外・保持`、
`## 完了条件`を現行計画全体へ照合する。前回ラウンドとの差分だけで完了を判定しない。
変更の方向または数値目標がある場合は計画記載の方法で累積結果を再測定する。
採用の累積が逆行して合意変更となる場合は追加採用を止め、モード別の確認へ送る。
照合結果は計画とGitから毎回再計算し、別の永続状態を設けない。

採用指摘の反映後、authorは各修正差分を対象に意味自己監査を1巡する。
各修正が根拠とした正本の該当箇所、変更前の条文、`## 変更履歴`と本文の一致を照合し、
計画目的と合意済みの除外・保持を維持していることを確認する。
採用指摘の修正が新しい機構、状態、工程、実行主体を追加した場合は、追加分へ初版の該当する完成条件をすべて適用し、
ライフサイクルの粒度、ファイル群別の変更説明、完了条件、検査項目、主体別の入力と知識境界を含む未確定を解消してから
再レビューへ送る。

反映後はauthorが機械検査を再実行し、同じ論理review系統へ前掲の最小入力で再レビューを指示する。
実識別子はengine別ライフサイクルに従い、Codexは同一thread、Claudeは検収済み状態を渡した新規起動とする。

reviewerが再設計・簡素化・撤去を求めた箇所へ小修正で応じない。
初回と第2回での収束を目標とするが、レビュー回数に上限を設けない。
未解決の実在欠陥がある限り、修正と累積再レビューを同じ条件で反復する。
ユーザー判断または対象外の変更が必要な場合は、指摘、根拠、必要な判断を`needs_escalation`として返す。

機械検査がエラー0で成功し、重大・中程度の指摘を解消し、未承認の変更が無い場合だけ計画レビューを完了する。
