# 計画準拠レビュータスク

最終commitの差分が承認済み計画と一致するかを読み取り専用で検査する。成果物を修正しない。

## 入力

- 計画ファイル（新書式はメイン側・detail側の絶対パスの組、旧形式は単一パス。両側の該当節を照合する）、
  対象worktree、プロジェクト規範、`../../review-standards/SKILL.md`の絶対パス
- 計画着手前SHA、レビュー対象commit、変更ファイル一覧、検証結果、進捗ログの現在状態
- 任意入力`対象ファイル限定`。計画着手前SHAからレビュー対象commitまでの差分のうち、
  指定されたファイルの差分だけをレビュー対象とする。範囲内の他ファイルは非レビュー対象として扱い、
  未レビューと扱わない。指定が無い場合は範囲の全差分をレビュー対象とする
- 初回または再レビューの別。再レビューでは、同一thread継続でも新規起動でも、今回のラウンド番号と今回のレビュー表の絶対パスを必須差分入力として受け取る
- 実装レビュー指摘管理表の絶対パス。指定されたmanaged temp領域内の`review.tsv`を用い、準拠系の`track`は`plan-conformance`とする
- 再レビューでは、今回のラウンドの指摘を同じ表へ`atk review-table add --round <ラウンド> --track plan-conformance`で追加する。過去ラウンドの行は変更しない

入力が欠ける場合は推測せず、欠落項目を返す。

## レビュー

準拠系のレビュー担当は`plan-conformance`の`track`で今回の差分だけを点検し、自系統以外の`track`の行や出力を受け取らない。

- 計画の`## 概要`、`## 実施内容`、実装者向け領域、`## 完了条件`、
  `## 進捗ログ`の現在状態を差分と実体へ照合する
- 変更ファイルは計画の目的とファイル群別の変更説明へ照合する。
  計画目的への帰属、必要性、ユーザー合意、公開契約、安全境界、許容済みの挙動変化との整合を確認する
- 計画に規定のない実装詳細を新しい義務として要求しない
- 確定指摘の前に、欠陥が通常運用で発生する再現経路と入力主体を示す。
  対象外の入力前提又は異なる脅威モデルだけで成立する候補は除外する
- 修正方針が永続状態、所有権、期限、復旧経路、互換経路の新設を必要とする場合は、指摘化の前に元の目的と非目標へ戻る。
  何もしない案、既存操作だけの案、局所運用案、新機構案を比較し、単純案が目的を満たす場合は新機構を要求しない
- 計画からの逸脱、実装漏れ、許容されていない挙動変化、生成・配布経路の追随漏れだけを指摘する
- 境界条件と回帰は盲検系が担うため、本系統の指摘として重複させない
- 初回は指摘候補を内部的に網羅列挙し、異なる観点で再走査してから確定指摘を一括して返す
- 再レビューは全修正とベースコミットからの累積差分全体を再監査する
- 第2回以降の新しい指摘は、計画時に判断可能だった事項、初回レビューの見逃し、直前の修正による混入の別を示す
- 指摘ごとに違反する計画項目の原文、対象への適用根拠、実行結果または実装箇所の裏付けを示す
- 指摘の証拠、重大度、`未検証`の分離、報告形式は`../../review-standards/SKILL.md`を正本とする
- 対象worktreeと計画ファイルを変更しない。起動前後のGit状態を報告する
- `## 進捗ログ`のうち呼び出し元だけが記入する項目（実装commitの受領記録、統合差分レビューの収束記録）の欠落は、レビュー表へ行を追加せず、欠落項目と根拠を`needs_escalation`で呼び出し元へ返す

## 出力

対象commit、点検範囲、`write_status: unchanged`を返す。
実在する指摘はレビュー表へ登録し、`指摘内容`に違反する計画項目の原文、対象への適用根拠、根拠及び修正方針を含める。
修正方針は元の目的と合意済みの除外・保持を変更する認可ではない。
指摘がない場合は`指摘なし`と明記する。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
