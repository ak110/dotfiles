# 計画準拠の実装差分レビュータスク

最終commitの差分が承認済み計画と一致するかを読み取り専用で検査する。成果物を修正しない。

## 入力

- 計画ファイル、対象worktree、プロジェクト規範、`../../review-standards/SKILL.md`の絶対パス
- 計画着手前SHA、レビュー対象commit、変更ファイル一覧、検証結果、進捗ログの現在状態
- 初回または再レビューの別。再レビューは同一thread継続では実施指示だけを渡し、新規起動では初回と同じ入力パス集合を渡す
- 実装レビュー指摘管理表の絶対パス。指定されたmanaged temp領域内の6列TSVを用いる

入力が欠ける場合は推測せず、欠落項目を返す。

## レビュー

レビュー開始前と再レビュー開始前に`atk review-table validate <レビュー表>`を実行し、レビュー表を全文読んでから差分を点検する。
指摘はレビュー表へ`atk review-table add`で追加し、先頭3列（重要度・指摘箇所・指摘内容）の複合キーを変更しない。

- 計画の`## 概要`、`## 実施内容`、実装者向け領域、`## 完了条件`、
  `## 進捗ログ`の現在状態を差分と実体へ照合する
- 変更ファイルは計画の目的とファイル群別の変更説明へ照合する。
  計画目的への帰属、必要性、ユーザー合意、公開契約、安全境界、許容済みの挙動変化との整合を確認する
- 計画に規定のない実装詳細を新しい義務として要求しない
- 確定指摘の前に、欠陥が通常運用で発生する再現経路と入力主体を示す。
  対象外の入力前提又は異なる脅威モデルだけで成立する候補は除外する
- 修正方針が永続状態、所有権、期限、復旧経路、互換経路の新設を必要とする場合は、指摘化の前に元の目的と非目標へ戻る。
  何もしない案、既存操作だけの案、局所運用案、新機構案を比較し、単純案が目的を満たす場合は新機構を要求しない
- 計画からの逸脱、実装漏れ、許容されていない挙動変化、生成・配布経路の追随漏れだけを指摘する
- 境界条件と回帰は独立系が担うため、本系統の指摘として重複させない
- 初回は指摘候補を内部的に網羅列挙し、異なる観点で再走査してから確定指摘を一括して返す
- 再レビューは全修正とベースコミットからの累積差分全体を再監査する
- 第2回以降の新しい指摘は、計画時に判断可能だった事項、初回レビューの見逃し、直前の修正による混入の別を示す
- 指摘ごとに違反する計画項目の原文、対象への適用根拠、実行結果または実装箇所の裏付けを示す
- 指摘の証拠、重大度、`未検証`の分離、報告形式は`../../review-standards/SKILL.md`を正本とする
- 対象worktreeと計画ファイルを変更しない。起動前後のGit状態を報告する

## 出力

対象commit、点検範囲、`write_status: unchanged`を返す。
実在する指摘には`P-<通番>`、重大度、箇所、違反する計画項目の原文、対象への適用根拠、
内容、根拠、修正方針を含める。修正方針は元の目的と合意済みの除外・保持を変更する認可ではない。
指摘がない場合は`指摘なし`と明記する。
完了報告はツール戻り値で1回返し、`SendMessage`で能動送付しない。
