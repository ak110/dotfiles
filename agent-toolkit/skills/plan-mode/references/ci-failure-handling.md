# CI失敗の対処選択肢別判定表

CI失敗の対処選択肢を横断で比較し、観測事実に対応する選択肢を確定するための判定表を提供する。
`agent-toolkit:commit`の`push後のCI通過確認`節から参照される。

## 前提

対処選択肢を決める前に、CI失敗の性質を実測で分類する。

- 監視で取得したrun IDまたはpipeline ID・job IDを引き継ぎ、失敗ジョブのログを取得する
  - GitHubでは`gh run view <run-id> --log-failed`を使用する
  - GitLabでは`glab ci list --sha=<sha> -F json`でpipeline IDを取得する。
    取得したIDを`glab ci get -p <pipeline-id> --with-job-details`へ渡し、
    失敗したjobを`glab ci trace <job>`へ渡す
- artifactが生成されるジョブでは、VRT差分画像やtest-resultsなどのartifactも取得する
- 取得したログとartifactを読み取り、失敗の性質を目視で確認する
- 同一SHAでローカル再現を試し、再現可否を確認する

artifactを生成しないlint・ビルド・テストの失敗は、ログ本文から分類する。
失敗テスト名・失敗ステップ・エラーメッセージを観測事実として使用する。

## 失敗の性質による分類

CI失敗は、原因箇所・セッション帰属・再現性の3観点を独立して分類する。
VRT失敗では、VRT固有差分分類も追加する。

### 原因箇所

原因箇所は、失敗を生じさせた対象を分類する。

| 原因箇所 | 特徴 | 代表的な観測方法 |
| --- | --- | --- |
| 実装コード欠陥 | 変更コードが公開契約やテスト期待値と矛盾する | 失敗ログ、変更ファイルと失敗テストの対応関係 |
| テストコード欠陥 | テスト側の期待値・待機条件・fixtureが実装変更に追随していない | 失敗テストの差分、実装側の意図との照合 |
| 環境起因 | 実行環境・依存・外部サービスが失敗を生じさせる | ローカルでの同一SHA再現、CI環境のイメージdigest、外部サービスの応答 |

### セッション帰属

セッション帰属は、原因が自セッションの変更に由来するかを分類する。

| セッション帰属 | 特徴 | 代表的な観測方法 |
| --- | --- | --- |
| 自セッション帰属 | 変更ファイルや設定変更が失敗箇所へ影響する | 変更差分、失敗ジョブ、呼び出し経路の対応関係 |
| 自セッションと無関係 | 変更ファイルと失敗箇所に依存関係がない | 失敗ジョブ名・エラー内容・変更ファイルとの非関連性 |

### 再現性

再現性は、同一SHAと同一実行条件で結果が変動するかを分類する。

| 再現性 | 特徴 | 代表的な観測方法 |
| --- | --- | --- |
| 非決定性を確認できない | 成功と失敗の変動を観測していない | 初回失敗ログ、同一箇所での再失敗 |
| 非決定性の疑い | ログにネットワーク断・runner枯渇・タイムアウトなどの一時的な障害が現れる | 初回失敗ログ、実行環境の状態 |
| 非決定的 | 同一SHAと同一実行条件で成功と失敗が変動する | 一度限りのジョブ再実行、実行時刻ごとのログ差分 |

非決定性の疑いは暫定判定とする。
同一原因につき1回だけジョブを再実行し、結果が変動した場合は非決定的と確定する。
同一箇所で再失敗した場合は非決定性を確認できなかったものとして再実行を打ち切り、
原因調査へ進む。

実装コード欠陥やテストコード欠陥が競合状態や待機条件の不備を含む場合、
原因箇所は実装コードまたはテストコード、セッション帰属は自セッション帰属となる。
成功と失敗の変動を観測した場合、再現性は非決定的となる。
非決定的であることを、両者の修正対象から除外する根拠にしない。

### VRT固有差分分類

VRT失敗では、artifactの差分画像を用いたVRT固有差分分類を3観点の分類と併せて実施する。
VRT固有差分分類は画像に現れた差分形態だけを示し、3観点を確定しない。
原因箇所・セッション帰属・再現性は、ログ・変更差分・ローカル再現結果から別途確定する。

| VRT差分分類 | 特徴 | 3観点の確定に必要な追加観測 |
| --- | --- | --- |
| 実装意図UI変更 | 差分画像がレイアウト変更を示す | 変更の意図・公開契約・対象画面の変更差分を照合し、実装コード欠陥またはテストコード欠陥を判定する |
| データ差分 | 差分画像に表の行数・件数・順序・値などの変化がある | 実装のデータ処理・初期データ・先行テストの副作用・並列実行順を照合する |
| 描画微差 | フォント・アンチエイリアス・線幅・スクロールバー幅などに微差がある | ブラウザー・フォント・OS・描画設定と変更コードを照合する |
| 静的アセット配信不良 | スタイルが適用されず、ワイヤーフレーム状に表示される | ビルドログ・HTTP応答・生成物・配信設定・実行環境を照合する |

原因箇所とセッション帰属が確定するまで恒久的な対処選択肢を決めない。
再現性の観測結果を更新するための一度限りのジョブ再実行は診断手順として先に実施できる。
環境差やタイミング差などの仮説だけで対処選択肢を先に決めない。

## 対処選択肢と判定基準

適用可能な分類には、原因箇所・セッション帰属・再現性を組み合わせて使用する。
VRTベースライン再生成とマスク追加では、VRT固有差分分類も併用する。

| 対処選択肢 | 適用可能な3観点 | 適用不可の条件 | 上位対策の検討 |
| --- | --- | --- | --- |
| 実装コード修正 | 実装コード欠陥。セッション帰属と再現性は問わない | 該当なし | 根本対応のため、上位対策は該当しない |
| テストコード修正 | テストコード欠陥。セッション帰属と再現性は問わない | 該当なし | fixture汚染・先行テストの副作用・並列実行順が原因の場合は、テスト設計を是正する |
| CI環境・依存・外部連携の修正 | 環境起因かつ自セッション帰属。再現性は問わない | 自セッションと無関係 | CIイメージ・環境変数・配信設定・依存・外部サービス連携を原因に応じて修正する |
| VRTベースライン再生成 | テストコード欠陥で、VRT固有分類が実装意図UI変更に該当する。セッション帰属は問わない | その他の分類 | 環境起因ではローカル環境をCIと一致させる。データ差分では初期データを固定する |
| マスク追加 | テストコード欠陥で、VRT固有分類が動的値のデータ差分に該当する。セッション帰属は問わない | 実装コード欠陥・環境起因の主要領域 | 初期データの固定を優先する |
| 失敗ジョブの再実行 | 非決定性の疑い。同一原因につき1回に限る | 非決定性の疑いがない失敗 | 診断手順として再現性を観測する。自セッション帰属の場合は、再実行の成否にかかわらず原因箇所を修正する |
| `rules:changes`によるジョブ除外 | 適用可能な分類なし | すべての分類 | 対象ファイル変更時に品質検証が欠落するため適用しない |
| specまたはtestの`.skip`・`xfail` | 適用可能な分類なし | すべての分類 | テスト修正または実装修正を適用する |
| `allow_failure: true`の付与 | 適用可能な分類なし | すべての分類 | 原因を除去する |
| 依存バージョンピン | 環境起因で、ライブラリのバージョン差が原因と実測で確定した場合に限る | その他の分類 | 自セッションと無関係な場合はユーザー確認を得る。該当ライブラリの仕様変更へ追随する |
| 変更差分がない`CI trigger`空コミットの再push | 適用可能な分類なし | すべての分類 | 非決定性の疑いがある場合は`gh run rerun`または`glab ci retry`で1回だけ再実行する |

ジョブ除外・テスト除外・失敗許容化は、`agent-toolkit:commit`の`push後のCI通過確認`節にある
CI設定側の抑制に関する具体的な禁止条件へ該当する。
変更差分がない空コミットの再pushは、同節の再実行上限と具体的な禁止条件へ該当する。
失敗が自セッション変更と無関係と判明済みで、根拠を提示してユーザーの明示合意を得た場合のみ制約を解除できる。
セッション帰属は、停止トリガーの失敗回数と、無関係な環境起因でユーザー確認が必要かの判定に使用する。
実装コード欠陥とテストコード欠陥は、セッション帰属を問わず同一作業内で修正する。

## 選択の流れ

1. すべてのCI失敗で、失敗ジョブのログを取得する
2. VRT系の失敗では、差分画像などのartifactも取得する
3. 原因箇所とセッション帰属を分類し、再現性を判定する
4. 非決定性の疑いでは一度だけジョブを再実行し、再現性の観測結果を更新して追加再実行を打ち切る
5. VRT系ではVRT固有差分分類も併記する
6. 3観点の組み合わせごとに適用可能な恒久的対処を判定表から選定する
7. 設計変更による構造的抑止、自動チェック、チェックリストまたは手順書、
   ドキュメントまたは注意喚起の順で対策の成立可否を評価する
8. 上位の対策が成立する場合は、上位の対策を適用する
9. 下位の対策を選ぶ場合は、上位の対策が成立しない理由を記録する
10. 同一変更系列内で3回連続する停止トリガーに該当する場合は、コンテキスト非共有のサブエージェントで再調査する

## 分類判定の補助

分類を単独で確定できない場合は、観測を追加する。

- 同一SHAをローカルで再現し、CIの結果と比較する
- `git log --oneline --grep="<失敗パターン>"`で過去の同一失敗事例を検索する
- テスト対象のコードを意図的に壊し、当該テストが失敗するかを確認する

分類が2つ以上残る場合は複数原因の合成として扱い、すべての適用可能な選択肢を検討する。
先に確定できる原因へ対処し、残る分類は観測を追加して確定する。

- 原因箇所・セッション帰属・再現性では、失敗ログを再取得し、ローカル再現を追加で試す
- VRT固有差分分類では、artifact生成ジョブに限って差分画像を再取得し、差分領域を再検査する
- artifactを生成しないジョブでは、失敗ログのみを対象とする
