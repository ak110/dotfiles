# 保持・復元を伴う計画の契約

本書は保持・不変性・完全復元を契約に含む計画と、過去の契約へ戻す変更または過去の契約を撤去する変更を計画する場合の調べ方を定める。

## 保持・不変性・完全復元の契約

保持、不変性、完全復元を計画の契約や確認の選択肢に書く場合は、確定前に、採用する入力形式がその不変性を表現できるかと、通過する既存処理（保存・読込・UI・エディターなど）が加える変換（再直列化、trim、値の補完・正規化など）を対象実装で確かめる。契約・完了条件・選択肢には、不変とする対象、許す変換、成立する範囲を同じ条件で書く。

## 復元・巻き戻し型の変更

- 対象項目ごとに導入目的を調べ、維持・修正・撤去を項目別に判定して`## 要件・外部仕様`へ記録する
- 現行状態が喪失後に意図的に確立されたものかを、後続commit、消費主体が観測する仕様、実装コメントで確かめ、意図的な再設計は復元対象から外して根拠を記録する
- 由来は記述単位で追跡する。現存値は`git blame -L`、削除値は`git log -S`で得た削除commitの親へのblame、再導入値は現存行と古い削除元を調べる。最終更新者や`git log -S`の最新結果だけで導入元を決めない
- 方式を元へ戻す変更では、その方式を前提に後から加えた回避策・分岐・例外・規定などを導入commit以降の履歴と方式名の検索で列挙し、復元後も前提が成り立たないものの撤去・修正を同じ計画へ含める。維持するものには前提が成り立つ根拠を記録する
