# Codexでの計画工程

本書はCodexで計画を起草するメインが、起草へ進む条件とPlan modeの扱いをCodexの公開能力に合わせるための差分を定める。

## 計画ファイルの起草開始条件

初版を起草するメインはネイティブPlan modeの有無を問わず、関連調査を終え未確定事項がなくなってから起草する。調査は規範・変更対象の全文・利用側・検証・配布を手掛かりとし、外部仕様と実行時挙動を公式一次資料または実機で確かめる。

開始条件の記録には`update_plan`で「調査」と「計画ファイル起草」を分けることを推奨する。使う場合は調査を`completed`にするとき、`explanation`へ確認対象・手段・確定事項・未確定事項の有無を記録する。ユーザー依存事項は`agent-toolkit:user-confirmation-and-report`の確認を完了してから起草へ進み、登録済みの起草工程を`in_progress`にする。

変更対象または採用方針を左右する提案的表現の扱いは`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「問い・提案・疑問形の扱い」に従う。自律モードで回答を同期的に得られない実行では、常時規範が定めるUWI記録と暫定判断を完了した事項だけを起草の対象にできる。レーン担当の確認の扱いは`agent-toolkit:plan-mode`のSKILL.mdに従う。

起草後に事実不足が判明した場合は、調査工程へ戻ってから再開する。レビュー指摘の反映と進捗ログ追記は初版の開始制御の対象外とする。

## Plan modeの扱い

Plan modeはターン開始時点のホスト状態を基準に扱い、ホストモードの切替はホスト側の操作でだけ起こるものとして扱う。

- ネイティブPlan modeが有効なら、ホストのガードレール、Plan限定対話および承認後の遷移を使う。ファイル変更を遮断する範囲は、ホストが公開する仕様が示す範囲だけを根拠として述べる
- 有効でない場合は、計画ファイル以外を変更しない運用と開始・終了宣言を互換運用として適用する
- いずれも計画立案に必要な読取操作は実行できる。ネイティブモードの提供範囲と、互換運用で計画ファイルへ記述できる範囲は、別のものとして書き分ける
