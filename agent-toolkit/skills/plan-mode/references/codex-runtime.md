# Codexでの計画工程

## 計画ファイルの起草開始条件

計画ファイル初版を起草するメインは、CodexのネイティブPlan modeの有無にかかわらず、`update_plan`へ「調査」と「計画ファイル起草」を独立工程として登録する。適用規範、変更対象の全文、定義・参照元・呼び出し元、既存テスト、生成・配布経路及び類似実装のうち該当する対象を調査し、外部仕様又は実行時挙動は公式一次資料か実機で確認する。

調査工程を`completed`へ更新するときは、`explanation`へ確認対象、確認手段、確定事項及び未確定事項の有無を対応付ける。起草へ進むのは、未確定事項がなくなった時点とする。該当しない調査項目には、対象外と判断した観測事実を書く。ユーザー依存事項は`agent-toolkit:confirmation-and-uwi`の確認経路を完了してから、起草工程を`in_progress`へ更新する。

変更対象又は採用方針を左右する提案的表現と、本文から提案と判定できる弱い自信の表現は、ユーザーが示した対象及び外部可視の結果と一致する範囲を技術判断で確定してよい。一致しない具体化、ユーザーが確認を求める問い、提案と判定できない不確かな事実記述は確認経路へ送る。範囲の拡大と仕組みの上乗せも一致しない場合に含める。回答を同期的に得られない実行では、共有規範が定めるUWI記録と暫定判断を完了した事項だけを起草の対象にできる。この扱いは`agent-toolkit:process-wi`と`agent-toolkit:fast-process-wi`の経路に限る。`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`を受け取ったレーン担当は、`agent-toolkit:plan-mode`のSKILL.mdが定めるとおり、確認事項を呼び出し元へ返して回答を受け取ってから続ける。`agent-toolkit:plan-mode`の完成条件とも照合し、その他の未確定事項がない状態で起草する。

起草後に事実不足が判明した場合は、同じ`update_plan`で起草工程を`pending`、調査工程を`in_progress`へ戻す。調査完了後に調査を`completed`、起草を`in_progress`へ更新してから再開する。レビュー指摘の反映と進捗ログ追記は初版の開始制御の対象外とする。

## Plan modeの扱い

Plan modeはターン開始時点のホスト状態を基準に扱う。

- ネイティブPlan modeが有効なら、ホストのガードレール、Plan限定対話及び承認後の遷移を使う。ファイル変更を遮断する範囲は、ホストが公開する仕様が示す範囲だけを根拠として述べる
- 有効でない場合は、計画ファイル以外を変更しない運用、開始・終了宣言及び承認待ちを互換運用として適用する。ホストモードの切替は、ホスト側の操作でだけ起こるものとして扱う
- いずれも計画立案に必要な読取操作は実行できる。ネイティブモードの提供範囲と、互換運用で計画ファイルへ記述できる範囲は、別のものとして書き分ける
