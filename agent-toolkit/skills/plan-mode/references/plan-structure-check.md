# 計画構造の自動チェック

本書は[plan-file-standards.md](plan-file-standards.md)の計画構造の検証に使う形式と操作を定める。

全ての節に共通して自動チェックが受理する形式は次のとおりとする。

- GFM表のセルのリテラルの`|`は、コードスパン内も含めて`\|`と書く
- `plan-file-standards.md`が列名または行名を定める固定表は、名称と順序を完全一致で判定する。同じ列名の固定表は節ごとに1件とし、内容行は少なくとも1つのセルへ値を持つ
- 固定H3を定める節へは、そのH3だけを見出しとして置く。同じ祖先見出しの下では、同じ文言の見出しを1件に限る
- 本文へ`なし`と書くと定めた箇所では、`なし`の1行だけを置く
- 計画メタ情報の`関連WI`の子項目は半角空白2字の字下げに`-`と半角空白1字を続け、ファイル名は`yyyymmdd-hhmmss-nnn.md`の形式で一意にする
- `## 実施内容`の`由来`のWIファイル名では、パス区切り文字、半角丸括弧、空白を禁止する
- `## 要件・外部仕様`と`## 終端工程`は内容を持つ
- 起動の形で参照するスキルとサブエージェントは定義が実在する
- コードフェンスを閉じる
- `## 変更履歴`配下は地の文とコードブロックで書き、`### ユーザー発言<連番>`は1から欠番なく昇順に置く
- `~/.claude/plans`直下の計画ファイルは、起草時から`plan-file-storage.md`「計画ファイルの保存と参照」のstem規約に対応する保存工程の受理条件を満たす（直下に無い計画はファイル名を検証しない）

検証は`skills/plan-mode/scripts/check_plan_file.py`が行い、現在のagent-toolkit環境から計画ファイルの絶対パスを渡して次の形で実行する（内部scriptを別のPythonから直接起動すると、この公開コマンドを示して終了コード2で終わる）。

```sh
atk run-script plan-check -- --reject-migration-warnings /absolute/path/to/plan.md
```

- `--reject-migration-warnings`は新規作成・改訂で旧形式からの移行警告をエラーにする。保存済み計画を読むだけの検証では省く。旧形式（単一9節、二ファイル）は[legacy-plan-file-standards.md](legacy-plan-file-standards.md)の読み取り互換で受理され、移行を警告される
- `--work-dir`が解決するGitルートが計画メタ情報の`対象リポジトリ`と一致するかを確かめる。対象リポジトリがセッションの作業ディレクトリと異なる場合と専用worktreeで作業する場合は、そのパスを`--work-dir`へ渡すかそこを作業ディレクトリにする（複製元の作業ツリーから実行すると拒否される）
- `agent-toolkit:process-wi`のレーンでは`--selection-file <選定工程の`選定結果の出力先ファイル`の絶対パス> --lane <レーン識別子>`を加える。そのレーンの`再開位置`を持たないWI集合が`関連WI`と一致し、人間由来の実施行に`根拠`があるかを確かめる。`再開位置`を持つWIは既存計画で続けるため、`関連WI`へ含めると余剰として失敗する
- 凍結済み計画の後に同じレーンへAWIを追加した場合は、先行計画を全件`--prior-plan <先行計画の絶対パス>`で反復指定する。各計画の`関連WI`の重複を拒否し、和集合を同じWI集合と比べる（先行計画の構造は検証し直さない）
- 初回に複数の計画へ分けた場合は、全計画の絶対パスを位置引数へ並べて1回で検証する。各計画を個別に判定して診断の先頭へパスを付け、和集合を比べる。`--agent-rule-path`の各パスはいずれかの計画の本文にあれば受理する。同じファイルの重複指定は終了コード2になる。1件ずつ他を先行計画として検証すると、未検証の計画のWIが集合に入らず失敗する

構造定数と値抽出は`agent-toolkit/agent_toolkit/_plan/structure/`に従う。素材と要約の意味の一致、根拠の妥当性、検討の実質はレビューで確かめる。
