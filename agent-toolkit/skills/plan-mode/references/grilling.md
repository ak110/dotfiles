# grilling

`agent-toolkit:plan-mode`の直接起動で実装前の共通理解へ到達し、`agent-toolkit:add-awi-by-user`の起動でAWI投入前の共通理解へ到達するためのユーザー確認手順。
`agent-toolkit:process-wi`での実行と、レーン担当としての起動では、確認事項の扱いを`../SKILL.md`が定める手順に従って進める。

## 確認対象

計画の目的、対象範囲、機能、実現方式、望む結果、制約、優先順位を、受領した依頼と成立済みの合意から整理する。この列挙は確認対象の種類を限定しない。未確定の判断を依存関係とともに列挙し、`agent-toolkit:confirmation-and-uwi`「確認要否の判定」の1判定（答えがユーザーだけが持つ情報に依存するか）で確認を要すると判定した判断だけを確認対象とする。
環境上の事実、既存コード、利用可能なツール、ライブラリ仕様など自分で調査できる事項は、自ら調べて確定する。
ユーザーが判定基準を示した集合に属する対象と、その集合から派生する対の対象（その対象を前提とする規範条文、テスト、設定など）へ同じ基準を当てはめる判断は、起草者が確定する。方針の選択肢として質問するのは、基準が当てはまるかを一意に決められない対象について、判定を分ける条件だけとする。
確認対象を列挙する時点で、受け取った要求どうしが同じ対象へ両立しない結果を求めていないかと、要求の実現に必要な事項のうち素材が値を与えていないものが無いかを併せて調べる。
両立しない要求と、値の与えられていない事項は、いずれも確認対象へ加える。

## 質問ラウンド

未回答の判断へ依存しない確認対象を同じラウンドへまとめて提示し、回答のたびに依存関係を更新する。
別の未回答判断へ答えが依存する確認対象は後のラウンドへ回す。
ユーザーの選好に依存する判断（命名や表記の形式など）は、判断ごとに独立した質問にする。別の質問の選択肢や説明へ例示として載せた内容は、その判断への回答として扱わない。例示へ異論が返らなくても、ユーザーはその判断を問われたと認識していないため、投入や実装の後に指定し直す手戻りが生じる。
調査の完了待ちで保留するのは、その調査結果を必要とする質問だけとし、他の確認は進める。

## 質問表示

実行環境の構造化質問で提示する。Claude Codeでは`AskUserQuestion`を使い、Codexでは`agent-toolkit/share/rules-main.codex.md`が定める手段を使う。
利用できる構造化質問が無い場合だけ、`agent-toolkit:confirmation-and-uwi`の`references/codex-format.md`が定める固定形式で提示する。
質問を提示したら、そのラウンドの回答を待ってから次のラウンドへ進む。

## 終了条件

確認を終了する条件は、前記の1判定で確認を要する未回答事項と、その回答を妨げる未調査の事実がいずれも残っていないことだけとする。

## 終了時報告

質問せずに自分で決めた事項のうち、別の合理的な実装者なら異なる判断をし得るものを、ユーザーが異論を持つ可能性が高い順に一度報告する。確認を経ずに完了する作業の完了報告も、`agent-toolkit:confirmation-and-uwi`「確認要否の判定」に従って同じ形式を使う。

````text
- **決定**: <エージェントが選んだ内容>
  - **理由**: <なぜそれを選んだか>
  - **最有力の対案**: <選ばなかった中で最も有力だった案>
````

この報告は承認を求めるものではないため、追加承認を待たず次の工程へ進む。次の工程は`agent-toolkit:plan-mode`では計画ファイルの起草、`agent-toolkit:add-awi-by-user`ではAWI本文の起草とする。
ユーザーが後から異論を示した場合は、その判断と依存する後続判断を更新する。
