# 完成条件や採否を決める値の測定

本書は、`agent-toolkit:add-awi-by-user`のセッションにおいて、成果物制限の例外として性能値などを測定するエージェントに向けて、測定完了後に対象リポジトリの作業ツリーを確実に測定前の状態へ復元するための手順を定める。

## 名指し参照の読込方法

名指し参照は`../SKILL.md`「名指し参照の読込方法」に従う。

| 時点または条件 | 全文読む資料 | 契機 | 配送操作 |
| --- | --- | --- | --- |
| 本文がこの資料の基準を使う場面で、資料を選択して取得する時 | `../SKILL.md` | 判断 | `read:agent-toolkit:*/skills/add-awi-by-user/SKILL.md` |

## 測定の手順

1. 環境変数、コマンドライン引数、別名の一時設定ファイルなど、Gitの追跡対象ファイルを変更しない手段を優先して使用する。
2. 追跡対象ファイルを一時的に変更せざるを得ない場合は、測定を開始する前に`git status --porcelain=v1`の出力結果と変更対象ファイルの内容をバックアップ領域へ退避する。変更対象のファイルや測定処理によって書き換わる可能性のあるパスにすでに既存の変更差分が存在する場合は、`git worktree add --detach`で独立した検証用worktreeを作成し、その作業ツリー内で測定を実行する。
3. 元の作業ツリー内で測定した場合は、変更したファイルを測定前に退避した内容で復元する。また、測定前に差分が存在しなかったパスのみを対象として`git -c submodule.recurse=false checkout`および`git clean`を実行し、元のクリーンな状態へ戻す。親リポジトリのみを復元するコマンド呼び出しにおいては、初期化済みのサブモジュールにおけるHEADコミット、ブランチ、および作業内容をそのまま維持する。
4. 測定後の`git status`の出力が退避しておいた測定前の状態と一致しない場合は、後続の工程へ進むのを止め、発生した差分の内容と退避先ディレクトリのパスをユーザーへ報告する。
