# AWI投入

本スキルはユーザーが手動起動したAWI登録の対話機能である。対象リポジトリについてこのセッションで編集できる成果物はWIの登録と更新に限り、リポジトリ内の恒久変更（実装、規範、文書、設定など）はWIへ渡す。WIの内容と同期が必要な操作も登録する要求へ含める。対象リポジトリの実装、実装用worktreeの作成、AWIの`processing`への移動と実装担当の起動は、後続の`agent-toolkit:process-wi`が担う。
WI作成工程の入力、責務および出口は`${CLAUDE_PLUGIN_ROOT}/share/workflow-phases.md`に従う。本スキルは協調モードで動作する。

正式な登録には、対象リポジトリと既存キューの読取、`atk`、WI投入担当の起動手段と参照資料が必要である。これらが無い環境では、対話で要求を整理した原稿を返し、登録前の下書きとして扱う。既存項目との比較・保留・投入と保存の検収は、機能を提供するClaude CodeまたはCodexで行う。要求の文は[文章の品質基準](references/quality-standards.md)で確かめる。

## 手順

1. `agent-toolkit:wi-standards`を起動し、AWIの粒度、由来、投入と取得は同スキルに従う。依頼が未終端の既存AWIの更新か既存AWIへの具体的な懸念を含む場合は、質問と調査より先に`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「起動前の前提」の保留を適用する。
2. `agent-toolkit:user-confirmation-and-report`を起動し、`references/grilling.md`の質問ラウンドで、認識の違いで要件や結果が変わる未確定事項がなくなるまで確認する。明示済み・合意済みの要件は確定済みとして扱う。終了時報告を出力してから、要求単位ごとの投入先、種別、趣旨、確定した要件を確定する。
   - 投入先を確定した時点で、全ての投入先を`--target-repo`へ並べて`atk wi submission begin`を実行する。投入先を加えたり変えたりした時点も、その時点の全件を並べて再実行する。この記録がある間、投入先を対象とする`atk wi process-loop`は開始前に投入を待つ。
   - 質問の前に、`atk wi list --status=active --target-repo=<対象リポジトリ> --type=awi --skip-pull --summary-only`と候補の`atk wi show`で既存AWIと比べる。既存本文が覆う要求は確定済みとし、未被覆の要求と既存要件との不一致だけを論点にする。照会先のリポジトリが一意に決まらなければその点だけ先に確認する。
   - 引数の無い起動で、直前の応答が項目ごとの処置を確定した成果物を示している場合は、それを登録対象の入力とし、示された基準でも決まらない項目だけを質問する。
   - 依頼が範囲語か開放列挙と、例示か理由を併せ持つ場合は、要求単位の確定より前に同スキルの`SKILL.md`「原文の保持と取り込み」の該当項を適用する。担当の調査に依存する問いへの回答は手順3の返却検収後に送る。
   - ユーザーがモデル、ツール、担当エージェント、操作方法などの手段を指定した場合は、逐語本文から、その指定が`workflow-phases.md`のどの工程（WI作成・計画・実行・実行レビュー）に向けたものかを対応付ける。このセッションへの指定はWI作成工程だけに適用し、後続工程の要件から外す。後続工程への適用範囲が原文から一意に決まらず要件や完成条件が変わる場合は、工程ごとの適用範囲を独立した質問で確認し、その回答だけを根拠にする。
   - 外部資料（論文、ベンチマーク、他プロジェクトの事例など）を根拠とする改善案を提案・確定する前に、`agent-toolkit:review-standards`を起動し、外部資料に基づく改善案の評価として適用する。
   - 対象リポジトリの外へ成果を反映する要求では、反映先ごとの終了状態（commitまでかpushまでか）を`agent-toolkit:wi-standards`の`references/awi-body.md`「完成条件」で判定する。質問ラウンドで確認するのは、反映先の規範と成立済みの認可で定まらずユーザーだけが決める部分に限る。
   - 観測した問題（失敗、不具合、未対応など）を起点とする要求では、対処の選択（方針や初期設定の変更の認可、適用範囲の選択など別の形の問いを含む）を質問ラウンドから外す。`add-wi.parent.md`「起動前の前提」の必須資料の取得と初動（直接的原因と類似見直しの母集団の見込みの把握）を適用して要求を投入先との組へ展開し、根本原因と対策の確定は手順3で`投入前に確定すべき事項`として担当へ渡す。対処の確認は、担当が原因を確定したうえでユーザーだけが持つ値に依存すると返した場合だけ行う。目的や対象範囲の確認はこの手順で行う。
3. 確定した要求を`add-wi.parent.md`に従ってWI投入担当へ渡す。`source`は`add-awi-by-user`とする。逐語本文と出所を保ち、ユーザーが確定した要件と委譲元の技術判断を分ける。委譲直前に、後者の事実とユーザー要求の対象を`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「原文の保持と取り込み」の範囲の記録書式で書いたことを確かめる。既存AWIで覆われると確かめた要求単位は、そのファイル名・H1タイトル・覆う範囲を`他の要求単位の割当`か`委譲元の判断`へ含める。起草時にも同書の重複判定を行う。調査に依存する問いへの回答は同書「受領後の報告」に従い検収後に送る。
   返却は同書「受領と検収」で確かめ、ユーザー依存の未確定事項が残る要求だけ手順2へ戻して、回答後に同じ担当を再開する。起動時に登録依頼が成立しているため、本文の全文提示、投入可否の一律確認、修正後の再承認は工程から外す。
4. `atk wi submission end`で投入作業の記録を削除し、返却された`ファイル名`を含む投入結果を`agent-toolkit:completion-report`へ渡して完了報告を生成する。

## セッション境界

成果物をWIの登録と更新へ限定する契約には、`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「成果物の制限」を適用する。

追加の発話は、途中・完了報告後を問わず、書き方への注文や振る舞いの是正も含めて要求単位へ分ける。単位ごとに`agent-toolkit:wi-standards`冒頭の要求の同一性によるAWIの粒度で、既存・起草中AWIへの合流か独立した要求かを判定する。同じファイル・節・文の部分重複は書込競合として扱う。一部が更新に当たっても、残りの単位はそれぞれ判定する。独立した要求は`add-wi.parent.md`「起動方法」で新しい担当へ渡す。合流する単位は確定済みの範囲と比べ、発話が範囲の一部だけを名指ししても確定済みの範囲を縮めない。縮小が明示された場合と意図が定まらない場合は、現在の範囲を`共通前提`へ示して確認する。
依頼の取り下げなどで投入作業を中止した場合も`atk wi submission end`を実行する。完了後の追加の発話で投入を再開する場合は、投入先の確定時に手順2の記録を再び行う。
既存AWIの更新と判断した場合は、調査より先に手順1の保留を適用し、メインは本文を書き換えず、確定した変更内容と逐語本文を対象の`ファイル名`とともにWI投入担当へ渡す。
起動後の「反映して」「修正して」、再発防止や完遂の要求はAWI本文への反映として扱う。成果物の制限の例外は、登録用一時入力の作成と`atk managed-temp`による後始末、対象リポジトリの規範が同じ工程で求める追跡先への記載、完成条件や採否が依存する値の測定と測定のための一時的な変更（`references/measurement.md`）とする。

対象リポジトリ外の操作の依頼範囲、認可と確認要否は、`agent-toolkit/rules/01-agent.md`「完遂と先送り」と`agent-toolkit:user-confirmation-and-report`「確認要否の判定」・`references/approval-scope.md`に従う。委譲する場合は、起動スキル、WIだけを許す成果物制限、session終端を委譲プロンプトへ含める。

## 完成条件

- 認識の違いで要件または結果が変わる事項の回答を投入前に得ている
- 必要な認識合わせを終え、起動時の登録依頼に基づく要求をWI投入担当が登録している
- WI投入担当の返却を`add-wi.parent.md`「受領と検収」に従って検収している
- 対象リポジトリの実装と`processing`項目を起動時のまま保っている
