# AWI投入

本スキルは、ユーザーが手動で起動して対話形式でAWIを登録・作成するための機能である。本セッションにおいて対象リポジトリに対して直接編集できる成果物は、WIの登録や更新に限定される。リポジトリ本体への恒久的な変更（コード実装、規範、ドキュメント、設定の変更など）は、すべてAWIとして起草して後続工程へ引き渡す。WIの内容と同期が必要な作業も、登録する要求項目に含める。対象リポジトリの実装作業、実装用worktreeの作成、AWIステータスの`processing`への変更、実装担当エージェントの起動は、後続の`agent-toolkit:process-wi`が担当する。
WI作成工程における入力、責務、完了基準（出口）は、`${CLAUDE_PLUGIN_ROOT}/share/workflow-phases.md`に準拠する。本スキルは協調モードで動作する。
この場で求められた設計案、回答、ユーザーの選好の確定はこのセッション内で完結させ、後続で行うべき変更要求事項をAWIとして保存する。

手動作成の登録条件は、`agent-toolkit:wi-standards`「起票目的別の調査出口」に従う。
本スキルでは、同条件を満たす調査、対話による確定および登録をメインエージェントが担当する。

正式なAWI登録には、対象リポジトリと既存キューの読み取り権限、`atk`コマンド、参照資料が必要である。これらが利用できない環境では、対話によって要求を整理した原稿を作成して返却し、登録前の下書きとして取り扱う。既存項目との比較、保留処理、登録実行、保存結果の検収は、それらの機能が備わっているClaude CodeまたはCodex環境で実施する。要求の文章表現は、[文章の品質基準](references/quality-standards.md)に沿って確認する。

## 手順

手順2では、現在求められた案・評価・回答を先に整理して提示し、それに依存するユーザー判断を質問する。
回答の内容と深さは`agent-toolkit:user-confirmation-and-report`の`references/user-utterance.md`「問い・提案・疑問形の扱い」に従う。

1. `agent-toolkit:wi-standards`を起動する。AWIの適切な粒度、由来の管理、投入および取得の手順は同スキルの基準に従う。ユーザーからの依頼が未完了の既存AWIの更新や既存AWIに対する具体的な懸念を含む場合は、質問や調査をする前にwi-standardsの状態遷移ルールを適用する。`inbox`や`hold`にある項目はステータスを保留にして更新し、`processing`にある項目への変更要求は新しいAWIとして切り出す。
2. `agent-toolkit:user-confirmation-and-report`を起動し、`references/grilling.md`に基づく質問ラウンドを実施する。認識の不一致によって要件や結果が変動する未確定事項が完全になくなるまで対話を通じて確認する。ユーザーからすでに明示・合意されている要件は、同スキルの`references/user-utterance.md`「原文の保持と取り込み」に従い、理由説明に含まれる主観的な評価と区別した上で確定済み要件として扱う。質問ラウンドの終了時報告を出力した後に、要求単位ごとの投入先リポジトリ、種別、趣旨、および確定した要件を整理する。
   - 投入先リポジトリを確定した段階で、すべての投入先を`--target-repo`引数に列挙して`atk wi submission begin`を実行する。`begin`コマンドはこの対話セッションの投入記録を渡されたリポジトリ集合で更新するため、投入先を追加・変更した際も、WI投入担当エージェントの稼働状況や原稿の返却状況にかかわらず、未保存の要求の投入先をすべて並べて再実行する。この記録が保持されている間、該当リポジトリを対象とする`atk wi process-loop`は処理を開始せずに投入の完了を待機する。
   - 質問する前に、具体的に分かっている既存AWIがある場合はその本文を取得して比較する。新規主題で未知の既存項目を探す照会は省略する。既存AWIで網羅された要求は確定済みとして扱い、新規の要求や既存要件との不整合を議論する。問い合わせ先のリポジトリが一意に特定できない場合は、その点のみを先にユーザーへ確認する。
   - 引数なしでスキルが起動され、直前の会話の応答で各項目の対応方針がすでに示されている場合は、その内容を登録対象の入力として受け入れ、提示済みの基準でも判断がつかない項目のみを質問する。
   - ユーザーの依頼が範囲を示す表現や網羅的な列挙と、具体例や理由の説明を兼ね備えている場合は、要求単位を確定する前に同スキルの`SKILL.md`「原文の保持と取り込み」の該当規定を適用する。事前の調査結果が必要な質問への回答は、手順3の作成主体が調査と根拠の確定を終えた後に送信する。
   - ユーザーがモデル、ツール、担当エージェント、操作手順などの具体的な手段を指定した場合は、その指定が`workflow-phases.md`で定義されているどの開発工程（WI作成・計画・実行・実行レビュー）に向けられたものかを原文から正確に対応付ける。現在のセッションに対する指定はWI作成工程のみに適用し、後続の開発工程に対する要件には含めない。後続工程への適用範囲が原文から一意に定まらず、要件や完成条件に影響を与える場合は、工程ごとの適用範囲を個別の質問で確認し、その回答結果のみを根拠として扱う。
   - 論文、ベンチマーク結果、他プロジェクトの実績など外部資料を根拠とする改善案を提案・確定する前に、`agent-toolkit:review-standards`を起動し、外部資料に基づく改善案の評価基準を適用する。
   - 対象リポジトリの外部へ成果を反映させる要求については、反映先ごとの終了状態（コミットまでかプッシュまでか）を`agent-toolkit:wi-standards`の`references/awi-body.md`「完成条件」に基づいて判定する。質問ラウンドで確認するのは、反映先の規範や取得済みの認可では決まらず、ユーザー自身の判断が必要な事項に限定する。
   - 観測された問題（失敗、不具合、未対応など）を起点とする要求では、対処方針の選定は原因分析を完了させた後に行う。wi-standardsの共通手順に沿って投入先を確定し、手順3の作成主体が初期調査、原因分析、および類似箇所の見直しを実施して具体的な対策を確定する。対処方針についてユーザー確認するのは、原因が特定された後もユーザー自身の選択が必要な事項が残る場合に限る。要求の目的や対象範囲の確認は本手順の段階で行う。
3. wi-standardsにおける要求の同一性基準に基づいて独立した要求を分割する。件数の多寡にかかわらず、メインエージェント自身が調査、対策の確定、起草、検収、および保存までを一貫して担当することを原則とする。
   - バグ対応では投入元が原因分析、類似調査と分類、独立別件の具体化・登録、再発防止方針の選定を登録前に終える。実行側は確定した修正と再発防止策を実装し、有効性を検証する。
   - `agent-toolkit:wi-standards`「起票目的別の調査出口」に従って確定した内容をAWI本文に記載する。
   - ユーザーの原文、情報の出所、確定した要件、および技術的な判断を明確に区別し、取得済みの証拠を再利用する。複数の要求を混同せずに個別管理し、同一要求の更新は同じ作成主体が現在の要件と差分情報に基づいて行う。新しく登録すべき要求が存在しない場合は、既存の再利用、回答による解決、または取り下げの結果を整理して手順4へ進む。
   - 本来の作業に付随する別件の登録など、作業の文脈を分ける明確な理由がある場合は、`add-wi.parent.md`に従って委譲を選択する。判断基準が明確な大量の走査処理には軽量な読み取り探索を利用してよく、起草と保存の最終責任はメインエージェントが保持する。
   - 検収の構成は`references/drafting-workflow.md`「直接起草と独立した検収の選択」に従い、原文と反映内容の読み比べ、構造の確認、および`references/draft-semantic-review.md`に基づく文脈の再確認を実施する。独立した検収が必要な場合は、同時に準備した原稿、要求内容、出所、証拠を要求識別子で紐付けて`share/wi-draft-review.parent.md`へ一括して引き渡し、作成主体がレビュー指摘の採否を確定した上で保存する。
   - ユーザー自身しか決定できない未確定事項のみを手順2の質問に戻す。委譲した調査に不足がある場合は元の調査担当へ差し戻す。AWI登録の認可はスキル起動の時点で成立しているため、本文全文を提示して登録可否を一律で確認するような不要なやり取りは追加しない。
4. `atk wi submission end`を実行して投入作業のセッション記録を削除し、出力された`ファイル名`、登録・再利用の結果、検収結果、未達事項を`agent-toolkit:completion-report`の作業完了報告へ集約して送達する。投入成功の要約を別の最終応答にせず、同スキルが定める終了処理まで終える。同期の振り返りは起動しない。

## セッション境界

成果物をAWIの登録と更新に限定する契約には、`agent-toolkit:user-confirmation-and-report`の`references/user-utterance.md`「成果物の制限」を適用する。

追加で受け取ったユーザー発話は、作業途中か完了報告後かを問わず、文章の書き方に対する指示や行動の是正も含めて要求単位に分解する。単位ごとに、`agent-toolkit:wi-standards`冒頭の要求の同一性基準に基づいて、既存・起草中のAWIへ合流させるか独立した要求として扱うかを判定する。同一ファイル、同一節、同一文章に対する部分的な重複は、編集上の競合として扱う。発話の一部が既存AWIの更新に該当する場合でも、残りの要求単位は個別に判定する。独立した要求と判定したものは、手順3の担当選定に戻す。合流させる要求単位は確定済みの作業範囲と比較し、ユーザー発話が範囲の一部のみに言及している場合であっても、確定済みの作業範囲を勝手に縮小しない。明示的に範囲の縮小が指示された場合や意図が曖昧な場合は、現在の範囲を`共通前提`として明示して確認する。
ユーザーによる依頼の取り下げ等で投入作業を中止する場合も、必ず`atk wi submission end`を実行する。完了後に追加の発話を受けて投入を再開する場合は、投入先リポジトリの確定時に手順2の記録処理を再度行い、再開した投入が完了した際や再度中止となった際にも`atk wi submission end`を実行する。
既存AWIの更新と判断した場合は、調査に着手する前に手順1の保留処理を適用し、手順3の同一作成主体が、現行の本文、確定した変更内容、および原文テキストを対象の`ファイル名`に紐付けて更新する。
スキル起動後に届く「反映して」「修正して」という指示や、再発防止・作業完遂の要求は、すべてAWI本文への反映指示として取り扱う。成果物制限の例外として許可される操作は次のものに限る。登録用の一時入力ファイルの作成、作成した一時ディレクトリの`rm -r -- <作成した絶対パス>`による後始末、対象リポジトリの規範が同一工程内で求めている追跡用ファイルへの記載である。また、完成条件や採否判定に用いる測定処理と測定のための可逆な一時変更（`references/measurement.md`）も含まれる。

対象リポジトリの外部に対する操作の依頼範囲、認可の有無、確認要否は、`agent-toolkit/rules/01-agent.md`「完遂と先送り」に従う。あわせて`agent-toolkit:user-confirmation-and-report`「確認要否の判定」・`references/approval-scope.md`にも従う。委譲する場合は、起動するスキル名、対象リポジトリ内の恒久変更をAWIに限定する制限範囲、対象外となる通常の判断基準、セッション終了条件を委譲プロンプトに明記する。

## 完成条件

- 認識の相違によって要件や結果が変わり得る事項について、登録前にすべてユーザーからの回答を得ていること。
- 登録されたすべてのAWIが、`agent-toolkit:wi-standards`「起票目的別の調査出口」を満たしていること。
- 必要な認識合わせを完了し、手順3の作成主体が要求の性質に応じた適切な検収を経て要求を登録していること。
- 直接起草の場合はメインエージェントによる意味検収と機械チェック、独立検収が必要な要求では登録前のレビューと保存結果の検収を完了していること。
- 対象リポジトリの実装ファイル群および`processing`ステータスのAWIが、スキル起動前の状態のまま保持されていること。
