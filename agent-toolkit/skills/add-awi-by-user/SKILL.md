# AWI投入

本スキルはユーザーが手動起動したAWI登録の対話機能である。このセッションで編集できる成果物はWIの登録と更新に限る。対象リポジトリの実装、実装用worktreeの作成、AWIの`processing`への移動と実装担当の起動は、このセッションの対象外とする。
本スキルが担うWI作成工程の入力、責務および出口は`${CLAUDE_PLUGIN_ROOT}/share/workflow-phases.md`に従う。

## 手順

1. `agent-toolkit:wi-standards`を起動する。AWIの粒度、由来、投入と取得の手順は`agent-toolkit:wi-standards`だけに従って適用する。
2. `agent-toolkit:user-confirmation-and-report`をSkill機能で起動し、同スキルの`references/grilling.md`を全文読み、認識の違いで要件や結果が変わる未確定事項がなくなるまで質問ラウンドを行う。同書の終了時報告を出力してから、要求単位ごとの投入先、種別、趣旨および確定した要件を確定する。既に明示された要件と合意済みの要件は再確認の対象外とする。引数の無い起動で直前の応答が項目ごとの処置を確定した成果物を示す場合は、その成果物を登録対象の入力とし、示された確度や処置の基準を起草者が当てはめ、基準でも一意に決まらない項目と処置未確定の項目だけを質問する。直前にそのような成果物がない場合は、受領した依頼と成立済みの合意から対象を整理する。
3. 手順2で確定した要求を`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`に従ってWI投入担当へ渡し、本文の起草と投入を委ねる。渡す入力は要求ごとの投入先、種別、趣旨、確定した要件、呼び出し元の判断（判断ごとの理由を含む）、投入前に確定すべき事項、`source: add-awi-by-user`、ユーザー発話の逐語本文と出所とする。確定した要件には手順2でユーザーが明示または合意した要件だけを置き、メインが技術判断で決めた前提は呼び出し元の判断へ置く。出所は同書「渡す入力」が定める抽出器の出力ファイルと記録位置とする。返却の検収は同書「受領と検収」に従う。返却が`needs_escalation`で、阻害要因が認識の違いで要件や結果が変わる未確定事項である場合は手順2へ戻り、回答を得てから失敗した要求だけを同じ担当へ渡す。登録依頼は本スキルの起動時に成立しているため、本文の`less`表示、投入可否の一律質問、修正後の機械的な再承認を工程から外す。
4. 返却された`filename`を含む投入結果を`agent-toolkit:completion-report`へ渡して完了報告を生成する。

本スキルは協調モードで動作する。投入する項目の`source`は`add-awi-by-user`とする。ユーザー要求の逐語転記は`agent-toolkit:wi-standards`「由来と承認」に従う。

## セッション境界

成果物をWIの登録と更新へ限定する契約には、`agent-toolkit:user-confirmation-and-report`の`references/user-utterance.md`の成果物制限を適用する。主題の分類は、既存AWIを更新するか別のAWIを起草するかの判断だけに使い、その判断は`agent-toolkit:wi-standards`冒頭のAWIの粒度の基準に従う。完了報告後の追加要求にも同じ順序を適用する。
追加要求を既存AWIの更新と判断した場合も、メインは自ら本文を書き換えない。確定した変更内容と逐語本文を、更新する項目の`filename`を付けて手順3と同じくWI投入担当へ渡す。
起動後の「反映して」「修正して」など、反映または修正を求める要求は、AWI本文への反映として扱う。再発防止と完遂の要求もAWI本文で満たす。成果物の制限から外れるのは、登録用一時入力の作成と管理CLIによる後始末、対象リポジトリの規範が同じ工程で要求する固有の追跡先への記載、および完成条件や採否が依存する値の測定と測定のための一時的な変更とする。測定は環境変数、引数または別の設定ファイルの指定で追跡ファイルを変えずに実施できる方法を先に使う。追跡ファイルの変更が必要な場合は測定前の`git status --porcelain=v1`を保存し、変更対象と測定が書き換え得るパスに既存差分があれば`git worktree add --detach`で作成した検証用worktreeで測定する。元の作業ツリーで測定した場合は変更ファイルを退避した内容へ戻し、測定が書き換えたパスのうち測定前に差分がなかったものだけを`git checkout`と`git clean`で戻す。測定後のstatusが保存した内容と一致しない場合は、後続工程へ進まず差分と退避先を利用者へ報告する。
制限を超える成果物の認可は`agent-toolkit/rules/01-agent.md`「完遂と先送り」に従う。委譲する場合は、起動スキル、WIだけを許す成果物制限、session終端を起動文へ含める。

## 完成条件

- 認識の違いで要件または結果が変わる事項の回答を投入前に得ている
- 必要な認識合わせを終え、起動時の登録依頼に基づく要求をWI投入担当が登録している
- WI投入担当の返却を`add-wi.parent.md`「受領と検収」に従って検収している
- 対象リポジトリの実装と`processing`項目を起動時のまま保っている
