# AWI投入

本スキルはユーザーが手動起動したAWI登録の対話機能である。このセッションで編集できる成果物はWIの登録と更新に限る。対象リポジトリの実装、実装用worktreeの作成、AWIの`processing`への移動と実装担当の起動は、このセッションの対象外とする。
本スキルが担うWI作成工程の入力、責務および出口は`${CLAUDE_PLUGIN_ROOT}/share/workflow-phases.md`に従う。

## 読込表

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 手順2で質問ラウンドを始める前 | `agent-toolkit:user-confirmation-and-report`の`references/grilling.md` |
| 手順2で観測した問題を起点とする要求の投入先を確定する前、手順3で要求をWI投入担当へ渡す前と、セッション境界で既存AWIの更新を渡す前 | `${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md` |
| 完成条件や採否が依存する値を測定する前 | `references/measurement.md` |

## 手順

1. `agent-toolkit:wi-standards`を起動する。AWIの粒度、由来、投入と取得の手順は`agent-toolkit:wi-standards`だけに従って適用する。
   依頼が未終端の既存AWIの更新か、既存AWIへの具体的な懸念を含む場合は、手順2の質問ラウンドと調査より先に、`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「起動前の前提」の保留を対象へ適用する。新しい要求の登録だけの場合は適用しない。
2. `agent-toolkit:user-confirmation-and-report`を起動し、同スキルの`references/grilling.md`に従って、認識の違いで要件や結果が変わる未確定事項がなくなるまで質問ラウンドを行う。同書の終了時報告を出力してから、要求単位ごとの投入先、種別、趣旨および確定した要件を確定する。既に明示された要件と合意済みの要件は再確認の対象外とする。引数の無い起動で直前の応答が項目ごとの処置を確定した成果物を示す場合は、その成果物を登録対象の入力とし、示された確度や処置の基準を起草者が当てはめ、基準でも一意に決まらない項目と処置未確定の項目だけを質問する。直前にそのような成果物がない場合は、受領した依頼と成立済みの合意から対象を整理する。
   - 依頼が範囲語か開放列挙と、例示か理由を併せ持つ場合は、依頼中の問いへの回答と要求単位の確定より前に、`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「原文の保持と取り込み」のうち範囲語と例示を併せ持つ依頼を扱う項を適用する。
   - ユーザーがモデル、ツール、担当エージェント、操作方法などの手段を指定した場合は、逐語本文から、その指定が`${CLAUDE_PLUGIN_ROOT}/share/workflow-phases.md`のWI作成・計画・実行・実行レビューのどの工程に向けたものかを対応付ける。このセッションに向けた指定はWI作成工程だけへ適用し、後続工程の確定した要件から外す。後続工程への適用で要件や完成条件が変わり、原文だけでは適用工程が一意に決まらない場合は、工程ごとの適用範囲を独立した質問で確認する。適用範囲の回答として使うのは、その質問への回答に限る。
   - 観測した問題（失敗、不具合、未対応など）を起点とする要求では、質問ラウンドで対処の選択を問わない。方針や初期設定の変更の認可、適用範囲の選択など、対処を別の形で問う確認も対処の選択に含める。手順2では事象を把握し、要求単位と投入先を確定する前に`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`「起動前の前提」の初動（直接的原因と類似範囲の把握）を適用して、要求を投入先との組へ展開する。根本原因と対策の確定は手順3で`投入前に確定すべき事項`としてWI投入担当へ渡す。対処の確認は、担当が原因を確定したうえで対策がユーザーだけが持つ値に依存すると判定し続行できない理由を返した場合に、手順3が定める手順2への戻りで発行する。目的や対象範囲など、対処の選択に当たらない確認は手順2で行う。
3. 確定した要求を`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`に従ってWI投入担当へ渡し、起草と投入を委ねる。同書「渡す入力」の全項目を渡し、`source`は`add-awi-by-user`とする。逐語本文と出所を保ち、ユーザーが確定した要件と委譲元の技術判断を分け、後者の事実確認と原文との比較を委譲直前に行う。返却は同書「受領と検収」で確かめ、ユーザー依存の未確定事項が残る要求だけ手順2へ戻し、回答後に同じ担当を再開する。起動時に登録依頼が成立しているため、本文の`less`表示、投入可否の一律質問、修正後の機械的な再承認を工程から外す。
4. 返却された`ファイル名`を含む投入結果を`agent-toolkit:completion-report`へ渡して完了報告を生成する。

本スキルは協調モードで動作する。ユーザー要求の逐語転記は`agent-toolkit:wi-standards`「由来と承認」に従う。

## セッション境界

成果物をWIの登録と更新へ限定する契約には、`agent-toolkit:user-confirmation-and-report`の`SKILL.md`「成果物の制限」を適用する。

追加要求は途中・完了報告後を問わず、書き方への注文や振る舞いの是正も含めて要求単位へ分ける。`agent-toolkit:wi-standards`冒頭の粒度で、各単位を既存・起草中AWIへの合流か独立要求かに判定し、独立要求は`add-wi.parent.md`「起動方法」で新しい担当へ渡す。合流する単位は対象・外部可視の結果・除外を確定済み範囲と比べる。一部の名指しだけで範囲を縮めず、縮小が明示された場合と意図が確定しない場合は、現在の範囲を`共通前提`へ示して確認する。既存AWIの更新と判断した時点で、調査より先に手順1の保留を適用する。
追加要求を既存AWIの更新と判断した場合も、メインは自ら本文を書き換えない。確定した変更内容と逐語本文を、更新する項目の`ファイル名`を付けて手順3と同じくWI投入担当へ渡す。
起動後の「反映して」「修正して」など、反映または修正を求める要求は、AWI本文への反映として扱う。再発防止と完遂の要求もAWI本文で満たす。成果物の制限から外れるのは、登録用一時入力の作成と`atk managed-temp`による後始末、対象リポジトリの規範が同じ工程で要求する固有の追跡先への記載、および完成条件や採否が依存する値の測定と測定のための一時的な変更とする。測定の手順は読込表の行の`references/measurement.md`に従う。

制限を超える成果物と操作の認可は`agent-toolkit/rules/01-agent.md`「完遂と先送り」に従い、ユーザー確認の回答で得る。外部の状態を変える操作（ホストの設定、外部サービスへの登録や作成など）の実施の主体か時機を問う確認では、この制限を全ての選択肢の共通前提にしない。ユーザーの認可を得れば同じセッションで今実施できる操作は、今実施する案を選択肢へ含める（`agent-toolkit:user-confirmation-and-report`の`references/choice-construction.md`「候補の構成」の判断の時機と実施の主体の軸）。冒頭が対象外とする対象リポジトリの実装、実装用worktreeの作成、AWIの`processing`への移動と実装担当の起動は、今実施する案の対象から外す。委譲する場合は、起動スキル、WIだけを許す成果物制限、session終端を委譲プロンプトへ含める。

## 完成条件

- 認識の違いで要件または結果が変わる事項の回答を投入前に得ている
- 必要な認識合わせを終え、起動時の登録依頼に基づく要求をWI投入担当が登録している
- WI投入担当の返却を`add-wi.parent.md`「受領と検収」に従って検収している
- 対象リポジトリの実装と`processing`項目を起動時のまま保っている
