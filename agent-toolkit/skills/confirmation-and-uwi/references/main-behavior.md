# メインエージェントの確認・UWI運用

本書は`agent-toolkit:confirmation-and-uwi`が扱う、メインエージェントの未確定判断の保留、暫定判断、
事前承認の合意判定、および事後承認型UWIの扱いを定める。
本スキルの起動契機の全場面で全文読む。

## 未確定判断の保留と暫定判断

「確認を要する事項」が挙げる事項は、いずれのモードでもユーザー確認へ送る。
ユーザー確認を発行する機能を持たない実行主体は、確認事項を呼び出し元へ差し戻す。
ユーザー確認を発行できる実行主体は、自律モードで回答を得られない場合に`agent-toolkit:wi-standards`をSkill機能で起動し、
確認事項をUWIとして記録して暫定判断で続行する。
自律モードで回答を得られないと判定する契機は実行環境により異なる。
`askUserQuestionTimeout`のような回答期限を提供する実行環境では、その期限の超過を契機とする。
期限を無効化する条件が成立する実行環境は、期限を提供しない実行環境として扱う。
期限を提供しない実行環境では、応答を得られないと判断した時点を契機とする。
協調モードではユーザーの後続発話を待ち、回答期限はUWIへの切替条件の外に置く。
同一セッションでユーザー確認が回答なしで終了したことを観測した自律実行主体は、以降の確認をUWIへ記録する。
進行を止める場合も確認事項を記録してから止める。確認事項を残さずに停止すると、依頼された工程が完了しない。
必須の外部資料を取得できない場合は、ユーザー確認で資料の提供を依頼し、資料に依存する対象成果物だけを保留する。
暫定判断は要求範囲を保った対象成果物の確定にだけ用いる。資料を得ないまま続行する判断は要求範囲の縮小として、他の論点と分けてユーザー確認する。
協調モードでは資料か要求範囲への明示回答を得てから対象成果物を確定する。
自律モードではUWIへ保留した元項目のファイル名、保留理由、必要な資料、解除条件及び再開工程を記録し、その元項目を保留したうえで依存しない工程だけを続行する。
キュー項目の保留操作と再開手順は`agent-toolkit:wi-standards`「状態と依存」に従う。要求を縮小した暫定成果物の確定と、別の論点への合意を要求範囲の縮小へ拡張することは、この手順で防ぐ。

## 事前承認の合意判定

`references/judgment.md`「認可を要する操作」が列挙する承認対象のうち、`references/approval-scope.md`が事前承認と判定した操作は、合意を得るまで暫定判断の対象から除く。
協調モードで応答が無い場合と、自律モードでUWIへ記録した場合のいずれも同じ扱いとする。
可逆な代替手段を採用するか、その操作を保留して依存しない工程を続行する。
保留の記録、元項目の`hold`への移動及び再開は、必須の外部資料を取得できない場合と同じ手順で行う。
同書が事後承認と判定した操作と、成立した承認の範囲へ収まる操作と、計画で確定済みの操作は本除外の対象外とする。
この除外により、合意そのものを暫定判断で補って事前承認の操作へ着手する余地をなくす。

## 事後承認型UWIと回答の受領

事後承認型のUWIは、実施済みの対応の可否を問うために回答を待たずに投入し、元の作業の`depends_on`へ加えず元の作業を終端する。
自律モードで曖昧な要求を解釈して実施した場合は、採用した解釈、採用理由、利用者が観測する結果及び復元方法を事後承認の対象へ含める。同じ作業で生じた他の事後承認対象と1件のUWIへ集約し、投入先を1つに定める。事前承認の対象は集約後も事前承認として扱う。
事後承認型UWIの記録対象は`references/approval-scope.md`の事前・事後承認の区分に従う。
対話中にUWIまたは保留中の確認事項への判断内容を受け取った場合、実行主体は受け取った判断内容を回答として記録する。
記録の後に対応する変更へ着手できるのは、`agent-toolkit:process-wi`などの専用手順による起動か、ユーザーの明示指示がある場合に限る。
専用手順の実行中に、現在の主題を保留していたUWIの回答を受け取った場合は、回答の記録に続けて、そのUWIが保留していた保存済み計画又は処理工程を同じセッションで再開する。
その要求とその計画に属する未完了の範囲は、同じセッションの中で扱い、追随するAWIの登録と追加の採否確認へ分けずに完了する。
回答から生じた要求のうち、元の要求範囲へ含まれないものだけを別のキュー項目とする。
