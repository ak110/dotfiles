## 処理中に確定した必須是正レーン

1. 処理中に追加された対象WIは、`selection-procedure-addition.md`「処理対象WIの追加」に従って分類と処理開始手続きを完了した後に、本節の基準に沿ってレーンへ割り当てる。
   目標の明示がある実行では`lanes-goals.md`「明示された目標からの実行」で具体化した必要作業も含める。
   通常のキュー処理では、`immediate-fix.md`「即時対応」で今回追加と判定した正式改善AWIも受け入れる。
   未回答UWI、未確定の要求、同判定にも明示追加にも該当しない新規到着項目は追加せず、最小修正後に残る正式対応AWIは次回へ引き継ぐ。

2. 追加された項目は必ず既存のレーンへ割り当て、処理中の一環として新たな最終レーン名を新設することは避ける（上限値および算定集合は`selection-format-generation.md`「初回配分の算定根拠」が定める。所在参照）。
   既存レーンが0件の場合は、上限および割り当て先リソースの不足を「続行できない理由」として報告する。

   1. 変更対象のファイルと該当箇所、実際の依存関係、再開対象の計画、既存レーンの残り工程、および書き込み所有権の状況を確認する。
   2. 同一の再開対象計画を持つ既存レーンが存在する場合は、そのレーンへの割り当てを最優先の分割不能条件として確定し、費用比較よりも先行させる。
      受け入れ不能な技術的要因が観測された場合でも、該当計画を別レーンへ割り当てず、同一レーンにおける所有権と再開状態の回復を図る。
   3. その他の項目については、実際の依存関係と書き込み所有権を満たす既存レーンに対して、工程境界で受け入れられるよう割り当てる。
      待ち時間や残存作業量は既存レーン間の選択基準として利用し、互いに独立した要素であっても同一レーン内で順次処理する。
   4. 割り当ての理由として、実際の依存関係、再開対象計画、待ち時間、現在の進行工程、書き込み所有権、および同一実行内で処理する順序を記録する。

3. メインエージェントは、`selection-procedure-addition.md`「処理対象WIの追加」に定められた公開merge操作によって仮の名称を既存の名称へと対応付け、全体確認の終了コード0と保存の成功を検収した上で、追加分のタスクを引き渡す。
   合流先のレーンは未統合の状態へ戻るが、追加のない他のレーン、所属WI、および初回の登録情報はそのまま保持される。

4. 割り当て先のレーンがすでに統合済みであってもリソースは保持されているため、同一の`atk lane create`を実行して所有登録とGit登録の一致を確認し、返却された同一のworktreeおよびbranchへ追加する。
   指示は、すでに準備された環境を維持している同一の担当スレッドと引き継ぎ記録へ送信する。
   登録情報と実態が一致しない場合は途中成果を保持し、回復に必要な事実を報告する。
   合流先レーンは未統合状態に戻るため、セッション終了時であっても再統合が完了するまでリソースを保持する。

5. 選定YAMLへの追加が完了した時点で、現在実行中の工程の完了を待たずに、同一スレッドへ一度だけ指示を送信する。
   指示には、追加するWI名、専用worktreeおよびbranch、引き継ぎ記録、選定YAMLから本文と`プロジェクト規範の指定`を取得すべき旨、ならびに現在の工程を中断・破棄せずに完了させ、ターンを終えずに追加計画の起草へ進むべき旨を含める。
   割り当ての再検討のみを目的として稼働中の担当エージェントを中断させない。
   工程境界の通知は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`に従う（所在参照）。
   非待機の`計画検査完了`は`atk agents notify`による一方通知であり、一律の返答を求めると実装が停止する。
   レーン担当は追加指示後の最初の工程境界メッセージの先頭に、現在工程の実行結果を含める。
   メインはその受領で追加工程の開始を認識し、先行計画の凍結を維持する。
   追加計画の絶対パス、対象AWI集合、保存状態、進捗をレーンの引き継ぎ記録へ蓄積し、全計画を実行レビューと統合へ渡す。

6. 同一スレッドの再開が成立しない場合は、公開応答の事実、対象、および不足している条件を「続行できない理由」として報告し、同一レーンの回復に関する判断を仰ぐ。
   再開が不可能な場合や全レーンが統合済みである場合であっても、新規レーンを作成することは避ける。
   追加分に対しても、計画起草、レビュー、統合、終了という既存の手順をそのまま適用する。

7. 同一セッション内で共有ツールや共通手順を修正し、稼働中のレーンが残りの作業でそれらを利用する場合は、該当するレーンに対してのみ、修正コミット、反映されるタイミング、再起動の要否、および反映前の回避手順を1通のメッセージにまとめて通知する。
