## 保存後のチェック

**34.** メインエージェントは、分類、割り当て、担当モデル、配置根拠、見込み時間、プロジェクト規範指定、ならびに結合条件の意味判断を、[selection-format-generation.md](selection-format-generation.md)「選定の生成入力」の形式に従ってYAMLファイルへ記録する。
`atk wi list --jsonl --with-staleness`の取得済み出力を`--candidate-file`に渡し、定型欄の生成、本文との対応確認、全体の条件検証、および不可分なファイル保存を1回の操作で実行する。
候補が0件の場合や、再開位置を持つ初回選定でも同じ操作を使う。

 ```text
 atk run-script pick-wi-check -- <意味判断YAMLの絶対パス> --candidate-file <取得済み候補JSONLの絶対パス> --output <pick-wi.yamlの絶対パス> --work-dir <対象リポジトリの絶対パス>
 ```

**35.** 鮮度、初回候補、初回割当、不可分成分、および確定した入力から導出可能な各辺のパス・段階・依存情報は、手作業での転記対象から除く。
通常の除外条件で除外するWI名のみを`除外候補`に指定する。
未確定の分類や担当モデルを生成ツールに推測させず、不足している意味判断はメインエージェントが元の本文と現物資料から補う。
検証に成功した同じ入力の、保存や再チェックだけを目的とする再実行は対象外とする。
既存の完成済み選定YAMLを受け取った場合は、取得済み候補と完成済み出力を保持して後述の確認操作を行う。

**36.** 初回・修正後・候補0件では保存のたびに次の手順を行う。
追加WI・統合状態の記録には全体検証付き保存の成功結果を使う。

 1. 初回は前述の生成付き保存操作の結果を使用し、`--body-wi`は指定しない。
    完成済みYAMLの受け取り確認には`atk run-script pick-wi-check -- --work-dir <対象リポジトリの絶対パス> <出力先の絶対パス>`を使用する。
    チェック対象は項目名・必須欄・型、書込予定のパス・範囲・区分、レーン重複記録・先行関係、担当モデル整合性、公開工程の規範根拠である。
    補正前の2値・係数・参照記録、同一再開計画の配置、norm-specによる規範指定、段階2以上・6000秒超の比較欄、初回配分・レーン数上限も確かめる。
 2. 終了コード1の場合は、該当するWIの元本文に戻って分類を再度判断する。
    変更領域や重複関係が変わった場合は`selection-procedure-allocation.md`「調査とレーン分け」に戻って配分を見直してから手順1を再実行する。
    終了コード2の場合は、出力された`次の操作:`の指示に従って修正し、手順1を再実行する。
 3. 終了コード0の場合は、標準出力に表示される要約情報（WI総数、レーンごとの件数・段階・先行レーン・秒数・WI名）を確認して選定件数と候補件数の一致を確かめ、次節の意味検収へ進む。
    チェック完了後にYAMLファイルを編集した場合は、再度チェックを実行する。

## 保存後の意味検収

**37.** 終了コード0は、構文構造と書込予定・レーン関係の機械的な確認が成立したことのみを示す。
選定YAMLと元のWI本文（AWIも`atk wi show`で取得する）を読み込み、初回、修正後、追加選定のいずれでも次の意味検収を行う。
不一致を発見した場合は、観測した事実を添えて該当箇所を修正し、再チェックする。

- 分類: `書込対象`と`公開工程の書込対象`の予定する個別対象に欠落がなく、妥当な範囲に限定され、両書込区分が元本文の変更要求および`公開工程の規範根拠`が指す規範と節の割り当てに合致しているか確認する。
  機械的に抽出したパス、ファイルの存在、名前順、一定の件数のみを根拠とした配分や、一律の独立性宣言は認めない。
  作業を伴う回答済みUWIでパスが明示されていない場合は、`pick-wi-check`による比較対象が存在しないため、限定調査で導出した範囲が回答の作業内容と合致しているかを確認する。
- `導出した新設先`: 要求と配置根拠が元本文および限定調査の現物資料に対応しており、要求範囲を満たす具体化となっているか、また残りの領域を保守的な範囲で保持しているか確認する。
- 重なり: 同一段階の未統合レーンで共通パスを持つ組は、双方の変更定義が意味上独立しているかを元本文と現物から確認する。
  独立性の記録は`レーン間の重なり`の`共通パス`、`レーン1の定義`、`レーン2の定義`、`判定`へ置く。
  別段階では書込予定の重複が`先行レーン`へ直接か推移的に反映され、後段の開始前に先行統合が完了する構成を確かめる。
- 依存: 候補内における同一リポジトリの依存関係を、正規化された`target_repo`と`depends_on`から推移的にたどる。
  依存関係の両端が同一レーンに配置され、依存先が先行して処理される構成になっているか確認する。
  別レーンの開始順序のみで依存を満たそうとする割り当ては認めない。
- 段階と上限: 段階2以上を採用している場合は、最上位の`単一段階案の完了見込み秒数`と、`レーンの所要時間`から算出した段階案の合計秒数を比較する。
  単一段階で6000秒を超える場合は、`段階案の完了見込み秒数`と採用案の見込み秒数を比較し、「成立する案がない」とする宣言の妥当性も確認する。
  書込対象の推移的な重複のみを理由として安易に6000秒超過を不可避と判断していないか、また比較の理由と後段レーンの先行統合条件が各レーンの`根拠`欄と一致しているかを確認する。
  レーン数上限はselection-format.md「初回配分の算定根拠」のNとBに基づいて検収し、初回割当ならびに統合済み・後段を含む現在の全レーン集合がそれぞれB以下であることを確認する。
  元の候補、初回割当、不可分成分の構成、および型付き結合条件が元の入力と一致しているかも確認する。
  上限を超える場合は複数の成分を同一レーンにまとめて同一の公開操作で確認し、所要時間の見込みを理由として上限を緩和しない。
- 初回情報を欠く旧入力: 元の候補、初回割当、構成WI、結合条件を過去の記録から復元して補い、同一の公開操作を再実行する。
  現在の選定件数から推測せず、元の記録を確認できない場合は情報不足として扱う。
- 所要時間: `レーンの所要時間`が`なし`以外のレーンと過不足なく一致し、秒数が0以上であり、根拠が空でないことを確認する。
  各行の補正前の2数値および`見込みの補正`から、各工程の積が正しく、総経過を加算せず共有待ちが全体へ1回だけ加算されていることを確認する。
  旧形式は未分離の履歴として読み取る。
- 上流投入: 省略時に補われる値を解決した各項目について、[selection-format.md](selection-format.md)の`上流投入`と`レーン`の組み合わせ条件を満たしているかを検収する。
  条件から外れている場合は分類を修正して再チェックする。
  通常レーンに配置された外部操作のみの項目について、ファイル変更を伴わないことを理由に分類を変更しない。
- `プロジェクト規範の指定`: 指定されたファイルが実在し、読み取り可能であることを確認する。
  指定された資料を実際に読み取ったかどうかの確認は、その指定を利用するレーン担当が行う。
- 再開位置: 再開位置が設定されており、その値が`反映後の観測だけが残る`で始まらない項目については、`~/.claude/plans`配下の計画ファイルの絶対パスであり、その計画の`関連WI`に対象AWIが含まれていることを確認する。
  `反映後の観測だけが残る`で始まる値は、AWI本文の末尾にある`## 反映後の観測の再開記録`（`finish-session-observation.md`「延期adoptと反映後の観測」により追記される）の`再開区分`が`反映後の観測だけが残る`である項目にのみ認める。
  この値の場合は前述の計画ファイルの確認に代えて、該当節の`計画`の値と再開位置の`計画:`の値が一致しているかを確認する。
  値が`private-notes/plans/`からの相対パスである場合は、`atk config get private_notes`が返すパスの`plans/`配下にファイルが実在し、`関連WI`に対象AWIが含まれていることも確認する。
  再開位置が存在しない項目は、新規に計画を起草する対象とする。
- 採否: 選定結果に不採用の決定や、既存実装による充足の確定が含まれていないことを確認する。
  選定工程においてメインエージェントがAWIを`reject`または`adopt`することはなく、採否の判断と通常の終了処理はレーン担当が行う。
- `続行できない理由`: 記録された根拠を検収し、自身で補える入力や技術的な不足事項は補ってから再チェックする。
  ユーザーのみが判断できる事項に限定して確認し、回答が得られない場合はUWIを登録して、回答を必要とする項目の`depends_on`へそのUWIを加える（`states-and-dependencies.md`「承認型UWIと元項目」）。

**38.** `選定`と`レーンの所要時間`が空の結果も正常として受け入れる。

## 選定工程の完了

**39.** `atk wi list --target-repo=<対象リポジトリの絶対パス> --skip-pull`を1回実行し、選定したすべての項目（`unhold`した元項目を含む）が`processing`状態にあり、対象外の回答済みUWIが`processing`状態に含まれていないことを確認する。
不一致がある場合はレーン起動に進まず、状態と理由を記録する。

 対象リポジトリの規範が選定完了時点での評価や記録を求めている場合は、本工程内で保存を完了する。
 以降は保存・検収済みの`選定`集合を基準とし、最新のチェック・意味検収・状態確認を終えてから、監査の終了を待たずレーン起動へ進む。
通常レーン0件なら圧縮を予約せず監査・公開へ進む。
