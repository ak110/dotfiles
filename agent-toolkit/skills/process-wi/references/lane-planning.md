# レーン計画の起草と再開

初回選定を受け取ったレーン担当は、まず選定結果の各項目に記載された再開位置を確認する。
そして、`再開位置`が指定されていないAWI群に対して`agent-toolkit:write-plan`「計画ファイルの作成要否」を適用する。
1件でも作成条件に該当する場合は、それらを1つの計画にまとめて起草する（計画を分割する条件は`lane-planning-drafting.md`「計画の起草」の手順4を参照）。
すでに`再開位置`を持つAWIは新規計画には含めず、`lane-planning-resume.md`「再開」の手順に従って作業を継続する。

対象リポジトリのバージョン規約により更新が必要な場合は、レーン数にかかわらずバージョン更新の種別（bump種別）とその根拠を計画に記録する。
同一実行内の変更がより上位の更新区分に該当する場合は、その上位区分を選択する。
実際のバージョン更新作業は公開工程の公開担当が行う。

入力情報は、pick-wi-checkが検証・保存した完成版の選定YAMLとレーン識別子から取得する（メインエージェントの生成入力、候補JSONL、定型欄は委譲プロンプトへ転記されない）。
選定時の分類と要求の採否は独立した判断として扱う。
鮮度、省略値、担当モデルに不一致がある場合は、同一担当の引き継ぎ記録を通じてメインエージェントへ報告する。
準備済みリソースの所有権登録は`atk lane create`が保持するため、レーン担当はカレントディレクトリのworktreeに対してのみ書き込みを行う。
統合完了後もリソースは回収せず、同一スレッドで追加指示を受け付ける。

選定の`書込対象`は初期配分の見込みである。
計画起草や実装で必要となった要求内の編集先は、他レーンとの重なりにかかわらず担当判断で加え、追加一覧の送信・選定更新・追加ログは要求の対象から除く。
編集と統合時の扱いは`../../../share/exec-subagent-implementation.md`「実装」に従う。

## 計画検査完了の通知

再開位置が`なし`であり、いずれの待機条件にも該当しない場合は、以下の形式で`atk agents notify`を用いてメインエージェントへ通知し、応答を待たずに実装作業へ進む。
統合区分は計画ごとに判定し、採用した実施内容を持つAWI行が含まれていれば`マージあり`、含まれていなければ`マージなし`とする。
計画を分割した場合は、この3行の組を計画ごとに作成順で繰り返し、`AWI:`にはその計画の`関連WI`のみを記載する。
すべての組が`マージなし`となった場合は実装せず、メインエージェントからの統合指示を待つ。

```text
計画検査完了
計画ファイル: <絶対パス|なし>
統合区分: <マージあり|マージなし>
AWI: <AWIファイル名のASCIIカンマ区切り>
```
