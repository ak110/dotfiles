# レーン計画の起草と再開

初回選定を受領した`レーン担当`は最初に、選定結果の各項目から再開位置を読み、`再開位置`を持たないAWI集合へ`agent-toolkit:plan-mode`「計画ファイルの作成要否」を適用する。1件でも作成条件に当たれば、それらのAWIを1つの計画へまとめ、以下の手順を実施する。同じレーンの`再開位置`を持つAWIは新しい計画へ含めず、再開位置が指す既存計画か再開記録で後述の再開の手順に従って続ける。

対象リポジトリの版数規範が更新を求める場合、レーン数を問わず、その判定基準からbump種別と根拠を計画へ記録する。AWI本文の区分は要求単独の起草時点の判定として扱い、process-wiの同じ実行の中の変更が上位区分に当たる場合は上位区分を選ぶ。版数更新は公開工程の終端担当が行う。

全AWIが作成を省く条件に当たる場合は、`atk wi show`で要求と完成条件を読み、由来・採否、AWI集合、最も近い既存実装、直接影響範囲、変更範囲の検証コマンドおよび統合区分を引き継ぎ記録先へ書く。`統合区分`は採用する要求を実装する場合に`マージあり`、実装が不要な場合に`マージなし`とする。エージェント向け文書の編集を含む場合は次の形式だけを返し、メインがエージェント向け文書を名指しした`実装開始`または`実装なし`を待つ。

```text
計画なし準備完了
AWI: <AWIファイル名のASCIIカンマ区切り>
統合区分: <マージあり|マージなし>
エージェント向け文書: <編集するリポジトリ相対パスのASCIIカンマ区切り|なし>
```

エージェント向け文書の編集を含まない場合は、同じAWI集合と統合区分を`計画検査完了`の通知でメインへ送り、応答を待たず`## 実装`へ進む。`マージなし`では実装せず、通知後にメインの統合指示を待つ。通知には後段の計画を作成した場合と同じ項目を記し、`計画ファイル: なし`を用いる。

1. `agent-toolkit:plan-mode`を起動し、同スキルの`references/plan-file-standards.md`を全文読み、AWI、解決したプロジェクト規範、対象実装、既存テスト、生成・配布手段および類似実装を調査する。
   対象実装を読む前に、要求と公開契約から比較対象とする最も近い既存実装を選ぶ。境界候補は入力値、時間経過、操作順、保持状態、同じ処理の反復などの軸から選び、要求に応じて権限や環境の差などの軸も加える。
   調査後は採用案の前提を反証する観点から、責務を変更箇所が負う必要性、既存機構への統合、対象リポジトリの外にある上流のツールや共有設定への責務の移管、機構の削除または簡素化を比較し、その結論を計画へ反映する。このうちAWIの`## 実現性`が結論を示した観点は比較し直さず、同節が触れていない観点と、AWIの記述との食い違いを観測した観点を比較する。不具合対策では`agent-toolkit:review-standards`の`references/reviewer.md`「初回レビュー」の手順4が適用する「前提を疑う観点」に従い、観測した害の消滅と呼び出す側の修正案も比較する。
   `選定`の各項目の`鮮度`を計画の`## 変更履歴`へ記録する。`notice`は停止と履歴調査の開始条件から外す。現行内容との不一致、既存実装による充足済み、巻戻しの危険のいずれかを観測した項目だけ関連履歴を確認する。観測条件、確認した履歴、採否への影響を同じ記録へ残す。いずれも観測しなかった場合は、その判定を記録して履歴調査を省く。
   - 多数の対象へ同じ作業をする要求では、`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「実施内容」が定める実施方式を比べる。作業量と難しさによる分担（`agent-toolkit:delegation`の`references/routing.md`「委譲単位の確定」）とあわせて、採った方式と理由を計画へ残す。
   - 長い比較調査（独立した複製で条件ごとに実行する対照実験など）を含む要求では、その調査に必要な先行成果、固定できる入力と版、書込先、観測に使う資源の競合を通常修正と分けて判断する。既存の成果だけで入力を固定でき、独立した複製へ出力できる調査は、`agent-toolkit:writing-standards`の`references/investigation.md`「実行結果の検証」が定める展開前の準備確認を終えた後、通常修正と並行して開始する。開始条件と通常修正との関係を`## 実施内容`へ書く。調査結果を使う是正と履歴統合はレーン担当が所有し、調査結果を待つ工程だけを直列にする。同時実行が観測条件を乱す場合と、共有の出力や後続の未完成成果へ依存する場合は、その理由で順序を決める。調査を待たずに進められる通常修正を調査の終了まで止めると、レーンの完了が調査時間の分だけ遅れる。
   - 検証コマンドを確定する前に`agent-toolkit:check-execution`を起動し、同スキルの`references/verification-scope.md`の類型で変更範囲の検証の対象を確定する。確定した対象を`## 検証`の`変更範囲の検証`へ加え、加えない対象は理由を`## 要件・外部仕様`の追随範囲へ書く。
   - 変更対象を確定する前の全文読解は、変更対象の候補ファイルと名指しされた基準となる文書（計画・WI・エージェント向け文書など）を基本とする（努力目標。調査中のコンテキスト消費を抑える）。候補の限定、所在の特定、横断的な列挙は、読み取り専用の探索委譲か検索で結論だけを得る。他の役割の`<役割名>.subagent.md`と、変更対象を含まないスキル本体は、検索で必要な箇所だけを読む。
   - 採否を確定する前に、各要求の変更対象パスに対応する必須スキル（対応表はプロジェクト規範が示す）を起動し、そのスキルと参照資料のうち変更する対象の成立条件と禁止条件を定める節を検索で特定して読み、要求と比べる。読む範囲は前項の全文読解の限定に従い、検索で特定した節とする。衝突する要求は`## 実施内容`で不採用または手段変更とし、人間由来の要求であれば手順2の即時通知へ送る。編集対象の規範を読む前に採否を確定すると、衝突が編集の段階で初めて見つかり、判断要請と実装済み差分の取り消しを招く。
   - 委譲プロンプトで`上流投入結果`を受領した場合は、`結果`が`completed`の要求を`## 実施内容`の採用範囲へ含めず、その要求を`移管`として投入先の`ファイル名`とともに記録する。上流の改訂を待つ要求を対象リポジトリ側で重ねて実装しないためである。
2. 人間由来の要求を不採用または部分採用にする判断も`agent-toolkit/share/rules-subagent.md`「確認事項の即時通知」の対象とし、計画を確定する前にメインへ通知する。
3. 手順4以降へ進む条件は、計画中に通知した確認事項への回答を全て受領し、計画の採否へ反映済みであることとする。未受領または未反映の確認事項が残る間は、回答に依存しない調査と計画本文の下書きに限って続ける。
4. `references/plan-file-standards.md`に従って計画本文を起草し、managed-tempの中のファイルへ保存する。計画ファイル（バグ）を作成する場合（同書「バグ調査」の作成条件）は、その本文も別のファイルへ保存する。`atk run-script plan-create -- --main-source <計画本文の絶対パス> --lane <レーン識別子>`で`~/.claude/plans`に計画ファイルを作成する。計画ファイル（バグ）を作成する場合は同じコマンドへ`--bugs-source <計画ファイル（バグ）の本文の絶対パス>`も渡す。stemは同処理が生成した値を使い、日付、時刻、固定接頭辞およびレーン番号の組み立ては同処理へ委ねる。
5. 計画全体から編集・新設・移動するエージェント向け文書の集合を確定する。全パスを変更対象として計画本文へリポジトリ相対パスで明記する。確認には`atk run-script plan-check -- --reject-migration-warnings --selection-file <選定結果の出力先ファイル> --lane <レーン識別子> <計画ファイルの絶対パス>`を用いる。集合の全パスを`--agent-rule-path <リポジトリ相対パス>`で反復指定し、単独実行する。終了コード0と警告の不在を確認する。不一致のパスは一覧から削除せず、計画本文を直して同じ集合で再び確認する。処理中に追加したAWIの計画にも適用する。その場合は同じレーンの先行する凍結済み計画を全件、`--prior-plan <先行計画の絶対パス>`で反復指定する。
6. `## 実施内容`の人間由来の行が`部分採用`または`不採用`である場合、計画がエージェント向け文書の編集を含む場合、人間の依頼かWIが明示した禁止条件が`## 実施内容`にある場合は、次の3行だけを返し、同じthreadでメインの`実装開始`または`実装なし`を待つ。処理中に追加した集合の計画でも同じ形式を用いる。

```text
計画作成完了
計画ファイル: <絶対パス>
エージェント向け文書: <編集するリポジトリ相対パスのASCIIカンマ区切り|なし>
```

レーン担当は手順5で確認した集合をそのまま`エージェント向け文書:`行へ書く。集合には`## 要件・外部仕様`の変更対象、`## 実施内容`および`## 恒久化・リファクタリング`の反映先を含め、参照するだけのファイルは含めない。エージェント向け文書の範囲は`計画なし準備完了`の`エージェント向け文書:`行と同じとする。エージェント向け文書の編集を含まず、人間由来の縮小か明示禁止条件のために返す場合は`なし`とする。メインはこの値を名指しにそのまま使うため、編集対象と参照の区別は計画を書いたレーン担当が確定する。

再開位置が計画ファイルの絶対パスである場合は、`## 概要`、`## 変更履歴`、`## 要件・外部仕様`および`## 進捗ログ`を読み、続けて同stemのレビュー指摘管理表の応答を読む。計画ファイルの記述と異なる箇所はレビュー指摘管理表の応答を現在の結論として採り、進捗ログの最終行が示す再開位置から続行する。新しい計画を作成せず、既存の計画をそのまま使う。
選定結果の`再開位置`が`反映後の観測だけが残る`で始まる項目と、進捗ログの最終行が「反映後の観測だけが残る」と示す再開は、観測だけで続ける。AWI本文の最後の`## 反映後の観測の再開記録`の節がある場合は、その節から実装commit、残る完成条件、観測手段と`計画`の値を読む。計画を持つ場合は、`~/.claude/plans`に同名の計画が無ければ`計画`の値を`atk plans checkout <private-notes/plans/からの相対パス>`へ渡して取得する。残る完成条件を記録された操作順で新しいプロセスから観測し、結果と報告時点から判明した差を進捗ログへ追記する。引き継ぎ記録にもその計画の観測のみの再開、取得した保存済み計画のパス、元の専用worktreeの回収状態と本文の凍結状態を記す。`計画`の値が`計画なし`の項目では同じ観測と結果を引き継ぎ記録へ記し、再開記録の実装commitを検収済みの実装として引き継ぐ。どちらも既存の実装commitを再実装せず、統合区分を`マージなし`として`計画検査完了`をメインへ通知する。計画なしの項目の通知は`計画ファイル: なし`を用いる。追加した処理対象WIの工程があれば続け、全計画の実装有無が確定した後はメインの統合指示を待つ。完成条件を直接観測できない場合は不足する反映状態と観測手段を`needs_escalation`で返す。残存するプロセスや状態が前提を妨げる場合は、その生成主体・起動元・起動契機を現物（親子関係、起動時刻、実行記録、実装など）から調べ、未確定の範囲とともに同じ返却へ書く。OS上の所有者はエージェント・常駐機構・ユーザーを区別しないため、それだけを生成主体の根拠にしない。
`再開位置: 計画なし`では引き継ぎ記録からAWI集合、採否、検証コマンドを取得し、完了commitを`git merge-base <専用branch> <ベースbranch>`と`git log <その結果>..<専用branch>`から得る。レビュー指摘管理表も読み、最後に完了した工程から続ける。計画を新設せず、既にcommitした範囲を再実装しない。

再開位置が`なし`で、いずれの待機条件にも当たらない場合は、計画ファイルの絶対パスと統合区分を次の形式で`atk agents notify`からメインへ送り、応答を待たず実装へ進む。統合区分は`## 実施内容`に採用する実施範囲を持つAWI行がある場合に`マージあり`、無い場合に`マージなし`とする。`マージなし`では実装せず、メインの統合指示を待つ。

```text
計画検査完了
計画ファイル: <絶対パス|なし>
統合区分: <マージあり|マージなし>
AWI: <AWIファイル名のASCIIカンマ区切り>
```

計画なしの調査で設計判断、バグ対応または人間由来の要求の縮小が必要と分かった場合は、差し替えだけで完結する条件を満たさないため、同節の計画起草へ切り替える。
