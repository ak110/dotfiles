# レーン計画の起草と再開

初回選定を受領したレーン担当は最初に、選定結果の各項目の再開位置を読み、`再開位置`を持たないAWI集合へ`agent-toolkit:plan-mode`「計画ファイルの作成要否」を適用する。1件でも作成条件に当たれば、それらを1つの計画へまとめて起草する（分ける条件は「計画の起草」の手順4）。`再開位置`を持つAWIは新しい計画へ含めず、「再開」に従って続ける。

対象リポジトリの版数規範が更新を求める場合は、レーン数を問わずbump種別と根拠を計画へ記録する。同じ実行の中の変更が上位区分に当たる場合は上位区分を選ぶ。版数更新は公開工程の終端担当が行う。

入力はpick-wi-checkが確認・保存した完成済み選定YAMLとレーン識別子から読む（メインの生成入力、候補JSONLと定型欄は委譲プロンプトへ転記されない）。選定の分類と要求の採否は別の判断として扱う。鮮度・省略値・担当モデルが一致しなければ同じ担当の引き継ぎからメインへ返す。準備済み資源の所有登録はatk lane createが保持するため、担当はcwdのworktreeへだけ書き、統合後も資源を回収せず同じthreadで追加を受ける。

## 作成要否と計画なしの準備

全AWIが作成を省く条件に当たる場合は、`atk wi show`で要求と完成条件を読み、由来・採否、AWI集合、最も近い既存実装、直接影響範囲、変更範囲の検証コマンド、統合区分（採用する要求を実装するなら`マージあり`、不要なら`マージなし`）を引き継ぎ記録先へ書く。ユーザーの依頼かWIが明示した禁止条件を持つ場合は、禁止条件と採用手段も同じ記録へ書き、次の形式だけを返してメインの`実装開始`または`実装なし`を待つ。

```text
計画なし準備完了
AWI: <AWIファイル名のASCIIカンマ区切り>
統合区分: <マージあり|マージなし>
```

持たない場合は「計画検査完了の通知」を`計画ファイル: なし`で送り、応答を待たず`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`「実装」へ進む（`マージなし`では実装せずメインの統合指示を待つ）。調査で設計判断、バグ対応または人間由来の要求の縮小が要ると分かった場合は「計画の起草」へ切り替える。

## 計画の起草

1. `agent-toolkit:plan-mode`を起動して同スキルの読込表の資料を読み、AWI、プロジェクト規範、対象実装、既存テスト、生成・配布手段、類似実装を調査する。
   - 対象実装を読む前に、要求と公開契約から比較対象とする最も近い既存実装を選ぶ。境界候補は入力値、時間経過、操作順、保持状態、反復、権限や環境の差などの軸から選ぶ。
   - 調査後は採用案の前提を反証する観点から、変更箇所が責務を負う必要性、既存機構への統合、上流のツールや共有設定への移管、機構の削除・簡素化を比べて計画へ反映する。AWIの`## 実現性`が結論を示した観点は、記述との食い違いを観測しない限り比べ直さない。「設計品質の劣化確認」（`agent-toolkit:writing-standards`の`references/design-heuristics.md`）は常に行う。評価の条件は`agent-toolkit:plan-mode`の`references/plan-file-standards.md`「恒久化・リファクタリング」と同じとする。不具合対策では`agent-toolkit:review-standards`の`references/reviewer.md`「初回レビュー」の「前提を疑う観点」に従い、観測した害の消滅と呼び出す側の修正案も比べる。
   - `選定`の各項目の`鮮度`を計画の`## 変更履歴`へ記録する。`鮮度`が`notice`であるだけでは作業を止めず、現行内容との不一致、既存実装による充足済み、巻戻しの危険のいずれかを観測した項目だけ関連履歴を確認し、観測条件、確認した履歴、採否への影響を同じ記録へ残す。
   - レーン担当はレーン数によらず自レーンの分担を`agent-toolkit:delegation`の`references/routing.md`「要否判定」「委譲単位の確定」で比べる。自身が実施する単位と自身が起動する委譲先へ分ける単位を、理由とともに`## 実施内容`（計画なしでは引き継ぎ記録）へ残す。計画はレーン担当自身が起草し、計画の起草と設計判断を内部群の担当へ委ねるのは独立が明らかな複数タスクに限る。分担には、内容の確定した書込作業の単位ごとに委譲先の段位か自ら行う理由を書く（段位は同スキルの`references/runtime-routing.md`「工程別モデル設定」の段位の段落）。
   - 多数の対象へ同じ作業をする要求では`plan-file-standards.md`「実施内容」の実施方式も比べ、採った方式と理由を残す。
   - 長い比較調査（独立した複製での対照実験など）は、入力と版を固定でき独立した複製へ出力できるなら、`agent-toolkit:writing-standards`の`references/investigation.md`「実行結果の検証」の準備確認の後に通常修正と並行して始める。結果を待つ工程だけを直列にする。順序は先行成果、書込先、観測資源の競合から決め、`## 実施内容`へ書く。
   - 検証コマンドを確定する前に`agent-toolkit:check-execution`を起動し、`references/verification-scope.md`の類型で変更範囲の検証の対象を確定して`## 検証`の`変更範囲の検証`へ加える。加えない対象は理由を`## 要件・外部仕様`の追随範囲へ書く。
   - 変更対象を確定する前に全文を読むのは、候補ファイルと名指しされた基準文書（計画・WI・エージェント向け文書など）を基本とする（努力目標。コンテキスト消費を抑える）。候補の限定や横断的な列挙は探索委譲か検索で結論だけを得る。他の役割の`<役割名>.subagent.md`と変更対象を含まないスキル本体は、検索で必要な箇所だけを読む。
   - 採否を確定する前に、変更対象パスに対応する必須スキル（対応表はプロジェクト規範が示す）を起動し、変更対象の成立条件と禁止条件を定める節を検索で特定して読み、要求と比べる。衝突する要求は`## 実施内容`で不採用または手段変更とし、人間由来なら手順2で通知する。編集の段階で衝突に気付くと、判断要請と実装済み差分の取り消しを招く。
   - `上流投入結果`を受領した場合は、`結果`が`completed`の要求を採用範囲へ含めず、`移管`として投入先の`ファイル名`とともに記録する。
2. 人間由来の要求を不採用または部分採用にする判断は、`agent-toolkit/share/rules-subagent.md`「確認事項の即時通知」で計画の確定前にメインへ通知する。計画確定前にエージェント由来の完成条件を外すメインの技術判断を受領した場合は、`review-loop-coordination.md`「技術判断で外せる完成条件」の境界を保ち、実施内容の根拠欄へ対象AWI・対象条件・`メインの技術判断`・外す根拠を記録する。実装着手後の判断は計画凍結に従いレビュー指摘管理表へ記録する。
3. 通知した確認事項の回答を全て受領して採否へ反映するまでは、回答に依存しない調査と下書きに限って進める。
4. `agent-toolkit:plan-mode`の`references/plan-file-standards.md`「初回起草の雛形」に案件の値を記入し、同書に従って計画本文を起草してmanaged-tempのファイルへ保存する。単一の計画では`plan-check`の行数の警告（1200行）を避けられない見込みなら、実装着手前に分析の単位と依存順で自己完結した複数の計画へ分け、全計画を同じレーン・専用worktree・書込所有者のまま扱う（凍結済み計画の事後分割とレーンの再配分はしない）。計画ファイル（バグ）を作成する場合（同書「バグ調査」）は本文を別のファイルへ保存する。各計画は`atk run-script plan-create -- --main-source <計画本文の絶対パス> --lane <レーン識別子>`で`~/.claude/plans`に作成し、計画ファイル（バグ）があれば`--bugs-source <計画ファイル（バグ）の本文の絶対パス>`も渡す。stemは同処理が生成した値を使う。
5. 計画全体から編集・新設・移動するエージェント向け文書の集合を確定し、全パスをリポジトリ相対パスで計画本文へ明記する。この集合は書込の認可の境界（WIの要求）の内側で着手時に見込んだ書込先の記録であり、実装中の追加は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`「実装」に従う。確認には次のコマンドを単独実行し、集合の全パスを`--agent-rule-path <リポジトリ相対パス>`で反復指定する。

   ```text
   atk run-script plan-check -- --reject-migration-warnings --selection-file <選定結果の出力先ファイル> --lane <レーン識別子> <計画ファイルの絶対パス>
   ```

   終了コード0と警告の不在を確かめる。分けた計画は全計画を位置引数へ並べて1回で実行する。処理中に追加したAWIの計画では、同じレーンの先行する凍結済み計画を全件`--prior-plan <先行計画の絶対パス>`で渡す。不一致のパスは一覧から外さず、計画本文を直して同じ集合で再確認する。各オプションは`agent-toolkit:plan-mode`の`references/plan-structure-check.md`が定める。
6. `## 実施内容`に人間由来の`部分採用`か`不採用`の行がある場合と、ユーザーの依頼かWIが明示した禁止条件が`## 実施内容`にある場合は、次の形式の行だけを返し、同じthreadでメインの`実装開始`または`実装なし`を待つ。それ以外は「計画検査完了の通知」へ進む。

```text
計画作成完了
計画ファイル: <絶対パス>
```

分けた計画では`計画ファイル:`行を作成順に繰り返す。

## 再開

再開位置が計画ファイルの絶対パスなら、`## 概要`、`## 変更履歴`、`## 要件・外部仕様`、`## 進捗ログ`と同stemのレビュー指摘管理表の応答を読み、計画と一致しない箇所は管理表の応答を現在の結論として、進捗ログの最終行が示す位置から既存の計画のまま続ける。

`再開位置: 計画なし`では引き継ぎ記録からAWI集合、採否、検証コマンドを取得し、完了commitを`git merge-base <専用branch> <ベースbranch>`と`git log <その結果>..<専用branch>`から得る。レビュー指摘管理表も読み、最後に完了した工程から続ける。計画を新設せず、commit済みの範囲を再実装しない。

選定結果の`再開位置`が`反映後の観測だけが残る`で始まる項目と、進捗ログの最終行が「反映後の観測だけが残る」と示す再開は、既存の実装commitを再実装せず観測だけを行う。

1. AWI本文の最後の`## 反映後の観測の再開記録`から実装commit、残る完成条件、観測手段（起動条件と根拠の所在を含む）と`計画`の値を読む。`~/.claude/plans`に計画が無ければ`atk plans checkout <private-notes/plans/からの相対パス>`で取得する。起動条件が欠けるか変化を観測した場合は、`finish-session.md`「延期adoptと反映後の観測」に従って現物の実装・設定から補い、到達性を確定してから認可と操作を判定する。
2. 残る完成条件を記録された操作順で新しいプロセスから観測し、結果と報告時点からの差を進捗ログ（`計画`が`計画なし`なら引き継ぎ記録）へ追記する。引き継ぎ記録には観測のみの再開であること、取得した計画のパス、元の専用worktreeの回収状態も記す。`計画なし`の項目は再開記録の実装commitを検収済みの実装として引き継ぐ。取得した計画は`atk plans commit`で保存せず`~/.claude/plans`に置き、保存は`${CLAUDE_PLUGIN_ROOT}/share/lane-integration.subagent.md`「計画最終化」の1回で行う。
3. 統合区分を`マージなし`として「計画検査完了の通知」を送る（計画なしは`計画ファイル: なし`）。追加した処理対象WIの工程があれば続け、全計画の実装有無が確定したらメインの統合指示を待つ。
4. 観測が完成条件を満たさなかった場合も再実装せず`マージなし`とし、満たさなかった完成条件、観測の操作と結果、観測の保存先を進捗ログ（計画なしでは引き継ぎ記録）と返却へ記す。終端区分は`終端しない`とし、`agent-toolkit:process-wi`の`references/run-lanes.md`「採否の確定と終端区分」に従う。
5. 完成条件を直接観測できない場合は、不足する反映状態と観測手段を続行できない理由として返す。残存するプロセスや状態が前提を妨げる場合は、その生成主体・起動元・起動契機を現物（親子関係、起動時刻、実行記録、実装など）から調べて未確定の範囲とともに書く。OS上の所有者はエージェント・常駐機構・ユーザーを区別しないため、それだけを生成主体の根拠にしない。

## 計画検査完了の通知

再開位置が`なし`で、いずれの待機条件にも当たらない場合は、次の形式を`atk agents notify`でメインへ送り、応答を待たず実装へ進む。統合区分は計画ごとに、採用する実施範囲を持つAWI行があれば`マージあり`、無ければ`マージなし`とする。分けた計画では3行の組を計画ごとに作成順で繰り返し、`AWI:`へはその計画の`関連WI`だけを書く。全ての組が`マージなし`なら実装せずメインの統合指示を待つ。

```text
計画検査完了
計画ファイル: <絶対パス|なし>
統合区分: <マージあり|マージなし>
AWI: <AWIファイル名のASCIIカンマ区切り>
```
