# push、CIおよび終了

公開工程は選定工程で固定した集合の全レーンが完了し、選定工程で自動コードレビュー監査を起動した場合はその返却の受領と処置の確定も終えた時点で開始する。
通常レーンはffマージ、`adopt`および後始末まで、固有指示で`adopt`を延期したレーンと`上流投入`が`混在`のレーンはffマージと実装資源回収まで完了した状態を開始条件とする。
`混在`のレーンは元項目を依存付きで`inbox`へ戻した状態とする。
ready一覧は選定工程で取得した内容を保ち、再取得しない。active一覧は公開工程の開始時点の内容として扱い、ここで処理するのは選定時に固定した項目と、ユーザーの明示指示で`選定結果の出力先ファイル`へ追記した項目から渡された終端工程だけとする。その他の新着はprocess-wiの次の実行へ残す。

## 公開対象が無い場合の短絡

公開工程の開始時に、公開対象と外部操作が1つも無いことを確認する。pickerの`選定`では、`レーン`が`なし`、`上流投入`が`なし`以外、または`プロジェクト固有の公開後の操作の順序`が`既定`以外の項目だけを外部操作として数える。省略された行はpickerが定める省略時の値で解釈する。レーンの統合による未公開のcommitは、後段の「公開状態の4項目」の判定で検出する。このセッションで回答を受け取ったUWI、選定工程で記録したプロジェクト固有の公開後の操作およびレーン工程から受け取った延期`adopt`の対象も確認する。

いずれもが無い場合は、メインが`agent-toolkit:commit`の`references/push-and-ci.md`「公開状態の4項目」を対象リポジトリの主作業ツリーから読み取り専用で取得する。公開状態の4項目が全て成立する場合は終端担当を起動せず、「セッション終了」節へ進む。

いずれかがある場合と、4つの観測項目に成立しないものがある場合は、終端担当への委譲を通常どおり実施する。
短絡時に全成立を確認した公開状態の4項目は、後段の「セッション終了」節へ検収済みの公開状態として引き継ぐ。

## セッション終了

対象リポジトリの規範が、対応する管理先への計上または終端と同じ工程で固有の追跡先への記載を求める場合は、その規範が定める対象と記載先を確認し、対応する記載を完了してからセッションを終端する。

終端担当の入力がそろい、対象リポジトリの主作業ツリーへ書き込む主体が解放された時点で終端担当を起動する。外部APIへcommitを渡す終端処理では、`agent-toolkit:commit`の`references/publish.md`「pushと公開状態」の完全OID解決契約を適用する。branch名または短縮OIDを公開契約として受理する操作へは拡張しない。対象リポジトリへ書き込まず、かつ終端担当の入力を生成しない工程の完了は待たず、その工程を起動後に実施する。この条件を満たすキュー投入に加え、公開結果に依存しない既知の警告の読取調査とmanaged-tempの中でのAWI原稿準備は、終端担当の公開・CI待機と並行して進める。メインは起動時に調査対象、既存の証拠、反映先候補を独立した担当へ渡し、その担当は主作業ツリーとprivate-notesへ書き込まない。準備した証拠と原稿は公開後に`agent-toolkit:session-review`へ渡し、正式な候補選別の結果と現行状態に照らして採否を確定する。公開結果に依存する問題は結果確定後に調べる。キュー投入は`${CLAUDE_PLUGIN_ROOT}/share/add-wi.parent.md`に従い、終端担当の起動と同じ工程で、同書「起動方法」の単位で投入担当へ委譲する。投入担当の完了と独立して終端担当を起動する。投入担当の書込先はprivate-notesとする。終端担当の観測によって初めて内容が確定する項目は、終端担当の返却後に、同書「起動方法」の単位に従って投入担当へ渡す。

終端担当の起動前に、長時間の公開・デプロイ・CI待機と追加の公開工程について、各工程の入力commit、成果物、配備先、排他資源および先行工程の成功結果への依存を進捗記録へ書く。終端担当への指示には待機対象と並行開始できる工程を区別して示し、後者を終端担当の実行対象から外す。これらが独立する追加工程は別の実行主体へ渡し、長時間工程の終端待ちと並行して開始する。例えば`deploy_azure_vm`の待機中に別の成果物と配備先へ緊急デプロイする工程は並行できる。同じDB migrationの成功を必要とするデプロイは、先行工程の成功を確認してから開始する。

専用worktreeとレーン専用branchの回収は前項の対象から外し、終端担当の起動前に完了する。`git worktree remove`と`git branch -D`は対象リポジトリのGit共通ディレクトリ（`--git-common-dir`）を書き換える。そのため`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`「起動前の前提」が定める単一の書込主体と競合する。

全レーンの統合と専用資源の回収が終わったら、開発マシン上の常時稼働サーバーへの反映を終端担当の公開・CI待機と並行して始める。対象は`agent-toolkit:completion-report`「工程」手順1が定める反映手段と稼働確認手段の双方を持つプロジェクトとする。反映が対象リポジトリへ書き込まず、終端担当の入力を生成せず、読み取る成果物と排他資源が終端担当の操作と競合しないことを確かめる。終端担当を起動するprocess-wiの実行ではその起動直後に始め、公開対象が無く起動を省く実行では資源回収の直後に始める。メインは反映したHEADの完全OID、反映コマンドの終了状態と稼働確認の結果を保持し、完了報告へ渡す。

メインはレーン数を問わず、各レーンの記録を対象リポジトリの版数規範の判定基準で比較し、未公開の統合変更へ適用する最上位の`bump種別`を確定する。公開工程のうち、版数更新、生成物同期、push前に実行するチェックの選定と実行、push、CI確認、検証失敗時の修正（終端担当が起動するCI修正担当が主作業ツリーで行う）、終端担当自身の実行対象としたプロジェクト固有の公開後の操作および延期`adopt`を1件の終端担当へ委譲する。起動、渡す入力、受領と検収は`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`が定める。同書を全文読んでから起動する。終端担当は`agent-toolkit:commit`の`references/publish.md`「検証とCI」に従い、全体検証をCIの結論で判定し、push前にはCIが実行しないチェックと全体走査のチェックを実行する。終端担当の稼働中に対象リポジトリの主作業ツリーへ書き込む主体は、終端担当と終端担当が起動したCI修正担当に限り、同時に書き込む主体は常に1つとする。メインの作業は読取に限る。

終端担当の返却後、`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`から受け取った延期`adopt`の未終端集合について、稼働環境への反映の終了状態と対象HEADを確かめる。反映後の新しいプロセスを起動でき、残る完成条件を直接観測した項目は、検収済みの実装commitを対応付けた`atk wi adopt`で終端する。実装差分の無い項目は`--commit`を省き、観測の根拠をnoteへ記す。新しいプロセスを起動できない項目と、残る完成条件を観測できなかった項目は`inbox`へ戻さず、次段落で`references/run-lanes.md`「採否の確定と終端区分」の判定に従って扱う。
commitを記録する採否操作は`agent-toolkit:wi-standards`「状態と依存」の共通前提に従い、
対象リポジトリの主作業ツリーの絶対パスを`--target-repo`へ渡す。

続けて、終端担当の起動を省いた実行も含め、処理対象WI（ユーザーの明示指示で追加した項目を含む）のうち、このセッションのレーン統合で計画を保存したAWIの状態を確かめる。確かめる対象は統合の返却`保存した計画ファイル`が挙げた各計画の`関連WI`とし、全件を`atk wi show <ファイル名>... --summary-only --target-repo=<対象リポジトリの絶対パス> --skip-pull`へ渡す。見出し行`### <ファイル名> [<状態>]`が`processing`を示す項目の計画を`~/.claude/plans`へ戻す。延期`adopt`の未終端集合と、観測のみの再開で統合が`終端しない`とした項目は、どちらもこの対象に含まれる。保存先相対パスを指定した`atk plans checkout`で計画を`~/.claude/plans`へ戻し、`~/.claude/plans`に同名の計画が既にある場合は取得を省く。`atk run-script plan-progress --`で実装commit、残る完成条件、観測の前提、反映後の観測手段および「反映後の観測だけが残る」再開位置を`## 進捗ログ`へ記録する。記録した計画は、後段の再開記録を追記した後に`atk plans commit`で保存する。次回のpickerはAWI本文の再開記録から再開位置を返すため、計画が`~/.claude/plans`に無くても再開できる。
観測の前提をユーザーの操作または追加認可でしか整えられないと判定した項目は、計画を戻した後に`agent-toolkit:wi-standards`に従ってUWIを保存する。UWIの本文には、元AWIのファイル名、ユーザーが行う操作と返してほしい観測結果、観測できない場合に完成条件の扱いを変えるにはユーザーの明示判断が要ることを書く。保存の成功を確かめてから`atk wi hold --state=processing <元AWIのファイル名>`で元AWIを保留し、進捗ログの再開位置には保存したUWIのファイル名と、その回答の観測結果で残る完成条件を判定することを添える。`hold`の項目は次回のpickerの選定対象から外れ、回答後は`agent-toolkit:wi-standards`「状態と依存」の回答済みUWIの取り込みで同じ計画の観測工程から再開する。UWIを保存できなかった項目は`hold`へ移さず`processing`を維持する。未回答の確認が無いまま保留すると、再開の契機が失われる。

反映後の観測だけが残る未終端の項目（延期`adopt`の未終端集合と、観測のみの再開で統合が`終端しない`とした項目）には、計画の有無によらず、次の形式の再開記録をAWI本文へ追記する。記録をmanaged-tempの中のファイルへ書き、`atk wi edit <ファイル名> --append --body-file <その絶対パス> --target-repo=<対象リポジトリの絶対パス>`で追記する。次回のpickerは最後の同名節を読み、`~/.claude/plans`に計画が無くても観測のみの再開位置を返す。計画を持たない項目は引き継ぎ記録が次のセッションへ届かないため、この記録が唯一の再開の手掛かりになる。

```markdown
## 反映後の観測の再開記録

- 再開区分: 反映後の観測だけが残る
- 実装commit: <検収済みの実装commitの完全OID。実装差分の無い項目は「なし」と充足の根拠>
- 残る完成条件: <観測で確かめる完成条件>
- 観測手段: <新しいプロセスでの観測の操作と確かめる結果>
- 観測できる最も早い時刻: <タイムゾーン付きISO 8601日時|不明>
- 計画: <`private-notes/plans/`からの相対パス|計画なし>
```

観測できる最も早い時刻が分かり、現在がその時刻より前の項目は、待機せずに次の手順でprocess-wiの次の実行へ渡す。再開記録の追記の成功を確かめてから`atk wi return-to-inbox <ファイル名> --target-repo=<対象リポジトリの絶対パス>`で`inbox`へ戻す。続けて`atk wi edit <ファイル名> --cooldown-until <その時刻> --target-repo=<対象リポジトリの絶対パス>`で再処理抑制期限を付け、セッションの終了工程へ進む。期限前の項目はpickerの候補にならず、期限後に通常の`inbox`の項目として選定される。その他の項目の状態は`references/run-lanes.md`「採否の確定と終端区分」の判定に従う。

completion-reportが報告する前に、メインは公開状態の4項目（`agent-toolkit:commit`の`references/push-and-ci.md`）が検収済みかを確認する。
短絡時の検収か`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`「受領と検収」のいずれかで得た公開状態の4項目は、主作業ツリーや対象refを変える操作、外部更新が間に観測されなければ、そのまま用いる。
状態が変わった場合と公開状態の4項目が未検収の場合だけ、現在のGit状態から取得し直す。終端担当が返した`ベースbranchの状態`だけでは検収済みと扱わない。
終端担当の返却後と`agent-toolkit:completion-report`の振り返り後に、主作業ツリーのHEAD、追跡ref、最新HEADのCIと作業ツリーの状態を確認する。前回pushのOIDからベースbranchへ新しいcommitが統合された場合は、全レーンの終端と書込主体の解放を確かめ、追加差分のbump種別、プロジェクト固有の公開後の操作および延期`adopt`だけを入力にして同じ終端手順を再実行する。主作業ツリーで直接作成した是正commitも追加差分に含める。再実行の返却を検収し、最新HEADのpushとCI成功を確かめる。新しいcommitが無い場合は再起動せず、既存のUWIへの報告処理へ進む。公開状態の不成立が新しいcommit以外に起因する場合は、`agent-toolkit:wi-standards`を起動してUWIを登録し、観測結果を報告へ含める。
公開工程の完了後に`agent-toolkit:completion-report`を起動する。完了報告と振り返りをユーザーへの報告（報告用UWI）として保存し、`agent-toolkit:wi-standards`「投入と取得」手順9の検収が成立してからセッションを終了する。振り返りが失敗した場合も未完了部分を同じUWIへ明示し、重複するUWIを投入しない。手順と報告内容は同スキルに従う。
自律モードのユーザーへの伝達は報告用UWIの保存の検収で完了し、Stop hookが可視発話に本文を求めるのは協調モードの報告に限る。作業完了報告の後に振り返りの結果報告へ進まない停止は自律モードでも遮断の対象となり、対処は`agent-toolkit:completion-report`の工程の末尾に従う。

公開工程の後にactive一覧へ現れた追加分は、次回セッションで扱う。

未終端の計画の復元は本節のメインによる保存後checkoutへ集約し、統合入力は全計画保存だけを指示する。
