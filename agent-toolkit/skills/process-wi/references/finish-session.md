# push、CI及び終了

公開工程の開始時に、通常レーンがffマージ、`adopt`及び後始末まで完了し、固有指示で`adopt`を延期したレーンがffマージと実装資源回収を完了したprocess-wiのメインがこの文書を全文読む。
`upstream_submission`が`混在`のレーンは、ffマージと実装資源回収を完了し、元項目を依存付きで`inbox`へ戻した状態を公開工程の開始条件とする。
選定工程で固定した集合の全レーンが完了し、かつ選定工程で起動した自動コードレビュー監査の返却の受領と処置の確定を終えた時点で公開工程を開始する。ready一覧は選定工程で固定した内容のまま扱う。
ここで処理するのは先行レーンが渡した終端工程だけとし、active一覧も公開工程の開始時点の内容のまま扱う。
自動コードレビュー監査は選定工程で実施し、公開工程ではその処置の確定だけを扱う。

## 公開対象が無い処理回の短絡

公開工程の開始時に、公開対象と外部操作が1つも無いことを次の5項目で確認する。pickerが返した`decisions`の項目、このセッションで回答を受け取ったUWI、選定工程で記録した固有の終端工程、レーン工程から受け取った延期`adopt`の対象、及びレーン工程の各レーンが返した`merged_head`である。

5項目のいずれもが無い場合は、メインが`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`の「受領と検収」節を全文読み、同節が挙げる4つの観測項目を対象リポジトリの主作業ツリーから読み取り専用で取得する。4項目が全て成立する場合は、版数更新、生成物同期、push、CI確認及び固有の終端工程を担う終端担当を起動せず、「セッション終了」節へ進む。

5項目のいずれかがある場合と、4つの観測項目に成立しないものがある場合は、終端担当への委譲を通常どおり実施する。

短絡した処理回でも、「セッション終了」節が定める`agent-toolkit:completion-report`の前のベースbranchの公開状態の観測を実施する。

## セッション終了

対象リポジトリの規範が、対応経路への計上又は終端と同じ工程で固有の追跡先への記載を求める場合は、その規範が定める対象と記載先を確認し、対応する記載を完了してからセッションを終端する。

メインは公開工程の工程のうち、版数更新、生成物同期、全体検証の要否判定、push、CI確認、検証失敗時の主作業ツリーでの修正、固有の終端工程及び延期`adopt`を1件の終端担当へ1回だけ委譲する。起動、渡す入力、受領と検収は`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`が定める。同書を全文読んでから起動する。終端担当は`${CLAUDE_PLUGIN_ROOT}/share/session-termination.subagent.md`「生成物とpush」に従い、対象リポジトリのタスクランナーが定める全体検査とCIの同値性から全体検証の要否を決める。終端担当の稼働中に対象リポジトリの主作業ツリーへ書き込む主体は、終端担当だけとする。

通常の公開では`検証・CI方針: 通常`を渡す。`SKILL.md`「局所変更の即時公開」の条件が全て成立する場合だけ、`検証・CI方針: 即時対応`と、成功した近接検査のコマンド・終了コード、正式対応AWIのファイル名を渡す。即時対応では全体検査とCI成功の待機を省略するが、push後のCI起動とrun URLは確認する。省略した全体検査、未確定のCI、run URL及び正式対応AWIをcompletion-reportへ含める。

completion-reportが報告する前に、メインがベースbranchの公開状態を1回観測する。
観測前に`${CLAUDE_PLUGIN_ROOT}/share/session-termination.parent.md`の「受領と検収」節を全文読み、同節が挙げる4つの観測項目を現在のGit状態から再取得する。
再観測は現在のGit状態から行い、終端担当が返した`base_branch_state`は参考値として扱う。
終端担当の終端後にセッションで生じた成果（主作業ツリーの是正commit、及び追加した是正レーンの統合commitを含む）がある場合は、その成果をローカルのベースbranchへ保持し、次のセッションの公開工程で公開する。終端担当の起動は1セッションにつき1回に保つ。この制約の正本は`SKILL.md`の「不変条件」とする。その他の理由で成立しない項目がある場合は、`agent-toolkit:wi-standards`をSkill機能で起動してUWIを登録し、観測結果を報告へ含める。
公開工程の完了後に`agent-toolkit:completion-report`を起動する。同スキルが定める手順と報告内容は、同スキルを正本とする。

公開工程の後にactive一覧へ現れた追加分は、次回セッションで扱う。
