# レーンの実行

pickerが固定した集合を、選定結果のレーン割当と依存順に従って実行する。各レーンの同じ担当threadが、計画の起草、実装、レビュー修正、履歴統合及び主作業ツリーへの統合を担う。

## レーンと資源

レーンごとに専用branchと専用worktreeを1つ作成する。作成前にベースbranchの7文字以上の一意な短縮OIDを取得し、用途、管理対象領域、作成時HEAD、作成主体、所有主体、回収対象及び専用branch名を記録する。対象リポジトリが定めるworktree前提ファイルとmise trustを準備する。

同じレーンへ割り当てられたAWIはpickerの実装依存順を維持し、1つの計画へまとめる。異なるレーンは別worktreeで並行できる。依存するレーンは先行レーンの統合完了後に開始する。

レーン担当の起動前に`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`を全文読み、pickerの固定出力ファイルとレーン識別子を含む同書所定の入力を渡す。AWI名、由来及び`project_notes`は起動文へ再掲せず、レーン担当が固定出力から自レーンのdecisionだけを読む。新規レーンの`再開位置`は`なし`とする。レーン担当の稼働中、メインは当該worktreeへ書き込まない。

## メインが読む対象の境界

メインはpickerの構造化出力、計画の`## 概要`と`## 実施内容`、レーン担当の工程境界出力、レビュー表の状態、統合結果だけを読む。AWI本文、計画の他の節、実装差分は、エスカレーション、ユーザー介入又はレビュー収束判断で内容が必要になった場合だけ読む。

## 計画の起草と実装開始

レーン担当が計画を起草し、`check_plan_file.py --reject-migration-warnings`の成功後に`計画作成完了`と絶対パスを返す。メインは`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`の「計画作成完了の受領」に従い、由来と採否を照合する。

採用する実施範囲がある場合は同じthreadへ`実装開始`を返す。採用範囲が無い場合は`実装なし`を返し、実装と実行レビューを省略して統合へ進む。確認が必要な不採用範囲がある場合は、依存しないレーンを進めながら次節で採否を確定する。

## 採否の確定と終端区分

人間由来の要求を全部又は一部不採用にする場合は、当該範囲、原文との差異、技術的理由、代替案をユーザーへ示して確認する。行全体の採否値だけで判定せず、部分採用の除外範囲も確認対象とする。確認を得るまで当該レーンへの返却値を確定せず、当該AWIを終端しない。

回答を得られない場合は`agent-toolkit:wi-standards`に従ってUWIを登録し、元AWIへ依存を追加して`inbox`かつ`blocked`へ戻す。計画ファイルの`## 進捗ログ`へ確認事項と再開位置を記録し、作業rootに残す。当該AWIを同じ処理回で採用又は不採用として確定しない。

第2段として、各AWIを次の終端区分へ割り当てる。

- 採用した要求を実装し、完成条件を満たした項目: `adopt`
- 既存実装で要求と完成条件を満たすことを実測した項目: `adopt`
- 人間由来の不採用について確認を得た項目、又はエージェント由来の要求を根拠付きで不採用にした項目: `reject`
- ユーザー回答、外部状態又は上流変更を待つ項目: この処理回では終端せず`inbox`へ戻す

複数要求を持つAWIは、採用した要求を全て満たした場合に`adopt`する。一部に未解決の保留が残る場合はファイル全体を終端しない。固有指示が終端工程後のadoptを求める場合は延期対象とする。

## 実装とレビュー

レーン担当から`実装完了`と`検証結果`を受領し、欠落があれば同じthreadへ返却を求める。受領後に`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`へ従い、指摘管理表を準備して計画をレビュー基準とする実行レビューを1件起動する。

指摘への修正は同じレーン担当threadへ`レビュー修正担当`として返す。`${CLAUDE_PLUGIN_ROOT}/share/review-loop-coordination.md`に従って収束させ、別の修正主体を同じworktreeへ起動しない。収束後、レーン担当がレビュー修正の履歴を統合する。

レビュー収束後、メインは計画の`## 実施内容`を再読する。対象は、計画起草時、実装時又はレビュー修正時に追加された全ての行とする。`根拠`が`事後承認対象:`から始まる行がある場合は、`agent-toolkit:confirmation-and-uwi`と`agent-toolkit:wi-standards`を起動する。当該行が保持するユーザーが観測する結果、採用理由及びトレードオフを事後承認型UWIへ記録する。複数行は、ユーザーが1件の判断で回答できる同じ変更だけを1件へまとめる。投入の成功と正本ファイル名を確認してから統合へ進み、回答は待たず元の作業を続ける。該当行が無い場合はUWIを投入しない。レーン担当はこのUWI投入を担わない。

## 統合とAWI終端

`${CLAUDE_PLUGIN_ROOT}/share/lane-integration.parent.md`を全文読み、同じレーン担当threadへ統合指示を送る。マージありでは専用branchをベースbranchへfast-forwardし、マージなしではベースbranchを変更しない。計画最終化とAWI終端も同じthreadが行う。

統合結果のOID、計画保存及びAWI終端を検収した後、レーン担当の終端と外部プロセスの終了を確認する。専用worktreeと管理対象一時領域は、それらを入力とする全工程が完了してから作成時の管理経路で回収する。

## 中断レーンの再開

`processing`のまま残った項目では、pickerが`atk plans list`と計画の`関連WI`から特定した作業root内の計画ファイルを`再開位置`として使う。メインは計画ファイルが実在すること、関連WIが当該レーンのAWI集合と一致すること及び専用worktreeの所有主体が終端済みであることを確認する。

残存する専用worktreeとbranchが安全に再利用できる場合は、新しいレーン担当へ同じ絶対パス、branch、現在HEAD及び計画ファイルを渡す。再利用できない場合は、既存成果を失わない新しい専用worktreeを現在HEADから作成し、計画の`## 進捗ログ`へ移行内容を記録する。未コミット差分の復元、破棄又は別worktreeへの移送が必要な場合は独自に処理せず確認経路へ送る。

再開担当は計画の`## 概要`、`## 変更履歴`、`## 要件・外部仕様`及び`## 進捗ログ`を読み、完了済み工程を再実行せず最初の未完了工程から続行する。キュー項目へ再開位置を追記しない。

## レーン完了

全レーンについて統合結果の検収、AWIの終端又は保留への遷移、計画保存及び資源回収を完了する。選定時に固定していない項目を追加せず、振り返りと監査の処置確定後に公開工程へ進む。
