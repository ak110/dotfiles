# レーンの実行

pickerが固定した集合を、選定結果のレーン割当と依存順に従って実行する。各レーンの同じ担当threadが、計画の起草、実装、レビュー修正、履歴統合及び主作業ツリーへの統合を担う。

## レーンと資源

レーンごとに専用branchと専用worktreeを1つ作成する。作成前にベースbranchの7文字以上の一意な短縮OIDを取得し、用途、管理対象領域、作成時HEAD、作成主体、所有主体、回収対象及び専用branch名を記録する。対象リポジトリが定めるworktree前提ファイルとmise trustを準備する。

専用worktreeが検証に必要な環境をベース作業ツリーから引き継がない場合は、対象リポジトリの開発手順が定める環境構築をworktreeの作成と同じ工程で背景ジョブとして開始する。作成主体はジョブの終了コードと出力を観測し、終了コード0と警告の不在を確認してからレーン担当を起動する。完了を確定できない場合と失敗した場合は、レーン担当の起動文へ環境構築を自ら実行する旨を渡す。起動文には、環境構築が完了済みかレーン担当が実行するかの一方を明記する。

環境を構築する作成主体の書込みはレーン担当の起動前に終端する。レーン担当の稼働区間と重ねないことで、専用worktreeへ書き込む主体を1つに保つ。

同じレーンへ割り当てられたAWIはpickerの実装依存順を維持し、1つの計画へまとめる。異なるレーンは別worktreeで並行できる。依存するレーンは先行レーンの統合完了後に開始する。

レーン工程の進行中に稼働レーンが1つになった時点では、そのまま続行する。そのレーンの未着手のAWIを新しいレーンへ移さない。
移す方式は、計画ファイルの分割と書込所有権の移譲を要し、実行工程で計画ファイルを更新しない方針と両立しない。
単独稼働の区間は、選定工程が1レーンの見込みの上限を守ることで短くする。

レーン担当の起動前に`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`を全文読み、pickerの固定出力ファイルとレーン識別子を含む同書所定の入力を渡す。AWI名、`project_notes`及び上流投入の各値はレーン担当が固定出力から自レーンのdecisionを読んで取得するため、起動文と`固有指示`へは再掲しない。要求単位の由来はレーン担当が計画の起草時にAWI本文とfrontmatterから判定し、計画の`由来`欄へ書く。メインと統合担当は由来を再判定せず、確定済みの採否と終端区分を用いる。新規レーンの`再開位置`は`なし`とする。レーン担当の稼働中に専用worktreeへ書き込む主体は、レーン担当だけとする。

## 処理中に確定した必須是正レーン

ユーザーの是正要求か`agent-toolkit/rules/01-agent.md`「完遂と先送り」により同一セッション修正が必須となり、本文、実現性、完成条件が確定したAWIを保存した場合だけ、固定済み選定集合へ是正レーンとして追加する。追加できるのはこの条件を満たすAWIに限り、通常の新着AWI、未回答UWI、要求が未確定の項目は固定集合の外に置く。ready一覧も選定時の内容のまま扱う。

追加時は、先行レーンの成果を入力とする実依存、確定済みのproduction・rule書込集合、残るクリティカルパス及び統合待ちを別々に判定し、割当理由へ各判定を記録する。production・ruleの実ファイルが重なる場合は単一writerを維持する。書込集合を分離でき、重複が検体又は補助記録だけの場合は、その重複だけを理由に直列化せず、新しいレーンと統合時の調整を候補に含める。
変更対象か書込領域が稼働中レーンと重なり、同じthreadと資源で現在工程後に新しい計画を作成できる場合は、そのレーンへ追加割当する。
固定出力の当該decisionへAWIを追加した時点で、現在工程の完了を待たずに事前通知を追送する。
事前通知は追加AWI名、継続する専用worktreeとbranch、継続する引き継ぎ記録先、及びAWI本文と`project_notes`を固定出力から取得する指示を持ち、現在工程を置換せず工程境界後に追加作業が続くことを伝える。配送状態の意味と継続手段は`${CLAUDE_PLUGIN_ROOT}/skills/delegation/references/waiting-and-monitoring.md`を正本とする。`send_message`が返す`delivery: steered`は、通知を配送キューへ投入した状態だけを確認する。
受領レーンは現在工程を中断せず、所定の工程境界を返してturnを終える。メインは境界結果を受領した後に、同じthreadへ追加集合の計画起草を開始する指示を送り、`delivery: reply_started`を観測して初めて開始済みとする。承認済みの既存計画は更新しない。
`reply_started`を観測する前にレーンが終端した場合は、`agents_server`の公開応答から同じthreadを再開できるかを判定する。再開可能な場合は同じthreadへ開始指示を送り、再開不能な場合だけ新しい是正レーンを作成する。現在の工程境界を受領する前に新しいレーン又はworktreeを作成しない。

稼働中レーンへの追加割当が実依存、現在工程、書込所有権の条件を満たさない場合は、専用branchと専用worktreeを持つ新しい是正レーンを作成する。
実依存が無い新規レーンは、統合待ちがあっても計画と実装を直ちに開始する。`agent-toolkit:session-review`の稼働と`agent-toolkit:completion-report`の残る手順は、それ自体では是正レーンの開始を待たせる条件にしない。実依存があるレーンの開始と、全レーンの主作業ツリーへの統合だけを依存順及び書込所有権に従って直列化する。

是正レーンにも本書の計画、レビュー、失敗時の再開、AWI終端及び資源回収の契約をそのまま適用する。追加したAWIとレーン割当は以後の固定集合として保持する。

同じセッションで共有ツール又は手順を修正し、残作業でその修正を使う稼働中レーンがある場合は、対象レーンへ1回のメッセージで通知する。通知には修正commit、実行時に変更を読み込む時機、再起動の要否及び反映前の回避手順を含める。レーンの現行操作を維持し、そのツール又は手順を使うレーンだけへ通知する。

## メインが読む対象の境界

メインはpickerの構造化出力、計画の`## 概要`と`## 実施内容`、レーン担当の工程境界出力、レビュー表の状態、統合結果だけを読む。AWI本文、計画の他の節、実装差分は、エスカレーション、ユーザー介入又はレビュー収束判断で内容が必要になった場合だけ読む。

## 計画の起草と実装開始

レーン担当が計画を起草し、`check_plan_file.py --reject-migration-warnings`の成功後に`計画作成完了`と絶対パスを返す。メインは`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`の「計画作成完了の受領」に従い、採否を照合する。

採用する実施範囲がある場合は同じthreadへ`実装開始`を返す。採用範囲が無い場合は`実装なし`を返し、実装と実行レビューを省略して統合へ進む。確認が必要な不採用範囲がある場合は、依存しないレーンを進めながら次節で採否を確定する。

## 採否の確定と終端区分

レーン担当は計画の起草時に要求単位の由来を判定する。人間由来の要求を全部又は一部不採用にする場合は、その範囲、原文との差異、技術的理由、代替案を計画の確定前にメインへ即時報告し、メインがユーザーへ示して確認する。確認対象には、行全体の採否値に加えて部分採用の除外範囲も含める。回答を計画へ反映するまで`計画作成完了`を返さない。計画確定後の工程は由来を再判定せず、計画で確定した採否を用いる。

回答を得られない場合は`agent-toolkit:wi-standards`に従ってUWIを登録し、`atk wi hold`で元AWIを保留する。そのUWIの本文へ、保留した元AWIのファイル名と回答後に再開する工程を書く。`atk run-script plan-progress --`で計画ファイルの`## 進捗ログ`へ確認事項と再開位置を記録し、作業rootに残す。採用又は不採用としての確定は、回答を受け取ってから行う。同じ処理回で回答を受け取った場合は、その回答を反映して同じレーンで採否を確定する。

第2段として、各AWIを次の終端区分へ割り当てる。

- 採用した要求を実装し、完成条件を満たした項目: `adopt`
- 既存実装で要求と完成条件を満たすことを実測した項目: `adopt`
- 計画確定前の確認を含む必要な採否工程を終え、不採用と確定した項目: `reject`
- 回答を保存した事前承認型UWIと、その回答を反映して採否を確定した元AWI: 双方を`adopt`
- ユーザー回答を待つ項目: この処理回では終端せず`atk wi hold`で保留する
- 外部状態又は上流変更を待つ項目: この処理回では終端せず`inbox`へ戻す

複数要求を持つAWIは、採用した要求を全て満たした場合に`adopt`する。ファイル全体を終端するのは、未解決の保留が残らない場合とする。固有指示が終端工程後のadoptを求める場合は延期対象とする。

## 実装とレビュー

レーン担当から`実装完了`と`検証結果`を受け取り、欠落があれば同じthreadへ返却を求める。受領後に`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`へ従い、指摘管理表を準備して計画とWIをレビュー基準とする実行レビューを1件起動する。レーンのWIは計画の`## 実施内容`から実行レビュー担当が取得するため、起動文はWI記録を含めずに構成する。

指摘への修正は同じレーン担当threadへ`レビュー修正担当`として返す。`${CLAUDE_PLUGIN_ROOT}/share/review-loop-coordination.md`に従って収束させ、同じworktreeの修正主体をレーン担当1つに保つ。収束後、レーン担当がレビュー修正の履歴を統合する。

メインは、レーン担当から確認事項又は事後承認の対象を受け取った時点で、`agent-toolkit:confirmation-and-uwi`と`agent-toolkit:wi-standards`に従って発行要否を判定する。発行対象は受領時に発行し、事後承認型UWIでは投入の成功と正本ファイル名を保持して回答を待たず元の作業を続ける。レビュー収束後、受領した全対象について発行が完了し、事後承認型UWIの投入成功と正本ファイル名を検収済みであることを確認してから統合へ進む。

## 統合とAWI終端

`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`「統合の指示と受領」に従い、同じレーン担当threadへ統合指示を送る。マージありでは専用branchをベースbranchへfast-forwardし、マージなしではベースbranchを現在の状態のまま保つ。計画最終化とAWI終端も同じthreadが行う。

統合結果のOID、計画保存及びAWI終端を検収した後、レーン担当の終端と外部プロセスの終了を確認する。専用worktreeと管理対象一時領域は、それらを入力とする全工程が完了してから作成時の管理経路で回収する。

## 中断レーンの再開

`processing`のまま残った項目では、pickerが`atk plans list`と計画の`関連WI`から特定した作業root内の計画ファイルを`再開位置`として使う。メインは計画ファイルが実在すること、関連WIがそのレーンのAWI集合と一致すること及び専用worktreeの所有主体が終端済みであることを確認する。

残存する専用worktreeとbranchが安全に再利用できる場合は、新しいレーン担当へ同じ絶対パス、branch、現在HEAD及び計画ファイルを渡す。再利用できない場合は、既存成果を失わない新しい専用worktreeを現在HEADから作成し、`atk run-script plan-progress --`で計画の`## 進捗ログ`へ移行内容を記録する。未コミット差分の復元、破棄又は別worktreeへの移送が必要な場合は独自に処理せず確認経路へ送る。

再開担当は計画の`## 概要`、`## 変更履歴`、`## 要件・外部仕様`及び`## 進捗ログ`を読み、完了済み工程を再実行せず最初の未完了工程から続行する。再開位置の記録先は計画ファイルとし、キュー項目は現在の本文のまま保つ。

## レーン完了

全レーンについて統合結果の検収、AWIの終端又は保留への遷移、計画保存及び資源回収を完了する。追補の対象は本書の必須是正レーンだけとし、通常の新着項目は次回セッションで扱う。監査の処置確定後に公開工程へ進む。
