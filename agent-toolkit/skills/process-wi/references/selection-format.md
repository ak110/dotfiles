# 選定YAMLの項目と省略規則

選定YAMLは対象リポジトリごとに生成・保存する。
all-reposでも各リポジトリ担当が自分の取得済み候補から作成し、複数リポジトリの候補数やレーンを1つのYAMLへまとめない。
候補の受領は[all-repos-orchestration.md](all-repos-orchestration.md)、分類と検収は[selection-procedure.md](selection-procedure.md)が定める。

## 選定の生成入力

[selection-procedure.md](selection-procedure.md)の生成付き操作へ渡す意味判断YAMLは、後掲の`選定`と`レーンの所要時間`、必要な比較値・重なり・続行できない理由を持つ。各選定項目の`WI`・`レーン`・`書込対象`と分類、担当モデル、配置根拠、見込みと規範指定はメインが確定する。`鮮度`と最上位の`初回配分`は生成側が作成するため入力へ置かない。指定のない担当モデルの省略は未指定のまま保ち、生成側は推測しない。0件も`選定: []`と`レーンの所要時間: []`を明示する。

候補入力は`atk wi list --jsonl --with-staleness`の取得済み出力本文とし、各行の`filename`と`staleness`をそのまま読む。JSON配列も受理する。通常の除外条件に当たる候補だけを`除外候補: ['<WI名>']`へ置く。省略時の値は空列であり、不在も空列と解釈する。候補集合を現在の選定件数から推定せず、元の取得結果を使う。

初回の最上位`結合条件`は後掲の型付き辺を平坦な列で指定する。各辺は`WI1`・`WI2`・`種別`・`根拠`を持ち、生成入力の根拠は次の意味判断だけとする。

- `依存`: `依存元`だけを指定し、正規化したリポジトリとdepends_onはWIのfrontmatterから生成する。
- `再開計画`: 空写像`{}`を指定し、両端の計画識別は確定した再開位置から生成する。
- `書込重複`: `定義1`・`定義2`の列と`段階比較`の理由を指定する。根拠はこの3欄だけを保存し、両端のパスと段階は`pick-wi-check`の実行のたびに選定の現在の`書込対象`と`レーンの所要時間`の`段階`から読む。

`結合条件`の省略時の値は空列であり、不在も空列と解釈する。生成側は確定した辺から不可分成分、候補集合と初回割当を組み立て、既存の本文対応・上限・競合・被覆・規範指定の確認に成功した場合だけ、次節の完成済み選定YAMLを原子的に保存する。失敗では保存先を変えない。
明示追加では`--merge <追加の意味判断YAML> --candidate-file <追加候補JSONL>`を使い、初回配分と初回の結合条件を加えない。元の初回履歴を保持して全体の関係を確認し、合流先だけを未統合へ戻して1回で保存する。生成入力と完成済みYAMLをレーンへ混在させず、担当には保存成功した完成済みYAMLの絶対パスだけを渡す。

## 選定結果の書式

生成付き保存の出力は次の形式とする。既存の完成済み選定YAMLも同じ形式で受領する。書き込み前に生成入力の意味判断として、`選定`の各項目の上流投入の3行の省略時の値と省略を解決し、次の組合せを確認する。

| `上流投入`の解決値 | `レーン` | 担当 |
| --- | --- | --- |
| `なし`（行の省略を含む） | 通常の`lane-NN` | ファイル変更の有無によらずレーン担当が採否・実施・終端を扱う |
| `上流要求だけ` | `なし` | メインが既存の上流投入工程を実施する |
| `混在` | 通常の`lane-NN` | メインの上流投入後、対象側の作業をレーン担当へ渡す |

この条件は作業を求める回答済みUWIにも適用する。ファイル変更が無い項目も待機とせず通常レーンへ割り当て、その割当は外部操作の承認を含まないものとして扱う。`上流投入`が`なし`以外なら`上流投入先`は1件以上の空でない文字列、`上流要求`は空でない文字列とし、`なし`なら3行とも省く。

```yaml
選定:
- WI: '<AWIまたは作業を求める回答が保存されたUWIのファイル名>'
  レーン: '<`lane-NN`形式のレーン識別子(`NN`は2桁のレーン番号)または「なし」>'
  鮮度: <`atk wi list --with-staleness`が返した`staleness`のYAMLフロー写像>
  書込対象: ['<書込対象のリポジトリ相対パス>']
  導出した新設先:  # 省略時の値: 「[]」
  - パス: '<限定調査で導いた完全な新設ファイルの相対パス>'
    反映範囲: '<対応する実在ディレクトリ範囲、末尾/付き>'
    要求: '<同じWIの新設を求める要求>'
    配置根拠: '<読んだ既存の定義・接続先と配置理由>'
  公開工程の書込対象: ['<全レーン統合後の公開工程だけが書くリポジトリ相対パス>']  # 省略時の値: 「[]」
  担当モデル: {実装担当: '<engine:model/effort>', 実行レビュー担当: '<engine:model/effort>'}
  書き込まない反映先: ['<反映先としてWI本文に現れるが書き込まないリポジトリ相対パス>']  # 省略時の値: 「[]」
  再開位置: '<`~/.claude/plans`内の計画ファイルの絶対パスと残る工程。観測のみの書式は「反映後の観測だけが残る（再開記録: AWI本文の最後の`## 反映後の観測の再開記録`、計画: <`private-notes/plans/`からの相対パス|計画なし>）」>'  # 省略時の値: 「なし」
  プロジェクト固有の公開後の操作の順序: '<プロジェクト固有の公開後の操作とその順序>'  # 省略時の値: 「既定」
  プロジェクト規範の指定: '<プロジェクト規範が指定した内容>'  # 省略時の値: 「なし」
  上流投入: '<上流要求だけまたは混在>'  # 省略時の値: 「なし」
  上流投入先: ['<投入先>']  # 省略時の値: 「なし」
  上流要求: '<上流要求と対象側の後続作業>'  # 省略時の値: 「なし」
単一段階案の完了見込み秒数: <bool以外の0以上の数値>  # 段階2以上がない場合は省略可、省略時の値: 「なし」
初回配分:
  候補WI: ['<開始時候補から通常の除外条件に当たるものを除いた全WI名。包含項目を含む>']
  レーン割当: {'<初回に選定したWI名>': '<初回レーンまたはなし>'}
  不可分成分:
  - WI: ['<成分の構成WI名>']
    結合条件: []  # 複数WIの成分では後掲の型付きの辺を列挙する
追加WI: ['<初回確定後に追加したWI名>']  # 省略時の値: 「[]」
レーンの所要時間:
- レーン: '<`lane-NN`形式のレーン識別子>'
  統合状態: '<未統合|統合済み>'  # 省略時の値: 「未統合」
  段階: <1以上の整数>  # 省略時の値: 「1」
  先行レーン: ['<このレーンのworktree作成前に統合を終える前段のレーン識別子>']  # 省略時の値: 「[]」
  実装秒数: <0以上の数値>
  統合秒数: <0以上の数値>
  根拠: '<同一レーン案と分割案の比較根拠を示す空でない文字列>'
レーン間の重なり:  # 省略時の値: 「[]」
- レーン1: '<レーン識別子>'
  レーン2: '<別のレーン識別子>'
  共通パス: '<共通ファイルまたは狭い方の範囲>'
  レーン1の定義: ['<変更する節または定義>']
  レーン2の定義: ['<変更する節または定義>']
  判定: '<交わる|交わらない>'
続行できない理由:
- '<確認事項>'  # 完了時の値: 「なし」
```

文字列の値は書式例のとおり単一引用符で囲み、値の中の`'`は`''`と重ねる。`[1m]`、`[`、`,`、コロンと空白の並びを含む値は引用しないとYAMLの構造として読まれるためである。`鮮度`と数値は引用符なしで書く。

候補が0件の場合は`選定`と`レーンの所要時間`を空の列（`[]`）とし、初回配分も`候補WI: []`、`レーン割当: {}`、`不可分成分: []`とする。
`追加WI`と`統合状態`は省略時の値と一致する場合に省略し、行の不在をそれぞれ空列と未統合として読む。

行末のコメントに省略時の値を記した行は、その値と一致する場合に省略でき、行の不在はその値として読む。`選定`の各項目が必ず持つ行は`WI`、`レーン`、`鮮度`、`書込対象`とする。`担当モデル`はWI本文が担当とモデルを明示した組だけを推論の深さを含む`engine:model/effort`で持ち、指定の無い担当のキーは省く。`鮮度`は一覧JSONの`staleness`の写像を値と型を変えずに転記する。

## 欄の意味

`書込対象`はレーン担当が書くファイルを、リポジトリ相対パスのYAMLフロー列で持つ。本文の列挙、作業を求めるUWIの回答から導いた変更対象、本文が指す手順書や限定調査から導いたファイルを含める。書込先を特定できない項目は、限定調査で見積もったディレクトリ範囲を末尾`/`付きで記す。配下の個別パスと並べて挙げたディレクトリ範囲（「対象リポジトリは`agent-toolkit/`配下とする」などの範囲説明）は写さず、配下の個別パスを書く（`pick-wi-check`も個別パスだけに被覆を求める）。`レーン`が`なし`の場合も行を残して空列`[]`とする。
保存後にレーン担当が書込対象の追加を返した場合、メインは該当項目の`書込対象`へ個別パスを加える。本文に無い新設先なら同じ項目の`導出した新設先`へ、他のレーンの`書込対象`と重なる場合は`レーン間の重なり`へも記録する。`初回配分`は変えない。直した後に`atk run-script pick-wi-check -- <選定YAML> --work-dir <対象リポジトリの絶対パス>`で確かめる。

`公開工程の書込対象`は対象リポジトリの規範が各レーンでは書かず全レーン統合後の公開工程だけで書くと明示した反映先を持つ。反映先の被覆には含め、レーン間の重複・包含・連結成分の判定からは除く。規範、節、各pathを`レーンの所要時間`の`根拠`へ記す。

両書込区分の要素は、実在ファイル、末尾`/`付き実在ディレクトリ、本文明示の新設先、正当な`導出した新設先`の個別パスとする。環境変数名・定義名・WI名、URL、絶対パス、遡行、グロブ、一般語句はパスの対象外とする。ファイル直後の「の」に続く定義名は配下パスとせず、ディレクトリ直後の「の」とファイルの列挙は配下の指定として扱う。
ファイル名・ディレクトリ名の内部の空白はパスの一部であり、インラインコード全体を1つの候補として解決する。YAMLの引用の有無・種類によらず同じ文字列は同じ判定になる。空白入りの新設先にも実在する親と完全なファイル名を求め、被覆、過大範囲と重複にも同じ個別パスを用いる。

`導出した新設先`の各記録は書式の4欄を持ち、全値は空でない文字列とする。4欄は選定時の判断履歴であり、ファイルの作成後も保持して各パスと反映範囲・書込区分との対応を確かめる。パスは実在する親ディレクトリと拡張子を持つ正規化した完全な新設名とし、未作成か作成後の通常ファイルだけを受理する（ディレクトリなど通常ファイルでない実在先は拒否）。反映範囲はそれをパス要素で含む末尾`/`付き実在ディレクトリとし、本文にディレクトリ範囲があれば同じWIの範囲へ対応させる。各パスは両書込区分のどちらかへ個別に置く。正当な記録は対応する反映範囲を具体化するが、別の個別反映先の被覆は別に要る。

`単一段階案の完了見込み秒数`は比較した単一段階配分の最長実装時間と全レーンの直列統合時間の和を持つ。段階案は`レーンの所要時間`から段階ごとに同じ和を求めて全段階で合計する。段階2以上では省略できない（型不正は終了コード2、欠落は終了コード1）。追加YAMLでは統合後の全体配分について確定した値を渡し、既存値は検収してから使う。

`書き込まない反映先`はAWIの`## 反映内容と反映先`や作業を求めるUWIの質問・判断材料・回答に現れるが、process-wiで書き込まない参照先または除外先を持つ。公開工程で書く対象は`公開工程の書込対象`へ置く。置く前に該当する表の行・箇条・段落（UWIでは回答）を読み、改訂要求と参照・除外の説明を区別する。分類は本文の意味で決める。AWI本文が変更しないと述べる上位ディレクトリ（「他の`docs/`配下は変更しない」の`docs/`）は範囲としてここへ置き、その配下で書くファイルは`書込対象`へ個別に置く。この範囲は、書込区分へ個別に置いたパスを除いた残りを表す。
反映先の各パスは3区分のいずれか1つへ分類する。UWIの本文に明示されたパスが未分類なら`pick-wi-check`が違反として報告する。パスを明示しないUWIの書込範囲は検査に現れないため、範囲と導いた根拠をそのレーンの`根拠`へ記す。

`レーンの所要時間`は`なし`でないレーンを重複なく1件ずつ含め、実装時間と直列統合時間を分けて一度だけ計上する。段階化した場合は単一段階案と段階案の完了見込みを`根拠`へ記し、後段の`先行レーン`には開始前に統合する全レーンを挙げる。同一レーン内で実装担当のモデル指定が異なる場合は、WI名と値を示して起動前に割当を直す。
`統合状態`は`atk lane integrate`が全計画の保存とWI終端の成立後に記録し、メインは結果と担当の終端を検収する（未知値は終了コード2）。
資源操作の入力と再開は[run-lanes.md](run-lanes.md)「統合とAWI終端」が定める。
統合済みレーンとの重なりも定義と判定を保持するが、重なりの相手が統合済みレーンだけのレーンは、同段階に置いて先行指定なしで開始できる。未統合同士は従来の排他と先行関係を保ち、未知参照と矛盾した重なりは状態によらず拒否する。追加が既存レーンへ合流した場合は合流先を未統合へ戻し、追加の仮名は既存の最終レーン名へ変換する。追加のない既存レーンと所属WIは履歴として保持する。

## 初回配分の算定根拠

単独検査、状態記録とmergeの既存側は`初回配分`を必須とする。mergeの追加側のYAMLだけがこれを省き、選定された全WIを`追加WI`へ加える。初回配分は追加統合やレーン名の対応付けの前後で同じ値を保つ。
`候補WI`は開始時候補から通常の除外条件に当たるものを除いた全件（包含された項目を含む）を各1回記す。初回確定前の明示追加はselection-procedure.md「処理対象の決定」の集合和へ含める。`レーン割当`は初回選定の各WIを初回レーンか`なし`へ対応付ける。初回割当と追加WIは互いに素で、その和が現在の選定と一致する。
不可分成分は初回の`なし`以外のWIを過不足なく1回ずつ覆い、各成分を1レーンへ割り当てる。単独成分の結合条件は空列でよく、複数WIでは有効な辺で連結させる。成分の欄は`WI`と`結合条件`だけとし、時間の見込みはレーン別の所要時間と根拠へ置く（成分別時間の旧欄を含む入力は終了コード2となるため、その欄を除いて同じ公開操作へ渡す）。
結合条件の各辺は`WI1`、`WI2`、`種別`、`根拠`だけを持つ。両WIは成分の異なる構成項目とし、根拠は次の欄だけを持つ写像とする。

- `依存`: `リポジトリ1`・`リポジトリ2`（正規化した識別子）、`依存元`（両端のどちらかのWI名）、`depends_on`（元の依存先の文字列列）。両リポジトリが同一で、依存先列に他端を含み、元WIのfrontmatterと一致する。依存の必要性はメインが元本文から検収する。
- `再開計画`: `計画1`・`計画2`（同じ計画を指す文字列）。通常再開の絶対パスと観測再開の相対パスは、既存の再開判定と同じ計画ファイル名へそろえて比べる。なし・計画なし以外の同じ計画を指し、選定の再開位置と一致する。
- `書込重複`: `定義1`・`定義2`（各変更定義の空でない文字列列）、`段階比較`（空でない比較理由）。定義が交わり、選定の現在の両端の`書込対象`に等しいパスか包含する範囲があり、両端のレーンの`段階`が等しい。変更前の版が保存した`パス1`・`パス2`・`段階1`・`段階2`を持つ根拠も受理し、その4欄は判定に使わない。ファイル単位の未特定範囲は双方の定義へ同じファイル名を記す。段階比較と定義の意味はメインが検収する。

Nは`候補WI`の件数であり、selection-procedure.md「調査とレーン分け」の`WI数`も同じ件数を指す。Bは`floor((N+9)/10)`とし、初回割当と現在の全レーン集合（`なし`を除き、統合済みと全段階のレーンを含む）をそれぞれB以下にする。時間の見込み・成分の大きさ・追加件数による例外は設けず、独立成分がBより多ければ複数成分を同じレーンで順に扱う。上限超過はN・B・実レーン数と理由を示して保存を拒否する。
追加の最終レーン名は既存の選定にある名前だけを受理し、Bに空きがあっても新しい最終名を拒否する。仮名は既存名へ対応付け、合流先だけを未統合へ戻す。
初回情報を欠く入力は、元候補・初回割当と結合根拠の記録から補い、元記録へ到達できなければ不足として扱う。

## 共通の読取りと重なり

選定結果を読む全ての主体は、本書が定める項目名、省略時の値および省略規則に従う。英字の旧欄名（`decisions`、`awi`、`lane`、`write_files`など）の既存の選定結果は、対応する新しい欄名と同じ意味で読む。

`根拠`には配分案の比較と不可分条件を記す。共有パスと定義の独立性は`レーン間の重なり`へ構造化して記し、受理には自由文でのパス再掲の有無によらずこの構造化した記録を要する。同一レーンの全書込集合や無関係なレーンのパスは再掲しない。

`レーン間の重なり`は共有パスが無ければ省略でき、不在は空列と読む。全レーンの組と共通パスに過不足なく対応させ、各組・パスの記録を1件に限る。定義は空でない文字列の列とし、`交わらない`では両側の定義の集合も互いに独立させる。意味上の独立性は本文と現物から判定する。追加選定では、追加内と新旧間の組だけを追加側が記録し、既存同士の記録を保持する。追加レーンの識別子は既存と重ならない仮名とし、最終割当は[selection-procedure.md](selection-procedure.md)「処理対象WIの追加」の統合操作で確定する。
