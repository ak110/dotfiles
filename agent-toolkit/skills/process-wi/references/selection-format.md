# 選定YAMLの項目と省略規則

選定YAMLは、対象リポジトリごとに生成して保存する。
登録全体の統括でも対象別の取得済み候補から作成し、複数リポジトリの候補数やレーンを1つのYAMLにまとめない。
候補の受け取り手順は[all-repos-orchestration.md](all-repos-orchestration.md)を、候補の分類と検収手順は[selection-procedure.md](selection-procedure.md)を参照する。

## 選定の生成入力

[selection-procedure.md](selection-procedure.md)の生成付き保存操作に渡す意味判断YAMLには、後述の`選定`、`レーンの所要時間`、および必要な比較値、重なり、続行できない理由を記載する。各選定項目の`WI`、`レーン`、`書込対象`、分類、担当モデル、配置根拠、見込み時間、プロジェクト規範指定は、メインエージェントが確定する。`鮮度`と最上位の`初回配分`は生成ツール側が組み立てるため、入力YAMLには含めない。指定のない担当モデルは未指定のまま維持し、生成ツール側で推測して補うことはしない。対象が0件の場合でも、`選定: []`および`レーンの所要時間: []`を明示する。

候補入力には、`atk wi list --jsonl --with-staleness`で取得した出力本文を用い、各行の`filename`と`staleness`をそのまま読み取る。JSON配列の形式も受理される。通常の除外条件に該当する候補のみを`除外候補: ['<WI名>']`に指定する。キーを省略した場合は空のリストとして扱い、キーが存在しない場合も空のリストとして解釈される。候補集合を現在の選定件数から推測してはならず、必ず元の取得結果を使用する。

初回生成時の最上位項目`結合条件`には、後述の型付き辺をフラットなリストとして指定する。各辺は`WI1`、`WI2`、`種別`、`根拠`を持ち、入力YAMLの`根拠`には以下の意味判断のみを指定する。

- `依存`: `依存元`のみを指定する。正規化されたリポジトリ識別子と`depends_on`は、WIのfrontmatterから自動生成される。
- `再開計画`: 空のマップ`{}`を指定する。両端の計画識別情報は、確定済みの再開位置から自動生成される。
- `書込重複`: `定義1`および`定義2`のリストと、`段階比較`の理由を指定する。根拠として保存されるのはこの3項目のみであり、両端のパスと段階は、`pick-wi-check`の実行ごとに選定の現在の`書込対象`と`レーンの所要時間`の`段階`から読み取られる。

`結合条件`を省略した場合は空のリストとして扱い、キーが存在しない場合も空のリストとして解釈される。生成ツールは確定した辺から不可分成分、候補集合、初回割当を組み立て、本文との対応、上限、競合、被覆、規範指定の検証に成功した場合に限り、次節で示す完成済み選定YAMLを不可分に（アトミックに）保存する。検証に失敗した場合は保存先ファイルを変更しない。
WIを明示的に追加する場合は`--merge <追加の意味判断YAML> --candidate-file <追加候補JSONL>`を使用し、初回配分や初回の結合条件は含めない。元の初回履歴を保持した上で全体の関係性を検証し、合流先レーンのみを未統合状態に戻して1回で保存する。生成入力用YAMLと完成済み選定YAMLをレーン担当に混同して渡してはならず、検証に成功して保存された完成済み選定YAMLの絶対パスのみをレーン担当へ渡す。

## 選定結果の書式

生成付き保存操作の出力は以下の形式となる。既存の完成済み選定YAMLを受け取る場合も同じ形式に従う。保存前には生成入力の意味判断として、`選定`の各項目における上流投入関連の3行について省略時の値を解決し、以下の組み合わせに合致していることを確認する。

| `上流投入`の解決値 | `レーン` | 担当 |
| --- | --- | --- |
| `なし`（行の省略を含む） | 通常の`lane-NN` | ファイル変更の有無を問わず、レーン担当が採否・実施・終了を担う |
| `上流要求だけ` | `なし` | メインエージェントが既存の上流投入工程を実施する |
| `混在` | 通常の`lane-NN` | メインエージェントが上流投入した後、対象リポジトリ側の作業をレーン担当へ引き渡す |

この条件は、作業を伴う回答済みUWIにも適用する。ファイルの変更を伴わない項目であっても待機状態にせず通常レーンへ割り当てる。その際、レーンへの割り当て自体は外部操作の承認を意味しないものとして扱う。`上流投入`が`なし`以外の場合、`上流投入先`には1件以上の空でない文字列のリストを、`上流要求`には空でない文字列を指定する。`なし`の場合は3行とも省略する。

```yaml
選定:
- WI: '<AWIまたは作業を求める回答が保存されたUWIのファイル名>'
  レーン: '<`lane-NN`形式のレーン識別子(`NN`は2桁のレーン番号)または「なし」>'
  鮮度: <`atk wi list --with-staleness`が返した`staleness`のYAMLフロー写像>
  書込対象: ['<書込対象のリポジトリ相対パス>']
  導出した新設先:  # 省略時の値: 「[]」
  - パス: '<限定調査で導いた完全な新設ファイルの相対パス>'
    反映範囲: '<対応する実在ディレクトリ範囲、末尾/付き>'
    要求: '<同じWIの新設を求める要求>'
    配置根拠: '<読んだ既存の定義・接続先と配置理由>'
  公開工程の書込対象: ['<全レーン統合後の公開工程だけが書くリポジトリ相対パス>']  # 省略時の値: 「[]」
  公開工程の規範根拠:  # 省略時の値: 「[]」
  - パス: '<公開工程の書込対象のパス>'
    規範ファイル: '<公開工程へ割り当てる規範のリポジトリ相対パス>'
    節: '<規範ファイルの見出し文字列>'
  担当モデル: {実装担当: '<engine:model/effort>', 実行レビュー担当: '<engine:model/effort>'}
  書き込まない反映先: ['<反映先としてWI本文に現れるが書き込まないリポジトリ相対パス>']  # 省略時の値: 「[]」
  再開位置: '<`~/.claude/plans`内の計画ファイルの絶対パスと残る工程。観測のみの書式は「反映後の観測だけが残る（再開記録: AWI本文の最後の`## 反映後の観測の再開記録`、計画: <`private-notes/plans/`からの相対パス|計画なし>）」>'  # 省略時の値: 「なし」
  プロジェクト固有の公開後の操作の順序: '<プロジェクト固有の公開後の操作とその順序>'  # 省略時の値: 「既定」
  プロジェクト規範の指定: '<プロジェクト規範が指定した内容>'  # 省略時の値: 「なし」
  上流投入: '<上流要求だけまたは混在>'  # 省略時の値: 「なし」
  上流投入先: ['<投入先>']  # 省略時の値: 「なし」
  上流要求: '<上流要求と対象側の後続作業>'  # 省略時の値: 「なし」
  統合状態: '<未統合|統合済み>'  # 省略時の値: 「未統合」
単一段階案の完了見込み秒数: <bool以外の0以上の数値>  # 段階2以上がない場合は省略可、省略時の値: 「なし」
段階案の完了見込み秒数: <bool以外の0以上の数値、または「成立する段階案なし」>  # 必須条件以外は省略可、省略時の値: 「なし」
見込みの補正:
  係数: <bool以外の0より大きい数値>
  参照した記録: ['<進捗ログか引き継ぎ記録の所在>']
  除外した記録:
  - 記録: '<除外した記録の所在>'
    理由: '<除外理由>'
初回配分:
  候補WI: ['<開始時候補から通常の除外条件に当たるものを除いた全WI名。包含項目を含む>']
  レーン割当: {'<初回に選定したWI名>': '<初回レーンまたはなし>'}
  不可分成分:
  - WI: ['<成分の構成WI名>']
    結合条件: []  # 複数WIの成分では後掲の型付きの辺を列挙する
追加WI: ['<初回確定後に追加したWI名>']  # 省略時の値: 「[]」
レーンの所要時間:
- レーン: '<`lane-NN`形式のレーン識別子>'
  統合状態: '<未統合|統合済み>'  # 省略時の値: 「未統合」
  段階: <1以上の整数>  # 省略時の値: 「1」
  先行レーン: ['<このレーンのworktree作成前に統合を終える前段のレーン識別子>']  # 省略時の値: 「[]」
  実装秒数: <0以上の数値>
  統合秒数: <0以上の数値>
  補正前の実装秒数: <bool以外の0以上の数値>
  補正前の統合秒数: <bool以外の0以上の数値>
  根拠: '<同一レーン案と分割案の比較根拠を示す空でない文字列>'
レーン間の重なり:  # 省略時の値: 「[]」
- レーン1: '<レーン識別子>'
  レーン2: '<別のレーン識別子>'
  共通パス: '<共通ファイルまたは狭い方の範囲>'
  レーン1の定義: ['<変更する節または定義>']
  レーン2の定義: ['<変更する節または定義>']
  判定: '<交わる|交わらない>'
続行できない理由:
- '<確認事項>'  # 完了時の値: 「なし」
```

文字列の値は書式例のように単一引用符（`'`）で囲み、文字列内の`'`は`''`とエスケープして重ねる。`[1m]`や`[`、`,`、コロンと空白の連続を含む文字列を引用符で囲まないと、YAMLの構文として誤認されるためである。`鮮度`のマップや数値は引用符で囲まずに記述する。

候補が0件の場合は、`選定`および`レーンの所要時間`を空のリスト（`[]`）とし、`初回配分`も`候補WI: []`、`レーン割当: {}`、`不可分成分: []`とする。
`追加WI`や、`選定`の各項目ならびに各レーン行の`統合状態`は、省略時の値と一致していれば省略可能であり、行が存在しない場合はそれぞれ空のリスト、未統合として解釈する。

行末のコメントに省略時の値を記載した行は、その値と一致する場合に省略できる。行が存在しない場合はその省略時の値として読み取る。`選定`の各項目で必須となる行は`WI`、`レーン`、`鮮度`、`書込対象`である。`担当モデル`には、WI本文で担当とモデルが明示されている組み合わせのみを、推論の深さを含めた`engine:model/effort`の形式で記録し、指定のない担当のキーは省略する。`鮮度`には、一覧JSONの`staleness`マップを値や型を変更せずにそのまま転記する。

## 欄の意味

`書込対象`はレーン担当が変更を加えるファイルを、リポジトリ相対パスのYAMLフローリスト形式で指定する。WI本文で列挙されたファイル、作業を伴うUWIの回答から導き出した変更対象、本文で参照されている手順書や限定調査から導いたファイルを含める。具体的な書き込み先ファイルを特定できない項目については、限定調査で見積もったディレクトリ範囲を末尾に`/`を付けて指定する。配下の個別パスとあわせて記載されたディレクトリ範囲（「対象リポジトリは`agent-toolkit/`配下とする」といった範囲の説明）は記載せず、配下の個別パスのみを記述する（`pick-wi-check`による被覆検証も個別パスに対してのみ行われる）。`レーン`が`なし`の項目であっても行自体は残し、空のリスト`[]`を指定する。
保存後に、レーン担当から未統合の他レーンの`書込対象`と重複する追加対象が返された場合に限り、メインエージェントはその追加パスと重複の記録を選定YAMLに保存する。他レーンと重複しない追加対象は、レーン担当が進捗ログまたは引き継ぎ記録に記録し、選定YAMLは変更しない（重複判定の詳細は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`「実装」参照）。
追加、全体チェック、保存までを完了するには、以下のコマンドを実行する。

```text
atk run-script pick-wi-check -- <選定YAML> --extend-write-targets <追加YAML> --output <保存先> --work-dir <対象リポジトリの絶対パス>
```

追加用YAMLの最上位項目は`選定`と`レーン間の重なり`とし、選定の各行に`WI`、追加する`書込対象`、および必要な`導出した新設先`の4項目を記述する。各リストは省略時に空のリストとなり、行が存在しない場合も空のリストとして解釈する。既存のリストの順序を保ったまま重複なく追記するため、記録の追記のみを行う用途にも対応している。他レーンと重複する追加については、`レーン間の重なり`に定義と判定結果を渡す。この操作では`初回配分`を含む既存の項目を保持し、全体チェックに成功した場合に限り不可分に保存する。失敗した場合は選定YAMLを変更せず、不足している記録と次に取るべき操作を出力する。本文の一部のチェックを指定する`--body-wi`や、新しいWIの合流、その他の更新操作を同時に指定しない。

`公開工程の書込対象`は対象リポジトリの規範において、各レーンでは編集せず全レーン統合後の公開工程でのみ変更すると明記されたファイルパスを指定する。このパスは反映先としての被覆検証には含まれるが、レーン間の重複・包含・連結成分の判定からは除外される。`公開工程の規範根拠`には、各パスに対応する記録を過不足なく1件ずつ記載する。規範ファイルには対象リポジトリに実在する通常ファイルを指定し、節にはそのMarkdown見出しと完全に一致する文字列を指定する。余分なパスや重複した指定は検証で拒否される。省略時は空のリストとなり、公開工程の対象が存在しない場合のみ省略できる。

両書込区分の要素は、実在するファイル、末尾に`/`を付けた実在ディレクトリ、本文で明示された新設先、または正当な`導出した新設先`の個別パスを指定する。環境変数名、定義名、WI名、URL、絶対パス、親ディレクトリへの遡行（`../`）、グロブ、一般的な語句はパスとして指定できない。ファイル名の直後に「の」を介して続く定義名は配下パスとはみなさない。一方、ディレクトリ名の直後に「の」を介してファイルを列挙している記述は、そのディレクトリ配下の指定として扱う。
ファイル名やディレクトリ名に含まれる空白はパスの一部として扱い、インラインコード全体を1つのパス候補として解決する。YAML内での引用符の有無や種類にかかわらず、同じ文字列であれば同一の判定結果となる。空白を含む新設先であっても実在する親ディレクトリと完全なファイル名を要求し、被覆、過大範囲、重複の判定においても同じ個別パスを用いる。
両書込区分の要素、`導出した新設先`、反映先の被覆と区分、`公開工程の規範根拠`、`プロジェクト規範の指定`の検証は作業ツリーのファイルを参照するため、未統合の項目にのみ適用される。これらは作業着手前の作業ツリーで成立していた選定時の前提条件である。そのため、統合済みの項目（項目自体または所属レーンの`統合状態`が`統合済み`である項目、および同じ呼び出しで`--mark-integrated`に指定されたレーンの項目）については、レーンでの作業によってファイルの改名、削除、追加が行われた後であっても、過去の履歴として扱われ検証で拒否されることはない。

`導出した新設先`の各記録には所定の4項目を記述し、すべての値に空でない文字列を指定する。この4項目は選定時の判断履歴であり、ファイルが実際に作成された後も保持して、各パスと反映範囲・書込区分との対応関係を確認するために用いる。パスには実在する親ディレクトリと拡張子を含む正規化された完全な新設ファイル名を指定し、未作成または作成済みの通常ファイルのみを受理する（ディレクトリなど通常ファイル以外が実在する場合は拒否される）。反映範囲には、その新設先をパス要素として含む末尾`/`付きの実在ディレクトリを指定する。本文に記載された範囲の外にある関連テストコードや補助ファイルであっても、要求との対応関係と配置根拠を備えていれば、個別の新設先として記録できる。メインエージェントは、元のWI本文と限定調査の現物資料から意味上の対応関係を検収する。各パスは両書込区分のいずれか一方へ個別に配置する。正当な新設先の記録は対応する反映範囲を具体化するが、別途指定されている個別反映先の被覆は個別に満たす必要がある。

`単一段階案の完了見込み秒数`は比較対象とした単一段階配分における「最長の実装時間」と「全レーンの直列統合時間の合計」との和を記録する。段階案の完了見込みは、`レーンの所要時間`から段階ごとに同様の和を求め、全段階の合計値として算出する。段階2以上を採用する選定では本項目を省略できない（型の不正は終了コード2、項目の欠落は終了コード1となる）。追加用YAMLでは、統合後の全体配分について確定し直した値を渡し、既存の値は検収した上で使用する。

`段階案の完了見込み秒数`はすべての行が段階1であり、いずれかのレーンの`実装秒数`が6000秒を超える場合に必須となる。値には、比較対象とした段階案の補正後の完了見込み秒数（真偽値以外の0以上の数値）、またはレーン数上限の範囲内で成立する段階案が存在しないことを示す固定値`成立する段階案なし`を記録する。必須条件に該当しない場合の省略は、比較値なしとして解釈される。項目の欠落は終了コード1、型の不正は終了コード2となる。合流処理では、両比較欄とも追加用YAMLで再確定された値のみを採用する。

`見込みの補正`は必須項目であり、`係数`、`参照した記録`、`除外した記録`の3項目を持つ。参照または除外した記録が存在しない場合は、それぞれのリストを空とする。係数が1以外の場合は、`参照した記録`に1件以上の記録を指定する。各レーンの補正前の2つの数値（`補正前の実装秒数`、`補正前の統合秒数`）も必須であり、`実装秒数`と`統合秒数`は、それぞれの補正前の値に係数を掛けた値と1秒以内の誤差で一致させる。項目の欠落や値の不一致は終了コード1、型の不正は終了コード2となる。追加用YAMLにも同じ係数を指定し、合流処理では補正前の各値を加算した後に係数を適用する。

`書き込まない反映先`はAWIの`## 反映内容と反映先`や、作業を伴うUWIの質問・判断材料・回答に記載されているものの、`process-wi`では変更を加えない参照先または除外先を指定する。公開工程で書き込む対象は`公開工程の書込対象`に配置する。本項目に含める前に、該当する表の行、箇条書き、段落（UWIの場合は回答）を確認し、変更要求なのか、参照や除外の説明なのかを区別する。この分類は本文の意味内容に基づいて判断する。AWI本文で変更しないと明記されている上位ディレクトリ（例：「他の`docs/`配下は変更しない」における`docs/`）は範囲としてここへ配置し、その配下で実際に変更するファイルは`書込対象`に個別に指定する。この範囲指定は、書込区分へ個別に指定したパスを除いた残りの領域を表す。
反映先として現れる各パスは、3つの区分のいずれか1つに必ず分類する。UWI本文に明示されているパスが未分類のままである場合、`pick-wi-check`は違反として報告する。本文の反映先に記載されていないディレクトリ範囲や、反映先パスを機械的に抽出できないUWIの`書込対象`については、メインエージェントが限定調査と回答内容からその意味的な妥当性を検収する。旧版の選定YAMLに存在した`書込範囲の理由`は、重複判定や配分計算に寄与しないため廃止された項目であり、読み取り時には破棄する。

`レーンの所要時間`は`なし`以外のレーンを重複なく1件ずつ含め、実装時間と直列統合時間とを分けて1回のみ計上する。比較値は前述の比較欄および各行の秒数から読み取り、後段レーンの`先行レーン`には、開始前に統合を完了しておくべきすべてのレーンを指定する。同一レーン内で実装担当のモデル指定が異なる場合は、WI名と指定値を確認し、レーン起動前に割り当てを修正する。
`統合状態`は、すべての計画の保存とWIの終了処理が完了した後に`atk lane integrate`が記録し、メインエージェントはその実行結果とレーン担当の終了状態を検収する（未知の値は終了コード2となる）。この記録処理によって、該当レーンの行と、その時点でそのレーンに属している全項目の`統合状態`が`統合済み`に更新される。
資源操作の入力と再開手順は[run-lanes.md](run-lanes.md)「統合とAWI終了」を参照する。
統合済みレーンとの重複についても定義と判定結果を保持するが、重複の相手が統合済みレーンのみであるレーンは、同じ段階に配置して先行指定なしで開始できる。未統合レーン同士については従来の排他関係と先行関係を維持し、未知の参照や矛盾した重複定義は状態にかかわらず拒否される。追加WIが既存レーンへ合流した場合は、合流先のレーン行を未統合に戻し、合流先の既存項目は統合済みのまま維持して追加項目を未統合とする。また、追加時の仮レーン名は既存の最終レーン名へ変換する。追加のなかった既存レーンおよび所属WIは、履歴としてそのまま保持する。

## 初回配分の算定根拠

単独チェック、状態記録、およびmerge操作における既存側YAMLでは、`初回配分`が必須となる。merge操作の追加側YAMLのみ本項目を省略でき、選定されたすべてのWIは`追加WI`に分類される。初回配分の内容は、追加統合やレーン名の対応付けの前後で同一の値を維持する。
`候補WI`には、開始時の候補から通常の除外条件に該当するものを除いたすべての件数（包含された項目を含む）を1回ずつ記述する。初回確定前に行われた明示的な追加WIは、[selection-procedure.md](selection-procedure.md)「処理対象の決定」の集合和に含める。`レーン割当`では、初回に選定した各WIを初回のレーンまたは`なし`に対応付ける。初回の割当集合と`追加WI`は互いに排他であり、両者の和が現在の選定集合と一致する。
不可分成分は、初回の`なし`以外のWIを過不足なく1回ずつ網羅し、各成分を1つのレーンへ割り当てる。単独のWIからなる成分では結合条件は空のリストでよく、複数のWIを含む成分では有効な辺によって相互に連結させる。成分の項目は`WI`と`結合条件`のみとし、所要時間の見込みはレーン別の所要時間と根拠に記録する（成分別の所要時間という旧項目を含む入力は終了コード2となるため、その項目を除外して同一の公開操作に渡す）。
結合条件の各辺は`WI1`、`WI2`、`種別`、`根拠`のみを持つ。両WIは成分内の異なる構成項目とし、`根拠`には以下の項目のみを持つマップを指定する。

- `依存`: `リポジトリ1`、`リポジトリ2`（正規化された識別子）、`依存元`（両端のいずれかのWI名）、`depends_on`（元の依存先文字列のリスト）。両リポジトリが同一であり、依存先リストに他方のWIを含み、元WIのfrontmatterと一致している必要がある。依存の必要性は、メインエージェントが元のWI本文から検収する。
- `再開計画`: `計画1`、`計画2`（同一の計画を指す文字列）。通常再開の絶対パスと観測再開の相対パスは、既存の再開判定と同様に計画ファイル名を揃えて比較する。`なし`や`計画なし`以外の同一の計画を指し、選定結果の再開位置と一致している必要がある。
- `書込重複`: `定義1`、`定義2`（各変更定義の空でない文字列リスト）、`段階比較`（空でない比較理由）。定義同士が重なり合い、選定結果における現在の両端の`書込対象`に同一のパスまたは包含関係にある範囲が存在し、両端のレーンの`段階`が等しい必要がある。旧版で保存された`パス1`、`パス2`、`段階1`、`段階2`を含む根拠も受理されるが、これら4項目は判定には使用されない。ファイル単位で範囲が特定されていない場合は、双方の定義に同一のファイル名を記述する。段階比較と定義の妥当性は、メインエージェントが検収する。

Nは`候補WI`の件数であり、[selection-procedure.md](selection-procedure.md)「調査とレーン分け」における`WI数`も同じ件数を指す。上限Bは`floor((N+9)/10)`と計算し、初回の割当数および現在の全レーン集合（`なし`を除き、統合済みレーンや全段階のレーンを含む）をそれぞれB以下に抑える。所要時間の見込み、成分の規模、追加件数などを理由とした例外は認めず、独立した成分の数がBを超える場合は、複数の成分を同一レーンにまとめて順番に処理する。上限を超過した場合は、N、B、実際のレーン数、および理由を示して保存を拒否する。
追加時の最終レーン名には、既存の選定結果に存在するレーン名のみを受理する。Bの枠に空きがある場合であっても、新しい最終レーン名の新設は拒否される。追加時の仮名は既存のレーン名に対応付け、合流先のレーンのみを未統合状態に戻す。
初回情報が欠落している入力については、元の候補、初回割当、結合根拠の記録から復元して補う。元の記録を確認できない場合は情報不足として扱う。

## 共通の読取りと重なり

選定結果を読み取るすべての主体は、本書で定める項目名、省略時の値、および省略規則に従う。英字の旧項目名（`decisions`、`awi`、`lane`、`write_files`など）で記述された既存の選定結果は、対応する新しい日本語項目名と同一の意味として読み取る。

`根拠`には、配分案の比較結果と不可分条件のみを記述する。公開工程の規範根拠、段階案の比較値、見込みの補正値は、それぞれの専用項目に配置する。共有パスおよび定義の独立性は、`レーン間の重なり`に構造化して記録する。受理されるためには、自由文におけるパスの再掲の有無にかかわらず、この構造化された記録が必須となる。同一レーン内のすべての書込対象集合や、無関係なレーンのパスを再掲しない。

`レーン間の重なり`は、共有パスが存在しない場合は省略でき、存在しない場合は空のリストとして解釈する。すべてのレーンの組み合わせと共通パスに対して過不足なく対応させ、各組み合わせ・パスごとの記録は1件に限定する。定義は空でない文字列のリストとし、`判定`が`交わらない`の場合は双方の定義集合も互いに独立していなければならない。意味上の独立性は、本文と現物のコードやドキュメントに基づいて判定する。追加選定する際は、追加分同士および新旧間の組み合わせのみを追加側で記録し、既存同士の記録はそのまま保持する。追加レーンの識別子には既存と重複しない仮名を使用し、最終的な割り当ては[selection-procedure.md](selection-procedure.md)「処理対象WIの追加」の統合操作によって確定する。
