# 選定YAMLの項目と省略規則

## 選定結果の書式

次の本文を出力先ファイルへ書く。書き込み前に、`選定`の各項目の上流投入の3行の省略時の値と省略を解決し、次の組合せを確認する。

| `上流投入`の解決値 | `レーン` | 担当 |
| --- | --- | --- |
| `なし`（行の省略を含む） | 通常の`lane-NN` | ファイル変更の有無によらずレーン担当が採否・実施・終端を扱う |
| `上流要求だけ` | `なし` | メインが既存の上流投入工程を実施する |
| `混在` | 通常の`lane-NN` | メインの上流投入後、対象側の作業をレーン担当へ渡す |

この条件は作業を求める回答済みUWIにも適用する。外部待ちで処理不能な項目は「処理対象の決定」と既存の続行できない理由を返す判断を用いる。ファイル変更が無いことだけでは待機としない。通常レーンへの割当は外部操作の承認を追加せず、操作の確認とAWI終端は既存の担当手順で判断する。

```yaml
選定:
- WI: '<AWIまたは作業を求める回答が保存されたUWIのファイル名>'
  レーン: '<`lane-NN`形式のレーン識別子(`NN`は2桁のレーン番号)または「なし」>'
  鮮度: <`atk wi list --with-staleness`が返した`staleness`のYAMLフロー写像>
  書込対象: ['<書込対象のリポジトリ相対パス>']
  導出した新設先:  # 省略時の値: 「[]」
  - パス: '<限定調査で導いた完全な新設ファイルの相対パス>'
    反映範囲: '<対応する実在ディレクトリ範囲、末尾/付き>'
    要求: '<同じWIの新設を求める要求>'
    配置根拠: '<読んだ既存の定義・接続先と配置理由>'
  公開工程の書込対象: ['<全レーン統合後の公開工程だけが書くリポジトリ相対パス>']  # 省略時の値: 「[]」
  担当モデル: {実装担当: '<engine:model/effort>', 実行レビュー担当: '<engine:model/effort>'}
  書き込まない反映先: ['<反映先としてWI本文に現れるが書き込まないリポジトリ相対パス>']  # 省略時の値: 「[]」
  再開位置: '<`~/.claude/plans`内の計画ファイルの絶対パスと残る工程。観測のみの書式は「反映後の観測だけが残る（再開記録: AWI本文の最後の`## 反映後の観測の再開記録`、計画: <`private-notes/plans/`からの相対パス|計画なし>）」>'  # 省略時の値: 「なし」
  プロジェクト固有の公開後の操作の順序: '<プロジェクト固有の公開後の操作とその順序>'  # 省略時の値: 「既定」
  プロジェクト規範の指定: '<プロジェクト規範が指定した内容>'  # 省略時の値: 「なし」
  上流投入: '<上流要求だけまたは混在>'  # 省略時の値: 「なし」
  上流投入先: ['<投入先>']  # 省略時の値: 「なし」
  上流要求: '<上流要求と対象側の後続作業>'  # 省略時の値: 「なし」
単一段階案の完了見込み秒数: <bool以外の0以上の数値>  # 段階2以上がない場合は省略可、省略時の値: 「なし」
初回配分:
  候補WI: ['<開始時候補から通常の除外条件に当たるものを除いた全WI名。包含項目を含む>']
  レーン割当: {'<初回に選定したWI名>': '<初回レーンまたはなし>'}
  不可分成分:
  - WI: ['<成分の構成WI名>']
    結合条件: []  # 複数WIの成分では後掲の型付きの辺を列挙する
追加WI: ['<初回確定後に追加したWI名>']  # 省略時の値: 「[]」
レーンの所要時間:
- レーン: '<`lane-NN`形式のレーン識別子>'
  統合状態: '<未統合|統合済み>'  # 省略時の値: 「未統合」
  段階: <1以上の整数>  # 省略時の値: 「1」
  先行レーン: ['<このレーンのworktree作成前に統合を終える前段のレーン識別子>']  # 省略時の値: 「[]」
  実装秒数: <0以上の数値>
  統合秒数: <0以上の数値>
  根拠: '<同一レーン案と分割案の比較根拠を示す空でない文字列>'
レーン間の重なり:  # 省略時の値: 「[]」
- レーン1: '<レーン識別子>'
  レーン2: '<別のレーン識別子>'
  共通パス: '<共通ファイルまたは狭い方の範囲>'
  レーン1の定義: ['<変更する節または定義>']
  レーン2の定義: ['<変更する節または定義>']
  判定: '<交わる|交わらない>'
続行できない理由:
- '<確認事項>'  # 完了時の値: 「なし」
```

文字列の値は書式例のとおり単一引用符で囲み、値の中の`'`は`''`と重ねて書く。モデル指定の`[1m]`、パスの`[`や`,`、根拠の`同一レーン案: 3000秒`のようなコロンと空白の並びは引用の無い値ではYAMLの構造として読まれ、読み込みが失敗するか別の値になるためである。`鮮度`と数値の行は引用しない。

処理可能な候補が0件の場合は、`選定`と`レーンの所要時間`を空の列（`[]`）とし、通常レーンを起動せず監査と公開工程へ進む。
初回配分も`候補WI: []`、`レーン割当: {}`、`不可分成分: []`とする。
`追加WI`と`統合状態`は省略時の値と一致する場合に省略し、行の不在をそれぞれ空列と未統合として解釈する。

書式例の行末のコメントに記載した省略時の値と一致する場合に省略する行は`再開位置`、`プロジェクト固有の公開後の操作の順序`、`プロジェクト規範の指定`、`公開工程の書込対象`、`導出した新設先`、`書き込まない反映先`、`担当モデル`、`段階`、`先行レーン`および上流投入の3行とする。`担当モデル`はWI本文が担当とモデルを明示した組だけを持ち、指定のない担当のキーは省く。モデル指定には推論の深さを含む`engine:model/effort`を使う。行の不在は記載した省略時の値として解釈する。`選定`の各項目が必ず持つ行は`WI`、`レーン`、`鮮度`、`書込対象`とする。`鮮度`は一覧JSONの`staleness`の写像を値と型を変えずに転記する。

## 欄の意味

`書込対象`は[selection-procedure.md](selection-procedure.md)「調査とレーン分け」で対応付けた、レーン担当が書くファイルの集合をリポジトリ相対パスのYAMLフロー列で持つ。AWI本文の列挙と、作業を求めるUWIの回答から導いた変更対象に加え、本文が指す手順書や限定調査から導いたファイルも含める。書込先を特定できない項目は、限定調査で見積もったディレクトリ単位などの範囲を記す。ディレクトリ範囲は末尾の`/`付きとする。
反映先が配下の個別パスと並べて挙げたディレクトリ範囲（「対象リポジトリは`agent-toolkit/`配下とする」などの範囲説明）は`書込対象`へ写さず、配下の個別パスを書く。`pick-wi-check`も配下の個別パスだけに被覆を求める。`レーン`が`なし`の場合は空列`[]`とし、この行も省略しない。

`公開工程の書込対象`は対象リポジトリの規範が各レーンでは書かず、全レーン統合後の公開工程だけで書くと明示した反映先を持つ。反映先の被覆には含め、レーン間の重複、包含および連結成分の判定からは除く。対象リポジトリの規範、該当する節と各pathを`レーンの所要時間`の`根拠`へ記録する。公開工程所有を一意に確認した対象だけをこの欄へ入れる。

両書込区分の要素は実在ファイル、末尾`/`付き実在ディレクトリ、本文明示の新設先、または正当な`導出した新設先`の個別パスとする。環境変数名・定義名・WI名は、パスとして扱う対象から外す。抽出ではファイル直後の「の」に続く定義名を配下パスとせず、ディレクトリ直後の「の」とファイルの列挙は配下の指定として扱う。
ファイル名・ディレクトリ名の内部の空白はパスの一部として保持する。インラインコード全体を1つの候補として解決し、YAMLの単一引用符・二重引用符・引用符なしで同じ文字列を渡した場合は同じ判定をする。空白入りの新設先にも実在する親と完全なファイル名を求め、被覆、過大範囲と重複にも同じ個別パスを用いる。URL、絶対パス、遡行、グロブや一般語句はパスの対象から外す。

`導出した新設先`は省略時の値が空列であり、行の不在も空列と解釈する。各記録は書式の4欄だけを持ち、全値は空でない文字列とする。この4欄は選定時の判断履歴であり、ファイルの作成後も保持して各パスと反映範囲・書込区分との対応を確かめる。パスは正規化した相対パスで、実在する親ディレクトリと拡張子を持つ完全な新設名とする。未作成のパスと作成後の通常ファイルを受理し、ディレクトリ等の通常ファイルでない実在先は拒否する。反映範囲は新設先をパス要素で含む末尾`/`付き実在ディレクトリで、本文にディレクトリ範囲がある場合は同じWIの範囲へ完全に対応させる。パスを示さない要求では限定調査から範囲を記す。各パスを両書込区分のどちらかへ個別に置き、宣言だけ、非書込だけ、重複宣言、範囲外の指定を避ける。正当な記録は対応する反映範囲を具体化するが、別の個別反映先の被覆は必要である。要求と配置根拠の意味、残る要求の範囲はメインが元本文から検収する。

`単一段階案の完了見込み秒数`は比較した単一段階配分の最長実装時間と全レーンの直列統合時間の和を持つ。段階案は`レーンの所要時間`から段階ごとに同じ和を求め、全段階で合計する。全行が段階1または空選定の場合は比較欄を省略でき、不在を「なし」と解釈する。段階2以上では省略できない。型不正は終了コード2、段階案の欠落は終了コード1、値がある成功時の要約は同名の値行を持つ。追加YAMLでは、統合後の全体配分について確定した比較値を渡す。既存値の無検収の流用はせず、追加で欄を省いた結果が段階案なら全体チェックで保存を拒否する。

`書き込まない反映先`はAWI本文の`## 反映内容と反映先`と、作業を求めるUWIの質問・判断材料・回答に現れるがprocess-wiで書き込まない参照先または除外先を持つ。公開工程で書く対象の退避先には使わない。非書込へ置く直前に、AWIでは該当する表の行・箇条・段落を、UWIでは該当する段落と回答を読み、改訂要求と参照・除外の説明を区別する。パスが規範・手順・設定であることだけで分類せず、意味が未確定なら限定調査を続ける。反映先の各パスは3区分のいずれか1つへ分類する。範囲説明は分類せず、配下の個別パスを分類する。AWI本文が変更しない範囲として挙げる上位ディレクトリ（「他の`docs/`配下は変更しない」の`docs/`）は`書き込まない反映先`へ範囲として置き、その配下で書くファイルは`書込対象`へ個別に置く。`書き込まない反映先`の範囲は配下で書込区分へ個別に置いたパスを除いた残りを表す。
UWIの本文に明示されたパスがどちらにも分類されていない場合は、`pick-wi-check`が違反として報告する。回答がパスを明示せず限定調査で書込範囲を導いた項目は、その範囲と導いた根拠を、その項目を含むレーンの`レーンの所要時間`の`根拠`へ記す。パスを明示しないUWIの書込範囲は`pick-wi-check`が比べる対象に現れないため、受領側はこの記述を読んで検収する。

`レーンの所要時間`は`なし`でないレーンを重複なく全て1件ずつ含める。秒数は実装時間と直列統合時間を分けて保持し、それぞれ一度だけ計上する。段階化した場合は比較した単一段階案と段階案の完了見込みを`根拠`へ記し、後段の`先行レーン`には開始前に統合する全レーンを挙げる。同一レーン内で実装担当の異なるモデル指定がある場合はWI名と指定値を示し、起動前に割当を直す。
`統合状態`はメインが統合結果と担当の終端を検収した後に公開操作で記録する。未知値は終了コード2とする。統合済みとの重なりも定義と判定を保持し、その履歴だけなら同段階・先行指定なしで開始できる。未統合同士は従来の排他と先行関係を保ち、未知参照と矛盾した重なりは状態によらず拒否する。追加が既存レーンへ合流した場合は合流先を未統合へ戻し、追加の仮名は既存の最終レーン名へ変換する。追加のない既存レーンと所属WIは履歴として保持する。

## 初回配分の算定根拠

単独検査、状態記録とmergeの既存側は`初回配分`を必須とする。追加用YAMLはmergeの追加側だけでこれを省き、選定された全WIを`追加WI`へ加える。初回配分は追加統合やレーン名の対応付けの前後で同じ値を保持する。
`候補WI`へ記録する集合は、開始時候補から通常の除外条件に当たるものを除いた全件とし、包含された項目も含め、各WI名を1回だけ記す。初回確定前の明示追加はselection-procedure.md「処理対象の決定」の集合和へ含める。`レーン割当`は初回選定の各WIを初回レーンか`なし`へ対応付ける。初回割当と追加WIは互いに独立した集合とし、その和を現在の選定へ一致させる。初回件数式の母集団はこの保存集合とする。
不可分成分は初回の`なし`以外のWIを過不足なく1回ずつ覆い、各成分を1レーンへ割り当てる。単独成分の結合条件は空列でよく、複数WIでは有効な辺で連結させる。
結合条件の各辺は`WI1`、`WI2`、`種別`、`根拠`だけを持つ。両WIは成分の異なる構成項目とし、根拠は次の欄だけを持つ写像とする。

- `依存`: 根拠は`リポジトリ1`・`リポジトリ2`（正規化した識別子）、`依存元`（両端のどちらかのWI名）、`depends_on`（元の依存先の文字列列）を持つ。両リポジトリが同一で、依存先列に他端を含み、元WIのfrontmatterと一致する。依存の必要性はメインが元本文から検収する。
- `再開計画`: 根拠は`計画1`・`計画2`（同じ計画を指す文字列）を持つ。通常再開の絶対パスと観測再開の相対パスを、既存の再開判定と同じ計画ファイル名へそろえて比較する。なし・計画なし以外の同じ計画を指し、選定の再開位置と一致する。
- `書込重複`: 根拠は`パス1`・`パス2`（各WIの書込対象の文字列列）、`定義1`・`定義2`（各変更定義の空でない文字列列）、`段階1`・`段階2`（1以上の整数）、`段階比較`（空でない比較理由）を持つ。パスと段階が選定に一致し、パスが等しいか範囲が包含し、同段階かつ定義が交わる。ファイル単位の未特定範囲は双方の定義へ同じファイル名を記す。段階比較と定義の意味はメインが検収する。

Nは前掲の`候補WI`へ記録した集合の件数であり、selection-procedure.md「調査とレーン分け」の`WI数`も同じ件数を指す。Bは`floor((N+9)/10)`とし、初回割当と現在の全レーン集合をそれぞれB以下にする。`なし`を除き、統合済みと全段階のレーンを数える。時間の見込み・成分の大きさ・追加件数による例外は設けない。独立成分がBより多い場合も複数成分を同じレーンで順に扱う。
不可分成分の欄は`WI`と`結合条件`だけとし、時間の見込みはレーン別の所要時間と根拠へ置く。結合の成立と元入力との一致は引き続き確認する。成分別時間の旧欄を含む入力は終了コード2となり、その欄を除いて同じ公開操作へ渡す。初回情報を欠く入力は、元候補・初回割当と結合根拠の記録から補い、元記録へ到達できなければ不足として扱う。
追加の最終レーン名は既存の選定にある名前だけを受理する。Bに空きがある場合も新しい最終名を拒否する。仮名は既存名へ対応付け、合流先だけを未統合へ戻す。上限超過はN・B・実レーン数と理由を示して保存を拒否する。

## 共通の読取りと重なり

選定結果を読む全ての主体は、本節が定める項目名、省略時の値および省略規則に従う。英字の旧欄名（`decisions`、`awi`、`lane`、`write_files`など）で書かれた既存の選定結果は、対応する新しい欄名と同じ意味で読む。消費側の文書は本節を参照し、項目の再掲を省く（努力目標。定義を持つ文書を1つに保つ）。

`根拠`には配分案の比較と不可分条件を記す。共有パスと具体的な定義の独立性は`レーン間の重なり`へ記し、受理には自由文のパス再掲の有無によらず、構造化した記録を要する。同一レーンの全書込集合や無関係なレーンのパスは再掲の対象から除く。

`レーン間の重なり`は共有パスが無い場合に省略でき、行の不在を空列として解釈する。全レーンの組と共通パスに過不足なく対応させ、各組・パスの記録を1件に限る。定義は空でない文字列の列とし、`交わらない`では両側の定義の集合も互いに独立させる。意味上の独立性は本文と現物から判定する。追加選定では、追加内と新旧間の組だけを追加側が記録し、既存同士の記録を保持する。追加レーンの識別子は既存識別子と重ならない仮名にし、最終割当はselection-procedure.mdの追加統合で確定する。
