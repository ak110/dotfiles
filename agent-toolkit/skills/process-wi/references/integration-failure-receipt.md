# レーン統合の失敗の受領

本書は`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`に従ってレーン担当を起動したメインが、統合の返却として、統合先との組合せだけで生じた変更範囲の検証失敗の是正commitか、rebase進行中の競合を受け取ったときの扱いを定める。

統合先との組合せだけで生じた変更範囲の検証失敗の是正commitを受領した場合は、失敗した検証が確かめる契約の送信側・受信側・実装・テストの差分と、再検証の終了コードを確認する。警告は統合するレーン担当が`${CLAUDE_PLUGIN_ROOT}/share/lane-integration.subagent.md`「検証結果の警告の判定」で付けた判定と根拠を受け取り、処理の成立に影響しない既存の警告だけを理由に同じ結果の受理を求め直さない。確認したcommitのHEADを明記し、同じthreadへ統合再開を指示する。契約外の差分または検証不足があれば、不足箇所を返して是正を求める。

`lane-integration.subagent.md`「マージありの統合」が返したrebase進行中の競合を受領した場合は、次の順で扱う。統合するレーン担当に競合を解消させず返させるのは、解消した差分がレビューを経ないまま統合先へ入ることを防ぐためである。

1. 同じレーン担当threadへ競合の解消を指示する。専用worktreeの書込主体はレーン担当のまま保ち、別の修正担当を起動しない。
2. レーン担当は`references/lane-integration-failure.md`「rebaseの競合（手順7）」に従って競合を解消し、レビュー指摘管理表へ記録して`対応完了`または`対応完了（再レビュー不要）`を返す。
3. `対応完了`を受領したら、同じターンで`${CLAUDE_PLUGIN_ROOT}/share/exec-review.parent.md`「レビュー修正」と同じ判定で実行レビュー担当へ`再レビューせよ`と`round`を送る。先行計画と追加計画を持つレーンでは、送る計画を同書「起動方法別のレビュー基準」の影響する計画の判定で選び、影響しない計画は同段落のとおり記録する。収束後に`${CLAUDE_PLUGIN_ROOT}/share/exec.parent.md`「統合の指示と受領」に従って新しい`実行レビュー済みHEAD`で統合指示を再送する。`対応完了（再レビュー不要）`の受領にも同書「レビュー修正」の証拠判定を適用し、再判定が必要なら同じ再レビューの収束後に統合指示を再送する。再判定が不要な場合だけ、同書が保持した修正前後OIDの対応を使い、現在のHEADで統合指示を再送する。
同じthreadを継続できない場合の扱いは`agent-toolkit:delegation`のSKILL.mdの`## 継続と新規起動`に従い、新しいレーン担当を起動する場合は`再開位置`へ`~/.claude/plans`の計画ファイルの絶対パスを渡す。
