# 選定とレーン分けの開始

①の開始時に、process-wiのメインが本書を全文読み、選定の前処理、pickerの起動及び①の完了判定へ適用する。
pickerの起動契約、渡す入力と出力の検収は`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.parent.md`を正本とし、本書へ複製しない。

## 計画保存先の移行

メインが`atk plans migrate`を1回実行する。当該コマンドは移行対象の有無にかかわらず、先に計画保存先の作業ツリーがcleanであることを検査してremoteと同期する。
他の主体が取得中の計画バンドルは、所有記録の実在により同コマンドが移行対象から除く。
当該コマンドが非0で終了した場合は再試行せず、終了コードと出力を報告して選定を続行する。

## pickerの起動と出力の検収

`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.parent.md`を全文読み、同書に従ってpickerを起動して出力を検収する。処理対象の決定はpickerが担う。

## 終端工程の承認スコープ

pickerの出力を検収した後、メインが本節を適用して当該セッションの承認スコープを確定する。

`AGENT_TOOLKIT_PROCESS_LOOP_SESSION`の値が`1`である起動を自動常駐起動、それ以外を手動起動とする。`atk wi process-loop`が子セッションへ当該変数を設定するため、この観測で両者を判別できる。判別は①の実行中に1回だけ行う。

手動起動では、pickerが固定した各AWIの完成条件から、release、tag、push、PR若しくはMRの作成又は配布に当たる終端工程を抽出する。抽出した工程のうち、操作、対象及び外部可視の結果が当該AWIの本文へ明示されているものだけを、要求の由来を問わず当該セッションの承認スコープとして保持する。保持する項目は、AWIの正本ファイル名、操作、対象、影響範囲と、当該記載を含む完成条件の引用とする。

自動常駐起動では承認スコープを保持しない。完成条件へ当該工程の記載が無いAWIも保持の対象にしない。

承認スコープを保持した工程について、計画担当と終端担当のいずれかが同じ操作、同じ対象かつ同じ影響範囲の実行を要求する場合は、同じ範囲の承認を重ねて求めるUWIと確認を発行せずに実行する。bump種別、公開先又は生成物を新たに具体化して対象若しくは影響範囲が承認スコープと異なる場合は、その差分だけを`agent-toolkit/rules/01-agent.md`「協調と自律」の確認経路へ送り、承認スコープの残りを取り消さない。

破壊的操作の実行前に行う実行内容、影響範囲及び復元方法の説明は、承認スコープの有無にかかわらず維持する。

## ①の完了

選定時に`inbox`だった全項目が`processing`へ移り、メインが当該配置を確認するまでを①の完了条件とする。
遷移はpickerが実行する。メインによる確認と、`processing`へ遷移していない項目が残る場合の扱いは`${CLAUDE_PLUGIN_ROOT}/share/pick-wi.parent.md`の「①の完了」節が定める。
