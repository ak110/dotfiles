# レーンの変更範囲の検証の失敗

本書は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`の担当が、計画の`## 検証`にある`変更範囲の検証`行か計画なしの引き継ぎ記録に確定したコマンドの失敗を受けたときの扱いを定める。

`agent-toolkit:bugfix`を起動し、失敗の帰属を比較で確定してから、認可範囲に応じて是正する。

1. 既存不具合・変更範囲外・環境差のいずれかへ帰属させる前に、失敗した起動形、入力、並列度および環境を固定して、ベースと専用worktreeの結果を比べる。再現に危険な副作用がある場合は、安全な同等条件と残る差を明示する。両側の測定値と残る条件差を検証結果へ記録し、一方だけが失敗する場合はレーン差分と環境差の影響を特定する。
2. 原因と影響範囲を確定し、認可範囲内で是正して再実行する。
3. 認可範囲の外にある既存不良が変更範囲の検証を妨げる場合は、観測した失敗、直接的原因、修正の対象と方向をメインへ通知し、認可を待つ間もその修正に依存しない実装を続ける。認可を受領した修正は計画の実装とは別のcommitにし、commitメッセージの本文へ計画外の既存不良の修正であることと理由を、計画の進捗ログ（計画なしでは引き継ぎ記録）へ認可の出所、修正の対象および対応する完全OIDを残す。公開commitの読み手と、メインが渡す認可と同じ記録から確かめる実行レビュー担当の双方が、それぞれ到達できる記録から修正の扱いを判断できるようにするためである。
4. 計画の実装と認可された修正の両方を終えてから、変更範囲の検証を1回実行する。
