# レーンの変更範囲の検証の失敗

本書は、`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`の担当者が、計画の`## 検証`にある`変更範囲の検証`行、または計画なしの引き継ぎ記録で確定させた検証コマンドの実行失敗に直面した際の対処手順を定める。

`agent-toolkit:bugfix`を起動し、比較検証によって失敗の原因がどこにあるかを特定した上で、認可された範囲に応じて修正する。

1. 失敗を既存の不具合、変更範囲外の要因、または環境差異に安易に帰属させる前に、起動コマンドの形式、入力データ、並列度、実行環境をそろえて、ベースブランチと専用worktreeの双方で結果を比較する。それぞれの測定結果と残存する条件差異を検証結果に記録する。再現時に危険な副作用を伴う場合は、安全に実行できる同等の条件と残る差異を明記する。
2. 原因と影響範囲を特定し、認可された作業範囲内で修正して再検証を実施する。
3. 認可範囲外の既存不良によって検証が妨げられている場合は、観測された失敗事象、直接の原因、修正すべき対象と修正方針をメインエージェントへ通知する。メインエージェントからの指示を待つ間も、その修正を必要としない他の実装作業を継続する。認可を得た修正は計画に基づく実装とは別のコミットに分割し、コミットメッセージ本文には計画外の既存不良に対する修正である旨とその理由を記載する。さらに、進捗ログ（計画なしの場合は引き継ぎ記録）へ認可の出所、修正対象、一意な短縮OIDを記録する。これにより、公開コミットの閲覧者と実行レビュー担当の双方が修正内容の性質を正しく判断できるようにする。
4. 計画に基づく実装と認可された修正の両方が完了した後に、変更範囲の検証を一度実行する。
