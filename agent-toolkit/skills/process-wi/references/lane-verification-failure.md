# レーンの変更範囲の検証の失敗

本書は`${CLAUDE_PLUGIN_ROOT}/share/exec.subagent.md`の担当が、計画の`## 検証`の`変更範囲の検証`行か計画なしの引き継ぎ記録に確定したコマンドの失敗を受けたときの扱いを定める。

`agent-toolkit:bugfix`を起動し、失敗の帰属を比較で確定してから、認可範囲に応じて是正する。

1. 既存不具合・変更範囲外・環境差へ帰属させる前に、起動形、入力、並列度、環境を固定してベースと専用worktreeの結果を比べ、両側の測定値と残る条件差を検証結果へ記録する。再現に危険な副作用がある場合は、安全な同等条件と残る差を明示する。
2. 原因と影響範囲を確定し、認可範囲内で是正して再実行する。
3. 認可範囲外の既存不良が検証を妨げる場合は、観測した失敗、直接的原因、修正の対象と方向をメインへ通知し、待つ間もその修正を必要としない実装を続ける。認可を受けた修正は計画の実装とは別のcommitにし、commitメッセージの本文へ計画外の既存不良の修正であることと理由を、進捗ログ（計画なしでは引き継ぎ記録）へ認可の出所、修正の対象、一意な短縮OIDを残す。公開commitの読み手と実行レビュー担当の双方が修正の扱いを判断できるようにするためである。
4. 計画の実装と認可された修正の両方を終えてから、変更範囲の検証を1回実行する。
