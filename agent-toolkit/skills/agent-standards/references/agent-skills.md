# Agent Skills実装ガイドライン

Skill仕様のうちコーディングエージェント横断で適用できる汎用部分を扱う。
Claude Code固有の挙動には節ごとに「Claude Code固有」の注記を付ける。

## YAML frontmatter

- `description`には対象作業（何をするか）と発火条件（いつ起動するか）のみを書く
  - スキルの概要・背景・手順・実装の詳細は本文へ書き、descriptionには含めない
  - `name`と合わせて100語程度までを目安にする。長すぎるとトリガー判定のノイズになる
  - 複数行に分けたい場合はYAML折り畳みスカラーを使う。改行は半角スペースに変換される
  - 起動条件の重複表現を避ける
    - 例:「明示指示でのみ起動する。`/name`での手動トリガー専用」のように同じ意味の文を並べない
    - 重複はモデルがどちらを優先するかの揺れを招き、後の改訂時に片側更新漏れが起きやすい
  - トリガー発話例を複数列挙する書き方（「Aと言われたら／Bと言われたら」など）は重複ではない
- `disable-model-invocation: true`（Claude Code固有）: Claudeによる自動起動を無効化し、`/name`の手動起動のみに限定する
  - 副作用の大きいワークフロー（デプロイ・引き継ぎファイル出力など）で意図しない起動を防ぐ用途に使う
- 他スキル・エージェントから明示的に呼ばれる前提、またはユーザーが`/name`で手動起動する前提のスキル・エージェントは、
  descriptionを起動元・起動条件の明示のみに圧縮し処理概要を含めない
  - `description`は恒常的にコンテキストを消費するため、呼び出し元側でスキル名・エージェント名を明記済みなら内容の再掲は無駄になる
  - 例外は、起動と同時に別コンテキストの実行主体を生成し、渡した引数だけが入力となるスキルとする
    （`context: fork`を持つスキルなど）。呼び出し元は本文を読まないまま引数を組み立てるため、
    受理する引数と返る結果をdescriptionへ書く。書かない場合は正しく呼び出せない
  - 呼び出し経路に応じてfrontmatter仕様を選ぶ
    - 他スキル・エージェントから呼ばれる前提: `user-invocable: false`
    - ユーザー手動起動専用: `disable-model-invocation: true`
    - 自動起動と手動起動の両方あり（混合型）: いずれも設定しない

## SKILL.md本体とreferences/の役割分担

言語・トピック非依存の汎用規範はSKILL.md本体へ置き、言語固有・トピック固有の詳細はreferences/配下へ置く。

- 本体は全対象に共通する原則を記述する
  - スキルには主に知識を提供するものと手順を提供するものの2種類が存在する。本体冒頭で当該スキルがどちらであるかとその概要を明記する。
- references/は対象拡張子・トピックごとの細則を記述し、トリガー時のみ読み込む
- ある規範の所在を調べる際は本体とreferences/配下の両方を確認する
  - 片方だけを確認して有無を判断すると、本体側の汎用規範を看過する
- トリガー条件・コア手順・停止条件などの必須指示は本体冒頭側へ置く
 （自然言語でスキルを選択する環境では本体冒頭から一定行までしか読み込まないことがあるため）
- 行数上限超過を理由に必須指示をreferences/へ移さない
 （references/はトリガー時のみ読み込まれ参照漏れが起きやすいため）

## 委譲文書の責務分離

- 委譲元は委譲経路、入力資料、制約、返却物、検収条件を定める。委譲先固有の作業手順は書かない
- named agentは調整責務と受信形式を定め、呼び出し時には所定のタスク文書のパスだけを受け取る
- 受信するタスク文書は実施内容、対象、必要な作成・レビューの規範スキル、検証、返却形式を定める
- skillは利用者または委譲元が選ぶ作業入口を定める。named agentやタスク文書の本文を複製しない
- 同じ判断を委譲元と委譲先の双方が必要とする場合は共通skillへ置き、双方から参照する
- 起動入力は、受信者が適用する規範スキル、プラグイン内文書、役割から一意に導けない値だけを渡す。受信者が自ら選択できるスキル、文書、手順を入力へ重複させない

## スキル間操作

- SKILL.mdの記述だけでは別スキルは自動起動されない。実行中のエージェントがSkill機能で対象スキルを起動する
- 起動手順は実行主体、スキル名、渡す引数、期待する返却値又は効果を明記する
- 参照文書の読込みはSkill起動と区別し、実行主体がReadで全文を読む対象として記述する
- スキル間引継ぎでは利用側スキルが必要とする完成済み入力を提供側スキルが返し、利用側スキルは暗黙の会話履歴へ依存しない
- 提供側スキルは利用側スキル固有の参照文書へ依存しない。共通判断は提供側スキル又は実際の判断主体へ置く
- 必須の指示文書ルートから到達しない参照文書を実行時の配布物へ残さない。履歴保管は配布物外へ分離する
- 他スキルの参照資料を指す場合は、`agent-toolkit:<skill-name>`でスキルを識別し、その`SKILL.md`を含むディレクトリを基準に
  `references/<file>`を相対解決して参照資料を読む。参照資料だけを読むために別スキルを起動せず、起動が必要な場合は起動主体、入力及び返却値を明記する

## サブエージェント実行とパス解決（Claude Code固有）

SKILL.md内で使用できる`${CLAUDE_SKILL_DIR}`は、
実行時に当該SKILL.md所在ディレクトリの絶対パスへ展開される。
同梱ファイルをインストール先非依存で参照する用途に使う。
展開対象はSKILL.md本文に限る。
自身のスキルに同梱したファイルは`${CLAUDE_SKILL_DIR}`で参照し、
プラグイン全体のファイルや別スキルのファイルは`${CLAUDE_PLUGIN_ROOT}`から参照する。

YAMLのfrontmatterで`context: fork`を指定するとスキルをサブエージェントコンテキストで実行できる。
あわせて`agent`フィールドでサブエージェント種別
（`Explore`・`Plan`・`claude`等）を指定する。
`agent: Explore`または`agent: Plan`を指定したfork配下は親の`CLAUDE.md`・ルール群を継承しないため、
依存する規範は`${CLAUDE_SKILL_DIR}`または`${CLAUDE_PLUGIN_ROOT}`から
実行時に明示的に読み込む。

fork形態の公式制約は次のとおりで、fork配下のスキル・サブエージェント設計はこれらの前提で行う。

- `AskUserQuestion`はfork配下では使用不可（ユーザー対話はメイン側でのみ発行できる）
- ネスト深さは5階層までに制限される。fork内から更にサブエージェント起動を連鎖させる設計は避ける
- fork完了時は最終報告テキストのみが親へ返る（ツール呼び出し結果・中間出力は親コンテキストへ流れない）
- 規範読込型の`agents/`定義を`agent:`フィールドへ指定するfork形態を採用する場合、
  当該agents定義のfrontmatterで宣言済みツール制限・モデル指定が適用される

## サブエージェント定義の既定値（Claude Code固有）

`agent-toolkit/agents/`配下のサブエージェント定義をfrontmatterで新設する際は次の既定に従う。

- `model: inherit`を既定とする。特定モデルへ固定する場合はfrontmatter内コメント行に理由を明記する
- `tools`の制限は省略し無制限を既定とする。`tools`を限定する場合はfrontmatter内コメント行に理由を明記する

理由は当該サブエージェントの実態（除外したツール集合・選択したモデル種別）と整合する形で書き、
明記できない場合は既定値を採用する。

## その他

- `description`や本文にはfrontmatterで設定済みの仕様（例えば`disable-model-invocation: true`による
  自動起動の無効化など）を書かない。
  システム側で保証される挙動を繰り返すとコンテキスト消費が増え、
  frontmatterと本文で表現に齟齬が生じた時の矛盾リスクも生じる。
  「YAML frontmatter」節の起動元・起動条件の明示のみに圧縮した極小descriptionは、
  仕様の説明ではなく起動経路の明示に留まるため本規定の対象外とする
- スキルの運用で繰り返し発生した失敗事例は、そこから上位原則を抽出し、既存節の通常箇条書きへ統合する。
  対比表・禁止事項の羅列形式（Red flags／Gotchas等）の節を新設しない。
  禁止事項の列挙はコンテキスト汚染を招き、規範参照負荷も上げるため、上位原則の補強として書く

## 呼び出し側プロンプトの責務分離

スキルの動作詳細・既定動作・条件分岐・引数なし時の既定対象選定はSKILL.md本体に集約する。
呼び出し側プロンプトに動作詳細を書くと挙動が分岐しSSOT違反となるため、起動指示と引数のみを書く。

- 引数なしで起動した場合の既定動作・既定対象の選定基準もSKILL.md本体で定義し、呼び出し側で都度指定させない
- 呼び出し側プロンプトで動作を上書きしたい場合は引数として渡し、引数仕様もSKILL.md本体に明示する

## 公式リファレンス（Claude Code）

スキル新規作成・hook実装、ホスト機能の可否・入出力契約の判定では公式マーケットプレイス（`anthropics/claude-plugins-official`）の
`skill-creator:skill-creator`・`plugin-dev`各スキルを参照する。
まず各スキルの`references/`、次に公式ドキュメント、最後に実行時の内部観測の順で確認する。
各スキルの`references/`に記載のない仕様と、記載と認識が相違する事項は公式ドキュメントで確認する。
参照先は`https://code.claude.com/docs/ja/`配下（`memory.md`・`skills.md`・`sub-agents.md`・
`hooks.md`・`plugins.md`・`plugins-reference.md`など）とする。
列挙にないページを参照する場合は、ドキュメントインデックス（`https://code.claude.com/docs/llms.txt`）を
取得して対象ページのURLを特定する。インデックスが列挙するURLは英語版
（`https://code.claude.com/docs/en/<page>.md`）のため、日本語版を読む場合は言語部分を`ja`へ置換して用いる。
`WebFetch`はページの特定と概要の把握に使用してよい。
公式資料の文言、値の一覧、表の内容を成果物へ引用する場合は、同じURLの生本文を管理対象一時領域へ保存する。
保存後に該当箇所だけを検索し、生本文を典拠として引用する。

## サブエージェントが参照する規範スキルの読み込み（Claude Code固有）

サブエージェントが常時参照する規範スキルは、agents定義のfrontmatter `skills`で宣言する。
宣言したスキルの全文は起動時にコンテキストへ注入されるため、本文へSkillツールの起動手順を書かない。
特定作業でだけ必要な条件付きスキルは、観測可能な起動契機と併せて本文へ起動手順を書く。
スキル配下の`references/`はスキル読み込みでは自動的に読み込まれないため、
必要な参照文書はエージェント本文から明示的にReadする。
frontmatter `skills`で注入されたスキル本文には、所在ディレクトリの絶対パスの表示が付随する
（公式ドキュメントに記載のない実測挙動。サブエージェント記録で確認済み）。
プラグイン内の他ファイルを参照するサブエージェントは、この所在から確定したplugin rootの相対パスで解決できる。
