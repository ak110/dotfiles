# 事象単位の調査の委譲と探索の分担

バグ対応、CI失敗の対応、振り返りの事実収集で、事象ごとの観測事実の収集を独立した担当へ委譲する時と、読む量の多い調査や探索を分担する時の手順書である。
方針: 調査は依頼された担当が似た対象から順に進めて知見を再利用し、分担は起動と読込を含む総費用が下がる時だけにする（原則2、`agent-basics:writing-standards/references/quality-principles-qcd.md`）。
担当の推定と対策案は他者の報告として検証し、原因の特定と処置の決定は委譲元が持つ（原則6、`agent-basics:writing-standards/references/quality-principles-verification.md`）。

## 調査の進め方と委譲時の入力

1. 委譲するかを`agent-toolkit:atk-mode/playbooks/delegation.md`「要否判定」の総費用で決める。
   費用には、起動、規範と背景の重複の読込、指示の作成、検収、結論の組み直しを含める。
   事象の件数や独立性だけで担当を分けず、似た対象はまとめて渡す。
   広い所在の探索は、読取専用の`explore`へ分けてよい。
2. 独立した文脈へ渡す入力は、事象、期待する契約、実際の結果、発生条件、ログや資料の絶対パス、対象のcommit、再現手順の7項目とする。
   委譲元の仮説、原因の候補、修正案と、委譲元の推測で調査範囲を限る指示は入力から除く。
3. 報告を受けたら、原因が共通する対象をまとめ、異なる原因を分けて整理する。
   報告された推定と対策案は有力な候補として検証し、原因と処置は委譲元が決める。

### 起動方法

`agents_server`の`start`を次の引数で呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 調査対象のリポジトリの作業ツリーの絶対パス。見つけたエージェントがその作業ツリーで動いていれば自分の作業ディレクトリ、対象の外で動く場合（常駐起動の統括など）は対象の主作業ツリー（`agent-toolkit:atk-mode/playbooks/process-wi.md`「用語」。常駐起動では集合JSONの`worktree`） |
| `subagent_md_path` | `defect-investigation` |
| `extra_params` | 本書「渡す入力」の各項目 |

### 渡す入力

- `対象の不良`: 本書「調査の進め方と委譲時の入力」の7項目（発生条件には症状を観測した所在を含める）。
  見つけた側の仮説、原因の候補、修正案は除く。
- `引き継ぎ記録先`: 省略時と継続時の扱いは`agent-toolkit:atk-mode/references/delegation-prompt.md`「引き継ぎ記録先」に従う。

### 受領と検収

各欄の基準は`agent-basics:bugfix`が定める。

1. `状態: completed`なら、`期待`・`原因`・`処置`・`広がり`・`確認`の各欄に具体的な値があることを確かめる。
2. 返却を、示された`分析記録`の箇所とコードやログの現物に突き合わせる。
   `原因`は観測の所在を持ち、推測の部分は推測と書かれていること。
   `処置`が足す案なら、より前の案（無くす、単純にする、直す）を採用しない理由があること。
   `広がり`は検索と結果を持ち、`再発`の欄があれば前回と違う種類の対策を示すこと。
   欄が埋まっていることや独立走査だけで観測点の外側を保証したことにせず、未確認の前提が採否を変える時は、同じ担当へ支持・反証と観測範囲の補完を求める。
3. 不足や食い違いは、同じ探索を自分でやり直さずに同じ担当へ差し戻す。
4. `続行できない理由`が、認識の食い違いで要件や期待する結果の変更を伴う未確定事項なら、ユーザーへの確認へ回す。
5. 合格した処置に従い、見つけたエージェントが元の文脈で直す。
   修正中に調査の前提と矛盾する観測を得たら、同じ担当へ渡して分析を補わせる。

### 調査担当の返却契約

調査が完了したら、次の形式のみを返却する。

```text
状態: completed
分析記録: <詳細な分析を保存したファイルの絶対パス>
期待: <起きるはずだったことと、その期待が正しく必要である根拠。見直した場合はその結果>
原因: <起こしたものと、確かめた観測の所在。推測の部分は推測と書く>
処置: <無くす・単純にする・直す・足すのどれか、変更する対象と内容。より前の案を採用しない理由>
広がり: <同じ仕組みの他の箇所と、同じ害への既存の対策を探した検索と結果、該当した対象ごとの処置。探索の範囲と限界、独立走査を適用した場合の担当識別子と起点の検出の有無>
確認: <修正後に確かめる観測と方法>
再発: <問い4で対策が既にあった場合だけ。前回の対策の所在と種類、効かなかった理由、今回変えた種類>
再発防止: <再発防止を検討した場合だけ。採用する策と防ぐ害、または採用しない区分名と理由>
```

各欄に書く内容は`agent-basics:bugfix`の`SKILL.md`「記録」と、条件が成立した確認観点の資料に従う。
`再発`と`再発防止`の欄は、条件が成立しない場合は行ごと省く。

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。

## 類似見直しの分担

調査の責任者は、破られた条件か誤った判断の規則（`agent-basics:bugfix`の問い4）から判定規則・母集団・判定基準を確定し、`agent-toolkit:atk-mode/roles/similar-review.parent.md`に従って読取専用の類似見直し担当へ渡す。
類似見直し担当の工程は`chores`で、原因の判断と結果の採否は責任者が持つ。
`execute`は原因を調べる担当のモデルの区分であり、調査を開発の実行の時点へ一律に割り当てる指定とは別である。
登録時に確定した調査は、対象の変化か新しい証拠が再確認を要する時だけ見直す。

## コンテキスト消費が大きい調査の切り出し

読む量の多い調査を分担する時も「要否判定」の総費用で決め、読取だけなら`explore`の起動を優先する（モデルの工程は`agent-toolkit:atk-mode/references/model-settings.md`「工程別モデル設定」）。

1. 委譲元は、既存の公開操作、共通の定義、呼び出し元の参照関係などを先に調べて調査対象の全体像を確定し、所在や接続が不明な部分を探索しておく。
2. 担当の分け方は、読む文章量、判定の独立性、返る情報量、モデルの能力を総費用で比べて決める。
   1回の応答の取得上限と、全体を読んで判断すべき情報量を分け、短い出力が多数ある場合も合計で見る。
   同じ担当が分割取得で続ける案、小規模な所在探索や分けられない判断を自分で行う案も比べ、固定のファイル数や行数だけでは分けない。
   自動の会話圧縮を前提とし、文脈の温存だけを理由に分けない。
3. 各担当へ、重ならない対象集合、完了条件、判定基準、原本の参照先、返す観測値を示す。
   読取の分割でも、既存の書込所有権とレーンの境界を守る。
4. 担当は必要な原本を自分で読み、割り当てた範囲を自力で終える。
5. 委譲元は全体像と統合の責任を持ち、未確認の対象と結論どうしの矛盾を解いてから判断する。
   切り詰めや上限到達が報告された結果は、網羅、件数、不在の根拠に使わない（原則3、`agent-basics:writing-standards/references/quality-principles-facts.md`）。

全体点検で対象の処理と担当範囲を対応付ける時も、本節に従う。

### 検索結果に基づく探索の分担

件数、ファイル名、要約は、必要な本文へ進む手掛かりとして使う。
要約だけを受け取ったことを理由に原本の確認を省かず、結論を左右する未確定の点は原本で確かめる。

返す報告に含める項目: 委譲した対象と入力、検収で確かめた欄と差し戻し、委譲元が決めた原因と処置、未確認の対象と限界。
