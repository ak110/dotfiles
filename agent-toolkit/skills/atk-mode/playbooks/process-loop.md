# 登録リポジトリを巡回する

ユーザーか `atk wi process-loop` の起動入力が名指しした時だけ使う自律モードの手順である。
CLIはセッションの起動・終了後の再起動と制御を担当し、WIの処理と更新はこのセッションが担当する。

## 巡回する

1. `atk config repos list` で登録した対象のパス、系統、直接編集と検証の条件を確かめる。
   全体作業契約には目的、現行要求と保つ対象だけを書き、再開した場合は既存の検証・公開の結果を読み戻す。
2. キューを同期し、登録対象の処理候補を選ぶ。
   必要なら `atk wi check-alerts` でCIの失敗を別に確認する。
   `atk wi submission activity --target-repo <対象リポジトリ>` のactiveを確かめる。
   投入待ちか対象が無い場合は60秒待ってから手順2に戻る。
3. `agent-toolkit:atk-mode/playbooks/process-wi.md` で対象ごとの設定・認可と候補を確認し、選定、専用worktree、実行レビュー、統合、公開を進める。
   複数対象の配分と担当への受け渡しは `agent-toolkit:atk-mode/playbooks/process-wi-all-repos.md` を使う。
   登録元checkoutは直接編集せず、対象と系統ごとの専用作業ツリーから各レーンを作る。
4. 主な公開・リリースが終わった区切りで、そのセッションの単発 `review-session` を起動して増分を分析する。
   次に `update-dotfiles` を実行し、出力と終了状態を自分で確認する。
   失敗や新しい不良はその場で `agent-basics:bugfix` を起動して対処し、処置の結果を確かめてから反映や次回の選定へ進む。
5. 更新に成功したら、Claude Codeでは必要なpluginやMCPを `apply_runtime_changes` で反映する。
   セッションを続ける時は `compact_conversation` の `resume` を指定して圧縮後に再開し、途中の作業を保存してから現ターンを終える。
   本体側の更新を読むか区切りで新しい会話を使う時は、残工程を記録し `atk agents-exit-session` で正常終了する。
   CodexとAntigravityでは自動反映と自動再開を前提にせず、必要な場合は手動で再起動する。

## 中断と再開

- ユーザーの中断要求を受けたら、新たな対象の選定を止め、書込担当と公開の結果を回収して、未達の工程を記録する。
- 以前の会話を再開したら、前回の候補・認可・検証・操作の成否を確認して未完了工程から進める。
  既に成功した公開や保存の結果は再利用する。
- ランチャーで次のセッションへの追加指示、中断、再開を予約する方法は、`atk wi process-loop --help` を参照する。
