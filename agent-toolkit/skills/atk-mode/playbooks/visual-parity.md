# 見た目の完全一致の検収

見た目の完全一致を求められた移行（2つの実装の見た目を合わせる、スタイルの仕組みを移す）で、一致を確かめる手順書である。
移行する担当と、その成果を検収する委譲元が使い、通常のユーザビリティレビュー（`agent-toolkit:atk-mode/roles/usability-review.parent.md`）とは別の手順として行う。
原則6（`agent-basics:writing-standards/references/quality-principles-verification.md`）を見た目の移行へ適用し、一致は画像の差分で確かめる。
入力は移行するコンポーネントと一致させる相手（移行前の現行の実装か、合わせる先の実装）であり、終了条件は全てのコンポーネントで基準との差分が0になった時点である。

1. 移行の前に比較の基準を作る。
   現行のコンポーネントを状態ごとに描画して画面を取得し、比べる仕組みを用意する。
   2つの実装を合わせる場合は、相手側も同じ状態で取得する。
   基準の作成は移行より先に終える工程とし、基準が無いうちは一致を主張しない。
2. 比較の基準と比較の仕組みは、移行の間そのまま保つ。
   差分を0にする修正は移行先の側で行い、比較の仕組みの変更、基準の画像の差し替え、差分を消すためのコンポーネントの構造の組み替えは行わない。
   基準が誤っていると考えられる時は、直さずに作業を止め、依頼元へ確かめる。
3. 描画は`agent-toolkit:atk-mode/playbooks/verification.md`「完了前の実描画確認」の手段で行う。
   環境の待ち受けは`127.0.0.1`に限り、対象HEADを配信していることを確かめてから描画する（`agent-toolkit:atk-mode/roles/usability-review.subagent.md`「操作」と同じ扱い）。
4. コンポーネントごとに、基準と同じ画面と状態で描画した画像の差分で確かめる。
   差分が0でなければ不合格とし、差の出た画素を調べて直し、0になるまで繰り返す。

返す報告に含める項目: 移したコンポーネントごとの差分の結果、比較の基準と仕組みの所在、残りのコンポーネント、止めて依頼元へ確かめた基準。
