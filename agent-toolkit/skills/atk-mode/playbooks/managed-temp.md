# 一時領域（managed-temp）

一時ファイルの置き場所を選ぶ時と、作業用ディレクトリを作成・回収する時の手順書である。
作った領域は作った者が回収する（`agent-basics:writing-standards/references/quality-principles-ownership.md`）。
回収の前に、後で参照する入力・証拠・記録を回収対象の外へ移しておく。

## 条件と行動

| 条件 | 行動 |
| --- | --- |
| 同じセッションの後のターンや委譲先が使う入力、証拠、検証結果、引き継ぎ記録 | 本書「セッションのmanaged-temp」へ置く |
| 元資料から再生成できる抽出・比較用の複製、検証用の環境 | 本書「作業用ディレクトリ」で作って回収する |
| セッションのmanaged-tempの通知が無い、`.git`を含む、別のファイルシステム名前空間から使う | 本書「一時root直下に作成する領域」 |
| セッションの終了後やWIの完了後に参照する記録 | 作成時に対象AWIの本文か計画の`## 進捗ログ`へ書く |
| 版管理や自動同期が有効な設定領域を変更する前 | 本書「設定領域を変更する前の一時バックアップ」 |
| process-wiのレーンworktree | `agent-toolkit:atk-mode/playbooks/process-wi-lane-resources.md`に従う |

## 一時rootと自動削除

managed-tempの一時rootは次のディレクトリである。

- Linux: `${XDG_CACHE_HOME:-~/.cache}/agent-toolkit/managed-temp`
- macOS: `~/Library/Caches/agent-toolkit/managed-temp`
- Windows: `%LOCALAPPDATA%\agent-toolkit\managed-temp`

一時root直下の各ディレクトリと通常ファイルは、配下の最終更新から7日を過ぎると`atk`の実行時に自動で削除される。
領域外の実在するgitdirと逆参照が一致する登録済みworktreeを含む領域と、使用中の配布物の複製は削除の対象から外れる。
判定の実装は`docs/development/design-storage.md`にある。

## セッションのmanaged-temp

SessionStartは、セッションごとに一時root直下へ専用のディレクトリを準備し、その絶対パスを文脈へ通知する。
同じ`session_id`で再開した会話と会話の圧縮の後も、同じパスが通知される。
`Agent`ツールで起動されたサブエージェントには担当専用の子ディレクトリが通知され、一時ファイルはそこへ置く（親ディレクトリは委譲元から渡されたファイルの読み書きに使ってよい）。

1. 同じセッションで参照するターンまたぎの入力、完成条件の証拠、検証結果、委譲先へ渡す成果物、引き継ぎ記録は、この領域（サブディレクトリを含む）へ置く。
2. 退避ファイル、差分比較用の一時ファイル、中間出力も作業ツリーの外のこの領域へ置き、commitする成果物と混ぜない。
3. セッションのmanaged-temp自体は消さず、自動削除に任せる（同じ`session_id`で再開した会話が同じ領域を引き継ぐため）。
   配下の再生成できる作業環境は、所有と消費の終了と使用中の参照が無いことを確かめて先に回収する。
   turn間や委譲先で消費中の資源、原稿、検証記録、唯一の証拠は保持する。

## 作業用ディレクトリ

1. 用途ごとに`mktemp -d '<セッションのmanaged-tempの絶対パス>/<用途>-XXXXXXXX'`で作る。
   Windows PowerShellでは`New-Item -ItemType Directory -Path <絶対パス>`で作る。
2. Git管理下の作業ツリーを検証用に複製する時は`git worktree add`かcloneで作り、仮想環境などはパッケージマネージャーの同期機能で作る。
   作業ツリーのファイルを複製する時は、入れ子のworktreeとgitignore対象の仮想環境を、キャッシュとのハードリンクを解除した実容量で複製する。
3. テストとツールは`TMPDIR`などの一時領域の環境変数を変えず、対象プロジェクトが通常使う一時領域で実行する。
   変えると通常の実行条件から外れ、成果物と無関係な失敗とテストの変更を招く。
4. 後続ターンの入力と後から参照する証拠・検証結果は、回収する作業用ディレクトリの外（セッションのmanaged-temp直下など）へ残す。
5. 全ての消費工程と起動したプロセスが終わった後に、作成者が`rm -r -- <作成した絶対パス>`で回収する。
   worktreeは`rm`の前に`git worktree remove`で登録を解除する。
   Windows PowerShellでは`Remove-Item -LiteralPath <作成した絶対パス> -Recurse -Force`で回収する。
   回収の完了は対象が無いことで確かめる。

過去のエージェントが残した作業用領域は、`agent-toolkit/skills/atk-mode/references/operations.md`「プロセス終了の安全規定」で調べ、現在の利用と必要な成果を保護して不要な範囲を回収する。
明示的な回収の依頼では、配布元の残存、親セッションのpending、登録worktreeやロックの存在だけで配下を一律に保持しない。
資源ごとに現在の消費者、再開に必要な実体、原本と再生成の手段を確かめ、使用中の資源、未保存の差分、唯一の証拠を保護し、再作成できる未使用の複製を回収する。
完了は削除件数や空き容量ではなく、元の依頼が挙げた対象ごとに残存の有無と保持の根拠を確かめて判定し、調査不足の残存は未完了として続ける。

## 一時root直下に作成する領域

次の用途では、作業用ディレクトリを一時root直下に`mktemp -d '<一時root>/<用途>-XXXXXXXX'`で作る。

- セッションのmanaged-tempの通知を受け取っていない: 作って、回収は7日の自動削除に任せてよい。
- Git worktree、検証用clone、Git fixtureなど`.git`を含む領域: 作った工程が不要になった時点で`git worktree remove`で登録を解除してから`rm -r --`で回収する（登録済みworktreeは自動削除の対象外のため、7日を待たずに容量を返す）。
- 別のファイルシステム名前空間（Dockerコンテナーなど）から同じパスを使う: 全ての利用主体が使える既存の共有ディレクトリを確かめ、`mktemp -d -p <共有先の絶対パス>`で作り、作成者が回収する。

`.git`を含む領域は、個別の確認なしで回収できるよう保存物を寿命で分ける。
作業ツリーと一緒に捨てられる一時ファイルだけをその領域へ置き、同じセッションで使う証拠・検証記録・引き継ぎ記録・完了報告の参照物・委譲先の保存先は委譲元か委譲先のセッションのmanaged-tempへ置く。

## 設定領域を変更する前の一時バックアップ

版管理や自動同期が有効な設定領域（etckeeperが管理する`/etc`など）を変更する時は、変更前の版をその領域のローカル履歴から復元できるなら、その履歴をバックアップに使う。
別の複製が必要な場合はmanaged-tempへ置く。
設定領域の中へ置いたファイルは自動commitで履歴に取り込まれ、後で消してもローカル履歴と送信済みの履歴に残る。
変更の後に、ローカルの自動commitと外部への送信の両方に作業用ファイルが含まれていないことを確かめる。

返す報告に含める項目: 作った領域と回収の結果（残した領域は保持の理由と回収の条件）。
