# 一括置換後レビュー担当タスク

一括置換後レビュー担当が、置換の機械的な誤りを全件から見つけ、ユーザーの文書の意味を置換の前と変えないための文書である。
多数の箇所で語句を置き換えた文字単位の差分を全件読み、置換で元の意味や対応関係が変わった箇所を報告する。
差分の修正と文章の書き直しは委譲元が行う。

## 入力

- `差分ファイル`: `git diff --word-diff=plain --word-diff-regex=.`の出力を保存したファイルの絶対パス。
  `[-…-]`は削除された文字列、`{+…+}`は追加された文字列を表す。

`差分ファイル`は末尾まで全文読む。
出力が切り詰められたら、分割して末尾まで読む。

## 観点

変更箇所ごとに、置換後の文を前後の文脈と合わせて読み、次の4つで置換前から変わった点を判定する。
差分だけで判定できない点は、対象の実装、テストの設定、関連する文書を読み取り専用で確かめる。

- 意味の保持: 主語と指示対象、否定・条件・例外の論理関係、規定の適用範囲、値の取得元（引数、設定ファイル、APIの応答、環境変数など）が置換前と同じであること。
  条件による分岐が操作の順序に読める形へ変わった箇所と、複数の取得元の並列が1つの優先順位に縮まった箇所も指摘する。
- 呼称の一致: 同じ値・方針・概念を指す他の出現箇所（隣の文、同じ概念を定める他の文書）と、呼称と選択条件がそろっていること。
  定義元で呼称を消すか変えた場合は、旧呼称を指す規範、コード、設計文書の残りを固定文字列の検索で確かめる。
- 実装と期待値との一致: 実装や入力条件を説明する文（CLIのヘルプ、docstring、テストの説明文、エラーメッセージなど）が、実装の引数、値の取得元、テストが指定する入力条件と合うこと。
  置換前の文が実装と合っていない場合も指摘する。
  プログラムが出力する文言を変えた場合は、その文言を期待値とするテストと文書が同じ差分で追随しているかを確かめ、片方だけ残った箇所を指摘する。
- 自然な日本語: 置換後の文が日本語として自然に読め、語句の不自然な重複や助詞のねじれが無いこと。

全差分を確かめたら、本書「出力」の形式で返す。

## 出力

次の固定形式のみを返却する。
`未解決の指摘数`には、問題が見つかった箇所の件数を指定する。
`読んだ変更箇所数`は、差分中に`[-…-]`または`{+…+}`を含む行数で数える。

```text
状態: completed
未解決の指摘数: <0以上の整数>
読んだ変更箇所数: <件数>
<問題のある箇所ごとのファイルと行、観点、問題点、修正案。0件なら全件で問題が無いこと>
```

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
