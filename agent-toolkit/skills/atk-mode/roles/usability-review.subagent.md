# ユーザビリティレビュータスク

着手時に`agent-basics:review-standards`を起動し、届いた`reviewer-usability.md`で変更画面を独立評価する。
指摘の範囲と内容は同スキルの`reviewer.md`に従う。

## 入力

<!-- caller-input:start -->
各入力の値は次のとおり。

- `対象worktree`: レビュー対象の作業ツリーの絶対パス。
  起動時の`cwd`と同じパスを渡す。
- `変更画面`: 変更した画面のパスかURLと、その表示状態を出す操作手順。
- `同種の既存画面`: 実装の返却にある比較先、状態を出す操作と比較結果。
  該当が無ければ検索語と範囲を含む「なし」。
  入力の記載によらず、自分でも比較先を探す。
- `主要シナリオ`: エンドユーザーが画面で終える一連の作業の流れ。
  原要求、変更前の画面・利用文脈・保つ設計意図と、現在の実装テストの開始状態・経路・結果の証拠を含む。
  使いやすさを観察する資料として使う。
- `検証環境`: 対象プロジェクトの手順から確定したローカル環境の起動コマンドか、`127.0.0.1`で稼働中のURL。
- `引き継ぎ記録先`: managed-temp配下に作る記録ファイルの絶対パス。
- `round`: 初回を1とし、修正後の再判定ごとに1ずつ増やす番号。
<!-- caller-input:end -->

受領した`対象worktree`と起動時の`cwd`が一致することを確かめる。

## 操作

1. 対象worktreeは読み取り専用として扱い、接続先はローカルの検証環境、待ち受けのアドレスは`127.0.0.1`に限る。
2. 起動するコマンドとプロセスには実行時間の上限を付ける。
3. 起動前の`git status --porcelain=v1`が空でなければ、`agent-toolkit:atk-mode/roles/exec-review.subagent.md`「レビュー対象HEADと異なる作業ツリーでの検証」に従い、対象HEADを配信する。
   参照だけで起動できなければ許可された配信手段を試し、検証できる範囲を進める。
4. プロジェクトの手順で起動し、配信コードが対象HEADと一致することを確かめて描画する。
   配信したHEADを記録する。
5. 本番データへの書き込み、commitやpush、外部サービスへの通信など、検証環境の外へ影響が残る操作は、実データから切り離した`検証環境`でだけ行う（`agent-basics:writing-standards/references/ui-ux.md`「完了前の実描画確認」の手順1）。
   `主要シナリオ`がそれ以外の環境でその操作を要する時と、`検証環境`で許されない操作を要する時は、その操作を見合わせ、該当する手順を`続行できない理由`に書いて返す。
6. キャプチャと取得した記録は、`agent-toolkit:atk-mode/playbooks/verification.md`「完了前の実描画確認」の手段でmanaged-temp配下へ保存する。

## 判定と記録

1. `agent-basics:review-standards/references/reviewer-usability.md`「ユーザビリティレビューの判定」の手順で、主要シナリオと操作後に現れる各表示状態へ到達して判定する。
   round 2以降の観測と判定は、既指摘、修正差分とそのデグレードの範囲に限る。
2. 主要作業の機能停止で以後のUXを確かめられない場合は、共通返却契約の`続行できない区分: owner_input`と`続行できない理由:`の2行で、必要な機能修正と、同じ通常の開始状態から再判定するための再開条件を返す。
   描画手段が使えない場合の`未確定`とは区別する。
   判定に必要な入力の不足も共通返却契約で返し、不足した範囲を合格に含めない。
3. 再判定では、指摘の類型と全ての該当箇所を手順1で限定した範囲の中で探す。
4. 引き継ぎ記録先へ、`agent-toolkit:atk-mode/references/work-contract.md`の記録項目に加えて次を保存する。
   - 対象HEADの7文字以上の一意な短縮OID、`round`、完遂を試みたシナリオ、観測した状態、キャプチャの絶対パス
   - 指摘ごとの問題の機構、対象範囲、該当箇所、確認条件
   - 画面ごとの原要求と確かめた品質に対する、観測結果と未検証の範囲
   - 前提を作るための準備の操作と、通常の操作が失敗する状態を避けるための切替の操作の区別
5. 機能停止による続行不能を除き、判定を次のように選ぶ。
   - `合格`・`不合格`: いずれかの描画手段（対象プロジェクトのE2E環境、Playwrightのライブラリ、ブラウザー操作ツール）で画面を描画できた場合。
     `不合格`では、修正後の独立再判定が必要なシナリオと直接影響範囲を「出力」の再レビュー欄に示す。
   - `未確定`: 3つの描画手段を全て試し、いずれも使えなかった場合に限る。
     手段ごとに試したコマンド、実行の出力、使えなかった理由を記録し、キャプチャの代わりとする。
6. 例外的な終了も含め、返却の前に自分が起動した全てのプロセスを終了させ、引き継ぎ記録先へ記録する。

## 出力

次の形式のみを返す。

```text
判定: 合格 | 不合格 | 未確定
判定の回数: <番号>
レビューしたHEAD: <7文字以上の一意な短縮OID>
記録: <引き継ぎ記録先の絶対パス>
再レビュー: <要（範囲・失われる前提・理由）|不要（評価前提の所在）>
```

合格では、各画面の比較と実画面の観測を次の6行へ示す。
再判定で変わらない観点は前回の証拠を参照する。

```text
類例の比較: <入力と独立探索で見つけた画面、比べた状態と採否の理由。同種画面がなければ探索範囲と代わりの基準> | 外見: <実画面で確かめた共通スタイルとの一致か、同種の画面がない場合の類例・起点との比較結果>
情報設計: <領域ごとの判断と導線>
行の揃い: <比較する情報の位置>
冗長表示: <省いた情報と保った情報>
入力負担: <入力と画面往復の観測>
modern-web-guidanceのガイドと適用結果: <ガイド名と適用結果。非Webはその根拠>
```

再レビューの要否は`agent-basics:review-standards/references/reviewer.md`で判定する。
判定が`未確定`の場合は、上記の固定行に続けて`E2E環境`、`Playwrightのライブラリ`、`ブラウザー操作ツール`の試行を1行ずつ書く。

```text
試行: <手段> | <実行したコマンド> | <終了コードまたは失敗の観測>
```

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
環境による未確定の判定と試行結果は本節の固有結果として保持する。
