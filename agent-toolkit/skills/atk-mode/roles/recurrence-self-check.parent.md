# 再発防止セルフチェックの起動と受領

```text
起動対象: recurrence-self-check.subagent.md
```

再発防止セルフチェックは、実行レビュー担当が通常の走査と並行して、独立した担当に観点ファイルの項目を今回の差分へ当てはめさせる工程である。
実行レビュー担当が、初回レビュー、再レビュー、引き継ぎ再レビューの各ラウンドで本書を上から適用する。
起動、終了の観測、失敗からの回復は`agent-toolkit:atk-mode/playbooks/delegation.md`に従う。

## 入力

入力の定義はこの起動契約とagents_serverの`start`の検査が所有する。
役割固有の入力（`extra_params`）はこの契約の入力一覧で完結する。

- 必須入力名: `観点ファイル`、`今回差分`、`変更ファイル一覧`、`対象worktree`、`未解決指摘`

<!-- input-contract:recurrence-self-check:end -->

1. 観点ファイルを集める。
   観点ファイルは、H1が`# 再発防止セルフチェック観点`で始まるMarkdownである。
   次の2つを実行し、実在するファイルの和集合を取る。

   ```sh
   git -C <対象worktreeの絶対パス> grep -l -E '^# 再発防止セルフチェック観点' -- '*.md'
   rg -l -e '^# 再発防止セルフチェック観点' --glob '*.md' -- <配布rootの絶対パス>
   ```

   - 配布rootには現在のplugin root（`${CLAUDE_PLUGIN_ROOT}`）を指定する。
   - 終了コードは、0が該当あり、1が該当なし、それ以外が検索の失敗である。
     失敗した時は原因を除いて再実行する。
   - `git grep`が返したパスは、対象worktreeを基準にした絶対パスへ直す。
   - 配布物の原本のリポジトリをレビューする時に、配布rootのファイルが作業ツリーで追跡している原本と同じ実体なら、作業ツリー側だけを採用する。
     別のファイルは、項目名や内容が重なっても別に保つ。
   - 検索コマンド、終了コード、採用したファイル、重複として除いたファイルを走査記録（`agent-toolkit:atk-mode/references/review-record.md`「走査記録と差分外の不良」）へ残す。
   - 0件なら起動を省き、理由を走査記録へ書いて通常のレビューへ進む。
   - 各項目が対象条件・確認内容・根拠規範を備えた有効な単位かは、担当が本文から判定する。
2. 入力の値を決める。
   - `観点ファイル`: 手順1で得た絶対パスのJSON配列。
   - `今回差分`: 自分のmanaged-tempへ保存した差分ファイルの絶対パスと、比較元・現行版の識別子。
     初回は開始時点からレビューHEADまで、再レビューと引き継ぎ再レビューは前回確認版に保存した前回のレビューHEADから現行HEADまでの差分とする。
     同じHEADなら空の差分ファイルを保存し、未解決指摘は別の入力で渡す。
     Git管理外の変更は、受け取った変更前の複製（再レビューでは前回の本文の複製）と現行の本文から差分を作って保存し、新規のファイルは全文を保存する。
   - `変更ファイル一覧`: 今回差分に含まれるパスの一覧。
     Git管理外の変更も含め、対象worktreeを基準に現行の本文を読める形で渡す。
   - `対象worktree`: レビュー対象の作業ツリーの絶対パス。
   - `未解決指摘`: 前回までのセルフチェックに由来する未解決指摘の箇所、根拠規範、管理表の識別子、応答、検証結果。
     コマンドで得た証拠は保存先の絶対パスで渡し、初回と該当が無い時は`なし`とする。
3. 引き継ぎ再レビューでは、前回確認版と未解決指摘を前任の記録から復元する。
   比較元を特定できない時は、委譲元へ問い合わせて入力を補ってから起動する。
4. 再レビューと引き継ぎ再レビューで、管理外のファイルと回答の下書きを含む今回差分が空で、セルフチェック由来の未解決が0件なら、起動を省く。
   空の差分、比較元、現行版、未解決0件を、観点が0件の時と同じ走査記録へ残す。

## 起動

省略の条件に当たらなければ、通常の走査と並行して、集めた全観点を1担当へ渡して`agents_server`の`start`を呼ぶ。

| 引数 | 値 |
| --- | --- |
| `cwd` | 対象worktreeの絶対パス |
| `subagent_md_path` | `recurrence-self-check` |
| `extra_params` | 本書「入力」で決めた各値 |
| `model_type` | 実行レビュー担当が`担当モデル`を受け取っていればその値。受け取っていなければ指定しない |

## 受領と採否

1. `atk agents wait`で回収した終了結果から、`session_id`、`model_type`、`engine`、`model`、`effort`を走査記録へ残す。
   `model_type`を指定した場合は、渡した値と一致するかを確かめる。
2. 本書「セルフチェックの返却契約」の形式で返った全項目を、入力した観点の集合と突き合わせる。
   結果を取得するまで、未確認の項目を`適合`として扱わない（`agent-basics:writing-standards/references/quality-principles-verification.md`）。
3. 各`違反`を差分と根拠規範で裏付け、採用する指摘を`agent-basics:review-standards/references/reviewer-execution.md`「指摘の分類」の種類7として、既存のレビュー指摘管理表へ登録する。
   登録の形式は`agent-toolkit:atk-mode/references/review-record.md`「レビュー指摘管理表への登録」に従う。
   - 指摘の本文には、観点ファイルの絶対パスと項目名を書く。
   - 既存の指摘へ統合した項目は、統合先の指摘の本文にも観点ファイルのパスと項目名を足し、対応先を走査記録へ残す。
   - 採用しない項目は、項目ごとの理由を走査記録へ残す。
4. 前回指摘が解消したかを、現行の本文と検証結果で確かめて管理表へ反映する。
5. 全項目を登録先か不採用の理由へ対応付け、未解決の件数は既存の指摘と合算する。

## セルフチェックの返却契約

全項目について、以下の固定形式のみを返却する。
`前回指摘`には、未解決指摘の各識別子に対応する解消・未解消の状態と、その根拠を記述する。
入力が`なし`の場合は、値に`なし`を設定する。

```text
状態: completed
項目: <観点ファイルの絶対パスと項目名>
判定: <対象外|適合|違反>
根拠: <確認箇所、確認内容、違反では根拠規範の所在>
<項目ごとに項目・判定・根拠を繰り返す>
前回指摘: <識別子ごとの解消・未解消と根拠|なし>
```

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
資料不足の場合は、影響する項目、欠けた資料と補完に必要な値を記す。
