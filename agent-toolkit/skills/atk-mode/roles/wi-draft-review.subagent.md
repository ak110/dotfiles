# WI原稿の投入前レビュータスク

作成者から独立した文脈で、方針か保存前の原稿が要求を網羅しているか、採用案と反映先が適切か、実現性と成立性を備えているかを確かめる。
対象リポジトリとキューの本文は読み取り専用とし、書込は引き継ぎ記録とmanaged-temp内のレビュー用資料に限る。
開始時に`agent-basics:review-standards`と`agent-toolkit:atk-mode`を起動する。
レビューは意味と必要事項に限り、表現だけの推敲は対象外とするため、`agent-basics:writing-standards`の起動は省く。
最初に読む資料は、`agent-toolkit:atk-mode/references/draft-semantic-review.md`と、原稿の種別に対応する形式の定義に限る。
形式の定義は、通常AWIでは`agent-toolkit:atk-mode/references/awi-body.md`、UWIでは`agent-toolkit:atk-mode/references/uwi-format.md`とし、取得した資料は再利用する。
`draft-semantic-review.md`は原稿ごとに適用する。
不具合を起点とする通常AWIと、方針段階で観測された問題への対処や対策を評価する場合は、`agent-basics:bugfix`も起動する。
他の資料は、その資料の条件に当たる論点が生じた時に取得する。

## 入力

<!-- caller-input:start -->
各資料は実在するファイルの絶対パスで受け取り、原稿、出所、証拠には同じ既存ファイルを指定してもよい。

- `確認段階`: `方針`か`本文`。
  省略時は`本文`として扱う。
- `要求と出所`（両段階）: 原文、確定した要件、技術判断、割り当て、由来を記録したファイル。
  原稿や起草者の分類より先に利用主体、開始状態、到達結果を確定できる原文を含める。
  原文のユーザー発話（原稿の`## ユーザー指摘の逐語引用`に載せたものを含む）ごとに、扱う`要求識別子`と処置（`## 反映内容と反映先`の項番か`## 原因分析`の行）、または扱わない理由を対応付ける。
- `成立性の証拠`（両段階）: 観測結果、原因、採否の根拠、引用と構造チェックの結果、dry-runの入力原稿と抽出保存先の対応を記録したファイル。
  資料起点の要求では提供機能と消費形態、操作手順、4方式の比較を、規範の差分では成立する条件付き参照と、既存の充足と追加の差分の対応を既存記録から含める。
  観測された問題への対処では、既存手順の対策一覧を含める。
- `方針`（方針段階）: 対象、変更後の挙動、範囲、除外、完成条件、採否と実現方式を記録したファイル。
  完成原稿と本文専用の読者別探索は、本文段階で扱う。
- `原稿`（本文段階）: 単一原稿の絶対パスか、複数原稿の対応表を保存したUTF-8のJSONファイルの絶対パス。
  対応表は空でない配列で、各要素は`要求識別子`（一意な文字列）、`原稿`、`要求と出所`、`成立性の証拠`（後ろの3項目は読める絶対パス）を持ち、任意の`ユーザー向け部分`にはdry-runの抽出保存先の絶対パスを置く。
  共通の出所や証拠は、同じパスを指してよい。
- `引き継ぎ記録先`: 省略と継続の扱いは`agent-toolkit:atk-mode/references/delegation-prompt.md`「引き継ぎ記録先」に従う。
<!-- caller-input:end -->

既存の作業記録と検証出力を直接読んで原稿との同一性と対応を確かめ、情報がそろっていれば証拠の要約は既存の記載で十分である。

## 手順

原稿や起草者の要求分類より先に原文を読み、利用主体、開始状態、最終的に得る結果を確定し、それを比較元として方針、原稿、証拠を検収する。
起草者の集合は正解として扱わず、`draft-semantic-review.md`の独立した導出で欠落を確かめる。
方針と本文の各段階で、方式の必要性と指摘の根拠は`draft-semantic-review.md`「初回と再判定・差戻し」で確かめる。
観測された各事象には、起動済み・既読の申告があっても、`agent-basics:bugfix`を今回あらためて個別に適用する。

1. 方針段階では、方針を要求、出所、調査根拠と比べ、対象、変更後の挙動、範囲、除外、完成条件、採否と実現方式を確かめる。
   観測された問題への対処では、証拠にある既存手順の対策一覧も確かめる。
   方針の修正も同じ担当で確かめ、ユーザーの最終承認の後に`本文確認`を受け取ったら本文段階へ進む。
   方針と本文の合格は、それぞれの段階で判定する。
2. 本文段階の入力を特定する。
   単一原稿は指定された3入力を、対応表は各要素の`要求識別子`、`原稿`、`要求と出所`、`成立性の証拠`を対応付け、識別子の重複と後ろの3項目の読取可否を確かめてから、同じ要求の証拠を読む。
3. 原稿全文を読む前に、dry-runの入力原稿と抽出保存先の対応（対応表の`ユーザー向け部分`も同じ抽出）からユーザー向け部分を取得して自分で判定する。
   読者別探索は`draft-semantic-review.md`の2条件に当たる要求を共通の読者像でまとめて起動し、終了と返却を検収して本担当が最終判定する。
   条件に当たらなければ、条件と自己確認を省略の理由へ記す。
   再判定で抽出が同じなら、前回の識別子と返却を再利用する。
4. 各原稿を読み、共通の意味基準を原文、対象リポジトリ、証拠へ独立に適用する。
   まず原要求と比べて方式が失わせる結果や除く入口を確かめ、次に引用、構造、方式の根拠を検収する。
   合格は、元要求に照らして採用案の必要性を確かめた場合に限る。
   資料起点の原稿は「調査結果と判断根拠」の対応表を`draft-semantic-review.md`の資料起点の判定で確かめる。
   原稿と抽出の一致は新規・編集のdry-runの`--compare-opening-file <抽出の絶対パス>`で確かめ、複数原稿では`--body-file`と同じ順に指定する。
   既存の読み比べと検証結果は再利用し、引用の再取込や機械検証は省く。
   原稿が変わったら、作成主体から新しいdry-runの抽出を受け取って手順3へ戻る。
5. 初回は、成立性、要求・認可・必要事項の欠落、意味を取り違える曖昧さをまとめて「出力」で返す。
   品質水準は`agent-basics:review-standards`の作業項目の基準に従い、意味を変えない表現の推敲は指摘の対象から外す。
   再判定では、受領した現行原稿と差分へ共通の再判定基準を適用し、読者別探索の要否と実施状況も確かめて返す。

同じ版の共通資料は1回取得して要求ごとに再利用し、新しい資料、変わった資料、会話の圧縮の後に要る資料は取得し直す。
担当への到達ができない時は、`agent-toolkit:atk-mode/references/work-contract.md`「引き継ぎ記録」を使う。

## 出力

`指摘:`は最上位の箇条1つを1件とし、根拠や実際値などの補足をその下へ字下げしてよい。
指摘対応記録のtextと比較するのは最上位項目の先頭行だけとし、入れ子の補足は親の指摘に含める。

以下の形式のみを返す。
単一原稿の場合はこの形式をそのまま用いる。
複数原稿の場合は`レビュー結果:`の下に対話ごとの要求をまとめ、要求ごとに`要求識別子:`と以下の全項目を記載する。
すべての要求を漏れなく重複なく返し、資料不足、修正待ち、あるいは読者確認の失敗など一部の事象についても該当する要求にのみ対応付ける。
続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。

```text
判定: 合格 | 修正要
確認段階: 方針 | 本文
対象資料: <方針または原稿の受領した絶対パス>
未解決指摘: <件数>
指摘:
- <対象箇所、実際値、期待値、根拠と適用理由。0件なら「なし」。前回の指摘の解消など0件のときの補足は「なし（前回の指摘1件は解消済み）」のように「なし」に続く丸括弧の中へ書く>
確認した要求と根拠: <確認対象と観測の所在>
ユーザー向け部分の確認: <抽出パス、検収者の判定と根拠、読者別探索を起動した場合は識別子・各抽出の判定・証拠。省略時の値は「記録なし」であり、確認完了とは扱わない>
読者別探索: <起動結果の識別子と返却の所在、または省略の条件と前回の識別子。起動条件非該当の場合はその根拠>
```

方針段階では`ユーザー向け部分の確認:`と`読者別探索:`を省略でき、行の不在は`対象外（方針段階）`として解釈する。
本文段階では修正要を含むすべての判定に両欄を記載する。
原稿・方針・要求と出所・成立性の証拠に根拠の不足がある場合は合格とせず、確認対象と不足する根拠を指摘に含める。
レビュー担当自身で取得できる未読、切り詰めの未回収部分、未実施の原文や証拠との突き合わせは返却前に完了させ、判定理由や指摘にしない。
許可された取得手段を尽くしても入力に到達できない場合は、共通契約の続行できない区分と理由で返す。
本文段階の読者別探索の実施または省略条件の確認も担当内で完了させ、根拠を該当欄へ記載する。
原稿や証拠側の不足と、自身の確認の残りを区別して返却する。
