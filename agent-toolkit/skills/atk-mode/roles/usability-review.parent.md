# ユーザビリティレビューの起動と検収

```text
起動対象: usability-review.subagent.md
```

エンドユーザーが変更画面の意味を迷わず理解して作業を完了できるかを、実装者から独立した担当に確かめさせるための文書である。
画面差分がある時の並列画面レビュー（`agent-toolkit:atk-mode/references/workflow-phases.md`「用語」）で、実行レビューを起動する者（レーン工程ではレーン担当）がユーザビリティレビュー担当を起動・検収する手順である。
判定の基準は`agent-basics:review-standards/references/reviewer-usability.md`「ユーザビリティレビューの判定」にあり、本書は入力、起動、受領を定める。
見た目の完全一致を求められた移行の検収は、本書ではなく`agent-toolkit:atk-mode/playbooks/visual-parity.md`に従う。

## 入力

入力の定義はこの起動契約とagents_serverの`start`の検査が所有する。
役割固有の入力（`extra_params`）はこの契約の入力一覧で完結する。
通常起動の前に`agent-toolkit:atk-mode/references/work-contract.md`に従う全体作業契約を用意する。
`agents_server.start`に役割文書の`subagent_md_path`と、以下の役割固有の入力をまとめた`extra_params`を渡す。
`mode`は省略する（明示する場合は`mode: task`）。
全体作業契約の絶対パスは`extra_params`の外の`whole_contract_path`に渡す。

- 必須入力名: `対象worktree`、`変更画面`、`同種の既存画面`、`主要シナリオ`、`検証環境`、`引き継ぎ記録先`、`round`
- 任意入力名: `レーン識別子`

各入力の値は次のとおり。

- `対象worktree`: レビュー対象の作業ツリーの絶対パス。
  起動時の`cwd`と同じパスを渡す。
- `変更画面`: 変更した画面のパスかURLと、その表示状態を出す操作手順。
- `同種の既存画面`: 実装の返却にある比較先、状態を出す操作と比較結果。
  該当が無ければ検索語と範囲を含む「なし」。
  入力の記載によらず、自分でも比較先を探す。
- `主要シナリオ`: エンドユーザーが画面で終える一連の作業の流れ。
  原要求、変更前の画面・利用文脈・保つ設計意図と、現在の実装テストの開始状態・経路・結果の証拠を含む。
  使いやすさを観察する資料として使う。
- `検証環境`: 対象プロジェクトの手順から確定したローカル環境の起動コマンドか、`127.0.0.1`で稼働中のURL。
- `引き継ぎ記録先`: managed-temp配下に作る記録ファイルの絶対パス。
- `round`: 初回を1とし、修正後の再判定ごとに1ずつ増やす番号。

<!-- input-contract:usability-review:end -->

画面ごとの改善と既存品質を渡し、要求か観点が違えばシナリオを分ける。
通常の開始状態と代表作業は担当が選ぶ。
機能の正しさと別画面の新機能は対象外とする。
危険な操作は隔離環境と許す操作を明記するか対象外とする（`agent-basics:writing-standards/references/ui-ux-topics.md`「完了前の実描画確認」）。
レーンの起動だけ`レーン識別子`を渡し、session識別名を`<レーン識別子>-usability-review`とする。

## 起動

1. 起動の前に、対象worktreeの書き込み担当が、プロジェクトの手順で対象HEADを配備し直すか起動し、完了を確かめる。
   実装途中に配備した環境も対象HEADへ更新し、修正後の再判定でも新しい対象HEADで同じく準備する。
2. `agents_server`の`start`を、`cwd`に対象worktreeの絶対パス、`subagent_md_path`に`usability-review`、`extra_params`に本書「入力」の値を渡して呼ぶ。
   実行レビューと同じ対象HEADで並行して起動する。

## ユーザビリティレビューの返却契約

次の形式のみを返す。

```text
判定: 合格 | 不合格 | 未確定
判定の回数: <番号>
レビューしたHEAD: <7文字以上の一意な短縮OID>
記録: <引き継ぎ記録先の絶対パス>
再レビュー: <要（範囲・失われる前提・理由）|不要（評価前提の所在）>
```

合格では、各画面の比較と実画面の観測を次の7行へ示す。
再判定で変わらない観点は前回の証拠を参照する。

```text
類例の比較: <入力と独立探索で見つけた画面、比べた状態と採否の理由。同種画面がなければ探索範囲と代わりの基準> | 外見: <実画面で確かめた共通スタイルとの一致か、同種の画面がない場合の類例・起点との比較結果>
情報設計: <領域ごとの判断と導線>
行の揃い: <比較する情報の位置>
冗長表示: <省いた情報と保った情報>
入力負担: <入力と画面往復の観測>
可読性・アクセシビリティ: <最小の文字の計算値、主要な文字と背景のコントラスト比、キーボードだけでの完遂、操作対象の大きさの観測>
modern-web-guidanceのガイドと適用結果: <ガイド名と適用結果。非Webはその根拠>
```

再レビューの要否は`agent-basics:review-standards/references/reviewer.md`で判定する。
Webで判定が`未確定`の場合は、上記の固定行に続けて`E2E環境`、`Playwrightのライブラリ`、`ブラウザー操作ツール`の試行を1行ずつ書く。
ネイティブGUIで判定が`未確定`の場合は、対象OSでの描画の試行と不足した前提を`試行:`行に書く。

```text
試行: <手段> | <実行したコマンド> | <終了コードまたは失敗の観測>
```

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
環境による未確定の判定と試行結果は本節の固有結果として保持する。

## 返却後

1. 記録に対象HEADと`判定の回数`が正しく示されているかを確かめる。
   - `合格`か`不合格`: 完遂を試みたシナリオ、観測した状態、キャプチャの実在を確かめる。
     合格の6欄は空・未確認では受理しない。
     `類例の比較`は製品内の同種画面と記録された外見を照合する。
     `可読性・アクセシビリティ`は文字の計算値、コントラスト比、キーボード操作と操作対象の大きさを証拠から確かめる。
     同種画面が無ければ独立した探索の範囲と比べた基準を確かめる。
   - `未確定`: ネイティブGUIは対象OSでの試行と不足した前提を確かめる。
     Webは`E2E環境`、`Playwrightのライブラリ`、`ブラウザー操作ツール`の3つの`試行:`行がそろうかを確かめる。
     欠けていれば受理せず、同じthreadへ不足する手段の試行と再判定を求める。
   - 主要作業の機能停止による`owner_input`の返却: 機能の担当へ必要な修正と再開条件を渡し、解消後に同じ通常の開始状態から再判定を頼む。
     再判定が済むまで、停止で未検証となった部分を含む合格は受理しない。
2. `不合格`の根拠は、原要求、変更画面の既存品質、今回の変更によるデグレードの範囲に入るかで分ける。
   完成条件に書かれていなくても、変更・追加した画面の外見と共通スタイルとの一致は範囲内とする。
   round 2以降は、既指摘、修正差分とそのデグレードに限る。
   - 範囲外の観察（別画面の新機能追加など）: 判定の根拠から外し、適用範囲を示して同じthreadへ再判定を頼む。
     その観察がエンドユーザーの作業の停止か誤った結果を示す欠落なら、`agent-toolkit:atk-mode/playbooks/confirmation.md`「認可を要する操作」のバグの修正と新しい挙動の追加の区分で扱う。
     それ以外は参考の記録とする。
   - 範囲内の根拠: 問題の機構、画面状態・操作手順・表示幅と観測結果を修正条件にまとめる。
     `agent-basics:review-standards/references/reviewee.md`「修正要否の立証」「方式見直しと再レビュー」の比較と採否を既存の応答へ記録し、そろってから採った指摘だけを同じ実装担当へ返す。
     実装担当は指摘箇所に加えて同じ機構を持つ依頼対象の全体を確かめ、新しい対象HEADを対象の実行環境で描画し、試した条件と表示結果を再提示する。
     要否が欠けるか、修正で評価前提が変わる場合は各担当に照会し、要とされた範囲だけ再レビューを頼む。
3. 統合前に双方の初回レビュー、要とされた再レビュー、全指摘の採否と修正後の描画の証拠を検収する。
   ユーザビリティレビューの記録は評価した版のまま、修正後の証拠と分けて計画の検証結果へ加える。
   `未確定`では、使えなかった描画手段と未確認の画面状態を完了報告に書く。
