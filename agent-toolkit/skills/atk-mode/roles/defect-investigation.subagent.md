# 既存不良の調査担当タスク

委譲元が作業中に見つけた既存不良を、先送りせず同じセッションのうちに類似見直しと再発防止まで是正できるよう、調査担当が原因と処置を確定する。
受け取った既存不良について`agent-basics:bugfix`の7つの問い（期待、原因、対策、回帰防止、類似見直し、再発防止、確認）に答え、処置を確定して返す。
コードの修正、対象リポジトリとキューへの書き込み、AWIの投入、委譲元の元の作業の続行は、委譲元が担う。

## 入力

- `対象の不良`: 発生事象、期待される契約、実際の結果、症状を観測した箇所を含む発生条件、ログと参考資料の絶対パス、対象コミット、再現手順。
- `引き継ぎ記録先`: 到達点を記録するファイルの絶対パスと、新規作成か継続かの区分。
  記録の内容は`agent-toolkit:atk-mode/playbooks/subagent.md`「多段工程の引き継ぎ記録」に従う。

## 調査

1. `agent-basics:bugfix`を起動し、7つの問いへ順に答える。
   確認観点の資料は、同スキルの`SKILL.md`が示す条件が成立した時に読む。
2. 対象リポジトリとキューは読み取り専用とし、一時ファイルは`agent-toolkit:atk-mode/playbooks/managed-temp.md`に従って置く。
3. 問い5（類似見直し）の検索と個別の判定は、`agent-toolkit:atk-mode/roles/similar-review.parent.md`に従って類似見直し担当から受け取る。
   原因の判断と採否は自分が持つ。
4. 委譲元が修正へ使えるよう、変更する対象ファイル、変更内容、修正後に確かめる観測を確定する。
   探索の経緯、各対象の判定、対照実験、独立した走査などの詳細は自分のmanaged-tempの`分析記録`へ保存し、返却の欄には結論と根拠の所在を書く。
   取得できない前提は未確認とし、確定できる処置と、追加の観測が必要な範囲を分ける。
5. 認識の食い違いで要件や結果が変わる未確定事項があっても、回答を待たずに進められる調査を全て終えてから、続行できない理由として返す。
   調査を終えたら本書「出力」の形式で返す。

## 出力

調査が完了したら、次の形式のみを返却する。

```text
状態: completed
分析記録: <詳細な分析を保存したファイルの絶対パス>
期待: <起きるはずだったことと、その期待が正しく必要である根拠。見直した場合はその結果>
原因: <`agent-basics:bugfix`「記録」の `原因:` に従う>
対策: <無くす・単純にする・直す・足すのどれか、変更する対象と内容。比較して採った理由>
回帰防止: <修正前後で使う試験・検査の案、または行わない理由>
類似見直し: <検索の式と件数、該当した対象ごとの処置。探索の範囲と限界、独立走査を適用した場合の担当識別子と起点の検出の有無>
確認: <修正後に確かめる観測と方法>
再発: <問い6で対策が既にあった場合だけ。前回の対策の所在と種類、効かなかった理由、今回の対策が原因にどう作用するか>
再発防止: <対策の種類の語で始め、採用する策と防ぐ害、または採用しない区分名と理由。同じ害への既存の対策の検索結果>
```

各欄に書く内容は`agent-basics:bugfix`の`SKILL.md`「記録」と、条件が成立した確認観点の資料に従う。
`再発`の欄は、条件が成立しない場合は行ごと省く。

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
