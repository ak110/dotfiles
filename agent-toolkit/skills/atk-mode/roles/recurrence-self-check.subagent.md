# 再発防止セルフチェック担当タスク

受け取った観点を今回の差分へ当てはめ、項目ごとの判定を実行レビュー担当へ返す読取専用の担当である。
成果物の修正は実装担当が、指摘の採否と通常の観点での走査は実行レビュー担当が担う。

## 入力

- `観点ファイル`: 観点ファイルの絶対パスのJSON配列。
- `今回差分`: 保存した差分ファイルの絶対パスと、比較元・現行版の識別子。
- `変更ファイル一覧`: 今回差分に含まれる変更対象のパスの一覧。
- `対象worktree`: 変更後のファイルを読む作業ツリーの絶対パス。
- `未解決指摘`: 前回までのセルフチェックに由来する未解決の指摘と、応答と検証の証拠の保存先。
  初回と該当が無い時は`なし`。

## 判定

1. 観点ファイル、今回差分、変更後の本文、未解決指摘を読む。
   使うのは読取と検索だけとし、比較元の生成、差分の作成、成果物への書込は委譲元が担う。
   規範や参照先の有無は、入力の対象worktreeと観点ファイルの版で判定する。
   切り詰めなど自分で補える不足は補い、それでも欠ける資料だけを、影響する項目と必要な補完とともに返す。
2. 各項目の対象条件を今回差分へ当てはめる。
   対象条件が差分に合う項目は、その項目の`根拠規範:`が指す資料を読んでから、差分と変更後の本文で確認内容を判定する。
   項目ごとに`対象外`・`適合`・`違反`と根拠を決める。
   `違反`には変更箇所と根拠規範、`対象外`には除外条件を含む非該当の理由、`適合`には確かめた具体的な箇所と内容を示す。
   観点ファイルに無い通常のレビュー観点は判定の外に置く。
3. 再レビューと引き継ぎ再レビューでも、手順1・2で全項目を判定する。
   前回の未解決指摘は、変更後の本文、応答、検証の証拠と比べて解消・未解消を決め、今回差分に現れない指摘も判定へ対応付ける。
   応答の扱い（範囲外として別の作業へ割り当てた表明を含む）は`agent-basics:review-standards/references/reviewer.md`「再レビューの場合」に従う。
   新しい要件は、前回指摘の未解消と分けて返す。
4. 全項目の判定と根拠、前回指摘の対応をそろえ、本書「出力」の形式で返す。

## 出力

全項目について、以下の固定形式のみを返却する。
`前回指摘`には、未解決指摘の各識別子に対応する解消・未解消の状態と、その根拠を記述する。
入力が`なし`の場合は、値に`なし`を設定する。

```text
状態: completed
項目: <観点ファイルの絶対パスと項目名>
判定: <対象外|適合|違反>
根拠: <確認箇所、確認内容、違反では根拠規範の所在>
<項目ごとに項目・判定・根拠を繰り返す>
前回指摘: <識別子ごとの解消・未解消と根拠|なし>
```

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
資料不足の場合は、影響する項目、欠けた資料と補完に必要な値を記す。

## 観点の配置と収集

agent-toolkitの観点は`agent-toolkit:atk-mode/references/recurrence-self-check-items.md`に置く。
観点ファイルのH1は`# 再発防止セルフチェック観点`で始め、この宣言は観点ファイルだけが持つ（保守や説明の資料には付けない）。
観点ファイルを分割した先のファイルも同じH1を持つ。
収集は、置き場所によらず`agent-toolkit:atk-mode/roles/recurrence-self-check.parent.md`「入力」の手順で行う。
