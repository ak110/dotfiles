入力の定義はこの起動契約とagents_serverの`start`の検査が所有する。
役割固有の入力（`extra_params`）はこの契約の入力一覧で完結する。

- 必須入力名: `判定規則`、`母集団`、`判定基準`

<!-- input-contract:similar-review:end -->

1. 確定した原因から、次の3つの入力を決める。
   - `判定規則`: 確定した原因を、破られた条件か誤った判断の規則として1文で書く。
   - `母集団`: 対象リポジトリと版、探す範囲の取得先、WIの投入開始日、ログの開始日時と観測終了時点。
     探す範囲は現存するファイルと直近7日の作業項目・会話の記録とし、原因が他の範囲に及ぶ時だけ、成立の根拠を添えて広げる。
   - `判定基準`: 該当・保留・非該当を分ける条件と、必要な調査の深さ。
2. 会話の記録の取得先を、対象ごとに確かめてから示す。
   Claudeのカタログの取得先は、親のJSONLが直下にある実在の`~/.claude/projects/<project>`とする（`~/.claude/projects`そのものは複数のprojectの収納先であり、ソースリポジトリのrootとも違う）。
   複数のprojectやglobalを含む母集団では、取得先を個別に示し、全対象との対応を保つ。
   担当が読めない資料は、取得済みのファイルを渡して補い、権限の境界は保つ。
3. 渡すのは3つの入力だけとし、起点の具体的な事象、場所、識別子、修正内容は除く。
4. `agents_server`の`start`を、`cwd`に対象worktreeの絶対パス、`subagent_md_path`に`similar-review`、`model_type`に`chores`、`extra_params`に3つの入力を渡して呼ぶ。

## 受領と採否

1. 共通の待機の手段で、終了と自動保存された返却ファイル（`agent_message_path`）を回収する。
   正常な結果と続行不能の区分は、本書「類似見直し担当の返却契約」のとおりに受け取る。
2. `検索記録`、`分類結果`、`調査の限界`を3つの入力と比べ、母集団・版・期間・判定基準との対応、各段の検索式・件数と単位、分類の根拠、0件の時の見直し、未取得と保留を確かめる。
   取得できなかった範囲は、0件や非該当と分けて扱う（`agent-basics:writing-standards/references/quality-principles-facts.md`）。
   非該当の全件は読み直さず、該当・保留と、基準が不明確な対象を自分で最終判断する。
3. 起点が見つからなければ、母集団の漏れ、検索の漏れ、本文を読んだうえでの非該当を区別し、検索の条件を1回直して同じ担当へ再依頼する。
   再依頼でも見つからなければ調査の限界として記録し、追加の起動を終える。
4. 該当した対象の修正の要否と、担当範囲外の引き継ぎを、既存の記録の`広がり:`の行へ反映する。

## 類似見直し担当の返却契約

次の形式のみを返す。
状態行、続行不能の区分と理由は`agent-toolkit:/share/rules/rules-subagent.md`「返却形式の受け渡し」に従う。

```text
状態: completed
検索記録: <各段の母集団・式・件数と単位、個別判定、再取得に使う保存出力の絶対パス>
分類結果: <該当・保留・非該当の候補数と各所在・根拠の参照先>
調査の限界: <未取得範囲、期間外、未確認事項。なければ「なし」>
```

補助的な広域走査で見つかった記録を取得できない場合は、許された所在確認を尽くし、取得済みの検索・分類結果と未取得範囲を`調査の限界`へ記して正常結果を返す（未取得範囲の不在・網羅性・期間外は未確認として扱う）。
指定された起点記録、要求・認可の確定、採否・原因の確定に不可欠な原記録が欠ける場合は、共通返却契約の続行できない区分と理由に必要な入力と再開条件を記し、取得済みの結果も返す。
