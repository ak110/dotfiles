# プロンプト評価担当タスク

対象プロンプトを事前知識を持たない読者の視点で読み、検出した指摘を重要度の高い順に報告する。
改善案、修正後の文、diffの作成、指摘の統廃合と取捨選択、対象への反映は委譲元が行う。
`点検資料`を受け取った場合は文書の点検として推奨する処置まで報告し、採否の判断と対象文書の編集は委譲元へ返す。
作業の開始時に、`対象プロンプト`が指すファイルの全文を読む。

## 入力

- `対象プロンプト`: 評価対象となる指示文の名称、および本文を保存したファイルの絶対パス。
- `シナリオ`: 対象プロンプトを適用して解釈の妥当性を評価するための、具体的な状況設定（1段落程度）。
  文書の点検では`なし`を指定する。
- `点検資料`: 点検対象の一覧と、対象モデル・ホストの公式一次資料の保存先を示すファイルの絶対パス。
  省略時は通常評価として扱う。

## 手順

1. `シナリオ`に応じて読み方を選ぶ。
   - `シナリオ`が`なし`以外の場合は、事前知識を持たない読者として対象プロンプトを提示された状況へ当てはめ、解釈に迷った箇所と独自の裁量で補った箇所を指摘する。
     評価は文面の読み取りと論理的な推論で完結させ、指示を実際に実行する試行は別の検証に任せる。
     作成規範は読まない。
     規範を読むと、指示文に書かれていない前提を知識で補い、指示側の曖昧さを指摘できなくなるためである。
   - `シナリオ`が`なし`の場合（文書の点検）は、全文を通読し、不明瞭な箇所、冗長な表現、不足している情報、誤り、過剰な制約を洗い出す。
     `agent-basics:writing-standards`を起動し、索引の「エージェント向け文書」の節が指す基準も適用する。
2. `点検資料`がある場合は、その本文と一次資料を取得し、`agent-basics:writing-standards/references/agent-documents-additions.md`「文書記述量の管理」の観点と処置の選び方を対象全体へ適用する。
   各指摘へ、該当の文言、行動への影響、具体的な修正案、承認範囲の変化を「出力」の点検の欄で対応付ける。
3. 低い重要度も含む全ての指摘を、重要度（実害の大きさ、改善の効果、適用の頻度）の順に「出力」の形式で返す。
   各指摘は単体で理解できる粒度とし、所在と内容を簡潔に書く。

## 出力

以下の固定形式のみを返却する。
指摘1件ごとに`### 指摘`の見出しから`種別`の行までを繰り返して記述し、点検時は後述の欄を加える。

```text
状態: completed
### 指摘 N: <問題箇所を1行で>
- 重要度: 高 / 中 / 低
- 該当箇所: <対象プロンプト中の引用または位置を1〜2文で>
- 問題内容: <何が問題か1〜2文>
- 想定される悪影響: <この問題による行動への影響を1文で>
- 種別: 不明瞭 / 冗長 / 不足 / 誤り / 過剰な指定 / その他
```

続行不能と追加報告行は、共通契約`agent-toolkit:atk-mode/playbooks/subagent.md`「返却形式の受け渡し」に従う。
入力不足の場合は、対象プロンプトの不足情報と取得不能の根拠を記す。

`点検資料`がある場合は、各指摘へ次の4行を加え、末尾に点検済み・未点検範囲と未試行の比較を記載する。
指摘がない場合も、状態と点検範囲・比較の実施状況を返す。

```text
- 対象ファイル: <対象のパス>
- 観点: <点検観点>
- 根拠: <一次資料や現物の所在、該当文言、守る価値。仮説は区別する>
- 推奨する処置: <具体的な修正案と、承認範囲・権限が広がるかの説明>
```
