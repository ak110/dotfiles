# 単一計画の初回以外の実行レビューの起動と再レビューの要否

実行レビューの起動側が、内部の群、複数の計画、`CI記録`、引き継ぎ再レビューのどれかで起動する時と、レビューの後にHEADが変わって再レビューの要否を決める時に読む。
起動、受領、修正、収束の手順は`agent-toolkit:atk-mode/playbooks/exec-review-loop.md`にあり、本書は同書「起動」と「ラウンドの遷移」の手順に足す前提と例外だけを置く。

## 起動方法別のレビュー基準

### 内部の群

別のbranchとworktreeへ分けた内部の群は、レーン担当が、群ごとの実装・焦点の検証・保存が終わった順にレビューの単位として起動する（全群の完了を待つ一斉の初回レビューは避ける）。

1. 他の群が編集中でも、対象の群の書込担当はレビューの間そのworktreeの編集と履歴の更新を止める。
2. レーン担当は、保存したHEAD、割り当てた要求と元のWIの条件の対応、直接影響の集合、検証の成功の証拠を引き継ぎ記録で固定する。
3. 起動には既存の`計画`、`対象ファイル限定`、`review_contract`、検証の記録を使い、割当外の未達の条件も元のWIとの対応を保って渡す。
   条件表では`agent-toolkit:atk-mode/references/review-contract.md`「記録する行と要求単位」の他項目への割当と除外理由の行を使い、群の割当外の条件を除外理由の一致として検収させる。
4. 同じ計画を複数の群で使う場合は、原本と割当の対応を記した群ごとの計画とcommit対応記録の複製を独立した保存先へ置き、その複製を`計画`として渡して、指摘管理表と契約を群ごとに保つ。
5. 起動側が固定した保存HEADとの一致も確かめさせ、未保存の本文と他の群の未完了の結果は判定の根拠から外す。
6. 群の完成条件証拠は群の判定範囲の合格であり、元のWI全体の合格と分けて扱う。
   独立した保存HEADで先に受けた群には群ごとの単位を使い、共通の検証が要る組合せは最終のレビュー単位へ含める。
7. 全ての群を取り込んだ後は、受理済みのレビューの本文・環境・契約との一致を確かめ、元のWIの全条件の被覆、群の間の契約、共有の生成物、組合せの差分、未達の条件を最終のレビュー単位で検収する。
   同じ条件で受理した群の本文を一律に再レビューすることは避け、本書「HEADの更新と再レビューの要否」の比較で影響する範囲だけを選ぶ。

### 複数の計画

同じレーンに複数の計画（初回の分割による複数の計画か、凍結済みの先行計画と追加の計画）がある場合は、レビューの単位を計画の境界でなく共有する変更で決める。

1. 同じ最終実装HEADで判定対象commitの変更ファイルが重なる計画と、同じ変更範囲の検証を共有する計画は、1つのレビュー単位にまとめて1回だけ起動する。
   計画を分けた理由（行数の警告、凍結済みの計画への追加）だけでは単位を分けない（同じ準備・起動・読込を計画の数だけ繰り返しても、独立した判定は増えずに所要だけが増えるため）。
2. レビュー済みの計画は、本書「HEADの更新と再レビューの要否」の影響を受ける計画に当たる時だけ新しい単位へ含める。
3. 1つの単位に複数の計画を含める場合は、`計画`へ全ての計画の絶対パスをJSON配列で渡し、1つの`review_contract`に計画名とAWIごとの要求行を残して、1つの指摘管理表と1つの返却を受ける。
   契約は初回か再レビューかによらず、`agent-toolkit:atk-mode/references/review-contract.md`「`review_contract`の生成」で単位ごとに作る。
4. 変更ファイルも検証も共有しない計画は別の単位とし、各単位にはその単位の計画に対応するAWIだけを割り当てる。
5. 単位ごとの成果物は、指摘管理表、完成条件証拠を含む返却、`review_contract`である。
   レーン全体を管理する担当には全ての単位の分を計画との対応を保って1回で渡し、各レビューのthreadにはその単位の分を渡す。
6. 並行して反復する間は、単位ごとに最後のレビューHEAD、ラウンド数、指摘管理表、受理した返却ファイルを保つ。
   レーンを統合する時は、単位ごとに受理した返却ファイルと`レビューHEAD`を`agent-toolkit:atk-mode/references/review-record.md`「統合時の完成条件判定」へ渡す。
7. 読者別探索の対象と修正の範囲は自分の単位の計画の判定対象commitによる差分とし、他の単位のcommitだけで変わった文書はその単位で判定する。
   他の単位が作った記述への指摘の候補は、委譲元がその単位のレビュー担当へ1回だけ回し、その担当が同じHEADで読者別探索を終えて出した結論を採用する。
   自分の単位の変更が参照先、手順、識別子などの前提を変えた場合は、自分の単位の直接影響範囲として判定する。

### CI記録

レビュー基準が`CI記録`だけの起動は、`agent-toolkit:atk-mode/playbooks/process-wi-ci-fix.md`「修正系列」の手順4が起動の条件と渡す値（CI記録の7項目、`修正系列の開始時のHEAD`、`原因commitOID`）を定める。

1. CI記録には、原因commitを作った担当がその時に持っていた情報を直接書く。
2. `レーン識別子`の指定と`<レーン識別子>-exec-review`のセッション識別名の規定は、`CI記録`だけによる起動には当てはまらない。
3. 指摘管理表は`agent-toolkit:atk-mode/references/review-record.md`「レビュー指摘管理表のパス」の`CI記録`の行に従い、同じ修正系列では同じ表を引き継ぐ。

### 引き継ぎ再レビュー

前の実行レビュー担当が続けられず、新しい担当へ再レビューを引き継ぐ時の起動である（継続できるかの判定と引き継ぎは`agent-toolkit:delegation`の`SKILL.md`「継続と新規起動」）。

1. `レビュー種別: 引き継ぎ再レビュー`と、`agent-toolkit:atk-mode/playbooks/exec-review-loop.md`「起動」と本書の他の節で決めた基準ごとの入力を渡す。
2. `前回確認版`には、前の担当の引き継ぎ記録に保存された記録ファイルの絶対パスを渡す。
   記録ファイルは、前回レビューしたHEADと、Git管理外の文章成果物ごとの識別子と前回の本文の複製のパスを含む。
   記録ファイルと比較元の実在を確かめてから起動し、取得できない情報があれば、欠けたHEADか本文の取得元を委譲元へ報告する。
3. `round`には`agent-toolkit:atk-mode/playbooks/exec-review-loop.md`「ラウンド番号の保持先」の値を渡す。
   `review_contract`は`agent-toolkit:atk-mode/references/review-contract.md`「`review_contract`の生成」で作り直す。
4. `引き継ぎ記録先`の`（継続）`の表記は`agent-toolkit:delegation/references/base-contract-handoff.md`「引き継ぎ記録先」に従い、`rewrite_map`は`extra_params`で渡す。

## HEADの更新と再レビューの要否

レビュー修正かmergeの競合の解消でHEADが変わったら、影響を受ける計画を含むレビューだけを再レビューする。
前回のレビューHEADを`R`、最新のHEADを`H`、開始時のHEAD（rebase後はrebase先のOID）を`<基点>`とし、次のどちらかに当たる計画を「影響を受ける計画」とする。

- `git range-diff <開始時のHEAD>..<R> <基点>..<H>`で、その計画の判定対象commit（`review_contract`で判定対象外としたcommitを除く）のどれかが`=`以外で対応している。
- `git diff --name-only <R> <H>`の変更ファイルが、その計画の判定対象commitで変更されたファイルと重なる。

1. 対象worktreeで上のコマンドを直接実行する。
   判定対象commitは、`atk run-script plan-commits -- <計画の絶対パス> --worktree <対象worktreeの絶対パス>`が返す一覧から判定対象外を除いたものである。
   変更ファイルは`git show --name-only --format= <commit>`で確かめ、終了コードが0でなければ原因を解消して判定し直す。
2. 影響を受けない計画は再レビューを省き、計画名、`R`と`H`の完全なOID、実行したコマンド、対応行の要点、省いた理由を引き継ぎ記録へ残す。
   rebaseでcommitのOIDだけが変わった場合も再レビューは要らない。
3. 影響を受ける計画でも、差分が`agent-basics:review-standards/references/reviewee.md`「方式見直しと再レビュー」の再レビューを省ける修正に当たれば省き、理由を同じ引き継ぎ記録へ残す。
