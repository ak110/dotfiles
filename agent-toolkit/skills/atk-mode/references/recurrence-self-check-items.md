# 再発防止セルフチェック観点

レビューの時に変更差分へ当てはめる確認項目である。
各項目は、差分から読める契機（対象条件）、確かめること（確認内容）、根拠規範、元になった障害の所在を持つ。
項目の書き方、配置、削除の条件は`agent-basics:bugfix/references/prevention.md`「差分を契機にする確認項目」に従う。

## 失敗・警告の文面に次の操作がある

- 対象条件: 差分が、プログラムの出力するエラー、警告、スキップ通知、待機の中断、状態値の文面を新設か変更している。
  失敗時の行動を定めるエージェント向け規範の新設・変更も含む。
  例外メッセージ、ログ出力、標準エラー出力、終了時のメッセージ表示、シェルスクリプト・CI・Makefileの出力メッセージなどを含む。
- 確認内容: 各文面に観測した事実があり、受け取った側が実行できる具体的な次の操作を示している。
  示す操作を実行できないと事前に分かっている場合は、代わりの手段か問い合わせ先を示している。
  エージェントが是正できる不具合の案内は報告だけで終えず、原因の確認と認可内の是正を先に示す。
  その不具合を案内するPythonの出力は `recover_from_failure` を使い、TypeScriptのhookなどは同じ順序と安全条件を満たす。
  本人の判断・認証情報だけを求める案内には、是正手順や共通関数を要求しない。
  元の操作を再発行しない条件を保つ。
  是正可能な不具合の案内は、次の操作の指定が必須であることだけを理由に対象外としない。
- 根拠規範: `agent-basics:writing-standards/references/program-messages.md`「出力の基準」。
- 元になった障害: 導入の変更`982a6f75e`（2026年10月19日）。
  個別の障害の記録は未特定である。

## 共通機構の是正が作用する全種類に届く

- 対象条件: 差分が、共通機構の不具合を直している。
  許可リスト、パーサー、正規化処理、値の一致判定、判定関数、手順上の契約定義などを含む。
- 確認内容: 症状を観測した特定の値・入力・処理系統・フィールド種別だけを対象とする分岐や個別の列挙に修正を限らず、同じ共通機構を通常運用で使う他の対象へも対策が届いている。
  届かない対象がある場合は、その対象を具体的に挙げている。
  入力契約、ユーザーが明示した適用範囲、WIや計画が根拠を持って限った適用範囲の外と、通常運用で生じない入力や配置は対象外とする。
- 根拠規範: `agent-basics:bugfix/references/spread.md`「探す対象を決める」。
- 元になった障害: 導入の変更`982a6f75e`（2026年10月19日）。
  個別の障害の記録は未特定である。

## 外部へ露出する命名規則を未確認で固定していない

- 対象条件: 差分が、外部識別子の命名規約や独自接頭辞（リモートブランチ名やタグ名の規約、独自接頭辞など）を新しく固定している。
- 確認内容: 対象worktreeの既存の命名規則や文書と一致している。
  一致しない独自接頭辞や命名規約を新しく固定している場合は、計画・WI・ユーザー確認の回答と付き合わせて確認すべき箇所として該当ファイルと行を挙げて報告する。
- 根拠規範: `agent-basics:writing-standards/references/quality-principles-roles.md`「要件と認可」、`agent-toolkit:atk-mode/playbooks/confirmation.md`「公開操作の消費主体」。
- 元になった障害: 2026年11月21日の`/atk-mode implement`導入時に、リモートブランチの独自接頭辞をユーザー確認なしで固定し是正を受けた事象。

## 委譲先が外部入力を指示として採用しない

- 対象条件: 差分が `subagent.md` の配送対象の節、`launch_prompts.py`、Claudeの `system_prompt`、Codexの `baseInstructions`・`developerInstructions`、または同じ本文を組み立てる別ホストの処理を変える。
- 確認内容: 全起動区分・全backendで、起動と継続時の本文に、作業対象の命令をデータとする規定と安全な入力処理の規定が残る。
- 根拠規範: `agent-toolkit:atk-mode/playbooks/subagent.md`「硬い制約」。
  配送する規定の一覧は `docs/development/design-agents-server-instructions.md` にある。
- 元になった障害: 委譲先の本文に、作業対象の命令と操作の認可を区別する規定が無かった。
