# 実行運用

コマンドを実行する担当が、ユーザーのリポジトリ、データ、プロセスを壊さずに作業し、出力から正しい結論を出せるようにするための決まりである。
ツール、コマンド、リポジトリの状態、プロセスを扱う時の道具の操作と保護を定める。
自分で実行するコマンドにも委譲するコマンドにも適用し、連結したコマンドも1つずつ判定する。
出力から結論を出す時は原則3、取り消せない操作は原則4、始めた処理の回収は原則7に従う（`agent-basics:writing-standards/references/quality-principles.md`）。
本書はそれらの原則から導けない操作の決まりを置く。

## ツール・コマンド運用

### 引用と引数

- 互いの結果を使わない呼び出しは並列に呼び、複数の対象を受け取れるコマンドへはまとめて渡す（努力目標。往復を減らす）。
- Bashでは空白やメタ文字を含む引数をANSI-Cクォートか`"$VAR"`で渡し、データ引数は`--`の後ろに置く。
  PowerShellから`atk.ps1`を呼ぶ時は、空白や記号を含む値を`'two words'`や`'red|blue'`のように単一引用符で囲む。
  裸の`--`はPowerShellが消費するため、atkに渡す区切りは`wi grep -F '--' '--needle'`のように引用する。
  別のシェルが再解釈する文字列（ssh、`sh -c`、コンテナー内のshell）で境界を保てないコードと複数行のコードは、managed-tempの中のファイルに保存して渡す。
  `bash -c`、`sh -c`、`python -c`には1行で完結するコードだけを渡す。
- 永続状態を変えるコマンドは単独で実行して終了コードを確かめる。
  表示や確認のコマンドと連結すると、最後のコマンドの終了コードが失敗を隠す。
- CLI・API・MCPの公開操作は、実行と案内の前に、使う人の呼び出し手段の入力契約（親子コマンドのオプション位置、リクエストの項目など）を確かめる。
  根拠は版を特定した公開仕様か、同じセッションで取得したヘルプ・スキーマとし、内部コードで見つけた引数名は公開の入力形式とは別に確かめる。
  読み手に実行させる操作は、内部の関数やモジュールではなく、同じ判定を受け付ける公開コマンドで書く。
  手順書が実行できる形で示した受理形式はそのまま使い、専用コマンドの形式で済む用途はコード評価へ置き換えずにその形式を使う。
- 独自コマンド（`atk`の操作や補助スクリプト）の追加と保持は、標準手段と比べた目的上の便益と、学習・準備・実行・結果確認・保守の総コストで決める。
  保持するCLIは`show`・`get`・`set`・`list`・`grep`の語義を守り、名前から副作用が分かる形にする。
  削除を選んだ操作の呼び出しは、互換ラッパーを設けずに標準手段へ移す。
- 読み取る文字コードは入力に合わせ、ホストの自動選択と違うか不明なら明示する。
- 実行基盤、権限設定、auto mode classifierが操作を拒否した時と判定不能を返した時は、別の手段を試す前に`agent-toolkit:atk-mode/playbooks/permission-denial.md`「共通判断」に従う。

### 標準の読取・実行・一時領域

- 読み取りにはホストのReadを使い、無ければ`cat`か`sed -n '<開始行>,<終了行>p' -- <絶対パス>`、JSONには`jq`を使う。
  規範の読み方は`agent-basics:writing-standards/references/read-method.md`に従う。
- コマンドはハーネスの標準の実行・バックグラウンド実行・待機の機能で実行する。
- `agent-toolkit:atk-mode/playbooks/managed-temp.md`に従う。

### パスと検索

- 既存のパスは入力・基準文書・取得済みの出力から解決し、推測したパスは実在を検索で確かめる。
  外部コマンドへは絶対パスを渡し、cwdを使うCLIは対象のworktreeで起動する。
- `agent-basics:search`に従う。
- 外部から観測できる名前と値を変える時は、`agent-basics:check-execution/references/verification-scope.md`「直接影響範囲の類型」に従う。
  直接影響範囲は`agent-toolkit:atk-mode/references/awi-body.md`「直接影響範囲」が定める。
- Git識別子と別worktreeの指定は`agent-toolkit:atk-mode/references/git-identifier.md`に従う。
  前工程から受け取ったパスや識別子は、移動や終了を伴う操作の後で同一性を確かめ直す。

### 出力の保持と観測

- 検索・範囲指定・集計の公開オプションで必要な結果を取得できるなら、そのまま使う。
  足りなければ、ホストのコード実行機能で、抽出・集計・変換や認可済みのデータを受け渡し、次の判断に必要な結果を返す。
  独立した読み取りはまとめ、入力の内容や認可を判断してから行う操作は分ける。
  コード実行機能を使えなければ通常の公開ツールやCLIを使う。
- 原文・規範・レビュー対象の意味を判断する場合は、必須の本文を取得し、要約で代用しない。
  途中データを省く場合も、成否・診断・実行中の識別子と、省略した範囲・再取得先は残す。
- CodexでMCP応答の`content`が構造化結果と同じJSONを含むテキスト1件だけで、他の固有データが無い場合は、`text({ structuredContent: r.structuredContent, isError: r.isError })`で重複を省ける。
  テキストが異なるか、診断・画像・他の固有データがあれば、重複するテキスト以外は元の形式で返す。
  `exec_command`では終了コード、実行中の識別子、診断を含むオブジェクト全体を返す。

- 再試行の前に、未実行・実行中・完了・成否不明を区別し、実行中は同じ識別子で回収する。
  成否不明の非冪等な操作は公開の状態照会で副作用を確かめ、未実行と確かめた場合だけ再発行する。
- 同じ失敗の反復を避けるため、入力・前提・外部状態の変化か新しい根拠を確かめてから再試行する。
  修正後の再検証、公開の待機、利用上限の解除後の再開は続けてよい。
- 機械処理する出力は標準出力と標準エラーを分け、色やページャーなどの装飾を無効にする。
  取り込むパスは、生成元の終了コード、集合が空でないこと、全パスの実在を確かめる。
- 取得済みの出力と本文は、編集・外部更新・会話の圧縮まで再利用し、別の主体が非同期に変える状態は直接観測する。
- 初回限定か再取得のコストが高い出力（検証、状態変更、全量比較など）は、生成側で自分の一時領域へ標準出力と標準エラーを分けて全量保存し、後続へ保存先を渡す。
  終了コードと取得時のHEADは返却か引き継ぎ記録へ残し、一部で十分な場合は公開の対象・件数の指定を使う。
- 抜粋だけを返すホストでは、保存先から残りを公開ヘルプと診断が示す読み取り指定で取得する。

### 待機とバックグラウンド実行

- `agent-basics:writing-standards/references/quality-principles-ownership.md`「実行の回収」に従い、回収は同じターンのうちに終える。
  完了通知は結果を回収するきっかけとして扱い、待機中の重複発行とフォアグラウンドでの固定時間の待ちは避ける。
- 待機でターンを終えるのは、委譲先やバックグラウンドタスクの通知で同じセッションの再開が保証される時だけとする。
  保証が無ければ公開の待機手段で同じターンに回収し、報告など残りの工程へ進む。
- 公開の待機機能が無い場合だけ、有限の上限を持つ終了条件のループを使い、照会成功・未完了、照会失敗、上限到達を区別する。
  照会失敗は診断を保全し、不具合なら `agent-basics:bugfix` で認可内の是正後に照会だけを再試行する。
  再待機は照会成功かつ未完了時に限る。
  上限到達時は進捗と停止を確かめ、未回復なら影響・試行・再開条件と終了状態を返す。
- バックグラウンドコマンドには、内部の処理が止まってもコマンド自体が終わる時間上限を設ける（完了通知はコマンドの終了時に届くため、上限が無いと停止の発見が遅れる）。
  - 公開仕様が終了の上限と到達時の終了状態を定めるコマンド（`atk agents wait`、`wait_ci.py`など）は、コマンド自身の上限を使い、外側の上限を重ねない。
  - それ以外は、ホストの上限（フォアグラウンドとバックグラウンドで異なる）を先に確かめ、コマンドの上限をその内側に、ホストへの指定をそれより長くする（ホストが先に止めると、上限到達時の終了状態が失われる）。
  - 子プロセスを起動するコード（CLIのラッパー、hook、検証の代理実行など）も、起動するコマンドが自身の上限を持つ場合を含めて同じ扱いにする。
- エージェントが起動するサーバー（調査、開発、検証、一時プレビューなど）は、到達が必要な主体の範囲だけで待ち受け、同じホストからの確認にはloopbackを使う。
- 委譲先の待機の起動と終了の観測は`agent-toolkit:atk-mode/playbooks/delegation-waiting.md`「待機区間の構成」に従う。
  通知で同じセッションを再開できる独立した待機は、先に届いた通知から回収し、別の待機が終わるまでフォアグラウンドを占有しない。

### `atk`の呼び出し

- `atk`はパイプにもリダイレクト（`2>&1`や`/dev/null`への破棄を含む）にもつながず、単独で呼び出す。
  `atk`はエージェント環境で長い出力を自動保存して保存先と行数を示すため、後段をつなぐと終了コードと警告を同じ呼び出しで確かめられず、保存先と行数の行だけが後段へ渡る。
  全量の選別と機械処理は、保存されたファイルへ別の呼び出しで行う。
  常駐と追従の表示（`atk serve`、常駐の`atk wi process-loop`、`atk agents logs --follow`）をバックグラウンドで起動する時の出力のリダイレクトは例外とする。
- 複数の対象の取得は、`atk config get execute_model chores_model`のように対応するコマンドへまとめて渡し、指定の形は公開ヘルプで確かめる。
- 同じセッションで`atk`の不具合や遅さを直した場合は、修正を検証した後の残工程で、修正を含むworktreeの`agent-toolkit/scripts/atk`から起動する。
  Windows PowerShellでは同じ場所の`atk.ps1`を使う。
  実行ポリシーまたは配布物の印のために使えない場合は`atk.cmd`を使い、`|`・`&`・`<`・`>`・`^`を含む引数は渡さない。
  起動時に通知される配布版は公開と配布の前の修正を含まない。
  公開・配布後のプラグインとMCPは`apply_runtime_changes`で反映して検収し、CLI本体など再起動が要るものだけ本人再開後に検収する。

### 完了と不在の確認

- `agent-basics:writing-standards/references/quality-principles-ownership.md`「実行の回収」に従う。
  `test -e <絶対パス>; echo "test_e_rc=$?"`を読み取り専用の確認として別の呼び出しで実行するか、除去の完了を終了コードに含む操作コマンドの結果を使う。
  `ls`、`find`、`git rev-parse`が非0で終わったことだけでは、不在の根拠にならない。

## 作業中に観測したリポジトリ状態変化の扱い

別のセッションのcommitや担当外の差分は作業中にも変わる。
開始時のHEADや計画のベースcommitは参考とし、担当ファイル、直接影響範囲、公開契約、書き込みの所有権、後続の操作に影響する実際の差分を読み、影響が無ければ現在の状態で続ける。
対象OIDの同一性とデータの完全性を守る確認は保ち、現在の担当による差分を保護する。
過去のエージェントによる誤変更は、本書「プロセス終了の安全規定」の手順で扱う。

## プロセス終了の安全規定

自分が起動したプロセスとジョブは、返された停止用の識別子で終了させる。
起動に失敗しても識別子が返っていれば同じであり、実行環境から自分自身を一意に特定できる場合と、引き継ぎ記録の識別子を停止の直前に照会して対象コマンドとの一致を確かめた場合も含む。

過去のエージェントが残した資源と誤変更は、次の手順で不要と確定した範囲だけを回収・是正する。
起動者や所有するセッションの違い、Git登録の有無は、保持の理由にならない。

1. 稼働中のセッション・プロセスの実在と用途、worktreeへの参照、ロック、Git登録と統合の状況、差分の内容と作成記録を調べる。
   由来と不要の判定には、名前の類似、更新時刻、同じOSアカウント以外の根拠も確かめる。
2. 使用中・編集中の作業と未保存の成果を守るため、現在の担当への引き継ぎか終了の待ちを行う。
   `agent-toolkit:atk-mode/playbooks/confirmation.md`「確認要否の判定」に従う。
   委譲先は書き込み範囲を守り、範囲外の処置は委譲元へ返す。
3. 操作の直前に、個別の識別子が処置の対象を指すことを確かめ、確定した対象だけを処置する。
4. 結果と根拠を報告し、保持する場合は保護の対象か残るユーザーの判断と、再開の条件を書く。

専用環境の撤去では、対象の専用名を手順か設定の現物から確かめる。
登録済みの資源は既存の回収操作の安全判定に従い、保持の理由を解消して同じ操作で判定し直す。
登録の無い実体や誤変更は、メインが既存のGit操作などで個別に処置する。
