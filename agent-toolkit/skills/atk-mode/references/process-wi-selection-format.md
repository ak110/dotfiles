# 選定結果の形式

作業`process-wi`の選定結果（選定YAML）の欄、省略時の値、欄の意味を定める唯一の定義である。
選定YAMLは対象リポジトリごとに生成して保存し、all-reposの統括でも、候補とレーンはリポジトリごとの別のYAMLに置く。
メインは選定と追加の入力を書く時に、レーン担当と公開担当は保存済みの選定結果を読む時に使う。
選定の手順は`agent-toolkit:atk-mode/playbooks/process-wi-selection.md`に、所要時間の見込みと補正の算定は`agent-toolkit:atk-mode/references/process-wi-selection-estimates.md`にある。
形の検査は`pick-wi-check`が行い、違反には直し方を`次の操作:`で示すため、本書は検査が判定できない意味と、書く時に決める値を扱う。

## 選定結果の書式

生成付き保存操作の出力は次の形式となり、既存の完成済み選定YAMLを受け取る場合も同じ形式に従う。
保存前には生成入力の意味判断として、`選定`の各項目の上流投入関連の3行について省略時の値を解決し、次の組み合わせに合うことを確かめる。

| `上流投入`の解決値 | `レーン` | 担当 |
| --- | --- | --- |
| `なし`（行の省略を含む） | 通常の`lane-NN` | ファイル変更の有無を問わず、レーン担当が採否・実施・終了を担う |
| `上流要求だけ` | `なし` | メインエージェントが既存の上流投入工程を実施する |
| `混在` | 通常の`lane-NN` | メインエージェントが上流投入した後、対象リポジトリ側の作業をレーン担当へ引き渡す |

frontmatterに`merge_branch`を持つマージ用AWIは例外として`レーン`を`なし`とし、メインが`agent-toolkit:atk-mode/playbooks/implement.md`「マージ用AWIの処理」で直接取り込む。

この条件は作業を伴う回答済みUWIにも適用し、ファイルの変更を伴わない項目も待機状態にせず通常レーンへ記録する。
追加分の実施担当と資源は`agent-toolkit:atk-mode/playbooks/process-wi-additions.md`「処理対象WIの追加」手順5で比べる。
選定上の所属レーンと実施担当は別の事柄であり、専用worktreeを要しない作業でも採否・実施・終了の責任を引き継ぐ。
外部操作の承認は、レーンへの割り当てとは別に得る。
`上流投入`が`なし`以外の場合、`上流投入先`には1件以上の空でない文字列のリストを、`上流要求`には空でない文字列を指定し、`なし`の場合は3行とも省略する。

```yaml
選定:
- WI: '<AWIまたは作業を求める回答が保存されたUWIのファイル名>'
  レーン: '<`lane-NN`形式のレーン識別子(`NN`は2桁のレーン番号)または「なし」>'
  鮮度: <`atk wi list --with-staleness`が返した`staleness`のYAMLフロー写像>
  書込対象: ['<書込対象のリポジトリ相対パス>']
  導出した新設先:  # 省略時の値: 「[]」
  - パス: '<限定調査で導いた完全な新設ファイルの相対パス>'
    反映範囲: '<対応する実在ディレクトリ範囲、末尾/付き>'
    要求: '<同じWIの新設を求める要求>'
    配置根拠: '<読んだ既存の定義・接続先と配置理由>'
  公開工程の書込対象: ['<公開単位の統合後、公開担当だけが書くリポジトリ相対パス>']  # 省略時の値: 「[]」
  公開工程の規範根拠:  # 省略時の値: 「[]」
  - パス: '<公開工程の書込対象のパス>'
    規範ファイル: '<公開工程へ割り当てる規範のリポジトリ相対パス>'
    節: '<規範ファイルの見出し文字列>'
  担当モデル: {実装担当: '<engine:model/effort>', 実行レビュー担当: '<engine:model/effort>'}
  書き込まない反映先: ['<反映先としてWI本文に現れるが書き込まないリポジトリ相対パス>']  # 省略時の値: 「[]」
  再開位置: '<`~/.claude/plans`内の計画ファイルの絶対パスと残る工程。観測のみの書式は「反映後の観測だけが残る（再開記録: AWI本文の最後の`## 反映後の観測の再開記録`、計画: <`private-notes/plans/`からの相対パス|計画なし>）」>'  # 省略時の値: 「なし」
  プロジェクト固有の公開後の操作の順序: '<プロジェクト固有の公開後の操作とその順序>'  # 省略時の値: 「既定」
  プロジェクト規範の指定: '<プロジェクト規範が指定した内容>'  # 省略時の値: 「なし」
  上流投入: '<上流要求だけまたは混在>'  # 省略時の値: 「なし」
  上流投入先: ['<投入先>']  # 省略時の値: 「なし」
  上流要求: '<上流要求と対象側の後続作業>'  # 省略時の値: 「なし」
  統合状態: '<未統合|統合済み>'  # 省略時の値: 「未統合」
  移管元レーン: ['<`--transfer-wi`で離れたレーン識別子>']  # 省略時の値: 「[]」
単一段階案の完了見込み秒数: <bool以外の0以上の数値>  # 段階2以上がない場合は省略可、省略時の値: 「なし」
段階案の完了見込み秒数: <bool以外の0以上の数値、または「成立する段階案なし」>  # 必須条件以外は省略可、省略時の値: 「なし」
目標超過時の配分比較: '<比べた配分の代替案と見込み、採った案>'  # 目標所要秒数を超えない場合は省略可、省略時の値: 「なし」
全工程の見込み:  # 目標を持つ実行配分で省略すると警告になる（拒否はしない）。旧保存形式の履歴では省略時「未確認」
  並列数:
    モデル同時数: <正の整数>
    検証同時数: <共有実行枠の定義から決めた正の整数>
    資源上限: <測定した資源から成立すると確認した正の整数>
    サービス上限: <API・CLIで利用可能な正の整数>
    根拠: {資源: '<実測の参照>', サービス: '<制限の参照>', 費用: '<同品質の候補間の総費用比較の参照>', 検証: '<対象のpyfltrの版とPYFLTR_EXECUTION_SLOTSの確認結果>'}
  工程:
  - ID: '<群と工程を区別するID>'
    工程: '<選定|準備|実装|レビュー|検証|統合|公開|後始末|報告>'
    WI: ['<この仕事が扱うWI。全体固定工程は[]>']
    先行工程: ['<先行成果を使う工程のID>']
    資源: '<モデル|検証|直列>'
    秒数: <0以上の有限数、未確認はnull>
    算定: '<実測|残量/速度|条件付き試算|未確認>'
    根拠: '<観測または残量と速度の出所>'
    未確認前提: []
    # 算定が残量/速度の場合だけ、残量と正の速度を追加する
  巨大WI:  # 省略時[]。指定しないWIは通常対象に残る
  - WI: '<意味判断の所有者が巨大と判定した具体的WI>'
    巨大判定根拠: '<合理的な資源・費用上限と最短案の比較の参照>'
    承認元: {対象WI: '<同じWI>', 判断: '<承認|拒否|未回答>', 出所: '<今回の名指しの承認原文の所在>'}
見込みの補正:
  実装係数: <bool以外の0より大きい有限数>
  統合係数: <bool以外の0より大きい有限数>
  共有待ち秒数: <bool以外の0以上の有限数>
  共有待ちの算定: '<実測|推定>'
  参照した記録: ['<進捗ログか引き継ぎ記録の所在>']
  除外した記録:
  - 記録: '<除外した記録の所在>'
    理由: '<除外理由>'
初回配分:
  候補WI: ['<開始時候補から通常の除外条件に当たるものを除いた全WI名。包含項目を含む>']
  レーン割当: {'<初回に選定したWI名>': '<初回レーンまたはなし>'}
  不可分成分:
  - WI: ['<成分の構成WI名>']
    結合条件: []  # 複数WIの成分では後掲の型付きの辺を列挙する
追加WI: ['<初回確定後に追加したWI名>']  # 省略時の値: 「[]」
レーンの所要時間:
- レーン: '<`lane-NN`形式のレーン識別子>'
  統合状態: '<未統合|統合済み>'  # 省略時の値: 「未統合」
  段階: <1以上の整数>  # 省略時の値: 「1」
  先行レーン: ['<このレーンのworktree作成前に統合を終える前段のレーン識別子>']  # 省略時の値: 「[]」
  実装秒数: <0以上の数値>
  統合秒数: <0以上の数値>
  補正前の実装秒数: <bool以外の0以上の数値>
  補正前の統合秒数: <bool以外の0以上の数値>
  根拠: '<同一レーン案と分割案の比較根拠を示す空でない文字列>'
レーン間の重なり:  # 省略時の値: 「[]」
- レーン1: '<レーン識別子>'
  レーン2: '<別のレーン識別子>'
  共通パス: '<共通ファイルまたは狭い方の範囲>'
  レーン1の定義: ['<変更する節または定義>']
  レーン2の定義: ['<変更する節または定義>']
  判定: '<交わる|交わらない>'
続行できない理由:
- '<確認事項>'  # 完了時の値: 「なし」
```

文字列の値は単一引用符（`'`）で囲み、値の中の`'`は`''`と重ねる。
`[1m]`、`[`、`,`、コロンと空白の連続を含む文字列は、囲まないとYAMLの構文として誤認されるためである。
`鮮度`のマップと数値は引用符で囲まずに書く。

候補が0件の場合は、`選定`と`レーンの所要時間`を`[]`とし、`初回配分`も`候補WI: []`、`レーン割当: {}`、`不可分成分: []`とする。
行末のコメントに省略時の値を書いた行は、その値と一致する場合に省略でき、行が無い場合はその値として読む。
`選定`の各項目で必須の行は`WI`、`レーン`、`鮮度`、`書込対象`である。
`担当モデル`には、WI本文が担当とモデルを明示した組み合わせだけを推論の深さを含む`engine:model/effort`の形で記録し、指定のない担当のキーは省略する。
`鮮度`には、一覧JSONの`staleness`マップを値も型も変えずに転記する。

## 欄の意味

`書込対象`は、レーン担当が変更するファイルのリポジトリ相対パスのリストである。
WI本文、作業を伴うUWIの回答、参照された手順書と限定調査から、変更予定と判断した個別対象を全て挙げる。
書き込み先のファイルを特定できない項目は、限定調査で見積もったディレクトリ範囲を末尾に`/`を付けて挙げる。
配下の個別パスとあわせて書かれた範囲の説明（「対象は`agent-toolkit/`配下とする」など）は挙げず、配下の個別パスだけを書く。
`レーン`が`なし`の項目も行を残して`[]`とする。

`書込対象`は初期配分と段階の見積もりに使い、開始後の編集認可はWIの要求を境界とする。
要求内の追加編集は`agent-toolkit:atk-mode/playbooks/implementation.md`「実装」に従い、選定YAMLへの反映を省いて進める。
初期配分の見積もりを直す場合は、次の操作で追加・全体チェック・保存を1回で行う。

```text
atk run-script pick-wi-check -- <選定YAML> --extend-write-targets <追加YAML> --output <保存先> --work-dir <対象リポジトリの絶対パス>
```

追加用YAMLの最上位は`選定`と`レーン間の重なり`とし、選定の各行には`WI`、追加する`書込対象`、必要な`導出した新設先`を書く。
`プロジェクト規範の指定`を書いた行は保存値をその値で置き換え、書かない行は保存値を保つ。
エージェント向け文書の追加でプロジェクト規範の指定の条件に当たるパスが増える場合は、増えた記載を含む全文を渡す。
追加した`書込対象`と同じパスか、その配下の`書き込まない反映先`の要素は、同じ保存で`書き込まない反映先`から除かれる。
既存のリストの順序を保って重複なく追記するため、記録の追記だけの用途にも使える。
同一段階の未統合レーンと重なる追加は、`レーン間の重なり`へ定義と判定を渡す。
この操作は`初回配分`を含む既存の項目を保ち、全体チェックに成功した時だけ保存し、失敗時は選定YAMLを元のまま残す。
`--body-wi`、新しいWIの合流、他の更新操作は別の呼び出しで行う。

`公開工程の書込対象`は、対象リポジトリの規範がレーンでは編集せず公開単位の統合後の公開工程だけで変更すると明記したファイルである。
レーン間の重複・包含・連結成分の判定からは除かれる。
`公開工程の規範根拠`には、各パスに対応する記録を1件ずつ書き、規範ファイルには実在する通常ファイルを、節にはそのMarkdown見出しと完全に一致する文字列を指定する。

両書込区分の要素の形（実在ファイル、末尾`/`付きの実在ディレクトリ、本文で明示された新設先、`導出した新設先`の個別パス）は`pick-wi-check`が検査する。
この検査は作業ツリーのファイルを参照するため未統合の項目にだけ適用され、作業着手前に成立していた選定時の前提を確かめる。
統合済みの項目（項目や所属レーンが統合済み、または同じ呼び出しで統合済みにする項目）は、ファイルの改名・削除・追加後も過去の履歴として扱う。

`導出した新設先`は、本文に無い新設ファイルを限定調査で導いた時の判断履歴であり、ファイルを作成した後も保つ。
本文の範囲外の関連する試験や補助ファイルも、要求との対応と配置根拠があれば個別の新設先として記録できる。
メインは要求との意味上の対応を、元のWI本文と限定調査の現物から検収する。
新設先を具体化した後も、他の予定書込先が欠けていないことを元本文と限定調査から検収する。

`書き込まない反映先`は、AWIの`## 反映内容と反映先`や作業を伴うUWIの質問・判断材料・回答に現れるが、`process-wi`では変更しない参照先・除外先である。
公開工程で書く対象は`公開工程の書込対象`に置く。
含める前に該当する表の行、箇条書き、段落（UWIでは回答）を読み、変更の要求か、参照や除外の説明かを本文の意味から区別する。
本文が変更しないと明記した上位ディレクトリ（「他の`docs/`配下は変更しない」の`docs/`など）を記録する場合は範囲としてここへ置き、その配下で実際に変更するファイルは`書込対象`に個別に挙げる。
この範囲は、書込区分へ個別に挙げたパスを除いた残りの領域を表す。
参照先・除外先の記載は任意で、本文から抽出した非書込パスを全て分類する必要はない。
`プロジェクト規範の指定`は両書込区分から判定し、機械抽出できないUWIの書込予定はメインが限定調査と回答から検収する。

`単一段階案の完了見込み秒数`と`段階案の完了見込み秒数`は旧方式の局所比較の履歴で、全工程の成立判定とは別に扱う。
旧方式の値は、段階ごとの最長実装と直列統合の和へ、全体の共有待ちを1回加えたものである。
段階2以上を採用する選定は`単一段階案の完了見込み秒数`を書き、全行が段階1でいずれかの`実装秒数`が6000秒を超える選定は`段階案の完了見込み秒数`を書く。
後者の値は、比べた段階案の補正後の完了見込み秒数か、レーン数上限の範囲で成立する段階案が無いことを示す`成立する段階案なし`である。
新しい算定は`全工程の見込み`を入力とし、要約では`全工程の壁時計見込み秒数`と`通常対象の完了見込み秒数`を別に出す。

`見込みの補正`と各レーンの補正前の秒数は、`agent-toolkit:atk-mode/references/process-wi-selection-estimates.md`「見込みの補正の算出」で求める。
`共有待ちの算定`は、参照した記録から測った値を`実測`、測っていない値を`推定`とする。

`--work-dir`の`pyproject.toml`の`[tool.agent-toolkit.pick-wi-check]`に`target-seconds`（bool以外の正の有限数）がある場合、その値が1回の処理の目標所要秒数となる。
実行用の選定に`全工程の見込み`が無い、未確認前提が残る、通常対象が目標を超える場合は、終了コード0のまま標準エラー出力へ警告が出る。
これらは経過時間や観測待ちに由来し、検査を渡した担当がその場で解消できないため、選定と追加のmergeは続行する。
警告を受けたら、全対象と品質工程・レーン上限を保ったまま組み直しを検討する。
`目標超過時の配分比較`は比べた代替案の記録であり、超過の判定とは独立している。

追加のmergeでは、比較欄（`単一段階案の完了見込み秒数`、`段階案の完了見込み秒数`、`目標超過時の配分比較`）と`共有待ちの算定`を、追加用YAMLで合流後の全体について確定し直した値だけで採用する。
追加用YAMLにも同じ工程係数を書き、合流処理は補正前の各値を加算した後に工程係数を掛け、共有待ちは追加側の値を1回採用する。
目標を持つ新しい配分は、これらの省略にかかわらず全工程を検収する。

`レーンの所要時間`は`なし`以外のレーンを1件ずつ含め、実装時間と直列統合時間を分けて1回だけ計上する。
後段レーンの`先行レーン`には、開始前に統合を終えておく全てのレーンを挙げる。
`統合状態`は、全ての計画の保存とWIの終了処理が終わった後に`atk lane integrate`が記録し、メインはその結果とレーン担当の終了状態を検収する。
今回処置した項目だけを`統合済み`にし、全項目が統合済みになった時にだけレーンの行も`統合済み`にする。
資源操作の入力と再開の手順は`agent-toolkit:atk-mode/playbooks/process-wi-lanes.md`「統合とAWI終了」にある。
統合済みの相手の詳細記録は省略でき、その相手だけと重なるレーンは同じ段階のまま先行指定なしで開始できる。
追加WIが既存レーンへ合流した場合は、合流先のレーン行を未統合に戻し、既存項目は統合済みのまま追加項目を未統合とする。
追加時の仮名は最終レーン名へ変換され、追加の無いレーンと所属WIは保たれる。
`--transfer-wi`で別レーンへ移した項目は、離れたレーンを`移管元レーン`へ記録する。
移管で空になったレーンは行が除かれるが、`移管元レーン`の値として累計のレーン上限に数える。

## 選定の生成入力

生成付き保存操作（`agent-toolkit:atk-mode/playbooks/process-wi-selection.md`）に渡す意味判断YAMLには、`選定`、`レーンの所要時間`と、必要な比較値、重なり、続行できない理由を書く。
各項目の`WI`、`レーン`、`書込対象`、分類、担当モデル、配置根拠、見込み時間、プロジェクト規範の指定はメインが確定する。
`鮮度`と最上位の`初回配分`は生成ツールが組み立てるため、入力から除く。
指定のない担当モデルは未指定のまま保ち、生成ツールも推測で補わない。
対象が0件の場合も`選定: []`と`レーンの所要時間: []`を明示する。

候補入力には`atk wi list --jsonl --with-staleness`の出力本文を使い、各行の`filename`と`staleness`をそのまま読む（JSON配列も受理される）。
通常の除外条件に当たる候補と、`agent-toolkit:atk-mode/playbooks/process-wi-selection-allocation.md`「調査とレーン分け」で今回の選定量に含めなかった未着手候補は`除外候補: ['<WI名>']`に挙げる。
後者は状態・本文・依存を変えず、取得した元候補と量の判断根拠を保つ。
候補集合は現在の選定件数から推測せず、必ず元の取得結果を使う。

初回生成の最上位の`結合条件`には、型付きの辺を平らなリストで書く。
各辺は`WI1`、`WI2`、`種別`、`根拠`を持ち、入力の`根拠`には次の意味判断だけを書く。

- `依存`: `依存元`だけを書く。
  正規化したリポジトリ識別子と`depends_on`は、WIのfrontmatterから生成される。
- `再開計画`: 空のマップ`{}`を書く。
  両端の計画の識別情報は、確定済みの再開位置から生成される。
- `書込重複`: `定義1`と`定義2`のリストと、`段階比較`の理由を書く。
  保存される根拠はこの3項目だけで、両端のパスと段階は`pick-wi-check`の実行ごとに現在の`書込対象`と`段階`から読まれる。

生成ツールは確定した辺から不可分成分、候補集合、初回割当を組み立て、書込予定の妥当性、上限、競合、規範の指定の検証に成功した時だけ、完成済み選定YAMLを不可分に保存する。
検証に失敗した場合は保存先を元のまま残す。
WIを明示的に追加する場合は`--merge <追加の意味判断YAML> --candidate-file <追加候補JSONL>`を使い、初回配分と初回の結合条件は含めない。
元の初回履歴を保ったまま全体の関係を検証し、合流先レーンだけを未統合に戻して1回で保存する。
レーン担当へは、生成入力のYAMLではなく、検証に成功して保存された完成済み選定YAMLの絶対パスだけを渡す。

## 共通の読取りと重なり

選定結果を読む全ての主体は、本書の欄名、省略時の値、省略規則に従う。
英字の旧欄名（`decisions`、`awi`、`lane`、`write_files`など）で書かれた既存の選定結果は、対応する日本語の欄名と同じ意味で読む。

`根拠`には、選定量・選択件数・残数・下限の適用・参照した実測、配分案の比較結果と不可分条件を書く。
公開工程の規範根拠、段階案の比較値、見込みの補正値は、それぞれの専用の欄に置く。

`レーン間の重なり`は、同一段階の未統合レーンどうしが共有する共通ファイルか狭い方の範囲ごとに1件記録し、自由文でパスを再掲していても省略できない。
記録には共有する箇所だけを書き、同一レーン内の書込対象の全集合や無関係なレーンのパスは除く。
定義は空でない文字列リストとし、双方が独立していることを本文と現物から検収した組だけを`判定: 交わらない`とする。
交わる定義や独立性が未確定の組は、同一レーンか別段階へ置く。
別段階の先行関係は書込予定の重複から導く。
旧形式の詳細記録も読み取れる。
追加選定では、新旧の組と追加どうしの組のうち必要なものだけを追加側へ記録し、既存の記録を保つ。
既存レーンへ合流する追加WIと他の既存レーンのWIの組も新旧の組であり、既存の記録はこの組を判定していないため追加側へ記録する。
追加レーンには既存と重ならない仮名を使い、`agent-toolkit:atk-mode/playbooks/process-wi-additions.md`「処理対象WIの追加」の統合操作で最終名へ対応付ける。
