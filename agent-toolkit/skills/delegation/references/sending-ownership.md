# 委譲プロンプトの送信：権限と成果物の取り決め

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## 権限と成果物の取り決め

- 成果物ファイルを新規作成または更新する委譲では、書き込みを担当する主体を明確に取り決める。
  委譲先が書き込みを担当する場合は、委譲元は完了報告を受領するまでそのファイルを読み取り専用として扱い、委譲元自身が書き込みを担当する場合は、委譲先に対して読み取り専用として扱うよう明示的に指示する。
- 成果物は指定された絶対パスへ直接出力させ、完了報告において、ファイルの絶対パス、実在確認およびファイル規模を示すコマンド（`ls -l`や`wc -c`など）の実行結果、集計値、および内容の要約を報告させる。
- 件数や行数などの集計値については、実行した集計コマンドとその出力結果を典拠として併記させ、典拠のない主観的な数値（目視による数え上げや推測値）は後続の判断や成果物に取り入れない。
- 境界線が機械的に一意に定まらない定性的な多値分類を委譲する場合は、各区分を識別するための具体的な判断事例（校正例）を判断材料として提示する。
  分類結果から合計や内訳を算出する場合は、保存した明細データを機械的に集計して数値の一致を確認する（努力目標）。
- 委譲された範囲を超える不可逆な操作に関する差し戻しルールは、`agent-toolkit/share/rules/rules-subagent.md`「委譲時の厳守事項」が定める。
  AWIの投入は、委譲元が明示的に指示した範囲に限定して実行させる。
- 対応方針の提案や実装上の制約事項を調査して返却させる場合は、対象リポジトリの方針文書および対象機能の外部仕様文書の該当セクション（絶対パス）を読み込ませ、整合性の評価結果と衝突箇所の有無を報告させる。
- 点検や調査の作業では、各指摘の裏付けに用いた具体的な手段を報告させる。
  裏付けを取得できなかった場合、レビュー指摘管理表と`track`を用いた対話フローでは`agent-basics:review-standards`のSKILL.mdに従う。
  それ以外の一般的な調査では証拠が不足している範囲、得られなかった根拠、および追加で必要な検証内容を報告させ、安易に完了としないよう指示する。
- 既存の成果物の削除、撤去、または記述の簡潔化を提案する点検作業では、候補ごとに、撤去対象が検出している契約違反の内容、代替となるテストや成果物が同一の違反を検出できる具体的なテスト入力と期待値、および双方の本文を直接確認した結果を報告させる。
  判断材料を取得する過程で出力の切り詰めや省略が確認された候補は証拠不足として扱わせ、十分な証拠が確認できた候補のみを撤去の判断対象とする。
- 複数の委譲先におけるツール、権限、モデル、またはホスト環境の能力を比較・分類する場合は、すべての対象に対して同一の機械的な照会コマンドを同一条件下で実行する。
  条件を揃えられない比較結果は未検証として扱わせ、委譲先による主観的な自己申告を能力判定の根拠として用いることは避ける（単一対象に対する通常のステータス確認や定期的な情報収集はこの対象外とする）。
