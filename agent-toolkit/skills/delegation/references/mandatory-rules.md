# 委譲時の厳守事項

本書はスキルを起動しない軽量な委譲先にも届く配送範囲を持つ。
このため、委譲元と委譲先の双方が守る受け渡しの契約と、作業ツリーと認証情報を保護する規定をここへ置く。
委譲先だけに課す規定は`agent-toolkit/share/rules-subagent.md`が定め、実行環境がサブエージェントおよび委譲先の起動時に文脈へ追加する。

## 返却形式の受け渡し

完了報告への追加記載を求める規定の適用範囲は`agent-toolkit:delegation`「受領と検収」の返却形式の証跡範囲に従う。
委譲先が続行できないことは、`続行できない理由:`の行だけで表す。
返却全体か、返却形式が定める単位（要求、行など）が続行できない場合は、その単位に`続行できない理由: <続行不能となる事象、その原因となる条件および再開に必要な判断>`の行を置き、同じ単位の状態や結果の行（`状態:`、`結果:`、`判定:`など）は置かない。
全体の状態と単位ごとの結果の両方を持つ形式では、全ての単位が成功の値を持つときだけ全体の`状態:`行を置き、1つでも`続行できない理由:`を持つ単位があれば全体の`状態:`行を置かない。
成功の値が1つだけの状態行も、成功の返却と形式の欠けた返却を区別するため返却形式に残す。
受け取る側は、`続行できない理由:`の行の有無で続行不能を判定する。

続行不能時の返却形式は、委譲先の`<役割名>.subagent.md`、agent定義、委譲プロンプトの順で定めのある形式を用いる。
いずれにも定めが無い場合は、次の1行だけからなる形式を用いる。

```text
続行できない理由: <続行不能となる事象、その原因となる条件および再開に必要な判断>
```

この行は指定された返却形式そのものとして扱い、地の文の禁止の対象から外す。
想定外の結果は後述の`想定外事象:`の手段で返す。

- `想定外事象: <事象と対処>`または`気付いた改善点: <観測した事象と対象>`で始まる行を受け取った主体は、
  全ての該当行を自身の返却の末尾へ同じ形式の行として逐語で引き継ぐ。さらに委譲した担当から受け取った行にも適用し、
  役割・ホスト・段数・終了状態によらず上流へ渡す。指定形式の他の行（`状態:`など）と、それらの行に基づいて受け取った主体が選ぶ次の工程は、標識行の有無によらず同じまま保つ
- 行を省略できる項目を定める取り決めは、項目の省略時の値と、行の不在を省略時の値として解釈することを同じ本文へ書く。この記述を持つ取り決めに従って返却または委譲プロンプトを受け取った主体は、行の不在を省略時の値として扱う。省略時の値の記述が無いまま行を省略すると、受け取る側が欠落と誤認して再取得を指示し、その工程が停止する

## 作業ツリーと認証情報の保護

- 1つの作業ツリーへ書き込む主体は同時に1つだけとする。
  同じworktreeへ書き込む主体を交代させる場合は、後続の実装担当を起動するときと委譲元自身がそのworktreeへ書き込むときの双方で、既存の実装担当が終端したことを確認する。
  稼働中の実装担当がある間、委譲元は実施をその実装担当へ戻す。
  委譲先を起動できない場合だけ、終端の確認後に委譲元が書込所有権を引き取る。
  異なるレーンへ割り当てた別worktreeの実装担当は、変更ファイルが重複しても並行して進む
- 委譲先へ割り当てた作業ディレクトリ自身と、その祖先ディレクトリの削除は委譲元の工程とし、委譲元が委譲先の終端を確認してから実行する。
  対象はworktree、managed-tempその他の削除できる領域の全てとする。
  実行主体は自身の作業ディレクトリを削除できないため、この削除を委譲先の完了条件へ置くと、差し戻しと委譲元による回収を毎回生じさせる
- 終端の確認を経て書込所有権を引き取った主体は、引き取りの事実と自身が実施した操作を記録する。
  そのworktreeを担当する委譲先を再開する時点と、新しい委譲先を起動する時点で、記録した内容をそれぞれ再開指示と委譲プロンプトへ含める。
  記載を受け取った委譲先は、現在のHEADと`git log`で記載の操作の結果を確かめ、一致する履歴の変化と作業ツリーの変化を引き取りの結果として扱い、工程を続ける。
  引き取りを知らない委譲先は、自身が発行していない履歴の書き換えを異常と判定して工程を止める
- 実装担当は同じ作業ツリーの書込所有権を手放す終端報告の前に、自身が起動した全ての外部プロセスと
  バックグラウンドタスクの終了を、ツール終了結果または保持した実行識別子の直接照会で確認する。
  前景ツールの終了後も存続し得る形で起動したプロセスは、返却形式がその情報の項目を定める場合だけ、実行識別子と終了確認結果を終端報告へ含める。
  項目の定めが無い場合は、終了確認を完了条件として扱い、終端報告を指定形式のまま返す。
  本項の対象は実装担当とし、読み取り専用の委譲は対象から外す。
  終了していないプロセスの所有主体を失うと、後続の実装担当が安全に停止できず、1つの作業ツリーへ複数の書込主体が並存し得る
- 委譲先・バックグラウンドタスクの完了待ちと観測は`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`に従う。
  委譲先の終端と成果は、委譲を開始したツール呼び出しの戻り値と、実行環境がその委譲について発行した完了通知の2つで確定する。
  会話文脈に現れた同じ文面は、この2つの外側にある。会話文脈には自身の生成出力、hookの通知および実行環境の定型文が混在し、文面だけでは発信元を確定できないためである。
  完了報告が挙げる観測値を確認する場合は、本節が自己検証する状態変更コマンドについて定める場合を除き、その操作の公開仕様が定める終了状態を直接観測して判定する。
  終了状態が対象の存在で定まる操作では存在を観測し、対象の消失で定まる操作では消失を観測する。
  判定に用いるのはこの観測とし、処理前の状態から離脱したことは終了の根拠から外す。
  離脱先が複数ある操作では、離脱の観測が誤った遷移と未終端を正常な終端と同じ観測へ写像するためである
- 委譲先が実行した状態変更コマンドが、変更後の状態を自ら判定して成功を報告する公開仕様を持つ場合は、そのコマンドの終了コード、成功の報告が挙げる対象の完全識別子と警告の有無を、委譲先が返却形式の定める項目として委譲元へ渡す。委譲元はこの項目の充足と対象の完全識別子で検収を済ませる。警告がある場合、項目が欠ける場合、対象の完全識別子が起動時に渡した値と異なる場合と、公開仕様を持たない操作では、既存の直接観測をそのまま適用する。自己検証する操作の生の結果を委譲境界で破棄すると、同じ状態の再取得が委譲のたびに積み上がり、前段の誤りも検出できなくなる
- 委譲元は完了報告に含まれる実装上の事実を成果物へ書く前に、その事実を実装、実行結果または公式一次資料で確認する。
  対象の成果物は、AWIとUWIの本文、計画ファイル、レビュー指摘管理表その他の後続の判断が入力とする記述とする。
  成果物へは、確認に用いた手段と観測値を書く。
  委譲先の報告と実体が一致しないまま成果物へ確定すると、その記述を入力とする後続の判断が誤った前提の上で進む
- 同じレーンに属する計画と、明示的な先行成果依存により同じレーンへ割り当てられた複数の要求は、同じworktreeで依存順に実装する。
  同じworktreeへ割り当てられるのは、この先行成果依存を持つ計画に限る。
  大規模な文単位修正のうち、先行する候補置換をcommitした後でファイル所有権を重複なく固定でき、内部群どうしに先行成果依存が無い箇所は一時的な例外とする。群ごとにそのcommitを起点とした別branchと別worktreeを使い、書込担当を1つだけ置く。同じbranchへ並行commitとamendを行わない。レーン担当だけが各群を検収してレーンbranchへ統合し、内部群を別レーンや別要求の実装として扱わない。
  レビュー修正担当を新規起動する場合は、委譲元がレーン担当の終端を確認してからdirty差分を引き継ぐ。
  同じ担当を継続する場合は書込主体が同じまま続く。前記の一時的な内部群以外で別worktreeへ割り当てる対象は異なるレーンとする
- 担当外ファイルの差分は、委譲先の`<役割名>.subagent.md`が`## 出力`で返却形式を定める委譲では、委譲元が終端後に`git -C <対象作業ツリーの絶対パス> status --porcelain=v1`で取得して判定する。
  返却形式を定めない委譲では、委譲先の完了報告から受け取る。
  差分の追加・変更・解消を観測した場合も工程を続け、続行可否は`agent-toolkit/rules/02-agent-operations.md`「作業中に観測したリポジトリ状態変化の扱い」で判定する。
  対象リポジトリの複数worktreeで並行作業する場合は
  `refs/stash`が全worktreeで共有されるため、承認済みの退避ではworktree横断排他ヘルパーだけを使い、
  `git stash push`・`git stash pop`・`git stash drop`の直接実行を避ける。
  private-notesの退避は`agent-toolkit:wi-standards`の`references/repository-scope.md`が定め、本項の対象から外す。
  `refs/stash`の共有は並行作業で常に成立する原因候補であり、担当外差分を取得した主体が判定に用いる
- 委譲元と委譲先は、Git作業ツリー外に実体があるユーザーの認証情報ファイルを元の場所に置いたまま扱う。
  認証を要する操作では通常の認証解決手順を維持し、その手順で成立しない場合は委譲元へ差し戻す。
  認証情報の複製、移動および別領域への保存は、委譲の信頼境界を越え、異常終了時に複製物を残し得る。
  Claude Codeの組み込み`Read`に対する拒否設定はBash経由の複製を遮断しないため、この扱いは実行主体自身の判断で守る。
  ホーム配下の認証情報ファイル（`~/.aws/credentials`など）の複製・移動・別領域への保存は禁止する
- 作業ツリー内のファイルはGit追跡やgitignore、ファイル名、拡張子によらず通常の読取・編集・複製・比較・出力で扱う。
  外部の認証情報を参照する場合は実体の位置で内外を判定する。
  同一リポジトリのworktreeの環境準備では、Git管理外の実行前提ファイル（`.env`等）を同じ相対パスへ複製する。
  複製先が複製元と同じリポジトリに属することは`git -C <複製先> worktree list`等で確認する。
  worktree作成時に`.worktreeinclude`（gitignore構文。パターンに一致し、かつgitignore対象のファイルだけを
  複製する）を処理する実行環境で、複製元に`.worktreeinclude`が存在する場合は作成時の自動複製を活用する。
  作成済みのworktreeへはシェルの`cp`で複製する

## 返却形式の設計

本節は努力目標とする。項目数と対象件数の積で固定文字列が積み上がると、生成側と受け取る側の双方が判断へ利用できる分を失うためである。

- 返却形式を新設または変更する場合は、その形式の行数と文字数が項目数に比例して増えるかを判定する。比例して増える形式は、委譲元が渡した絶対パスのファイルへ書き込ませ、ツール戻り値へは絶対パスと件数だけを返させる
- 返却形式と委譲プロンプトの入力構造で行を省略できる項目の定め方は、`## 返却形式の受け渡し`の省略時の値の項に従う。同じ要素は1つの構造だけへ列挙させる
