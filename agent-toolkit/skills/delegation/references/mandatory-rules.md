# 委譲の受け渡しと作業ツリーの保護

本書は委譲元が同じworktreeへ後続の書込担当を起動する前と、委譲先の完了報告を受領する時に読む資料であり、作業ツリーへ書き込む主体の交代と、書込所有権を引き取ったエージェントの受け渡しを定める。
委譲先が自ら守る返却形式、作業ツリー内外のファイルの扱い、終端前のプロセスの確認と完了報告の主張の範囲は`agent-toolkit/share/rules-subagent.md`が定め、実行環境がサブエージェントおよび委譲先の起動時に文脈へ追加する。
完了報告の終端と観測値の確認、担当外差分の判定は`references/receiving.md`が定める。

## 作業ツリーの保護

- 同じ作業ツリーへ複数の書込担当を並列に置く場合は、書込を所有する呼び出し元が、編集対象と各操作の生成物・lockfile・スナップショットなどの書込先を互いに交わらない集合へ分け、担当ごとに確定して渡す。
  書込先を分けていない担当の追加と、先行担当の終端を確かめない同じ作業への後続起動は行わない。
  並列の担当は割り当てたファイルだけを変更し、追跡ファイルを書き換えない静的解析や対象を限定したテストで確認する。
  作業ツリー全体または共有状態へ作用する操作は、呼び出し元が全担当の終端を確かめた後に直列に行う。
  対象の操作にはcommitとGit hook（prekなど）、indexや履歴を変えるGit操作（add・stash・checkout・reset・rebaseなど）を含む。
  ファイルを書き換える整形とlint（pyfltr runなど）、生成物の同期、依存更新と環境構築も対象とする。
  同じworktreeへ書き込む主体を交代させる場合は、後続の実装担当を起動するときと委譲元自身がそのworktreeへ書き込むときの双方で、既存の実装担当が終端したことを確認する。
  稼働中の実装担当がある間、委譲元は実施をその実装担当へ戻す。
  委譲先を起動できない場合だけ、終端の確認後に委譲元が書込所有権を引き取る。
  異なるレーンへ割り当てた別worktreeの実装担当は、変更ファイルが重複しても並行して進む
- 委譲先へ割り当てた作業ディレクトリ自身と、その祖先ディレクトリを削除する場合は委譲元の工程とし、委譲元が委譲先の終端を確認してから実行する。
  対象はworktree、個別に作成したmanaged-tempの領域その他の削除する領域の全てとする。セッションのmanaged-tempは`agent-toolkit:managed-temp`のとおりエージェントが回収せず、自動削除へ委ねる。
  エージェントは自身の作業ディレクトリを削除できないため、この削除を委譲先の完了条件へ置くと、差し戻しと委譲元による回収を毎回生じさせる
- 終端の確認を経て書込所有権を引き取ったエージェントは、引き取りの事実と自身が実施した操作を記録する。
  そのworktreeを担当する委譲先を再開する時点と、新しい委譲先を起動する時点で、記録した内容をそれぞれ再開指示と委譲プロンプトへ含める。
  記載を受け取った委譲先は、現在のHEADと`git log`で記載の操作の結果を確かめ、一致する履歴の変化と作業ツリーの変化を引き取りの結果として扱い、工程を続ける。
  引き取りを知らない委譲先は、自身が発行していない履歴の書き換えを異常と判定して工程を止める
- 同じレーンに属する計画と要求は同じ専用worktreeで扱い、成果依存がある部分は依存順に実装する。
  レーン内の書込を分ける場合は、前段の条件を満たす同じworktreeの分担と、別branch・別worktreeの一時的な内部群を比較する。
  担当ごとのcommitや書き換えを伴う検証が必要な単位と、書込先を事前に確定できない単位は内部群へ分ける。
  分割と統合は`references/routing.md`「委譲単位の確定」が定める。
  レビュー修正担当を新規起動する場合は、委譲元がレーン担当の終端を確認してからdirty差分を引き継ぐ。
  同じ担当を継続する場合は書込の所有者が同じまま続く。異なるレーンは別worktreeへ割り当てる
- 委譲元も、Git作業ツリー外に実体があるユーザーの認証情報ファイルを`agent-toolkit/share/rules-subagent.md`「作業ツリーと認証情報の扱い」と同じく元の場所に置いたまま扱う
