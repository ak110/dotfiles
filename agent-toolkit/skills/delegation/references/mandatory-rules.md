# 委譲時の厳守事項

本節には、委譲の有無にかかわらず作業ツリーと規範文書を保護する既定で従う規定と、
委譲元と委譲先の双方が守る受け渡しの既定で従う規定を置く。
委譲先だけに課す既定で従う規定は`agent-toolkit/share/rules-subagent.md`が定め、実行環境がサブエージェント及び委譲先の起動時に文脈へ追加する。

受信者のタスク文書が`## 出力`で返却形式を定める委譲では、本節が完了報告又は終端報告への追加記載を求める規定を、その形式が名前と構造を定める項目に限って適用する。
返却形式に定めの無い通常の証跡は、委譲先が書き込む成果物か、委譲元が終端後に実行するコマンドから取得する。
続行不能時の返却形式は、受信者のタスク文書がその経路について定める形式を用いる。
agent定義が同じ経路について形式を定める場合も同じとする。
専用のタスク文書もagent定義も持たない汎用委譲では、起動文が指定した返却形式を用いる。
いずれにも続行不能時の形式が無い場合は、次の2行だけからなる既定形式を用いる。

```text
status: needs_escalation
reason: <続行不能となる事象、阻害条件及び再開に必要な判断>
```

この2行は指定された返却形式そのものとして扱い、本節が禁じる地の文の対象の外に置く。
想定外の結果は本節が定める`想定外事象:`の手段で返す。

- 1つの作業ツリーへ書き込む主体は同時に1つだけとする。
  同じworktreeへ書き込む主体を交代させる場合は、後続の実装担当を起動するときと起動側自身がそのworktreeへ書き込むときの双方で、既存の実装担当が終端したことを確認する。
  稼働中の実装担当がある間、起動側は実施をその実装担当へ戻す。
  委譲先を起動できない場合だけ、終端の確認後に起動側が書込所有権を引き取る。
  異なるレーンへ割り当てた別worktreeの実装担当は、変更ファイルが重複しても並行して進む
- 委譲先へ割り当てた作業ディレクトリ自身と、その祖先ディレクトリの削除は委譲元の工程とし、委譲元が委譲先の終端を確認してから実行する。
  対象はworktree、管理対象一時領域その他の削除できる領域の全てとする。
  実行主体は自身の作業ディレクトリを削除できないため、この削除を委譲先の完了条件へ置くと、差し戻しと委譲元による回収を毎回生じさせる
- 終端の確認を経て書込所有権を引き取った主体は、引き取りの事実、自身が実施した操作及び操作後のHEADの7文字以上の一意な短縮OIDを記録する。
  そのworktreeを担当する委譲先を再開する時点と、新しい委譲先を起動する時点で、記録した内容をそれぞれ再開指示と起動文へ含める。
  記載を受け取った委譲先は、記載と一致する履歴の変化と作業ツリーの変化を引き取りの結果として扱い、工程を続ける。
  引き取りを知らない委譲先は、自身が発行していない履歴の書き換えを異常と判定して工程を止める
- 実装担当は同じ作業ツリーの書込所有権を手放す終端報告の前に、自身が起動した全ての外部プロセスと
  背景ジョブの終了を、ツール終了結果又は保持した実行識別子の直接照会で確認する。
  前景ツールの終了後も存続し得る形で起動したプロセスは、返却形式がその情報の項目を定める場合だけ、実行識別子と終了確認結果を終端報告へ含める。
  項目の定めが無い場合は、終了確認を完了条件として扱い、終端報告を指定形式のまま返す。
  本項の対象は実装担当とし、読み取り専用の委譲は対象の外に置く。
  終了していないプロセスの所有主体を失うと、後続の実装担当が安全に停止できず、1つの作業ツリーへ複数の書込主体が並存し得る
- 委譲先・背景ジョブの完了待ちでは、待機対象の終了状態を返す手段だけを使い、シェルコマンドによる能動的な時間待ちを避ける。
  観測手段が終端statusを返さずに制御を戻した場合は、待機表明でターンを終えるか同じターン内で観測を再発行するかを、
  `agent-toolkit:delegation`の`references/waiting-and-monitoring.md`「待機区間の構成」が定める戻り方の区分で判定する。

  待機と観測の手順は`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`を正本とする。
  委譲先の終端と成果は、委譲を開始したツール呼び出しの戻り値と、実行環境がその委譲について発行した完了通知の2つで確定する。
  会話文脈に現れた同じ文面は、この2つの外側にある。会話文脈には自身の生成出力、hookの通知及び実行環境の定型文が混在し、文面だけでは発信元を確定できないためである。
  完了報告が挙げる実測値を照合する場合は、本節が自己検証する状態変更コマンドについて定める場合を除き、その操作の公開仕様が定める終了状態を直接観測して判定する。
  終了状態が対象の存在で定まる操作では存在を観測し、対象の消失で定まる操作では消失を観測する。
  判定に用いるのはこの観測とし、処理前の状態から離脱したことは終了の根拠から外す。
  離脱先が複数ある操作では、離脱の観測が誤った遷移と未終端を正常な終端と同じ観測へ写像するためである
- 委譲先が実行した状態変更コマンドが、変更後の状態を自ら判定して成功を報告する公開仕様を持つ場合は、そのコマンドの終了コード、成功の報告が挙げる対象の完全識別子と警告の有無を、委譲先が返却形式の定める項目として委譲元へ渡す。委譲元は、この項目の充足と対象の完全識別子で検収を済ませる。警告がある場合、項目が欠ける場合、対象の完全識別子が起動時に渡した値と異なる場合と、公開仕様を持たない操作では、既存の直接観測をそのまま適用する。自己検証する操作の生の結果を委譲境界で破棄すると、同じ状態の再取得が委譲のたびに積み上がり、前段の誤りも検出できなくなる
- 委譲元は、完了報告に含まれる実装上の事実を成果物へ書く前に、その事実を実装、実行結果又は公式一次資料で確認する。
  対象の成果物は、AWIとUWIの本文、計画ファイル、レビュー指摘管理表その他の後続の判断が入力とする記述とする。
  成果物へは、確認に用いた手段と観測値を書く。
  委譲先の報告と実体が一致しないまま成果物へ確定すると、その記述を入力とする後続の判断が誤った前提の上で進む
- 同じレーンに属する計画と、明示的な先行成果依存により同じレーンへ割り当てられた複数の要求は、同じworktreeで依存順に実装する。
  同じworktreeへ割り当てられるのは、この先行成果依存を持つ計画に限る。
  レビュー修正担当を新規起動する場合は、起動元がレーン担当の終端を確認してからdirty差分を引き継ぐ。
  同じthreadを継続する場合は書込主体が同じまま続く。別worktreeへ割り当てる対象は異なるレーンとする
- 担当外ファイルの差分は、受信者のタスク文書が`## 出力`で返却形式を定める委譲では、委譲元が終端後に`git -C <対象作業ツリーの絶対パス> status --porcelain=v1`で取得して判定する。
  返却形式を定めない委譲では、委譲先の完了報告から受け取る。
  差分の追加・変更・解消を観測した場合も工程を続け、続行可否は`agent-toolkit/rules/02-agent-operations.md`「作業中に観測したリポジトリ状態変化の扱い」で判定する。
  作業対象リポジトリの複数worktreeで並行作業する場合は
  `refs/stash`が全worktreeで共有されるため、承認済みの退避ではworktree横断排他ヘルパーだけを使い、
  `git stash push`・`git stash pop`・`git stash drop`の直接実行を避ける。
  キュー管理リポジトリの退避は`agent-toolkit:wi-standards`の`references/repository-scope.md`が定め、本項の対象の外に置く。
  `refs/stash`の共有は並行作業で常に成立する原因候補であり、担当外差分を取得した主体が判定に用いる
- 委譲元と委譲先は、ユーザーの認証情報ファイルを元の場所に置いたまま扱う。
  認証を要する操作では既定の認証解決経路を維持し、その経路で成立しない場合は呼び出し元へ差し戻す。
  認証情報の複製、移動及び別領域への保存は、委譲の信頼境界を越え、異常終了時に複製物を残し得る。
  例外は、同一リポジトリのworktreeを作業場所として成立させるために、Git管理外の実行前提ファイル
  （`.env`等）をそのworktree内の同じ相対パスへ複製する操作とする。
  この例外は、複製先が複製元と同じリポジトリに属することを`git -C <複製先> worktree list`等の出力で確認できる場合に限る。
  worktree作成時に`.worktreeinclude`（gitignore構文。パターンに一致し、かつgitignore対象のファイルだけを
  複製する）を処理する実行環境で、複製元に`.worktreeinclude`が存在する場合は作成時の自動複製を活用する。
  作成済みのworktreeへはシェルの`cp`で複製する
- 委譲先の返却形式を新設又は変更する主体は、その形式の行数と文字数が項目数に比例して増えるかを判定する。比例して増える形式は、起動側が渡した絶対パスのファイルへ書き込ませ、ツール戻り値へは絶対パスと件数だけを返させる。本項の適用先は新設した返却形式と変更した返却形式とし、既存の返却形式は現行のまま維持する。長い定型構造を1回の応答で逐語生成させると、文字の取り違えと途中終了により本文が欠落する
- 委譲先の返却形式と起動文の入力構造を新設又は変更する主体は、省略時の既定値を取り決めが定める項目について、値が既定値と一致する場合に行を省く形で定義する。値が常に意味を持つ項目だけを、常に出力する行として定義する。同じ要素は1つの構造だけへ列挙させる（努力目標。項目数と対象件数の積で固定文字列が積み上がると、生成側と受け取る側の双方が判断へ利用できる分を失う）
- 前項により行を省略できる項目を定める取り決めは、項目の既定値と、行の不在を既定値として解釈することを同じ本文へ書く。この記述を持つ取り決めに従って返却又は起動文を受け取った主体は、行の不在を既定値として扱う。既定値の記述が無いまま行を省略すると、受け取る側が欠落と誤認して再取得を指示し、その工程が停止する
- `想定外事象: <事象と対処>`の1行を受け取った主体は、自身の返却の末尾へ同じ形式の1行として逐語で引き継ぐ。
  指定形式の他の行と既存の遷移は、この行の有無によらず同じまま保つ。
  完了報告を受け取った主体は、後続工程へ進む前に返却形式と受け取った本文を照合し、返却形式が定める行だけからなる報告を完了として扱う
