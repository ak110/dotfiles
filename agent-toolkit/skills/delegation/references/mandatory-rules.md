# 委譲の受け渡しと作業ツリーの保護

本書は作業ツリーへ書き込む主体の交代と、書込所有権を引き取ったエージェントの受け渡しを定める。委譲先自身の義務は`agent-toolkit/share/rules-subagent.md`、完了報告の確認と担当外差分の判定は`references/receiving.md`が定める。

## 作業ツリーの保護

- 同じ作業ツリーへ複数の書込担当を並列に置く場合は、書込を所有する呼び出し元が編集対象と各操作の書込先（生成物、lockfile、スナップショットなど）を互いに交わらない集合へ分けて担当ごとに渡す。書込先を分けていない担当の追加と、先行担当の終端を確かめない同じ作業への後続起動は行わない。並列の担当は割り当てたファイルだけを変更し、追跡ファイルを書き換えない静的解析や対象を限定したテストで確かめる。
  稼働中のCLI・hook・MCP・検証が同時に読むファイル群は、実行に必要な整合を保つ組として扱い、その組全体を同じ担当へ割り当てる。
  作業ツリー全体か共有状態へ作用する操作は、呼び出し元が全担当の終端を確かめた後に直列に行う。commitとGit hook（prekなど）、indexや履歴を変えるGit操作（add・stash・checkout・reset・rebaseなど）、ファイルを書き換える整形とlint（`pyfltr run`など）、生成物の同期、依存更新と環境構築がこれに当たる。
  依存宣言・対応lockfileの更新と必要な環境準備は1つの直列工程とし、並行担当の起動前か全担当の終端後に呼び出し元が行う。
  並行担当は必要になった依存変更を委譲元へ返す
- 同じworktreeへ書き込む主体を交代させる場合は、後続の実装担当を起動するときも委譲元自身が書き込むときも、既存の実装担当の終端を先に確かめる。稼働中の実装担当がある間は作業をその担当へ戻し、委譲先を起動できない場合だけ終端確認後に委譲元が引き取る。別worktreeの担当は変更ファイルが重複しても並行してよい
- 委譲先の作業ディレクトリとその祖先（worktree、個別に作成したmanaged-tempの領域など）の削除は、委譲先の終端を確かめてから委譲元が行う。エージェントは自身の作業ディレクトリを削除できないため、この削除は委譲元の工程とする。セッションのmanaged-tempは回収せず自動削除へ委ねる
- 終端確認を経て書込所有権を引き取ったエージェントは、引き取りの事実と自身の操作を記録し、そのworktreeの委譲先を再開・新規起動するときに渡す。受け取った委譲先は現在のHEADと`git log`で記載の結果を確かめ、引き取りの結果として扱って続ける（知らされないと、自身が発行していない履歴の書き換えを異常として止まる）
- 同じレーンの計画と要求は同じ専用worktreeで扱い、成果依存がある部分は依存順に実装する。レーン内の書込は第1項の条件を満たす同じworktreeの分担か、別branch・別worktreeの一時的な内部群で分け、担当ごとのcommitや書き換えを伴う検証が必要な単位と書込先を事前に確定できない単位は内部群へ分ける。分割と統合は`references/routing.md`「委譲単位の確定」が定める。異なるレーンは別worktreeへ割り当てる。レビュー修正担当を新規起動する場合はレーン担当の終端を確かめてからdirty差分を引き継ぐ
- 委譲元も、Git作業ツリー外にあるユーザーの認証情報ファイルを`agent-toolkit/share/rules-subagent.md`「作業ツリーと認証情報の扱い」のとおり元の場所に置いたまま扱う
