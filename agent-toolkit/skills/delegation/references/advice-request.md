# 委譲先からの助言依頼

本書は、`agents_server`の通常起動で起動された委譲先が、自力で作業を進められなくなったときに、自分を起動した直上の委譲元へ技術的な助言を求める条件と手順を定める。
この通知を「助言依頼」と呼ぶ。

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## 助言依頼ができる委譲先

起動本文に助言依頼ができる旨の通知（`atk-auto`要素の`kind="advice-request"`）を受け取った委譲先だけが、助言依頼を出せる。
`agents_server`は起動時に委譲先と直上の委譲元の実モデルを比べ、次のどちらかを満たす組の委譲先にだけ通知を加える。

- エンジンが異なる（委譲元のモデルが同等以下でも、観点が異なりうるため対象とする）
- エンジンが同じで、委譲元のモデルが委譲先より上の段にある

通知を受け取っていない委譲先は、本書を適用せず、既存の「確認事項の即時通知」と返却形式だけを使う。
レビューを担当する工程（`review`・`review_fast`）の担当、軽量起動（`explore`・`shell`・`write`）、ホスト組み込みの委譲機能で起動された委譲先へは、通知は届かない。

## 助言依頼を出す時機

次のどちらかに当たる場合に限る。

- 対処を変えても同じ失敗が続く
- 担当範囲内の技術判断で、複数案の優劣を自力で決めきれず、誤ると手戻りが大きい

次の事項は助言依頼に含めず、既存の経路で扱う。

- ユーザー確認が要る事項: `agent-toolkit/share/rules/rules-subagent.md`「確認事項の即時通知」
- 判断・認可・入力・権限の不足: 同書「返却形式の受け渡し」の続行できない理由の返却
- 調査で確定できる事項: 助言依頼の前に自分で調べる

助言のたびに委譲元の文脈へ会話の抜粋と助言が残るため、方針を決める前や完了を宣言する前の確認には使わない。

## 手順

1. 助言依頼を1件送る。
   環境変数`AGENT_TOOLKIT_OWNER_SESSION`が設定されていれば、最初の操作は`atk agents notify`とする。
   設定されていなければ「確認事項の即時通知」の2番目以降の手段を順に選ぶ。
   agents_serverの`send_message`とCodexの協調機能の`send_message`は、委譲元への通知の手段から除く。
   本文は`助言依頼:`で始め、決めたい事項、試した対処と結果、自分の案を短く書く。
   委譲元が会話の抜粋を読むため、経過の再掲は省く。
2. 助言に依存しない作業が残っていれば続ける。
   残っていなければ、`続行できない区分: owner_input`と、助言依頼への返答を待つ旨の理由を返してターンを終える。
3. 助言は、委譲元が`send_message`で送る、同じセッションへの新しい入力として届く。
   委譲先は待機や照会の操作を省き、届いた入力を受けて同じ担当として作業を再開する。

担当と成果の責任は、助言を受けた後も委譲先に残る。
助言が自分の観測と矛盾する場合は、従う前に矛盾する観測を委譲元へ返す。
