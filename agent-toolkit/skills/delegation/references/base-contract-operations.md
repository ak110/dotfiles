# 基本委譲契約：操作の制限と応答言語

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## 操作の制限と応答言語

委譲先の操作を制限する場合は、操作の目的、対象となる資源、状態遷移を指定する形で行い、`<役割名>.subagent.md`でその担当に必須と定められている状態遷移と競合しない範囲に限定する。
コマンド名やサブコマンド名だけで禁止を指定すると、同一名称を持つ別目的の操作まで禁止してしまい、委譲先が必要な状態遷移を省略したまま完了を報告する原因となる。

文書、コメント、WI本文の起草を委譲する場合は、現行のplugin rootを解決した上で、`<plugin root>/.venv/bin/python -m pyfltr.colloquial <起草ファイルの絶対パス>`という実行コマンドを渡す。
あわせて、検出された指摘の解消、または解消しない理由の記録と、その結果を完了報告へ記載することも求める（努力目標）。
辞書ファイルのパスは起動入力には含めない。
なお、役割文書を指定する定型起動ではこの指定をしない（手順と検証内容は役割文書側で定義されており、`extra_params`は宣言済みの入力項目のみを受け付けるため）。

記述言語は`agent-toolkit/share/rules/common/01-agent.md`「使用言語」の読者基準に従う。
ユーザーが読む本文・成果物へ日本語の義務を適用し、内部連絡・委譲プロンプト・内部返却は言語だけを理由とする書き直しの対象外とする。
内部連絡をユーザーへ届ける主体が日本語の説明を作成する。

- `agents_server`経由の起動: `share/agents-server-<mode>.md`で言語が規定されているため、委譲プロンプトには記述しない。
- `Agent`ツールやCodexのネイティブ委譲など`agents_server`を経由しない起動: ユーザーが読む本文・成果物を作成する担当には、`agent-toolkit/share/rules/common/01-agent.md`「使用言語」の読者基準を伝える。
  英語の自動挿入指示を成果物の記述言語へ引き継がない条件も伝える。
  `<役割名>.subagent.md`やagent定義に同じ指定があれば再掲せず、どちらも指定しない委譲では`応答言語`という名前付き入力で対象範囲とともに渡す。

`<役割名>.subagent.md`を指定する起動における待機および再開の方針は、サーバーが選択したバックエンドに応じて`share/agents-server-<mode>.md`で通知されるため、委譲プロンプト内には記述しない。
