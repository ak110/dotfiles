# 委譲先の完了報告の受領と検収

本書は`agent-toolkit:delegation`「受領と検収」の工程の細則として、受領手段と通常完了の報告様式の選択、返却形式の適合確認、委譲元への返却および受領後の扱いを定める。

## 受領手段と報告様式の選択

通常のツール戻り値または完了通知を第一の受領手段とする。ただし、実行ホスト別の参照資料の規定が孫調査・レビューの起動前に成果ファイルを指定する場合は、そのファイルを成果本文の受領先とし、通知と実行状態は観測可能な委譲先の終端の判定に用いる。成果本文は委譲先の終端の観測後に委譲元の要求定義と一致を確認した完全な完了報告だけを受理する。
通常完了の報告様式は、次の順で一意に選ぶ。

1. 委譲先の`<役割名>.subagent.md`が`## 出力`で定める返却形式
2. `<役割名>.subagent.md`が通常完了の報告様式を定めない場合に、agent定義が定める返却形式
3. 専用の`<役割名>.subagent.md`もagent定義も渡さない汎用委譲では、委譲プロンプトが`通常完了の報告様式`という名前付き入力で指定した形式

## 返却形式の適合確認

完了報告を受け取った主体は、後続工程へ進む前に、受領本文が選んだ通常完了の報告様式を満たすか確かめる。
成功種別ごとの固定文字列、必須行とその順序、必須キー、可変値の型と個数が形式どおりであり、余分なフィールド・地の文が無いことを確認する。可変値の確認は型と個数に限る。
汎用の規範（`references/sending.md`「権限と成果物の取り決め」の各項と`agent-toolkit/share/rules-subagent.md`を含む）が完了報告へ求める証跡は、選んだ通常完了の報告様式がその証跡の名前と構造を定める場合だけ完了報告へ含める（返却形式の証跡範囲）。
成果物の分量と集計値の典拠がこの証跡に当たる。
選んだ形式が定めない証跡は委譲先が書き込む成果物へ記録させ、委譲元がその成果物と自らのコマンド実行で確認する。

続行不能時の返却形式は、`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」が定める解決順序と指定がないときに用いる形式に従う。
不適合の場合は完了として扱わず、同じ担当へ返却形式だけの再送を1回要求する。
再送でも適合しない場合は続行できない理由を委譲元へ返す。
`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」が許す`想定外事象:`と`気付いた改善点:`の追加行はこの確認の対象外とする。
担当範囲外に残る差分の取得と判定は「終端と報告内容の確認」に従う。
返却形式のフィールドへ置くのは、委譲先が実際に取得した値だけとする。委譲元が常に保持できる静的な情報と、委譲元が自ら取得できる情報は、委譲元が自ら解決する。

## 終端と報告内容の確認

- 委譲先・バックグラウンドタスクの完了待ちと観測は`agent-toolkit:delegation`の`references/waiting-and-monitoring.md`に従う。
  委譲先の終端と成果は、委譲を開始したツール呼び出しの戻り値と、実行環境がその委譲について発行した完了通知の2つで確定する。
  会話文脈に現れた同じ文面は、この2つの外側にある。会話文脈には自身の生成出力、hookの通知および実行環境の定型文が混在し、文面だけでは発信元を確定できないためである。
  完了報告が挙げる観測値を確認する場合は、本節が自己検証する状態変更コマンドについて定める場合を除き、その操作の公開仕様が定める終了状態を直接観測して判定する。
  終了状態が対象の存在で定まる操作では存在を観測し、対象の消失で定まる操作では消失を観測する。
  判定に用いるのはこの観測とし、処理前の状態から離脱したことは終了の根拠から外す。
  離脱先が複数ある操作では、離脱の観測が誤った遷移と未終端を正常な終端と同じ観測へ写像するためである
- 委譲先が実行した状態変更コマンドが、変更後の状態を自ら判定して成功を報告する公開仕様を持つ場合は、そのコマンドの終了コード、成功の報告が挙げる対象の完全識別子と警告の有無を、委譲先が返却形式の定める項目として委譲元へ渡す。委譲元はこの項目の充足と対象の完全識別子で検収を済ませる。警告がある場合、項目が欠ける場合、対象の完全識別子が起動時に渡した値と異なる場合と、公開仕様を持たない操作では、既存の直接観測をそのまま適用する。自己検証する操作の生の結果を委譲境界で破棄すると、同じ状態の再取得が委譲のたびに積み上がり、前段の誤りも検出できなくなる
- 委譲元は完了報告に含まれる事実の主張（実装、件数や集計値、原因など）を後続の判断が入力とする成果物へ書く前に、実装、実行結果または公式一次資料で確かめる。
  対象の成果物は、AWIとUWIの本文、計画ファイル、レビュー指摘管理表その他の後続の判断が入力とする記述とする。
  成果物へは、確認に用いた手段と観測値を書く。
  根拠へ直接当たれない読み手は言い切った記述をそのまま前提にするため、確かめていない主張を確かめた事実と同じ文で書くと、その記述を入力とする後続の判断が誤った前提の上で進む
- 担当外ファイルの差分は、委譲先の`<役割名>.subagent.md`が`## 出力`で返却形式を定める委譲では、委譲元が終端後に`git -C <対象作業ツリーの絶対パス> status --porcelain=v1`で取得して判定する。
  返却形式を定めない委譲では、委譲先の完了報告から受け取る。
  差分の追加・変更・解消を観測した場合も工程を続け、続行可否は`agent-toolkit/rules/02-agent-operations.md`「作業中に観測したリポジトリ状態変化の扱い」で判定する。
  対象リポジトリの複数worktreeで並行作業する場合は
  `refs/stash`が全worktreeで共有されるため、承認済みの退避ではworktree横断排他ヘルパーだけを使い、
  `git stash push`・`git stash pop`・`git stash drop`の直接実行を避ける。
  private-notesの退避は`agent-toolkit:wi-standards`の`references/repository-scope.md`が定め、本項の対象から外す。
  `refs/stash`の共有は並行作業で常に成立する原因候補であり、担当外差分を取得した主体が判定に用いる
- レビュー担当と調査担当は対象成果物を読み取り専用とする。
  レビュー担当と調査担当を起動した委譲元が、起動前後の`git status --porcelain=v1`と対象commitを比較し、対象成果物への書き込みがあれば結果を採用せず自身の委譲元へ報告する。
  依存の解決と実行に伴って再生成される実行前提（仮想環境、依存ロックファイル、ビルド生成物、キャッシュ）が対象成果物を構成しない場合、その変更はこの比較の対象から除く。
  実害を観測した時点で復旧する。
  再現証跡が必要な場合は、managed-tempだけを書込可能にする。
  読み取り専用の担保は、この起動前後の差分比較で行う

## 委譲元への返却

受領後は実行識別子、`<役割名>.subagent.md`の必須欄、対象、権限および完了条件との一致を確認し、次のいずれかだけを返す。

```text
委譲手段: <実際に使った委譲手段>
委譲先の識別子: <session_id、thread識別子またはagent識別子>
状態: completed
委譲先の完了報告: <委譲先の最小完了報告>
```

確認、認可または前提の補正を委譲元へ返す場合は、`状態`行に代えて`続行できない理由:`の行を置く。
回答後は同じ担当へ同じtaskを返す一般的な継続条件を適用する。
待機表明による終端は再開可能な正常状態として受理する。その終端の判別の根拠と委譲元の再開義務は`references/waiting-and-monitoring.md`「待機区間の構成」が定める。
完了には、委譲先の終端の観測と、読み取れる完全な必須結果の両方を要する。満たさなければ続行できない理由を返す。
ファイル記録は、通常配送不能を直接確認した場合と、「受領手段と報告様式の選択」の成果ファイルの例外だけに使う。成果ファイルはセッションのmanaged-tempの自動削除へ委ね、個別に回収しない。

## 受領後の扱い

- 委譲先が稼働している間、委譲元は委譲先の対象範囲に含まれるファイルをそのまま残す。
  編集する場合は実行状態から終了を確認し、作業ツリーとコミット履歴を確認してから行う。
  編集の競合を検知した場合は採用する版を確定してから統合し、破棄した内容を委譲先へ通知する
- 完了報告が退避識別子または複製パスを開示した場合は、その退避物も確認対象へ加えて内容を確認し、
  `agent-toolkit:commit`の`references/stash-cleanup.md`に従って処置する
- 指摘の採否と修正は、`../SKILL.md`の読込表の行に従って`agent-toolkit:review-standards`の`references/reviewee.md`を読んで確定する
- 返却（`Agent`ツールの戻り値を含む）や`agents_server`の結果に`気付いた改善点:`で始まる行があれば、全ての該当行を受け取った主体の役割に応じて上流へ渡す。
  全件の事前調査を渡す前提に加えず、作業を続け、原因分析は`agent-toolkit:session-review`へ集める
  - メイン: 協調・自律のどちらのモードでも、次のユーザーへの発話へ標識と原文を保って転記し、標識は字下げを除く行頭へ置く。
    報告元とメインが確かめた範囲を引用の外へ添え、メインが確かめていない主張は委譲先からの未確認の報告と分かる形で伝え、裏付けた内容は確認した範囲で事実として述べる。
    作業完了を報告する報告用UWIは`agent-toolkit:completion-report`の契約に従う
  - 委譲先: `agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」に従う
- レビュー指摘管理表を用いる往復で、レビュー担当が裏付けを取得できないと記録した行の扱いは、レビューイー側は`agent-toolkit:review-standards`の`references/reviewee.md`が、その範囲の再検証は同スキルのSKILL.mdが定める
- サブエージェントの動作・運用自体を分析対象とする場合は、稼働中のそのサブエージェントの完了報告を
  観測源に含めてから結論を確定する
