# 待機と観測

委譲先または背景ジョブの完了待機を開始する直前に、
`references/waiting-and-monitoring.md`を全文読む（努力目標）。

委譲先の完了を待つ場合と、委譲を伴わない背景ジョブの完了を待つ場合の双方へ適用する。
プロセスを終了させる操作の所有権規定は
`agent-toolkit/rules/02-agent-operations.md`「プロセス終了の安全規定」節を正本とする。

## 待機区間の構成

- 各待機区間を1回のツール呼び出しへ閉じ込める。
  待機条件を満たした時点で終了するループ（`until <条件>; do sleep <間隔>; done`）を1回起動するか、
  機械的な完了通知を受領できる場合は通知の受領をもって待機解除とする
- 待機の間隔は、対象が正常に動作しているときの想定応答間隔と、既に経過した無応答時間の双方から決める。
  既経過の無応答時間が想定応答間隔を大きく超える場合は間隔を短くし、停滞の判定を早める（努力目標）
- 前景実行の待機ループは、ループ自身の上限をシェル実行のタイムアウト上限以下に設定する。
  より長い待機を要する場合は、各区間の開始前に対象の生存と充足可能性を再確認したうえで複数区間へ分ける

## 背景ジョブの起動形（Claude Code）

- `run_in_background=true`の長時間ジョブは`Monitor`で全行取得するか完了マーカーを`grep -q`で待つ。
  マーカー未生成の背景タスク完了検出目的では`Monitor`を起動しない。
  ツール側で背景実行を指定したコマンドはシェル側を前景のまま保ち、末尾の`&`や`nohup`を重ねない。
  二重に背景化するとシェルの終了が完了通知となり、実ジョブの完了を検知できない
- 完了までに時間を要するコマンドは、Bashツールのタイムアウト引数を上限まで引き上げた前景実行を既定とする。
  上限時間内に収まらない場合は、実行対象を限定して複数回の前景実行へ分ける

## 待機の起動条件

- 待機ループ（前景・背景、`until`・`for`・`while`のいずれも含む）を起動する前に、
  待機条件が実データへ1回以上一致することを前景の単発実行で確認する
- 併せて待機条件の状態を機械的に照会できるかを評価する。
  照会できる外部・ユーザー依存の条件は、充足時期を観測できない場合も待機上限まで評価を継続する。
  照会できない条件は待機の対象外とし、待機を起動せず次工程へ進む
- 待機ループが1回タイムアウトした時点で、単純に再度待たず原因（条件式の誤り・対象プロセスの消失など）を疑う。
  調査は待機条件が参照する実体を直接照会するコマンド（`ps -p <PID>`・`gh run list --commit <SHA>`等）で行う

## 完了通知を待ってターンを終える場合

- 待機対象の完了通知から独立した定時起動を1件装着する。
  利用できない場合は上限付きの前景待機を継続してターンを終えない。
  外部事象の到達だけに依存する待機は、当該事象が到達しない障害時に打ち切る契機を失う
- 定時起動の依頼文へは、現在の作業状態を正本となるファイル（計画ファイル・作業ツリー・
  課題管理の一覧など）から読み直して判定する旨だけを書き、
  コミット識別子・残工程の列挙・完了済み工程の記述を埋め込まない。
  依頼文が可変状態の写しを保持すると、工程が進むたびに内容が事実と相違する（努力目標）
- 定時起動が発火した時点で稼働状況を実測し、変化が無い場合は停滞の検知手順へ進む
- ターンを終える直前に稼働状況を1回だけ実測し、成果物の更新時刻と分量、
  または委譲先プロセスの生存をユーザーへ1行で示す。
  同一の状態確認コマンドを応答ごとに反復発行すると、同一結果の再取得へコンテキストを消費する

## 待機中の先行実施

待機中は、後続工程のうち委譲先の対象範囲と競合せず、
かつ着手条件と入力が待機対象の結果に依存しない全ての工程を先行して実施する（努力目標）。
競合の有無は委譲先の対象ファイル一覧との突合で判定し、読み取りのみの調査は競合しないものとして扱う。
別リポジトリへの操作もファイル競合は生じないが、入力が待機対象の結果に依存する場合は先行しない。

## 停滞の検知と巻き取り

- 委譲先が所有する外部プロセスまたは背景ジョブの実行中は、成果物差分だけで停滞を判定しない。
  所有主体が返した安定した実行識別子を直接照会し、生存中、識別子消失、終了後の結果未回収を区別する。
  外部実行を終了できるのは所有主体だけとし、委譲元は生存中の処理を重複起動しない
- 間隔を空けた複数回の観測に差が無ければ継続を1回促し、その後も応答が無ければ未完了工程を巻き取るか、
  縮減した新規サブエージェントを起動する。観測結果はユーザーへ短く提示する。
  ただし成果物ファイルの更新が続いている間と、更新元を別主体（CI・formatter・並行セッション等）と
  区別できない間は、停止・巻き取りの判断を保留して催促にとどめる
- 稼働中の同一委譲先へ、先に送った方針と矛盾する差し替えを繰り返す状況になった時点で作業の保留を指示し、
  委譲元で方針を確定してから旧方針との差分を統合した指示を1回で送付して再開させる
- 起動文へ明示した同一の制約への違反が繰り返される場合は、同じ制約を伝え直す起動を繰り返さず、
  呼び出し元が当該工程を巻き取るか別の経路へ切り替える。切り替えの前に、違反が委譲先の出力形式と
  受信側の判定条件のどちらに起因するかを実装で確認し、受信側に起因する場合は判定条件を是正する
- 停滞を確定して巻き取る場合、再実装を決める前に委譲先の記録と、委譲先が起動した外部実行系のログを
  末尾に限定して確認する。外部実行系が完了報告を出力している場合は実作業が完遂しているため
  再実装せず、未完了の工程だけを巻き取る

## 成果物側の観測

委譲先・背景ジョブの成果物側の状況は、実行環境向けに配布されたagent-toolkitの管理CLIが提供する状態確認手段で、
作業ツリーの差分件数・HEAD・成果物ファイルの行数と最終更新からの経過時間を1回の呼び出しでまとめて得る。
同一の観測へ複数のコマンドを個別に発行しない（努力目標）。当該手段が返すのは成果物側の値だけであり、
実行識別子の直接照会と、生存中・識別子消失・終了後の結果未回収の区別を置き換えない。
