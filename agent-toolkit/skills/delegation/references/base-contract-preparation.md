# 基本委譲契約：用語と起動前の確認

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## 用語

- 委譲プロンプト: 委譲先を起動するときに渡す指示の本文（`agents_server`の`start`の`prompt`、`Agent`ツールの`prompt`）。
- 返却値: 委譲先が`<役割名>.subagent.md`の`## 出力`に従って返す値（`実装完了`などの固定の先頭行と各項目の値）。
- `<役割名>.subagent.md`を指定する起動: `agents_server`の`start`へ`subagent_md_path`、`extra_params`、`cwd`を渡す起動。
  `subagent_md_path`は役割名または同じplugin rootの`share/<役割名>.subagent.md`の絶対パス、`extra_params`は該当文書が宣言した入力項目、`cwd`は委譲先が基準とする作業ツリーの絶対パスとする。

委譲先が引き継ぐ入力は委譲プロンプトのみであり、委譲元の会話履歴や読み込んだファイル、起動したスキルは引き継がれない。
例外として、`routing-fork.md`「会話を引き継ぐ委譲」に基づきホスト標準のforkを選択した場合は、起動時点までの会話履歴も委譲先へ引き継がれる。
取り決めを記述する文書の配置指針は、`agent-basics:writing-standards/references/sub-agents-contracts.md`「`<役割名>.parent.md`と`<役割名>.subagent.md`の自己完結（双方向）」で定める。
監査記録は`docs/development/audit-records-delegation.md`の「agent-toolkit/skills/delegation/references/base-contract.md：基本委譲契約：2026年9月27日」に記載されている。

## 起動前の確認

単発の委譲をする際は、起動前に対象、読取・書込の権限、完了条件を確定する。
委譲する方針について未回答の確認事項や未反映の指摘が残っている場合は、それらを解決してから起動する。
委譲元の文書において必須入力や値の決定規則が別文書に委ねられている場合は、該当する節を読んでから値を決定する。
推測に基づいて起動すると、委譲先から不整合として差し戻される原因となる。

委譲元が渡す値に起因する情報の不足は、委譲元が起動前に防止する（入力値の再確認を委譲先へ求める処理は行わない）。

- `<役割名>.subagent.md`が要求する必須入力がそろい、絶対パスで指定された既存の入力ファイルや、委譲先自身が解決して読み込むplugin配下の資源が実在することを確認する。
- 委譲プロンプトで指定するファイルパスはすべて絶対パスで記述する（相対パスを使うと委譲先が意図しない基準で解決する恐れがある）。
  委譲先が本文を読み込む対象ファイルには、行数または取得範囲（`offset`と`limit`）を併記する（努力目標。初回の読込が出力上限で切り詰められ、再取得の往復が発生するのを防ぐ）。
  コマンド出力を読ませる場合は、委譲元がmanaged-temp配下へ全量を保存し、同様に絶対パスで引き渡す。
- 全体点検を分担するかは、`routing-investigation.md`「コンテキスト消費が大きい調査の切り出し」の総費用と利点で判断する。
  確定した全対象を保持し、各担当に完了条件、根拠の所在、担当内で完結する範囲を対応付ける。
  通常探索と軽量探索で同一の対象集合を使用する。
- 出力上限を超過する恐れがある対象を読み取り専用で調査する場合は、実在するファイルの絶対パスと範囲指定による本文取得を指定する。
  一致件数や候補ファイルを事前に絞り込むだけでは、本文取得時に同様の切り詰めが発生し、網羅性が求められる判断に不完全な本文が使われる恐れがある。
- 参照させる比較基準や取り決めが起動時点の実態と一致し、委譲先が自ら解決するPATH上のコマンドやplugin配下の資源のバージョンが委譲元の前提と一致することを確認する。
  plugin rootの解決は委譲元の事前確認の範囲内にとどめ、委譲先自身にも独立して解決させる。
- 起動から実際に使用されるまでの間に別主体によって変更される可能性がある値（統合中のベースブランチの先端コミットや、rebase起点のコミットOIDなど）については、取得手段と取得時点を併記して渡し、使用直前の再取得を指示する。
- 前景で終了を監視する委譲先には、孫エージェントの起動手段とその終了を監視できる公開待機機能をセットで引き渡す（`agents_server`のセッションであれば`atk agents wait`、Codexの組み込み委譲スレッドであれば`wait_agent`）。
  これらが両立しない場合は、成果物側で終了を監視する対象と手段を起動前に決定しておく。
- 操作の直前に判定すべき前提条件（全体の上書きや置換の直前に現行本文を取得することや、編集直前の必須スキル起動など）は、起動時に一度だけ確認する基準文書の列挙とは分けて記述する。

不一致や不足が解消できない場合は起動を見送り、不足している項目、存在しなかったパス、または不一致となった対象と観測値を委譲元へ報告する。
役割文書を指定する定型起動では、必須入力や資源の実在性・版をサーバー自身がplugin rootで検証するため、事前確認や行数の併記は省略できる（`delegation-role-launch.md`「`<役割名>.parent.md`を持つ委譲の起動」、ならびに呼び出し元へ統合された契約を含む）。
委譲先から差し戻しを受けるのは、委譲先自身の実行環境に起因し、委譲元からは事前に観測できない事象に限定する。

実行可能資源の欠陥を作業ツリー側で修正したセッションにおいて、修正後のバージョンが稼働中のplugin rootへまだ反映されていない場合に限り、`是正済み資源: <plugin rootからの相対パス> = <作業ツリー側の絶対パス>`という行を資源ごとに含める。
この行には、修正した欠陥の内容と、それが委譲先の工程を停止させる要因であることも併記する。
委譲先はこの行で指定された資源に限り、作業ツリー側のファイルを実行する。

通常起動は`rules-subagent.md`の全文、軽量起動は同書「返却形式の受け渡し」の共通短節を受け取る。
役割の有無にかかわらず共通の返却・エスカレーション契約を使用し、操作権限は各modeと依頼の指定を維持する。
委譲元は共通処理を依頼へ再掲せず、役割固有の結果欄だけを定める。
返却形式に指定がなければ同節の正常結果の形式を使う。
軽量起動で委譲先自身がコマンドを組み立てる場合は、短節の対象外となる次の規則を伝達する（努力目標。操作遮断による手順のやり直しを減らすため）。

- 初回しか観測できない出力や再取得コストの高い出力は、出力全量、終了状態、診断情報を確実に保存する。
- 既存ファイルの上書きや文字列置換をする直前に、現行のファイル内容を読み込む。
- シェルのメタ文字はANSI-Cクォートや変数でエスケープし、入れ子のシェル実行や複数行にわたるコードはスクリプトファイルを作成して実行する。
- ツールの呼び出し形式は最下層のヘルプやスキーマで確認し、既存のパスは基準定義や実体検索に基づいて解決する。
- `git rev-parse --short`には1回の実行で1つのコミット指定のみを渡す。
  Gitの識別子指定は`agent-toolkit:commit`の`references/git-identifier.md`に従う。
