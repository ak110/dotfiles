## 代替起動

本節で述べる代替起動のルールは、主に`Agent`ツールを用いる場合に適用する。
`agents_server`の起動時の候補切り替えはサーバー側に任せる。
Claudeの`api_error.type`が`usage_limit`である場合は、後述の利用上限の条件に従い同一セッションでの継続を優先する。

1. 指定した組み合わせが一時的に利用できない事象（過負荷、レートリミット、サーバー障害、モデルや実行手段の利用不能など、実行環境の可用性に起因する障害）を実際に確認した場合、設定を解決して委譲を起動したエージェントが、セッション内の起動時指定のみを用いて代替の組み合わせへ切り替えて再起動してよい。
     委譲した作業内容自体の失敗は、次項のツール入力失敗を除き代替起動の対象外とする

2. 委譲先が同型のツール入力失敗を具体的な是正の追送後も繰り返し、全工程を実行できないまま返した場合は、前任の終了と書込所有権の解放を確認し、同じ工程の候補列の次の候補を`model_type`へ指定して1回起動し直せる。
     観測した入力の型、追送した是正、切替先と結果を進捗ログか引き継ぎ記録へ残す。
     工程別に設定された候補列は維持し、失敗回数による自動切替は行わない

3. Claude CodeのWeekly limitおよび5時間の利用上限による拒否は代替起動の対象とはせず、制限の解除を待って同一のClaudeで作業を継続する（待機すれば確実に制限が解除され、モデルの切り替えによって思考文脈を失う不利益の方が大きいため）。
     `agents_server`は候補を切り替えずに同一セッションで待機し、委譲元へは`api_error`の種別として`usage_limit`を返す

4. 設定ファイルの内容を直接書き換えることや、`atk config set`を実行することは禁止する。
     設定値はユーザー単位の単一の値として全セッションで共有されているため、不用意に変更すると並行して動作している他のセッションへ意図せぬ影響を及ぼすためである

5. 代替候補は、後述の「代替時の組合せの目安」の表を参照し、障害を確認した時点の状況に基づいて選定する。
     上位の行から軽量の行へ向かい、各行の中では`codex`列、`claude`列の順を目安としつつ、最終的には観測された障害内容と各組み合わせの可用性を考慮して判断する。
     どの組み合わせに該当するかは`engine`と`model`の一致によって判定する。
     失敗した組み合わせが表に含まれている場合は、同一行のもう一方の候補から試行する。
     engineの実行機能そのものを呼び出せない組み合わせは試行対象から外し、利用不能として処理する。
     残るすべての候補で失敗するか利用不能となった場合は処理を打ち切り、`process-model-settings.md`「工程別モデル設定」の手順4へ戻る

6. 後任のエージェントには、前任の起動時の指示本文と、`引き継ぎ記録先`が存在する場合はそれを`（継続）`として渡す。
     `atk run-script session-review-prepare`が生成した`conversation.md`と引き継ぎ記録の両方を読み込んで現時点の確定事項と残りの工程を復元し、追加入力および各ターンの最終応答については全文を引き渡す。
     詳細な記録を照会する場合は、`atk run-script session-review-evidence -- --codex-thread-id <id>`または`--claude-session-id <id>`に`--detail <記録位置>`を付与して実行する。
     コマンドを実行できない後任へは記録ファイルの絶対パスを渡す。
     Antigravity環境の前任を引き継ぐ場合は、`atk agents logs <session_id> --format markdown`の出力を渡す。
     後任に対しては、完了済みの操作や成果物を実物で確認した上で、最新の指示と残された認可の範囲内で作業を進めるよう指示する

7. 後任へ安全に移すため、起動後のターンでそれ以外の可用性トラブルが確定したときは、前任が終了し書込所有権が解放されたことを確認した上で、終了結果の`next_action`に従って`start`に`handoff_from`のみを渡して1回起動する。
   この後任の`session_id`を追加入力の送信先および待機対象とする。
   同様の障害が続く場合は自身で実施可能な範囲を進め、委譲が不可欠な工程については未完了として委譲元へ返す

8. 代替起動を試みた場合は、観測された障害内容、`atk config get`で確認した設定値、実際に使用した組み合わせ、対象工程、および試行を見送った組み合わせとその理由を報告に記録する（努力目標）

9. 委譲先の判断によって、設定と異なるengineやモデルへ勝手に切り替えることは認められず、`process-model-settings.md`「工程別モデル設定」の手順4の定めに従って結果を返却する

10. Codexにおける外側セルと内側コマンドの待機中の取り扱いについては、`references/codex-runtime.md`「agents_serverの二層待機」に従う

## 代替時の組合せの目安

本節の目安表は、「代替起動」における候補選定の目的に限って適用する。
記載されている対応関係や得手不得手は運用上の実用的な目安として定めたものであり、厳密なモデル能力比較の検証結果とは異なる。

| レベル | `codex` | `claude` |
| --- | --- | --- |
| 上位 | `gpt-6-sol/medium` | `opus/medium` |
| 中位 | `sol/medium` | 用途に応じて`opus/medium`または`sonnet/medium` |
| 軽量 | `gpt-6-luna/medium` | `haiku/medium` |

- 同一行に記載された`codex`と`claude`を相互の代替候補とみなし、effortは表内の値を使用する。
  なお、各行の間で世代を統一することは前提としない
- 通常は上位の行を選択し、中位や軽量の行を選択するのは、工程別モデル設定の値がその行に該当する場合、または作業内容がすでに確定しておりリスクの低い機械的な作業に限る
- 表に記載されていないモデルは、表内の組み合わせと同等以上の能力を持つことが確認できる場合に限って代替として使用してよい
- effortを指定できない実行環境で表の組み合わせを満たせない場合は、`codex`列へ切り替えるか上位の行を選択する。
  なお、Claudeのeffortはエージェント定義のfrontmatterで確定するため、frontmatterを持たない起動方法では指定できない
- 差分の逐条確認や欠陥の列挙を主な成果とする工程では`codex`列を選び、複数の代替案の比較検討や設計の確定を主な成果とする工程では`claude`列を選択する
