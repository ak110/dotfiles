# 委譲の要否判定と委譲単位の確定

本書は`agent-toolkit/rules/01-agent.md`「委譲の要否判定」が委ねる委譲の要否判定と委譲単位の確定、および読み取り専用の探索委譲の選定を定める。

## 要否判定

委譲を指定する手順が無い場面でも、独立コンテキストによる先入観のない評価、モデルの使い分け、並列実行の3つの利益に照らして委譲の要否を判定する（努力目標）。読み取り専用の調査を自ら行う条件は、agents_serverのserver instructionsが示す`explore`の採算の目安に従う。上位段位で動くエージェント（メインと上位段位の委譲先）が多数の対象を自ら全文で読むかを判定するときは、コンテキストの節約に加えて費用の差でも軽量段位の`explore`への切り出しを比べる。判定基準を言語化して渡せる走査は切り出し、自身は観点の選定と返った候補の判定に使う（分担は`references/runtime-routing.md`「工程別モデル設定」）。
求める事実を自身が起動した担当が既に確定しているなら、継続可能なその担当へ問い、保持していない事実だけを新規委譲する（努力目標）。

## 委譲単位の確定

独立性、権限、書込所有権、依存関係、文脈共有と統合費用から委譲単位を選ぶ。

- 同じ実行時機、作業ディレクトリ、権限区分で書込所有権が競合しない作業は1件の委譲へまとめる候補とし、作業量と難しさからQCDで比べる。独立した単純作業の直列集中と、難しい作業の背景読込・判断・統合の重複をともに避ける。担当数と粒度に固定値を置かない
- 先行作業の結果を後続の入力にする作業も1件にまとめ、実行順を示して同じ委譲先に順に実行させる。計画ファイルなどの反復編集では整合確認と修正を同じ委譲先へまとめる
- まとめない場合は、まとめる条件のどれが成立しないかを理由として記録する。規範が委譲の種別を指定していることは理由にならない
- 独立した文脈を利益として選ぶ委譲（ユーザー介入を扱う原因分析、独立した事象が2件以上ある原因分析、作業文脈の少ない担当による起草など）は対象ごとに分け、起動後に生じた別の対象は稼働中の担当にも終端済みの担当にも追送せず、新しい担当へ渡す

確定した構成（件数、担当範囲、起動順）は、依存関係か書込所有権の変化で成立しなくなった場合に限って変える（努力目標。停止と再起動で進行中の成果を失う）。変える場合は、稼働中の担当を止める前に同じ基準で構成を再計算し、維持する成果を確定してから移る。

書込主体とworktreeの対応は`references/mandatory-rules.md`に従う。
レーン内で書込を分ける場合は、書込先を確定して同じ専用worktreeへ担当を置く方法と、別branch・別worktreeの一時的な内部群を比べる。同じworktreeの分担は`references/mandatory-rules.md`「作業ツリーの保護」に従い、全体へ作用する操作はレーン担当が全担当の終端後に直列に行う。担当ごとのcommitや書き換えを伴う検証が必要な場合と、書込先を事前に確定できない場合は内部群を選ぶ。内部群では次を守る。

- レーン担当が、各ファイルと契約で結び付くテストを群ごとに対応付けた所有表で書込所有権を固定する。出力元と完全一致期待値のように契約で結び付くファイルは同じ群へ置く
- レーンbranchの確定済みcommitを起点とし、群どうしに未解決の先行成果依存が無い範囲だけを群ごとの別branchと別worktreeへ分ける。各worktreeの書込担当は1つ、1つのbranchへcommitとamendを行う主体も1つに限る
- 群の粒度と同時担当数は固定値にせず前段の比較で選ぶ。粒度の誤りの不利益は速度であり、品質は各群の検収で守る
- 検収、レーンbranchへの統合と競合解消はレーン担当だけが行う。統合後に全追跡ファイルの対象語、生成物、直接影響範囲、変更範囲テストを確かめてから一時worktreeとbranchを回収する。内部群は同じ要求の実装の一部として扱う

## 会話を引き継ぐ委譲

次の条件をすべて満たすときにホスト標準のforkを選ぶ。

- 委譲先が親のユーザー指示、読んだ資料、調査結果の大半を必要とし、新規起動では同じ背景を書き直すことになる
- 親と同じモデルとreasoning effortで作業が成立する
- 工程別モデル設定のキーを持つ工程でも、`share/`配下の専用の`<役割名>.subagent.md`を渡す委譲でもない
- 独立文脈レビュー（成果物の作成者と文脈を共有しない委譲先が先入観なく行うレビュー。実行レビューなど）のような、独立した文脈を要する評価ではない

forkの入力は作業対象、分担、完了条件と報告様式に限り、共有済みの規範と背景を省く。ホスト別の起動形は`references/runtime-routing.md`「実行手段」が定める。
監査記録は`docs/development/audit-records.md`の「agent-toolkit/skills/delegation/references/routing.md：会話を引き継ぐ委譲：2026年9月27日」にある。

## コンテキスト消費が大きい調査の切り出し

結論だけで後続の判断が成立し、コンテキスト消費が大きい調査は、読み取り専用の探索委譲へ切り出す。`start`が`explore`の`mode`を提供する場合はそれを優先し、委譲と直接実行の分岐はagents_serverのserver instructionsが`explore`に示す採算の目安で判定する。軽量起動の委譲先が受け取る取り決めと`model_type`の扱いは`references/runtime-routing.md`「実行手段」が定める。

同じ担当が多数の独立した比較確認を受けた場合は、対象を依存関係と読者・契約の単位で分け、各まとまりの読取探索を並列に委ねる。各子へは重複のない対象集合、判定する契約と返す観測値を渡し、担当は全対象と統合責任を保持して、返却後に未確認の対象と結論間の矛盾を調べてから統合する。書込所有権とレーン数は増やさない。
