# 委譲の要否判定と委譲単位の確定

本書は`agent-toolkit/rules/01-agent.md`「委譲の要否判定」が`agent-toolkit:delegation`へ委ねる委譲の要否判定と委譲単位の確定、および読み取り専用の探索委譲の選定を定める。
読む時点は`agent-toolkit:delegation`の読込表が定める。

## 要否判定

委譲先を指定する手順が無い場面でも、独立コンテキストによる先入観のない評価、モデルの使い分け、
並列実行の3つの利益に照らして委譲の要否を自ら判定する（努力目標）。
対象が特定済みで読む範囲が少量の場合は、起動の固定コストを踏まえて自ら実施してよい。
調査で求める事実を自身が起動した既存の担当が確定済みなら、継続可能なその担当へ保持済みの事実だけを問う。終端済みの担当も継続可能性で判定し、保持していない事実だけを新規委譲の対象とする（努力目標。同じ事実を得るための調査の反復を減らす）。

## 委譲単位の確定

起動前に、独立性、権限、書込所有権、依存関係、文脈共有と統合費用から委譲単位を選ぶ。
同じ作業ディレクトリ・権限区分で書込所有権が競合しない作業は集約の候補とし、作業量と難しさによるQCDで比較する。
独立した単純作業の直列集中と、難しい作業の背景読込・判断・統合の重複を避けるよう分割する。担当内の読み取り・候補作成・レビューの並列化も比較し、担当数と粒度に固定値を置かない。
独立文脈を利益として選ぶ委譲は対象ごとに分け、起動後に生じた別対象も新しい担当へ渡す。
先行作業の結果を後続作業の入力にする依存関係がある作業も1件の委譲へまとめ、実行順を委譲プロンプトへ示して同じ委譲先が順に実行する。
計画ファイルなどを反復編集する工程は、整合確認と修正を同じ委譲先へまとめる。
まとめられない場合は、前段のまとめる条件のうちどれが成立しないかを理由として記録する。
規範が委譲の種別を指定していることは、この分割理由に当たらない。

確定した委譲単位の構成（件数、各単位の担当範囲、起動順）は、依存関係または書込所有権の変化により構成が成立しなくなった場合に変更する（努力目標。起動済みの担当の停止と再起動で進行中の成果を失うため）。
変更する場合は、稼働中の担当を停止する前に確定時と同じ判断基準で構成を再計算し、維持する進捗済みの成果を確定してから移行する。

実装を委譲する際の書込主体とworktreeの対応は`references/mandatory-rules.md`に従う。
大規模な文単位修正で1つのレーン内に一時的な内部群を作成する場合は、レーン担当が各ファイルと契約で結び付くテストを群ごとに対応付けた所有表で書込所有権を固定する。先行する候補置換がレーンbranchへcommit済みで、群どうしに未解決の先行成果依存が無い範囲だけを、そのcommitを起点とした群ごとの別branchと別worktreeへ分け、各worktreeに書込担当を1つだけ置く。1つのbranchへcommitとamendを行う主体は1つに限る。出力元と完全一致期待値のように契約で結び付くファイルは同じ群へ置く。群の粒度と同時担当数は、分割数と上限を固定値にせず前段の比較で選ぶ。粒度の選択を誤った場合の不利益は所要時間の増加と資源の競合による速度の低下であり、品質は各群の検収で守る。
レーン担当だけが各担当の終端、clean状態、commit・差分、群内の変更範囲テストと送受信側を確かめて検収し、各commitをレーンbranchへ順に統合する。競合はレーン担当だけが解消し、統合後に全追跡ファイルの対象語、生成物、直接影響範囲と変更範囲テストを確かめてから一時worktreeとbranchを回収する。内部群はそのレーンの同じ要求の実装の一部として扱う。

## 会話を引き継ぐ委譲

親が保持する文脈を委譲先も使う場合は、次の条件をすべて満たすときにホスト標準のforkを選ぶ。

- 委譲先が親のユーザー指示、読んだ資料および調査結果の大半を必要とし、新規起動では同じ背景を委譲プロンプトへ書き直す
- 親と同じモデルおよびreasoning effortで作業が成立する
- 工程別モデル設定のキーを持つ工程と、`share/`配下の専用の`<役割名>.subagent.md`を渡す委譲の対象外である
- 独立文脈レビュー（成果物の作成者と文脈を共有しない委譲先が先入観なく行うレビュー。実行レビューなど）のような、独立した文脈による先入観のない評価を要さない作業である

親の文脈の大半が無関係なら新規起動を選ぶ。forkの入力は作業対象、分担、完了条件と報告様式に限定し、共有済みの規範と背景を省く。ホスト別の起動形は`references/runtime-routing.md`「実行手段」が定める。
監査記録は`docs/development/audit-records.md`の「agent-toolkit/skills/delegation/references/routing.md：会話を引き継ぐ委譲：2026年9月27日」にある。

## コンテキスト消費が大きい調査の切り出し

同じ担当が多数の独立した比較確認を受領した場合は、対象を依存関係と読者・契約の単位で分け、各まとまりの読取探索を並列に委ねる。各子へは重複のない対象集合、判定する契約および返す観測値を渡す。担当は全対象と統合責任を保持し、子の返却後に未確認の対象と結論間の矛盾を調べてから統合する。書込所有権とレーン数は増やさない。

結論だけで後続の判断が成立し、コンテキスト消費が大きい調査は、読み取り専用の探索委譲へ切り出す。
`agents_server`の`start`が`explore`の`mode`を提供する場合は、通常の委譲起動よりそのmodeを優先する。
軽量起動の委譲先が受け取る取り決めと`model_type`で指定がない場合の扱いは`references/runtime-routing.md`「実行手段」が定める。
委譲と直接実行の分岐は、`start`の説明が`explore`に示す採算の目安で判定する（努力目標）。
