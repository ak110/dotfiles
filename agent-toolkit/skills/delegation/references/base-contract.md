# 基本委譲契約

## 用語

- 委譲プロンプト: 委譲先を起動するときに渡す指示の本文（`agents_server`の`start`の`prompt`、`Agent`ツールの`prompt`）。
- 返却値: 委譲先が`<役割名>.subagent.md`の`## 出力`に従って返す値（`実装完了`などの固定の先頭行と欄の値）。
- `<役割名>.subagent.md`を指定する起動: `agents_server`の`start`へ`subagent_md_path`、`extra_params`、`cwd`を渡す起動。`subagent_md_path`は役割名か同じplugin rootの`share/<役割名>.subagent.md`の絶対パス、`extra_params`は同書が宣言した入力、`cwd`は委譲先が解決の起点とする作業ツリーの絶対パスとする。

委譲先が引き継ぐ入力は委譲プロンプトだけであり、委譲元の会話履歴、読んだファイル、起動したスキルはその外側にある。例外は`routing.md`「会話を引き継ぐ委譲」でホスト標準のforkを選んだ場合で、fork先は起動時点までの会話履歴も受け取る。
取り決めを置く文書の選び方は`agent-toolkit:writing-standards`の`references/sub-agents.md`「`<役割名>.parent.md`と`<役割名>.subagent.md`の自己完結（双方向）」が定める。
監査記録は`docs/development/audit-records.md`の「agent-toolkit/skills/delegation/references/base-contract.md：基本委譲契約：2026年9月27日」にある。

## 起動前の確認

単発の委譲では、起動前に対象、読取・書込権限および完了条件を確定する。委ねる方針に未回答の確認事項や未反映の指摘が残る場合は、確定してから起動する。
委譲元の文書が必須入力や値の確定規則を別の文書へ委ねている場合は、その節を読んでから値を確定する（推定で起動すると委譲先が不整合で差し戻す）。

委譲元が渡す値に起因する欠落は委譲元が起動前に防ぐ（入力の再確認を委譲先へ求めることは省く）。

- `<役割名>.subagent.md`が要求する必須入力がそろい、絶対パスで示す既存の入力と、委譲先が自ら解決して読むplugin配下の資源が実在すること
- 委譲プロンプトが名指しするファイルは全て絶対パスで書く（相対パスは委譲先が任意の基準で解決する）。委譲先が本文を読む対象には、行数か取得範囲（`offset`と`limit`）を添える（努力目標。最初の取得が切り詰めで終わる往復を防ぐ）。コマンド出力を読ませる場合は委譲元がmanaged-tempへ全量を保存して同様に渡す
- 出力上限を超え得る対象の読み取り専用調査では、実在ファイルの絶対パスと範囲指定での本文取得を指定する。一致件数や候補ファイルを先に限定するだけでは本文取得で同じ切り詰めが生じ、網羅性を要する判断へ欠けた本文が入る
- 参照させる比較基準と取り決めが起動時点の実体と一致し、委譲先が自ら解決するPATH上のコマンドとplugin配下の資源の版が委譲元の前提と一致すること。plugin rootの解決は委譲元の確認の内側に留め、委譲先は引き続き自ら解決する
- 起動から消費までに別主体が変え得る値（統合中のベースbranchの到達点、rebase起点のOIDなど）は、固定値でなく取得手段と取得時点を渡し、消費直前の再取得を求める
- 前景で終端を観測する委譲先には、孫の起動手段とその終端を観測できる公開待機機能を組で渡す（`agents_server`のsessionは`atk agents wait`、Codexの組み込み委譲のthreadは`wait_agent`）。両立しない場合は成果物側で終端を観測する対象と手段を起動前に決める
- 操作の直前に判定する前提（全体上書き・置換の直前の現行本文取得、編集直前の必須スキル起動など）は、起動時に1回読む基準文書の列挙と分けて書く

不一致や欠落が解消できない場合は起動せず、欠けた項目、実在しなかったパスまたは不一致の対象と観測値を委譲元へ返す。
`<役割名>.parent.md`を持つ起動では、必須入力と資源の実在・版をサーバーが自身のplugin rootで確かめるため、これらの確認と行数の併記を省く（`agent-toolkit:delegation`「`<役割名>.parent.md`を持つ委譲の起動」）。
委譲先へ差し戻しを残すのは、委譲先自身の実行環境に起因し委譲元から観測できない事象に限る。

実行可能資源の欠陥をそのセッションで作業ツリーへ是正し、是正後の版が稼働中のplugin rootへ未配布の場合だけ、`是正済み資源: <plugin rootからの相対パス> = <作業ツリー側の絶対パス>`の1行を資源ごとに含め、同じ行へ是正した欠陥とそれが委譲先の工程を止めることを併記する。委譲先はこの行が指す資源だけを作業ツリー側で実行する。

`<役割名>.subagent.md`を渡さない軽量起動の委譲先は、`agent-toolkit/share/rules-subagent.md`が届く範囲の外にある。自らコマンドを組み立てる委譲では次の規律を渡す（努力目標。遮断後の組み直しを減らす）。

- 初回しか観測できない出力と再取得の費用が高い出力は全量、終了状態、診断を保持する
- 既存ファイルの上書きと置換の直前に現行本文を読む
- シェルメタ文字はANSI-Cクォートか変数で保護し、二段シェルのコードと複数行コードはファイルから実行する
- ツール形式は最下層のヘルプかスキーマで確定し、既存パスは基準となる定義か実体検索から解決する
- `git rev-parse --short`は1回に1つのrevisionを渡す。Git識別子は`agent-toolkit:commit`の`references/git-identifier.md`に従う

## 入力の適格性と追送

初回の委譲プロンプトと稼働中の委譲先への追送は、載せる要素ごとに本節で判定する。`agent-toolkit:delegation`「送信」、`references/sending.md`および追送を中継する各工程の文書は、許容する入力を本節に委ねる。
載せてよいのは、委譲先が他の入力から得られない次の要素とする。`<役割名>.subagent.md`、agent定義、基準となる記録が持つ内容は、転記せず記録を参照させる。

- ユーザーの発話の逐語
- 作業の対象と、参照させる基準となる記録の絶対パスと対象ID
- 基準となる記録が持たない目的、要件、制約と完了条件
- 委譲元が現物で確かめた事実と、実行時に確定した値
- 委譲先の`<役割名>.subagent.md`、プロジェクト規範および適用スキルが定めていない認可と対象範囲
- 既存の規範が委譲プロンプトか追送へ含めるよう定める項目（前提を覆す追送で維持する成果と破棄する成果の範囲、`引き継ぎ記録先`、応答言語など）

委譲先の`<役割名>.subagent.md`、プロジェクト規範または適用スキルが既に決めている手段は、初回にも追送にも書き足すことを禁じる。重ねて書くと委譲先はどちらに従うかを判定できず、委譲元の誤った指定がそのまま成果物へ入る。

<例>
commitをまとめるか分けるか
fixupとautosquashを使うか
検証方法の選択
pushしてよいか
必須スキルの起動
</例>

手段を書くのは、ユーザーが手段を指定した場合と、目的・要件・制約の達成にその手段が必要であることを実装、公式仕様または実機結果から確定した場合（根拠を併記する）に限る。委譲元自身が選んだだけの実装手段を固定すると、委譲先の調査と単純な設計の選択が狭まる。
詳しさは`agent-toolkit:writing-standards`の`references/writing.md`「読み手別の追加注意点」のエージェント向け文書の項に従う。必須入力の形式とユーザーが指定した手段は省かずに渡す。

操作の許可または禁止は、対象リポジトリと操作を組にして示す。対象リポジトリとWI・計画を保存するprivate-notesは別の対象として扱う。
人間由来の要求を渡す場合は、採用した要求の原文と出所を`forwarded-user-input`標識の内側へ置き、起動前に原文と標識の双方が一致することを確かめる。自然文の引用だけでは、委譲先にとって出所が判定不能になる。

追送する要件は確定してから送る。確定した要件は、委譲プロンプトの前提（対象、範囲、外部可視の結果、判断基準）を覆す場合も先行応答を待たずに追送し、維持する成果と破棄する成果の範囲を同じ追送文へ示す。追送で成果を引き継げない場合だけ、終了させてから新しい委譲先を起動する。
稼働中の委譲先の停止は最終手段とし、停止で失われる書込み、未着の報告と文脈を確かめ、回収できる成果を回収してから停止する。

## 操作の制限と応答言語

委譲先の操作を制限する場合は、目的、対象資源および状態遷移で示し、`<役割名>.subagent.md`がその担当に必須と定める状態遷移と重ならない範囲に限る。コマンド名やサブコマンド名だけで禁止を表すと、同名の別目的の操作まで禁じ、委譲先が必須の状態遷移を省いたまま完了を報告する。

文書、コメントまたはWI本文の起草を委ねる場合は、現行plugin rootを解決して`<plugin root>/.venv/bin/python -m pyfltr.colloquial <起草ファイルの絶対パス>`の起動形を渡す。検出の解消か解消しない理由の記録と、結果の完了報告への記載も求める（努力目標）。辞書ファイルのパスは起動入力から外す。`<役割名>.parent.md`を持つ起動は対象外とする（手順と検証は`<役割名>.subagent.md`が定め、`extra_params`は宣言済みの入力だけを受け付ける）。

言語の指定の対象は、委譲先が委譲元へ返す完了報告と、委譲先が作成する成果物に限る。作業途中の出力は委譲元もユーザーも読まないため拘束の対象外とする。

- `agents_server`経由の起動: `share/agents-server-<mode>.md`が言語を定めるため、委譲プロンプトへ書かない
- `Agent`ツールやCodexのネイティブ委譲など`agents_server`を経由しない起動: `agent-toolkit/rules/01-agent.md`「使用言語」の言語を指定し、実行環境が英語で挿入した指示を受け取っても応答言語として引き継がない条件を含める。`<役割名>.subagent.md`かagent定義が同じ指定を持てば、それを指す1行目の命令で指定を満たす。どちらも渡さない委譲では`応答言語`を項目名とする名前付き入力で指定する

`<役割名>.subagent.md`を指定する起動の待機と再開の方針は、サーバーが採用したbackendに応じて`share/agents-server-<mode>.md`で伝えるため、委譲プロンプトの外へ置く。

## 引き継ぎ記録先

`<役割名>.subagent.md`が2つ以上の工程を順に実行する委譲では、`引き継ぎ記録先: <絶対パス>（新規）`か`引き継ぎ記録先: <絶対パス>（継続）`の1行を委譲プロンプトへ含める。

- `（新規）`か`（継続）`かは先行する担当がそのパスへ記録したかだけで決める（ファイルは委譲先が作成する）。新規か継続かを示さない行を受け取った委譲先は、不在のファイルの読取から始めてしまう
- パスは委譲元のセッションのmanaged-temp（`agent-toolkit:managed-temp`）直下のファイルとし、回収しない
- `agents_server`の`start`による`<役割名>.subagent.md`を指定する起動では`（新規）`の行を省略できる。サーバーが記録先を用意して委譲プロンプトへ加え、`handoff_record_path`で返す。`Agent`ツールなどサーバーを経由しない起動では委譲元が行を含める
- 委譲先が応答を停止して別の担当へ工程を引き継ぐ場合は、先の起動のパス（省略した場合は`handoff_record_path`の値）へ`（継続）`を付けて渡す

記録の内容は`references/handoff-record.md`が定める。

## 分離実行の受領物

委譲元の分岐が分離先の判別に依存する検証では、判別の結論に代えて、分岐が依存する観測値を逐語で返させる（結論だけでは分離先の誤りが観測不能になる）。コマンド実行では終了コード、終了シグナル、標準エラーの該当行（抽出条件は判別に用いる文字列で示す）を、読み取り専用の調査では一致件数、走査した対象、打ち切りの有無のうち分岐が依存するものを返させる。指定先は実行時の公開スキーマで確かめる（コマンド実行は要約方針、読み取り専用の調査は委譲プロンプト）。

実行上限を超える見込みの複数コマンドの連結は、コマンドごとに終了コードを別ファイルへ保存する形で`command`を組み、その内容を返すよう`summary_policy`へ指定する（連結が上限で強制終了すると後続の終了コードを失う）。上限を確定できなければ10分超の見込みを目安とする。複数の対象を受理する同一コマンドの1回の実行は対象外とする。
