# 基本委譲契約

単発の委譲では、起動前に対象、読取・書込権限及び完了条件を確定する。
委譲元と委譲先は独立した文脈で動作し、委譲先が引き継ぐ入力は起動文の内容だけとする。
委譲元の会話履歴、委譲元が読み込んだファイル、委譲元が起動したスキルは、この入力の外側にある。
委譲の手順を設計する主体は、この独立を前提として、1つの取り決めを1つの文書だけへ置く。
返却形式、応答言語、成果物の書式その他の受け渡しの取り決めは、その取り決めに従う主体が読む側の文書を正本とし、もう一方の文書へは正本を指す参照だけを置く。
委譲先の内部の分岐と判断手順は、委譲先側の文書だけが持つ。
同じ参照資料を双方へ読ませる指示は、両者がその資料を異なる判断へ用いる場合だけ置き、判断の差を条文へ書く。
同じ取り決めが2箇所にあると、一方だけを改訂した後にどちらが正本かを実行主体が決められなくなる。
起動文の構成と必須入力の列挙形式は`agent-toolkit:delegation`のSKILL.mdの`## 送信`を正本とする。
起動側が起動文へ載せる値に起因する欠落は、起動側が起動前に防ぐ。委譲先のタスク文書が要求する必須入力が起動文にそろっていること、絶対パスで示す入力のうち起動時点で作成済みのものが実在すること、委譲先が受け取った値から自ら解決して読むplugin配下の資源が実在することを、起動前に確認する。
読解対象として絶対パスで渡すファイルは、行数も起動前に確認して起動文へ載せる。行数に代えて、委譲先が取得する範囲（`offset`と`limit`に相当する範囲）を載せてもよい。行数と取得範囲のどちらかを確定できた対象だけを、読解対象として絶対パスで渡す。量の判断入力を持たない委譲先の最初の取得は切り詰め又は遮断で終わり、同じ取得の再発行が生じる。
起動文の本文が読解対象のファイルを名指しする場合も、そのファイルを絶対パスで書き、行数と取得範囲のどちらかを併記する。リポジトリ相対の表記と作業ディレクトリからの相対の表記は用いない。適用の対象は、読解対象を列挙する箇所に限らず、調査項目、制約、完成条件その他の起動文の本文が名指しするファイルの全体とする。解決の基準が起動文に無いと、委譲先は任意の基準で相対パスを解決し、実在しない対象へ操作を発行する。
操作の直前に判定する前提は、起動時に1回読む正本の列挙と分けて記載する。対象は、既存ファイルの全体上書きと文字列置換の直前に行う現行本文の取得と、編集操作の直前に行う必須スキルの起動とし、後者では対応表の所在を併記する。
待機表明の例外の適用可否も起動文へ明示する。適用する場合はそのsessionが自身の起動した委譲先の完了通知で自動再開する旨を、適用しない場合は待機対象の種別を問わず前景で終端を観測する旨を書く。待機対象の種別を前件とする形では、委譲先が適用可否を判定できない。
読み取り専用の調査を委譲する起動文へ、対象の本文の取得手段を書く。指定する手段は、実行環境が提供する読み取りツールの範囲指定と、出力先ファイルへのリダイレクト及び保存したファイルからの範囲指定の読み取りの2つに限る。同じ起動文へ、本文の取得には文脈行を付ける内容検索に代えてこの2つの手段を用いる旨を書く。一致件数と候補ファイルを先に確定する指定だけでは、候補を限定した後の本文取得で同じ切り詰めが生じるためである。本項が指定するのは、調査の結論を得る実装手段ではなく、受け取る情報の完全性を保つ取得の形である。このため、実装手段を起動文の既定の入力から外す後掲の規定とは適用範囲が別になる。取得手段を限定しない起動文では、委譲先が出力量の定まらない手段を選び、切り詰められた本文が網羅性を要する判断へ入る。
実在確認とは別に、起動文が参照する記録済みの比較基準と取り決めが起動時点の実体と一致することと、委譲先が自ら解決するPATH上のコマンド・plugin配下の資源の版が起動側の前提と一致することを、起動前に確認する。
一致しない場合は、起動文へ現在の実体から取得した値を渡すか、既存の実行経路の取り決めが許す形で前提と一致する経路を明示する。いずれも成立しない場合は委譲先を起動せず、不一致の対象と観測値を呼び出し元へ返す。
plugin配下の資源の確認は、起動側が同じ手順でrootを解決して行う検査とし、解決した絶対パスは起動側の内側に留める。委譲先は引き続き資源を自ら解決する。
実行可能資源の欠陥をそのセッションで配布元の作業ツリーへ是正し、是正後の版が稼働中のplugin rootへまだ配布されていない場合だけ、起動側は`是正済み資源: <plugin rootからの相対パス> = <作業ツリー側の絶対パス>`の1行を資源ごとに起動文へ含める。同じ行へ、是正した欠陥と、その欠陥が委譲先の工程を止めることを併記する。委譲先は、この行が指す資源だけを受け取った絶対パスで実行し、他の資源は自ら解決する。是正していない資源まで作業ツリー側から実行すると、配布済みの版との差異を検証しないまま工程が進む。
確認が成立しない場合は委譲先を起動せず、欠けていた入力項目と実在しなかった絶対パスを呼び出し元へ返す。
起動側は、入力の完備と実在の再確認を自ら済ませる（努力目標）。
委譲先へ差し戻しを残すのは、委譲先自身の実行環境に起因し起動側から観測できない事象に限る。

起動側の文書が、起動文の必須入力又は値の確定規則を別の文書へ委ねる場合は、その文書の該当節を全文読んでから値を確定する。担当種別、`model_type`その他の必須入力も、参照先を読んだうえで確定する。未読のまま推定して起動すると、委譲先が入力の不整合を検出して差し戻し、その工程が停止する。

起動前に、委譲先へ渡す方針が確定していることを判定する。判定は、委譲が確定する成果物の対象、範囲及び外部可視の結果について確認へ送るべき未回答の事項が解消していることと、直前に受け取った指摘による見直しが済んでいることで行う。未確定の事項が残る場合は、方針を確定してから起動する。

委譲元は、目的、要件、制約、確認済みの観測事実及び完了条件を起動文へ渡す。
起動文へ手段を書くのは、ユーザーが手段を指定した場合と、目的、要件若しくは制約の達成にその手段が必要であることを実装、公式仕様若しくは実機結果から確定した場合の2つとし、後者では根拠も併記する。
委譲元自身が選んだ実装手段は、この2つのどちらにも当たらない限り起動文の外へ置く。
根拠を確定していない手段を固定すると、委譲先の調査と単純な設計の選択が狭まり、誤った機構と将来の不具合を作り込む。

稼働中の委譲先へ指示を追送する場合は、追送する要件が確定しているかを判定する。確定していない要件は、方針を確定してから送る。確定した要件は、起動文の前提である対象、範囲、外部可視の結果又は判断基準を覆す場合も、先行応答を待たずに追送する。前提を覆す追送では、その委譲先が持つ成果のうち維持する範囲と破棄する範囲を同じ追送文へ示す。追送では成果を引き継げないと判定した場合だけ、その委譲先を終了させてから新しい委譲先を起動する。

稼働中の委譲先の停止は最終手段とする。停止の前に、その委譲先による作業ツリーへの書込み、未着の報告及びその委譲先が持つ文脈のうち、停止により失われる範囲を確認する。回収できる成果を回収してから停止する。

起動文へは、委譲先が呼び出し元へ返す完了報告と、委譲先が作成する成果物に用いる言語の指定を含める。指定する言語は`agent-toolkit/rules/01-agent.md`「使用言語」節が定める言語とする。言語の指定の対象は完了報告と成果物に限る。委譲先が作業の途中で出力する文章は、呼び出し元とユーザーのいずれも読まないためである。委譲先のタスク文書又はagent定義が同じ指定を持つ場合は、それを指す1行目の命令だけで指定を満たす。どちらも渡さない委譲では、`応答言語`を項目名とする名前付き入力で指定する。定義を変更できない汎用のサブエージェントでは、この入力が唯一の指定手段となるためである。

受信者のタスク文書が2つ以上の工程を順に実行すると定める委譲では、起動側が`引き継ぎ記録先: <絶対パス>（新規）`又は`引き継ぎ記録先: <絶対パス>（継続）`の1行を起動文へ含める。
先行する担当がそのパスへ記録しておらず受信者がファイルを作成する場合は`（新規）`、先行する担当が書いた内容を受信者が引き継ぐ場合は`（継続）`を付ける。
ファイルを作成するのは受信者であるため、`（新規）`と`（継続）`の別は先行する担当の記録の有無だけで決める。存在の有無を示さない行を受け取った受信者は、最初の行動としてそのパスの読取を発行し、不在の結果を受け取る。
絶対パスは、起動側が所有する管理対象一時領域の直下のファイルとする。
所有する領域が無い場合は`atk managed-temp create --prefix=handoff`で作成し、標準出力へ返る絶対パスの直下へファイルを置く。
セッションの管理対象一時領域が通知されている場合は`--session-root <通知された絶対パス>`を付けて作成し、その子領域はセッション終了時の回収へ委ねる。
独立して作成した領域だけを、委譲の全工程の完了後に`atk managed-temp cleanup --path <領域の絶対パス>`で回収する。
委譲先が応答を停止して別の担当へ工程を引き継ぐ場合は、同じ絶対パスへ`（継続）`を付けて後続の担当の起動文へ渡す。
委譲先がそのファイルへ記録する内容は`agent-toolkit/share/rules-subagent.md`「多段工程の引き継ぎ記録」が定める。

委譲先の操作を制限する場合は、制限を目的、対象資源及び状態遷移で示す。起動文と追送文へ書く制限は、受信者のタスク文書がその担当種別へ必須と定める状態遷移と重ならない範囲に限る。コマンド名、サブコマンド名その他の実装上の操作名だけで禁止を表すと、低水準の操作名が一致する別目的の操作まで禁止の範囲へ入り、受信者が必須の状態遷移を省いたまま完了を報告する。

委譲先が待機を表明して終了した場合の判別の根拠と、呼び出し元が再開を指示するかどうかは`references/waiting-and-monitoring.md`「待機区間の構成」を正本とする。

## 分離実行の受領物

分離実行で受け取る内容は、観測値の伝達と、観測値に基づく判別に分ける。
呼び出し元の分岐が分離先の判別に依存する検証では、判別の結論に代えて、分岐が依存する観測値を逐語で返すことを指定する。
指定先は、要約方針の入力を持つ`start_shell`では`summary_policy`とし、
その入力を持たない`start_explore`では起動プロンプトとする。
返させる観測値は起動形ごとに定める。
コマンドを実行する分離実行では、終了コード、終了シグナル及び標準エラーの該当行とする。
該当行の抽出条件は、判別に用いる文字列で示す。
読み取り専用の分離実行では、一致件数、走査した対象、打ち切りの有無のうち分岐が依存するものとする。
本項が定めるのは分離実行へ渡す指定の内容であり、分離実行の返し方は現行のままとする。
判別の結論だけを受け取ると、分離先の判別の誤りを呼び出し元が観測できなくなる。

分離先がコマンドを実行するツールの実行上限を超える見込みのコマンドは、コマンドごとに実行を分ける。
各コマンドの終了コードをコマンドごとの別ファイルへ保存する形で`command`を組み立て、
保存したファイルの内容を返すことを`summary_policy`へ指定する。
実行上限を確定できない場合は、所要時間が10分を超える見込みのコマンドを本項の対象とする。
本項の対象は複数のコマンドの連結に限り、複数の対象を受理する同一コマンドの1回の実行は対象の外に置く。
連結した実行が上限で強制終了すると、後続のコマンドの終了コードを取得できなくなる。
