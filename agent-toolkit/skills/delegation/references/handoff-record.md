# 多段工程の引き継ぎ記録

本書は委譲プロンプトで`引き継ぎ記録先`を受け取った委譲先が、そのファイルへ書く内容と更新の契機を定める。記録するのは、その行を受け取った委譲に限る。

`share/work-contract.md`の現行の作業契約を同じファイルへ統合し、追加入力の分類・整理と各工程境界の再読にも使う。

記録の目的は、委譲先が応答を停止した後に起動する担当が、そのファイルを1回読むだけで残る工程へ着手できることである。完了した工程、確定した判断、残る工程と再開位置に加えて、後続の担当が再走査しなければ得られない次の値を残す。

- 確認済みの作業ツリーの絶対パスと、残る工程が使う成果物（原稿、証拠、調査記録など）の用途、絶対パス、所属リポジトリ
- 計画なしでWI実装commitを作成した場合は、`agent-toolkit:commit`の`SKILL.md`「WI実装commitの対応」で残した、引き継ぎ記録と同じstemの対応記録ファイル（`<stem>.wi-commits.jsonl`）の短縮OIDとAWI集合の対応。取得と履歴変更後の継承も同節に従う
- 存続中の外部プロセスとバックグラウンドタスクの種別、安定した実行識別子、対象コマンド（認証情報は除く）
- `agents_server`で起動した`session_id`と、それぞれ観測を試みたか

`（新規）`なら読取をせず最初の記録を書き、`（継続）`なら最初に全文を読む。以後は工程の区切りごとと、外部プロセスかバックグラウンドタスクの起動直後、成果物を新しいパスへ初めて保存した直後、`session_id`の受領直後とその観測を試みた直後に、現行内容を取得してから上書きする。終了を直接照会で確かめた対象は次の更新で存続中から除く。
