# 多段工程の引き継ぎ記録

本書は`agent-toolkit/share/rules-subagent.md`が定める、起動文で`引き継ぎ記録先`を受領した委譲先の記録項目と更新契機の正本である。
起動文で`引き継ぎ記録先`を受領した委譲先が全文読む。起動側は当該行を起動文へ含める義務だけを`references/base-contract.md`から受け取り、本書を読まない。

起動文が`引き継ぎ記録先`として絶対パスを受領した委譲先は、当該パスのファイルへ到達点を記録する。
記録する項目は次の9つとする。

- 完了した工程
- 確定した判断
- 残る工程
- 再開位置
- `git -C <起動時のcwd> rev-parse --show-toplevel`が終了コード0で返した、確認済みの作業ツリーの絶対パス
- 残る工程が使用する成果物の用途と絶対パス
- 記録する各成果物が属するリポジトリの作業ツリーの絶対パス、又は当該成果物がいずれのリポジトリにも属さないこと
- 存続中の外部プロセス及び背景ジョブの種別、安定した実行識別子並びに対象コマンド
- 当該委譲先が`agents_server`で起動した`session_id`と、各`session_id`について観測（`wait`による終端の受領、又は`kill`による破棄）を試みたかの対応

初回の記録では、当該パスのファイルを委譲先自身が作成するため、現行内容を取得せずに書き込む。
2回目以降の更新では、工程の区切りごとに対象ファイルの現行内容を取得してから同じファイルを上書きする。
外部プロセス又は背景ジョブの起動結果を受領した直後にも記録を更新する。
`session_id`を受領した直後と、当該`session_id`への観測を試みた直後にも記録を更新する。
直接照会で終了を確認した対象は、次の更新で存続中の対象から除く。
認証情報を実行識別子と対象コマンドのいずれにも転記しない。
記録の粒度は、当該委譲先が応答を停止した後に起動する担当が、当該ファイルの1回の読み取りだけで残る工程へ着手できる粒度とする。
当該行を受領しない委譲では本書の記録をしない（厳守規定。到達点が委譲先のコンテキストだけに存在すると、後続の担当が成果物とGit状態の再走査で到達点を再構成する）。
