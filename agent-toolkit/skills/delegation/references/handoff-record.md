# 多段工程の引き継ぎ記録

本書は、委譲プロンプトで`引き継ぎ記録先`の指定を受け取った委譲先に向けて、引き継ぎファイルへ記録する内容と更新のタイミングを定める。この記録は、プロンプトで該当行を受け取った委譲先だけが作成・更新する。

記録を担当する委譲先は、担当範囲の目的・要件と、担当範囲の要求を示す原本の所在や識別子、および現時点の結論を引き継ぎ記録へ記入する。追加入力の整理や、各工程の境界で状況を再確認する際にもこの記録を活用する。

記録の目的は、委譲先が応答を停止した後に後続の担当が起動された際、このファイルを一度読むだけで残りの工程へスムーズに着手できるようにすることである。完了済みの工程、確定した判断、残りの工程と再開位置を記録する。さらに、後続の担当が改めて探索しないと取得できない次の情報も記載しておく。

- 確認済みの作業ツリーの絶対パス、および後続工程で使用する成果物（原稿、検証証跡、調査記録など）の用途、絶対パス、所属リポジトリ
- 計画ファイルを作成せずにWI実装commitを作成した場合は、`agent-toolkit:commit`の`SKILL.md`「WI実装commitの対応」に従って出力した対応記録ファイル（引き継ぎ記録と同じstemを持つ`<stem>.wi-commits.jsonl`）の短縮OIDとAWI集合の対応関係。情報の取得や履歴変更後の引き継ぎ手順も同節に従う
- 現在も動作している外部プロセスやバックグラウンドタスクの種別、安定した実行識別子、および対象コマンド（認証情報は含めない）
- `agents_server`で起動した`session_id`の一覧と、それぞれの状態観測を試みたかどうかの記録

指定が`（新規）`の場合は既存ファイルを読み込まずに最初の記録を作成し、`（継続）`の場合はまず全文を読み込んで状況を把握する。その後は、要求内容、再開位置、後続担当が必要とするリソースの参照先などが変化したタイミングで更新する。
計画や検証記録から確認できる進捗や結果は、内容を重複して書き写さず原本を参照する。引き継ぎに必要な実行識別子や稼働中のリソース情報は維持し、直接の照会で終了を確認できた対象は次回の更新時に一覧から除去する。
