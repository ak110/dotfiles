# 多段工程の引き継ぎ記録

本書は`agent-toolkit/share/rules-subagent.md`の定めに従い、委譲プロンプトで`引き継ぎ記録先`を受け取った委譲先の記録項目と更新契機を定める。
本書の読み手は委譲プロンプトで`引き継ぎ記録先`を受け取った委譲先であり、読む時点は`agent-toolkit:delegation`の読込表が定める。委譲元が`references/base-contract.md`から受け取るのは、その行を委譲プロンプトへ含める義務だけである。

委譲プロンプトが`引き継ぎ記録先`として絶対パスと新規・継続の別を示した委譲先は、そのパスのファイルへ到達点を記録する。
記録が満たす条件は、委譲先が応答を停止した後に起動する担当が、そのファイルの1回の読み取りだけで残る工程へ着手できることとする。
完了した工程、確定した判断、残る工程と再開位置に加えて、後続の担当が自ら再走査しなければ得られない次の値を残す。

- 確認済みの作業ツリーの絶対パスと、残る工程が使用する成果物の用途、絶対パスおよび所属リポジトリ
- 計画なしでWI実装commitを作成した場合は、`agent-toolkit:commit`の`SKILL.md`「WI実装commitの対応」の記録の手段で残した完全OIDとAWI集合の構造化した対応。取得と履歴変更後の継承も同節に従う
- 存続中の外部プロセスおよびバックグラウンドタスクの種別、安定した実行識別子ならびに対象コマンド
- 委譲先が`agents_server`で起動した`session_id`と、各`session_id`について観測を試みたかの対応

初回の記録では、委譲先自身がそのファイルを作成するため、現行内容を取得せずに書き込む。
委譲プロンプトが`（新規）`を示す場合は、読取を発行せずに最初の記録を書き込む。
委譲プロンプトが`（継続）`を示す場合だけ、最初にそのファイルの全文を読む。
2回目以降の更新では、工程の区切りごとに対象ファイルの現行内容を取得してから同じファイルを上書きする。
外部プロセスまたはバックグラウンドタスクの起動結果を受け取った直後にも記録を更新する。
`session_id`を受け取った直後と、その`session_id`への観測を試みた直後にも記録を更新する。
直接照会で終了を確認した対象は、次の更新で存続中の対象から除く。
実行識別子と対象コマンドには、認証情報を除いた値を書く。
`引き継ぎ記録先`の行を受け取らない委譲では、本書の記録を省く。
到達点が委譲先のコンテキストだけに残ると、後続の担当が成果物とGit状態の再走査で到達点を組み立て直すことになる。
