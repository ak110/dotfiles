# 多段工程の引き継ぎ記録

本書は、委譲プロンプトで`引き継ぎ記録先`の指定を受け取った委譲先に向けて、引き継ぎファイルへ記録する内容と更新のタイミングを定める。
この記録は、プロンプトで該当行を受け取った委譲先だけが作成・更新する。

後続の担当は、起動時の依頼、追送、会話の流れ、全体作業契約、計画とGitから、目的・要件・完了した工程・判断と残りの工程を復元する（`agents_server`の引き継ぎ起動もこれらを読む）。
引き継ぎ記録には、それらから復元できない次の値と、他の規範や役割契約が引き継ぎ記録へ書くと定めた項目（延期した条件、見込みの変化など）だけを書く。

- 現在も動作している外部プロセスやバックグラウンドタスクの種別、安定した実行識別子、および対象コマンド（認証情報は含めない）
- `agents_server`で起動した`session_id`の一覧と、それぞれの状態観測を試みたかどうか
- 後続工程で使うGit管理外の成果物（原稿、検証の保存出力、調査記録など）の用途と絶対パス
- 計画ファイルを作成せずにWI実装commitを作成した場合の、対応記録ファイル（引き継ぎ記録と同じstemの`<stem>.wi-commits.jsonl`）の所在。
  出力・取得・履歴変更後の手順は`../../commit/references/commit-wi-records.md`「WI実装commitの対応」に従う
- 計画が無い作業で、途中報告のAWI化ステータスを`予定`とした改善点の対象、区分と再開条件。
  確定の手順は`agent-toolkit:report-completion/SKILL.md`「工程」の手順5に従う

書く値が無い間は、ファイルを作成しない。
値が変わった時に該当する項目を書き換える。
上記の項目（役割契約が定める項目を含む）に当たらない目的・要件や原本の写し、作業の経緯、判断の説明、進捗は書かない。
直接の照会で終了を確認したプロセスや`session_id`は、次の更新で一覧から除く。
指定が`（継続）`の場合は、最初に記録の全文を読む。
不在を確かめた場合は前任に書く値が無かったものとして続け、役割契約が記録を前提とする値を読めない場合だけ不足として委譲元へ返す。
それ以外で読めない場合は、起動本文・会話・成果物の現物から復元し、復元できない値を委譲元へ返す。
