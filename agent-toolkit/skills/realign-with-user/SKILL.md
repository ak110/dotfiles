# ユーザーとの認識合わせ

本スキルはメインエージェントがユーザーの目標と問題の理解を言葉にして確かめる手順を提供する。
まず現在の依頼とユーザーの発話を読み、理解している目標と問題を自分の言葉で言い換える。
採用案の見直しは`agent-toolkit:review-standards`の`references/reviewee.md`「ユーザー指摘の受領」に、回答後の処置は`agent-toolkit:user-confirmation-and-report`「回答後の状態遷移」に従う。

1. ユーザーが達成したい目標と、解決しようとしている問題を、それぞれ自分の言葉で提示する。
   ユーザーの発話から得た理解と、実行主体が補った前提を区別する。
2. その理解が合っているか、その場で実行環境の構造化質問を使ってユーザーへ確認する。
   問う対象は目標と問題の理解とし、採用案の承認へ置き換えない。
   メインが`agent-toolkit:user-confirmation-and-report`を起動し、言い換えた理解を入力として
   「確認要否の判定」「手段の選択」に従って質問を構成し、実際の回答を受け取る。
   Claude Codeは`AskUserQuestion`、Codexはホストのモード・用途制限に適合する構造化質問を使う。
3. 回答が元の依頼の目的・要件と自分の理解に一致するか確かめる。
   `agent-toolkit/share/rules-main.md`「ユーザー発話の解釈」と
   `agent-toolkit:review-standards`の`references/reviewee.md`「ユーザー指摘の受領」に従い、
   採用済み案の縮小・撤回・置換を含めて次に行う処置を確定する。

協調モードと自律モードの双方で、理解を提示してその場で確認する。
ユーザー割り込みの扱いは`agent-toolkit/share/rules-main.md`「協調と自律」に従い、
関係のない工程の実行モードは保持する。
自律モードでの発行と回答が無い場合の扱いは、`agent-toolkit:user-confirmation-and-report`「手段の選択」の表に代えて、実行環境ごとに次のとおりとする。

- `atk wi process-loop`から起動したセッションのように、実行環境が回答期限を与える場合は、その場で質問する。期限を超えて回答が無ければ、同スキルの`references/main-behavior.md`「未確定判断の保留と暫定判断」に従ってUWIへ記録し、回答を要する元項目だけを保留する
- 手動で起動したClaude Codeのように回答期限が無い場合も、その場で質問して回答を待つ。認識合わせはユーザーの割り込みや是正の直後に起動され、理解を確かめる回答を得ることが本スキルの目的だからである
- 構造化質問を発行できないCodex Default modeでは、`agent-toolkit/share/rules-main.codex.md`の自律モードの例外に従い、質問に代えて提示する理解と問いをUWIへ記録し、回答を要する元項目だけを保留する
質問の発行成功や初期選択を回答として扱わず、回答に依存する処置は実回答まで確定しない。
委譲先で認識合わせが必要と分かった場合は、確認事項を委譲元へ返す。
