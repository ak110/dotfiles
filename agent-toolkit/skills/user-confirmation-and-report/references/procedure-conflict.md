# 手順どおりに進められない場合

本書は`agent-toolkit/rules/01-agent.md`が定める、手順・規範の両立不能と前提の不成立を観測した場合の判定順を定める。

手順・規範は`agent-toolkit/rules/01-agent.md`の「役割分担」「判断指針」が示す指針を達成する手段であり、手順どおりに進められないときも、目的から次の工程を選んで依頼の完了へ進める。適用対象は同「方針が衝突する場合の優先順位」で確定してから本書を使う。

本書は次のいずれかを観測し、優先順位でも次の1工程が定まらない場合に適用する。

- 適用範囲が重なる2つ以上の手順・規範が、同じ場面で両立しない動作を要求する
- 手順が前提とする対象・コマンド・状態が実在せず、代替手段も未定義である
- 手順が定めた取得手段の値が、手順の目的を満たさない

名指しのskill・command・fileが実在しない場合は、名前の類似ではなく、規範が定める役割・責務・所有者から同じ成果を担う候補を導く。取得値が目的に合わない場合も、手順の目的から入力を導き直す。

次の順に判定し、最初に成立した終端を選ぶ。

1. 委譲先が受け取った依頼文と適用中のスキル規則が矛盾する場合、または権限・認証が不足する場合は、`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」に従って委譲元へ差し戻す
2. 「確認を要する事項」に該当する場合は、`SKILL.md`「確認要否の判定」に従ってユーザー確認する
3. ユーザーの目的・要件と硬い制約を維持したまま次の1工程を実行できる場合は、その工程を実行して継続する。手段が複数ある場合はQCDで選び、目的から工程が一意に決まれば自ら実施して判断根拠を報告する。選好・認可に依存する部分は判定順2で扱う。従える規範や手段の方針からQCDの明らかな悪化を理由に外れる場合も、`agent-toolkit/rules/01-agent.md`「QCDと3段判定」と`SKILL.md`「確認要否の判定」に従う
4. いずれの手段でも目的・要件と硬い制約を維持できない場合は、その操作へ着手せず、依存しない工程を継続する

下位の手順・`<役割名>.subagent.md`が差し戻しまたは確認の対象を限定列挙していても、本書の適用条件を満たす事象は判定順1と2の対象とする。その列挙は列挙した事象で差し戻しを必須とする規定として扱う。

選んだ終端と判断根拠は同一ターンで報告し、判断に用いた規範の所在と該当条文を示して、条文の明示要求と自身の解釈を区別する。2つ以上の手順・規範が両立しない場合は、そのファイル名と節名を報告へ含め、矛盾の是正を`agent-toolkit/rules/01-agent.md`「完遂と先送り」の手順で登録する（条文の修正前の由来の確定は`references/conflict-resolution.md`）。手順の前提が実在しないだけで矛盾が無い場合は報告に留める。委譲先の返却は`agent-toolkit/share/rules-subagent.md`「手順どおりに進められない場合の返却」が定める。
