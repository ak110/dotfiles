# 手順どおりに進められない場合

本書は`agent-toolkit/rules/01-agent.md`が定める、手順・規範の両立不能と前提の不成立を観測した場合の判定順を定める。

手順・規範は`agent-toolkit/rules/01-agent.md`の「役割分担」「判断指針」の各節が示す指針を達成する手段であり、同「方針が衝突する場合の優先順位」で適用対象を確定した後に適用する。
手順どおりに進められないときも、目的から次の工程を選んで依頼の完了へ進める。

次のいずれかを観測し、その優先順位でも次の1工程が定まらない場合に本書を適用する。

- 適用範囲が重なる2つ以上の手順・規範が、同じ場面で両立しない動作を要求する
- 手順が前提とする対象・コマンド・状態が実在せず、その手順に代替手段の定めがない
- 手順が定めた取得手段が値を返したが、その値が手順の目的を満たさない

名指しのskill・command・fileが実在しない場合は、規範が定める役割・責務・所有者から同じ成果を担う候補を導く。名前の類似は導出条件の対象外とする。
取得値が目的に合わない場合も、手順の目的から入力を導き直す。
対象や入力が一意に定まれば後掲の判定順で後続工程へ渡し、定まらなければ同じ判定順で確認・差し戻しを選ぶ。

適用時は次の順に判定し、最初に成立した終端を選ぶ。

1. 委譲先が受け取った依頼文と適用中のスキル規則が矛盾する場合、または権限・認証が不足する場合は、
   `agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」に従って委譲元へ差し戻す
2. 「確認を要する事項」に該当する場合は、`references/judgment.md`に従ってユーザー確認する
3. ユーザーの目的・要件と硬い制約を維持したまま次の1工程を実行できる場合は、その工程を実行して継続する。
   手段が複数ある場合は`agent-toolkit/rules/01-agent.md`「判断指針」のQCDで選ぶ。
   両立不能や想定外の状況でも目的から工程が一意に決まれば、自ら実施し末尾の報告へ判断根拠を残す。選好・認可に依存する場合は判定順2で扱う。
   従える規範からQCDの明らかな悪化を理由に外れる場合は、同「QCDと3段判定」に従い、規範からの逸脱は報告、手段の方針からの逸脱は事後承認とする
4. いずれの手段でもユーザーの目的・要件と硬い制約を維持できない場合は、その操作へ着手せず、依存しない工程を継続する

下位の手順・`<役割名>.subagent.md`が差し戻しまたは確認の対象を限定列挙している場合も、
本書の適用条件を満たす事象は判定順1と2の対象とする。
その列挙は列挙した事象で差し戻しを必須とする規定として扱う。

選んだ終端と判断根拠は同一ターンで報告する。
報告には判断に用いた規範の所在と該当条文を示し、条文が明示する要求と自身の解釈を区別して書く。
2つ以上の手順・規範が両立しない場合は、その規範のファイル名と節名を報告へ含め、
矛盾そのものの是正を`agent-toolkit/rules/01-agent.md`「完遂と先送り」が定める手順で登録する。是正で条文を修正する前の由来の確定は`references/conflict-resolution.md`に従う。
登録の対象は、2つ以上の手順・規範が両立しない場合に限る。手順の前提が実在しないだけで矛盾が無い場合は、報告に留める。
委譲先の返却は`agent-toolkit/share/rules-subagent.md`「手順どおりに進められない場合の返却」が定める。
