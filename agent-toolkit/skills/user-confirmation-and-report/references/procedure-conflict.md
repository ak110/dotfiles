# 手順どおりに進められない場合

本書は、`agent-toolkit/rules/01-agent.md`に基づき、手順や規範の両立不能、または前提条件の不成立を観測した際の判定順序を定める。

手順や規範は、`agent-toolkit/rules/01-agent.md`の「役割分担」および「判断指針」が示す原則を達成するための手段である。そのため、手順どおりに進められない状況であっても、本来の目的に立ち返って次の工程を選択し、依頼の完遂を目指す。なお、適用対象の優先順位は同書の「方針が衝突する場合の優先順位」であらかじめ確定させてから本書を適用する。

本書は、以下のいずれかの事象を観測し、規定の優先順位を用いても次の工程を決定できない場合に適用する。

- 適用範囲が重複する2つ以上の手順や規範が、同じ状況において両立しない動作を要求している
- 手順が前提としている対象、コマンド、状態が実在せず、代替手段も定義されていない
- 手順で指定された取得手段による値が、手順本来の目的を満たさない

指定されたスキル、コマンド、ファイルが存在しない場合は、規範が定める役割、責務、所有者の観点から、同様の成果を達成できる代替候補を導き出す。取得した値が目的に合致しない場合も、手順本来の目的から必要な入力を再考する。

以下の優先順位に従って判定し、最初に成立した対応を選択する。

1. 委譲先が受領した依頼文と適用中のスキル規則が矛盾する場合、あるいは必要な権限や認証が不足している場合は、`agent-toolkit/share/rules-subagent.md`「返却形式の受け渡し」に従って委譲元へ差し戻す。
2. 「確認を要する事項」に該当する場合は、`SKILL.md`「確認要否の判定」に従ってユーザーへ確認する。
3. ユーザーの目的、要件、必須制約を維持したまま次の工程を実行できる場合は、その工程を実行して作業を継続する。複数の手段が存在する場合はQCDの観点から選択し、目的から工程が一意に定まる場合は自身で判断して実施した上で、その判断根拠を報告する。ユーザーの選好や承認が必要な論点については、判定順2に従って確認する。遵守すべき規範や手段の方針からQCDの明白な悪化を理由に外れる場合も、`agent-toolkit/rules/01-agent.md`「QCDと3段判定」と`SKILL.md`「確認要否の判定」に従う。
4. いずれの手段を用いても目的、要件、必須制約を維持できない場合は、その操作に着手せず、その操作を待たずに進められる工程を継続する。

下位の手順書や`<役割名>.subagent.md`において、差し戻しや確認の対象が限定して列挙されている場合であっても、本書の適用条件を満たす事象は判定順1および2の対象とする。その限定列挙は、該当する事象について差し戻しを必須とする規定として解釈する。

選択した対応方針とその判断根拠は同一ターン内で報告し、判断に用いた規範の所在と該当条文を明記して、条文の明示的な要求とエージェント自身の解釈を明確に区別する。2つ以上の手順や規範が両立しない場合は、そのファイル名と節名を報告に含め、矛盾の解消を`agent-toolkit/rules/01-agent.md`「完遂と先送り」の手順に従って登録する（条文修正前の由来特定は`references/conflict-resolution.md`に従う）。手順の前提条件が存在しないだけで規範間の矛盾がない場合は、報告にとどめる。委譲先の返却手順は、`agent-toolkit/share/rules-subagent.md`「手順どおりに進められない場合の返却」が定める。
