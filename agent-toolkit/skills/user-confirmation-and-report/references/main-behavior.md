# メインエージェントの確認・UWI運用

本書は`agent-toolkit:user-confirmation-and-report`が扱う、Claude Codeメインが利用上限の猶予通知を受けたときの続行と再開、
メインエージェントの未確定判断の保留、暫定判断、事前承認の合意判定、および回答の受領を定める。

## 利用上限の猶予通知を受けたときの続行と再開

利用上限の猶予通知は、Claude Codeが会話へ挿入する注記のうち、利用上限への到達が近く作業が打ち切られ得ることを示すものを指す。Claude Codeメインがこの通知を受けた場合は、通知をホストの挿入注記として`01-agent.md`「方針が衝突する場合の優先順位」を適用し、次の順に進める。

1. 通知の受領、実行済みの成果、未完了工程と、実際に打ち切られた場合の再開位置をユーザーへ伝える。残工程は適用中の工程の終了条件と実行結果を比べて確定する。強制打ち切り後には書き込めないため、この時点で下記の再開情報を保存し、保存先の絶対パスも報告へ含める。
2. 通知が無い場合と同じ工程を続ける。現在の工程の後も、仕上げ、検証、公開、完了報告、振り返りなど依頼に必要な後続工程へ進む。未実施工程を残工程として維持し、残る工程がある場合はその工程を列挙した報告をする。
3. 工程が進むたびに再開情報を更新する。実際に中断された後に再開指示を受けた主体は、前回の報告または再開指示が示す保存先を読み、成立済みの認可と成果を引き継いで最初の未完了工程から続行する。

再開情報は計画がある場合は`agent-toolkit:plan-mode`の計画ファイルの`## 進捗ログ`へ、既存の引き継ぎ記録がある場合はその記録へ残す。いずれも無い場合は、`agent-toolkit:managed-temp`で確定したセッションのmanaged-tempの中にMarkdownの再開記録を保存する。
目的、認可の内容と出所、対象worktreeの絶対パス、成果物の絶対パスまたはcommit、完了した工程と検証結果、順序付きの未完了工程、最初の未完了工程を次の主体が読める形で記す。
計画を使う再開では`agent-toolkit:plan-mode`の進捗ログの読取手順に従う。その他の再開では記録を全文読み、記録した成果と現在の実体を比べてから次の工程を選ぶ。記録の保存先や認可を復元できない場合は、不足する情報をユーザーへ確認する。

猶予通知を受けた後も権限とツール契約を守り、ホストが強制打ち切りした場合は中断として扱う。
ユーザーが中止を指示した場合はその指示に従う。

## 未確定判断の保留と暫定判断

「確認を要する事項」が挙げる事項は、いずれのモードでもユーザー確認へ送る。
ユーザー確認を発行できる実行主体は、自律モードで回答を得られない場合に`agent-toolkit:wi-standards`を起動し、
確認事項をUWIとして記録して暫定判断で続行する。
自律モードで回答を得られないと判定する契機は実行環境により異なる。
`askUserQuestionTimeout`のような回答期限を提供する実行環境では、その期限の超過を契機とする。
期限を無効化する条件が成立する実行環境は、期限を提供しない実行環境として扱う。
期限を提供しない実行環境では、応答を得られないと判断した時点を契機とする。
協調モードではユーザーの後続発話を待ち、回答期限はUWIへの切替条件に含めない。
同一セッションでユーザー確認が回答なしで終了したことを観測した自律モードで動く主体は、以降の確認をUWIへ記録し、その回答を得るまで進められない元項目だけを`atk wi hold`で保留する。自身が処理中（`processing`）の元項目は`atk wi hold --state=processing <元項目のファイル名>`で保留する。
進行を止める場合も確認事項を記録してから止める。確認事項を残さずに停止すると、依頼された工程が完了しない。
必須の外部資料を取得できない場合は、ユーザー確認で資料の提供を依頼し、資料に依存する対象成果物だけを保留する。
暫定判断は要求範囲を保った対象成果物の確定にだけ用いる。資料を得ないまま続行する判断は要求範囲の縮小として、他の論点と分けてユーザー確認する。
協調モードでは資料か要求範囲への明示回答を得てから対象成果物を確定する。
自律モードではUWIへ保留した元項目のファイル名と対象の説明、保留理由、必要な資料と回答で変わる結果を記録し、その元項目を保留したうえで依存しない工程だけを続行する。解除条件と再開工程はユーザーの判断に使わないため、元項目の計画の進捗ログか引き継ぎ記録へ残し、回答後の担当がUWIの元項目からその記録をたどれるようにする。
キュー項目の保留操作と再開手順は`agent-toolkit:wi-standards`「状態と依存」に従う。要求を縮小した暫定成果物の確定と、別の論点への合意を要求範囲の縮小へ拡張することは、この手順で防ぐ。

## 事前承認の合意判定

`references/judgment.md`「認可を要する操作」が列挙する承認対象のうち、`references/approval-scope.md`が事前承認と判定した操作は、合意を得るまで暫定判断の対象から除く。
協調モードで応答が無い場合と、自律モードでUWIへ記録した場合のいずれも同じ扱いとする。
可逆な代替手段を採用するか、その操作を保留して依存しない工程を続行する。
保留の記録、元項目の`hold`への移動および再開は、必須の外部資料を取得できない場合と同じ手順で行う。
同書が事後承認と判定した操作と、成立した承認の範囲へ収まる操作は本除外の対象外とする。
この除外により、合意そのものを暫定判断で補って事前承認の操作へ着手する余地をなくす。

## 回答の受領

対話中にUWIへの判断内容を受け取った場合、実行主体はその内容を回答として記録する。保留中の確認事項への判断内容も同様に記録する。
記録の後に対応する変更へ着手できるのは、`agent-toolkit:process-wi`などの専用手順による起動か、ユーザーの明示指示がある場合に限る。
専用手順の実行中に、現在の主題を保留していたUWIの回答を受け取った場合は、回答の記録に続けて、そのUWIが保留していた保存済み計画または処理工程を同じセッションで再開する。
その要求とその計画に属する未完了の範囲は、同じセッションの中で扱い、追随するAWIの登録と追加の採否確認へ分けずに完了する。
回答から生じた要求のうち、元の要求範囲へ含まれないものだけを別のキュー項目とする。
