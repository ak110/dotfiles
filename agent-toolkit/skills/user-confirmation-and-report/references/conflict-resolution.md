# 規範どうしが矛盾する場合の由来確定

本書は、`agent-toolkit/rules/01-agent.md`「方針が衝突する場合の優先順位」に基づき、規範同士が矛盾した際の手順を定める。

規範同士に矛盾が生じた場合は、優先順位を適用する前に各条文の由来を特定する。由来を特定しないまま優先順位を適用すると、ユーザーの指示に由来する条文を下位の規範として誤って扱い、すでに合意された要件を取り消してしまう恐れがある。
`git log -S`などを用いて該当の変更を導入したコミットを特定し、ユーザーの明示的な指示によるものか、エージェント側の判断によるものかを判別する。対応するキュー項目や計画ファイルが存在する場合は、その項目の`source`や明示的な由来、計画ファイルの実施内容にある由来欄を参照して判断材料とする。
由来を特定できない場合であっても、由来が不明であることだけを理由に修正の可否を安易にユーザーへ質問することは避ける。現在の明示的な要求、判断の記録、優先順位を確認した上で、`SKILL.md`「確認要否の判定」を適用する。目的、要件、結果、既存の承認を維持できる修正であれば、エージェント自身で確定して報告する。一方で、合意済みの目的側の要求を取り消す修正や、ユーザー固有の資料や判断が必要となる修正については、必要な論点に絞ってユーザーへ確認する。
本書が対象とするのは矛盾する条文自体の修正である。作業を進める際にどちらの規範に従うかについては、`references/procedure-conflict.md`の判定順に従う。
