# grilling

本書を使う工程が定める場面でユーザーとの共通理解へ到達するための質問ラウンドを扱う。
確認事項の扱いと、質問ラウンド後の工程は本書を使う工程が定める。

## 確認対象

確認対象を列挙する前に、同じスキルの`SKILL.md`「確認要否の判定」を各候補へ適用する。

依頼と成立済みの合意から、目的・範囲・結果・制約・優先順位などを整理し、未確定判断と依存関係を列挙する。
確認対象は`SKILL.md`「確認要否の判定」3で選び、程度・裁量の具体化にも同じ判定を使う。
WI作成工程（`agent-toolkit:add-awi-by-user`などでAWIを登録する時点）で本書を使う場合は、登録する要求を処理する計画・実行の工程が判断を要する要件・意図の曖昧さ（完成条件の境界、外部から観測できる挙動、対象範囲の端、除外）も列挙し、同じ質問ラウンドで全件確認する。後続工程へ残すのは、登録時点の調査で現れず処理時に初めて判明する曖昧さに限る。登録時に確認できた曖昧さを処理工程へ残すと、自律モードの処理で元項目が保留され、回答を待つ間その要求が進まない。
環境上の事実、既存コード、利用可能なツール、ライブラリ仕様など自分で調査できる事項は、自ら調べて確定する。
ユーザーが判定基準を示した集合に属する対象と、その集合から派生する対の対象（その対象を前提とする規範条文、テスト、設定など）へ同じ基準を当てはめる判断は、起草者が確定する。方針の選択肢として質問するのは、基準が当てはまるかを一意に決められない対象について、判定を分ける条件だけとする。
要求間の両立不能、方針の不一致・例外、実現に必要な未指定値も確認対象に含める。
両立する要求でも例外が残る場合は、その不一致と規約・運用の継続費用を確認本文へ書く。
協調モードのリポジトリ変更では、`agent-toolkit:user-confirmation-and-report`の`references/publish-scope.md`「公開範囲の確認」に従って着手前の公開範囲を質問ラウンドへ含める。依頼文が範囲を指定している場合は、その指定を使う。

## 質問ラウンド

判断ごとに独立した質問を作成し、未回答判断へ依存しない質問を同じラウンドで提示する。回答後に依存関係を更新し、依存する質問は次のラウンドへ送る。
概念名・画面ラベル・質問の説明語などの候補は`agent-toolkit:writing-standards`の`references/defined-names.md`「命名の方針」に従い、既存用例と意味、検索範囲を添える。
命名・用語・表記の方針を定める依頼では、同じ範囲の既存名も列挙し、方針に反するものへ適用するかを「確認対象」の基準で判定する。
指定語の変更は`references/user-utterance.md`に従って確認する。別の質問に載せた例示への黙認は、その判断の回答と扱わない。
調査の完了待ちで保留するのは、その調査結果を必要とする質問だけとし、他の確認は進める。

## 質問表示

`SKILL.md`「手段の選択」の手段で提示する。
質問を提示したら、そのラウンドの回答を待ってから次のラウンドへ進む。

## 終了条件

確認を終了する条件は、前記の判定で確認を要する未回答事項と、その回答を妨げる未調査の事実がいずれも残っていないことだけとする。

## 終了時報告

質問せずに自分で決めた事項のうち、別の合理的な実装者なら異なる判断をし得るものを、質問ラウンドの終了時に一度報告する。書式、並べ順、自律モードでの報告用UWIへの記載および後から異論が示された場合の扱いは、`agent-toolkit:completion-report`の`references/report-formats.md`「作業完了報告のフォーマット」の`### 自ら確定した判断`に従う。
この報告は承認を求めるものではないため、追加承認を待たず本書を使う工程が定める次の工程へ進む。
