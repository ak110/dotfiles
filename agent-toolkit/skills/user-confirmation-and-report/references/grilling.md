# grilling

本書を使う工程が定める場面でユーザーとの共通理解へ到達するための質問ラウンドを扱う。
確認事項の扱いと、質問ラウンド後の工程は本書を使う工程が定める。

## 確認対象

確認対象を列挙する前に、同じスキルの`SKILL.md`「確認要否の判定」を各候補へ適用する。

計画の目的、対象範囲、機能、実現方式、望む結果、制約、優先順位を、受領した依頼と成立済みの合意から整理する。この列挙は確認対象の種類を限定しない。未確定の判断を依存関係とともに列挙し、`SKILL.md`「確認要否の判定」3に当たる判断だけを確認対象とする。程度や裁量の具体化も同じ判定で決める。
WI作成工程（`agent-toolkit:add-awi-by-user`などでAWIを登録する時点）で本書を使う場合は、登録する要求を処理する計画・実行の工程が判断を要する要件・意図の曖昧さ（完成条件の境界、外部から観測できる挙動、対象範囲の端、除外）も列挙し、同じ質問ラウンドで全件確認する。後続工程へ残すのは、登録時点の調査で現れず処理時に初めて判明する曖昧さに限る。登録時に確認できた曖昧さを処理工程へ残すと、自律モードの処理で元項目が保留され、回答を待つ間その要求が進まない。
環境上の事実、既存コード、利用可能なツール、ライブラリ仕様など自分で調査できる事項は、自ら調べて確定する。
ユーザーが判定基準を示した集合に属する対象と、その集合から派生する対の対象（その対象を前提とする規範条文、テスト、設定など）へ同じ基準を当てはめる判断は、起草者が確定する。方針の選択肢として質問するのは、基準が当てはまるかを一意に決められない対象について、判定を分ける条件だけとする。
確認対象を列挙する時点で、受け取った要求どうしが同じ対象へ両立しない結果を求めていないかと、要求の実現に必要な事項のうち素材が値を与えていないものが無いかを併せて調べる。
要求どうしを比較するときは、両立はするが一方の要求が他方の方針に不一致や例外を残す組合せも探す（命名の方針を新しく定めつつ、同じ対象の一部の名前だけ旧来の形に保つ指示など）。
両立しない要求、不一致や例外を残す組合せ、値の与えられていない事項は、いずれも確認対象へ加える。不一致や例外を残す組合せの確認本文には、残る不一致と、今後の規約や運用に残る例外などの継続費用を書く。
協調モードのリポジトリ変更では、`agent-toolkit:user-confirmation-and-report`の`references/judgment.md`「公開範囲の確認」に従って着手前の公開範囲を質問ラウンドへ含める。依頼文が範囲を指定している場合は、その指定を使う。

## 質問ラウンド

未回答の判断へ依存しない確認対象を同じラウンドへまとめて提示し、回答のたびに依存関係を更新する。
別の未回答判断へ答えが依存する確認対象は後のラウンドへ回す。
確認を要すると判定した判断は、判断ごとに独立した質問にする。規範、設計、計画またはWIへ導入する方針・作業区分・工程・状態などの新しい概念名は、質問の説明のために自ら作成した語も命名として扱い、候補を`agent-toolkit:writing-standards`の`references/defined-names.md`「命名の方針」に従って作成する。同節の検索で見つかった既存の用例とその意味、および検索した範囲を質問へ添える。範囲を示すと、ユーザーが検索の狭さに気付ける。依頼が命名、用語または表記の方針を定める場合は、その方針に反する既存の名前（スキル名、ファイル名、節名、識別子など）を同じ範囲から列挙し、方針をそれらへ及ぼすかを確認対象の候補に加える。候補ごとに質問するか自ら確定するかは、本書「確認対象」の判定で決める。ユーザーが指定した語を変える案は`references/user-utterance.md`に従ってユーザー確認する。別の質問の選択肢や説明へ例示として載せた内容は、その判断への回答として扱わない。例示へ異論が返らなくても、ユーザーはその判断を問われたと認識していないため、投入や実装の後に指定し直す手戻りが生じる。
調査の完了待ちで保留するのは、その調査結果を必要とする質問だけとし、他の確認は進める。

## 質問表示

`SKILL.md`「手段の選択」の手段で提示する。
質問を提示したら、そのラウンドの回答を待ってから次のラウンドへ進む。

## 終了条件

確認を終了する条件は、前記の判定で確認を要する未回答事項と、その回答を妨げる未調査の事実がいずれも残っていないことだけとする。

## 終了時報告

質問せずに自分で決めた事項のうち、別の合理的な実装者なら異なる判断をし得るものを一度報告する。並べ順はユーザーが異論を持つ可能性が高い順とする（努力目標。異論の出やすい判断を先に読めるようにするため）。確認を経ずに完了する作業の完了報告も、`agent-toolkit:user-confirmation-and-report`「確認要否の判定」に従って同じ形式を使う。自律モードでは、`agent-toolkit:completion-report`の`references/report-formats.md`「報告用UWIのフォーマット」の`### 自ら確定した判断`へも、同じ内容を同書が定める1件1行の形式で書く。

````text
- **決定**: <エージェントが選んだ内容>
  - **理由**: <なぜそれを選んだか>
  - **最有力の対案**: <選ばなかった中で最も有力だった案>
````

この報告は承認を求めるものではないため、追加承認を待たず本書を使う工程が定める次の工程へ進む。
ユーザーが後から異論を示した場合は、その判断と依存する後続判断を更新する。
