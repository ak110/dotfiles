# grilling

本書を使う工程が定める場面でユーザーとの共通理解へ到達するための質問ラウンドを扱う。
確認事項の扱いと、質問ラウンド後の工程は本書を使う工程が定める。

## 確認対象

依頼と成立済みの合意から、目的・範囲・結果・制約・優先順位などを整理し、未確定判断と判断間の前後関係、要求間の両立不能、方針の不一致・例外、実現に必要な未指定値を候補として列挙する。各候補へ`SKILL.md`「確認要否の判定」を適用し、ユーザーだけが持つ値が残る事項を全件確認し、調べれば決まる事項と技術とQCDで決まる値は自ら確定する。両立する要求でも例外が残る場合は、その不一致と規約・運用の継続費用を確認本文へ書く。

WI作成工程（`agent-toolkit:add-awi-by-user`などでAWIを登録する時点）で本書を使う場合は、登録する要求を処理する工程が判断を要する曖昧さ（完成条件の境界、外部から観測できる挙動、対象範囲の端、除外など）も列挙する。前提が成立しない場合や環境・状態が異なる場合にも同じ目的を適用し、対応する結果・対象範囲・例外のうち技術とQCDで確定できない判断を同じ質問ラウンドで全件確認する。後続工程へ残すのは、登録時点の調査で現れず処理時に初めて判明する曖昧さに限る。登録時に確認できた曖昧さを処理工程へ残すと、自律モードで元項目が保留され、回答を待つ間その要求が止まる。

ユーザーが判定基準を示した集合に属する対象と、その集合から派生する対の対象（その対象を前提とする規範条文、テスト、設定など）へ同じ基準を当てはめる判断は起草者が確定し、基準が当てはまるかを一意に決められない対象について判定を分ける条件だけを問う。
協調モードのリポジトリ変更では、`references/publish-scope.md`「公開範囲の確認」で不足する公開認可・選好だけを質問ラウンドへ含める。

## 質問ラウンド

判断ごとに独立した質問を作成し、未回答の判断を待たずに答えられる質問を同じラウンドで提示する。回答後に質問間の前後関係を更新し、その回答を必要とする質問は次のラウンドへ送る。調査の完了待ちで保留するのは、その調査結果を必要とする質問だけとする。
概念名・画面ラベル・説明語などの候補は`agent-toolkit:writing-standards`の`agent-basics:writing-standards/references/defined-names.md`「命名の方針」に従い、既存用例と意味、検索範囲を添える。命名・用語・表記の方針を定める依頼では、同じ範囲の既存名も列挙し、方針に反するものへ適用するかを「確認対象」の基準で判定する。
指定語の変更は`SKILL.md`「原文の保持と取り込み」に従って確認し、別の質問に載せた例示への黙認をその判断の回答として扱わない。

## 質問表示

`SKILL.md`「手段の選択」の手段で提示し、そのラウンドの回答を待ってから次のラウンドへ進む。

## 終了条件

確認を要する未回答事項と、その回答を妨げる未調査の事実がいずれも残っていないことを終了条件とする。

## 終了時報告

決定と最有力の対案を記録する前に、`SKILL.md`「確認要否の判定」4の原文の目的・理由・程度との比較を適用する。
ユーザーだけの値が残れば、質問ラウンドの終了とその回答を必要とする後続工程の前に確認へ戻る。

質問せずに自分で決めた事項のうち、別の合理的なエージェントなら異なる判断をし得るものを、質問ラウンドの終了時に一度報告する。書式と自律モードでの記載は`agent-toolkit:completion-report`の`references/report-formats.md`「作業完了報告のフォーマット」の`### 自ら確定した判断`に従う。この報告は承認を求めないため、本書を使う工程が定める次の工程へ進む。
