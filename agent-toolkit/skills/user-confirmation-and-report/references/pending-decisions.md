## 未確定判断の保留と暫定判断

`SKILL.md`「確認を要する事項」に該当する論点は、実行モードにかかわらずユーザー確認へ送る。自律モードで回答が得られない場合は、`agent-toolkit:wi-standards`を起動してUWIへ記録する。無回答と判定するタイミングや、最初からUWIを利用する環境については、`references/communication-methods.md`「手段の選択」の対応表に従う。
`SKILL.md`「確認要否の判定」項目3で定める曖昧さについては、自律モードであっても事前承認型UWIへ記録し、回答を必要とする元の作業項目を`agent-toolkit:wi-standards`「状態と依存」の規定に従って保留とする。エージェント側の暫定判断で勝手に埋めることは避け、その回答を待たずに進められる成果物や工程のみを継続する（無回答のまま確定させて進めると、意図と異なる成果物の作成や手戻りの原因となるためである）。
回答を得られないまま確認処理が終了した場合（協調モードのセッション終了を含む）は、モードを問わず未解決の判断事項をUWIへ移管する。同じセッションで無回答による終了を観測した自律モードのエージェントは、以降の確認事項をUWIへ記録し、回答が必要な元の作業項目のみを`atk wi hold`（処理中であれば`atk wi hold --state=processing <元項目のファイル名>`）で保留にする。工程を停止する前に、確認事項を必ず記録する。

作業に必須となる外部資料が得られない場合は、資料の提供を依頼し、その資料を必要とする成果物の作成のみを保留とする。暫定判断の適用は、要求範囲を保った成果物の確定にのみ限定する。資料がない状態で作業を続行する行為は要求範囲の縮小にあたるため、他の論点と明確に分けてユーザーへ確認する。協調モードでは、資料の提供か要求範囲の変更に関する明示的な回答を待つ。自律モードでは、元項目のファイル名、説明、保留理由、必要な資料、および回答によって変化する結果をUWIへ記録した上で元項目を保留にし、該当の資料を必要としない他の工程を継続する。
保留解除の条件や再開手順はユーザー向けの判断材料ではないため、元項目の計画書にある進捗ログへ記載する。計画書が存在しない場合は、`atk wi edit <元AWIのファイル名> --append --body-file <絶対パス> --target-repo=<対象リポジトリ>`を用いて元AWIの本文へ追記し、UWIの元項目からたどれる状態にしておく。

## 事前承認の合意判定

`references/approval-scope.md`において事前承認を要すると定められている操作は、協調モードでの無回答時や自律モードでのUWI記録後であっても、合意が得られるまでは暫定判断の対象外とする。可逆な代替手段をとるか保留を選択し、その回答を待たずに進められる工程のみを継続する。事後承認の対象となる操作や、すでに成立した承認の範囲内にある操作は、通常通り進めてよい。

## 回答の受領

対話中に得られたUWIへの判断（保留中の確認事項に対する回答を含む）は、回答として記録する。その後に実際の変更へ着手するのは、`agent-toolkit:process-wi`などの専用手順を起動した場合や、明示的な作業指示がある場合に限る。
専用手順の実行中に、現在の作業対象を保留にしていたUWIの回答が得られた場合は、記録した後、保存されている計画や工程を同一セッション内で再開する。元の要求および計画に含まれる未完了の作業範囲は、追加のAWI登録や採否確認に分割することなく同一作業内で完遂する。要求範囲外の新しい要望のみを別項目として切り出す。
