# 文字エンコーディングの詳細

日本語環境（Windows／Linux混在）で開発する際の陥穽と対処。

## 基本原則

- 入出力境界でエンコーディングを明示する。内部処理ではUTF-8を基本とする
- ランタイムが自動で選ぶ文字コードに依存しない: 日本語WindowsのACPはCP932であり、
  明示しない場合に文字化けや例外が起きる
- ライブラリ提供フィールドの暗黙加工: stdlib・サードパーティライブラリのフィールドには
  プラットフォーム依存の暗黙加工が含まれうる。
  生データ復元の用途では、加工済みフィールドではなく未加工のフィールド／APIが
  別途提供されていないかを必ず確認する
- バイト長と文字長の混同防止: バイト長と文字数（コードポイント数・書記素クラスター数）は別物として扱う

## BOMの扱い

- 読み込み時はBOM有無を両方許容する
- 出力時はBOMなしで書く（Excelに渡すCSV等、対象側が要求する場合のみ付ける）

## 日本語テキストの自動判定順序

BOM検出→ISO-2022-JP特有エスケープシーケンスの整合性検証→UTF-8での厳格なデコードの試行→EUC-JP・CP932の順で判定する。
ISO-2022-JPはASCII系バイト列で構成されUTF-8での厳格なデコードにも成功するため、必ずUTF-8より先に検出する。
入手元情報から判断できる場合はその情報で文字コードを決める。

## ZIPファイル名の扱い

General Purpose Bit FlagのBit 11がセットされている場合はUTF-8でデコードする。
未設定時の仕様上の基本はCP437であり、作成元が日本語Windows等である根拠がある場合のみCP932をフォールバック候補とする。
Info-ZIP Unicode Path Extra Fieldなど補助情報も確認対象に含める。

Pythonの`zipfile.ZipInfo`を扱う場合、`filename`は`_sanitize_filename`を経由する。
Windowsでは`os.sep`の`\`が`/`に置換されるため、
CP932の2バイト目に`0x5C`を含む文字（ソ・ポ・表など）で往復復元に失敗する。
生バイト列の復元には未加工の`orig_filename`を使う。

## Unicodeの比較と安全性

比較・検索・一意性判定に使うキーはドメイン要件に応じてNFC等の正規化形式を用いる。
認可・識別キー・パスワード等でNFKCを使うと合字・互換文字経由のバイパスを許す恐れがある。
大文字小文字の畳み込みが必要な場合はNFCで正規化してから`casefold`を適用する
（逆順にすると言語固有の畳み込みが不完全になる）。
HFS+はApple変種のNFD相当でファイル名を保存し、APFSは正規化形式を保持するため、
ファイルシステム・API境界をまたぐ比較では正規化形式の差を考慮する。
Bidi制御文字（Trojan Source）・ゼロ幅文字・ホモグラフは、ソースコード・識別子・ユーザー入力・ログで禁止または警告する。

## 書込ツールの改行・BOM保全

ホストの書込ツールごとの改行・BOM・文字コードの扱いと、CRLF・BOM・非UTF-8のファイルを作成・編集する共通の手段を「書込ツールの改行・BOM保全」と呼ぶ。
EditとWriteが要求する読取状態は`file-editing.md`「ファイル更新時の編集ツールの前提」が定める。

- Claude CodeのRead・Edit・WriteはUTF-8を前提とし、非UTF-8（CP932など）のファイルを直接扱えない
- EditはCRLF改行とUTF-8 BOMを透過的に維持するため、既存ファイルの編集にはEditを使う
- Writeは常にLF改行・BOMなしで書くため、CRLFとBOMが消失する。CRLFやBOMを要するファイルをWriteで書いた場合は、改行とBOMを別途復元する
- CRLF・BOM付きの新規ファイルはBashで書く（例: `printf '\xEF\xBB\xBF' > file && cat <<'EOF' | sed 's/$/\r/' >> file`）
- 非UTF-8のファイルは`iconv`でUTF-8へ変換し、変換後のファイルをReadで読んでからEditで編集して元の文字コードへ戻すか、Pythonでバイト列を置換する
  - iconvの往復: 読み取りは`iconv -f <元の文字コード> -t utf-8 <ファイル>`、編集はUTF-8へ変換したファイルをReadで読んでからEditかWriteで編集し、`iconv -f utf-8 -t <元の文字コード>`で戻す。新規作成はUTF-8で書いてから同じ変換で戻す
  - Pythonによるバイト列の置換: iconvの往復より手順が短く、CRLFも維持できる。単純置換・行追加・日本語コメントの変更のいずれにも使える。雛形は`from pathlib import Path; p=Path('<ファイル>'); data=p.read_bytes(); p.write_bytes(data.replace(old, new))`とし、`old`と`new`は元の文字コードで符号化したバイト列にする。行追加は「直前行＋`\r\n`＋新規行＋`\r\n`」の形で`old`の末尾に`b'\r\n'`を含めて置換する
- `.gitattributes`の`eol=crlf`は改行だけを管理し、BOMを復元しない
