# コーディングエージェント向け文書品質（基本）

本書は、コーディングエージェントが直接読み込む文書（`AGENTS.md`・`CLAUDE.md`・ルール・`SKILL.md`・サブエージェント定義・`references/`）の責務、記述内容、条件の書き方及び語調の基準を定める。
規範文書へ新しい規定を追記する場面と文書の記述量を管理する場面の基準は`agent-documents-additions.md`に従う。
なお、計画ファイルの成果物契約は`agent-toolkit:plan-mode`が定め、本書の対象外とする。

## 完成条件

新規作成・改訂した文書は次の要件を満たす。

### 責務と構成

- agent定義、スキル、タスク指示文書では、冒頭で担当する責務、担当しない責務、最初に行う行為を明示する
- 委譲元側の文書は受渡しと検収に専念する。委譲先固有の手順は委譲先側の文書に持たせ、委譲先は渡されたタスク文書と必要な規範を自ら読み込む
- 冒頭の1〜2文で目的（適用判断の核となる動機）を述べ、frontmatterの`description`には目的の詳細を書かない
- 新しい挙動や制約は次の区分へ振り分ける。常時参照する横断標準は`AGENTS.md`や`CLAUDE.md`本文またはpaths未指定ルール、特定パス限定則はpaths指定ルール、手順やワークフローはスキル、機械的な強制や自動検査はhook、調査の隔離や冗長出力の抑制はサブエージェントとする
- スキルやエージェントの責務配置は、スキル編集の資料に従う
- 判断に用いる規範、基準、目標値は、その判断をする工程で確実に読み込まれる文書へ配置する。常時ロードされる規範、その工程で起動するスキルの`SKILL.md`、または工程内で明示的に読む指示がある`references/`配下の文書がこれに当たる。読む契機が定められていない文書の記述は、実行時の判断材料として参照されない
- 情報の配置場所は、その情報が必要となる工程の範囲に合わせて選ぶ。特定の工程でのみ必要な情報は該当工程の文書へ配置し、常時ロードされる文書へ全工程向けの記述以外を混入させない
- MCPツールなどの説明文には、ツールの動作、使用場面、使用しない場面、引数の意味、返さない結果を記載する。ツールの組み合わせや実行順序などの手順は、説明文ではなく手順文書へ配置する

### 記述内容の取捨

- すでに自動ロード済みや呼び出し済みの規範を不要に要約・反復しない。各記述は、削除すると判断の一貫性が損なわれる場合に限って残す
- 実行判断に直接寄与しないメタ情報（管理方針、編集判断、同期対象など）はfrontmatterコメントへ移し、本文には実行判断に直結する記述のみを置く
- サブエージェントや委譲先は、起動時に注入される共通ルールに加えて、環境が自動ロードするユーザールールも受け取る。すでに提供されている条文の重複記載を避け、必要な場合は既存条文を参照する

### 条件と範囲の記述

- 判断条件、例外条件、許容条件は客観的に観測可能な事実（コマンド終了コード、ファイルの有無、ユーザー合意など）で記述する。作業量や所要時間などの主観的な推定量は条件に含めない
- 規定が既定で従うべきものか努力目標かを明確にし、区分に応じた表現を選ぶ。既定の規定では適用範囲、除外対象、前提条件を明確に示し、解釈の揺れを防ぐ。努力目標では達成する目的と外れた場合の不利益を理由として述べる
- 独立して変化し得る複数の制約は箇条書きを分け、個別に記述する
- 禁止規定を設ける前に肯定形での表現を検討し、禁止事項には推奨する代替行動を併記する
- 既存規定の表現形式を変更する際は、変更前後で適用条件、禁止範囲、実行時要件が同値であることを確認する
- 手順の各工程は、実行主体がその記述のみで次の工程を確定できるように記述する。後続工程や参照先がある場合はその所在を明記する
- 多義的な語を用いる場合は、条文内で対象を明確に限定する
- 指示語（「今回」「先ほど」「本規則」「上記」など）は文脈が失われやすいため避け、具体的な名称で記述する
- 数値の上限は表や固定形式の出力にのみ適用し、探索や判断を伴う出力では重要度の順序や除外条件で制御する
- 規範と手順では達成すべき性質を規定する。特定のツールや実行順序を限定する場合は、その手段が必要不可欠である根拠を併記する

### 語調と現行規則の表現

- 語調を強める表記（`必ず`、`絶対`など）は、違反を防ぐ理由が明確な重要規定に限定して用いる
- 読者の傾向を主語にする記述（「〜しがちである」など）を避け、判定基準と望ましい行動を直接記述する
- 現行の規則のみを記述し、過去の版との差異を示す表現（「従来どおり」「今後は」など）は残さない
- 未定義の概念を否定する形での記述を避け、望ましい行動を肯定形で記述する
- 何かを制限する場合は、制限対象と代わりに行うべき行動を合わせて明記する
- 具体的な役割名（エージェント、委譲先、ユーザー、読者など）を用いる
- 法令調の硬い表現は、平易な動詞や具体的な対象名へ置き換える
- 努力目標には「（努力目標。〜）」の形式で理由を明記する。それ以外の規定は通常の平文で理由を添える
