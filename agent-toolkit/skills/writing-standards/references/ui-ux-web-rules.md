# Web画面の実装とレビューで確認する規則

本書はHTML、CSS、JavaScriptでエンドユーザー向け画面を実装またはレビューするエージェントが、コードから判定できる条件を扱う。エンドユーザーの操作で生じる結果の正しさはE2Eテストで、操作の分かりやすさは`ui-ux.md`「完了前の実描画確認」とユーザビリティレビューで確かめる。

主な参考資料: [Vercel Web Interface Guidelinesの取得時点の原文](https://github.com/vercel-labs/web-interface-guidelines/blob/e3d624baaf29dc1fc645aff3e38f03e564d2d6b1/command.md)（commit `e3d624baaf29dc1fc645aff3e38f03e564d2d6b1`）。原文を実行時に再取得せず、本書の規則を判定へ使う。英語の文章表記に固有の規則は日本語画面の判定対象から外す。

## アクセシビリティとフォーカス

- 操作には`button`、遷移には`a`を使い、キーボードと新しいタブでの利用を保つ。アイコンだけのボタンへ名前を付け、装飾アイコンを支援技術から隠す。意味のある画像へ代替テキストを付ける。
- 入力欄へ関連付いたラベルを置く。見出しを階層順に置き、本文へ移動するスキップリンクを用意する。非同期通知と入力検証の結果を適切なlive regionで伝える。
- キーボードで到達する操作に`:focus-visible`の視認可能な表示を用意する。`outline: none`を使う場合は同等以上の代替を同じ状態へ置く。固定ヘッダー、フッター、オーバーレイの下でもフォーカス中の要素を視認できる位置へ保つ。

## フォーム

- 入力の目的に合う`name`、`autocomplete`、`type`および`inputmode`を指定する。ラベルのクリックで対応する欄へ移れる構造とし、貼り付けを利用できるようにする。
- 送信開始前の送信ボタンは利用可能に保ち、送信中は進行を示す。
- ブラウザーの戻る操作とダイアログを閉じる操作も、`ui-ux-patterns.md`「フォームと入力」の入力値を失う操作として扱う。

## 内容、状態、遷移

- 長い値と空の値でも内容へ到達できるレイアウトを保つ。
- 再訪や戻る操作で復元すべき状態はURLへ反映する。
- 閉じたオーバーレイはキーボードフォーカスの対象から外す。

## 動き、画像、性能

- 動きによる描画負荷を抑え、操作で中断できるようにする。prefers-reduced-motionでは装飾的な動きを止める。
- 画像の領域を予約してレイアウトを安定させ、表示に必要な順で取得する。
- 描画時間を測定して描画量とレイアウト計算を減らす。仮想化などの採否は件数だけで決めない。

## テーマと地域化

- 提供するテーマをネイティブの操作要素にも適用する。
- 日付と数値はIntl等で地域化し、翻訳対象でない名前・コード・識別子を区別する。
- Reactなどでサーバー側描画とhydrateを使う場合は、入力値の変更ハンドラーと、日時の描画結果が両側で一致する条件を確認する。

## 避ける実装

画面拡大を妨げる`user-scalable=no`と`maximum-scale=1`、操作できると誤認する非操作要素などを検出した場合は、利用シナリオへの影響を確認して修正する。
