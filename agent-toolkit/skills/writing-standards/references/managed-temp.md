# 管理対象一時領域

本書は`agent-toolkit/rules/02-agent-operations.md`「ツール・コマンド運用」が委ねる、管理対象一時領域の作成、保持、回収及び消費工程の完了判定の正本である。
管理対象一時領域を扱う時に全文読む。

セッションの開始時に自動で作成される管理対象一時領域は、そのセッションの範囲で使う一時領域とする。
この領域の作成と回収は実行環境が担い、最終更新から7日を超えた後の次の`atk`実行時の掃引で回収される。
絶対パスは、セッションの開始時に実行環境が文脈へ追加する本文が示す。
同一turnの内側で作成から消費まで完了する作業用領域は、その本文を受け取っている場合に
`atk managed-temp create --prefix <用途> --session-root <通知された絶対パス>`でその直下へ作成する。
セッション内の子領域は個別の登録を持たないため、回収はセッションrootの掃引へ委ねる。
turnを終えて再開する可能性がある場合は、`--session-root`を付けずに`atk managed-temp create --prefix <用途>`で個別の登録を持つ領域として作成する。
本文を受け取っていない場合も、必要な領域を`atk managed-temp create --prefix <用途>`で作成し、用途完了後に回収する。
次の成果物は、個別の登録を持つ領域へ置いて次項の回収規定に従う。
セッションの終了で回収される領域へこれらを置くと、再取得できなくなる。
セッションの終了後にも参照する成果物、領域を作成したsessionのturnの終了後に読む成果物、
及び自身が起動する委譲先へ絶対パスで渡す成果物が該当する。
`agents_server`経由のsessionはturnの終了の時点でsessionが終了し得るため、
`send_message`で再開した同一sessionの読み取りもこの回収の後になる。

管理対象一時領域内の成果物を生成工程とは異なる後続工程が入力として使う場合と、生成工程と同じ工程がturnをまたいで再度読む場合、領域を所有する主体は成果物を使う全工程の完了と、成果物から確定した判断の恒久的な記録を確認した後にだけ領域を回収する。
後続の消費工程の完了は、この確認で判定する。成果物を1回読み取ったことと生成工程が完了したことは、その判定の入力の外に置く。
コンパクションや別ターンからの再開を経る間も消費工程が残る場合は、回収前に再開情報を永続する成果物へ記録する。
再開情報は必要な結論、未完了工程、成果物の絶対パスとし、再開する主体が読む計画やレビュー指摘管理表へ置く。
未完了工程がある間は管理対象一時領域を保持し、`--session-root`を付けずに作成した独立領域は全消費工程の完了後に既存の管理CLIで回収する。
初回の読取後に入力成果物を回収すると、再開後の工程が同じ生成や委譲を反復する。
