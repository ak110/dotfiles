# Claude Code auto modeのカスタムルール

本書はauto modeのカスタムルールを追加・編集する手順を扱う。
拒否に遭遇したときの行動手順は`agent-toolkit:confirmation-and-uwi`の`references/permission-denial.md`が定める。

auto modeはユーザー環境の`~/.claude/settings.json`の`autoMode.allow`配列に自然言語の許可指示を追加できる。
`allow`・`soft_deny`・`hard_deny`・`environment`の各配列は、設定するとその区分のデフォルト一覧を置き換える。
デフォルトを維持したまま追加するには、配列へリテラル文字列`"$defaults"`を含める。
`allow`の許可指示はデフォルトの`soft_deny`判定を上書きする。
区分外のキー（`allowMode`等）は無効であり、実在は公式スキーマ（`$schema`のURL）で確認する。

## ルール区分

auto modeは次の4区分でルールを判定する。

- `allow`: 明示的に許可する操作
- `soft_deny`: 既定では拒否するが、ユーザー指示や文脈で`clears`される操作
- `hard_deny`: いかなる場合も拒否する操作
- `environment`: 信頼境界（リポジトリ・ドメイン・バケット・サービス）の定義

## CLIサブコマンド

- `claude auto-mode defaults`: デフォルトの全ルール（`allow`・`soft_deny`・`hard_deny`・`environment`）をJSON形式で出力する
- `claude auto-mode config`: 現在有効な設定（デフォルト＋カスタム）を表示する
- `claude auto-mode critique`: カスタムルールをAIがレビューし、曖昧・冗長・偽陽性のリスクを指摘する

## カスタムルール追加のワークフロー

1. 編集前に`claude auto-mode config`で有効なルールを読み、配布側の設定ファイルがある場合はそのsourceも読む。
   `claude auto-mode defaults`で既定のルールと`clears when ...`の例外条件を確認し、誤拒否されている領域を特定する。
2. 提案するルールと有効なルールを、ラベルと文面ではなく、対象操作、適用条件及び信頼境界の包含関係で比較する。
   既存ルールが提案の全範囲を含む場合は追加せず、一部だけを含む場合は未被覆の操作だけを追加対象にする。
   同じ範囲を持つローカルルールは、由来を確認し、利用者の承認を得た場合だけ冗長な側の撤去候補にする。
3. 配布側の設定ファイルがある場合はそのsourceを、無い場合はユーザー環境の`~/.claude/settings.json`を編集し、`autoMode.allow`配列へ許可指示を追加する。
4. 再ロード後に`claude auto-mode config`でその項目が有効設定として表示されることと、`"$defaults"`を含む区分で既定の件数が維持されていることを確認する。
5. `claude auto-mode critique`を実行して結果を点検する。指摘の全件採用を必須とせず、`agent-toolkit:review-standards`が定める問題と手段の比例性で採否を決める。

配布元の`autoMode.allow`からラベルごと廃止したルールは、ユーザー環境の設定に残る。
配列のunionマージは配布元からの削除を反映しないため、廃止したラベルの旧文面を除去する経路を配布処理へ登録する。

## カスタムルール記述の注意点

- 適用対象（対象操作・対象コミットの性質・対象パスなど）を文面に明示する
- 記述の粒度は操作の種別とし、変化しやすい識別子（サブコマンド名、オプションの完全な綴り、個別ファイルのパス）の列挙を避ける。
  classifierが対象を判別するために必要な代表例だけを添える（ユーザー指定）
- 許可する対象の記述だけでルールを構成する。「〜には適用しない」「〜は許可しない」の形の除外文は書式の外に置く。
  許可の範囲は対象の記述で定め、記述の外にある操作は`soft_deny`と`hard_deny`の既定の判定に委ねる（ユーザー指定）
  - ユーザー意図に依存する条件（「計画・指示で承認された場合」など）はUser Intent Ruleに任せる領域と重複する
  - 対象の記述を狭めると、手順どおりの操作が拒否されて工程が止まる。対象は実際に行う操作の範囲で書く
- カスタムルールが上書きする範囲は`soft_deny`までとし、デフォルトの`hard_deny`領域はそのまま維持する（auto modeの安全境界を保つため）
- 信頼対象（個人リポジトリ・信頼ドメイン等）を参照するallowルールは、`autoMode.environment`の信頼境界宣言と整合させる
- `claude auto-mode critique`の出力は非決定的で、末尾が欠落する場合を実測している（exit 0のまま文中切断）。
  出力はファイルへ保存して欠落の有無を確認し、欠落時は再実行で補完する
