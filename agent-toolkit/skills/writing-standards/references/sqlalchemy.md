# SQLAlchemy

本書はSQLAlchemy 2.0系のORMを使うコードを書くエージェントへ、問い合わせの書き方と、autoflushで入力検証の誤りがDB制約違反として先に送出されることを防ぐ順序を示す。

## 問い合わせの書き方

- NULLチェックには`.is_(None)`を使う

## 成立条件

設定を変えていない`Session`はORM対応の問い合わせを送信する前に保留中の変更をflushする。
次の条件が全て成立する処理では、入力検証で扱うべき誤りがDB制約違反として先に送出される。

- autoflushが有効である
- 永続インスタンスの属性を更新中か、新規行を`Session`へ追加した後である
- 保留中の変更が一意、`NOT NULL`、外部キーなどのDB制約へ違反し得る
- 呼び出し元が入力エラーとDBドライバー由来の例外を区別する

最初の属性代入（新規行では`Session`への追加）から、入力値の検証と必要な属性代入を終えるまでを属性代入区間とする。

## 問い合わせと属性代入の順序

- DBへの問い合わせ（設定値の判定や一意性の事前確認を含む）は属性代入区間より前に完了し、結果を変数へ保持してから代入する（原則）
- その問い合わせは、DBアクセスを要しない入力検証の後へ置く（努力目標。検証だけで終わる処理で`Session`の開始と問い合わせを避けられる）
- 同じ処理単位の保留変更を反映した問い合わせ結果へ依存する契約は維持し、必要な箇所では`Session.flush()`を明示して送信時点を問い合わせより前へ固定する。読み取り側でautoflushを無効にする方法へ置き換えない（原則。同じ処理単位で追加・更新した行を問い合わせる呼び出し元が古い状態を受け取る）
