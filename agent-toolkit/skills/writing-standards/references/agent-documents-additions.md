# エージェント向け文書への追記と記述量の管理

本書はエージェントが直接読み込む文書へ新しい規定を追記する場面と、
文書の記述量を管理する場面の判定基準を定める。
文書の責務、記述内容、条件の書き方および語調の基準は`agent-documents-basics.md`が定める。

## 規範追記時の判定

エージェント向け文書へ規定を追記・改訂する前に、その文章がQCD（`agent-toolkit/rules/01-agent.md`「判断指針」）へ貢献するかを判定し、貢献しない文章は書かず、既存なら除く。
読むエージェントのコンテキストを占めるだけの文章はCostだけを増やす。
Qに影響する問題の処置として加える規定の要否は`agent-toolkit:bugfix`の`references/root-cause-analysis.md`「QとC・Dの区別」に従い、本節の費用と便益の比較はQを満たす記述どうしの選択とC・Dだけの問題へ使う。
詳しさは`writing.md`「読み手別の追加注意点」のエージェント向け文書の項に従う。

### 常時規範への追記条件

- 常時規範へ追記できるのは、ユーザーが逐語で示した要件を規定にする場合、`agent-toolkit/rules/01-agent.md`「規定の区分と標示」の硬い制約を守る条件を加える場合、既存条文を統合して同じファイルの総量を減らす場合の3つとする。ほかの知見は、その工程で起動するスキル、参照資料、hookの通知へ置く
- 常時ロードされる規範（`agent-toolkit/rules/`配下・`AGENTS.md`・`CLAUDE.md`）がスキルや`references/`の起動・読込を指示する箇所には、起動契機、起動対象、そのスキルが定める範囲だけを置く。観点、判定手順、例外、具体例はスキル側だけが持つ。双方に置くと、どちらに従うか判定できなくなる
- 規範が起点として名指しする起動対象は、その規範を読むエージェントが自ら起動できるものに限る（努力目標）
- 規範・基準・目標値の有無を判定する場合は、その判断をする工程で記述がコンテキストへ実際に載るかで判定する
- ユーザーへの発話へ適用する規定は`agent-toolkit/share/rules-main.md`「ユーザー向け発話ルール」節だけが持ち、守らないとユーザーへ内容が伝わらない条文に限る（努力目標。発話のたびに参照する規定が増えると本来の作業へ回る能力が減る）

### 失敗時の回復手順

- 失敗・拒否・上限超過・遮断などの異常時だけ実行する手順（失敗時の回復手順）は、異常時に読み手へ届く手段へ置く。手段にはホストやCLIのエラー本文、hookの遮断通知の`fix`、`PostToolUseFailure`の`additionalContext`、異常を条件とする読込表の行が指す`references/`などがある。
  異常の有無にかかわらず全文を読む階層（`agent-documents-basics.md`「置き場所と配送」の読込の階層のうち常時ロード、役割別注入、配送文、メイン起動時と役割起動時）には、異常の種類と参照先を示す起動契機だけを置く（努力目標。平常時の判断へ影響するため）。
  既存の手段が同じ手順を届けているなら文書側の本文を除く。読み手が異常を観測できない場合（出力なしで成果物を壊す異常など）は事前に防ぐ規定として置き、手順が起動契機と同程度以下の分量なら移さない

### 工程と検証の追記

- 規範の未適用への処置を選ぶ前に`agent-toolkit:bugfix`を起動し、`references/root-cause-analysis.md`の再発防止策の選定を用いる
- 検証、レビュー、待機または再確認の工程を追加・改訂する場合は、その工程が守る成果と、先行工程や既存基準で既に達成される条件を確かめ、必要性が残る条件だけを書く（努力目標。消費されない記録や重複工程を増やさない）
- 不具合対策として作業を制限する規定では、原因への対策と症状を抑える制約が守る価値を比べる。原因への対策で成果を守れるなら制約の要否を判定し直し、残すなら見直し契機を記す
- 将来の観測値を削除条件とする暫定規範は、追記時点でその条件がまだ成立していないことを実際値で確かめ、条件成立後に必要な状態も同じ粒度で記録する
- 直接操作や代替手段に関する要件では、操作開始に必要な対象と入力を、同じ読込文脈から取得できる手段とともに書く
- 品質要件は生成側（起草時と実装時の完成条件）と検出側（レビュー観点、自動チェック）の双方へ同じ改訂で加える（努力目標）
- 複数の委譲先を起動する手順は1件へまとめた形を初期案とし、分ける場合は理由を書く（努力目標。起動ごとの固定費と待機往復が件数だけ積み上がるため）
- 完了条件はその工程が達成すべき成果で書く

計画やレビュー契約へ実装順序・単位分割・個別コマンドなどの詳細を書くのは、既存規範と確定済み外部仕様から一意に導けない場合、または導出を誤ると安全性、データ保全、公開契約、主体間の認可境界などを損なう場合に限る。

### 条文の形式

- 守る価値、基本方針、例示と適用範囲の書式は`agent-documents-basics.md`「条件と範囲の記述」、役割別の配置は同「置き場所と配送」に従う
- 判断の分岐や報告・成果物の欄は、個別の列挙より列挙全体を貫く判定基準で書けないかを先に比べる。列挙を残す場合は列挙外の扱いと対象範囲を同じ条文へ書く（定めないと狭い解釈でも違反にならず、意図した場面で発火を逃す）
- 数値の閾値や複雑な判定手順は単純な原則で代替できないかを比べ、閾値を置くなら境界値の根拠を本文へ残す
- 実行環境やモデルの版数を伴う条文は`investigation.md`「エージェント向け文書の技術的条文」に従う

### 既存対象への波及

- 変更する判断規則と同じ判断をする既存規定・生成側・消費側を見直す前に`agent-toolkit:bugfix`を起動し、`references/root-cause-analysis.md`「類似見直し」の母集団導出と判定を適用する。根拠は既存の改訂記録へ残す。新しい場面別条文が一般則の母集団を狭めたり相反する処置を定めたりしないかの比較にも同じ判定を使う。Qに影響する問題の処置として規定を加えた場合は、既存対象の是正の範囲と完了を努力目標の標示によらず同書の「類似見直し」と「類似見直しと再発防止の完了」で決める
- 同じ目的の既存条文を統合・撤去できないかを併せて判定する。不足の指摘では追記、既存記述の書き換え、不採用を比べる（努力目標。条文が積み上がると適用範囲を広げないまま読込量だけが増える）
- 同一の事象へ反対の判断を与える条文を併存させない。衝突する既存条文は同じ変更で置換するか優先順を確定し、別リポジトリの所管ならそのリポジトリ向けのAWIへ記録する
- 努力目標でない規定を追加・強化した場合は、その規定が支配する既存対象も走査し、認可の内側の違反は同じセッションで直し、書込権限の外ならWIへ渡す。努力目標の規定は新しい記述から適用する
- 記録先を新設・改名・移設する改訂では、同じ内容の記録を求める既存条文を新しい記録先への参照へ置き換える

## 文書記述量の管理

### 記述量の水準

対象はエージェントが読み込む配布物と、その判定条件を持つ機械チェックの実装コードとする。
新規作成・改訂では記述量を現状の水準に保ち、既存記述との重複統合（除去・統合・`references/`分離）を常に検討する（努力目標。合計行数の上限は設けず、自動チェックもしない）。
`references/`への分離など記述を分ける方向を選ぶ前に、`design-heuristics.md`「設計品質の劣化確認」の観点(f)で統合案・現状維持案と比べる。
`share/<役割名>.parent.md`と`share/<役割名>.subagent.md`の分担は`sub-agents.md`「`<役割名>.parent.md`と`<役割名>.subagent.md`の組」に従う。

文体、表記および口調の統制はlintによる自動チェックを一次手段とする。
エージェント向け文書は生成時の予防ガイドとして維持し、lintと重複する細則は細かすぎるものだけを削る（検出後の書き直しだけに頼ると指摘と対応の往復が増えるため）。

### 配置の階層

規範量が作業へ影響する要因は、同一契約の分散で同期箇所が増えることと、判断に使わない記述を起動時に読んで初期コンテキストを消費することの2つであり、削減対象はこれで決める。総バイト数は補助指標に留める。
記述は`agent-documents-basics.md`「置き場所と配送」の読込の階層に沿って、読むエージェントと必要になる時点へ合わせて配置する。
スキルの本数削減は常時ロード量をほとんど減らさないため、起動のたびには使わない記述の`references/`への退避とagent定義の縮小を先に検討する。
スキルの統廃合は起動手順を変えるため、起動の判断を改善する場合に採用する。

### 削減の判定根拠

ユーザーが常時規範の削減を求めた場合、名指しされたファイルにかかわらず自動ロード対象の常時規範の全体を対象とし、努力目標の標示が無い条文の削除も候補に含める。
移設先のスキルが無ければ新規作成してよい。削減の目標値はユーザーが具体値を示した場合だけ採用する。

削減・統合は次のいずれかの根拠を満たすことを条件とする。

- SSOT違反: 他ファイルに正規の記述があり、ここはその転記である
- 自明導出: 上位指針・学習データから自明に導出できる。
  作法の細則を削っても、明示されないと安定して考慮されない観点（セキュリティ、エラー処理など）は代表語で残し、硬い制約の条件は具体的に残す。学習データから導けない事実は自明導出に当たらない
- 公式ドキュメント代替可能: 公式ドキュメントの一次資料参照で同等の情報が得られる
- 上位指針への統合: 細則列挙を束ねる上位指針へ昇格できる。同一工程の箇条が同じ節へ並列に蓄積している場合も含む
- 手段固定: 特定のコマンド、ツール、実行順またはパスを固定し、その手段でなければ性質を満たせない根拠の記載を欠く
- 個別事象特化: 観測1件の対象、工程または識別子へ貼り付いており、機構の水準の一般則へ畳める
- 過剰な手順化: 読み手が目的と常識から判断できる工程、確認、分岐または例外処理を逐一書いている（`writing.md`「読み手別の追加注意点」のエージェント向け文書の項）
- 条件の入れ子: 例外と除外が重なり、条件と行動が一対一で対応していない
- 拘束力の過剰: 技術的な不成立、データ破損、公開インターフェース破壊、セキュリティ欠陥のいずれも防がない条文を努力目標の標示なしで書き、適用範囲と除外を列挙している

数値・閾値・境界値の根拠（由来、境界を分ける理由、トレードオフ）は削減対象から除く。
削減で規範性が失われる場合は他節で代替できるかを確かめ、できなければ残す。圧縮・統合では元の規定の順序の制約・前提条件・除外条件を保ち、`writing.md`「日本語の書き方」の省略の復元、動詞の意味、主題と述語の関係を確かめる。

### 保護対象

圧縮・統合・削除のいずれでも次を維持する。短縮後も文と前後の文脈から意味と関係を一意に読み取れるようにする。

- 本文冒頭の目的記述（適用判断の核となる動機）
- 開いた列挙表現（「等」「〜を含む」「〜など」）。閉じた列挙への書き換えは範囲を狭める
- 同一ファイル内の既存表記との整合が必要な用語と、並列表現の対称性
