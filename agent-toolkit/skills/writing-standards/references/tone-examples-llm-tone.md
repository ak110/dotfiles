# LLM口調

論点を増やさず装飾として用いる型を排除する。
術語・概念を議論や説明に使うこと自体は対象外とする。

## 予告と総括

主張内容を述べずに姿勢・構成を宣言する前置きや言い換えだけの結びは、
主張そのものを直接書くことで代替できる。

```text
悪い例: ここで大切なのは入力形式です。なお、設定はJSONで保存します。以上、JSON形式で保存するという説明でした。
書き換え: 設定はJSONで保存する。
解説: 保存形式を述べる文を残し、内容を増やさない宣言と結びを省く。必要な次の操作の案内は残す。
```

```text
悪い例: 重要なのは、テストを設計段階から考慮することである。まとめると、境界値を外さないことが大切だ。
書き換え: テスト設計は実装前の仕様策定段階から開始する。テストケースは境界値を網羅する。
解説: 「重要なのは〜である」は姿勢の宣言であり主張を含まないため削除する。
「まとめると」が直前の言い換えとして機能する場合はその文ごと削除する。
```

## 空虚な形容

中身を述べずに強調や概観だけを示す形容詞類は、
何を評価し、どんな結果を得るかが分かる記述に置き換える。

```text
悪い例: 不可欠な性能改善として、キャッシュ戦略が核心的な役割を担う。
書き換え: キャッシュを導入するとDBクエリ回数が減少し、レスポンスタイムが短縮される。
解説: 「不可欠な」「核心的な」は何がどう改善するかを述べない形容のため、観測可能な指標と因果関係で記述する。
```

```text
悪い例: 本UIは直感的に操作できる。
書き換え: 本UIはメニューを2階層に抑え、主要操作を1クリックで完了する構造とする。
解説: 「直感的」は読者ごとに解釈が異なる形容のため、観測可能な構造（階層数・操作ステップ数）で記述する。
```

## 空虚な動詞

何をどう記述したかを示さず終わる動詞類は、
述べる対象と内容を具体化した動詞句に置き換える。

```text
悪い例: APIのレスポンス仕様について深掘りする。認証エラーの挙動に触れる。
書き換え: APIのレスポンスボディの構造とステータスコードの対応を示す。
解説: 「深掘りする」「触れる」は何を述べるかを示さないため、具体的な対象を明示した動詞句に置き換える。
```

## 接続の型

新情報を持たない接続表現の連打は、複数の事項を1文に集約することで代替できる。

```text
悪い例: 設定において、タイムアウト値を指定する。また、リトライ回数を指定する。さらに、ログレベルを設定するという側面から挙動を変更できる。
書き換え: タイムアウト値・リトライ回数・ログレベルの3項目を設定ファイルで指定する。
解説: 「において」「また」「さらに」「という側面から」で分割した各文が独立情報を持たない場合は、1文へ集約して接続表現を削除する。
```

## 翻訳調・英語統語

判断した主体と根拠が分からない擬人化や推量は、判断とその根拠を対応付けて書く。
結果が直接示す値とシステムの動作は、その主体で説明する。
確定した内容を推量へ変えたり、未確定の内容を確定した事実へ変えたりせず、元の確実性を保つ。
言い切りの形で書くのは、エージェント自身が確かめた内容に限る。ユーザーが「ほぼ」「はず」などの限定付きで述べた内容を書き写す場合は、限定を外さず原文と同じ強さで書く。

```text
悪い例: 担当者が確認したログは、キャッシュへの要求が失敗したことを物語っている。原因はまだ分からない。
書き換え: 担当者がログを確認し、キャッシュへの要求が失敗したと判断した。原因はまだ分からない。
解説: 観測した内容と判断した主体を残し、比喩を操作と判断へ戻す。原因や測定値を補わない。
```

```text
良い例: 集計結果は成功が8件、失敗が2件であることを示す。システムは失敗した要求を再実行する。
解説: 集計値と処理主体の動作を直接述べているため、無生物を主語にしたことだけを理由に書き直さない。
```

```text
悪い例: 入力を受け付けることではない。結果を保存することこそ、この処理の価値である。
書き換え: この処理は結果を保存する。
解説: 入力の拒否を求める契約がなく、結果の保存を強調するためだけの否定対比を整理する。
```

```text
良い例: 入力には文字列ではなく整数を指定する。
解説: 受理する入力を伝える否定は意味を持つため保持する。
```

```text
悪い例: 本設定が必要な理由は、それが再実行時の整合性を担保するという点で重要だからではないかと思われる。
書き換え: 本設定は再実行の開始時に中間ファイルを削除する。削除しない場合は前回の出力が残り、結果が変わる。
解説: 「それは〜である。なぜなら〜だ」型の2文構成と「〜という点で重要」は英語構文の直訳形のため、何を実行し、どんな結果になるかを1文ずつで書く。
「〜ではないかと思われる」は推量述部を二重に重ねた曖昧化のため、確定している内容は事実として書く。
```

## メタ構造宣言

構成を本文で予告・自己解説する記述は、見出しと本文から読み取れる情報を繰り返す。
予告を削除し、規定・手順の内容から書き始める。

```text
悪い例: 以下の3つの観点から説明する。それぞれ順に見ていく。ここからが本題である。
書き換え: 検索フェーズはクエリを正規化してからベクトル検索を実行する。
解説: 「以下の〜から説明する」「順に見ていく」「ここからが本題」は構成の予告で内容を含まないため削除し、最初の項目から書く。
```

```text
悪い例: 見出し「キャッシュ設計の要点」の直後に、本文冒頭で「本節ではキャッシュ設計の要点について改めて整理する」と書く。
書き換え: 見出しを「キャッシュ設計」とし、本文冒頭を「キャッシュキーはリクエストURLとAuthorizationヘッダーのハッシュで構成する」とする。
解説: 見出しの言い換えを本文冒頭へ置くと同じ内容を2回書くことになるため、見出しは名詞句とし本文は具体的な規定から始める。
「改めて整理する」は自身の記述を解説する前置きのため削除する。
```

## AI偏愛語・名詞比喩・造語

根拠を伴わない抽象評価語と、道具・土台に見立てた名詞比喩は、対象の性質を述べずに価値だけを主張する。
観測できる構造・数値へ置き換える。

```text
悪い例: 変更箇所を読んだが、まだ原因が分からず、理解の解像度が上がらない。
書き換え: 変更箇所を読んだが、まだ原因を理解できていない。
解説: 分かった対象と未確定の内容を保ち、理解の程度を装う語を具体的な状況へ戻す。
```

```text
悪い例: 会議で初めて自分の案を説明できてうれしかった。人類の未来を拓く経験となった。
書き換え: 会議で初めて自分の案を説明できてうれしかった。
解説: 本人が述べた出来事と感想を残し、その体験から裏付けられない普遍的な価値を加えない。
```

```text
悪い例: 本ライブラリの本質は地に足のついた設計にあり、利用側の解像度を上げる土台となる。
書き換え: 本ライブラリは入出力を関数3つに限定し、内部状態を持たない。利用側は各関数を単体で呼び出すことができる。
解説: 「本質」「地に足のついた」「解像度を上げる」は根拠を示さない抽象評価語のため、構造の記述へ置き換える。
「土台となる」は名詞比喩のため、利用側から見た具体的な機能で書く。
```

```text
悪い例: 本規範は開発フローの羅針盤であり、品質の哲学を凝縮した結晶である。
書き換え: 本規範はレビュー時の判定条件を定める。判定条件を満たさない変更は差し戻す。
解説: 「羅針盤」「結晶」は道具・造形に見立てた名詞比喩のため、文書が定める内容そのものを書く。
「哲学」「凝縮」は対象を壮大に見せる熟語のため削除する。
```

## 唐突な否定と不変の表明

先行する文脈（直前の問い・話題・抽象度）が求めていない否定・除外・不変の表明は、読み手に問われていない問いを作らせる。
読み手の判断に要らない文は削除し、要る内容はその内容を求める問いや話題を示してから書く。

```text
悪い例: はい、その2件はサブエージェントです。最初の対象外の判断は撤回し、ツリー化の対象に含めます。（中略）process-loopが起動したprocess-wiセッション（106件）は、親となるセッションが無いため、トップレベルのままにする判断を変えていません。
書き換え: 最後の文を削除する。
解説: 撤回した判断の説明の直後に、問われていない別の判断の不変を述べており、読み手はその判断が問題になっていたかを考えさせられる。
```

```text
悪い例: レーンの検証を妨げる確定済みの既存不良を、メインが同じレーンへ名指しで認可し、レーン担当は計画の実装と別のcommitで直す。未確定や選好で決まる不良は従来の手順に残し、single-lane-processは変えない。
書き換え: 「single-lane-processは変えない」を削除するか、影響を受ける利用者の操作を仕様の水準で書く。
解説: レーンでの既存不良の扱いという仕様を説明している途中に、それまで出てこない別スキルの不変を実装の水準で挿入している。
```

```text
良い例: 実データで2回目以降の一覧が0.15秒を超えていたため、変更のないファイルの再確認と時刻の整形を省く。返す一覧の内容は変えない。
解説: 性能改善の説明では出力が変わるかが読み手の問いになるため、先行する文脈が求める否定として残す。
```
