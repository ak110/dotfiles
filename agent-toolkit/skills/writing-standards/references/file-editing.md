# 既存ファイルの編集

本書は既存ファイルをEditで編集する主体と、Writeで既存ファイルを上書きする主体へ、編集ツールが要求する読取状態と、編集の前後に確かめることを定める。対象はコード、文書、エージェント向け文書を問わない。改行とBOMの保全は`encoding.md`「書込ツールの改行・BOM保全」が定める。

## ファイル更新時の編集ツールの前提

編集方法を選ぶときは、担当が本文を理解したことと、編集ツールが要求する読取状態を分けて確認する。
Claude CodeのEditと、Writeによる既存ファイルの上書きは、同じ会話でその絶対パスをReadしていないと拒否される。発行する担当は、対象の絶対パスをReadで取得してから発行する。
BashやPythonによる取得、別の担当から受け取った本文、以前のWrite結果は、本文を理解した根拠として扱う。
次の取得は編集ツールの前提を満たさない。

- Bashでの表示。表示がRead状態になるかはホストのコマンド解析に依存し、変数を含むパスや複数コマンドの連結では成立しないため、前提として扱わない
- Bashのリダイレクト、`cp`、`sed -i`、`iconv`などで作成または変更したファイル
- 同じ内容を持つ別パスのRead

EditとWriteの前提は、担当自身がその絶対パスのReadに成功したことで確かめる。
成功した編集の通知が現在の状態を保持すると明示する場合は、その状態で連続編集を続ける。

複数のEditをまとめる場合は、各対象で必要なReadが成功してから編集群を発行する。
Readとそれに依存するEditは順に実行する。
Read不足の失敗が返ったら、同じ前提のまま残る編集を進めず、必要なReadの後に失敗した操作を回収する。
一括結果を受け取った場合は失敗した全操作を回収する。
スクリプトで機械的に置換する場合は、その手段の入力、一致数、終了状態と差分で確かめる。
Read履歴を持つEditとの区別を保ち、Codexのapply_patchは現在本文の確認とpatchの結果で検収する。
