# コメントの記述粒度

コード・スクリプトへコメントを書く前に読む詳細規定。

- ソースコードには必要最小限のコメントを書き、コードから自明な処理にコメントを付けない
  - 書く場合は「なぜそうするか」（設計判断の背景・閾値の選定理由等）または「何をしているか」（非自明な制御フローの要約）に限る
  - 実装の判断根拠となる外部の挙動、観測値及び選定の経緯は「なぜそうするか」に当たり、削減の対象にしない。
    文書化されていない外部APIのエラー本文のように、当該根拠を失うと後続の変更が分岐の成立条件を判定できなくなる情報は、観測した原文のまま残す
- 設定値・変数値・数値リテラルそのものは、同じ値がコード上に現れて重複記載となる場合はコメント本文へ埋め込まず、
  値の選定理由・制約の根拠のみを書く（値変更時のコメント修正漏れで実態と乖離することを避ける）
  - 当該値がコード上に現れないか、コード上の値と別の出所を持ち、かつ判断根拠として必要な場合は本項の対象から外し、出所とともに書く
- 実装詳細はインラインコメントに書き、モジュール冒頭のdocstring・fileoverviewコメントには
  「役割・スコープ・使い分けの指針」のみを置く（アルゴリズム選択理由等の非自明な判断は該当行直上へ移す）
- 同概念を扱う複数の関数で説明が重複する場合、本質的な説明は呼び出し関係の入口側1箇所に集約する。
  内部関数側は1行サマリーか入口関数への参照で済ませる
- ドキュメントはコードからわからない情報や意図・設計理由を書いて現在の状態を直接記述する
  （時系列表現は使わず履歴はコミットメッセージへ委ねる）
  - 過去の挙動が現在の判断の根拠となる場合は、履歴へ委ねず、当該挙動を判断根拠として現在の記述へ含める
