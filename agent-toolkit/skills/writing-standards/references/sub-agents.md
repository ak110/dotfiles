# サブエージェント定義ファイルの記述基準（Claude Code固有）

`agents/`配下のサブエージェント定義ファイルの新規作成・改訂と、サブエージェントが関与する手順の
作成・改訂で満たす基準を定める。
frontmatterの項目名と受理値は`https://code.claude.com/docs/ja/sub-agents.md`を正本とする。

## ディレクトリ構成

`agents/`配下にはサブエージェント定義ファイルだけを置き、参照資料・補助スクリプト・
サブディレクトリを作成しない。
`agents/`配下は再帰的に走査され、サブディレクトリ内のファイルもサブエージェント定義として登録される
（プラグインではサブディレクトリ名がスコープ付き識別子の一部となり、
`<plugin-name>:<サブディレクトリ名>:<name>`として公開される）。

定義が参照する資料は次の場所へ置く。

- 当該サブエージェントが担う工程だけで読む資料: 対応するスキルの`references/`配下。対応するスキルが無い場合はスキルの新設を検討する
- 複数のスキル又は定義が共有する資料: プラグインの`share/`配下。定義本文からは`${CLAUDE_PLUGIN_ROOT}/share/<ファイル名>`で参照する

## 起動文書のペア

サブエージェントを起動する手順は、呼び元用文書と呼び先用文書を別のファイルへ分ける（厳守規定。同じファイルへ両者の手順を置くと、呼び先が呼び元の割当・認可判断を作業契約として読み、責務境界が成立しない）。

- 命名は`<役割名>.parent.md`（呼び元用）と`<役割名>.subagent.md`（呼び先用）とし、役割名を両者で一致させる
- 配置は呼び先の所在にかかわらずプラグインの`share/`配下とし、`${CLAUDE_PLUGIN_ROOT}/share/<ファイル名>`で参照する。前節の資料の配置規定は、本節が定めるペア文書へ適用しない。単一のスキルからだけ起動するペアも`share/`配下へ置く。委譲先が呼び元スキルの所在を解決せず、`${CLAUDE_PLUGIN_ROOT}/share/<ファイル名>`の単一の書式でタスク文書へ到達する状態を保つためである
- 呼び元は起動時に`<役割名>.subagent.md`の絶対パスを起動プロンプトへ渡す
- 呼び先の恒常手順が`agents/`配下のサブエージェント定義として既に存在する場合は、定義本文が呼び先用文書を兼ねるため`<役割名>.parent.md`だけを置く

`<役割名>.parent.md`は、起動経路、起動前の前提（先行主体の終端確認、渡す資源）、渡す入力、受領する中間報告と返却物、検収条件を定める。呼び先固有の作業手順を書かない。
起動プロンプトの組み立て手順は`agent-toolkit:delegation`のSKILL.mdの`## 送信`を正本とし、`<役割名>.parent.md`へ複製しない。

`<役割名>.subagent.md`は、冒頭で受信者が担う責務、担わない責務、最初に行う行為を示し、続けて入力、実行手順、出力形式を定める。呼び元の割当・認可判断を書かず、別文書が正本を持つ手順を複製せず、当該文書の読込指示として書く。

### 必須入力名と起動対象の書式

`<役割名>.subagent.md`の`## 入力`は、見出しの直後へ`text`のコードブロックを1件置く。
当該ブロックの1行目を`必須入力名:`とその直後の半角空白で始め、当該文書がどの受領条件でも必須とする項目名をASCIIカンマ区切りで並べる。
当該行の項目名は起動文が用いる名称の正本とする。項目名にバッククォート、空白、コロン、全角の記号を含めない。
受領条件によって必須かどうかが変わる項目は当該行へ含めず、箇条書きの本文で条件とともに定める。
`## 入力`の項目を追加、除去又は改名する変更では、同じ変更単位で当該行を更新する。

`<役割名>.parent.md`は、H1の直後で最初のH2より前へ`text`のコードブロックを1件置く。
当該ブロックの1行目を`起動対象:`とその直後の半角空白で始め、当該文書が直接起動する呼び先用文書のファイル名をASCIIカンマで区切って並べる。当該行を起動関係の正本とする。
`<役割名>.parent.md`は、当該行が挙げる各呼び先の`必須入力名:`が並べる項目名を本文へ逐語で記載し、項目ごとに値の確定規則を書く。項目名を言い換えた別名を本文へ置かない。
項目を箇条書きで列挙する場合は、当該箇条書きの本文を項目名で始める。
項目名の直後へ置けるのはコロン・句点・読点・全角丸括弧・空白のいずれかとする。
項目名へ語を足した表記で箇条書きを始めない
（厳守規定。別名で始めた箇条書きは、起動側が当該箇条書きと`必須入力名:`の値を対応付ける工程を要する。対応を誤ると起動時の必須入力検査が当該項目の欠落を報告し、呼び先が起動しない）。

### 呼び元用文書の自己完結

`<役割名>.parent.md`は、呼び元の工程（起動前の確認、入力の確定、返却物の検収）に必要な定義を自身の本文だけで与える。
当該定義を`<役割名>.subagent.md`の節、必須入力名又は本文を読ませる記述で代替しない。
次の2つは当該記述に当たらない。起動引数として渡す`<役割名>.subagent.md`の絶対パスの指定と、呼び先の作業手順の正本が当該文書であることを述べる記述とする
（厳守規定。呼び元が呼び先用文書も読むと、同じ契約を2箇所から取得することになる。改訂が片側だけへ入ったとき、どちらを正本とするかを起動側が判定できない）。

## 委譲文書の責務分離

- 委譲元は委譲経路、入力資料、制約、返却物、検収条件を定める。委譲先固有の作業手順は書かない
- named agentは調整責務と受信形式を定め、呼び出し時には所定のタスク文書のパスだけを受け取る
- 受信するタスク文書は実施内容、対象、必要な作成・レビューの規範スキル、検証、返却形式を定める
- 受信するタスク文書は、完了報告と作成する成果物の言語を日本語とする条件を含める
- skillはユーザーまたは委譲元が選ぶ作業入口を定める。named agentやタスク文書の本文を複製しない
- 同じ判断を委譲元と委譲先の双方が必要とする場合は共通skillへ置き、双方から参照する
- 起動入力は、受信者が適用する規範スキル、プラグイン内文書、役割から一意に導けない値だけを渡す。受信者が自ら選択できるスキル、文書、手順を入力へ重複させない

## frontmatter

- エージェント定義はセッション起動時に読み込まれる。実行中のセッションで新規作成又は改訂した定義は、当該セッションの`subagent_type`から解決できない
- 明示された起動経路からだけ起動する定義は、`description`へ起動経路だけを書き、`user-invocable: false`を設定する。責務・処理概要・手順を`description`へ書かない（`description`は自動委譲の判定材料として恒常的にコンテキストを消費し、呼び出し元が起動契約を明示済みなら再掲を要しないため）
- `description`は、起動元のスキル名又は起動契約を一意に特定できる文面とする
- 起動時に常に必要な規範スキルは`skills`へ列挙する。列挙したスキルは全文が起動時のコンテキストへ注入されるため、本文へ当該スキルの起動手順を書かない。特定の工程だけで必要なスキルは列挙せず、観測可能な起動契機とともに本文へ起動手順を書く
- `model`は`inherit`を既定とする。特定モデルへ固定する場合はfrontmatter内のコメント行へ理由を書く
- `tools`の制限は省略し、無制限を既定とする。限定する場合はfrontmatter内のコメント行へ理由を書く
- `effort`は当該サブエージェントが担う工程が要する推論量へ合わせて設定する

`model`・`tools`の理由は、当該サブエージェントの実態（選択したモデル種別、除外したツール集合）と
整合する形で書き、整合する理由を記述できない場合は既定値を採用する。

`skills`が注入したスキル本文には、所在ディレクトリの絶対パスの表示が付随する
（公式ドキュメントに記載のない実測挙動。サブエージェント記録で確認済み）。
プラグイン内の他ファイルを参照する定義は、この所在から確定したplugin rootの相対パスで解決する。
スキル配下の`references/`は`skills`の宣言では読み込まれないため、
必要な参照文書は定義本文から明示的に`Read`する。

## コンテキスト境界

サブエージェントは呼び出し元と別のコンテキストで動作し、呼び出し元の会話履歴、
呼び出し元が読み込んだファイル、呼び出し元が起動したスキルを引き継がない。
サブエージェントとその下位のサブエージェントの間も同じ関係になる。

起動経路を問わず、委譲元と委譲先の文脈が独立することを前提として手順を設計する。設計時の判定は`agent-toolkit:delegation`の`references/base-contract.md`を正本とする。
`agents_server`で起動した委譲先が起動時に受け取るものは、起動プロンプトと、`agent-toolkit:delegation`の`references/runtime-routing.md`「経路」が定める起動条件で決まる。当該委譲先は`agents/`配下の定義本文と`skills`の宣言を受け取らない。

`Agent`ツールで`agents/`配下の定義から起動したサブエージェントが起動時に受け取るものは次のとおりとする。

- 定義本文と、実行環境が付与する環境情報
- 呼び出し元が組み立てた起動プロンプト
- 呼び出し元が読み込むメモリー階層（`CLAUDE.md`・プロジェクトルールなど）
- 親セッションの開始時点で取得したGitステータス（作業ディレクトリがGitリポジトリでない場合と、`includeGitInstructions`が`false`の場合は付かない）
- `skills`で宣言したスキルの全文
- `main`とセッション内の他の名前付きエージェントを列挙した名簿（当該定義の`tools`が`SendMessage`を含み、ほかに名前付きのエージェントが1つ以上ある場合に付く。Claude Code v2.1.206以降）

呼び出し元は定義本文を読まないまま起動プロンプトを組み立てる。
起動に必要な入力の項目は、定義本文ではなく呼び出し元側の手順へ書く。

サブエージェントが関与する手順を作成・改訂する場合は、確定前に次を確認する。

- 手順が要求する判断ごとに、判断主体が起動時に受け取るものだけでその判断へ到達できる
- 起動元・工程・処理段階の区別を条件とする記述では、当該区別を起動プロンプト、宣言したスキル又は参照する文書から観測できる
- 呼び出し元側の手順が渡す入力項目と、定義本文が要求する入力項目が一致する

起動元の名称、経路又は工程を条件に用いる記述は、起動プロンプトへ当該条件を判別できる入力が現れる場合だけ成立する。
成立しない場合は、呼び元用文書へ当該条件を起動文へ明示させる要求を置くか、起動プロンプトから観測できる別の入力の有無へ条件を置き換える。
いずれを選ぶ場合も、改訂前の条文が適用されていた範囲を狭めず、広げない
（厳守規定。観測不能な条件を除去する目的で適用条件を緩和すると、当該条文が想定していなかった起動経路まで同じ扱いになる）。
