# 画面の主題別設計

本書はフォーム、一覧、検索、通知、パネル、AI機能、同意と解約、多言語表示を含む画面の計画、実装とレビューで使う。最初にエンドユーザーの作業と中断できる範囲を特定し、各主題の操作を結果までたどる。

参考資料: [ux-designer-skill](https://github.com/szilu/ux-designer-skill)、[frontend-ui-ux-skill](https://github.com/overseek944/frontend-ui-ux-skill)。主題の判断材料を再構成した。アクセシビリティと性能の数値は[W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)と[web.dev Core Web Vitals](https://web.dev/articles/vitals/)に従い、共通値は`ui-ux.md`に置く。

## フォームと入力

入力は判断の順にまとめ、必須・形式・上限を事前に示す。確定したエラーを対応する欄で伝え、送信時には全体を検証して問題へ到達できるようにする。入力を失う操作では保存・破棄・継続を選べるようにする。

## 一覧とデータ表

一覧では対象と次の操作を識別できるようにし、並び順・位置・選択状態を示す。一括操作の対象集合と結果、閲覧を中断した位置への復帰手段を保つ。

## 検索

入力中の候補は、その候補を選ぶと何が起こるかを示す。結果0件では検索条件を保ち、条件の解除または再入力へ進める操作を示す。元データが空の場合は検索条件による0件と区別する。非同期検索では最新条件の結果だけを適用する。

## 通知と割り込み

通知は作業を止める必要性と後から参照する必要性で選ぶ。エラーは読んで閉じられるまで保持し、取り消しを示す場合は操作できる手段を置く。通知で配置とフォーカスを不用意に変えない。

## モーダル、サイドパネル、全画面

モーダル・パネル・全画面は作業の長さ、中断の必要性、元の文脈を参照する必要性で選ぶ。閉じる操作、未保存変更、フォーカスの復帰、狭い幅でも操作できることを確かめる。

## AIを使う画面

生成された内容をエンドユーザー自身の内容と区別し、出典を提示できるときは確認できる位置に示す。生成の進行と停止、AIが加えた変更の取り消し、エンドユーザーによる上書きを用意する。生成物が未確認なら未確認と伝え、エンドユーザーが最終判断できる操作を保つ。

## 同意、拒否、解約

任意の同意は初期状態では未選択にする。承諾と拒否は同程度に見つけやすくし、拒否を責める文言を除く。解約の操作は登録と同程度に到達しやすくし、結果、影響と必要な保存操作を実行前に説明する。

## 多言語表示

翻訳対象を分離し、訳文の長さ・文字方向・地域設定が変わっても操作と内容へ到達できるようにする。固有名とコード片は翻訳対象から除く。
