# 画面の主題別設計

本書はフォーム、一覧、検索、通知、パネル、AI機能、同意と解約、多言語表示を含む画面の計画、実装とレビューで使う。最初に利用者の作業と中断できる範囲を特定し、各主題の操作を結果までたどる。

参考資料: [ux-designer-skill](https://github.com/szilu/ux-designer-skill)、[frontend-ui-ux-skill](https://github.com/overseek944/frontend-ui-ux-skill)。主題の判断材料を再構成した。アクセシビリティと性能の数値は[W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)と[web.dev Core Web Vitals](https://web.dev/articles/vitals/)に従い、共通値は`ui-ux.md`に置く。

## フォームと入力

入力欄は判断の順に配置し、関係する欄を見出しやfieldsetでまとめる。必須か任意か、形式と上限を入力前に示す。利用者が欄を離れた時点で確定できるエラーを近くに伝え、送信時には全体を検証して最初の問題へフォーカスを移す。入力値を失う操作には保存、破棄、操作継続を選べる手段を置く。

## 一覧とデータ表

一覧へ主要な識別情報と次の操作を置き、詳細を開く前に対象を区別できるようにする。並べ替えのキーと方向、ページ位置、選択状態を示す。一括操作は対象集合と結果を確認できる形にする。無限スクロールを採用する場合は閲覧位置と復帰手段を保つ。数値の比較列には等幅数字を使う。

## 検索

入力中の候補は、その候補を選ぶと何が起こるかを示す。結果0件では検索条件を保ち、条件の解除又は再入力へ進める操作を示す。元データが空の場合は検索条件による0件と区別する。非同期検索では最新条件の結果だけを適用する。

## 通知と割り込み

入力欄の問題は欄の近くへ、画面全体を止める重大な判断はモーダルへ置く。作業を続けながら参照する情報はバナーへ、操作の短い結果はトーストへ、後から確認する件数はバッジへ置く。トーストの成功通知は4〜8秒を目安に自動で閉じ、エラーは利用者が読んで閉じられるまで残す。取り消し操作を載せるトーストには操作可能なボタンを置く。通知が画面の配置とフォーカスを保持することを確認する。

## モーダル、サイドパネル、全画面

現在の作業を一時停止し、短い判断を求める場合はモーダルを使う。元の一覧や文脈を参照しながら編集・閲覧する場合はサイドパネルを使う。長い作業、多段入力又は広い比較を要する場合は全画面を使う。いずれも閉じる操作、未保存変更、開閉前後のフォーカス、狭い幅での操作を確認する。

## AIを使う画面

生成された内容を利用者自身の内容と区別し、出典を提示できるときは確認できる位置に示す。生成の進行と停止、AIが加えた変更の取り消し、利用者による上書きを用意する。生成物が未確認なら未確認と伝え、利用者が最終判断できる操作を保つ。

## 同意、拒否、解約

任意の同意は既定値を未選択にする。承諾と拒否は同程度に見つけやすくし、拒否を責める文言を除く。解約の操作は登録と同程度に到達しやすくし、結果、影響と必要な保存操作を実行前に説明する。

## 多言語表示

画面の文字列を外部化し、訳文が長くなっても収まる幅を設計する。画像へ翻訳対象の文字を直接埋め込まず、言語と文字方向の変更を確認する。日付と数値は表示先の地域設定で整形し、固有名とコード片は翻訳対象から除く。
