# 文書の役割と種類

文書が後続の読者へ何を伝えるかを決め、参照用、作業用、経緯記録の用途を選ぶ。ファイル名だけでは決めない。参照用文書には現行の仕様や使い方を残し、作業中の進捗は作業用文書で扱う。経緯記録には後から判断を検証するための事実を残す。情報の置き分けは`writing.md`「人間向け文章の共通規定」に従う。

次の表は読者と役割を選ぶための案内であり、見出しのテンプレートではない。各種類の形式と判定の詳細は示した専用規定を読む。

| 文書 | 主な読者と役割 | 伝える内容と詳細規定 |
| --- | --- | --- |
| README | エンドユーザーと開発者が使い始める参照用 | 対象、できること、導入の前提、主要な操作と詳細資料への案内。文章は`writing.md` |
| 利用ガイド・運用手順 | エンドユーザーと開発者が操作を確かめる参照用 | 操作の前提、手順、期待結果、条件が合わないときの対応 |
| 構成の説明 | 開発者と保守担当が全体構成を把握する参照用 | 配置、責務と境界、配布先、主要な接続と実装との対応 |
| 設計の記録 | 開発者と保守担当が理由を引く参照用 | 制約、構造、選択理由、退けた案と影響。分割資料では主題を探せる目次 |
| エージェント向け文書 | コーディングエージェントが判断に使う参照用 | 読み手、適用契機、判断基準と次の操作。`agent-documents-basics.md`、`agent-documents-additions.md`、`agent-skills.md`など該当資料 |
| 方針の由来の記録 | 後続の開発者とエージェントが過去の判断を調べる記録 | 決めた内容と背景、現在その判断を適用する規範との関係 |
| 障害の記録 | 後続の開発者とエージェントが再発防止に使う記録 | 観測事象、直接原因、対策、発生条件 |
| 検証記録 | 後続の開発者とエージェントが技術判断を再検証する記録 | 観測条件、結果、再検証手段と結果に依存する判断 |
| 計画ファイル | 実行担当が変更を進める作業用 | 要件、変更、検証、終端と進捗の対応。形式は`agent-toolkit:plan-mode` |
| AWI・UWI | ユーザーと実行担当が要求と確認を共有する作業用 | AWIの対象と完成条件、UWIの問いと判断材料。形式は`agent-toolkit:wi-standards` |
| 実行レビュー指摘管理表 | 実装担当とレビュー担当が是正を追跡する作業用 | 指摘、根拠、採否と対応結果。形式は`agent-toolkit:review-standards` |
| コミットメッセージ | 開発者が変更目的を履歴からたどる記録 | 何をなぜ変更したかを件名と必要な本文で示す。形式は`agent-toolkit:commit` |
| PR・MRの説明 | レビュアーと関係者へ審査を依頼する連絡 | 変更の目的、届く結果と確認済みの範囲。文章は`writing.md`、投稿前の確認は`agent-toolkit:external-write-review` |
| Release本文 | エンドユーザーと開発者へ配布済みの変更を伝える記録 | エンドユーザーへ届く変更、必要な操作と注意点。投稿前の確認は`agent-toolkit:external-write-review` |
