# 計画起草委譲プロンプト

`plan-codex-delegate`（用途: 計画作成）の初回・継続プロンプトテンプレート。
`{materials}`は呼び出し元（`plan-file-creator`）が渡す合意済み事項一式・提示素材原文・
対象ファイル一覧・「編集対象にコーディングエージェント向け文書が含まれるか」の判定結果を機械転記する。
埋め込み欄の分割・見出し粒度は`plan-file-creator`が起動プロンプト受領時点の構造をそのまま踏襲してよい。
既存実装の挙動保存が要件となる起草では、`{materials}`へ当該実装の本体を引用形式で含める。
対象には既存処理の移設と既存APIの呼び出しを含む。
シグネチャの記述だけでは推測による呼び出しを防げなかったため、実装本体を材料とする。
実装本体の引用による対策の有効性は未実測であり、導入後の再発有無で評価する。
`{quality_standards_paths}`は`{materials}`中の対象ファイル一覧・判定結果に応じて`plan-codex-delegate`が
埋め込む絶対パスである。計画ファイル自体が文書であるため`writing-standards/SKILL.md`は常に含める。
「編集対象にコーディングエージェント向け文書が含まれるか」の判定結果が真の場合は
`agent-standards/SKILL.md`を追加する。対象ファイル一覧にコード・テストコードの新規作成・修正
（非Markdownの実装ファイル）を含む場合は`coding-standards/SKILL.md`を追加する
（同規範「コード・テストコードを新規作成または修正する時、その計画時…に最初に必ず呼び出すこと」の
起動条件に該当するため）。複数条件に該当する場合は該当する全パスを列挙する。
`impl-prompt.md`の`{quality_standards_paths}`は呼び出し元が渡す対象種別で分岐する別方式であり、
本欄は`{materials}`内の対象ファイル一覧から`plan-codex-delegate`自身が判定する点が異なる。
`{plan_mode_skill_path}`・`{sample_path}`・
`{textlint_violations_path}`はいずれも本エージェント自身が解決した絶対パスとする。

以下が初回プロンプト本文である。

```text
{plan_full_path}（新規作成時は親ディレクトリの実在を確認済み）にこの計画ファイルを作成して。

## 完成条件

{plan_mode_skill_path}「計画ファイルの完成条件」節を直接読み込んで適用すること。
参照テンプレートは{sample_path}、頻出textlint違反の予防策は{textlint_violations_path}
「頻出違反パターン予防策」節を直接読み込んで適用すること。

## 品質規範

{quality_standards_paths}を直接読み込んで適用すること。

## 材料

{materials}

## 遵守事項

- 判断・調査・ユーザー確認はすべて計画ファイル内で確定し、実装段階への先送り表現は書かない。
- 「材料」に記載された合意済み事項・エージェント判断・却下した代替案は、計画ファイルの対応する節へ
  過不足なく転記する。「材料」に記載の無い新規の設計判断（ユーザー合意・調査確定を要する事項）を
  自ら考案して計画ファイルへ書き加えない。転記の過程で材料の不足に気付いた場合、計画ファイル側は
  空欄のまま残さず現状わかる範囲で記述したうえで、不足点を完了報告で報告する
  （不足の解消は呼び出し元`plan-file-creator`の責務とする）。
- 既存実装の挙動保存が要件となる起草は、「材料」に引用された実装本体を根拠とする。
  実装本体がなくシグネチャだけが提示された場合は推測で補わず、不足点として完了報告へ記載する。
- git commit・push・タグ作成などの不可逆操作、および対象計画ファイル以外のファイル変更は行わない。
- 書き込み完了後に`wc -l {plan_full_path}`を実行し、実行結果（行数）を最終応答へ含める。
```

継続時は以下のプロンプトを使う。

```text
以下の不足点を反映して計画ファイルを更新して。

{不足点全文}
```
