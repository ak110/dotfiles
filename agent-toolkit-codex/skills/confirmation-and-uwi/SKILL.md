# 確認とUWIの状態遷移

本スキルは、確認要否の判定から回答後の作業再開までを一続きに扱う手順を提供する。
UWIの本文、投入、状態及び依存関係の形式は`agent-toolkit:wi-standards`を起動して適用する。

## 確認要否の判定

候補ごとに次の順で判定する。

候補の比較へ進む前に`agent-toolkit:review-standards`を起動し、`review-standards/references/judgment-details.md`を全文読む。
既存の条件分岐、状態及び手順を維持する案だけでなく、元の要求に不要な分岐、条件又は確認を除去して成立する案も候補へ含める。

1. ユーザーの指示、成立済み承認及び規範から、操作、対象と副作用が許容されるかを判定する。
2. 許容される候補のうち、依頼された成果に必要な変更だけを残す。
3. 必要な変更の実装品質を比較し、技術資料又は実測で一意に決まる選択を確定する。

確定した候補について、次のいずれかへ分類する。

- 技術判断で確定し、公開インターフェース変更、破壊的操作、第三者又は外部サービスへの影響、ユーザーが直接観測する出力変更のいずれにも当たらない場合は、確認せず実施する。
- 同じ操作、対象、影響範囲と成立条件について承認済みの場合は、その承認を適用して再確認しない。
- 可逆で第三者又は外部サービスへ影響せず、復元に外部操作を要しない変更は、最善案を実施して事後承認へ送る。
- それ以外の承認対象と、技術判断だけでは決まらないユーザーの選好は、実施前の確認へ送る。

確認本文には、判断対象、推奨案、代替案、根拠、影響範囲及び回答後に実施する操作を書く。

## 確認経路

ユーザーへ直接質問できるメインは、実行環境の構造化質問を使う。同一セッションで同期的なユーザー確認が回答なしで終わったことを観測した後は、同じセッションの以降の確認を同期的に発行せず、`agent-toolkit:wi-standards`が定めるUWIへ記録して依存する作業だけを保留する。実行環境の待機上限による回答なしをこの切替条件として扱うのは自律実行に限り、協調実行ではユーザーの後続発話を待つ。
委譲先は質問もUWI投入も行わず、確認事項と推奨案を呼び出し元へ返す。

事後承認では変更を元へ戻さず、実施内容、根拠、影響及び復元方法を確認本文へ書く。自律実行では事後承認型UWIを投入し、元の作業を継続する。

## 回答後の状態遷移

回答済みUWIの通知を受領した主体は、次を同じ作業の連続した工程として完了する。

1. `atk wi show <UWIファイル名> --target-repo=<対象リポジトリ>`で質問と回答を読み、暫定判断との差分を確定する。
2. 回答を元の作業へ反映する。回答済みUWIを通常AWIへ変換せず、別の作業要求が明示された場合だけ独立したAWIの要否を判定する。
3. 反映が成立したUWIを`atk wi adopt <UWIファイル名> --target-repo=<対象リポジトリ>`で終端する。回答が質問を退けた場合は`reject`を使い、理由を回答と対応付ける。
4. 当該UWIへ依存するAWIのreadinessを再評価し、回答待ち以外の阻害条件が無ければ元の処理を再開する。
5. 元の`agents_server` sessionを保持している場合は同じsessionへ回答を配送して再開する。保持していない場合は、計画又は引き継ぎ記録から未完了工程だけを再開する。

状態変更コマンドの成功報告と警告の不在を各遷移の完了根拠とする。途中で失敗した場合は、成功済みの状態を巻き戻さず、未完了の遷移から再開する。
