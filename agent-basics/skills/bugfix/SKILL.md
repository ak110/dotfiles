# バグ対応

観測された不具合は、本来あるべき仕様（期待契約）と直接の原因を確定してから修正し、原因が異なっても同じ害の型の問題を防ぐ。
害の型は、原因の違いを問わず、消費主体から見て同じ種類の損失や是正負担を生む問題のまとまりを指す。
期待される結果・品質・手順・判断からの逸脱、またはその疑いは、対象の種類、工程、発見者、修正の有無を問わず、事象ごとに「初動の判断」を適用する。
同じ文脈で本スキルを取得済みなら本文を再利用し、今回の事象への適用結果を残す。
同じ事象の再通知で、本文・対象版・前提が変わらず新しい証拠もない場合は、既存の原因・影響・処置・再検証・終了根拠の記録を再利用できる。
記録の不足があればその部分だけを補い、充足済みの分析・修正・再検証は再利用する。
別件や再発した事象は初動に戻し、今回の事象に対応する原因と処置を確かめる。
ユーザーの介入、セルフレビューと他者のレビュー指摘、lint・型検査・自動テスト・CIのエラー、エージェントの行動誤りを示すhookの拒否、自分で気付いた作業ミスは、その例である。
エージェントの作業ミスや既存規範への違反も、初動で直接原因と影響を確認する。
未適用を生んだ要因を確認し、自己発見や再実行の成功だけを分析免除の根拠にしない。
初動の手順3の兆候がある場合に、その行動を生成・許容した規範と適用経路・作業構造を詳細分析する。
対象化の後に期待契約との比較で正常動作と欠陥を分け、影響に応じて分析の深さ・処置・再発防止策の採否を決める。
同じ種類と規模のミスでも、ユーザーが指摘した場合はユーザーの時間と是正の負担を重大度へ加える。
既存の検出が有効に働いた初回の指摘・エラーでは、後述の詳細化条件を確認した上で、再発防止策の検討を省略できる。
ユーザー介入で発覚した場合は、最初の指摘から同じ種類の指摘を再び受ける負担を含めて再発防止策を比較する。
詳細分析への移行は、発見者や発見工程によらず、初動で確認した原因・影響と反復の兆候から決める。
未対応（ユーザーの要求を満たさないまま完了した項目）やデグレード（過去に動作していた機能や定めた規範の喪失）も、不具合と同じ初動手順で扱う。
本スキルは、原因分析、類似箇所の見直し、対策および再発防止策の定義を定めたものである。
呼び出し元の各工程の文書では起動の契機、入力、権限、結果の適用、記録を定め、分析手順や処置の妥当性判断は本スキルを参照する。
ユーザーの発話が新規の要求や提案の形式であっても、実際の作業内容が本スキルの対象に該当する場合は、作業着手前に本スキルを適用する。
対象（成果物・規範・仕組み）が資料や要求の目的を満たしているか、不足・未対応があるかを判定する作業も対象に含める。
欠陥や不足の判定を伴わない単純な改善提案、正常な進捗照会、誤操作を伴わない通常の分割取得、予定された負例試験は、作業ミスへ変換しない。
実装や文章の品質は`agent-basics:writing-standards`、レビューの判断基準は`agent-basics:review-standards`に従う。

原因を確定するには仕様や契約、実装、記録を確認する手段が必要であり、再現や修正には対象コードを実行・編集できる権限や環境が必要である。
提示された資料の読み取りしかできない環境では、確認が取れた原因と未確認の候補を区別し、調査条件や修正案の下書きを返す。
追加情報の取得、再現、実際の修正は、それらの操作を実行できる環境で行う。
詳細分析の下書きは[文章の品質基準](references/quality-standards.md)に沿って確認する。

詳細分析で用いるQCD・3段判定、事実と推論、硬い制約・努力目標の詳しい定義は、次の資料に従う。

- `../writing-standards/references/quality-principles-qcd.md`
- `../writing-standards/references/quality-principles-facts.md`
- `../writing-standards/references/quality-principles-constraints.md`

## 初動の判断

次の手順は本体だけで実施できる。
本スキルの追加資料は、詳細化条件が成立した場合に、必要な判断に対応する読込表の行から選ぶ。
単純な実装エラー、CI失敗、レビュー指摘、ユーザー介入、文書誤りは、原因と影響が確認できれば発見経路だけを理由に詳細化しない。

1. 期待する契約と実際の結果、発生条件、対象版、既存の診断・差分・証拠を対応付ける。
   正常な回復や予定された負例は欠陥へ変換せず、未確認事項と欠陥の疑いを区別する。
   期待契約どおりの正常動作・正常な回復・予定された負例と確認できた場合は、事象、期待との対応、確認した証拠、修正不要の根拠を短く記録して終了できる。
2. 直接的原因を既存証拠から確認する。
   不足する場合は原因候補を分ける最小の再現・比較・計測で確かめ、生成・変換・途中検証・最終消費のどこまで確認したかを示す。
   上位の構造原因や判断意図を推測で補わない。
3. 消費主体への影響、波及範囲、回復可能性、頻度を確認する。
   後段で回復した誤りも品質への影響を記録し、ユーザーの是正負担を含める。
   初動で直接原因や影響を説明できない、同じ害が反復する、回避処理が増える、複数箇所の責務へ波及する、重大な影響がある場合は詳細分析へ進む。
   初回・修正済みという事情だけではこれらの兆候を免除しない。
4. 局所修正と、原因を除く整理・統合・撤去を、必要な結果を保てるか、変更と継続保守の負担から比較する。
   必要な機能・契約を保ち、原因と直接影響範囲を是正できる最小の構成を選ぶ。
   同じ原因が成立しうる近傍を確認する。
   正常時、処置自身の失敗時、他の処置との相互作用で生じる問題と最悪結果を、元の問題の損失・頻度・回復可能性と比べる。
   主経路の成果を失う案は選び直す。
   認可、安全性、セキュリティ、データ完全性と明示された結果を守り、追加の認可や結果の変更は依頼元へ確認する。
   再発防止を検討する場合は、今回の原因と異なる原因でも同じ害を防ぐ案を、誤りを不要にする構造の整理・統合・撤去、既存検査、手順や説明の改訂から選ぶ。
   防げる損失と、導入・読込・実行・保守の継続費用を比べ、採否と理由を短く残す。
   ユーザー介入の場合もこの比較を本体だけで行え、影響が限定され原因と有効な処置を確認できれば詳細化は不要である。
5. 修正を適用し、元の失敗条件と影響する正常条件を再検証する。
   解消しない、別症状が生じる、影響範囲を限定できない場合は詳細分析へ進む。
6. 既存の作業記録・指摘管理表・報告へ、事象、期待、直接原因と根拠、影響、処置、再検証結果、終了根拠を短く残す。
   詳細化の兆候がなく、原因と影響が確認でき、修正と再検証が完了した場合は、この短記録で終了できる。
   近傍確認の範囲・限界と残存リスクも示す。
   初動に2系統・L1〜L4の表やリポジトリ全体・履歴・ログの一律探索を要求しない。

## 詳細分析

初動で詳細化条件が成立した場合は、読込表の該当資料を取得し、次の順に進める。

1. 分析対象を選別するため、期待契約と比べた品質・結果への影響、または観測した無視できない費用を既存証拠から確認する。
   必要な入力を回収した切り詰めなど正常回復だけを欠陥とせず、未回収・未達・判断を変える診断を保持する。
   分析表や点検記録は、考える工程としての形式を維持する。
2. 観測範囲を明確にするため、期待契約、実際の症状、発生条件、対象バージョンと取得済み証拠を整理し、出所と未確認事項を区別する。
   原因を絞る不足情報を最小の負担で得る調査として、診断の精読、コード・差分・正常系との比較、公式仕様、再現、追加計測を使い分ける。
   明確なlint診断、保存済みのテスト失敗、実行を伴わないレビュー指摘は既存証拠を先に使い、挙動や発生条件が不明なら再現・計測を優先する。
3. 原因を裏付けるため、対策の前提となる入力や外部挙動の生成・変換・観測・消費を対応付け、コードや合成入力で説明できた範囲と実入力で確認した範囲を分ける。
   `references/root-cause-analysis-evidence.md`「直接的原因と事象時点の確定」に従い、原因仮説を検証し、直接的原因、作り込み・見逃しの要因、根本原因を確定する。
   特定できない場合は候補を絞る条件を記録する。
   深度・重大度によらず、`references/analysis-records.md`の確認完了基準を適用し、記録形式は前掲の比例性を保つ。
   詳細分析では2系統・L1〜L4の結論を残す。
4. 影響に合う深さを選ぶため、エンドユーザーや利用システムへの影響、波及範囲、回復可能性からQ影響と重大度を判断し、根拠を残す。
   Q影響とC・Dだけの問題を区別し、後段の確認・再実行で回復した誤りと、どちらに当たるか判断が分かれる問題もQ影響として扱う。
   未知の問題の探索終了基準と是正範囲は分けて決める。
5. 利用主体から見た害の型を定め、`references/root-cause-remediation.md`「類似見直し」の標準母集団で、原因を問わず同じ害の型の過去事例を調べる。
   期間外の反復にユーザーが言及した場合は、その発話を事例に含める。
   過去事例があれば原因ごとの修正だけで完了にせず、害の型へ作用する再発防止策を検討する。
   原因から調査母集団を導き、重大度によらず段階的な類似見直しを行い、重大度を母集団の広さと判定の深さへ反映する。
   初回検出の例外を踏まえ、対策・回帰防止策と、類似見直し観点・再発防止策の作り込み・見逃しの各候補を区別し、採否は影響度と総費用で別に決める。
   再発防止策を見送る前に、`references/root-cause-prevention-selection.md`「再発防止策」に従い、原因となった入力・条文・参照経路を除去・改訂する案を候補に含めて比べる。
   認可の境界と指定された結果を維持し、結果を変える処置や認可を要する操作は事前に合意を得る。
   採用した処置の適用と有効性、修正後の解消を確認する。
   未再現・解消済み・文書の誤りは手順3の参照先に従い、軽微な問題は調査範囲と限界を示す。
   実行不能・権限不足・根拠取得不能は、目標未達の理由と区別して報告する。
