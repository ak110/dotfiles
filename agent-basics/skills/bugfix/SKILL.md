# バグ対応

期待からの逸脱（エラー、失敗、指摘、自分のミス、未対応、退行）とその疑いに気付いたら、直す前にこの手順を使う。
逸脱は直す対象である前に情報である。
目的は、目先の失敗を消すことではなく、期待した結果を最も少ない仕組みで取り戻すことである。
同じ文脈で本書を読んだ後の別の事象にも、事象ごとに5つの問いを適用する。

## 5つの問い

1. 期待: 何が起きるはずだったか。
   その期待（要件、検査、試験、仕組み、規範、自分で足した目標）は、誰が何のために求めたもので、今も正しく必要か。
   試験や検査の失敗なら、製品コードより先に観測方法、期待値、実行環境、検証スクリプトを確かめる。
   正常な動作、正常な回復、予定した失敗だと分かったら、その根拠を報告か作業の記録へ1行残してここで終える。
2. 原因: 何がそれを起こしたか。
   観測（診断の全文、差分、再現、正常な例との比較）で確かめる。
   確かめていない部分は推測と呼ぶ。
   同じ誤りの2回目なら、その誤りを誘った入力（手順の例、直前の出力、置いていた前提）を探す。
3. 処置: 無くす、単純にする、直す、足すの順に比べ、期待した結果を保てる最初の案を採用する。
   修正は通常の変更である。
   その成果物の品質基準（`agent-basics:writing-standards`、`agent-basics:review-standards`など）を、新規の変更と同じに適用する。
   結果を変える処置と、認可の要る操作は、先に合意を得る。
   認可、安全性、データの完全性、公開している契約を弱める案は除く。
4. 広がり: 同じ仕組みは他のどこにあるか。
   同じ害を防ぐはずの対策（規範、検査、試験）は既にあったか。
   検索して確かめ、見つけた同じ誤りは一緒に直す。
5. 確認: 元の失敗を観測した方法で、直ったことと、周りの正常な動作が保たれたことを確かめる。

読むことしかできない環境では、確かめた原因と推測を分け、調べる条件と修正の案を返す。

## 書き出す場面

次のどれかに当たる時は、処置を適用する前に、5つの問いへの答えを各1行で作業の記録へ書く。
処置の前に結果が出ていない行（広がりの検索の結果、確認）は予定を書き、終えた時に結果へ書き換える。
どれにも当たらない時（既存の検査が初めて見つけた単純な誤りなど）は、5つの問いを考えて直せばよい。

- ユーザーに指摘された。
- 同じ症状への2回目の修正である（同じ誤りを別の対象で繰り返した場合を含む）。
- 処置が何かを足す（回避処理、分岐、再試行、待機、例外、検査、規範の文章）。
- 処置が期待の側を変える（試験・検査・設定を緩める、要件を読み替える、対象から外す）。
- 完了を報告した後か、公開した後に見つかった。
- 害が大きい（データの破損、安全、認可、公開している契約、依頼の未達）。

## 確認観点

次の条件が成立した時だけ、その資料を全文読む。
読み方は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 問い1で期待の出所や必要性が分からない。問い3で足す案か期待を緩める案しか出ない | `references/premises.md` |
| 問い2で原因を説明できない。外部の挙動、並行する処理、試験の作り、所要の増大、他者からの報告が関わる | `references/causes.md` |
| 問い4の探し方を決める。害が大きく、探す範囲を広げる | `references/spread.md` |
| 問い4で対策が既にあった。同じ誤りを繰り返した。2回目の修正でも直らない。直したら別の症状が出た | `references/recurrence.md` |
| 再発防止を検討する（不具合を観測した場合か、費用・所要だけの改善機会の採否を決める場合） | `references/prevention.md` |
| CIの失敗を扱う | `references/ci-failures.md` |
| 記録や報告を、作業項目など後に残る文書へ書く | `references/quality-standards.md` |

## 記録

書き出す場面では、次の形で残す。
置き場所は作業の記録、指摘への応答、作業項目など、その工程の既存の記録先とする。

- 期待: <起きるはずだったことと、その期待が正しく必要である根拠。見直した場合はその結果>
- 原因: <起こしたものと、確かめた観測の所在。推測の部分は推測と書く>
- 処置: <無くす・単純にする・直す・足すのどれか。より前の案を採用しない理由>
- 広がり: <同じ仕組みの他の箇所を探した検索と結果。同じ害への既存の対策を探した検索と結果>
- 確認: <直ったことを確かめた方法と結果>

問い4で対策が既にあった場合は`再発:`の行を、再発防止を検討した場合は`再発防止:`の行を加える。
書く内容は各資料が定める。
