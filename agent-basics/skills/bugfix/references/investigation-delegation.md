# 独立した調査を依頼・検収する際の品質

別の担当者やサブエージェントに独立した調査を依頼する際は、発生した事象、本来あるべき仕様（期待契約）、実際の観測結果、発生条件、ログや関連資料、対象のバージョン、および再現手順を伝える。あらかじめ原因の候補や修正案を伝えてしまうと、相手の思考がその仮説の検証だけに狭まってしまう可能性があるため注意する。調査先から返された推定結果や対策案はあくまで候補の1つとして扱い、直接的な原因、根本原因、影響を受ける母集団、必要な処置について、実際のコードや実行結果をもとに自身で独立して再確認する。分析の深さにかかわらず、調査結果の妥当性判断には`root-cause-analysis.md`の合否基準を適用する。

## 名指し参照の読込方法
