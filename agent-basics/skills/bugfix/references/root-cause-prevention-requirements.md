# 再発防止の選定と完了：再発防止策の必須性

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 本文の条件に従い「直接的原因と事象時点の確定」を判断する前 | `root-cause-analysis-evidence.md` |
| 本文の条件に従い「QとC・Dの区別」「原因分析の品質確認」を判断する前 | `root-cause-severity-quality.md`、`root-cause-severity-impact.md` |
| 本文の条件に従い「処置の階層」を判断する前 | `root-cause-actions-hierarchy.md` |

## 再発防止策の必須性

既存の仕組み（レビュー、lint、テスト、CI）で初めて検出された指摘・エラーは、検出が有効に働いた証拠として再発防止策の検討を省略できる。
原因分析と類似見直しは必須とし、初回検出の根拠を既存の作業記録へ短く残す。
同じ根本原因の指摘・エラーが反復した場合と、ユーザー介入で発覚した場合は再発防止策を検討する。
この初回検出の例外を除き、分析の深度や重大度にかかわらず、両系統の候補を作る義務と採用の判断を区別する。
同じ根本原因から生じる別の問題で防げる損失と処置の継続費用を比べ、採否と手段を`root-cause-severity-impact.md`「QとC・Dの区別」の費用対効果に従って決める。

重複する検討を省略できるのは、「同一セッション内でその処置がすでに実装されている場合」または「進行中の未完了タスクが根本原因と必要なすべての処置を網羅している場合」に限られる。
いずれの場合も、対象母集団、根本原因、処置内容、有効性のすべてを完全にカバーしている必要がある（一部しかカバーしていない場合は、不足分を自ら処置するか後続へ引き継ぐ）。
問題発生時にすでに存在していた規範に違反した場合は、「すでに規範があること」や「似たような条文がすでにあること」を理由に処置を省略してはならず、なぜその規範が適用されなかったのかという原因に対する処置を確定させる。
この原則を「未適用規範の是正原則」と呼ぶ。
規範本文の確認や必要な変更履歴との比較で欠陥が確定した場合は、記録照会を省いてその欠陥を是正する。
本文に欠陥が見当たらず、未適用の区分によって対策が変わる場合に限り、当時の記録を照会する。
当時の規範が存在していたかの確認は、`root-cause-analysis-evidence.md`「直接的原因と事象時点の確定」に従う。
原因の検討にあたっては、起動契機、参照のタイミング、判定条件、責務の所在、思い出しやすさ（想起性：語彙、例示、原則名、条件と行動の対応関係）の観点から分析し、想起性の改善と条文の重複を区別する。

再発防止策を採用しないと判断する場合や「対策不要」と判定する場合、問題の重大度や記載形式（`気付いた改善点:`の行を含む）にかかわらず、以下の4点を理由にしない。

1. すでに規範、案内、手順が存在しており、単にその適用が漏れただけであること。
   未適用規範の是正原則および`root-cause-severity-quality.md`「原因分析の品質確認」に従い、適用を妨げた要因そのものに対する処置を確定する
2. 上記の初回検出の例外に当たらず、後段の確認工程、担当者の作業中の気付き、または再実行によって結果的に問題が解消し、最終成果物に不具合が残らなかったこと。
   これらは見逃し要因の分析に用いるものであり、品質（Q）への影響の判定や再発防止の利点見積もりを否定する理由には使えない
3. その問題とは別の論点で行われた判断（別の作業でユーザーが現状維持を選択したなど）や、ユーザーによる判断が必要であること。
   後者については、どのような判断や認可が不足しているのかを特定し、依頼元へ判断を仰ぐ
4. 観測された事象への因果関係が確定していないこと。
   すでに確認された欠陥そのものは、事象への寄与度とは明確に切り離して処置する

再発防止策を検討しない・採用しないと短く記録する場合（作業中の改善点の`AWI化ステータス: 不要`など）は、理由を次の区分名で始める。
どの区分にも当たらなければ、再発防止策を検討する。

- `非欠陥`: 正常な回復や新しい情報だけで、期待契約からの逸脱が無い
- `処置済み`: 同じセッションで根本原因に作用する処置を実装した。
  commitかWI名を添える
- `被覆`: 未完了の既存項目が根本原因と必要な処置をすべて被覆する。
  既存のWI名を添える
- `見送り`: 両系統の候補を作り、防げる損失と継続費用の比較で採用しない。
  比較の結論を添える

過去に採用して完了したはずの対策と同じ原因に属する問題については、その由来にかかわらず、今回の調査母集団と前回の母集団、除外理由、適用条件を比較する。
分析結果は「範囲不足」（今回の条件が前回の想定範囲外だった）、「未適用」（対策の存在下で適用されなかった）、「効果不足」（対策の適用後も原因が解消しなかった）に分類して記録する。
処置が有効であるかどうかは、今回の条件下で原因が解消するかどうかで判定し、過去と同じ階層の処置であっても、残された条件を解消できる別の処置であれば採用できる。
まだ反映されていない処置は「効果未確認」として扱い、タスクの登録、採用の決定、コードの統合などはあくまで実施状況の証拠であって、原因解消の効果そのものとは区別する。
別の原因によって作業負荷などが増加した事象は、その原因へ帰属させ、前回の処置の効果不足と区別する。
ユーザーによる指示の取り消しや修正指示があった場合は、判断の内容そのものに対する修正なのか、判断した主体（エージェントが判断すべきかユーザーが決めるべきか）に対する修正なのかを切り分ける。
技術的な判断の誤りであれば判断材料、規範、手順を修正する。

再発防止策を採用しない場合は、両系統の候補と採否、防げる損失と継続費用の比較の結論を記録する。
観測された事象、原因、Qへの影響と重大度、調査範囲と限界、許容する残存リスクを原因分析記録に残し、比較の経緯は証拠として保持する。
明示要件や硬い制約を満たせずに残る事項は、費用による見送りと区別して未達成として報告する。
処置の採否は技術的な判断としてエージェント自身で確定し、平易で分かりやすい根拠を結果報告に記載して作業を継続する。
ユーザー固有の判断が必要な事項が残る場合に限って、その判断を依頼元へ委ねる。

再発防止策は、以下の条件をすべて満たすものとする。

- 後続の実行でも参照される永続的な成果物または規範として残ること（個別の計画書に書かれた変更履歴、単一セッション内での口頭説明、その場限りのレビュープロンプトなどは、修正の確認記録にすぎず再発防止策とはみなさない）
- 作り込み要因と見逃し要因の両系統の最深段に作用し、各系統の根本原因自体を成立させなくするか、あるいはその発生を検知できること。
  また、表面的な構造が異なる類似の事象にも効果があること
- 適用範囲が類似見直しの母集団を網羅しており、予防対象（現時点ではその仕組みを持たないが、将来追加・変更される可能性があるもの）も含んでカバーしていること。
  現存する該当箇所が観測された1件だけであっても、適用範囲は同じ基準で決定する。
  処置の区分は`root-cause-actions-hierarchy.md`「処置の階層」の持ち込みの試験で確認し、観測された事象の再現に留まる処置は「対策」か「回帰防止策」として記録する
- 根本原因の各要素（不変条件や判断規則）に対して、混入防止または自動検出の処置が明確に対応付けられていること。
  判断の契機で起動するスキル、成立する読込表の行、常時規範を通じて判断前に本文が届くことを読込経路として示せる手順・規範は、混入防止の処置に当たる。
  混入を防止することで見逃し要因自体が発生しなくなる場合も、見逃し側の候補を作り、因果関係と「混入防止で不要」という不採用理由を記録して重複する処置を省く。
  文書化や手順を置いたことだけを他方の系統への作用の根拠にせず、作用を立証できずに残る要因があれば、それに対処する処置を選ぶ
