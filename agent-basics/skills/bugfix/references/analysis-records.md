# 原因分析の記録の品質

原因分析の記録には、発生した事象、発生条件、実際の値、本来期待される仕様（契約）、直接的な原因とその根拠、施した対策、類似箇所の見直し観点と結果、および再発防止策を明記する。また、品質（Q）と費用・納期（C・D）の区別、重大度とその根拠、調査対象の母集団、修正や予防の対象、調査の限界と残存リスク、各処置が根本原因にどう作用し完了を確認できたかを対応づけて記録する。数値データを扱う場合は、生成元や条件が一致する比較対象を確認し、確定していない数値は推定値として区別する。

拡張原因分析では、`causal-analysis.md`に定める2系統およびL1〜L4の各段階を記録する。その段階まで到達しない場合は「該当なし」の根拠を、資料不足で調査できない場合は「未確認」としてそれぞれ区別して記載する。判断の過程や比較の詳細なデータは再取得可能な証拠（ログや差分など）として残し、本文には結論とその証拠の所在を記す。

観測された複数の事象を1つのバグとしてまとめて扱うのは、直接的な原因と対策の修正単位がともに同一である場合に限る。根本原因が共通であっても直接的な原因が異なる場合は、別のバグとして分ける。なお、バグ単位を分けた場合でも、同一の根本原因に対する類似箇所の見直しや再発防止策の完了確認は、関連するすべての対象について行う。

再発防止策を採用した記録には、`root-cause-analysis.md`「処置の階層」に基づき、持ち込み試験に用いたパターンの異なる問題（対象の所在が異なるケースや、将来新しく追加されるケースなど）を1件以上挙げ、その処置によって問題の混入を防げる理由、または確実に検出できる理由を明記する。今回発生した箇所に対する回帰テストは「対策」の項目に記録する。再発防止策を採用しない場合は、その結論と判断の根拠を同じ記録に残す。
