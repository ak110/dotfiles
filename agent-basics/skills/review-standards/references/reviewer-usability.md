# ユーザビリティレビューの手順

変更された画面を実際に描画・操作し、エンドユーザーが画面の意味を迷わず理解して作業を完了できるかを評価する手順を定める。
対象は、E2Eテスト、VRT（ビジュアルリグレッションテスト）、lintなどの自動テストでは判定できない、エンドユーザーから見た使いやすさである。
原則6（`agent-basics:writing-standards/references/quality-principles-verification.md`）を画面のレビューへ適用する。

## ユーザビリティレビューの判定

読み取りに障害を注入した実描画で、取得中・短い障害からの回復・継続失敗を、`agent-basics:writing-standards/references/ui-ux.md`「視覚と構造」の自動更新の基準に照らして判定する。

1. 提出された成功手順に頼らず、原要求と変更前の通常利用から開始状態と代表作業を選ぶ。
2. `agent-basics:writing-standards/references/ui-ux-topics.md`「完了前の実描画確認」に従い、Webはブラウザー、ネイティブGUIは対象OSで変更後の画面を描画・操作する。
   Web画面では`agent-basics:writing-standards/references/ui-ux-web-rules.md`と該当するModern Web Guidanceを使う。
   文言は文章の基準で判定する。
   この実機の観測で、`references/reviewer.md`「初回レビュー」の最初の合否を決める。
   対象の一部だけが使いやすい、見た目だけが揃うなど、原要求に足りない場合はここで不合格とする。
3. `agent-basics:writing-standards/references/ui-ux.md`「判断の順序」「用途と参考例の調査」「操作と情報」「状態と内容」に照らして判定する。
   入力に頼らず同じ製品で同じ機能・資源・目的の画面や部品を探す。
   同じ作業・データ・幅と状態で並べて描画し、枠・背景・見出し、操作と表示条件、項目名・並び・共通スタイルを比べる。
   見た目と操作状態の比較には、`agent-basics:writing-standards/references/ui-ux-topics.md`「完了前の実描画確認」の観察点を使う。
   変更した操作と同じ画面や共通の操作欄を、通常表示と操作後の両方で確認する。
   主ラベルと配置だけで意味が通るか、補足がある場合は何を新たに伝えるかを判定する。
   対象内で主ラベルや見た目を言い直す補足は、操作を完了できても不合格とする。
   無関係な画面まで差し戻しの対象にしない。
   比較相手があるのに入力が「なし」の場合と、理由のない相違は不合格とする。
   外部の類例は製品内に同種のものが無い場合だけ使い、他製品の手数は合格基準にしない。
   実描画で、変更部分の外見、自動更新時の配置、反復操作の待ち時間を同書の条件で別々に判定する。
   初期表示から完了まで、判断の順に情報がたどれ、長さの違う行でも比較する列が揃うか、空値や反復が主役を隠さず、不要な入力や画面往復が残っているかを判定する。
   事前知識のないエンドユーザーとして、変更画面だけから操作を見つけ、候補と既定値を理解し、必要な確認を経て保存後の結果を確かめられるかを見る。
   反復操作でも、選択肢やヘルプを前画面の記憶に頼らず見つけられるかを確かめる。
4. 機能の正しさ（受入シナリオの期待結果との一致、データの反映、操作の成否）は判定の対象から外し、自動テストと実行レビューへ任せる。
   同じ確認を重ねると、使いやすさを評価する目的が損なわれるためである。
   提出されたテストの開始状態・操作・結果が観測の対象と一致するかは確かめて不足を明示し、テストが足りない受入シナリオは実行レビューの種類5とする。
   機能上の停止に当たった時は、開始状態・操作・停止箇所・未検証の部分・証拠を機能の担当へ渡し、到達していない操作の流れは未検証として扱う。
5. 各指摘には、観測した画面の状態とキャプチャー画像、エンドユーザーが誤解するか操作を中断する具体的な場面、`agent-basics:writing-standards/references/ui-ux.md`の該当する基準を示す。
   指摘の該当箇所は、外観、要素名、DOM構造の表面的な類似だけで限定せず、同じ発生機構を持つ変更画面、表示幅、操作後の状態の全体から探す。
