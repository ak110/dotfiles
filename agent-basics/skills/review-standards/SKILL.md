# レビュー担当とレビューイーの心得

本スキルはレビューを実施するエージェントと、指摘を受領して採否と修正を確定するエージェントへ判断基準を提供する。
指摘の確定基準、種類、範囲と書き方は本スキルと`references/reviewer.md`が定める。レビューの役割文書とスキルは独自の判定観点を追加せず、不足は本スキルを改訂して補う（観点が分散すると同じ成果物への判定が分岐し、修正と再レビューが収束しない）。
自身の役割を先に確定し、その役割の行の資料を読む。同じエージェントが別の時点で他方の役割を担う場合は、その時点で改めて確定する。

レビューの判断には対象成果物と契約の読取が必要であり、Git実体の確認・検証・観測結果の保存には各操作の手段も要する。資料だけを読める環境では、提示された範囲で裏付けた指摘と、追加の観測が必要な範囲を返す。検証と保存を含む実行レビューは、それらを行える実行環境で続ける。指摘の文面は[文章の品質基準](references/quality-standards.md)で確かめる。

QCD、3段判定、事実と推論、硬い制約と努力目標は`agent-basics:writing-standards`の`references/quality-principles.md`が定義する。

## 名指し参照の読込方法

本文の各参照の適用条件を保ち、選んだ資料の指定範囲を取得してから、その基準を使う具体的な判断へ進む。起動時の行の資料は起動本文とともに届く。

いずれの役割でも、判定は`agent-basics:writing-standards`の`references/quality-principles.md`の3段判定（許容性、必要性、実装品質の順）に従う。案の必要性・既存機構・過剰設計・点修正と共通原因修正・責務帰属の比較は`agent-basics:writing-standards`の`references/design-heuristics.md`「設計案の予備選別」に従う。
レビュー担当とレビューイーで原要求の読み方が分かれ、成果や操作が変わる場合は、原文、先行発話、実回答と現物を比べて解消する。
ユーザーだけが持つ値が残れば、双方の読み方と各結果を、ユーザーと確認できるメインへ返す。
実回答まで、その解釈を前提とする指摘の採否と修正は保留し、独立した作業は続ける。

## 対象成果物の作成規範

作成規範とは対象成果物の種別に適用する作成側の品質基準を指し、`agent-basics:writing-standards`の該当資料と、対象リポジトリの`AGENTS.md`・`CLAUDE.md`・`.claude/rules/`配下のうち実在するものとする。
レビュー担当は初回レビューで、作成規範に加えて`agent-basics:writing-standards`の`references/review-only-criteria.md`を一括して適用する。
レビューイーは指摘を受けた基準だけを同書から取得する。

## 文章成果物の実害

文章成果物では、読者像が本文から行為者・対象・条件・結果を一意に読めず、判断・操作・検証を誤るか進めないことを実害とする。
文章の指摘の採否は、本文が適用する作成規範またはレビュー限定基準の条文に反するか、前述の実害があるかで判定する。
機能上の害の有無や計画・WIの完成条件の充足は、文章の採否とは別に確かめる。
エンドユーザー向け文書の誤記と適用対象のスタイル違反はQに影響する指摘として是正する。
