# 規範があっても起きた失敗への対処

事象を見つけた担当が、当時の判断と結果を比べ、ユーザーが同じ害を受けないための処置を実施するか、次の担当が進められる状態で引き継ぐ。
特定の発話や書式がなくても、判断と結果の食い違いがあれば調べる。

1. ユーザーが得るはずだった結果と実際の害を特定する。
   当時の版の要求・規範、適用範囲、その場で利用できた記録、実際に届いた指示・読んだ本文を判断と結果に突き合わせる。
   現行版に書かれていることや、読める場所にあったことだけを、当時の適用の証拠にしない。
2. 未配送・未読、読んだ後の未適用、対象や効果の不足、相反する入力、文面どおりに従った結果と目的の不一致を、証拠から区別する。
   規範名しか記録されていない場合は、観測した結果と対案への比較があったかを確かめる。
   記録の不足は未確認とし、未読・未適用と断定しない。
   当時まだなかった要求や規範、通常の初出の不具合、結果と制約で説明できる正当な例外は、通常の `agent-basics:bugfix` で扱う。
3. 原因分析と対策の比較は `agent-basics:bugfix` の7つの問いと、その確認観点が選ぶ資料で行う。
   元の害、当時の証拠、変える対象、原因に対して有効な理由、元の事例での確認方法を、既存の原因分析か改善の受付へ1回渡す。
   当座の訂正と、同じ害を防ぐ処置を分ける。
4. 同じ作業で処置できた場合は、変えた成果物と元の事例での確認結果を既存の記録へ残す。
   別の修正が必要なら、既存の受付や作業項目に担当と根拠を渡す。
   既存項目が害と処置を覆うか、正式な作業項目が保存されたことを確かめ、識別子を対応付ける。
   引き継ぎ済みは処置済みではない。
   証拠、認可、入力、配布、保存のいずれかが足りなければ、未解決のまま次の操作と担当を残す。
   受付や原稿、「次から気を付ける」だけでは閉じず、当座の訂正、必要な即時通知、続けられる本題は止めない。
