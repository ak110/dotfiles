## 基準版と変更行への帰属

変更行への帰属関係を正しく判定するため、比較の基準となるバージョン（基準版）と今回の検証対象バージョンを、検証結果か、プロジェクトが定める作業の記録（計画の進捗欄、引き継ぎの記録など）に明記する。
基準版には、通常の機能変更では実装着手直前のコミット、CI修正では修正前のコミット、ブランチ統合では統合前のコミットを採用する。
比較の途中で基準版を変更せず、一連の変更全体に対して診断結果を正しく対応付ける。

各診断メッセージについて、対象ファイル、該当行範囲、指摘ルール（rule）をGit差分の追加行・変更行と突き合わせる。
行番号の情報を持たない全般的な警告については、発生元のモジュール、警告種別、メッセージ内容、発動条件を分析して帰属を判定する。
変更行に対する指摘が検出された場合は、ツールの結果ステータスにかかわらず原因を解消するか、その指摘の意味、影響範囲、あえて残す理由を記録する。
指摘の位置や帰属先が特定できない場合は判断を保留し、不足している判断材料を報告先へ伝える。

警告が既存のものか今回の変更で新たに発生したものかを切り分ける必要がある場合は、該当する検証項目のみを抽出し、対象範囲、実行オプション、依存ライブラリのバージョン、並列度、および実行環境をそろえた上で基準版に対して実行して比較する。
同一バージョンかつ同一条件の保存記録がすでにあればそれを再利用する。
比較は診断対象ファイル、該当行、ルール、およびメッセージ内容に基づいて行い、ファイル改名、行の移動、重複出力を正しく対応付ける。
警告件数が同じであってもメッセージ内容が変化していれば差分として扱い、行番号の移動だけで内容が同一のものは既存の警告とみなす。
プロセスID（PID）や絶対パスなど実行ごとに変化する固有値は比較対象から除外する。
