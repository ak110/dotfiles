# 検証結果の診断と警告の判定

本書は検証したエージェントが、診断本文と警告を基準版との差で判定し、結果と不足を報告先へ返す基準を定める。
報告先は検証を依頼した主体とする。

## 読む出力

終了コードと要約だけで判定せず、診断本文、実行時警告、未到達・未適用・未完了を示す出力を読む。
pyfltrの`commands_summary.needs_action.warning`はコマンド結果の区分の件数であり、個々の診断のwarning件数とは別の値である。0でも診断本文から変更行への指摘の有無を確かめる。
出力契約の確認記録は`docs/development/audit-records.md`の「agent-basics/skills/check-execution/references/diagnostics.md：読む出力：2026年10月3日」にある。

テストと検証は成功・失敗にかかわらず、結果を判定するたびに個別の所要と実行全体の経過時間を読み、想定より長すぎないか次の基準と比べる。メインと委譲先、ローカル実行とCIの結果確認に共通で適用する。

- 個別の所要はsetup・本体・後始末を保証する契約と必要な仕事量へ対応付ける。全体は準備・対象集合・並列度・終了処理を含む経過時間で比較する。並列caseの所要累積は壁時計の経過時間と区別する
- 同じ実行環境・対象集合・依存版・並列度・準備状態の保存結果を第一の比較材料にする。条件差があればその差と必要仕事量から見込める所要を併せて使い、比較できる部分と見込みの限界を書く
- 保存結果がない初回は、必要な処理・データ量・外部起動・契約上必要な待機から所要の見込みの根拠を示し、今回の観測と比べる。必要な待機や実プロセス・実環境の保証を比較基準に含める
- 既存の所要出力（pytestのduration、pyfltrの`slow_tests`など）、保存済み実行記録とツールの経過時間を使う。区間の判別に必要な情報が不足する不審な対象だけ追加で測る

仕事量や条件差で説明できない増大、不要な準備・取得・起動・待機の反復は、`agent-basics:bugfix`を起動して同スキルの`SKILL.md`「所要の原因調査」へ渡す。単独再実行の成功は仕事量の妥当性の根拠から外す。観測した個別・全体の所要、比較基準と条件、妥当性と改善または追加調査の判断を既存の検証結果へ残す。
設計時の不要仕事の除去とハング検出の時間上限は、`agent-basics:writing-standards`の`references/testing.md`「速度」に従う。ハング検出のtimeoutと所要の妥当性の基準は目的を分け、固定の許容秒数やその機械チェック、専用台帳・監視、毎回の全件再測定は加えない。

## 基準版と変更行への帰属

変更行への帰属を判定する基準版と検証対象版を、検証結果・進捗ログまたは引き継ぎ記録へ残す。
基準版は通常の変更では実装着手直前の版、CI修正では修正前の版、統合では統合前の版とし、比較の途中で基準を変えず変更全体へ診断を対応付ける。

診断はファイル・行範囲・ruleをGit差分の追加・変更行へ対応付け、位置のない警告は発生元・種別・内容・発動条件から帰属を判定する。
変更行への指摘は結果区分にかかわらず解消するか、意味・影響・残す理由を記録する。位置・帰属が不明なら保留し、不足条件を報告先へ返す。

既存か新規かを確かめる必要がある警告は、その検証だけを対象範囲・オプション・依存版・並列度・実行環境をそろえて基準版で比べる。同じ版と条件の保存結果があれば再利用する。比較は診断のファイル・対応行・rule・内容で行い、改名・行移動・重複を対応付ける。同件数でも内容の変化は差とし、行番号だけの移動は既存とする。PID・絶対パスなど実行固有値は比較から除く。

## 合否

- 未到達・未適用・未完了の出力は、既存か新規かにかかわらず阻害として扱う。比較不能と、意味・影響・帰属の未確定も阻害とし、残す理由の記録だけでは受理せず、理由と不足する条件を報告先へ返す
- 欠陥を示す診断は是正し、権限や入力が不足する場合は報告先へ返す。警告の意味の判定は`agent-basics:bugfix`の`SKILL.md`「問題を見つけたときの対処」に従う
- 処理が成立し欠陥を示さず、意味・影響・帰属・比較した版・残す理由を確定できた警告は、それらと診断本文を検証結果と進捗ログ（または引き継ぎ記録）へ残して続行する
- 是正を要する既存不良は、観測した出力、直接的原因、修正の対象と方向を依頼元へ返し、割当と認可に従って是正する
- 統合時は実装で警告を残した理由が統合後の入力と実行条件でも成立するかを確かめ、成立しなくなった理由と統合で初めて生じた欠陥を同じ基準で扱う
- 警告の抑制と検証範囲の縮小は、警告の意味を確定した後に理由を検証記録へ残して選ぶ。意味と由来の確認や是正の代わりには使えない手段として扱う
