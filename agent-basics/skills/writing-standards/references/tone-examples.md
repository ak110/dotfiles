# 自然な日本語の例と説明

本書は、文章の修飾、動詞の選び方、専門用語の扱い、文の長さなどを適切に調整し、読み手が対象と結果をスムーズに理解できるようにするための指針と用例をまとめたものである。
判定基準は`writing.md`、具体的な表記ルールは`notation-rules.md`に従い、各用例も通常の文章校正ルールに沿って確認する。
掲載している例文は着眼点を示すためのサンプルであり、実際に適用する際は書き直す対象の事実関係、前提条件、不確実性の度合いを維持する。

## 修飾過多

過剰な修飾語を避けつつ、読み手の理解や判断に必要な明確さと拘束力を伝える語は残す。判断は`writing.md`「日本語の書き方」に従う。

```text
例文: バリデーション機能を提供する。設定したルールに違反するコードを検出する。
説明: 提供する機能と検出対象を端的に示す。
```

```text
例文: APIは関数3つで構成される。load・save・validateの各関数を提供する。
説明: APIの構成と呼び出し可能な関数名を明確に示す。
```

```text
例文: 設定ファイルは必ずUTF-8で保存する。
説明: 「必ず」は保存形式の拘束力を伝えるために必要である。
```

## 不要なアピール

主観的なアピール表現を使わず、読み手が実行する操作と、その結果として得られる客観的な観測事実を記述する。

```text
例文: uvx pyfltrで実行する。
説明: 実行するコマンドを示し、バージョン取得などの詳細条件は必要な場合にのみ説明する。
```

```text
例文: CLIはJSON形式の診断を返す。CIは終了コードで合否を判定する。
説明: 出力の形式と、その出力を受け取る側の処理で行われる判定内容を示す。
```

## 擬人化副詞

擬人化した副詞（「黙って」「静かに」など）を使わず、処理の進行状況、警告や出力の有無を具体的な動作として説明する。

```text
例文: 設定が見つからない場合は、警告ログを出力せずに処理を継続する。
説明: 設定の有無を条件として、処理の継続と警告ログの扱いを対応付けて記述する。
```

```text
例文: ロックが取れない場合は、ログを出力せずに最大3回まで再試行する。
説明: 再試行を行う条件、回数の上限、ログ出力の扱いを具体的に示す。
```

## ら抜き言葉と可能表現

五段動詞は自然な可能動詞を使い、一段動詞やカ変動詞も正しい可能形で記述する（ら抜き言葉を避ける）。
動作の内容と実行可能であることを簡潔に表現する。

```text
例文: 出力ログを見られる。設定の挙動を確認できる。
説明: 正しい可能形を用いるか、動作を表す動詞によって実行可能であることを表現する。
```

```text
例文: 本ツールでスクリプトを実行できる。
説明: 操作の手段と実行可能な動作を1つの文で簡潔に示す。
```

## カタカナ動詞比喩

動詞は、文脈を通じて読み手と意味を正しく共有できる自然な日本語を選ぶ。
専門分野ですでに定着している用語は、その本来の意味に合った場面に限定して用いる。

```text
例文: 習慣をつける。考え方を整理する。工夫する。
説明: 対象に対する動作を、一般的な意味で正しく理解できる動詞で表現する。
```

## カタカナ用語省略形

カタカナ用語は正式な表記を用いるか、読み手と意味を確実に共有できる定着した略称を用いる。

```text
例文: アーキテクチャを見直す。仕様を確認する。ドキュメントを更新する。
インフラストラクチャを増強する。リポジトリをクローンする。設定を変更する。パラメーターを渡す。
説明: 操作の対象を正式な名称で明確に特定する。
```

API・CLI・JSON・URLのように広く定着している略称は、本来の意味に合わせてそのまま用いる。

## 比喩動詞

選択、拒否、呼び出し、変更などの動作は、技術や文書編集の文脈で一般的に共有されている動詞を用いて表現する。
物理的な動作や専門分野における字義どおりの用法についても、本来の意味を正確に保って記述する。

```text
例文: キャッシュによって応答を待つ時間が減った。原因を調べるのに時間を費やした。
説明: 効果と作業内容を具体的に記述し、元の情報に含まれる所要時間や確実性の度合いを維持する。
```

```text
例文: 方針Aを採らず、方針Bを選んだ。失敗した要求への対処を終えたが、原因は分からない。
説明: 選択した方針、対処した対象、原因の特定状況を正確に示す。
```

```text
例文: 氷を溶かす。画像の解像度を変更する。触媒を使って反応を進める。
説明: 物理的な動作や専門分野での意味に合致する適切な動詞を用いる。
```

```text
例文: 不正な入力を拒否する。許可されない操作を拒否する。サブコマンドを呼び出す。
入力値がスキーマに合致するか確認する。型定義との整合を確かめる。
説明: 対象と、それに対する拒否・呼び出し・検査などの動作を正確に対応付ける。
```

```text
例文: 旧APIを無効化する。互換処理を削除する。
説明: 変更の対象と、変更後に期待される状態を明確に示す。
```

```text
例文: 設定を適用する。修正をmainブランチへ反映する。
既存の文体を保って書き換える。先行プロジェクトの方針を採用する。
説明: 適用する対象、反映先、維持すべき性質、採用する方針をそれぞれ具体的に示す。
```

## 冗長表現

名詞だけが連続する不自然な表現を避け、適切な助詞と動詞を補った文に組み立て直す。
複合語を用いる際も、本来の意味と自然な語順を保った表現にする。

```text
例文: 担当者が対応方針を定めるか検討する。
説明: 検討するという動作と、方針の決定が未確定である状態を明確に示す。
```

```text
例文: 設定を読み込む。
説明: 対象と動作を簡潔な動詞で端的に示す。
```

```text
例文: 整合をチェックする。整合性を確認する。事前に確認する。
説明: 文脈に合った動詞と助詞を用い、検査の対象や確認のタイミングを正確に表現する。
```

```text
例文: ファイル出力を実行する。全項目を実施する。
説明: 起動する操作や実施項目を指す文脈では、実際の動作に合致した自然な表現を用いる。
```
