# 自然な日本語の例と説明

文章の修飾、動作、用語と文の長さを、読み手が対象と結果を理解できる形へ整えるための例を示す。
判定基準は`writing.md`、表記は`notation-rules.md`に従い、各例は通常の文章チェックへ渡す。
例は観点を示すための文章であり、書き直す対象の事実・条件・不確実性を保って適用する。

## 名指し参照の読込方法

本文の各参照の適用条件を保ち、選んだ資料の指定範囲を取得してから、その基準を使う具体的な判断へ進む。起動時の行の資料は起動本文とともに届く。

| 時点または条件 | 全文読む資料 | 契機 | 配送操作 |
| --- | --- | --- | --- |
| 本文がこの資料の基準を使う場面で、資料を選択して取得する時 | `writing.md` | 判断 | `read:agent-basics:*/skills/writing-standards/references/writing.md` |
| 本文がこの資料の基準を使う場面で、資料を選択して取得する時 | `notation-rules.md` | 判断 | `read:agent-basics:*/skills/writing-standards/references/notation-rules.md` |

## 修飾過多

何を提供するか、どの結果を観測できるかを具体的に書く。

```text
例文: バリデーション機能を提供する。設定したルールに違反するコードを検出する。
説明: 提供する機能と検出対象を示す。
```

```text
例文: APIは関数3つで構成される。load・save・validateの各関数を提供する。
説明: APIの構造と呼び出す関数名を示す。
```

## 不要なアピール

読み手が実行する操作と、その結果を観測事実として書く。

```text
例文: uvx pyfltrで実行する。
説明: 起動するコマンドを示し、版の取得条件は必要な場合に説明する。
```

```text
例文: CLIはJSON形式の診断を返す。CIは終了コードで合否を判定する。
説明: 出力の形式と、出力を受け取る処理が行う判定を示す。
```

## 擬人化副詞

処理の進行、警告と出力の有無を、その動作として説明する。

```text
例文: 設定が見つからない場合は、警告ログを出力せずに処理を継続する。
説明: 設定の存否を条件に、継続と警告の扱いを対応付ける。
```

```text
例文: ロックが取れない場合は、ログを出力せずに最大3回まで再試行する。
説明: 再試行を始める条件、回数とログの扱いを示す。
```

## ら抜き言葉と可能表現

五段動詞の可能動詞は自然な形で使い、一段動詞とカ変動詞も正しい可能形で書く。
動作と可能であることを簡潔に述べる。

```text
例文: 出力ログを見られる。設定の挙動を確認できる。
説明: 正しい可能形か、動作を示す動詞で可能であることを表す。
```

```text
例文: 本ツールでスクリプトを実行できる。
説明: 操作の手段と、できる動作を一つの文で示す。
```

## カタカナ動詞比喩

動詞は文脈で意味を共有できる自然な日本語を選ぶ。
専門分野で定着した用語はその意味に合う場面で使う。

```text
例文: 習慣をつける。考え方を整理する。工夫する。
説明: 対象に対する動作を、一般的な意味で理解できる動詞で表す。
```

## カタカナ用語省略形

用語は正式な表記か読み手が意味を共有できる定着した略称で書く。

```text
例文: アーキテクチャを見直す。仕様を確認する。ドキュメントを更新する。
インフラストラクチャを増強する。リポジトリをクローンする。設定を変更する。パラメーターを渡す。
説明: 操作の対象を正式な表記で特定する。
```

API・CLI・JSON・URLのように定着した略称は、その意味で使う。

## 比喩動詞

選択、拒否、呼び出し、変更などの動作を、技術や編集の文脈で共有される動詞で書く。
物理動作や専門分野の字義どおりの用法も、その意味を保つ。

```text
例文: キャッシュによって応答を待つ時間が減った。原因を調べるのに時間を費やした。
説明: 効果と作業を具体的に述べ、素材が持つ時間と確実性を保つ。
```

```text
例文: 方針Aを採らず、方針Bを選んだ。失敗した要求への対処を終えたが、原因は分からない。
説明: 選んだ方針と対処した対象、原因の特定状況を示す。
```

```text
例文: 氷を溶かす。画像の解像度を変更する。触媒を使って反応を進める。
説明: 物理動作や専門分野での意味に合う動詞を使う。
```

```text
例文: 不正な入力を拒否する。許可されない操作を拒否する。サブコマンドを呼び出す。
入力値がスキーマに合致するか確認する。型定義との整合を確かめる。
説明: 対象と、拒否・呼び出し・検査の動作を対応付ける。
```

```text
例文: 旧APIを無効化する。互換処理を削除する。
説明: 変更する対象と、変更後の状態を示す。
```

```text
例文: 設定を適用する。修正をmainブランチへ反映する。
既存の文体を保って書き換える。先行プロジェクトの方針を採用する。
説明: 適用する対象、反映先、保持する性質と採用する方針を示す。
```

## 冗長表現

名詞の連結を、動詞と助詞のある文へ組み直す。
複合語は意味と自然な語順を保つ表現で書く。

```text
例文: 担当者が対応方針を定めるか検討する。
説明: 検討する動作と、方針を定めることが未決である状態を示す。
```

```text
例文: 設定を読み込む。
説明: 対象と動作を簡潔な動詞で示す。
```

```text
例文: 整合をチェックする。整合性を確認する。事前に確認する。
説明: 文脈に合う動詞と助詞で、検査する関係と確認する時点を表す。
```

```text
例文: ファイル出力を実行する。全項目を実施する。
説明: 起動する操作や実施する項目を指す文脈では、実際の動作に合う表現を使う。
```
