## 技術仕様と実利用環境の評価

負荷、データ、外部システムの条件に依存する技術仕様や非機能要件では、期待する利用結果、事前検証の仮定と限界、実利用環境で評価する観測を対応付ける（努力目標。影響と取得費用に合う検証を選ぶため）。
既存のログや計測を先に利用し、対象版、処理結果、時間・資源消費、入力条件を、劣化した処理や条件を特定できる粒度で関連付ける。
変更した処理の計算量と入力規模、遅延・資源消費、失敗率・分布、並行性、不変条件、部分失敗から関係する観点を選び、明確なエラーを出さない劣化や低頻度失敗も既存の観測で判断できるか確認する。
CIや静的解析の成功と利用目的を満たす根拠を分け、不足する観測は作業範囲内で補う。
計装の追加は、判断に必要な情報と取得・保守費用を比べて選ぶ。
継続サービスにサービスレベル目標（SLO）がある場合は、目標と実績も変更の評価に使う。

可逆な変更の限定的な展開と、取り消せない操作や永続データの変更を区別する。
影響範囲、評価する観測、継続・中止・復旧の判断を、既存の公開方針と認可の範囲で選ぶ。
事前検証、実装の完成、後日の運用効果を区別し、自然発生する事象の待機を全変更の完成条件にしない。
軽微な文言修正に負荷試験や運用計測を一律に追加しない。
