# 外部公開するサービスの法令上の義務

本書は、不特定のエンドユーザーへ公開・提供するWebサービスやアプリを作るエージェントが、気付かないまま法令上の問題を作り込まないための指針である。
技術で直せる点は設計と実装で直し、法的な適否の判断とユーザー自身が行う手続きはユーザーへ短く報告する。

参考資料: Suraj Sharma「[Nobody warns vibe coders about this part.](https://x.com/suraj_sharma14/status/2115337772521115904)」（2026年10月28日）。記事が挙げた公開前の確認事項を、義務の種類ごとの設計指針へ一般化した。

## 適用範囲

次のどちらかに当たる場合に適用する。

- ユーザーが法令上の義務やプライバシーの確認を依頼した場合
- 不特定のエンドユーザーへ公開・提供するWebサービスやアプリで、次節の義務の種類に当たる機能を新設・変更する場合と、その計画・作業項目の起草またはレビューの場合

自分用のツール、社内システム、ユーザーが自分で開く単体HTML成果物は、ユーザーが確認を依頼した場合と、社外の不特定のエンドユーザーへ公開範囲を広げる変更の場合を除いて対象外とする。
これらは第三者の閲覧者や会員を持たず、本書の義務の前提が成り立たないためである。

## 義務の種類ごとの設計指針

- 第三者サーバーからのリソース読み込み（フォント、スクリプト、CSS、画像など）と解析・広告タグ: 閲覧者のIPアドレスなどが送信先へ渡る。自己ホストで同じ結果が得られる場合は自己ホストを優先する。第三者からの読み込みを残す場合は、送信先と送られる情報をユーザーへ報告する
- エンドユーザーの操作や入力内容を記録する仕組み（セッション録画など）: 記録を始める前にエンドユーザーの同意を得る仕組みを設け、パスワードや個人情報の入力欄は記録から除く
- 宣伝目的のメールの一斉送信: 受信に同意した宛先だけへ送る設計にし、本文に配信停止の手段と送信者の連絡先を含める
- 定期課金: 申込の操作の直近に金額、更新の周期、解約方法を表示し、申込を確定する前に条件を確認できる画面を設ける
- エンドユーザーの投稿の公開: 権利侵害を通報する窓口と、通報を受けた投稿を削除する手順を設ける
- 会員登録: 未成年の利用を想定するか、年齢確認を設けるかはユーザーが決める事項として報告する

## 報告

法的な適否、適用される法域、届出や登録などの手続きは、ユーザーが判断する事項として報告へ回す。
該当した義務の種類、実施した技術的な対処、ユーザー自身が行う作業だけを短く報告する。
該当しない項目と、対処済みで報告事項の無い項目は報告に挙げない。
