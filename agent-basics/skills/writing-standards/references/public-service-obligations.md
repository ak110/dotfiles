# 外部公開するサービスの法令上の義務

不特定のエンドユーザーへ公開・提供するWebサービスやアプリで、気付かないまま法令上の問題を作り込まないための指針を置く。
技術で直せる点は設計と実装で直し、法的な適否の判断とユーザー自身が行う手続きはユーザーへ短く報告する（原則1と原則4の適用）。
参考資料: Suraj Sharma「[Nobody warns vibe coders about this part.](https://x.com/suraj_sharma14/status/2115337772521115904)」（2026年10月28日）の公開前の確認事項を、義務の種類ごとに一般化した。

## 適用範囲

ユーザーが法令上の義務やプライバシーの確認を依頼した場合と、不特定のエンドユーザーへ公開・提供するサービスで次節の機能を新設・変更する場合（計画・作業項目の起草とレビューを含む）に適用する。
自分用のツール、社内システム、ユーザーが自分で開く単体HTML成果物は、第三者の閲覧者や会員を持たないため対象外とする。
ただし、ユーザーが確認を依頼した場合と、社外の不特定のエンドユーザーへ公開範囲を広げる変更は対象にする。

## 義務の種類ごとの設計指針

- 第三者サーバーからのリソース読み込み（フォント、スクリプト、CSS、画像など）と解析・広告タグ: 閲覧者のIPアドレスなどが送信先へ渡る。
  自己ホストで同じ結果が得られる場合は自己ホストを優先し、残す場合は送信先と送られる情報をユーザーへ報告する
- 操作や入力内容の記録（セッション録画など）: 記録を始める前にエンドユーザーの同意を得る仕組みを設け、パスワードや個人情報の入力欄は記録から除く
- 宣伝目的のメールの一斉送信: 受信に同意した宛先だけへ送り、本文に配信停止の手段と送信者の連絡先を含める
- 定期課金: 申込の操作の直近に金額、更新の周期、解約方法を表示し、確定の前に条件を確認できる画面を設ける
- エンドユーザーの投稿の公開: 権利侵害を通報する窓口と、通報を受けた投稿を削除する手順を設ける
- 会員登録: 未成年の利用を想定するか、年齢確認を設けるかはユーザーが決める事項として報告する

## 報告

法的な適否、適用される法域、届出や登録などの手続きは、ユーザーが判断する事項として報告へ回す。
該当した義務の種類、実施した技術的な対処、ユーザー自身が行う作業だけを短く報告し、該当しない項目と対処済みで報告事項の無い項目は挙げない。
