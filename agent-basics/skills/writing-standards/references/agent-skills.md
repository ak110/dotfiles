# Agent Skills実装ガイドライン

Skill仕様のうちエージェントの種別をまたいで適用できる汎用部分を扱う。
Claude Code固有の挙動には節ごとに「Claude Code固有」の注記を付ける。

## YAML frontmatter

- `name`（ディレクトリ名と同じ値）は、そのスキルが担う工程と起動の契機を表す語で選び、実現手段（WIの記録形式、ツール名、コマンド名など）や実装内部の語を中心に置かない（努力目標）。エージェントは名前を起動判断の強い手掛かりにするため、手段の名前は別手段で同じ工程を行う場面での不起動と、手段の語が現れるだけの場面での誤起動を招く。起動条件の全体は`description`へ書く
- `description`には対象作業と起動条件だけを書き、目的・背景・手順は本文へ置く（努力目標。`description`は常時ロードされる）。複数行はYAML折り畳みスカラーで書く
- 他スキル・エージェントから明示的に呼ばれる前提のスキルと、ユーザーが`/name`で起動する前提のスキルは、`description`を起動元・起動条件の明示に限定する。渡した引数だけが入力となるスキル（`context: fork`を持つものなど）は、受理する引数と返る結果を`description`へ書く
- 起動方法に応じて設定する
  - ユーザーが`/name`で手動起動する前提がない: `user-invocable: false`
  - ユーザーの手動起動専用（副作用の大きいワークフローなど。Claude Code固有）: `disable-model-invocation: true`
  - 両方を前提とする: いずれも設定しない
- Codex向けの`agents/openai.yaml`を置くスキルは、`interface.display_name`をディレクトリ名と一致させる。Codexの入力補助はその値を候補名として表示するため、異なるとスキル名を入力しても候補から選べない
- frontmatterで設定済みの仕様を`description`や本文へ再掲しない（努力目標）

## SKILL.md本体とreferences/の役割分担

- 付属資料は`skills/<skill-name>/references/`へ置き、スキルに属さない参照文書は別の名前のディレクトリへ置く（努力目標。所属スキルを判定できるようにする）
- 本体は全対象に共通する原則と、知識提供型か手順提供型かを冒頭で示す。言語・トピック固有の細則は`references/`へ置く
- トリガー条件・コア手順・停止条件などの必須指示は、削減を求められても本体冒頭側へ残す（本体の後半は起動判定の時点で読まれにくい）。それ以外は`agent-documents-additions.md`「文書記述量の管理」に従って`references/`への退避を先に検討する
- 規範の所在を調べるときは本体と`references/`の両方を確かめる

## スキル間操作

- 別スキルの起動は実行中のエージェントが行うため、起動させる場合は起動するエージェント、スキル名、引数、期待する返却値または効果を書く。参照文書の読込はSkill起動と区別し、Readで読む資料と必要な節を明記する（全文・節指定の選択は`agent-documents-basics.md`「読込表」に従う）
- 他スキルの参照資料は`<plugin-name>:<skill-name>`でスキルを識別し、その`SKILL.md`のディレクトリを基準に`references/<file>`を解決して読む。常時ロードされる文書には参照先の識別子だけを置く
- スキル間の引継ぎでは提供側が完成済みの入力を返し、利用側は受け取った入力だけで処理する。提供側は利用側固有の参照文書へ依存しない
- 配布物の参照文書は起点の文書（`SKILL.md`、agent定義または`<役割名>.subagent.md`）から到達するものとし、履歴保管は配布物外へ分離する（努力目標）
- 重複を片側へ統一する場合の置き場所と採否は`agent-documents-basics.md`「定義の所有者」に従う

## スキルのパス解決とfork実行（Claude Code固有）

- `${CLAUDE_SKILL_DIR}`はSKILL.md本文の中でだけ、そのSKILL.mdのディレクトリの絶対パスへ展開される。自スキルの同梱ファイルはこれで、プラグイン全体や別スキルのファイルは`${CLAUDE_PLUGIN_ROOT}`から参照する
- frontmatterの`context: fork`でスキルをサブエージェントコンテキストで実行し、`agent`フィールドで種別（`Explore`・`Plan`・`claude`等）を指定する。`agent: Explore`・`agent: Plan`のfork配下は親の`CLAUDE.md`・ルール群を継承しないため、必要な規範は実行時に明示的に読み込む
- fork配下では`AskUserQuestion`を使えず、ネストは5階層までで、親へ返るのは最終報告テキストだけである。`agents/`定義を`agent:`へ指定すると、その定義のツール制限・モデル指定が適用される

## ユーザーが起動するスキルの着手手順

`user-invocable: false`を持たないスキルは、起動から作業の着手までにユーザーの操作を要さない形で書き、確認・選択・追加入力の要求は着手後に置く。ユーザーはそのスキルを作業の起点として起動するため、着手前に操作を求める手順は目的を損なう。着手前に確定したい判断は、必要になった時点で尋ねるか、指定なしの動作を採用して事後に報告する。

## 呼び出し側プロンプトの責務分離

スキルの動作詳細、条件分岐、引数を省いたときの動作と対象の選定、引数仕様はSKILL.md本体に集約する。呼び出し側プロンプトは起動指示と、呼び出し固有の値を渡す引数だけを書く。動作詳細を呼び出し側へ書くと挙動が分岐する。

## 失敗事例の反映

繰り返した失敗事例は上位原則を抽出して既存節の箇条へ統合する。満たす性質と判断条件を示し、禁止事項の羅列や対比表を追加する構成は避ける（努力目標。読込量が増え、羅列以外は許容という誤読を招く）。
