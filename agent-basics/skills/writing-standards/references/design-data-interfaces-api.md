## API設計

発火条件: 自コードベース外に利用元が存在する公開APIのエンドポイントやスキーマを新規設計または変更する場面。
同一コードベース内でのみ呼び出される内部APIは本節の対象外とし、`quality-principles-qcd.md`「設計の判定順」にある「内部の構造や文書は積極的に整理する」という方針に従う。

既存の呼び出し元が自身のコードを変更することなく継続利用できる互換性を維持すること、およびエラー発生時に完全な失敗と部分的な失敗とを明確に判別できる設計を守る。
一覧取得系エンドポイントには、`design-display.md`「検索・一覧画面の設計」におけるページネーションの設計観点を適用する。

長時間接続（SSEなど）では、経路の各層のアイドルタイムアウト・バッファ、切断・再接続・欠落を利用形態と負荷に合わせて評価する。

## Webhook受信設計

発火条件: Webhookの受信処理を設計・変更・レビューする場面。

- 送信元の真正性を確かめる署名検証
- 再送と重複受信への対処
- 到着順序が前後する場合の整合性
