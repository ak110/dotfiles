# エージェント向け文書品質（基本）：記述内容の取捨

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 実作業の知見を保存・整理する前 | `investigation-experience.md` |

## 記述内容の取捨

- 記述の詳しさは、`writing-readers.md`「読み手別の追加注意点」のエージェント向け文書の項に従う。
  例示の形式と適用条件は「条件と範囲の記述」に従う。
- すでに自動ロードされている規範、呼び出し済みの規範、委譲先に届いている共通ルールなどは、要約や再掲をせずに参照リンクで示す（努力目標。読み込み量が増大し、改訂時に一方の更新漏れが発生しやすくなるため）。
- エージェントの実行判断に直接寄与しないメタ情報（管理方針、編集判断の経緯、同期対象など）は、frontmatterのコメントへ移動する（努力目標）。

## 条件と範囲の記述

- ユーザーの要求を規範や手順へ変換する際は、原文が持つ目的、要件、対象範囲、例示の開放性、変更指示、論理関係をそのまま保ち、既存の分類枠に収まる範囲へと狭めないようにする。
- 判断条件、例外条件、許容条件は、客観的に確認できる事実に基づいて記述する。
  対象を名詞句で限定できる指示は「変更するPython関数に…を記す」のように書く。
  工程・権限・入力状態で適用が変わる条件は残し、条件と行動を対応付ける。
  作業量や所要時間の見込みは、品質、コスト、完了までの時間を比較・評価するための材料として扱う。
  ある工程を省略できる条件を定義する場合は、その工程が検出・達成すべき変化が実際の差分に含まれているかどうかに基づいて記述する。
  作業規模の主観的な印象だけで条件を決めると、本来その工程で検出すべき変化を含む差分まで省略されてしまう恐れがある。
- エージェントに判断を委ねる条文では、守るべき価値、逸脱した場合の不利益、考慮すべき観点を代表的な語句で示し、最終的な結論は読み手の総合的な判断に委ねる。
- 簡潔な基本方針の後に具体的な手段を例示する場合は、独立した行の`<例>`と`</例>`で囲み、その間に1行1例の形式で語句または`<条件>: <対応>`を記述する。
  例示はあくまで開放的な具体例であり、実際の適用範囲は基本方針に基づいて判断する。
  閉じた網羅的な列挙をするのは、`quality-principles-constraints.md`「規定の区分と標示」の硬い制約を守る条文に限定する。

<例>
編集する対象と、規範を読む役割を示す
入力の状態ごとに条件と行動を対応付ける
共通の判断は、その判断を定める文書へ接続する
入力を受理する条件は、要求と公開契約から決める
</例>

- 独立して変更され得る制約事項は、箇条書きの項目を分ける。
  衝突する可能性がある指示には優先順位や判断基準を明記し、否定形や例外条件が重なる場合は、条件と取るべき行動との対応関係が一目で読み取れるように記述を整理する（努力目標。相反する指示が併存すると満たしやすい方に判断が偏りやすく、変更範囲の最小化を優先する指示が原因への根本対策を妨げることがあるため）。
- 代替案が自明でない制限を設ける場合は、代わりに行うべき行動を合わせて明記する。
- 禁止や承認の規則は、次の3点に従って書く（努力目標。Claude Fable 5.2は規則を書かれたとおりに適用するためで、dotfilesでの比較は行っていない）。
  根拠は`docs/development/audit-records.md`の次の見出しにある。
  「agent-basics/skills/writing-standards/references/agent-documents-basics-content.md：条件と範囲の記述：2026年11月11日」
  - 対象とする操作を特定して書く。
    対象の広い規則は、日常の作業まで控えさせる。
  - 禁止に例外や事前承認で許す条件がある場合は、その条件を同じ規則の文へ書く。
    別の行に置いた許可は効果が小さい。
  - 承認なしで進めてよい操作は個別に名指しする。
    「より自由に行動してよい」のような一般的な指示では挙動が変わらない。
    再試行を名指しするのは、繰り返しても安全な操作に限る。
- 既存の規定の表現を変更する際は、実行時の振る舞いが意図せず変化しないことを確認する。
  条文を別資料への参照に置き換える場合は、集約した義務（判定、工程、契機など）が参照先の本文に確実に含まれていることを読み取って確認する（努力目標）。
- 対象を一意に特定できる明確な言葉で記述し、指示語は具体的な名称に置き換える。
  既存の段落を編集（文の挿入、移動、削除、置換、段落の分割や統合など）した後は、後続の文に含まれる指示語の指示対象がずれていないかを確認する。
- 数値の上限値は、その制限を設けないと成果物の品質や利用シナリオを維持できない場合に限って設定する。
- 達成すべき本質的な性質を規定する。
  特定のツールや実行順序に限定する場合や、検出・判定の対象を特定の検索語、正規表現、単語リストで限定する場合は、その手段が必要な理由と、リストが対象全体を十分に網羅している根拠を併記する。
  網羅性を担保できない場合は、文脈を含めて全体を確認するなど、リスト外の事象も判定できる手法と比較して選定する。
  出力形式を事前に確定できないデータから未知の異常を検出する手順において、既知のキーワードのみを候補にすると、それ以外の異常が確認対象から漏れてしまう。
