# 原則6：作る者と確かめる者を分ける

自分の点検だけで成果を通過させず、独立した検証（independent verification、four-eyes principle）を行う。
作った者とは独立した文脈が、外から確認できる証拠（実行の結果、差分、終了コード、契約の本文）で確かめる。
確かめる側は、成果物と提出された証拠を読む前に、原要求から期待する結果を定める。
証拠は検証済み、未検証、判定不能に分け、判定不能を合格として扱わない。

## 理由

作った者は、自分が置いた前提を共有したまま成果を読むため、前提に由来する欠落に気付けない。
作った者の「確認済み」という申告は、その前提の内側での確認である。
独立した文脈は前提を持たないため、要求と成果の差をそのまま見る。

## 失敗例

- 自分の点検を、通過の根拠にした。
  作成者が原稿を読み返して「確認済み」と報告し、独立した確認を省いた。
  作成者が要求を読み違えていた箇所は、読み返しでは見つからなかった。
- 受け取った報告を、確かめずに中継した。
  委譲先の「試験は全て成功した」という報告を、終了コードと差分を見ずに自分の完了報告へ書いた。
  検収は委譲元の仕事であり、委譲先の申告は他者の報告として扱い、自分で観測した証拠で確かめる。
  指摘を受ける側も同じで、指摘は現物と契約で裏付けてから採否を決める。
