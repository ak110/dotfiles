# エージェント向け文書品質（基本）：置き場所と配送

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 実作業の知見を保存・整理する前 | `investigation-experience.md` |

## 置き場所と配送

- 置き場所の区分としては、常時参照する横断的な標準は`AGENTS.md`や`CLAUDE.md`の本文、またはpaths未指定のルールに配置する。
  特定のパスに限定される規則はpaths指定ルールに、手順やワークフローはスキルに、機械的な強制や自動検証はhookに、調査プロセスの隔離や冗長な出力の抑制はサブエージェントにそれぞれ配置する。
- 置き場所（保存先）を決める際は、読み込みの契機と対象エージェントに加えて、その置き場所の記述が届く読み手の範囲も考慮する。
  規定が必要となった背景（共有ブランチの状態、チームの合意事項、特定ホストの制約、個人の運用判断など）から、適用すべき読み手の範囲を特定し、過不足がないか比較する。
  届く範囲が狭すぎると守るべき主体へ伝わらず、広すぎると本来対象外のエージェントが自身に適用してしまう。
  ユーザーが指定した置き場所は、適切な適用範囲と一致しない場合も自己判断で変更しない。

<例>
個人のルール: `~/.claude/rules/`配下、`CLAUDE.local.md`
全員とCIが読む規範: `AGENTS.md`、`CLAUDE.md`、プロジェクトスキル
全配布先の規範: 配布物の`rules/`と`skills/`
</例>

- 役割別の規範は、読み手と読み込みの契機に合わせて配置する。
  全エージェントに適用する規範と、委譲元・委譲先のどちらか一方のみに適用する規範とを明確に分ける。
  双方が守るべき受け渡しに関する取り決めは、共通の定義元を設けて集約する。
  起動時に常に読み込まれる規範を「常時規範」と呼ぶ。
- 読み込みの階層は、常時ロード、役割別注入、スキル起動時、役割起動時、明示読取に分ける。
  各階層の記述が実際にエージェントへ届くタイミングを、ホストの仕様に基づいて確認する。
  明示読取以外の階層は、該当する主題の具体的な作業に入っていなくても、起動時に全文が読み込まれる。
- どの起動区分のエージェントへ届くかは、対象ホストの配送仕様と実装を確認して判断する。
- プロジェクト規範とは、対象リポジトリが規範として定めている指示（`AGENTS.md`、`CLAUDE.md`、`.claude/rules/`、プロジェクトスキルなど）を指す。
  プロジェクト方針とは、プロジェクト規範に加えて、README、コードコメント、設定ファイルなど規範化されていない箇所に書かれた方針も含めた全体を指す。
- スキルとエージェントの責務の配置は、`agent-skills.md`および`sub-agents.md`に従う。
  委譲元側の文書はタスクの受け渡しと検収に専念させ、委譲先固有の手順は委譲先側の文書に持たせる（`sub-agents-contracts.md`「`<役割名>.parent.md`と`<役割名>.subagent.md`の構成」を参照）。
  両者への指示を同一の文書に併記すると、委譲元が委譲先向けの制約を自身に適用しやすくなる。
- 各記述は、その情報を必要とする工程で確実に読まれる文書へ配置する。
  読む契機がない記述は参照されず、特定工程でのみ必要な記述を常時ロードに置くと、無関係な全工程でその分のコンテキストが消費される。
  常時ロードには優先順位、不変条件、禁止事項、完了条件、プロジェクト固有の概念を置き、言語・技術領域・作業種別ごとの規範はスキルやpaths指定ルールへ、工程の途中で必要となる詳細な手順は`references/`や工程内の読み込み指示へ配置する。
- 同時に必要となる情報は1箇所にまとめ、主題が異なる項目は見出しを分けて整理する（努力目標。情報が散在していると読み飛ばされやすく、無関係な内容が混在していると重要な項目への注意が削がれるため）。
- 実作業から得た知見は既存の主題別資料へ統合し、索引には所在と、読む知見を選ぶための情報を置く（努力目標。重複保存と探索の負担を抑えるため）。
  保存内容の出所・確度・適用範囲と利用時の判断は`investigation-experience.md`「経験の保存と適用」に従い、重複や矛盾の整理でも原記録へ戻れる参照を保つ。
