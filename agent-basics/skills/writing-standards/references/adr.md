# ADRの書き方

設計判断を残す担当とレビュー担当が、後から原本を読んだ人に、何をなぜ決め、どこに適用するかを伝えるために使う。

## 決定と影響

- プロジェクトの既存の形式を使い、背景、決定、状態、影響を見出しや項目で区別する。
  背景には、現に起きている問題と今決める理由を中立の事実で書く。
  ADRだけで判断の要旨と理由が分かるようにする。
- 決定には誰が何をするかを書く。
  「実装方式だけを差し替えた時に本文を書き換える必要があるか」を目安に、決定ではない実装詳細を仕様・コード・PRの説明へ移す。
  技術の選択そのものが決定なら、理解に必要な具体性は残す。
- 影響は利点、不利益、中立の変化に分ける。
  適用範囲と、決めない事項の実在する委譲先（文書や判断の場）を示し、例外には失効条件を書く。
- 移行計画、工程図、進捗、タスク表、チケット・PR・Issueの番号、最終更新日は本文に書かない。
  移行中にも守る条件は決定として残す。

## 根拠と参照

- 背景・影響・代替案の事実は、実コードと一次資料を[調査の基準](investigation.md)に従って照合する。
  第三者が確認できる出所と確認日を添え、会議や口頭の確認だけを根拠にしない。
- 外部資料、関連ADR、置き換え関係は、既存形式に専用の節があればそこへ、なければ本文の末尾へまとめる。
  他のADRの決定は行番号で指さず、ADRの番号と題に、決定を1つに特定できる項番号と項題（項番号がなければ決定の見出し）を添える。
  例（作例）: 「ADR 12: 履歴の保存」「失敗記録の保持」。

## 状態

提案中と採用済みを分け、このADRの適用範囲に未決事項があれば採用済みにしない。
範囲外として実在する委譲先を示した事項は採用を妨げない。
採用、廃止、置き換え、アーカイブの際は一覧と参照元を更新し、廃止・置き換えでは当時と後続の判断を別々に残す。
