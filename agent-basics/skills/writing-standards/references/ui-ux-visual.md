## 視覚と構造

フォントサイズ、余白、カラーパレットは既存のデザイントークンに統一し、要素の意味や重要度を色、文言、形状の組み合わせによって表現する。
要素の役割や関係性は、長文の説明を追加する前に、配置、余白、グルーピング、視覚的な階層構造、および端的なラベルによって直感的に伝わる設計を心がける。
ライトテーマとダークテーマの両方を提供する画面では、両環境で文字の可読性、境界線の見やすさ、背景色、フォーカスインジケーターの視認性を確認する（ダークテーマの新規作成は要件に応じて判断する）。
アニメーションなどの動きは画面状態の理解を助ける目的に限定し、OSの動き軽減設定（`prefers-reduced-motion`）を尊重する。
ブラウザー標準のネイティブ操作要素と意味的に正しい見出し構造（h1〜h6）を優先し、モバイル幅（狭い画面）を起点にレイアウトを組み立てる。
左右の余白や配置の指定には論理プロパティを用い、ページ全体に意図しない横スクロールが発生しないようにする。

## 装飾を選ぶ基準

要件、デザインシステム、ユーザーの明示指示による理由がある場合は、その表現を採用できる。
理由がない場合は、次の装飾を理由なく採用しない（努力目標。情報の構造と操作への注意を保つ）。

- グラデーションを塗った文字
- カードの中にカードを重ねる構造
- 同じ大きさのアイコン、見出し、本文のカードだけで構成する画面
- 見出しの上に毎回付ける小さな分類ラベル
- 片側だけに付ける1pxを超える色帯
- 色付き背景に置く無彩色の灰色文字（背景の色相に寄せた文字色を検討する）
- ずれのない発光影、ぼかしのない硬い影
- 操作上の役割がないガラス風の透過表現
- 絵文字やUnicode記号のアイコン代用（線の太さがそろう1つのアイコン体系を使う）
- 技術的な雰囲気だけを目的とした等幅フォント
- 中断も専用のフォーカスも必要としない作業へのモーダル
