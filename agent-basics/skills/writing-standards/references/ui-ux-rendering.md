## 完了前の実描画確認

機能的な正確さ（受入テストシナリオの期待結果、データの更新反映、各種操作の成否など）は、`testing-selection.md`「検証単位の選定」で選んだ層の自動テストによって担保する。
実描画は自動テストでは判定が難しい使いやすさや視覚的な違和感を検証する。
実装担当の自己点検と独立したユーザビリティレビューの双方で、`../../review-standards/references/reviewer-usability.md`「ユーザビリティレビューの判定」に沿って次の手順を実施する。

1. 安全に描画するため、導入済みのE2Eテスト環境、Playwright、またはブラウザー自動化ツールを使う。
   本番データへの書き込み、Gitのcommitやpush、外部サービスへの通信など、検証環境の外部に影響が残る操作は、プロジェクトの手順や設定で本番データから安全に隔離されたテスト専用環境でのみ実行する。
   隔離環境がなければ操作直前まで描画を確認し、操作後は未確認と記録する。
   ローカルサーバーも本番データへ直接書き込み得るため、`127.0.0.1`だけでは隔離の根拠としない。
2. 操作と表示の使いやすさを確かめるため、ブラウザーを利用できる環境では変更画面を実描画し、次を確認してから作業完了とする。
   1回で確認できる配置、文言、状態、装飾の問題をまとめて点検する。
   - エンドユーザーと同じクリック、入力、キーボード操作で主要シナリオを最初から最後まで実行し、迷わずスムーズに進められるか、次の操作が明確かを確認する
   - 各種状態（ドロップダウンメニュー、ダイアログ、ローディング表示、入力エラー表示、空の一覧、通知トーストなど）を表示し、画面キャプチャーを取得して、配置、文言、フォーカス位置、スクリーンリーダーの読み上げ対象、表示意図が正しく伝わるか確認する
   - 画面幅320px、400%拡大、キーボードのみの操作、提供する各テーマ（ライト/ダーク）、`prefers-reduced-motion`有効時、極端に短い値や長い値で表示崩れがないか確認する
   - 一覧や集計の0件・1件・大量件数を描画し、単数の文言や孤立した配置、大量件数での見え方と操作性を確認する。
     ページ送りや仮想スクロールがある場合は、それらが働く大量件数にする
   - 回線速度を制限して読み込み中を描画し、配置が不用意に動かず待機状態が伝わるか確認する
   - 画面をぼかすか縮小し、主要な見出し・操作・状態表示を周囲から見分けられるか、提供する各テーマで確認する
3. 問題の解消を確かめるため、観測した不具合や使いにくさをまとめて修正し、同じシナリオと状態で再描画して完全に解消されたことを確認する
4. 後続のレビューで確認できるよう、画面キャプチャーを確認可能な形式で保存し、ファイルパスを記録する。
   ブラウザーを利用できない場合は、確認できた前提条件と未確認の画面状態を明記し、実描画結果を未確定として報告する
