# 文字エンコーディングの詳細

文字コードと改行を扱う担当が混在する環境で誤りやすい点を避け、ユーザーが文字化けや壊れたファイルを受け取らないようにする。
WindowsとLinuxが混在する日本語の環境で文字コードと改行を扱う時（入出力、ZIP、Unicodeの正規化、書込ツールでの編集）の、一般知識から導けない誤りやすい点と避け方を示す。
原則9（`agent-basics:writing-standards/references/quality-principles-subtraction.md`）の適用である。

## 基本原則

- 入出力の境界で文字コードを明示し、内部はUTF-8で扱う。
  日本語のWindowsのANSIコードページ（ACP）はCP932で、ランタイムの自動選択に任せると文字化けや例外が起きる。
- 生のデータを復元する処理では、ライブラリがフィールドの値をプラットフォームに応じて加工していないかを確かめ、未加工の値を返すフィールドやAPIを探す（例は本書「ZIPファイル名の扱い」）。
- 文字列を一定の長さで保存する時は、デコードしてから文字単位で短くする（GNU `cut -c`などはバイト単位で処理し、マルチバイト文字を壊す）。
- 読込ではBOMの有無の両方を受け付け、書出しではBOMを付けない（Excel向けのCSVなど、受け取り側が要する時を除く）。

## 日本語テキストの自動判定順序

自動判定はBOM、ISO-2022-JPのエスケープシーケンス、UTF-8の厳格なデコード、EUC-JPとCP932の順に行う。
ISO-2022-JPはASCII互換のバイト列で、UTF-8の厳格なデコードでも失敗しないことがあるため、UTF-8より先に判定する。

## ZIPファイル名の扱い

- ファイル名は、General Purpose Bit FlagのBit 11が1ならUTF-8でデコードする。
- Bit 11が0の時の仕様上の文字コードはCP437で、作成元が日本語のWindowsだと確かな時だけCP932を使う。
  Info-ZIP Unicode Path Extra Fieldなどの拡張属性も確かめる。
- Windowsでは、Pythonの`zipfile.ZipInfo.filename`の内部の`_sanitize_filename`がパス区切りの`\`を`/`へ置き換える。
  CP932の2バイト目に`0x5C`（`\`）を含む文字（「ソ」「ポ」「表」など）が戻せなくなるため、生のバイト列は`orig_filename`から復元する。

## Unicodeの比較と安全性

- 比較、検索、一意性のキーには、要件に合わせてNFCなどで正規化した文字列を使う。
  認証・認可の識別キーやパスワードの突き合わせにNFKCを使うと、合字や互換文字の違いをすり抜ける脆弱性になりうる。
- 大文字と小文字を区別しないUnicode比較の方式は、対象の契約が要求する同値関係に合わせる。
  Pythonで標準的なUnicodeの大小文字を吸収する場合は、NFCで正規化してから`casefold()`を適用する。
- 大文字小文字の変換を介すと、入力が異なっても同じ値になり得る（例: `"ı".upper()`と`"I"`）。
  入力からアカウントを特定した後のパスワード再設定、通知や権限付与は、受け取った入力ではなく、そのアカウントの登録済みの値を送信先・操作対象に使う。
- macOSのHFS+はファイル名をNFD相当で保存し、APFSは元の正規化形式を保つため、ファイルシステムをまたぐファイル名の比較では正規化形式の違いを考える。
- 双方向テキストの制御文字（Trojan Sourceなど）、ゼロ幅文字、紛らわしい類似文字は、ソースコード、識別子、ユーザーの入力、ログへの混入を禁じるか警告する。

## 書込ツールの改行・BOM保全

CRLF、BOM付き、UTF-8以外のファイルを書込ツールで正しく作成・編集する手順を「書込ツールの改行・BOM保全」と呼ぶ。
`Edit`と`Write`に要る読取の状態は、`agent-basics:writing-standards/references/file-editing.md`「ファイル更新時の編集ツールの前提」に従う。

- Claude Codeの`Read`、`Edit`、`Write`はUTF-8を前提にし、CP932などのファイルはUTF-8へ変換してから扱う。
- `Edit`は既存ファイルのCRLFとUTF-8のBOMを保つため、既存ファイルの更新には`Edit`を使う。
- `Write`は常にLF・BOM無しで書く。
  CRLFやBOMを要するファイルは、`Write`で書いた後に改行とBOMを戻すか、新規作成ならBashで改行とBOMを指定して書く。
- UTF-8以外の既存ファイルは、`iconv -f <元の文字コード> -t utf-8`で変換して`Read`と`Edit`を行い、`iconv -f utf-8 -t <元の文字コード>`で戻す（新規作成も同じ）。
  変換を往復させない時は、Pythonでバイト列を元の文字コードのまま置換し、行末のCRLFも保つ。
- `.gitattributes`の`eol=crlf`が管理するのは改行だけで、BOMは別に戻す。
