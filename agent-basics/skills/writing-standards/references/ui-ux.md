# 画面の設計とユーザビリティの検収

本書は、エンドユーザーが操作する画面を計画、作成、変更、またはレビューするエージェントが参照する共通基準をまとめたものである。
画面の目的や達成すべき成果は、`quality-principles-qcd.md`「QCDと3段判定」に示された「利用主体と利用場面から仕様と設計を導く原則」に基づいて確定する。
画面設計は、用途を確かめ、既存画面・類例・参考画像から方向性を選び、プロジェクトの共通スタイルへ反映する順に進める。
主要な操作から結果までの流れを定義し、業務操作では既存画面と後掲の条件で調べた類例に沿う操作・一貫性・情報密度、読み物では行長と見出し構造を重視する。
宣伝や作品提示では目的に合う表現を強めてよい。
既存のデザインシステムとして、プロジェクトに存在するものから設計資料（DESIGN.mdなど）、デザイントークンの定義、コンポーネントカタログ（Storybookなど）、利用できるデザインツールのMCP、ユーザーが示したモックアップや画像を調べる。
存在しない資料やツールは作成・導入を求めず、調べた範囲を設計の根拠と併せて残す。
既存画面の改修は、その画面と既存のトークン・部品を基準にする。
ユーザーが一般的・普通の作りを求めた画面と、アカウント設定・ログイン・一覧と編集など広く使われる種類でプロジェクト内に同じ役割の画面がないものは、外部の類例も調べる。
同種の画面を持つ普及したサービス・製品やプラットフォーム提供元の設計指針から、参考にできる数があるものを複数選び、共通する構成と操作手順を設計の基準にする。
1製品だけの特殊な形を共通形とせず、調べた類例と意図して変える点の理由を、前掲の設計の根拠へ記録する。
新規画面や外見の作り直しでは、提示画像と利用できる参考例を実際に確認し、レイアウト・文字・配色・情報密度の何を参考にするかを選ぶ。
外部探索や画像提供の依頼は、既存資料と目的から必要性を判断する。
共通スタイルが未整備なら、今回必要な配色・文字・余白・部品の方針を既存のスタイル定義や設計資料へまとめ、後続画面でも再利用できるようにする。
独立した設計書やカタログ、特定のサービス・MCP・有料契約の新設は要件にしない。
参考画像が得られない場合も、用途と既存要件から設計を続ける。
既存画面の変更では、変更前の通常利用、保持する設計意図、製品の一貫した慣例を調べ、変更後の結果と比較する。
要求された改善だけでなく、この変更が既存の使いやすさを損なっていないかを判断する根拠にする。

画面設計に関する基準は、本書（共通方針）と`ui-ux-patterns.md`（主題別の設計）で定め、`ui-ux-web-rules.md`はHTML、CSS、JavaScriptによる実装手段やコードから機械的に判定できる条件を扱う。
この役割分担を「画面基準の3層」と呼ぶ。
