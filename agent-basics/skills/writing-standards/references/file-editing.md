# 既存ファイルの編集

既存のファイル（コード、文書、エージェント向け文書）を変える時の、編集の前提、結果の確認、複数ファイルの機械変換を定める。
原則4（`agent-basics:writing-standards/references/quality-principles-constraints.md`）を編集へ適用し、本番のファイルを壊さずに変更を確かめる。
改行コードとBOMの保持は`agent-basics:writing-standards/references/encoding.md`「書込ツールの改行・BOM保全」に従う。

## ファイル更新時の編集ツールの前提

対象の現在の内容と変更の前提を確かめてから編集し、ツールの終了状態と生じた差分で、意図どおりに変わったことを確かめる。
スクリプトで置換する時は、対象の入力と置換の一致件数も確かめる。
編集を委譲する時も、書き込む担当が自分の実行ホストでの前提を満たす。

## 複数ファイルの機械変換

1. 最初の1件を手で変換して手順を確かめてから、その手順を変換スクリプト（codemodなど）にする。
   スクリプトをその1件に再実行し、手で変換した結果との差分が無いことを確かめる。
2. 全ての入力の読込と前提（対象のファイル、一致件数など）を確かめ、出力の生成と構文の検査まで終えてから、本番のファイルへ書き込む。
   途中のデータはメモリーか実行環境の一時領域に置き、前提の不一致や構文エラーが見つかっても本番のファイルを元のまま保つ。
3. 構文の検査に成功した後も、参照先、呼出側、テストとの意味の整合を直接影響範囲で確かめる。
   直接影響範囲は`agent-basics:writing-standards/references/design-heuristics.md`「変更と検証の範囲」に従う。

## 操作前の読取状態

Claude Codeの`Edit`と、既存ファイルへの`Write`は同じ会話で対象の絶対パスを`Read`した読取状態を要求する。
内容を把握していることと、読取状態が成立していることは、別々に確かめる。
次の操作は読取状態を作らないため、行った後も編集の前に`Read`を実行する。

- Bashでの内容の表示（読取状態の成立はコマンドの解析に依存し、変数を含むパスやパイプで連結したコマンドでは不成立になる）
- Code Mode（REPL）の`file()`や`$`で実行したコマンドによる内容の表示
- リダイレクト、`cp`、`sed -i`、`iconv`などによる作成や変更
- 別のパスへの`Read`、他の担当から受け取った本文、過去の`Write`の結果

REPL内で編集する時は、先に同じ対象を`tools.Read`で読んで読取状態を作る。
複数のファイルへ`Edit`をまとめて発行する時は、全ての対象で`Read`が成功してから実行する。
未読を理由に拒否された時は、対象を`Read`してから再実行する。
書込を担当するサブエージェントにも同じ前提を適用する。
