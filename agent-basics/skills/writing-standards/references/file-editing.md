# 既存ファイルの編集

本書は既存ファイルをEditで編集するエージェントと、Writeで既存ファイルを上書きするエージェントへ、編集ツールが要求する読取状態と、機械変換の進め方を定める。対象はコード、文書、エージェント向け文書を問わない。改行とBOMの保全は`encoding.md`「書込ツールの改行・BOM保全」が定める。

## ファイル更新時の編集ツールの前提

Claude CodeのEditと、Writeによる既存ファイルの上書きは、対象パスの読取状態をホストが保持していることを要求する。確実にその状態を成立させるため、編集前に同じ会話で対象の絶対パスをReadする。本文を理解したことと、ツールが要求する読取状態は別であり、次の取得や操作だけでReadを省略しない。

- Bashでの表示（Read状態になるかはホストのコマンド解析で決まり、変数を含むパスや連結したコマンドでは成立しない）
- Bashのリダイレクト、`cp`、`sed -i`、`iconv`などで作成または変更したファイル
- 同じ内容を持つ別パスのRead、別の担当から受け取った本文、以前のWrite結果

複数のEditをまとめて発行する場合は、各対象のReadが成功してから発行する。Read不足で失敗した編集は、必要なReadの後に再発行する。
スクリプトによる置換は入力、一致数、終了状態と差分で確かめる。Codexのapply_patchは現在の本文とpatchの結果で確かめる。

## 複数ファイルの機械変換

スクリプトで複数ファイルを変換する場合は、全入力の読取と前提（対象、一致数など）の確認、全出力の生成と構文チェックを済ませてから製品ファイルへ書き込む。生成結果はメモリーか実行環境が用意した一時領域へ保持し、途中で前提不成立や構文不良を見つけた時点で製品ファイルを元の状態に保てるようにする。
構文が成立しても参照先・呼出側・テストとの意味の整合は保証されないため、書込後に直接影響範囲（`quality-principles.md`「変更と検証の範囲」）を確かめる。
