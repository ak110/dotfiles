# 表記の一括置換

多数の箇所で同一機能の語句へ置き換える場合（1対1の表記統一や、文脈に応じた決まった候補からの置き換えなど）は、一括置換と変更箇所の一括置換後レビューをセットで行う。まずは代表例を用いて、置換候補が指示対象、動作の主体、条件、否定や例外の意味を崩さずに維持できるかを検証する。意味を保てる部分は一括置換を適用し、候補に当てはまらない部分や文脈上意味が変わりやすい部分のみを個別に手動で修正する。修正箇所が少なく手動修正の方が低コストかつ高品質に完了できる場合は、QCDの観点に従って担当者自身が直接修正する。

- 置換を実行する前に、`git status --porcelain=v1 -- <対象パス>`を実行して対象ファイルに未コミットの変更がないことを確認する。変更したファイルをもとの状態に戻す際も、着手前に未コミットの差分が存在しなかったファイルに限定して戻す。
- 置換の適用直前に、`file-editing.md`「ファイル更新時の編集ツールの前提」に従ってファイルごとの読み取り状態を確認する。
- `git diff --word-diff=plain --word-diff-regex=.`を用いて文字単位の差分を出力し、変更箇所を全件レビューする。意図しない誤置換が発生している場合は、置換対象の条件を絞り込んで再実行する。
- 指摘を受けた文や一括置換の対象外となった文は個別に書き直し、`textlint-violations.md`「文の書き直しの委譲と検収」に定める品質条件に従って検収する。最後に通常のtextlintチェックと対象の自動テストを実行して完了を確認する。
