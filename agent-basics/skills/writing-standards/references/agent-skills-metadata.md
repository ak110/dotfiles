# Agent Skills実装ガイドライン：YAML frontmatter

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## YAML frontmatter

- 手順を書いたスキル（本文が順序だった作業を中心とするスキル）の名前は動詞で始める。
  判断基準・契約・規約集を提供するスキルの名前は、対象を表す語にする。
- `name`（ディレクトリ名と一致させる値）には、そのスキルが担当する工程や起動のきっかけを表す言葉を選ぶ。
  特定の実現手段（作業項目の記録形式、ツール名、コマンド名など）や実装内部の専門用語は避ける（努力目標）。
  エージェントはスキル名を起動判断の重要な手がかりにするため、手段名を中心にしてしまうと、別の手段で同じ工程を行う際に起動されなかったり、手段名が単に出現しただけの文脈で誤って起動されたりする。
  起動条件の全体像は`description`に記述する
- `description`には対象とする作業と起動条件のみを記載し、目的、背景、手順は本文に記載する（努力目標。`description`は常時読み込まれるため）。
  複数行にわたる場合はYAMLの折り畳みスカラー（`>`）を用いる
- 他のスキルやエージェントから明示的に呼び出される前提のスキルや、ユーザーが`/name`で明示起動する前提のスキルでは、`description`には呼び出し元と起動条件のみを簡潔に記載する。
  渡された引数のみを入力として受け取るスキル（`context: fork`を持つものなど）は、受け付ける引数と返却する結果の仕様を`description`に明記する
- 起動方法に合わせて以下のように設定する
  - ユーザーが`/name`で手動起動することを想定しない場合: `user-invocable: false`
  - ユーザーの手動起動専用とする場合（副作用の大きいワークフローなど。Claude Code固有）: `disable-model-invocation: true`
  - エージェントとユーザーの双方が起動する場合: どちらも設定しない
- Codex向けの`agents/openai.yaml`を配置するスキルでは、`interface.display_name`をディレクトリ名と一致させる。
  Codexの入力補完機能はその値を候補名として表示するため、異なっているとスキル名を入力しても候補から選択できなくなる
- ユーザーが`/name`で起動できるスキルが、動作を切り替える決まった語を引数に取る場合は、その語を`argument-hint`へ書く。
  自由記述だけを受け取るスキルでは、入力の判断材料が増えないため省略する。
  決まった語に続く自由記述も受け取る場合は、その枠を併記する。
  省略できる引数は角括弧、択一は`|`で示し、角括弧で始まる値はYAMLの文字列として引用符で囲む
- frontmatterで設定済みの仕様を、`description`や本文に重複して再掲することは避ける（努力目標）。
  `argument-hint`は人間向けの入力補完であり、エージェントが引数を選ぶための`description`の説明は保持する

## ユーザーが起動するスキルの着手手順

`user-invocable: false`が設定されていないスキルは、起動から作業開始までの間にユーザーの追加操作を求めない構成で記述し、確認、選択肢の提示、追加入力の要求などは作業に着手した後に配置する。
ユーザーはそのスキルを作業の起点として起動するため、着手前に追加操作を求める手順にすると作業のスムーズな開始を妨げてしまう。
