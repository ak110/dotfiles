# Bash記述スタイル

本書は、Bashで記述するスクリプト（`sh`、`bash`、`sh.tmpl`）のスタイル基準を定める。

- シバンは`#!/usr/bin/env bash`とし、先頭で`set -euo pipefail`を宣言することを基本とする。スクリプト自身の配置場所は`BASH_SOURCE`から解決する。
- 変数参照やコマンド置換は、常にダブルクォートで囲む。
- スクリプトが作成した一時ファイルやディレクトリなどの資源は、`trap`を用いてスクリプト終了時に確実に回収する。
- コマンドの終了コードに基づいて分岐させる場合は、`cmd1 || cmd2`のように記述する。`exec`が成功するとプロセス自体が置き換わるため、後続のシェル処理で終了コードに応じた分岐は行えなくなる点に留意する。`exec`自体の起動失敗をハンドリングする処理と、コマンド実行後の終了コードを処理する記述は明確に区別する。
- 外部入力の取り扱いに関する一般的な作法は、`implementation-time.md`の「セキュリティ・ロギング・エラー処理」に従う。Bashにおいては`eval`や`bash -c`に外部入力を直接渡すことを避け、動的な分岐が必要な場合は`case`文を用いてあらかじめ定義した固定の候補へ振り分ける。
- `rm -rf`を使用する前に、削除範囲をより安全に限定できる代替手段を優先して検討する（空ディレクトリの削除には`rmdir`、Git管理下のファイルには`git rm -r`を用いるなど）。対象が特定の一時ディレクトリに限定される後始末で`rm -rf`を使う場合は、対象パスを表す変数が空でないことを確認し、`trap`と組み合わせて安全に実行する。
