# エージェント宛てメッセージ

本書では、hookやその他の生成元がエージェントへ直接渡すメッセージの記述言語、機械生成テキストの識別方法、およびhook通知の整形ルールを定める。

名指し参照は`../SKILL.md`「名指し参照の読込方法」に従う。

## メッセージの記述言語

エージェントへ直接渡す出力（`reason`、`additionalContext`、終了コード2のstderrなど）は日本語で記述する。日本語以外の文章が会話に混ざると、その後のモデルの応答言語が影響を受けるためである。
原本ファイル（`CLAUDE.md`など）の章名、節名、キーワードは、将来の名称変更に追従しやすくするため原本の表記通りに引用する。

## エージェント宛てメッセージの標識

機械が生成したテキストには、ユーザー自身の発話と区別できるように明確な境界、生成元、通知種別を設ける。メッセージ内にユーザー入力を転載する場合も個別に識別できるようにし、機械が生成した説明文をユーザーによる認可として扱わないようにする。エージェントへ届かないフィールドや、追加本文のない通常の許可応答は本規定の対象外とする。

## 通知本文の整形

hook通知は、ユーザーロールなどでエージェントへ届く外部からの指示である。
求める行動は「取得せよ」「確認せよ」などの命令形で書き、手順本文の「〜する」という終止形と区別する。
事実の説明と理由は平叙文のまま保つ。

本節では、遮断（`block`）、問題への対処を促す警告（`warn`）、および発話ごとに届ける定型通知（`notice`）の本文構成を定める。問題の解消方法を指定する引数を`fix`と呼ぶ。遮断と警告の選択基準は`claude-hooks-block-warn.md`に従う。

以降の整形関数の規定は、hookの出力用に共通の整形関数を持つ場合に適用する。

- 遮断や警告の整形関数は、解消方法（`fix`）を必須の引数として受け取る。空文字列や空白のみの値は拒否し、本文に続けて次の具体的な操作を明記する。
- 遮断と警告は共通の整形関数を通し、メッセージ本文と解消方法を別の引数として受け取る。文章表現は`writing.md`「読み手別の追加注意点」に合わせる。
- `notice`区分は行動指示そのものを本文とする定型配信であり、`fix`の指定は任意とする。

遮断を解除するために必要な情報は、すべて通知本文に含める。別のツール呼び出しによる情報取得を求めると、遮断されるたびに往復のターンを消費するためである。
判定処理が出力の有無や形式など代替的な条件のみを検査している場合は、`fix`で本来達成すべき結果に至る操作を具体的に指定し、判定だけを通過する最小限の出力と本来の結果を区別する。
`fix`で示した手段を実行できないエージェントが存在する場合は、同じ判定を通過できる別の手段や、遮断が解除される条件を併記する。
メッセージ本文に一覧を列挙する場合は、判定対象と関連する要素だけに限定する（努力目標）。

`warn`区分の反復抑止は、`claude-hooks-block-warn.md`「遮断と警告の選択」に従う。
内部障害を通知する場合も、イベントとホストが受理するLLM向けの欄へ標識付き本文を集約し、1回の応答を単一JSONに保つ。
配送先を持たない保守イベントでは通知を出力しない。
終了イベントの障害を知らせるためだけに継続を強制せず、既存の診断ログへ記録する。
