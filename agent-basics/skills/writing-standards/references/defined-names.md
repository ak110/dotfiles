# 名前の方針と定義済みの名前の一覧

本書は名前を選ぶ方針を定める。
本書の読み手は名前を書く全ての主体（規範、設計文書、WI、計画、コミットメッセージおよびコードの書き手）である。
定義そのものは定義元だけに置き、複数資料に共通する名前は定義元への索引を設ける（`agent-documents-basics.md`「主要用語の初出定義先」）。

## 名指し参照の読込方法

## 命名の方針

工程・レビュー・検証・判定・担当などの名前は定義して統一する。
適用範囲は本スキルに従って書く全ての成果物とし、名前は次の方針で選ぶ。

1. 定義を読まなくても指す対象が分かる自然な語を選ぶ
2. 一般的な語（独立、root、固定、管理など）に独自の意味を持たせず、別々の概念に似た名前を付けない
3. 識別子（スキル名、コマンド名、ファイル名、定数名など）がある対象は、日本語の説明的な名前を作成せず識別子で書く
4. ユーザーが名付けた名前と、画面などエンドユーザーが目にする場所で使う名前は残す
5. 境界があいまいな名前は原要求と既存の定義を調べ、`quality-principles.md`「要件と認可」を適用する。技術的に確定する境界は自ら決め、ユーザーだけの選好や適否が残る場合だけ確認する
6. 返却形式の欄名も日本語名にする
7. 名前を残す根拠から、用例の多さと既存の定義の有無を除く

対象を指す時は、識別子があれば識別子を、無ければ定義済みの名前を使う。
どちらも無い対象へ繰り返し参照する名前が要る場合は、自然な語を選び、定義元へ1文の定義を置いて索引へ行を加えてから使う。定義を置く前の対象は説明で書く（`writing.md`の実在する名前の規定）。
新しく導入する概念名と画面に新しく表示する名前（1つの文書の中だけで定義する語や、質問の説明のために作成した語を含む）は、次の点を押さえて候補を選び、方針1と方針7で順位を付ける。

- 候補には索引に無い既存の呼び方も含め、候補語ごとに全追跡ファイル（変更予定の外にある設計文書、経緯記録、エンドユーザー向け文書と隠しディレクトリを含む）を固定文字列で検索する。一覧だけから選ぶと、別の意味で使われている語を新しい概念へ割り当てる
- 別の意味の用例がある語は、既存の用例を書き換えても両方の意味に読めるため候補から外す。ユーザーが指定した語を変える案は方針5に従ってユーザー確認する
- 画面に表示する名前は、同じ表示領域の既存ラベルの記法（言語、大文字と小文字、語の区切り）に合わせる（`ui-ux.md`「判断の順序」）。記法の異なる既存ラベルは設計記録で目的を確かめ、記録が無ければ方針4に従って残す案を推奨し、揃える案は目的が記録に無いことを添えて選択肢に載せる
