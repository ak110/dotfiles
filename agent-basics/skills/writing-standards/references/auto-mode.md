# Claude Code auto modeのカスタムルール

本書は、Claude Codeのauto modeにおけるカスタムルールの記述形式、適用範囲、および安全境界に関する品質基準を定める。

カスタムルールは、`~/.claude/settings.json`内の`autoMode`配下に自然言語で記述する。
`allow`、`soft_deny`、`hard_deny`、`environment`の各配列を設定すると、該当する区分のデフォルト一覧が上書きされる。デフォルトの設定を保持したままルールを追加する場合は、配列内に文字列リテラル`"$defaults"`を含める。
`allow`に指定した許可ルールは、デフォルトの`soft_deny`による拒否判定を上書きする。設定対象となるキー名は、公式スキーマ（`$schema`のURL）を参照して実在することを確認する。

## ルール区分

- `allow`: 明示的に実行を許可する操作
- `soft_deny`: 標準では拒否されるが、ユーザーの指示や文脈に応じて許可（`clears`）される操作
- `hard_deny`: いかなる状況でも実行を拒否する操作
- `environment`: 信頼境界（対象リポジトリ、ドメイン、バケット、クラウドサービスなど）の定義

## カスタムルール記述の注意点

- 適用対象となる操作、対象コミットの性質、対象パスなどを文面上で明確に示す。
- 記述の粒度は操作の種別単位とし、分類器（classifier）が判別するのに必要な代表例のみを添える。将来変更されやすい具体的な識別子（サブコマンド名、コマンドラインオプションの詳細な綴り、個別ファイルのパスなど）の網羅的な列挙は避ける（ユーザー指定）。
- ルール文は許可する対象の操作のみを簡潔に記述し、それ以外の操作の判定は`soft_deny`や`hard_deny`の標準動作に委ねる（ユーザー指定）。対象範囲は実際に行う作業操作に合わせて記述し、リモートホスト、コードの由来、所有者、ユーザーの意図などによる過度な限定は加えない（ユーザー意図の判定はUser Intent Ruleに任せる）。対象を狭めすぎると、正規の手順に沿った操作まで拒否されて作業が停止してしまう。
- ルールによる上書きの範囲は`soft_deny`にとどめ、デフォルトの`hard_deny`で保護されている領域は維持する（auto modeが持つ安全境界を損なわないため）。
- 信頼対象（個人の管理リポジトリや信頼できるドメインなど）を参照する`allow`ルールは、`autoMode.environment`で宣言した信頼境界と内容を一致させる。
