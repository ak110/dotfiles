# 規範資料の読込方法

SKILL.md、references、ルール、役割契約などのエージェント向け文書は、選択したファイルの全文を読む。
節名は該当する基準の所在を示す手掛かりであり、取得範囲はファイル全体とする。
無関係な内容まで読む構成は、読む契機・主体・判断が同じ単位へファイルを分割して整える。
同時に必要な前提・例外・認可・終了条件は同じ判断単位に保つ。

## 名指し参照の読込方法

本文で名指しした資料と読込表の資料は、条件が成立したら、判断や操作の前に自分で全文を読む。
参照先を無条件に連鎖して読むことはせず、次の操作・対象・役割・判断から成立する条件を選ぶ。
規範以外の記録類やソースなどの資料では、確認する内容に必要な範囲を選べる。

## 読込表の読み方

読込表は、どの時点でどの基準へ到達するかを示す。
本文が条件を付けて他の資料を名指しする箇所も同じ読み方をする。

- 読み手が使う列は「時点または条件」と「全文読む資料」である。
  条件が成立したら、対象の判断や操作の前に指定ファイルの全文を読む。
  硬い制約、認可、変更範囲、終了条件を含む基準を取得してから適用する。
- 「起動時」の資料は、スキルや役割を起動した直後、その本文に従った判断を始める前に読む。
  実行環境が同じ全文を起動入力へ挿入した場合は、読んだものとして扱う。
- 「契機」「配送操作」「資料選択子」は、読込を補助する自動化の解析用の列であり、読み手の条件判定の対象から除く。
  自動化が導出できる行では、これらの列が無いか空である。
  自動化がない環境も、読み手向けの2列に従う。
- 同じ条件の行が続く場合は、各行の指定するファイルを読む。
  現在の条件に該当する参照先を選び、別の役割や工程の資料を無条件に読み進めない。
- 同一の主体・内容・文脈境界内で取得済みの本文は再利用する。
  行番号で分割取得する場合は、必要な未取得部分を末尾まで補い、全文が届いた後に取得済みとする。
  参照案内、保存先の提示、出力の省略は、本文の取得の判定対象から除く。
- 会話圧縮後は、現在の要求・認可・未完了の操作を原本から復元し、残工程で必要な資料を選び直す。
  圧縮前の資料一覧は再取得先を選ぶための手掛かりとする。
