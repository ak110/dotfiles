# 入力素材の取扱い

本書はユーザーの入力素材を文章へ取り込むときの基準を定める。
「文章の共通規定」と「日本語の書き方」は`writing.md`の同名節を指す。

## 名指し参照の読込方法

名指し参照は`../SKILL.md`「名指し参照の読込方法」に従う。

| 時点または条件 | 全文読む資料 | 契機 | 配送操作 |
| --- | --- | --- | --- |
| 入力素材を文章へ取り込む前 | `writing.md` | 判断 | `read:agent-basics:*/skills/writing-standards/references/writing.md` |
| 各名詞句の定義元と参照可能性を確認する前 | `review-only-criteria.md`の「名前の到達性」 | 判断 | `section:agent-basics:*/skills/writing-standards/references/review-only-criteria.md#「名前の到達性」` |
| 文章の書き直しを委ねる時とtextlintの診断へ対処する時 | `textlint-violations.md` | 判断 | `read:agent-basics:*/skills/writing-standards/references/textlint-violations.md` |

## ユーザー入力素材の取扱い

ユーザーが作業の背景や経緯を説明しながら指示を出す場合、提示されたテキストは想定読者と必要な情報の粒度に合わせて整理してからドキュメントに取り込み、要件として正式に反映すべき情報と、背景理解のための参考情報とを明確に区別する。
質問に対する回答と、成果物自体の変更を求める要求も区別して扱い、説明文を成果物に追加するかどうかは「文章の共通規定」の「情報を追加する前の判断」に従って決定する。質問に回答したという事実だけで、その回答内容をそのままドキュメントへ追記しない。

- 書き直しの前後で、主体、対象、条件、動作、数値、例外事項、識別子、不確実性の度合いを綿密に比較し、原文や観測事実にない仕様、設定値、原因、効果を推測で補わず、不明な点は不明なまま維持する
- 主張とその比重、言い切りの強さ、文の働きを保つ。許可、能力、義務、保証や、評価、予定、現在の動作、完了を区別し、否定や比較で退ける対象と優先順位を維持する
- 原文の理由と根拠を保持し、説明のつながりを整える際は、必要に応じて同じ具体例を引き継ぎ、仕組み、条件、結果を追えるようにする（努力目標）
- 一時的な作業事情、特定のセッションに固有の事象、特定の個人に対する言及などは、後続の読者の判断に真に必要な場合に限って残す
- 対話の中で言及された事物は、第三者が一意に特定できる正式な実体名または客観的な説明文で記述する
- 原文の改変を避けるべき逐語的な引用は、言語指定を`text`としたコードブロックで囲む。コードブロックの内部は各種チェックツールの対象外となるため、原文のまま正確に保持できる

文章が完成した段階で、作業の経緯を知らない読者の視点に立って全体を通読し、制作過程で生じた作業メモや試行錯誤の痕跡を整理する。実装上の制約や不採用となった代替案は文章の構成や語彙の中に自然に反映し、「〜についてご了承ください」といった免責調の言及は読者がその制約自体を把握する必要がある場合に限定する。修正指示に対する作業完了の表明や前バージョンとの差分解説は、コミットメッセージやレビュー返信に記述する（努力目標）。各名詞句の定義元と参照可能性の確認は、レビュー限定基準の`review-only-criteria.md`「名前の到達性」に沿って実施する。

文章の起草を外部に委譲する場合の品質基準は`textlint-violations.md`の「文の書き直しの委譲と検収」に、textlintの指摘への対応方針は同資料の「textlint指摘への修正方針」に従う。
