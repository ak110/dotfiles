# Web画面の実装とレビューで確認する規則

本書は、HTML、CSS、JavaScriptを用いてエンドユーザー向け画面を実装またはレビューするエージェントに向けて、ソースコードから判定できる確認項目をまとめたものである。
エンドユーザーの操作によって生じる動作結果の正しさは`testing.md`「検証単位の選定」で選んだ層の自動テストで確認し、操作の分かりやすさは`ui-ux.md`の「完了前の実描画確認」およびユーザビリティレビューを通じて確認する。

主な参考資料: [Vercel Web Interface Guidelinesの取得時点の原文](https://github.com/vercel-labs/web-interface-guidelines/blob/e3d624baaf29dc1fc645aff3e38f03e564d2d6b1/command.md)（commit `e3d624baaf29dc1fc645aff3e38f03e564d2d6b1`）。作業時に原文を毎回再取得するのではなく、本書にまとめた規則に基づいて判断する。英語の文章表記に固有の規則は、日本語画面の判定対象から除外する。

## アクセシビリティとフォーカス

- アクションの実行には`button`タグ、画面遷移には`a`タグを適切に使い分け、キーボード操作や「新しいタブで開く」操作ができる状態を維持する。アイコンのみのボタンにはアクセシブルな名前（`aria-label`など）を付与し、装飾目的のアイコンは支援技術から隠す（`aria-hidden="true"`）。意味を持つ画像には適切な代替テキスト（`alt`属性）を設定する
- すべての入力欄に関連付けられたラベル（`label`タグや`aria-labelledby`）を配置する。見出しタグは階層順（h1〜h6）に正しく配置し、ページの主コンテンツへ直接移動できるスキップリンクを用意する。非同期の通知やリアルタイムの入力検証結果は、適切なlive region（`aria-live`）を用いてスクリーンリーダーに伝える
- キーボード操作でフォーカスが当たった要素には、`:focus-visible`を用いて視認しやすいフォーカスインジケーターを表示する。ブラウザー標準の`outline`を削除する場合は、同等以上の代替スタイルを同じフォーカス状態で明示する。固定ヘッダー、フッター、オーバーレイなどに隠れることなく、フォーカス中の要素が常に画面内で視認できる位置に保たれるようにスクロールや配置を調整する

## フォーム

- 入力目的に応じて適切な`name`、`autocomplete`、`type`、および`inputmode`属性を指定する。ラベルをクリックした際に対応する入力欄へフォーカスが移動する構造にし、クリップボードからのテキスト貼り付けを妨げないようにする
- 送信処理を開始する前の送信ボタンはクリック可能な状態を維持し、送信処理の実行中は進行中であることを明示する
- ブラウザーの「戻る」操作やダイアログを閉じる操作も、`ui-ux-patterns.md`の「フォームと入力」で定めている「入力値を失う操作」として扱い、未保存の入力がある場合は確認を挟む

## コンテンツ、状態、画面遷移

- 極端に長いテキストや空の値（データなし）が含まれる場合でも、レイアウトが崩れず必要な情報にアクセスできる構造を保つ
- ユーザーが画面を再訪した際やブラウザーの「戻る」操作した際に復元すべき状態（検索条件、絞り込み、ページ番号など）は、URLのクエリパラメーターなどに反映する
- 非表示にしたモーダルやオーバーレイは、キーボードフォーカスが到達しないようにDOMから除外するか`inert`属性などを適用する

## アニメーション、画像、パフォーマンス

- CSSアニメーションや画面の動きに伴う描画負荷を低く抑え、ユーザーの操作によって中断できるようにする。ユーザーがOS側で`prefers-reduced-motion`（視覚効果の抑制）を設定している場合は、装飾的な動きを停止する
- 画像タグには幅と高さを指定して表示領域を事前に確保し、CLS（レイアウトのズレ）を防ぐ。画像は画面の表示に必要な優先度に合わせて順次読み込む
- レンダリング時間を測定し、不要なDOM要素の削減やレイアウト再計算を抑制する。仮想スクロールなどの最適化手法の採否は、単にデータ件数だけで判断せず実際の描画負荷を踏まえて決定する

## テーマとローカライズ

- アプリケーションが提供するダークテーマなどの配色設定は、スクロールバーやフォームコントロールなどのネイティブUI要素にも適用する
- 日付や数値の表示は`Intl`APIなどを活用してユーザーの地域設定に合わせて表示し、翻訳対象外とすべき固有名詞、プログラムコード、内部識別子は明確に区別する
- Reactなどのフレームワークでサーバーサイドレンダリング（SSR）とハイドレーションを併用する場合は、入力欄の変更イベントハンドラーや日時の描画結果がサーバー側とクライアント側で完全に一致することを確認する

## 避けるべき実装

ユーザーが画面を自由に拡大表示できるよう適切な`viewport`メタタグを設定し、クリックやタップが可能な要素と単なる装飾要素を視覚的に明確に区別する。
`viewport`設定で`user-scalable=no`や`maximum-scale=1`を指定して拡大操作を制限している場合や、操作可能に見えるのに実際には反応しない要素が存在する場合は、ユーザーの利用シナリオへの影響を確認した上で修正する。
