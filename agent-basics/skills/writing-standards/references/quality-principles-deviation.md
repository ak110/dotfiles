# 原則5：逸脱は情報である

期待との違い（エラー、失敗、指摘、自分のミス、退行）に気付いたら、直す前に、期待、原因、処置、広がり、確認の5つを問う。
目的は、目先の失敗を消すことではなく、期待した結果を最も少ない仕組みで取り戻すことである。
5つの問いと、書き出す場面は`agent-basics:bugfix`が定める。

## 理由

逸脱は、成果物か、期待か、手順のどこかが思っていた状態と違うことを知らせている。
症状だけを消すと原因が残り、同じ誤りが別の場所で起きる。
期待の側が誤っていることもあり、その場合に成果物を直すと、要らない仕組みを足すことになる。

## 失敗例

- 失敗を消すことを目的にした。
  試験が失敗した時に、原因を確かめずに試験の期待値を書き換え、別の場面では再試行と待機を足して通した。
  期待が今も正しいか、何が失敗を起こしたかを観測で確かめてから処置を選ぶ。
  期待の側を変える処置と何かを足す処置は、無くす案、単純にする案、直す案を比べた後に選ぶ。
- 同じ誤りの2回目に、同じ種類の対策を重ねた。
  既存の規定が適用されなかった誤りに対して、同じ趣旨の禁止文をもう1つ足した。
  2回目は、その誤りを誘った入力（手順の例、直前の出力、置いていた前提）と作業の構造を探して直す。
