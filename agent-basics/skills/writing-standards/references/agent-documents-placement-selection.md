## 置き場所の選定

規範を追記・新設・移動するときは、置き場所を層から順に決める。
作業中に開いていた資料や追記の契機になった資料は、次の比較を経ずに置き場所にしない（手近な資料へ書くと、規範が必要な主体へ届かないか、無関係な主体の読込を増やすため）。

1. 規範を読む主体（全エージェント、委譲元、委譲先、特定の役割、特定スキルを起動したエージェント、特定プロジェクトの編集者など）と、読む契機（常時、スキル起動時、役割起動時、読込表の条件成立時、異常時など）を確定する。
2. 対象リポジトリが規範の層の一覧（地図）を持つ場合はそれを使い、無い場合は`agent-documents-basics-placement.md`「置き場所と配送」の区分を使って、主体と契機に合う最も狭い層を選ぶ。
3. 選んだ層の中で、責務（スキルの`description`と冒頭の責務文、資料の冒頭）が規範の主題と一致するスキル・資料を選ぶ。
   一致する資料が無い場合は、近い資料へ混ぜず、新設と既存資料の責務の拡張を比べる。
4. 選んだ置き場所から、規範を要する判断の前に本文へ届く経路（常時の配送、スキル起動、読込表の行）があるかを`agent-documents-basics-ownership.md`「既存規範による被覆の判定」で確かめ、無ければ経路を同じ変更で加える。

hook通知、CLIの`次の操作`、自動挿入本文などの機械生成文には、検出した事実、読み手に必要な操作、参照先の節だけを書く。
判断の手順や条件の本文は規範側の節だけに書き、機械生成文はその節を参照する。
検出や強制の処理そのものは`agent-documents-basics-placement.md`「置き場所と配送」のとおりhookやCLIへ置き、判断の本文と分ける。
通知本文の書き方は`claude-hooks-messages.md`がこの原則を参照して定める。
