# 成果物へ書く事実の調査：実行結果の検証

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| X投稿などの外部資料の本文・日時・添付画像を取得する前 | `../../fetch-sources/SKILL.md` |
| 経験の保存先と索引を選ぶ前 | `agent-documents-basics-placement.md` |

## 実行結果の検証

- 現在の製品の欠陥、期待どおりの挙動、過去の失敗、外部サービスの障害を、観測時点と原因の出所を区別して報告する。
  必須の検証が外部障害で成立しない場合は、成功と扱わず、未確認の要求、続行できない理由、実施済みの確認を示す。
- 性能改善を主目的とする作業の結果は、変更前後の数値と比較条件、挙動の維持、および速度と資源使用量などのトレードオフを報告する。
- 事実、推論、評価、仮説を明確に区別し、特定の仕組みや機能を原因として挙げる場合は、その機能が実際に関与していることを現物の観測によって確認する。
  規範で判定基準が定義されている用語（「採用」「合格」「完了」など）は、その基準に基づいて実際に判定してから使用する。
- 調査・測定の結果を報告するときは、読み手が根拠と確かさを判断できるよう、確認済みの事実、使用したデータと測定条件、根拠を添えた仮説、未確認事項を、内容に必要な範囲で見出しと自然な文章によって対応付ける。
  資料から確認した他者の報告と自分で観測・測定した結果を分け、推測は未確認と分かるように書く。
  単純な確認結果は必要な情報が分かる短文で答え、空の節や文ごとの固定ラベルは付与対象から除く。
  役割固有の返却構文がある場合は、その構文の本文欄や参照先の成果物で同じ区別を保つ。
- 副作用の有無は、変更対象となる実体の状態を直接確認して判断する（失敗した操作であっても、途中の変更が残存する場合がある）。
- 共有状態を扱うホスト、ツール、またはエージェントCLI（`claude -p`や`codex exec`など）を実際に実行して検証する場合は、公式に提供されている状態隔離手段（`CODEX_HOME`など）の適用範囲を確認し、必要な状態のみを一時領域へ隔離して実行する。
  隔離が正しく機能しているかどうかは、環境変数を設定したこと自体から推測しない。
  対象プロセスが実際に参照する読み込み先や書き込み先を公式の確認コマンド（設定の解決値を出力するコマンドなど）で取得し、実データへの初回アクセス前に期待する検証領域と一致していることを確認して判定する。
  環境変数名の指定ミスや、ホームディレクトリを変更しても個別に指定した保存先が引き継がれてしまうような問題も、この事前確認で検出する。
  検証時の副作用には、起動されたエージェント自身によるシェル実行、ファイル編集、MCP経由の外部送信も含まれる。
  既存の実セッションの再開や分岐（`--resume`、`--continue`、`--fork-session`、`codex exec resume`など）をして、ログから抽出した実際の作業指示を実行すると、元の作業が再開されてしまう。
  この実行は元の一時領域、委譲先、作業項目の管理場所などの共有リソースに影響を及ぼす可能性があるため、ツールの挙動自体を検証する場合を除き、ツールの利用を無効化する。
  Claude Codeでは`--tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}'`を組み合わせて指定する。
  ツールを無効化する必要があるCodexの調査において同等の公開手段が確認できない場合は、実セッションの再開や分岐をせず、実際の作業指示も実行しない。
  保存されたログの照会や公式一次資料の調査にとどめる。
  使用可能なツールと権限は初回の実行ログで確認した上で、複数の実行へと展開する。
  Claude Codeでは、stream-json形式の`system`イベント（`subtype: init`）に含まれる`tools`、`mcp_servers`、`permissionMode`を確認する。
  副作用がないかどうかは実際の観測結果に基づいて判断する。
  `--allowedTools`は確認プロンプトなしで実行できるツールを指定するものであり、ツールの使用を制限する設定ではない。
  `codex --ephemeral`はセッションログの永続化を抑止するが、ChatGPT認証の更新や`auth.json`への保存は抑止しない（トークンの有効期限が5分以内の場合や、前回の更新から8日を超えている場合は更新して保存される）。
  隔離環境で認証が通らない場合は通常の認証解決を維持し、共有ファイルの更新時刻（mtime）などの変化を観測して副作用の有無を報告する。
  Git管理外の認証情報ファイルは元の場所に置いたままにする。
  通常の認証解決が成立しない場合は、成立しない条件を担当者へ報告する。
  こうした隔離処理の追加は本調査の場面に限定し、通常利用や既存のテスト環境の隔離設定は現状のまま維持する。
  関連する監査記録は、`docs/development/audit-records-investigation.md`の「agent-basics/skills/writing-standards/references/investigation.md：実行結果の検証：2026年10月9日」を参照する。
  同「agent-basics/skills/writing-standards/references/investigation.md：実行結果の検証：2026年10月18日（1）」も参照する。
- 応答テキストの内容自体を評価対象とせず、動作確認や対照実験、識別子の観測のみを目的としてエージェントCLIを起動する場合は、検証対象がモデルの性能、思考レベル（effort）、設定、ツール群に依存しない限り、利用可能な最も安価なモデルと低いeffort設定を選択する。
  セッションは保存せず、不要な設定・ツール・MCPは読み込まず、最小限のシステムプロンプトで起動する。
  公開されているコマンドライン引数は対象バージョンのヘルプで確認し、起動回数は検証に必要な最小限にとどめる。
- システム負荷によって変動する測定では、制御できる重い処理を停止させるなど条件をそろえ、条件差、通常のばらつき、計測・デバッグ処理自身の影響を変更効果と区別する。
  同時に変更した要素の寄与は未分離のまま断定せず、採否を変える場合に対照や反復を選ぶ。
  ユーザー自身の主観でしか判断できない使い勝手や適合性については、実装の完了のみを報告し、評価の確定は事後承認に委ねる。
- 独立した複製環境を作成して多数の条件を比較検証する場合は、展開する前に代表的な1つの条件を用いて、必要な資料の取得、対象バージョンと入力データの対応、判定用コマンドの正常終了までが確実に成立することを確認する。
  複製対象には、主入力データ、処理側が参照する関連資料、および対象リポジトリの識別情報を含める。
  検証対象の機能不全による未達と、実行環境の不備による判定不能は明確に区別し、後者は比較結果のデータから除く。
- 行った変更が次回のセッションでも正しく反映されるかどうかは、Gitの保持ブランチから実行時の読み込み先までの配布・反映フロー（プロセスの再起動や自動更新のタイミングを含む）を確認して検証する。
- 処理の完了と成功は、処理の開始や受付の観測とは明確に区別し、終了状態を最終的に判定する主体の観測結果に基づいて判断する。
  終了状態を観測する前は「処理中」または「未確認」と表記し、終了状態を判定する主体を観測できない場合は、対象と不足している確認条件を報告する。
