# テスト方針（全言語共通）

テストを追加するかどうかは、そのテストが検出する契約違反の価値に基づいて判断する。
テストコードにおいては、簡潔さ、安定性、および実行速度を重視する。
単に公開関数を新設したことだけを理由にしてテストを追加することは避ける。
必要な品質と観測する結果から検証手段を選び、TDDの実施やテスト件数そのものを目標にしない。
テストの新設・変更・レビューでは、契約違反を起こす変更を検出できるか、同じ契約を保つ内部変更で失敗しないかを両方向の反例として確かめる。
非空・真偽・型・例外の不発生を確認する試験も、契約に反する値や状態で成功しないかを判定する。
対象を実行せず準備データ同士だけを比べる試験や、必要な副作用の欠落・二重実行を検出できない試験は、その契約を観測する形へ改める。
通常は本文とコードの読解で判断し、効果を判断しにくい対象は`testing-conditions.md`「分岐条件の効果の裏付け」で確認する。
公開された呼出順序、性能、安全性、構造的制約など契約自体が求める性質と、修正前の失敗確認を含む回帰検証は維持する。
