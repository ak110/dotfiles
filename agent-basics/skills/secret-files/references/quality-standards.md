# 日本語の書き方

伝える内容は直接書く。
主張を際立たせるためだけに否定する側を並べる対比、求められていない否定・除外・現状維持の表明、誤解を先回りして封じる防御的な説明は省く。
読み手が明らかに知っている常識、結論に関係しない例外、結論を変えない限定条件の補足も省く。
読み手の判断に要る実在の制約と例外、確定した事実と未確認の事項の区別、認可・安全性・公開契約に関わる条件は残す。
読者が取り違えやすい実在の選択肢や誤解を除く時は、「`== None`ではなく`.is_(None)`を使う」のように1文で対比してよい。
肯定文の対象の一部を除く時は「検証を除く変更を記録する」のように同じ文で限定し、別の制約は独立した文で示す（努力目標）。
程度、確度、拘束力を表す語は読み手の判断に加える意味を基準に残し、強い語は求める行動や拘束力を伝える範囲で使う。
「原則として」は一般的に使える表現で、硬い制約を弱めるなど実際に意味が変わる場合は文脈で判断する。

行為の主体、対象、動作、前提条件、結果を、文単体か前後の自然な文脈から読み取れる形で書く。
省略は補い方が一意に定まり、動詞の意味が読者と共有され、主語と述語が対応する場合に限る。
指示対象が曖昧な代名詞は対象の名前に戻し、同じ段落で一意に分かる指示語は残す。
語順は日本語として自然な形を選び、主語を常に文頭に置くことや受動態を全て除くことは求めない（努力目標）。
システムの挙動は動作を実行する主体を主語にして書き、擬人化と、判断した主体や根拠を曖昧にする推量の表現を避ける。

1文では1つの事柄を述べる。
主語や対象が違う別々の事柄は、読点や連用形（「〜し、」「〜して」）でつながずに文を分ける（努力目標。別々の事柄かは文の意味で決まり、機械の検査では判定できずレビューで回収する）。
並列する事柄は箇条書きにし、条件と結果、理由と結論、手段と目的のように1つの事柄を成り立たせる関係は1文のまま書いてよい。
文を分ける基準は事柄の数とし、文字数や読点の数は基準にしない。
文長や文末の統一などの数値の指標を満たすためだけの分割や言い換えは避け、条件と結果のつながり、時制、確度を保つ（努力目標）。

不自然な連用形の単独の名詞化は対象を特定した動詞の文か自然な名詞に直し、見直し、組み合わせ、資金集めのように定着した語は保つ。
技術用語を一字に縮めて対象が曖昧になる場合はその分野で通じる名称を使い、出版物の版、記号の印、身体の頭は本来の意味で使う。
具体的な操作や状態を思い描けない比喩と、漢語や名詞を続けて並べた表現は避け、助詞と動詞を補って文を組み立て直す。
表現の不自然さを指摘する時は、その文や句の内部で論理関係が成り立たない箇所を示し、他の記述や専門知識との不整合による事実誤認の指摘と区別する。
定着した専門用語、字義どおりの動作の表現、文脈から一意に復元できる省略、見出しや一覧、エージェント向け文書の体言止めは保つ（努力目標）。

機械の処理は実際の処理を表す動詞（取得する・読み取る・抽出する・成立する・許可される・追加するなど）で書き、人間や動物の動作を当てはめた比喩を書き換える。
システムの構造は、公開エンドポイント、起動コマンド、呼び出し元、接続先URLなど構成要素を特定できる名称で書き、場所にたとえた名詞をその名称に書き換える。
`依存`と`依存先`は作業項目の間の依存（`depends_on`など）とソフトウェアの依存関係に使い、一般の成立条件や通信の相手は前提条件や接続先として書く。
英語の定型句は単語ごとに直訳せず、「得られるものがない」「次のリクエストから拒否される」のように意味を直接書く。

事物の呼び名は、想定する読者がその分野で自分で書く時に使う標準的な名称にそろえる。
文が長くなっても、思いついた短い比喩や独自の言い換え（リクエストを`要求`、夜間バッチを`夜間の処理`とするなど）で済ませず、その分野で通じる名称を使う。
構成図の箱の中や表の列名など、記述の場所が狭い箇所ほど独自の置き換えが起きやすいため、同じ基準を当てはめる。
統計、数学、法律などの用語は、書こうとする意味がその分野の定義か辞書に載る一般語の語義のどれかと一致するかを確かめ、一致しない俗用は避けて指す内容を直接書く。
一般語として定着した語義での使用（「有意な設定項目」を「意味のある設定項目」の意味で書くなど）は正しい用法である。
例えば「母数」は母集団の特性値を指すため、分母、集計対象、基準額の意味では「分母」「集計対象」「基準額」と書く。
`届く`、`動く`、`入れる`、`受ける`のような多義の動詞は避け、何がどう変わるかを読者の分野の表現で書く（インフラ担当者向けの「社内VPNからしかアクセスできない」など）。

素材や作業メモの作業用の仮称（実験の条件名、Gitのブランチ名、集計で付けた分類名など）は外部の読者に伝わらないため、何を指すかを言葉で説明する。
独自の略称や記号を新しく作って読者に覚えさせる書き方（「以下「高」と呼ぶ」など）は避け、通常の言葉で書ける場合は言葉で書く。
略称を導入する時は名前から内容を連想できる語を選び（住所入力と決済入力を1画面にまとめた案を「1画面案」と呼ぶなど）、同じ文書の中で表記をそろえる。
