# 検索手段の選定と出力量の制御

ファイル属性と内容を検索する時の手段、範囲、出力量を扱う。
読み取り手段と検索手段が無い環境では、対象と検索条件を整理して返し、未取得の範囲の不在と件数は未確認として扱う。

| 時点または条件 | 全文読む資料 |
| --- | --- |
| 検索の結果から不在・件数・網羅を判断する前（母集団の確認） | `agent-basics:writing-standards/references/quality-principles-facts.md` |

## 手段の選定

- 属性（名前、種類、更新時刻、構造）は、対象パスを限った`find`を使う。
- 現在の作業ツリーの追跡対象は`git grep`を使う。
  `rg`は`--hidden`なしでは隠しディレクトリ配下の追跡ファイルを外す。
- 作業ツリー外の明示パス、Git管理外、除外設定に従う検索は`rg`を使う。
  隠しファイルを含める時は`--hidden`を付ける。
- 除外設定を反映した一覧は`rg --files`、件数の上限や集計が要る検索は`pyfltr grep`を使う。
- `rg`も`git grep`も無い環境では、`command grep`で対象を絞って出力をファイルへ保存し、必要な範囲だけ読む。
- 作業ツリー外の秘匿情報らしい値の検索は`agent-basics:secret-files`に従う。

## 引数とシェルの扱い

Claude CodeのBashでは、`grep`がugrepへ転送するシェル関数の場合がある（`type grep`で確認する。パイプの後段も同じ）。
ugrepは、ignore設定やバイナリ判定で除外されると無出力・終了コード1を返し、上限付き反復を2つ含む`-E`（例: `.{0,160}a.{0,160}`）では複雑度エラーで終了コード2・標準出力が空になる。
不在や件数の確定、有界反復の検索は、対照として`command grep`で確かめる。

- `git grep`は`-F`、`-E`、`-P`のいずれかを明示し、オプション、パターン、`--`、pathspecの順に並べる。
  `grep.patternType`などの設定に左右されず、メタ文字を含む文字列の誤った0件を避けるためである。
- `grep.lineNumber=true`の環境では`-h`でも行番号が出る。
  消すには`--no-line-number`を付ける。
- `-w`と`\b`は日本語を単語構成文字として扱い、日本語に隣接する英単語に一致しない。
  日本語の文書では境界をパターンで明示する。
- パイプラインは`pipefail`などで全段の終了コードを取る。
  `rg`は一致0件で1、パスの不在や引数の誤りで2を返す。
  `git grep`は一致するファイルが無いpathspecでも1を返すため、推測したパスは`git ls-files`か`rg --files`で実在を確かめる。

## 出力量と母集団

- 全体を検索する時は先に件数・ファイル名・要約（`-l`、`-c`、`pyfltr grep`の要約）を取り、候補数を見てから本文へ進む（努力目標。大量の本文はコンテキストを急に消費する）。
  source mapやminify済みの極端に長い行にも注意する。
- `-c`は一致行数であり、関数やクラスの数として使う前に、実体と行が1対1か構造で確かめる。
- 検索範囲は、リポジトリのルートから除外設定を保って検索する。
  ディレクトリやglobで限定するのは、対象がその範囲にしか無いと別の観測で確定している場合に限る。
  見込みで限定すると、テストコードなど範囲外の同じ値を未修正のまま残す。
- 意味で定まる集合は、定義元と利用側が値を取り出す方法（CLIの出力、説明用属性、辞書のキーなど）から母集団を定め、検索語ごとの件数を記録する。
  未調査の対象が残る間、一部の0件はその範囲の観測として扱う。
- 不在・件数・網羅性は、母集団全体を覆い省略されていない結果で結論する。
  `head`、`cut`、件数・行長・サイズの上限で切り詰められた結果は限定的な観測であり、省略のない形で再取得する。
  全量が大きい時は、コンテキストを分けた環境で取得して要約を受け取る。
  不在の主張は`agent-basics:writing-standards/references/investigation.md`「不在の主張」に従う。
