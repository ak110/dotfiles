## 識別子・言語仕様・運用契約の検証

- 2026年7月: 完了報告のコミットSHAが1文字誤っており、存在しないSHAへのCI通過待ちを約10分継続した。
  直接原因: 報告値を確認せず後続コマンドへ渡した。
  対策: 識別子は実行結果の値をそのまま使い、短縮形からの復元・記憶で組み立てない

- 2026年7月: Python 3.13/3.14で合法な構文（`except (A, B):`・PEP 758）を旧構文と誤判定した重大誤指摘が複数回発生。
  直接原因: レビュー担当が対象言語バージョンの仕様を確認せず学習知識だけを根拠に言い切った。
  対策: 言語バージョン確認とレビュー指摘採用前の一次資料での確認を義務化

- 2026年8月27日: review-sessionで、未完了作業へのユーザー介入を観測したにもかかわらず、メインが長時間待機後に既存規範・重複・過剰設計を先に評価し、「提案無し」で終了した。
  直接原因: 原因と既存対策の有効性を確定する前に抑止判定を行った。
  背景原因: 2026年8月27日の`75a3efa4`で原因分析の責務をadvisorからメインへ移した際、介入対応と被覆の完了条件を移さなかった（混入要因）。
  advisorを問題列挙に限定し、判断の重複と実行時間を減らすことを優先した（動機的要因）。
  「提案無し」テストがユーザー入力と証拠位置だけを確認し、4原因区分、三層処置、抑止判定の順序と根本原因単位の被覆を確認しなかった（見逃し原因）。
  判断責務の移管時に実害の是正を抑止判定より先に完了する不変条件を移さず、既存規範の存在を有効性の根拠へ反転できる状態を残した（根本原因）。
  対策: 原因分析・類似見直し・三層処置・根本原因単位の被覆を抑止判定より先に確定し、契約テストで4原因区分、三層処置、部分被覆、全被覆と最終報告の根拠を検証する。
  advisorの問題列挙専任契約は維持する

- 2026年8月28日: review-sessionのメインがadvisorの確認済みユーザー入力と問題locatorを構造検収するため、オプションを付けない、本文を含む証拠抽出を再実行し、イベント数の多いtranscriptで出力上限による欠落を発生させた。
  直接原因: 位置情報だけで成立する構造検収に、問題発見用の本文を含む、オプションを付けない出力を共用した。
  背景原因: advisorとメインの責務分離時に、同じ抽出結果を再利用すれば整合すると判断し、消費主体ごとの必要フィールドを分けなかった（混入要因）。
  新しい抽出機構と状態を増やさず、既存の出力とlocator契約を再利用することを優先した（動機的要因）。
  契約テストがイベント位置の安定性と被覆訂正を検証する一方、メイン検収の出力フィールドと問題locatorの出力予算を検証しなかった（見逃し原因）。
  問題発見用の本文と構造検収用の位置情報を同じ照会契約へ結合し、消費主体が必要としない本文を渡さない不変条件を設計・テストへ持たなかった（根本原因）。
  対策: オプションなしの抽出と同じ順序の位置情報だけを返す索引照会へメイン検収を切り替え、問題locatorからオプションなしの照会を除外し、出力フィールド・順序・照会回数・オプションなしの出力の後方互換性を契約テストで固定する

- 2026年8月29日: 複数の`planning`項目を1件の計画型AWIへ統合する手順について、既存の`convert-to-plan`が同じ状態遷移を実装済みであると判断し、文書同期だけの改善提案を作成した。
  実際の`convert_entries_to_plan`は`planning`の最古項目への統合を実装しておらず、対象WIが実装導入として示したcommitも文書だけの変更であった。
  直接原因: 公開コマンド名と複数入力対応だけを比較し、状態別の入力解決、保存結果と失敗復旧を実装本体から復元しなかった。
  背景原因: CLIの変更履歴をファイル差分で確認せず、関連項目に記録されたcommitを実装導入の根拠として採用した（混入要因）。
  既存CLIを利用する文書同期だけで変更を完了できるという前提を、状態遷移を実物で確かめるより先に固定した（動機的要因）。
  ファイル名モードが指示するCLI、対象状態と最終保存集合を同じ契約として検証するテストがなかった（見逃し原因）。
  公開CLIを実行手順へ採用する際に、コマンド名と引数に加えて、対象状態、成功後の保存集合、失敗境界と導入履歴を実装・テスト・commit差分と比べる変更境界を設けていなかった（根本原因）。
  対策: `convert-to-plan`へ`planning`統合を原子的に実装し、ファイル名モードのスキル、ガイド、設計と方針を単一コマンドへ同期し、対象文書が指示するコマンドと導入履歴を契約テストで検証した。
  `convert-to-plan`と計画型AWIは2026年9月13日に廃止した（`docs/development/removed-mechanisms-wi.md`）

- 2026年9月8日: 振り返りが、大幅な改善を求めたユーザー介入を成果の説明段落で是正と認めながら、候補別の判定記録の行へ対応させなかった。
  この介入への処置は要求単位の本文を書き換えるだけで終わった。
  直接原因: 完了条件の条件列が「該当する行が残る間は」と行を主語に置き、行が存在しない介入を判定の対象にできなかった。
  `処置`欄が成果物への修正と再発防止策を分けて要求していなかった。
  背景原因: 工程を簡素化して抽出専任の委譲を省いた処理回で、簡素化した手段とともに全件一覧と表の対応の検収も実施しなかった（混入要因）。
  対策: 表の確定前にlocator集合の一致を確認する規則を表の作成手順へ置き、完了条件の判定対象へ行の不在を含める。
  `処置`には成果物への修正と再発防止策を判別できる形で記録し、成果物を書き換えただけでは再発防止策に数えない

- 2026年9月8日: 振り返りの対象セッションを選ぶコマンドが更新時刻の最新の1件だけを条件としたため、対象リポジトリで稼働していた対話セッションを返し、振り返り担当が観測境界より後の増分を理由に停止した。
  直接原因: 選定側が更新時刻の新しさだけで対象を選び、消費側が対象の終了と起動方法の双方を前提としていたため、選定条件が消費側の成立条件を満たしていなかった。
  対策: 選定条件へ`agent-toolkit:atk-mode`の作業`process-wi`の起動標識と、対象の最終更新が自身のセッションの開始より前であることを加える。
  セッションを選ぶ条件は、そのセッションを消費する工程の成立条件と同じ変更単位でそろえる

## 要求と判断の脱落

- 2026年9月8日: 「抜本的に手順やスクリプトを見直して大幅な高速化を達成できるようにしてね」という改善効果の指定を受領した後も、局所の不具合の調査が先行し、現行構造を維持する案と変更する案の比較が行われなかった。
  直接原因: 改善効果を採用案の受入条件として先に確定し、個別調査を構造の維持案と変更案を比較する設計判断に結び付ける規定が無かった。
  対策: `agent-basics:review-standards`の`references/reviewee.md`へ改善効果を指定する要求の扱いを新設し、受入条件の確定と維持案・変更案の比較を個別調査より先に置く

- 2026年9月9日: 依頼した成果へ到達する前に部分結果を示し、続行の可否をユーザーへ質問して工程を停止する応答が繰り返された。
  直接原因: `agent-toolkit/rules/01-agent.md`「完遂と先送り」が`AskUserQuestion`の回答待ちと承認待ちを無条件の例外とし、例外を適用する際に質問が同ファイルの確認要件を満たすか判定させていなかった。
  対策: 「協調と自律」、「確認を要する事項」、適用中のスキルのいずれかが定める条件を満たす確認に限り、質問待ちと承認待ちを例外として扱う。
  依頼と成立済み承認の範囲の内側にある実行可能な未完了工程は、続行可否を確認へ変換せず同じターンで継続する

- 2026年9月21日: 確認、AWI投入、終了判定および検証通知で、既存の分類や状態値を先に適用した結果、ユーザーが示した要件と未回収の結果が工程から脱落した。
  直接原因: 発話原文と成果物種別の境界を分類より先に保持する契約、未回収結果を継続中とする共通判定、用途別の具体的な修復案が直接消費側へ届いていなかった。
  対策: 原文保持と優先順位判定をユーザー確認の前段へ置き、AWI専用境界を主題分類より先に適用する。
  未回収のagents_server結果をStop共通判定へ加える。
  外部パスのチェック、機械識別子の言語判定除外、切り詰め用途別の修復案は自動チェックで固定する

- 2026年11月15日〜17日: `atk wi process-loop`を、対象ごとの独立した会話、通常起動の非対話CLI、予約のない前回会話の再開へ変える変更が、ユーザー確認なしに実装・公開された。
  ユーザーの発話は「process-loopの処理がどうあるべきかを考え直した方がいい」「process-wiで重要なのは単位時間あたりのWI処理数」であり、会話の分割も端末表示の廃止も求めていなかった。
  直接原因: 統括がこの発話からAWIを起草する際に、全対象共通の統括会話を外す構成を設計比較の技術判断として確定した。
  計画担当は、そのAWIの対象別実行を実現する手段として非対話CLIを選び、端末で画面を見て入力できなくなる結果を既存の動作と比べず、人間由来の要求（再開は明示予約に限る）とエージェント由来の要求（未完了は元会話で再開する）の食い違いも検出しなかった。
  背景原因: 改善を広く任せる発話を、ユーザーが現在使っている起動形・表示・既定の動作を変える個々の判断の承認源として扱った（混入要因）。
  既存の「認可を要する操作」は、エージェントが起草するAWIへ補った外部から観測される結果には、起草・採否・計画のどの段でも適用されなかった。
  計画は「各WIの反映内容・完成条件を全件保持する」としてAWIの本文を要件として引き継ぎ、ユーザーの発話との差を比べる段が無かった。
  実行レビューの契約はWIの完成条件から作られ、ユーザーが使っている既存の動作の喪失を条件に含まなかった。
  会話の単位と前景の対話CLIは明文化されていない現状であり、方針記録との照合でも衝突として現れなかった（見逃し要因）。
  影響: dotfilesユーザーが進行を端末で確認・介入できなくなり、41時間続いた前回の会話が予約なしに再開され、ユーザーが4回の是正指示で元の動作へ戻させた。
  対策: 1つの統括会話を前景の対話CLIで起動し、再開を予約時に限る構成へ戻した。
  エージェントが補った結果のうち、エンドユーザーが自分で起動・操作するコマンドや画面の動作を大きく変えるものは保存前に確認し、軽微な利便性の向上と細部の変更はエージェントが確定して報告する。
  この扱いを`agent-toolkit/skills/atk-mode/references/origin-and-approval.md`「由来と`source`」へ加えた。
  守る動作を`docs/development/concepts-environment.md`「実行環境と表示」へ記録し、以後の変更が方針記録との照合で衝突として検出されるようにした

- 2026年11月20日: 自動連携を減らすための起草で、手動機能も無効にする案を採り、1つの起動方法を対象外にした。
  直接原因: 設定が作用する機能と条件を確かめる前に、名前の似た停止方法を選んだ。
  原要求を保つか確認する前に方式を確定し、利用者の設計への問いも仕様として扱った。
  対策: 残す機能と停止する機能を先に分け、各設定の使用版、作用する設定層、起動方法と観測した結果を採否へつなぐ。
  投入前レビューでは原要求に対する機能喪失と対象外を先に比べ、合成対照で意図の未確定・明示済みと、設計の問い・確定仕様を区別する
