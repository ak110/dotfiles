# 原因分析節と保存前の確認の設計記録

[設計記録の索引](design.md)と[WIキューと要求本文の設計記録](design-wi.md)から参照する主題別の記録である。

## AWIの原因分析節と保存前の確認

原因分析は観測した欠陥を起点とする通常AWIの`## 原因分析`節だけへ書く。
WI作成工程の規範が投入前に直接的原因と根本原因の確定を求め、計画工程の規範も同じ分析の記録を独立に求めていたため、同じ分析がAWIと計画ファイル（バグ）の双方へ書かれていた。
後工程が前工程の記録を参照で済ませる手段を持たないことが二重記述の機構であり、記録を前工程側へ1つだけ置き、後工程がそれを参照する手段を設ける。
計画ファイル（バグ）は、入力にWIが無い計画と、計画時にWIの原因分析を訂正または追加した計画の2条件でだけ作成する。
前者は原因分析を書く記録が他に無く、後者は計画時点の観測でWIの分析を改める記録先が要るためである。
分析の共通定義と記録の分担は`agent-toolkit:wi-standards/references/analysis-records.md`「原因分析の記録先」を参照する。
類似見直しと再発防止の範囲・採否・終了は2026年10月10日のユーザー指示により同スキルの`references/root-cause-analysis.md`へ集約し、拡張原因分析の条件に該当しない不良のAWIでも`類似見直し観点`と`再発防止策`の行を書く。
工程側が同じ表構造・分析方法を再定義せず、既存の保存前検収から共通定義へ接続する。
同じ内容を新しい節と既存の節の双方へ書かせると、AWIの中で再び二重記述が生じるためである。
`atk wi add`は`## 原因分析`の位置と非空を検証し、必須節の集合へは加えない。
起点が観測した欠陥かは本文から機械判定できないため、必須性は投入前の読み直しで確かめる。
エージェント環境から起動した`atk wi add`と`atk wi edit`（本文置換）は、本文の表の`直接的原因`行の値の冒頭に「未確定」「不明」「未特定」「調査中」「未確認」が単独で置かれるか、直後に句読点・空白・括弧・Markdown装飾の閉じ記号が続く場合に保存を拒否する。
対象はAWIとUWIの全てであり、種別と`source`の有無で分けない（2026年10月2日、ユーザーのコメント「全AWIでしょ。更にいうとUWIだって未確認事項残したまま書くべきではない」）。
原因を確定してから書く起草の条件は規範と投入担当の差し戻しで既に存在したが、委譲元の追送が差し戻しを上書きし、未確定の`直接的原因`行が保存された。
条件を守る主体を保存処理自身へ移すことで、どの委譲の流れから保存されても同じ結果を得る。
判定は保存前の確認（`agent-toolkit/agent_toolkit/_atk/wi/add_validation.py`の`require_confirmed_cause`）へ集約し、`atk wi edit`も同じ関数を呼ぶ。
既存本文が必須節を欠く旧書式でも、置換後の本文へは必ず適用する。
保証する範囲は、欄に明示された未確定の宣言の拒否に限る。
値の冒頭の語とその直後の区切りだけを判定し、確定した原因の説明に現れる同じ語（「不明だった設定を特定した」など）とコードフェンス内の例は拒否しない。
区切りを伴わない宣言（「未確定のため」など）は拒否の対象から外れるため、起草とレビューで確かめる。
原因として書かれた内容が正しいかは起草とレビューで確かめる。
人間の入力（エージェント環境外の`atk`と`atk serve`の画面）は拒否しない。
原因分析節や行の存在を必須にする案は、起点が観測した欠陥かを機械判定できない前段の理由により採らない。
計画構造の自動チェックは、作業種別`バグ対応`で`関連WI`を持つ計画には`計画ファイル（バグ）`行を求めず、`関連WI`が`なし`の計画には同行を求める。
却下した代替案は、作り込み要因・見逃し要因の分析を計画側へ寄せてAWIには直接的原因までを書く案と、二重記述を残す案である。
前者はWI作成工程が投入前に根本原因の確定を求める規定と両立せず、後者は起草と計画の手間とAWIの容量の二重化を残すため採らない（2026年9月30日のユーザー回答で「`AWIを正本に`」を選択）。
WI作成工程が投入前に根本原因の確定を求める規定は、`agent-toolkit:wi-standards/references/wi-standards-body.md`「起草完了の条件」にある。

## 規範の読込と共通準備の単位

WIの共通判定はdrafting-completion.mdが所有し、作成主体と確認主体が同じ定義を独立に適用する。
複数原稿の投入前レビューは要求識別子と原稿・出所・証拠の対応表で共通準備を再利用し、意味の判定と未解決事項は要求別に返す。
冒頭は改変せず抽出し検収者が先に単独で判定する。
ユーザーの分かりにくさの是正か判定不能の名詞句がある場合は独立した読者へ、抽出と比較資料だけをまとめて渡す。
合格済み要求は他要求の修正待ちと独立に保存する。

通常AWIは、全経路で登録可否と既存項目との被覆を本文で比較する。
手動具体化では今回の対象別結論を投入元で確定し、独立別件では確定事実、原因仮説、未確定事項と次の問いを残せる。
保存処理は通常AWIの未確定語だけで拒否せず、UWIおよび移行・復元の既存条件を維持する。
