# 事故・欠陥の記録

本書は`docs/development/incidents.md`から主題別に分割した記録であり、実行時に適用する規範の正本ではない。

## フック・セッション状態の不全

- 2026年9月9日: `agent-toolkit/scripts/hook.py`を`agent-toolkit/agent_toolkit/hook.py`へ移した変更を`develop`へマージした後、当該マージより前に開始した稼働中セッションの全ツール呼び出しがフックの起動失敗で拒否された。
  直接原因: 稼働中のセッションは起動時に読み込んだ`hooks.json`の旧パスを参照し続けるが、当該移動が旧パスへ互換入口を残さなかった。マーケットプレイスがdirectory型で作業ツリーを直接参照するため、`${CLAUDE_PLUGIN_ROOT}`は配布キャッシュではなく当該作業ツリーへ解決される。
  影響: 互換入口の作成も委譲による迂回もツール呼び出しを要するため自己回復できず、ユーザーがClaude Codeを再起動するまで復旧しなかった。
  対策: 稼働中セッションが起動時に解決する入口（`hooks.json`の`command`と`.mcp.json`のMCPサーバー起動対象）のリポジトリ相対パスを固定値として検査へ写し、当該パスを変える変更が検査の失敗として現れるようにする。入口を移動する計画は、`agent-toolkit:writing-standards`の`references/claude-hooks.md`が定める互換入口の残置を同一commitへ含める

- 2026年9月7日: 常駐ループのセッションで`agent-toolkit:exit-session`が未起動のままターンが終端し、ユーザーの指摘まで常駐ループが停止した。
  直接原因: Stopの自律終了ゲートが`stop_hook_active`の真だけを根拠に無条件approveへ遷移し、唯一の遮断機会を先行するターンで消費した。
  対策: Stopの共通入口へ連続blockの上限管理を置き、3つのfail-closedゲートから当該無条件approveを撤去する
- 2026年9月7日: PreToolUseが`--help`だけを連結したコマンドを状態変更コマンドの連結として遮断した。
  直接原因: 副作用の有無を前置トークン列の一致だけで判定し、当該呼び出しがヘルプ表示であるかを判定へ加えていなかった。
  対策: ヘルプ専用の呼び出しを判定する述語を共通化し、状態変更コマンドの判定から当該呼び出しを除く
- 2026年9月5日: 直前のアシスタント応答の記述言語検査が、英語だけの地の文を含むターンを判定せず警告を返さなかった。
  直接原因: 判定対象を直前のアシスタントターンだけに限定し、当該ターンが思考ブロックとツール呼び出しだけの場合に地の文を空として判定を省いた。
  対策: 判定対象をテキストブロックを持つ直近のアシスタントターンとし、テキストブロックを持たないターンを走査の対象から除いて遡る。
  同じ走査を使うユーザー向け本文と地の文の長さ比較は、`PreToolUse`の時点で当該ターンの地の文が記録へ未書き込みであり判定対象を取得できないため撤去する
- 2026年9月5日: Linux CLIで現在のCodex本体を一意に停止できる条件でも、`agent-toolkit:exit-session`の停止要求を送らなかった。
  直接原因: 停止後に`final`応答を返せないことを停止不能と誤認し、停止要求自体がCodexの正常な終端であることを適用しなかった。
  対策: `agent-toolkit/share/rules-main.codex.md`で停止コマンドのツール呼び出し自体を終端とし、停止後の応答不能を停止不能の根拠にしない。

  直接原因: 継続要求の応答futureを解決する主体がsession所有タスクの正常経路だけであり、保持期限の到達、message streamの例外、タスクの取り消しで所有タスクが終了する経路に未解決futureを解決する処理が無かった。
  背景原因: 同一実装のCodex側は接続終了時に未解決の要求を解決していたが、Claude側の継続要求キューは所有タスクが生存している間だけ要求が届く前提で設計され、契約テストも所有タスクの生存中と終了後の定常状態だけを固定していた。
  対策: 要求の受理と応答の解決を1つの継続要求チャネルへ集約し、所有タスクのいずれの終了経路でも受理済みの要求を解決する。所有タスクが終了したsessionへの継続送信は保持期限の経過と同じ再開経路へ回し、保持中の直前結果のうち`wait`又は`kill`で回収されていないものを`previous_result`として返す
