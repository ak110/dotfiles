# 会話IDによる識別と中断要求の設計記録

[設計記録の索引](design.md)と[継続処理の起動・隔離・制御の設計記録](design-process-loop.md)から参照する主題別の記録である。

## process-loopの会話IDによる識別

process-loopがClaude会話を新規に起動するときは`--session-id`で会話IDを指定し、同じIDを子環境へ渡す。
ID指定の再開では指定値を渡す。
hookは環境印とhook入力の`session_id`の一致から対象会話を決める。
入れ子の`claude`は環境印を継承する一方で会話IDが異なるため、常駐本体の終了保証と空転ガードの対象にならない。
IDを指定しない再開はホストCLI本来の会話選択画面を使い、目的文を検索語やIDとして渡さない。
既存のSessionStart起動入力にnonceと一時応答先を載せ、選択した実会話IDとcwdをhookから返す。
起動側はnonce・engine・対象を照合し、選択対象の所有とmanifestを確定してからACKする。
hookは所有側のPID世代と120秒の期限を確認し、ACKを得られなければ元のgoalを進めず失敗する。
ログの更新時刻から会話を推定する案は、会話を取り違える可能性があるため選ばない。
未知の手動会話の再開ではprocess-wiへ置き換えず、元のgoalを続行する。
選ばれなかった対象は暫定所有を解放して通常処理へ戻し、その会話の結果を転用しない。
親プロセスの探索はプロセス階層とOSを前提とする条件を増やし、hook入力に既にある会話IDより間接的な判定になるため採用しない。

## process-loopの中断要求

`atk wi process-loop abort`は中断要求をOSアカウントの状態ディレクトリにある`process-wi-abort`の存在で表す。
process-loopは反復境界と開始直前に要求を確認し、新しい対象の起動を止める。
実行中の会話は強制終了せず、すべての終了を観測してから常駐を終了する。
終了時は端末ベルを3回鳴らし、各鳴動を端末が区別できるよう短い間隔を置く。
中断要求は終了時に消費し、次回のprocess-loopを通常状態で開始する。

状態ファイルは`process-wi.log`の親ディレクトリへ配置する。
これにより、process-loopと操作コマンドは`XDG_STATE_HOME`を含む同じOSアカウントの状態の解決規則を共有し、対象リポジトリやprivate-notesの初期化を必要としない。
OSシグナルや稼働中プロセスへの直接通知は、process-loopが動いていない時点で要求を設定できず、解除と状態参照に使う永続状態も提供しないため採用しない。

## 再開予約と次回指示

`resume [ID|auto]`はOSアカウントの状態ディレクトリへ次の再開を保存する。
値省略はnative picker、`auto`は所有記録にある未完了会話であり、直近会話への無条件継続とは区別する。
予約・取消・実起動は同じ有限ロックで排他し、予約世代を照合してからPopenだけを保護する。
Popen成功で消費するため、準備・更新・起動失敗で予約が消えず、複数の常駐も同じ予約を二重起動しない。
対話端末やpickerの無いengineではIDかautoの指定を案内し、独自の選択UIを追加しない。
abortによる停止を予約より優先し、未消費の予約は保持する。

未達goalから本人が再起動する場合は、要求・認可・成果・残工程を保存して読戻し、配下writerの終了を観測してから、本人IDを予約して`atk agents-exit-session`を実行する。
本人IDと一致する保存済み予約がある場合、このコマンドは既存のPID世代照合後に単一PIDへ終了要求を送る。
旧modの`turn.complete`にある`/exit`へ委ねる方式は、未達goalのStop評価がその前に継続を要求するため使わない。
この再起動を通常完了として記録せず、予約と未完了成果を更新後の同一会話へ引き継ぐ。

`instruct`も同じ状態解決を使う。
対象workerが実CLIを起動する短い排他区間でmanifestへ指示を反映し、起動成功後に1回消費する。
更新・候補なし・起動失敗では指示を保持し、指示の追加・取消も同じロックを使う。
