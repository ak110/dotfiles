# WIの共通処理と一覧の限定条件の設計記録

[設計記録の索引](design.md)と[WIキューと要求本文の設計記録](design-wi.md)から参照する主題別の記録である。

## WIキューと実行準備

### 共通処理の構成と一覧の限定条件

WIの共通処理は`agent-toolkit/agent_toolkit/_atk/wi/`配下の責務ごとのモジュールへ分ける。
WI保存リポジトリの準備・remote同期・排他ロック・commitとpushは`sync.py`、エントリの走査・種別の判定・処理結果の追記は`entries.py`、ファイル名の検証・採番・補完候補は`filenames.py`が持つ。
CLIの位置引数と本文の入力は`cli_input.py`、CLIとWeb APIが共有する入力エラーは`web_input.py`が持つ。
他のモジュールが使う名前は公開名とし、`_`で始まる名前を定義したモジュールの外からimportしない。
以前の`common.py`はこれらを1つのファイルに同居させ、`git_sync`へ委譲するだけの非公開の関数の上に公開の関数を重ねていた。
他のモジュールは非公開名を直接importし、テストは同じ名前を束縛した複数のモジュールを個別に差し替えていた。
二重の名前は1つの公開名へまとめ、呼び出し側は定義元のモジュールの属性として呼ぶ。
テストは定義元のモジュール1か所を差し替える。

排他ロック（`git_sync.repo_lock`）は、保持と待機の両方に時間上限を持つ。
保持している区間のgit操作は合計120秒で打ち切り、待機は省略時に150秒で終える。
待機の上限は保持区間の上限より長くする。
正常に動いている保持者は待機の間に解放し、上限に達した待機は保持者の停止を意味するためである。
値を変えるときはこの大小関係を保つ。
ロックを取得した主体は、ロックファイルと同じディレクトリの`<ロックファイル名>.holder`へPID・起動時刻・コマンドラインを書き、解放の直前に消す。
待機が上限に達したCLIは、この記録から保持者を失敗行に示す。
エージェントは待機中の表示を受け取れないため、上限での終了と保持者の表示で原因を知る。
以前は待機が無期限で、保持中のgit操作にも上限が無かった。
応答しないリモートへの`git fetch`がロックを保持し続け、`atk wi add`が30分以上進まなかった（2026年11月10日）。
gitの操作ごとの既定の上限と区分は`agent-toolkit/agent_toolkit/_git/command.py`のモジュールdocstringが定める。
SSHの`ConnectTimeout`を渡す案は、接続を確立した後の応答停止とHTTPSの通信を覆えないため採らない。
時間上限の無い外部コマンドの起動を検出するチェックを置く案は、常駐サーバーや対話型のエディターなど意図して無期限とする起動の例外を保守する費用が上回るため採らない。

`ensure_environment`は旧状態別配置と旧々配置を検証し、年月固定配置へ移行する。
`pull`による旧予約形式の移行も、同じ起動時の準備として維持する。

一覧を限定する条件（状態、回答状況、`source`、`target_repo`）の判定は`filters.py`の1つの実装を`atk wi list`・`grep`・`show`・一括遷移とWI画面の一覧が使う。
以前はCLIと画面が別々に実装し、`source`の否定指定と、識別子へ正規化できない`target_repo`の扱いが分かれていた。
正規化できない`target_repo`の指定値は保存値と原値のまま比べる。
WI画面が示す`target_repo`の選択肢には、正規化できない保存値が原値のまま入るためである。
CLIは`--target-repo`の値を識別子へ解決してから渡すため、この規則へそろえてもCLIの結果は変わらない。
画面だけが持つ条件（検索語、期間、`plan`、種別の由来、`source`の空）は画面側に残す。
両者の一致は`_atk/serve/wi_listing_parity_test.py`が同じprivate-notesに対する項目集合の比較で確かめる。
CLIの判定を画面へ複製して両方を保つ案は、片方だけを直すと結果が分かれる状態を残すため採らない。
