# 障害・欠陥の記録: WI投入とAWI起草の欠陥（2026年9月13日〜2026年10月5日）

[WI投入とAWI起草の欠陥](incidents-wi-drafting.md#wi投入とawi起草の欠陥)の事例を発生時期別に収録する。

- 2026年9月13日: process-wiがClaude CLIの`--worktree`を渡す方式を自前worktreeとcwd指定へ変更し、別の変更がMermaidを常時最新版から版数固定とSRIへ変更したが、いずれもユーザーへ事後承認型UWIを投入しなかった。
  直接原因: 対話で確定した設計判断を後続主体が読む成果物へ残す手段がなく、エージェント由来のエンドユーザーが観測できる変更を判定したレーン担当から、UWIを投入できるメインへ対象、理由およびトレードオフを渡す契約も無かった。
  対策: 将来の合理的な代替案を制約するユーザー合意を計画固有でも恒久成果物へ残す。
  計画の実施内容に事後承認対象を標識し、レビュー収束後にメインが事後承認型UWIを投入してから統合する送受信契約とテストを追加する。
  Mermaidの現行版数固定はユーザー指示に従って変更しない

- 2026年9月20日: 次回の処理を求めてWIを投入したユーザーに対し、投入元セッションの固定集合へ加えるかを判定する規定が、即時対応も求めているように読まれた。
  直接原因: キューへの保存と現在の依頼の完遂を同じ固定集合の更新として扱い、WIの取得時機を明文化していなかった。
  背景原因: （作り込み・流出要因）完遂規定へWI固有の取得契約を置き、キューの正式な基準である`agent-toolkit:wi-standards`との意味の確認を欠いた。
  対策: WIは次回以降の`agent-toolkit:process-wi`が取得する要求と定め、投入元セッションの固定集合を変えない。
  即時の是正と後続の独立した作業要求の投入を別の操作として扱う

- 2026年9月20日: `wait-ci`の文字コードをUTF-8へ固定する技術的な対応を、実施後にユーザーへ承認を求めるUWIとして投入した。
  直接原因: 指定手段と異なる内部実装を一律に事後承認の対象とし、技術的に一意な判断とユーザーの選好で決まる判断を分けていなかった。
  背景原因: （作り込み・流出要因）手段変更の規定が確認要否の2段階判定より広く、UWI投入前にユーザーの判断が必要かを再度確認する工程が無かった。
  対策: 目的、範囲、制約、権限、安全性および要求された外部可視の結果を変えない技術的に一意な内部実装は、自律的に選んで事後承認型UWIから除外する

- 2026年9月20日: UWIの回答でエージェントの判断が否定された際、その是正要求をAWIのユーザーコメントと同じ類似見直しおよび再発防止の手順へ送る規定が無かった。
  直接原因: 是正要求の受領契機をAWIの`## ユーザーコメント`だけへ限定し、同じ意味を持つUWIの`## 回答`を列挙しなかった。
  背景原因: （作り込み・流出要因）回答済みUWIを作業要求へ変える状態遷移は定めたが、その内容をユーザー指摘として評価する工程との接続を確認しなかった。
  対策: AWIのユーザーコメントとUWIの回答に共通する是正要求の手順を`agent-toolkit:wi-standards`へ置き、内容確認、採否、原因分析の要否判定、類似見直しから再発防止策の確定までを適用する。
  AWIの適用範囲が反映対象を超えた場合は、対象の包含または除外の判断と根拠を投入と同じターンで報告する

- 2026年10月5日: 別リポジトリのログ監視のAWIを起草したWI投入担当が、CIの配備用SSH鍵の接続可否と既存のサービスプリンシパルの照会権限を「確かめていない範囲（完成条件の判定を変えない）」として証拠へ残し、「取得失敗として記録・報告される設計にした」ことを理由に挙げた。
  委譲元は`add-wi.parent.md`「受領と検収」でこれを受理した。
  ユーザーの是正後に同じ作業マシンから確かめると、照会は成功し、SSH鍵は8ホストで拒否された。
  どちらも起草者の環境で確かめる手段があった。
  直接原因: `awi-body.md`の条文は確認していない範囲を「判定が変わらない」ことだけで許し、起草者が失敗を記録する設計を加えれば満たせた。
  確かめる手段の有無を条件とする`drafting-completion.md`の条文を参照せず、「受領と検収」も確かめていない範囲を確かめられるかを判定しなかった。
  対策: `awi-body.md`の条件を自環境の手段で確かめられない事項に限り、失敗を記録する設計を根拠にしないと定めた。
  `add-wi.parent.md`「受領と検収」へ、確かめていない範囲ごとに確かめる手段の有無を判定し、手段がある範囲を担当へ戻すか委譲元が確かめて渡す項を加えた
