# 記録の解決と集合照会の設計記録

[設計記録の索引](design.md)と[振り返り・知見集約の設計記録](design-session-review.md)から参照する主題別の記録である。

Claude Codeは現在のtranscript絶対パスを`atk run-script session-review-prepare`へ渡す。
Codexはメインの`CODEX_THREAD_ID`を渡す。
`atk run-script session-review-prepare`はthread IDを`atk run-script session-review-evidence`へ渡し、対応するrolloutの解決を委ねる。
保存先の解決順と完全suffix一致による一意性の検証は`atk run-script session-review-evidence`が単独で持ち、呼び出し側は検索式を組み立てない。
親transcriptと委譲先記録で解決規則を別々に実装する案は、環境変数が未設定の場合に使う保存先と一意性の検証が二重に必要となり、片方だけが欠ける状態を生むため採用しない。
UserPromptSubmitの追加コンテキスト、振り返り境界、開始マーカーおよび起動済み状態は用いない。

委譲先の記録の所在は`atk run-script session-review-evidence`が解決する。
同コマンドはメインの記録から、サブエージェント記録のディレクトリと委譲先セッションの識別子を導出し、導出した記録に対しても同じ導出を繰り返すことで、入れ子の委譲先まで到達する。
全ての照会モードは1回の実行で全記録へ適用する。
メインが委譲先の記録の絶対パスを組み立てて渡す案は、記録の所在が実行系ごとに分かれるうえ、委譲先が増えるほどメインの手順と起動回数が伸びるため採用しない。
`atk run-script session-review-evidence`が所在を確定できなかった記録を`unresolved-record`として報告し、委譲の起動を検出しながら結果から識別子を取得できなかった呼び出しを`unresolved-delegation`として報告する。
振り返りの統計と候補は、双方を未確認範囲として示す。
結果の解釈に失敗した呼び出しを報告せずに破棄する形は、検出できなかった委譲先を存在しないものとして扱うため採用しない。

`atk run-script session-review-evidence`は通常表示と警告、集計、hook通知の走査を1回の記録読み込みでまとめて行う集約実行を持つ。
集約実行は走査ごとの全量に加えて`candidate-evidence.jsonl`を指定ディレクトリへ書き、標準出力へは走査ごとの要約だけを返す。
同ファイルは候補IDと分析グループのヒント、全locator、各位置の有界な本文を持つ。
`atk run-script session-review-prepare`は候補の要約と代表位置を`candidates.md`へ載せ、必要なツール呼び出しの全入力へ保存索引から接続する。
シェルの構文情報は同じ準備内で有界に再利用し、記録位置・用途別の判断や出現回数は呼び出しごとに保持する。
bundleの生成から効果確認の観測まで同じ寿命とし、別の準備や単独照会へ入力を持ち越さない。
永続キャッシュは鮮度管理と保存費用を増やすため採らず、構文情報を変更可能なリストとして共有する案も消費側どうしの干渉を生むため採らない。
`--detail`、`--grep`と候補別証拠の各イベントは元記録行の時刻を持ち、区間境界の時刻を記録の直接読取なしで確定できる。
走査ごとに実行を分ける形と、全量ファイルを常に読む形は採用しない。
処理する行数とバイト数、判断回数が候補数へ比例するためである。

親セッションの比較用カタログは、`atk run-script session-review-evidence`の次の指定で行と表示項目を選べる。

| 指定 | 値の形式 | 選択 |
| --- | --- | --- |
| `--catalog-workflow NAME` | workflow名 | workflowが完全一致する親行 |
| `--catalog-known-workflow` | 値なし | workflowが`unknown`でない親行 |
| `--catalog-cwd-contains TEXT` | 文字列 | cwdがその文字列を部分文字列として含む親行 |
| `--catalog-fields FIELD,FIELD` | ASCIIカンマ区切りの項目名 | 指定順の表示項目。`kind`は常に先頭に残し、省略時は全項目 |

行条件を併記した場合は全ての条件を満たす行（積集合）を返す。
未知・空・重複の項目名を含む指定と、カタログの走査以外や`--tool-calls`と併用した指定は、次の操作を示す診断で拒否する。
選択は`session_evidence_catalog.py`の生成済みの親行へ適用し、ClaudeとCodexで同じ並びと項目の指定順を使う。
本文検索の親条件は親本文のworkflow・cwdだけで判定し、一覧が表示するトークン量や成功WI操作の統計を構築しない。
検索の家族収集で解決したroot外の記録は、初段の所在探索で未解決だった集合と比較して最終診断から除く。
全走査rootと選択照会の未確認範囲を分け、時刻不明の一致行数、読込失敗の理由と失敗行を保持する。
全履歴の永続索引や本文の一括保持は加えず、家族単位で本文を解放する。
走査した親セッションの記録数と選択した行数は要約の別の項目にし、選択0件を走査全体の不在へ置き換えない。
呼出し側に選択のスクリプトを持たせる案は、比較表示の組み立てと保守を各呼出し元へ分散させるため採らない。
指定を省いた全項目の表示と、走査root・期間・未解決記録数の要約は維持する。

`atk run-script session-review-evidence`の`--tool-calls`はツール呼び出しを単位として選び、呼び出しごとに列挙し、委譲先を含む記録と複数セッションにまたがって数える照会modeである。
2026年10月6日にはあるセッションのメインと、同じ日に起動されたWI投入担当2件が、ツール呼び出しの時系列の列挙と計数のために記録のJSONLを読むスクリプトを計18本その場で書いた。
そのうち正規表現で`--since`の値を取り出す集計は、スクリプトを編集するコマンドの本文まで97件中19件抽出していた。
既存の照会では、`--grep`が行単位の一致と2000字の切り詰めと自己呼び出しの除外を持ち、`--stats`が上位件数だけを返し、カタログ走査が照会modeと併用できないため、呼び出し単位の選択も複数セッションの計数も得られなかった。
`--input-regex`は代表入力の全体へ`re.search`を適用し、`^`で始まる式でヒアドキュメントへ埋め込まれた同じ文字列を除けるようにする。
本スクリプト自身の呼び出しは、その呼び出し回数を数える調査を成立させるため含める。
カタログ走査と併用する場合は、窓の中の親セッションごとに単一transcriptと同じ手段で委譲先を集める。
カタログが組み立てる子孫は走査rootの中に限られ、走査rootの外（別のプロジェクトディレクトリ）の委譲先が未解決になるためである（同日の観測で29件の親セッションに120件の未解決記録）。
記録ごとのツール呼び出しの抽出（記録行、時刻、ツール名、呼び出し識別子、代表入力、結果の記録行）は1つの関数が持ち、会話の流れと`adhoc-processing`候補と共有する。
`--grep`へ欄の限定を加える案は、行単位の一致と切り詰めを前提とする振り返りの既存の照会の意味を変えるため採らない。
別のスクリプトを新設する案は、2つの実行系の記録形式の解釈と委譲先の解決を二重に持つことになるため採らない。
`--bundle`の`conversation.jsonl`を案内するだけの案は、メイン記録だけを対象とし、代表入力を1000字で切り詰め、選択条件と複数セッションへの適用を持たないため採らない。

委譲先の識別子は実行系をまたいで一意であるため、記録の所在は識別子だけで確定し、呼び出しに現れる実行系の指定は探索に使わない。
探索先はClaude Code・Codex・Antigravityの3系統とし、探索処理は`atk agents logs`と共有して`agents_server`の実行系集合と一致するかをテストで確かめる。
`atk run-script session-review-evidence`が探索を独自に持つ形は、実行系の追加時に`atk run-script session-review-evidence`だけが古い探索先のまま残り、その実行系の委譲先を未確認範囲にし続けたため採用しない。
共有の探索処理は同じ実行系で一致した全ての記録を返し、複数一致の扱いは呼び出し側が決める。
`atk agents logs`は先頭を表示し、`atk run-script session-review-evidence`はCodexの複数一致を未解決として扱う。
別の委譲先の記録を候補へ混入させないためである。
実行系と識別子の組を必須キーとする案は、実行系の指定を伴わない継続・停止の呼び出しで所在を確定できず、解決済みの記録を未確認範囲として重複報告するため採用しない。
Codexの記録では委譲の呼び出しが、JavaScript本文を評価してツールを呼び出すexecツールの入力へ埋め込まれるため、識別子の抽出母集団を委譲の呼び出しに対応する実行結果へ限定し、無関係な実行結果に現れる同形の構造化データを委譲先として採用しない。
