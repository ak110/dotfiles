# 遮断・警告フックの存廃判定の設計記録

[設計記録の索引](design.md)から参照する、遮断・警告フックの存廃判定の記録である。

## 遮断・警告フックの存廃判定と一覧

hookによるチェックを置くかは、QCDでhookの費用と防ぐ手戻りの便益を比べて決める（2026年10月2日、ユーザー指示）。
誤検出、発火ごとのトークンと実行時間、保守費用が便益に見合わないチェックは置かず、明らかなエージェントの行動誤りを入力から機械的に判定でき費用が小さいチェックは、元へ戻せる誤りを防ぐものでも置く。
不可逆な操作の防止、データ破損の防止、常駐運用の終了保証は、1回の発火でも結果が残るため置く理由になる。
規範の配送と権限の自動許可も、発火・重複・受信量・再取得と保守の費用を比較する。
現行の規定は`.claude/skills/agent-toolkit-edit/references/claude-hooks-block-warn.md`「遮断・警告フックの成立条件」にある。

操作の後に対象の公開仕様が定める手段で元の状態へ戻せないことを不可逆と呼ぶ。
操作の種類の名前や過去の分類表の語に頼らず、その手段の有無を公開仕様で確かめて判定する。
例えば、Gitの履歴書換えは`git reflog`と`git reset`で元のcommitへ戻せるため可逆である。
パッケージの削除は、設定ファイルを残す`remove`と残さない`purge`で結果が分かれる。

2026年10月23日の見直しでは、`hooks/hooks.json`・`hooks/hooks.codex.json`と`hooks/register.ts`から到達する生成元を、具体的な実害の保護、回復可能な支援、意味判断、規範配送に分けた。
下表は現在の判断を示す。
過去の「明らかな行動誤り・低費用」だけをblockの根拠へ流用しない。

パスは`agent-toolkit/agent_toolkit/_hooks/`起点とし、TSは`agent-toolkit/hooks/`起点とする。

| 生成元 | 分類と出力 | 残す目的と境界 |
| --- | --- | --- |
| `pretooluse/agent_checks.py` TaskStop・継続対象 | 実害保護、block | 起動と所有を確かめられない対象の停止・追送を防ぐ。対象IDと記録を照合する |
| `pretooluse/agent_checks.py` 組み込みの汎用Agent定義の起動 | 明らかな行動誤りの是正、block（同じ入力の再発行は通す） | 工程別設定と終了観測の外で委譲が行われることを防ぐ。軽量起動の委譲先、`fork`、専用定義は対象外とする。経緯は「委譲手段の選択と待機の装着の手掛かり」にある |
| `pretooluse/shell_checks.py` heredoc置換・pattern kill | 実害保護、block | 文書の文字列が意図しないコマンドとして実行されることと、所有外プロセスの終了を防ぐ |
| 同 Git commitの形式・帰属 | 公開契約の保護、block | 通常commitへ確定した`Co-Authored-By:`と公開メッセージの契約を保つ |
| 同 終端後option・atk出力接続・読取述語stderr・rev-parse | 回復可能な支援、warn | 失敗や結果誤認の原因と正しい入力を一度示す。実害保護へ一般化しない |
| 同 WindowsのPATH | 回復可能な支援、warn | Windows上のClaude CodeのBashに限り、ドライブ文字の分断を案内する |
| `pretooluse/task_document_launch.py` | 入力契約の保護と起動支援 | 定型起動の必須入力の欠落はblock。自由本文の起動形式と宣言外の説明はwarn。コンテキストへの取込みだけを実害としない |
| `pretooluse/content_checks.py` | 回復可能な支援、warn | 文字化け、ツール境界タグ、PowerShellの改行、lockfile・manifestを対象とし、再編集・再生成を案内する |
| `pretooluse/large_reads.py` | 回復可能な支援、warn | 原記録参照の専用照会と大量読取の予算確認を案内する。予算内の標準読取を通し、超過・省略時は分割取得へ接続する |
| `pretooluse/dispatch.py` 背景出力・帰属行 | 関連操作の支援・配送 | 途中出力の取扱いと、資料読取時点（Claude Codeではcommitスキルの起動完了時点にPostToolUseから）に観測した帰属行を共通noticeで通知する |
| `pretooluse/read_delivery.py` | 関連操作に必要な資料の初回warn | 通常読取・診断・結果回収・質問・既存復旧を保つ。現在の資料を案内し、取得証拠と案内の実配送を分ける。未取得を理由に再書込を遮断しない |
| `posttooluse.py` | 観測・配送・出力の変換 | 所有・取得証拠を記録し、計画構造、回答UWI、完了処理の関連案内を共通noticeへ集約する。退避出力の置換は結果取得先を保つ |
| `user_prompt_submit.py` | 状態観測・関連規範の配送 | 実ユーザー入力と機械生成を区別する。意味の判定は受領側が文書に従って行う |
| `rules_context.py`・`rules_context_codex.py` | 起動時の規範配送 | ホストと主体ごとの役割・一時領域・原記録の所在を届ける。開始・圧縮という受領境界に対応する |
| `response_language_advisor.py` | ユーザー向け本文の言語保護、block | 内部返却とClaude Codeの非同期処理を待つStopを除き、作業を終える最上位メインの本文を判定する。Codexの完了本文の保護と、誤検出時に成果・判断・未達を保って終了する手段を維持する |
| `busy_loop_guard.py`・`autonomous_exit.py` | 常駐運用の終了保証、halt・block | 対象の常駐セッションだけで機械的な無進捗と終了操作の有無を扱う。正当な非同期待機を除く |
| `plan_save_advisor.py` | 回復可能な支援、notify | 所有する現存計画を知らせ、保存契機の判断は受領側へ残す。同じ対象を抑止し、対象変化と解消後の再発を通知する |
| `agents_server_session_advisor.py` | 観測支援、notify | 呼出主体の未観測対象だけを知らせ、正常な待機と観測済みの対象を除く |
| `user_response_advisor.py` | 可視本文の欠落支援、notify | 人間入力ごとに本文の有無を調べる。回答の内容は判定せず、同じ不足の反復を共通noticeで抑止する |
| `termination_order_advisor.py` | 起動証拠の不足支援、notify | Claude Codeだけで成果作業の起動不足を通知する。起動済み作業の送達・残工程と報告の固定句は判定しない |
| `queued_notification_advisor.py` | 既存結果の配送、yield・notify | 他のblockが無ければホスト配送へ戻す。blockが残る場合だけ未配送対象の受領を一度案内する |
| 旧`pending_question_advisor.py` | 意味判断、文書へ移管して撤去 | 疑問符・定型表現から質問の意味を推測する終了判定を撤去した。確認の要否と手段は`user-confirmation-and-report`が定める |
| `subagent_stop_advisor.py` | 返却契約の保護、block | 空の返却で委譲元が成果を失うことを防ぐ。内部返却の言語は判定しない |
| `permissionrequest.py` | 権限応答 | Claude Codeの設定済みの自動許可を返す。新たな遮断・反復通知を持たない |
| `session_end_cleanup.py`・`session_activity.py`・`stopfailure_notifier.py` | 記録と回収 | 状態の寿命、活動、API失敗を記録する。StopFailureは出力で遮断・通知できず、利用上限の再開予約だけを既存modへ渡す |
| TS `register.ts`・`send_to_user.tsx` | 公開範囲・入力・言語の保護 | 自moduleのメイン専用toolと文字列入力を守り、言語checker障害は許可して一度通知する |
| TS `response_language.ts` | 言語例外、deny・支援通知 | 言語違反を差し戻し、checker利用不能は継続する。同じ障害の再送を抑止する |
| TS `compact_conversation.ts` | 圧縮実行・関連支援 | 自moduleのtool、現在のusageと待機状態を扱う。同じ未完了対象への案内を抑止する |
| TS `session_exit.ts`・`periodic_recheck.ts` | 終了とcronの装着・回収 | `changedWarning`を共有し、同じ失敗を抑止する。正常化後の再発は通知し、未点検を正常化と扱わない |
| TS `usage_limit_resume.ts` | 利用上限の解除後の再開 | 所有する予約を世代で置換し、新turnが始まれば再開を重ねない。上限が継続する間はタイマーだけを更新する |

共通noticeは原因・対象・次の操作を同じ主体と操作範囲に結び付ける。
内容の変化、条件の解消後の再発、別主体を区別し、回数だけの通知とblock昇格を生成しない。
空になった通知はイベントの集約側で配送から除く。
TSの反復抑止は既存modの寿命に合わせたMapを使う。
新しい監視とLLM判定は追加しない。

UserPromptSubmitの180秒ごとの固定手順の再配送は撤去した。
新しい発話の意味を判断する必要性と、同じ一般手順の再注入が必要なことは別であり、定期再注入の追加便益を示す観測を欠いたためである。
一般手順は`user-confirmation-and-report`の既存規範へ保持し、起動・圧縮後の最初の実入力へ一度だけ起動を案内する。
既存のpending状態を両ホストで消費し、不要になった時刻・閾値と通知本文を揺らす分岐は持たない。

### 事前に防ぐ型と遮断後に対処する型

blockとwarnは、実行主体が操作の前に条件を満たす事前に防ぐ型と、hookが判定を担い通知が解消手段を示す遮断後に対処する型に分け、費用の小さい型を選ぶ。
規定の本文は`.claude/skills/agent-toolkit-edit/references/claude-hooks-block-warn.md`にある。
事前に防ぐ型の費用は、対象の操作のたびに規範が求める事前工程の呼び出しの合計である。
遮断後に対処する型の費用は、実際の遮断回数に、遮断された呼び出しと通知に従った取得の分を掛けた量である。
CodexのBash全文取得は、閾値が出力上限から導かれていなかった間、SKILL.mdなどを読む前に`wc -l`・`wc -c`で行数と容量を測る事前工程を操作のたびに生んでいた。
事前計測の呼び出しは失敗しないため振り返りの候補にも現れず、費用が観測されなかった。
閾値を出力上限から導いた48KiBへ上げると、agent-toolkitの規範Markdownはすべて閾値以下に収まり、遮断は実際に上限を超え得るファイルだけで発火する。
このため同hookを遮断後に対処する型とし、規範から事前計測を撤去した（2026年9月29日、ユーザー指示）。
規範Markdownが閾値を超えないことは`agent-toolkit/markdown_size_invariant_test.py`の容量のテストが保つ。
全文取得の共有解析は、cat・less・moreの既知の本文表示オプションとその値、終端をファイル引数から区別し、配送と容量判定の双方へ同じ対象を渡す。
help・version・未知のオプションから全文取得を推測せず、sed・awkの分類とパイプ・リダイレクトの境界は既存の解析へ保つ。

却下した代替案は次の2つである。

- 事前計測の規範を残して閾値だけ上げる案: 閾値以下のファイルでも読む前の計測の呼び出しが残り、事前工程の費用が減らない
- hookがCodexの設定を読み、閾値を動的に決める案: 設定の所在と優先順位の解決をhookへ持ち込み、出力上限の変更は配布設定の改訂と同じ機会の閾値の見直しで扱えるため、恒常的な複雑性に見合わない

取り消しの難しい操作やデータ破損を防ぐhook（`pkill`・`killall`の遮断など）は、1回の発火でも結果が残るため事前に防ぐ型で扱う。

### 全件確認の経緯（2026年9月26日）

2026年9月26日の見直しは、当時のユーザー指示による基準「通した場合に元へ戻せない結果を防ぐものだけを残す」で行った。
規範の想起、CLI形式の事前検出または文体の検出を目的とするチェックは、可逆な失敗を防ぐに留まるとしてhookから外した。
hookの静的な解析はシェル構文、作業ディレクトリの遷移、ホストの通知挙動を完全には再現できず、判定条件を広く取ったチェックは正当な操作を遮断・警告し、個別の是正を積み重ねる構造になる。
この観測は現行の基準でも増やしすぎを防ぐ費用として扱う。
2026年10月2日に基準をQCDの費用比較へ改めた際、旧基準を根拠に撤去・不採用とした判断と、表に行の無かった存続中のチェックを再評価し、区分に「2026年10月2日再評価」と付けた5行として表へ加えた。
秘匿ファイルの読取と編集はauto mode classifierと権限設定が担う（2026年9月26日、ユーザー指示）。

2026年9月25日の一覧表は、実行時の入力を測れるという事実を存続の理由とし、Git履歴のチェックを復元手段を確かめずに「取り消し難」と分類していた。

2026年9月26日の見直しで、同25日の一覧表79行のうち55行のチェックを撤去した。
表に載っていなかったPreToolUseの7件のチェックも撤去した。
対象はCo-Authored-Byの遮断、`git log`への`--decorate`の自動付与、前景ループ待機、`codex exec`の念押し、WebFetchの逐語要求、汎用Agentの選択およびSendMessageの宛先である。
dotfiles個人用hookの7件のチェックのうち5件も撤去した。
個人用hookに残るのは、PowerShellの必須ディレクティブ欠落と配布物へのdotfiles固有名混入の警告である。

2026年10月1日、3日、5日および6日の各節が維持するとした「規範の想起を目的とするチェックをhookに置かない」方針は、この旧基準（元へ戻せない結果を防ぐものだけを残す）から導かれた。
旧基準は2026年10月2日のユーザー指示で現行の費用比較へ改められた。
以後の採否は`agent-basics:writing-standards`の`agent-basics:writing-standards/references/claude-hooks-block-warn-eligibility.md`「遮断・警告フックの成立条件」で判定する。
