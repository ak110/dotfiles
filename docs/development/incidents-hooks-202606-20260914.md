# 障害・欠陥の記録: フックとセッション状態の不全（2026年6月〜2026年9月14日）

[フックとセッション状態の不全](incidents-hooks.md#フックとセッション状態の不全)の事例を発生時期別に収録する。

- 2026年6月: Windowsでフックのパス判定が常に偽となり、編集が恒常ブロックされた
  （ユーザーはセッション状態の直接書き換えで回避した）。
  直接原因: バックスラッシュ区切りパスの未正規化。
  対策: フック2スクリプトのパス区切り正規化

- 2026年7〜8月: 状態フラグが立たず正当な工程が誤ブロックされる事象が複数セッションで再発した。
  直接原因: 完了報告の書式や配送手段の揺れを、フラグ記録側の抽出仕様が許容していなかった。
  対策: 抽出仕様の許容拡大・SubagentStop経由の真化手順追加・ブロック文言の是正

- 2026年8月30日: フック定義が参照する共通起動スクリプトの改名が作業ツリーへ統合された時点で、
  稼働中のメイン1セッションと委譲先6セッションの全ツール呼び出しが拒否された。
  直接原因: hook定義はセッション起動時に読み込まれ、`command`のスクリプトを起動時点のパスで参照し続けるため、
  旧パスの実体が消えるとフック実行が起動前に失敗した。
  対策: フック定義が参照するスクリプトの改名・移動・削除では旧パスへ委譲専用の互換スクリプトを残す。
  撤去は新しいスクリプトを含む版の配布後の版数更新以降であり、かつ旧定義を読み込んだセッションの終了を確認できた場合だけとする。
  再発（2026年9月9日）: `agent-toolkit/scripts/hook.py`を`agent-toolkit/agent_toolkit/hook.py`へ移した変更を`develop`へマージした。
  マージ前に開始した稼働中セッションでは、フックの起動に失敗し、全ツール呼び出しが拒否された。
  （直接原因）稼働中のセッションは起動時に読み込んだ`hooks.json`の旧パスを参照し続けるが、ファイルの移動時に旧パスへ互換スクリプトを残さなかった。
  マーケットプレイスがdirectory型で作業ツリーを直接参照するため、`${CLAUDE_PLUGIN_ROOT}`は移動したファイルを含む作業ツリーへ解決される。
  （影響）互換スクリプトの作成も委譲による迂回もツール呼び出しを要するため自己回復できず、ユーザーがClaude Codeを再起動するまで復旧しなかった。
  （対策）稼働中セッションが起動時に解決する起動対象（`hooks.json`の`command`と`.mcp.json`のMCPサーバー起動対象）のリポジトリ相対パスを固定値としてテストへ写す。
  起動対象のパスが変わるとテストが失敗するようにする。
  起動対象ファイルを移動する計画は、`agent-basics:writing-standards`の`references/claude-hooks.md`が定める互換スクリプトの残置を同一commitへ含める

- 2026年8月30日: 常駐実行の委譲先セッションで自律終了の再促が毎ターン発火し、委譲範囲外の終了工程を求められた。
  直接原因: 発火条件を常駐実行の印である環境変数だけで表した。
  その環境変数は委譲先セッションにも継承された。
  対策: 委譲先セッションの印をセッション起動処理が付与し、発火条件を最上位セッションへ限定する

- 2026年8月31日: 常駐実行の最上位セッションが`agent-toolkit:exit-session`を起動しないまま終了した。
  直接原因: Stop入力の`background_tasks`が空の一覧を渡す一方、transcript復元による未完了の起動記録が残り、
  共有Stop判定器が両者の論理和で継続中と判定して終了を承認した。
  対策: 有効な`background_tasks`一覧を基準とし、transcript復元の未完了残差を継続根拠へ加えない。
  常駐実行の起動目的文へ`agent-toolkit:exit-session`によるセッション終了を含める。
  再発（2026年9月7日）: 常駐ループのセッションで`agent-toolkit:exit-session`が未起動のままターンが終了し、ユーザーの指摘まで常駐ループが停止した。
  （直接原因）Stopの自律終了判定が`stop_hook_active`の真だけを根拠に無条件approveへ遷移し、唯一の遮断機会を先行するターンで消費した。
  （対策）Stopの共通処理へ連続blockの上限管理を置き、3つのfail-closed判定にある無条件approveの処理を撤去する

- 2026年8月31日: 委譲先セッションの自律終了再促を最上位セッションへ限定する修正を確定した後も同じ遮断が観測され、
  既存の除外判定が実効的でないという診断が記録された。
  その後の実物での観測では、委譲サーバー経由で起動した委譲先の
  停止判定が委譲先として承認され、除外判定は現行の処理で成立した。
  直接原因: 未確定。
  遮断の記録は修正commitの時刻より後にもあるが、当時の委譲サーバープロセスの
  起動スクリプトのパスと起動時刻は残っておらず、遮断を起こしたプロセスが読み込んだ版を確定できない。
  常駐プロセスが修正前のモジュールを保持していたことは、観測された時間対応を説明できるが確定はできない。
  対策: `agent-toolkit/agent_toolkit/`配下の実装の修正後に同じ事象を観測した場合は、稼働プロセスの起動スクリプトのパスと
  起動時刻、および起動スクリプトと同じ配布rootの`agent_toolkit/`配下にある対象ファイルの更新時刻を比較する。
  稼働プロセスが読み込んだ版を確定してから、修正の有効性を判定する。
  過去のプロセスの証拠を回収できない事象は、版差を直接原因として記録せず、現行コードでの再現可否を結論とする

- 2026年8月: 個人配布フックが8種類の編集保護を無効化したまま動作していた。
  直接原因: `ModuleNotFoundError`発生時も終了コード0を返す実装で、隔離実行の検証も無かった。
  対策: 依存分離と隔離実行のsmoke test

- 2026年8月: 状態フラグがセッション途中で失われ誤警告が13回反復した。
  直接原因: 状態ファイルの回収がセッション終了理由で決まり、稼働中でも削除された。
  対策: 状態ファイルの回収を期限方式へ変更

- 2026年8月: PreToolUseのBashチェックが、検証ツール名・禁止コマンド名を引数として含むだけの
  読み取り操作へ誤発火した（切り詰め警告を実セッションで3回観測）。
  直接原因: 検出条件をコマンド文字列全体への部分一致で実装し、対象が実行位置にあるかを判定していなかった。
  対策: 実行位置のトークン列を返す共通ヘルパーへ助言用の3つのチェックを集約し、引数位置の負例テストを追加。
  遮断用のチェックは当時の判定を維持した。
  2026年9月5日に次の事例を観測し、遮断用のチェックも見直した

- 2026年8月: フック警告が案内する対処自体が同一原因で再ブロックされる構造や、
  規範間で両立しない警告（検収補正時のやり直し誘導）が観測された。
  直接原因: 警告文の対処案内が実際の原因や正当な継続手順と乖離していた。
  対策: 警告文へ実際の原因と継続手順を明記

- 2026年8月: 単発のAgent・Taskまたはagents_server起動が、`agent-toolkit:delegation`の起動記録が無いことだけを理由にPreToolUseで遮断され、対応するスキル起動時にも警告が出ていた。
  直接原因: 単発の基本委譲と、起動方式の選択・継続・複数主体調整を要する高度な委譲を、フックの状態フラグで同一の必須手順として扱っていた。
  対策: 基本委譲の対象・権限・完了条件・受領後に現物を観測して行う検収を常設規範へ置き、高度な委譲だけへ`agent-toolkit:delegation`を適用する。
  PreToolUseの遮断・警告およびPostToolUseの専用状態記録を撤去し、agents_serverのcwd・継続入力など独立した入力検証は保持する

- 2026年8月: `SubagentStop`が未消化の子エージェント起動を理由にblockを返し、待機中の調整役のターン終了を拒否した。
  調整役にはその場で状態を変える操作がなく、無操作のコマンド呼び出しが反復し、ユーザーが2回中断した。
  直接原因: 対象主体の同一ターン内の行動で解消できない他主体の状態を、`SubagentStop`の終了条件にした。
  対策: `SubagentStop`から未消化の子エージェント起動のチェックを撤去し、対象主体が同一ターンで解消できるblockだけを残す。
  block通知は解消手段を伴う単一の整形関数へ集約する

- 2026年8月: 直接の子エージェントが完了済みでも、子のtranscriptで起動した孫エージェントが稼働中のまま、
  最上位Stopが通常終了を許可した。
  直接原因: 最上位transcriptだけを走査し、直接の子記録にある孫起動と、最上位の`queue-operation`にある完了通知を同じ集合へ統合していなかった。
  対策: 共有Stop判定器が固定された子記録から孫起動とtask-id対応を収集し、最上位生transcriptの`enqueue`・`remove`完了通知で相殺する。
  LLM実行主体への完了通知配送契約とは観測面を分離し、`SubagentStop`の子孫blockは復活させない

- 2026年8月: 直接子がいったんCompletedを返した後、孫の完了通知またはSendMessageで同じagent IDのまま自動再開した場面で、Stopが未完了0件としてセッション振り返りを誘導した。
  直接原因: 自動再開しても、親transcriptには新しい起動イベントが無かった。
  対策: Stop入力の`background_tasks`にある非`teammate` taskを現在状態の根拠として共有判定へ接続する。
  旧ホストとCodexではその入力を得られないため、transcriptから推論した状態を代替入力とする。
  `SubagentStop`の子孫blockは循環待ちを再発させるため復元しない

- 2026年9月1日: フック定義が参照するスクリプトを解決できず、PreToolUseのツール呼び出しが17件遮断された。
  直接原因: コマンド定義が終了コード2を条件なく遮断へ変換し、判定による遮断とスクリプト不在によるuvの終了を区別しなかった。
  対策: 個人環境向け設定のPreToolUseへ参照先の実在確認を前置し、不在時は判定せず終了コード0で終える。
  agent-toolkitプラグインのフック定義へ同じ確認を導入しないのは、定義と実体が同一のplugin root配下で同時に配布され、
  POSIXシェルによるラッパーがWindows実行環境で成立しないためである。
  後継方針（2026年10月25日）: hookの起動不能で作業が止まる事象が反復したため、ユーザーはhook定義のコマンドラインで起動の失敗を吸収するよう指示した。
  agent-toolkitの`hooks.json`と生成する`hooks.codex.json`の全commandの末尾へ`|| exit 1`を置き、起動の失敗による終了コード2を非遮断の1へ変換する。
  `|| exit 1`はbash・PowerShell 7・cmdで同じ意味を持つため、前段の存在確認ラッパーを採用しなかった理由には当たらない。
  現行の記録は[design-hooks.md](design-hooks-responsibility.md#エントリーポイントと判定の集約)「エントリーポイントと判定の集約」にある

- 2026年9月5日: 直前のアシスタント応答の記述言語チェックが、英語だけの地の文を含むターンを判定せず警告を返さなかった。
  直接原因: 判定対象を直前のアシスタントターンだけに限定した。
  そのターンが思考ブロックとツール呼び出しだけで構成される場合は、地の文を空として判定を省いた。
  対策: 判定対象をテキストブロックを持つ直近のアシスタントターンとし、テキストブロックを持たないターンを走査の対象から除いて遡る。
  同じ走査を使うユーザー向け本文と地の文の長さ比較は、`PreToolUse`の時点では判定中のターンの地の文が記録にまだ書き込まれず、判定対象を取得できないため撤去する

- 2026年9月5日: Linux CLIで現在のCodex本体を一意に停止できる条件でも、`agent-toolkit:exit-session`の停止要求を送らなかった。
  直接原因: 停止後に`final`応答を返せないことを停止不能と誤認し、停止要求自体がCodexの正常な終了であることを適用しなかった。
  対策: `agent-toolkit/share/rules-main.codex.md`で停止コマンドのツール呼び出し自体を終了とし、停止後の応答不能を停止不能の根拠にしない。
  同じ不履行をClaudeでは観測していないため、共通`agent-toolkit:exit-session`は変更しない

- 2026年9月5日: PreToolUseの一括終了遮断判定が、禁止コマンド名を引用符内の検索語として含む`grep`を遮断し、
  同じ共通ヘルパーを使う`git log`への`--decorate`自動挿入が、引数位置の一致へ挿入してコマンド本文を書き換えた。
  直接原因: 実行位置の判定を、一致位置より前にヒアドキュメントの開始があるかだけで行い、
  引用符内の引数として現れる語を除外していなかった。
  対策: 両チェックを区間分割と実行位置解決による判定へ移し、実行位置を確定できたことを許可の根拠にせず、
  禁止語が引数位置のリテラルであることを確定できた場合にだけ遮断を緩める。
  `--decorate`の挿入は対象のgit呼び出しと挿入位置を同じ区間から求める。
  引用符内の検索語を負例、シェル、コマンド置換、サブシェルおよび複合コマンドの条件部を介する間接呼び出しを正例とするテストを追加する

- 2026年9月7日: PreToolUseが`--help`だけを連結したコマンドを状態変更コマンドの連結として遮断した。
  直接原因: 副作用の有無を前置トークン列の一致だけで判定し、呼び出しがヘルプ表示だけで終わるかを確認していなかった。
  対策: ヘルプ専用の呼び出しかどうかを判定する述語を共通化し、ヘルプ表示だけで終わる呼び出しを状態変更コマンドの判定から除く

- 2026年9月14日: PreToolUseが`atk`サブコマンドのヘルプ契約を注入しても観測済み状態を記録せず、
  同じ契約を後続の呼び出しへ反復注入した。
  PostToolUseもリダイレクト後の空応答を未観測とした。
  直接原因: 観測済み状態の更新を非空のPostToolUse応答だけへ限定し、PreToolUseの注入成功を状態遷移に含めなかった。
  対策: 注入成功時にサブコマンド名を記録し、単独ヘルプからリダイレクトを除いて判定し、成功イベントは空応答でも記録する

- 2026年9月14日: コーディングエージェント向け文書の編集前参照を、部分Readまたは別主体の要約で代替できる余地があった。
  直接原因: 規範が読解主体、実行コンテキストおよび全文到達の成立条件を明記せず、個人用PostToolUseも部分Readを記録した。
  対策: 実際の編集主体による同一コンテキストの全文読了を規範へ明記し、offset・limit付きReadを状態記録から除外する
