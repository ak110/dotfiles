# 方針・意向: 依存と一時領域

## 依存とサプライチェーン

現行の規定は`agent-basics:writing-standards`の各参照資料にある。

- サプライチェーン対策としてmiseの`minimum_release_age`を設定し、依存の即日更新を避ける
- 自作パッケージをuvの公開待機設定から外す指定は、各プロジェクトの`pyproject.toml`かコマンドライン引数へ置く。
  グローバルなuv設定（`~/.config/uv/uv.toml`）へは置かない（2026年10月6日、ユーザー回答。グローバル設定の除外は各プロジェクトの`uv.lock`へ入り込むため）。
  agent-toolkitのMCP定義が起動するpyfltrは、`uvx`の引数`--exclude-newer-package pyfltr=false`で公開待機から外す。
  MCP定義のpyfltrの下限を公開直後の版へ上げた際、ユーザーは、待機の経過を待つ案と、この引数でCIとMCPサーバーの起動を先に回復する案のうち、後者を選んだ（同日のユーザー回答）。
  現行の規定は`agent-basics:writing-standards`の`agent-basics:writing-standards/references/dependency-management.md`「公開待機設定」にある
- 配布物へ波及しない依存上書きは、エンドユーザー環境の脆弱性を未解消のまま残すため
  採用しない

## managed-temp

現行の規定は[design-storage.md](design-storage.md#managed-temp)の「managed-temp」と`agent-toolkit:managed-temp`にある。

- エージェントの一時領域は、通知されたセッションのmanaged-tempの中へ`mktemp -d`で作成し、作成者が`rm -r --`で回収する。
  `.git`を含む領域と通知が無い場合は一時root直下へ同じ標準手段で作成し、別名前空間との共有は`mktemp -d -p <共有先>`と作成者の明示回収を使う。
  公開の`atk managed-temp`は持たない。
  この方針は2026年10月25日のユーザー指示による。
  独自コマンドの用途を各セッション・各エージェントが毎回学び直す費用が大きく、一時領域の登録簿とロックも作成ごとに増え続けていた。
  それまでの`atk managed-temp create`・`cleanup`・`list`と`--root`・`--recover-registry`・`--force-remove`の運用（2026年9月〜10月）を置き換えた
- 一時rootの直下は、配下を含む最終更新から7日を超えると`atk`の実行時に自動削除する。
  通常ファイルも同じ期限の対象とし、領域外の実在するgitdirと逆参照が一致する登録済みworktreeを含む対象と使用中の保持配布物は削除しない。
  未来の更新時刻は現在以前の状態変更時刻へ置き換える。
  採用できる時刻が無ければ期限切れとする。
  `.git`の有無による一律保持と未来時刻による期限延長で、テストや複製が残した領域を回収できなかったため、保護対象の状態で保持を判定する形へ改めた（2026年10月29日）。
  新規の領域は登録簿・marker・会話参照・cleanupロックを作成せず、旧版が残した状態は対象が無くロックを取れたものだけを個別に回収する。
  7日の自動削除は2026年9月から行う。
  所有を確かめられない領域も使用中以外を自動削除する判断は、2026年10月2日のユーザー回答による。
  managed-tempはユーザーが作成せず、各所にゴミが残る方が有害であるため
- 削除できなかった期限切れの対象の警告は、回収を判断できる主体だけへ出力し、`is_delegated`が真である委譲先セッションでは出力しない
  （2026年9月、エージェント由来のAWI。所有しない領域の警告を委譲先が同一記録で2回受け取り、処置できない通知として扱う工程が生じた観測に由来する）
