# 方針・意向: 計画レビューの経緯

## レビューの運用

### 計画レビュー廃止前の運用（2026年9月13日まで）

本項の項目は2026年9月13日に廃止した計画レビューと、廃止前の担当（`fast担当`、`fix担当`、`計画レビュー担当`、`統合担当`）と工程（`主作業ツリー前処理`）を前提とする判断経緯である。
現行の実行契約は同日の変更以降の規範が定める。
同日の変更は[concepts-planning-history.md](concepts-planning-history.md#計画レビュー廃止前の運用2026年9月13日まで)の同名の節が記録する。

- メインはfast担当のエスカレーション時に実効設定を比較し、新規fix担当を起動する場合だけfast担当の終了を確認してからdirtyな同一worktreeを渡す。
  書込所有権は同時に1主体だけとする
- fast担当からfix担当への移行は実効`engine`・`model`・`effort`がすべて一致する場合だけ同じthreadを継続するという、廃止前の判断経緯である。
  現行ではeffortだけが異なる場合は相対操作で同じthreadを継続する。
  継続接続は同じ担当へ同じタスクの後続作業を返す場合と、fast担当からfix担当へ移る場合に使い、
  実際の起動routeと保持識別子に対応する接続手段を使う。
  `agents_server`で起動したthreadは実行ホストとengineによらず`send_message(session_id, ...)`、Claude CodeのAgentツールで起動したthreadだけは`SendMessage`を使う。
  継続条件は
  `agent-toolkit/skills/delegation/references/continuation.md`が定める。
  UWIへの回答後も同じpickerまたはレーンを一般継続契約で再開する
- 1つのレビュー収束ループは1つのレビュー表へ集約し、計画レビューは`plan-review`、実行レビューは`exec-review`の`track`で帰属を表す。
  実行レビュー担当は計画との比較と成果物評価を順番に行い、実在指摘を表へ記録して指摘件数だけを返す。
  再レビューは表の修正記録と直接影響範囲へ限定する。
  保存済み表の`implementation-review`・`plan-conformance`・`independent`は読み取り互換として扱うが、新規作成時は生成しない。
  モデル解決と共通checkpointの受領は`review-loop-coordination.md`へ集約し、表の操作、レビュー担当およびレビューイーの固有契約はそれぞれのSSOTへ残す（2026年8月、ユーザー指示。表の分散と共通手順の重複を解消するため）
- 計画作成中に発見して計画へ含めた既存不良は、ユーザー指示との関連を問わず計画レビュー対象とする
  レビュー担当は無関係な既存不良を能動的に探索せず、必須の走査中に遭遇した実害のある既存不良は計画との関連だけを理由に除外しない
- 計画レビューは正常系の起動、書込み許可、配布および成果到達を主要な異常系より先に成立させる。
  ロック、所有権、排他、復旧または移行の指摘は要件出所と対象操作ごとの主体・競合・同時成立条件へ対応付け、ユーザーの是正または実際の検証で前提が失効した場合は、その前提だけを根拠とする指摘、修正方針および追加機構を次回レビュー前に撤去する。
  この方針は正常系の書込み許可が第5ラウンドまで認識されず、別操作とレビュー修正に由来する状態管理がユーザー要件として扱われた観測事象に基づく（2026年8月、review-session）
- 計画レビューは要求の被覆、外部可視の契約、実装単位の分割と依存および検証区分の対応を対象とし、実装した後でなければ確定できない内部の状態遷移と例外処理の細部は実行レビューで扱う
- 全ての実装要求は計画、計画レビュー、実装および単一の実行レビューを必須とする。
  実装不要またはholdの項目には計画、worktreeおよびレビューを作成しない。
  要求の不採用と既存の変更による充足は計画工程で確定する。
  pickerは要求の不採用や既存の変更による充足を理由に終了しない
- pickerはメインが設定モデルへ直接委譲し、通常型の各レーンは1計画・1専用worktreeとする。
  1レーンの計画起草と計画レビューは、メインが計画担当と計画レビュー担当を直接起動して所有する
- 実装工程へ進む各レーンは実行レビュー収束後の計画最終化、最新ベースへのrebase、競合解消後の単一実行レビュー、メインの許可を受けて`atk lane integrate`が1レーンずつ行うffマージおよびAWI行ごとの終了までを所有する。
  2026年11月11日、統合を手早く行い統合後の検証を他の作業と並行させるユーザーの是正の要求により、直列にする区間を統合先HEADの更新に限った。
  採用する実施範囲を持たないレーンも、メインが起動する統合担当が計画証拠の保存とAWI行ごとの終了までを所有する。
  所有資源の回収は、いずれの方法でも完了報告を検収したメインが所有する。
  全レーン後の全体レビューは追加しない
- 各ラウンドは検収点として維持し、第2ラウンド以降はメインが反復原因と計画目的への累積影響を検証する。
  その他の逸脱と確認待ちは続行できない理由の返却へ統合し、回答または補正後に同じ担当を再開する
- 版数・生成物同期・push・CI・AWI固有の公開後の操作は全レーン後にメインが1件の公開担当へ委譲し、受領した固定形式の値を確認する。
  CI修正では確定済みの原因分析を引き継ぎ、実装と単一実行レビューだけを行い、新しいバグ計画と計画レビューを作成しない。
  原因commitに対応する計画契約があれば、その計画が実行レビューの比較基準となる。
  計画契約がなければ、原因分析結果、修正認可根拠、対象の検証結果、変更目的、対象、公開契約および入力計画を持つインラインのCI記録を比較基準とする。
  計画なしCI修正commitに起因する次のCI失敗では直前のCI記録を更新し、最初の原因commitの7文字以上の一意な短縮OIDから一意に命名した同じ独立CI実行レビュー表を継続する。
  commitの生成主体または固定集合にある別計画の有無で比較基準と表を変えない。
  正式な保存操作で表をprivate-notesへcommit・pushする
- 確定済み計画に基づく実装工程では、既存実装または規範との不整合を理由に、計画が確定した目的、方針、採否、対象範囲または除外・保持を覆す修正を確定しない。
  矛盾を観測した場合は計画側と対立側の双方の由来を調べて優先順位を適用し、計画側が上位となる場合と由来を確定できない場合は呼び出し元へ返し、ユーザー確認で解消する。
  この方針はレビュー指摘対応で計画の前提・方針・意図に反する修正が反復して確定した観測事象に基づく（2026年8月、ユーザー指示）
- 実行レビュー収束後の計画最終化は、計画ファイルを所有する主体が実行する。
  `agent-toolkit:write-plan`をメインが起動した場合はメインが実行する。
  `agent-toolkit:process-wi`の実行ではメインが統合指示へ最終化の入力を載せ、統合指示を受領した実装担当が統合担当として実行する。
  統合指示を伴わずに最終化だけを求められた実装担当は着手せず呼び出し元へ差し戻す。
  この分担は2026年9月の観測事象とユーザー指示に基づく
- 主作業ツリーでのみ実行できる前処理は、専用worktreeの実装単位へ置かず、計画ファイル（詳細）の`### 主作業ツリー前処理`か計画ファイル（メイン）の統合後検証へ置く。
  メインはレーンの起動前に、実行する前処理が変更するパスと主作業ツリーの既存の差分が交差しないことを確認する。
  交差する場合は実行しない。
  変更するパスを実行前に確定できない前処理では、主作業ツリーがcleanであることを確認してから実行する。
  失敗時、変更するパスと既存の差分が交差しないことを確認していた場合は、前処理が変更するパスを前処理の生成物として復元する。
  主作業ツリーがcleanであることを確認していた場合は、実行後に現れた差分の全てを前処理の生成物として復元する。
  復元後は前処理の成果を入力とする実装単位だけを遮断する。
  実行順序が先であることを成果依存として扱わない。
  変更するパスを特定できないまま、既存の差分を残して前処理由来の差分を事後に識別する設計は採らない（2026年9月、ユーザー確認）
- レビュー担当のthreadが継続不能と確定した場合は、同じ`model_type`で新しいレビュー担当を起動し、レビュー指摘管理表、ラウンド番号およびレビュー対象HEADの7文字以上の一意な短縮OIDを引き継ぐ。
  実行レビューでは`review_contract`を同じ生成元から再生成する。
  解消済みの指摘を再走査せず、最初のラウンドへ戻さない

### 経緯（レビューの運用）

- 2026年8月に記述形式を計画レビューと修正の対象外とした方針は、2026年9月15日のユーザー指示で改め、妥当な指摘は種別によらず是正する方針（本節の「計画ファイルの体裁を変える指摘と、記述間の矛盾を示す指摘」の項目）へ置き換えた。
  改める前の方針を適用していた計画レビュー工程も2026年9月13日に廃止済みである
