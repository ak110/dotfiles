# 障害・欠陥の記録: フックとセッション状態の不全（2026年9月22日〜2026年11月6日）

[フックとセッション状態の不全](incidents.md#フックとセッション状態の不全)の事例を発生時期別に収録する。

- 2026年9月22日〜26日: メインエージェントの地の文がツール呼び出し直前の短い進捗行で英語になった。
  hookの英語検知通知の直後には、ユーザーへの訂正宣言で直前の報告が英語だったことを認め、以後は日本語で書くと述べた。
  直接原因: 英語のシステムプロンプトと途中挿入される英語の注記の文体を短いステータス行が写し、日本語で書く指示はセッション開始時の通知だけで長いセッションでは文脈上遠くなった。
  対策: `agent-toolkit/rules/01-agent.md`に段落を加え、自動挿入本文とホスト生成の注記へ返信や訂正宣言を書かず、英語の挿入文を受けても日本語で書くことを定めた。
  英語検知通知から応答し直しを求める文面を除いた。
  PreToolUseがメインセッションで10回のツール呼び出しごとに日本語の応答指示を再注入する

- 2026年9月30日: `atk wi process-loop`が起動したClaude Codeの子セッションが、終了時に「Background work is running」の確認画面で止まり、次の周期へ進まなかった。
  直接原因: Function hooksの`turn.complete`が実行する`/exit`は終了とともに停止するセッション限りの作業（非durableのcron task、背景作業）が残ると確認画面を表示し、無人のセッションでは回答する主体がいない。
  対策: `turn.complete`が`/exit`の直前に非durableのcron taskを削除する（許可の判定が`allow`の場合だけ。
  失敗しても`/exit`は実行する）

- 2026年10月19日: 操作前hookのスキル本文配送がホストのSkill起動を代替し、起動登録と圧縮後の復元の効果を失わせた。
  直接原因: 生ファイルをhook応答へ載せたことを取得とみなし、ホスト固有の取得操作と同等に扱った。
  対策: 本文配送をやめ、主体ごとのSkill起動または読取を案内し、成功した取得を観測する方式にした。
  再発（2026年10月27日）: 宣言型読込表の導入時に、Claude向けの本文配送と配送時の取得済み記録を再導入していた。
  後続の配送順変更も、ユーザーの指摘で既存方針に反すると確認し、撤去した。
  後継方針（2026年10月27日）: 宣言型経路でも本文を返さず、絶対パス・注目する節・本来の全文取得操作を非遮断で案内する。
  後継方針（2026年10月30日）: 初回案内は警告とし、同じ主体・本文の案内済み資料を未取得のまま再書込する場合だけ遮断する。
  成功した全文被覆で解除し、通知一般の反復昇格は行わない。
  再発（2026年10月30日）: Codexの出力予算による省略を補うとして、成功した読取本文をPostToolUseが追加コンテキストへ配送する方式を導入し、全文を読んだ担当の取得記録を消して再書込を止めた。
  2026年10月31日のユーザー指摘で撤去し、省略は担当が行範囲を分けて読む方式へ戻した。
  再発防止として、ホスト・ツール・省略補償の別を問わず本文を載せないことを方針記録へ明記し、公開PostToolUseの出力に資料本文が含まれないことをCodexの全読取形式で検査する。
  追加事象（2026年10月31日）: 会話圧縮のたびに圧縮前に選んだ資料の全候補を毎回の操作で未取得として再掲し、1回の案内が27ファイル・586,805バイトに達して自動圧縮と続行不能返却が反復した。
  現在は履歴候補を列挙せず、圧縮通知で必要資料を選ぶよう案内する。
  再現条件、観測の範囲と再検証の手順は`audit-records-read-triggers-initial.md`「agent-toolkit/share/read-trigger-bootstrap.md：操作を契機とする共有資料：2026年10月27日」にある
- 2026年10月27日: hook通知を命令形へ統一したが、次の操作を作る引数と、その後の通知本文へ適用が及ばなかった
  直接原因: 通知規範の読込条件がformatterや標識の変更を指し、通知本文の新設・変更を明示していなかった。
  既存の警告検査も行動要求の終止形を受理した。
  対策: 通知本文・fix・次の操作・圧縮時本文を読込条件へ含め、行動要求を持つfix・next_actionの語尾を検査する。
  再発（2026年11月9日）: 範囲不足として、前回の見直しに含まれなかった次の操作を確認した。
  未適用として、規範導入後の圧縮時本文と復元案内、10月31日に要求された短さの基準の欠落を確認した

- 2026年10月31日: 正常拒否を終了コード2で返すPreToolUseが登録末尾の起動失敗用ラッパーで終了1へ変換され、正常拒否と起動障害を区別できなかった。
  直接原因: 正常な判定結果をプロセスの失敗と同じ経路へ出力し、AGY変換も構造化denyを参照していなかった。
  対策: 正常拒否を終了0の`hookSpecificOutput.permissionDecision=deny`と非空理由へ分離し、AGYも同じ結果を公開denyへ変換する。
  保留通知と拒否理由を別フィールドで扱う。
  内部エラーは対処可能なイベントでは標識付き通知、対処不能・イベント不明では出力停止とする

- 2026年11月2日: 送達ツールを使うClaude Codeの途中のターン末尾まで言語判定が遮断し、書き直しのターンが増えた。
  対策: 72ea09448で送達ツールの準備印がある場合の末尾判定を外した。
  再発（2026年11月11日）: 対策の喪失により、11月4日の99d31ee1cが準備印の条件を外した後は、背景Bashを待つ途中の英語本文も遮断された。
  背景原因: 待機中と作業終了時を区別する過去のユーザー判断が、次の規範編集時に読む方針記録と撤去台帳へ残されていなかった。
  後継方針（2026年11月11日）: 既存の非同期待機判定が真になるClaude CodeのStopだけを除外し、作業終了時の本文とCodexの言語保護を保つ。
  方針記録・撤去台帳と元対策の効果確認を更新する
