# 処理中の不良への即時対応の設計記録

[設計記録の索引](design.md)と[担当の責務と工程間の知識境界の設計記録](design-workflow-boundaries.md)から参照する主題別の記録である。

公開工程の開始前に見つけた不良は、process-wiの「即時対応」が持つ共通基準で、本作業による導入と残工程への作用を先に判定する。
停止・遮断の有無だけでは判定せず、担当が欠陥のある判断入力を使い要求・判断・成果物を誤る場合も同じセッションで是正する。
振り返りの類似範囲を狭める規範欠陥もこの判定に含める。
現在発生中の不良は、残工程への作用によらず今回の正式対応に含める。
潜在不良・効率改善では、次のセッションの停止・遮断・やり直しへの影響を判定する。
即時対応する項目は既存の追加処理へ接続し、延期できる独立改善はAWIで次回以降へ回す。
品質不良や保守改善という名前だけでは対象外にしない。
メインは即時対応する項目を`add-wi`の委譲で調査、AWIの起草および投入まで1件の委譲先へ渡し、投入または再利用するAWIを自ら追加選定し、処理開始と`pick-wi-check`の成功、意味検収を確認する。
メインは指定集合と状態を検収し、割当基準で受入先のレーンへ対応付け、元の選定結果へ反映してからレーンへ渡す。
調査を委譲するのは、原因分析と類似見直しの過程で得る無関係な情報を、メインと修正を担うレーンの文脈へ入れないためである。
投入されたAWIは原因と対策を確定済みであるため、修正を既存レーンの文脈で行ってもこの目的を損なわない。
レーン担当が自レーンの検証を妨げる既存不良を報告し、修正の対象と方向が報告と現物から技術的に定まる場合は、メインがAWIを経ずに同じレーンへ修正を認可する。
原因と対象が定まった不良では調査を分ける目的が成立せず、AWIを経ると投入担当とレーン担当が同じ検証を二重に実行するためである。
修正は計画の実装と別のcommitにし、両方を終えてから変更範囲の検証を1回実行する。
認可は計画を更新せず、認可の出所・対象・対応する完全OIDを計画の進捗ログ（計画なしでは引き継ぎ記録）と実行レビューの`review_contract`へ置く。
commitメッセージには計画外の既存不良の修正であることと修正理由だけを書く。
公開commit本文の読み手は内部の認可記録へ到達できないためである。
公開工程の開始後も、現在発生中の不良は共通の先送り条件に当たらなければ今回の正式対応に含め、追加統合後の再公開へ接続する。
`agent-toolkit:process-wi single-lane`では同じ委譲で投入した即時対応のAWIを処理対象WIへ加え、メインが自ら実装して同じ実行レビューへ含める。

本作業で扱った問題と根本原因を同じくする不良は、独立した既存不良として次回へ送らず、その問題の類似見直しの母集団として扱う（2026年10月10日のユーザー指示による`agent-basics:bugfix`への集約）。
範囲・時機・完了は同スキルの次の資料に従う。

- `agent-basics:bugfix/references/root-cause-severity-impact.md`「QとC・Dの区別」
- `agent-basics:bugfix/references/root-cause-prevention-verification.md`「類似見直しと再発防止の完了」

AWIを要さず見つけた主体が元の文脈で直す用途には、専用の起動・受領契約を用意する。
契約は`agent-toolkit:delegation/references/investigation-delegation.md`に置く。
`defect-investigation.subagent.md`を指定して、`agents_server`の`start`で`execute`の調査担当を起動する。
調査担当は`agent-basics:bugfix`を起動し、対策、横展開処置および再発防止策の確定まで行う。
見つけた主体は返った対策で修正する。
`start`の`explore`は委譲先が`Skill`ツールを持たずスキルを読み込めないため使わない。
`add-wi`はAWIの投入までを完了条件とするため、投入せずに直す用途と分ける。
知識境界として、調査の手順は`agent-basics:bugfix`、起動と受領は前掲の起動・受領契約が持つ。
process-wiでの扱いは`agent-toolkit:process-wi/references/lanes-followup.md`「即時対応」が持つ。
process-wi single-laneでの扱いは`agent-toolkit/skills/process-wi/references/single-lane.md`が持つ。

比較した代替案は次のとおりである。
観測した箇所だけを局所修正して類似見直しと再発防止策を後続のAWIへ回す組は、セッションが終わるたびにAWIが投入されて次のセッションが続くため採用しない。
修正まで独立した担当や新しいレーンへ分ける案は、潜在不良・効率改善では書込主体と工程の増加も比較する。
現在発生中の不良の正式対応では、新しいレーンも受入先に含め、律速の延長だけで次回へ送らない。
是正で見つかった不良に世代の上限を置く案は、そうした連鎖を想定しなくてよいとのユーザー判断により採用しない。
公開工程の反復を避けることだけを理由に現在発生中の不良を次回へ送る案は、今回の正式対応を求める方針に合わないため採用しない。
