# 方針・意向: 所要時間とコスト

## 所要時間とコスト

レーン分けは`agent-toolkit/skills/process-wi/references/selection-procedure.md`が定める。
所要時間の分析の現行の規定は`agent-toolkit/skills/review-session/references/duration-analysis.md`の「所要時間の分析と改善」にある。

- 速度や資源使用量の改善を主目的とする作業は、変更前のボトルネックと、同じ負荷・比較可能な条件での変更前後の数値を測定し、挙動の維持とトレードオフを報告する。
  一般的な手順整理やコスト削減は推定による判断を保つ。
  2026年10月27日、ユーザーは性能改善の比較測定を求める提案を採用した。
  現行の基準は`agent-basics/skills/writing-standards/references/investigation.md`と`agent-basics/skills/check-execution/references/diagnostics.md`にある

- セッションの所要時間目標は、処理したAWIの件数によらず1セッション3時間以内とする。
  この値は`github.com/ak110/dotfiles`を処理の対象に含む`agent-toolkit:process-wi`のセッションへ適用する。
  `atk wi process-loop`が別のディレクトリで起動する統括のセッションのうち、本リポジトリを対象に含むものにも同じ目標と計測範囲を適用する（2026年11月11日。ユーザーが複数のリポジトリをまとめて処理する巡回についても3時間を基準に述べているため、起動の形に合わせて記述を改めた）。
  本リポジトリを対象に含まない作業と、同スキルによらない作業へは適用しない。
  1セッションの所要時間は、最初の記録からセッションが終了する時点までを計測範囲とし、
  振り返り、公開工程とセッション終了工程、完了報告および`atk agents-exit-session`に要する時間を除かない。
  目標は振り返り対象セッションで計測したこの時間へ適用し、値は証拠抽出器の`--stats`が返す`elapsed_seconds`から取得する。
  2026年9月3日には、処理対象として固定したAWI件数から目標値を算出する規模別の式を置いた。
  この式は、目標を参照するたびに件数の確定と計算を必要とし、目標の用途である内訳の分析に対して手順が複雑だったため撤去した。
  目標超過を、必要な品質工程の省略、処理の停止または時間都合の次回送りの理由にしない。
  2026年11月12日のユーザー指示により、dotfilesを含む巡回は毎回、全件とレーン数上限を保持し、次回の原則3時間の達成に必要な改善を実装・公開して、その見込みを検収するまで継続する。
  次回候補全体と全工程へ実測と残量を対応付け、合理的な内部同時数と共有2検証枠、代表外の実機・別ホスト・公開工程を含める。
  巨大WIだけは分割・並行化等の比較と資源・費用の根拠を伴う具体的対象への事前承認で時間目標から除外でき、全件実装と品質・公開は保持する。
  既存の調査・内訳分析の目的を保ち、今回の指示で達成見込みの検収を終了条件へ接続したものである。
  現行の終了条件は`AGENTS.md`「process-wiの終了条件」と`.claude/skills/develop-dotfiles/SKILL.md`「process-wiの所要時間と終了条件」にある。
  超過の有無にかかわらず毎セッションで所要時間の内訳を分析する。
  超過していない場合は、記録の照会結果から、品質と必須工程を維持した高速化の改善提案を作成するかを判断する。
  目標を超過した場合は、超過を再発防止策が必須の事象として扱い、改善提案の作成を判断に委ねない（2026年10月7日、ユーザー指示。不適切なユーザー確認、ユーザーの手を煩わせた事象、品質への悪影響と並べて、目標時間の超過を対策必須と述べた）。
  2026年10月15日の重大度別方針により、超過の評価と原因分析を保持し、探索の深さ・終了と再発防止策の要否は問題の影響と継続費用から判断する。
  現行の判断は`agent-basics:bugfix`の`SKILL.md`「QとC・Dの区別」にある。
  次のセッションが前のセッションより短くなるよう改善を続ける。
  振り返り時に読み込まれる原本は`~/.claude/docs/session-review-dotfiles.md`の
  「セッションの所要時間目標」節とする。
  配布元は`.chezmoi-source/dot_claude/docs/session-review-dotfiles.md`である。
  進行中も定期的および重い処理への着手前に、進捗と目標時間から必須性と低負担な案を比較する。
  曖昧な要求による必要な調査と、手順・ツールによる回避可能な反復を区別する。
  現行規範は`agent-basics/skills/writing-standards/references/quality-principles.md`と`.claude/skills/develop-dotfiles/SKILL.md`にある（2026年10月25日、ユーザー指示）。
  本文書は経緯を記録する（2026年8月、ユーザー指示）。
  （2026年9月2日、ユーザー指示により計測範囲と毎セッションの分析を定めた。
  2026年9月4日、ユーザー指示により規模別の目標を撤去して単一の値へ戻した。
  2026年9月7日、ユーザー指示により計測範囲の終端と目標の適用先を改めた）。
  改善提案を毎セッション作成する規定は、2026年9月30日のユーザー回答により、記録の照会結果から作成の要否を判断する規定へ改めた
- 所要時間とコストの交換では、コストを強く重視し、所要時間が半分になる代わりに
  コスト合計が1.2倍になる交換も採らない。
  2026年9月1日以降の3セッション（件数20件から33件）の実際の計測では、件数が2倍になるとコストは約3.0倍になり、コストはレーン数へほぼ比例する。
  この重み付けでは、レーン数を2倍にして所要時間が13分の1にならない限りレーンを増やす利益が生じない。
  したがってレーン分けではレーン数を最小にする（2026年9月2日、ユーザー指示）。
  現行の規定は`agent-toolkit/skills/process-wi/references/selection-procedure.md`にある
- レーン数の上限は、処理回で固定した候補集合の件数を使い、`floor((WI数+9)/10)`で算出する。
  レーン数をやみくもに増やさないという制約を、件数から一意に算出できる形で保つためである
  （2026年9月15日、ユーザー指示。lane-01へ20件が集中し単独稼働が約95分となった処理回の分析に由来する。
  2026年9月20日、ユーザー指示により上限の分母を10へ改めた）。
  2026年10月10日のユーザー指示により、この上限を時間・不可分成分・処理中の追加による例外のない制約とする。
  初回候補数を保持し、統合済みと全段階のレーンも上限へ数える。
  追加項目は既存レーンで処理し、高速化は上限の内側の配分と工程の改善で行う。
  上限の内側の配分は所要時間の見込みで均衡させ、上限未満のレーン数を選んでよい。
  レーン工程は最も遅いレーンが終わるまで完了せず、件数はその所要時間と相関しないためである
  （2026年9月16日、ユーザー回答。AWI 51件を7レーンへ件数で分けた処理回で、
  レーン別の稼働時間が2298秒から6708秒まで広がった観測に由来する）。
  現行の規定は`agent-toolkit/skills/process-wi/references/selection-procedure.md`にある
- `agent-toolkit:review-session`の時間目標の値・計測区間・用途は、`references/duration-analysis.md`「所要時間の分析と改善」に集約する。
  2026年9月15日の900秒目標は同月25日に300秒へ改められた。
  2026年11月3日のユーザー回答により、目標を超えた場合に時間改善案を必須とする判断だけへ用途を限定した。
  必要な調査の範囲・順序・省略・先送り・停止には使わず、超過しない場合も証拠から改善案を判断する
- `agent-toolkit:process-wi`と`atk wi process-loop`の一連の手順は、品質を保ったまま単位時間あたりに処理する
  ユーザー由来のWIの件数を最大化する目的で構築し、この目的に沿って手順と規範自体を見直す。
  エージェント由来のWIを何件処理したかは、成果を測る尺度に含めない。
  振り返りの改善提案では、対象セッションの工程に加え、処理手順と規範の改廃も検討する。
  手順の撤去、変更または置換を提案する前に、その導入目的と由来を調べる
  （2026年9月16日、ユーザー指示。既存の手順と規範を見直さず直近の工程の短縮だけを提案した観測に由来する）
- 所要時間の分析は、所要時間目標の有無にかかわらず実施する。
  目標を定めていない対象での作業でも、所要時間の短縮が時間とコストの効率を高めるためである。
  所要時間目標との比較を必要とする記述だけは、目標が定められている場合に限る扱いを維持する
  （2026年9月16日、ユーザー指示）
