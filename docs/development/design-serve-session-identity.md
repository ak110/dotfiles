# セッションの親子判定と見出しの設計記録

[設計記録の索引](design.md)と[画面統合とセッション・計画一覧の設計記録](design-serve.md)から参照する主題別の記録である。

## セッション画面

### 親子判定

セッションの親子判定は、親の記録に残る`agents_server`の`start`（統合前の旧名を含む）の結果を使う。
Codexの`exec`経由の呼び出しは`McpToolCall`の結果へ、従来の直接呼び出しはtool結果へ識別子を残すため、両形式を読む。
候補切替で起動してから捨てたsessionも作成済みの子であり、`start`はその識別子を`excluded_candidates`へ載せる。
親の記録だけから親子を組み立てる画面には、作成した全sessionの識別子が戻り値へ残る契約が必要である。
旧記録で返されなかった識別子は復元せず、一覧の実体を別の情報から推測して誤った親へ結ばない。

親子の情報源は、記録自身か記録を作成した主体が親を示すものに限り、次の順に調べて最初に親が決まったものを採用する。
1番目はClaude Codeのサブエージェントのmetadata、2番目は親の記録に残る`start`系の結果である。
3番目はCodexの記録の最初の`session_meta`が示す親thread（`source.subagent.thread_spawn.parent_thread_id`）であり、2行目以降の`session_meta`は親thread側の写しのため使わない。
4番目は`agents_server`のsession登録簿の委譲元（`launcher_session_id`）である。

登録簿の委譲元は、テストや検証スクリプトがプロセス内や独自のMCPクライアントから`start`を呼び、親のセッション記録に起動結果が残らない委譲先を結ぶために読む。
`agents_server`はsessionの作成時に、状態ファイルが射影する委譲元、所有ルート（プロセス専用ルートを除く）、`CODEX_THREAD_ID`の順に解決した値を登録簿へ書き、状態の更新と解放済みへの置き換えでも保持する。
登録簿を最後に置くのは、最上位のClaude Codeが起動したMCPサーバーが起動時のsession識別子を保持し続け、`/clear`の後は古い会話を指し得るためである。
登録簿のレコードは最終更新から7日で掃引されるため、その後は委譲元を失い、他の情報源を持たない委譲先は第1階層へ戻る。
変更前に作成した委譲先と、状態ディレクトリを一時領域へ隔離して動かした委譲先も委譲元を読めず、第1階層に残る。
委譲先の入力へ委譲元を載せる案は、配送の開始タグ`<atk-auto source="agents-server" kind="delivery">`を変えるため採らない。
親と子の実行系（Claude CodeとCodex）は`agents_server`を介して異なり得るため、画面（`static/sessions.js`の`treeRows`）は親を同じホストの記録のパスで検索し、子の実行系を検索条件に含めない。
親子付けの規則は`_atk/serve/session_parents.py`の1つの関数へ集め、ローカルの一覧とリモートヘルパーの双方が呼ぶ。
規則を2か所で別に持つと、一方だけに情報源を加えたときに親子が一致しなくなる。
件数上限（`MAX_LIST_ENTRIES`）で切り詰めた後は、残した記録の祖先が外れていれば戻す。
上限を超えるのは戻した祖先の件数に限り、応答量を抑える上限の目的は保つ。
親の見つからない子を画面自身が失敗として扱う案は、記録ファイルの削除などで親が一覧から消える正当な状態でも失敗するため採らない。

### 右ペインの見出し

右ペインの見出しはエンジン名と、取得できた記録ではセッション名を`<エンジン名> / <セッション名>`の形で表示する。
ホスト名と作業ディレクトリは左ペインの一覧項目が示すため見出しから外し、エンジン名は一覧に無いため残す（2026年10月20日のユーザーの回答）。
名前を取得できない記録は空欄や代替の文字列を表示せず、エンジン名だけを表示する。
セッション名は画面の他の場所に無いため、見出しは長い名前も省略せず折り返して全文を表示する。
末尾を省略する表示は、狭い幅や拡大時に全文へ到達する手段が無くなる（2026年10月のユーザビリティレビューで320px幅の省略を観測）。
セッション名は詳細APIの`session_name`で返す。
Claude Codeは記録の最後の`custom-title`の`customTitle`（`/rename`などで付けた名前）を使い、無ければ最後の`ai-title`の`aiTitle`（Claude Codeが生成した題名）を使う。
抽出は`session_record_format.py`の`claude_session_name`が持つ。
リモートの記録も転送された本文からサーバー側で同じ関数を使う。
Codexのthread名はロールアウトの記録に無く、`<CODEX_HOME>/session_index.jsonl`のthread IDが一致する最後の行の`thread_name`だけが持つ。
ローカルはサーバーが`codex_home`のファイルを読み、リモートはヘルパーの`read`応答の`thread_name`欄で返す。
欄を返さない旧版のヘルパーでは名前なしとして扱う。
これらは製品の内部形式であり、形式が変われば名前を取得できずエンジン名だけの表示に戻る。
