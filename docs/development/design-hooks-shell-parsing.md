# Bashコマンドの解析とheredoc遮断の設計記録

[設計記録の索引](design.md)から参照する、Bashコマンドの解析とheredoc遮断の記録である。

## フックの責務境界

### Bashコマンドの解析とheredoc遮断

Bashの引数所属と出力接続は、`_common/bash_invocations.py`の`extract_bash_invocations`が解析する。
外側の語と能動的な置換内の呼び出しを分け、引用・エスケープ・入れ子と、展開結果が未確定であることを保持する。
出力接続はパイプ、背景化、リダイレクトを区別し、記述順とグループへの継承から判断する。
複合文の条件と本体は同じ解析で実行位置として扱い、for・算術for・select・while・until・if/elif/else・caseの入れ子にも文全体の接続を継承する。
反復値、caseのパターン、引用した予約語、算術式のデータと未実行の関数定義は実行位置へ変えない。
各消費側で予約語を取り除く案は、入力の所属と接続の判定を分散させるため採らない。
未引用の`time`・`time -p`・`!`の反復と組合せ、`coproc`を文種の判定前に扱う。
coprocの名前は後続が複合文・グループ・関数定義の場合だけ取り除き、暗黙の標準出力パイプと背景実行を呼び出しへ継承する。
明示リダイレクトは記述順にその接続を上書きする。
引用された語、`/usr/bin/time`や`command time`、動的語を予約語の前置へ変えない。
PreToolUseの判定・書込先とPostToolUseの前景Git案内は同じ結果を使い、消費側固有の予約語除去を加えない。
未知の実行位置を推定して遮断する案と、置換を含むコマンドを一律に免除する案は、それぞれ誤拒否と外側の明らかな誤りの見逃しを生むため採らない。
助言や実行記録が使う`extract_execution_pipelines`の区間と実行位置の契約は、用途が異なるため保持する。
語の構文情報はどの経路でも`_common/shell_tokens.py`の`ShellWord`（`split_words`が返す）で共有する。
引用除去後の値に、引用の有無、展開の有無、引用の外側のリダイレクト演算子、元の語を添え、区間解析（`shell_segments`）と実行位置の解析（`bash_invocations`）の`tokens`もこの型を持つ。
区間と区切り演算子の組は`shell_segments.split_bash_commands`が返す。
消費側は引用を外した文字列から演算子を推測し直さず、`strip_redirections`は引用した`'>'`を引数として残す。
語の列を同じ構文として渡し直す場合は`join_words`で元の語へ戻し、`shlex.join`で再引用してリダイレクトをデータへ変えない。
共通化の対象は構文の認識であり、受理条件は用途ごとに保つ。
静的な読取計画は候補探索と案内の保留に使い、取得の確定は実配送本文の共通照会へ渡す。
警告候補は`;`と改行の連結も読取として扱う。
待機回収、検証コマンドの限定文法、CLI例の検査も同じ表現から各自の受理条件を評価する。
2026年11月3日、引用属性を失ったトークンを消費側が再解釈する構造と、取得判定の独自の字句解析が別々の解析修正を反復させていた観測を受けて改めた。
引用・エスケープの対照入力と演算子の対照入力は、`_hooks/shell_syntax_contrast_test.py`が解析APIの判定を確かめる。
最終結果は各消費側の公開入力の試験が確かめる（`pretooluse/shell_checks_test.py`の警告、`pretooluse/read_delivery_test.py`の取得記録、`_agents_server/codex_test.py`の待機回収）。
第三者のparserへ置き換える案は、heredoc・埋込記録・部分入力の既存契約を再実装する費用に見合わないため採らない。
文書書込の判定には、引用を除き展開部分を未知印で保持した`static_tokens`と`static_outputs`を別に渡す。
既存のtokens・arguments_known・outputsは変更しない。
入出力先の確定度は、実行位置や引数全体の確定から独立させる。
`extract_bash_effects`は、実行するコマンドが未知の文（`$COMMAND > out`、リダイレクトだけの文、前置代入だけの文）も`execution_known=False`の呼出しとして返し、書込先の判定は構文から確定した出力先をコマンドの確定によらず使う。
未知の実行の後はcwdを不明として扱う。
実行位置の判定（`extract_bash_invocations`）は未知のコマンドを既知の実行とみなさない契約を保つ。
2026年10月31日、未知の実行の静的出力先が書込先から消え、資料の未取得による保護を通過した観測を受けた変更である。
同じ考え方を各消費側にも適用する。
`sh -c`の本文は本文自身の語だけで確定を判断し、後続の位置引数が未知でも静的な本文を解析する。
読取候補と原記録の参照案内は既知のファイル引数を残し、取得済みの判定は実配送本文を使い、構文の確定度と区別する。
commitメッセージの確認は`--`より後ろの未知のpathspecを無視し、それより前の未知の語では判定しない。
未知の展開を含むパスは実パスとして確定しない。
文書種別の識別に限り、最後の未知印以降が`/`で始まる末尾を部分情報として使い（`$ROOT/path.md`の末尾`/path.md`を実在の場所へ変換しない）、環境変数を評価せずに判定する。

呼出しごとの作業ディレクトリは`_common/shell_cwd.py`の`bash_invocation_cwds`が所有する。
Bash解析が保持する作用範囲を使い、サブシェル、パイプの要素、背景実行、コマンド置換の移動を子環境へ閉じ、波括弧と複合文の移動は後続へ渡す。
未知の展開と`popd`の後は位置を不明として保持し、絶対パスへの移動で解決を再開する。
読取・書込・commitのメッセージファイルと成果作業の帰属は同じ結果を使い、消費側ごとの移動追跡と元のcwdへの代用を避ける。

読取述語の定義は`_common/bash_invocations.py`の`is_read_predicate`が所有し、PreToolUseとreview-sessionが共用する。
`shell_checks.py`は同じBash解析の標準エラーの最終接続先がリテラルの`/dev/null`となる述語を、診断喪失による誤判断を防ぐため実行前に警告する。
リダイレクトを記述順に適用するため、`>/dev/null 2>&1`は警告し、`2>&1 >/dev/null`と`2>errors.log`は診断を保持する形として通す。
前置、`xargs`、シェル本文、グループ、複合文と置換にも同じ判定を適用し、実行名と接続先を静的に確定できない入力は推定しない。
両ホストの入力と各接続の対照は`shell_checks_test.py`が確かめる。

原セッション記録の本文参照も、共通の呼出解析と静的な読取対象から判定する。
`pretooluse/large_reads.py`は設定ホームからClaudeのprojectsとCodexのsessionsを解決し、Read・Grep・Bashの本文読取や検索へ既存の`session-review-evidence`の照会を案内する。
Bashでは読取コマンドの入力パスと静的cwd、Pythonの直列に実行されるliteralの読取を扱う。
Pythonの読取と文書書込は同じ`python_file_paths`で代入・実行位置を解析し、対象操作だけを分ける。
未知のコードと外部スクリプトの内部へ解析を広げない。
属性確認、パスの表示、正式な抽出・準備と派生証拠の処理は除く。
大容量の原記録の警告でも専用CLIを案内し、一般本文には`sed -n '<開始行>,<終了行>p' -- <絶対パス>`の行範囲の分割取得を案内する。
案内の目的は原記録を手で読み直す反復を減らすことであり、新しい証拠CLIと判定状態は加えず、反復による遮断へ昇格しない。
コマンドを使え、実行が許可される担当には専用照会を案内する。
実行できない担当には原記録の識別子・位置・照会内容を委譲元へ返し、抽出済み資料を受け取る手段を併記する。
同じ能力条件を単一・複数の大量本文読取と、PowerShell・lockfile・manifestの編集通知にも適用し、対象パスと必要な修正・再生成を引き渡せるようにする。
受信側の能力台帳を加えず、手元のツールと依頼された権限から手段を選べる。

Bashの原記録検索では、ファイル名・件数だけを返す`-l`・`-c`と対応する長いオプション、grep系列の`-L`を除外する。
検索語・オプション値・`--`以降のデータを指定と誤認しない。
`rg -L`はシンボリックリンク追従のため本文参照として扱う。
記録横断の所在探索には`rg -l -F -- '<文字列>' <記録のディレクトリ>`を案内し、本文は各パスを`--transcript`へ渡して照会する。
`--fixed-string`は単一の`--transcript`だけで使い、期間と親セッションの一覧にはカタログを使う。

コンテナー起動では`docker`・`podman`の`run`・`create`（`container`経由を含む）を既存の実行位置解析で判定する。
rootまたはユーザー未指定で書き込み可能なbind mountを渡す場合は、ホストへroot所有の生成物を残した事例に基づいて警告する。
読取専用mount・非root指定・名前付きボリューム・composeは除く。
イメージの既定USERは追加照会せず、正当なroot実行も継続できる警告にとどめる。
読取専用ソースを専用ボリュームへ複製する構文と、ホストのUID・GIDを渡す構文を通知する。

heredocの区切り語は、bashと同じく引用を除いた語で終端行と比べる。
区切り語のどこかに引用（`'`・`"`・`\`）があれば本文を展開しない区切り語として扱い、`\EOF`・`E"OF"`も`'EOF'`と同じ終端行`EOF`で閉じる。
本文の範囲と展開の有無は`_common/heredocs.py`の`heredoc_bodies`が1つの定義から返し、本文のマスクと置換の遮断が同じ結果を使う。
本文はいずれも実行位置として扱わずにマスクし、本文に書いた文書の文字列（`pkill`などの禁止語）への誤遮断を防ぐ。
区切り語を引用しない本文のうち、エスケープされていないバッククォートと`$(`（`$((`の算術展開を除く）だけはbashがコマンドとして実行するため、`shell_checks.py`の`_check_bash_unquoted_heredoc_substitution`が実行前に遮断する。
外側のコマンドに加え、`sh -c`・`bash -c`の引数とコマンド置換の本文の中のheredocも対象にする。
置換の内側を既存の判定へ渡す案は採らない。
本文の置換は全て遮断するため内側を個別に判定する必要が無く、事象の`atk wi add`のように既存のどの判定にも当たらない置換も防げないためである。
heredoc本文のマスクを除く案も採らない。
本文の文字列への誤遮断が戻るためである。
