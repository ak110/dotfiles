# 方針・意向: 計画レビュー廃止の経緯

## 計画レビュー廃止前の運用（2026年9月13日まで）

本節に残る計画レビュー、計画型AWI、二ファイル書式およびモデル分岐の記述は、2026年9月13日の変更より前の判断経緯を示す。
現行の実行契約は同日の変更以降の規範が定める。

- 2026年9月13日、ユーザー指示により、計画レビューを廃止し、計画の起草者であるレーン担当がそのまま実装と変更範囲の検証までを担う方針へ改めた
  - 計画は1ファイル書式とし、計画型AWIと計画変換を廃止する
  - 実装系モデルは`high_tier_model`（現行はexecute工程）へ一本化し、レーンでは変更範囲の検証だけを実行する
  - 全体検証はCIへ委ね、ローカルではCIが実行しない検証だけを実行する。
    現行の適用規範は`agent-toolkit:commit`の`references/publish.md`「検証とCI」と、変更範囲の検証の対象選定を定める`agent-basics:check-execution`の`references/verification-scope.md`である
  - `agent-toolkit:write-plan`をメインが起動した場合は、追加worktreeを作成せず現在のworktreeで実装する
- 計画ファイルは複数の要求単位を統合して作成し、要求単位ごとの細分化は例外とする。
  計画ファイルとレビュー指摘管理表を
  要求単位ごとに起草・維持して計画レビューを別個に反復する固定費が、レビューのコストを押し上げるためである
  （2026年9月5日、ユーザー指示）
- 第2ラウンド以降はメインがレビュー指摘管理表を読み、未解消行を違反契約および発生条件で比較して、同じ2要素を持つ指摘の未解消と新たに成立した欠陥の順に最初に該当した遷移を1つ選ぶ。
  同じ違反契約の指摘が2ラウンド連続した時点で構造的な対処へ切り替え、レビューの往復回数を減らす。
  前提または検収手段の成否が確定しないレビューはcheckpointが返らないため、続行できない理由として受け取り、その手順で扱う。
  ラウンド数だけを根拠として指摘を放棄せず、上限へ到達した場合はその論点を今回の計画に含めなければ成果物が技術的に成立しないかを判定する。
  含めなくても成立する論点は次回のAWIへ分割する。
  計画レビューの上限と判定手順を定めていた`agent-toolkit/share/review-loop-coordination.md`の`## 計画レビューの打ち切り`は撤去済みである
