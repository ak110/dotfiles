# 障害・欠陥の記録: 要求と判断の脱落

[障害事例集の索引](incidents.md)に区分の定義と事例の書式を示す。

## 要求と判断の脱落

- 2026年9月8日: 振り返りが、大幅な改善を求めたユーザー介入を成果の説明段落で是正と認めながら、候補別の判定記録の行へ対応させなかった。
  この介入への処置は要求単位の本文を書き換えるだけで終わった。
  直接原因: 完了条件の条件列が「該当する行が残る間は」と行を主語に置き、行が存在しない介入を判定の対象にできなかった。
  `処置`欄が成果物への修正と再発防止策を分けて要求していなかった。
  背景原因: （混入要因）工程を簡素化して抽出専任の委譲を省いた処理回で、簡素化した手段とともに全件一覧と表の対応の検収も実施しなかった。
  対策: 表の確定前にlocator集合の一致を確認する規則を表の作成手順へ置き、完了条件の判定対象へ行の不在を含める。
  `処置`には成果物への修正と再発防止策を判別できる形で記録し、成果物を書き換えただけでは再発防止策に数えない

- 2026年9月8日: 「抜本的に手順やスクリプトを見直して大幅な高速化を達成できるようにしてね」という改善効果の指定を受領した後も、局所の不具合の調査が先行し、現行構造を維持する案と変更する案の比較が行われなかった。
  直接原因: 改善効果を採用案の受入条件として先に確定し、個別調査を構造の維持案と変更案を比較する設計判断に結び付ける規定が無かった。
  対策: `agent-basics:review-standards`の`references/reviewee.md`へ改善効果を指定する要求の扱いを新設し、受入条件の確定と維持案・変更案の比較を個別調査より先に置く

- 2026年9月8日: 振り返りの対象セッションを選ぶコマンドが更新時刻の最新の1件だけを条件としたため、対象リポジトリで稼働していた対話セッションを返し、振り返り担当が観測境界より後の増分を理由に停止した。
  直接原因: 選定側が更新時刻の新しさだけで対象を選び、消費側が対象の終了と起動方法の双方を前提としていたため、選定条件が消費側の成立条件を満たしていなかった。
  対策: 選定条件へ`agent-toolkit:process-wi`の起動標識と、対象の最終更新が自身のセッションの開始より前であることを加える。
  セッションを選ぶ条件は、そのセッションを消費する工程の成立条件と同じ変更単位でそろえる

- 2026年9月9日: 依頼した成果へ到達する前に部分結果を示し、続行の可否をユーザーへ質問して工程を停止する応答が繰り返された。
  直接原因: `agent-toolkit/rules/01-agent.md`「完遂と先送り」が`AskUserQuestion`の回答待ちと承認待ちを無条件の例外とし、例外を適用する際に質問が同ファイルの確認要件を満たすか判定させていなかった。
  対策: 「協調と自律」、「確認を要する事項」、適用中のスキルのいずれかが定める条件を満たす確認に限り、質問待ちと承認待ちを例外として扱う。
  依頼と成立済み承認の範囲の内側にある実行可能な未完了工程は、続行可否を確認へ変換せず同じターンで継続する

- 2026年9月21日: 確認、AWI投入、終了判定および検証通知で、既存の分類や状態値を先に適用した結果、ユーザーが示した要件と未回収の結果が工程から脱落した。
  直接原因: 発話原文と成果物種別の境界を分類より先に保持する契約、未回収結果を継続中とする共通判定、用途別の具体的な修復案が直接消費側へ届いていなかった。
  対策: 原文保持と優先順位判定をユーザー確認の前段へ置き、AWI専用境界を主題分類より先に適用する。
  未回収のagents_server結果をStop共通判定へ加える。
  外部パスのチェック、機械識別子の言語判定除外、切り詰め用途別の修復案は自動チェックで固定する
