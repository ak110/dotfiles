# 方針・意向: 実行環境とブラウザー資産

## 実行環境と表示

- codex呼び出しの`sandbox: danger-full-access`指定を弱めない（障害対策）。
  他の値では相手プロセスが承認待ちから復帰せず完了を検知できない。
  弱体化改変は過去に複数回発生し、ユーザーが都度差し戻した（incidents.md参照）。
  本方針は旧blocking MCP連携の入力契約に対するものであり、`agents_server`連携へは適用しない。
  現行の扱いは`agent-toolkit:delegation`の`delegation/references/runtime-routing.md`が定める
- Windows（CP932・PowerShell・パス区切り）での動作を常に考慮し、subprocess境界はUTF-8を明示する
  （障害対策。デコード失敗・文字化けの反復観測に由来。incidents.md参照）
- コーディングエージェントの稼働状況をユーザーへ示す表示では、ユーザーに見せてはならない情報は存在しないものとして扱い、
  表示できる範囲の情報をすべて含める。
  秘匿値が現れ得ることを理由に、ツール呼び出しの引数、コマンド文字列その他の入力を表示から除かない
  （2026年9月15日、ユーザー指示）。
  `agents_server`のstatusline表示がツール名だけを載せ、同じツールを繰り返す区間で稼働と停止を区別できなかった観測に由来する。
  現行の実装契約は[design-agents-runtime.md](design-agents-runtime-statusline.md#statuslineの表示)の「statuslineの表示」にある
- `atk wi process-loop`は登録した全対象を1つの統括会話で処理し、常駐の端末の前景で対話CLIとして起動して、ユーザーが処理中の画面を見て直接入力できる状態を保つ。
  会話を対象ごとに分ける変更、通常の起動を非対話CLIへ置き換える変更、予約のない前回会話の再開は、新しいユーザー判断なしに導入しない
  （2026年11月17日、ユーザー指示）。
  同15日の変更はこの3つを伴っていた。
  ユーザーが求めていたのは、統括が柔軟に采配して単位時間あたりのWI処理数を上げることである。
  現行の起動形は`agent-toolkit:workflow-overview`の`references/orchestrator-runtime.md`「起動形の比較」が定める
- 同一の変更がpushとPR/MRで重複してCIを起動することを避ける1回限りのCIスキップは許可の対象とする。
  リポジトリまたは組織のチェック設定を変える操作（必須チェックの解除、branch protectionの変更、ワークフローの無効化）は、この許可に含めない
  （2026年9月17日、ユーザー指示。一時的にCI無効でpushする手順を持つプロジェクトがあるため）
- 実行中の依頼、WIまたは確定済み要件を実現するCI関連の外部サービス設定は、全agent-toolkitユーザーと全リポジトリで個別確認なしに変更する。
  CIの実行・入力・権限・認証情報・保護・結果報告・合否判定へ直接作用する設定を対象とし、CI用secretsの作成・変更も含む。
  サービス名による閉集合にはしない
  CIと独立した公開・配信設定や副作用、目的・要件の変更、権限拒否は対象外とする。
  安全な対象解決と影響・復元方法の事前説明に加え、結果報告も維持する。
  この2026年10月6日の恒久方針は、2026年9月17日の1回限りのCIスキップ許可より広い認可であり、個別作業だけに限定しない
  （2026年10月6日、ユーザー指示。対象は全agent-toolkitユーザーであり、secretsも全て含める）
- 常駐ループのセッションで無進捗の反復を検出した場合は、通知や再促に留めず、常駐処理へ中断を要求し、セッションが終了するまで処理する
  （2026年9月17日、ユーザー指示。auto modeの拒否で工程が進まない状態が続くと、目標評価と無進捗ターンの往復がトークンを消費し続けるため）
- dotfilesが管理するコマンドは、dotfiles管理下のバイナリ（miseの導入物など）へ統一する。
  同名のコマンドをdotfiles外で導入したもの（WinGet、npmのグローバル導入、standalone pnpmなど）は、導入元の正規の手順で削除する。
  導入元の中身ごとの所有確認や、同じ導入元に含まれる別のコマンドを残すための条件は設けない
  （2026年11月18日、ユーザー指示。dotfiles外の導入物との競合で動作がおかしくなる事象が過去に繰り返したため）。
  自動で削除する導入元と、削除せず案内に留める導入元は`pytools/_internal/prune_foreign_tools.py`が定める

## 配布するブラウザー資産

`atk serve`の表示を補助するMermaidのようなブラウザー資産では、取得方式と版数が可用性、供給元の信頼、表示結果を変える。
対話で確定した方式はコード近傍と本節へ理由を残し、後続のエージェント判断だけで別方式へ置き換えない。
置き換える場合は、変更後にエンドユーザーが観測する結果、採用理由およびトレードオフを事後承認型UWIで報告する。
Mermaidは`agent-toolkit/agent_toolkit/_atk/serve/static/plans.js`の`mermaid@12.0.0`とSRIを維持する。
2026年9月13日のユーザー指示は、対話で確定した判断の無断変更を禁止し、変更時の事後承認型UWIを求めるものである。
常時最新版へ戻すことは同指示の対象外である。
