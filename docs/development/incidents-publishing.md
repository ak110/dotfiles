## 公開とリリース工程の未完了

- 2026年9月6日: ベースbranchへ直接commitした未公開の変更を残したままセッションを終了し、後続のprocess-loopの開始前更新が`chezmoi git pull --rebase`の衝突で停止して次セッションが開始しなくなる事象が多発した。
  直接原因: 公開工程の検収は、ベースbranchのローカルOIDとリモート追跡refのOIDがpushした完全OIDと一致することだけを対象とし、作業ツリーのclean状態とrebase・merge・cherry-pickの中断状態はどの工程でも観測していなかった。
  このOIDの一致確認は公開担当の返却時に1回だけ行われ、その後の工程を経た状態は対象に入らない。
  未公開のcommitがこの確認を通過して残った具体的な経緯は特定できておらず未確定である。
  対策: 公開担当の返却へベースbranchの公開状態の観測結果を追加し、メインが固定報告の前にも同じ項目を観測する。
  前者は返却時点、後者は以降の工程を経た後の状態を対象とし、未確定の経緯を含めて検出する。
  解消できない場合はUWIへ引き継ぐ

- 2026年9月6日: `agent-toolkit:process-wi`の3回目の公開担当が全体の自動チェックの途中でユーザー指示により中断し、版数更新だけが未コミットで残った状態をメインが手動でcommitして終えた。
  直接原因: `agent-toolkit/share/session-termination.subagent.md`「生成物とpush」が版数更新と派生manifest同期の後に検証を置く順序だけを定め、版数更新で生じた差分のcommitまでを連続して行うよう要求していなかった。
  対策: 版数更新、派生manifest同期、生成同期の確認から一連の差分のcommitまでを続けて実行する。
  版数更新だけが未コミットで残る状態で工程を終えないことを同節へ定める

- 2026年9月7日: `agent-toolkit:process-wi`の公開担当が工程の途中で3回連続して応答を停止し、委譲元が主作業ツリーのGit状態、一時領域のファイルの更新時刻とセッション記録から到達点を再構成した。
  直接原因: 複数の工程を順に処理する委譲先の到達点と確定した判断が、その委譲先のコンテキスト内にしか残らず、成果物へ記録されなかった。
  対策: 起動側が引き継ぎ記録先の絶対パスを起動文へ渡す。
  委譲先は工程の区切りごとに完了した工程、確定した判断、残る工程および再開位置を指定された記録先へ上書きする

- 2026年9月29日: pyfltrとglatasksの処理回で、公開担当の初回公開後に統合された是正commitが未pushで残った。
  直接原因: 重複公開を防ぐ条件を、新しい公開対象の有無を見ずに公開担当の起動回数1回で表し、後続成果を次のセッションへ送る手順になっていた。
  対策: 前回push後の新しいcommitがベースbranchへ統合された場合だけ公開手順を再実行し、追加差分の版数、固有工程と延期adoptを渡して、最新HEADのpushとCI成功を同じセッションで検収する

- 2026年10月19日: `atk wi process-loop all-repos`の実行で、各リポジトリ担当が振り返りを「委譲されたセッションなので起動判断を委譲元へ返す」として省き、dotfiles以外の担当は報告用UWIも「委譲先の完了報告は適用外」として省いた。
  ユーザーが報告用UWIの回答で是正した。
  直接原因: agents_serverの通常委譲の配送文がメインと最上位セッションへ限定した条文を適用対象から外し、review-sessionとreport-completionも委譲先を除外していた。
  all-repos担当の委譲元はエージェントではない常駐プログラムであり、返却された判断と依頼を誰も処理しなかった。
  背景原因: （根本原因）規範が工程の担い手を起動位置で定め、委譲先が残す工程は委譲元のエージェントが受け取ることを前提にしていた。
  all-reposの導入はprocess-wiのメインの役割を担当へ移したが、担当へ届く配送文と役割限定の条文の適用結果を点検しなかった。
  対策: `agents-server-delegate.md`で、最初の入力が`source="process-loop"`の`atk-auto`要素である担当を対象リポジトリのprocess-wiのメインとして扱う。
  `all-repos-orchestration.md`「担当の役割」に完了報告・振り返り・WI投入・UWI確認・メイン向け規範の読込を定めた。
  review-session、report-completion、finish-sessionとガイドを同じ契約へそろえ、標識値の一致を`launch_prompts_test.py`で検出する
