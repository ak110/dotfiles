# 正常な否定結果と失敗署名の設計記録

[設計記録の索引](design.md)と[振り返り・知見集約の設計記録](design-session-review.md)から参照する主題別の記録である。

読取述語の終了1は診断が空なら正常な否定結果として扱う。
述語の定義は`_common/bash_invocations.py`の`is_read_predicate`をPreToolUseと共用し、リダイレクトを持つ単独の実行位置は`extract_bash_invocations`から得る。
`rg ... 2>/dev/null`の診断保持の不備はPreToolUseが警告し、診断を保持した再取得を案内する。
review-sessionの失敗候補と台帳では正常な否定結果を除く。
標準出力だけをファイルへ保存する単独の`rg`も、診断が空で終了1なら一致0件として除く。
終了2以上、他のコマンドの失敗、終了状態を単独の述語へ帰属できない接続は候補へ残す。
静的に確定しない実行名・構文から正常な否定結果を推定しない。
台帳も既存の読込時再判定で同じ除外を適用し、リダイレクト付きの否定結果を計数と書き戻しから除く。
`atk run-script session-review-evidence`は生成側の3接頭辞を参照し、`失敗:`と`警告:`を伴う結果、別コードと連結したコマンドを候補へ残す。
先頭の`cd <パス>;`か`cd <パス> &&`の前置1つは後続の単独のコマンドの終了コードと出力を変えないため、除外判定の前に外す。
外した結果の判定は全ての除外区分で共通の処理（`session_evidence_candidates_commands.py`の`_event_without_cd_prefix`）が担い、区分ごとに前置の扱いが分かれないようにする。
出力に`cd:`の診断行がある場合は後続のコマンドが意図した場所で動いていないため前置を外さない。
サブコマンド名を列挙する案は同じ契約を持つ追加のコマンドへ追随する維持費を生むため採らない。
PowerShellの文字列`-Command`は確定できる単独コマンドだけを同じ分類へ渡す。
PSの引用・backtickとWindowsパスを保持し、式・展開・連結と対応外の実行モードは候補へ残す。
先頭1個のcd前置は同じ共通処理で外し、`Set-Location`の診断を伴う結果は外さない。
署名も同じPS解釈を使うが、候補と個別証拠は元の包装コマンドと位置を保持する。
POSIXの引用解析だけをPSへ適用する案は引数を変えるため採らず、完全なシェル評価器も不要なため採らない。
単独の`atk run-command`の子結果への帰属には、公開CLIの保存JSONの子argv・終了コード・時間切れ・signal・記録所在と出力バイト数の比較を使う。
正常な否定は子の両出力が空の場合だけ、検証の検出は既存の検証分類で除く。
不正・不足JSON、子診断を持つ検索、時間切れ・signal・保存失敗・不一致と連結は元の候補へ残す。
包装の定型案内を子の異常診断へ混ぜる案は正常な否定を誤分類するため採らない。

委譲返却に`気付いた改善点:`の行がある場合は、返却値・適合判定・shellの正常終了より先に分析対象として候補へ残す。
表示用の先頭2000文字の短縮は維持し、省略区間にある標識行だけを行全体で保持する。
短縮境界をまたぐ標識行は部分的な行を完全な行へ置き換え、記録形式が違っても同じアシスタント本文の生成で扱う。
メインの本文も行を保持するが、委譲返却の分類は既存のrecordの区別を使う。
正常除外の全廃は雑音を戻し、短縮の全廃は表示量を増やすため採らず、既存の本文と候補の保存へ必要な行だけを渡す。

失敗したコマンドとツールは実行ファイル、サブコマンド、終了コード、診断を正規化した失敗署名で集約する。
`atk run-script session-review-prepare`は状態ディレクトリへ署名と最上位セッションIDをロックと原子的置換で記録し、過去30日に2セッション以上で観測した署名だけを個別分析の候補へ残す。
単発の失敗は件数表へ置く。
Codex記録のコマンドはシェル起動の内側の本文と診断の末尾を表示する。
記録は再実行で同じ組を増やさず、期限を過ぎた行を回収し、破損した行の件数を結果へ示す。
過去の全記録を振り返りごとに再走査する案は、2026年9月時点でClaude Code 771ファイル約795MB、Codex 776ファイル約1524MBあり、3.6MBの記録1件の抽出に1.64秒を要したため300秒の目標に収まらない。
失敗候補を全件個別判定する案では反復した失敗が毎回単発として見送られ、候補自体を廃止する案では改善対象を失う。
台帳の各記録は、候補の除外判定と署名計算が読むイベントの欄を代表イベントから写して保持する。
準備は台帳を読むたびに、その欄へ抽出と同じ除外判定（`session_evidence_candidates_failures.py`の`failure_candidate_exclusion`）と署名計算を適用し、現在の判定が除く記録を数えず、書き戻す台帳からも除く。
候補であるという記録時の結論と署名だけを保存する形は、除外規則を後から広げても旧規則で記録した失敗を期限の30日まで反復に数え、2026年10月には単独の`atk wi grep`の一致0件と単独の`atk agents wait`の終了コード3が正常な結果として除かれた後も反復の計数に残ったため採らない。
規則の版を記録へ付けて版が変わった記録だけを判定し直す案は、識別子と版の管理を加える一方で全件の再判定が2,400件で約1.7秒に収まるため採らない。
旧形式の記録を一律に破棄する案と規則の改訂ごとに台帳を初期化する案は、反復の判定に使っている履歴を最長30日失うため採らない。
