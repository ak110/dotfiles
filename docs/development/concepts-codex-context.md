# 方針・意向: Codexの文脈長

## Codexの文脈長設定

目的は、頻繁な自動圧縮による待ち時間と作業の進行阻害を避けることである。
2026年10月9日のユーザーの明示的な復元要求で導入し、10月23日に削除した。
2026年11月1日の次のユーザー指摘を受けて復元した。

```text
あとcodexのコンテキストが足りないならconfig.tomlで拡張した方がいいのでは？明らかにそこの問題で進行が阻害されてるじゃん。
```

2026年11月23日、ユーザーが自動圧縮の境界をClaude CodeとCodexの両方で400kにそろえるよう指示し、`model_auto_compact_token_limit`を900000から400000へ変えた。

```text
250kは小さすぎるのでいったん400kに揃えよう。Claude CodeもCodexも。
```

- `model_context_window=1000000`は保つ。
  これを減らす、またはモデルの標準へ戻す変更は、別の改善で圧縮の頻度と待ち時間が許容範囲に下がることを、実作業の記録で観測してから行う。
  設定の生成結果とテストの一致は、この目的の達成を表さない。
  10月23日の削除は「別の改善である程度改善されるなら減らすかデフォルトにする余地は無いか」という条件付きの問いを、条件を観測しないまま採用したものだった
- `model_auto_compact_token_limit`の400000は、Claude Codeの`autoCompactWindow`と同じ値に保つ。
  変える時は両ホストを一緒に見直す
- 設定値はCodexへの宣言であり、モデルが実際に受理できる上限とは別である。
  100万トークンの実受理やモデル能力の変更は保証しない
