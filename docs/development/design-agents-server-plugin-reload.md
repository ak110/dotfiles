# Claude委譲先のプラグイン再読込の設計記録

[設計記録の索引](design.md)から参照する、Claude委譲先のプラグイン再読み込みの記録である。

`_agents_server/claude_plugins.py`は有効なプラグインの実体と、子Claudeが読む設定・導入一覧のファイル変更を監視する。
利用対象の不正や、入力と応答の不一致は診断可能な失敗とする。
Claude backendの所有タスクは進行中のturnを中断せず、idleになってから同じSDK接続へ`reload_plugins`制御要求を送り、保留された次の入力より先に反映する。
SDKの専用公開methodが無いため、制御要求のprivate APIへの依存は局所adapterに限定する。

サーバー自身が実行する`SERVER_PLUGIN_ROOT`の保持版と、子Claudeへ渡す更新可能なプラグイン実体を分離する。
開発checkoutは元のrootを監視して再読み込みする。
兄弟ディレクトリで準備して固定読込先を切り替え、失敗時は前の有効な実体を保持する。
登録済みのコマンドhookとFunction hookの起動先は、設定を読み込んだ世代のディレクトリに固定する。
委譲先へ案内するスキル・手順書の場所も、SDKが確認した世代のディレクトリとする。
MCPの起動先は設定と同じ世代とし、agents_serverは接続元の保持版に固定したままとする。
差し替えと復元が動かすのは次の読み込みに使う固定名の複製だけであり、登録済みのhookの起動先は動かさない。
既に読み込まれたhookが起動できるよう、世代のディレクトリはCLIの終了確認まで保持する。
現行導入先は子と同じCLI・cwd・設定読み込み条件の`claude plugin list --json`から解決し、無効なプラグインを有効化しない。
版付き入力の導入先選択と固定mirrorの構成は起動に不可欠であり、失敗時は起動しない。
静的な明示入力が確保されている場合の一覧取得不能と、監視開始・再開の外部失敗は補助機能の境界へ分離する。
失敗した監視を停止・回収し、自動再読み込みを無効にした診断を残して、確定済み入力で同じ接続の作業を続ける。
監視を再開するには原因を解消して新しい委譲を開始する。
利用対象の不正や、所有資源の停止・回収に失敗した状態を隠す縮退は行わない。
一覧取得のtimeoutは共通helperが停止未確認も同じ例外で返すため、補助失敗として吸収せず、初回起動と更新時の所有タスクへ停止確認不能を伝える。
mirror内のagents_serverのMCP起動定義はserverの保持版へ固定し、Python実行基盤をskill・modsの更新から分離する。
監視threadを停止し、CLIの終了を確認してからmirrorを回収する。
CLIを回収できない場合は入力を保持する。
サーバー保持版の書き換え、`add_plugins`の反復、サーバーや子Claudeの自動再起動は、実行中コードと読込先を不安定にするため採用しない。
