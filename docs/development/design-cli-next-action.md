# 失敗と警告の次の操作の設計記録

[設計記録の索引](design.md)から参照する、失敗と警告の次の操作の記録である。

## 失敗と警告の次の操作

失敗行と警告行には、続く行に`次の操作:`で始まる次の操作を必ず置く。
結果行だけで成否は確定しても、事実だけを受け取ったエージェントは次の行動を推測で選び、実行できない操作や同じ失敗を繰り返した（`atk`の引数エラー、agents_serverの`unknown session`、hookの警告などで観測した）。
`report_failure`と`report_warning`は理由と次の操作を別々の必須の引数として受け取り、次の操作を欠いた呼び出しを失敗させる。
警告の出力条件は「atkの出力に含める情報」と`agent-basics/skills/writing-standards/references/program-messages.md`のエージェントが読む出力の規定に従う。

共通起動の持続状態の警告は`outcome.report_persistent_warning`を通し、同じ会話で同じ内容を1回だけ出力する。
会話識別子は`AGENT_TOOLKIT_OWNER_SESSION`、`CLAUDE_CODE_SESSION_ID`、`CODEX_THREAD_ID`の順に解決し、識別子の無い端末では毎回出力する。
委譲先では共通起動の掃引警告を出力しない。
`hook.py`起動時の引数不整合（usageと未知のサブコマンド）の通知は、標準入力の`session_id`で重複を抑止する。
各hookの同一条件の通知は`notice_fingerprints`で重複を抑止する。

不正な管理情報を持つ項目の確認先である`atk wi show <ファイル名>`は種別と`target_repo`を検証せず保存内容を表示する。
失敗の案内が、失敗を起こした状態のまま実行できるようにするためである。
指定名の探索とファイル名の検証を持つshowへ集約し、状態ごとに`cat`などの別手段を案内する形は採らない。

次の操作を必須とする構造は`atk`以外の発生源にも同じ形で置く。
標識`次の操作:`、空の次の操作の拒否、理由と次の操作を持つ例外型（`ActionableError`）、標準エラーへの出力関数の4つは`agent-toolkit/agent_toolkit/_common/next_action.py`が持つ。
同モジュールは層の順序で最も前にあり、全ての層、公開スクリプトとスキル付属スクリプトから使える。
hookは`_hooks/notice.py`の`block_formatter`と`warn`区分の整形関数が解消手段`fix`を必須とする。
通知を届ける場合は同じ行を保持し、同じ条件の警告は初回だけ届ける。
`atk`は`WebInputError`を`ActionableError`の派生とし、各サブコマンドの実行を振り分ける処理が`_atk/cli_support.py`の`report_rejected`で理由と次の操作の2行を出力する。
Web APIの入力エラー応答は、`error`へ`str()`が返す理由だけを保ち、例外の次の操作を`next_action`項目として別に返す。
WI一覧から除外したファイルの警告も、`reason`の理由と`next_action`の修正・確認操作を分けて返し、WI画面は両方をテキストとして表示する。
理由だけを返していた間は、画面を使うユーザーが入力や保存ファイルの直し方を推測する必要があったためである。
`ActionableError.__str__`は理由だけを返す契約を保ち、理由文字列を使う既存の呼び出し元を変えない。
agents_serverはツール関数の登録の1箇所で例外を包み、`ActionableError`と想定外の例外を次の操作付きのエラー本文へ変える。
状態値だけを返す応答（配送の失敗、期限切れsessionの中断、待機の打ち切りなど）には`next_action`項目を加える。
`atk agents wait`、`wait_ci.py`、スキル付属スクリプトと計画ファイルの構造チェックも、非0の終了で同じ標識の行を出力する。

知識境界として、標識と必須性は`_common/next_action.py`、文面は各発生源、状態値の`next_action`項目はagents_serverがそれぞれ持つ。
受信時に参照できる位置は受け取ったメッセージだけであるため、次の操作をツールの説明文やエージェント向け文書だけに置く形は採らない。
却下した代替案は、本文中で次の操作を任意とし、レビューと規範で補う案である。
文面の正しさを確かめるレビューは次の操作の欠落と実在しない名前の案内を検出できず、観測した事象はいずれもレビューで検出されずに混入したため採用しない。
