# 計画と実行レビューの分担の設計記録

[設計記録の索引](design.md)

## 計画と実行レビューの分担

計画とテストへ手段を固定する前に、目的を使う側の結果へ戻し、既存操作だけで満たす案と比較する。
比較基準は`writing-standards/references/design-heuristics.md`の「自作機構の兆候と自問」へ集約し、新しい自己申告や別担当を設けない。

人間による計画自体の承認は求めない。
process-wiの1回の実行の全体を1件へ集約する案は、計画とレビューが前提とする単一Gitルートおよび単一HEADを表現できないため採用しない。
仕様と設計を導く原則は`agent-toolkit:atk-mode/references/conduct.md`「QCDと3段判定」が所有する。
実装の検証直後と履歴統合後、統合の検証後から同じ判断へ到達させ、統合前に初めて変更行の診断を見つける往復を防ぐ。
全検証を毎回ベースで二重実行する案は、警告を観測した検証だけの比較で結果を判定できるため採らない。

レビュー担当とメインが複数WIの本文を一括取得するときは、結果をセッションのmanaged-tempへ保存し、要求した全WIの見出しを確かめてから読む。
実行ツールの戻り値が切り詰められると後半のWI本文が欠け、逐語要求と完成条件の評価から漏れるためである。
計画の条項を根拠とする指摘では、先に対象WIの明示条件との両立を確かめる。
計画がWIを具体化した際の誤りを実装修正へ持ち込まないため、衝突時はWIの明示条件を優先する。
レビュー担当は衝突を差し戻し、メインが契約を確定する。
計画構造の自動チェックは他のチェックと同じシェル呼び出しへ連結せず、直接返された終了コード0だけを実装開始条件にする。

要件仕様件数が1件以上のラウンドと第2ラウンド以降のラウンドでは、メインが表を読んで介入する。
それ以外のラウンドでは、メインはレビュー指摘管理表を読まず、受領した指摘件数と要件仕様件数だけで次の指示を確定する。
採用案そのものを選び直せる主体はメインだけであり、要件と仕様に関わる指摘をレーン内で局所修正すると反復が止まらないためである。
上流要求と対象リポジトリ側の要求が混在する項目は`adopt`せず、所有資源を回収して固定の完了報告を返した後にメインが依存を更新して`inbox`へ戻す。
マージ許可は対象レーンが`統合完了`を返すまで有効とし、競合解消と再レビューを経た再収束では許可を再発行しない。
収束ごとに許可を失効させると、許可の再発行と統合完了が交差して、完了済みのレーンへ同じ統合指示が届くためである。
実行レビュー担当へ渡す開始時点の7文字以上の一意な短縮OIDは、渡す直前に対象worktreeで解決できることを実際に確認してから渡す。
範囲起点の誤りはレビュー対象範囲の取り違えと担当側の実行失敗を生むため、記憶と転記で識別子を組み立てない。

外部可視の変更を伴うことを担当AWIの本文から起草前に判定できる場合は、メインが承認を取得してからレーン担当を起動し、承認した操作、対象、影響範囲と承認の出所を委譲プロンプトへ渡す。
承認の回答を得られない場合はUWIを登録して依存を追加し、承認を得るまで承認を要するレーン担当を起動しない。
レーン担当は受領した承認範囲を詳細化した対象WIの`## ユーザー指摘の逐語引用`へ記録し、他の節はその承認範囲を参照する。
却下した代替案も同じ節へ記録する。

計画構造の自動チェックの終了コードを保存する新しいwrapperは、既存の独立コマンドと直接返却値の検収で要件を満たし、終了状態の保持と別の失敗要因を増やすため採用しない。
未承認のままレーン担当を起動して差し戻させる案は、起草前に判定できた変更でも起動と差し戻しの往復を生み、承認の取得時機が一意に定まらないため採用しない。
詳細な被覆報告とメインによる成果物再検収は、レビューイーとレビュー担当の責務を重複させるため採用しない。

実行レビューでは、`review_model`で選ばれたengineと実際の起動ツールの一致を
フックで強制せず、`agent-toolkit:atk-mode/references/model-settings.md`「工程別モデル設定」と実行レビューを起動するメインの手順で統制する。
フックは設定値、`<役割名>.subagent.md`および起動ツールを同時に観測できる一方、設定されたengineが実際に応答するかを
観測できない。
Codexを指定した状態で`agents_server` MCP自体を利用できない場合、
可用性に起因する正当な代替であるClaudeの起動まで遮断され、代替の候補が残らない。
指定からの逸脱は、代替時に記録する観測した失敗と実際に用いた組み合わせから事後に判定する。
