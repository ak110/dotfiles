# 証拠抽出の由来分離と記録IDの設計記録

[設計記録の索引](design.md)と[振り返り・知見集約の設計記録](design-session-review.md)から参照する主題別の記録である。

## review-sessionの構成と候補抽出

### 証拠抽出の由来分離と記録ID

確認回答はユーザー値と質問・選択肢へ由来分離する。
記録IDは物理記録から決め、役割は別メタデータで扱う。
一意な旧IDだけを互換別名として受理し、曖昧な別名は終了コード2で拒否する。
統計は全観測model・effort組を保持し、`--context-at`は事象以前の直近identityとlocatorを返す。
返却の分類は記録全体からturn単位へ変え、Codexのtask_complete、Claude Codeのend_turn、Antigravityのresultを境界にする。
後続turnの追加で先行返却が途中発話へ戻ると改善点とエスカレーションが候補から消えるためである。
作業位置とhandbackの判定も同じturnに閉じ、終了情報の無い旧記録は従来の最終本文の取得を使う。
全収集照会は共通の`record-provenance`を追加し、親の由来・起動mode・最初の配送の役割文書を本文イベントのlocatorとは分ける。
欠けた値はnullにし、追加イベントを各modeが独自に組み立てる案は母集団が分かれるため採らない。
照会の標準出力は、結果のイベントが`record`欄か配列要素（`locators`など）の`record`欄で参照する記録と、その`source_record`を根までたどった起動元の記録だけの由来を、共通の出力処理1か所で前置する。
全収集記録の由来を前置すると、委譲先の多い記録で結果が由来の行に埋もれるためである（2026年10月12日、`explore`の委譲先を653件持つCodexの記録への`--fixed-string`の出力674行のうち673行が由来だった）。
通常表示と`--bundle`が書くファイル（`timeline.jsonl`と、由来を前置する`warnings`・`stats`・`hook-notices`の各ファイル）は全収集記録の由来を保つ。
`session_review_prepare.py`が`timeline.jsonl`から候補の記録とその起動元の由来を取得するためである。
`candidates.md`は共有の記録索引へ同じbundleの`record-provenance`に基づく由来を示す。
表示外の由来は同イベントから取得でき、由来の無い記録はそのことを示す。
2026年10月10日のprocess-wiの1回の実行で、メインが候補の1行の要約（引数のパスやコマンド）から実行主体を推して誤った帰属を要求へ書いたためである。
由来を保持せず要約文から毎回推定する案は、帰属の誤りを成立させるため採らない。
tool-callsの要約は役割文書がある記録を文書別、無い記録を収集区分別に数え、カタログのroot外も同じ集計に含める。
statsの圧縮はClaude CodeとCodexの両方を数え、準備文書の記録別回数・位置・時刻からdetailへ到達できる。
