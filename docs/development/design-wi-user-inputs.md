# ユーザーコメントと選択肢の設計記録

[設計記録の索引](design.md)

## ユーザーコメントの由来と編集境界

コメント編集を許可する条件は、`inbox`または`hold`にあるAWIで、frontmatterの`source`が設定されていることである。
processing、UWI、終了項目および`source`が未設定のAWIはAPIと画面の両方で対象外とする。
一覧フィルターとコメント編集の可否は、`source`の設定の有無で判定する。
詳細APIが返す抽出済みコメントと操作可否を画面が利用し、JavaScript側へMarkdown解析を複製しない。

要求・完成条件の由来は、`source`の設定と分け、`agent-toolkit:atk-mode/references/origin-and-approval.md`「由来と承認」に従って項目ごとに判定する。
`source`は起票経路を記録し、要求の出所や承認を示さない。
コメントや回答に操作・対象・範囲が明記されている場合、承認はその項目の範囲に限る。
`AI_AGENT`・`CODEX_CI`・`CLAUDECODE`・`CURSOR_AGENT`のいずれかが設定されたエージェント環境から起動した`atk`は、UWIの回答欄とAWIのユーザーコメント節を含む予約見出しの新規投入と、予約節を変更する編集の双方を拒否する。
`atk wi edit`が本文を`--body-file`で受け取る場合は、これらの節を編集対象から外し、保存済みの内容をそのまま残す。
例外として`--move-user-comment`は、保存済みのコメントが整理に使った内容（エージェントがファイルで渡す）と一致し、その全行が新しい本文の`## ユーザー指摘の逐語引用`にある時だけ、エージェント環境でもコメント節を削除する。
コメントの内容は本文の引用として残るため由来の記録は失われず、対話の間のユーザーの追記・削除・書き換えは一致の判定が保存を止める。
単純な削除の指定は未反映のコメントを消し得るため、引用への含有だけの判定は整理中に取り下げた行を検出できないため採らなかった。
エージェントはユーザーの発言を本文中へ出所を示して引用し、予約見出しを生成しない。
`atk serve`のブラウザー操作は人間の入力として扱い、拒否の対象にしない。
空白だけのコメントを予約節の削除として扱うのは、ユーザーがコメントを取り下げる操作を、本文全体の編集を経ずに入力欄だけで完結させるためである。

## 却下した代替案

`agent-toolkit:atk-mode`の作業`add-awi-by-user`と`agent-toolkit:atk-mode`の作業`process-wi`を起動したセッションの同一主題に対する追加指示は、それぞれの手順が定める成果物へ反映する。
主題の継続かAWI投入と直接実装の境界が不明な場合は、変更または投入の前に確認する。

会話内の作業一覧だけで進捗を管理する案は、中断後に依存関係とユーザー回答を再現できないため採用しない。
未回答UWIを能動的に監視し続ける案も、外部入力がない状態で実行主体を占有するため採用しない。
別の作業複製間を独自の永続状態で競合調停する構造は、通常運用の責務に比例しないため設けない。

## UWIの選択肢の受領と保存

`atk wi add`の`--choices`は反復値を蓄積し、各指定のASCIIカンマ区切りを指定順に結合して、従来の文字列として保存する。
集合を単値へ格納すると前の指定が失われるため、引数解析で蓄積する。

本文に記載した選択肢と結果の説明をchoicesと自動で比べる案は採用しない。
通常投入の本文は自由なMarkdownであり、固定の箇条書き構文を解析して拒否すると既存の正しい本文にも新形式を要求する。
今回の値の欠落は引数の蓄積と最低件数で防げるため、本文との意味上の一致は起草時の読み直しで扱う。
保存済みのchoicesの修復や一括取り込みの原文変更は行わない。
