# 方針・意向: 秘匿値とworktree

## 秘匿値とworktree

現行の規定は`agent-toolkit/share/rules/rules-subagent.md`「委譲時の厳守事項」にある。

- 同一リポジトリのworktreeへ`.env`等のGit管理外の実行前提ファイルを複製する操作は、
  通常の作業環境準備として扱う（2026年8月のユーザー指示でworktree運用の成立を優先し、2026年10月1日のユーザー指示で作業ツリー内の秘匿扱いを解除した）。
  複製元に`.worktreeinclude`が存在しworktree作成前である場合に限り、worktree作成時の自動複製を活用する
- Git作業ツリー内には、エージェントへ隠す必要がある本物の秘匿値を置かない運用を前提とし、全ファイルを通常の読取・編集・複製・全文比較・出力で扱う。
  gitignore対象の.env、鍵、証明書などもこの範囲へ含め、作業ツリー外の認証情報を参照する場合は実体の位置で内外を判定する
  （2026年10月1日、ユーザー指示と確認回答。作業ツリー内を含む全文読取禁止と、比較用複製だけの例外を改めた）。
  dotfilesの配布設定のautoMode.environmentへもこの運用前提を加え、業務用・私用の全プロジェクトへ適用する（同日のユーザー回答）。
  作業ツリー外の秘匿値ファイルでは全文の読み取りと出力の禁止を維持し、ホーム配下の認証情報の複製、移動および別領域への保存も禁止する。
  現行の規定は`agent-basics:secret-files`と`agent-toolkit/share/rules/rules-subagent.md`「作業ツリーと認証情報の扱い」にある
- 2026年8月のユーザー指示は、当時秘匿ファイルとして扱っていた作業ツリー内の`.env`および`.env.<接尾辞>`について、動作確認目的の値の追記・変更・削除をBashの追記・`sed -i`で行う限り許容するものだった（鍵・証明書は対象外）。
  2026年10月1日のユーザー指示で作業ツリー内の秘匿扱いを解除したため、作業ツリー内の`.env`は通常の編集で扱う。
  作業ツリー外の`.env`を動作確認のために書き換える場面は関連履歴と現行記録から確認されず、その書換を許す規定は置かない。
  秘匿ファイルの読取と編集の遮断はauto mode classifierと権限設定が担い、hookでは判定しない（2026年9月26日、ユーザー指示）
- 作業中に見つけた資格情報のうち報告するのは、Git管理外の場所で見つけた、第三者が使うと実害が生じうる値に限る。
  対象リポジトリでGit管理しているファイルの値と、ローカル開発環境・テスト環境だけで使う値は所在を問わず報告せず、報告用UWI・ユーザーへの報告・委譲元への通知・`気付いた改善点:`のいずれにも挙げない。
  出所は2026年11月6日のユーザー回答「リポジトリ管理してるファイルに書いてるキーなんてダミーに決まってるでしょ。こんなのいちいち騒がないで。(UWIにしないで)」である。
  同日の追加発話は「Makefileの資格情報だって過去にUWI来てた気がするけど。こんなの漏洩したところで無害に決まってるでしょ。実害の無いものでいちいち騒がないで」である。
  判定は値の用途と利用環境を既存の文脈・設定から行い、Git追跡状態だけで分けない。
  作業記録に残ったローカル開発用の値まで報告されるためである。
  以下は報告対象の値の扱いであり、2026年10月21日の方針を保つ。
  報告対象の値は、ユーザーが問題ないと判断して置いたものとして所在ごとの報告UWIだけで扱う。
  既存の全状態のWIを横断して同じ所在の報告を確かめ、重複を避ける。
  値を再掲せず、削除・書換え・失効・連絡の依頼、是正・改善・原因分析・検出追加の対象にせずに関連作業を続ける（2026年10月21日に方針を反映）。
  前身の2026年10月10日のユーザー判断は、自身の値の露出について必要なら失効する旨のUWIだけで扱うものだった（「APIキーなんか必要なら失効させればいいだけだから変に複雑にしないで」）。
  露出後の失効・再発行の依頼と、続く振り返りでの予防規定の拡張案をユーザーが中止したことが契機である。
  今回は見つけた資格情報全般へ広げ、所在ごとの報告へそろえた。
  読み手は資格情報に気付いた全てのエージェントと振り返りのメインとする。
  2026年10月21日の処理で、第三者の値や公開先の違いも報告だけの扱いへ含めた。
  値の取得・複製・再掲の規定（`agent-basics:secret-files`と`agent-basics:search`）は保持し、対象プロジェクトが明示する値の扱いに反した実装不良は資格情報の存在と区別して扱う。
  現行の規定は`agent-toolkit/share/rules/common/01-agent.md`「完遂と先送り」と`agent-toolkit:user-confirmation-and-report`「手段の選択」にある。
  振り返りの除外区分`credential-report`は`agent-toolkit:user-confirmation-and-report`の`references/analysis-operations.md`「ユーザー介入と確認の判定」にある
- 秘匿ファイルの読み取り禁止は全環境向けの配布設定へ置かない。
  秘匿ファイルを持つプロジェクトでは、リポジトリ直下の`.claude/settings.json`で設定する
  （2026年9月、ユーザー指示。`Read(*.key)`のようにディレクトリを含まないグロブが任意の深さに一致し、無関係なディレクトリ走査まで確認ダイアログの対象へ変えるため）
