# commitと計画検証の公開境界の設計記録

[設計記録の索引](design.md)から参照する、commitと計画検証の公開境界の記録である。

## atk commitとsetup-projectの公開境界

コミット作成とプロジェクト規範の統一は、配布先の全エンドユーザーが使う操作であるため`atk`のサブコマンドとして公開する。
旧コマンドをdotfilesの`pytools/`へ残すと、agent-toolkit単体のユーザーとdotfilesユーザーで到達できる機能が異なり、同じ処理を2箇所へ維持する。
実装は`agent-toolkit/agent_toolkit/_atk/`に置き、モデル候補は既存の`resolve_model_candidates`でchores工程から解決する。

`atk commit`は未対応engine、実行ファイルの不在、および子の非0終了後もHEADと`git status --porcelain=v1`が起動前と一致する場合だけ次候補を試す。
Git状態を変更した失敗で候補を進めると、前候補が途中まで行ったstageやcommitを別のモデルが重ね、ユーザーの意図しない履歴を作成し得る。
子は一時ディレクトリで起動し、操作対象のGit rootを明示してプロジェクト規範の自動読込を避ける。
ClaudeがWeekly limitか5時間の利用上限で拒否した場合は、Git状態の変化によらず次の候補へ進まず、解除予定時刻まで待って同じ会話を`--resume`で続ける（ユーザー指示）。
このためClaudeは会話を保存する形（`--session-id`で識別子を指定）と構造化出力（`stream-json`）で起動し、利用枠の種類と解除予定時刻を出力から読む。
元の依頼を新しい作業として送り直すと、拒否より前に行ったstageやcommitを繰り返し得るため、同じ会話へ継続だけを送る。
会話は起動した作業ディレクトリでだけ再開できるため、一時ディレクトリは待機の間も保持する。
`atk setup-project`は既存の指示移行とスキルリンクを通常は実行し、規範複製は指定時だけ行う。
グローバル配布済みの規範を各プロジェクトへ通常時に複製すると、同じ条文を重ねて読み込むためである。

## 計画検証と検索記録

GitLab CIのbaseline、待機、一覧、詳細と失敗ログは、glabのホスト別API解決を共有する。
ホスト設定、`GL_HOST`を含む環境変数と明示HTTP(S) URLは公開glabの優先順で解決し、リポジトリ指定は設定キーとして保持する。
リポジトリ指定からHTTP APIのauthorityを独自に組み立てる案は、ホスト別endpointの指定を失わせるため採用しない。

計画の検証行は、実装担当とレビュー担当が計画の検証コマンドをハーネスの標準実行でそのまま動かす。
直接影響範囲の固定文字列検索は語ごとに`git grep -n -F`か明示対象の`rg -n -F`で行い、終了コード0は一致、1は一致なし、それ以外は検索失敗として観測する。
2026年10月25日に、検証行を列挙・実行・保存した`plan-verify`を撤去した（ユーザー指示）。
registryを使う動的bash補完は新しいコマンド名を同じ定義から取得する。

初期配分の見積もりを修正する書込対象追加には、既存pick-wi-checkの`--extend-write-targets`を使える。
開始後の追加編集に伴う選定更新は求めず、commit差分と既存の統合時の追随・競合解消を使う。
追加一覧の受渡しや統合CLIへの接続は、同じ情報の重複管理を増やすため設けない。
追加入力に新設先とレーン間の重なりの意味判断を持たせ、初回配分と既存の順序を保持する。
型と書込予定の妥当性・レーン関係のチェックは初回生成・合流と共有し、不足する記録があれば保存先を変更せず次の操作を返す。
各回のYAML編集コードをメインへ委ねる方式は同じ構造の加工を反復させるため、既存のチェックと保存の境界へ操作を加えた。
追加操作は自身の追記で成立し得る全体チェックの違反を同じ追加入力で解消できることを不変条件とする。
このため、全体チェックが`書込対象`に連動して求める欄（`導出した新設先`、`レーン間の重なり`、`プロジェクト規範の指定`、`書き込まない反映先`）を追加入力で更新できる。
`プロジェクト規範の指定`は値全体の置換、`書き込まない反映先`は追加した書込パスと同じか配下の要素の除去で扱う。
2026年10月28日の1回のprocess-wiで、規範指定を受け取れない追加操作が全体チェックで拒否され、メインが選定YAMLの写しを手で書き換えて再実行することを4回繰り返したことによる。
規範指定を共有スクリプトが`norm-spec`設定から自動生成する案は、読む要求の文面と原本の指定をメインが組み立てる所有の境界に反するため採らない。
`書込対象`に連動するチェックを加えるときは、`selection_merge.py`の追加入力の許可欄も同じ変更で見直す。
