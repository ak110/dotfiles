# 画面統合の設計記録

[設計記録の索引](design.md)

## 待受範囲と認証の責任分界

`atk serve`はユーザー本人が起動し、待受範囲とリバースプロキシなど前段の認証を管理する。
新しい画面も既存のWI画面と同じ扱いとし、`atk serve`側に画面ごとの認証は加えない。
個別機能の入力検証や、`atk serve`の外にある信頼境界は、この方針の対象外とする。

## 作業の開始から結果まで

| 作業 | 始点から結果への順 | 必要な時に開く内容 |
| --- | --- | --- |
| 判断する | キューで次に扱う項目を選び、題と本文を読む。コメントは入力欄の右の「コメントを保存」で確定し、対象名を含む通知を確認する | 詳細な絞り込み、参照先、危険な操作 |
| 計画の指摘を読む | 一覧の名前の識別箇所で選び、指摘内容と対応の列を比較する | コピー、移動、完全パス |
| 会話を読む | 記録を選び、最初の発話から読み、必要な発話を共有する | 検索と移動、費用・識別子 |
| 稼働と消費を調べる | ホストと対象を見て記録へ進む。消費を見る場合は使用率、経過、戻る時刻の順に判断する | 終了済み、観測と計算の詳細 |
| 設定を変える | ホストと項目を選び、値を編集し、変わった値と反映時期を確かめる | 比較、値の出所・形式、起動時の診断 |

計画と会話を1つの一覧に混ぜると、検索対象と続きの操作（比較と発話共有）が分からなくなるため、同じ「記録」から別々に直接到達させる。
稼働と利用枠も、異なる対象と判断を混ぜず「稼働状況」にまとめる。
設定を作業面から分け、変更対象を記録やセッションと混同させない。
現在地、対象、最初に読む本文、選んだ操作、結果の順に視線を移せるようにし、フォーカスも同じ順にする。
調べるときだけ必要な情報は最初の場所を取らないが、操作対象、危険性、反映条件は隠さない。

## 共通スタイルと表示名

一般的なデスクトップのブラウザーを主な利用環境とし、Androidでは表示が崩れず操作できることを副次確認する。
デスクトップでの読みやすさを確保し、Androidでは一覧の引き出しや操作列の折り返しで対応する。

`static/app.css`の文字と行間は、画面名・選択中の対象、区画、項目と操作、補足の順に役割を分ける。
本文は独立した読み幅と行間を持ち、Markdownの見出し・表・図の構造は本文の外へ及ぼさない。
同じ役割は`.page-heading`、`.section-heading`、`.secondary-text`などの共通スタイルを使い、画面別の文字サイズは作らない。
余白は4pxを起点とする段を使い、ラベルと値、行、区画の順に離す。
画面別のCSSはツリーの階層、グラフの位置、表や操作の折り返しなど、内容に固有の配置を担う。

中立色で閲覧面と周囲を区別し、青緑は現在地と主操作に使う。
通常の主操作だけを塗り、補助操作は枠線かテキスト、危険色の塗りは確認後の実行に使う。
入力欄は境界を持ち、表示を切り替える設定の分類は塗りと選択の線で現在地を示す。
一覧は行の境界で分け、長さで他行を押し下げないよう短い表示と詳細を使い分ける。
ライトとダークに同じ役割を保ち、状態には色だけでなく状態名か選択の線を使う。

- ワークアイテムでは一覧の題と状態を先に見せ、フィルターと一括コピーは一覧の補助に置く。
  詳細は本文と回答、新規追加は入力と追加、削除確認は対象と実行を優先する
- 計画とセッションでは、未選択時は一覧、選択後は本文の見出しと内容を優先する。
  検索・移動・コピーは本文とは別の操作列に置く
- エージェントはホストで分け、行の名前と階層・状態が先に読めるようにする。
  終了済みの表示切替は見出しの横の副操作にする
- 利用枠は率とリセットの見込み、設定は分類と設定項目の実効値・保存値を優先する。
  計測の補足、値の出所と形式は値から分ける

ユーザー向けのラベルと状態名は日本語で表示する。
CLIやfrontmatterとの照合に必要な設定キー・ファイル名・値は補足に原表記で残し、操作のラベルに用いない。

## 画面統合

ワークアイテム・計画ファイル・セッションはSSEで更新する。
エージェント、利用枠、設定の初回取得は文書の初期化で始める。
定期取得は画面の切替から独立させる。
リモートの設定はサーバーが60秒ごとに読み取り専用で取得し、最後に取得できた状態を保持する。
旧版への通常の取得は、ホストを選ぶなどの手動操作に限る。
2026-11-26にeuryaleからsthenoへ同じ読み取り専用のホスト名を照会し、SSHでは0.29秒、非昇格の起動では8.28秒だった（各1回）。
設定取得の時間そのものではないが、非昇格の起動が連続しない間隔として60秒を選んだ。

計画ファイル閲覧の実装は`pytools/claude_plans_viewer/`から`agent-toolkit/agent_toolkit/`配下へ移した。
閲覧対象の計画ファイルはagent-toolkitが`atk plans`で作成・保管するものであり、閲覧機能だけが個人のdotfilesリポジトリ側に残ると、計画ファイルの書式変更のたびに配布境界をまたいだ2リポジトリの同時更新が必要になる。
移設後は計画ファイルの生成側と閲覧側が同じ配布物に属する。

移設に伴い、配布物独立性（`agent-toolkit/`配下から`pytools/`を参照しない）を保つため、ファイルロックとwatchdogイベント判定はagent-toolkit側の実装へ置き換えた。
private-notesの解決は`agent-toolkit/agent_toolkit/_common/private_notes.py`を同一プロセス内で呼び、外部プロセスの起動を伴わない。
作成日時インデックスのキャッシュディレクトリ名は統合前の名前を維持する。
名前を変えると初回観測時刻が失われ、一覧の並び順が変わるためである。

共通ヘッダーとナビゲーションは、全画面で操作の大きさと位置を揃えるため、折り返しを含めて `app.css` で定める。
詳細ツールバーの折り返しと操作寸法も共通側で定める。
計画の表の列構成やセッション固有の記録内検索が必要とする配置は、画面別のCSSで定める。

6画面は1つのHTMLドキュメントと1つのスタイルシートで構成する。
画面ごとに別のドキュメントと別のスタイルシートを持つ構成は、画面ごとに読み込む資産の集合とカスケードが分かれ、エンドユーザーが画面ごとに異なる表示を観測するため採らない。

6画面のDOMは常に同じドキュメントへ存在するため、`body`の属性で限定する方式では非表示の画面の指定が`body`と共有要素へ及ぶ。

共通シェルの画面登録契約は`init`だけとし、各画面のモジュールが`static/shell.js`の`registerScreen`を`import`して登録する。
一時的なデータ取得失敗は直前の表示を保って自動で取り直す。
最初の自動再試行まで通知を出さない。
失敗が続く間は間隔を延ばして自動更新を続け、共通通知からも再取得できる。
取得が回復したら通知を閉じる。
保存の失敗は表示し、自動では再送しない。

`init`は登録された画面の要素への購読、サーバーからの初期取得、SSEの購読をまとめて1回だけ実行する。
初期表示の画面を先に初期化し、完了を待たず残りの準備を開始する。
遅い応答で他の画面の準備まで止めない。
以後の画面の切り替えでは`init`を再実行せず、表示中でない画面もSSEの購読を保ったまま内容を更新する。
画面の表示のたびに初期取得をやり直す契約は、エンドユーザーが同じ画面へ戻るたびにGitの同期と一覧の再取得を待つため採らない。
WI・計画ファイル・セッションのSSEをブラウザーのタブごとに開くと、HTTP/1.1で取得や保存に使う接続が不足する。
Web LocksとBroadcastChannelを利用できる環境では、同じサイトのタブで購読を共有する。
接続を持つタブを閉じると、別のタブがつなぎ直して更新を再開する。
共有できない環境ではタブごとに接続する。
表示中でない画面の購読を閉じる案は、再表示のたびに取得をやり直す必要が生じ、上記の契約と両立しないため採らない。

各画面のスクリプトはESモジュールとして読み込み、同じ役割の処理を共通モジュール`static/common.js`から使う。
エージェントは定期取得を続け、画面が前面なら約2秒、それ以外は約30秒を次の間隔にする。
切替でタイマーを始め直さない。
設定の定期取得は30秒、利用枠の定期取得は5分を間隔とし、取得中も最後の観測を残す。
いずれもSSEを追加しない。
取得するAPI、一覧の項目の描画、画面固有の操作は各画面が引数の関数として渡し、同じ役割の関数を画面側で再定義しない。
以前は3画面が別々の実装から統合され、同じ役割の関数を画面ごとに持ち、スクリプトのスコープを即時実行関数で閉じていたため、一方の画面だけを直すと挙動が分かれた。
WI画面のスクリプトだけをサーバー側の文字列置換で配信する方式は、画面ごとに設定値の受け取り方が分かれるため採らない。

ESモジュールは文書の解析後に順に評価されるため、各画面は`DOMContentLoaded`より前に登録を終え、共通シェルが`DOMContentLoaded`で全画面の`init`を実行する。

消失を処理して選択を解除する前に対象を確保するため、失敗後にも所在を読める。
clipboardや図の描画はブラウザーを主体として示し、参照する遠隔データの所在とは分ける。
理由だけを表示する案は同じ理由の複数対象を区別できず、生source IDを表示する案は内部の識別子をエンドユーザーに解釈させるため採らない。

WI一覧はタイトルとメタ情報を1行ずつ表示する。
行末のコピーは名前を持つアイコンボタンとし、完了しても幅を変えない。
`target-repo`は末尾の所有者と名前を表示し、完全な値はツールチップと読み上げ用の名前に残す。

### サーバー側のモジュール構成

`atk serve`のサーバー側は`agent-toolkit/agent_toolkit/_atk/serve/`配下の責務ごとのモジュールへ分ける。
以前は1つのファイルがドメイン処理とルーティングを同居させ、画面の機能を加える計画ごとに同じファイルへ追記していた。
ドメイン処理をルートの登録から分けると、`Operations`の振る舞いをHTTPを介さずに確かめられる。

WI保存の同期と排他の方針は`wi/sync.py`の`Storage`が持ち、`Operations`は構築時にローカル保存とロック待機上限を確定して各操作へ渡す。
全件検証、生成名、回答の自動採用、無変更と競合の判定は各操作が所有する。
各操作に低水準の同期省略とロック時間を渡す構成は、保存手順と画面用の方針を呼び出し側ごとに持たせるため採らない。

ワーカーで実行する同期処理の`SystemExit`はスレッドで同期関数を呼ぶ際に要求のエラーへ変換する。
CLI向けの終了通知を常駐サーバー全体へ波及させず、同じプロセスで後続の要求へ応答するためである。
一覧と詳細は終了しない種別判定を使い、欠落・不正なtypeの項目もunknownとして表示する。
呼び出し箇所ごとの`except SystemExit`は新たな操作の追加で包み忘れが生じるため共通境界の代わりにはしない。
CLIライブラリ全体から`sys.exit`を除く案は単発CLIの終了コードと案内も変えるため採らない。

### リモートヘルパーの起動コード

リモートホスト側ヘルパーの起動コードは`agent-toolkit/agent_toolkit/_atk/serve/remote.py`の`remote_bootstrap`へ集約する。
計画ファイル画面とセッション画面は別々のヘルパーを起動するが、SSH越しの起動形は同じ制約を負う。
起動コードは`python -c`へ1行で渡し、ヘルパー本体を`exec`で実行する。
このときヘルパーは`python -c`が用意した名前空間をそのまま使い、`python -c`が用意した名前空間には`__file__`が無い。
そのため起動コードは`exec`の前にヘルパー本体の絶対パスを`__file__`へ束縛し、通常のスクリプト実行と同じ属性を与える。
画面ごとに起動コードを複製する案は、一方の画面で確定した名前空間の契約が他方へ伝わらず、ヘルパー側の記述が実行形式によっては成立しなくなるため採らない。
ヘルパー側で`__file__`の不在に耐える案も、ヘルパー自身の設置場所から導くrootと`~/dotfiles`という2つのroot候補の区別が失われるため採らない。

### 設定の保存先と移行

設定画面ではローカルの共有設定と、選択したホストの設定を別々に表示する。
共有先は資格情報を除いた接続先、上流ブランチ、共有ファイル名から作る要約値で比較する。
共有先と設定の移行状態を確認できない値は、ホスト別に扱う。
比較表はサーバーが裏で取得した保存値を表示し、取得していない値を補わない。

`atk serve`の待受と2画面の参照元は、`atk config`の変更可能設定（`serve_host`・`serve_port`・`serve_plans_*`・`serve_sessions_*`）として統一設定の`config.json`へ保存する。
キー・検証・省略時の値は`_atk/config.py`が持ち、`_atk/serve/config.py`はその実効値から`ServeConfig`を組み立てるだけを持つ。
以前は`serve.toml`だけが別ファイルに分かれ、確認・変更の手段が`atk config`と揃わなかったため、2026年10月のユーザーの要求で統合した。

解決順はCLI、`AGENT_TOOLKIT_SERVE_HOST`・`AGENT_TOOLKIT_SERVE_PORT`、`atk config`の実効値（`AGENT_TOOLKIT_CONFIG_SERVE_*`、保存値、省略時の値）とし、統合前の上書きの順を保つ。

旧`serve.toml`（`AGENT_TOOLKIT_SERVE_CONFIG`の指定先を含む）は、`atk serve`の設定解決と`atk config get/set`の時点で移行する。
`atk config show`・`list`・サブコマンドなしでは移行せず、同じ変換規則で旧ファイルの値を読み取る。
保存値がなく旧ファイルからも確定できない項目は省いて原因を示す。
統一設定に無いキーだけを補い、保存後に旧ファイルを`<旧ファイル名>.migrated`へ改名する。
保存済みのキーを上書きしないことで明示保存値を保ち、改名で移行元を無くすことで再実行が移行済みの値を変えないようにする。
旧ファイルを残して毎回補う案は、旧ファイルを編集しても保存済みのキーだけが反映されず、どの値が有効になるかが分かりにくくなるため採らない。
読めない旧ファイル、未知キー・型不正、破損した統一設定、保存・改名の失敗では、旧ファイルと統一設定の既存内容を変えずに原因と次の操作を示して終了する。
破損した`config.json`を空とみなして書き込むと他用途の設定を失うため、移行と`save_mutable_settings`は厳密に読む。
移行の契機をモデル候補などの他用途の設定読込に広げないのは、旧ファイルの不備が委譲など無関係の機能を止めないためである。
