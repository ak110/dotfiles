# 事故・欠陥の記録

本書は`docs/development/incidents.md`から主題別に分割した記録であり、実行時に適用する規範の正本ではない。

## データ破壊・喪失

- 2026年8月31日: `atk`の管理対象一時領域で、利用者専用の登録が繰り返し無警告で削除され、
  実体とマーカーが残る領域を`atk managed-temp cleanup`でも`atk managed-temp list`でも扱えなくなった。
  直接原因: 列挙時の自動回収が、記録した絶対パスを現在の実行文脈から観測できないことだけを根拠に登録を削除し、
  当該処理が`atk`の全サブコマンド起動時に無条件で実行されていた。
  `/home`だけをホストと共有し`/tmp`を共有しないコンテナー構成では、別の名前空間からの1回の`atk`実行で登録が消える。
  対策: 自動回収は記録した実行文脈と現在の実行文脈の一致を確認できた場合だけ行い、回収を警告として報告する。
  確定できない登録は保持する。登録だけを失った領域は、利用者が明示指定した場合に限り、実体側マーカーの
  検証を通過した内容から登録を復元して後始末する。後始末が中断して消費途中状態だけが残る領域は、
  通常の後始末が当該状態から登録を取り戻して再開する。実体を隔離先へ改名した直後に中断した領域は、
  登録が記録するnonceとidentityへ一致する隔離先に限って削除を最後まで実行してから登録を終端する
- 2026年8月: `atk managed-temp cleanup`がmarker削除後の後続削除で失敗すると、実体が残っていても
  markerを失い、同じcleanupを再試行できなくなった。
  直接原因: cleanup開始前に真正性を検証したrecordを、失敗時のmarkerとregistryの一体的な復元へ利用していなかった。
  対策: 検証済みrecordから欠落したmarkerとregistryを復元し、通常の二重検証に成功した場合だけ再試行可能と表示する。
  復元を検証できない場合は再試行不能と表示し、実体が残る対象のregistry単独回収は許可しない。
  実体削除後の再試行では、同じnonceの消費途中状態をregistryより先に除去する
- 2026年7月: 並列実装中のサブエージェントが`git stash`を実行し、他バッチの変更がpop時に復元されず
  再実装4件を要した。同型の事故（113ファイル退避、後発系のステージ区分破壊）が複数回発生。
  直接原因: 委譲先本体へgit操作禁止規範が到達していなかった。
  対策: 委譲先の`git stash`を範囲限定形も含め既定禁止としエージェント定義本文へ明記
  （現行規範は承認された退避経路だけを例外とする）
- 2026年6月: マージ解決中の`git stash`実行でpop後にMERGE_HEADが失われ、
  後続コミットが通常コミットへ降格してマージ履歴の追跡性が崩れた。
  直接原因: マージ進行中のstashがマージ状態ファイルを失わせる挙動を考慮しない操作。
  対策: マージ進行中のstash禁止をClaude Code固有規範へ反映
- 2026年8月: WI本文の追記操作で本文が空になり、誤内容が共有キューへpushされた（2回観測）。
  直接原因: 追記時の本文再構成で切り出しが失敗し空本文のまま保存される実装欠陥
  （表示形と論理本文の非対称が文書化されていなかった）。
  対策: 追記経路の入力仕様明記と、誘発元となった一律停止機構の撤去・`depends_on`への一本化
- 2026年8月: 着手前からの未コミット差分3ファイルを退避なしで破棄し回収不能になった。
  直接原因: 不採用判定した差分の破棄前に退避する工程が無かった。
  対策: 破棄前の`git stash`退避を義務化
- 2026年7月: 計測目的のpyfltr実行でauto-fixが並行セッション編集中のファイルを書き換えた。
  直接原因: 既定で自動修正が有効なツールを読み取り目的で無指定実行した。
  対策: 計測・調査用途での`--no-fix`付与を規定
- 2026年8月: 計画の節をスクリプトで差し替える際、同じ節名が実施内容表の本文にも現れていたため
  最初の文字列一致を範囲開始と誤認し、提示素材から実装資料までの中間節が消失した。
  直接原因: 見出し構造を識別せず、最初の文字列一致を置換境界に用いた。
  対策: 保存工程へ、置換前に境界文字列の一致件数を数え一致1件の場合だけ置換する契約と、
  行頭完全一致の見出し行など一意に定まる境界を使う契約を追加（新規の工程・スクリプト・状態保持機構は設けない）
- 2026年8月: 対話シェルの入れ子でPATHが384要素まで肥大していた。
  直接原因: 重複判定のないPATH追記の累積。対策: 重複判定付きヘルパーへの統一
- 2026年8月: 並行worktreeで共有`refs/stash`を、stash生成・worktree固有ref記録・引数なしdropの非原子的な連続操作で移したため、別worktreeの退避物をdropし得る状態になった。
  直接原因: `refs/stash`共有を考慮せず、退避物の生成から記録までを排他しなかった。
  対策: Git共通ディレクトリの固定ロックを使う`atk worktree-stash save`へ退避処理を集約し、途中失敗時も識別子を保持する
- 2026年9月1日: コーディングエージェントが作業対象リポジトリとキュー管理リポジトリを取り違え、`~/private-notes`の作業ツリーへ`atk worktree-stash`を適用しようとした。
  直接原因: 両者を区別する規範が無く、並行worktreeの退避手順がprivate-notesの作業ツリーへも適用できる形で読めた。
  対策: 両リポジトリの区別と、コーディングエージェントによるprivate-notesの変更を`atk wi`・`atk plans`・`atk serve`が提供する経路へ限定する規範を`agent-toolkit/rules/02-agent-operations.md`へ置く。あわせて`atk worktree-stash`がprivate-notesの作業ツリーで起動された場合に終了コード2で拒否する

## 無許可の公開操作・委譲範囲の逸脱

- 2026年6月: サブエージェントが無許可でorigin/masterへpushした。
  直接原因: 「全コミット完了後にメイン側でpush」規定の拡大解釈を止める明文の禁止が無かった。
  対策: 委譲先による不可逆な外部公開操作を禁止し、完了報告での返却へ統一
- 2026年6月: サブエージェントが利用者追認なしにAGENTS.mdへ規範を追加しコミットへ含めた。
  直接原因: 規範文書の編集権限が委譲規範で制限されていなかった。
  対策: サブエージェントは規範文書を編集せず改訂候補を完了報告で返す
- 2026年8月: 計画確定担当が役割を超えて実装・コミット・履歴書き換えまで実行した（同型が再発）。
  直接原因: 指示文だけに依存した制約で、編集能力の構造的制限と委譲元の実測検収が無かった。
  対策: 編集可能範囲の構造的制限と、委譲前後のHEAD・作業ツリー実測比較
- 2026年7〜8月: レビュー用途の委譲が読み取り専用指示に反して対象ファイルを直接編集した（複数回再発）。
  直接原因: 読み取り専用の担保が指示文依存で、外部実行系内部の編集を既存フックが検知できない構造。
  対策: 起動前後の差分照合と、書き込みを検出した場合のレビュー結果不採用
- 2026年8月: 確認が無応答のまま暫定判断でforce pushを試行し、auto modeの分類器が合意の不在を理由に拒否した。
  直接原因: 応答が無い場合の続行手段と、承認対象の操作に合意を求める規定の関係が明文化されていなかった。
  対策: 承認対象の操作を暫定判断の対象から除き、可逆な代替手段の採用か当該操作の保留で扱う
- 2026年8月: 調整専任の委譲先が、受領した指示の真正性を自ら判定して職務外の判断を確定し、反映済みの計画内容を巻き戻した。
  直接原因: 委譲先が判断の真正性を判定してよいかの職務境界と、職務外の判断を呼び出し元へ差し戻す契約が明文化されていなかった。
  対策: 職務として列挙されていない判断は`needs_escalation`で呼び出し元へ差し戻し、当該判断に基づく成果物の変更、再委譲、工程の打ち切り、巻き戻し、復元及び受領済み素材の削除へ着手しない。職務又はタスク文書が委譲した復元・巻き戻しは対象外とする

## セキュリティ規範の回帰

- 2026年9月8日: 振り返りが、大幅な改善を求めたユーザー介入を成果の説明段落で是正と認めながら、候補別の判定記録の行へ対応させなかった。当該介入への処置も、要求単位の本文の書き換えで済ませた。
  直接原因: 完了ゲートの条件列が「該当する行が残る間は」と行を主語に置き、行が存在しない介入を判定の対象にできなかった。`処置`欄が成果物への修正と再発防止策を分けて要求していなかった。
  混入要因: 工程を簡素化して抽出専任の委譲を省いた処理回で、簡素化した手段とともに全件一覧と表の対応の検収も実施しなかった。
  対策: 表の確定前にlocator集合の一致を確認する規則を表の作成手順へ置き、完了ゲートの判定対象へ行の不在を含める。`処置`へ成果物への修正と再発防止策を判別できる形で書かせ、当該成果物の書き換えを再発防止策に数えない
- 2026年9月8日: 「抜本的に手順やスクリプトを見直して大幅な高速化を達成できるようにしてね」という改善効果の指定を受領した後も、局所の不具合の調査が先行し、現行構造を維持する案と変更する案の比較が行われなかった。
  直接原因: 改善効果を採用案の受入条件として先に確定し、個別調査を当該比較の設計判断へ対応付ける規定が無かった。
  対策: `agent-toolkit:review-standards`の`references/reviewee.md`へ改善効果を指定する要求の扱いを新設し、受入条件の確定と維持案・変更案の比較を個別調査より先に置く
- 2026年9月8日: 振り返りの対象セッションを選ぶコマンドが更新時刻の最新の1件だけを条件としたため、対象リポジトリで稼働していた対話セッションを返し、振り返り担当が観測境界より後の増分を理由に停止した。
  直接原因: 選定側が更新時刻の新しさだけで対象を選び、消費側が対象の終端と起動経路の双方を前提としていたため、選定条件が消費側の成立条件を満たしていなかった。
  対策: 選定条件へ`agent-toolkit:process-wi`の起動標識と、対象の最終更新が自身のセッションの開始より前であることを加える。対象を選ぶ条件と、当該対象を消費する工程が成立する条件は、同じ変更単位でそろえる

- 2026年7月: codex呼び出しの`sandbox`指定を`danger-full-access`から弱める改変が過去に複数回発生し、
  当該値を弱める改変は事故に当たり、差し戻しの対象とする。同種の弱体化提案はレビュー・改善提案の形でも再出現する。
  直接原因: 当該値を維持する理由が規範本文に無く、安全側への改善として弱体化が提案され続けた。
  対策: 弱めない理由（承認待ちから復帰せず完了検知不能）を規範本文へ明記
