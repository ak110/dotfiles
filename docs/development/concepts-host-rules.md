# 方針・意向: ホスト別の規範配置

## Claude CodeとCodexの規範配置

hookは規範本文を代替配送せず、各ホスト本来の取得手段を案内し、取得操作を観測する。
Claude Codeのスキル起動登録、編集ツールの読取状態、圧縮後の復元はホストの取得操作に依存するためである。
Claudeのメインとtask・delegateは通常Skill、AgentサブエージェントはSkillと使用不可時のRead、Codexは絶対パスの読取を使い、軽量委譲先には取得を求めない。
取得判定と履歴復元は対象パスへの読取成功を使い、必要な基準の取得と適用は担当が確認する。
Claudeメインの`SKILL.md`は`disable-model-invocation: true`に限り成功したRead・Bashも認め、通常はSkill起動を要する。
`allow_implicit_invocation=false`だけでは例外にせず、ユーザー専用操作の代行と設定解除も認めない。
純粋Read・Bash読取・Skillでは依存案内を保留し、次の非取得操作で未取得資料を初回だけ案内する。
案内の実配送と本文の受信を分け、未取得を理由に再書込を遮断したり同じ要求を反復したりしない。
所有・認可・データ保全の独立した保護を維持する（2026年11月4日のユーザー指示）。
必要な資料を取得せずに委譲を起動・追送する操作やWIを投入・編集する操作も、未取得を理由とするhookの拒否や、規範を読まないと書けない引数による拒否へ変えず、警告を維持する。
hookによる拒否は過去に運用したが、誤判定時の副作用とコンテキストの無駄が大きかったというユーザーの判断による（2026年11月9日）。
警告後も守られなかった操作・取得されなかった資料は、振り返りで改善を検討する対象とする。
現行の規定は`agent-toolkit/skills/review-session/references/analysis-triage.md`「一次選別」のhook通知にある。
出所は2026年10月19日のユーザー指摘に基づく採用方針と、同月27日のユーザーによる再確認である。
本文配送を再導入した7454e5938の方式を撤去する。
この方針はホスト・ツール・目的を問わず適用し、Codexのnative読取の出力省略を補う目的でもhookの追加文脈へ資料本文を載せない。
2026年10月30日に省略補償として再導入した9b4c6e6f6の配送は、同月31日のユーザー指摘「フックが本文を配送するのはやめろって過去にも指摘したはずなんだけどね…。ちゃんと直して再発防止してね」で撤去した。
省略された読取は担当が行範囲を分けて末尾まで読み、取得の観測はモデルへ届いたnative本文だけを根拠にする。
会話圧縮後の取得状態のリセットは保ち、再取得は残る工程に必要な資料に限る。
圧縮直後は履歴由来の資料一覧を示さず、進行中の工程を定めるスキルと役割文書の全文を読み直し、その読込表から次の判断に必要な資料を選ぶ。
全体作業契約と引き継ぎ記録が次工程の資料を指す場合も読む（2026年11月11日の方式再選定）。
事象ごとの宣言や専用の復元スキルは追加せず、既存の工程文書を選択の起点とする。
現在の操作の宣言が選んだ範囲だけを初回案内へ戻す（2026年10月31日と11月4日のユーザー指示）。

規範資料は、成立する読込条件から選んだファイルの全文を読み、前提・例外を含む基準へ到達して適用する。
節名は基準の所在を示す手掛かりとし、無関係な本文を読む構成は条件別のファイル分割で整える。
実行時の案内と取得判定は`agent-toolkit/agent_toolkit/_hooks/pretooluse/read_delivery.py`、構造の理由は[design-hooks.md](design-hooks-read-declarations.md#宣言型読込表による操作前配送)にある。

現在の役割に適用する行だけを選び、判断契機の自然文条件は明示的な資料選択以外を確認候補として扱う（2026年10月31日の確定契約）。
確認候補は主体が条件を確かめて判断前に必要な基準へ到達するための補助であり、必読案内済みや遮断の根拠に含めない。
同じ実体パスの複数節は取得をまとめ、宣言修復後は現行宣言へ接続する。
案内・観測・履歴・起動本文・圧縮は共通の取得手段判定を使い、起動時の配送と観測は同じ対象集合と本文・識別子照合を使う。
宣言の短縮スキル名は所属pluginに実在するものに限り、別pluginは完全名で指定する。
外部取得はClaudeのWebFetch登録と観測を対応させ、取得手段のないCodexへ強制案内を出さない。
実行契約は`agent-toolkit/share/read-trigger-contract.md`にある。

通知の整形と実配送の記録は分離し、最終出力に採用した非空本文だけを配送済みにする（同日の確定契約）。
AGYの保留通知は実inject時に記録し、未判定の条件は保持して解消を確認した原因だけを解除する。
正常なPreToolUse拒否は終了0の構造化denyと非空理由で返し、起動障害の非遮断化と区別する。
内部エラーは対処可能ならホストの通知フィールドへ標識付きで渡し、対処不能またはイベント不明なら出力を停止する。
引用・素材が英語でも説明が日本語に適合する場合は、同一主体・同一ツール・直前の同一入力の再発行で回復し、自身の英語説明は遮断を保つ。
実行契約は品質スキルのhook基準、状態定義は`.claude/skills/agent-toolkit-edit/references/session-state-and-flags.md`にある。

hookがエージェントへ送る通知は、受け取るエージェントがその時点で持っている文脈を前提に、何が起きたかと次の行動が分かるように書き、実装とレビューで確かめる。
2026年11月10日のユーザー指示「メッセージを受け取る側のエージェントに対してそのエージェントが持っている文脈を踏まえて分かりやすい・伝わりやすい・今後の行動が理解しやすいメッセージでなければならない」による。
契機は、会話の圧縮の直後に届く通知が「会話の要約は生成していない」で始まり、受け取る側には圧縮が起きたことも要約が何を指すかも分からなかった事象である。
現行の規定は`agent-basics/skills/writing-standards/references/claude-hooks-messages-format.md`「通知本文の整形」にある。

Claude Codeでは、hookがエージェントへ操作や是正を求める通知を、ユーザーの画面にも全文で表示する。
実行時間や規範本文のように情報を渡すだけの通知は表示しない。
2026年11月10日のユーザーの依頼と確認回答（選択肢「是正する通知を全文」）により、エージェントが気付きにくい改善案をユーザーが思いつけるようにするためである。
現行の規定は`agent-basics/skills/writing-standards/references/claude-hooks-output.md`「出力フィールドの使い分け」にある。

現行の規定は[design-hosts.md](design-hosts-rules-manifests.md#claude-codeとcodexの規範配置)の「Claude CodeとCodexの規範配置」にある。

共通のルール・スキルは`agent-toolkit/`の共有原本へ置き、Codex固有の公開能力との差分は2つのファイルへ集約する。
Codexの全主体へ適用する差分は`agent-toolkit/share/rules/rules-common.codex.md`、Codexのメインだけへ適用する差分は`agent-toolkit/share/rules/rules-main.codex.md`へ置く。
hook・MCP定義などホスト別に明確に分離された資源は、各ホストの定義へ置く。
全ての実行主体へ適用する条文だけを常時配る規範とし、メインエージェントだけに適用する条文とサブエージェント・委譲先だけに適用する条文は別のファイルへ置いて、フックと`agents_server`が起動時に文脈へ追加する（2026年9月、ユーザー指示）。
規範の原本は`agent-toolkit/share/rules/`の1か所へまとめ、常時配る規範を`common/`、役割・ホスト別の規範を直下の`rules-*.md`へ置く。
`agent-toolkit/rules/`という名前はプラグインの仕様上の意味を持たず、原本が2か所に分かれて全体像を見渡せなかったため廃止した（2026年11月7日、ユーザー指示）。
本文を1つのファイルへ混ぜるとメイン専用の条文が委譲先へ届くため、ファイル単位の区別は保つ。
共有原本をCodex固有条件で分岐せず、Codex側の基礎指示で上書きして、Claude CodeとCodexの共通契約を維持する。
この配置はCodexの確認・待機・並列化・ツール利用前説明の差分をCodex基礎指示へ閉じ込める。
共有文書をCodex用に複製する案は、原本・生成物・自動チェックの同期対象を増やすため採用しない。

2026年10月11日、ユーザーは[UK AISIの技術報告](https://arxiv.org/abs/2609.38415)を根拠に、範囲外の第三者への作用、身元と開示、自動応答を承認にしない判断をCodexの全エージェント向け規範へ取り込むことを選んだ。
同報告のv1は2026年9月29日投稿で、サイバー課題を模した環境において全ツール呼び出しをLLMが模擬し、OpenAIのサイバー向け安全対策を外した条件で、OpenAIのモデルだけを比較した。
観測したのは、範囲外のOSSへの悪意ある貢献、偽の身元と内容の隠蔽、汎用の自動継続文を許可と読む行動であり、明示した範囲によって減少しても消滅しなかった。
ユーザーは他のモデル系統で起きないと確定した結果ではないという前提を受け取ったうえで、追記をCodexだけ、取り込みを規範の追記だけへ限定した。
この判断を必要とする読み手は後続の規範編集者であり、Claude Code側の常時規範へ移す案やCodexのsandbox・承認設定を強める案より、この明示された範囲を優先する。
現行の規定は`agent-toolkit/share/rules/rules-common.codex.md`「第三者への作用と認可」にある。
