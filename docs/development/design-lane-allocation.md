# レーン配分の上限と単独稼働の設計記録

[設計記録の索引](design.md)と[担当の責務と工程間の知識境界の設計記録](design-workflow-boundaries.md)から参照する主題別の記録である。

## AWI処理の工程と選定

### レーン配分の上限と単独稼働の扱い

選定YAMLは初回候補・初回割当・不可分成分の構成WIと型付き結合条件を`初回配分`として保持する。
上限は初回候補数Nから求めるB=`floor((N+9)/10)`に固定し、初回割当と統合済み・全段階を含む現在の全レーン集合へ適用する。
追加件数や成分の時間で上限を増やす例外は撤去する。
独立成分がBより多い場合も同じレーンで順に扱えるため、全件の処理と不可分性を保てる。
初回候補0件ならB=0を保ち、既存レーン0件では追加の割当先がないため、run-lanes.mdの割当手順で上限と割当先の不足を続行できない理由として返す。
時間の見込みはレーン別の所要時間へ集約し、成分別の実装・統合秒数は保持しない。
結合の構造と元入力との一致は公開確認（`pick-wi-check`）が確かめて不成立なら拒否し、依存・定義・段階比較の意味はメインが検収する。
公開確認は依存の根拠が元のWIのfrontmatterと、再開計画の根拠が選定の再開位置と一致するかを確かめる。
書込重複の根拠は定義と段階比較だけを持ち、公開確認は実行のたびに両端のパスの重なりと段階の一致を選定の現在の`書込対象`と`レーンの所要時間`の`段階`から判定する。
`初回配分`は保存後も同じ値を保ち、パスと段階は重複して保持しない。
`書込対象`は初期配分の見込みであり、開始後の要求内の追加編集によって逐次更新しない。
担当間の衝突は統合時の追随・解消で扱う。

レーンの現在の`統合状態`は初回配分と別の事実であり、`atk lane integrate`が全計画の保存とWI終了の成立後に`pick-wi-check --mark-integrated`で、レーン行とその時点でそのレーンに属する全項目へ記録する。
メインは統合結果と担当の終了を検収し、同じ状態を別の操作で保存しない。
状態記録（`--mark-integrated`）と追加統合（`--merge`）は全体の条件を確かめてから原子的に保存する`pick-wi-check`の同じ公開操作を使う。
統合済み相手の詳細記録は省略でき、その相手だけとの重複なら同段階・先行指定なしで開始できる。
旧詳細は履歴として読める。
新しい実施内容を合流したレーンは未統合へ戻し、追加のないレーンと所属WIを保持する。
所属WIの履歴と状態の所有を保つため、完了レーンも同じYAMLへ保持し、統合状態の記録を`atk lane integrate`の1つの操作へ集約する。

統合状態はレーン行に加えて`選定`の各項目にも持ち、記録時にそのレーンの全項目を統合済みにする。
合流で未統合へ戻ったレーンでは、レーン単位の状態だけでは統合済みの旧項目と追加項目を区別できないためである。
合流は統合済みレーンの既存項目へ状態を写してからレーン行を戻し、追加項目は未統合とする。
項目の欄を持たない保存済みYAMLは、所属レーンの行の状態で同じく判定する。
書込区分のパスの実在、書込予定の範囲と区分、導出記録、公開工程の規範根拠、規範指定の判定は作業ツリーを読み、作業前の作業ツリーで成り立つ選定時の前提を確かめる。
統合済みの項目と、同じ呼び出しで統合状態を記録するレーンの項目にはこれらを適用せず、履歴として扱う。
2026-10-16に、レーンの作業で書込対象を改名した統合の記録が、改名前のパスを統合後の作業ツリーで判定して終了コード1で止まり、`atk lane integrate`が最終化できなかったためである。
未統合の項目への判定、本文の特定、target_repoとoriginの一致、レーン間と初回配分の判定は全項目へ適用する。
統合前の作業ツリーで判定し直す案は、統合記録の入力に統合前のcommitを加えて再現する機構を要するため採らない。
未統合の項目まで判定を緩める案は、選定時の検収を失うため採らない。
作成後の`導出した新設先`を受理した過去の是正は判定を個別に広げただけで、改名・削除や規範条件の変化を覆わなかった。
このため、統合済みの項目へ作業ツリーの状態を前提とする判定を適用しない構造で、今後加わる同種の判定も覆う。

選定の段階案は、比較した単一段階案の完了見込みを最上位の`単一段階案の完了見込み秒数`へ保持する。
採用した段階側の見込みはレーン別秒数から求める。
単一段階で実装秒数が6000を超える場合は、比較した段階案の秒数か上限内に成立する段階案がない宣言を`段階案の完了見込み秒数`へ保持する。
生成・チェック・受領・説明が同じ比較値を読み、
段階2以上で欄を欠く入力は保存前に拒否する。
型と欠落の判定は機械チェック、配分と理由の妥当性はメインの読解が担う。
追加選定では全体の比較値を再確定し、追加YAMLの値だけを使う。

公開工程の規範根拠・段階案の比較・補正は構造化した欄で持ち、パスや数値との対応と記録の有無をチェックする。
自由記述の`根拠`だけでは定型文の貼り付けや記録の欠落をチェックが通し、メインの読解でしか見つからないためである。
各レーンの補正前の2値と最上位の`見込みの補正`が持つ係数から補正後の値を確かめ、係数が1以外なら参照した記録を求める。
追加でも係数を共通に保ち、補正前の値を累積する。
割当・比較・補正の意味の妥当性はメインの読解へ残す。

選定の書込範囲の記録とチェックは、レーン配分の正しさ（同じ段階の書込競合の回避）への寄与で採否を決める。
判定の条件は、[「AWI処理の工程と選定」](design-selection-workflow.md#awi処理の工程と選定)が導入理由に挙げる2026年10月1日（個別ファイルの欠落）と10月6日（範囲説明を覆う広い範囲による全レーンの包含関係）の観測が再発しないことである。
変更対象管理の厳密さへの指摘と選定入力の削減要求を踏まえ、現在の各項目を次のとおり扱う。

| 項目 | 判定 | 根拠 |
| --- | --- | --- |
| 非書込パスの全分類 | 除く | 配分に必要な書込予定を元本文と限定調査で意味検収し、参照先の目録作成を省く。個別書込先の欠落を防ぐ判断は保持する |
| 広すぎる書込範囲 | 残す | 10月6日の包含関係の再発を防ぎ、個別対象を不必要な上位範囲へ広げない |
| 書込区分のパスの不正 | 残す | 実在しない・正規化されないパスは重なりの比較を成立させない |
| 区分間の重複と書き込まない反映先の不正 | 残す | 任意で記載した非書込区分との矛盾を検出し、公開工程所有をレーン競合から分離する |
| 公開工程の規範根拠 | 残す | 公開工程の書込対象をレーン競合から外す根拠であり、配分に直接作用する |
| 導出した新設先 | 残す | 本文に無い新設先を書込対象へ置く受理の手段である |
| 書込範囲の理由 | 除く | 自由文の有無だけをチェックし、重なりの判定と配分を変えない。範囲を狭める限定調査と意味検収はメインの手順に残るため、両観測の再発防止に寄与しない |

同一段階の未統合レーンで共有するパスだけに、双方の独立した定義の詳細を求める。
別段階の先行関係は現在の書込予定の重複から導き、先行指定の欠落と逆転を検出する。
全共通パスの詳細を生成し続ける案は入力削減にならず、競合判断の全撤去は誤配分を防げないため採らない。
要求内で計画・実装中に増えた編集先は既存の担当裁量と直列統合の追随・競合解消で扱い、追加通知を設けない。

撤去した`書込範囲の理由`は保存済みの選定YAMLをそのまま読めるよう読取時に破棄し、新しく書く入力では未知の欄として拒否する。

`agent-toolkit:process-wi`の選定工程は、上限内で配分を比較する目安に6,000秒を使う。
見込みの入力は、AWI本文に加えて過去の計画の`## 進捗ログ`が持つレーン別の稼働時間の計測値とする。
この目安を置く理由は、開始時点の見込みだけで配分を確定すると、見込みが外れたレーンが他のレーンの終了後も
1つだけ動き続け、その区間がそのまま壁時計時間へ乗ることである。
2026-09-16のprocess-wiの実行では、レーン別の稼働時間が2,298秒から6,708秒まで広がり、単独稼働が9,482.3秒に達した。

候補内の同一リポジトリ依存は推移的な連結成分も同じレーンへ置き、依存先から処理する。
同じ計画を再開する候補も、進捗ログとレビュー指摘管理表を共有する単一の書込資源として同じレーンへ置く。
通常中断は`~/.claude/plans`の絶対パス、観測のみの再開は`private-notes/plans/`からの相対パスを計画識別に使い、メインが分割不能な連結成分へ加える。
処理中の追加では、追加候補と既存選定の計画識別も同じ規則で比較し、同じ計画を持つ既存レーンへ費用比較より先に割り当てる。
`pick-wi-check`と保存後の意味検収でも同じ不変条件を確かめる。
計画ファイルを探索して補う案は、メインが確定した再開位置とは別の対象集合を確認処理が生成するため採らない。
必要な依存と同じ再開計画を持つ成分は同じレーンへ保ち、他の成分もそのレーンで順に扱って件数式の上限を維持する。
書込の重複は同段階の同時書込を避ける条件とし、推移的な連結だけで全件の単一レーン固定や6000秒超過を不可避としない。
例えばAがX、BがXとY、CがYを変更する独立要求では、AとCの並行後にBを始める案を比較できる。
全件が同一定義を書く場合の直列性と、実依存・同じ再開計画の不可分性は維持する。
既存のレーン数上限内で段階案を作成し、各段階の最長実装時間と直列統合時間の和を全段階で合計して単一段階案と比較する。
短い単一段階案を採用する場合にも比較理由を残す。
選定結果の既存の`段階`と`先行レーン`で先行統合後の開始を表せるため、新しい実行基盤は要らない。
着手不能な先行項目や上流成果待ちがある後続は待機を維持する。
同じ候補をprocess-wiの別の実行へ送る案は採用しない。
段階化する場合も全候補をprocess-wiの同じ実行に保持し、後段は先行統合後のHEADから始める。

レーン工程の進行中に稼働レーンが1つになった時点は、そのまま続行する。
そのレーンの未着手のAWIを新しいレーンへ移す方式は採用しない。
未着手AWIを新しいレーンへ移す方式は、計画ファイルの分割と書込所有権の移譲を要し、実行工程で計画ファイルを更新しない方針と両立しない。
単独稼働の区間は、選定工程が前段の上限と段階案を比較して短くする。
品質確認の削減とClaude利用上限時のモデル切替は短縮案に含めない。
