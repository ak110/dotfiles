# 処理中の処理対象WIの追加の設計記録

[設計記録の索引](design.md)と[担当の責務と工程間の知識境界の設計記録](design-workflow-boundaries.md)から参照する主題別の記録である。

## AWI処理の工程と選定

### 処理中の処理対象WIの追加と反映後の観測

同じprocess-wiの1回の実行へ追加するAWIの正式ファイル名の受領と、ユーザーの指定対象の確定を追加選定の開始契機とする。
並行する他の起草の完了を待つ案は、メインが確定済み差分を選定へ渡せる時点より開始を遅くするため採らない。
初期選定中は集合和、完了後は追加mergeへ直ちに接続し、通常新着と次回向け振り返りAWIの境界を保つ。

追加の構造更新は`atk run-script pick-wi-check`の`--merge`・`--lane-map`・`--output`で一括して行う。
最終割当の費用を再確定した場合は任意の`--lane-cost-updates`で合流後の秒数と根拠を渡し、段階・先行参照・元項目は保持する。
専用の合流スクリプトとチェック後の手編集を増やすと参照変換と保存の所有が分散するため、全体チェック成功後の原子的保存へ集約する。
追加項目の導出記録も同じ入力の値として保持し、分類・配置・共有定義の意味は担当が検収する。

process-wiの1回の実行が長いと、選定後に投入されたAWIの待ち時間が増える。
明示追加と即時対応で確定した項目は初期選定中なら元の集合へ合流し、選定後ならメインが追加YAMLを分類・チェックして既存の統合操作で元YAMLへ保存する。
集合和と重複除外、回答済みUWIの元項目の既存操作、未遷移分だけの開始と最新の保存後の検収を保つ。
レーン工程の書込対象・定義、依存と再開計画を既存レーンと比較し、公開工程だけの書込対象を競合へ入れない。
追加は既存レーンへ割り当て、同じthreadへ渡し、先行計画を凍結して追加計画を作成する。
統合済みの割当先も保持した同じ資源をcreateの所有登録から再利用し、同じthreadへ追加する。
回収をレーンの識別子とthreadの失効にすると、同じ文脈の再開を新しい文脈の再取得へ変えて費用を増やすためである。
稼働中の担当は現在工程を完了してから追加へ続け、割当変更だけを理由に中断しない。
告げられていない新着と振り返りAWIは次回へ残す。
選定は`selection-procedure.md`、割当は`run-lanes.md`が持つ。
別の選定担当を起動する案は廃止要求に反し、選定と保存の往復を戻すため採らない。

ユーザーが処理中のセッションへキュー操作（UWIへの回答かAWIの投入）を告げた発話は、その項目を同じ実行へ加える明示指示として扱い、追加の可否を問い返さない。
2026年10月6日にユーザーが「UWI回答した」と告げた際、メインは回答済みUWIが別のセッションの投入であり処理中の追加がAWIに限られることから次の実行へ回し、追加の可否を問い返した。
回答済みUWIを投入元のセッションで限る条文は、回答済みUWIの通知が全セッションへ届いて無関係なセッションが処置を検討する往復を防ぐためのもので、ユーザーが自ら告げる場面を想定していなかった。
このため限定の対象をユーザーが働きかけていない自動の通知に限り、告げた発話の扱いは`agent-toolkit:process-wi/references/selection-procedure-addition.md`「処理対象WIの追加」の1箇所に置いて他の文書から参照する。
名指しの無い告知では処理対象WIに含まれない回答済みUWIの全件を候補差分とし、告げられていない新着は従来どおり次の実行へ残す。
発話の意図を機械で判定する案は、意味の判断を要するため採らない。

初回の新規計画作成は項目別の再開位置が無い集合へ適用し、既存計画へ属する再開項目と分ける。
統合の全計画保存と未終了計画の後続復元は、保存後のcheckoutとして順序を保ち、保存省略の例外へしない。
復元はセッション終了時のメインが所有する。

2026年10月4日に、メインの追加分類で不足・誤分類の修正が反復した。
当時は選定と処理開始をpickerへ集約した。
2026年10月9日の役割廃止後は、その対処が守っていた元本文による分類、最新のチェックと意味検収をメインの初期・追加選定へ同じ基準で残す。
独自の部分分類でチェックを埋める処置は採らない。
