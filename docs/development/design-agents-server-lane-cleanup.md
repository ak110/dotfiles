# レーン回収と資源解放の設計記録

[設計記録の索引](design.md)から参照する、レーン回収と資源解放の記録である。

## 公開ツールの契約

### レーン回収と資源解放

レーン回収では、登録簿が終了・未解放と示し、cwdが対象worktree配下にある委譲sessionについて、使用中判定の前に所有agents_serverへ解放を要求する。
既存state_dir内の要求・応答を介し、所有側の常駐監視が所有者と終了を再確認してmanager内部の`stop(session_id, retain_result=True)`で解放する。
明示的な`atk lane delete`は未回収結果を保ち、main用の待機期限から導出した単一期限内で解放応答と資源終了を待って再判定する。
自動回収では未回収結果を保ち、解放待ちで終了処理を占有せず、その時点の適格条件で回収を判定する。
実行中、未解放、所有側無応答、解放後の残存資源では保持し、対象の委譲session IDと未回収理由、再開操作を案内する。
委譲元は終了と結果本文の回収を確認し、再開する予定が無ければ、公開MCPの`agents_server`の`stop`へそのIDを`session_id`として渡す。
公開呼び出しは`stop(session_id="<回収結果にある委譲sessionのID>")`であり、`retain_result`を指定する引数は公開しない。
公開`stop`は終了時の結果も破棄するため、未回収結果を保持する自動解放と使い分ける。
停止が成功して保持理由を解消した後、対象リポジトリをcwdとして`atk lane delete --session-id <レーン資源を作成した所有sessionのID>`を再実行する。
`--session-id`は元の回収と同じレーン資源の所有sessionを指し、公開`stop`の対象IDとは役割が異なる。
実行中は終了と結果回収を待ち、所有側の停止失敗や外部プロセスの使用が残る場合は資源と回収結果を保持する。
通常削除、終了時回収、固定作成先回収と移管は同じ使用中判定を使う。
完了した要求・応答は回収し、異常終了時の残存は既存state_dirの7日掃引へ委ねる。
未知PIDへのsignal送出や使用中判定の免除は、所有境界と生存資源保護を失うため採らない。
