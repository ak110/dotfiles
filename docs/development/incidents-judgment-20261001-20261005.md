# 障害・欠陥の記録: 誤判定と検証不足（2026年10月1日〜2026年10月5日）

[誤判定と検証不足](incidents-judgment.md#誤判定と検証不足)の事例を発生時期別に収録する。

- 2026年10月1日: CIのpytest指定へnode selectorを加えた変更で、その指定を別の文法で読むrootのテストが変更範囲の検証から外れていた。
  ランチャーへのlogs追加でも、実行中のランチャーを書き換える更新操作が検証されなかった。
  どちらもCIで初めて検出された。
  直接原因: 検証対象の選定が変更ファイルの静的な参照名と新機能のシナリオに閉じ、異なる文法で読む主体と操作途中の状態遷移を検証対象へ結び付けていなかった。
  実行レビューも提出された探索記録を範囲として受け取り、独立に得た範囲と比べなかった。
  対策: `exec.subagent.md`と`plan-file-standards.md`で、検証コマンドの確定前に変更ファイルを読む主体と状態遷移を実装からたどり、探索記録へ対象・結果・除外理由を対応付ける。
  `reviewer.md`の種類8と`exec-review.subagent.md`の走査で、独立に得た範囲を提出記録と比べる

- 2026年10月1日: 共有branchの状態を条件とする運用規定を、ユーザーの指定どおり特定の実行環境だけが読み込むユーザー環境のルールファイルへ書き、規定の理由が求める読み手の範囲と保存先が届く範囲が合うかに触れずに完了を報告した。
  ユーザーの問いを経てプロジェクトスキルへ移した。
  直接原因: 置き場所を判定する条文が読込契機と実行主体による振り分けだけを持ち、読み手の範囲と比べる基準を持たなかった。
  ユーザーが示した手段を評価する一般則は「置き場所」「保存先」の語を持たず、想起されなかった。
  対策: `agent-basics:writing-standards`の次の資料へ、置き場所が届く読み手の範囲と規定の理由が求める範囲を双方向に比べる項を加えた。
  - `agent-basics:writing-standards/references/agent-documents-basics.md`

- 2026年10月1日: レーンの統合前検証が終了コード0で、変更していないテスト由来の非推奨通知だけを含んでいたのに、統合担当が手順の「警告の不在」に照らして阻害とし、メインの受理まで統合を保留した。
  直接原因: 統合手順の検証判定が、警告の種類と由来を問わない一律の不在条件を置き、警告の意味で判定する一般規定（`agent-basics:bugfix`の`references/response.md`）とそろっていなかった。
  対策: 統合手順に、警告の意味による判定と、警告を観測したときだけ統合前HEADの同条件の結果と比べる手順を置いた。
  是正commitの受領と公開前の検証も同じ判定へそろえた。
  警告の抑制と検証範囲の縮小は行わない

- 2026年10月2日: 実行レビューの対照実験で、第1群の複製はoriginがローカルworktreeのパスを指し、計画が参照する原因分析資料も複製していなかった。
  直接原因: 準備を主入力（リポジトリと計画本文）の複製だけで完了と扱い、消費側がたどる関連資料とリポジトリの識別、判定コマンドの起動まで代表条件で確かめずに全条件へ展開した。
  対策: `investigation.md`へ展開前に代表条件で資料の取得と判定コマンドの起動を確かめ、対象の未達と判定不能を分ける工程を置いた。
  `exec.subagent.md`の計画起草へ長い比較調査の開始条件と通常修正との並行開始の判断を、`exec.parent.md`の計画準備の受領へその記述の確認を加えた。
  再発（2026年11月13日）: 範囲不足。
  通知比較の編集先が一時領域に置かれ、成果物編集向けの通知を測れなかった。
  代表条件の合格がコマンド終了までで、隔離のための配置が対象の分岐も変える条件を判別できなかった

- 2026年10月2日: `agent-toolkit:atk-mode`の作業`add-awi-by-user`のセッションで、メインはCI失敗の確定的な回帰8件の直接的原因を確定しないまま、全体検証の方針変更の認可を問う形で症状の側の案だけを選択肢とする確認を発行した。
  直接原因: `agent-basics:bugfix`の初動による原因の確定を経ずに確認を発行した。
  対策: `add-awi-by-user`手順2で観測した問題を起点とする要求の対処の選択を問わず、原因と対策の確定をWI投入担当へ渡し、担当の`needs_escalation`を受けてから対処の確認を発行する。
  `add-wi.subagent.md`の返却へ確定した原因と対策の案を含める

- 2026年10月3日: GLATasksで今日の食事量を決める表示へ過去6日の余裕を加えた7日分の残量を表示し、算術の正しさと〇の判定との整合を理由に受理した。
  是正時にはユーザーの事実認識を〇の判定の変更要求へ広げる案を提示した。
  直接原因: 既存仕様との整合、算術の正しさと目的への適切さを区別せず、実装・テストの期待値・評価が同じ採用前提を共有して互いの一致で合格した。
  対策: 共通判断基準（`design-heuristics.md`「設計案の予備選別」）へ利用場面から必要な結果を導く評価を置き、初回レビューと是正の受領から接続する。
  確認要否の判定を目的・期待結果・認可の確定と手段の選択に分け、UWI書式・WIの裁量判定・ホスト別規範の旧条件を共通判定への参照へそろえる

- 2026年10月3日: Stop hookへの対処をWI投入担当へ委譲したメインが、機能の目的と比べずに不具合と文面の直し方を述べ、ユーザーに2回是正された。
  直接原因: `agent-basics:bugfix`の起動条件が対処への着手に結び付き、委譲中に判断を述べる場面を含まなかった。
  期待する契約を実装自身の文言から選び、目的を定める設計記録と、文面を受け取る主体が観測できる条件を評価していなかった。
  対策: 起動条件を不具合の有無・原因・直し方を述べるか提案する前へ広げた。
  初動と現物との比較に目的を定める仕様・設計記録を含め、文面の方向を提案・委譲する前に`agent-basics:writing-standards`を起動する。
  注記の180秒の間隔と機械注入の除外は保持した

- 2026年10月5日: process-wiで反映後の完成条件の観測だけが残る項目を扱ったレーン担当が、観測の前提を妨げる残存Codexの3プロセスを、同じOSアカウントの所有であることから「ユーザー所有」と返し、前提を整えられる主体をユーザーだけと記録した。
  直接原因: 残存プロセスのOS上の所有者を、生成主体と前提を整えられる主体へ読み替えた。
  対策: `exec.subagent.md`の観測のみの再開と検証結果で、前提を妨げる状態の生成主体・起動元・起動契機を親子関係、起動時刻、実行記録、実装から調べ、未確定範囲とともにメインへ返す

- 2026年10月5日: aichat2のAWI投入のセッションで、メインは`agent-basics:bugfix`の`references/response.md`だけを読んで原因を述べた。
  直接原因: 原因に用いる値の事象時点を確かめる規定は`references/root-cause-analysis.md`の1項だけにあり、拡張原因分析へ進んだ場合にしか読まれず、対象の例も設定、依存版、外部状態で規範の条文を挙げていなかった。
  対策: 時点の確認を`agent-basics:bugfix`の`SKILL.md`「初動と拡張原因分析の判定」の第1項へ置き、対象に規範・スキル・手順の条文を含め、確かめていない候補を推定として扱う。
  `root-cause-analysis.md`の上位規範の確認と未適用規範の是正原則の適用対象を、事象時点に存在した規範に限った

- 2026年10月5日: Claude Codeのセッションで、メインは何か計上されないものが無いか確認するよう求め、「例えば」に続けて1つの呼び出し元を挙げた依頼を受けた。
  直接原因: 例示の語と調査を求める語を併せ持つ発話を受けたメインの文脈に、その発話が`user-utterance.md`の範囲語と例示を併せた依頼の項に当たることを示す手掛かりが無かった。
  対策: 例示の語と調査を求める語を併せ持つ通常発話へ、`UserPromptSubmit/user_prompt_submit`が注記を返す。
  再発（2026年11月3日）: CI定義の複雑さとpytestの例を併記した調査語の無い指摘で、メインが対応範囲をpytestへ狭めた。
  注記が調査語との同時一致を条件にしていたため返らなかった。
  例示の語だけを条件に範囲判断の節の所在を示し、調査語を含む場合だけ独立調査の所在を加える形へ改めた
