# AWI本文起草の分離の設計記録

[設計記録の索引](design.md)と[WIキューと要求本文の設計記録](design-wi.md)から参照する主題別の記録である。

## AWI本文起草の分離

単一で定型的な要求は、原因分析、複数リポジトリ、未確定な要件分類を伴わない場合にメインが直接起草する。
メインは保存前の意味検収と構造・表記・重複の機械チェックを所有する。
複数の独立要求、欠陥の原因分析、対象・由来の分類、公開契約、部分採用または未確定事項を持つ原稿は独立した起草と投入前レビューへ分ける。
要求の性質による選択は`wi-standards`が所有し、専念型・付随型の配送方式だけで担当構成を固定しない。
単純な要求へ常に独立した読者別探索を課す案は、メインの意味検収で満たせる確認を重ねるため採用しない。

保存直前には、起草前と同じ対象・条件でactiveキューを再照会する。
要求全体を覆う既存項目は再利用し、部分被覆・衝突・被覆元の終了では原稿の修正へ戻る。
保存CLIの排他制御は物理的な競合を防ぎ、保存主体の再照会は要求の意味上の重複を防ぐ。

処理時点の対象集合を判定する要求では、起草時に分類軸、判定主体、判定時点、保持条件と完成条件を確定する。
個々の対象の採否は指定された処理時点に残し、起草時の候補一覧を閉じた集合へ変えない。
実現方式は既存内部機構の流用・統合・処理なし・新設から選び、必要な結論を`## 調査結果と判断根拠`へ残す。
比較には実行ごとの費用も含める。
