# 障害・欠陥の記録: agents_serverと委譲基盤の不全（2026年11月）

[agents_serverと委譲基盤の不全](incidents.md#agents_serverと委譲基盤の不全)の事例を発生時期別に収録する。

- 2026年11月17日: 巡回中、Codexの担当がturnを終えた後も`running`のまま公開され、`kill`は配送未確定、`send_message`は時間切れとなった。
  統括は約1時間待機を繰り返した。
  直接原因: 旧世代の共有管理サービスが会話を新世代へ移す`move_context`で、登録簿から復元した停止済みsessionの型が状態codecに未登録だった。
  共有監視の1巡が毎秒`TypeError`で失敗した（`agents-server.log`に12:27以降1300件超）。
  失敗が世代移行の確認の中で起きるため、同じ巡回の自動再開と状態保存が全会話で止まった。
  背景原因: codecは型の厳密一致で対応表を引くため、再開状態の派生型を加えた変更で往復の試験が無かった。
  1件の移行失敗が監視全体を中断する構造で、ERRORログが続いても`show`・`wait`の診断へ届かなかった。
  統括は配送未確定の後に所有者を確かめず、サーバー停止前に自身の接続先を確かめなかった。
  対策: 派生型をcodecへ登録して往復を試験で固定し、世代移行の確認が失敗しても状態保存は続ける。
  実行中の別所有sessionへの照会・停止の応答に、所有サーバーと照会したサーバーの識別子を含める。
  同じ前提での待機の反復と、自身の接続先の停止を避ける案内を加えた。
- 2026年11月18日: Windowsで`update-dotfiles`の更新後処理が公開した管理サービスの新世代が、起動確認の終了と同時に終了した。
  受付先は終了した世代を指し続け、旧世代で稼働していた会話の状態保存が`FileNotFoundError`となり、ユーザーへの送達も失敗した。
  直接原因: 起動確認が使うMCP SDKの`stdio_client`は子プロセスを離脱不可の`KILL_ON_JOB_CLOSE`のJobへ入れる。
  確認用の転送側が起動した管理サービスも同じJobに属し、接続を閉じた時点で止められた。
  背景原因: 確認後も常駐する管理サービスを、短時間の確認が所有する子プロセスから起動していた。
  受付先の切替は起動直後の公開だけで確定し、公開した世代が終了した場合に生存する世代へ戻す処理が無かった。
  対策: 管理サービスを確認用の接続とは別の子プロセスから公開を保留して起動し、確認の終了後に生存を確かめてから公開する。
  受付先の世代が終了していれば生存する公開済みの世代へ受付先を戻し、公開の途中で終了した世代が残した静止も解除する。
  修正の検証で、SSHのセッションから起動した管理サービスがセッションの終了とともに終了することも観測した（2026年11月19日）。
  転送側は即時Jobの制限だけから離脱の要否を決めており、venvの`python.exe`が作るJobの外側にあるセッションのJobへ管理サービスが残っていた。
  転送側が離脱を常に指定し、拒否された場合だけ所属を継承して起動するよう改めた。
- 2026年11月19日: 統括がSSHから`update-dotfiles`を実行した後、Windowsで非昇格の旧世代の管理サービス5つが`generations.json`の読取で`PermissionError`となって停止し、ログが132MBまで増えた世代もあった。
  新世代の公開は、停止した旧世代のpipeへ接続できず`FileNotFoundError`で失敗した。
  直接原因: 状態ディレクトリは`mkdir(mode=0o700)`と`tempfile.mkdtemp`で作成され、WindowsのPythonはOWNER RIGHTSだけに依存する保護付きDACLを付けていた。
  SSHのログオンは昇格したtokenで動き、書き直した`generations.json`の所有者が`BUILTIN\Administrators`になって、非昇格のtokenでは読めなくなった。
  背景原因: POSIXの0o700がWindowsでも同じ意味になると見なし、昇格したプロセスと非昇格のプロセスが同じユーザーの状態を共有する構成を試験していなかった。
  昇格した`update-dotfiles`が、非昇格の会話と共有する管理サービスを起動して受付先として公開した。
  対策: 所有者だけが使うディレクトリの作成を`private_directory`へ集め、Windowsでは継承するACLで作成する。
  更新後処理で旧版の保護付きDACLを継承へ戻し、昇格した実行では管理サービスの起動と公開を次の非昇格の実行へ延期する。
  経緯と判断は[design-windows-permissions.md](design-windows-permissions.md)にある。
