# 通読資料と費用の集計の設計記録

[設計記録の索引](design.md)と[振り返り・知見集約の設計記録](design-session-review.md)から参照する主題別の記録である。

全記録から生成する統計と、メインが通読する会話の流れは別の集合として扱う。
会話の流れはセッション全体の目的、判断、主要な操作、分担、待機、再読、失敗と手戻りを原則100,000バイト以下へ縮約し、1エージェントが一続きで読む。
自動挿入本文と詳細本文の写しを除き、必要な全文は記録位置から取得する。
会話の流れを複数の読取担当へ分ける案は、全体像を分断し、起動ごとの固定費と利用枠の消費を増やすため採らない。
統計の母集団は全記録を保つ。
分析の費用と作業全体の費用を混同しないためである。

会話抽出は復元・点検・状況照会・引き継ぎ・特定操作の調査でも共用する。
少量表示は担当・期間・直近件数・前回位置を選び、既定16000バイトを文書全体へ適用する。
固定説明、記録位置、選択条件、件数、省略・未確認の案内も予算へ含め、表示と全文bundleを分ける。
固定部分が全体概要の予算を超える入力は、予算を超えた出力や準備失敗にせず、有限表示と継続・詳細取得へ接続する。
条件自体を含む最小表示が収まらない指定は、理由と次操作を伴う入力エラーとする。
本文を切り詰めた概要から成功・認可・全体の完成を確定する案は採らず、原文と結果、公開の実行状態へ対応付ける。
毎操作の全履歴再抽出と新しい進捗台帳を加える案は、同じ抽出の再利用と範囲指定で目的を満たせるため採らない。
公開入力と利用手順の定義元は`agent-toolkit:/share/session-conversation-extraction.md`「会話の少量取得」に置く。
run-skillの失敗報告は、起票ホスト・OS・配布版、対象入力と記録の状態、manifestの診断と準備済み対象、終了コードと有限のログ末尾を本文へ埋め込む。
記録のパスも残すが、別ホストの処理担当がそのパスへアクセスできることを前提にしない。
会話本文は転記せず、抜粋の欠測と切り詰めを明示する。
処理担当は本文の入力を合成した再現テストで是正を検収し、不足する根拠だけを起票ホストへ求める。

OpenCodeの対話ホスト記録はSQLiteのsession・message・partから読取専用transactionで取得し、既存のイベント・証拠・準備文書へ正規化する。
prepareとevidenceは`--opencode-session-id`を受理し、任意の`--opencode-db`で記録の所在を指定できる。
原本のmessage/part識別子と論理的な記録位置を保持し、同じ応答をmessageとpartの両方からusageへ重ねて数えない。
DB不在と未対応schemaは理由・次の操作と終了2を返し、記録のあるホストでの再開へつなぐ。
別ホストの原セッションの実際の振り返りは、是正を含む配布版が届いた後の起動元が検収する。
是正する担当の完成条件とは分け、原ホストでの振り返り完了を再現テストの成功から推定しない。

候補と統計も、保存する全量と初回に読む表示を分ける。
候補は70,000バイト、統計は30,000バイト以下のUTF-8とし、会話の流れと合わせてメイン1エージェントが全体を判断する。
候補は種別・件数・必須性と代表位置を示し、全ID・全候補の詳細への対応・過去の同種記録を`bundle/review-index.jsonl`へ保持する。
候補の全欄は`candidates.jsonl`、個別の原文証拠は`candidate-evidence.jsonl`が案内する。
記録の由来は共有索引と`timeline.jsonl`の`record-provenance`を使い、候補ごとの反復展開を減らす。
統計は総量・計数定義・担当別tokens上位・律速・圧縮と未計測・読込と反復の上位を表示し、17観点の初回材料と追加照会先を対応付ける。
担当と対象の全量は`stats.jsonl`と`resource-usage.jsonl`に保持し、表示外・非律速担当も必要に応じて照会する。
上位外の件数と粒度を表示し、表示の省略と未解決記録を分ける。
全量の操作入力と発生位置、質問・全選択肢・実回答は保存側へ保持し、趣旨や原因を確定する際に詳細を取得する。
候補の削除、必須評価の免除、全詳細を分割して毎回読む案は、全体の判断と読込費用削減の目的へ適合しないため採らない。
大出力の点検は、収集済みの呼出しと結果の対応から、記録の返却本文8,192バイト以上を大きい順に最大10件示す。
明示された単独の本文取得を除外してから上位を選び、複合・解釈不能の入力は点検へ残す。
量だけで問題候補へ昇格させず、メインが目的・必要情報・後続の利用と比べる。
新しい監視・常設担当は加えない。

読取・Skill起動・範囲指定・結果本文量・locatorは担当別に集計し、メインの反復・token上位と担当別の大量結果も準備資料へ示す。
費用の無駄を毎回17観点で確認し、確認結果を報告へ1行で残す。
同じ対象への担当横断の読取量と回数も集計する。
担当別の値だけでは複数担当が同じ対象を読む費用が分散するためであり、必要な読取かは目的と担当範囲から判断する。
集計値だけで問題候補へ昇格する案は、必要な読取と不要な反復を量だけで区別できないため採用しない。

生成作業の入力は、編集本文・委譲入力・コマンド・その他のbyte量と保存本文の参照を既存のresource-usageへ保持する。
hookは生成元・用途・本文を対応付け、部分的な文の再出現も元と再出現の記録位置を残す。
同一イベントの文の反復を含め、履歴をAPIへ再送することは新しい発生に数えない。
識別子と数値を保ち、必要な独立配送・圧縮後の復元・不要な重複の判定は担当が文脈から行う。
初回統計は上位例を示し、全量は既存bundleから取得する。
mode別の費用は記録にあるusageと実行identityへ帰属させ、未計測を別に示す。
入力byte量からtokenや料金を換算した値と実測値を混ぜず、要求モデルだけから実行モデルを推定しない。
新しい台帳と常設の分析担当は加えない。
改善案の比較は、一連の仕事を先に定め、具体的な代替案が各原因へ作用する機構を比べる。
既存AWIとの部分被覆は、未被覆の原因に作用する案を検討する入力とする。
全体通読・17観点と同じセッション内の処置を保持し、分析だけの短縮で作業全体の費用を説明しない。

時間分析と過去対策の比較は、`references/analysis.md`「原因と対策」の共通判断を使う。
以前は反復判定の対象が規範未適用とユーザー介入に限定され、時間分析が当回の局所的な短縮案で終わっていた。
2026年10月8日の是正では対象の限定を除き、メイン、レーン内部、公開・検証、振り返り自身の律速も同じ比較へ接続した。
比較するのは過去対策が狙った原因・適用条件・反映状態と今回の原因条件であり、未反映、未適用、範囲不足、適用後も同原因が残る場合、別原因を区別する。
AWIの登録・採用や統合は効果の証拠とせず、別要因による全体時間の変化とも分ける。
未終了AWIとの重複判定は投入の要否を担い、有効性の判定とは分離する。
既存の本文検索と原因分析・報告欄で必要な証拠を扱えるため、新しい台帳、全過去ログの走査、追加の分析担当は設けない。

情報探索の遠回りと現行に合わない資料を根拠とすることは、成功した検索・読取にも現れるため、通読のツール呼び出しと前後の発話から抽出する。
分析は探索区間、必要な情報、読んだ文書の順序と定義元、現行の実装・契約との差を証拠へ対応付け、必要な詳細だけを照会する。
原因が案内不足や文書の陳腐化なら、その原因へ作用する索引・参照案内・文書是正を比較して通常AWIへ送る。
正常な調査を機械候補へ追加する案は、既存の通読と詳細照会で情報を取得できるため採らない。
