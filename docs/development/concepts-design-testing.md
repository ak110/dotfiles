# 方針・意向: 概念設計とテスト

## 概念設計と最小実装の優先順位

2026年8月のユーザー指示（Zenn記事「概念設計が、その後のコードの命運を左右する」の考え方の取り込み）に
由来する領域である。
現行の規定は`agent-basics:review-standards`の`agent-basics:review-standards/references/judgment-details-decisions.md`「解決案の比較」節にある。

- 対象領域の現実を無理なく表現する概念の切り分けを先に確定し、その制約の内側で最小実装を選ぶ。
  現実には別種である事象を既存概念の特殊ケースとして表現する案と、
  概念を分離する案は同じ階層で比較する
- 概念の分離・新設は観測済みの要件と現実の表現に必要な範囲に限る。
  設計を委譲したモデルが
  過剰設計に傾きユーザー介入が反復した観測が背景にあり、「過剰設計の抑制」の各方針は
  概念設計の優先と両立するものとして引き続き適用する
- 実装の選択は、ユーザーがその結果で何を判断し何を行うかから必要な結果を導いて評価する。
  既存仕様という事実、算術・実装の正しさ、目的への適切さは別々に判断し、意味の異なる値や概念を既存仕様へ一律にそろえない（2026年10月3日、対応commit `6566f6a0e`）。
  2026年10月21日には、成果物を使う主体の目的・利用場面から仕様と設計を導く共通原則を`agent-toolkit/share/rules/common/01-agent.md`「QCDと3段判定」へ集約した。
  人・機械、内部・外部を通じて適用し、明示要求と当然期待される条件を合わせて判断する。
  計画・確認・レビュー・画面設計と`design-heuristics.md`はこの原則へ接続する

## テストの本質性

- CIが全体の試験と静的検査を担う公開先では、手元の検証を変更箇所と関連テスト・lintに限る（2026年11月11日、ユーザー指示）。
  レーン内・統合時・公開前のいずれも、全体の試験を毎回実行する方式と、最後にまとめて全体を1回実行する方式を採用しない。
  2026年10月2日の「実行対象を正しく選べば回避できる」という回答と、9月13日のCIへ委ねる方針を引き継ぐ。
  CIが無い、または公開先でCIが実行されない場合は既存の全体検証を保つ。
  現行の上限は`agent-basics/skills/check-execution/references/verification-scope.md`にある

2026年8月のユーザー指示（Qiita記事「AIが実装し、AIがテストし、AIが「問題ありません」と言う時代の品質保証」の
考え方の取り込み）に由来する領域である。
現行の規定は`agent-basics:writing-standards`の
`references/testing.md`「検証単位の選定」節と、`plan-file-standards.md`「要件・外部仕様」節にある。

- 細かい挙動で、不具合の害が小さく、エンドユーザーが気付いてから直せば足りる対象には、テストを書かない（2026年11月11日、ユーザー指示）。
  発端は、作業項目の一覧でコピー後の表示が2秒間だけ変わることを確かめる実ブラウザーの試験が、負荷の高い実行でまれに失敗した件である。
  ユーザーは、その試験を直す作業項目に対して「だいたい書いたとおりに動くだろうし、バグったところで大した害もないし、ユーザーが気付いたら直すで十分」「あまり意味のないテストコードは書かないようにすべき」と述べ、試験全体を同じ観点で見直すことも求めた。
  表示の確認は試験から削除した。
  現行の基準は`agent-basics/skills/writing-standards/references/testing-selection.md`「削除・統合の類型」にある
- テストの価値は、何を保証するか（どの契約違反を検出できるか）にある。
  実装の実行結果として得た出力を期待値へ転記するテストは、実装の欠陥ごと固定するため避ける
- テスト設計（保証する契約・想定する失敗様態・テストレイヤー選択）は計画段階で確定し、
  テストコードの作成・変更を含む計画では`## 要件・外部仕様`への記載を必須とする
- テストはエンドユーザーまたは外部主体が使う最上位の公開操作から最終結果までを利用シナリオとして扱う。
  上位のコマンドやhookがある場合、内部の公開関数だけを通す試験で全体を保証しない（2026年10月21日、ユーザー指示）
- 記事が人間の役割とする独立検証の構造とテスト回避の防止は、既存規範（実行レビュー担当による要件・外部仕様水準の成果物評価、
  失敗テストの除外による回避禁止、分岐条件の効果の裏付け）が既にカバーするため、重複する規範を追加しない
