# 委譲プロンプトと役割文書の設計記録

[設計記録の索引](design.md)と[担当の責務と工程間の知識境界の設計記録](design-workflow-boundaries.md)から参照する主題別の記録である。

## 委譲の共通契約

### 委譲プロンプトと`<役割名>.subagent.md`

メインは委譲先専用の`<役割名>.subagent.md`および作成規範を読み込まず、`<役割名>.subagent.md`は役割名で、作成規範は絶対パスで各担当へ渡す。
agent-toolkitプラグイン内の`<役割名>.subagent.md`は`agents_server`がメインから受け取った役割名を自身のplugin rootの`share/`直下へ解決する。
作成規範の絶対パスは、メインが注入済みの`agent-toolkit:delegation`の所在から現行plugin rootを確定して解決する。
委譲元は新規成果物の絶対パスを起動時に指定するか、委譲先から報告を受領してから観測する。
AWI計画では、委譲元が既存ファイルと衝突しない保存先の絶対パスを確定する。
通常型のAWIの下流主体は、担当ファイル名と対象リポジトリを受け取り、キューCLIから保存本文を独立に取得する。
専用の原文ファイルを作成せず、本文を委譲プロンプトへ複製しない。
直接受領した人間由来のユーザー指示、ユーザー合意、参考素材または処理対象資料は、受領順を保持した素材レコード集合として渡す。
各レコードは種別、出所および引用範囲をこの順で保持し、逐語本文・回答全文をレコードの末尾へ続ける。
キューにない素材の逐語本文・回答全文は、計画外の明示入力として調査、起草、初回レビュー、再レビューへ渡し、計画本文へ転記しない。
初回起動後の追送ユーザー発言は、レーン担当が逐語本文、入力種別、出所、引用範囲を保持して真正性を保証し、レビュー担当は本文との整合だけを検収する。
調査担当は同じキューCLI出力のfrontmatterから投入元識別子を取得し、文字列を改変せずメインへ渡す。
`source`欄がない場合は値なしとして渡す。
レーン担当は全ての投入元で、原文が方針改訂を要求するか、明示した検証手段が現行方針に適合するかを先に確かめる。
この提案成立性の事前確認後に、投入元識別子に対応する生成手段固有の優先順位を適用する。
frontmatterの`source`からエージェント由来と判定される項目は後段で優先順位4に準じて懐疑的に判定する。
投入元識別子で由来境界を判定するが、投入元識別子やAWI本文からユーザー認可を推定しない。

別コンテキストに専用の起点の文書（`SKILL.md`、agent定義または`<役割名>.subagent.md`）を渡す構成では、委譲元は目的、入力、制約、期待出力および検収を定める。
委譲先の再走査、累積再監査、証拠抽出などの内部手順はその起点の文書だけを基準とする。
完了報告の返却方法の契約も同じ側へ置き、専用の`<役割名>.subagent.md`とagent定義のいずれかを持つ委譲では、
委譲プロンプトが基準文書の絶対パスと基準文書に未記録の差分だけを渡す。
委譲プロンプトへの前提の複製を禁じたまま契約を委譲先へ届けるには、契約の保持先を委譲先が読む資料側へ置く以外に方法が無いためである。
`claude-code-runtime.md`は契約を保持する側の要求だけを持ち、契約の本文は各`<役割名>.subagent.md`とagent定義が持つ。
同じ内部手順を委譲元へ複製する案は、委譲プロンプトへの転記と改訂時の不一致を誘発するため採用しない。
返却方法の契約を委譲プロンプトへ毎回複製する案も、専用資料を持つ委譲での複製禁止と衝突するため採用しない。
完了報告の宛先をフックで自動チェックする案は、文書1行の契約で同じ目的を満たせるため採用しない。
共有出力ディレクトリから成果物を推定する案は、並行する委譲の成果物を取り違えるため採用しない。

実行環境が委譲プロンプトを`user` roleで配送しても、そのtransport上のroleは人間の発話者を証明しない。
直接対話で受領した実際のユーザーメッセージと、委譲元が人間由来として出所と引用範囲を明示した素材だけをユーザー指示および合意へ分類する。
委譲元は起動命令と人間由来の素材を区別する。
起動命令と人間由来の素材を区別する基準は委譲先にある。
配送本文の出所判定は`agent-toolkit/share/rules/common/01-agent.md`の「方針が衝突する場合の優先順位」節が担う。
計画への由来記録は`agent-toolkit/skills/write-plan/references/plan-file-standards.md`の`由来`区分が担う。
実行レビュー担当への受け渡しは`agent-toolkit/share/exec-review-contract-generation.md`の「`review_contract`の生成」節が担う。
起動命令をユーザー合意へ昇格させた差分は、`agent-toolkit/share/exec-review.subagent.md`の種類2（認可された対象、範囲または外部可視の結果からの逸脱）と種類7（自動チェックでは検出できない作成規範またはプロジェクト規範への違反）で指摘する。
独立した指摘種類は新設しない。
委譲プロンプト全体の転記は委譲元の命令をユーザー合意へ昇格させるため採用しない。
