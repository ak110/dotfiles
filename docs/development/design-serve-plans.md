# 計画ファイル画面の設計記録

[設計記録の索引](design.md)と[画面統合とセッション・計画一覧の設計記録](design-serve.md)から参照する主題別の記録である。

## 計画ファイル画面

計画一覧はメイン計画を通常の項目とし、同じstemのメイン計画が存在しないレビュー指摘管理表も独立した項目として表示する。
目的はメイン計画とレビュー指摘管理表を重複表示せず、メイン計画が移動または削除された後も残存するレビュー指摘管理表へ到達できるようにすることである。
メイン計画が存在する場合はレビュー指摘管理表を一覧へ載せず、detail、バグ調査およびその他の付属ファイルも独立表示しない。
本文検索は一覧上のメイン計画へ対応付けたパスと実際のファイルパスの双方を比べ、孤立したレビュー指摘管理表の一致を失わない。

リモートのread RPCはファイル不在を`error_type: not_found`で障害から区別する。
共通取得処理はこの応答をFileNotFoundErrorで呼出側へ伝え、WARNINGや単発SSHへの切り替えを行わない。
存在確認は未作成の付属ファイルを正常な不在としてリンクから省き、明示的な本文取得は同じ不在をHTTP 404と取得失敗のWARNINGへ変える。
接続断・権限不足・パス不正など他の失敗は従来の警告と代替取得を保つ。
用途別にログを抑えるだけでは下位層の警告とSSH反復を止められないため、不在の分類はヘルパーと共通取得処理が所有する。

知識境界として、計画バンドルの種別と接尾辞、種別ごとの一覧の扱いは`agent-toolkit/agent_toolkit/_plan/bundle_kinds.py`が持つ。
計画rootの定義、表示と一覧の対象判定、走査、全文検索は`_plan/viewer_files.py`が、作成日時インデックスは`_plan/creation_times.py`が持ち、ローカル側（`_atk/serve/plans/`）とSSH先のヘルパーが同じモジュールを使用する。
SSH先のヘルパー（`agent-toolkit/scripts/atk_serve_plans_remote_helper.py`）は同じcheckoutの`agent-toolkit`を`sys.path`へ加え、これらの共有モジュールをimportする。
両ヘルパーは共通の`remote_command_argv`から`uv run --no-project --python 3.15 --with watchdog --with platformdirs`で起動する。
importできるのは標準ライブラリ、`platformdirs`、`watchdog`と、それらだけに依存する`agent_toolkit`のモジュールに限る。
Markdownの描画（`markdown_it`・`pygments`）など、リモートの実行環境に無い依存を持つ処理は`_atk/serve/plans/`に置き、共有モジュールからimportしない。
この依存の条件は`agent-toolkit/scripts/atk_serve_plans_remote_helper_test.py`がリモートの実行環境と同じ依存集合でヘルパーを起動して確かめる。
同じ判定をヘルパーへ複写して同期テストで一致を確かめる案は採らない。
同期テストは比べる組の外の定義の不一致を検出できず、接尾辞の集合が箇所ごとに一致しなくなったためである。

付属ファイルを常に一覧へ載せる案は採用しない。
メイン計画が存在する通常のバンドルで同じ計画を複数の項目として表示し、エンドユーザーが一覧から選ぶ対象を重複させるためである。

計画ファイル画面のプレビュー取得は`previewGeneration`で世代を管理し、新しい取得の結果だけを本文へ反映する。
同じHTMLの再同期では表示中の画像DOMとblob URLを再利用するため、画像のload・errorはDOMの接続と同じ選択対象であることから判定する。
URLの回収は`revokePreviewObjectUrls`へ集約し、要求の順序と表示中DOMの寿命を分ける。
画像の通知を取得世代だけで判定する案は、遅延した失敗の表示を失い、遅延した成功で現行URLを回収するため採用しない。
3画面のDOMは常に同じドキュメントへ存在し、画面の切り替えで購読も取得も中断しないため、画面をまたぐ世代管理は置かない。
画面をまたぐ世代で非同期処理を一括して遮断する案は、遮断する対象が存在しない分岐を各画面の全ての取得処理へ残すため採らない。
