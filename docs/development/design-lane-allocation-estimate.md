# 2026年10月のレーン配分試算の設計記録

[設計記録の索引](design.md)と[担当の責務と工程間の知識境界の設計記録](design-workflow-boundaries.md)から参照する主題別の記録である。

以下は2026年10月9日時点の例外規定を使った過去の試算であり、現行の配分では件数式の上限を維持する。

2026年10月9日の14件の配分は、完全な新設名を限定調査から渡すことで、旧lane-03の5件を読取・案内・帰属の3件と
履歴比較・検証記録の2件へ分ける案を比較できる。
SDK登録・transport・依存・導入の1件、backend・指示配送の2件、
旧lane-04の6件は元の群を維持する。
要求から導いた新設先は両書込区分のいずれかへ個別に置き、`導出した新設先`に要求と配置根拠を対応付ける。
親ディレクトリの実在だけによる受理は要求外の新設を通し、全WIへ名前を先に固定する方式は計画の配置判断を起草側へ移すため採らない。
未具体化の範囲は保守的な指定で保持し、具体化した箇所も既存の独立性・実依存・同じ再開計画の判定へ渡す。

当時の実装commit `1438c95c652d5172b9ce2c5fed3a4f2d37247ca0`では、両群が共有する
`agent-toolkit/agent_toolkit/_atk/help_text.py`の読取・agentsの説明とrun-scriptの説明は異なる`HELP`のキーだった。
run-scriptの登録は履歴比較・検証記録群だけが書き、帰属の説明と履歴比較も別の定義である。
履歴比較と旧lane-04が共有する`agent-toolkit/agent_toolkit/_plan/commit_mapping.py`は案内と入力検証・診断の定義が異なる。
旧lane-01と旧lane-02の設計文書の独立した定義も保持し、共有パスは`レーン間の重なり`で意味を検収する。
新設名そのものを今後の配分の固定要件にはしない。

補正前の実装予測2100・2400・4000・1750秒、各統合300秒、係数2.887864313を同じ条件で使う。
4000秒の個別内訳は記録されていないため件数比3対2で2400・1600秒へ分け、新レーンの固定費を統合1回分と仮定する。

```text
c = 2.887864313
変更前 = (max(2100, 2400, 4000, 1750) + 4 * 300) * c = 15016.894秒
分離案 = (max(2100, 2400, 2400, 1600, 1750) + 5 * 300) * c = 11262.671秒
推定短縮 = 3754.224秒
一般形 = (max(2400, x, 4000-x) + 1500) * c
```

配分が1600秒以上2400秒以下なら旧lane-02が最長で同じ推計となり、その外側や追加の調査・レビュー・競合解消で短縮幅は変わる。
この試算は14件の通常上限2レーンに対して、当時の6000秒超の例外を前提に他成分を分ける案を比較した。
分離案も目標10800秒を超え、観測した12757秒から推定短縮を引いた実績として扱わない。
入力と経過値の原記録はリポジトリ外のセッション記録にあり、
係数は当時の選定根拠の値である。
ここで過去レーンの補正を再計測した値ではない。
