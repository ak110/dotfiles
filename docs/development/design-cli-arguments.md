# サブコマンド登録と引数拒否の設計記録

[設計記録の索引](design.md)から参照する、サブコマンド登録と引数拒否の記録である。

## atkのサブコマンドの登録

ヘルプのsummaryとdescriptionは、目的または最重要結果を冒頭の短い文で示す。
タイトル、件名とユーザーが読むWIの部分も同じ文章原則を使い、コマンド木の全リーフは生成されたヘルプで確認する。
定義元は`writing-standards`とし、各コマンドは自分の目的と入出力だけを説明する。

`atk`の各サブコマンドは、実装のモジュールが引数を登録する`build_parser`と実行する`dispatch`を公開する。
`agent-toolkit/agent_toolkit/atk.py`はサブコマンドと`build_parser`の登録表、実行の登録表と、全サブコマンドに共通の前処理（旧形式の引数の解決、出力の保存、managed-tempの掃引）だけを持つ。
`atk wi`配下の入口と実行の振り分けは`_atk/wi/cli.py`が持つ。
引数の具体的な登録は同ディレクトリの`cli_read_parsers.py`・`cli_mutation_parsers.py`・`cli_process_parsers.py`が持つ。
`atk serve`は起動処理の依存を遅延して読み込む`_atk/serve/command.py`が持つ。
以前は`wi`の全サブコマンドの引数と`commit`・`serve`などの引数を`atk.py`へ直接書き、`main`の分岐が他モジュールの非公開の関数を呼んでいた。
登録方式が2通りに分かれ、サブコマンドを加える計画ごとに`atk.py`へ追記する構造だったためである。

`atk wi`の引数の確定は`prepare_args`と`validate_args`の2段とし、前者をmanaged-tempの掃引より前、後者を掃引の後に呼ぶ。
分ける前の`main`と同じ順序で、引数の誤りと掃引の警告を出力するためである。
`info`・`commit`・`setup-project`は掃引より前に実行する。
知識境界として、各サブコマンドの引数と実行は実装のモジュールが持ち、`atk.py`は登録の順序と共通の前処理だけを持つ。
`--help`の文面と引数は登録の移動前後で変えず、`atk_help_test.py`と既存の動作テストの期待値で確かめる。

## atkサブコマンドの引数拒否形式

委譲の開始・追送・中断・終了済みsessionの破棄はMCPサーバー`agents_server`の公開ツール`start`・`send_message`・`kill`・`stop`が所有する。
`atk agents`のヘルプはこの分担とCLIの`wait`・`notify`・`list`・`show`・`logs`を示し、MCP専用名の誤入力は実行せず対応する公開説明へ案内する。
引数のスキーマとホスト固有の接頭辞をCLIへ複製しないのは、MCP登録と説明の不一致を防ぐためである。

目的は`atk`の利用主体であるコーディングエージェントが、受理しないオプション名を与えた場合に、1回の出力から正しい呼び出し形式へ到達できるようにすることである。
構造の理由は、拒否の判定を`agent-toolkit/agent_toolkit/_atk/help_text.py`の`add_subcommands`が生成する全サブパーサーの`GuidedSubcommandParser`へ置き、サブコマンドごとに適用の有無が分かれる状態を表現できなくする点にある。
argparseはサブパーサーが解釈できない引数をトップレベルの`parse_args`で報告するため、argparseの標準動作ではトップレベルのusageだけが出て、引数を拒否したサブコマンドが受理するオプションが出力へ入らない。
知識境界として、各サブコマンドが受理するオプションの定義は各`build_parser`が持ち、本節は拒否時の出力形式だけを扱う。
登録済みオプションが`--`の後ろで余剰引数になった場合は、位置引数と子コマンドへの転送引数を保って再解析する。
未知オプションは受理せず、登録情報から正しい呼び出し形式を案内する。
位置引数が余った場合は、その値とサブコマンドが受け取る位置引数を示す。
位置引数を持たない場合も明示する。
正常に消費した位置引数と子コマンドへ転送する引数は、そのまま受理する。
全ての後置引数を一律に移す案は、位置引数と子コマンドへの転送引数を変えるため採らない。
却下した代替案は、拒否形式を必要なサブコマンドごとに`parser_class`で指定する案と、推測されやすいオプション名を追加で受理する案である。
前者は同じ判定を複数の呼び出し元へ分散させ、後者は受理する名前を増やしても別の推測した名前では同じ拒否が生じるため採用しない。

## atkの実行例が受理条件を満たすことの確認

公開ヘルプ、skills・share・rulesと利用ガイドの完全な実行例は、`_testing/cli_examples.py`が実物から抽出し、コマンド木とrun-script登録先の実parserへ渡す。
引数名、必須指定、選択肢と区切り位置の不一致は案内の所在付きで検出する。
インラインの説明用断片は、引数の一部を示す用途として抽出から分ける。
プレースホルダーの値と実在ディレクトリの前提だけを検証環境で補い、引数定義は各`build_parser`が所有する。
出力パスの引き渡しはplansのcheckout・listからcommitへの往復など、既存の動作試験で操作の完了まで確かめる。
文法を写した別schemaと実行時監視は同期先を増やすため採用しない。
