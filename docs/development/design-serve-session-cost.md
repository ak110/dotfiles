# セッションの推定費用の設計記録

[設計記録の索引](design.md)と[画面統合とセッション・計画一覧の設計記録](design-serve.md)から参照する主題別の記録である。

## セッション画面

### 推定費用

セッションを選んだエンドユーザーが、その作業と子孫のAPI相当額を比べられるよう、右ペインの見出しへUSDの推定費用を置く。
入力・出力トークン数は本文のメタ情報へ移し、料金表の基準日と集計対象も本文へ示す。
親は子孫を含み、一覧または本文から開いた子・委譲先はその記録自身の額とする。
APIは家族の合計と`breakdown.self`を返し、画面は一覧の親子情報と既存の戻り先から表示範囲を選ぶ。
一覧を費用計算のたびに再走査して表示範囲を推測する案は、既に持つ情報を得るための読取が増えるため採らない。

ローカルの記録の推定費用は、詳細とは別の`/api/sessions/cost`で返す。
費用の算出は子孫の全記録を読むため、子孫の多いセッションでは単独でも3.5秒かかり（2026年11月7日、子孫を多数持つ10MBの記録）、本文の表示まで待たせていた。
詳細は`cost`を`null`、`cost_pending`を真として先に返し、画面は本文を描画してから費用を取得して見出しへ反映する。
取得中は「算出中」と表示し、追記に伴う詳細の取り直しでは新しい費用が届くまで前回の値を表示する。
リモートの記録はヘルパーが詳細の応答に費用を含めて返すため、別の要求を設けない。

`agent-toolkit/agent_toolkit/`配下では料金表は`_common/model_pricing.py`、応答と家族の計算は`_common/session_cost.py`が所有する。
既存の再帰収集を`_common/session_family.py`へ移し、費用CLI・画面・SSH先で同じ家族を使う。
`session_evidence_records.py`などの既存の起動スクリプトは再公開し、呼出しと記録形式を保つ。
解決・配置・MCPツール名の既存処理も共通層へ置き、層を逆に参照する案と、同じ判定をコピーする案は採らない。
画面側の収集接続は`_common/session_cost_records.py`が持ち、起点の解析済み本文は再取得・再直列化しない。
リモートはヘルパーが現地で同じ式を実行して額だけを返し、子孫の全文転送とサーバー側での再取得を省く。
依存は標準ライブラリと既存のplatformdirsの範囲へ保つ。

解析済みの辞書を受ける収集境界でも、会話以外の`message`をファイル読取と同じ正規化へ通す。
ファイル読取だけに正規化を置く案は、事前に解析する画面入力で要求の写しを本物として扱うため採らない。
応答の計数は`assistant`行に限り、一覧の子抽出も同じ解析入力を使う。
写しの応答による過大額と、写しの起動結果による子の誤発見を、CLI・ローカル・remote helperの入力方法に対応付けて検証する。

Claudeの最新`cost-state`を優先し、未収録の応答だけを料金表で補う。
同じプロセスのClaudeサブエージェントと補助呼び出しの額を含むため、親の算出額へ含まれる子を重ねて加えない。
内訳は合計への追加額であり、`self`の累積額に含まれる子を再配分しない。
記録のusageだけから全額を再構成する案は、記録に応答の無い補助呼び出しを含められないため採らない。
Codexは直前の`turn_context`と応答ごとの`last_token_usage`を使い、既存の4成分と同じ対応で料金へ変換する。
単価不明・記録不足は合計未確定と既知分へ分け、0 USDへ補完しない。
実行時に料金ページを取得する案は、外部接続と価格変動で同じ記録の比較条件が変わるため採らない。
出所・基準日と区分はパッケージ内の表から取得し、CLIのcoverageと画面へ届ける。
TTL不明の書込はClaudeを1時間、Codexを30分の区分として明示する。
