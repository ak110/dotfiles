# 障害・欠陥の記録: テスト、CIと検索出力の欠陥

[障害事例集の索引](incidents.md)に区分の定義と事例の書式を示す。

## テスト、CIと検索出力の欠陥

- 2026年8月: テストが生成したGitリポジトリへ識別情報を設定せず、開発機では成功しCIの全Pythonバージョンで失敗した。
  直接原因: 識別情報の設定をリポジトリ生成箇所ごとの手続きとし、実行環境のGit設定の混入を遮断していなかった。
  対策: 識別情報の環境変数と実行環境の設定遮断をautouse fixtureで与え、生成箇所ごとの設定が欠落しても結果が変わらないようにする

- 2026年8月: 上記の設定遮断を導入した直後、本リポジトリの作業ツリーへgitを実行するテストが
  CIの全Pythonバージョンで失敗した（開発機では成功）。
  直接原因: 遮断したglobal設定にCIが`safe.directory`を置いており、遮断後は所有者の異なる作業ツリーを
  gitが拒否した。
  対策: global・system設定を遮断するfixtureへ`safe.directory=*`をコマンドスコープのGit設定として追加し、
  所有者差による拒否を開発機とCIで同じ条件に固定

- 2026年9月12日: `agent-toolkit/agent_toolkit/_atk/serve/static/vendor/mermaid.min.js`を追跡した状態で
  `git grep 123 | wc --chars`を実行すると、標準出力が1,016,731文字になった。
  `CLAUDECODE=1 uvx pyfltr grep 123 | wc --chars`も32,937文字となり、追加の指定なしで適用される除外だけでは一般的な検索語の本文出力を十分に抑制できなかった。
  直接原因: minifiedされた巨大な単一行をリポジトリへ保持し、広域検索の最初の取得で一致本文を出力できる構造にしていた。
  対策: 不要なローカルbundleをCDNの常時最新版へ置き換える。
  広域検索では件数・ファイル・要約を先に取得してから本文を限定する。
  pyfltrには、エージェント環境で出力量に応じて自動要約する変更をAWIとして登録する

- 2026年9月13日: marketplaceのtimeoutテストが実ユーザーの`known_marketplaces.json`へpytestの一時ディレクトリを保存した。
  直接原因: テストがdotfiles rootだけを差し替え、`claude_marketplace`がmodule定数で保持するmarketplace登録とsettingsの書込先を隔離しなかった。
  対策: marketplace書込操作のテストでは、同モジュールが保持する全永続パスを`tmp_path`へ差し替え、書込先をテスト内へ閉じる

- 2026年9月22日: 行数が閾値以下の長大な1行を全文取得し、ツール応答が切り詰められた。
  直接原因: 大容量読取の判定が改行数だけを測り、実際のバイト数を評価していなかった。
  対策: 行数から独立したバイト閾値を設け、単一ファイルの値と複数ファイルの合計値をReadと単純Bash全文取得へ適用する

- 2026年9月29日〜30日: 開発機では成功したテストがCIだけで2回失敗した。
  1回目では偽のbackendへの差し替え先を誤ったテストが実際の`codex`を起動し、開発機では導入済みの`codex`が起動に成功して誤りが隠れた。
  2回目ではスキル配下のテストが実行環境で設定の無い場合に使うキュー管理リポジトリを参照し、実物を持たないCIだけで警告が出た。
  直接原因: テストの隔離を起動範囲ごと・事象ごとに個別の`conftest.py`で定義しており、PATH上の開発機専用のエージェントCLIを隔離する定義はどこにも無く、スキル配下にはキュー管理リポジトリの隔離が無かった。
  2026年8月のGit設定の2件も同じ構造による。
  対策: 偽のbackendの差し替え先とテストのキュー管理リポジトリを個別に直したうえで、隔離の定義を`agent-toolkit/agent_toolkit/_testing/isolation.py`の1箇所へ集約し、4つの起動範囲の全てのテストへ自動で適用した。
  隔離の次元へPATH上の`codex`・`claude`・`agy`を加え、開発機でもCIと同じくCLIを解決できない状態にした。
  各起動範囲には隔離が適用されていることを確かめるテストを置いた

- 2026年10月3日: 文書・設定の実物を調べるテストがPython実装のディレクトリへ置かれ、対象の編集からテストをたどれなかった。
  直接原因: Pythonモジュールとの同居だけを配置規則にし、実物の文書・設定や複数領域の契約を確かめるテストも同じ場所へ集めていた。
  横断テストの説明も全ソース走査に限り、文書と実装の整合性を確かめるテストが選択から漏れた。
  対策: 実物を読むテストを対象か対象群を包含する最も近い場所へ移し、通常の実行テストと分離した。
  複数領域の不変条件をrepo_invariantへ含め、収集・参照・CI指定・投影の同期を追随した。
  個別の対応表は増やさず、配置の定義元をpytools-editへ集約した。
  過去の記録にある旧テスト名は当時の所在として保持する

- 2026年10月4日: 不変条件テストの選択が手動コマンドに残り、通常のcommitで起動するfastはこれらを実行しなかった。
  直接原因: マーカーで識別しても通常のpre-commitでは起動しないため、担当が対象を選ぶ必要があった。
  対策: マーカー対象を近接する専用ファイルへ分離し、pyfltrの単一globから既存のfastで自動実行する。
  統合後の組合せも同じ対象選択で確かめ、手動のファイル一覧と独立したhookを増やさない
