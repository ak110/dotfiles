# 完了報告と振り返りの設計記録

[設計記録の索引](design.md)と[振り返り・知見集約の設計記録](design-session-review.md)から参照する主題別の記録である。

## 完了報告と振り返りの関係

2026年10月28日の非同期化要求により、通常作業の完了報告と振り返りの起動を分離した。
作業完了報告はreport-completionが所有し、成果・検証・公開・未達と必要な判断を1本文へ集約する。
add-awi-by-userの登録成功や公開成功は本文への入力であり、必要報告の代わりとなる最終回答ではない。
通常のCodexは必要なツール処理を終えてから最終回答で本文を届ける。
停止コマンドでホストを終える起動では、報告用UWIの保存検収と必要な可視報告を先に済ませ、停止を最後にする。
Claude Codeのsend_to_userによる送達成功と、送達後のターン終了は区別する。

同期の振り返りはreport-completion、process-wiの公開・終了、計画実行、プロンプト改善などの終了工程から撤去する。
SessionStart/SessionEndの軽量な登録・起動を契機に、非活動の対象をreview-session batchが処理する。
自動起動設定は`session_review_auto_start`（既定true）であり、停止しても未処理範囲を保持する。
全体ロックと対象範囲の固定により重複分析を避け、準備後の追記・再開を処理済み範囲へ混ぜない。
対象の作業完了報告へ振り返り結果を追記せず、batchはrun-skill経由の報告用UWIを1件保存する。
報告先と実行cwdは分け、複数リポジトリを扱うときの帰属はbatch契約に従う。

自動起動の間隔は前回のbatch実行開始から6時間とし、排他取得後にも再確認する。
ユーザーが指定したまとめ実行の間隔であり、手動起動には適用しない。
batch自身の記録も分析対象として保持するが、待っている記録がbatchだけなら起動を見送る。
通常の記録と混在する場合はまとめて分析し、batch自身の開始・終了からの再帰起動は抑止する。
run-skillが渡すgoalでは、子の報告保存・batchのfinish・終了要求と、子終了後に起動元が行う報告同期検収・処理済み確定を区別する。

手動のreview-sessionは現在のセッション全体を対象とし、引数は追加の着眼点として扱う。
全手順と全候補の分析を保ち、batchも同じ分析基準を対象ごとに共用する。
既調査の改善点は証拠・対象・条件の一致を確かめて再利用し、不足や変更範囲だけを補う。
発見時の最低限調査とQCDによる採否は、その場の担当が行い、非同期化を理由に初動まで遅らせない。
標識行と担当外の処置は返却契約に従って上流へ引き継ぐ。

準備結果の`scope_path`で分析対象の境界を保存する。
手動は分析・必要なWI保存・報告本文の確定後に、保存した準備結果JSONを`session-review-state complete --prepared`へ渡して準備済み範囲を確定する。
これは分析範囲の証拠であり、本文の送達証拠ではない。
batchでは報告用UWIの同期検収後に起動元run-skillが範囲を確定し、分析側が先に完了扱いにしない。
失敗や未処理の増分は待ち状態へ残す。

振り返り自身の300秒超過は最終報告前に当回の分析・必要な追加投入・報告へ接続する。
既存の統計と読了証拠を再利用し、起動から最終報告までを1事象として、原因・全処置・報告が確定した後は秒数の増加だけで反復しない。
全体の経過時間を振り返り区間の終点に代用しない。

対策は通常AWIへ渡し、batch由来のAWIもユーザーの内容確認を待たずに採否検討と処理の対象にする。
確認待ちの属性・選定分岐・画面操作を撤去し、既存の`confirmation`は未知のfrontmatterとして保持するだけで動作へ影響させない。
人間由来の要求の保護と外部操作の認可は、wi-standardsのorigin-and-approval.md「承認」が引き続き所有する。
同じ範囲の二重分析を避け、必要な全記録を覆うという目的は範囲管理と証拠再利用で保つ。

報告書式はreport-completionのreport-formatsへ集約し、作業完了と手動・batchの振り返り報告で適用時機を分ける。
ユーザーに残る判断・行動は個別UWIへ保存し、報告には所在を示す。
本文の再出力、固定句・見出し・自己申告による機械的な完了保証、新たなStopは加えない。
132319の記録では必要指示の存在を確認できたため、単なる条文の再掲に効果を仮定しない。
報告本文の集約が未送達を防ぐ効果は、新規の無作用な行動試験で元条件・別パターン・正当な除外を確認する。
文書の変更や文字列の一致だけで効果を成功扱いにしない。
