# 採用済み対策の効果確認と知見集約の設計記録

[設計記録の索引](design.md)と[振り返り・知見集約の設計記録](design-session-review.md)から参照する主題別の記録である。

## 採用済み対策の効果確認

実装commit付きで採用するAWIは、採用状態を保ったまま`effect_check: pending`を保存する。
見直す項目は、対象のセッションで続いている問題から振り返りの担当が選ぶ。
確認待ちの一覧（`atk wi list --state=adopted --effect-check=pending`）と採用済み項目の検索から、その問題を目的にして採用された項目を先に選ぶ。
選んだ項目の変更ファイルと対象のセッションでの実際の操作は、担当がその場で確かめる。

効果の結論は分析担当が原記録を読み、項目の目的の結果で判断する。
目的を達したかの判定を作業項目の全体へ保存し、効果を確認した場合はfrontmatterへ`effect_check: confirmed`を記録する。
効果不足と判定した場合は、是正AWIの保存後に`effect_check: insufficient`を記録する。
変更ファイルごとの判定も保存でき、保存済みのファイル別の結果は保持する。
適用機会や対応commitを解決できなければ理由付きの`pending`を保ち、後日確認が不要なら`not_required`と理由を保存する。
読込や起動だけでは効果を確認済みとしない。

2026年11月11日に、振り返りの準備が候補と未確認の一覧を自動で作る処理を撤去した。
この処理は、確認待ちの項目の変更ファイルと対象のセッションの読取位置の組を1対象あたり690〜4,897件作り、確認済みになった項目が無いまま確認待ちが652件たまった。
変更ファイルの読取は効果の有無を示さず、件数が判定できる量を超えていたためである。
撤去の記録は`removed-mechanisms.md`にある。
保存は採用済みAWIの効果属性と結果追記だけを許可する`atk wi effect-check`へ限定し、通常の終了済み本文編集の制限を維持する。
新しい台帳を作る案は、採用結果と対応commitを保持する既存WIと二重管理になるため採用しない。

## AWI由来の知見の集約

過去のAWIから確定した方針・意向は[concepts.md](concepts.md)へ、
再発防止の判断材料となる障害・欠陥は[incidents.md](incidents.md)へ集約する。
エージェント向け文書の編集規範は、両文書を編集前に参照し、
新たな障害または確定した意向が生じた場合に対応する文書を更新するよう求める。
参照の時機は`.claude/skills/agent-toolkit-edit/SKILL.md`などのスキルの工程が定め、フックでは観測しない。
未読の警告は規範の想起を目的とし、読了の事実から理解の成否を判定できないため、2026年9月26日に撤去した。

時系列の全件一覧は判断材料を探しにくくするため採用せず、主題別のコンセプト集と障害区分別の事例集に整理する。

## 振り返りのモード選択

起動スキルをreview-sessionへ統合し、先頭語batchの完全一致だけで複数対象の処理を選ぶ。
残りの着眼点と自動起動の制御情報は分離し、autoも着眼点として保持する。
通常の準備・範囲確定とbatchの準備済み分析を別資料へ分け、共通分析を両方から参照する。
run-skillの排他と報告scopeはスキル名とモードの組で区別し、着眼点の違いによる多重起動を防ぐ。
旧scope・旧起動標識・旧ログは保存記録の読取に限って保持する。
batchのアカウント共通排他、失敗抑止、準備済み範囲の回復と成功確定は既存の所有者が継続する。
