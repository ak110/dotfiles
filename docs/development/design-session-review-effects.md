# 採用済み対策の効果確認と知見集約の設計記録

[設計記録の索引](design.md)

## 週次のメタ分析

batchは複数の個別セッションを分析し、metaは複数のWIから対策の効果を見直す。
既存WIと報告を起点に反復の束を選び、その束に関係する本文と適用の証拠だけを読む。
個別セッション向けに候補と関連ファイルの読取位置を機械的に総ざらいした旧方式とは異なり、効果は害と同じ利用結果を比較して判断する。
個別の効果記録は既存の `atk wi effect-check` を使い、未分析の束は前回報告から回収する。

## 採用済み対策の効果確認

実装commit付きAWIの採用では、後日の実利用で確かめる目的があれば `pending`、採用前に目的を検収済みなら理由付きの `not_required` を保存する。
見直す項目は、対象のセッションで続いている問題から振り返りの担当が選ぶ。

選んだ項目の変更ファイルと対象のセッションでの実際の操作は、担当がその場で確かめる。

効果の結論は分析担当が原記録を読み、項目の目的の結果で判断する。
目的を達したかの判定を作業項目の全体へ保存し、効果を確認した場合はfrontmatterへ`effect_check: confirmed`を記録する。
効果不足と判定した場合は、是正AWIの保存後に`effect_check: insufficient`を記録する。
適用機会や対応commitを解決できなければ理由付きの`pending`を保ち、後日確認が不要なら`not_required`と理由を保存する。
読込や起動だけでは効果を確認済みとしない。

2026年11月11日に、振り返りの準備が候補と未確認の一覧を自動で作る処理を撤去した。
この処理は、確認待ちの項目の変更ファイルと対象のセッションの読取位置の組を1対象あたり690〜4,897件作り、確認済みになった項目が無いまま確認待ちが652件たまった。
変更ファイルの読取は効果の有無を示さず、件数が判定できる量を超えていたためである。
撤去の記録は削除前の撤去台帳`docs/development/removed-mechanisms-records.md`にある。
採用後の保存は採用済みAWIの効果属性と結果追記だけを許可する`atk wi effect-check`へ限定し、通常の終了済み本文編集の制限を維持する。
新しい台帳を作る案は、採用結果と対応commitを保持する既存WIと二重管理になるため採用しない。

## AWI由来の知見の集約

過去のAWIから確定した方針・意向は[concepts.md](concepts.md)へ、
再発防止の判断材料となる障害・欠陥は、是正のcommit本文に残す。
エージェント向け文書の編集規範は、concepts.mdの全文と、変更対象の名前で検索したcommit本文を編集前に参照し、
新たな障害は是正のcommit本文へ、確定した意向はconcepts.mdへ書くよう求める。
参照の時機は`.claude/skills/agent-toolkit-edit/SKILL.md`などのスキルの工程が定め、フックでは観測しない。
未読の警告は規範の想起を目的とし、読了の事実から理解の成否を判定できないため、2026年9月26日に撤去した。

時系列の全件一覧は判断材料を探しにくくするため採用せず、意向は主題別のコンセプト集に整理する。
障害は2026年11月22日まで区分別の事例集に整理していたが、同日のユーザー選択で事例集を削除し、commit本文と`git log --grep`で引く形へ移した。

## 振り返りのモード選択

起動スキルをreview-sessionへ統合し、先頭語`batch`の完全一致で複数セッションを、`meta`の完全一致でWIの横断分析を選ぶ。

## 維持する判断と戻さない条件

振り返りの所要短縮（同期実行の廃止、候補の集約、証拠再利用、4走査を1回に）と手動の週次費用指標は維持する。
振り返りをまとめて非同期実行する方式はユーザー要求であり、週次費用・hook指標は提示案の選択による。
最新のユーザー指示である非同期のまとめ実行と選択済み指標を保ち、撤回済みの後送り案へ戻さない。
最新の非同期方式の同条件の全区間対照は未確認である。
run-skillの排他と報告scopeはスキル名とモードの組で区別し、着眼点の違いによる多重起動を防ぐ。
旧scope・旧起動標識・旧ログは保存記録の読取に限って保持する。
