# commitと委譲手段の選択の支援の設計記録

[設計記録の索引](design.md)から参照する、commitと委譲手段の選択の支援の記録である。

## PreToolUseの個別設計

### commitメッセージの空行と帰属trailerの確認

通常のcommitで最終メッセージを確定できる場合は、件名と本文の間の空行を確認する。
2行目が空行でない複数行メッセージを遮断し、件名の直後へ空行を加える操作を案内する。
本文の取得は帰属チェックと共用し、`-m`・`--message`・`-F`・heredocと複数の`-m`の段落連結を扱う。
件名だけの入力と正しい空行は許可する。
identityの不在と帰属設定の無効化は書式チェックを免除しない。
reuse・reedit・amendのno-edit・fixup・squashと、ファイルや実行位置から本文を確定できない入力は既存の対象外条件を保つ。
`dispatch.py`は通常commitの対象と本文を先に確定し、その本文を1回取得して書式チェックと帰属チェックへ渡す。
非commit、対象外、本文不明の場合は帰属用identity・transcript・設定を取得しない。
必要な通常commitだけで帰属設定と観測identityを使う。
書式の違反と帰属行の違反は集めて1回の遮断へ並べ、通知はBashのコマンド全体（連結した`git add`などを含む）が未実行であることを示す。
最初の違反だけを返すと残りの違反で再び遮断され、commitだけを直した再実行は前段の欠落で失敗するためである（2026年11月9日に2セッションで観測した）。
`-C`・`--git-dir`・`--work-tree`の値は対象リポジトリと実行位置だけを変えるため、展開を含んでもcommitを検査し、実行位置を不明として相対パスの本文だけを読まない。
`-c`など、メッセージに作用しうる大域オプションの値の未知語では従来どおり検査しない。
値を取る大域オプションの分類はテストが全要素について強制する。
以前は`commit`より前の語の未知語で一律に検査を外し、`git -C $R commit`の帰属行の欠落と作業項目のファイル名を遮断できなかった。
通常のBash呼び出しごとにcommit用の記録を走査する案は、対象外の入力にも同じ取得費用を課すため採らない。

Codexでは`commit/references/message.md`を実際にシェルで読む操作へ、既存の観測identityと`co_author_trailer`で求めた帰属行を先に届ける。
`dispatch.py`が確定したファイル引数の末尾と実在を確認するため、plugin rootや配布先の違いを許容し、引用・検索・別資料には配送しない。
読取は許可し、モデルと推論量を観測できない場合は設定や起動候補から補わない。
先行配送は読取時点の観測であり、通常commit直前の帰属確認はそのturnの現在値を使う。
turn変化、不正と重複を現在の行で回復させ、明示指定・無効化・Claude Codeと対象外入力の取得順を保つ。
最初のcommitを拒否して行を教える案は、同turnの既知の情報を読取時に渡せるのに手戻りを残すため採らない。
Claude Codeでは`agent-toolkit:commit`の`Skill`の起動が完了した時点に、PostToolUseが同じ生成元の帰属行を追加コンテキストで示す。
スキルを起動して`message.md`を読まずにcommitする場合にも届く時点である。
観測できない場合と帰属行を無効にした設定では示さない。
常時読み込む規範へ要件を置く案は全セッションの読込量を増やし、`updatedInput`で行を加える案は`-F`やheredocの本文を書き換える範囲が広いため採らない。

通常の`git commit`では、実行位置、最終メッセージ、実行turnの観測identityを確定できる場合だけ帰属trailerを確認する。
Claude Codeは`attribution.commit`の`{model}`と`{effort}`を置き換えないため、確認しないと誤った帰属行がpushまで残る（2026年10月6日に4件のcommitで推論量の欠落と誤りを観測した）。
Claude Codeの期待値は、推論量をhook入力の`effort.level`、モデルを記録の`message.model`の最後の観測値から求める。
hook入力が`agent_id`を持つ場合はsubagentの記録（`<session_id>/subagents/agent-<agent_id>.jsonl`）のモデルを使い、一意に解決できなければ確認しない。
PreToolUseの時点ではそのturnの応答がまだ記録に無いため、セッションの最初のツール呼び出しがcommitの場合はモデルを観測できず確認しない。
2026年10月6日にClaude Code 2.1.291の`claude -p`で、最初の呼び出しのcommitが許可され、別のコマンドの後のcommitが遮断されることを確かめた。
hook入力とBashの環境はモデルを持たないため、この区間の期待値を得る手段が無い。
最終メッセージは`-m`に加え、`-F -`・`--file=-`へ同じコマンドのheredocで渡した本文と、`-F <path>`で指定した存在するファイルから読む。
エージェントのcommitの多くは`-F -`のheredocで作成されるためである。
Claude Codeではフックから観測できるuser・project・local設定を優先順位どおり解決する。
最上位の`attribution.commit`が空文字なら、明示的な帰属無効化として確認しない。
`--amend --no-edit`、fixup、検索・引用中の文字列、人間がagent session外で実行するcommit、入力を確定できない呼び出しも対象外とする。

managed settingsの`attribution.sessionUrl`と`attribution.pr`は設定せず、Claude Codeの既定動作を変えない。

### 委譲手段の選択と待機の装着の手掛かり

Claude Codeのメインが調査を`Agent`ツールで委譲し、待機の定期再確認を委譲先の起動後に装着した事象をユーザーが何度も指摘した。
条文はセッション開始時の文脈にあったが、ツールを選ぶ時点と起動の直前に読まれる文面に手掛かりが無かった。
そこで、選択の時点の語彙と起動直前の文面へ手掛かりを置き、hookは使わない。
常時規範`agent-toolkit/share/rules/common/01-agent.md`「委譲の要否判定」は比べる相手として`Agent`ツールの名前を含める。
`agents_server`のサーバー`instructions`は本サーバーを標準とすることを示す。
`start`の公開説明は、`CronCreate`を使える実行主体が最初の呼び出しの前に定期再確認を装着することを示す。
Claude Codeはツールを遅延読み込みし、スキーマを取得する最初の呼び出しの直前に`start`の説明を読む。
`agent-toolkit:delegation`はClaude Codeで`Agent`ツールの委譲先かバックグラウンドタスクを最初に起動する前と、定期再確認を自ら装着する前に`references/claude-code-runtime.md`を読む契機を持つ。
`agents_server`の通常起動と軽量起動の設定読込先の違いは、委譲先とモデルを選ぶ時点に読む`references/runtime-routing.md`「実行手段」が持つ。

却下した代替案は3つある。
PreToolUseで通知する案は、当時の、規範の想起を目的とするチェックをhookに置かない方針に反するため採らなかった。
現行の判定基準は`agent-basics:writing-standards`の`agent-basics:writing-standards/references/claude-hooks-block-warn-eligibility.md`「遮断・警告フックの成立条件」にある。
旧基準からの変更の経緯は「全件確認の経緯（2026年9月26日）」にある。
本節の判断そのものは見直していない。
`agent-toolkit:delegation`のdescriptionへ起動の語を加える案は、descriptionを対象作業と発火条件に限る規定に反し、単発の委譲のたびにスキル本体と参照資料を読む費用を生む。
`agent-toolkit/share/rules/rules-main.claude-code.md`へ追記する案は、常時規範への新しい規定の追記に当たり、メインだけへ配られるため委譲先が委譲する場合を覆わない。
観測した事象では条文がセッション開始時の文脈にあったため、同じ層へ文を移しても想起の条件は変わらない。

その後、組み込みの汎用Agent定義（general-purpose・Explore・Plan・web-fetch・claudeと、`subagent_type`を省いた起動）の起動だけは、PreToolUseで扱うよう改めた。
2026年11月7日に非遮断の警告を加えたが、警告の後の2回の起動（2026年11月10日のweb-fetchとExplore）はどちらも変わらなかった。
PreToolUseの追加文脈は呼び出しの実行を止めず、エージェントが読むのは呼び出しの結果と同時であるため、当該の起動には作用できない。
そこで2026年11月11日に、汎用定義の起動を拒否し、同じ依頼を対応する`agents_server`の`mode`で出し直すよう通知する形へ改めた。
web-fetchを拒否して`explore`へ切り替えさせることは、ユーザーの回答（「web-fetchは遮断されたらagents_serverのexploreを使うように読み替えて対応すべきなのでは」。末尾の疑問符は省いた）による。
`explore`がWebページの本文を取得できることは、同日にCodexの`explore`で確かめた。
他の汎用定義へ対象を広げたのは、警告が作用しない理由が定義の種類によらないためである。

この拒否は、`agent-basics:writing-standards`の`references/claude-hooks-block-warn-behavior.md`「遮断と警告の選択」が挙げる4つの場合（認可境界の逸脱、破壊的操作、データ整合性の毀損、公開契約の破壊）には当たらない。
同節が拒否を限る理由は、拒否のたびにそのターンの入力と進行中の作業が失われることである。
汎用定義の起動で失われる入力は依頼の本文であり、同じ本文を`agents_server`の`start`へ渡せば回復できるため、損失は起動1回分の再発行にとどまる。
設定の外で委譲の作業全体が実行される費用より小さいと判断し、費用の比較で拒否を選んだ。

同じ会話の同じ主体が、拒否された入力と同一の入力で再発行した起動は通す。
`agents_server`のMCPツールを呼べない場合、ユーザーの明示指示がある場合、対応する`mode`で同等の結果を得られなかった場合に、作業そのものを止めないためである。
hookはこれらを入力から判定できないため、判断を通知を受け取ったエージェントへ委ねる。
再発行を使った迂回を防ぐ仕組みは、同資料「迂回手段」に従い加えない。
最初の再発行の後は会話の単位で拒否を省く案は、例外の成否が起動ごとに変わるため採らない。
拒否された入力の指紋は、主体ごとの有限件数をセッション状態へ保持する。
続けて発行した複数の起動と、`agents_server`を試した後の再発行を通すため、別の操作を挟んでも失効させない。
指紋を保存できない場合（セッション識別子が無い、状態ファイルへ書けないなど）は、拒否せず警告だけを返して起動を通す。
保存できないまま拒否すると、案内した再発行も拒否され、起動の手段が残らないためである。

### atkの出力受領の案内

`atk`の出力をパイプで他のコマンドへ渡す操作、`atk agents wait`をシェルの`&`で背景化する操作、出力をリダイレクトする操作は、hookが警告し、呼び出し自体は実行される。
常駐・追従表示のリダイレクトとホストが管理する背景実行は、この警告の対象外である。
通知はパイプなどの接続を外して`atk`を単独で発行し、`atk`が返す保存先のファイルを読む操作を案内する。
複数対象の取得は対応するコマンドへまとめて渡し、保存と選別は自動保存後の別操作へ分ける案内を同じ通知へ置く。
実行済みの呼び出しは保存結果と終了状態を回収し、以後の呼び出しへ案内を適用する。
保存するかどうかは`atk`が出力の量と用途から決める（[design-cli.md](design-cli-auto-save.md#エージェント環境での長い出力の自動保存)）ため、hookは呼び出し側へ保存先の指定や出力量の予測を求めない。
標準エラーの詳細は標準出力と別の`標準エラー保存先:`へ保存され、`atk agents wait`の回収判定は標準出力の保存結果だけを読む。

通知を見直すときは、エージェントが何を得るために取得したか、すでに得ていた情報、出力先、通知に従った後の結果を元の記録と対応付けて確かめる。
初回のヘルプ表示が長いことを観測前に原因とみなす案と、判断済みの警告以外を読む目的を出力全体の要約で置き換える案は、エージェントが取得したかった情報を得られないため採らない。
警告が実行結果と一緒に届くことによる反復には、操作を組み立てる常時規範の同じ節へ複数対象の呼出例を置く。
復旧できる手順支援を遮断へ変える案は、結果を保存先から回復できる一方で正当な操作の誤検出時の往復を増やすため採らない。
