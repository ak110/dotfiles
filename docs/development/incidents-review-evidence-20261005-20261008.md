# 障害・欠陥の記録: 実行レビューと証拠検査の欠陥（2026年10月5日〜2026年10月8日）

[実行レビューと証拠検査の欠陥](incidents-review-evidence.md#実行レビューと証拠検査の欠陥)の事例を発生時期別に収録する。

- 2026年10月5日: process-wiの実行レビューで、`atk run-script exec-review-evidence-check`は共通の参照のままの完成条件証拠を共用根拠として拒否した。
  担当が全行の末尾へ`確認対象:`と各行の条件文または要求原文を付け足し、参照不備3行だけを直すと、同じコマンドは終了コード0で受理した。
  さらに担当は、完成条件証拠の再判定をレーン担当へ求める指摘を、証拠JSONを`location`としてレビュー指摘管理表へ登録した。
  同じコマンドはこの指摘を未解決1件と数え、`completed`を返した。
  直接原因: 共用判定の前の正規化が、限定列挙した標識の構文だけを除き、各行の条件文・要求原文そのものを対象にしていなかったため、付け足した条件文が行固有の観測として残った。
  返却の整合の確認は現在roundの未応答指摘が1件以上あることだけを確かめ、その指摘が実行レビュー担当自身の記入する完成条件証拠を修正対象にしているかを判定しなかった。
  対策: 共用判定の前に、その行が持つ条件文・要求原文と一致する再掲を識別情報として除く。
  現在roundの未応答指摘が確認対象の完成条件証拠そのものを`location`にした場合は拒否し、担当が証拠を判定・記入して再実行する操作を診断に示す。
  実装成果物を指す未応答指摘と正当な共用は従来どおり受理する
- 2026年10月5日: 関連開発が必要にした整理（付帯作業）が同じ処理から脱落し、完成条件証拠の書込主体が曖昧だった。
  直接原因: 付帯作業を任意に分離できた。
  未判定検証記録も進捗ログの探索を必要としていた。
  対策: 付帯作業は同じ計画・WI・commitへ統合し、未判定検証記録は必須入力で直接配送し、完成条件証拠はレビュー担当だけが更新する

- 2026年10月5日: process-wiで、ユーザーが会話の中でエージェント由来のAWIの完成条件を否定した。
  実行レビュー担当は失効の根拠が対象AWIの`## ユーザーコメント`か回答済みUWIの`## 回答`に限られると判断し、メインは同じ否定を逐語で載せた事後承認型UWIを保存した。
  回答前は`atk run-script exec-review-evidence-check`が失効行を受理せず、レーンは実装の指摘が0件に収束した後も`needs_escalation`で止まり、ユーザーがUWIへ回答するまで統合が進まなかった。
  直接原因: `check_exec_review_evidence.py`の`_expired_source_error`と5つの文書が、失効の根拠の担体をユーザーコメントと回答済みUWIの2種に限っていた。
  5つの文書は`exec-review.parent.md`、`exec-review.subagent.md`、`exec.parent.md`、`exec.subagent.md`、`review-loop-coordination.md`である。
  `agent-toolkit:wi-standards/references/wi-standards-origin.md`「由来と承認」が明示由来に挙げる出所付きの対話回答は、この閉じた列挙に含まれていなかった。
  対策: `_expired_source_error`へ、`--user-events`の出力ファイルの絶対パスと`<record>:<line>`、否定した要求単位の「」による逐語で示す会話中の発話を受け付ける判定を加え、発話主体と引用の所在を確かめる。
  担体の定義を`exec-review.subagent.md`「出力」の一覧1箇所へ集約し、他の4文書はその一覧を参照する。
  メインは自身の会話に否定の発話がある場合、出力と記録位置を同じ担当へ返し、無い場合だけユーザー確認とUWIへ進む

- 2026年10月6日: process-wiの2つのレーンの実行レビューで、分割起票したAWIの原文要求のうち他のAWIが扱う単位（合わせて18行）を`割当外`にできなかった。
  割当元のAWIは割当先を名指しせず、割当先のAWIは自身の`## 反映内容と反映先`の位置参照か`## ユーザー指摘の逐語引用`の注記で同じ単位を自身の反映先へ対応付けていた。
  担当は延期の記録を引き継ぎ記録へ置くか、委譲元の受理記録を`## 実施内容`節の形へ写した複製を`source`に指定して受理させた。
  直接原因: `atk run-script exec-review-evidence-check`は割当外の行について、割当元のAWIか計画の記録で割当の語を持つ行に割当先が現れることだけを受理の所在とした。
  割当は割当元と割当先の2つの本文に現れる事実だが、要求ごとに別のWI投入担当を起動する運用では割当元の起草者が割当先を知らず、計画は実装着手後に凍結されるため、割当元の記録を補う手段が実行レビューの時点で残らなかった。
  対策: 割当先のAWIが`## 反映内容と反映先`（保存済みの形では`## ユーザー指摘の逐語引用`のtextフェンス外の注記）で同じ単位を位置参照か「」の引用で指す記録（引受の記録）も受理の所在に加えた。
  割当・割り当て・分割元の依頼全体・背景・含めない・対象外の語か別のWIファイル名を持つ行は割当先自身が引き受けない単位の記録として除き、どちらの記録も無い単位は従来どおり達成・未達・証拠不足で判定する。
  記録規範、統合時の完成条件判定、起草規範と設計記録を同じ受理の形へそろえた
