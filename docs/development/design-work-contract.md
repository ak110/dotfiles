# 現在の目的・要件を保つ作業契約

追加指示の局所的な処理で当初の目的を見失わないよう、メインの`work-contract.md`へ、現在有効な目的・要件を簡潔に保持する。
記録の仕様は`agent-toolkit/skills/atk-mode/references/work-contract.md`が所有し、計画・レビュー表・会話・WIの原本は所在参照で保持する。

2026年10月21日、工程境界ごとの更新と成果物・検収証拠の対応付けが、細かな進捗や試験結果の転記を誘発する運用を是正した。
進捗・検証結果を集約する台帳として使う案は、既存の原本を重複させ、追加指示への固執を防ぐ目的に対する更新負担が大きいため採らない。
通常の委譲先の引き継ぎ記録も同じ要求を参照し、後任に必要な再開位置と資源の識別子を保つ。
工程の区切りや保存・観測のたびの上書きは要求しない。

2026年10月26日のユーザー指示により、作業契約へ目的・要件以外の承認・残作業・変更履歴を転記する運用と、入力連番・処理済み位置の記入・完了時のUUID付き退避を廃止した。
2026年10月31日、質問へ回答しただけで元の未完了工程へ戻らず終了した事例（契約は回答前から存在した）を受け、両ホストのメインへの実ユーザー入力時と圧縮後の通知を、所在案内から契約本文と回答後の復帰基準の配送へ改めた。
完了の意味判定や中止の解釈をhookへ移す案と、Stopで一律に終了を遮断する案は、正当な回答待ちや中止との区別に同じ文脈判断を要するため採らない。
質問や続行だけの発話は本文を変える契機にせず、次の作業では現在の目的・要件へ置き換える。
圧縮後はホストが注入する要約を起点とし、不足する情報だけを原文・既存成果物・状態照会から取得するため、圧縮専用の記録は作成しない。

依頼本文が行頭の`引き継ぎ記録先:`行を既に持つ場合は、その値を唯一の記録先とし、サーバーは記録先を生成せず行も加えない。
値を絶対パスとして読めない行は、委譲先を起動せずに拒否する。
サーバーが起動本文へ足す入力と同じ意味の値を委譲元が自由本文で渡している場合に、本文の値を優先するという規則である。
2026年11月10日に、依頼本文の記録先とサーバーが生成した記録先の2行が同じ担当へ届き、委譲先が2か所へ書く事象が4回起きたため定めた。
依頼本文の行を削ってサーバーの記録先へ統一する案は、委譲元が自分の書いたパスを検収で読むため採らない。
記録先の行を含む依頼を全て拒否する案は、正しいパスを書いた委譲元にも再発行を強いるため採らない。
委譲元は検収を、記録を読めた場合、記録の不在を確かめた場合、それ以外で記録を読めない場合の3つに分ける。
不在を確かめた場合は書く値が無かったことを示し、返却や役割契約が記録を前提とする値を読めない場合だけ不足として扱う。
それ以外で読めない場合は既存の資料と現物から復元し、復元できない値を未確認とする。
`mode`を解決するサーバーが入力の使用を判断することで、呼出側は役割本文から内部設定を調べずに保持中の契約を渡せる。
軽量役割では指定値を参照せず、不在パスも拒否せず、契約本文と専用記録を追加しない。
自己完結した軽量起動を維持するためであり、自由本文の軽量起動と引き継ぎ起動の入力制約は維持する。
全体記録の更新の所有権はメインに保ち、起動側は本文を書き換えない。

記録が無いメインでは、PreToolUseが実ユーザー入力ごとの最初の操作に、絶対パスと作成条件を非遮断で通知する。
事実回答のための調査と成果作業は操作だけでは区別できないため、通知は作成判断と記入をエージェントに残す。
毎回の通知は他の注記を埋もれさせ、UserPromptSubmitだけの通知は自動起動を覆えないため採らない。
共有状態の名前空間（ルート）は会話と一致しないことがあり、`process-wi all-repos`の統括担当が委譲したリポジトリ担当などでは名前空間から記録を探すと所在が未解決になる。
委譲元の受領済み参照を所有会話より先に使うのは、委譲先自身の保存領域が全体記録を持たず、孫へも委譲元と同じ全体記録を渡すためである。
どの解決元も成立しない起動と、期待パスが確定して記録が未作成の起動は、担当と専用記録先を作成せずに拒否し、記録の作成か`whole_contract_path`での再発行を返す。

却下した案は次のとおりである。
未解決の通知を配送して担当を起動する案は、担当が委譲元へ所在を照会する往復を残す。
全会話の保存領域を走査する案は会話境界を越える。
最初のMCP応答で作成される別名索引を使う案は、その応答より前の最初の起動で成立しない。
受入時は`agent-toolkit:atk-mode/references/work-contract.md`「追加入力の統合」の例（推奨Aの有効な利点へX・Y・ZZを統合する場面と、`A-b`から`c'`への部分訂正後にA全体へ戻る場面）を、各工程から同節への参照とともに検収する。
