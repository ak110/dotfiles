# 現在の目的・要件を保つ作業契約

追加指示の局所的な処理で当初の目的を見失わないよう、メインの`work-contract.md`へ、現在有効な目的・要件を簡潔に保持する。
記録の仕様は`agent-toolkit/share/work-contract.md`が所有し、計画・レビュー表・会話・WIの原本は所在参照で保持する。

2026年10月21日、工程境界ごとの更新と成果物・検収証拠の対応付けが、細かな進捗や試験結果の転記を誘発する運用を是正した。
工程境界では成果と目的・要件の一致を確認し、目的・要件が変わったときに本文へ統合する。
進捗・検証結果を集約する台帳として使う案は、既存の原本を重複させ、追加指示への固執を防ぐ目的に対する更新負担が大きいため採らない。
通常の委譲先の引き継ぎ記録も同じ要求を参照し、後任に必要な再開位置と資源の識別子を保つ。工程の区切りや保存・観測のたびの上書きは要求しない。

2026年10月26日のユーザー指示により、作業契約へ目的・要件以外の承認・残作業・変更履歴を転記する運用と、入力連番・処理済み位置の記入・完了時のUUID付き退避を廃止した。
UserPromptSubmitとSessionStartは実在する作業契約の所在を通知し、本文の解釈と要求の充足は各工程のエージェントが判断する。
質問や続行だけの発話は本文を変える契機にせず、次の作業では現在の目的・要件へ置き換える。
担当別引き継ぎに必要な進捗・再開位置・実行識別子は、その担当記録が所有する。
圧縮後はホストが注入する要約を起点とし、不足する情報だけを原文・既存成果物・状態照会から取得するため、圧縮専用の記録は作成しない。
Stopは既存の終了工程の証拠の責務を保つ。

通常taskは役割文書が記録先を宣言する場合に既存の必須入力補完を使い、宣言しない場合はサーバー所有の共通入力として配送する。
自由本文delegateは原文を保って同じ共通入力を加える。自動生成した記録先は起動応答の`handoff_record_path`にも返す。
記録のファイルは委譲先が最初に作成し、委譲元は終了後の検収で読む。後任には既存のsession_handoffが同じパスを継続として渡す。
自己完結した軽量起動は、その入力と返却を全体の目的・現行要求と比べ、記録の更新は要求や戻り先が変わった場合に行う。

通常taskとdelegateは全体作業契約の参照と現行本文を起動promptへ配送する。初回を含む通常起動では、呼出側が保持する現行契約を`start`の`whole_contract_path`へ渡す。参照先はその明示入力、直接の委譲元がsession登録簿の起動本文に持つ受領済みの参照、所有会話のmanaged-tempの`work-contract.md`の順に解決する。後者2つは既存の省略起動の互換処理である。
本文は宣言型配送のstartup-documentを使い、`input:作業契約`として実体・本文hash・参照基点を受領側へ渡す。これにより、担当工程の判断前に現行要求が同じ文脈へ届き、圧縮後も同じ実体を再取得できる。全体記録の更新の所有権はメインに保ち、起動側は本文を書き換えない。
メインのスキルが`input:作業契約`を読む場合は、委譲の起動入力を優先し、その入力がなければ自身のmanaged-temp直下の`work-contract.md`へ解決する。
未作成時は期待パスと作成手順を通知する。
入力名ごとの解決元は共通定義へ登録し、役割文書以外の読込表に解決元のない入力名を宣言すると検査で拒否する。
所有会話は起動時に保持した会話とし、それがプロセス専用ルート（`mcp-`形式）か不在の場合はManagerが状態書込主体の索引から解決した委譲元会話とする。専用記録先も同じ所有会話の保存領域へ置く。
共有状態の名前空間（ルート）は会話と一致しないことがあり、process-loop all-reposの対象リポジトリ担当などでは名前空間から記録を探すと所在が未解決になる。
委譲元の受領済み参照を所有会話より先に使うのは、委譲先自身の保存領域が全体記録を持たず、孫へも委譲元と同じ全体記録を渡すためである。
どの解決元も成立しない起動と、期待パスが確定して記録が未作成の起動は、担当と専用記録先を作成せずに拒否し、記録の作成か`whole_contract_path`での再発行を返す。

却下した案は次のとおりである。未解決の通知を配送して担当を起動する案は、担当が委譲元へ所在を照会する往復を残す。全会話の保存領域を走査する案は会話境界を越える。最初のMCP応答で作成される別名索引を使う案は、その応答より前の最初の起動で成立しない。

受入時は`agent-toolkit/share/work-contract.md`「追加入力の統合」の例（推奨Aの有効な利点へX・Y・ZZを統合する場面と、`A-b`から`c'`への部分訂正後にA全体へ戻る場面）を、各工程から同節への参照とともに検収する。
回帰テストは質問・訂正・機械注入・圧縮復元の所在通知と、宣言済みtask・宣言のないtask・自由本文delegate・軽量起動・後任の記録先の同一性、メインの本文配送と未作成時の診断を扱う。
