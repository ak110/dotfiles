# atk serveの画面と選定設定

## atk serveの画面

読み取りが一時的に失敗したときは自動で取り直す。
取得できない状態が続いて案内が出たら、画面の「再取得」を押す。

`atk serve`を実行し、起動ログに表示されたURL（初期値は`http://127.0.0.1:28766/`、Windowsではポート28876）をブラウザーで開く。
終了するにはそのターミナルで`Ctrl+C`を押す。
画面は次の6つである。

- WI: AWI・UWIの登録、編集、回答、状態の変更
- 計画ファイル: ローカルと設定済みリモートホストの計画ファイルの一覧・全文検索・表示
- エージェント: ホストごとの稼働中の会話、委譲の親子関係と進捗の表示。
  記録があればセッションへ移動できる
- セッション: Claude CodeとCodexの保存済みセッションの一覧と会話の表示。
  右ペインの見出しにAPI料金換算の推定費用を表示する。
  単価が分からない応答は金額に含めず、モデル名と件数を示す。
  記録にモデル名がない場合は「モデル名なし」と表示する
- 利用枠: Claude・Codexの使用率、回復時刻、見込み、リセット権（目盛りは5時間の枠なら1時間、週の枠なら1日ごと）
- 設定: `atk config` の実効値と出所の確認、保存値やリポジトリ登録の変更

利用枠はローカルの観測を表示する。
見込みには窓の開始から観測時刻までの平均ペースが続くと仮定した値を使う。
画面を表示している間は、最後に取得してから5分経つと取り直す。
「再取得」は間隔を待たない。
取り直している間も最後に取得した観測を表示する。
Claudeのリセット権は手入力の在庫を表示し、消費は公式の利用状況画面で行う。
「リセットの許可を設定」からローカルの設定を開ける。

WI一覧の行末にあるコピーのアイコンで、ファイル名と要約をコピーできる。
「全てコピー」は、現在の条件に一致する全ページを対象にする。

WIの詳細では、本文やメタデータのWIファイル名から参照先を子ダイアログで開ける。
編集するときは子ダイアログの「このWIを開く」を選び、通常の詳細に切り替える。

WI画面の状態表示のうち、`answered`は回答済みで次の処理を待つUWI、`cooldown`は期限まで処理を始めないAWI、`needs-verify`は反映後の観測待ちで再処理を待つAWIを示す。
振り返りのbatchが登録したAWIも、エージェントが採否を検討して自動処理する。
未回答のUWIの回答を待つAWIには`blocked`バッジが付き、UWIへ回答すると外れて次の処理で回答とともに処理される。
処理中のUWIは`processing`と表示される。

通常表示・条件検索で回答できるUWIを開くと、下部に選択肢と回答欄が表示される。
選択肢を押すと回答欄へ入り、「回答を保存」で保存する。
採用・編集などの操作も同じ詳細から行える。

未回答のUWIを続けて確認するには、表示モードの「判断待ち」を選ぶ。
inbox・processing・holdの未回答UWIを全期間から集め、重要な項目を先に、同じ重要度では作成日時の古い順に表示する。

1. 「判断待ちのtarget-repo」をallにすると全リポジトリ、対象を選ぶとそのリポジトリに限定する
2. 一覧から項目を開き、本文を読んで回答を入力する。
   選択肢を押しただけでは保存されない
3. 「保存して次へ」で今の1件を保存して次を開く。
   「保存せず次へ」は未回答のまま見送り、入力済みなら破棄を確認する
4. 詳細の現在位置と未回答の残件数を確認しながら、ページをまたいで進める。
   最後の候補を終えると詳細が閉じ、見送った分を含む残件数が表示される
5. 一覧へ戻って「通常表示」または「条件検索」を選ぶ。
   検索の入力値は保持される。
   編集や状態の変更もこちらから行える

保存に失敗した場合は今の項目と入力が残るため、案内に従って原因を解消してから再試行する。
外部更新による競合では開き直して内容を確認する。
保存済みで次の取得だけが失敗した場合は、「保存せず次へ」で次の取得を再試行する。
キーボードではTabで一覧のリンクやボタンへ移動し、Enterで実行できる。
回答欄のEnterや日本語入力の確定では保存されない。

回答の保存後、エージェントが既存の処理で元の作業へ反映する。
今後も同じ判断を使ってほしい場合は、適用する範囲と継続して使うことを回答に明記する。
今回限りの回答は一般化されず、回答の保存と実装・方針記録への反映完了は別に扱われる。

エージェントが登録したinboxまたはholdのAWIには、詳細画面から`## ユーザーコメント`を追記できる。
コメントに操作・対象・範囲を具体的に書くと、その範囲の外部操作への承認として扱われる。
「進めて」だけでは範囲が確定しないため承認にならない。

「設定」の「全ホスト共通」では、ローカルと同じ共有先の設定をまとめて表示する。
「ホスト別」では、対象ホストと分類を選ぶ。
共有先の一致を確認できないホストの値は、そのホストの設定として扱う。
共有前の値が残る端末は「ホスト別」の「共有へ移行」で移す（[共有設定への移行](claude-code-settings.md#共有設定への移行)）。
設定の絞り込みでは、設定名と説明の両方を対象にする。
編集中の値は未保存の一覧から確認でき、画面を離れる前に警告する。
「ホスト別の設定を比較」では、その時点で取得できた保存値を横に並べて表示する。
ローカルの「atk serve」で `remote_hosts` に追加した接続先は、設定の切替欄に保存後すぐに現れる。
計画とセッションの参照先や待受の変更は、次に `atk serve` を起動したときに反映する。
リモートの設定はSSH先の `atk config` で取得・保存する。
設定画面を開いている間はローカルの設定を定期的に読み直す。
読み取り専用の取得に対応するリモートホストの設定は、選ばれていない間もサーバーが裏で取得する。
各画面は表示中に自動で更新する。
更新を取り直せない状態が続く場合だけ、上部に「再取得」を表示する。
Windowsの設定は、初回の取得から保存まで非昇格で操作する。
ローカルに `ssh-unelevated` があり、接続先でユーザーがログオンしている必要がある。
旧版のみにあるキーは読み取り専用で、複雑な値や一括操作を編集するにはSSH先の更新が必要となる。
一時指定の期限と利用枠の許可期間はブラウザーの時刻で入力する。
許可の開始は「今」、終了は週次リセットの1〜3日前や、現在から24時間後・7日後から選べる。
提案のボタンは入力だけを行う。
リモートを再訪すると最後に取得した設定を表示する。
最新の設定が届くまでは保存できない。
編集中の値が別の操作で変更された場合は、最新の値を取り込むか、自分の入力で上書きするかを選ぶ。

旧版の計画用とセッション用のSSH接続先は、重複を除いて `remote_hosts` に移行する。
セッション詳細では、先頭・末尾へ移動できる。
「会話だけ」にすると、振り返りと同じ規則で発話と呼び出しを表示する。
「記録内検索」はまだ表示していないイベントも探し、「前のユーザー発話」「次のユーザー発話」は実際のユーザー入力へ移動する。
各イベントの「リンク」でその位置を開ける。
ツールから送ったユーザーへの報告はMarkdownで読み、送達結果を開いて確認できる。

計画ファイル、セッション、エージェント、WI詳細にあるWIファイル名のリンクは、その画面で閲覧用の詳細を開く。
計画ファイルの「関連WI」からも開ける。
中ボタンでクリックすると別タブで通常のWI詳細を開く。

セッションの保存先は `CLAUDE_CONFIG_DIR`・`CODEX_HOME` で指定でき、未設定時は `~/.claude`・`~/.codex` を使う。

各操作の所要時間は`atk config get state_dir`が示すディレクトリの`serve/timings.jsonl`へ常に記録される（1MiBごとに1世代を残して回す）。
画面の操作が遅い場合は、`"kind": "operation"`で`total_ms`の大きい行を探し、同じ`operation_id`の取得の行と、その`request_id`のサーバーの行を比べると、画面の描画、実行枠やロックの待機、処理のどこで時間を使ったかが分かる。

リモートのエージェント一覧、自動更新、費用表示には、リモートホスト側のdotfilesの更新が必要である。
画面の詳細な振る舞いは[design-serve-session-list.md](../development/design-serve-session-list.md)を参照。

### WI画面を閉じていても通知を受け取る

初期状態ではWeb Pushを使わない。
HTTPSと認証を備えたリバースプロキシの先から利用する場合に、次の手順で有効にする。

1. 配信するホストで `atk config set serve_web_push true` を実行し、`atk serve` を再起動する。
2. 対応するChrome・Edge・FirefoxでWI画面を開き、「閉じていても通知する」を押して通知を許可する。
   iOS・iPadOS 16.4以降では、Safariの共有メニューからホーム画面に追加し、追加したアイコンから開いて許可する。
3. 停止するには端末ごとに「Web Pushを解除」を押す。
   ホスト全体の送信を止めるには `atk config set serve_web_push false` を実行し、`atk serve` を再起動する。

新しい未回答UWIと観測が必要なAWIが通知対象である。
購読していない端末では、開いているWI画面の従来の通知を使える。
初期設定の通知にはWIのタイトル・対象リポジトリ・本文を含めない。
タイトルとリポジトリも受け取る場合は、ロック画面などで読めることを確かめてから `atk config set serve_web_push_details true` を設定し、再起動する。
本文は送らない。
購読が失効した場合はWI画面で再度購読する。

### WIに検証の画像やログを添付する

`atk wi attach <WIファイル名> <パス>...` で添付し、`atk wi attachments <WIファイル名>` で一覧できる。
本文に `attachment:ファイル名` と書くと、WI詳細に画像またはダウンロードのリンクが出る。
説明と同じ行に書ける。
Markdownリンクの宛先やコードブロックには書かない。
名前には半角英数字・ピリオド・下線・ハイフンを使う。
PNG・JPEG・GIF・WebP以外はダウンロードする。
添付はprivate-notesのGitでWIとともに同期する。
実データや秘匿値を含まないことを保存前に確かめる。
`atk wi detach <WIファイル名> <添付名>` やWIの削除後も、添付はGit履歴に残り、累計容量は戻らない。

## 選定結果の確認設定

対象リポジトリの`pyproject.toml`に`[tool.agent-toolkit.pick-wi-check]`の`norm-spec`を置くと、AWIの選定時に、条件に当たる項目へ指定の規範を書くことを求められる。
各条件は`paths`と`suffixes`か`agent-doc = true`（エージェント向け文書）で対象を選び、`require-paths = true`か`require-text`で求める記載を指定する。
設定の誤りは、場所と直し方を示して終了コード2で報告される。
