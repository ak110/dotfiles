# サブエージェント定義ファイルと`<役割名>.parent.md`・`<役割名>.subagent.md`の記述基準：agents_serverのfrontmatter

## 名指し参照の読込方法

名指し参照は`agent-basics:writing-standards/references/read-method.md`に従う。

## agents_serverのfrontmatter

`<役割名>.subagent.md`は先頭のYAML frontmatterへ起動設定を置く。

```yaml
---
mode: explore
model_type: chores_fast
required_inputs:
  - 対象
optional_inputs:
  - 観点
writes_worktree: false
continuations:
  - instruction: 追加確認
    required: [対象]
---
```

必須キーは`mode`、`model_type`、`required_inputs`、`writes_worktree`の4つである。
`optional_inputs`、`continuations`、`result_heads`を省略した場合は、空の配列として扱う。
キー、値、入力名、継続宣言の静的な整合性は、配布対象となるすべての役割文書を列挙するテストによって保証する。
起動時には設定を読み込み、起動方法や書き込み主体の判定に必要な`mode`、`writes_worktree`、および呼び出し時の入力を検証する。
正しく読み込めない設定が含まれる場合は、診断情報を出力して終了する。

| キー | 値と意味 |
| --- | --- |
| `mode` | `delegate`・`explore`・`shell`・`write`のいずれか。後3種は同名modeの軽量な起動条件を使う |
| `model_type` | `execute`・`review`・`review_fast`・`chores`・`chores_fast`・`orchestrate`・`write`。起動時の明示指定による上書きを保つ |
| `required_inputs` | 全受領条件で必須の入力名の配列 |
| `optional_inputs` | 任意または条件付きで必要な入力名の配列。条件は本文の`## 入力`へ書く |
| `writes_worktree` | 起動cwdの作業ツリーへ書く役割は`true`、書込先をその外へ限定した役割は`false` |
| `continuations` | 後述の継続指示の配列 |
| `result_heads` | 返却形式が共通の状態行（`状態:`）以外に定める固定行の配列。agents_serverの返却検査は、状態行・この固定行・`待機中:`・区分と理由の2行のいずれも無い返却を形式違反として1回回復させる。`:`で終わる値は前方一致、それ以外は行全体の一致で受理する。返却形式を変える役割文書は同じ変更で更新する |

必須入力と任意入力の名前は宣言全体で重複を避け、空白文字、バッククォート、読点、全角カンマ、先頭・末尾のコロンを含めないようにする。
モデルの上書きと候補列の直接指定にも、`process-model-settings.md`「工程別モデル設定」の自律選択制限とユーザー明示指定の境界を適用する。
サーバーは、必須入力の不足や未宣言の入力が存在する場合、起動前に処理を拒否する。
入力項目の追加・削除・名称変更する際は、宣言、本文、ならびに呼び出し元の契約を同一の変更で整合させる。
新しい定型チェックは、役割文書の宣言と本文、および呼び出し元の入力・検収契約を追加するだけで起動可能になる。
共通の読み取り処理は`agent_toolkit/_common/task_documents.py`に集約し、サーバー、hook、プロンプト生成、レーンの書き込み判定が同一の宣言定義を共有する。
旧バージョンの入力textブロックや、古い役割のモデル・用途対応表は、保存済みの過去の文書や既存セッションとの読み取り互換性を維持する目的でのみ利用する。

作業ツリーへの書き込み手順を含む場合や、対象プロンプトの自由な操作、書き込み先を限定しない検証環境の起動を伴う役割には、`writes_worktree: true`を指定する。
書き込み先をmanaged-temp、引き継ぎ記録、private-notesのみに限定できる役割は`false`に設定できる。
書き込み先をこれらの範囲に限定できない役割は`true`とする。
`atk lane integrate`は、`false`が設定された担当者を書き込み主体の対象から除外する。
新しい役割を作成する際は書き込み先を明確にし、`writes_worktree`に明示的に設定する。
軽量起動時に届く規範やスキルは`agent-toolkit:delegation/references/delivery-scope.md`の配送範囲表で確認し、必要な判定基準や手順は役割文書内で完結するように記述する。
`explore`モードでは、すべてのバックエンドで通常の読み取りコマンドや読み取り用MCPを利用できる。
対象成果物、委譲入力、ユーザーデータの変更禁止は共通プロンプト側から指示し、実行環境が管理するキャッシュ、内部状態、保存出力とは区別して扱う。
同一バージョンの比較など、役割固有の検収に必要な保存資料は入力契約の中に保持する。

`continuations`の各要素には、以下の入力名配列および指示を定義する。
`instruction`には指示内容を記述し、`required`や`optional`には入力名を指定する。
`paths`には実在するファイルの絶対パスのみを受け付ける入力名を指定する。
`path_lists`には実在するファイルの絶対パス1件、またはそれらを含む空でないJSON配列を受け付ける入力名を指定し、`references`にはファイルパスとテキスト本文の双方を受け付ける入力名を指定する。
各配列を省略した場合は空配列、`condition`を省略した場合は空文字列として処理する。
`paths`、`path_lists`、`references`は該当指示が受け付ける入力のみを対象とし、指示ごとの宣言は1回に限る。
絶対パスについては、配列内の各要素を含めてファイルが実在するかどうかを検証し、不正な値が含まれる場合はその値と再実行用の形式を明示してリクエストを拒否する。
本文データは役割ごとに定められた契約に従って引き渡す。
`condition`によって条件付き必須値が定義されている場合、送信側は対象の工程や履歴に基づいて要否を判定する。
サーバーおよび生成CLIは、この宣言に基づいて必須入力の欠落、宣言外の入力、パス欄への説明文の混入などをチェックする。
プロンプトの生成と配送の手順は、`sending-prompt.md`「委譲プロンプトの構成」に従う。

## 起動対象と入力の案内

`<役割名>.parent.md`では、H1見出しの直後かつ最初のH2見出しの手前に`text`コードブロックを1つ配置する。
その1行目には`起動対象:`と半角スペースに続けて、直接起動する`<役割名>.subagent.md`のファイル名をASCIIカンマ区切りで列挙する。
この行が起動関係を定義する基準となる。
呼び出し元へ統合した契約を記述する場合はH2見出しの節とし、見出しの直後に同様の起動対象コードブロックを配置する。
節内の起動手順、入力定義、検収基準はH3以下の見出しに配置することで、共有parentと同様に宣言や入力の自動チェックへ通せるようにする。
共有の`<役割名>.parent.md`には単一の入力専用H2節（`入力`または`渡す入力`）を設ける。
節内の`- 必須入力名:`行に各委譲先の`required_inputs`と一致する名前をバッククォートで囲んで列挙し、必須・条件付き・任意の各入力の値の決定規則を記載する。
詳細な生成規則は既存の節を参照できる。
箇条書きで列挙する際は文頭を項目名から開始し、直後にはコロン、句点、読点、全角丸括弧、空白のいずれかのみを置く。
別の単語を付け加えると項目名の対応付けが正しく認識されず、必須入力チェックで欠落と判定されて委譲先の起動に失敗する原因となる。
